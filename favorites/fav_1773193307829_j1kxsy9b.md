# 一、项目定义

## 1.1 什么是 Agent Harness

**Agent Harness**可以理解为一个 “面向 AI Agent 的运行、编排、观测、评测与安全控制平台”。

它不是单个 Agent，而是一个为 Agent 提供以下能力的基础设施层：

- **任务接入**
- **Agent 编排**
- **工具调用**
- **上下文管理**
- **多模型路由**
- **执行监控**
- **结果评测**
- **安全治理**
- **回放调试**
- **线上运营**

一句话概括：

> Agent Harness = Agent Runtime + Workflow Orchestration + Tool Layer + Memory Layer + Observability + Evaluation + Governance

---

## 1.2 产品目标

建设一个可扩展、可观测、可治理的 Agent 平台，支持企业快速搭建和运营以下场景：

- 智能问答 Agent
- 企业 Copilot
- 流程自动化 Agent
- 数据分析 Agent
- 工单处理 Agent
- 多 Agent 协作系统
- 面向 API / IM / Web 的 Agent 服务

---

## 2.2 逻辑关系图（执行流）

```text
用户请求
   │
   ▼
[接入层 / API Gateway]
   │
   ▼
[Agent Runtime]
   │
   ├─ 读取会话上下文
   ├─ 选择 Prompt / Policy
   ├─ 调用 Planner 进行任务拆解
   ├─ 决定是否调用 Tool / RAG / 子 Agent
   │
   ▼
[Model Router]
   │
   ├─ 选择模型（GPT / Claude / Qwen / DeepSeek 等）
   ├─ 控制成本、延迟、降级策略
   │
   ▼
[Tool Engine / Memory / KB]
   │
   ├─ 检索知识
   ├─ 调用外部工具
   ├─ 更新状态与记忆
   │
   ▼
[Response Composer]
   │
   ▼
输出结果 + 保存 Trace + 触发 Eval / Audit
```

# 三、核心模块清单

下面按 “产品模块 + 技术职责 + MVP 优先级” 来列。

---

## 3.1 接入层模块

### 1）管理控制台 Console
**职责：**
- Agent 配置管理
- Prompt 配置
- 工具注册
- 知识库管理
- 运行日志查看
- 回放调试
- 发布与版本管理

**MVP 优先级：P0**

---

### 2）开放接口 API / SDK
**职责：**
- 提供对外调用 Agent 的 HTTP / WebSocket API
- 提供 Python / JS SDK
- 支持同步与流式输出
- 支持 Session / User / Tenant 标识

**MVP 优先级：P0**

---

### 3）渠道连接器 Channel Connectors
**职责：**
- 接入 Web Chat
- 接入企业微信 / 钉钉 / Slack
- 接入工单系统 / Webhook

**MVP 优先级：P1**

---

## 3.2 Agent 运行与编排模块

### 4）Agent Runtime
**职责：**
- 承载单次 Agent 执行生命周期
- 管理输入、上下文、工具调用、输出
- 管理执行状态（init /planning/acting /done/failed）

**MVP 优先级：P0**

---

### 5）Prompt Runtime / Policy Engine
**职责：**
- Prompt 模板渲染
- 系统提示词注入
- 角色与权限约束
- 任务策略注入（例如不能直接执行高风险动作）

**MVP 优先级：P0**

---

### 6）Planner / Task Decomposer
**职责：**
- 将复杂任务拆解为多个步骤
- 判断是否需要工具
- 决定执行顺序

**MVP 优先级：P1**
> MVP 第一版也可先用 ReAct /function calling 替代显式 Planner

---

### 7）Workflow Engine
**职责：**
- 支持固定流程与半自主流程
- 定义节点：LLM、Tool、Condition、Human Approval
- 实现有状态执行

**MVP 优先级：P1**
> MVP 可先做轻量版 DAG / Step Runner

---

### 8）Multi-Agent Coordinator
**职责：**
- 管理多个 Agent 协同
- 角色分工（Researcher / Executor / Reviewer）
- 消息与任务传递

**MVP 优先级：P2**

---

## 3.3 模型层模块

### 9）Model Router
**职责：**
- 按任务类型选择模型
- 支持主备切换
- 支持成本、质量、时延策略
- 支持模型降级

**MVP 优先级：P0**

---

### 10）Model Adapters
**职责：**
统一封装各模型供应商能力：
- OpenAI

**MVP 优先级：P0**

### 11）Prompt Template Center

- Prompt 模板管理
- 版本化
- A/B Test
- 多场景复用

**MVP 优先级：P1**

## 3.4 工具层模块

# 四、MVP 范围定义

---

## 4.1 MVP 目标

MVP 目标不是一次性做完整 Agent 平台，而是先支持：

> “配置一个可调用知识库与工具的单 Agent，并可通过 API / Web UI 使用，且具备最基本的日志、回放和安全控制能力。”

---

## 4.2 MVP 必做能力（P0）

### 产品侧
- Agent 创建 / 编辑 / 发布
- Prompt 配置
- Tool 注册与调用
- 知识库导入与检索
- API 调用
- Web Chat 调试页
- 运行日志查看
- Trace 回放

### 技术侧
- 单 Agent Runtime
- Model Router
- 至少 2 个模型 Adapter
- Tool Registry + Invocation Engine
- RAG Pipeline
- Session Memory
- Context Builder
- Metadata DB
- Trace Store
- Auth + Tenant 基础隔离
- Guardrails 基础版

---

## 4.3 MVP 不做 / 延后能力

- 多 Agent 协同
- 复杂 Workflow Designer（可视化编排）
- 长时记忆
- 自动评测平台全量能力
- Browser use / Computer use
- 复杂审批流
- 精细化计费系统

---

## 5.1 推荐技术栈

### 后端
- **语言**：Python
- **Web Framework**：FastAPI
- **Agent 编排**：自研轻量 Runtime + LangGraph / 自定义 Step Runner（二选一）
- **异步任务**：Celery / Dramatiq / Arq
- **ORM**：SQLAlchemy
- **鉴权**：JWT / OAuth2
- **接口协议**：REST + SSE（流式输出）

### 前端
- **Console**：React + Next.js
- **UI**：Ant Design / Shadcn UI
- **状态管理**：Zustand / Redux Toolkit

### 数据层
- **关系库**：PostgreSQL
- **缓存**：Redis
- **对象存储**：S3 / MinIO
- **向量库**：pgvector / Milvus / Weaviate
  - MVP 推荐：**PostgreSQL + pgvector**
- **全文检索**：Postgres FTS / Elasticsearch
  - MVP 推荐：先用 Postgres FTS

### 可观测性
- **日志**：OpenTelemetry + ELK / Loki
- **指标**：Prometheus + Grafana
- **链路追踪**：Jaeger / Tempo

### 模型接入
- OpenAI / Azure OpenAI
- Anthropic
- 国内可增加：通义 / DeepSeek
- 本地模型：vLLM（P1）

## 5.4 核心执行流程设计

### 场景：用户向 Agent 提问

```text
1. 用户请求进入 API Gateway
2. 鉴权、识别 tenant /user/session
3. 加载 Agent 配置
4. 读取 Session Memory
5. Context Builder 组装：
   - system prompt
   - session history
   - kb 检索结果
   - 可用工具说明
   - policy 限制
6. Agent Runtime 调用 Model Router
7. 模型决定：
   - 直接回答，或
   - 发起 tool call
8. Tool Engine 执行工具
9. 工具结果回填上下文，再次推理
10. 输出最终结果
11. 保存 trace /metrics/logs
12. 返回响应（支持流式）
```

---

## 5.5 RAG MVP 实现方案

### 文档处理链路
```text
文档上传
  → 文本提取
  → 清洗
  → Chunk 切分
  → Embedding
  → 写入 pgvector
  → 建立元数据索引
```

### 检索链路
```text
用户问题
  → Query Rewrite（可选）
  → 向量召回 TopK
  → 关键词过滤（可选）
  → 重排（MVP 可不做）
  → 拼接引用片段
  → 注入上下文
```

### MVP 建议
- 先不做复杂 reranker
- 先用固定 chunk size + overlap
- 输出中强制附带引用来源
- 每次检索保存 trace

## 5.6 Tool Calling MVP 实现方案

### 工具协议
采用统一 JSON Schema 定义输入输出：

```json
{
  "name": "ticket_query",
  "description": "查询工单状态",
  "input_schema": {
    "type": "object",
    "properties": {
      "ticket_id": { "type": "string" }
    },
    "required": ["ticket_id"]
  }
}
```

### 执行要求
- 参数校验
- 超时控制
- 重试机制
- 幂等支持
- 敏感工具审批开关
- 全链路日志记录

### MVP 推荐工具形态
- Python function tool
- HTTP tool
- SQL readonly tool

## 5.7 安全治理 MVP 方案

至少做以下基础能力：

### 输入侧
- Prompt Injection 基础检测
- 敏感词检测
- 超长输入截断
- 文件类型白名单

### 执行侧
- 工具白名单
- 工具按 Agent 授权
- 高风险工具禁用写操作
- SQL 只读限制
- Secret 不落 Prompt

### 输出侧
- 敏感信息脱敏
- 风险内容分类拦截
- 引用来源控制

### 审计侧
- 保留请求、工具调用、配置变更日志
