# Cursor 3 用户反馈总结：从 AI IDE 走向 AI 开发工作台

## 一、核心结论

Cursor 3 的方向被用户认可，尤其是**Agent 化开发**。  
但用户真正想要的不是一个 “更炫的 AI IDE”，而是一个：

> 稳定、可控、键盘友好、支持多 Agent 并行、能贯穿 IDE / Git / 终端 / 浏览器 / 模型 / 团队协作的 AI 开发工作台。

换句话说，Cursor 的竞争焦点正在从 “AI 写代码能力” 转向 “AI 工程工作流管理能力”。

---

## 二、用户最核心的诉求：Agent 不能割裂 IDE

Agent Window 很有潜力，但现在的问题是：  
用户进入 Agent 模式后，经常会失去传统 IDE 的完整能力。

用户希望 Agent Window 里也保留：

- LSP、代码跳转、格式化
- 调试、任务运行、终端命令
- 文件搜索、扩展、快捷键
- Diff 接受 / 拒绝
- Git 操作与代码审查

理想状态是：

> Agent 推进任务，人类随时无缝接管、检查、微调、运行和调试。

---

## 三、多 Agent 与多仓库协作是最大机会

用户不再满足于 “一个聊天框写代码”，而是期待：

- 多个 Agent 并行处理任务
- 每个 Agent 有独立 worktree
- 可视化查看 Agent 进度、阻塞点和状态
- 不同角色 Agent 协作：规划、实现、Review、QA
- 用户像项目经理一样统一调度和验收

这意味着 Cursor 未来更像是：

> 开发者管理 AI 工程团队的主界面。

---

## 四、Git / Worktree / PR 需要产品化

当 Agent 多任务并行后，Git 工作流会变得更复杂。  
用户希望 Cursor 提供低摩擦、可控、可审计的 Git 控制台，而不是每次都靠自然语言指挥 Agent。

高频需求包括：

- Branch 创建与切换
- Worktree 管理
- 当前 Chat 改动生成 commit
- 选择性 staging
- Multi-repo diff
- PR 检测、评论、Review
- CI 状态展示
- Merge 后同步 main
- Submodule 支持

本质需求是：

> 把 Agent 产出的代码变成可追踪、可审查、可合并的工程资产。

---

## 五、信息架构需要从 “聊天列表” 升级为 “任务记忆系统”

随着 Agent 和 Chat 增多，用户开始遇到严重的导航和记忆管理问题：

- 找不到历史 Chat
- 项目太多，Sidebar 混乱
- 当前 Active Agent 不明显
- Chat 自动滚动影响阅读
- Session 无法方便 pin、fork、引用、复用
- Chat 命名和管理成本高

一个有价值的方向是：

- 自动根据内容给 Chat 命名
- 支持消息 pin
- 支持从某条消息 fork session
- 支持旧 Chat 拖入新 Chat 作为上下文
- 支持跨项目引用历史 Session

核心变化是：

> Cursor 不能只是保存聊天记录，而要管理任务上下文和工程记忆。

---

## 六、重度用户要求键盘优先和高度可定制

开发者工具的效率，很大程度来自肌肉记忆。  
用户明确希望 Cursor 3 能做到：

- 全流程无需鼠标
- 快速切换 Chat、文件、终端、浏览器、Diff、Agent
- 自定义快捷键
- 继承旧 Cursor / VS Code 的操作习惯

对重度开发者来说，快捷键不是细节，而是生产力基础设施。

---

## 七、稳定性与性能正在影响信任

Cursor 3 的愿景很大，但基础稳定性仍是用户痛点。  
反馈集中在：

- 启动慢
- Windows / WSL / SSH 问题
- 内存、CPU 飙升
- 多 Agent 后卡死
- 大代码库索引变慢
- 文件树空白
- Chat reload 后丢失
- Markdown 内容丢失
- LSP 失效
- Cloud / Local 状态不一致

用户的信号很明确：

> 如果基础体验不稳定，即使 Agent 很强，用户也会回退到 Claude Code、Codex、T3 Code 或旧 Cursor。

---

## 八、模型选择与成本透明度越来越重要

用户开始关心的不只是 “模型强不强”，而是：

> 这个任务用哪个模型最划算？

高频诉求包括：

- 更高额度
- 更便宜的 Composer
- 支持本地模型
- BYOK
- OpenRouter
- 第三方模型订阅
- 在模型选择器中展示价格、质量、速度

更理想的体验是 Cursor 主动建议：

- 简单任务用便宜模型
- 复杂任务用强模型
- 上下文快满时自动生成 handoff
- 根据任务类型自动分配模型

---

## 九、扩展、MCP 和外部集成决定护城河

用户希望 Cursor 不只是 AI 编辑器，而是开发自动化中枢。

关键诉求包括：

- 新 Agent 界面支持旧 IDE 扩展
- 更稳定的 MCP 连接
- 更好的 MCP 鉴权和状态管理
- 按 Chat 启用不同 MCP
- 自动发现和推荐合适 MCP
- 集成 GitHub、Vercel、Slack、Linear、Asana、数据库、邮箱、部署和 Review 工具

Cursor 的机会在于：

> 连接代码、工具、流程和团队，成为 AI 驱动的软件交付中枢。

---

## 十、移动端需求来自 “远程监管 Agent”

用户想要移动端，不是为了在手机上写代码，而是为了：

- 查看 Agent 进度
- 回复 Agent 问题
- 批准命令
- 继续对话
- 查看 Preview
- 远程触发任务

Agent 越自主，移动端价值越高。  
因为用户需要的是：

> 随时监管一个正在工作的 AI 开发助理。

---

## 十一、前端与设计工作流仍有提升空间

前端开发者希望 Cursor 更好支持：

- 浏览器 Preview、Terminal、Files 同屏
- 移动端视图和缩放
- DOM 元素选择
- 浏览器 Profile 隔离
- Design Mode 中直接修改文案、间距、标题
- 多元素选择与父子层级切换
- 接入 Figma tokens /design system

核心诉求是：

> 保证 Figma → Cursor → Code → Figma 的一致性，避免 AI 修改导致设计系统漂移。

---

## 十二、产品优先级建议

Cursor 3 最值得优先打磨四件事：

1. **Agent 与 IDE 无缝融合**  
   让 Agent 模式具备完整 IDE 能力，人类可随时接管。

2. **Worktree / Git / PR 工作流产品化**  
   支持多 Agent 并行后的代码管理、审查和合并。

3. **大项目下稳定、快速、不丢上下文**  
   稳定性是用户信任 Agent 的前提。

4. **模型成本、能力和任务分配透明可控**  
   帮用户用合适成本完成合适任务。

---

## 最终判断

Cursor 3 的下一阶段，不应只是做 “更强的 AI 编码助手”，而应成为：

> 开发者管理多个 AI Agent、复杂代码仓库、模型资源和工程流程的 AI 开发操作系统。

如果 Cursor 能把 Agent、IDE、Git、模型和协作流程真正打通，它就有机会从 “AI 编辑器” 升级为软件开发的新工作台。
