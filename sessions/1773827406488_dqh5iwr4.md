## 正文

今天，我们推出 **Unsloth Studio** （测试版）：一个开源、无需代码的网页用户界面，用于在一个统一的 **本地** 界面中训练、运行和导出开源模型。

Quickstart Features [Github](https://github.com/unslothai/unsloth)

- 在 Mac、Windows、Linux 上本地运行 GGUF 和 safetensor 模型
- 训练500多个模型，速度提升2倍，显存减少70%（无精度损失）
- 运行和训练文本、视觉、TTS 音频、嵌入模型

##### No-code training

上传 PDF、CSV、JSON 文档，或 YAML 配置文件，然后在 NVIDIA 上立即开始训练。Unsloth 的内核优化了 LoRA、FP8、FFT、PT，适用于 500 多种文本、视觉、文本转语音/音频和嵌入模型。

微调最新的 LLMs，如 Qwen3.5 和 NVIDIA Nemotron 3 。 Multi-GPU 自动工作，新版本即将推出。

#### ⚡ Quickstart

Unsloth Studio 适用于 Windows、Linux、WSL 和 MacOS（目前仅聊天）。

- CPU: Unsloth 在没有 GPU 的情况下仍然可以运行，但仅适用于 Chat 推理。
- 训练： 适用于 NVIDIA GPU：RTX 30、40、50、Blackwell、DGX Spark/Station 等。
- **Mac：** 类似 CPU，目前仅聊天功能可用。 **MLX** 训练即将推出。
- **即将推出：** 对 **Apple MLX** 、 **AMD** 和 **Intel** 的支持。
- **多 GPU：** 已经可用，即将有重大升级。

```
git clone https://github.com/unslothai/unsloth.git

cd unsloth

pip install -e .

unsloth studio setup

unsloth studio -H 0.0.0.0 -p 8888
```

首次安装可能需要 5-10 分钟。这是正常的，因为 llama.cpp 需要编译二进制文件。我们正在开发预编译二进制文件，因此下次安装将不会花费这么长时间。

#### Workflow

以下是 Unsloth Studio 的常规工作流程，助你入门：

1. 从 安装说明 启动 Studio.
2. 从本地文件或受支持的集成中加载模型。
3. 从 PDF、CSV 或 JSONL 文件导入训练数据，或从零开始构建一个数据集。
4. 在 数据配方 中清理、优化和扩展您的数据集。
5. 开始使用推荐的预设进行训练，或者你自己自定义配置。
6. 与已训练模型进行对话，并将其输出与基础模型进行比较。
7. 本地保存或导出到你已使用的技术栈

#### FAQ

Unsloth 会收集或存储数据吗？ 我们不收集使用遥测数据。我们仅收集用于兼容性所需的最少量硬件信息，例如 GPU 类型和设备（例如 Mac）。Unsloth Studio 100%离线且在本地运行。

我该如何使用之前从 Hugging Face 下载的旧/现有模型？ 是的，你可以使用你之前从 Hugging Face 等平台下载的现有或旧模型或 GGUFs。阅读我们的 此处的说明 。

Unsloth Studio 是否支持与 OpenAI 兼容的 API？ 是的，对于我们的数据配方确实如此。对于推理功能，我们正在着手处理，希望本周内尽快发布对它的支持，请持续关注！

**Unsloth 现在的许可证是否为 AGPL-3.0？** Unsloth 采用 Apache 2.0 和 AGPL-3.0 的双许可模式。核心的 Unsloth 包仍根据 [**Apache 2.0**](https://github.com/unslothai/unsloth?tab=Apache-2.0-1-ov-file) 许可，而某些可选组件（如 Unsloth Studio UI）则根据 [**AGPL-3.0**](https://github.com/unslothai/unsloth?tab=AGPL-3.0-2-ov-file) 许可。

这种结构有助于支持 Unsloth 的持续开发，同时保持项目开源，并使更广泛的生态系统能够持续发展。

**Studio 是否仅支持 LLMs？** No. Studio 支持一系列与 transformers 兼容的模型家族，包括文本、多模态模型、 文本转语音 、音频、 嵌入模型 和 BERT 风格的模型。

**我可以使用我自己的训练配置吗？** 是的。导入一个 YAML 配置，Studio 会预先填充相关设置。

**你需要训练模型来使用 UI 吗？** 不，你可以直接下载任何 GGUF 或模型，无需微调任何模型。

我们正全力以赴，让开源 AI 尽可能易于获取和使用。对于 Unsloth 和 Unsloth Studio，我们即将推出对以下方面的官方支持：多 GPU、Apple Silicon/MLX、AMD 和 Intel。提醒一下，这是 Unsloth Studio 的测试版，因此在未来几周内会有大量公告和改进。我们还正与 NVIDIA 紧密合作，以提供最佳且最简单的多 GPU 使用体验。

## A结构化（1）

### 2026-03-18 10:01:58

这篇文章主要介绍了 Unsloth Studio（测试版）—— 一个开源、无需代码、可本地运行的 AI 模型训练与推理工具。它的核心价值是：把 “训练、运行、导出模型” 整合到一个统一网页界面里，让普通用户也能更容易使用开源模型。

- **1. 产品定位：一个本地化、无代码的开源 AI 工作台**
  - Unsloth Studio 是一个本地网页 UI，可在一个界面里完成模型训练、聊天推理和导出。
  - 支持在`Mac / Windows / Linux`上运行，强调`100% 本地离线`。
  - 不只是 LLM，还支持`文本、视觉、多模态、TTS 音频、嵌入模型、BERT 类模型`。
  - 目标是降低开源 AI 使用门槛，让 “不写代码也能训练和使用模型”。

- **2. 核心能力：训练更快、显存更省、模型类型更多**
  - 官方给出的关键数据是：可训练`500+ 模型`，训练速度提升`2 倍`，显存占用减少`70%`，且`无精度损失`。
  - 支持`GGUF`和`safetensor`模型格式，可搜索、运行并导出。
  - 支持上传`图像、文档、音频、代码文件`，并提供：
    - 自修复工具调用 / 网络搜索
    - 代码执行
    - 自动推理参数调优
    - 聊天模板编辑
  - 还支持模型并排比较，比如对比 “基础模型” 和 “微调后模型” 的输出差异。

- **3. 无代码训练与数据处理：从文档直接生成可训练数据**
  - 用户可以上传`PDF、CSV、JSON、DOCX、TXT`文件，系统可自动生成数据集，不一定需要提前准备好数据集。
  - 提供`Data Recipes（数据食谱）`，可把非结构化或结构化文件转成所需训练格式。
  - 这一功能由`NVIDIA DataDesigner`支持，适合把原始文档快速变成合成 / 可用数据集。
  - 也支持导入`YAML 配置`，让用户直接使用自己的训练设置。

- **4. 训练观测与导出：过程可见，结果可复用**
  - 支持实时查看训练指标，包括：
    - `training loss`
    - `gradient norms`
    - `GPU utilization`
  - 还能在其他设备上看进度，例如手机。
  - 模型可导出为`safetensors`或`GGUF`，兼容`llama.cpp、vLLM、Ollama、LM Studio`等工具。
  - 训练历史会被保留，方便之后重新查看、再次导出或继续实验。

- **5. 对比聊天与模型竞技场：更容易判断微调效果**
  - `Model Arena`支持同时和两个模型聊天，直接比较回答差异。
  - 一个典型例子是：对比 “原始基础模型” 和 “微调后的模型”，看微调是否真的改善效果。
  - 使用方式比较简单：先加载第一个`GGUF`模型，再加载第二个即可。
  - 目前仍是`BETA`，后续几天到几周会持续修复和增强。

- **6. 安装与使用：适用平台、步骤和注意事项**
  - 当前支持：
    - `Windows / Linux / WSL /macOS`
    - 但`macOS`目前主要支持聊天，`MLX 训练`还在开发中
    - `CPU`可运行，但仅适合聊天推理
    - 训练主要支持`NVIDIA GPU`，如`RTX 30 / 40 / 50 / Blackwell / DGX Spark/Station`
  - 即将支持：`Apple MLX、AMD、Intel`
  - 多 GPU 已可用，官方表示很快会有重大升级。
  - 首次安装可能需要`5-10 分钟`，因为要编译`llama.cpp`；而在`Google Colab T4 GPU`上编译甚至需要`40+ 分钟`。
  - 官方也提供：
    - `Docker`镜像
    - `pip`安装方式
    - 免费`Google Colab`笔记本
  - Colab 中可运行大多数`220 亿参数`以内模型，更大模型可切换更强 GPU。

- **7. 推荐工作流：从安装到导出的一条龙流程**
  - 官方建议的使用步骤大致是：
    - 先安装并启动 Studio
    - 从本地或集成源加载模型
    - 导入`PDF / CSV / JSONL`数据，或从零构建数据集
    - 用`Data Recipes`清洗、优化、扩展数据
    - 用推荐预设或自定义配置开始训练
    - 和训练后模型聊天，并与基础模型对比
    - 最后保存到本地或导出到现有技术栈
  - 这说明产品设计重点是：把 “数据准备 — 训练 — 验证 — 部署” 串成一条可视化流程。
