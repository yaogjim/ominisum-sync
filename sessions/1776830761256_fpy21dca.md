#### Huashu Design

> *「打字。回车。一份能交付的设计。」* *"Type. Hit enter. A finished design lands in your lap."*

**在你的 agent 里打一句话，拿回一份能交付的设计。**

3 到 30 分钟，你能 ship 一段 **产品发布动画** 、一个能点击的 App 原型、一套能编辑的 PPT、一份印刷级的信息图。

不是「AI 做的还行」那种水平——是看起来像大厂设计团队做的。给 skill 你的品牌资产（logo、色板、UI 截图），它会读懂你的品牌气质；什么都不给，内置的 20 种设计语汇也能兜底到不出 AI slop。

#### 核心机制

##### 品牌资产协议

skill 里最硬的一段规则。涉及具体品牌（Stripe、Linear、Anthropic、自家公司等）时强制执行 5 步：

步骤 动作 目的

1 · 问 用户有 brand guidelines 吗？ 尊重已有资源

2 · 搜官方品牌页 `<brand>.com/brand` · `brand.<brand>.com` · `<brand>.com/press` 抓权威色值

3 · 下载资产 SVG 文件 → 官网 HTML 全文 → 产品截图取色 三条兜底，前一条失败立刻走下一条

4 · grep 提取色值 从资产里抓所有 `#xxxxxx` ，按频率排序，过滤黑白灰 **绝不从记忆猜品牌色**

5 · 固化 spec 写 `brand-spec.md` + CSS 变量，所有 HTML 引用 `var(--brand-*)` 不固化就会忘

A/B 测试（v1 vs v2，各跑 6 agent）： **v2 的稳定性方差比 v1 低 5 倍** 。稳定性的稳定性，这是 skill 真正的护城河。

##### 设计方向顾问（Fallback）

当用户需求模糊到无法着手时触发：

- 不凭通用直觉硬做，进入 Fallback 模式
- 从 5 流派 × 20 种设计哲学里推荐 3 个 **必须来自不同流派** 的差异化方向
- 每个方向配代表作、气质关键词、代表设计师
- 并行生成 3 个视觉 Demo 让用户选
- 选定后进入主干 Junior Designer 流程

默认工作模式，贯穿所有任务：

- 开工前 show 问题清单一次性发给用户，等批量答完再动手
- HTML 里先写 assumptions + placeholders + reasoning comments
- 尽早 show 给用户（哪怕只是灰色方块）
- 填充实际内容 → variations → Tweaks 这三步分别再 show 一次
- 交付前用 Playwright 肉眼过一遍浏览器

避免一眼 AI 的视觉最大公约数（紫渐变 / emoji 图标 / 圆角+左 border accent / SVG 画人脸 / Inter 做 display）。用 `text-wrap: pretty` + CSS Grid + 精心选择的 serif display 和 oklch 色彩。

---

我大方承认：品牌资产协议的哲学是从 Claude Design 流传出来的提示词里偷师的。那份提示词反复强调 **好的高保真设计不是从白纸开始，而是从已有的设计上下文长出来** 。这个原则是 65 分作品和 90 分作品的分水岭。

定位差异：

Claude Design huashu-design

形态 网页产品（浏览器里用） skill（Claude Code 里用）

配额 订阅 quota API 消耗 · 并行跑 agent 不受 quota 限

交付物 画布内 + 可导 Figma HTML / MP4 / GIF / 可编辑 PPTX / PDF

操作方式 GUI（点、拖、改） 对话（说话、等 agent 做完）

复杂动画 有限 Stage + Sprite 时间轴 · 60fps 导出

跨 agent 专属 Claude.ai 任意 skill 兼容 agent

Claude Design 是 **更好的图形工具** ，huashu-design 是 **让图形工具这层消失** 。两条路，不同受众。

#### Limitations

- **不支持图层级可编辑的 PPTX 到 Figma** 。产出 HTML，可截图、录屏、导图，但不能拖进 Keynote 改文字位置。
- **Framer Motion 级别的复杂动画不行** 。3D、物理模拟、粒子系统超出 skill 边界。
- **完全空白的品牌从零设计质量会掉到 60–65 分** 。凭空画 hi-fi 本来就是 last resort。

这是一个 80 分的 skill，不是 100 分的产品。对不愿意打开图形界面的人，80 分的 skill 比 100 分的产品好用。

#### Huashu Design 是什么

Huashu Design 是一个装在 AI Agent 里的 “设计技能包”。  
你只要用一句自然语言描述需求，它就能在几分钟内产出可交付的设计内容，比如高保真原型、演讲 PPT、动画视频、信息图等。

它的核心卖点不是 “帮你画个草图”，而是直接给你能用、能演示、能导出的成品，而且不依赖 Figma、AE 这类传统图形工具。

##### 它解决了什么问题

传统设计工具的问题是：强大，但重；专业，但流程长。  
Huashu Design 反过来，把 “设计操作” 隐藏在 Agent 后面，让用户只需要 “说需求”。

对产品经理、独立开发者、内容创作者来说，这意味着：
- 不必切 GUI 工具
- 不必自己搭视觉稿
- 可以更快把想法变成原型、演示稿或宣传内容

一句话：它想把 “设计工具” 变成 “设计结果”。

##### 它能做什么

这个 skill 覆盖了几类高频设计场景：

###### 1. 交互原型
可生成可点击的 App / Web 原型，还原手机外壳、页面切换和交互流程，适合快速验证产品方案。

###### 2. 演讲幻灯片
可输出 HTML 演讲稿和可编辑 PPTX，重点是导出的 PPT 不是整页截图，而是真文本框，后续修改更方便。

###### 3. 动画与视频
可把内容做成时间轴动画，并导出 MP4、GIF，甚至支持补帧和加背景音乐，适合产品发布、宣传短片等场景。

###### 4. 信息图与可视化
支持高质量排版和多格式导出，适合做报告配图、海报、长图和可视化内容。

###### 5. 设计评审
内置一套 5 维评审机制，能从一致性、层级、细节、功能性、创新性等角度给出修改建议。

##### 它为什么不容易做出 “AI 味”

Huashu Design 的一个重要特点，是它不满足于 “生成一个还行的页面”，而是尽量避免常见的 AI 审美套路。

它主要靠三件事做到这一点：

###### 1. 内置设计哲学库
预设了 5 大流派、20 种设计哲学。  
当用户需求模糊时，它不会直接硬做一个平均答案，而是先给出 3 个差异化方向供选择。

###### 2. 品牌资产协议
如果需求涉及具体品牌，它会强制去询问、搜索、下载、提取品牌色，再写成统一规范，而不是凭记忆 “猜品牌风格”。

###### 3. 先展示再迭代
它强调先写 assumptions、placeholders、reasoning，尽早给用户看半成品，避免方向错了却做得很深。

本质上，它把 “先对方向，再做精细化” 这套设计协作逻辑，固化进了 Agent 工作流。

##### 它的核心机制是什么

这个项目最有价值的，不只是素材和脚本，而是一套可复用的方法论：

###### 1. HTML First
无论是原型、幻灯片还是动画，底层都优先用 HTML 来做。  
这样带来两个好处：一是可直接浏览、演示、录制；二是后续导出更灵活。

###### 2. 参数化设计
颜色、字体、信息密度、布局等都可以调参，不是一次性死稿，更适合快速出多个版本。

###### 3. 自动化导出链路
项目内置了 HTML 转 MP4、GIF、PDF、PPTX 的脚本，把 “设计完成” 直接延伸到 “交付完成”。

##### 它和 Claude Design 的关系

作者明确承认，它受到 Claude Design 启发，尤其借鉴了 “品牌资产协议” 这类方法。  
但两者定位不同：

- Claude Design 更像一个完整的图形工具
- Huashu Design 更像一个嵌入 Agent 的设计执行能力

前者适合在浏览器里直接设计；后者适合不想打开图形界面、只想通过对话完成工作的用户。

可以理解为：  
Claude Design 是 “更强的工具”，Huashu Design 是 “更轻的工作方式”。

##### 它的局限性

这个项目并不声称自己无所不能，反而很诚实地划定了边界：

- 不支持像 Figma 那样的深度图层级编辑
- 不适合复杂 3D、粒子、物理模拟类动画
- 如果完全没有品牌和设计上下文，最终质量会明显下降
- 它更像 “80 分但非常高效” 的方案，而不是 “100 分的全能设计平台”

这也说明它的真实定位：  
不是替代所有设计工具，而是优先服务 “想快速把东西做出来的人”。

##### 适合谁用

最适合这几类人：

- 产品经理：快速做原型、汇报材料、方案演示
- 独立开发者：低成本补齐设计表达能力
- 内容创作者：高效做可传播的视觉内容
- AI 工作流用户：希望把设计直接接入 Agent 协作链路

它尤其适合 “表达需求强，但不想打开复杂设计软件” 的人。

##### 商业价值怎么理解

从商业角度看，Huashu Design 的价值不只是一个开源仓库，而是一个信号：

###### 1. 设计正在被 Agent 化
未来很多设计工作不再是 “人操作工具”，而是 “人给目标，Agent 组织产出”。

###### 2. 竞争点从工具能力转向工作流能力
真正的壁垒，不只是会不会生成页面，而是能不能稳定地产出接近专业团队水平的结果。

###### 3. 开源正在成为 AI 产品能力外溢的新路径
它不是简单复刻某个产品，而是把产品能力拆解、抽象、重组，变成可复用的 skill，这很像 AI 时代的新型开源创新。

##### 一句话结论

Huashu Design 本质上是在做一件事：  
把 “高保真设计产出” 从专业工具里解放出来，变成 Agent 可直接执行的能力。

它不是最强的设计平台，但很可能是最符合 AI Native 工作方式的一类产品雏形。  
对懂产品、懂效率的人来说，它的意义不只是 “能做设计”，而是 “让设计成为一句话就能调度的生产力”。
