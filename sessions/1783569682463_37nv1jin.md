## 分析要点

- **核心高价值点**：将智能体操作划分为只读探索、计划确认、逐项审批和自动执行模式，使高权限任务具备渐进授权与可审计性。

**知识要点**

- 探索模式先读取环境并生成计划，确认后再切换执行模式，可降低智能体直接修改文件或外部系统的风险。
- 来源层可统一封装MCP、API和本地目录，并同时生成配置、使用指南与权限规则。
- “接受并压缩”会总结已有上下文并重新注入计划，有助于长任务在压缩上下文后保持执行目标。

**行动项**

- 在非关键目录中测试探索、询问编辑和执行三种权限模式，核对命令记录及中断能力。
- 以只读权限连接一个Linear或GitHub来源，检查自动生成的配置、权限文件和工具调用内容。
- 设计一次跨GitHub、文档和日历的真实任务，评估其减少上下文复制和工具切换的实际效果。

## 结构化（1）

### 2026-07-09 04:01:22

Craft Agents 0.3.1 是一个开源、跨平台的桌面 AI Agent 应用，核心目标是把 GitHub、Linear、日历、Slack、文档、本地文件等工具连接到同一个对话里，减少来回切换和复制上下文。它强调 “可控的自动化”：既能让 AI 执行任务，也能通过权限模式、计划阶段和本地加密存储来降低风险。

##### 1. 产品背景与定位

- Craft Agents 由 Craft 团队内部开发，最初用于提升公司内部工作流，开发周期约**1.5 个月**。
- 后来团队认为体验不错，因此将其**开源**，方便更多人使用和二次开发。
- 支持多平台：
  - macOS Apple Silicon
  - macOS Intel
  - Windows
  - Linux
- 相关地址：
  - 下载：`https://agents.craft.do`
  - 源码：`https://github.com/lukilabs/craft-agents-oss`
- 项目采用开源方式发布，文中提到为**Apache 2.0**，用户可以查看代码、修改或构建自己的版本。

##### 2. 连接 AI 提供商

- 首次使用时，需要选择 AI 连接方式。
- 官方推荐使用**Claude Pro / Claude Max**订阅，以获得较好体验。
- 也支持多种第三方或自定义方式：
  - Anthropic API Key
  - OpenRouter
  - Vercel AI Gateway
  - Ollama
  - 自定义第三方提供商
- 示例中，作者使用 Claude 订阅，通过浏览器完成认证，再把授权码粘贴回应用即可开始聊天。
- 底层使用了**Claude Agent SDK**，体验类似 Claude Code。

##### 3. 界面结构与工作区

- 应用左侧栏提供常用组织功能：
  - 所有聊天
  - Flag 标记
  - Status 状态
  - Label 标签
  - Sources 数据源
  - Skills 技能
- 设置里可以自定义：
  - 主题样式
  - 发送消息方式，例如 Enter 或 Command + Enter
  - 模型选择
  - 权限模式
- Craft Agents 鼓励用户按**Workspace 工作区**管理任务：
  - 不同工作区可以配置不同模型
  - 可以设置不同权限策略
  - 适合把个人任务、代码任务、项目管理任务分开管理

##### 4. 权限模式、Explore Mode 与计划阶段

这一部分是视频重点：Craft Agents 不会默认让 AI 直接操作你的电脑，而是通过权限模式逐步放权。

###### Explore Mode：只读探索模式

- 在 Explore Mode 下，AI 可以查看信息，但不能真正执行修改命令。
- 示例：作者让 AI 整理 Downloads 文件夹，并找出可以删除的文件。
- AI 扫描后发现：
  - 有一批高优先级可删除文件
  - 预计可释放**23GB**空间
  - 一些安装包可以删除
  - 一些敏感文件应保留
- 当作者要求 AI 删除文件时，命令被阻止，因为当前仍处于只读探索模式。

###### Planning：执行前先出计划

- 当 AI 无法直接操作时，它会先生成计划。
- 用户可以查看计划，再决定是否批准。
- 有两个接受方式：
  - **Accept**：接受计划并继续保留当前上下文
  - **Accept and Compact**：接受计划，同时压缩上下文，把前面的讨论总结后继续执行
- 接受后，应用会切换到执行模式，AI 才能真正删除、移动、创建文件。

###### Ask-to-edit：每步都要确认

- 如果用户不完全信任 AI，可以使用 Ask-to-edit 模式。
- AI 每次执行命令前都会弹出确认，例如：
  - 创建文件夹
  - 移动文件
  - 删除文件
- 用户可以选择：
  - Allow：允许这一次
  - Always allow：以后类似操作都允许
  - Deny：拒绝
- 如果确认次数太多，用户也可以切换到 Execute 模式，让 AI 自动执行。

##### 5. Sources：连接外部工具和本地资源

- Craft Agents 的核心功能之一是**Sources 数据源连接**。
- Sources 可以是：
  - API
  - MCP Server
  - 本地文件夹
- 用户不需要理解 API 或 MCP 的技术细节，可以直接用自然语言告诉 Agent：
  - “连接 Linear”
  - “连接 GitHub API”
  - “添加某个本地文件夹”
- 应用会自动查文档、生成配置，并引导用户完成授权。

##### 6. 连接 Linear：MCP 示例

视频中用 Linear 展示了如何通过 MCP 连接项目管理工具。

- 用户在 Sources 里输入：`connect to linear`
- AI 会：
  - 查找 Craft Agents 的文档
  - 搜索 Linear 官方 MCP Server 的连接方式
  - 询问用户使用目的、团队、项目范围等
- 示例中，作者选择给 Linear **full access**。
- AI 自动完成配置：
  - 修改`config.json`
  - 添加**18 行配置**
  - 生成约**100 行使用指南**
  - 生成 Linear MCP 的自定义权限配置
- 应用提供清晰的变更视图：
  - 显示新增多少行
  - 删除多少行
  - 修改了哪些内容
- 配置完成后，通过浏览器 OAuth 登录 Linear。
- 连接成功后，可以直接问：
  - 当前有哪些进行中的 ticket？
  - 某个项目有哪些 issue？
- 用户还能展开查看 AI 调用 Linear 工具时发送了什么请求，方便审计。

##### 7. 连接 GitHub：API 示例

另一个示例是连接 GitHub API。

- 用户输入：`connect to GitHub API`
- 作者希望 AI 能：
  - 列出 GitHub issues
  - 检查 Pull Requests
  - 帮助整理相关任务
- 连接时可以选择不同模型，例如：
  - Sonnet 4.5
  - Opus
- 也可以设置**max thinking**，用于控制推理强度和 token 使用。
- 因为当时处于 Explore Mode，AI 没有直接写入配置，而是先给出计划：
  - 创建 source 文件夹
  - 创建配置文件
  - 生成使用指南
  - 设置权限
  - 运行测试
  - 请求用户提供 access token
- 用户确认计划后，再提供 GitHub API Key，继续完成连接。

##### 8. 新版本 0.3.1 的重点功能

Craft Agents 0.3.1 增加了几个实用功能：

###### Session Search

- 支持用**Cmd + F**搜索整个历史会话。
- 可以快速找到过去讨论过的任务、配置、错误或决策。

###### Mini Agents

- 提供轻量级内联 Agent。
- 适合快速做配置调整，不必开启完整复杂流程。

###### 更好的 Mermaid 图表

- Mermaid 图表可以原生渲染。
- 支持更好的缩放和拖动画布体验。
- 相关项目：`https://github.com/lukilabs/beautiful-mermaid`

##### 9. 组织、技能与多源工作流

- 应用支持通过 Status、Label、Flag 等方式管理不同会话和任务。
- Skills 功能用于封装可复用能力，用户可以查看文档学习如何创建。
- 视频后半部分还展示了多源工作流：
  - 在一个对话里同时使用 GitHub、Linear、本地文件等来源
  - AI 可以跨工具理解上下文并执行任务
- 这也是 Craft Agents 的主要价值：把分散在不同工具里的信息整合进同一个 Agent 工作流。

##### 10. 总结

- Craft Agents 适合经常在 GitHub、文档、项目管理工具、本地文件之间切换的人。
- 它的优势不是单纯聊天，而是让 AI 能 “连接工具、理解上下文、按权限执行任务”。
- 关键亮点包括：
  - 跨平台桌面应用
  - 开源
  - 支持 API、MCP、本地文件夹

## 总结（1）

### 2026-07-09 04:11:36

Craft Agents 0.3.1 是一款开源桌面端 AI Agent 工作台，目标是把 GitHub、日历、Slack、文档、本地文件等工具接到同一个对话里，减少在不同软件之间复制粘贴上下文。它强调 “可控地自动化”：既能让 AI 执行任务，也能通过权限、计划和审计界面让用户知道 AI 在做什么。

##### 1. 项目背景与定位

- Craft Agents 是 Craft 团队在约**1 个半月**内为提升内部工作流开发的工具，后来选择开源分享。
- 它是一个跨平台桌面应用，支持：
  - macOS Apple Silicon
  - macOS Intel
  - Windows
  - Linux
- 下载地址：`https://agents.craft.do`
- 源码地址：`https://github.com/lukilabs/craft-agents-oss`
- 项目开源协议为**Apache 2.0**，用户可以查看源码，技术用户也能自行构建版本。

##### 2. 核心价值：一个对话连接所有工作上下文

- 作者认为 Craft Agents 最有用的地方，是能把多个工具和数据源连接到同一个 AI 对话中。
- 支持连接的内容包括：
  - GitHub
  - Calendar
  - Slack
  - 文档
  - 本地文件
  - API
  - MCP Server
- 这样用户不需要在 GitHub、文档、日历等工具之间反复复制粘贴信息，AI 可以直接跨来源理解和处理任务。

##### 3. 连接 AI 提供商

- 初次使用时，用户需要选择 AI 连接方式。
- 官方推荐使用**Claude Pro / Claude Max**订阅，以获得较好体验。
- 同时也支持多种第三方或自定义方式：
  - Anthropic API Key
  - OpenRouter
  - Vercel AI Gateway
  - Ollama
  - 自定义第三方服务
- 应用底层使用**Claude Agent SDK**，体验上类似 Claude Code。

##### 4. 界面结构与工作区设置

- 左侧栏提供主要组织功能，包括：
  - All Chats：所有对话
  - Flag：标记
  - Statuses：状态
  - Labels：标签
  - Sources：数据源
  - Skills：技能
  - Settings：设置
- 设置里可以自定义：
  - 主题
  - 发送消息方式，例如 Enter 或 Command + Enter
  - 工作区
  - 使用的模型
  - 权限模式
- 作者强调，Craft Agents 建议用户以**Workspace 工作区**为单位使用，并在工作区中配置模型和权限。

##### 5. 权限模式：让 AI 自动化但不失控

Craft Agents 的权限系统是重点功能，主要用来控制 AI 能做什么、什么时候需要询问用户。

###### 5.1 Explore Mode：只探索，不执行

- 在 Explore Mode 下，AI 可以查看信息、分析情况，但不能直接修改文件或执行危险命令。
- 示例：作者让 AI 整理 Downloads 文件夹，并找出可以删除的文件。
- AI 扫描后发现：
  - 有高优先级可删除内容
  - 预计可节省**23GB**空间
  - 有一些安装包可以删除
  - 有敏感文件应保留
- 当作者要求 AI 删除文件时，因为仍在 Explore Mode，命令被阻止，AI 只能先生成计划。

###### 5.2 Planning Phase：先计划，再执行

- 作者强调，和 AI 协作时 “计划阶段” 非常重要。
- 在无法执行操作时，AI 会生成一个计划，说明接下来会做什么。
- 用户可以选择：
  - **Accept**：接受计划并继续执行，保留当前上下文
  - **Accept and Compact**：接受计划并压缩上下文，把之前内容总结后再继续，适合长对话
- 接受计划后，应用会自动切换到可执行模式。

###### 5.3 Execute Mode：允许 AI 自动执行

- 在 Execute Mode 下，AI 可以执行命令，例如：
  - 删除文件
  - 移动文件
  - 创建文件夹
  - 整理目录
- 执行过程中，界面会显示 AI 的步骤、命令和输出。
- 用户可以随时中止任务，例如告诉 AI “不要继续”。

###### 5.4 Ask to Edit：每一步改动都先询问

- 如果用户不完全信任 AI，可以使用 Ask to Edit 模式。
- 示例：作者让 AI 在 Downloads 下创建`archive`文件夹，并移动部分文件进去。
- AI 会展示即将执行的命令，例如创建文件夹、移动文件。
- 用户可以选择：
  - Allow：允许一次
  - Always Allow：总是允许类似操作
  - Deny：拒绝
- 当确认过多、操作变得繁琐时，用户也可以切回 Execute Mode。

##### 6. Sources：连接外部工具和数据源

- Craft Agents 把连接能力集中在**Sources**菜单中。
- Sources 支持：
  - API
  - MCP Server
  - 本地文件夹
- 如果用户不理解 API 或 MCP，也可以直接用自然语言告诉 AI 要连接什么，AI 会自动查文档并引导配置。

##### 7. 案例一：连接 Linear MCP

- 作者演示通过自然语言输入：`connect to linear`
- Linear 是团队用于管理 issue 和 ticket 的工具。
- AI 会：
  - 查询 Craft Agents 文档
  - 搜索 Linear 官方 MCP Server 的连接方式
  - 询问用户连接用途、团队、项目等信息
- 作者选择 “full access” 后，AI 自动执行配置流程。
- 过程中 AI 修改了配置文件：
  - 向`config.json`添加了**18 行**
  - 生成了约**100 行**使用指南
  - 生成了 Linear MCP Server 的自定义权限配置
- 随后应用弹出浏览器，用户通过 OAuth 登录并授权 Linear。
- 配置完成后，用户可以在当前聊天中启用 Linear 数据源，并询问 Linear 中的任务状态。
- AI 会调用 Linear 工具，返回例如 “哪些 ticket 正在进行中” 等结果。
- 用户还能展开详情，查看 AI 实际发送了什么请求，便于审计。

##### 8. 案例二：连接 GitHub API

- 作者还演示连接 GitHub API。
- 在配置前，可以切换模型，例如：
  - Sonnet 4.5
  - Opus
- 还可以设置最大 thinking token，用于控制模型思考量和 token 使用。
- 作者输入：`connect to GitHub API`
- AI 会询问用途，例如：
  - 列出 issues
  - 检查 pull requests
  - 组织 GitHub 工作内容
- 因为作者当时处于 Explore Mode，AI 不能直接创建配置，于是先生成计划。
- 计划包括：
  - 创建 source 文件夹
  - 创建配置文件
  - 创建使用指南
  - 设置权限
  - 运行测试
  - 请求用户提供 access token
- 用户接受计划后，AI 继续配置，并要求输入 GitHub API Key。
