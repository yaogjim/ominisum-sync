## 正文

**Rachel**

ClaudeCode意外流出的代码可以说是当前 AI Agent 工程领域最好的一本架构教科书。

基于这份还原的源码，我深度硬核拆解了Claude Code 的记忆架构。

1\. 核心理念：受限式、结构化的人类式记忆  
过去很多Agent的记忆系统是大而全，不管什么聊天记录、代码片段都往向量数据库里塞，最后导致相似度检索混乱、上下文爆炸。 而从源码可以看出，Claude Code 采取的是一种受限式的、结构化且具备自愈能力的记忆机制。它完全模拟了人类优秀高级程序员的工作习惯——随手记笔记、列提纲、定期做总结。

2\. 双轨记忆系统：CLAUDE.md 与 自动记忆 (Auto-Memory)  
系统在每次对话启动时，会加载两个互补的记忆模块，且绝不盲目吃Token：  
•静态/显式记忆（CLAUDE.md）： 这部分由用户定义，类似于传统系统提示词的延伸。源码显示，启动时系统会自动读取主分支、当前分支、最近提交记录，再加上 CLAUDE.md（里面通常包含构建命令、代码规范、项目架构），构建出一个动态的项目全景。  
•动态/自动记忆（Auto-Memory）： 这是最亮眼的部分。Claude会在工作时“自己给自己写工作日志”。它通过一个 MEMORY.md 文件作为“记忆目录索引”，并且代码中硬性规定将其控制在极其精简的 200行以内。它不会把所有细节都塞进这个主文件，而是将详细的Debug记录、架构分析抽离到独立的主题文件中（如 debugging.md 或 patterns.md）。需要用到时，再通过专属的文件工具（File Tools）按需读取。

3\. Memory Type System：四分类与绝对不记清单  
源码中定义了一个严格的记忆类型系统，将记忆精准分为四类：  
1User（用户画像）： 用户的偏好和工作流习惯。  
2Feedback（纠正反馈）： 用户过去指出的错误和纠正方向，防止在同一个坑里跌倒。  
3Project（项目状态）： 任务规格、当前进度、错误与修正日志。  
4Reference（引用指针）： 指向外部文档或大文件的索引。

代码中硬编码了一个\*\*「绝对不记清单」\*\*！ Claude Code 明确限制写入以下内容：具体的代码实现细节、Git提交历史、可以直接用 grep 或 git log 搜到的具体报错日志。 为什么？ 因为工程团队认为：“能通过现成工具低成本现查的东西，就不该占用宝贵的长效记忆空间”。这极大地减少了上下文污染和记忆冗余。

4\. 极致的上下文压缩术 (Context Compression)  
如何防止Agent工作时间一长就“失忆”或突破Token上限？源码给出了教科书级别的解法：  
•结果截断与落盘： 当调用命令行或搜索工具返回巨大的结果时，Claude Code 不会将其全部塞入上下文。源码逻辑是：将过大的输出写到本地磁盘，大模型上下文中只保留预览摘要和文件引用指针。  
•滚动摘要机制： 当对话轮次接近清除阈值时，系统会触发警告通知。在旧的对话内容被上下文窗口剔除前，Claude 会主动将当前的关键进展浓缩，并写入持久化的记忆文件（如 refactoring\_progress.xml）。

5\. AutoDream 系统：令人惊艳的后台反思与梦境  
内置的 AutoDream (梦境机制) 会在用户闲置或会话结束时悄悄激活。它会指挥 Claude Code 运行在一种后台Agent模式下，执行对记忆文件的“反思性处理”：  
•扫描与提取： 翻阅当天的会话日志，寻找值得长期保存的通用新知识。  
•去重与整合： 将新知识与旧记忆进行合并，消除矛盾和重复片段。  
•遗忘机制： 主动删除或归档过时的记忆（例如已经废弃的旧架构讨论）。  
这就相当于 AI 在你下班后，自己默默在后台整理当天的“工作日记”，并将其提炼为高浓度的知识库，供第二天的会话随时调用。

总结：对 AI 开发者们的启示  
1不要盲信向量检索：结构化的 Markdown/XML 笔记加按需文件读取，往往比纯 Vector DB 更有逻辑、更不容易产生幻觉。  
2让 AI 学会“记目录”而不是“背全文”：用层级索引来管理信息。  
3增加“后台反思与GC(垃圾回收)”机制：好记忆是靠整理和定期清理出来的，不是靠无限堆砌出来的。

## 通俗精炼（1）

#### Claude Code 记忆架构总结

##### 一句话结论
这篇文章的核心观点是：**Claude Code 的强大，不在于“记得更多”，而在于“只记真正重要的内容，并且把记忆整理得非常有结构”**。这套设计很像优秀程序员的工作方式：记笔记、分主题归档、定期复盘、及时清理。

##### 核心理念：少而精的结构化记忆
作者认为，很多 AI Agent 的问题在于把所有信息都丢进记忆系统，导致检索混乱、上下文臃肿。  
而 Claude Code 采用的是一种**受限式、结构化、可自我整理的记忆机制**：不是一股脑存信息，而是有选择地记录、归类和压缩。

##### 双轨记忆：用户定义 + 系统自动整理
Claude Code 的记忆主要分成两部分：

###### 1. 显式记忆：`CLAUDE.md`
这是用户或项目主动提供的内容，通常包括项目结构、构建命令、编码规范等。  
它相当于 AI 的“项目说明书”，帮助模型快速理解当前工作环境。

###### 2. 自动记忆：`MEMORY.md`
这是系统自动维护的“工作日志索引”。  
它本身保持很短，只记录关键事项；更详细的调试记录、架构分析等，则拆到单独文件里，需要时再读取。  
重点不是“全记住”，而是**记住信息放在哪里**。

##### 记忆分类：只存高价值信息
源码里把记忆分成四类：

- **User**：用户偏好与工作习惯
- **Feedback**：用户纠正过的问题，避免重复犯错
- **Project**：项目进展、任务状态、问题修复过程
- **Reference**：外部文档或大文件的索引入口

同时，它还明确规定了**不该记的内容**，比如具体代码实现、Git 历史、可随时搜索到的报错信息。  
背后的原则是：**能低成本现查的，就不要占用长期记忆。**

##### 上下文压缩：避免“越聊越失忆”
为了防止会话过长导致上下文爆炸，Claude Code 做了两件事：

###### 1. 大结果不直接塞进上下文
命令行或搜索结果太长时，会写到本地文件里，只在上下文保留摘要和引用。  
这样既保留信息，又不浪费 Token。

###### 2. 对话快超限时自动做摘要
当旧内容即将被清出上下文窗口时，系统会先把关键进展提炼出来，写进持久化记忆文件。  
本质上是在做“滚动总结”，防止工作中途断片。

##### AutoDream：后台复盘与整理
文章认为最亮眼的设计，是 Claude Code 的 **AutoDream** 机制。  
它会在空闲或会话结束后，在后台对当天信息做进一步处理，包括：

- 提取值得长期保留的新知识
- 合并重复内容，消除冲突
- 删除或归档过时记忆

这相当于 AI 会“下班后自己整理笔记”，把零散对话沉淀成更高质量的知识库。

##### 对 AI Agent 设计的启示
这篇文章给出的启发主要有三点：

1. **不要迷信向量数据库**：结构化笔记 + 按需读取，很多时候比无差别检索更可靠。  
2. **记目录比记全文更重要**：AI 更应该知道“信息在哪”，而不是“把所有内容背下来”。  
3. **记忆系统必须能整理和遗忘**：高质量记忆来自持续压缩、归档和清理，而不是无限堆积。

##### 总结
作者想表达的是：**Claude Code 的先进之处，不是单纯提升模型能力，而是把“记忆管理”做成了一套工程化系统。**  
它更像一个会做笔记、会复盘、会归档、会遗忘的高级程序员，而不是一个机械地存储信息的聊天机器人。

## 结构化（1）

### 2026-04-03 06:51:12

文章主旨是：Claude Code 的“泄露源码”展示了一套非常成熟的 AI Agent 记忆架构，其核心不是“把所有信息都存起来”，而是像优秀程序员一样，进行受限、结构化、可整理的记忆管理。作者认为，这套设计对当前 AI Agent 工程有很强的借鉴意义，尤其体现在记忆分类、上下文压缩和后台反思机制上。

##### 1. 核心理念：像人类程序员一样管理记忆
- 作者认为，很多 Agent 过去的问题是“什么都记”，把聊天记录、代码片段等一股脑塞进向量数据库，结果造成检索混乱、上下文膨胀。
- Claude Code 的做法相反：采用“受限式、结构化、可自愈”的记忆机制。
- 这种方式更像高级程序员的工作习惯：随手记笔记、列提纲、定期总结，而不是死记所有细节。

##### 2. 双轨记忆系统：显式记忆 + 自动记忆
###### 2.1 `CLAUDE.md`：静态/显式记忆
- 这是用户定义的长期信息，类似系统提示词的扩展。
- 系统启动时会综合读取：
  - 主分支信息
  - 当前分支信息
  - 最近提交记录
  - `CLAUDE.md`
- 这些内容共同组成项目的“动态全景图”。
- `CLAUDE.md` 里通常会放构建命令、代码规范、项目架构等高价值信息。

###### 2.2 Auto-Memory：动态/自动记忆
- Claude Code 会在工作过程中“给自己写工作日志”。
- 它使用 `MEMORY.md` 作为总索引文件，而且源码中明确要求将其控制在 **200 行以内**，非常克制。
- 详细内容不会都塞进主记忆文件，而是拆到不同主题文件中，比如：
  - `debugging.md`
  - `patterns.md`
- 需要时再通过文件工具按需读取，而不是每次都把全部内容放进上下文。
- 这相当于把记忆分成“目录 + 专题笔记”，提高可读性，也节省 Token。

##### 3. 记忆类型系统：只记该记的内容
- 源码里把记忆严格分为 4 类：
  1. `User`：用户偏好、工作习惯
  2. `Feedback`：用户过去纠正过的问题，避免重复犯错
  3. `Project`：任务需求、当前进度、错误和修正记录
  4. `Reference`：外部文档或大文件的索引指针
- 这说明 Claude Code 不是泛化存储，而是带着明确目的进行记忆。

###### 3.1 “绝对不记清单”
- 系统还硬编码了一份“不该记”的内容，包括：
  - 具体代码实现细节
  - Git 提交历史
  - 可以直接用 `grep` 或 `git log` 查到的报错日志
- 背后的原则很清楚：**凡是能低成本现查的信息，就不值得占用长期记忆空间。**
- 这样做的好处是减少记忆冗余，降低上下文污染。

##### 4. 上下文压缩：防止对话越长越失控
###### 4.1 大结果不直接塞进上下文
- 当命令行或搜索返回大量结果时，Claude Code 不会把全部输出放进上下文。
- 它会把过大的内容写入本地磁盘，上下文里只保留：
  - 预览摘要
  - 文件引用指针
- 例如，一次很长的搜索结果，不会完整喂给模型，只保留“摘要 + 路径”，需要时再读取详细内容。

###### 4.2 滚动摘要机制
- 当对话快接近上下文清除阈值时，系统会先发出警告。
- 在旧对话内容被移出上下文前，Claude 会主动提炼关键进展，写入持久化记忆文件，比如 `refactoring_progress.xml`。
- 这样即使长会话被截断，重要进展也不会丢失。

##### 5. AutoDream：后台反思与“梦境机制”
- 作者认为最惊艳的部分，是内置的 `AutoDream` 机制。
- 当用户闲置或会话结束后，它会在后台进入一种 Agent 模式，对记忆进行“反思性处理”。

###### 5.1 它会做三件事
- **扫描与提取**：回看当天会话，找出值得长期保存的新知识。
- **去重与整合**：把新旧记忆合并，消除重复和冲突。
- **遗忘机制**：删除或归档已经过时的信息，比如废弃的旧架构讨论。

###### 5.2 可以怎么理解
- 这就像程序员下班后，系统自己整理当天工作笔记，提炼出真正有价值的经验，供第二天继续使用。
- 重点不是“记得更多”，而是“记得更干净、更有组织”。

##### 6. 作者给 AI 开发者的启示
- **不要迷信向量检索**：结构化的 Markdown/XML 笔记，加上按需读取文件，有时比纯向量数据库更稳定，也更不容易引发幻觉。
- **让 AI 记目录，而不是背全文**：先建立层级索引，再在需要时展开细节。
- **加入后台反思与垃圾回收机制**：好的记忆系统不是靠无限堆积，而是靠持续整理和清理。

##### 7. 关键信息回看
- `MEMORY.md` 被限制在 **200 行以内**
- 记忆被严格分成 **4 类**：`User`、`Feedback`、`Project`、`Reference`
- 详细信息拆分到专题文件，如 `debugging.md`、`patterns.md`
- 接近上下文上限时，会将关键进展写入持久化文件，如 `refactoring_progress.xml`

##### 总结
这篇文章最核心的观点是：优秀的 AI Agent 记忆系统，不是“大而全”的存储系统，而是“有限、分层、可整理、会遗忘”的知识管理系统。Claude Code 展示出的价值，不在于记住了多少，而在于它知道“该记什么、不该记什么，以及什么时候整理记忆”。
