- **核心高价值点**：将持久化终端会话、代理语义状态与可编程控制接口结合，使代理任务能够被远程查看、等待、读取和继续编排。

- **不足**：产品功能与对比结论主要来自官方陈述，缺少性能数据、完整案例和可核验的长期使用结果。

**知识要点**

- Herdr试图填补传统tmux缺少代理状态、桌面代理管理器难以跨机器运行的空缺。
- 远程使用包括在服务器上直接运行后通过SSH进入，以及用本地客户端附加远程会话两种模式。
- CLI和JSON Socket API可操作工作区、标签页、窗格、输出及状态等待，为自动化Agent编排提供控制面。

**行动项**

## 解读（1）

### 2026-07-14 10:06:27

#### Herdr：一座运行在终端里的 AI Agent 调度台

##### 一句话总结

**Herdr = tmux 的持久会话能力 + AI Agent 状态感知 + 可编程调度接口。**

##### 深度总结

Herdr 不是终端模拟器，也不是桌面或网页式 Agent 管理器，而是一个运行在现有终端中的**Agent-aware multiplexer（懂 Agent 的终端复用器）**。

其核心能力有四项：

1. **真实终端窗格**：直接运行 Shell、Agent、测试与日志，不重做聊天界面。
2. **会话持久化**：终端关闭或 SSH 断开后，任务仍继续运行。
3. **Agent 状态感知**：统一显示`工作中 / 等待输入 / 完成 / 空闲`。
4. **自动化控制**：通过 CLI 和 JSON Socket API 创建窗格、读取输出、等待状态，让人、脚本甚至 Agent 自己编排工作流。

它支持：

- 本机运行；
- SSH 到服务器后运行；
- 本地客户端连接远端会话，并保留快捷键、剪贴板与图片粘贴；
- 手机和平板远程查看、切换任务；
- 接入 Claude Code、Codex、Kimi 等终端 Agent；普通 CLI Agent 也能直接运行，专门集成则提供更丰富的状态与恢复能力。

##### 通俗解读

可以把 Herdr 想成一个**远程施工现场的总控室**：

- 每个窗格是一张工位；
- 每个 Agent 是一名工人；
- Herdr 告诉你谁在干活、谁卡住、谁已完成；
- 即使你关掉电脑，工人仍在服务器上继续工作；
- 你可换电脑或用手机重新接管；
- Agent 还能通过 API 自己开工位、查结果、安排下一步。

它真正解决的不是 “如何和一个 Agent 聊天”，而是：

> **如何同时、持续、跨设备地管理多个 Agent 与真实开发进程。**

##### 辩证思考

###### 价值

- **定位准确**：填补了 tmux “不懂 Agent” 和桌面 Agent 工具 “不擅长远程持久运行” 之间的空白。
- **开放且可组合**：真实 PTY、CLI、API 比封闭 GUI 更适合自动化和工程化。
- **顺应趋势**：当开发从 “亲自操作” 转向 “监督多个 Agent”，状态总览与任务编排会越来越重要。

###### 局限

- **门槛仍在**：终端、SSH、会话和窗格概念对普通用户并不友好。
- **集成深度不一**：任何 Agent 都能运行，不等于都能准确识别状态或无缝恢复。
- **手机可用不等于好用**：适合查看、切换和应急处理，不适合复杂开发。
- **安全面扩大**：能控制进程、读取输出的 API，也需要严格管理权限与远程访问。
- **价值取决于规模**：只用一个本地 Agent 时，它可能比普通终端更复杂；多 Agent、远程服务器、长任务场景下优势才明显。

##### 结论

Herdr 的创新不在于 “重新发明终端”，而在于把终端升级为**面向 AI Agent 的持久化控制平面**。

**它不是人人必需，但很可能适合重度终端用户、远程开发者，以及需要并行调度多个编码 Agent 的团队。**

#### Herdr：用一个终端管理整支 AI Agent “团队”

Herdr 是一款面向 AI 编程 Agent 的终端多路复用器：它保留了 tmux/Zellij 的持久会话与远程连接能力，同时增加 Agent 状态识别、直接接入和自动编排功能。用户可在服务器、Mac Mini 或沙箱虚拟机上运行任务，再从电脑、手机等任意终端连接管理。

##### 1. 第三方开发者体验

官网提供了 3 个独立实操视频，帮助用户了解 Herdr 的使用方式：

- **Jilles（6 分 37 秒）**：快速介绍安装、工作区、Agent 状态、会话持久化及 Agent Skill 工作流。
- **DevOps Toolbox（16 分 40 秒）**：深入展示鼠标操作窗格、远程使用、Agent 支持和 CLI。
- **Better Stack（7 分 10 秒）**：重点比较 Herdr 与 tmux，介绍 Agent 感知、远程接入及纯终端运行模式。

##### 2. Agent 在工作所在的机器运行

Herdr 不要求 Agent 与管理界面位于同一台电脑。Agent 可以运行在：

- 远程服务器
- Mac Mini
- 沙箱虚拟机
- 任何能够通过 SSH 访问的设备

用户则可从任意终端连接，包括手机和平板。相比只能依附于本机 GUI 的桌面 Agent 管理器，Herdr 更适合远程开发和长期任务。

##### 3. 三种主要使用方式

###### 本机运行

直接在本机启动 Herdr，可拆分窗格、创建标签页，并让 Agent 持续运行。即使关闭终端，任务和会话也不会随之消失。

```bash
herdr
```

###### 通过 SSH 在远程主机运行

像使用 tmux 一样，先登录服务器，再启动 Herdr：

```bash
ssh you@server
herdr
```

断开 SSH 后会话仍然保留，之后可以重新连接，适合用手机临时查看或处理任务。

###### 以轻客户端连接远程会话

```bash
herdr --remote workbox
```

Herdr 会协助在远程主机安装所需组件，并提供：

- 本地快捷键保留
- 本地与远程剪贴板互通
- 支持粘贴图片
- 从本地终端直接管理远程会话

##### 4. 针对手机等窄屏设备优化

Herdr 可通过手机或平板上的 SSH 客户端使用。它依然显示真实终端内容，同时在窄屏下提供更易操作的会话切换界面。

官网案例展示了在手机上通过 SSH 查看 Agent 工作状态、代码输出和运行进度，适合移动场景下快速检查或切换任务。

##### 5. 定位：既不是普通 tmux，也不是桌面 Agent 应用

Herdr 试图填补两类工具之间的空白：

- **tmux/Zellij**：擅长持久终端会话和远程连接，但不了解 Agent 当前是在工作、等待还是完成。
- **桌面 Agent 应用**：能够理解 Agent，但通常受限于安装 GUI 的那台机器。
- **Herdr**：在真实终端中运行，同时具备持久会话、远程连接和 Agent 感知能力。

它明确不属于以下产品：

- **不是终端模拟器**：Ghostty、Kitty、iTerm、Alacritty 等原有终端可以继续使用。
- **不是浏览器控制台**：没有网页管理界面，不要求账号，也没有托管控制平面。
- **不是重做的聊天界面**：Agent 和命令都运行在真实 PTY 进程中。

##### 6. 与其他工具的能力对比

| 能力 | tmux/Zellij | 桌面 Agent 应用 | Herdr |
|---|---|---|---|
| 在现有终端内运行 | 支持 | 通常不支持 | 支持 |
| 持久 PTY 会话 | 支持 | 有限 | 支持 |
| 通过 SSH 远程连接 | 支持 | 有限 | 支持 |
| 识别 Agent 语义状态 | 不支持 | 部分支持 | 支持 |
| 直接连接 Agent 会话 | 不支持 | 通常不支持 | 支持 |
| 允许 Agent 反向编排工具 | 可脚本化 | 部分支持 | 支持 |

核心区别是：Herdr 不只保存终端进程，还能理解并展示 Agent 的运行状态，并通过 API 让 Agent 自己管理工作区和窗格。

##### 7. 四项核心能力

###### 真实窗格

支持工作区、标签页和可点击窗格，也能用鼠标操作。用户可以继续使用原有的 Shell、字体和快捷键。

###### Agent 状态总览

可在整个会话中快速查看 Agent 当前状态，包括：

- **Blocked**：被阻塞或等待输入
- **Working**：正在工作
- **Done**：任务完成
- **Idle**：空闲

###### 会话持久化

关闭或断开终端后，Agent 与会话仍然继续运行；重新连接即可恢复现场。

###### CLI 与 JSON Socket API

Herdr 通过 CLI 和 JSON Socket API 暴露工作区、窗格、输出读取和等待条件等能力，既方便人工操作，也便于 Agent 自动编排。

例如：

```bash
# 创建工作区
herdr workspace create --cwd ~/project --label api

# 创建日志标签页
herdr tab create --label logs

# 向右拆分窗格并运行测试
herdr pane split 1-1 --direction right
herdr pane run 1-2 "just test"

# 等待 Agent 完成，再读取另一个窗格的最新输出
herdr wait agent-status 1-1 --status done
herdr pane read 1-2 --source recent-unwrapped
```

这意味着 Agent 可以自己创建布局、启动测试、等待其他 Agent 完成，并读取结果后继续下一步。

##### 8. 兼容多种终端 Agent

原则上，任何能在终端中运行的 Agent 都可直接使用；集成后还能获得更准确的状态识别和会话恢复能力。

官网列出的工具包括：

- Claude Code、Codex、Cursor、Copilot
- Pi、Droid、Amp、OpenCode
- Grok CLI、Kimi、Kiro、Qoder CLI
- Hermes、Antigravity、MastraCode 等

##### 9. 插件与社区扩展

Herdr 的 CLI 和 Socket API 同时也是插件接口。社区可以像 Agent 一样控制 Herdr，实现通知、布局预设、链接处理和版本检查等功能。

官网示例包括：

- **Agent Telegram Notify**：Agent 完成任务后发送 Telegram 消息。
- **GitHub Link Preview**：点击 Issue 或 PR 链接时，在侧边窗格中打开预览。
- **Dev Layout Bootstrap**：围绕当前窗格快速创建一个三窗格开发布局。

开发者也可以使用指定的 GitHub Topic 发布自己的插件。

##### 总结

Herdr 的核心价值是把 “持久终端”“远程连接” 和 “AI Agent 编排” 合并到同一套终端工作流中。它尤其适合需要在远程服务器上长期运行多个编程 Agent、跨设备接入，并希望通过 CLI/API 自动协调任务的开发者。

##### 5. 核心能力：真实终端、代理状态和可编程接口

Herdr 不会重建一套聊天界面，而是让程序运行在真实的 **PTY（伪终端）** 中，并提供以下能力：

- **真实窗格**：支持鼠标操作、标签页和工作区，同时保留原有 Shell、字体和快捷键。
- **代理状态**：可统一查看代理处于 `blocked`（受阻）、`working`（工作中）、`done`（完成）或 `idle`（空闲）状态。
- **持久化**：关闭终端或断开连接后，会话与代理仍继续运行，可稍后重新接入。
- **控制接口**：通过 CLI 和 JSON Socket API 管理工作区、窗格、输出内容及等待条件。

例如，可以自动创建工作区、拆分窗格、运行测试，并等待代理完成：

```bash
# 创建工作区与标签页
herdr workspace create --cwd ~/project --label api
herdr tab create --label logs

# 拆分窗格并运行测试
herdr pane split 1-1 --direction right
herdr pane run 1-2 "just test"

# 等待代理完成并读取输出
herdr wait agent-status 1-1 --status done
herdr pane read 1-2 --source recent-unwrapped
```

这意味着不仅用户可以操作 Herdr，AI 代理也能通过其控制接口自行创建窗格、执行命令、读取结果并继续下一步任务。
