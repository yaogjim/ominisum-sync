## 分析要点

- **核心高价值点**：从Jev迁移时，应依据各选项的probabilities重新设定行动阈值，而不是复用confidence阈值。
- **留存建议**：精读并存档，供本地决策模型集成和Jev迁移时查阅（包含本地部署入口、可复现的请求示例，以及迁移时需要重新设定阈值的关键说明。）

**知识要点**

- Decision API可在一次请求中对同一输入提出选择、是非和评分问题。
- choice和score返回的confidence不等同于某个选项的概率；按选项触发动作应查看probabilities。
- Jev兼容迁移可通过设置SDK的服务地址和密钥完成，但原有置信度阈值不能直接沿用。

**行动项**

- 在Unsloth设置中启用Decision API并下载Laya模型。
- 使用文中的请求示例测试分类结果及返回的概率字段。
- 如需迁移Jev集成，修改SDK环境变量，并用实际样本重新设定概率阈值。

## 正文

For the complete documentation index, see [llms.txt](https://unsloth.ai/docs/llms.txt). This page is also available as [Markdown](https://unsloth.ai/docs/models/decision-laya.md).

使用 Unsloth，在您的本地 Mac、Windows 和 Linux 设备上运行和提供决策模型，例如 Laya——一个开源的 Jev 替代方案。决策模型将文本输入转化为结构化的决策，供您的应用执行操作——从路由支持工单、过滤邮件到自动化标签和分类。

您可以使用 Unsloth GUI 界面，通过兼容 TypeSafe 的 Jev API 来暴露 Laya，这样现有的 Jev 集成只需将其指向您的本地服务器即可正常工作。

所有数据都保留在你的设备上，CPU、统一内存和 GPU 配置均受支持。

###### Send a decision request

是时候发送决策 请求 了。在这个例子中，我们对支持工单进行分类，检测退款 请求 ，并对紧急程度进行评分。

```
curl http://localhost:8888/v1/systemone \

  -H "Authorization: Bearer sk-unsloth-YOUR_KEY" \

  -H "Content-Type: application/json" \

  -d '{

    "model": "laya",

    "state": "Hi, I was charged twice for my March invoice (#4411). Please refund the duplicate today.",

    "questions": {

      "team": {

        "type": "choice",

        "instructions": "Which team should handle this?",

        "criteria": {

          "billing": "invoices, payments, refunds",

          "technical": "bugs, outages, errors",

          "sales": "pricing, new plans",

          "other": "everything else"

        }

      },

      "refund": {"type": "noul", "instructions": "Does the customer ask for a refund?"},

      "urgency": {"type": "score", "instructions": "How urgent is this?", "criteria": ["not urgent", "soon", "today"]}

    }

  }'
```

You get back:

```
{

  "model": "laya-multilingual",

  "answers": {

    "team": {"type": "choice", "choice": "billing", "confidence": 1.0, "probabilities": {"billing": 1.0, "technical": 0.0, "sales": 0.0, "other": 0.0}},

    "refund": {"type": "noul", "noul": 0.9794},
```

首次 请求 会加载模型，耗时 10 到 20 秒。之后，在大多数 CPU 上， 请求 耗时远低于一秒。

`state` 可以是字符串或任意 JSON。 `model` 接受 `laya` 、 `default` 或 `jev-latest` （对应你在设置中选择的模型），或者 `laya-multilingual` 、 `laya-english` 、 `laya-typed-decisions` 来指定一个。

`noul` 表示是/否。它返回“是”的概率： `0.98` 表示非常可能， `0.5` 表示两种可能性相同。

`choice` 和 `score` 还会返回 `confidence` 。接近 `1` 表示某个答案明显突出。接近 `0` 表示概率分布均匀。

要根据某个选择采取行动，请使用 `probabilities` 中的值，而不是 `confidence` 。例如，只有当 `technical` 高于 `0.8` 时才提交错误报告。Laya 和 Jev 计算置信度的方式不同，因此不要复用你的 Jev 置信度阈值。

##### 🔁 从 Jev 迁移

使用 `pip install typesafe-sdk` 安装 SDK，设置两个环境变量，你现有的代码就能与 Unsloth 通信：

```
export TYPESAFE_BASE_URL=http://localhost:8888

export TYPESAFE_API_KEY=sk-unsloth-YOUR_KEY
```

SDK 的默认模型 `jev-latest` 会映射到你在“设置”中选择的任意模型。

有两点与 Jev 不同。 `confidence` 使用不同的公式，因此在 Jev 上调好的阈值无法迁移；应改为在 `probabilities` 上调整阈值。此外，一个选择中的各个选项共享固定的 token 预算，因此当描述的选项超过约 20 个时，标签会被截断。

## 深度解读-口播（1）

### 2026-09-30 12:22:04

如果你希望应用自动判断一段文字该交给哪个部门、是否需要退款，或者事情有多紧急，不一定要把数据发到云端。Unsloth 的这份文档介绍了一个本地方案：运行开源决策模型 Laya，把文字转成应用可以直接使用的结构化结果。

这里的“决策模型”，重点不是陪你聊天，也不是生成一篇解释。你给它一段内容，再规定需要回答哪些问题，它就返回选项、评分和相应的概率。真正执行操作的，仍然是接收这些结果的应用。

比如，客服系统收到一条消息：“我的三月账单被重复扣款了，请今天退还多扣的钱。”

这条消息可以同时交给模型回答三个问题。该由哪个团队处理？客户有没有要求退款？这件事有多紧急？

文档里的示例，先把负责团队限定为账务、技术、销售和其他，并说明每个团队负责什么。模型返回的选择是账务团队。在这个示例的概率分布里，账务选项占百分之百。

第二个问题只需要回答是或否。模型判断，客户要求退款的概率约为百分之九十八。

第三个问题是评分。开发者事先定义三个等级：零代表不紧急，一代表尽快，二代表今天处理。模型返回的评分约为一点九；同时，“今天处理”这一档的概率约为百分之九十。

这个例子说明，决策模型的价值，是把一句自然语言拆成几个明确、可供程序使用的判断。同一段文字，可以既用于分派工单，又用于识别退款请求，还可以用于安排处理优先级。

不过，真正把模型接进业务流程时，有一个区别尤其重要：答案的概率，不等于模型返回的置信度。

对于是非问题，模型直接返回“是”的概率。比如零点九八，就是百分之九十八；零点五，则表示是与否的可能性相同。

对于选项和评分问题，模型除了返回各个答案的概率，还会返回一个叫置信度的数值。按照文档的解释，置信度接近一，表示某个答案明显突出；接近零，表示概率分布比较均匀。

所以，置信度主要反映答案之间是否拉开了差距。它不是某个具体选项的概率，也不应直接当作这个答案正确的概率。

如果你的规则是：“只有模型认为这是技术问题的概率超过百分之八十，才提交错误报告”，就应该读取技术选项对应的概率，而不是读取整体置信度。

这也是从 Jev 迁移到 Laya 时最需要留意的地方。Jev 是文档中提到的另一套决策模型服务。两者计算置信度的公式不同，因此，在 Jev 上调好的置信度阈值，不能原样搬到 Laya。文档建议，改为围绕具体选项的概率设置阈值。

理解了怎样使用结果，再看本地运行的成本。

Laya 可以通过 Unsloth 在 Mac、Windows 和 Linux 设备上运行。文档提供三种模型选择：默认的多语言模型、英语模型，以及仅支持英语、面向发票、安全事件、客户服务等场景的类型化决策模型。

默认多语言模型的下载大小是六百七十八兆字节，最低需要四吉字节运行内存。另两种模型的下载大小都是八百四十六兆字节，最低需要五吉字节运行内存。这里要分清，下载文件大小和设备运行内存，是两个不同的要求。

默认使用中央处理器，也就是 CPU。你也可以切换到图形处理器，也就是 GPU，以获得更快的响应。如果 GPU 内存不足，Laya 会回退到 CPU，继续回答。

GPU 模式还有一个需要注意的行为：模型会一直保留在内存里，直到你手动卸载模型，或者重启 Unsloth。

响应速度也要区分首次请求和后续请求。第一次请求需要加载模型，文档给出的时间是十到二十秒。加载完成后，文档称，在大多数 CPU 上，后续请求的耗时远低于一秒。这不是所有设备都保证达到的固定速度。

本地方案的另一个重点是数据位置。按照文档描述，这套决策服务在你的设备上运行，输入数据也保留在设备上。

实际启用时，进入 Unsloth 的设置页面，找到 API，也就是应用调用服务的接口，再打开决策 API 的请求服务。确认下载后，默认模型就会开始下载。调用所需的访问令牌，也可以在同一页面找到。

如果你原本已经使用 Jev，迁移不一定需要重写业务代码。Unsloth 提供兼容 TypeSafe 的 Jev 接口。对于文档所描述的现有集成，主要调整是把服务地址改成本地 Unsloth 服务器，并设置对应的访问密钥。

原来的默认模型名，也会映射到你在 Unsloth 设置中选定的模型。但接口兼容，不代表所有行为都完全相同。除了置信度公式不同，还有一个选项数量的限制。

在一道选择题里，各个选项共享固定的文本处理预算。文档提醒，当带描述的选项超过大约二十个时，标签会被截断。因此，设计分类问题时，不能假定选项可以无限增加，而且所有描述都会被完整处理。

最值得记住的是：Laya 的用途，是在本地把文字转成明确的决策结果，而不是直接替你执行操作。用这些结果驱动业务时，要看具体答案的概率，不能把置信度当成同一个东西。已有 Jev 集成可以利用兼容接口迁移，但概率阈值和选项规模，仍然需要单独检查。
