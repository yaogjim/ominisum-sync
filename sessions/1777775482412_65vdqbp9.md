#### About

[Warp](https://www.warp.dev) is an agentic development environment, born out of the terminal. Use Warp's built-in coding agent, or bring your own CLI agent (Claude Code, Codex, Gemini CLI, and others).

#### Installation

You can [download Warp](https://www.warp.dev/download) and [read our docs](https://docs.warp.dev/) for platform-specific instructions.

Explore [build.warp.dev](https://build.warp.dev) to:

- Watch thousands of Oz agents triage issues, write specs, implement changes, and review PRs
- View top contributors and in-flight features
- Track your own issues with GitHub sign-in
- Click into active agent sessions in a web-compiled Warp terminal

#### Licensing

Warp's UI framework (the `warpui_core` and `warpui` crates) are licensed under the MIT license.

The rest of the code in this repository is licensed under the AGPL v3.

Warp's client codebase is open source and lives in this repository. We welcome community contributions and have designed a lightweight workflow to help new contributors get started. For the full contribution flow, read our CONTRIBUTING.md guide.

Before filing, [search existing issues](https://github.com/warpdotdev/warp/issues?q=is%3Aissue+is%3Aopen+sort%3Areactions-%2B1-desc) for your bug or feature request. If nothing exists, [file an issue](https://github.com/warpdotdev/warp/issues/new/choose) using our templates. Security vulnerabilities should be reported privately as described in CONTRIBUTING.md.

Once filed, a Warp maintainer reviews the issue and may apply a readiness label: [`ready-to-spec`](https://github.com/warpdotdev/warp/issues?q=is%3Aissue+is%3Aopen+label%3Aready-to-spec) signals the design is open for contributors to spec out, and [`ready-to-implement`](https://github.com/warpdotdev/warp/issues?q=is%3Aissue+is%3Aopen+label%3Aready-to-implement) signals the design is settled and code PRs are welcome. Anyone can pick up a labeled issue — mention **@oss-maintainers** on an issue if you'd like it considered for a readiness label.

To build and run Warp from source:

```
./script/bootstrap   # platform-specific setup
./script/run         # build and run Warp
./script/presubmit   # fmt, clippy, and tests
```

See WARP.md for the full engineering guide, including coding style, testing, and platform-specific notes.

#### Warp：从终端进化而来的智能开发环境

##### 一句话总结

Warp 是一个开源的「Agentic Development Environment」，可以理解为：以终端为基础，内置 AI 编程代理，并支持接入 Claude Code、Codex、Gemini CLI 等外部 AI Agent 的新一代开发工具。

##### 核心定位

Warp 不只是传统终端，而是面向 AI 编程时代的开发环境。

它希望把以下能力整合在一起：

- 终端操作
- AI 编程 Agent
- 代码协作
- Issue 处理
- PR 审查
- 开发工作流自动化

本质上，Warp 试图把「终端」升级为「AI 驱动的开发中枢」。

##### 主要能力

###### 1. 内置 AI 编程代理

Warp 提供内置 Coding Agent，可以帮助开发者处理代码相关任务，例如：

- 分析问题
- 编写规格说明
- 实现代码变更
- 审查 PR

###### 2. 支持自带 CLI Agent

除了内置 Agent，Warp 也支持接入其他命令行 AI 工具，包括：

- Claude Code
- Codex
- Gemini CLI
- 其他 CLI Agent

这说明 Warp 更像一个开放的 AI 开发入口，而不是封闭工具。

###### 3. 可视化 Agent 工作流

用户可以访问 `build.warp.dev` 查看：

- 大量 AI Agent 如何处理 GitHub Issue
- 当前正在开发的功能
- 顶级贡献者
- Agent 的实时会话
- 自己关注或提交的问题进展

这让 AI 编程过程更透明、可追踪。

##### 开源与许可

Warp 的客户端代码已经开源，代码托管在 GitHub。

许可方式分为两部分：

- `warpui_core` 和 `warpui`：MIT License
- 其他代码：AGPL v3

这意味着 Warp 鼓励社区参与，但对核心代码使用有一定开源约束。

##### 贡献方式

Warp 欢迎社区贡献，并提供了较轻量的参与流程。

贡献者可以：

1. 搜索已有 Issue
2. 提交 Bug 或 Feature Request
3. 等待维护者打标签
4. 根据标签参与设计或实现

关键标签包括：

- `ready-to-spec`：适合贡献者参与方案设计
- `ready-to-implement`：方案已确定，可以直接提交代码

##### 本地构建方式

开发者可以通过以下命令从源码构建 Warp：

```bash
./script/bootstrap
./script/run
./script/presubmit
```

分别用于：

- 环境初始化
- 构建并运行
- 格式检查、Clippy 检查和测试

##### 产品意义

从产品视角看，Warp 代表了开发工具的一个重要趋势：

> 终端不再只是输入命令的地方，而正在变成 AI Agent 协作、代码执行、任务推进和工程管理的统一入口。

它的价值不只是「更好用的终端」，而是尝试重构开发者与代码、工具、任务之间的交互方式。

##### 适合人群

Warp 适合：

- 使用终端频繁的开发者
- 希望用 AI 提升编码效率的工程师
- 关注 AI Agent 开发工作流的团队
- 想参与开源开发工具建设的贡献者
- 对下一代 IDE / Terminal 形态感兴趣的产品和技术人员

##### 总结

Warp 是一个开源的 AI 原生开发环境，以终端为起点，融合 AI Agent、代码协作和自动化开发流程。

它的方向不是简单替代传统终端，而是让终端成为 AI 时代的软件开发操作系统。

./script/bootstrap
./script/run
./script/presubmit

- Slack 社区

- build.warp.dev，用于查看 AI agents 处理 issue、写规格、实现代码、审查 PR 等过程

##### 二、深入浅出解读

###### 1. Warp 不只是一个“好看的终端”

传统终端主要是让用户输入命令，比如：

```bash
git status
npm run build
cargo test
```

而 Warp 想做的是：  
**把终端升级成一个带 AI 助手的开发工作台。**

也就是说，它不只是帮你执行命令，还希望帮你：

- 理解项目；
- 修改代码；
- 处理 GitHub issue；
- 写技术方案；
- 生成或审查 PR；
- 调用不同 AI 编程工具。

可以把它理解为：

> 终端 + IDE 能力 + AI 编程助手 + 自动化代理平台

---

###### 2. “Agentic development environment”是什么意思？

“Agentic”可以理解为“具备代理能力”。

普通 AI 助手通常是你问一句，它答一句。  
而 Agent 更像一个“能执行任务的小助手”，它可以：

1. 阅读问题；
2. 分析代码；
3. 制定方案；
4. 修改文件；
5. 运行测试；
6. 提交结果。

Warp 的目标就是让这些 AI agents 能在开发环境里更自然地工作。

---

###### 3. 支持“自带 AI 工具”

Warp 没有只绑定自己的 AI。  
它也允许用户接入其他命令行 AI 工具，比如 Claude Code、Codex、Gemini CLI。

这点很重要，因为开发者可以根据自己的习惯选择工具，而不是被单一平台锁死。

---

###### 4. 开源策略比较明确

Warp 的客户端代码已经开源。

但它的许可证分成两类：

| 部分 | 协议 |
|---|---|
| UI 框架 `warpui_core`、`warpui` | MIT |
| 其他主要代码 | AGPL v3 |

简单说：

- **MIT** 更宽松，商业使用限制少；
- **AGPL v3** 更严格，如果你基于它做网络服务，通常也需要开源相关修改。

这说明 Warp 鼓励社区参与，但也希望保护项目本身不被闭源商业化滥用。

---

###### 5. 对贡献者比较友好

它提供了比较标准的开源协作流程：

- 先搜索已有 issue；
- 没有的话再提交新 issue；
- 维护者会打标签：
  - `ready-to-spec`：适合贡献者先写设计方案；
  - `ready-to-implement`：设计已确定，可以直接写代码；
- 有问题可以提到 `@oss-maintainers`；
- 安全漏洞需要私下报告；
- 遵守行为准则。

这对新贡献者来说比较友好，不容易一上来就不知道该做什么。

---

##### 三、我的意见

我认为 Warp 是一个很值得关注的项目。

它的价值不只是“重新做一个终端”，而是尝试把终端变成 **AI 时代的开发入口**。过去开发者在终端里主要是执行命令；未来可能会在终端里直接指挥 AI 完成一部分开发工作。

它的优点很明显：

- 产品方向符合 AI 编程趋势；
- 支持多种 CLI agent，开放性较好；
- 开源后有利于社区参与和信任建设；
- 开发流程和贡献说明相对规范；
- 对重度终端用户、AI 编程用户很有吸引力。

但也有一些需要注意的地方：

- AGPL v3 对商业二次开发有一定限制；
- AI agent 自动写代码、改代码仍需要人工审查；
- 作为开发环境，稳定性、安全性和隐私保护非常关键；
- 是否能真正提升效率，还取决于具体场景和使用习惯。

###### 总体评价

> Warp 正在把“终端”从命令执行工具，升级为 AI 驱动的开发协作平台。

如果你是开发者，尤其是经常使用终端、GitHub、AI 编程工具的人，Warp 值得尝试。  
如果你是企业用户，则需要重点关注许可证、安全策略和数据隐私问题。
