##### 通知面板

在一处查看所有待处理通知，快速跳转到最新未读通知 侧边栏通知徽章

##### 内置浏览器

在终端旁边分割出浏览器窗格，提供从 [agent-browser](https://github.com/vercel-labs/agent-browser) 移植的可脚本化 API 内置浏览器

侧边栏显示 git 分支、关联 PR 状态/编号、工作目录、监听端口和最新通知文本。支持水平和垂直分割。 垂直标签页和分割窗格

##### SSH

`cmux ssh user@remote` 为远程机器创建工作区。浏览器窗格通过远程网络路由，因此 localhost 直接可用。将图片拖入远程会话即可通过 scp 上传。 cmux SSH

`cmux claude-teams` 一条命令运行 Claude Code 的队友模式。队友以原生分割的形式生成，侧边栏显示元数据和通知。无需 tmux。 Claude Code Teams

- **浏览器导入** — 从 Chrome、Firefox、Arc 及 20 多种浏览器导入 Cookie、历史记录和会话，让浏览器窗格启动即已登录
- **自定义命令** — 在 [`cmux.json`](https://cmux.com/docs/custom-commands) 中定义项目专属操作，通过命令面板启动
- **可脚本化** — 通过 CLI 和 socket API 创建工作区、分割窗格、发送按键和自动化浏览器操作
- **原生 macOS 应用** — 使用 Swift 和 AppKit 构建，非 Electron。启动快速，内存占用低。
- **兼容 Ghostty** — 读取您现有的 `~/.config/ghostty/config` 配置文件中的主题、字体和颜色设置
- **GPU 加速** — 由 libghostty 驱动，渲染流畅

#### 为什么做 cmux？

我同时运行大量 Claude Code 和 Codex 会话。之前我用 Ghostty 开了一堆分割窗格，依靠 macOS 原生通知来了解代理何时需要我。但 Claude Code 的通知内容总是千篇一律的"Claude is waiting for your input"，没有任何上下文信息，而且标签页一多，连标题都看不清了。

我试过几个编程协调工具，但大多数都是 Electron/Tauri 应用，性能让我不满意。我也更喜欢终端，因为 GUI 协调工具会把你锁定在它们的工作流里。所以我用 Swift/AppKit 构建了 cmux，作为一个原生 macOS 应用。它使用 libghostty 进行终端渲染，并读取您现有的 Ghostty 配置中的主题、字体和颜色设置。

主要新增的是侧边栏和通知系统。侧边栏有垂直标签页，显示每个工作区的 git 分支、关联 PR 状态/编号、工作目录、监听端口和最新通知文本。通知系统能捕获终端序列（OSC 9/99/777），并提供 CLI（ `cmux notify` ），您可以将其接入 Claude Code、OpenCode 等代理的钩子。当代理等待时，其窗格会显示蓝色光环，标签页会在侧边栏高亮，这样我就能在多个分割窗格和标签页之间一眼看出哪个需要我。⌘⇧U 可以跳转到最新的未读通知。

内置浏览器拥有从 [agent-browser](https://github.com/vercel-labs/agent-browser) 移植的可脚本化 API。代理可以抓取无障碍树快照、获取元素引用、执行点击、填写表单和执行 JS。您可以在终端旁边分割出浏览器窗格，让 Claude Code 直接与您的开发服务器交互。

所有操作都可以通过 CLI 和 socket API 进行脚本化 — 创建工作区/标签页、分割窗格、发送按键、在浏览器中打开 URL。

cmux 不规定开发者应该如何使用工具。它是一个带有 CLI 的终端和浏览器，其余的由你决定。

cmux 是原语，而非解决方案。它提供终端、浏览器、通知、工作区、分割、标签页，以及控制这一切的 CLI。cmux 不强迫你以特定方式使用编程代理。你用这些原语构建什么，完全取决于你自己。

最优秀的开发者一直在构建自己的工具。还没有人找到与代理协作的最佳方式，那些构建封闭产品的团队也没有找到。最接近自己代码库的开发者会最先找到答案。

给一百万个开发者可组合的原语，他们会比任何自上而下设计的产品团队更快地找到最高效的工作流。

#### 会话恢复（当前行为）

重新启动时，cmux 目前仅恢复应用布局和元数据：

- 窗口/工作区/窗格布局
- 工作目录
- 终端回滚缓冲区（尽力恢复）
- 浏览器 URL 和导航历史

cmux **不会** 恢复终端应用内部的实时进程状态。例如，活动的 Claude Code/tmux/vim 会话在重启后尚无法恢复。

#### cmux：为 AI 编程工作流打造的原生 macOS 终端

##### 一句话概括

`cmux`是一个面向 AI 编程代理协作场景的 macOS 原生终端工具。它在 Ghostty 的能力之上，补上了**通知、工作区管理、内置浏览器和自动化接口**，核心目标是：**让你同时管理多个 AI 会话时，更快发现 “哪个代理在等你”，并保持终端式的自由工作流。**

##### 它解决了什么问题

作者的核心痛点很直接：  
当同时跑很多 Claude Code、Codex 等会话时，传统终端和系统通知都不够用。

###### 具体问题
- 系统通知内容太泛，只有 “等你输入”，没有上下文
- 标签页一多，很难快速看出哪个任务需要处理
- 现有一些 AI 协作工具偏 GUI 化、偏封闭，性能和灵活性都不理想

###### cmux 的回答
它不是重新发明 IDE，而是把**终端 + 浏览器 + 通知 + 工作区管理**组合起来，做成一套更适合 AI 编程代理并行协作的基础设施。

##### 核心能力

###### 1. 通知系统：让 “谁在等你” 一眼可见
这是 cmux 最突出的价值。

- 当某个代理需要你处理时，对应窗格会出现蓝色高亮环
- 侧边栏中的标签页也会同步高亮
- 可在通知面板统一查看所有待处理消息
- 支持直接跳转到最新未读通知

本质上，它把 “AI 等待人工介入” 从模糊的系统提醒，变成了**可定位、可聚合、可跳转**的工作流信号。

###### 2. 内置浏览器：终端旁直接操作 Web
cmux 可以在终端旁边分出一个浏览器窗格，并提供可脚本化 API。

- 可抓取页面结构
- 可点击、填表、执行 JS
- 能让 AI 直接和本地开发服务交互
- 支持导入 Chrome、Firefox、Arc 等浏览器的 Cookie、历史和会话

这意味着它不只是 “终端容器”，而是把**代码执行环境 + 浏览器操作环境**放在同一个工作界面里。

###### 3. 工作区与侧边栏：为多任务并行而设计
cmux 支持工作区、标签页、分割窗格等组织方式，并通过侧边栏展示关键信息：

- Git 分支
- PR 状态和编号
- 工作目录
- 监听端口
- 最新通知内容

相比传统终端，它更像是把 “项目状态” 和 “协作上下文” 显性化了，降低多任务切换成本。

###### 4. 可脚本化：更像 “原语平台” 而不是成品工作流
cmux 提供 CLI 和 socket API，可以自动化：

- 创建工作区和分割窗格
- 发送按键
- 打开浏览器 URL
- 触发通知
- 连接 AI agent hooks

作者强调，cmux 不是规定你怎么用 AI，而是提供一组基础能力，由开发者自己拼装出最适合自己的流程。

##### 产品理念：不是 “完整方案”，而是 “可组合原语”

这是文章最值得注意的产品思想。

###### 作者的判断
- 现在还没有谁真正找到人机协作的最佳工作流
- 封闭式产品也没有标准答案
- 最懂自己代码库的人，才最可能找到高效方法

###### cmux 的定位
因此，cmux 不试图替你设计流程，而是提供：
- 终端
- 浏览器
- 通知
- 工作区
- 分割
- 标签页
- 自动化接口

也就是说，它卖的不是 “预设工作流”，而是**让高手自行搭建工作流的基础组件**。

##### 为什么它有吸引力

###### 对资深开发者 / 产品人来说，价值主要在三点
- **效率**：并行管理多个 AI 会话时，能快速识别优先级
- **自由度**：保留终端生态，不被 GUI 工作流锁死
- **扩展性**：可以接入自己的 agent、hook 和自动化脚本

从产品角度看，cmux 不是在做 “大而全”，而是在做一个非常聚焦的高频场景：  
**AI 编程时代的多会话协调器。**

##### 技术与产品特点

###### 技术实现
- 原生 macOS 应用，基于 Swift 和 AppKit
- 使用`libghostty`渲染终端
- 兼容现有 Ghostty 配置
- 非 Electron，启动更快、内存更省

###### 适合的人群
- 同时跑多个 Claude Code / Codex / OpenCode 会话的人
- 习惯终端工作流、不想被图形化工具绑定的人
- 希望自己定义 AI 协作方式的高级用户

##### 当前边界与不足

###### 会话恢复还不完整
重启后目前能恢复的是：
- 窗口 / 工作区 / 窗格布局
- 工作目录
- 终端回滚记录
- 浏览器 URL 和历史

但**不能恢复终端内部正在运行的实时进程状态**，比如：
- Claude Code 会话
- tmux 会话
- vim 状态

这说明它在 “界面层恢复” 上已经可用，但在 “运行态连续性” 上还有明显边界。

##### 商业化方式

cmux 本体是：
- 免费
- 开源
- GPL-3.0-or-later

同时提供`Founder's Edition`，作为付费支持版本，包含：
- 功能请求和 Bug 修复优先处理
- 即将上线能力的抢先体验
- 商业授权选项

这是一种典型的**开源底座 + 增值服务 / 抢先功能 + 商业许可**模式。

##### 总结

cmux 本质上不是一个 “更漂亮的终端”，而是一个专门为**AI 编程协作、多代理并行工作、终端派开发者**设计的操作台。

###### 最核心的价值判断
它抓住的不是 “写代码” 本身，而是 AI 时代一个新问题：  
**当越来越多代理同时为你工作时，人该如何高效地进行监督、介入和切换。**

而 cmux 给出的答案是：  
**用原生终端体验承载 AI 协作，把通知、浏览器和工作区管理做成可组合的原语。**
