#### English

**OpenCodex** is a plug-and-play local gateway that unlocks Codex Desktop for third-party APIs, featuring a premium web dashboard, custom Computer Use engine, and Vision Bridge for text-only models.

- **Zero-Config Setup**: Start the server, it auto-patches `~/.codex/config.toml` with backups. No CLI, no manual editing.
- **Premium Web Dashboard** (`http://localhost:8765/dashboard`):
  - 🌐 Bilingual (EN/中文) with instant switch
  - 🔑 API key &amp; endpoint management
  - 📝 Add/delete custom models, toggle visibility in Codex
  - 📡 Live SSE log streaming
  - 🚀 One-click Codex restart
  - ↺ One-click reset to native Codex
- **Custom Computer Use Engine**:
  - 🖱️ Native macOS mouse/keyboard/window control via CGEvent
  - 📸 Screenshot capture with `sips` compression (1200px)
- **Vision Bridge**:
  - 👁️ For text-only models (DeepSeek, etc.)
  - Automatically compresses screenshots, describes via multimodal model, injects description into prompt
  - Supports any OpenAI-compatible vision model (configurable endpoint, model, API key)

##### Prerequisites

- macOS
- Node.js v18+
- Codex Desktop installed

```
git clone https://github.com/AITabby/opencodex.git
cd opencodex
npm install
npm start
```

Server starts, browser opens to the dashboard. Add your API key and model names, click save — done.

#### OpenCodex 深度总结与解读

##### 一句话概括

**OpenCodex 是一个运行在本地的“中转网关”，让 Codex Desktop 可以接入第三方大模型 API，并提供网页控制台、自动配置、电脑操作能力和视觉桥接能力。**

---

##### 深度总结

###### 1. 它解决什么问题？

Codex Desktop 原生能力可能受限于默认模型或配置方式。  
OpenCodex 通过本地服务，把 Codex Desktop 和第三方 OpenAI 兼容 API 连接起来，让用户可以更自由地使用不同模型。

核心目标是：

- **不用手动改配置**
- **方便管理 API Key、模型和接口**
- **让 Codex Desktop 能调用更多第三方模型**
- **增强 Computer Use 能力**
- **让纯文本模型也能间接“看图”**

---

###### 2. 核心功能

###### 零配置启动

启动后自动修改：

```bash
~/.codex/config.toml
```

并且会做备份。  
用户无需手动编辑配置文件，也不需要复杂 CLI 操作。

---

###### Web 控制台

访问：

```text
http://localhost:8765/dashboard
```

可以完成：

- 中英文切换
- 管理 API Key
- 管理接口地址
- 添加 / 删除自定义模型
- 控制哪些模型显示在 Codex 中
- 查看实时 SSE 日志
- 一键重启 Codex
- 一键恢复原生 Codex 配置

它本质上把原本偏工程化的配置流程，变成了图形化操作。

---

###### 自研 Computer Use 引擎

OpenCodex 提供 macOS 原生电脑控制能力，包括：

- 鼠标控制
- 键盘控制
- 窗口控制
- 截图能力

底层使用 macOS 的 CGEvent，并通过 `sips` 将截图压缩到 1200px，降低传输和模型处理成本。

---

###### Vision Bridge

这是项目中比较关键的设计。

一些模型，比如 DeepSeek 等，可能本身是纯文本模型，不能直接处理图片。  
OpenCodex 的做法是：

1. 截图
2. 压缩图片
3. 交给多模态模型识别
4. 生成文字描述
5. 把描述注入 Prompt
6. 再让纯文本模型继续执行任务

也就是说，它让“不能看图的模型”通过外部视觉模型间接获得视觉信息。

---

###### 3. 使用条件

需要：

- macOS
- Node.js v18+
- 已安装 Codex Desktop

启动方式：

```bash
git clone https://github.com/AITabby/opencodex.git
cd opencodex
npm install
npm start
```

启动后浏览器会自动打开控制台，填写 API Key 和模型名即可使用。

##### 深入浅出解读

可以把 OpenCodex 理解成：

> **Codex Desktop 的“本地外挂控制台 + 模型转接器 + 视觉翻译器”。**

###### 类比理解

Codex Desktop 像一台智能机器人。  
但它默认只能用某些指定大脑，配置也不够方便。

OpenCodex 做了三件事：

1. **换大脑**  
   让 Codex 可以接入第三方模型 API。

2. **装遥控器**  
   用网页控制台管理 Key、模型、日志、重启等操作。

3. **配眼睛翻译官**  
   如果某个模型看不见图片，就找一个视觉模型先看图，再把画面内容翻译成文字告诉它。

---

##### 价值判断

###### 优点

- **降低使用门槛**：自动改配置，图形化管理。
- **增强模型自由度**：可接入第三方 OpenAI 兼容模型。
- **提升实用性**：支持本地电脑操作和截图。
- **兼容纯文本模型**：Vision Bridge 让文本模型也能参与视觉任务。
- **本地网关模式更灵活**：用户掌控配置和接口。

---

###### 潜在局限

- **平台限制明显**：目前重点依赖 macOS。
- **安全风险需要重视**：涉及 API Key、本地配置修改、鼠标键盘控制。
- **稳定性取决于 Codex Desktop 和第三方 API**。
- **Vision Bridge 不是原生视觉能力**：图片转文字会损失信息，复杂界面可能理解不准。
- **自动 patch 配置虽方便，但也可能带来不可预期问题**。

---

##### 辩证思考

OpenCodex 的价值在于，它把 Codex Desktop 从一个相对封闭的工具，改造成了更开放、更可配置的本地 AI 工作台。

但它的强大也意味着更高风险：

- 它能控制电脑，所以需要信任它。
- 它能修改配置，所以需要可回滚。
- 它能接入各种模型，所以效果会参差不齐。
- 它能让文本模型“看图”，但这只是视觉描述，不等于真正视觉理解。

因此，OpenCodex 更适合有一定技术判断力、愿意折腾并关注隐私安全的用户。  
对于普通用户，它降低了配置门槛；但对于安全敏感场景，仍应谨慎使用。

---

##### 最终结论

**OpenCodex 是一个面向 Codex Desktop 的本地增强网关。**

它的核心意义不是单一功能，而是把：

- 第三方模型接入
- 本地电脑控制
- 图形化配置
- 视觉桥接

整合成一个可用的本地系统。

一句话评价：

> **它让 Codex Desktop 更开放、更易用、更强，但也要求用户更重视安全、稳定性和模型质量。**
