## 追问（1）

### 提问 · 2026-03-31 03:18:11

在医疗 AI 研究领域，长时间运行的智能体、用于临床模型的强化学习(RL)/基于人类反馈的强化学习(RLHF)，可以有哪些最佳实践，请结合具体的例子深入浅出讲解

### 回答 · 2026-03-31 03:18:11

可以把这条招聘里提到的两个方向，理解成医疗 AI 里最难也最有价值的两类能力：

- 长时间运行的智能体：不是 “一问一答”，而是能持续几小时、几天，围绕一个临床任务分阶段工作、不断纠错、保留上下文。
- 临床模型上的 RL / RLHF：不是只学 “像医生怎么说”，而是进一步学 “什么样的决策过程更安全、更有帮助、更符合临床目标”。

这两个方向如果做得好，确实更容易产生 “真正影响患者” 的系统，而不只是论文 demo。

**先讲核心判断**
- 医疗 AI 的最佳实践，不是先追求 “更聪明”，而是先追求 “更可控、更可审计、更可回退”。
- 在医疗里，最危险的不是模型不会，而是模型 “看起来会”，然后自信地下错结论。
- 所以不管是 agent 还是 RL/RLHF，第一原则都应该是：高风险任务拆解、证据绑定、人工兜底、可追溯评估。

下面我分两部分讲，并尽量用具体例子解释。

---

**一、长时间运行的医疗智能体：最佳实践**

先用一句大白话解释：

普通聊天模型像 “门诊里回答一个问题的助手”；  
长时间运行的 agent 更像 “一个跟着病例走完整流程的住院总助理”。

比如一个住院患者从入院到出院，agent 可能要连续参与：
- 整理病史
- 汇总化验趋势
- 发现风险变化
- 提醒指南中的下一步检查
- 起草病程记录
- 追踪医嘱执行情况
- 交班时生成摘要

这类任务不是一次生成能完成的，所以最佳实践是 “工作流化”，而不是 “让一个大模型自己想”。

**1) 把 agent 设计成多阶段工作流，不要单轮端到端**
最佳实践：
- 把任务拆成：信息收集、证据校验、候选结论生成、风险筛查、人工确认、行动执行。
- 每一阶段都有独立输入输出，不允许模型 “跳步骤”。
- 关键节点必须保留结构化中间结果。

例子：住院患者 “脓毒症早期识别 agent”
- 阶段 1：读取最近 24 小时生命体征、乳酸、白细胞、血培养状态。
- 阶段 2：根据规则和模型，判断是否存在脓毒症风险信号。
- 阶段 3：生成 “为什么怀疑” 的证据摘要，比如 “体温 39.1、心率 128、乳酸升高到 3.8”。
- 阶段 4：只输出 “建议复核” 而不是 “直接下治疗医嘱”。
- 阶段 5：由临床医生确认是否启动脓毒症 bundle。

为什么这是最佳实践？
因为医疗里最重要的是 “证据链”，不是一句很像医生的话。

**2) 让 agent 的每个结论都绑定证据来源**
最佳实践：
- 每个临床判断都必须附带来源：哪份病历、哪条化验、哪个时间点、哪条指南。
- 输出中区分 “事实”“推断”“建议”。
- 不允许模型把没看到的内容说成已经看到。

例子：
差的输出：
- “患者可能存在感染性休克，建议升级抗生素。”

好的输出：
- “事实：过去 6 小时平均 MAP 低于 65，乳酸从 2.1 升到 4.0，血培养待回报。”
- “推断：存在感染相关低灌注风险，需要医生评估是否符合感染性休克标准。”
- “建议：提示复核液体复苏、升压药使用情况，并参考本院脓毒症路径。”

这会显著降低幻觉风险，也方便医生快速判断。

**3) 长期记忆要分层，不要把所有历史都塞进上下文**
长时间运行 agent 最大的问题之一，就是上下文越来越长，噪音越来越大。

最佳实践是做三层记忆：
- 原始记忆：原始病历、检验、护理记录，不改写，作为 “证据仓库”
- 工作记忆：当前任务真正需要的重点信息，比如 “今天重点是 AKI 风险”
- 摘要记忆：跨天保留的稳定事实，比如 “慢性肾病 3 期，对青霉素过敏”

例子：肿瘤患者长期随访 agent
- 原始记忆：所有影像报告、病理、用药史
- 工作记忆：这次门诊要关注近期 CT 变化和免疫治疗不良反应
- 摘要记忆：既往 EGFR 突变、对某药有 3 级肝毒性、最近两次病灶大小趋势

这样做的好处：
- 降低 token 消耗
- 减少模型被旧信息干扰
- 提升多轮任务中的稳定性

**4) 给 agent 明确 “升级处理” 和 “停止条件”**
医疗 agent 不能一味自主，它必须知道什么时候停下，什么时候叫人。

最佳实践：
- 定义高风险触发器：胸痛、低氧、意识改变、快速恶化、化验危急值等
- 一旦命中触发器，禁止继续自动推理到治疗结论，直接升级给医生
- 定义任务失败条件，比如 “证据冲突”“关键信息缺失”“无法确认患者身份”

例子：药物剂量调整 agent
如果系统发现：
- 肌酐突增
- 当前药物为肾毒性药物
- 但最新体重缺失，尿量数据冲突

此时最佳实践不是 “猜一个剂量”，而是输出：
- “无法安全推荐剂量调整，因为缺少可靠体重与尿量信息，请人工复核。”

在医疗里，知道 “不该回答” 比 “回答得漂亮” 更重要。

**5) 用工具调用而不是纯文本推理**
最佳实践：
- 让 agent 调用确定性的工具：风险评分器、药物相互作用检查器、指南检索器、数据库查询器
- 让模型负责 “协调与解释”，不要让模型自己 “心算医学规则”

例子：抗凝治疗评估
agent 不应靠语言模型记忆来硬算 CHA2DS2-VASc 或 HAS-BLED。
更好的方式是：
- 模型抽取结构化变量
- 工具进行打分
- 模型解释分数和临床含义
- 医生最终确认治疗方案

这样能大幅减少隐藏错误。

**6) 评估不能只看正确率，要看 “过程安全性”**
普通 AI 常看准确率，但医疗 agent 更该看：
- 是否引用真实证据
- 是否遗漏关键信号
- 是否在高风险场景及时升级
- 是否在信息不足时拒答
- 是否能在多轮过程中保持前后一致

例子：
做 “出院总结 agent” 评估时，不只看摘要像不像医生写的，还要看：
- 是否漏掉抗凝禁忌
- 是否把住院中短暂异常写成确定诊断
- 是否错误继承了已停药的药物
- 是否能正确区分 “住院问题” 与 “长期问题”

这类评估比 BLEU、ROUGE 之类文本指标重要得多。

**二、用于临床模型的 RL / RLHF：最佳实践**

先讲一个直觉：

监督微调（SFT）像是在教模型 “医生通常怎么回答”；  
RL / RLHF 更像是在教模型 “怎样的回答和决策过程更值得奖励”。

但在医疗里，“奖励” 设计不好会非常危险。

比如：
- 如果只奖励 “回答像专家”，模型可能学会自信表达，而不学会谨慎。
- 如果只奖励 “最终诊断正确”，模型可能在中间编造证据。
- 如果只奖励 “减少检查”，模型可能漏诊。
- 如果只奖励 “多检查”，模型可能过度医疗。

所以医疗 RL 的核心不是 “把 reward 做大”，而是 “把 reward 设计得符合真实临床目标”。

**1) 先从低风险任务做 RL，不要直接对治疗决策做全自主优化**
最佳实践：
- 优先在信息组织、检索、分诊建议、病历摘要、指南匹配、问题澄清这些低到中风险环节做 RL
- 对高风险治疗决策先做 “建议排序” 或 “辅助评估”，不要直接做自动决策

例子：
安全的 RL 应用：
- 优化模型在病历问答中先问哪些澄清问题
- 优化 discharge summary 的完整性与错误率
- 优化文献检索 agent 找到高质量临床证据的能力

高风险、需更谨慎的 RL 应用：
- 直接学习 ICU 用药策略
- 直接建议升压药剂量
- 直接决定是否停止抗生素

这不是说后者不能做，而是要更强的因果建模、离线验证和临床治理。

**2) 奖励函数要多目标，而不是单一分数**
医疗场景下，好的 reward 通常至少包括：
- 正确性：结论是否与标准或专家一致
- 证据性：是否引用到真实、相关的病历或指南依据
- 安全性：高风险时是否及时升级、是否避免过度自信
- 完整性：是否覆盖关键鉴别诊断或危险信号
- 效率性：是否减少无意义步骤、降低医生认知负担

例子：胸痛分诊模型的 RL 奖励设计
不要只奖励 “是否最终识别 ACS”。
更好的 reward 组合可以是：
- 识别高危 ACS：高奖励
- 漏掉高危 ACS：极大惩罚
- 没有问到关键病史（放射痛、出汗、既往 CAD）：惩罚
- 在低危患者中盲目升级急诊资源：小惩罚
- 在信息不足时主动请求 ECG /troponin：奖励
- 明确表达不确定性并建议人工评估：奖励

这样训练出来的模型，行为会更像 “安全的临床助手”，而不是 “只追求某个终点分数的投机者”。

**3) RLHF 的反馈者不能只看文风，要看临床过程**
很多 RLHF 失败，是因为人类反馈只偏好：
- 更流畅
- 更像专家口吻
- 更简洁

但医疗里真正重要的是：
- 有没有抓住危险点
- 有没有胡编
- 有没有过度确定
- 是否建议了合理的下一步

最佳实践：
- 让反馈标准结构化
- 让标注者按多个维度打分，而不是 “哪个好”
- 尽量引入临床人员和受训的医学标注员共同参与

例子：比较两个回答
问题：发热、低压、呼吸急促患者下一步怎么做？

回答 A：
- 文风流畅，像专家，但直接说 “考虑社区获得性肺炎，建议头孢 + 阿奇霉素”

回答 B：
- 先指出可能存在脓毒症风险
- 明确需要立即评估生命体征稳定性
- 建议尽快乳酸、血培养、氧合评估，并由医生决定抗感染方案

在普通偏好标注里，A 可能因为 “更像成品答案” 得高分；  
在临床 RLHF 里，B 才应该被奖励，因为它更安全、更符合优先级。

**4) 临床 RL 更适合离线强化学习 + 模拟环境 + 人工审查**
医疗里不能让模型直接在线试错，这和推荐系统、游戏不一样。

最佳实践组合：
- 用历史 EHR 数据做离线 RL
- 在临床模拟器或专家构造场景里做策略评估
- 用回顾性研究验证
- 小范围静默部署
- 最后再做人机协作上线

例子：败血症液体复苏策略研究
一个团队可能会这样做：
- 第一步：用 ICU 历史数据学习不同患者状态下的治疗策略
- 第二步：用因果推断方法处理 “医生为什么当时这样做” 的偏差
- 第三步：只让模型输出 “推荐排序” 和 “置信理由”
- 第四步：先静默运行，不影响真实治疗，只看它和专家选择的一致性、安全性
- 第五步：再进入 “医生可见，但不能自动执行” 的阶段

这比直接把 RL 策略接入临床系统安全得多。

**5) 明确区分 “模仿最优医生” 与 “优化患者结果”**
这是医疗 RL 里最容易混淆的一点。

- 模仿学习：学会 “优秀医生一般会怎么做”
- 强化学习：学会 “什么策略长期结果更好”

问题是，历史数据中的医生决策并不总是最优，而且有很多偏差：
- 不同医院习惯不同
- 资源约束不同
- 病情严重程度不同
- 一些群体存在系统性照护差异

所以最佳实践：
- 先做高质量行为克隆 / SFT，学会基本临床语言与流程
- 再用 RL 微调 “安全性、证据性、升级时机、长期目标”
- 不要把历史行为直接当作最优真理

例子：
如果历史上某类患者因为流程问题，经常延迟镇痛或延迟检查，模型若只做模仿学习，就可能把这种延迟也学进去。
RL 的价值之一，就是在更合理的 reward 下，推动模型偏离 “历史平均行为”，靠近 “更好的临床行为”。

**6) 奖励模型本身也要被审计**
RLHF 往往会训练一个 reward model 来判断回答好坏，但医疗里这个 reward model 也可能带偏整个系统。

最佳实践：
- 单独评估 reward model 的偏差
- 看它是否偏爱 “更像医生的语气” 而不是 “更安全的决策”
- 检查不同亚群体上是否有系统偏差
- 用对抗样本测试它是否会被华丽措辞欺骗

例子：
两份回答内容一样，一个用很多专业术语、一个更朴素。
如果 reward model 总是偏爱术语更密的那个，就说明它在学 “表面像专家”，而不是学 “真正更好”。

**三、把两者结合：医疗 AI 里最有前景的做法**

从这条招聘内容看，他们提到的方向其实很可能不是孤立的，而是组合拳：

- 用长时间运行 agent 处理复杂、多阶段临床任务
- 用 RL / RLHF 优化 agent 在关键节点的行为
- 用动态提示词优化、工作流搜索、工具使用，让系统逐步收敛到更可靠的策略

一个典型组合例子：

**例子：肿瘤随访智能体**
目标：帮助肿瘤科团队处理长期随访患者

agent 工作流：
- 读取最近影像、实验室、病理和用药史
- 生成本次门诊前摘要
- 识别免疫治疗不良反应风险
- 检索相关指南
- 提出需要医生确认的问题清单
- 门诊后自动起草总结和待办事项

RL / RLHF 优化点：
- 奖励它优先发现严重免疫相关不良反应
- 奖励它在信息缺失时主动提问，而不是瞎猜
- 奖励它引用最新、相关的肿瘤指南
- 惩罚它把 “待排除问题” 写成 “确定诊断”
- 奖励它生成医生真正愿意采用的结构化摘要

这样系统不是为了 “说得更像医生”，而是为了 “在长期工作流里持续可靠”。

**四、落地时最重要的 8 条实践原则**

如果你真的要做医疗 AI 研究，我会把最佳实践浓缩成这 8 条：

- 先做辅助，不做替代：先支持医生决策，不直接自动执行高风险动作。
- 证据先于结论：每个建议都要能追溯到病历或指南。
- 工作流先于模型：把任务拆成可控步骤，而不是迷信单次大模型输出。
- 安全优先于准确：宁可在高风险时升级人工，也不要自信给错。
- 离线验证先于上线：先回顾性评估，再静默部署，再灰度开放。
- 多目标奖励优于单目标奖励：正确、安全、完整、效率都要考虑。
- 过程评估重于表面评估：不仅看答案像不像，还看推理过程是否合规。
- 人在环是产品设计，不是权宜之计：医疗 AI 的 “人工确认” 不是落后，而是成熟。

**五、几个很具体的 “好实践 / 坏实践” 对照**

**场景 1：出院总结**
坏实践：
- 直接让模型根据整段病历生成最终出院小结

好实践：
- 先抽取诊断、检查、住院事件、用药变更
- 再逐项校验
- 最后生成摘要
- 对高风险字段如抗凝药、胰岛素、过敏史做单独核对

**场景 2：ICU 风险预警**
坏实践：
- 模型发现异常后直接建议具体治疗方案

好实践：
- 先输出风险等级和证据
- 再提示医生复核
- 只有在规则明确、低风险的情境下才给标准化建议

**场景 3：RLHF 优化临床问答**
坏实践：
- 让标注员只选 “哪一个回答更专业”

好实践：
- 分开标注：事实准确性、危险识别、证据质量、不确定性表达、下一步建议合理性

**六、如果你想研究这个方向，最值得切入的题目**

结合你给的上下文，那条招聘强调的是 “能真正落地” 的方向。比较值得做、也相对现实的题目有：

- 长时间运行的病历整理 agent：跨住院周期维护患者状态和关键问题
- 临床检索 agent 的 RL 优化：让系统更会找指南、论文和院内路径
- 面向高风险场景的升级策略学习：训练模型知道何时必须交给医生
- 临床摘要的偏好对齐：让模型生成医生愿意直接使用的结构化输出
- 医疗 agent 的过程评估框架：不是只评最终答案，而是评估每一步是否安全、可证据化

这些方向很符合 “研究成果能进入真实工作流” 的要求。

---

**一句话总结**
在医疗 AI 里，长时间运行的智能体要像 “有纪律的住院总助理”，而不是 “会聊天的全能专家”；  
临床 RL / RLHF 要优化的也不是 “更像医生说话”，而是 “更安全、更有证据、更懂何时不该自己做决定”。

2. 用一个真实场景，比如 “脓毒症” 或 “肿瘤随访”，详细演示 RL/RLHF 怎么设计奖励函数和评估集

## 产品-最佳实践（1）

### 2026-03-31 03:24:26

#### 医疗 AI 研究的具体实例与最佳实践

结合你提供的上下文，这里我用一个非常贴近该招聘描述的实例来讲：  
**“一个用于肿瘤患者长期随访的长时间运行智能体（Long-running Agent）”**，并说明在这个实例上，如何结合**RL / RLHF**做出真正能落地的医疗 AI 系统。

---

##### 一、实例设定：肿瘤患者长期随访智能体

###### 1. 业务背景
假设 Sully AI 这类团队想做一个真正服务临床的系统，不是一次性回答问题，而是持续参与患者管理流程。

这个智能体的目标是：

- 持续跟踪肿瘤患者的病程
- 汇总影像、化验、病理、治疗方案和不良反应
- 在门诊前生成重点摘要
- 识别需要优先处理的风险
- 提醒医生关注可能被遗漏的问题
- 起草随访记录和后续待办事项

这就是一个典型的**长时间运行智能体**场景，因为它不是只回答一次，而是要跨很多次就诊、很多份记录、很多轮任务持续工作。

---

##### 二、为什么这个实例适合做长时间运行 Agent + RL/RLHF

这个场景同时包含你提到的两个核心方向：

###### 长时间运行智能体
因为患者管理是连续的，不是单轮对话：

- 第一次门诊要看初诊信息
- 第二次要看用药后不良反应
- 第三次要看影像变化
- 第四次要决定是否继续当前方案

模型必须能维护长期上下文，而不是每次 “重新做人”。

###### RL / RLHF
因为这里不是简单追求 “回答像医生”，而是追求：

- 哪些信息应该优先呈现
- 哪些风险必须被及时发现
- 什么时候该提示升级人工处理
- 生成的摘要是否真的对医生有帮助

这类 “行为质量” 非常适合用 RL / RLHF 优化。

##### 三、具体病例示例

下面构造一个简化但真实感很强的例子。

###### 患者资料
- 62 岁女性
- 非小细胞肺癌（NSCLC）
- EGFR 突变阳性
- 正在接受靶向治疗
- 既往有高血压、2 型糖尿病
- 3 周前开始出现轻度咳嗽
- 1 周前复查 CT，提示肺部病灶轻度缩小
- 近 3 天实验室检查显示：
  - ALT/AST 升高
  - 血氧略低
  - CRP 升高
- 护理记录提到患者主诉 “活动后气短加重”

###### 临床难点
此时医生面临的问题可能不是单一的：

- 是治疗有效，但出现了药物性肝损伤？
- 是感染？
- 是免疫相关肺炎？
- 是肿瘤进展导致呼吸问题？
- 哪个问题最优先？
- 哪些证据最关键？
- 下一步该补什么检查？

如果没有一个好的智能体，医生需要自己翻很多系统和记录。

##### 四、在这个实例上的最佳实践

---

##### 1. 最佳实践一：不要做 “万能医生”，而要做 “分阶段协作系统”

###### 错误做法
让模型直接读完所有病历，然后输出：

> “患者可能为药物性肝损伤合并感染，建议停药并抗感染治疗。”

这看起来很聪明，但问题很多：

- 结论跳跃过大
- 缺乏证据链
- 容易误导
- 没有体现不确定性
- 可能直接影响治疗决策

###### 最佳做法
把 agent 设计成多个阶段：

###### 阶段 A：信息收集
提取本次随访所需核心信息：

- 当前诊断
- 近 3 次影像变化
- 近期用药变化
- 肝功能趋势
- 呼吸症状变化
- 炎症指标变化
- 最近是否发热
- 是否有感染证据

###### 阶段 B：问题列表生成
输出结构化问题，而不是直接结论：

- 是否存在药物相关肝损伤？
- 是否存在感染性病变？
- 是否需要排查免疫相关肺炎或药物性肺炎？
- 当前氧合是否较基线恶化？

###### 阶段 C：证据绑定
每个问题后都附证据：

- “ALT/AST 较 2 周前明显升高”
- “患者近 3 天活动后气短加重”
- “CRP 升高”
- “CT 显示病灶缩小，但未明确感染性阴影变化”

###### 阶段 D：风险分层
- 低风险：常规随访可处理
- 中风险：建议本次门诊重点复核
- 高风险：建议优先人工介入或急诊评估

###### 阶段 E：生成医生可用输出
不是替医生下诊断，而是生成：

- 门诊前摘要
- 高优先级风险提示
- 建议补充确认的问题
- 建议检查项草稿

###### 为什么这是最佳实践
因为医疗 AI 最重要的不是 “一步答对”，而是：

- 帮助医生快速抓重点
- 让每个建议都有来源
- 在不确定时知道停下来

---

##### 2. 最佳实践二：所有结论必须 “证据化”

###### 错误做法
模型直接说：

> “考虑感染并发药物性肺炎。”

这种回答的危险在于，它很像专家，但没有告诉你依据是什么。

###### 最佳做法
输出必须分层：

###### 事实
- 近 3 天活动后气短加重
- CRP 较上次升高
- ALT/AST 升高
- CT 显示肺部原发病灶轻度缩小

###### 推断
- 存在炎症或感染相关风险信号
- 存在治疗相关不良反应风险
- 需要区分感染、药物毒性与肿瘤相关原因

###### 建议
- 建议医生优先复核氧饱和度变化、近期影像细节与用药时间线
- 建议考虑进一步检查以区分感染与治疗毒性
- 如低氧明显加重，应立即人工升级处理

###### 最佳实践原则
在医疗场景里，智能体输出最好遵循这个格式：

```markdown
- 事实：来自病历、化验、影像、护理记录
- 推断：基于事实形成的临床怀疑
- 建议：下一步需要人工确认或补充的动作
```

这样可以显著减少 “看似聪明、实际上不可追责” 的风险。

---

##### 3. 最佳实践三：长期记忆要分层管理

长时间运行 agent 最大的问题，不是模型不会想，而是**上下文会失控**。

###### 错误做法
每次随访都把患者所有病历全文塞给模型。

结果通常是：

- token 成本高
- 旧信息干扰新信息
- 模型抓不住当前重点
- 容易把过时问题当成当前问题

###### 最佳做法：三层记忆结构

###### 原始记忆层
保存不可修改的基础资料：

- 全量病历
- 检验结果
- 影像报告
- 病理结果
- 医嘱和护理记录

###### 摘要记忆层
保存稳定、跨时间的重要信息：

- 肿瘤分型和分期
- 关键突变信息
- 既往严重不良反应
- 药物过敏史
- 主要合并症

###### 工作记忆层
只保留当前任务相关内容：

- 这次门诊最需要关注什么
- 最近一次治疗后出现了哪些新变化
- 这次需要医生确认的 3 个核心问题

###### 在本例中如何应用
对这位 NSCLC 患者：

###### 摘要记忆
- EGFR 突变阳性
- 正在接受靶向治疗
- 既往糖尿病、高血压
- 无已知严重过敏史

###### 工作记忆
- 本次重点：气短加重 + CRP 上升 + 转氨酶升高
- 需优先排查：感染、药物毒性、肺部并发症
- 门诊前待确认：低氧程度、是否发热、影像细节

###### 为什么这是最佳实践
因为长时间运行系统的关键能力不是 “记得多”，而是 “记得对、调得准”。

---

##### 4. 最佳实践四：高风险场景必须触发升级，而不是继续自动推理

###### 错误做法
模型看到 “气短 + 炎症指标升高 + 血氧降低”，还继续自动给出完整治疗建议。

###### 最佳做法
为 agent 定义明确的**升级规则**。

###### 在本例中的升级触发条件
如果出现以下任一情况，智能体应停止自主推进，并明确提示人工立即介入：

- 静息血氧明显下降
- 呼吸困难快速进展
- 发热合并影像异常
- 肝功能异常达到重度
- 症状与影像 / 检验结果明显矛盾
- 关键信息缺失，无法做出安全判断

###### 推荐输出方式
```markdown
### 风险等级
高风险

### 触发原因
- 近 3 天活动后气短加重
- 血氧较基线下降
- 炎症指标上升
- 同时存在治疗相关不良反应可能

### 系统动作
- 停止自动生成治疗建议
- 标记为需医生优先评估
- 建议补充感染与药物毒性鉴别检查
```

###### 这为什么重要
医疗 AI 最成熟的标志之一，不是它 “总有答案”，而是它知道什么时候必须把问题交还给医生。

---

##### 5. 最佳实践五：RL / RLHF 的奖励不能只看 “像不像专家”

这个实例特别适合讲 RL / RLHF，因为它能清楚看出 “文风好” 和 “临床好” 不是一回事。

###### 一个典型问题
如果你让标注员只看哪个回答更专业、更流畅，那么模型可能学到：

- 多用术语
- 说得更肯定
- 语气更像资深医生

但这不等于更安全。

###### 在本例中的奖励设计应该是什么

对于 “门诊前摘要生成” 这个任务，奖励函数可以包含以下维度：

###### 1. 风险识别奖励
如果模型正确识别出：
- 低氧风险
- 感染风险
- 药物毒性风险

给予奖励。

如果遗漏高风险信号，给予较大惩罚。

###### 2. 证据绑定奖励
如果每个判断都能引用：
- 哪次化验
- 哪条护理记录
- 哪份影像报告

给予奖励。

如果出现无证据结论，惩罚。

###### 3. 不确定性表达奖励
如果模型在信息不足时说：
- “需要进一步检查确认”
- “目前无法区分感染与药物毒性”

给予奖励。

如果它在证据不足时强行下结论，惩罚。

###### 4. 临床实用性奖励
如果摘要能帮助医生快速进入状态，比如：
- 列出 3 个最优先问题
- 给出简洁但完整的证据链
- 提示下一步需要确认什么

给予奖励。

###### 5. 安全性惩罚
如果模型：
- 直接下治疗医嘱
- 省略升级条件
- 过度自信
- 把 “待排查” 说成 “明确诊断”

要给较强惩罚。

---

##### 6. 最佳实践六：RLHF 标注要结构化，而不是 “二选一偏好”

###### 错误做法
让标注者只做这种任务：

> A 和 B 哪个更好？

这在医疗里不够，因为一个回答可能 “更好看”，但 “更危险”。

###### 最佳做法
让标注者按多个维度打分。

###### 在本例中的推荐标注表

| 维度 | 说明 | 分值示例 |
|---|---|---|
| 事实准确性 | 是否正确提取病历事实 | 1-5 |
| 风险识别 | 是否识别关键危险信号 | 1-5 |
| 证据充分性 | 每条推断是否有依据 | 1-5 |
| 不确定性表达 | 是否在证据不足时保持谨慎 | 1-5 |
| 临床实用性 | 是否帮助医生节省时间并聚焦重点 | 1-5 |
| 安全性 | 是否避免越权建议和高风险误导 | 1-5 |

###### 这样做的好处
RLHF 不再只是优化 “语气偏好”，而是在优化 “临床行为质量”。

---

##### 7. 最佳实践七：先做低风险闭环，再逐步进入高风险任务

这个实例里，不建议一上来就让系统直接做 “治疗建议自动化”。

###### 最好的上线顺序

###### 第一步：摘要与检索辅助
让 agent 做：

- 门诊前摘要
- 风险点提示
- 指南检索
- 需要确认的问题清单

这是低风险、高价值的切入点。

###### 第二步：建议排序
系统可以进一步输出：

- “最值得优先排查的 3 个方向”
- “建议先确认的信息”
- “建议调用的工具或检查”

但仍然不直接做最终治疗决定。

###### 第三步：静默评估
系统后台运行，但不展示给医生，先观察：

- 是否能稳定识别高风险病人
- 是否经常误报
- 是否遗漏重要问题

###### 第四步：医生可见但不能自动执行
允许医生参考它的摘要和优先级提示，但不允许系统直接下医嘱。

###### 为什么这是最佳实践
因为医疗 AI 不是 “功能越强越好”，而是 “在风险可控前提下逐步释放能力”。

---

##### 8. 最佳实践八：评估指标要关注 “过程安全”，不是只看最终答案

###### 错误做法
只看模型最后生成的摘要像不像医生写的。

###### 最佳做法
对整个过程进行评估。

###### 在本例中的关键评估指标

###### 1. 高风险遗漏率
模型有没有漏掉：
- 低氧
- 气短加重
- 肝功能恶化
- 可能的感染信号

###### 2. 证据引用正确率
模型引用的证据是否真的存在于病历中。

###### 3. 不确定性合理性
在证据不足时，模型是否知道说 “不确定”。

###### 4. 升级触发准确率
该升级时是否升级，不该升级时是否不过度报警。

###### 5. 医生采纳率
医生是否愿意使用这份摘要。

###### 6. 时间节约效果
是否真的减少医生翻阅病历的时间。

###### 最有价值的评估问题
不是：

> “它写得像不像一个医生？”

而是：

> “它有没有帮助医生更快、更安全地抓住该抓住的问题？”

---

##### 五、在这个实例中，如何结合 DSPy / GEPA 一类思路

你提供的上下文里，热门回复提到了**DSPy GEPA**、动态优化和基于真实信号收敛，这和这个实例非常契合。

###### 可以怎样用
对于肿瘤随访 agent，不要手工拍脑袋写一个固定 prompt，而可以优化下面这些中间策略：

- 哪些病历字段优先抽取
- 摘要应该先呈现影像、症状还是实验室
- 风险提示的排序逻辑
- 遇到信息冲突时的处理模板
- 什么情况下优先触发人工升级

###### 一个简单例子
假设你有一个目标：

> 希望门诊前摘要既不漏掉高风险问题，又不过度打扰医生。

你可以让系统在一组真实回顾性病例上自动搜索更好的 prompt /pipeline：

- 版本 A：优先按时间线总结
- 版本 B：优先按风险等级总结
- 版本 C：先列异常，再列稳定信息
- 版本 D：发现呼吸问题时强制插入低氧检查节点

然后用真实临床反馈信号来优化：

- 漏报率是否下降
- 医生采纳率是否上升
- 摘要长度是否合适
- 高危病例是否更早被标出

###### 这为什么符合 “真正落地”
因为这不是为了在 benchmark 上多拿一点分，而是在优化：

- 工作流可用性
- 医生认知负担
- 高风险识别质量
- 患者安全

这正符合原文里那种 “不是只发 arXiv，而是最后能惠及患者” 的研究取向。

##### 六、这个实例上的一套推荐落地方案

下面给出一个比较完整、也比较符合最佳实践的方案。

###### 系统输入
- EHR 结构化数据
- 化验结果
- 影像报告
- 护理记录
- 医嘱记录
- 历次门诊摘要

###### 系统模块
1. 患者长期记忆模块  
2. 当前随访工作记忆模块  
3. 风险识别模块  
4. 指南 / 知识检索模块  
5. 摘要生成模块  
6. 升级决策模块  
7. 人工反馈收集模块  

###### 模型职责
- 提取信息
- 组织信息
- 排序优先级
- 提示不确定性
- 生成可读摘要

###### 工具职责
- 趋势计算
- 阈值判断
- 指南检索
- 历史记录查询
- 风险评分

###### 人工职责
- 最终诊断
- 治疗方案确定
- 高风险场景处置
- 对系统输出进行反馈修正

---

##### 七、这个实例上最值得记住的一句话

如果只用一句话概括这个实例上的最佳实践，那就是：

> **在医疗 AI 里，最好的长时间运行智能体，不是替医生做决定，而是持续、可靠、可追溯地帮助医生更早看见真正重要的问题。**

而 RL / RLHF 的作用，不是把模型训练得 “更像专家说话”，而是把它训练得：

- 更会抓风险
- 更会引用证据
- 更懂得谨慎
- 更知道何时必须交给人

---

- 所有推断都必须绑定原始病历证据
