- 双向编码器可联合编码输入状态、问题和候选选项，通过选项标记位置的隐藏状态生成候选概率，无需自回归生成标签文本；这限制了输出形式，但不能保证判断正确。

#### 1\. 真正的问题：为什么 LLM 不擅长做决策

每个现代 AI 流水线都有一个巨大的瓶颈：我们用生成式 LLM 来做简单的反射式决策。

当客户支持工单到达，或一封邮件进入你的收件箱，或用户向你的 API 提交提示词时，你通常只需要回答几个简单的问题：

- 这应该转到哪个部门？
- 这封邮件是钓鱼攻击吗？
- 这个提示词是在试图越狱系统吗？
- 这个问题在 0 到 3 的紧急程度量表上有多紧急？

为此调用一个 8B 或 70B 的生成式 LLM 完全是大材小用。你要等待 500 毫秒到 2000 毫秒让 token 流式输出，花费真金白银进行推理，然后还得编写正则表达式或 JSON 解析器从自由格式文本中提取一个干净的标签。最糟糕的是，LLMs 喜欢产生幻觉并生成虚假的置信度。当一个 LLM 输出 `"confidence: 0.95"` 时，它只是在预测听起来自信的 token。其背后没有任何数学校准。

我们需要一个像人脑系统 1 那样运作的模型：即时、反射性的决策，并给出诚实且经过校准的概率，在标准硬件上仅需 30 到 40 毫秒。

#### 2\. 三种决策原语

遵循系统 1 的理念，RL Agent 接收一个状态（原始文本、电子邮件、工单或 JSON 文档）以及一个或多个带类型的问题，并在一次单一的并行前向传递中评估所有问题。

It uses three primitives:

1. choice：从标准字典中挑选一个选项。返回所选标签、每个候选选项的概率以及置信度分数。（非常适合部门路由、意图检测、主题分类）。
2. score：将状态置于有序评分标准上，如等级 0、1、2、3。返回预期分数值、各等级的概率以及置信度。（非常适合客户挫败感、紧迫性、提示危害严重程度）。
3. noul：一个直接的布尔问题，返回校准后的概率 P(true)，范围从 0.0 到 1.0。（非常适合检测钓鱼、垃圾邮件、越狱或流失风险）。

由于输出空间严格限定为概率和数字，模型从不生成文本，不可能产生幻觉，并且从物理上不可能出现损坏的 JSON。

#### 3\. 模型架构：421M 参数

在我 2025 年 3 月的工作中，我使用了冻结的序列嵌入，并结合了一个独立的 PPO 价值网络。它在逐轮销售预测中有效，但它不是端到端的，并且无法在运行时处理动态的新问题。

对于 RL Agent，我们构建了一个 421M 参数的端到端架构，包含两个紧密耦合的组件：

```
State (Text or JSON) + Typed Questions & Options
                       │
                       ▼
Prompt Construction:
[CLS] <type> question: <instructions> [SEP] [MASK] opt0 [MASK] opt1 ... [SEP] <state> [SEP]
                       │
                       ▼
┌──────────────────────────────────────────────────────────────┐
│ ENCODER: ModernBERT-large (395M, Bidirectional)              │
│ • 28 layers, hidden dim 1024, 16 heads, GeGLU MLP            │
│ • Full sequence bidirectional attention across state and opts│
└──────────────────────────────┬───────────────────────────────┘
                               │ Hidden states [L × 1024]
                               ▼
               + Question-Type Embedding (choice=0, score=1, noul=2)
                               │
┌──────────────────────────────▼───────────────────────────────┐
│ DECISION HEAD TRANSFORMER (~25.2M parameters)                │
│ • 2 TransformerEncoder layers (d=1024, 16 heads, FFN=4096)   │
│ • Pre-LayerNorm, Dropout 0.1                                 │
└──────────────┬───────────────────────────────┬───────────────┘
               │                               │
               ▼ Extract [MASK] markers        ▼ Pooled [CLS] state
┌──────────────────────────────┐ ┌─────────────────────────────┐
│ OPTION SCORER (~1.05M)       │ │ ACT / ESCALATE HEAD (~0.26M)│
│ • LayerNorm(1024)            │ │ • Input: [CLS] (1024)       │
│ • Linear(1024 -> 1024)       │ │   + 4 distribution stats    │
│ • GELU()                     │ │ • Linear(1028 -> 256)       │
│ • Linear(1024 -> 1)          │ │ • GELU()                    │
│ Yields 1 scalar logit per opt│ │ • Linear(256 -> 2)          │
└──────────────┬───────────────┘ └─────────────┬───────────────┘
               │                               │
               ▼                               ▼
       Logits ÷ Temperature           P(Act) vs P(Escalate)
         -> Softmax                                  
               │
               ▼
 [ Probabilities + Confidence ]
```

##### ModernBERT-large Backbone

我们使用 ModernBERT-large（395M 参数）作为基础编码器。ModernBERT 有 28 层、隐藏维度 1024、16 个注意力头、GeGLU 中间层（维度 2624），并通过旋转位置嵌入（RoPE）支持 8,192 个 token。由于它是完全双向的，每个 token 都会同时关注状态和选项的所有部分。

##### \[MASK\]选项提取机制

对于每个问题，我们的 `build_sequence` 函数会打包提示词：

```
[CLS] choice question: Which team should handle `body`? [SEP]
[MASK] billing: payments [MASK] tech: bugs [MASK] other: general [SEP]
{"subject": "Refund request", "body": "I was billed twice..."} [SEP]
```

每个选项都会获得一个 `[MASK]` token。经过 ModernBERT 和 2 层决策头 transformer 处理后，我们使用 `torch.gather` 专门在这些标记位置提取隐藏状态。

Option Scorer MLP 将每个 1024 维标记状态投影为一个标量 logit。对属于该问题的选项进行 softmax 运算，得到候选概率分布：

```
p = softmax(z / T)
```

其中 T 是按问题类型和选项数量拟合的温度参数。

##### The Act vs Escalate Head

在真实的自动化系统中，你需要知道何时信任模型，何时调用人工。我们添加了一个 Act/Escalate 头，它接收池化的\[CLS\] token（1024 维）并与 4 个分布特征拼接：

- Top probability: max(p)
- Top-2 margin: p\_top1 - p\_top2
- 归一化熵：H(p) / log(K)
- Option budget ratio: K / 255

这个 1028 维向量通过一个 2 层 MLP 输出\[P(act), P(escalate)\]。

##### 单次前向传播处理多个问题

如果你有一封电子邮件，并针对它提出 5 个问题，那么这 5 个序列会被整理成一个批次。ModernBERT 在 GPU 上通过一次前向传播就能处理完它们，耗时大约 35 毫秒。

#### 4\. 使用 RLCD 进行训练：校准的数学原理

如何用强化学习来训练它，从而使概率真正得到校准？

##### 常规分类与朴素 RL 的陷阱

如果你用交叉熵训练一个分类器：

```
Loss_CE = -sum(y_k * log(p_k))
```

只有当获胜的 logit 趋近于无穷大时，损失才能被最小化。模型会变得过度自信。

而如果你尝试使用二元奖励（正确为 +1，错误为 0）的标准强化学习，期望奖励是：

```
E[R] = sum(y_k * p_k)
```

策略梯度会迫使最高概率趋近于 1.0，而所有其他概率趋近于 0.0。换句话说，朴素的强化学习通过破坏校准来最大化准确率。它会把你的模型变成一台自信地犯错的机器。

##### Strictly Proper Scoring Rules

RLCD（用于校准决策的强化学习）的基础是使用严格适当的评分规则作为奖励。

在决策理论中，评分规则 S(q, y) 在模型报告分布 q 且真实结果为 y 时分配一个分数。当且仅当 q 等于真实分布 p 时，期望分数唯一最大化，该评分规则才是严格适当的：

```
E_{y ~ p}[S(q, y)] <= E_{y ~ p}[S(p, y)], with equality if and only if q = p
```

这保证了模型只有在报告诚实概率时才能获得最高可能的奖励。

我们的复合奖励结合了三个适当的分数：

```
Reward(q, y) = S_log(q, y) + 0.5 * S_sph(q, y) - 1.0 * S_rps(q, y)
```

###### 1\. Logarithmic Score (S\_log)

```
S_log(q, y) = sum(y_k * log(max(q_k, 1e-12)))
```

如果模型对真实结果赋予低概率，就会受到严重惩罚。为了数值稳定性，我们将下限截断为 -9.21。

###### 2\. Spherical Score (S\_sph)

```
S_sph(q, y) = sum(y_k * q_k) / sqrt(sum(q_k^2))
```

一个位于 \[0, 1\] 范围内的有界分数，奖励将概率质量放在正确类上，同时避免纯对数损失的极端梯度尖峰。

###### 3\. 排序概率分数（S\_rps）

用于有序分数问题（如 0、1、2、3 这样的评分标准）。如果真实紧急程度是 3 级，猜 2 级比猜 0 级要好得多。RPS 衡量累积分布之间的平方距离：

```
S_rps(q, y) = (1 / (K - 1)) * sum((CDF_q(i) - CDF_y(i))^2)
```

从奖励中减去 RPS，教会模型在评分标准上的距离。

##### 策略梯度更新（带组基线的 REINFORCE）

我们使用纯策略梯度进行训练（零监督交叉熵损失）：

1. 高斯探索：对于每个问题，我们采样 G = 8 个带噪声的候选 logits：

```
z_noisy = z + epsilon, where epsilon ~ Normal(0, sigma^2)
```

我们将噪声向量投影，使其在所有选项上的和为零（epsilon - mean(epsilon)），因为在 softmax 中给所有 logits 加上一个常数会相互抵消。探索标准差 sigma 从 1.0 衰减到 0.3。

1. **Noisy Distribution**:

```
q_noisy = softmax(z_noisy)
```

1. **Reward Evaluation**:

```
r_noisy = Reward(q_noisy, y)
```

1. 组均值优势（GRPO 风格）：我们相对于 8 个样本的组均值计算优势：

```
Advantage = (r_noisy - mean(r)) / (std(r) + 1e-6)
```

1. 策略损失：使用高斯对数概率：

```
Loss_policy = -mean(Advantage * log_prob(z_noisy | z))
```

1. 成本敏感行动头：行动头在 {act, escalate} 中采样动作，并从成本矩阵中接收奖励：
   - Action correct: +1.0
   - Action incorrect: -3.0
   - Escalated: -0.5

只有在以下情况下，采取自动化行动才是有利可图的：

```
P(correct) * (+1.0) + (1 - P(correct)) * (-3.0) > -0.5 => P(correct) > 2.5 / 4.0 = 0.625
```

该策略会自动学习仅在置信度高于 62.5% 时才采取行动。

#### 5\. 使用 TD(lambda) 的多轮轨迹

在我 2025 年 3 月的论文中，我们使用 PPO 预测了跨轮次的销售转化。当时我们发现的一个重大问题是泄漏：如果你在第 1 轮就输入整个对话的嵌入，模型就会看到未来的信号。

在 RL Agent 中，我们干净利落地解决了这个问题：

- 对话按轮次逐一切分为前缀（第 1 轮、第 2 轮、第 3 轮……）。模型只接收截至该轮的上下文。
- 我们采用蒙特卡洛回报目标的时间差分学习（TD(lambda = 1.0)）：

```
G_T = y (terminal outcome)
G_t = (1 - lambda) * V(s_{t+1}) + lambda * G_{t+1}
```

当 lambda = 1.0 时，早期轮次直接针对对话的真实终端结果进行训练，学习哪些早期对话模式真正会导致转化或流失，而不依赖模型自身猜测进行自举。

---

#### 6\. 通过归一化熵衡量置信度

对于每个问题，模型返回一个介于 0.0 和 1.0 之间的置信度分数。我们使用归一化香农熵来计算：

```
Confidence = 1 - (Entropy(p) / log(K))
           = 1 + sum(p_k * log(max(p_k, 1e-12))) / log(K)
```

其中 K 是选项的数量：

- 如果模型完全不确定，所有选项的概率均为 1/K。熵等于 log(K)，因此置信度恰好为 0.00。
- 如果模型完全确定，一个选项的概率为 1.0，熵为 0，因此置信度为 1.00。

#### 7\. 数据集流水线：零合成捷径

许多团队试图通过让 LLM 生成合成训练问题和标签来构建这些模型。这是一个错误。当你用合成标签训练校准模型时，你只不过是在让模型去校准 LLM 自身的错误和幻觉。

我们使用 100%人工标注的真实世界公开数据集构建了训练流水线，涵盖：

- 支持分类与意图：真实的客户服务对话、银行意图和工单路由队列。
- 推理与事实核查：前提-假设对、事实核实和矛盾检查。
- 内容安全：针对有毒言论、骚扰和严重辱骂的人工共识标签。
- 安全与防护栏：真实的越狱提示和提示注入攻击。
- 评分标准与质量：针对有用性、复杂性和正确性的多轴人工评分标准评级。
- 多轮轨迹：SaaS 销售和支持交互，并带有已验证的最终结果。

为了阻止模型走捷径，我们的数据管道会动态打乱选项顺序、改写问题、在原始文本和嵌套 JSON 状态之间交替，并注入随机干扰问题。

#### 9\. How to Run It in Python

你可以使用我们的 PyPI 包一行代码直接运行 Laya：

```
pip install laya
```

##### Quickstart Code

```
import laya

# Download and load the fine-tuned model from Hugging Face
agent = laya.load("convaiinnovations/laya")

# Define your input state (raw text or JSON dict)
state = {
    "from": "user@company.com",
    "subject": "Charged twice on March invoice",
    "body": "Hi, we were billed twice for invoice 4411. Please refund the duplicate today or we will cancel our plan."
}

# Define your typed questions
questions = {
    "department": {
        "type": "choice",
        "instructions": "Which department should handle this email?",
        "criteria": {
            "billing": "invoices, payments, refunds",
            "technical": "bugs, outages, system errors",
            "sales": "pricing, new contracts",
            "other": "everything else"
        }
    },
    "urgency": {
        "type": "score",
        "instructions": "How urgent is this request?",
        "criteria": ["not urgent", "soon", "critical deadline or blocking issue"]
    },
    "churn_risk": {
        "type": "noul",
        "instructions": "Does the user threaten to cancel or leave?"
    },
    "is_phishing": {
        "type": "noul",
        "instructions": "Is this email a phishing or scam attempt?"
    }
}

# Run all questions in one single forward pass (~35 ms on GPU)
result = agent.predict(state, questions)
answers = result["answers"]

print("Department :", answers["department"]["choice"])
# -> billing (confidence: 0.94)

print("Urgency    :", answers["urgency"]["score"])
# -> 1.84 / 2.0

print("Churn Risk :", answers["churn_risk"]["noul"])
# -> 0.892 (89.2% probability)

print("Phishing   :", answers["is_phishing"]["noul"])
# -> 0.008 (0.8% probability)
```

##### Automated Gating Logic

因为概率经过数学校准，路由逻辑就是简单的代码：

```
dept = answers["department"]["choice"]
conf = answers["department"]["confidence"]

if conf >= 0.85:
    route_automatically(dept)
else:
    send_to_human_triage(dept, reason=f"Low confidence ({conf:.2f})")
```
