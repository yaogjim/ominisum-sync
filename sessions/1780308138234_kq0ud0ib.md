##### 一、总结

这条内容主要说：  
Anthropic 的 workshop 难得之处在于，直接拆解了他们内部使用 Claude / Claude Code 的方法。

重点包括：

1. **Prompt 怎么组织**
2. **Context 上下文怎么管理**
3. **Role 角色怎么设定**
4. **示例怎么提供**
5. **输出格式怎么约束**
6. **多轮任务怎么拆解**

同时引用了一篇关于 **CLAUDE.md** 的文章，核心观点是：

> 不要把所有信息都塞进 CLAUDE.md，否则 Claude 会在冗长上下文里迷失。  
> CLAUDE.md 应该精简、结构化、只放真正有用的项目规则。

---

##### 二、解读

###### 1. Prompt 不是越长越好

很多人以为提示词写得越多，AI 越懂。  
其实不是。

更好的方式是：

- 目标清楚
- 约束明确
- 信息分层
- 不塞无关背景

简单说：

> 给 AI 的不是“资料堆”，而是“任务说明书”。

---

###### 2. Context 要管理，不是乱塞

AI 编程最怕上下文混乱。

比如你把这些都塞进去：

- 项目历史
- 技术选型原因
- 老代码说明
- 个人习惯
- 公司文化
- 未来规划

结果 AI 反而不知道该优先听谁的。

更合理的是：

```md
## 项目结构
## 编码规范
## 常用命令
## 禁止事项
## 当前任务相关背景
```

---

###### 3. Role 设定要服务任务

“你是资深工程师”这种角色设定有用，但不够。

更好的写法是：

> 你是一个熟悉 React、TypeScript 和大型前端项目维护的工程师。  
> 请优先保证代码可维护性，不要引入新依赖。

角色要具体，不能空泛。

---

###### 4. 示例比抽象要求更有效

不要只说：

> 代码要优雅。

而要给例子：

```ts
// 推荐写法
function getUserName(user: User) {
  return user.name ?? 'Unknown'
}
```

AI 更擅长模仿明确样例。

---

###### 5. 输出要约束格式

如果不约束，AI 可能输出一堆解释。

可以直接要求：

```md
请按以下格式输出：

1. 修改方案
2. 影响范围
3. 代码改动
4. 测试建议
```

这样结果更稳定。

---

###### 6. 多轮任务要拆开做

不要一次让 AI：

> 分析项目、找问题、重构代码、写测试、生成文档。

更好的流程是：

1. 先让它理解项目
2. 再让它提出方案
3. 确认后再改代码
4. 最后补测试和文档

AI 编程不是“一口吃完”，而是“分步协作”。

---

##### 三、我的意见

这条内容的价值在于提醒大家：

> 用好 AI 编程，关键不是会不会写神奇 Prompt，  
> 而是会不会管理信息、拆解任务、约束输出。

尤其是 **CLAUDE.md**，不要写成项目百科全书。  
它更应该像一份简洁的“开发协作说明”。

我建议这样写：

```md
# CLAUDE.md

## 项目简介
一句话说明项目是做什么的。

## 技术栈
列出主要框架、语言、工具。

## 代码规范
说明命名、目录、风格要求。

## 常用命令
如安装、启动、测试、构建。

## 注意事项
哪些文件不能改，哪些依赖不能加。

## 当前优先级
当前最重要的开发目标。
```

一句话总结：

> AI 不是读心术工具，而是执行力很强的协作者。  
> 你给的信息越清楚，它产出的结果越可靠。
