## 分析要点

- **核心高价值点**：将公司研究从一次性报告转为由 Agent 驱动、可持续更新并可交叉验证的研究记忆系统。
- **留存建议**：值得精读并长期保留，适合作为 AI 市场研究和知识库建设的参考框架（文章提出了可持续更新的 AI 公司研究循环、结构化研究记忆和多源信号交叉验证方法，与 AI 产品、Agent 开发及知识管理高度相关。）

**知识要点**

- 研究输入可以从公司、融资消息、投资人或产品线索出发，并沿产品、创始人、融资、技术、流量、GTM、社区和竞品关系等维度扩展。
- 结构化对象、可读的 Markdown 正文和关系图谱结合后，可以让人和 Agent 共同维护长期研究记忆。
- Similarweb 更适合观察流量的量级、结构和趋势，必须与官网、文档、GitHub、融资报道及社区讨论交叉验证。

**行动项**

- 为 AI 公司研究设计一个可重复的 research loop，并固定产品、融资、技术、流量和竞品等调查维度。
- 用结构化对象记录公司、人物和来源，同时保留 Markdown 研究正文及对象间关系。
- 将第三方流量数据与官方资料、文档、GitHub 和社区反馈交叉验证，避免把流量估算直接当作结论。

**yan5xu**

分享一个我最近整理的AI公司研究库：Oh My AI Company。  
bb-browser 被收购之后，作为 co-founder，我有一项很重要、也很耗时间的工作，就是持续跟进市场方向：新的产品形态在往哪里发展，哪些技术正在成熟，企业真正愿意为什么付费，谁在融资、谁在增长，以及哪些公司是竞品、哪些只是相邻方向。

过去这些信息主要来自 X、微信公众号、公司博客和日常 feed。每看到一家有意思的公司，我都要自己做大量 deep research。这个方式能看得深，但受限于个人时间，很难持续覆盖足够大的市场范围。

所以我开始思考，能不能让 agent 接手其中一部分工作。  
慢慢地，这套过程形成了一个 research loop：输入一家新公司、一条融资消息、一个投资人或产品线索，agent 会继续沿着产品、创始人、融资与投资机构、技术和 docs、流量与 GTM、社区反馈、竞品关系等方向展开。最终输出的不是一篇孤立的报告，而是一张可以继续生长的小型市场地图。

随着调研量增加，我们又遇到了新的问题：这些公司、人物、来源和判断如果只是散落在聊天记录或 Markdown 里，下一轮仍然很难复用。  
Memex 也是在这个过程中开发出来的。我们需要的不只是一个笔记工具，而是一套可以让人和 agent 共同维护长期研究记忆的基础设施：用结构化对象保存公司、人物和来源，用 Markdown 保留可读的研究正文，再通过图谱关系把它们连接起来。

这个库里还有一类外面比较少见的数据：Similarweb 流量分析。  
我并不是用它简单比较哪个公司流量更大，而是用第三方流量信号辅助判断：  
一个产品是否已经形成真实访问规模，还是只有融资和 PR 声量；  
增长来自 SEO、投放、社区、LinkedIn、Product Hunt，还是媒体传播；  
用户在搜索品牌名、具体需求，还是竞争产品；  
看起来相似的公司，究竟是直接竞品、相邻产品，还是受众重合带来的噪声。

例如，我们最初想判断 Viktor 的增长是否主要来自融资 PR。流量结构显示，它更像是 PR、搜索、社交、付费投放共同推动的启动，而且大量官网访问继续进入产品 App，并不只是内容曝光。  
再比如 Browserbase、Hyperbrowser 和 Browserless，表面上都属于 browser execution，但结合流量来源、搜索词、GitHub、Docs 和社区信号后，可以进一步区分出开发者 agent infra、早期开发者 GTM，以及更成熟的 scraping/browser automation infrastructure。它们不能简单放进同一个竞品桶里。  
Similarweb 当然只是第三方估算，更适合观察量级、结构和趋势，不能代替官方数据或一手用户验证。所以库里也会把流量数据与官网、文档、GitHub、融资报道和社区讨论交叉验证。

积累到现在，AI Company Atlas 已经整理了：  
75 家 AI 公司和产品  
75 位投资人或投资机构  
111 位创始人、投资人、记者和关键从业者  
227 个持续跟踪入口  
重点覆盖 AI 产品、AI infra、企业 Agent、Browser/Agent Infra 和垂直 AI。  
它不是公司排行榜，也不是几篇一次性的行业报告，更像一张持续更新的 market map。

我还会继续更新。如果有人也在做 AI 产品、Agent 或相关研究，可以直接拿去使用。发现信息错误，或者有值得继续跟进的公司，也欢迎告诉我或直接提 Issue / PR。

#### 文章总结

作者分享了一个持续更新的 AI 公司研究库 **Oh My AI Company（AI Company Atlas）**。该项目利用 Agent 自动扩展研究线索，并结合 Memex、知识图谱和 Similarweb 流量数据，构建可长期复用的 AI 市场地图。

##### 1. 为什么要建立 AI 公司研究库

- bb-browser 被收购后，作者作为联合创始人，需要持续追踪：
  - 新产品形态和技术成熟度；
  - 企业的真实付费需求；
  - 公司融资、增长与竞争关系。
- 过去的信息主要来自 X、微信公众号、公司博客和日常信息流，每发现一家新公司，都要手动进行深度研究。
- 这种方式虽然研究得深，但受个人时间限制，难以长期、大范围覆盖市场，因此作者开始尝试让 **Agent 接手部分工作**。

##### 2. 用 Agent 建立自动扩展的研究闭环

输入一家新公司、融资消息、投资人或产品线索后，Agent 会沿多个方向继续调查：

- 产品与创始人；
- 融资情况和投资机构；
- 技术、文档与 GitHub；
- 流量、市场进入策略（GTM）；
- 社区反馈与竞品关系。

最终产出的不是一篇孤立报告，而是一张能够随着新信息不断扩展的 **小型市场地图**。

##### 3. 用 Memex 保存长期研究记忆

随着研究量增加，聊天记录和 Markdown 文件中的信息越来越分散，难以在下一轮研究中复用。

因此，作者开发了 **Memex**，让人和 Agent 可以共同维护长期研究记忆：

- 用结构化对象保存公司、人物和信息来源；
- 用 Markdown 保留易读的研究正文；
- 用图谱关系连接公司、人物、投资机构和其他线索。

它不只是笔记工具，更是一套面向长期研究的基础设施。

##### 4. 用 Similarweb 判断真实增长与竞争关系

研究库还引入了较少见的 **Similarweb 流量分析**，但目的不是简单比较谁的流量更高，而是辅助判断：

- 产品是否拥有真实访问规模，还是只有融资和公关声量；
- 增长来自 SEO、广告投放、社区、LinkedIn、Product Hunt，还是媒体传播；
- 用户搜索的是品牌名、具体需求，还是竞争产品；
- 相似公司究竟是直接竞品、相邻产品，还是仅仅受众重合。

###### 案例一：Viktor 的增长来源

作者最初怀疑 Viktor 的增长主要来自融资公关，但流量结构显示：

- 增长由 PR、搜索、社交和付费投放共同推动；
- 大量官网访问会继续进入产品 App；
- 因此其增长不只是媒体曝光，也包含较真实的产品使用意图。

###### 案例二：三家 Browser Infra 公司的差异

Browserbase、Hyperbrowser 和 Browserless 表面上都属于 **browser execution**，但结合流量来源、搜索词、GitHub、产品文档和社区信号后，可以发现它们分别更偏向：

- 开发者 Agent 基础设施；
- 面向早期开发者的 GTM；
- 更成熟的爬取与浏览器自动化基础设施。

因此，三者不能被简单归入同一个“竞品桶”。

##### 5. 第三方数据需要交叉验证

Similarweb 提供的是第三方估算，更适合观察：

- 流量量级；
- 来源结构；
- 增长趋势。

它不能替代公司官方数据或真实用户验证。因此，研究库会将流量信息与官网、产品文档、GitHub、融资报道和社区讨论进行交叉验证，以减少误判。

## 口播总结（1）

### 2026-08-03 01:28:30

#### 这份 AI 公司研究库，解决了什么问题

这份材料介绍了一个持续更新的 AI 公司研究库，以及它背后的研究方法。你可以从中了解：为什么要用智能代理，也就是 agent，来辅助市场调研；怎样把零散信息整理成长期可复用的研究记忆；以及如何用流量、搜索、文档和社区反馈，判断一家公司的真实发展情况。

#### 首先：传统调研看得深，但很难覆盖足够广

核心结论是，个人做 AI 市场研究时，最大的问题不是找不到信息，而是很难持续跟进足够多的公司和方向。

这套研究库的发起人是 bb-browser 的联合创始人。在公司被收购之后，他的一项重要工作，就是持续观察市场变化。比如，新的产品形态正在往哪里发展，哪些技术逐渐成熟，企业到底愿意为什么付费，哪些公司正在融资或增长，以及哪些公司是真正的竞品。

过去，这些信息主要来自 X、微信公众号、公司博客和日常信息流。每看到一家有意思的公司，都需要自己做大量深入研究。这样做的好处是看得比较深，但问题也很明显：研究完全受个人时间限制，很难覆盖整个市场。

因此，他开始思考，能不能让 agent 接手其中一部分工作。这里的 agent，可以理解为能够根据目标，自动搜索、整理和继续追踪信息的智能助手。

#### 接下来：研究过程被做成了一条循环流程

核心结论是，这套方法并不是让 agent 写一篇孤立的报告，而是让它围绕一个线索不断扩展，最后形成一张可以继续生长的市场地图。

具体来说，研究可以从一家新公司、一条融资消息、一个投资人，或者一个产品线索开始。Agent 接下来会继续调查多个方向。

它会看公司的产品和创始人，也会看融资情况以及背后的投资机构。除此之外，还会查看技术资料和文档，分析流量和获客方式，了解社区反馈，并判断它和其他公司的竞品关系。

这样得到的结果，就不只是“这家公司是做什么的”这样一篇介绍，而是一组相互关联的信息。新的公司、人物、产品和来源，都可以继续接入这张地图，成为下一轮研究的起点。

不过，研究量增加之后，又出现了一个新问题：如果这些公司、人物、来源和判断，只是散落在聊天记录或者 Markdown 文件里，下一次研究时仍然很难复用。

#### 更重要的是：Memex 用来保存长期研究记忆

核心结论是，Memex 的目标不是做一个普通笔记工具，而是建立一套人和 agent 可以共同维护的长期研究基础设施。

通俗地说，它把研究资料拆成几个可以持续更新的部分。公司、人物和来源，会用结构化对象保存。研究正文，则继续用 Markdown 保存，方便人阅读。不同对象之间，还会通过图谱关系连接起来。

这样一来，某家公司对应哪些创始人，拿过哪些融资，使用了哪些技术，和哪些竞品有关，都可以被保存成相互连接的研究记忆。

这解决的不只是“把资料放在哪里”的问题，也让后续的 agent 能够在已有研究的基础上继续工作，而不是每次都从零开始。

#### 然后：流量数据用来判断真实增长，而不是简单比大小

核心结论是，这个研究库还加入了一类比较少见的数据：Similarweb 的流量分析。

Similarweb 可以理解为一种第三方网站流量估算工具。这里并不是简单比较哪家公司访问量更大，而是把流量信号当作辅助判断市场情况的证据。

它主要帮助回答几个问题。

第一，一款产品到底已经形成了真实的访问规模，还是只有融资新闻和公关传播带来的声量。

第二，增长主要来自哪里。可能是搜索引擎优化，也就是 SEO；可能是广告投放、社区、LinkedIn、Product Hunt，或者媒体传播。

第三，用户在搜索什么。用户可能是在搜索品牌名称，也可能是在搜索某个具体需求，或者直接搜索竞争产品。

第四，两家看起来相似的公司，到底是真正的直接竞品，还是只是产品相邻，或者因为目标受众重叠而产生了表面上的相似。

这里有一个具体案例。研究团队一开始想判断 Viktor 的增长，是否主要来自融资公关。流量结构显示，它更像是由多种因素共同推动，包括公关传播、搜索、社交渠道和付费投放。而且，大量官网访问还会继续进入产品应用，并不只是停留在内容曝光层面。

另一个案例是 Browserbase、Hyperbrowser 和 Browserless。它们表面上都属于 browser execution，也就是让软件能够调用和执行浏览器操作的基础设施。

但结合流量来源、搜索词、GitHub、产品文档和社区信号之后，可以看出它们的定位并不完全相同。有的更接近开发者使用的 agent 基础设施，有的还处在早期开发者获客阶段，还有的更接近成熟的网页抓取和浏览器自动化基础设施。

所以，这几家公司不能简单地被放进同一个“竞品”分类里。

当然，Similarweb 只是第三方估算工具。它更适合观察访问量级、流量结构和变化趋势，不能替代公司的官方数据，也不能替代对真实用户的直接验证。

因此，这个研究库还会把流量数据和官网、技术文档、GitHub、融资报道以及社区讨论放在一起交叉验证。这样做，是为了避免只根据单一数据源下结论。

#### 最后：这已经是一张持续更新的 AI 市场地图

核心结论是，这个项目目前已经从个人调研流程，发展成了一张持续更新的 AI 市场地图。

到目前为止，AI Company Atlas，也就是这套 AI 公司研究库，已经整理了七十五家 AI 公司和产品，七十五位投资人或投资机构，以及一百一十一位创始人、投资人、记者和关键从业者。

同时，库里还有二百二十七个持续跟踪入口。这里的入口，可以理解为值得继续观察的网站、账号、文档、项目或其他信息来源。

它重点覆盖几个方向，包括 AI 产品、AI 基础设施、企业 Agent、浏览器和 Agent 基础设施，以及垂直领域的 AI 应用。

这个项目不是公司排行榜，也不是几篇写完就结束的一次性行业报告。它更像是一张会不断补充新节点、更新旧信息的市场地图。

研究发起人还会继续更新这个库。正在做 AI 产品、Agent 或相关研究的人，可以直接使用它。如果发现信息错误，或者有值得继续跟进的公司，也可以反馈，或者直接提交 Issue 和 PR，也就是提出问题和修改请求。

#### 结尾回顾：最值得记住的四件事

第一，个人做市场研究时，最大限制往往是时间。深入研究一家公司并不难，难的是长期覆盖足够大的市场范围。

第二，Agent 的价值不只是自动写报告，而是围绕公司、产品、创始人、融资、技术和竞品关系，持续扩展研究线索。

第三，真正有用的研究记忆，需要被结构化保存，并通过关系连接起来。这样人和 agent 才能在过去的研究基础上继续工作。

第四，流量数据不能单独证明一家公司的真实情况，但结合搜索词、流量来源、GitHub、文档和社区反馈，可以更好地判断增长来源、产品定位和竞品关系。

总体来说，这套 AI Company Atlas 想做的，不是一份静态名单，而是一套能够持续积累、持续验证、也持续生长的 AI 市场研究系统。

#### AI 市场研究的瓶颈，正从信息搜集转向“可复用的判断系统”

这份分享最值得关注的，不是它收录了 75 家 AI 公司，而是展示了一种更适合高变化市场的研究方式：**让 Agent 扩大调查范围，让结构化记忆保存上下文，再由人完成证据权衡与判断。**

传统行业研究通常以报告为终点。但 AI 市场变化太快，一篇报告发布时，融资、产品定位、增长渠道和竞争关系可能已经改变。作者设计的 research loop 则从公司、融资消息或投资人等线索出发，继续追踪创始人、技术文档、流量、GTM、社区反馈与竞品关系，最终形成一张可继续扩展的市场地图。研究成果不再是静态结论，而是一组能被更新、连接和重新调用的对象。

##### Agent 的价值不只是搜索，而是维持研究连续性

一次性的深度搜索已经不难，真正昂贵的是连续研究：上次查过什么、依据来自哪里、哪些判断已经被新证据推翻，以及一家新公司会改变地图中的哪些关系。

因此，Memex 所解决的问题比“AI 笔记”更具体：公司、人物和来源以结构化对象保存，正文用 Markdown 保持可读，实体之间再通过图谱连接。这样，一条新融资消息不必从零研究，而可以自动关联既有公司、投资机构、产品类别和历史判断。

这揭示了 Agent 产品的一个重要边界：**模型可以降低信息展开的成本，但如果缺少稳定的数据模型、来源记录和更新机制，产出仍会退化成更多难以复用的文本。** 对企业知识管理、竞品分析、投研和用户研究而言，机会可能不在“再生成一份报告”，而在把检索、证据、对象关系与版本变化组织成长期工作流。

##### 流量数据的意义，是检验叙事而非排列名次

作者对 Similarweb 的使用也很有启发。流量不是简单的公司热度榜，而是用来拆解更具体的问题：增长来自融资 PR、搜索、社区还是付费投放；访问者是在找品牌、解决方案还是竞品；官网曝光是否继续转化为产品访问。

例如，Viktor 的流量结构被用来修正“增长主要来自融资宣传”的猜测；Browserbase、Hyperbrowser 和 Browserless 虽然都属于 browser execution，但结合搜索词、GitHub、文档和社区信号后，可以区分开发者 Agent 基础设施、早期开发者 GTM 与成熟的自动化基础设施。**竞品判断不能只看功能标签，还要看用户意图、获客方式和产品成熟度。** 这对产品经理尤其重要：表面相似不等于争夺同一预算，受众重合也不等于直接替代。

当然，Similarweb 是第三方估算，只适合观察量级、结构和趋势；作者也明确需要与官网、文档、GitHub、融资报道和社区讨论交叉验证。整个项目目前更多证明了方法可行，而非数据质量已经可靠——75 家公司的覆盖量不能替代更新频率、来源可信度和人工校验率。

真正值得验证的产品命题是：当 Agent 能低成本扩展调查后，用户是否愿意为**持续更新、证据可追溯、关系可复用的市场记忆**付费。未来研究工具的差异，可能不再是谁写报告更快，而是谁能让判断随着新证据持续进化。
