开源 Multica：专为 AI-native 团队设计的 Agent + 人的协作平台

[github.com/multica-ai/mul…](https://github.com/multica-ai/multica/)

**为什么做 Multica？**

Multica 最初是为了解决我们团队自己的问题：

1. 团队间的知识无法共享。 每个人都在用 coding agent，但产出的上下文全部散落在各自的 agent session 里。A 做完了一件事，B 不知道；agent 跑完了一轮，结果只有发起人看得到。团队知识变成了一座座孤岛。
2. 多人 + 多 Agent 的协作缺乏中枢。 当团队同时有多个 agent 在跑任务，谁在做什么、做到哪了、卡住了没有——没有一个地方能看到全貌。人和 agent 之间、agent 和 agent 之间，缺少一个共同的协作界面。

**Multica 是什么？**

一句话：像 Linear 一样管理任务，但 AI agent 是一等公民。

你可以像分配任务给同事一样，把 issue 分配给 agent。agent 会自动领取任务、在你的本地机器上执行代码、提交结果、更新状态、发表评论——一切都发生在同一个看板里，所有人实时可见。

核心思路很简单：每个人把自己的 coding agent（Claude Code / Codex）注册到团队 workspace，之后就可以像分配任务给同事一样分配给 agent。agent 自动执行、更新状态、发表评论，所有人实时可见。

**适合谁？**

- 1-10 人的 AI-native 小团队
- 正在大量使用 coding agent 但缺少协作中枢的团队
- 希望让 agent 融入日常工作流而不是当作独立工具的团队

官网: [https://t.co/sdFwgJM8KU](https://t.co/sdFwgJM8KU)

欢迎 star、试用、提 issue，也欢迎 PR。

1）创建 Workspace

有两种方式，最简单的是直接使用 [multica.ai](http://multica.ai) 的云服务，另一种就是自己通过 docker 的方式来部署，需要一些动手能力。

创建完了就会有一个空的 workspace。

![](https://pbs.twimg.com/media/HEzUTTjaoAAdP-7.jpg?name=orig)

2）连接本地 or 云端的 Agent Runtime

在运行了你的 agent 的机器（例如本机 or 一台专用的 mac mini）安装 multica cli。

brew tap multica-ai/tap

brew install multica-cli

然后进行鉴权并注册本地的算力到 workspace 中：

multica login

multica daemon start

连接成功之后就可以在 Runtime

![](https://pbs.twimg.com/media/HEzVVqCboAE0jVn.jpg?name=orig)

3）创建你的第一个 AI 员工

在 Agents 页面可以直接创建对应的 AI 员工并选择运行的机器（runtime）。

每个 Agent 都有自己独立的记忆、设置，可以理解就是一个员工的角色。

例如这里我们给 Multica 创建了一个 SRE 工程师，专门负责 Multica 服务的部署工作。

![](https://pbs.twimg.com/media/HEzVuwebsAAs4iM.jpg?name=orig)

4）分配任务给 Agent

让这个 AI 员工直接帮我们部署一下服务，只需要创建一个 issue 分配给它即可。

![](https://pbs.twimg.com/media/HEzWXazbQAAVA_7.jpg?name=orig)

这是 Multica 这个项目的任务 Kanban，整个 Multica 项目就是使用 Multica 来开发的。

![](https://pbs.twimg.com/media/HEzWuzpakAAZm7g.jpg?name=orig)

## 结构化（1）

### 2026-04-03 06:42:32

#### 开头概括

Multica 是一个面向 AI-native 小团队的开源协作平台，核心目标是把分散在个人 agent 会话里的知识和任务流程统一到一个团队协作中枢里。  
它的定位可以理解为 “像 Linear 一样管理任务，但把 AI agent 当作团队正式成员来协作”。

##### 一、为什么要做 Multica

- 文章先指出了团队在使用 coding agent 时的两个核心痛点：
  - **知识无法共享**：每个人都在用 agent，但上下文散落在各自 session 中，别人看不到过程和结果。
  - **多人 + 多 Agent 缺少协作中枢**：当多个 agent 同时跑任务时，团队很难统一看到 “谁在做什么、进度如何、是否卡住”。

- 作者用很直白的场景说明问题：
  - A 做完了一件事，B 不知道；
  - agent 跑完一轮，结果只有发起人能看到；
  - 最终团队知识变成一座座 “孤岛”。

- 本质上，Multica 想解决的不是单个 agent 能不能写代码，而是**团队如何围绕多个 agent 高效协作**。

##### 二、Multica 是什么

- 用一句话概括：
  - **Multica = 像 Linear 一样管理任务，但 AI agent 是一等公民。**

- 它支持的协作方式是：
  - 像给同事派任务一样，把 issue 分配给 agent；
  - agent 自动领取任务；
  - 在本地机器执行代码；
  - 提交结果、更新状态、发表评论；
  - 整个过程都在同一个看板中实时可见。

- 核心设计思路很简单：
  - 团队成员把自己的 coding agent（文中举例：**Claude Code / Codex**）注册到团队 workspace；
  - 之后 agent 就能像 “AI 员工” 一样参与日常工作流，而不是作为孤立工具存在。

##### 三、适合什么团队

- 文中明确给出了适用人群：
  - **1-10 人的 AI-native 小团队**
  - 已经大量使用 coding agent，但缺少统一协作中心的团队
  - 希望把 agent 融入日常工作流，而不是单独使用的团队

- 这说明 Multica 并不是面向所有公司，而是更适合：
  - 团队规模不大；
  - agent 使用频率高；
  - 对协作透明度和知识沉淀要求高的场景。

##### 四、Multica 的使用方式

###### 1. 创建 Workspace

- 有两种方式：
  - 直接使用`multica.ai`的云服务；
  - 自己通过`docker`部署。

- 创建完成后，会得到一个空的 workspace，作为团队协作的基础空间。

###### 2. 连接本地或云端 Agent Runtime

- 在运行 agent 的机器上安装`multica cli`，比如本机或一台专用的`mac mini`。
- 文中给出的安装命令是：

```bash
brew tap multica-ai/tap
brew install multica-cli
multica login
multica daemon start
```

- 完成鉴权和注册后，本地算力就会接入 workspace，成为可调度的 runtime。

###### 3. 创建第一个 AI 员工

- 在 Agents 页面中，可以创建一个具体的 agent，并选择它运行在哪台机器上。
- 每个 Agent 都有：
  - 独立记忆
  - 独立设置
  - 独立角色定位

- 文中举的例子是：
  - 创建了一个**SRE 工程师角色的 AI 员工**
  - 专门负责**Multica 服务部署工作**

###### 4. 给 Agent 分配任务

- 使用方式和给人派任务类似：
  - 创建一个 issue；
  - 直接分配给某个 agent。

- 文中的具体案例是：
  - 让这个 AI 员工帮忙部署服务；
  - 只需要在系统里创建 issue 并指派给它即可。

- 作者还提到一个很有代表性的案例：
  - **Multica 这个项目本身，就是使用 Multica 来开发的。**
  - 这相当于用自己的产品管理自己的研发流程，说明它已经被拿来做真实协作验证。

##### 五、这款产品的关键价值

- 从文章逻辑看，Multica 的核心价值主要有 3 点：
  - **任务透明**：所有人都能实时看到 agent 在做什么。
  - **知识沉淀**：不再只有发起人知道 agent 做过什么，团队可以共享上下文。
  - **人机协作统一**：人和 agent、agent 和 agent 可以在同一套看板和任务系统里协同。

- 换句话说，它想解决的不是 “让 agent 更聪明”，而是 “让 agent 更像团队成员，能被管理、被协作、被追踪”。

##### 六、文章结尾传达的信息

- 文章最后给出了明显的开源项目信号：
  - 提供官网入口；
  - 欢迎用户**star、试用、提 issue、提交 PR**。

- 这说明 Multica 当前处在积极吸引开发者和早期团队参与的阶段，重点是：
  - 让更多 AI-native 团队试用；
  - 收集反馈；
  - 通过开源社区完善产品。

#### 总结

Multica 关注的不是 “单个 AI agent 的能力”，而是 “团队如何围绕多个 agent 高效协作”。  
它通过 workspace、runtime、AI 员工和任务看板，把原本零散的 agent 使用方式，变成一个对团队可见、可分工、可追踪的协作系统，尤其适合**1-10 人、重度使用 coding agent 的 AI-native 小团队**。
