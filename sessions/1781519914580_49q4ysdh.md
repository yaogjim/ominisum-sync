## 通俗精炼（1）

### 2026-06-15 10:38:02

#### 便宜模型 + 对抗性审查，可能成为 AI 编程主流范式

##### 核心观点

未来多数 AI 编程场景中，用户可能不会长期依赖单一昂贵模型，而是转向：

> **便宜模型负责产出 + 另一个模型进行对抗性审查**

这种方式可以在显著降低成本的同时，获得接近甚至超过昂贵模型的效果。

##### 可能的演进路径

作者认为会有一个过渡阶段：

1. **早期阶段**  
   使用 Claude Code 与 Codex 互相对抗、审查。

2. **中期阶段**  
   组合可能变成：
   - Claude Code + DeepSeek
   - Codex + DeepSeek

3. **长期阶段**  
   随着开源模型能力提升，以及用户自身工作流、评测和 harness 能力增强，开源模型之间的联合对抗将能完成大多数任务。

##### 昂贵模型的角色变化

即便便宜模型和开源模型承担大部分日常工作，昂贵模型仍有价值。

它们更可能成为“救火员”：

- 处理复杂疑难问题
- 修复关键错误
- 在便宜模型失效时兜底
- 做高风险决策或最终审查

##### 成本驱动是关键原因

引用内容提到，Claude Fable 消耗订阅配额且 API 成本很高，团队单日支出曾超过 2000 美元。

因此，更现实的方案是：

> 用低成本模型形成循环，通过互相批判、修正、审查来提升最终结果。

##### 对 AI Coding 的提醒

热门回复强调：真正难的不是让模型疯狂写代码，而是保持克制。

在开始 coding 前，agent 应该先思考：

- 这个需求真的存在吗？
- 标准库是否已经支持？
- 平台原生能力是否已经具备？
- 依赖中是否已有实现？
- 能否通过配置解决？
- 能否减少一层抽象？
- 能否只写一行代码？

##### 总结

这篇内容的核心判断是：

> AI 编程的未来，不一定是“最强模型包打天下”，而是“低成本模型组合 + 对抗性审查 + 昂贵模型兜底”。

真正高质量的代码，不只是模型能力强，更来自于需求克制、架构判断和避免不必要的复杂度。
