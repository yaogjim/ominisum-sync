## 分析要点

- **核心高价值点**：共享状态、隔离问题分支的注意力设计支持多问题打包推理；文档报告打包与分开推理的最大概率差为3.7e-6、速度约提升2倍，为兼顾吞吐与问题间隔离提供了具体实现参考。
- **留存建议**：精读并存档，作为轻量决策组件实现与评估的参考，不作为生产可靠性的证明（提供具体架构、训练配置、复现命令、校准指标及机制测试，可复用于本地决策模型实验和评估清单设计。）

**知识要点**

- 类型化决策可通过读取&lt;decide&gt;与各选项结束位置的隐藏状态并计算softmax实现，再分别映射为选择结果、是非概率或等级期望，无需生成完整答案文本。
- 模型输出的confidence不等于经验证的正确概率；同来源留出集上的校准结果不足以支持陌生任务中的重大决策阈值。
- 选项顺序与新增干扰选项应纳入决策模型评估：该检查点报告了7.4%的排列后argmax翻转，且尚未采用当前代码默认的排列一致性与序数损失。

**行动项**

- 开展复现实验时使用文档给出的训练参数：--n\_per\_source 1500 --epochs 2 --accum 8 --perm\_kl 0 --ord\_w 0，并记录当前逐轮重做增强导致的非逐位复现差异。
- 在自有标注集上测量准确率、ECE和NLL，并测试选项重排、追加无关选项及问题隔离，再判断概率输出是否适合目标任务。
- 使用python -m kev.serve --run runs/kev启动本地研究服务，通过POST /v1/systemone验证Choice、Noul和Score接口，不用于影响人员的生产决策。

#### Model details

Developed by Jared Palmer，与 Devin（Cognition）合作

Model type 因果 transformer，仅预填充，块因果分支掩码，指针读出

Base model `Qwen/Qwen2.5-0.5B` (494M parameters, frozen)

Adapter LoRA 秩 16，alpha 32，dropout 0.05，作用于 `q_proj k_proj v_proj o_proj gate_proj up_proj down_proj` （全部 24 层）

Head 两个线性映射 `896 → 256` （查询来自 `<decide>` ，键来自每个 `</opt>` ），缩放点积，对选项进行 softmax

Trainable parameters 9.3M（LoRA 8.8M + 头部 0.46M），占主干网络的 1.9%

Precision fp32（在 Apple MPS 上进行训练和推理）

Context used in training ≤ 384 个状态 token，每个问题分支 ≤ 1,024 个 token

Context allowed at serving 每个分支 8,192 个（主干支持 32k）

Question types `noul` （是/否）， `choice` （2–255 个选项）， `score` （2–255 个有序等级）

Language English

License 适配器和头部采用 Apache-2.0 许可证。基础模型遵循 Qwen 许可证（Qwen2.5-0.5B 采用 Apache-2.0）。数据集各自带有自己的许可证。

Version `kev-0.5b` v0.1, trained 2026-09-17

#### Intended use

预期用途。决策模型研究：直接概率读数的校准、共享状态/隔离问题注意力、选项顺序敏感性，以及与 TypeSafe 的 System One 契约的 API 级兼容性。本地演示和教学。

非预期用途。任何影响人员的生产决策：审核、欺诈、信用、招聘、医疗或法律路由。该模型的知识仅限于 0.5B 主干，其校准仅在训练分布上得到验证，其在陌生任务上的输出尚未经过测量。

输入是一个打包的 token 序列：

```
<state> …state…  <q> instr <opt> o1 </opt> <opt> o2 </opt> … <decide>  <q> … <decide>  …
```

- 注意力掩码让一个问题 token 只能看到状态及其自己的分支。问题之间无法相互看到。
- 每个分支在状态之后重新开始位置 id。
- 对于每个问题，头部会对每个 `</opt>` 隐藏状态与 `<decide>` 隐藏状态进行评分，并应用 softmax。
- 应用代码将分布转换为 API 答案：Choice 使用 `choice` / `confidence` ，Noul 使用 `p(yes)` ，Score 使用期望等级。

保留 token 是现有的 Qwen 特殊 token（ `<|fim_prefix|>` 、 `<|fim_middle|>` 、 `<|box_start|>` 、 `<|box_end|>` 、 `<|fim_suffix|>` ）。用户文本经过清理，因此无法生成这些 token。

使用 `python -m kev.serve --run runs/kev` 提供服务并调用 `POST /v1/systemone` ，或使用 `typesafe-sdk` 搭配 `base_url="http://127.0.0.1:8009"` 。

#### Training data

六个公开数据集，转换为 TypeSafe 形状的请求，并使用与 serving 时相同的代码路径进行渲染（ `api.to_record()` ）。从标准训练集中每个来源采样了 1,500 条记录，共得到 9,000 条记录和 13,500 个问题（4,500 个 Choice、6,000 个 Noul、3,000 个 Score）。

#### Limitations

#### 偏见、风险和建议

训练集带有其来源的偏见：以美国为中心的新闻类别、英语银行术语、餐厅评论以及众包 NLI 标签。模型会反映这些偏见。

直接概率输出看起来具有权威性。来自该模型的 `confidence: 0.92` 是关于其自身在三个选项上分布的统计量，而非其正确的已验证概率。在未先基于你自己的标注结果测量校准之前，不要将其作为阈值用于重大决策。

问题隔离属性是一项真正的安全功能（一个问题的文本无法操纵另一个问题的答案），并已通过验证。分隔符伪造防护已针对五个保留 token 完成验证。通过状态文本进行的其他提示注入途径尚未研究。

#### Environmental impact

一次训练运行：\~1.75 小时，在单台 Apple M5 笔记本电脑 SoC 上，功耗约为 30–40 W，即约 0.06 kWh。评估和冒烟测试运行会增加大致相同的能耗。这个量很小。

## 结构化（1）

### 2026-09-20 03:44:37

#### Kev-0.5B：面向类型化决策与概率校准的轻量模型

Kev-0.5B 是一个基于 Qwen2.5-0.5B 改造的决策模型，可直接对选择题、是非题和有序评分题输出概率。它重点研究问题隔离、概率校准和选项顺序影响，而非面向现实中的高风险自动决策。

##### 核心设计：共享背景，但问题彼此隔离

模型可在一次请求中接收一段公共状态信息和多个问题，支持三种类型：

- **Choice**：2—255 个选项，返回选择结果和置信度。
- **Noul**：是 / 否题，返回 “是” 的概率。
- **Score**：2—255 个有序等级，返回期望等级。

其关键机制是 “分支注意力”：每个问题只能看到公共状态和自己的内容，不能读取同一请求中的其他问题。模型再比较`&lt;decide>`位置与各选项结尾位置的表示，通过 softmax 得到选项概率。

这种设计兼顾了效率与隔离性：多个问题可以打包处理，但理论上不会互相影响。实验中，打包与逐题运行的最大概率差仅为**3.7×10⁻⁶**，打包速度约快**2 倍**。

##### 模型规模：冻结主干，只训练少量参数

模型以**Qwen2.5-0.5B（4.94 亿参数）**为主干，并完全冻结，只训练：

- LoRA 适配器：约**880 万参数**
- 决策头：约**46 万参数**
- 总可训练参数：**930 万**，约占主干的**1.9%**

训练时每个公共状态最多使用 384 个 token、每个问题分支最多 1,024 个 token；部署时每个分支允许 8,192 个 token。

##### 训练数据：六个公开数据集转成统一决策格式

训练数据来自 Banking77、BoolQ、AG News、MNLI、SST-5 和 Yelp Review Full。每个来源抽取 1,500 条，共：

- **9,000 条记录**
- **13,500 个问题**
- 其中 Choice 4,500 题、Noul 6,000 题、Score 3,000 题

不同数据集被转换成对应任务，例如：

- Banking77：在 77 个银行业务意图中选择
- BoolQ：根据文章回答是或否
- MNLI：判断文本关系
- SST-5、Yelp：预测 5 级情感或评分

训练前还会随机打乱选项、加入 “以上皆非” 或无关干扰项，并改变文本和结构化字段的呈现形式。数据中**没有使用大模型生成内容**，也没有原数据集之外的额外人工标注。

模型训练 2 个 epoch，共 2,250 次优化步骤；在一台 Apple M5、32GB 内存的设备上耗时约**1 小时 45 分钟**，最终训练损失为 0.27。

##### 评估结果：同源留出集上准确率较高，校准有所改善

评估使用上述六个来源的留出测试或验证数据，共**1,350 个问题**。总体结果为：

- **准确率：0.799**
- **ECE：0.065**  
  ECE 即 “预报置信度与实际正确率之间的偏差”，越低越好。
- 温度缩放后，ECE 降至**0.031**，温度参数为 1.47。

主要任务表现包括：

- AG News 分类：**0.940**
- AG News 是非题：**0.960**
- Banking77：**0.860**
- Yelp 是非题：**0.887**
- BoolQ：**0.753**
- MNLI：**0.747**
- SST-5 五级评分：**0.533**，平均等级误差 0.59
- Yelp 五级评分：**0.553**，平均等级误差 0.54

在可比较的任务上，Kev-0.5B 的准确率均高于原始 Qwen2.5-0.5B 和其 Instruct 版本。但这些结果来自与训练数据同来源的留出集，不能证明它在陌生任务上同样可靠。

##### 机制测试：隔离有效，但仍受选项设计影响

专项测试显示：

- **问题隔离有效**：秘密信息放在其他问题中时，目标答案概率约为 0.03；放在公共状态中时升至 0.99。
- **选项顺序仍有影响**：对至少三个选项的题目进行四种排序后，最高概率选项有**7.4%**的情况发生翻转；正确选项概率平均变化 0.065，90 分位变化达 0.25。
- **无关选项会扰动结果**：加入一个无关选项后，原前两名选项的相对对数几率平均变化 0.13。
- **伪造分隔符防护有效**：在选项文本中插入保留分隔符不会增加选项数量，伪造选项的概率不超过 0.09。

因此，问题隔离和已测试的分隔符防护属于真实的安全特性，但模型并未消除选项顺序敏感性，也尚未研究通过公共状态文本实施的其他提示注入。

##### 适用范围与主要风险

作者将该模型定位于：

- 决策模型与概率校准研究
- 问题隔离、选项顺序和概率行为实验
- TypeSafe System One API 兼容性测试
- 本地演示和教学

不应将其用于会影响个人权益的生产决策，例如审核、反欺诈、信贷、招聘、医疗或法律分流。主要原因是：

1. 模型知识受限于 0.5B 主干；
2. 校准只在训练来源的数据上验证；
3. 陌生任务上的表现尚未测量；
4. `confidence: 0.92`只表示模型自身对选项的概率分布，不等于 “已验证有 92% 的正确率”；
5. 训练数据包含美国新闻类别、英语银行术语、餐厅评论和众包标签等来源偏见。

作者特别建议：在使用自己的标注数据验证校准之前，不要把模型置信度作为重大决策的阈值。

##### 其他信息

适配器和决策头采用**Apache-2.0**许可证，基础模型遵循 Qwen 的许可证。单次训练估计耗电约**0.06 kWh**；模型卡记录的版本为**kev-0.5b v0.1**。

## 深度解读（1）

### 2026-09-20 03:46:57

#### Kev 的真正价值：把小模型从 “聊天者” 改造成受约束的决策器

Kev 并不是缩小版聊天机器人，而是一次更有产品意义的尝试：**让语言模型只做类型明确、边界清楚的判断**。它基于冻结的 Qwen2.5-0.5B，只训练约 930 万参数，接受共享背景后，输出选择题、是非题或有序评分的概率分布。训练仅用 9000 条公开数据，在笔记本上约两小时完成。

这组数字不能证明它已具备通用决策能力，却证明了一件更实际的事：很多分类与路由任务，未必需要大模型生成答案，更适合把预训练模型改造成一个低成本、可本地部署的 “语言决策组件”。

##### 类型化接口比自然语言输出更接近可靠产品

传统提示词让模型生成 “A”“是” 或 “4 分”，概率通常来自下一个 token，容易受措辞、格式和候选字母影响。Kev 则直接读取每个选项结束位置的表示，与问题表示计算分数，再在候选项上归一化。这使输出天然满足 API 契约，也避免了解析自由文本。

这一设计适合意图路由、内容标签、工单分流、低风险审核辅助等场景：输入仍可灵活表达，但输出空间由产品预先定义。它的价值不是 “更聪明”，而是**用架构减少模型可以犯错的方式**。与通用 LLM API 相比，它可能更便宜、更稳定、更易审计；与传统分类器相比，则可能更容易接收自然语言描述和动态候选项。

##### 隔离注意力是安全与效率的共同设计

模型允许多个问题共享一份状态，但每个问题只能看到状态和自己的分支，不能读取其他问题。测试中，秘密放在兄弟问题里时概率约为 0.03，放进共享状态后升至 0.99；打包推理与逐题推理的最大概率差仅为 \(3.7\times10^{-6}\)，速度约快两倍。

这比单纯要求模型 “不要参考其他问题” 更可靠，因为约束落在注意力掩码上。不过边界也很清楚：它只能阻止问题之间相互污染，**无法防止共享状态本身携带提示注入**。因此，这是一项局部安全属性，不是完整的输入安全方案。

##### 最值得警惕的不是准确率，而是概率的权威感

模型在同来源留出集上达到 79.9% 准确率，整体 ECE 为 0.065，温度缩放后为 0.031。但训练和评估都来自同样的六个数据源，且基线是未经微调的零样本模型，所以这些结果主要说明 “专门训练有效”，不能证明陌生业务上的泛化与校准。

机制测试反而更有启发：候选顺序变化会让 7.4% 的多选题翻转答案；加入无关选项，也会明显改变原有选项之间的相对赔率。也就是说，`confidence: 0.92`只是模型在当前候选集合与排列下的内部集中度，不能直接解释成 “有 92% 概率正确”。

对产品落地而言，真正需要验证的是：在自己的数据分布、候选设计和错误成本下，概率是否仍然稳定。**Kev 展示了一条有潜力的工程路线，但也提醒我们：可输出概率，不等于概率可信；接口受约束，也不等于决策可托付。**

## 深度解读-口播（1）

### 2026-09-30 12:16:22

一个语言模型，不一定要靠生成一段话来回答问题。凯夫这个项目探索了另一条路：给模型明确的选项，让它直接输出各个选项的概率。但最值得注意的是，输出概率，并不等于知道自己有多大把握答对。

凯夫是一个小型决策模型，基于约五亿参数的通义千问模型改造。它主要处理三类任务：从多个选项中做选择，回答是或否，以及在有序等级中打分。比如，判断一条银行客服消息属于哪种业务，判断一篇新闻属于哪个主题，或者给一条评论评定星级。

它不需要先生成解释，再从解释中提取答案。而是读取问题和选项，给每个选项打分，再把这些分数转换为概率。应用程序根据这份概率分布，返回选择结果、肯定答案的概率，或者期望等级。

这让模型的输出更规整，也更容易接入程序。不过，模型只能在给定的选项和任务范围内判断。输出形式明确，并不代表判断一定可靠。

凯夫在结构上最有意思的设计，是让多个问题共享一份背景资料，同时把问题彼此隔离。

比如，一篇新闻可以同时对应两个问题：这篇新闻属于哪个类别？它是否涉及体育？两个问题都能读取新闻正文，但不能读取对方的问题和选项。也就是说，共享的是背景，不是每个问题自己的内容。

这种隔离不是一句提示词要求，而是通过模型内部的信息访问规则实现的。模型处理一个问题时，只能看到公共背景和这个问题自己的分支。

项目做了一个测试：把回答所需的秘密信息放进另一个问题里。目标问题给出相关答案的概率，和秘密完全不存在时一样，都约为百分之三。只有把秘密放进共享背景，概率才升到约百分之九十九。这支持了一个判断：在该测试中，信息没有从一个问题泄漏到另一个问题。

共享背景也能节省重复计算。测试中，把多个问题打包处理，和分别处理得到的概率几乎一致；在每个请求平均约有二点七个问题的情况下，打包处理速度约快一倍。

所以，这项设计的价值是，把共同背景复用起来，又尽量避免问题之间相互干扰。

接下来要看的是：这样一个小模型，能做到多好？

凯夫训练时冻结了基础模型，只训练少量新增参数。这种方法叫低秩适配，可以理解为保留原有模型，在内部加上一小部分可训练的调整模块。再加上负责选项评分的模块，总共训练了约九百三十万参数，只占基础模型参数量的百分之一点九。

训练数据来自六个公开数据集，涉及银行意图、新闻分类、阅读判断、文本推理和评论评分。总共使用九千条记录，没有额外使用大模型生成的数据，也没有增加新的人工标注。模型在一台苹果笔记本上，训练了约一小时四十五分钟。

这说明，项目的训练规模和硬件门槛都比较小。它的定位也是本地演示、教学，以及决策模型研究，而不是已经成熟的生产系统。

在来自同样六个数据来源的一千三百五十个留出问题上，凯夫的总体准确率是百分之七十九点九。但这个平均数掩盖了明显的任务差异。

比如，新闻主题分类的准确率达到百分之九十四。判断新闻是否属于某个主题，准确率达到百分之九十六。相比之下，把评论精确分成五个情绪或评分等级，准确率只有百分之五十三到五十五左右。

在有基线结果的任务上，凯夫的准确率高于未经这类训练的基础模型和指令模型。不过，这些测试仍然来自训练涉及的六个数据来源。它们说明模型在这些任务上有效，不能证明模型到了陌生领域，也能保持同样的表现。

比准确率更容易被误读的，是置信度。

假设模型输出某个选项的置信度为百分之九十二。这首先表示，在当前选项之间，模型给这个选项分配了百分之九十二的概率。它并不自动意味着，类似判断做一百次，就一定能答对九十二次。

要让这个数字具有后一种意义，需要验证“校准”。简单说，就是检查模型声称的把握，是否和实际正确率相匹配。

项目报告的总体校准误差，原本约为百分之六点五。经过一种叫温度缩放的调整后，降到了约百分之三点一。温度缩放主要调整概率分布的尖锐程度，让模型表达的把握更接近测试中的实际表现。这是校准改善，不应理解为准确率也相应提高了。

更重要的是，这种校准只在所测试的数据分布上得到验证。换成自己的业务数据，仍然需要用自己的标注结果重新检查。

模型还有一个值得记住的限制：答案会受到选项顺序影响。测试中，在至少三个选项的选择题里，改变选项排列，约有百分之七点四的情况会改变模型的最终选择。也就是说，即使输出是规整的概率，模型也还没有完全摆脱排列方式带来的干扰。

安全性同样需要划清边界。问题之间的隔离通过了测试，伪造特定分隔符的防护也经过验证。但通过共享背景发起的其他提示注入，尚未研究。问题隔离是一项有价值的防护，不是对所有攻击都免疫。

因此，作者明确不建议把凯夫用于影响人的生产决策，例如信用、招聘、医疗或法律分流。

凯夫最值得记住的，是一种小模型的设计思路：不生成长篇答案，而是直接做结构化选择；让多个问题共享背景，又限制它们相互影响。但概率输出只是判断的表达方式，不是可靠性的证明。真正用于重要决策之前，仍然要在自己的场景里验证准确率、校准和安全边界。
