### 一行代码没写，纯 Vibe Coding 重构 AITDK 官网，体感还不错

过去我比较抗拒 Vibe Coding，总觉得完全交给 AI 会脱离掌控，会变成一堆屎山，风险比较大。所以我一直更倾向于人机协作：Claude Code 主写，我和 Codex 负责 review 和辅助修改。

最近重构

[AITDK](http://aitdk.com/) 官网，想换一种方式，体验下纯 Vibe Coding，也简单记录下重构过程。

旧版 AITDK 官网使用 SaaSBold 搭建，网站功能和 UI 基本都是手搓，加载速度和体验不太理想，部署也绑定在 Vercel 上，重构也是希望解决这些痛点。

#### 选型过程

我不想被平台绑定，核心诉求是一套代码能顺滑部署到 Cloudflare Workers / Vercel / Railway / Dokploy 等平台。

- Next.js：过去一直在用，就算搭配 OpenNext 部署到 Cloudflare Workers 效果也不是特别好。
- Vinext：Cloudflare 基于 Vite 重新实现 Next.js API 的兼容方案，试了一把速度很快，版本一直是 v0.0.x（前两天发布了 v0.1.x 版本），公开可参考的生产案例还不多，稍微有点慌。
- TanStack：最近很火，全平台部署，很轻量，速度也很快，前几天看到
  [Lovable 也切到了 TanStack](https://x.com/FabianHedin/status/2061486467520593965)，看着很不错。

整体对比下来 TanStack 最符合，于是开搞，模板选的是

[@idoubicc](https://x.com/@idoubicc) 新上线的 shipany-tanstack。功能很多，我最钟意的是下面两点：

1. 多平台部署：Cloudflare Workers / Vercel / Railway / Dokploy 等。
2. 多数据库支持：PostgreSQL / MySQL / SQLite / D1 / Turso 等。

![Image](https://pbs.twimg.com/media/HKba7t4bcAAufqX?format=jpg&name=large)

#### 重构过程

1. 使用 /clone-website skill 逐一复刻
   aitdk.com 生产环境的各个页面。
2. 让 Claude Code 对照源码检查是否有遗漏并进行补齐。这里没有跳过第 1 步直接对照源码重构，主要是因为我担心 AI 偷懒，会沿用旧的代码和结构。
3. 让 Claude Code 重新设计各个页面。先首页，效果满意后再内页，可以给一些案例网站供 AI 参考，自由发挥也可以，有时也会有惊喜。

整个重构耗时大约一天，主要是第 3 步占用时间比较多，让 Claude Code 设计了很多个版本，从里面选了一个看着最顺眼的。

新版官网周一就上线了，观察了两天，整体体验和速度还是比较满意的，后面打算把长期维护的项目都用 TanStack 重构了。

## 解读（1）

### 2026-06-11 08:54:57

#### 深度总结

作者原本不信任 **纯 Vibe Coding**，担心 AI 全权写代码会失控、产出“屎山”。过去更偏向 **AI 写、人类审、另一个 AI 辅助改** 的人机协作模式。

这次重构 AITDK 官网，他刻意尝试了“一行代码不写”的纯 AI 重构流程。

##### 核心动机

旧官网存在几个问题：

- 基于 SaaSBold，功能和 UI 多为手搓；
- 加载速度和体验不理想；
- 部署绑定 Vercel，不够自由；
- 希望重构成一套代码，多平台可部署。

##### 技术选型

作者比较了几种方案：

| 方案 | 评价 |
|---|---|
| Next.js | 熟悉，但部署到 Cloudflare Workers 体验不够理想 |
| Vinext | 速度快，但版本早、生产案例少，有不确定性 |
| TanStack | 轻量、快、多平台部署，最符合需求 |

最终选择了 **TanStack + shipany-tanstack 模板**。

看重两点：

1. 支持多平台部署：Cloudflare Workers、Vercel、Railway、Dokploy 等；
2. 支持多数据库：PostgreSQL、MySQL、SQLite、D1、Turso 等。

##### 重构流程

作者的纯 Vibe Coding 大致分三步：

1. 用 `/clone-website` 逐页复刻线上网站；
2. 再让 Claude Code 对照旧源码检查遗漏并补齐；
3. 让 Claude Code 重新设计页面，先首页，再内页，多出几个版本后人工挑选。

整个过程大约一天，主要时间花在让 AI 反复设计页面、筛选最满意版本上。

新版上线后观察两天，作者认为速度和体验都不错，并计划后续长期维护项目也用 TanStack 重构。

---

#### 通俗解读

这篇内容本质上讲的是：

> 作者以前怕 AI 乱写代码，这次干脆放手让 AI 重做官网，结果发现效果还不错。

他不是让 AI 在旧代码上小修小补，而是先让 AI “照着网站外观重做”，再拿旧源码查漏补缺，最后让 AI 重新设计 UI。

这里有个关键点：

> 他没有第一步就把旧代码丢给 AI，是为了防止 AI 偷懒，直接沿用旧架构和旧问题。

所以这次“纯 Vibe Coding”并不是完全无脑交给 AI，而是：

- 方向由人定；
- 技术栈由人选；
- 页面效果由 AI 生成；
- 最终方案由人挑；
- 代码细节基本交给 AI。

换句话说，人从“写代码的人”，变成了“产品经理 + 技术决策者 + 审美把关人”。

---

#### 关键启发

##### 1. Vibe Coding 适合“重构展示型网站”

官网、落地页、博客、营销页这类项目，逻辑相对清晰，AI 发挥空间大。

尤其适合：

- 页面重设计；
- 旧站复刻；
- UI 调整；
- 多版本尝试；
- 模板化项目搭建。

##### 2. 技术选型比写代码更重要

作者真正花心思的是：

- 不想被 Vercel 绑定；
- 想多平台部署；
- 想未来维护成本低；
- 想速度快、架构轻。

代码可以交给 AI，但方向选错了，AI 写得再快也没用。

##### 3. AI 不一定替代程序员，但会改变程序员工作方式

以前是：

> 人写代码，AI 辅助。

现在逐渐变成：

> AI 写代码，人负责判断、取舍、验收。

程序员的价值从“实现能力”转向：

- 架构判断；
- 需求拆解；
- 审美判断；
- 风险识别；
- 质量控制。

---

#### 辩证思考

##### 积极面

纯 Vibe Coding 的优势很明显：

- 开发速度极快；
- 适合快速重构和试错；
- 可以低成本生成多个设计版本；
- 对展示型网站非常友好；
- 降低了从 0 到 1 的门槛。

这类场景里，AI 已经不只是“代码助手”，更像是一个高速执行团队。

##### 隐忧

但它也有风险：

- AI 可能写出看似能跑、实际难维护的代码；
- 复杂业务逻辑容易埋坑；
- 安全、性能、边界条件可能被忽略；
- 如果人不懂技术，很难判断 AI 产物质量；
- 模板依赖和生态成熟度仍需验证。

尤其是“纯 Vibe Coding”很容易带来一种错觉：

> 页面能跑 = 项目完成。

但真实项目还包括可维护性、可扩展性、安全性、监控、测试、部署稳定性等问题。

##### 我的判断

这篇文章的价值不在于证明“AI 可以完全替代开发者”，而在于说明：

> 对合适的项目，AI 已经可以承担大部分实现工作；但人必须掌握方向、标准和风险。

纯 Vibe Coding 可以用，但不能迷信。

更稳妥的方式是：

- 展示型项目：可以大胆用；
- 复杂业务系统：谨慎用；
- 核心生产系统：必须加强 review、测试和监控；
- 技术选型：不能完全交给 AI；
- 最终责任：仍然在人。

一句话总结：

> Vibe Coding 正在把开发从“手工编码”推向“意图驱动”，但真正的壁垒不再是会不会写代码，而是会不会判断什么代码值得留下。
