## 正文

**Yuu**

多 agent 能奏效的本质是模型路由和上下文隔离  
模型路由的意思就是，让每种模型去做他自己擅长的事情，opus 天生对前端品味好，那就让它去写前端，gpt 对后端逻辑要求更严谨，那就让他审其他模型写的代码逻辑  
上下文隔离则是，每个模型负责的范围很小，所以不容易注意力漂移  
这里我要讲一个例子，在写 skill 的时候，如果你让模型把检索和写作（这里泛指以某种对人类友好的格式输出）分开来做（这两个阶段的上下文都很长），且不隔离上下文，那么模型会因为注意力漂移而忽略一部分检索内容，或者协作时因为过长的检索而忽略一部分写作要求，那么你可能会得到一份不太像人话的文档 / 其他格式的文件  
但如果你让它把检索和写作结合在一起进行，做多个 loop，例如 search1-&gt;writing1-&gt;search2-&gt;writing2，每个 search-&gt;writing 视为一个小阶段，要求 agent 在小阶段结束时就去 edit 最终的产出文件，那么 agent 的表现会很好  
在这个例子里，我相当于是通过 skill prompt，手动编排了一个循环结构，agent 不需要记住很多东西，只需要记住当前阶段做了什么，然后记下来，这就取消掉了当前阶段和之前阶段的关联，在这个结构中，虽然 agent 持有之前的上下文，但我们只需要确保循环当前阶段的是有效上下文即可，这很 tricky，但我相信未来会有更 generalization 的解法

所以隔离上下文的本质是防止注意力漂移

#### 深度总结

这段内容的核心观点：

> **多 Agent 真正有效，不是因为“像人类团队分工”，而是因为它实现了两件事：模型路由 + 上下文隔离。**

##### 1. 模型路由

不同模型有不同强项，应让它们做最适合的事。

- Opus：可能更擅长审美、前端、表达
- GPT：可能更擅长逻辑、后端、代码审查
- 其他模型：也可根据能力分配任务

重点不是“产品经理 Agent、开发 Agent、测试 Agent”这种人类组织结构模拟，而是：

> **把任务路由给最适合处理它的模型。**

---

##### 2. 上下文隔离

模型上下文太长时，容易发生“注意力漂移”：

- 忽略前面检索到的重要信息
- 忘记后面的写作要求
- 输出内容机械、不像人话
- 协作时互相干扰

因此，要把大任务拆成小阶段，让模型每次只关注当前关键内容。

---

##### 3. 有效方式：检索与写作交替循环

低效方式：

```text
大量检索 -> 一次性写作
```

问题：上下文太长，模型容易遗漏重点。

更好的方式：

```text
search1 -> writing1 -> search2 -> writing2 -> search3 -> writing3
```

每一轮都完成一个小闭环，并及时编辑最终产物。

这样模型不需要记住全部历史，只需做好当前阶段，然后把结果沉淀到文件中。

---

#### 深入浅出解读

可以把 Agent 想象成一个注意力有限的助手。

如果你一次性给它：

- 一堆资料
- 一堆要求
- 一堆格式规范
- 一堆历史讨论

它就容易“看花眼”。

不是它不聪明，而是上下文太复杂，重点会被冲淡。

所以更好的方法不是让它扮演很多角色，而是设计一个流程：

```text
查一点 -> 写一点 -> 再查一点 -> 再改一点
```

就像人写论文，也不是先读完所有资料再一口气写完，而是：

1. 查资料
2. 记笔记
3. 写一段
4. 发现缺口
5. 再查资料
6. 再修改

本质上，这是在帮模型降低认知负担。

---

#### 关键洞察

##### 多 Agent 的价值，不在“角色扮演”

很多多 Agent 产品喜欢模拟人类公司：

- 产品经理 Agent
- 程序员 Agent
- 测试 Agent
- 运营 Agent

听起来很酷，但可能只是“情绪价值”。

真正有用的不是让 AI 像人一样开会协作，而是：

> **让合适的模型，在合适的上下文里，做合适的小任务。**

---

#### 辩证思考

##### 赞同之处

这个观点很重要。

现在很多多 Agent 方案失败，是因为它们模仿了人类组织，而不是适配模型特性。

AI 不需要“职位”，它更需要：

- 清晰任务边界
- 精准上下文
- 明确输入输出
- 可持续迭代的工作流

所以，多 Agent 的本质不是“AI 公司”，而是“任务编排系统”。

---

##### 需要补充之处

但也不能完全否定角色型 Agent。

在某些场景下，角色仍然有价值，比如：

- 审稿人视角
- 安全审查视角
- 用户体验视角
- 法务合规视角

不过这些角色的价值，不是因为它们“像人”，而是因为它们提供了不同的评价维度。

也就是说：

> **角色有用，但角色不是本质；本质仍是任务拆解、能力匹配和上下文管理。**

---

##### 我的判断

未来有效的 Agent 系统，大概率不是一群 AI 员工坐在一起聊天，而是更像一个自动化流水线：

```text
任务拆解 -> 模型选择 -> 小上下文执行 -> 结果沉淀 -> 循环修正
```

多 Agent 能不能奏效，关键看三点：

1. **有没有把任务拆小**
2. **有没有选对模型**
3. **有没有控制上下文污染**

如果只是给 Agent 起不同名字，让它们互相讨论，那大概率只是“AI 过家家”。

---

#### 一句话结论

> **多 Agent 的真正价值，不是模拟人类团队，而是用模型路由发挥各模型优势，用上下文隔离减少注意力漂移。**
