## 正文

**kejun**

传统 UI 注定会被「生成式 UI」取代，只不过它不是消息流中的一张「卡片」，这两天做了一个探索（数据都是Mock的）

1\. 交互模式：用户的顺序式操作 / 固定的界面 → Agent 驱动的事件流，界面按需生成 / 销毁  
2\. 状态管理：前端单向状态管理 / 后端仅持久化 → 前端与 Agent 共享状态，双向同步且可冲突调和  
3\. 输出方式：静态页面 + 局部异步刷新 → 动态组件树、流式语音/视频、思考链可视化、可中断提示  
4\. 任务模式：规定流程，用户必须遍历步骤 → AI 自主规划子任务、多步执行与人机中断/回退  
5\. 可观测性：仅记录用户行为→ 全面记录 Agent 思考、规划、工具调用、审批链，支持审计与重放  
6\. 安全模式：基于用户权限的接口调用 → 基于 Agent 能力边界的沙盒渲染与操作指令校验

## 通俗精炼（1）

#### 文章总结：生成式 UI 将取代传统 UI

##### 核心观点

作者认为，传统固定界面形态会逐步被「生成式 UI」取代。  
但生成式 UI 不只是聊天消息流里的一张卡片，而是一种由 Agent 驱动、按任务动态生成和销毁界面的新交互范式。

---

##### 1. 交互模式变化

传统 UI 是用户按固定流程点击、填写、跳转。  
生成式 UI 则由 Agent 根据任务进展生成事件流，界面可以按需出现、变化或消失。

**从“人操作界面”变成“Agent 推动界面”。**

---

##### 2. 状态管理变化

过去前端主要负责单向状态管理，后端负责数据持久化。  
未来前端需要和 Agent 共享状态，并支持双向同步、冲突调和。

**界面状态不再只属于前端，而是人与 AI 共同协作的上下文。**

---

##### 3. 输出方式变化

传统产品多是静态页面加局部刷新。  
生成式 UI 可以输出动态组件树、流式语音/视频、思考过程可视化，并支持用户随时打断或提示。

**界面从“展示结果”变成“实时呈现 AI 工作过程”。**

---

##### 4. 任务执行变化

传统产品要求用户按预设步骤完成任务。  
AI 产品中，Agent 可以自主拆解任务、多步执行，并允许人在关键节点中断、回退或介入。

**流程从“用户走流程”变成“AI 执行任务，人做监督与决策”。**

---

##### 5. 可观测性变化

过去主要记录用户点击、浏览等行为。  
未来需要记录 Agent 的思考、规划、工具调用、审批链路，并支持审计和重放。

**AI 系统必须可追踪、可解释、可复盘。**

---

##### 6. 安全模式变化

传统安全主要基于用户权限控制接口访问。  
生成式 UI 时代，还要限制 Agent 的能力边界，通过沙盒渲染和操作指令校验防止越权或误操作。

**安全对象从“用户”扩展到“用户 + Agent”。**

---

##### 一句话总结

生成式 UI 的本质不是更智能的页面，而是由 Agent 驱动的动态交互系统：界面、状态、任务、审计和安全都会围绕 AI 的自主执行能力重新设计。
