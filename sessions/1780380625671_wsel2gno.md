**宝玉**

Codex 使用技巧：Steer 和 Queue

通常 Agent 执行一个任务不会马上结束，可能会要等几分钟甚至更久，如果这时候你有个新的要求想补充，这里有两种方式补充：Steer（任务干预） 和 Queue（排队）。

&gt; Steer（快捷键：Shift + Enter）：在当前任务还没完成时，中途打断 Codex 并给它指引新的方向。

这个功能相当于你按停止，输入新指令然后再让 Agent 继续。但不需要你去手动停止再让它继续，只要输入指令，按 Shift + 回车，或者先回车，在点击“Steer”按钮就可以发送。Agent 会在下一轮工具调用间隙直接添加新的指令到上下文。

&gt; Queue（快捷键：Enter）：在 Codex 完成当前步骤后，给它安排接下来的活儿。

任务排队就不太一样了。它不会打断正在进行的任务，而是把新任务排在队伍后面。而且你提交多条信息，它在任务结束后，不会一次性把你队列的消息执行，而是执行一条，完成这一条对应的任务后，继续下一条。

所以有时候我睡觉前，会在一个长任务后面加上几个 “Continue” 消息到队列，让它尽可能多跑一会，免得中间就停止了。

简单来说，“Steer”是改变 Codex 眼下正在做的事，而“Queue”是安排它接下来要做的事。

##### 一、总结

这篇内容讲的是 **Codex 里补充指令的两种方式**：

| 功能 | 作用 | 是否打断当前任务 |
|---|---|---|
| **Steer / 引导** | 立刻调整当前任务方向 | 会干预 |
| **Queue / 排队** | 安排后续任务 | 不打断 |

补充勘误：

> **Steer 快捷键**：  
> Windows / Linux：`Ctrl + Enter`  
> Mac：`Command + Enter`

---

##### 二、通俗解读

可以把 Codex Agent 想象成一个正在干活的助手。

###### 1. Steer：现在就改方向

比如它正在写代码，你发现它理解错了。

你可以直接说：

> 不要用 React，改成 Vue。

然后用 **Steer** 发出去。

这相当于：

> “停一下，听我补充一句，再继续。”

适合用于：

- 发现方向错了
- 临时补充关键要求
- 让它立即调整实现方式

---

###### 2. Queue：先干完，再干下一个

比如它正在修 bug，你又想到：

> 修完后顺便写测试。

这时可以用 **Queue**。

它不会马上打断当前任务，而是排到后面。

适合用于：

- 当前任务没问题，只是追加后续工作
- 让 Agent 连续执行多个步骤
- 长任务时提前安排下一步

---

##### 三、我的意见

这两个功能的核心区别很简单：

> **Steer 是“改现在”，Queue 是“排以后”。**

我的建议：

- 如果 Agent **跑偏了**：用 **Steer**
- 如果只是 **追加任务**：用 **Queue**
- 如果睡前想让它多跑一会：可以 Queue 几个 `Continue`

但要注意：

> 不要盲目一直 `Continue`，否则 Agent 可能会越跑越偏，或者做很多低价值工作。

更好的做法是排明确任务，例如：

```text
继续检查剩余 bug
补充测试用例
优化代码结构
生成总结报告
```

这样比单纯说 `Continue` 更稳。

##### 主旨概括

文章介绍了 Codex 中给正在运行的 Agent 补充指令的两种方式：**Steer（引导/任务干预）** 和 **Queue（排队）**。简单来说，**Steer 是改变当前正在做的事，Queue 是安排后续要做的事**。

##### 1. 背景：Agent 任务通常不会立刻结束

- Codex Agent 执行一个任务时，往往需要等待几分钟甚至更久。
- 在任务运行过程中，如果用户突然有新的要求想补充，就可以使用两种方式：
  - **Steer：中途干预当前任务**
  - **Queue：把新任务排到后面**

##### 2. Steer：中途打断并调整方向

- **Steer** 的作用是：在当前任务尚未完成时，给 Codex 新的指引，让它调整接下来的执行方向。
- 它类似于：
  - 先手动停止当前任务；
  - 输入新指令；
  - 再让 Agent 继续执行。
- 但 Steer 不需要手动停止，Codex 会在下一轮工具调用的间隙，把新指令加入上下文。

> 勘误：Codex 中 Steer 的快捷键为：  
> - Windows / Linux：`Ctrl + Enter`  
> - Mac：`Command + Enter`

##### 3. Queue：不打断当前任务，安排后续工作

- **Queue** 的作用是：不影响当前正在运行的任务，而是把新指令放到后续队列中。
- 当 Codex 完成当前步骤或当前任务后，会继续执行队列中的任务。
- 如果提交多条 Queue 消息，Codex 不会一次性全部执行，而是：
  1. 执行第一条；
  2. 完成后再执行下一条；
  3. 依次推进。

##### 4. 使用案例：睡觉前让 Agent 多跑一会

- 作者提到，自己有时会在睡觉前，在一个长任务后面加入几个 **“Continue”** 消息到 Queue。
- 这样做的目的是让 Codex 在当前任务完成后继续推进，避免中途停下来。
- 热门回复中也有人表示，自己会“睡觉前打 6 个继续不要停”，让任务持续运行。

##### 5. 核心区别总结

| 功能 | 作用 | 是否打断当前任务 | 适合场景 |
|---|---|---|---|
| **Steer** | 调整当前任务方向 | 会干预当前任务 | 发现 Agent 跑偏了，需要立刻纠正 |
| **Queue** | 安排后续任务 | 不打断当前任务 | 想让 Agent 做完当前任务后继续执行新任务 |

**一句话理解：Steer 是“现在改方向”，Queue 是“之后接着做”。**

#### Codex「Steer vs Queue」使用技巧精炼

##### 1. 启发

这条内容的核心不只是一个快捷键技巧，而是揭示了一个更重要的 Agent 使用范式：

> 使用 AI Agent 时，关键不是“一次性写出完美 Prompt”，而是学会在任务执行过程中进行动态调度。

传统使用 AI 更像是「问答」：输入一次，等待输出。  
而 Codex / Agent 类工具更像是「协作型执行系统」：它会持续运行、调用工具、修改代码、验证结果。此时用户的角色从“提问者”变成了“任务调度者”或“项目经理”。

因此，Steer 和 Queue 本质上对应两种管理动作：

| 功能 | 本质 | 类比 |
|---|---|---|
| Steer | 中途干预方向 | 项目经理发现方向错了，立刻纠偏 |
| Queue | 安排后续任务 | 给团队排下一批待办事项 |

真正高效的 AI Agent 使用者，不是写完 Prompt 就放任执行，而是懂得在不同阶段选择「打断」「追加」「等待」「排队」。

---

##### 2. 高价值信息深挖

###### 2.1 Steer：适合“方向性纠偏”

Steer 的价值在于：当 Agent 正在执行，但你发现它的理解、路径、优先级出现偏差时，可以及时干预。

适合使用 Steer 的场景：

- Agent 开始改错文件了
- 它理解错了需求
- 它准备采用你不想要的技术方案
- 它在做过度工程
- 它忽略了某个关键约束
- 你突然想到一个必须立即加入的限制条件

例如：

```text
不要重构整个模块，只修复登录状态丢失的问题。
```

```text
停止引入新依赖，优先使用现有工具函数实现。
```

```text
当前方向不对，请先阅读 auth/session.ts，再决定修改方案。
```

Steer 的关键不是“新增任务”，而是“改变当前任务的执行轨迹”。

---

###### 2.2 Queue：适合“任务流水线”

Queue 不会打断当前执行，而是把你的消息放到后续队列中。

适合使用 Queue 的场景：

- 当前任务方向没问题，但你想追加后续工作
- 想让 Agent 完成一个链式流程
- 想睡觉前/离开前让它继续推进
- 想把一个大任务拆成多个连续步骤
- 想让它完成后继续测试、总结、提交说明

例如：

```text
完成后请运行测试，并修复失败用例。
```

```text
测试通过后，请总结你改动了哪些文件，以及为什么这么改。
```

```text
继续检查是否有相似问题。
```

```text
Continue.
```

Queue 的关键不是“纠偏”，而是“延长 Agent 的工作流”。

| 让 Agent 多跑一会 | Queue |
| 防止 Agent 继续错误路径 | Steer |

###### 3.2 Steer 指令模板

###### 纠正方向

```text
当前方向不对。请停止继续修改 X，先检查 Y，再重新制定方案。
```

###### 限制范围

```text
不要扩大修改范围，只允许修改 A、B 两个文件。
```

###### 改变优先级

```text
优先保证功能正确性，暂时不要优化样式或重构结构。
```

###### 阻止过度工程

```text
不要引入新框架或新依赖，用现有代码风格完成。
```

###### 要求先分析

```text
先不要改代码，请先说明你认为问题原因是什么，以及准备修改哪些文件。
```

###### 追加测试

```text
Continue.
```

```text
继续推进，直到当前目标完成或遇到需要我决策的问题。
```

##### 4. 反方与张力

###### 4.1 Queue 不等于真正的自动化

原文中提到“睡觉前加几个 Continue，让它尽可能多跑一会”。这很实用，但也有风险。

问题在于：

- Agent 可能在错误方向上越走越远
- 可能产生大量无效修改
- 可能反复修复自己制造的问题
- 可能越权修改不该动的模块
- 可能缺少关键业务判断

所以 Queue 更适合低风险、边界清晰的任务，例如：

- 跑测试
- 修复 lint
- 补充文档
- 检查类型错误
- 总结改动
- 查找相似问题

不适合无人值守的任务包括：

- 大规模重构
- 复杂架构迁移
- 涉及生产数据的操作
- 安全权限相关修改
- 商业逻辑核心变更

---

###### 4.2 Steer 太频繁会降低 Agent 连贯性

虽然 Steer 可以纠偏，但如果用户不断中途打断，也会破坏 Agent 的执行链路。

过度 Steer 可能导致：

- Agent 上下文混乱
- 任务目标频繁变化
- 修改缺乏完整性
- 代码出现半成品状态
- 浪费工具调用成本

更好的方式是：

> 在关键节点 Steer，而不是在每一步都 Steer。

例如，当 Agent 开始改代码前、选择方案时、测试失败后，是比较适合干预的节点。

---

###### 4.3 不同 Agent 的 Queue 实现可能不同

热门回复中有人提到：

> 在我的 agent 实现中，是把 follow-up 队列中的消息全部拉出来一起提交，而不是逐个提交。

这说明 Queue 的具体行为并不是行业标准。

有些工具可能是：

- 一条一条执行队列
- 批量合并队列内容
- 当前任务结束后只处理最后一条
- 把后续消息作为上下文，而非任务队列

所以不能机械照搬，要观察工具的实际行为。

##### 5. 情境化落地

###### 场景一：产品开发中的 Bug 修复

你让 Codex 修复一个登录 Bug。它开始修改前端状态管理，但你发现真正问题在后端 session。

此时用 Steer：

```text
当前方向可能不对。请先检查后端 session 生成和刷新逻辑，不要继续修改前端状态管理。
```

等它修完后，用 Queue：

```text
完成后请补充一个覆盖 session 过期与刷新的测试用例。
```

---

###### 场景二：AI 产品原型开发

你让 Agent 实现一个 AI 聊天侧边栏。它准备引入一套复杂状态管理库。

用 Steer：

```text
不要引入新的状态管理库。这个原型只需要最小可用实现，优先用 React useState/useReducer 完成。
```

再用 Queue：

```text
实现完成后，请列出下一步可以产品化增强的功能点。
```

---

###### 场景三：商业系统搭建

你让 Agent 搭建一个订单管理后台。它正在扩展复杂权限系统，但当前阶段只需要 MVP。

用 Steer：

```text
暂时不要实现复杂 RBAC。当前只需要管理员单角色权限，先完成订单列表、订单详情和状态更新。
```

用 Queue：

```text
完成后请生成一份后续权限系统升级方案，但不要直接实现。
```

---

###### 场景四：睡前无人值守执行

适合 Queue 的安全版本不是简单堆多个 Continue，而是加上边界条件：

```text
完成当前任务后，请运行测试。如果测试失败，请尝试修复；如果连续两次失败，请停止并总结阻塞原因。
```

```text
如果测试通过，请继续检查同类问题。只允许修改与当前问题直接相关的文件。
```

```text
最后请输出修改摘要、测试结果和仍需人工确认的问题。
```

这样比单纯输入多个：

```text
Continue.
```

更安全、更可控。

---

##### 6. 核心结论

Steer 和 Queue 对应的是两种 Agent 协作能力：

- **Steer：管理当下方向**
- **Queue：管理后续流程**

对 AI/产品开发/商业系统构建者来说，真正值得迁移的不是快捷键，而是这种工作方式：

> 把 AI Agent 当作一个持续执行的协作对象，而不是一次性响应的聊天机器人。

更高阶的用法是：

1. 先给清晰目标  
2. 执行中用 Steer 纠偏  
3. 任务后用 Queue 串联流程  
4. 对高风险任务设置边界  
5. 对长任务要求阶段性总结  
6. 不追求完全放手，而是建立可控的自动化协作机制

**核心高价值点**: 明确区分 Steer 是干预当前任务，Queue 是安排后续任务。

###### 摘要
文章介绍 Codex Agent 执行任务时补充指令的两种方式：Steer 用于中途干预并改变当前方向，Queue 用于在当前任务完成后排队执行后续任务，并补充了正确快捷键说明。

###### 知识要点
- Steer 可在 Agent 当前任务未完成时插入新指令，引导其改变执行方向
- Queue 不打断当前任务，而是将消息排队，在当前步骤或任务完成后依次执行
- Codex 中 Steer 的快捷键勘误为 Ctrl + Enter，Mac 为 Command + Enter
- 可通过排队多个 Continue 让长任务在无人值守时持续推进
