### 介绍用于 Claude Code 的 Codex 插件

如果你已经在使用 Claude Code，这个 Codex 插件为你提供了一种简单的方式，将 Codex 整合到相同的工作流程中。

它对三件事有用：常规的 Codex 评审、更持怀疑态度的对抗性评审，以及当你希望由不同的代理进行二次评审时将工作交给 Codex。

#### 设置

```bash
/plugin marketplace add openai/codex-plugin-cc
/plugin install codex@openai-codex
/codex:setup
```

查看此处的插件：

[https://github.com/openai/codex-plugin-cc](https://github.com/openai/codex-plugin-cc) 你需要 ChatGPT 订阅（包括免费版）或 OpenAI API 密钥，以及 Node.js 18.18 或更高版本。

如果 Codex 尚未安装：

```bash
npm install -g @openai/codex
```

如果 Codex 已安装但未认证：

```bash
!codex login
```

#### 核心命令

/codex:review 运行标准的只读 Codex 审查。

/codex:adversarial-review 执行可引导的挑战性审查。当你希望 Codex 质疑实现而非仅仅检查它时使用此功能。

/codex:rescue 直接向 Codex 分配任务。

较长的任务可以在后台运行，可使用 /codex:status、/codex:result 和 /codex:cancel 来管理它们。

一个简单的首次运行:

何时使用它

```bash
/codex:review --background
/codex:status
/codex:result
```

这里的主要价值在于无需离开 Claude Code，就能获得来自不同代理的真正的第二次检查。

一个好的默认模式很简单：

1. 运行 /codex:review 针对所有事物
2. 运行 /codex:adversarial-review 对任何高风险的事物
3. 当线程停滞或者你希望 Codex 接管时，使用 /codex:rescue

对抗性审查对于迁移、认证变更、基础设施脚本、重构以及任何危险来自隐藏假设而非明显语法错误的场景特别有用。

#### 它是如何工作的

该插件通过本地 Codex CLI 和 Codex 应用服务器进行委托。因此，它使用与你在 Codex 中已有的相同的本地认证、配置、环境和 MCP 设置。

这就是为什么它感觉很轻量。它不是一个单独的运行时。它是 Codex，只是从 Claude Code 内部调用的。

#### 可选评审关卡

你也可以启用一个评审关卡：

```bash
/codex:setup --enable-review-gate
```

这可以阻止 Claude Code 在 Codex 审查运行之前退出。

有用，但需要谨慎使用。它可能会形成一个长时间的 Claude/Codex 循环，并快速耗尽使用额度。

#### 关键结论

这个插件是一种简单的方式，可以保留您的 Claude Code 工作流程，同时在 Codex 表现出色的地方继续使用 Codex。

安装它，运行 /codex:setup，将 /codex:review 用作您默认的第二遍检查，当您需要的不仅仅是常规检查时，使用 /codex:adversarial-review 或 /codex:rescue。

在这里查看插件：

[https://github.com/openai/codex-plugin-cc](https://github.com/openai/codex-plugin-cc)

## 通俗精炼（1）

### 2026-03-31 01:18:19

#### 用 Claude Code 无缝调用 Codex

##### 一句话概括
这篇文章介绍了一个 Claude Code 插件：让你不用离开 Claude Code，就能直接调用 Codex 做代码评审、对抗性审查和任务接管，相当于在同一工作流里多了一个 “第二审稿人”。

##### 它解决了什么问题
核心价值不是 “多一个工具”，而是 “多一个不同的代理视角”。

在实际开发中，同一个模型既写代码又审代码，容易忽略同类问题。这个插件的意义在于：让 Claude 负责生成，让 Codex 负责复查、质疑和补位，提升高风险任务的可靠性。

##### 主要能力
###### 1. 常规评审
使用`/codex:review`，让 Codex 做标准的只读审查。

适合日常开发，作为默认的 “第二遍检查”。

###### 2. 对抗性评审
使用`/codex:adversarial-review`，让 Codex 不只是检查代码，而是主动挑战实现方案、挖隐藏假设。

这类能力尤其适合迁移、认证改动、基础设施脚本、重构等高风险场景，因为这些问题往往不是语法错误，而是思路和假设出了偏差。

###### 3. 任务接管
使用`/codex:rescue`，可以把任务直接交给 Codex 继续处理。

适合当前线程卡住，或者你想换一个代理继续推进时使用。

##### 如何开始
安装流程很简单：

- 添加并安装插件
- 运行`/codex:setup`
- 确保本地已安装并登录 Codex CLI
- 需要`Node.js 18.18+`
- 认证方式支持`ChatGPT 订阅（含免费版）`或`OpenAI API Key`

如果任务较长，还可以后台运行，并通过`/codex:status`、`/codex:result`、`/codex:cancel`管理。

##### 为什么它显得轻量
这个插件本质上不是新造一个运行环境，而是直接调用本地的 Codex CLI 和应用服务器。

这意味着它会继承你在 Codex 里已有的认证、配置、环境和 MCP 设置，所以接入成本低、使用体验也更顺滑。

##### 推荐使用方式
一个很实用的默认模式是：

- 所有任务先跑一次`/codex:review`
- 高风险任务再加`/codex:adversarial-review`
- 卡住时用`/codex:rescue`

这样既不打断原有 Claude Code 工作流，又能把 Codex 作为 “复核层” 和 “接管层” 使用。

##### 需要注意的点
插件支持开启 review gate：先让 Codex 审完，Claude Code 才能退出。

这个机制适合强约束场景，但要谨慎使用，因为 Claude 和 Codex 之间可能形成长循环，快速消耗额度。

##### 文章结论
这不是一个复杂的新系统，而是一个很实用的工作流增强插件。

它最大的意义，是让 Claude Code 用户在不切换环境的前提下，引入 Codex 作为真正独立的第二视角。对于追求质量和稳定性的开发流程，尤其是高风险任务，这个价值很直接。

## 结构化（1）

### 2026-03-31 01:19:40

#### 文章主旨

这篇文章介绍了一个面向 Claude Code 的 Codex 官方插件：它让用户不用离开 Claude Code，就能把 Codex 接入同一套开发流程中。  
核心价值是：用不同代理做 “第二次检查”，尤其适合常规评审、高风险场景的对抗性评审，以及把任务直接转交给 Codex 处理。

##### 1. 这个插件是做什么的

- 如果你已经在用 Claude Code，这个插件可以把 Codex 无缝接入现有工作流。
- 主要有 3 个用途：
  - `常规评审`：做标准的只读代码审查。
  - `对抗性评审`：更 “挑刺”、更怀疑实现方案，主动找隐藏问题。
  - `任务接管`：当当前线程卡住，或者你想换个代理继续推进时，把任务交给 Codex。
- 文章强调，它最大的意义不是 “多一个工具”，而是 “在同一环境里得到不同代理的第二视角”。

##### 2. 如何安装和配置

- 安装步骤如下：

```bash
/plugin marketplace add openai/codex-plugin-cc
/plugin install codex@openai-codex
/codex:setup
```

- 插件仓库地址：`https://github.com/openai/codex-plugin-cc`
- 使用前提：
  - 需要`ChatGPT 订阅（包括免费版）`，或者`OpenAI API 密钥`
  - 需要`Node.js 18.18 或更高版本`
- 如果本地还没有安装 Codex，需要执行：

```bash
npm install -g @openai/codex
```

- 如果已经安装但还没认证，需要执行：

```bash
!codex login
```

- 这说明插件本质上依赖本地 Codex 环境，而不是一套全新的独立系统。

##### 3. 核心命令与推荐用法

- 文章列出了 3 个核心命令：
  - `/codex:review`：运行标准的只读 Codex 审查
  - `/codex:adversarial-review`：执行更具挑战性的 “对抗性审查”
  - `/codex:rescue`：直接把任务分配给 Codex
- 长任务支持后台运行，并可用这些命令管理：
  - `/codex:status`
  - `/codex:result`
  - `/codex:cancel`

###### 一个简单的首次运行方式

```bash
/codex:review --background
/codex:status
/codex:result
```

- 这套流程的重点是：你不需要离开 Claude Code，就能拿到 Codex 的独立复查结果。
- 作者给出的 “默认工作模式” 很清晰：
  - 所有内容先跑`/codex:review`
  - 高风险内容再跑`/codex:adversarial-review`
  - 线程卡住或需要换代理时，用`/codex:rescue`

##### 4. 什么场景最适合用对抗性审查

- 文章特别强调：`对抗性审查`是这个插件里很有价值的能力。
- 它尤其适合这些高风险场景：
  - `迁移`
  - `认证变更`
  - `基础设施脚本`
  - `重构`
  - 以及那些 “风险来自隐藏假设，而不是明显语法错误” 的任务
- 通俗理解就是：
  - 普通审查更像 “看看有没有明显 bug”
  - 对抗性审查更像 “故意质疑你的方案是否建立在错误前提上”
- 例如：
  - 一次认证改造，代码可能语法完全正确，但权限边界、回滚逻辑、旧 token 兼容策略可能有隐藏风险；
  - 这种情况下，对抗性审查比普通检查更有价值。

##### 5. 它为什么显得轻量

- 插件并不是单独再造一个运行时，而是通过：
  - `本地 Codex CLI`
  - `Codex 应用服务器`
  来完成委托调用。
- 因此它会直接复用你在 Codex 里已经配置好的内容：
  - 本地认证
  - 配置
  - 环境
  - MCP 设置
- 文章用一句话概括这个设计：  
  它不是一个独立的新系统，“它就是 Codex，只是从 Claude Code 内部调用出来”。

##### 6. 可选的 “评审关卡” 功能

- 可以通过下面命令启用评审关卡：

```bash
/codex:setup --enable-review-gate
```

- 作用是：在 Codex 审查完成之前，阻止 Claude Code 直接退出。
- 这个功能适合那些希望 “先审后结束” 的用户，但作者提醒要谨慎：
  - 它可能导致 Claude 和 Codex 之间形成长时间循环
  - 会更快消耗使用额度
- 换句话说，这个功能能提升流程约束力，但也可能带来成本和效率问题。

##### 7. 作者的最终结论

- 这款插件的定位很明确：  
  `保留 Claude Code 的主工作流，同时在 Codex 擅长的地方继续用 Codex。`
- 作者给出的建议是：
  - 安装插件
  - 运行`/codex:setup`
  - 把`/codex:review`当作默认的 “第二遍检查”
  - 当普通检查不够时，再使用`/codex:adversarial-review`或`/codex:rescue`
- 核心思想不是替代 Claude Code，而是让两个代理在同一流程里协作，各自发挥优势。

##### 8. 热门回复反映了什么观点

- 文末共有`5 条热门回复`，讨论的重点集中在 “不同模型交叉审查” 的价值。
- 最有代表性的观点是：
  - `对抗性审查才是真正的突破口`
  - 同一个模型审查自己生成的内容，就像自己校对自己的文章，容易重复忽略同样的问题
- 这个观点在评论中被多次重复，说明大家普遍认可：
  - `Claude 负责生成`
  - `Codex 负责批判性审查`
  是一种更稳妥、与模型无关的工作流。
- 其他评论则补充了两点现实价值：
  - 官方插件比自己用`hook`、`共享消息系统`、甚至`tmux`拼接协作方案更简单
  - 一些用户也在确认：`免费版 ChatGPT 订阅`是否也可用于该插件（原文给出的答案是支持 “包括免费版”）

##### 9. 一句话总结

- 这篇文章本质上是在推荐一种 “双代理协作” 的开发方式：用 Claude Code 继续主流程，再用 Codex 做独立复核、对抗性挑错或任务接管。
- 如果你经常处理高风险改动，这个插件最值得关注的不是 “接入方便”，而是它提供了一个真正不同视角的第二审查者。
