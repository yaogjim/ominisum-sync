**Leo**

过去这一周 CF 基本把 agent 生态补齐了——Agents SDK v2、Agent Memory（managed context 外挂）、Browser Run（agent 级浏览器 + human in the loop）、AI Gateway（14 家 provider 统一接入）、Registrar API 让 agent 自己注册域名，还成了 OpenAI 新 Agents SDK 的 sandbox partner。

这已经不是"替 agent 省 token"，是把 agent 运行时栈（记忆/浏览/推理/动作）全做齐了。

今天顺手把剩的 3 个 Vercel project 全删了——昨晚供应链事件之后彻底清理。我的几个在跑的项目早就迁 CF Pages 了。Worker + R2 + D1 对"一个人维护多项目"的场景太合适：免费额度吃不满，冷启动快，配置少。

唯一没 all in 的是数据库。策略相关的还在自建 PG——真钱系统最烦多一层不可控依赖。

## 通俗精炼（1）

### 2026-04-22 04:06:24

#### Cloudflare 正在补齐 Agent 全栈能力

##### 核心观点

过去一周，Cloudflare 基本把 AI Agent 需要的关键基础设施补齐了。它做的已经不只是 “帮 AI 省 token”，而是在搭一整套 Agent 运行时：从记忆、浏览、推理到执行动作，越来越接近一个完整平台。

##### Cloudflare 补了哪些能力

Cloudflare 这次补齐的能力，覆盖了 Agent 落地最常见的几个环节：

- **Agents SDK v2**：更完整的 Agent 开发框架  
- **Agent Memory**：给 Agent 增加可管理的长期上下文记忆  
- **Browser Run**：让 Agent 能直接操作浏览器，并支持人工介入  
- **AI Gateway**：统一接入 14 家模型供应商，方便切换和管理  
- **Registrar API**：Agent 甚至可以自己注册域名  

这意味着 Cloudflare 想做的，不是单点工具，而是 Agent 的底层操作系统。

##### 为什么这件事重要

以前大家更多把 Cloudflare 看成 “网络层” 或 “加速省钱工具”，比如把网页转成干净文本，减少 AI 读取网页时的 token 浪费。

但现在它的角色在升级：

- 不只是优化成本，而是承接 Agent 的完整运行过程  
- 不只是模型调用，而是把 “记忆 + 浏览 + 推理 + 动作” 串起来  
- 不只是提供接口，而是直接参与 Agent 生态标准化  

一句话：Cloudflare 正从 “基础设施配角”，变成 Agent 时代的核心平台之一。

##### 作者自己的技术选择

作者已经把剩下的 3 个 Vercel 项目删掉，全面清理并迁移到 Cloudflare Pages。原因很现实：

- **更适合个人维护多个项目**
- **免费额度够用**
- **冷启动快**
- **配置简单**

配合`Workers + R2 + D1`，对独立开发者或小团队来说，整体性价比很高。

##### 仍然保留的谨慎点

作者并没有完全 all in Cloudflare，**数据库仍保留部分自建 PostgreSQL**。

原因是：涉及策略或真钱系统时，最怕再多一层不可控依赖。也就是说，Cloudflare 很适合大部分应用层能力，但在最核心、最敏感的数据层，作者依然倾向自己掌控。

##### 一个值得注意的信号

Cloudflare 还成为了 OpenAI 新 Agents SDK 的 sandbox partner，这说明它不仅在补产品能力，也在进入更核心的 Agent 生态合作链条。

这释放出一个明确信号：**Cloudflare 正在争夺 AI Agent 基础设施入口。**

##### 一句话总结

Cloudflare 正从 “帮 AI 省 token 的网络工具”，升级为 “承载 Agent 全生命周期的基础设施平台”；对独立开发者很友好，但在核心数据库等高风险场景，仍需保留自主可控。
