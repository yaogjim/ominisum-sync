## 分析要点

- **核心高价值点**：让廉价多模态模型充当“观察者”，仅向高成本推理模型传递结构化文本，并在关键帧上按需升级，可以显著压缩视觉内容在长对话中的重复成本。
- **留存建议**：精读其模型分工思路，核验价格、接口兼容性和实际识别效果后存档（视觉观察与复杂推理解耦的架构可复用于多种 Agent 工作流，并提供了基本接入方式与任务升级策略。）

**知识要点**

- 将视觉感知和复杂推理拆分给不同模型，可以避免高成本图像输入在多轮上下文中反复累积。
- 视觉观察提示应明确要求时间戳、屏幕文字、剪辑、构图和开场钩子，而不是笼统要求描述视频。
- 廉价模型负责批量观察，遇到决定性单帧或细微内容时再升级到更强模型，可形成分层处理机制。

**行动项**

- 封装一个可由主 Agent 调用的视觉工具，将图片或视频提交给低成本多模态模型并返回文本。
- 使用自有视频样本核验输入输出成本、格式兼容性、识别准确率和上下文节省幅度。
- 设置关键帧升级条件，在低成本模型置信不足或内容影响最终判断时调用更强模型复核。

#### 文章主旨

文章提出一种低成本的“模型分工”方案：让昂贵的 Claude/Fable 等前沿模型专注推理，使用便宜的 **Gemini 2.5 Flash-Lite** 负责观看图片和视频，再将视觉内容转成文本交给前沿模型判断。这样既补足视频理解能力，也能大幅降低多轮对话中的图像成本。

##### 1. 问题：前沿推理模型的“眼睛”昂贵且受限

- 很多人使用 Claude Code 或 Codex，但这些工具通常绑定特定模型，难以针对不同任务灵活分工。
- 作者通过 OpenCode 和 OMO 为不同代理配置不同模型，发现：
  - 不同模型各有专长；
  - 最强的推理模型不必亲自完成信息查找和视觉观察。
- 文中称，Fable 5 和 Opus 5 无法直接观看视频，因为 Claude API 不支持视频输入。
- 即使只看图片，成本也不低：
  - Opus 5 查看一张全分辨率图片最高约消耗 **4,784 tokens**；
  - 按每百万输入 token **5 美元**计算，每张约 **2 美分**；
  - Fable 按每百万输入 token **10 美元**计算，每张约 **5 美分**。

##### 2. 隐性成本：图片会在多轮对话中反复计费

图片成本不只是首次输入费用：

- 代理分析网页或视频时，往往要查看数十张截图或视频帧。
- 图片会保留在对话历史中，并在后续每轮交互中重新发送。
- 例如，一个含 **10 张图片、持续 20 轮**的会话，实际可能接近产生 **200 次图片输入成本**，而不是只支付 10 次。

因此，直接让昂贵模型持续查看视觉内容，会让成本随对话轮数快速累积。

##### 3. 核心方案：让便宜模型观察，让强模型推理

作者建议将任务拆成两部分：

1. **Gemini 2.5 Flash-Lite** 负责读取图片和视频，并输出文字描述；
2. **Claude/Fable 等前沿模型** 根据描述进行分析、判断和决策。

这样做的优势是：

- 前沿模型不必反复接收高 token 的原始图片；
- 一张约 **4,784 tokens** 的图片，可以被压缩成约 **300 tokens** 的文本描述；
- 后续对话只需携带短文本，而不是反复发送图片。

作者将 Flash-Lite 定位为“**见证者而非裁判**”：它只需准确描述自己看到了什么，最终判断仍由更强的模型完成。

##### 4. “便宜的眼睛”：Gemini 2.5 Flash-Lite

作者通过 OpenRouter 使用 Gemini 2.5 Flash-Lite，其文中价格与能力如下：

| 项目 | 数据 |
|---|---:|
| 输入价格 | 每百万 tokens **0.10 美元** |
| 输出价格 | 每百万 tokens **0.40 美元** |
| 上下文窗口 | **100 万 tokens** |
| 支持内容 | 图片、MP4、MOV、WebM、公开 YouTube 链接 |

###### 视频成本估算

Gemini 默认以约 **每秒 1 帧**采样视频，每秒素材约消耗 **300 tokens**：

- **60 秒 TikTok**：约 18,000 tokens，成本约 **0.2 美分**；
- **3 分钟视频**：约 **0.5 美分**；
- **1 小时低分辨率 YouTube 视频**：约 **4 美分**。

###### 图片成本估算

- 一张图片约消耗 **258 tokens**；
- 成本约 **0.003 美分**；
- 文中称，这大约比直接把同一张图片交给 Opus 便宜 **1,000 倍**。

##### 5. 接入方式：封装成一个视觉工具

OpenRouter 使用标准 Chat Completions 格式，因此可以通过一个简单的 `curl` 请求调用：

```bash
curl https://openrouter.ai/api/v1/chat/completions \
  -H "Authorization: Bearer $OPENROUTER_API_KEY" \
  -d '{
    "model": "google/gemini-2.5-flash-lite",
    "messages": [{
      "role": "user",
      "content": [
        {
          "type": "text",
          "text": "逐镜头描述视频，包括时间戳、屏幕文字、剪辑，以及前3秒发生了什么"
        },
        {
          "type": "video_url",
          "video_url": {
            "url": "data:video/mp4;base64,..."
          }
        }
      ]
    }]
  }'
```

作者建议将其封装成一个如 `look.sh` 的小脚本，再告诉 Claude：

> 当需要查看图片或视频时，调用 `look.sh`，并附带文件路径和具体问题。

完整工作流如下：

1. Claude 遇到需要视觉理解的内容；
2. Claude 调用 `look.sh`；
3. Flash-Lite 查看图片或视频；
4. Flash-Lite 返回文字描述；
5. Claude 根据文字进行推理和决策。

##### 6. 提示词质量决定观察结果

不要只让视觉模型“描述这个视频”，而应提出具体要求，例如：

- 给出准确时间戳；
- 识别屏幕文字；
- 标出镜头切换；
- 描述画面构图；
- 分析前 3 秒的吸引点；
- 拆解视频的钩子和叙事结构。

问题越具体，返回的信息越适合后续推理。对于大规模 TikTok 分析等场景，这种精细化提示尤其重要。

##### 7. 局限与最佳实践

Flash-Lite 成本低，但视觉判断能力不如前沿模型，可能遗漏微妙细节。因此作者建议采用分级处理：

- **大多数图片和视频**：交给 Flash-Lite 低成本观察；
- **决定性单帧或关键细节**：单独发送给 Claude，并支付约 **2 美分**的高质量视觉分析费用。

也就是说，不应完全替代前沿模型的视觉能力，而应只在真正重要的节点使用它。

##### 8. 最终结论

作者的核心观点是：

> 最强模型不需要亲自“看见”一切，它只需要获得可靠观察者整理出的信息。

通过“廉价视觉模型观察 + 前沿模型推理”的架构，可以把视频和图片分析扩展到更大规模，同时显著减少视觉输入及多轮上下文带来的成本。热门回复也补充了一点：AI 往往能完成大量基础认知工作，但最终价值仍来自人的品味、判断、迭代、专业知识和原创性。

## 细节还原（1）

### 2026-07-28 03:04:57

#### 给 Fable 配上一双几美分的“眼睛”

文章从一个常见困境开始：Claude Code、Codex 等前沿工具擅长推理，却无法直接观看视频；即使能够读取图片，连续处理大量画面也会迅速推高成本。作者由此提出一套分工方案——让昂贵模型负责判断，让 Gemini 2.5 Flash-Lite 以极低价格观察图片和视频，再把文字描述交还给前者。

##### 从单一模型转向“不同代理使用不同模型”

许多人使用 Claude Code 或 Codex 作为主要工具，只能被动接受这些框架默认提供的模型配置。遇到视频时，他们往往要手动转录内容、截取画面，再把截图或视频帧粘贴给 Claude。

作者从 12 月开始通过 OpenCode 使用 OMO（Oh My OpenAgent），因此可以为不同代理指定不同模型。这段实践很快让他意识到：没有一个模型能同时把所有任务都做到最好，为不同任务准备不同模型，往往比让最昂贵、最聪明的模型包办一切更有效。

当时，Claude Code、Codex 这类闭源代码框架还不容易定制。后来，随着模型能力提升、相关配置也变得更容易，作者重新使用这些前沿工具，但仍然保留了让不同代理调用不同模型的 harness。原因并没有改变：一些模型在特定任务上明显更出色。

Fable 是作者很喜欢的模型，但它有一个直接限制——不能观看视频。解决这个问题的关键，不是等待 Fable 自己获得视频能力，而是给它接入一个专门负责观察的廉价模型。

##### 真正昂贵的不是一张图片，而是图片被反复带进上下文

Fable 5 和 Opus 5 都不能直接观看视频，因为 Claude API 没有视频输入，无论支付多少费用都无法改变这一点。它们虽然可以查看图片，但视觉输入的成本并不低。

在 Opus 5 上，一张全分辨率图片最多会消耗 4,784 个 token。按照每百万输入 token 5 美元计算，查看一张图片大约需要 2 美分。Fable 的输入价格是每百万 token 10 美元，同一张图片的成本更接近 5 美分。

单看 2 美分似乎微不足道，但代理很少只查看一张图。一次浏览器操作或一次视频拆解，通常会产生数十张截图。更容易被忽略的是，这些图片会留在对话历史中，并在之后的每轮交互里重新发送。

因此，一个包含 10 张图片、持续 20 轮的会话，并不只是承担 10 次图片输入的费用，而可能接近 200 次。视觉内容越多、对话越长，前沿模型直接“看”的成本就越难控制。

作者由此改变了任务分配方式：昂贵模型不再负责亲自观察全部素材，而只负责推理；另一个极其便宜的多模态模型负责看图、看视频，并将观察结果转换成文本。对 Claude 来说，文本本来就是更适合推理的输入。相比一张占用 4,784 个 token 的图片，一段约 300 token 的描述只占约 6% 的上下文重量，而且后续每轮重发时都更加便宜。

##### Gemini 2.5 Flash-Lite 成为廉价的视觉见证者

作者选择的“眼睛”是通过 OpenRouter 调用的 Gemini 2.5 Flash-Lite。它是谷歌的轻量级快速多模态模型，在 OpenRouter 上，每百万输入 token 收费 0.10 美元，每百万输出 token 收费 0.40 美元，并支持 100 万 token 的上下文窗口。

与 Claude 不同，Flash-Lite 不仅可以读取图片，还能处理 MP4、MOV、WebM 等视频格式，甚至能够读取公开的 YouTube 链接。

它处理视频时，以每秒 1 帧的速度采样。在默认分辨率下，每秒视频大约对应 300 个 token。按照这个规模计算，一段 60 秒的 TikTok 视频约为 18,000 token，输入成本约为五分之一美分；一段 3 分钟的视频约需半美分；即使是一小时的低分辨率 YouTube 视频，成本也只有约 4 美分。

静态图片的差距更明显。一张图片在 Flash-Lite 中约占 258 个 token，成本约为千分之三美分，大约比将同一张图片直接交给 Opus 便宜 1,000 倍。

Flash-Lite 本身并不是一个特别聪明的推理模型，但作者认为它不需要承担这项职责。它的角色是“见证者而非裁判”：负责如实描述屏幕上出现了什么，真正的判断、分析和决策仍然交给 Claude 或 Fable。

##### 一个工具脚本把观察结果交还给 Claude

由于 OpenRouter 使用标准的聊天补全格式，整个接入过程可以缩小为一个 `curl` 调用。请求中指定 `google/gemini-2.5-flash-lite`，同时发送问题和视频内容：

```bash
curl https://openrouter.ai/api/v1/chat/completions \
  -H "Authorization: Bearer $OPENROUTER_API_KEY" \
  -d '{
    "model": "google/gemini-2.5-flash-lite",
    "messages": [{
      "role": "user",
      "content": [
        {
          "type": "text",
          "text": "describe this video shot by shot: timestamps, on-screen text, cuts, and what happens in the first 3 seconds"
        },
        {
          "type": "video_url",
          "video_url": {
            "url": "data:video/mp4;base64,..."
          }
        }
      ]
    }]
  }'
```

作者将这段调用封装进一个小脚本，然后告诉 Claude：“当你需要查看图片或视频时，调用 `look.sh`，并附带文件路径和问题。”

由此形成的工作循环非常直接：Claude 在任务中遇到视觉内容，调用工具；Flash-Lite 读取图片或视频，返回文字观察结果；Claude 再依据这些文字进行推理。这样，视觉素材不会以高成本反复留在前沿模型的对话历史里，留下的主要是体积更小的文本描述。

不过，工具只是连接方式，真正决定观察质量的是发送给视觉模型的问题。作者不建议只说“描述这个视频”，而应明确要求它提供时间戳、屏幕文字、剪辑变化、画面构图、钩子结构，以及视频前 3 秒具体发生了什么。问题越具体，返回的信息越有用。

##### 大规模素材走廉价通道，关键单帧再交给前沿模型

这套架构并非只是为了节省少量费用。作者的业务需要大规模分析 TikTok 视频，如果所有观看任务都发生在前沿模型上，整体成本根本无法成立。只有当“眼睛”足够便宜，批量视频分析流程才有可能持续运行。

作者也明确指出了 Flash-Lite 的局限：它会错过一些前沿模型能够捕捉到的细微之处。因此，这套方法不是要求所有画面都永远只交给廉价模型。当某个单帧确实决定判断结果时，可以把那一帧直接发送给 Claude，为它支付约 2 美分，让更强的模型进行细致分析。

其余绝大多数素材则先经过廉价的“眼睛”。最终形成的原则是：最好的推理模型几乎不应该亲自承担大规模观察工作，它需要的不是把所有东西都看一遍，而是获得一个已经看过素材、能够返回具体事实的观察者。正如作者最后概括的那样：“你的模型不需要看，它需要的是见过的人。”

## 口播总结（1）

### 2026-08-03 01:09:23

#### 如何让 Fable 观看视频只需几美分

这篇材料介绍了一种低成本的“视觉分工”方案：让昂贵、擅长推理的模型负责判断，让便宜的多模态模型负责观看图片和视频。听完你会了解，为什么直接把大量截图交给 Claude 一类的模型成本很高，以及如何用一个外部视觉工具，把视频分析费用降到几美分。

##### 首先，关键思路是：不同任务，交给不同模型

作者一开始遇到的问题很普遍。很多人使用 Claude Code 或 Codex 时，只能接受工具默认分配的模型。这样做方便，但也意味着一个模型要承担所有任务。

作者从十二月开始使用 OpenCode 和 OMO。OMO 的全称是 Oh My OpenAgent，可以理解成一套让不同代理调用不同模型的工具。通过这种方式，作者发现，模型之间各有所长。一个模型可能特别擅长写代码，另一个模型可能更适合分析内容，还有的模型更适合处理视觉信息。

后来，即使作者重新使用 Claude Code 和 Codex 这样的前沿工具，仍然保留了自己的工具流程，让不同模型各自承担擅长的任务。

这个思路的重点是：不要强迫一个模型包办一切。推理、观察、检索和执行，可以拆开来完成。

##### 接下来，看看让昂贵模型直接“看”的代价

作者很喜欢 Fable，但 Fable 的一个明显问题是，它不能直接观看视频。按照材料中的说法，Fable 5 和 Opus 5 都不能在 Claude API 中直接接收视频输入。它们可以处理图片，但价格并不便宜。

以 Opus 5 为例，一张全分辨率图片最多可能占用四千七百八十四个 token。Token 可以简单理解成模型处理文字和图像信息时使用的计费单位。按照每百万输入 token 五美元计算，一张图片大约要花两美分。

在 Fable 上，输入价格是每百万 token 十美元，所以同样一张图片的成本更接近五美分。

单看一张图片，这个价格似乎不高。但问题在于，视频分析通常需要处理很多帧。一次浏览，或者一次视频拆解，可能就要分析几十张截图。

更重要的是，图片一旦进入对话历史，后面每一轮对话可能都会再次发送这些图片。比如，一个对话里有十张图片，持续进行二十轮交流，实际产生的图片处理费用就不只是十张，而可能接近两百次图片调用。

所以，真正昂贵的不是某一张截图，而是视觉内容在长对话中被反复发送。

##### 更重要的是，解决办法不是让推理模型更强，而是让模型分工

作者提出的方案很直接：让昂贵的模型负责推理，让一个非常便宜的模型负责观察。

这个便宜模型先把图片或视频转换成文字描述。然后，Claude 不再反复读取原始图片，而是根据这些文字进行判断和推理。

为什么这样做有效？因为推理模型最终需要的，往往是视觉内容里提炼出的信息，而不是完整的图像文件。原文举例说，一张图片可能占用四千七百八十四个 token，但经过整理后，只需要大约三百个 token 的描述文字。也就是说，文字描述大约只占原始图像 token 数的百分之六，却能保留相当一部分有用信息，而且后续对话只需要重复发送文字。

在这个分工里，便宜模型像“眼睛”，只负责报告自己看到了什么；昂贵模型像“裁判”，负责判断这些内容意味着什么。

##### 具体的低价“眼睛”：Gemini 2.5 Flash-Lite

作者选择的视觉模型，是谷歌的 Gemini 2.5 Flash-Lite，并通过 OpenRouter 调用。OpenRouter 可以理解成一个统一接入多种模型的平台。

Flash-Lite 是一个轻量、快速的多模态模型。多模态的意思是，它不只处理文字，也能处理图片和视频。

按照材料中的价格，它的输入费用是每百万 token 零点一美元，输出费用是每百万 token 零点四美元，上下文窗口支持一百万 token。上下文窗口可以理解成模型一次能够记住和处理的内容总量。

它不仅能读取图片，也能读取 MP4、MOV 和 WebM 等视频格式，甚至可以读取公开的 YouTube 链接。

作者最关注的是它的成本。模型大约按照每秒一帧的速度采样视频，在默认分辨率下，每秒大约处理三百个 token。

按照作者给出的估算，一段六十秒的 TikTok 视频，大约需要一万八千个 token，成本约为五分之一美分。三分钟视频大约是半美分。整整一小时的低分辨率 YouTube 视频，作者估算成本大约为四美分。

单张图片大约占用二百五十八个 token，成本约为千分之三美分。作者认为，这比把同一张图片交给 Opus 处理便宜大约一千倍。

当然，Flash-Lite 并不是最聪明的模型。但在这个方案里，它不需要负责复杂判断。它只需要稳定地回答几个问题：画面里有什么，什么时候发生了变化，屏幕上写了什么，以及视频是怎样剪辑的。

##### 然后，用一个工具把两种模型接起来

技术接线其实很简单。OpenRouter 使用标准的聊天补全格式，所以可以通过一个 API 请求，把文字问题和视频一起发送给 Gemini 2.5 Flash-Lite。

实际使用时，可以把这个请求封装成一个小脚本，比如叫作 `look.sh`。然后告诉 Claude：当你需要查看图片或视频时，就调用 `look.sh`，并提供文件路径和具体问题。

这样一来，整个工作流程就变成了三步。

第一步，Claude 遇到图片或视频，判断自己需要视觉信息。

第二步，Claude 调用 `look.sh`，把文件交给 Flash-Lite 观察。

第三步，Flash-Lite 返回文字描述，Claude 再根据这些描述继续推理。

对 Claude 来说，它不需要亲自处理每一帧图像。它只需要读取“有人看过之后写下来的观察结果”。

##### 提示词越具体，视觉结果越有用

作者特别强调，提示词往往比模型本身更重要。

不要只问：“描述这个视频。”

更好的问法，是明确要求模型提供时间戳、屏幕文字、镜头切换、画面构图、开头几秒发生的事情，以及视频的吸引点和结构。

比如，可以让模型逐镜头说明：每个时间点发生了什么，画面上出现了哪些文字，什么时候发生剪辑，前几秒用了什么钩子。

“钩子”指的是视频开头用来吸引观众继续观看的内容。问题越具体，模型返回的信息就越容易直接用于后续分析。

对于大规模分析 TikTok 视频来说，这种具体的提问方式尤其重要。因为如果每个视频都交给昂贵的前沿模型去看，整体成本很快就会失控。

##### 最后，要接受便宜模型会漏掉细节

这个方案并不意味着 Flash-Lite 能完全替代 Claude。

作者坦率地提醒，便宜的视觉模型可能会错过前沿模型能够发现的细微内容。因此，比较合理的做法不是让所有内容都经过昂贵模型，而是采用分层策略。

大多数图片和视频帧，交给便宜的 Flash-Lite 处理。只有当某一帧看起来非常关键，或者它可能决定最终判断时，再把这一帧单独发送给 Claude，并支付大约两美分的费用。

这样做，就把高价模型留给真正重要的内容，把低价模型用于大规模筛选和初步观察。

作者最后把这套方法概括成一句话：你的模型不一定需要亲自看见一切，它需要的是有人先看过，并把重要信息告诉它。

##### 结尾：四件最值得记住的事

如果只记住四点，可以记住下面这些。

第一，最强的推理模型不一定适合承担所有视觉工作。让不同模型各自处理擅长的任务，通常更省钱，也更高效。

第二，直接把图片交给昂贵模型，成本会因为多帧视频和重复对话而迅速增加。图片进入对话历史后，后续轮次可能会反复计费。

第三，Gemini 2.5 Flash-Lite 可以作为低价视觉助手，负责读取图片、视频和部分在线视频内容，再把观察结果转换成文字。

第四，最实用的方案是分层处理：大部分内容交给便宜模型，只有真正关键的画面，才交给昂贵模型做精细判断。

- 少量关键帧再升级给昂贵模型复核。

这种设计可迁移到视频研究、UI 自动测试、广告素材分析、客服录屏诊断等场景。它成立的条件不是便宜模型“足够聪明”，而是多数素材只需先被筛选和结构化，真正需要高级判断的部分很少。免费使用 Gemini 并不能替代这套方案，因为规模化工作流需要自动调用、统一上下文和可控的升级机制，而不是人工在多个产品间搬运信息。

因此，提示词确实比泛泛要求“描述视频”更重要，但更稳妥的系统还应保留时间戳和原始素材引用，允许推理模型追问，并根据低置信度、异常片段或任务重要性自动升级到更强模型。产品上真正该验证的，也不是单次调用价格，而是目标任务的召回率：便宜视觉模型会漏掉多少影响最终结论的证据？

- 视觉观察提示应明确要求时间戳、屏幕文字、剪辑、构图和开场钩子，而不是笼统要求描述视频。
- 廉价模型负责批量观察，遇到决定性单帧或细微内容时再升级到更强模型，可形成分层处理机制。
