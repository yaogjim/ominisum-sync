#### 深度代理部署：Claude 托管代理的一个开放替代方案

今天我们推出 [**Deep Agents deploy**](https://docs.langchain.com/oss/python/deepagents/deploy?ref=blog.langchain.com) 的测试版。Deep Agents deploy 是部署一个与模型无关的开源代理框架的最快方式，该框架可直接投入生产。

Deep Agents 部署是为开放世界而构建的。它基于 [**Deep Agents**](https://docs.langchain.com/oss/python/deepagents/overview?ref=blog.langchain.com) 构建——这是一个开源的、与模型无关的代理框架。框架与内存紧密相关，这意味着通过选择一个开放的框架，你将选择掌控自己的内存，而不是让它被锁定在专有框架中或与单一模型绑定。

#### Harness engineering → productionHarness 工程 → 生产

在过去几个月里， [**“框架工程”**](https://blog.langchain.com/the-anatomy-of-an-agent-harness/) 作为构建框架以将 LLMs 转化为智能体的学科兴起。这些框架包含编排逻辑、工具和技能，作为智能体的基础，但允许构建者提供自定义指令、工具和技能，以根据自身使用场景定制框架。

要上线，需要几个步骤：

- 以多租户、可扩展的方式部署代理编排逻辑和内存
- 设置沙箱，使其在每个代理会话中被启动
- 部署端点以与代理进行交互，从 MCP 到 A2A 及其他端点，用于人在回路、记忆等场景

今天我们将所有这些步骤整合为一个命令： `deepagents deploy`

#### What are you deploying?

使用 `deepagents deploy` 命令，你正在部署自己的自定义代理。有一些你需要指定的参数：

- `model`: 要使用的大型语言模型。Deep Agents 可与任何模型或模型提供商配合使用，包括 OpenAI、Google、Anthropic、Azure、Bedrock、Fireworks、Baseten、Open Router 和 Ollama。请参阅我们的 [**模型**](https://docs.langchain.com/oss/python/deepagents/models?ref=blog.langchain.com) 文档以获取更多信息。
- `AGENTS.md` ：这是代理的核心指令集，其中你需要指定在会话开始时加载的指令。
- `skills`: These are [**Agent Skills**](https://agentskills.io/?ref=blog.langchain.com) that allow for specialized knowledge (via markdown files) and actions (via scripts to run). See our [**Skills docs**](https://docs.langchain.com/oss/python/deepagents/skills?ref=blog.langchain.com) for more.  
  `技能`: 这些是 [**代理技能**](https://agentskills.io/?ref=blog.langchain.com) ，它们支持专业知识（通过 markdown 文件）和操作（通过可运行的脚本）。有关更多信息，请查看我们的 [**技能文档**](https://docs.langchain.com/oss/python/deepagents/skills?ref=blog.langchain.com) 。
- `mcp.json`: 这些是代理可以使用 MCP 协议（HTTPS/SSE）调用的工具
- `沙箱` ：如果需要，你可以指定一个 [**沙箱**](https://docs.langchain.com/oss/python/deepagents/sandboxes?ref=blog.langchain.com) ，供代理执行工作和运行技能。开箱即用的 Deep Agents 包含与 Daytona、Runloop、Modal 或 LangSmith 沙箱的集成。任何沙箱提供商都可以与 Deep Agents 配合使用；请参阅我们的 [**实施指南**](https://docs.langchain.com/oss/python/contributing/implement-langchain?ref=blog.langchain.com#sandboxes) 。

#### 与 Claude 托管代理相比

[**Claude Managed Agents**](https://platform.claude.com/docs/en/managed-agents/overview?ref=blog.langchain.com) 是另一个近期推出的竞争性产品。其高层架构（harness、agent server、沙箱）相同，但 Claude Managed Agents 是一个围墙花园，会造成极大的锁定效应。

![](https://cdn.prod.website-files.com/65c81e88c254bb0f97633a71/69dce886ae22acf1e99a6a29_Screenshot-2026-04-09-at-8.50.43---AM.png)

#### Memory

开放生态系统对代理工具包和代理平台至关重要的核心原因在于内存。

代理框架与记忆密不可分（Sarah Wooders [**写了一篇关于此的精彩文章**](https://x.com/sarahwooders/status/2040121230473457921?s=20&ref=blog.langchain.com) ）。框架的一个关键作用是管理上下文（记忆只是上下文）。随着框架的越来越多部分变得封闭并被 API 锁定，你的记忆也会如此。

从一个模型切换到另一个模型其实相当容易。当然，你可能需要稍微调整一下提示词，但没什么太困难的。所以仅模型 API 本身并不会造成太多锁定——就像我们最近看到的，有很多从 OpenAI 迁移到 Anthropic 的情况。

当你开始在这些 API 中整合内存功能时——无论是短期还是长期——都会产生难以置信的锁定效应。

设想创建一个内部 SDR 代理。它从基础开始，但随着与用户的交互，它会实时学习。这种记忆会累积——但这一切都在封闭的 API 后面。如果你想脱离那个框架或模型，那就意味着重置你的代理的记忆，从头开始。

It’s even worse for agents that you expose to your customers. You build an external facing sales agent, that builds up memory of the clients it interacts with. All of these memories are behind a closed API. These memories are part of a data flywheel you should be building to make your customer’s experience better over time. But they are no longer yours - they belong to whomever owns that closed API.  
对于面向客户的代理而言，情况甚至更糟。你构建一个面向外部的销售代理，它会积累与所交互客户的记忆。这些记忆都位于封闭的 API 之后。这些记忆是你本应构建的数据飞轮的一部分，你构建这个飞轮是为了随着时间的推移提升客户体验。但这些记忆不再属于你——它们属于拥有该封闭 API 的人。

`deepagents deploy` stores memory in a standard format ([**AGENTS.md**](http://agents.md/?ref=blog.langchain.com), skills, and other files), allows you to query them directly via API, and if you self host ensures that memory always remains in your databases only.  
`deepagents deploy` 以标准格式存储内存（ [**AGENTS.md**](http://agents.md/?ref=blog.langchain.com) 、技能和其他文件），允许您直接通过 API 查询它们，如果您自托管，则确保内存始终仅保留在您的数据库中。

#### Try out an open harness

在专有框架上构建代理会造成极大的锁定效应。我们相信，在这样一个世界里，代理的构建和部署应该变得简单，但你仍然可以选择模型，并且仍然拥有自己的记忆。

如果你也认同这一点，今天就尝试使用 `deepagents deploy` 吧。

#### Deep Agents Deploy：Claude Managed Agents 的开放替代方案

##### 一句话总结

Deep Agents Deploy 是一个开源、模型无关的 Agent 部署方案，目标是让开发者用一条命令把自定义 Agent 部署到生产环境，同时避免被单一模型、封闭框架和专有记忆系统锁定。

---

##### 核心价值

###### 1. 一条命令部署生产级 Agent

过去将 LLM Agent 上线需要处理多项复杂工作：

- 部署 Agent 编排逻辑和记忆系统
- 支持多租户与可扩展架构
- 配置沙箱环境，供 Agent 执行任务
- 暴露交互端点，如 MCP、A2A、人类介入、记忆访问等

Deep Agents Deploy 将这些流程简化为：

```bash
deepagents deploy
```

---

##### 你实际部署的是什么？

###### 1. 自定义 Agent

使用`deepagents deploy`时，开发者可以配置自己的 Agent，包括：

- **model**：支持 OpenAI、Google、Anthropic、Azure、Bedrock、Ollama 等多种模型和服务商
- **AGENTS.md**：Agent 的核心系统指令
- **skills**：Agent 技能，可通过 Markdown 提供知识，通过脚本执行动作
- **mcp.json**：定义 Agent 可通过 MCP 协议调用的工具
- **sandbox**：为 Agent 提供执行环境，支持 Daytona、Runloop、Modal、LangSmith 等

核心特点是：**框架开放，模型可替换，能力可扩展。**

---

##### 与 Claude Managed Agents 的差异

###### 1. 架构类似，但开放性不同

Deep Agents Deploy 和 Claude Managed Agents 在高层架构上类似，都包括：

- Agent harness / 编排框架
- Agent server
- 沙箱环境
- 工具调用与记忆管理

但关键区别在于：

- **Claude Managed Agents 是封闭生态**
- **Deep Agents Deploy 是开源、模型无关、可自托管的开放方案**

---

##### 为什么 “记忆” 是关键？

###### 1. 真正的锁定不只是模型，而是记忆

文章认为，单纯切换模型并不难，最多需要调整提示词。

真正的锁定来自 Agent 的记忆系统：

- Agent 与用户交互后会积累上下文
- 这些记忆会形成业务知识和客户理解
- 如果记忆被封闭 API 托管，迁移成本会极高

一旦离开封闭框架，就可能意味着：

> Agent 的历史经验和用户记忆需要全部重建。

---

##### 对企业和产品的影响

###### 1. 记忆是数据飞轮的一部分

对于内部 Agent，比如 SDR 销售代理，记忆会帮助它越来越理解业务流程。

对于面向客户的 Agent，问题更重要：

- 它会积累客户偏好
- 记录客户上下文
- 提升未来交互体验
- 形成产品的数据飞轮

如果这些记忆在封闭 API 内部，本质上这些数据资产就不再完全属于企业自己。

---

##### Deep Agents Deploy 的解决方案

###### 1. 记忆可控、可查、可迁移

Deep Agents Deploy 将记忆存储为标准格式，例如：

- `AGENTS.md`
- skills 文件
- 其他结构化文件

同时支持：

- 通过 API 直接查询记忆
- 自托管部署
- 记忆保存在自己的数据库中
- 不绑定特定模型或云厂商

这意味着企业可以真正掌控 Agent 的长期资产。

---

##### 产品视角总结

###### 1. 这是 Agent 基础设施的开放化竞争

Deep Agents Deploy 的核心定位不是简单 “部署工具”，而是对抗封闭 Agent 平台锁定的开放基础设施。

它解决的是三个关键问题：

- **部署复杂度**：用一条命令降低 Agent 上线门槛
- **模型灵活性**：避免绑定单一模型供应商
- **记忆所有权**：让企业保有自己的 Agent 数据资产

---

##### 最终判断

Deep Agents Deploy 的价值在于：

> 让企业既能快速部署生产级 Agent，又能保留模型选择权和记忆所有权。

对于重视长期数据资产、客户体验飞轮和技术自主权的团队，开放 Agent 框架相比封闭托管方案更具战略价值。

## 结构化（1）

### 2026-04-28 01:16:29

##### 主旨概括

Deep Agents 发布了**Deep Agents Deploy（Beta）**，主打用一条命令把开源、模型无关的 Agent Harness 部署到生产环境。文章核心观点是：相比 Claude Managed Agents 这类封闭方案，开放式 Harness 能让开发者保留模型选择权，并真正拥有 Agent 的记忆数据。

---

##### 1. Deep Agents Deploy 是什么

Deep Agents Deploy 是一个面向生产环境的 Agent 部署工具，命令为：

```bash
deepagents deploy
```

它基于**Deep Agents**构建，后者是一个：

- 开源的 Agent Harness
- 模型无关，支持多种模型和模型提供商
- 面向生产部署
- 强调用户拥有自己的 Agent 记忆与数据

文章认为，Agent Harness 与 “记忆” 高度绑定，因此选择开放 Harness，本质上也是选择不把记忆锁死在某个封闭平台或单一模型中。

---

##### 2. 从 Harness 工程到生产部署

近几个月，“Harness Engineering” 逐渐成为一个重要方向，指的是构建一套系统，把大语言模型变成可执行任务的 Agent。

一个 Agent Harness 通常包括：

- 编排逻辑
- 工具调用
- 技能系统
- 自定义指令
- 记忆管理

要把 Agent 真正部署到生产环境，通常需要完成几件事：

1. 以多租户、可扩展方式部署 Agent 编排逻辑和记忆系统  
2. 为每个 Agent 会话启动独立沙箱  
3. 提供多个交互接口，例如：
   - MCP
   - A2A
   - Human-in-the-loop
   - 记忆访问接口

Deep Agents Deploy 将这些步骤打包成一个命令，降低生产部署复杂度。

---

##### 3. 使用 deepagents deploy 时部署什么

使用`deepagents deploy`时，开发者部署的是自己的自定义 Agent，主要需要配置以下内容：

###### 3.1 模型 model

Deep Agents 支持任意模型或模型提供商，包括：

- OpenAI
- Google
- Anthropic
- Azure
- Bedrock
- Fireworks
- Baseten
- Open Router
- Ollama

这意味着开发者可以根据任务选择最合适的模型，而不是被某一家模型厂商绑定。

###### 3.2 AGENTS.md

`AGENTS.md`是 Agent 的核心指令文件。

它定义 Agent 在会话开始时加载的基础规则和行为，例如：

- Agent 的身份
- 工作方式
- 回答风格
- 任务边界

###### 3.3 skills

Skills 是 Agent 的技能模块，用来提供：

- 专业知识，例如 Markdown 文件
- 可执行动作，例如脚本

例如，一个销售 Agent 可以通过 Skills 获得产品知识、报价规则或客户跟进流程。

###### 3.4 mcp.json

`mcp.json`用于配置 Agent 可通过 MCP 协议调用的工具。

支持的形式包括：

- HTTPS
- SSE

###### 3.5 sandbox

如果 Agent 需要执行代码或运行技能，可以配置沙箱环境。

Deep Agents 默认集成了：

- Daytona
- Runloop
- Modal
- LangSmith Sandboxes

同时也支持接入其他沙箱服务商。

---

##### 4. 部署后的能力

`deepagents deploy`会把 Deep Agent 与独立的**LangSmith Deployment server**打包部署。

这个服务具备生产级能力：

- 可水平扩展
- 适合生产环境
- 提供超过**30 个接口**

主要接口包括：

| 接口类型 | 作用 |
|---|---|
| MCP | 可以把部署后的 Agent 当作工具调用 |
| A2A | 支持多 Agent 系统中互相调用 |
| Agent Protocol | 方便开发交互式 UI |
| Human-in-the-loop | 为关键操作加入人工审核和保护机制 |
| Memory endpoints | 访问 Agent 的短期记忆和长期记忆 |

---

##### 5. Deep Agents 强调开放生态

文章强调，Deep Agents Deploy 的核心价值是接入开放生态，而不是把用户锁在单一平台中。

具体体现包括：

- 使用**deepagents**：完全开源，MIT License，支持 Python 和 TypeScript
- 使用**AGENTS.md**：开放标准，用于定义 Agent 指令
- 使用**Agent Skills**：开放标准，用于提供专业知识和动作能力
- 支持所有模型提供商，避免 Anthropic 等单一厂商锁定
- 支持所有沙箱服务商
- 通过开放协议暴露 Agent：
  - MCP
  - A2A
  - Agent Protocol
- 可自托管 LangSmith Deployments，从而掌控自己的记忆数据

---

##### 6. 与 Claude Managed Agents 的对比

文章提到，Claude Managed Agents 是近期推出的竞争产品。

两者在高层架构上类似，都包含：

- Harness
- Agent Server
- Sandboxes

但文章认为，Claude Managed Agents 更像是一个 “封闭花园”，会造成严重的绑定问题。

核心差异在于：

| 维度 | Deep Agents Deploy | Claude Managed Agents |
|---|---|---|
| 生态 | 开放 | 封闭 |
| 模型选择 | 支持任意模型 | 更偏向绑定 Claude |
| Harness | 开源 | 专有 |
| 记忆归属 | 用户可拥有和自托管 | 可能被锁在封闭 API 后 |
| 协议 | MCP、A2A、Agent Protocol 等开放标准 | 平台内封闭能力为主 |

---

##### 7. 为什么 “记忆” 是开放生态的关键

文章认为，Agent 平台是否开放，最关键的问题不是模型，而是**记忆 Memory**。

原因是：

- Harness 负责管理上下文
- 记忆本质上也是上下文
- 当 Harness 被封装在封闭 API 后，记忆也会被锁进去

文章指出，切换模型其实相对容易：

- 可能需要调整 Prompt
- 但整体迁移难度不算太高

真正造成锁定的是：

- 短期记忆
- 长期记忆
- Agent 与用户互动中积累的数据

一旦这些记忆被放在封闭 API 后，迁移 Agent 就会非常困难。

---

##### 8. 文章中的具体案例

###### 8.1 内部 SDR Agent

假设企业构建了一个内部 SDR Agent。

一开始它只是基础版本，但随着与员工互动，它会不断学习：

- 客户偏好
- 销售流程
- 历史沟通方式
- 常见问题处理方式

如果这些记忆都存在封闭 API 后，一旦企业想换 Harness 或换模型，就可能面临：

- 记忆无法迁移
- Agent 需要从零开始
- 之前积累的经验全部丢失

###### 8.2 面向客户的销售 Agent

如果企业构建的是外部销售 Agent，它会积累客户相关记忆，例如：

- 客户需求
- 历史咨询
- 产品偏好
- 成交可能性

这些记忆本应成为企业的数据飞轮，让客户体验越来越好。

但如果数据被封闭平台控制，企业就不再真正拥有这些记忆，反而会被平台锁定。

---

##### 9. Deep Agents 如何解决记忆归属问题

Deep Agents Deploy 通过开放格式和可查询接口来避免记忆锁定。

它会将记忆存储在标准格式中，例如：

- AGENTS.md
- Skills
- 其他文件

同时支持：

- 通过 API 直接查询记忆
- 自托管部署
- 将记忆保留在自己的数据库中

这样开发者既可以方便部署 Agent，也能持续掌控自己的数据资产。

---

##### 10. 总结

文章最后呼吁开发者尝试 Deep Agents Deploy。其核心立场是：构建和部署 Agent 应该足够简单，但开发者仍应拥有模型选择权，并真正拥有自己的 Agent 记忆。

Deep Agents Deploy 的价值可以概括为：

- 一条命令部署生产级 Agent
- 开源、模型无关
- 支持开放协议和开放标准
- 可自托管
- 避免记忆被封闭平台锁定
- 更适合长期构建企业自己的 Agent 数据资产
