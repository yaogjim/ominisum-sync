## 正文

**歸藏(guizang.ai)**

Claude 官方写了一篇关于 Loop Engineer 的入门文章。

其实现在我们所说的 Loop Engineer，所有的底层逻辑在提出这个概念以前就已经具备了，甚至这些工作流程也是大家一直在用的，只是被套上了一个新的概念。

在这篇文章中，他们把 Loop 分成了四种类型：

回合制循环（Single-turn Loop）

这是最基本的 Claude Code 工作方式。你发出的每一个提示词（Prompt）都是一个循环，在这个循环中你不需要额外干预。Claude Code 完成这个循环后会给你输出，它的具体步骤是：收集上下文、采取行动、检查工作、重复，直到它认为你的提示词任务已经完成，或者觉得需要你介入时才会停止。

基于目标的循环（Goal-oriented Loop）

也就是 GOAL 模式（如 Codex、Claude Code 等工具都支持该模式）。有时候单回合不足以完成复杂任务，系统就会进行多次迭代，直到达成那个更大的目标。

基于时间的循环（Time-based Loop）

也就是 Claude Code 中的 loop 命令。你可以设置在指定的时间间隔自动触发某一个提示词，去运行特定任务，比如定期进行 PR 合并等。

主动循环（Active Loop）

你只需要设置一个事件，一旦该事件发生就会自动触发循环，完全不需要人工干预。例如，一旦 GitHub 上有了新的 Issue 或 PR，AI 就会自动进行审核和记录。

此外，官方还针对 Loop 给出了一些优化建议：

循环的质量取决于系统：你需要保证代码库本身的质量，比如完善的文档、严格的代码审查以及保持代码库的简洁等。

管理你的 Token 消耗：像 GOAL 这种基于目标的模式，对 Token 的消耗是非常巨大的。因此，你需要给循环设置明确的界限，比如什么时候该用大模型、什么时候该用小模型，以及明确的启动和结束条件。否则，一旦系统自己无限制地跑下去，不仅容易跑偏，还会消耗大量的 Token。

这些循环模式，本质上都是由我们现在 Agent 常见的各种能力组合而成的，比如前面提到的 GOAL 模式、Loop 模式，以及常见的 Skills 和 Hooks 等。

## 结构化（1）

### 2026-07-09 00:48:35

##### 主旨概括

文章介绍了 Claude 官方关于 **Loop Engineer（循环工程）** 的入门观点：所谓 Loop，本质上并不是全新能力，而是把现有 AI Agent 的工作流程重新概念化。核心是让 AI 按一定规则反复执行任务，直到目标完成、时间触发或事件发生。

---

##### 1. Loop Engineer 的背景：新概念包装旧流程

作者认为，现在讨论的 **Loop Engineer**，底层逻辑在概念提出前就已经存在。

- 许多开发者早就在使用类似流程；
- 只是现在被统一命名为“Loop”；
- 本质是让 AI Agent 在一定条件下自动反复执行：  
  **收集上下文 → 执行动作 → 检查结果 → 继续迭代**。

---

##### 2. 官方将 Loop 分为四种类型

###### 2.1 回合制循环：Single-turn Loop

这是 Claude Code 最基础的工作方式。

- 用户每发出一个 Prompt，就相当于启动一次循环；
- Claude Code 会自动完成任务，不需要用户中途干预；
- 它会反复执行：
  - 收集上下文；
  - 采取行动；
  - 检查结果；
  - 必要时继续重复。

**停止条件：**

- Claude 认为任务已经完成；
- 或者它判断需要用户介入。

---

###### 2.2 基于目标的循环：Goal-oriented Loop

这类循环适合处理更复杂的任务，也就是常说的 **GOAL 模式**。

- 代表工具包括：Codex、Claude Code 等；
- 当单次对话无法完成复杂目标时，系统会多轮迭代；
- AI 会围绕一个更大的目标持续推进，直到完成。

**例子：**

如果目标是“重构一个模块并通过测试”，AI 可能会多次修改代码、运行测试、修复错误，直到整体目标达成。

---

###### 2.3 基于时间的循环：Time-based Loop

这对应 Claude Code 中的 **loop 命令**。

- 用户可以设定固定时间间隔；
- 到时间后自动触发某个 Prompt；
- 适合周期性任务。

**例子：**

定期执行 PR 合并、自动检查代码状态、周期性生成报告等。

---

###### 2.4 主动循环：Active Loop

主动循环由事件触发，不需要人工干预。

- 用户只需要设置好触发事件；
- 一旦事件发生，AI 自动启动循环处理任务。

**例子：**

当 GitHub 上出现新的 Issue 或 PR 时，AI 自动进行审核、记录或初步处理。

---

##### 3. 官方给出的 Loop 优化建议

###### 3.1 循环质量取决于系统基础

Loop 能否高质量运行，不只取决于 AI，还取决于代码库和工程环境。

需要保证：

- 文档完善；
- 代码审查严格；
- 代码库保持简洁；
- 项目结构清晰。

如果基础环境混乱，AI 循环越多，可能越容易跑偏。

---

###### 3.2 管理 Token 消耗

文章特别提醒：基于目标的 GOAL 模式会消耗大量 Token。

因此需要设置边界：

- 明确什么时候使用大模型；
- 明确什么时候使用小模型；
- 设置清楚启动条件；
- 设置清楚结束条件；
- 避免 AI 无限制运行。

否则可能出现两个问题：

1. **任务跑偏**：AI 在长循环中逐渐偏离原目标；  
2. **Token 浪费**：持续迭代导致成本快速上升。

---

##### 4. 总结：Loop 是 Agent 能力的组合

作者最后指出，这些 Loop 模式本质上都是现有 Agent 能力的组合。

包括：

- GOAL 模式；
- Loop 模式；
- Skills；
- Hooks；
- 自动触发机制等。

也就是说，Loop Engineer 并不是凭空出现的新技术，而是把 AI Agent 已有的自动化、迭代和触发能力，组织成更清晰的工程方法。

## 通俗精炼（1）

### 2026-09-18 11:00:25

#### Loop Engineer：从写提示词转向设计可控的 Agent 循环

文章转述 Claude 官方对“Loop Engineer”的介绍。作者认为，这并非全新的底层能力，而是把 Agent 已有的目标执行、定时任务、事件触发、Skills 和 Hooks 等工作流，统一包装成“循环设计”概念：让 AI 持续获取信息、行动和检查，直至完成任务或需要人工介入。

##### 四类循环覆盖不同自动化场景

- **单回合循环**：每个提示词触发一次完整流程，Claude Code 会收集上下文、执行、检查并重复，直到认为任务完成。
- **目标循环**：复杂任务拆成多轮迭代，持续运行到更大的目标达成，类似 Codex、Claude Code 的 GOAL 模式。
- **时间循环**：按设定间隔重复执行任务，如定期处理 PR 合并。
- **主动循环**：由外部事件触发，无需人工启动；例如 GitHub 出现新 Issue 或 PR 后，AI 自动审核并记录。

##### 循环效果取决于系统基础，而非模型单打独斗

高质量循环需要清晰文档、严格代码审查和简洁代码库。基础环境混乱时，Agent 即使能反复执行，也可能持续放大错误。

##### 自动运行必须设置成本与权限边界

目标循环可能大量消耗 Token，也容易在长期运行中偏离目标。官方建议明确启动、停止和人工介入条件，并按任务难度选择大模型或小模型。其核心意义是：AI 编程的重点正从“写好一次提示词”，转向设计可持续、可观测且成本可控的执行机制。
