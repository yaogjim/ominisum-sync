## 正文

**烟花老师**

Pi Agent = 可定制 coding harness / agent workbench

Pi Agent 可以理解成一个极简、可自我改造的 terminal coding agent harness。

它不是 LangGraph 那种通用编排引擎，也不是 OpenAI Agents SDK 那种产品级 agent SDK；

它更像是“给开发者自己改、自己装 skill、自己做上下文工程的 Codex/Claude Code 替代品”。

Pi 现在的主仓库在 earendil-works/pi，官方描述是 AI agent toolkit，包含 coding agent CLI、agent runtime、统一多模型 API、TUI、Slack bot、vLLM pods 等模块；  
核心包包括 pi-coding-agent、pi-agent-core、pi-ai。

Pi 的产品哲学很鲜明：  
core 保持小，复杂能力交给 extension / skill / prompt / package。

官网明确说 Pi 是 minimal terminal coding harness，可以通过 extensions、skills、prompt templates、themes 定制；

它默认不内置 sub-agent、plan mode 这类重功能，而是鼓励你自己构建或安装。

它真正有意思的地方有几块：

一是 上下文工程优先。  
Pi 支持 AGENTS.md、SYSTEM.md、skills、prompt templates、动态 context injection、可自定义 compaction。对你这种做 agent harness / RAG / sandbox 的人来说，这比“多 agent 聊天”更关键，因为很多 agent 失败不是模型不行，而是上下文入口混乱、长期任务压缩失真、项目规则没有被稳定加载。

二是 session tree 设计。  
Pi 的历史记录是树状结构，可以回到任意历史节点继续分支，也能导出 HTML 或分享 session。这一点很适合 coding agent，因为代码任务经常要回滚到某个设计分叉点，而普通线性聊天历史不适合做 trial-and-error。

三是 多运行模式。  
Pi 有 interactive、print/JSON、RPC、SDK 四种模式。也就是说它既可以作为终端 coding agent 使用，也可以被脚本、非 Node 程序、上层产品集成调用。

四是 多模型/多 provider 亲和。  
它支持 OpenAI、Anthropic、Google、Azure、Bedrock、Mistral、Groq、Cerebras、xAI、Hugging Face、OpenRouter、Ollama 等，并支持会话中切换模型。

它适合的场景：  
本地代码库改造、长期 coding session、项目级 AGENTS.md、自己做 skill、自己控制 compaction、把 agent session 当成工程资产管理。

它不太适合直接做严肃企业业务流，比如审批、支付、CRM 自动化、工单系统，因为这些需要强状态、审计、权限、可靠恢复、可观测平台和业务持久化。

## 结构化（1）

### 2026-06-04 08:43:07

##### 主旨概括

Pi Agent 可以理解为一个**极简、可自定义的终端 coding agent 框架 / 工作台**，更适合开发者自己改造、安装 skills、做上下文工程，而不是开箱即用的企业级 Agent SDK。它的核心价值在于：**小核心 + 强可扩展 + 面向代码任务的上下文与会话管理**。

---

##### 1. Pi Agent 的定位：不是通用编排引擎，而是可改造的 coding harness

Pi Agent 不像 **LangGraph** 那样偏通用 Agent 编排，也不像 **OpenAI Agents SDK** 那样偏产品级 SDK。

它更像是：

> 给开发者自己定制的 Codex / Claude Code 替代品。

目前 Pi 的主仓库是 **earendil-works/pi**，官方称其为 **AI agent toolkit**，包含多个模块：

- coding agent CLI
- agent runtime
- 统一多模型 API
- TUI
- Slack bot
- vLLM pods

核心包包括：

- `pi-coding-agent`
- `pi-agent-core`
- `pi-ai`

---

##### 2. 产品哲学：核心保持极简，复杂能力交给扩展

Pi 的设计理念是：

> core 保持小，复杂能力交给 extension / skill / prompt / package。

官网明确把 Pi 定义为 **minimal terminal coding harness**，可以通过以下方式定制：

- extensions
- skills
- prompt templates
- themes

它默认不内置很多重功能，比如：

- sub-agent
- plan mode

而是鼓励开发者根据自己的需求自己构建或安装。

---

##### 3. 关键能力一：重视上下文工程

Pi 最有价值的一点是它把**上下文工程**放在很重要的位置。

它支持：

- `AGENTS.md`
- `SYSTEM.md`
- skills
- prompt templates
- 动态 context injection
- 自定义 compaction

作者认为，对于做 **agent harness / RAG / sandbox** 的人来说，这比“多 Agent 聊天”更关键。

原因是很多 Agent 失败并不是模型不够强，而是：

- 上下文入口混乱
- 长期任务压缩失真
- 项目规则没有稳定加载

例如，一个代码 Agent 如果没有稳定读取项目里的 `AGENTS.md`，就可能反复违背项目规范；如果长期会话压缩不好，也容易丢失关键设计决策。

---

##### 4. 关键能力二：Session Tree 会话树

Pi 的历史记录不是普通线性聊天，而是**树状结构**。

它可以：

- 回到任意历史节点
- 从某个节点继续分支
- 导出 HTML
- 分享 session

这对 coding agent 很有用，因为代码开发经常需要尝试不同方案。

例如：

- 先尝试方案 A
- 发现不合适后回到之前节点
- 再分支尝试方案 B

普通线性聊天不适合这种 trial-and-error，而 session tree 更适合管理代码任务中的分叉与回滚。

---

##### 5. 关键能力三：支持多种运行模式

Pi 支持四种运行方式：

- interactive
- print / JSON
- RPC
- SDK

这意味着它既可以作为终端里的 coding agent 使用，也可以被其他系统调用。

适用方式包括：

- 终端交互使用
- 脚本调用
- 非 Node 程序集成
- 上层产品封装调用

---

##### 6. 关键能力四：多模型、多 Provider 友好

Pi 支持很多模型服务商，并且可以在会话中切换模型。

支持的 provider 包括：

- OpenAI
- Anthropic
- Google
- Azure
- Bedrock
- Mistral
- Groq
- Cerebras
- xAI
- Hugging Face
- OpenRouter
- Ollama

这让开发者可以根据任务需要灵活选择模型，而不被单一供应商绑定。

---

##### 7. 适合的使用场景

Pi 更适合偏开发者、偏代码工程的场景，例如：

- 本地代码库改造
- 长期 coding session
- 项目级 `AGENTS.md`
- 自己开发 skill

Pi 更偏 coding agent workbench，而不是完整企业业务自动化平台。

#### 二、深入浅出解读

##### 1. Pi Agent 更像 “可改装的 AI 编程工作台”

如果把 AI 编程工具分成几类：

| 类型 | 代表 | 特点 |
|---|---|---|
| 成品工具 | Claude Code、Codex | 拿来就用，但可控性有限 |
| 通用编排框架 | LangGraph | 适合复杂流程编排 |
| 企业级 SDK | OpenAI Agents SDK | 更偏产品集成和工程化 |
| 可定制 Coding Harness | Pi Agent | 小核心、高自由度、适合开发者折腾 |

Pi Agent 的定位不是 “我帮你把所有功能都做好”，而是：

> 我给你一个干净、灵活的底座，你自己决定怎么组织上下文、怎么加技能、怎么调用模型、怎么管理任务历史。

所以它特别适合喜欢自己搭 Agent 工具链的开发者。

---

##### 2. 它重视的不是 “多 Agent 聊天”，而是 “上下文工程”

很多 Agent 做不好任务，不一定是模型太差，而是因为：

- 项目规则没稳定加载
- 历史上下文太乱
- 长任务压缩后信息丢失
- 不同文件、规范、指令混在一起
- Agent 不知道当前项目真正的约束

Pi Agent 重点解决的就是这些问题。

例如：

- `AGENTS.md`：告诉 Agent 这个项目的规则和工作方式。
- `SYSTEM.md`：定义更高层的系统提示。
- skills：封装可复用能力。
- prompt templates：复用提示词模板。
- context injection：动态注入相关上下文。
- compaction：自定义长对话压缩方式。

这对长期编程任务很重要。

因为写代码不是一次问答，而是一个持续过程：理解项目、修改代码、调试、回滚、再修改。

---

##### 3. 树状 Session 很适合写代码

普通聊天工具的历史是线性的：

```text
A -> B -> C -> D
```

但真实编码过程经常是分叉的：

```text
方案 A
  ├── 方案 A1
  └── 方案 A2

方案 B
  ├── 方案 B1
  └── 方案 B2
```

比如你让 Agent 改一个功能：

- 第一次尝试用了方案 A
- 后来发现不合适
- 想回到之前节点，换方案 B
- 又想比较两个方案的效果

Pi Agent 的树状历史就适合这种场景。

它让 Agent Session 更像一个 “工程过程记录”，而不是普通聊天记录。

---

##### 4. Pi Agent 强在开发者可控，不强在企业业务闭环

Pi Agent 适合技术人员自己用、自己改、自己扩展。

但如果要做企业里的正式业务系统，比如：

- 自动审批
- 财务支付
- CRM 操作
- 工单派发
- 权限管理
- 审计追踪
- 失败恢复

Pi Agent 就不是最佳选择。

因为这些场景需要的不只是 Agent 能说会写，而是完整的平台能力：

- 状态管理
- 权限体系
- 审计日志
- 异常恢复
- 任务持久化
- 可观测性
- 人工介入机制

Pi Agent 更像 “开发者工作台”，不是 “企业业务操作系统”。

---

#### 三、我的意见

##### 1. Pi Agent 的价值在于 “可控性”

现在很多 AI Coding 工具越来越像黑盒产品：好用，但你很难控制它怎么想、怎么压缩上下文、怎么加载规则。

Pi Agent 的优势是把这些控制权还给开发者。

对于懂工程的人来说，这很重要。

因为 Agent 真正进入复杂项目后，决定效果的往往不是一句 prompt，而是：

- 上下文怎么组织
- 规则怎么稳定加载
- 工具怎么调用
- 历史怎么压缩
- 错误路径怎么回滚
- Session 怎么复用

Pi Agent 正好切中了这些痛点。

---

##### 2. 它适合 “Agent 工程师”，不适合普通用户

如果你只是想让 AI 帮你快速写点代码，Claude Code、Cursor、Codex 这类工具可能更直接。

但如果你想研究：

- Coding Agent 如何工作
- 如何做上下文工程
- 如何封装技能
- 如何控制多模型
- 如何管理长期 Agent Session
- 如何搭建自己的 Agent Harness

那 Pi Agent 会很有价值。

它更像一个 “半成品工具箱”，而不是 “消费级成品”。

---

##### 3. 不要把它误用成企业 Agent 平台

Pi Agent 可以作为开发者内部工具，但不建议直接拿来做企业核心业务流程。

原因很简单：

> 写代码时，Agent 错了可以回滚；  
> 企业业务里，Agent 错了可能就是事故。

所以它最适合用在 “开发、实验、代码改造、Agent 原型验证” 这些场景。

---

#### 结论

**Pi Agent 的核心定位：**

> 一个轻量、可定制、适合开发者深度改造的 AI Coding Agent 工作台。

它不追求大而全，而是把重点放在：

- 上下文工程
- Session 管理
- 多模型调用
- 自定义 Skill
- 开发者可控性

如果你是普通 AI 编程用户，它可能有点折腾；  
如果你是 Agent 开发者、AI Engineer 或正在做 Coding Agent/RAG/Sandbox，它值得关注。
