Update renamed skill metadata and add WeCom vault

#### yichen-skills

English \| 中文

一个面向内容创作者的技能仓库，帮助你用 Claude Code / Codex 打通”沉淀知识 + X 文章草稿上传 + 微信数字资产 + 本地解析”的完整流程。

#### 这个仓库能做什么

1. 把 Claude Code 对话沉淀为结构化 Obsidian 笔记（ `yichen-summary` ）
2. 把 Obsidian/Markdown 长文上传为 X Articles 草稿（ `yichen-x-article-draft-uploader` ）
3. Mac 微信双开，第二个微信带蓝色图标（ `yichen-mac-wechat-dual-open` ）
4. 从微信聊天、朋友圈、收藏夹沉淀 AI 数字资产（ `yichen-wechat-local-vault` ）
5. 抓取抖音对标视频（ `yichen-douyin-fetcher` ）
6. 抓取小红书对标笔记（ `yichen-xiaohongshu-fetch` ）
7. 用火山 ASR 做转写、字幕和口播粗剪（ `yichen-volc-asr` ）
8. 诊断对标视频口播稿（ `yichen-video-content` ）
9. 通过 ChatGPT 官网完成可验证调研（ `yichen-chatgpt-web-research` ）
10. 把粗剪成片交给剪映/CapCut 做最后精修（ `yichen-jianying-editor` ）
11. 安装和维护 Markdown/Obsidian-first 的 Codex 记忆系统（ `yichen-agent-memory` ）
12. 批量导出公众号历史文章、原创列表、正文，以及可选阅读量/评论数据（ `yichen-wechat-mp-batch-exporter` ）
13. 只读解析并导出本机企业微信 5.x 数据库快照，不操控客户端（ `yichen-wecom-local-vault` ）

#### 包含的技能

##### 1\) yichen-summary

- 用途：提炼当前对话精华并保存到 Obsidian
- 常见触发词： `/yichen-summary` 、保存对话、导出精华
- 关键能力：
  - 自动过滤低价值过渡内容
  - 输出结构化笔记（背景、核心内容、解决方案、关键要点、相关）
  - 适合长期知识沉淀

##### 2\) yichen-x-article-draft-uploader

把 Obsidian/Markdown 长文上传到 X Articles 草稿：

- 第一张图片自动作为 X Article 封面
- Markdown 转成 X 编辑器可识别的 rich text
- 正文图片按原文位置插入
- 使用独立 Playwright 浏览器，不抢占用户当前 Chrome
- 通过临时导出的 cookies 复用 Chrome 登录态
- 只保存草稿，不点击最终 `发布`

完整说明见 yichen-x-article-draft-uploader/README.md 。

##### 3\) yichen-mac-wechat-dual-open

Mac 微信双开——无需第三方工具，一条命令搞定：

- 复制微信、改 Bundle Identifier、本地重签名
- 第二个微信图标自动改为蓝色，视觉上一眼区分
- 同时处理外层和内嵌图标文件、Finder 自定义图标和缓存刷新
- 命令行工作流： `create` → `recolor-icon` → `launch`
- 常见触发词："微信双开"、"WeChat dual open"
- 依赖：macOS 12+、微信（ `/Applications/WeChat.app` ）、Python 3.10+、Pillow
- 限制：微信更新后需要重新运行（用 `repair` ）；推送通知可能不稳定
- 方法来源： [@koffuxu](https://x.com/koffuxu/status/2043110831584690427) 的公开教程

##### 4\) yichen-wechat-local-vault

微信数字资产沉淀助手（macOS 专属）：

- 解密微信 Mac 4.x 本地 SQLCipher 数据库（AES-256-CBC）
- 提取聊天记录、朋友圈（ `sns.db` ）和收藏夹（ `favorite.db` ）
- 生成群聊解析、朋友圈解析、收藏夹整理、客户跟进和大佬对话复盘草案
- 首次引导展示三大类九种玩法：聊天记录、朋友圈、收藏夹
- 可配置监控指定群聊、联系人、朋友圈对象和收藏夹整理偏好
- 首次使用通过 frida 引导密钥提取
- 常见触发词：”微信解析”、”微信全量”、”微信增量”、”导出聊天”、”朋友圈解析”、”收藏夹整理”、”客户跟进”、”yichen-wechat-local-vault”
- 依赖：macOS、微信 Mac 4.x、Python 3.9+、 `pycryptodome` 、 `zstandard`
- 详细文档见 yichen-wechat-local-vault/README.md

##### 5\) yichen-douyin-fetcher

抓取抖音视频元数据并下载 MP4：

- 支持 `/video/<id>` 链接和部分弹窗类链接
- 下载视频旁边生成精简 `.metadata.json`
- 支持 `--metadata-only` ，只验证链接不下载视频

##### 6\) yichen-xiaohongshu-fetch

抓取小红书视频/图文笔记到本地：

- 解析 `window.__INITIAL_STATE__`
- 尽量下载视频、字幕、图片和元数据
- 不把 Cookie、飞书 AppToken/TableID、目标表 ID 写进仓库

##### 7\) yichen-volc-asr

本地音视频转写和口播粗剪：

- 火山 ASR 和 TOS 配置全部通过环境变量读取
- 输出转写稿、SRT 字幕、ASR 缓存和可选粗剪 MP4
- 清理临时文件前必须得到用户明确允许

##### 8\) yichen-video-content

对标视频内容拆解：

- 对口播稿逐句标注作用
- 输出可模仿结构和改进建议

##### 9\) yichen-chatgpt-web-research

通过用户已登录的 ChatGPT 官网账号执行调研：

- 使用真实 ChatGPT 网页，不走 OpenAI API，也不切到另一个账号
- 优先使用 Chrome 扩展控制，必要时才用可视化 Computer Use 兜底
- 等待完整答案和唯一校验标记后再提取
- 把原始输出和可读报告保存到当前工作区的 `reports/` 目录
- 公开版已去掉个人路径、Chrome 配置名、cookie、token 和浏览器存储信息

隐私边界和工作流见 yichen-chatgpt-web-research/README.md 。

##### 10\) yichen-jianying-editor

剪映/CapCut 桌面端精修助手：

- 检查素材、导入粗剪、放入时间线
- 处理字幕、画面精修、导出和项目记录
- 自动粗剪逻辑交给 `yichen-volc-asr`

##### 11\) yichen-agent-memory

安装和维护公开版 Agent Memory Vault 系统：

- 从公开模板创建本地 Markdown/Obsidian-first 记忆库
- Markdown 是事实源，SQLite/FTS 是快速索引
- 可选接入 Zvec 语义检索，用来找“意思相近但措辞不同”的记忆
- 引导写入前对账、任务结束 closeout、定期 audit 和公开模板脱敏更新
- 常见触发词：“安装 Codex 记忆系统”、“搭建记忆库”、“运行 memory closeout”、“audit 我的 Codex 记忆”
- 模板仓库： [mcncarl/agent-memory-vault](https://github.com/mcncarl/agent-memory-vault)

##### 12\) yichen-wechat-mp-batch-exporter

批量导出微信公众号文章：

- 把已知 `mp.weixin.qq.com` 文章链接下载成 Markdown/JSON/text/HTML
- 通过 `wechat-article-exporter` 做公众号搜索和历史列表同步
- 明确区分 `publish_groups` 、 `expanded_url_items` 和 `original_articles`
- 在有新鲜、用户自有凭证时，可规划导出阅读量、点赞、转发、评论和评论回复
- 扫码登录、凭证捕获、证书信任、代理修改和任何微信桌面端动作都必须先得到用户确认
- 不操控微信 UI，也不把真实凭据写入仓库

安装和隐私边界见 yichen-wechat-mp-batch-exporter/README.md 。

##### 13\) yichen-wecom-local-vault

只读解析、查询和导出 macOS 企业微信 5.x 桌面端数据库：

- 生成私密、带时间戳的明文快照，绝不写回企业微信容器
- 支持联系人、会话、聊天记录、搜索与 Markdown/JSON 导出
- raw key、快照和聊天导出都不进入 Git
- 不操控原始企业微信，也不发送消息

#### 环境要求

- Claude Code / Codex CLI（支持加载本地 skills）
- Python Playwright（ `yichen-x-article-draft-uploader` 必需）
- Python 3.9+
- 依赖：
  - X 文章草稿： `pip install playwright pycryptodome && python3 -m playwright install chromium`
  - 微信本地解析： `pip install pycryptodome zstandard`
  - 微信双开： `pip install Pillow`
  - 抖音抓取： `pip install playwright requests && python3 -m playwright install chromium`
  - 小红书抓取： `pip install requests`
  - 火山 ASR 粗剪： `pip install requests` ，并安装本机 `ffmpeg` / `ffprobe`
  - ChatGPT 官网调研：Chrome 已登录 ChatGPT，且当前 Agent 环境支持 Chrome/Computer Use 能力
  - 公众号批量导出：已知 URL 正文下载只需 Python 3 标准库；历史列表、阅读量和评论需要额外配置 `wechat-article-exporter` / `wxdown-service`
  - 企业微信本地解析： `pycryptodome` ；只有明确授权抓取本机 raw key 时才需要 `frida`

#### 3 分钟快速上手

##### A）启用 yichen-summary

1. 确保 `yichen-summary/SKILL.md` 在已加载的 skills 路径里
2. 新开会话后输入 `/yichen-summary`
3. 确认输出写入 Obsidian 目录（示例路径通常是 `<OBSIDIAN_VAULT>/...`）

##### B）启用 yichen-x-article-draft-uploader

1. 安装 Python Playwright： `pip3 install playwright pycryptodome && python3 -m playwright install chromium`
2. 确认 Chrome 已经登录 X
3. 直接说“把这篇 Markdown 上传到 X Articles 草稿”，或手动运行脚本
4. Skill 会新建干净草稿，第一张图作为封面，正文图片按原文位置插入
5. 详细命令见 yichen-x-article-draft-uploader/README.md

##### C）启用 yichen-mac-wechat-dual-open

1. 安装 Python 依赖： `pip3 install Pillow`
2. 在 Claude Code 中说"帮我微信双开"或 "WeChat dual open"
3. 脚本会自动创建第二个微信（ `~/Applications/WeChat-2.app` ）并改蓝色图标
4. 详细命令见 `yichen-mac-wechat-dual-open/SKILL.md`

##### D）启用 yichen-wechat-local-vault

1. 安装 Python 依赖： `pip3 install pycryptodome zstandard`
2. 在 Claude Code 或 Codex 中说"微信解析"、"导出聊天"或"收藏夹整理"
3. 首次运行会引导你完成密钥提取，并从九种玩法里选择当前要启用的工作流
4. 如果不确定，默认从"聊天记录解析 + 朋友圈解析 + 收藏夹整理"开始
5. 后续使用自动生成对应的解析报告或草案
6. 详细说明见 yichen-wechat-local-vault/README.md

##### E）启用自媒体视频工作流

1. 安装 Playwright、requests 和 ffmpeg
2. 用 `yichen-douyin-fetcher` 或 `yichen-xiaohongshu-fetch` 保存对标素材
3. 用 `yichen-volc-asr` 做转写、字幕或口播粗剪
4. 用 `yichen-video-content` 诊断对标稿
5. 用 `yichen-jianying-editor` 做剪映/CapCut 导入、字幕、精修和导出

##### F）启用 yichen-chatgpt-web-research

1. 确认 Chrome 已登录目标 ChatGPT 账号
2. 如果任务要求 Pro 路线，保持可见页面能确认账号或模型状态
3. 直接提出官网调研任务，例如：“用 ChatGPT 官网调研 Anthropic，并保存 Markdown 报告”
4. Skill 会等待完整答案、校验标记，并保存原始版和可读版报告

##### G）启用 yichen-agent-memory

1. 确保 `yichen-agent-memory/SKILL.md` 在已加载的 skills 路径里
2. 对 Codex 说“安装 Codex 记忆系统”或“搭建本地 Codex 记忆库”
3. Skill 会使用 [mcncarl/agent-memory-vault](https://github.com/mcncarl/agent-memory-vault) 创建一个本地私有 vault
4. 安装后用 `codex_memory_search.py` 、 `codex_memory_closeout.py` 、 `codex_memory_audit.py` 分别做搜索、任务结束整理和定期体检

##### H）启用 yichen-wechat-mp-batch-exporter

1. 确保 `yichen-wechat-mp-batch-exporter/SKILL.md` 在已加载的 skills 路径里
2. 如果只是下载已知文章链接，直接要求下载 Markdown 即可
3. 如果要抓公众号历史列表，配置 `WECHAT_ARTICLE_EXPORTER_DIR` ，或使用 `wechat-article-exporter` 支持的公开 exporter 路线
4. 如果要抓阅读量和评论，配置 `WXDOWN_SERVICE_DIR` ，并在启动任何本地凭证辅助服务前确认凭证捕获流程
5. 涉及指标、评论、代理、证书或微信桌面端动作前，先看 yichen-wechat-mp-batch-exporter/README.md

##### I）启用 yichen-wecom-local-vault

1. 确保 `yichen-wecom-local-vault/SKILL.md` 在已加载的 skills 路径里
2. 安装 `pycryptodome` ；只有在明确授权本机捕获 raw key 时才安装 `frida`
3. 直接要求检查或导出本机企业微信数据；流程不会操控原始客户端

本仓库不包含真实凭据，也不再提供需要手动填写的 cookie 模板。

#### 安全说明

- 不包含真实 token/cookie
- 历史缓存类目录默认不追踪
- 个人绝对路径已替换为通用写法
- 第三方 AppID、AppToken、TableID、bucket 名和 ASR token 必须通过环境变量或私有配置提供
- 公众号 exporter auth-key、凭证文件、扫码登录秘密、捕获 cookies 和下载的文章归档必须只保存在本地

如果你曾在公开仓库暴露过 Cookie，请立即轮换。

#### 文章总结

`yichen-skills` 是一个面向内容创作者的本地技能仓库，帮助 Claude Code / Codex 串联知识沉淀、内容采集、转写剪辑、平台发布、微信数据整理和 Agent 记忆管理。仓库强调**本地处理、凭据隔离、只读操作与非商业使用**。

##### 一、仓库提供的核心能力

仓库共包含 **13 个技能**，覆盖从素材获取、内容加工到发布和归档的完整流程：

1. **`yichen-summary`：对话沉淀**
   - 提炼当前对话的有效内容，过滤低价值过渡信息。
   - 生成包含背景、核心内容、解决方案和关键要点的结构化 Obsidian 笔记。
   - 可通过 `/yichen-summary`、“保存对话”等指令触发。

2. **`yichen-x-article-draft-uploader`：上传 X Articles 草稿**
   - 将 Obsidian/Markdown 长文转换为 X 编辑器可识别的富文本。
   - 自动把第一张图片设为封面，并按原文位置插入正文图片。
   - 使用独立 Playwright 浏览器，通过临时导出的 Chrome Cookies 复用登录状态。
   - **只保存草稿，不执行最终发布。**

3. **`yichen-mac-wechat-dual-open`：Mac 微信双开**
   - 通过复制微信、修改 Bundle Identifier 和本地重签名创建第二个微信。
   - 第二个微信自动改为蓝色图标，默认位于 `~/Applications/WeChat-2.app`。
   - 支持 `create → recolor-icon → launch` 工作流。
   - 要求 macOS 12+、微信、Python 3.10+ 和 Pillow；微信更新后可能需要执行 `repair`。

4. **`yichen-wechat-local-vault`：微信本地数字资产整理**
   - 面向 macOS 微信 4.x，解密本地 SQLCipher 数据库，涉及 AES-256-CBC。
   - 可提取聊天记录、朋友圈 `sns.db` 和收藏夹 `favorite.db`。
   - 能生成群聊解析、朋友圈分析、收藏夹整理、客户跟进及重要对话复盘草案。
   - 首次使用通过 Frida 引导提取密钥，并提供聊天、朋友圈、收藏夹三大类共九种玩法。

5. **`yichen-douyin-fetcher`：抖音素材抓取**
   - 解析抖音 `/video/&lt;id>` 及部分弹窗链接。
   - 下载 MP4，并生成精简的 `.metadata.json`。
   - 支持 `--metadata-only`，仅检查链接和元数据，不下载视频。

6. **`yichen-xiaohongshu-fetch`：小红书素材抓取**
   - 解析页面中的 `window.__INITIAL_STATE__`。
   - 尽量保存视频、字幕、图片和元数据。
   - Cookie、飞书 AppToken/TableID 等敏感信息不会写入仓库。

7. **`yichen-volc-asr`：转写、字幕与口播粗剪**
   - 使用火山 ASR 完成本地音视频转写。
   - 输出转写稿、SRT 字幕、ASR 缓存及可选的粗剪 MP4。
   - 配置通过环境变量读取；删除临时文件前必须获得用户明确同意。

8. **`yichen-video-content`：对标视频分析**
   - 逐句标注口播稿中每句话的作用。
   - 提炼可模仿的内容结构，并给出改进建议。

9. **`yichen-chatgpt-web-research`：ChatGPT 官网调研**
   - 使用用户已登录的 ChatGPT 网页账号，不调用 OpenAI API，也不切换账号。
   - 优先通过 Chrome 扩展操作，必要时使用可视化 Computer Use。
   - 等待完整回答及唯一校验标记后，再将原始输出和可读报告保存到 `reports/`。

10. **`yichen-jianying-editor`：剪映/CapCut 精修**
    - 检查素材、导入粗剪、放入时间线，并处理字幕、画面精修、导出和项目记录。
    - 自动粗剪由 `yichen-volc-asr` 负责，本技能侧重最后的人工化精修。

11. **`yichen-agent-memory`：Agent 记忆系统**
    - 基于公开模板 `mcncarl/agent-memory-vault` 创建本地私有记忆库。
    - 以 Markdown 为事实源，以 SQLite/FTS 为快速索引。
    - 可选接入 Zvec，检索“意思相近但表达不同”的记忆。
    - 支持任务结束整理 `closeout`、定期检查 `audit` 和写入前对账。

12. **`yichen-wechat-mp-batch-exporter`：公众号文章批量导出**
    - 将已知 `mp.weixin.qq.com` 链接保存为 Markdown、JSON、纯文本或 HTML。
    - 可通过 `wechat-article-exporter` 同步公众号搜索结果和历史文章列表。
    - 区分发布批次、展开后的文章链接和原创文章。
    - 在用户提供新鲜且自有凭证时，可规划导出阅读量、点赞、转发、评论及回复。
    - 扫码登录、代理、证书、凭证捕获及微信客户端操作都必须事先确认。

13. **`yichen-wecom-local-vault`：企业微信本地数据导出**
    - 只读解析 macOS 企业微信 5.x 数据库。
    - 可查询联系人、会话和聊天记录，并导出 Markdown/JSON。
    - 生成私密、带时间戳的明文快照，但绝不写回企业微信容器。
    - 不操控客户端、不发送消息，raw key、快照和导出内容均不进入 Git。

### 2026-08-03 01:46:31

#### 一句话了解这个项目

这是一套面向内容创作者的个人技能仓库，目标是把知识沉淀、内容采集、视频处理、文章发布，以及微信和企业微信数据解析，串成一套本地化工作流。听完后，你可以了解它包含哪些工具、如何安装使用，以及最重要的隐私、安全和合规边界。

##### 一、这个仓库主要解决什么问题

首先，这个项目把 Claude Code 或 Codex 的能力，扩展成一组可以重复使用的本地技能。

通俗来说，它不是一个单独的软件，而是一套技能集合。你可以用它保存对话、整理微信资料、抓取抖音和小红书内容、处理视频、上传 X 文章草稿，还可以维护一个本地的 AI 记忆库。

目前仓库里包含十三类主要技能。

接下来，我们按照它们在内容生产和知识管理中的用途，逐一说明。

##### 二、知识沉淀和内容发布

第一类技能，叫做 `yichen-summary`，用于整理当前对话并保存到 Obsidian。

它会自动过滤低价值的寒暄和过渡内容，再把对话整理成结构化笔记。常见结构包括背景、核心内容、解决方案、关键要点和相关资料。使用时，可以输入类似“保存对话”“导出精华”，或者使用对应的技能命令。

这里的重点是，它更适合长期积累知识，而不是简单复制聊天记录。

第二类技能，叫做 `yichen-x-article-draft-uploader`，用于把 Obsidian 或 Markdown 长文上传成 X，也就是原 Twitter 的 Articles 草稿。

它会把 Markdown 转成 X 编辑器可以识别的富文本。文章中的第一张图片会自动作为封面，其他图片会按照原文位置插入。上传过程使用独立的 Playwright 浏览器，不会抢占用户正在使用的 Chrome。

它还可以临时导出 Chrome 的登录状态，也就是 cookies，来复用 X 的登录信息。不过，它只保存草稿，不会点击最终发布按钮。这一点可以降低误发布风险。

##### 三、微信数据和本地数字资产

第三类技能，是 `yichen-mac-wechat-dual-open`，用于在 Mac 上实现微信双开。

它不依赖第三方工具，而是复制微信应用，修改应用标识，重新进行本地签名，并把第二个微信的图标改成蓝色。这样，两个微信在视觉上比较容易区分。它还会处理内层和外层图标、Finder 自定义图标，以及图标缓存刷新。

这项技能要求使用 macOS 十二或更高版本，电脑中安装微信，并且需要 Python 三点十或更高版本以及 Pillow 图像处理库。微信更新后，通常需要重新运行修复流程。项目也提醒，双开后的推送通知可能不稳定。

第四类技能，是 `yichen-wechat-local-vault`，用于把 Mac 微信中的内容沉淀成个人数字资产。

它面向微信 Mac 四点几版本，可以读取并解密本地 SQLCipher 数据库。SQLCipher 可以理解为一种带加密功能的数据库方案。项目材料还提到，它使用 AES-256-CBC 这类加密方式处理数据库内容。

它可以提取聊天记录、朋友圈和收藏夹。其中，朋友圈数据来自 `sns.db`，收藏夹数据来自 `favorite.db`。在此基础上，它能够生成群聊解析、朋友圈解析、收藏夹整理、客户跟进，以及重要对话复盘等草案。

首次使用时，项目会通过 Frida 引导提取密钥。Frida 是一种用于观察和调试程序运行过程的工具。首次引导还会展示三大类、九种玩法，分别围绕聊天记录、朋友圈和收藏夹展开。之后，用户还可以配置需要持续关注的群聊、联系人、朋友圈对象和收藏夹整理偏好。

这项技能依赖 macOS、微信 Mac 四点几版本、Python 三点九或更高版本，以及 `pycryptodome` 和 `zstandard` 等组件。

需要特别强调的是，这项能力只应该用于读取和整理自己的微信数据，不能用来侵犯他人隐私。

##### 四、对标内容采集和视频处理

第五类技能，是 `yichen-douyin-fetcher`，用于抓取抖音对标视频。

它可以处理带有视频编号的链接，以及部分弹窗类型的链接。下载视频时，会同时生成精简版的元数据文件，也就是记录标题、链接或其他基础信息的 JSON 文件。

如果只想检查链接是否有效，而不想下载视频，可以使用只读取元数据的模式。

第六类技能，是 `yichen-xiaohongshu-fetch`，用于抓取小红书的视频和图文笔记。

它会解析网页中的初始状态数据，也就是页面加载时保存的结构化信息，并尽量下载视频、字幕、图片和元数据。项目明确要求，不要把 Cookie、飞书应用令牌、数据表编号等敏感信息写进仓库。

第七类技能，是 `yichen-volc-asr`，用于本地音视频转写和口播粗剪。

这里的 ASR，指的是自动语音识别，也就是把音频中的讲话内容转换成文字。这个技能使用火山 ASR 和 TOS 服务，相关配置通过环境变量读取，而不是直接写在代码里。

它可以输出转写稿、SRT 字幕、识别缓存，以及可选的粗剪视频。SRT 是一种常见的字幕文件格式。项目特别规定，在清理临时文件之前，必须先得到用户明确允许。

第八类技能，是 `yichen-video-content`，用于拆解对标视频的口播内容。

它会逐句标注每句话在整段口播中的作用，比如开头吸引注意、解释问题、提供案例，或者推动转化。然后，它会进一步总结可以模仿的结构，并提出改进建议。

它的重点不是简单转写，而是帮助创作者理解一段口播为什么有效，以及哪些结构可以迁移到自己的内容中。

第九类技能，是 `yichen-chatgpt-web-research`，用于通过已经登录的 ChatGPT 官网完成调研。

它不走 OpenAI API，也不会切换到另一个账号，而是使用真实的 ChatGPT 网页。通常优先使用 Chrome 扩展控制网页，必要时才使用可视化的 Computer Use，也就是让系统像人一样操作网页。

它会等待完整答案和唯一的校验标记出现后，再提取结果。完成后，会把原始输出和可读版报告保存到当前工作区的 `reports` 目录。公开版本已经去掉个人路径、Chrome 配置名称、Cookie、令牌和浏览器存储信息。

第十类技能，是 `yichen-jianying-editor`，也就是剪映或 CapCut 桌面端精修助手。

它负责检查素材、导入粗剪视频、放入时间线、处理字幕、进行画面精修、导出成片，并记录项目情况。视频的自动粗剪逻辑，则交给前面的火山 ASR 技能完成。

这样一来，一条比较完整的自媒体视频流程就形成了：先抓取抖音或小红书的对标素材，再做语音转写和粗剪，然后分析口播结构，最后交给剪映或 CapCut 完成精修和导出。

##### 五、AI 记忆系统和公众号文章导出

第十一类技能，是 `yichen-agent-memory`，用于安装和维护一套公开版的 Agent Memory Vault，也就是智能代理记忆库。

它会从公开模板创建一个本地的 Markdown 和 Obsidian 优先记忆库。这里的“Markdown 是事实源”，意思是最重要、最可信的内容保存在 Markdown 文件中。SQLite 和全文搜索功能，也就是 FTS，则主要用于快速查找。

如果需要，还可以接入 Zvec 语义检索。语义检索的作用是，找到“意思相近但用词不同”的记忆，而不是只能匹配完全相同的关键词。

这套系统还提供写入前对账、任务结束后的 closeout，也就是收尾整理，以及定期 audit，也就是检查和维护。它适合希望让 Codex 长期记住项目背景、工作习惯和历史决策的人。

第十二类技能，是 `yichen-wechat-mp-batch-exporter`，用于批量导出微信公众号文章。

对于已知的公众号文章链接，它可以下载并转换成 Markdown、JSON、纯文本或 HTML。通过额外的公众号文章导出工具，它还可以同步公众号搜索结果和历史文章列表。

项目特别区分了三类内容：发布分组、展开后的链接条目，以及原创文章列表。这个区分可以避免把搜索结果、历史列表和原创内容混在一起。

如果用户拥有新鲜且属于自己的凭证，还可以进一步规划导出阅读量、点赞、转发、评论和评论回复等数据。但扫码登录、捕获凭证、证书信任、代理修改，以及任何微信桌面端操作，都必须先得到用户确认。

这项技能不会操控微信界面，也不会把真实凭据写入仓库。

第十三类技能，是 `yichen-wecom-local-vault`，用于只读解析和导出 Mac 企业微信五点几版本的数据。

它可以读取联系人、会话和聊天记录，支持搜索，也支持导出为 Markdown 或 JSON。每次会生成带时间戳的私密明文快照，但绝不会把内容写回企业微信容器。

它不操控原始企业微信，也不会发送消息。原始密钥、快照和聊天导出文件都不会进入 Git。只有在用户明确授权抓取本机原始密钥时，才需要安装 Frida。

从目录组织上看，每项技能通常都有自己的文件夹，并包含一个 `SKILL.md` 文件。

有些技能还带有 README 文档、脚本、代理配置或参考资料。例如，X 文章上传技能包含 Cookie 导出、Markdown 解析和草稿上传脚本。微信本地解析技能则包含密钥提取、数据库解密、联系人查询、聊天导出和朋友圈搜索等脚本。

##### 七、安装前需要准备什么

接下来，说一下环境要求。

首先，需要能够加载本地技能的 Claude Code 或 Codex CLI。

不同技能需要的 Python 版本和依赖不完全相同。X 文章上传需要 Playwright，也就是浏览器自动化工具，同时需要安装 Chromium 浏览器。微信本地解析需要 `pycryptodome` 和 `zstandard`。微信双开需要 Pillow。抖音抓取需要 Playwright 和 requests。小红书抓取需要 requests。

火山 ASR 粗剪需要 requests，还需要在本机安装 `ffmpeg` 和 `ffprobe`，它们是常用的音视频处理工具。

ChatGPT 官网调研则需要 Chrome 已经登录目标 ChatGPT 账号，并且当前运行环境支持 Chrome 控制或 Computer Use。

公众号批量导出中，已知文章链接的正文下载只需要 Python 标准库。但如果要同步历史文章列表，或者导出阅读量、评论等数据，就需要额外配置相关的导出服务。

企业微信本地解析需要 `pycryptodome`。只有在明确授权抓取本机原始密钥时，才需要额外安装 Frida。

安装方式比较直接。把仓库内容复制到本地技能目录即可。

常见的 Claude 技能目录是用户主目录下的 `.claude/skills`。常见的其他 Agent 技能目录是 `.agents/skills`。如果你有自定义技能目录，也可以使用自定义路径。

项目建议保持各个技能的目录名称不变，比如 `yichen-summary`、`yichen-wechat-local-vault`、`yichen-volc-asr` 和 `yichen-agent-memory` 等。

启用微信双开时，安装 Pillow，然后对 Claude Code 说“帮我微信双开”。脚本会尝试创建第二个微信应用，并将其放在用户目录下的应用文件夹里，同时使用蓝色图标。

如果要使用 ChatGPT 官网调研，先确认 Chrome 登录的是目标账号，再直接提出调研任务。技能会等待完整答案和校验标记，并保存原始报告与可读报告。

对于公众号文章，已知链接可以直接要求导出 Markdown。如果要抓历史列表、阅读量或评论，需要先配置相应服务，并在涉及凭证和微信桌面端动作前确认授权。

对于企业微信，只需安装加密依赖，然后要求检查或导出本机企业微信数据。整个流程只读取本地数据，不操控客户端。

##### 九、隐私和安全边界

更重要的是，这个仓库对隐私安全有比较明确的要求。

#### 从“会聊天”到“能交付”：Agent Skill 真正补的是工作流缺口

这个仓库最值得关注的，不是它收集了 13 个工具，而是它呈现了一种更接近真实生产力的 Agent 形态：**模型负责理解意图和组织步骤，脚本负责确定性执行，本地文件系统负责保存状态。**

例如，一条内容链路可以从抖音、小红书采集素材，经 ASR 转写、口播结构分析和粗剪，再进入剪映精修；另一条链路则把 Claude/Codex 对话沉淀到 Obsidian，经 Markdown 处理后上传为 X Articles 草稿。每个单点能力都不新鲜，价值来自它们被封装成可用自然语言触发、能连续交付结果的流程。

##### Skill 层解决的是“最后一公里”，不是模型能力

很多 AI 产品的问题并非模型不会写、不会分析，而是无法进入用户已经存在的工作环境：读不到本地资料，接不上微信和剪映，不能复用网页登录态，也无法把产物放到正确目录。

这里的 Skill 实际承担了三类适配工作：把模糊指令转成明确步骤，把模型连接到浏览器、数据库和桌面软件，再把中间状态保存为 Markdown、JSON、字幕或草稿。由此看，Agent 的竞争变量会逐渐从“回答质量”扩展到**环境适配率、任务完成率和失败后的可恢复性**。真正形成黏性的，也可能不是某个模型，而是围绕个人数据和既有工具建立起来的适配层。

但 README 展示的是能力声明，而非效果验证。它没有给出成功率、耗时、平台封禁概率或版本失效率，因此还不能据此判断这些流程是否足够稳定。

##### 本地优先，正在把个人内容变成可计算资产

仓库把聊天记录、朋友圈、收藏夹、公众号文章和 Agent 对话统一导向本地 Markdown、JSON、SQLite/FTS 与可选向量检索。这背后有一个重要判断：**个人知识库的关键不只是“保存内容”，而是获得可迁移、可索引、可再次加工的数据所有权。**

当 Markdown 成为事实源，模型和检索引擎都只是可替换的消费层。相比把记忆锁在某个 SaaS 对话框里，这种架构更利于长期积累，也更适合跨模型迁移。对产品设计而言，“AI 记忆”未必应首先表现为一个更聪明的聊天窗口，而可能是一套可审计的写入、检索、任务收尾和定期清理机制。

##### 权限与脆弱性才是这类产品的真实边界

仓库反复强调只保存草稿、敏感操作前确认、只读数据库快照、不写回客户端、凭据不入库。这不是附属的安全说明，而是 Agent 产品不可缺少的交互设计：**能力越深入本机和账号，越需要把授权范围、执行预览、数据去向与撤销方式做成产品能力。**

同时，这套方案高度依赖网页结构、Cookie、客户端数据库格式、Frida、平台接口和桌面软件版本。平台一更新，适配器就可能失效；本地执行降低了云端泄露风险，却没有消除隐私、合规和账号风险。更通用的机会因此不只是继续增加 Skill，而是建设一层“工作流控制面”：统一权限、运行日志、版本兼容、失败重试、敏感数据检查和人工确认。

这个仓库提供的最好启发是：**Agent 落地的瓶颈，正从“模型能不能理解”转向“系统能不能可靠、安全地完成”。**谁能把这些看似琐碎的连接与边界做扎实，谁才更可能把演示变成日常工具。
