## 通俗精炼（1）

### 2026-04-14 04:10:57

#### 用一套 AI 工作流，把“想法验证”压缩到一个会话里

##### 核心观点

这篇内容讲的是：借助 `Claude Code + MCP + 设计/分析工具`，现在可以把“从想法产生、页面设计、上线、数据追踪到 A/B 测试”的完整流程，压缩到一次连续操作中完成。

它真正强调的不是“会不会做落地页”，而是：**能不能更快找到有效获客方式，并持续基于数据优化。**

##### 工作流拆解

###### 1. 先把业务上下文接入 AI

通过把 `ideabrowser` 作为 MCP 接入，AI 可以直接获取你的产品背景信息，比如目标用户、市场定位、价值主张和增长策略。

这一步的意义是：AI 不再是“空想”，而是基于你的真实业务语境来生成方案。

###### 2. 让 AI 直接产出获客策略

利用 `ideabrowser` 的技能能力，AI 可以针对你的细分市场生成获客创意和策略文档，并自动保存下来。

也就是说，AI 不只是“给灵感”，而是开始承担部分策略输出工作。

###### 3. 一边设计，一边同步到代码

通过 `Paper` 连接 `Claude Code`，可以直接可视化设计落地页，并持续迭代首屏、模块和组件。

重点在于：**设计和代码是同步的**，很多场景下甚至不再需要先去 Figma 再交付开发。

###### 4. 上线后立即进入数据闭环

页面部署后，再接入 `Humblytics` 做流量分析、滚动深度、热力图、漏斗和归因追踪。

这意味着整个过程不是“做完页面就结束”，而是从一开始就为后续优化准备好数据基础。

###### 5. 直接在真实站点上跑 A/B 测试

最关键的一步是：可以直接从 `Claude Code` 发起无代码 A/B 实验，在真实网站上动态替换标题等内容，快速验证效果。

本质上，AI 已经从“辅助生产”进一步走向“参与增长实验执行”。

## 结构化（1）

### 2026-04-14 04:23:48

#### 文章主旨

这篇内容主要介绍了一套“AI + MCP + 无代码实验”的工作流：把市场策略、页面设计、上线部署、数据分析和 A/B 测试串成一个连续流程，在一次会话里就能把一个冷启动想法快速变成可验证的线上实验。  
作者的核心观点是：未来真正的差距，不在于“能不能做页面”，而在于“知道该测试什么、如何获客、以及如何根据数据持续优化”。

#### 1. 从项目上下文出发，而不是从空白页开始

- 第一步是把 `ideabrowser` 接成一个 MCP，让它直接把项目关键上下文拉进终端。
- 这些上下文包括：
  - ICP（理想客户画像）
  - 品牌/产品定位
  - 产品价值主张
  - 增长策略
- 这样做的意义是：后续 AI 生成的内容，不再是泛泛而谈，而是建立在具体业务背景上的。

**通俗理解：**  
不是先让 AI“随便想个营销方案”，而是先把“我们卖给谁、解决什么问题、怎么增长”喂给它，再让它输出方案，质量会高很多。

#### 2. 用 AI 直接生成获客概念和策略文档

- 接着，作者用 `ideabrowser` 的技能，直接生成一个面向细分市场的获客概念。
- 系统不仅给想法，还会输出一份**策略文档**，并保存成文件。
- 这意味着从“有个模糊念头”到“形成可执行文档”，可以一步完成。

**关键点：**
- 输出不是零散灵感，而是结构化策略。
- 文档直接落盘，方便后续继续调用、迭代和复用。

**例子：**  
如果你做的是某个垂直 SaaS，AI 不只是说“做个落地页试试”，而是可能直接产出“针对该细分人群的页面角度、卖点表达、实验方向”等成体系内容。

#### 3. 设计落地页时，设计和代码同步推进

- 作者提到使用 `Paper`（连接到 Claude Code）来可视化设计着陆页。
- 可以直接迭代：
  - 英雄区（Hero Section）
  - 内容区块
  - 页面组件
- 一个重要信号是：**设计和代码保持同步**，因此“不一定需要 Figma”。

**核心价值：**
- 省掉了传统流程中“设计稿 → 前端还原 → 再修改”的多轮切换。
- 设计不再只是静态图，而是直接朝可上线页面推进。

**通俗理解：**  
过去可能先画图、再切图、再开发；这里更像是一边看页面效果，一边直接改成可运行版本。

#### 4. 页面上线后，立刻接入完整分析体系

- 落地页部署后，作者建议配置 `Humblytics` 做数据分析。
- 跟踪能力包括：
  - 流量分析
  - 滚动深度
  - 热力图
  - 漏斗追踪
  - 完整归因

**关键点：**
- 不是“先上线再说”，而是上线同时就把分析能力接好。
- 这样后面做 A/B 测试时，不只是看表面点击率，而是能看到用户行为全链路。

**例子：**  
如果某个标题点击高，但用户滚动深度低、漏斗转化差，就说明它可能“吸引了错误的人”，而不是真的更有效。

#### 5. 直接在 Claude Code 里运行无代码 A/B 测试

- 作者强调，可以**直接从 Claude Code 运行无代码 A/B 实验**。
- 它甚至可以在真实运行的网站上，动态替换标题进行测试。
- 这让“提出假设 → 上线实验 → 观察结果”的周期大幅缩短。

**核心变化：**
- A/B 测试不再高度依赖工程资源。
- 验证速度变成竞争优势。

**相关案例：**
- 热门回复中，`Vance Lever` 提到他们在 1 月就用这套栈测试定价页。
- 结果是：
  - Claude Code 自动选择了变体 B 并部署
  - 然后继续运行新的实验，甚至没有再询问
  - 到第 3 周时，已经测试了 **91 个标题变体**
  - 转化率提高到了**原来的 3 倍**

这个案例说明，这套方法不只是“理论上可行”，而是已经在实际业务中产生了明显结果。

#### 6. 把实验结果沉淀回系统，形成长期可复用的增长记忆

- 第 6 步是把结果存回 `@ideabrowser`（专业版）。
- 这样做的目的，是让智能代理随着时间积累上下文。
- 作者强调：未来每一次决策，都可以基于过去的数据来做。

**关键点：**
- 不只是一次性生成内容，而是持续积累“业务知识库”。
- AI 不是每次从零开始，而是越来越懂你的产品、用户和历史实验结果。

**通俗理解：**  
相当于给团队建了一个会不断学习的“增长大脑”：  
它知道你之前测过什么、哪个角度有效、哪些文案转化更好。

#### 7. 作者的结论：真正稀缺的是“测试与优化能力”

- 作者认为，现在“每个人都可以做 landing page”，门槛已经明显降低。
- 真正拉开差距的，是三件事：
  - 知道该测试什么
  - 知道如何获取客户
  - 知道如何持续优化
- 这套工具栈的价值，就在于补上这部分能力缺口。

**作者的判断：**
