**LotusDecoder**

从前天意识到要转型，不能老做驾驶员，到昨天实践了 系统设计+agent，来做一个小项目，目前感受挺好的。

整套做法还是基于，软件工程老一套了。

类似于，做公司一把手，

对一个软件，写两套描述，  
一个是自然语言描述有什么需求，第二是这个需求点有什么计算机可量化的指标、llm可以理解的评估器，评估器目前还很不完善。

先写个总的，再持续往下拆分模块，每个子模块还是这样写两层描述。

写好后，交给 agent 自己去coding，ta 是怎么写的，用什么语言和包，我都不管，反正 agent 自己去把 评估器 给写到通过为止。

整体感受下来是，人的认知带宽给打开了，注意力放在整体事情怎么做好，不用 几个小时一直坐在电脑前盯着了，不用写一步做法，等着 agent 转圈，检查一步，再让 agent 做下一步。  
精力也好了很多。

## 结构化（1）

### 2026-03-15 06:57:54

**主旨概括：**  
作者分享了自己从“亲自盯执行的驾驶员思维”转向“做整体设计和目标拆解的 CEO 思维”的实践体会。核心方法是：先把需求和可量化评估标准定义清楚，再交给 agent 自主完成编码，人主要负责系统设计与方向控制。

---

###### 1. 从“驾驶员”转向“CEO”：角色认知的变化
- 作者前天开始意识到，自己不能一直停留在“亲自驾驶、一步步盯进度”的状态。  
- 到昨天，他已经实际尝试用“系统设计 + agent”的方式做了一个小项目，体验不错。  
- 他认为，agent 时代里，人更应该做的是**架构设计和整体统筹**，而不是陷在具体执行里。

**通俗理解：**  
以前像是你亲自开车、不断修正方向；现在更像是你告诉司机目的地、路线要求和考核标准，剩下的让司机自己开。

---

###### 2. 方法本质：还是软件工程那一套，但换了执行方式
- 作者强调，这套做法本质上还是基于**传统软件工程思路**。  
- 只是人的位置变了：像公司一把手一样，先定义清楚要做什么，再定义怎么判断做得好不好。  
- 具体来说，要对一个软件写**两套描述**：

###### 两层描述
1. **自然语言描述需求**  
   - 说明产品要实现什么功能、满足什么需求。  
2. **可量化指标 / 评估器**  
   - 把需求转成计算机能衡量、LLM 能理解的标准。  
   - 作者也提到：**目前评估器还很不完善**。

**例子：**  
如果要做一个搜索功能：  
- 第一层描述：用户输入关键词后，要快速找到最相关内容。  
- 第二层描述：比如“返回结果中前 3 条至少有 2 条相关”“响应时间低于 2 秒”等，这些就是可量化指标。

---

###### 3. 按系统设计思路逐层拆解
- 作者不是一次性把所有细节写完，而是先写**总体描述**，再持续往下拆成模块。  
- 每个子模块依然继续用上面的“两层描述”方式来定义：
  - 这个模块要做什么  
  - 用什么指标衡量是否合格

**关键点：**
- 先有整体，再分模块  
- 每个模块都要有需求描述和评估标准  
- 这样 agent 才能围绕清晰目标自主工作

---

###### 4. agent 的职责：自己 coding，直到通过评估
- 当这些描述写好后，就把任务交给 agent。  
- 作者不会再去管：
  - agent 怎么写  
  - 用什么语言  
  - 用什么包  
- 只看一个结果：**agent 要把代码做到评估器通过为止**。

**这说明作者关注点发生了转移：**
- 不再盯实现过程  
- 而是盯“目标是否达成”

---

###### 5. 实践后的感受：认知带宽被释放，精力更好了
- 作者最大的感受是：**人的认知带宽被打开了**。  
- 过去可能要连续几个小时坐在电脑前：
  - 盯着 agent 转圈  
  - 写一步、看一步  
  - 检查一步、再让 agent 做下一步  
- 现在则可以把注意力放在：**整体事情怎么做好**。  
- 作者直接反馈：**精力也好了很多**。

---

###### 6. 对“可量化目标”的新理解
- 作者引用自己的补充观点说，自己以前其实还只是“半自动驾驶员”状态。  
- 虽然已经在用 Claude Code 一类工具，但仍然是自己不断掌握进度：  
  - 走偏了要扶正  
  - 缺资料了要补资料  
- 而真正的“CEO 思维”是：
  - 找出关键变量  
  - 布置任务  
  - 让 agent 自己想办法完成

**一句话理解：**  
不是教 agent 每一步怎么走，而是告诉它“什么叫成功”。

---

###### 7. 对 agent 时代分工的判断
- 作者在热门回复里进一步总结：
  - 在 AI 出现之前，不深入做整体设计、只做局部执行，也还能“混口饭吃”，这是常见情况。  
  - 但在 **agent 时代**，AI 写代码**比人更快更多**，而且**有一部分产出甚至比人更好**。  
- 所以，人真正有价值的方向就变成了：  
  **做架构、做整体设计、统管 agent。**

---

**总结一句：**  
这篇内容的核心不是“让 AI 写代码”本身，而是强调人要升级角色：从盯过程的执行者，变成定义目标、拆解系统、制定评估标准的总设计师。
