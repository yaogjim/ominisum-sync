Elysia: Decision Tree Agentic Framework

> **⚠️ Elysia is in beta!**
>
> If you encounter any issues, please [open an issue on GitHub](https://github.com/weaviate/elysia/issues).

Elysia is an agentic platform designed to use tools in a decision tree. A decision agent decides which tools to use dynamically based on its environment and context. You can use custom tools or use the pre-built tools designed to retrieve your data in a Weaviate cluster.

[Read the docs!](https://weaviate.github.io/elysia/)

> 💡 Don't forget to check out [the Github Repository for the Frontend](https://github.com/weaviate/elysia-frontend)!

Run the app via

```
elysia start
```

Then head to `localhost:8000` in a browser, navigate to the settings page, add your required API keys, Weaviate cloud cluster details and specify your models. Optionally use `--port` to specify which port Elysia will be run on.

Alternatively, we have created a demo version of Elysia (rate-limited, fixed datasets) to experiment with. Find it at: [https://elysia.weaviate.io/](https://elysia.weaviate.io/)

To use Elysia, you need to either set up your models and API keys in your `.env` file, or specify them in the config. [See the setup page to get started.](https://weaviate.github.io/elysia/setting_up/)

Elysia can be used very simply:

```
from elysia import tool, Tree

tree = Tree()

@tool(tree=tree)
async def add(x: int, y: int) -> int:
    return x + y

tree("What is the sum of 9009 and 6006?")
```

Elysia is pre-configured to be capable of connecting to and interacting with your [Weaviate](https://weaviate.io/deployment/serverless) clusters!

```
import elysia
tree = elysia.Tree()
response, objects = tree(
    "What are the 10 most expensive items in the Ecommerce collection?",
    collection_names = ["Ecommerce"]
)
```

This will use the built-in open source *query* tool or *aggregate* tool to interact with your Weaviate collections. To get started connecting to Weaviate, [see the setting up page in the docs](https://weaviate.github.io/elysia/setting_up/).

##### Configuring Settings

Settings page

To use Elysia with Weaviate, i.e. for agentic searching and retrieval, you need to either have a *locally running* instance of Weaviate, or access to a *Weaviate cloud cluster* via an api key and URL. This can be specific in the app directly (see above image), or by creating a `.env` file with

```
WCD_URL=...
WCD_API_KEY=...
WEAVIATE_IS_LOCAL=... # True or False
```

Elysia will automatically detect these when running locally, and this will be the default Weaviate cluster for all users logging into the Elysia app. But these can be configured on a user-by-user basis through the config.

Whichever vectoriser you use for your Weaviate collection you will need to specify your corresponding API key, e.g.

```
OPENAI_API_KEY=...
```

These will automatically be added to the headers for the Weaviate client.

Same for whichever model you choose for the LLM in Elysia, so if you are using GPT-4o, for example, specify an `OPENAI_API_KEY`.

Elysia's recommended config is to use [OpenRouter](https://openrouter.ai/) to give easy access to a variety of models. So this requires

```
OPENROUTER_API_KEY=...
```

#### Architecture

Elysia is architectured as a modern web application with a full-featured frontend for a responsive, real-time interface and a FastAPI backend serving both the web interface and API. The core logic is written in pure Python – what we call "blood, sweat, and tears" custom logic – with DSPy handling LLM interactions.

Unlike simple agentic platforms which have access to all possible tools at runtime, Elysia has a pre-defined web of possible nodes, each with a corresponding action. Each node in the tree is orchestrated by a decision agent with global context awareness about its environment and its available options. The decision agent evaluates its environment, available actions, past actions and future actions to strategize the best tool to use.

Read more about how we built Elysia in [this blog](https://weaviate.io/blog/elysia-agentic-rag).

#### FAQ

**How do I use Elysia with my own data?**

You can connect to your own Weaviate cloud cluster, which will automatically identify any collections that exist in the cluster.

Collections require being *preprocessed* for Elysia. In the app, you just click the 'analyze' button in the Data tab. In Python you can do:

```
from elysia.preprocessing.collection import preprocess

preprocess(collection_names=["YourCollectionName"])
```

**Can I run Elysia completely locally? (Locally running Weaviate, local models)**

Yes!

You can connect to a locally running Weaviate instance in Docker, and connect to Ollama for locally running language models.[See the setup page to get started.](https://weaviate.github.io/elysia/setting_up/)

**Help! My local model isn't working with Elysia. It's timing out or there are errors.**

Elysia works with quite long context, so some smaller models will struggle with this - it will either take a very long time to complete or the model will error to output the correct structured response.

For a complete guide and troubleshooting, [see this page of the documentation](https://weaviate.github.io/elysia/Advanced/local_models/).

**How do I clear all my Elysia data?**

Everything Elysia doesn't store locally will be a collection in your Weaviate cluster. You can delete any collections that start with `ELYSIA_` to reset all your Elysia data.

For example, in Python:

```
from elysia.util.client import ClientManager()
with ClientManager().connect_to_client() as client:
    for collection_name in client.collections.list_all():
        if collection_name.startswith("ELYSIA_"):
            client.collections.delete(collection_name)
```

**Can I contribute to Elysia?**

Elysia is **fully open source**, so yes of course you can! Clone and create a new branch of Elysia via

```
git clone https://github.com/weaviate/elysia
git checkout -b <branch_name>
```

Make your changes, push them to your branch, go to GitHub and submit a pull request.

**Where is the best place I can start contributing?**

There are no 'huge' new features we are planning for Elysia (for the moment). You could start with creating a new tool, or multiple new tools to create a custom workflow for something specific. Look for pain points you experience from your user journey and find what exactly is causing these. Then try to fix them or create an alternative way of doing things!

#### Elysia 项目精炼总结

Elysia 是 Weaviate 推出的开源智能体平台，通过“决策树”动态选择合适的工具执行任务，尤其适合搜索、分析和检索 Weaviate 集群中的数据。项目目前处于 **Beta 阶段**，既可作为网页应用运行，也可作为 Python 包集成。

##### 1. 核心能力

- Elysia 将多个工具组织成决策树，由“决策智能体”根据以下信息选择下一步行动：
  - 当前环境与上下文；
  - 可用工具；
  - 已执行的操作；
  - 未来可能采取的操作。
- 支持两类工具：
  - 用户自定义工具；
  - 用于查询和聚合 Weaviate 数据的内置开源工具。
- 与普通智能体平台一次性开放全部工具不同，Elysia 预先定义了由节点和动作构成的网络，以更有策略地选择工具。

##### 2. 快速使用

###### 运行网页应用

安装并启动：

```bash
pip install elysia-ai
elysia start
```

随后访问：

```text
http://localhost:8000
```

在设置页面中填写：

- 模型及其 API Key；
- Weaviate 云集群地址与密钥；
- 所需模型配置。

也可通过 `--port` 指定服务端口。官方还提供了一个**限流且数据集固定**的演示版本：

&lt;https://elysia.weaviate.io/>

###### 在 Python 中创建自定义工具

```python
from elysia import tool, Tree

tree = Tree()

@tool(tree=tree)
async def add(x: int, y: int) -> int:
    return x + y

tree("What is the sum of 9009 and 6006?")
```

该示例让 Elysia 调用自定义加法工具，计算 `9009 + 6006 = 15015`。

###### 查询 Weaviate 数据

```python
import elysia

tree = elysia.Tree()

response, objects = tree(
    "What are the 10 most expensive items in the Ecommerce collection?",
    collection_names=["Ecommerce"]
)
```

Elysia 会自动选择内置的查询或聚合工具，从 `Ecommerce` 集合中找出价格最高的 10 件商品。

Elysia 采用现代 Web 应用架构：

- **核心逻辑**：使用纯 Python 编写；
- **LLM 交互**：由 DSPy 处理。

其关键设计是预定义的决策树网络：每个节点对应一种动作，并由具备全局上下文的决策智能体进行调度，从而综合判断应该使用哪个工具。

##### 6. 使用自有数据

Elysia 可以连接用户自己的 Weaviate 云集群，并自动识别其中已有的集合。不过，集合在使用前需要经过预处理。

- 在网页应用中：进入 **Data** 页面，点击 **Analyze**。
- 在 Python 中：

```python
from elysia.preprocessing.collection import preprocess

preprocess(collection_names=["YourCollectionName"])
```

##### 7. 本地部署与模型限制

Elysia 支持完全本地运行：

- 使用 Docker 启动本地 Weaviate；
- 使用 Ollama 运行本地语言模型。

但 Elysia 通常需要处理较长上下文，因此较小的本地模型可能出现：

- 响应时间过长；
- 请求超时；
- 无法输出正确的结构化结果；
- 直接报错。

因此，本地部署时应选择上下文能力和结构化输出能力较强的模型。

##### 8. 数据清理

Elysia 未保存在本地的数据通常会存放在 Weaviate 集群中。要重置 Elysia 数据，可删除名称以 `ELYSIA_` 开头的集合：

```python
from elysia.util.client import ClientManager

with ClientManager().connect_to_client() as client:
    for collection_name in client.collections.list_all():
        if collection_name.startswith("ELYSIA_"):
            client.collections.delete(collection_name)
```

执行前应确认集合内容，避免误删需要保留的数据。

## 口播总结（1）

#### Elysia：用智能决策代理连接数据与工具的 Python 平台

这份材料介绍的是 Weaviate 开源的 Elysia。它既是一个 Python 软件包，也是一个带网页界面的智能代理平台。接下来，你会了解到它能做什么、怎样安装和连接自己的数据，以及它背后的工作方式和常见问题。

##### 首先，Elysia 是什么

核心来说，Elysia 是一个能够根据环境和任务，自动选择工具的智能平台。

这里的“代理”，可以理解为一个会自己判断下一步该做什么的软件助手。Elysia 不会把所有工具都同时交给模型，而是把工具组织成一棵“决策树”。决策代理会根据当前环境、可用工具、已经执行过的动作，以及接下来可能采取的动作，选择更合适的工具。

这意味着，Elysia 不只是简单地回答问题。它还可以根据问题，动态决定是查询数据、进行统计，还是调用你自己定义的功能。

项目目前处于测试阶段，也就是 beta 版本。如果遇到问题，官方建议在 GitHub 上提交 issue。Elysia 是开源项目，但官方也提醒，它不一定像成熟的生产软件那样被严格维护。

##### 接下来，如何启动 Elysia 应用

最简单的方式，是通过 Python 的包管理工具安装。

首先，需要准备 Python。通过 PyPI，也就是 Python 官方软件包仓库安装时，Elysia 要求 Python 3.12。安装命令是 `pip install elysia-ai`。

安装完成后，运行 `elysia start`。然后在浏览器中打开本机的八千端口，也就是 `localhost:8000`。进入设置页面后，填入所需的模型 API 密钥、Weaviate 云集群信息，以及你要使用的模型。端口也可以通过启动参数自行指定。

如果只是想体验功能，官方还提供了一个演示版本。不过这个版本有访问频率限制，而且使用的是固定数据集。

如果希望使用最新的开发版本，也可以从 GitHub 克隆项目。开发版支持 Python 3.10 到 3.12。创建虚拟环境后，用 `pip install -e .` 安装，就可以直接使用 Elysia 的 Python 软件包。

##### 更重要的是，Elysia 也可以直接用 Python 调用

Elysia 的使用方式可以非常简单。

你可以先创建一棵工具决策树，然后用 `tool` 装饰器，把自己的 Python 函数注册成工具。比如，定义一个接收两个整数、返回它们之和的 `add` 函数。接着向这棵树提问：“九千零九加六千零六是多少？”Elysia 就可以决定调用这个加法工具，并得到一万五千零一十五这个结果。

这个例子说明，开发者不需要手动写死每一步调用逻辑。只要把函数注册成工具，Elysia 就能让决策代理根据问题选择它。

##### 然后，Elysia 可以连接 Weaviate 中的数据

Elysia 已经预先配置好了连接和操作 Weaviate 集群的能力。

Weaviate 可以理解为一个存放并检索数据的服务。Elysia 可以使用内置的查询工具或聚合工具，去访问其中的集合。这里的“集合”，可以理解为一组结构相近的数据。

例如，你可以向 Elysia 提问：“电商集合中最贵的十件商品是什么？”同时指定要查询名为 `Ecommerce` 的集合。Elysia 会调用合适的查询或统计工具，返回结果。

如果要连接 Weaviate，需要准备两种情况中的一种。第一种，是本地运行的 Weaviate 实例。第二种，是 Weaviate Cloud，也就是云端集群，并提供对应的地址和 API 密钥。

##### 配置时，需要准备数据服务和模型的密钥

Elysia 的连接信息可以直接在网页应用中填写，也可以写进 `.env` 文件，也就是项目使用的环境变量配置文件。

连接 Weaviate 时，主要需要配置云集群地址、API 密钥，以及是否使用本地实例。对应的配置项包括 `WCD_URL`、`WCD_API_KEY` 和 `WEAVIATE_IS_LOCAL`。

如果你的 Weaviate 集合使用了某种向量化工具，也需要提供对应的 API 密钥。所谓向量化，就是把文字或其他数据转换成便于相似度检索的数字表示。比如使用 OpenAI 的向量化服务，就要配置 `OPENAI_API_KEY`。

如果 Elysia 使用 GPT-4o 这类大语言模型，同样需要配置模型服务的密钥。官方更推荐使用 OpenRouter。OpenRouter 可以用一个接口访问多种模型，因此需要配置 `OPENROUTER_API_KEY`。

这些密钥通常会被自动加入 Weaviate 客户端的请求头中，供数据检索和模型调用使用。

##### 接下来，了解 Elysia 的内部架构

Elysia 是一个现代网页应用。

它有一个完整的前端，用来提供响应式、实时的操作界面；后端则使用 FastAPI。FastAPI 是一种 Python 网页开发框架，负责同时提供网页界面和接口服务。

平台的核心逻辑使用纯 Python 编写。与大语言模型交互的部分，则由 DSPy 处理。DSPy 可以理解为一个帮助程序组织和调用语言模型的框架。

Elysia 的独特之处，在于它使用预先定义好的工具节点网络。每个节点对应一个动作。决策代理会在这个网络中，根据全局上下文判断下一步该走哪条路径。

所以，Elysia 的重点不是简单地“让模型看到所有工具，再自由发挥”，而是让模型在一个有结构的工具网络中做选择。它会综合考虑当前环境、可用动作、历史动作和后续动作，制定更合适的执行策略。

##### 使用自己的数据时，需要先做预处理

如果你想让 Elysia 使用自己的 Weaviate 数据，可以连接自己的 Weaviate Cloud 集群。Elysia 会自动识别集群中已有的集合。

不过，这些集合需要先经过 Elysia 的预处理。网页应用中，可以进入 Data，也就是数据页面，然后点击“分析”按钮。

在 Python 中，也可以调用预处理函数，并传入集合名称。比如，指定名为 `YourCollectionName` 的集合进行处理。

这一步的意义是，让 Elysia 了解集合中的数据结构，从而知道之后该如何查询和操作这些数据。

##### Elysia 也支持完全本地运行

如果比较关注数据不离开本地，Elysia 可以连接本地运行的 Weaviate，也可以使用本地语言模型。

一种方式，是在 Docker 中运行本地 Weaviate 实例。另一种方式，是连接 Ollama，让语言模型也在本地运行。

不过，本地模型可能遇到超时或输出错误。原因是 Elysia 需要处理比较长的上下文。上下文可以理解为模型在一次任务中需要参考的背景信息和历史内容。

一些较小的模型不一定能很好地处理这么长的上下文。结果可能是运行时间很长，或者无法生成 Elysia 所需要的结构化结果，也就是符合预定格式的输出。

##### 如果要清空 Elysia 数据，可以删除特定集合

Elysia 没有存放在本地的那部分数据，会保存在 Weaviate 集群中。

如果想重置 Elysia 的数据，可以删除名称以 `ELYSIA_` 开头的集合。官方给出的 Python 做法，是连接 Weaviate，列出所有集合，然后筛选出名称以 `ELYSIA_` 开头的集合并删除。

需要注意的是，这个操作会清除对应的 Elysia 数据，因此在执行前要确认这些集合中没有需要保留的内容。

##### 最后，Elysia 欢迎社区贡献

Elysia 完全开源，任何人都可以参与开发。

基本流程是先克隆项目，创建新的分支，在分支中修改代码，然后推送到自己的分支，最后在 GitHub 上提交合并请求。

官方建议，比较容易开始的方向，是创建一个新工具，或者创建一组工具，为某个具体任务设计自定义工作流。

与其一开始就追求很大的新功能，不如先观察使用过程中的具体痛点，找到问题所在，再尝试修复，或者设计一种替代方案。

##### 重点回顾

最后，可以记住五点。

第一，Elysia 是一个开源的 Python 智能代理平台，能够根据环境和任务，自动选择工具。

第二，它把工具组织成决策树，由决策代理结合当前环境、历史动作和后续可能动作，决定下一步怎么做。

第三，它可以直接连接 Weaviate 集群，使用内置查询和统计工具检索自己的数据，也支持开发者注册自定义 Python 工具。

第四，使用 Elysia 需要配置 Weaviate、向量化服务和大语言模型的相关密钥；同时，它也支持本地 Weaviate 和 Ollama 本地模型。

第五，Elysia 目前仍处于 beta 阶段。它完全开源，适合通过自定义工具和工作流进行扩展，但使用本地小模型时，要特别注意长上下文带来的超时和结构化输出问题。

## 深度解读（1）

### 2026-09-18 00:28:57

#### Elysia 的真正信号：Agent 正从“自由调用工具”转向“受约束的动态工作流”

Elysia 表面上是一个连接 Weaviate、让大模型查询私有数据的开源 Agent 平台，但更值得关注的是它对 Agent 架构的选择：**不是把所有工具一次性暴露给模型，而是预先定义一张可行的节点网络，再让决策 Agent 根据上下文、历史动作和后续选项选择路径。**

这代表一种务实的折中——既保留 Agent 的动态决策能力，又用工作流边界降低不可控性。

##### 可靠性可能主要来自缩小决策空间

很多 Agent 产品的问题并非模型完全不会调用工具，而是每一步都有过多选择：工具含义相近、参数复杂，错误还会在多轮执行中累积。Elysia 的方案相当于先由开发者规定“哪些动作可以从哪里发生”，模型只负责在有限选项中判断下一步。

这与完全固定的工作流不同：用户问“最贵的十件商品”时，系统仍可根据数据结构选择查询、聚合或其他工具；但它也不同于开放式 Agent，不允许模型任意组合全部能力。**Agent 的实用形态可能不是自主性越高越好，而是把确定性留给系统设计，把不确定性留给模型处理。**

这对产品设计有直接启发：决定体验上限的未必只是模型和提示词，还包括工具如何拆分、哪些路径合法、失败后能否回退，以及系统向模型暴露多少环境状态。未来 Agent 平台的关键资产，很可能是经过验证的工具拓扑和执行约束，而不只是工具数量。

不过，README 只陈述了架构，没有提供成功率、延迟或成本对照实验。因此“决策树优于全工具 Agent”目前是一个合理主张，而非已被该项目证明的结论。值得验证的指标应包括工具选择准确率、多步任务完成率，以及随着节点增加，维护成本是否迅速上升。

##### “与数据对话”仍然包含大量前置工程

示例代码看起来很简单：连接 Weaviate 后，系统便能回答“电商集合中最贵的十件商品”。但实际条件并不少：用户要准备集群、向量化与模型 API Key，还要先对 collection 做预处理；本地模型则可能因为长上下文和结构化输出能力不足而超时或报错。

这揭示了 Agentic RAG 容易被界面掩盖的一点：**自然语言入口很轻，数据准备、模式理解、权限管理和模型适配却很重。** Elysia 能自动发现 collection，不等于能自动理解数据质量、业务口径和访问边界。尤其是“最贵”这类问题，仍依赖价格字段、币种、缺失值及聚合语义被正确处理。

因此，真正的产品机会未必是再做一个聊天界面，而是降低这段前置工程：自动识别数据语义、生成并验证工具、发现口径冲突、评估查询结果，并让用户看见 Agent 为何选择某条路径。需求对象也更可能是已有向量数据库、希望开放数据访问能力的技术团队，而非完全没有数据基础设施的普通企业。

##### 它也是数据库厂商向应用层延伸的一次尝试

Elysia支持自定义工具、云端或本地 Weaviate、OpenRouter 及 Ollama，并以开源方式提供前后端。这降低了试用门槛，但它与 Weaviate 的集成最成熟，预处理结果和运行数据也会写回集群。商业上，这是一种典型的平台策略：**用开源 Agent 应用扩大数据库的使用场景，而不必先把 Agent 本身做成独立收费产品。**

目前项目明确处于 beta，维护强度也不按生产软件承诺。更合适的判断不是“它是否已能取代成熟方案”，而是把它视为一个架构样本：下一阶段可用的企业 Agent，竞争重点可能从“模型能不能调用工具”，转向“谁能更好地约束工具路径、准备数据，并解释和评估每一次决策”。
