## 通俗精炼（1）

### 2026-05-05 05:56:36

#### 摩根大通多智能体系统「Ask David」架构总结

##### 核心观点

摩根大通投资研究团队分享了其多智能体系统 **Ask David** 的构建方式。该系统代表了当前企业级 AI Agent 应用的一种主流架构：不是让一个大模型完成所有任务，而是通过多个专业 Agent 分工协作，提升可靠性与准确性。

##### 架构模式

###### 1. Supervisor Agent 统一编排

系统中有一个类似“主管”的 Agent，负责理解用户问题、拆解任务，并协调不同子 Agent 的工作流程。

它不是直接完成所有事情，而是决定：

- 调用哪个子 Agent
- 如何组织任务顺序
- 如何汇总最终结果

###### 2. 专业子 Agent 分工处理

不同子 Agent 负责不同类型的任务，例如：

- 信息检索
- 结构化数据查询
- 金融分析
- 文档理解
- 结果归纳

这种方式类似企业中的专业团队分工，比单一 Agent 更稳定、更可控。

###### 3. LLM 作为“裁判”进行反思检查

在答案输出前，系统会让另一个 LLM 扮演“裁判”或“审稿人”，检查回答是否合理、完整、可信。

但评论中也指出：  
**LLM 作为裁判是很多系统容易失效的环节。**  
如果裁判只是重复模型的自信判断，而不能真正发现错误，反思节点的价值会大打折扣。

###### 4. 人机闭环补足最后精度

即使系统自动化程度很高，最后仍需要人类参与审核或确认。

尤其在投资研究、金融分析等高风险场景中，人类专家仍然是保证准确性和责任边界的重要环节。

##### 产品启示

###### 从“一个智能体”到“一套组织系统”

这类架构说明，企业 AI 应用的重点不再是打造一个无所不能的超级 Agent，而是构建一个类似“小公司”的工作流：

- 一个 Agent 负责思考和调度
- 多个 Agent 负责具体执行
- 一个 Agent 负责检查
- 人类负责最终确认

这更像是在业务流程中嵌入一套 AI 组织，而不是简单调用一个聊天机器人。

##### 关键价值

这种多智能体架构适合复杂、高专业度、高准确性要求的场景，例如：

- 投资研究
- 企业知识问答
- 数据分析
- 法务与合规
- 医疗辅助
- 咨询报告生成

它的核心价值在于：

- 提升任务拆解能力
- 增强专业处理能力
- 降低单模型幻觉风险
- 提高输出可控性
- 保留人类专家的最终判断权

##### 一句话总结

摩根大通的 Ask David 展示了企业级 AI Agent 的主流方向：**用 Supervisor Agent 编排多个专业子 Agent，再通过反思检查和人类审核，构建可靠、可控、可落地的 AI 工作流。**

## 解读（1）

### 2026-05-05 06:02:55

##### 一、内容总结

这条内容提到：摩根大通投资研究团队分享了他们构建多智能体系统 **“Ask David”** 的方法。

其核心架构包括：

1. **Supervisor Agent（主管智能体）**
   - 负责整体任务分配与流程编排。

2. **专业子代理**
   - 分别处理不同任务，例如：
     - 信息检索
     - 结构化数据处理
     - 投资分析

3. **LLM 作为裁判 / 反思节点**
   - 在最终答案输出前，对结果进行检查、评估和修正。

4. **Human-in-the-loop（人机闭环）**
   - 在关键环节由人类介入审核，弥补最后的精度差距。

热门评论中也指出：  
这种模式正在成为当前企业级 AI 系统的常见蓝图，但“LLM 当裁判”可能是系统失效的薄弱点，除非它真的能独立发现问题，而不是简单复述模型信心。

---

##### 二、深入浅出解读

###### 1. 这不是一个 AI 包办所有事

传统想法可能是：  
> 给一个超级 AI，它自己搜索、分析、写报告、下结论。

但现实中，更可靠的做法是：  
> 把 AI 系统设计成一个“小团队”。

类似公司里的工作流：

| 角色 | 对应 AI 系统 |
|---|---|
| 项目经理 | Supervisor Agent |
| 研究员 | 检索 Agent |
| 数据分析师 | 结构化数据 Agent |
| 投资分析师 | 分析 Agent |
| 审稿人 | LLM 裁判节点 |
| 负责人 | 人类审核 |

所以它更像是：  
**不是让一个 AI 成为全才，而是让多个 AI 分工协作。**

---

###### 2. Supervisor Agent 的作用很关键

主管智能体不是负责回答所有问题，而是负责判断：

- 这个问题该拆成几个任务？
- 哪些子代理来处理？
- 先查资料还是先分析数据？
- 子代理结果是否需要再次验证？
- 最后如何整合成答案？

它相当于整个系统的“大脑调度中心”。

---

###### 3. 专业子代理提升稳定性

如果让一个模型同时做检索、计算、分析、写作，容易出错。

拆成多个子代理后，每个代理专注一件事：

- 检索代理：找资料
- 数据代理：处理表格、指标、财务数据
- 分析代理：生成观点和结论
- 总结代理：组织表达

这样可以降低复杂度，提高可控性。

---

###### 4. LLM 当裁判有用，但不能迷信

“LLM 作为裁判”指的是：  
让另一个模型检查前面生成的答案是否合理。

例如：

- 有没有幻觉？
- 数据是否前后一致？
- 推理是否跳跃？
- 结论是否过度自信？
- 是否遗漏重要风险？

但热门评论中有人指出：  
**如果裁判模型只是重复确认答案，那它并没有真正发挥监督作用。**

也就是说，裁判节点必须有独立标准，比如：

- 引用来源是否真实
- 数字是否能追溯
- 逻辑链是否完整
- 是否存在反例
- 是否需要人类复核

否则，“AI 审 AI”可能只是形式主义。

---

###### 5. 人机闭环仍然不可替代

在投资研究这种高风险场景里，最后仍然需要人类审核。

原因很简单：

- AI 可能编造来源
- AI 可能误解金融数据
- AI 可能忽略宏观风险
- AI 可能给出看似合理但实际危险的判断

所以人类不是被完全替代，而是从“亲自做所有事”变成：

> 监督、判断、修正和最终负责。

---

##### 三、我的意见

我认为这类架构代表了企业 AI 应用的主流方向：  
**多智能体 + 流程编排 + 自动检查 + 人类审核。**

它比单一聊天机器人更适合严肃业务场景，尤其是金融、法律、医疗、咨询、研究等领域。

但要注意三点：

###### 1. 多智能体不是越多越好

代理太多，系统会变复杂：

- 成本更高
- 延迟更长
- 错误链条更难排查
- 各代理之间可能互相污染结果

关键不是“堆 Agent”，而是设计清楚的流程。

---

###### 2. LLM 裁判不能代替真实验证

真正可靠的检查应结合：

- 数据库校验
- 规则校验
- 引用溯源
- 结构化评估指标
- 人类抽查

只靠另一个大模型来判断对错，风险依然很高。

---

###### 3. 人类角色会升级，而不是消失

AI 可以提高效率，但最终责任仍在人。

未来专业人士的核心能力会变成：

- 会拆任务
- 会设计工作流
- 会判断 AI 输出质量
- 会识别模型幻觉
- 会做最终决策

---

##### 四、一句话结论

**“Ask David” 展示的不是一个万能 AI，而是一套 AI 工作流系统：让多个专业智能体分工协作，再通过模型检查和人类审核提高可靠性。**

这可能就是未来企业级 AI 的重要形态。
