## 分析要点

- **核心高价值点**：将创作侧与生产侧拆分，并通过待制作队列、自动化工具和质检归档降低人工参与度，这一流程设计比单个工具推荐更值得借鉴。
- **留存建议**：选择性浏览并保留，适合作为AI视频生产流水线的案例参考（文章提供了较具体的工具组合、角色分工、成本结构和自动化思路，具有一定复用价值。）

**知识要点**

- 可将 Claude Code 等工具用于选题和脚本创作，将 Codex 用于配音、渲染、字幕、质检和归档，以降低不同任务之间的协作成本。
- 基于 HTML、CSS 和 JavaScript 的视频渲染方式便于模型生成、局部修改、版本管理和确定性渲染。
- 本地声音克隆可以降低持续配音成本，并在声音一致性和文稿隐私方面优于完全依赖云端服务。

**行动项**

- 先用一条短视频验证 Codex、HyperFrames、HeyGen 和 IndexTTS2 的端到端流程，再根据实际质量和成本决定是否扩展。
- 把选题、脚本、配音、渲染、字幕、质检和归档拆成明确环节，并尝试通过待制作队列衔接创作侧与生产侧。
- 围绕中文断句、语句组织、视频钩子和自身审美偏好持续调试 Skill，形成适合自己内容类型的版本。

#### 1\. Codex - 主控

Codex ,我把它当成视频制作端。Claude Code 负责创作侧（选题、洗稿、策划），Codex 负责生产侧（配音、渲染、字幕、质检、归档）。

为什么不全用 Claude Code 做？因为视频渲染是重 I/O 任务，经常需要长时间跑 FFmpeg、Node.js 渲染、ASR 调用。Codex Token便宜，调用组织迅速，量大管饱，而且内置了生图功能。

Claude Code 写完交接稿丢到待制作队列，Codex 取稿开工，做完归档，登记发布看板。我在中间只需要审一次稿。

#### 2\. HyperFrames — 视频渲染框架

HyperFrames 是用 HTML + CSS + JS 写视频的框架。每一页就是一个 HTML 文件，用 data-\* 属性标记时间轴，框架负责把它渲染成 MP4。

我选它有三个原因：

AI 能直接写。HTML/CSS 是所有大模型最熟悉的输出格式，Codex 写一页 HyperFrames 比写 After Effects 脚本或剪映模板靠谱得多。我的大部分视频就是两三轮提示词出来的。

改动成本低。改文案就改 HTML 里的文字，改样式就改 CSS，改动画就改 GSAP timeline。不用重新导出工程文件、不用重新对时间轴。

确定性渲染。同一份代码渲染出来的视频逐帧一致，没有「这次渲染和上次不一样」的问题。这对做质检和版本管理很重要——我可以用 SHA-256 校验成片有没有变。

Remotion（React 写视频）也在我的技术栈里，但 HyperFrames 上手更快，Codex 写 HTML 比写 React 组件更稳定。两个我都用，按项目选。

#### 3\. HeyGen — 数字人

HeyGen 解决的问题是：我不想每条视频都真人出镜。

我用自己的照片和视频训练了一个 Digital Twin（黑 T 坐姿形象），HeyGen 根据我上传的音频生成对口型的数字人视频。默认圆形裁切放在视频左下角，像一个小窗口在讲话。

我选 HeyGen 是因为三件事都满足了。

Digital Twin 效果够用。训练完的数字人嘴型同步、表情自然度能过审。Avatar III 引擎大约 1 美元/分钟，一条 2 分钟的短视频数字人成本 2 美元。需要更高质量可以切 Avatar V，大约 4 美元/分钟，但大部分视频 III 就够了。

减少出镜焦虑。我录实操教程会真人出镜，但日常短视频用数字人就行。省下来的时间和精力用来打磨内容。

CLI 可自动化。HeyGen 有命令行工具，可以写进 Skill 里自动调用。认证走 OAuth 用网页套餐额度，不额外扣 API 钱包。

#### 4\. IndexTTS2 — 本地声音克隆

所有视频的配音都跑 IndexTTS2，一个开源的本地 TTS 模型。

我录了一段自己说话的无损 WAV 作为声线参考（pluvio-indextts2-calm-v1），IndexTTS2 克隆这个声线来念稿。默认平静语气，FFmpeg atempo=1.12 提速到 1.12 倍保持音高。

我没用云端 TTS，原因很直接。

零成本。本地跑，不按字数或时长计费。一个月做几十条视频，配音成本是零。

声线一致。每次用同一个无损 WAV 参考，声音风格稳定。我的声线参考文件锁了 SHA-256，防止被意外覆盖导致声音漂移。

隐私。文稿不出本地机器。

MiniMax 我只在对外教程里用——教读者怎么接入 TTS 中转站。自己的视频成片从不走云端 TTS。

##### 一、核心主旨

作者分享了一套以 **Codex、HyperFrames、HeyGen 和 IndexTTS2** 为核心的 AI 视频生产流程。过去一个月，作者投入不到 **10小时**，在抖音涨粉约 **2000人**，并接到第一个商单；这套流程可以减少真人出镜、配音和视频制作的时间成本。

##### 二、整体工作流：Claude Code 负责创作，Codex 负责生产

作者将视频制作拆成两个部分：

- **Claude Code：创作端**
  - 负责选题
  - 内容改写、策划
  - 生成视频制作稿件
- **Codex：生产端**
  - 配音
  - 视频渲染
  - 字幕生成
  - 质量检查
  - 文件归档
  - 登记发布看板

具体流程是：

1. Claude Code 完成选题和文案；
2. 将制作稿放入待制作队列；
3. Codex 自动取稿并完成配音、渲染、字幕等工作；
4. 作者中途只需审核一次；
5. 视频完成后归档并进入发布流程。

作者没有完全使用 Claude Code，是因为视频生产涉及较多重 I/O 任务，例如长时间运行 FFmpeg、Node.js 渲染和 ASR 调用。作者认为 Codex 成本较低、执行速度快、适合大量调用，并且自带生图能力。

##### 三、核心工具一：HyperFrames——用网页技术渲染视频

###### 1. 基本原理

HyperFrames 是一个基于 **HTML、CSS 和 JavaScript** 的视频渲染框架：

- 每一页视频对应一个 HTML 文件；
- 使用 `data-*` 属性标记时间轴；
- 框架将网页内容渲染成 MP4 视频。

###### 2. 作者选择它的原因

###### AI 更容易生成

HTML 和 CSS 是大模型熟悉的输出格式。相比 After Effects 脚本或剪映模板，Codex 更容易生成 HyperFrames 页面。

作者表示，大多数视频通过 **两三轮提示词** 就能制作出来。

###### 修改成本低

- 修改文案：直接修改 HTML 中的文字；
- 修改样式：调整 CSS；
- 修改动画：修改 GSAP 时间轴；
- 不需要重新导出工程文件，也不用手动重新调整复杂时间轴。

###### 渲染结果稳定

相同代码每次渲染出来的视频逐帧一致，便于：

- 视频质量检查；
- 版本管理；
- 使用 **SHA-256** 校验成片是否被修改。

###### 3. 与 Remotion 的关系

作者并不是完全不用 Remotion。Remotion 仍然在其技术栈中，但作者认为：

- HyperFrames 上手更快；
- Codex 生成 HTML 比生成 React 组件更稳定；
- 两者会根据项目需求分别使用。

---

##### 四、核心工具二：HeyGen——用数字人替代真人出镜

###### 1. 使用方式

作者使用自己的照片和视频训练了一个 Digital Twin，形象是：

- 黑色 T 恤；
- 坐姿；
- 通常被裁成圆形；
- 放在视频左下角，类似一个讲解窗口。

HeyGen 会根据上传的音频生成与声音同步的数字人视频。

###### 2. 主要价值

###### 减少真人出镜压力

作者不想每条视频都真人出镜：

- 实操教程仍然可以真人出镜；
- 日常短视频则使用数字人；
- 可以减少外貌焦虑，把时间投入到内容打磨中。

###### 数字人效果基本够用

作者认为训练后的 Digital Twin 在以下方面表现合格：

- 嘴型同步；
- 表情自然度；
- 能够满足普通短视频发布要求。

###### 3. 成本

HeyGen 的费用按照视频时长计算：

- **Avatar III：约1美元/分钟**
  - 一条2分钟短视频的数字人部分约 **2美元**；
- **Avatar V：约4美元/分钟**
  - 适合需要更高质量的场景；
- 对大多数视频而言，作者认为 Avatar III 已经够用。

HeyGen 还支持命令行工具，可以集成到 Skill 中自动调用。认证采用 OAuth，使用网页套餐中的额度，不会额外扣除 API 钱包费用。

---

##### 五、核心工具三：IndexTTS2——本地声音克隆

###### 1. 使用方法

作者使用开源本地 TTS 模型 **IndexTTS2** 生成所有视频配音：

1. 录制一段自己的无损 WAV 音频；
2. 将其作为声音参考；
3. 使用 IndexTTS2 克隆个人声线；
4. 用克隆的声音朗读视频文稿；
5. 通过 FFmpeg 的 `atempo=1.12` 将语速提高到 **1.12倍**，同时保持音高不变。

作者使用的声线参考文件名为：

> `pluvio-indextts2-calm-v1`

整体声音风格偏平静。

###### 2. 不使用云端 TTS 的原因

###### 成本为零

IndexTTS2 在本地运行，不按字数或时长收费。即使一个月制作几十条视频，配音成本也基本为零。

###### 声音风格稳定

每次都使用同一个无损 WAV 作为参考，能够保持声线一致。作者还为参考文件锁定了 SHA-256，避免文件被意外覆盖后导致声音发生变化。

###### 保护隐私

视频文稿不需要上传到云端，能够保留在本地机器上。

作者只在对外教程中使用 MiniMax，自己的视频成片并不使用云端 TTS。

##### 七、想复制这套模式，需要具备两个前提

###### 1. 具备基本的内容能力

AI 可以帮助完成：

- 配音；
- 视频渲染；
- 字幕；
- 封面；
- 部分自动化流程。

但 AI 无法完全替代以下能力：

- 判断什么选题值得做；
- 判断观众是否愿意观看；
- 理解平台内容风格；
- 提升内容质量；
- 形成稳定的账号定位。

作者认为，零基础者可以通过学习和参考已有内容起步，简单来说就是先“抄作业”，再逐步形成自己的内容能力。

###### 2. 愿意持续调整 Skill

这套系统不是安装后就能直接使用的 SaaS 产品。每个 Skill 都是作者根据以下因素反复调试出来的：

- 自己的内容类型；
- 目标平台策略；
- 个人审美偏好；
- 视频制作流程。

别人可以直接拿去运行，但如果想形成自己的风格，还需要自行修改和优化。

## 通俗精炼（1）

### 2026-09-18 10:46:37

#### AI 短视频流水线：把创作判断留给人，把生产交给智能体

作者称，过去一个月投入不到 10 小时，借助 AI 工作流在抖音涨粉约 2000，并获得首个商单。核心并非“一键生成爆款”，而是将选题、策划与视频生产拆开，用 Codex、HyperFrames、HeyGen 和 IndexTTS2 自动完成配音、画面、数字人、字幕、质检与归档。

##### Codex 统筹生产，HyperFrames 负责稳定渲染

Claude Code 用于选题、改稿和策划，Codex 接收定稿后执行生产任务，作者只需中途审稿一次。选择 Codex，主要因为视频制作涉及 FFmpeg、Node.js、语音识别等长时间、高 I/O 任务，其调用成本和调度效率更合适。

HyperFrames 用 HTML、CSS、JavaScript 描述画面和时间轴。大模型更擅长生成这类代码，文案、样式和动画也可分别修改；相同代码能逐帧一致地渲染，便于质检、版本管理和 SHA-256 校验。相比 React 技术栈的 Remotion，它更易上手，但作者会按项目混用。

##### 数字人减少出镜，本地克隆声音控制成本

HeyGen 根据音频生成作者的 Digital Twin，用于替代日常真人口播。Avatar III 约 1 美元/分钟，2 分钟视频约 2 美元，并可通过命令行接入自动化流程。

配音使用开源、本地运行的 IndexTTS2：以固定 WAV 样本克隆声线，再用 FFmpeg 提速至 1.12 倍。其优势是零按量费用、声音一致、文稿不出本机。

##### 增量成本不高，但内容能力仍是瓶颈

主要固定开销是 OpenAI Pro、Anthropic Max 和 HeyGen Creator（月费 49 美元）；火山 ASR 约 0.4 元/小时，作者月支出不足 20 元。HeyGen 是唯一随产量线性增长的成本。

作者强调，这不是开箱即用的 SaaS：AI只能提高生产效率，无法替代选题判断、内容质量和平台感觉；各项 Skill 也需持续调试，才能形成个人风格。相关效果与收益均为作者自述，工作流仍缺中文断句和差异化开场钩子等能力。
