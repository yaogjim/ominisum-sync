## 结构化（1）

### 2026-07-24 11:01:11

#### 文章精炼总结

动态工作流可以看作一种更通用的**智能体编排方式**：它把工作流框架、自动化、循环、任务路由和图结构统一起来，并根据任务需求动态组织多个 AI 智能体。作者认为，这是其代理编排器中最强大的功能之一，有望解锁更多“测试时计算”模式。

##### 1. 核心概念：统一不同智能体工作流

- 动态工作流是一种 **Meta-harness（元级编排层）**，即在多个智能体或工具之上提供统一的调度界面。
- 它不仅执行预先写死的流程，还能根据任务情况，**动态、自动地调整执行路径与智能体之间的交互方式**。
- 支持多种代理后端，例如：
  - Claude
  - Codex
  - Pi
  - Hermes
  - 其他模型或智能体框架

##### 2. 主要应用模式

动态工作流可以支持多种复杂任务：

- **LLM 委员会**：让多个模型分别提出观点，用于获得多元意见或进行更深入的规划。
- **动态任务路由**：按照成本、速度、智能水平等需求，把任务分配给最合适的智能体。
- **顾问/评审人 + 执行器**：一个智能体负责提出建议或审查，另一个负责具体执行和修改。
- **图结构协作**：根据任务依赖关系，组织多个智能体按复杂流程协作，而非只进行简单的线性调用。
- **智能体团队通信**：在长任务中，让多个智能体按需沟通、交换信息并共同推进工作。

##### 3. 特别适用的场景

作者认为，该功能尤其适合：

- 长时间运行的复杂任务
- 代码审查
- AI 辅助编辑
- 成果物或内容创作
- 其他需要反复评审、协作和迭代的创意任务

例如，在代码审查中，可以由一个智能体分析风险，另一个检查架构，第三个负责修改代码，再由评审智能体验证结果。

##### 4. 灵感来源与未来判断

- 作者受到 **Claude Code 团队动态工作流功能**的启发。
- 他在当年早些时候已经实现了类似能力，但希望将其扩展到不同代理后端，而不是绑定单一模型。
- 作者认为动态工作流未来会更流行，并计划继续分享实验结果和更多实践细节。

##### 5. 回复中的补充观点与当前局限

- 作者认为，循环、路由和图等概念最终可能整合成一个统一界面，用来支持各种复杂的智能体工作流。
- 目前这些想法仍处于早期阶段，最通用的代理框架形式尚未完全确定。
- 有回复指出，动态工作流尚未真正普及，部分原因是**令牌消耗较高**。
- 作者表示，多后端编排反而能延长 Claude、Codex 等订阅额度的使用时间，因此在实际使用中可以：
  - 降低成本
  - 提升速度
  - 避免过度依赖单一后端
- 当前的主要不足是：**多智能体协作与通信的可靠性仍需提升**。

## 通俗精炼（1）

### 2026-09-18 10:47:44

#### 动态工作流：用统一编排层组织多模型、多智能体协作

作者认为，动态工作流是对自动化、循环、路由、图式流程及传统 Agent Harness（智能体运行框架）的进一步抽象：通过一个“元编排层”，根据任务实时组合不同模型和智能体，从而支持更复杂的测试时计算与协作模式。

##### 从固定流程转向按任务动态组装

该方案可接入 Claude、Codex、Pi、Hermes 等不同后端，并自动决定任务如何拆分、由谁执行以及智能体之间如何交互。典型模式包括：

- 让多个大模型组成“委员会”，提供不同观点或完成深度规划；
- 根据成本、速度和能力动态路由任务；
- 采用“顾问/评审者 + 执行者”的协作方式；
- 构建循环、分支和智能体通信等复杂图式流程。

作者称，这种方式尤其适合长时间运行的任务、代码审查、AI 编辑、内容创作及其他需要多智能体协作的工作。

##### 价值在于跨模型调度，但可靠性仍待提升

相比依赖单一模型，跨后端编排可以在智能水平、成本和速度之间灵活取舍。作者表示，实际使用中，它能分摊不同服务的订阅额度，从而降低成本并提高执行速度。

不过，这一方向仍处早期阶段：多智能体协作与通信的可靠性尚不成熟，动态流程还可能带来较高的 Token 消耗。作者受 Claude Code 团队相关功能启发，希望最终将各种循环和图式概念统一为一个可自动运行的通用界面；但其最通用的形态和更多有效场景仍在探索中。
