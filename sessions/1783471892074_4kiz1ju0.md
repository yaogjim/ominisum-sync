## 正文

Every message you send Claude Code ships a payload you never see. Not your prompt — the machinery around it: tool definitions, a skills catalogue, system instructions for features you may never touch. It goes out on every request, and you're billed for it every turn.

You can remove most of it. The six steps below show how to see what your requests actually contain, then trim it with two settings Claude Code already has. Mine dropped by tens of thousands of tokens per turn.

#### 1\. Measure your context with `/context`

Type `/context` in any Claude Code session. It breaks your context window down by category — system prompt, system tools, MCP tools, memory files, messages — each with a token count and its share of the window.

Note the numbers now, before changing anything. You'll compare against them in the last step.

`/context` shows the tools as a group. It won't tell you which individual tool is largest — it reports one "tools" number, not a ranking. The next step fixes that.

Claude Code talks to the Anthropic API over HTTP, so you can put a proxy in between that forwards each request untouched, streams the reply straight back, and records what went past. The CLI doesn't notice.

Grab [`proxy.mjs`](https://gist.github.com/mattpocock/5b3d76ea21f5f698aefded47a9cea3b1) — one file, no dependencies, Node built-ins only. Run it:

Point Claude Code at it in another terminal and send a message:

```

ANTHROPIC_BASE_URL=http://localhost:8787 claude
```

Each request is written to `./logs/` as readable Markdown, and a ranked table prints to the terminal:

```

[agent-proxy] 69 tools · 154,946 tool bytes · 65,538 real input tokens

Workflow      21229 B  ~5307 tok

DesignSync     8978 B  ~2245 tok
```

Open the Markdown file and read it: every tool's full schema, the system prompt, the message history — the whole request as the model receives it. The ranked table at the top is your list to work from, so you can remove the exact tools you don't use rather than guess.

Now you know what's in the payload and which parts are largest. The next two steps remove it. Both settings live in your settings file — `~/.claude/settings.json` for every project, or `.claude/settings.json` for one.

Some features bring a whole cluster of tools and instructions with them. A single flag turns the feature off along with everything it carries:

- `disableBundledSkills` — removes all of Anthropic's bundled skills at once (the `dataviz`, `review`, `init` catalogue), while leaving their slash commands typable.
- `disableWorkflows` — removes the multi-agent `Workflow` tool, the largest single line in the table.

Use one whenever a whole feature isn't earning its place.

For individual tools, a `permissions.deny` rule with a bare tool name removes that tool's definition from the payload — Claude never sees it:

```

"deny": ["NotebookEdit", "CronCreate"]
```

One detail worth knowing: a bare name (`"NotebookEdit"`) removes the tool. A scoped rule (`"Bash(rm *)"`, `"Skill(dataviz)"`) blocks the matching call but leaves the definition in the payload. To shrink the request, use bare names.

The flags in the previous step are the broad first pass; these deny rules pick off the individual tools the flags don't cover.

> Keeping some skills but not all? `disableBundledSkills` is all-or-nothing. To drop them one at a time, use `skillOverrides` with a skill set to `"off"` (removed from the payload) or `"user-invocable-only"` (still typable, but Claude doesn't see it).

Here's what the previous two steps produced — the flags and deny rules that trim the bloat, ready to drop into `~/.claude/settings.json`:

```

"disableBundledSkills": true,

"disableWorkflows": true,

"disableRemoteControl": true,

"disableClaudeAiConnectors": true,
```

Treat it as a menu, not a prescription. The reason to see your own payload first is so you cut what you don't use. If you work in plan mode, keep it. If you write notebooks, keep `NotebookEdit`. The list above is what earned removal for me.

One caveat: some of what looks like bloat is machinery that background jobs and multi-agent runs rely on — the task tools, `Workflow`, worktree tools. If you use those, keep them.

#### 6\. Re-measure with `/context`

Restart Claude Code so it reloads the settings, and run `/context` again. The tools count and token total should be lower.

That difference is the tokens you were sending every turn and now aren't — cheaper requests, and less for the model to read past before it reaches your problem.

## 通俗精炼（1）

### 2026-07-08 00:51:32

#### Claude Code 系统提示 “瘦身” 指南总结

##### 一句话概括

Claude Code 每次请求都会携带大量你看不见的系统提示、工具定义和技能说明，这些内容会占用上下文、增加 token 成本。文章教你先量化、再裁剪不使用的工具和功能，从而降低每轮请求的 token 消耗。

---

##### 核心问题：隐藏的 Token 成本

Claude Code 不只是发送你的 prompt，还会附带：

- 系统提示词
- 工具定义
- 内置 skills 目录
- Workflow、多 Agent、Notebook、远程控制等功能说明
- MCP 工具与历史消息

这些内容每轮请求都会发送给模型，并计入 token 费用。很多功能你可能根本没用，但仍然在持续消耗上下文窗口和成本。

---

##### 方法一：用`/context`先量化上下文

在 Claude Code 中输入：

```bash
/context
```

它会展示上下文窗口的组成，包括：

- system prompt
- system tools
- MCP tools
- memory files
- messages

这一步的作用是建立 baseline，方便后续对比优化效果。

---

##### 方法二：用代理查看完整请求内容

`/context`只能看到大类 token 数，无法知道哪个具体工具最占空间。

文章建议使用一个本地 HTTP proxy：

```bash
ANTHROPIC_BASE_URL=http://localhost:8787 claude
```

它会拦截 Claude Code 发给 Anthropic API 的请求，并记录：

- 每个工具的完整 schema
- 系统提示
- 消息历史
- 工具体积排名

这样你可以精确识别 “最肥” 的工具，而不是凭感觉删除。

---

##### 方法三：关闭整组不用的功能

在配置文件中修改：

- 全局配置：`~/.claude/settings.json`
- 项目配置：`.claude/settings.json`

常见可关闭项包括：

```json
{
  "disableBundledSkills": true,
  "disableWorkflows": true,
  "disableRemoteControl": true,
  "disableClaudeAiConnectors": true
}
```

含义：

- `disableBundledSkills`：关闭 Anthropic 内置 skills，如 dataviz、review、init 等
- `disableWorkflows`：关闭多 Agent Workflow 工具，通常体积很大
- `disableRemoteControl`：关闭远程控制相关能力
- `disableClaudeAiConnectors`：关闭 Claude AI 连接器相关能力

这些适合 “一整类功能都不用” 的场景。

---

##### 方法四：用`permissions.deny`删除单个工具

如果只想删除个别工具，可以用：

```json
{
  "permissions": {
    "deny": ["NotebookEdit", "CronCreate"]
  }
}
```

关键细节：

- `"NotebookEdit"`：会从请求 payload 中移除该工具定义
- `"Bash (rm *)"`：只是禁止匹配调用，但工具定义仍会发送

所以，如果目标是减少 token，要使用 “裸工具名”。

---

##### 方法五：精细管理 Skills

`disableBundledSkills`是全关。如果只想关闭部分 skill，可以用`skillOverrides`：

- `"off"`：彻底移除，不进入 payload
- `"user-invocable-only"`：用户仍可手动调用，但 Claude 默认看不到

适合保留少数高频 skill，同时移除大部分低频 skill。

---

##### 方法六：重启并重新测量

修改配置后，需要重启 Claude Code，然后再次运行：

```bash
/context
```

对比前后 token 数变化。

节省下来的 token，就是过去每轮请求都在无形浪费的上下文和费用。

---

##### 产品视角解读

这本质上是在做 AI 工具的 “上下文成本治理”。

对 Claude Code 这类 Agent 产品来说，默认开启大量能力能提升开箱即用体验，但也带来：

- 更高 token 成本
- 更长上下文
- 更高延迟
- 模型注意力被无关工具干扰
- 对用户不可见的 “系统负担”

所以，对高频使用者来说，按需裁剪工具链是一种非常现实的降本增效手段。

---

##### 适用与风险

###### 适合关闭的情况

- 不使用 Workflow / 多 Agent
- 不写 Notebook
- 不用内置 dataviz /review skills
- 不依赖远程控制或 Claude 连接器
- 追求更低成本、更干净上下文

###### 不建议关闭的情况

- 依赖 plan mode
- 使用后台任务
- 使用多 Agent Workflow
- 使用 worktree 工具
- 经常操作 Notebook
- 依赖某些内置 skill 工作流

---

##### 总结

文章的核心方法是：

1. 用`/context`量化上下文
2. 用 proxy 看清真实请求 payload
3. 关闭整组不用的功能
4. 删除单个低频工具
5. 精细管理 skills
6. 重测 token 变化

核心原则不是盲目 “瘦身”，而是：**先观测，再决策；只删除自己不用的能力。**

## 口播总结（1）

### 2026-08-03 01:52:32

#### 如何清理 Claude Code 系统提示词中的臃肿内容

每次向 Claude Code 发送消息时，实际发出去的不只是你输入的提示词，还包括工具定义、技能目录和系统指令等隐藏内容，而且这些内容每一轮都会消耗并计费。下面用六步说明，如何看清这些隐藏内容，找出真正用不到的部分，再把它们删掉；有的人每轮就因此减少了数万枚令牌，也就是模型需要读取和计费的文本单位。

##### 第一步：先用 `/context` 测量当前上下文

首先，核心结论是：在修改设置之前，先记录当前请求到底有多大。

在任意 Claude Code 会话中输入 `/context`。它会把上下文窗口拆成几类，包括系统提示词、系统工具、MCP 工具、记忆文件和消息记录，并显示每一类占用了多少令牌，以及占整个窗口的比例。

这里的“系统提示词”，指的是模型运行时必须遵守的背景指令。“MCP 工具”，可以简单理解为通过外部协议接入的工具。

先记下这些数字。因为最后重新测量时，你需要用它们和优化后的结果进行比较。

不过，`/context` 有一个限制。它只会把工具作为一个整体显示，不会告诉你其中哪个具体工具最大。也就是说，你只能看到一个总的“工具”数字，看不到工具之间的排名。接下来，就需要用代理把每个工具拆开来看。

##### 第二步：用代理查看每个工具的真实大小

接下来，核心结论是：想知道到底是哪几个工具占用了最多空间，就在 Claude Code 和 Anthropic 接口之间加一个代理。

Claude Code 通过 HTTP，也就是网页服务常用的通信方式，和 Anthropic 的接口通信。你可以放入一个中间代理，让它原样转发每个请求，把回复直接传回来，同时记录请求内容。Claude Code 本身不会察觉这一层代理。

原文提供了一个叫 `proxy.mjs` 的单文件代理。它不需要额外依赖，只使用 Node.js 自带的功能。

启动代理后，在另一个终端里，把 Claude Code 的接口地址设置为本机的八七八七端口。具体来说，就是把 `ANTHROPIC_BASE_URL` 设置为 `http://localhost:8787`，然后运行 `claude`。

之后，每个请求都会以易读的 Markdown 文件形式写入当前目录下的 `logs` 文件夹。终端还会打印一张按大小排序的列表。

原文给出的示例是：一共有 69 个工具，工具定义占用了 154,946 字节，真正的输入内容有 65,538 枚令牌。其中，名为 Workflow 的部分占 21,229 字节，大约相当于 5,307 枚令牌；名为 DesignSync 的部分占 8,978 字节，大约相当于 2,245 枚令牌。

这些数字的意义是，你不再需要凭感觉猜测哪些工具臃肿，而是能直接看到排名靠前的工具。

打开生成的 Markdown 文件后，还能看到每个工具的完整定义，也就是工具的参数和使用规则；同时还能看到系统提示词、消息历史，以及模型实际接收到的完整请求。

##### 第三步：先关闭不用的整组功能

看清请求中有什么之后，下一步就是删减。相关设置都放在 Claude Code 的设置文件里。

如果希望对所有项目生效，使用用户目录下的 `~/.claude/settings.json`。如果只希望对某一个项目生效，使用项目目录下的 `.claude/settings.json`。

核心结论是：如果某个完整功能你根本不用，可以用一个开关，把它带来的整组工具和指令一起移除。

第一个开关是 `disableBundledSkills`。它会一次性移除 Anthropic 自带的全部技能，包括数据可视化、代码审查和项目初始化等技能目录。不过，这些技能对应的斜杠命令仍然可以输入，只是它们不再被放进模型每次收到的请求里。

第二个开关是 `disableWorkflows`。它会移除多智能体 Workflow 工具。原文的实测列表中，Workflow 是占用空间最大的单个项目。

所谓“多智能体”，就是让多个模型角色或任务代理协同工作的功能。如果你并不使用这类工作流，那么关闭它通常是一次比较明显的清理。

##### 第四步：用权限规则移除单个工具

前面的开关适合关闭一整组功能。接下来，核心结论是：对于单个不需要的工具，可以用权限设置里的 `deny` 规则，把它的定义直接从请求中移除。

例如，可以把 `NotebookEdit` 和 `CronCreate` 写进 `deny` 列表。这样一来，Claude 根本看不到这两个工具的定义，也就不会在每一轮请求中携带它们。

这里有一个很重要的区别。

如果写的是一个不带范围的工具名，比如 `NotebookEdit`，它会把整个工具定义移除，从而真正缩小请求。

但如果写的是带范围的规则，比如 `Bash(rm *)`，或者 `Skill(dataviz)`，它只会阻止符合条件的调用，却仍然把这个工具的定义留在请求中。

所以，如果你的目标是减少上下文和令牌消耗，就要使用不带范围的工具名称，而不是只限制某一种调用方式。

##### 第五步：按需处理技能和其他功能

更重要的是，关闭功能时不要盲目追求越多越好，而要根据自己的工作方式来选择。

`disableBundledSkills` 是一次性开关，不能只关闭其中一个技能。如果你想保留一部分技能，只移除另一部分，可以使用 `skillOverrides`。

把某个技能设为 `off`，表示彻底从请求中移除。把它设为 `user-invocable-only`，则表示你仍然可以手动输入这个技能的命令，但 Claude 不会在默认请求中看到它。

原文作者最终整理出了一组可以放进 `settings.json` 的设置，包括：

`disableBundledSkills` 设为 `true`；

`disableWorkflows` 设为 `true`；

`disableRemoteControl` 设为 `true`；

以及 `disableClaudeAiConnectors` 设为 `true`。

不过，这份列表只是作者自己的清理结果，不是所有人都应该照抄的固定方案。

如果你经常使用计划模式，就应该保留相关功能。如果你需要编辑笔记本文件，就应该保留 `NotebookEdit`。最可靠的做法，是先测量自己的请求，再根据工具排名，删除真正用不到的内容。

还要注意，有些看起来像臃肿内容的工具，其实是后台任务、多智能体运行和工作树功能依赖的基础设施。这里的“工作树”，可以理解为让不同任务使用相互隔离的代码工作目录。

如果你正在使用任务工具、Workflow 或工作树工具，就不要贸然关闭它们，否则可能影响这些功能。

##### 第六步：重启后再次用 `/context` 测量

最后，核心结论是：修改设置后，必须重启 Claude Code，再检查一次结果。

重启是为了让新的设置真正加载。然后再次运行 `/context`，观察工具数量和令牌总数是否下降。

下降的部分，就是你之前每一轮都发送、现在已经不再发送的内容。

这意味着请求会更便宜，模型也不必先阅读大量无关工具和指令，再去处理你真正的问题。

##### 最后回顾

最后，记住四个重点。

第一，Claude Code 每次请求都可能携带大量隐藏内容，包括工具定义、技能目录和系统指令，这些内容会占用令牌并产生费用。

第二，先用 `/context` 看整体大小，再用代理记录完整请求，才能知道具体是哪些工具最占空间。

第三，关闭整组功能时，可以使用 `disableBundledSkills` 和 `disableWorkflows`；清理单个工具时，要使用不带范围的 `deny` 工具名。

第四，不要为了缩小请求而关闭自己确实需要的功能。修改设置后重启 Claude Code，再运行 `/context`，用前后数字确认清理是否真的有效。

## 深度解读（1）

### 2026-09-18 00:36:05

#### AI Agent 的隐藏成本：每项“可用能力”都可能按轮收费

文章最值得保留的，不是某份 Claude Code 精简配置，而是它揭示了一个容易被忽视的机制：**在 AI Agent 中，未被使用的功能也可能持续消耗资源。**

Claude Code 每次请求携带的不只有用户消息，还包括系统指令、工具定义、技能目录、MCP 工具和历史记录。文章展示的一次请求包含 69 个工具、约 15 万字节工具描述，完整输入达到 6.5 万 token；其中仅 Workflow 的定义就约占 5300 token。传统软件里，一个入口只要没人点击，运行成本通常很低；但 Agent 为了让模型知道“自己能做什么”，往往需要反复附上能力说明。于是，**产品功能从一次性的界面复杂度，变成了每轮推理都要支付的“能力税”**。

##### 真正有效的方法是先建立可观测性

作者没有直接给出一份“最佳配置”，而是先用 `/context` 查看系统提示、工具、记忆和消息分别占多少上下文，再通过本地 HTTP 代理记录完整请求，并按工具 schema 大小排序。这样，优化对象从模糊的“上下文太长”，变成了具体问题：哪个工具最重、是否真的使用、删除后节省多少。

随后才是两层裁剪：

- 用 `disableBundledSkills`、`disableWorkflows` 等开关整体关闭一组能力；
- 用 `permissions.deny` 或 `skillOverrides` 删除单个工具或技能。

一个关键细节是：裸工具名如 `NotebookEdit` 会让定义不再进入请求；而 `Bash(rm *)` 这类带范围的规则只是阻止调用，schema 仍然存在，因此并不能缩短上下文。最后重启并再次运行 `/context`，形成“测量—裁剪—复测”的闭环。

##### 这也是 Agent 产品设计的一条重要原则

这套方法可以迁移为更普遍的设计判断：**Agent 不应默认向模型暴露全部能力，而应按任务、项目或阶段动态装载。** 手工维护静态配置只是临时方案，更合理的产品形态应是能力包、按需发现和延迟加载：写 Notebook 时再提供编辑工具，进入多 Agent 流程时再注入 Workflow，而不是让所有会话永久背负完整目录。

这可能同时改善成本、上下文容量和工具选择准确率。但文章只直接证明了 token 减少，并没有证明回答质量必然提升；实际费用还受提示缓存与计费规则影响。删掉后台任务、多 Agent 或工作树依赖的工具，也会直接损害能力。

还有一个被文章轻描淡写的风险：代理会把完整系统提示、消息历史和代码写入本地 Markdown，可能包含密钥与商业代码。使用时至少要限制日志权限并及时清理。

因此，最稳妥的实践不是复制作者的禁用清单，而是把每项能力当作有持续成本的依赖：**只有测量出它占了什么、确认它没有创造相应价值，才值得移除。**
