##### 3️⃣ 下载数据库文件（新用户必做）

本项目不会自动建表， **没有数据库文件无法启动** 。为避免把开发者本机的配置和登录态一起发布，仓库中不包含数据库文件，请从 release 页面下载空数据库：

1. 到 [最新 release](https://github.com/loks666/get_jobs/releases/latest) 下载 `getjobs.db.template`
2. **把它重命名为 `getjobs.db`**
3. 放到项目根目录的 `db/` 文件夹下，最终路径为 `db/getjobs.db`

这个空库已经带好了 16 张表的结构和各平台下拉框的字典数据（城市、行业、经验、学历等共 673 条），配置、Cookie、投递记录都是空的，由你自己在网页端填写。

> ⚠️ 老用户升级时不要覆盖自己已有的 `db/getjobs.db` ，否则配置和登录态会全部丢失。

##### 4️⃣ 网页端修改配置，并保存(一般默认即可,需要修改自己的地区和岗位)

- 🤖 AI配置
  - `.env` 配制如下：
    ```
    HOOK_URL=https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=your_key_here
    BASE_URL=https://api.openai.com
    API_KEY=sk-xxx
    MODEL=gpt-5-nano
    ```
  - `HOOK_URL` ：企业微信机器人推送的链接
  - `BASE_URL` ：直连或中转链接地址
  - `API_KEY` ：调用的API KEY
  - `MODEL` ：需要使用的模型名称
  > 根据测试，boss直聘在每天所有的岗位投递结束后消耗的额度(gpt-5-nano)大约在0.06美元(6美分)左右，日常使用成本很低  
  > 💥 `BASE_URL` 填任意兼容 OpenAI 接口格式的地址即可（官方接口或你自己的中转服务都可以），本项目不绑定、不推荐任何第三方代理商

#### get_jobs：用 AI 辅助筛选岗位、自动投递简历的本地工具

这篇 GitHub 项目说明介绍了 `get_jobs`：一个带网页管理界面的求职自动化工具，面向 Boss 直聘、猎聘、前程无忧和智联招聘，帮助用户筛选岗位、批量投递并接收通知。**最重要的边界是：作者目前只明确确认 Boss 可以投递，其他平台尚未测试；项目需要在本地配置运行，并非开箱即用的在线服务，而且仅允许免费、非商业使用。**

##### 1. 它自动化的是求职操作，AI 主要负责岗位匹配和打招呼

项目的核心流程是：用户配置求职条件并登录招聘平台，程序操作浏览器查找岗位、执行筛选、发送消息或投递简历，再记录结果和发送通知。

主要功能包括：

| 功能 | 具体作用与边界 |
|---|---|
| 网页管理界面 | 在网页上配置求职条件、管理和运行任务，减少直接修改代码的需求。 |
| AI 岗位匹配 | 判断岗位与求职者的匹配程度，并根据 JD——也就是岗位描述和要求——生成个性化打招呼语。**目前仅限 Boss 直聘。** |
| 图片简历发送 | 在 Boss 上发送打招呼语后，自动发送图片版简历，不必等待 HR 索要。作者称这有助于提高回复率，但未提供效果数据。 |
| 条件过滤 | 按 HR 活跃度、是否为猎头岗位、目标薪资等条件过滤岗位。 |
| 企业黑名单 | 投递结束后更新黑名单；例如，回复过“不合适”等消息的 HR 所属公司会被加入，之后不再投递该公司。 |
| 实时通知 | 通过企业微信机器人推送投递情况。 |
| 登录状态保存 | 保存 Cookie，即网站用于识别登录状态的信息。作者称大部分平台通常每周扫码一次即可。 |

**它减少的是重复操作，不等于保证找到合适工作。** 岗位匹配、批量投递和个性化消息是工具能力；能否获得回复、面试或录用，原文没有提供验证数据。

##### 2. “支持四个平台”不等于四个平台目前都可靠可用

项目标题覆盖四家招聘平台，但说明顶部的最新提示更谨慎：**Boss 已可投递，其他平台暂未测试；作者仍建议以手动在 Boss 投递为主，把本项目作为 PC 端的补充手段。**

正文还保留了各平台的操作说明：

| 平台 | 原文中的条件与限制 |
|---|---|
| **Boss 直聘** | 支持 AI 打招呼语和图片简历。必须设置 `sayHi` 打招呼文本，否则可能投递失败。文档称每日打招呼上限为 150 次。 |
| **猎聘** | 需要绑定微信并扫码登录，在最新版猎聘 App 中设置打招呼文本。作者称默认打招呼与主动发消息的限制不同，前者可大量使用，但成功率不高。 |

##### 3. 使用门槛主要在本地环境、数据库和账号配置

虽然项目提供了图形界面，但首次使用仍需要完成一套本地部署流程。

###### 第一步：获取代码并准备运行环境

从 GitHub 或 Gitee 镜像下载代码，准备：

- **JDK 21**：运行 Java 程序所需的环境。
- **Gradle**：负责构建项目、管理依赖的工具。

程序会根据系统环境下载对应的 ChromeDriver，也就是让代码能够操作浏览器的组件。因此，首次启动还取决于相关文件能否正常下载。

###### 第二步：下载数据库，这是新用户的必做项

**项目不会自动创建数据库表，没有数据库文件就无法启动。**

新用户需要从 Release 下载 `getjobs.db.template`，重命名为 `getjobs.db`，放到项目根目录的 `db/` 文件夹中，最终路径为：

```text
db/getjobs.db
```

这个模板已经包含 **16 张表**，以及城市、行业、经验、学历等 **673 条选项数据**；用户配置、Cookie 和投递记录则是空的。

仓库不直接附带开发者的数据库，是为了避免把开发者自己的配置和登录状态一起发布。

**老用户升级时不要覆盖已有数据库，否则会丢失原来的配置和登录状态。**

###### 第三步：配置求职条件和 AI 服务

在网页端设置并保存地区、目标岗位等条件；AI 与通知相关参数放在 `.env` 配置文件中：

- `HOOK_URL`：企业微信机器人的消息推送地址。
- `BASE_URL`：AI 服务的接口地址。
- `API_KEY`：调用 AI 服务所需的密钥。
- `MODEL`：使用的模型名称，文档示例为 `gpt-5-nano`。

项目支持兼容 OpenAI 接口格式的服务，既可以使用官方接口，也可以使用自己的中转服务；作者明确表示不绑定、不推荐特定第三方代理商。

作者的测试显示，使用 `gpt-5-nano` 完成一天的 Boss 岗位投递，AI 调用费用约为 **0.06 美元，即 6 美分**。这是特定测试条件下的参考值，不是固定日费，实际费用会随模型和调用量变化。

###### 第四步：配置图片简历并启动

如果要在 Boss 自动发送图片简历，需要把自己的 PDF 简历转换成 `resume.jpg`，放入 `resources` 文件夹，并开启 `sendImgResume` 配置项。

随后运行启动类 `GetJobsApplication.java`。

不想单独启动前端的用户，可以下载 Release 中已编译的前端文件，把 `dist` 文件夹放进 `resources`，再启动后端使用网页界面。

## 深度解读-口播（1）

### 2026-09-30 11:37:21

这款名叫 Get Jobs 的求职助手，想解决的是一个很具体的问题：找工作时，筛岗位、反复打招呼、投简历，往往要花掉大量时间。但理解这个项目，最重要的是分清两件事：它能代替你执行哪些重复操作，以及这些自动化功能目前有哪些限制。

先说最关键的使用现状。项目标题列出了 Boss 直聘、前程无忧、猎聘和智联招聘，但作者在最新说明中明确表示，目前 Boss 直聘已经可以投递，其他平台暂时没有测试。作者仍然建议，主要在 Boss 直聘上手动投递，把这个项目作为电脑端的补充工具。

所以，不能因为标题写着“全平台”，就认为所有平台都已经稳定可用。页面后面保留了其他平台的操作说明，但这些说明不能替代最新的测试状态。这是判断这个工具是否适合自己时，首先要记住的前提。

在这个前提下，它最有价值的功能，是把岗位筛选和联系招聘方串起来。

普通的自动投递脚本，主要是替人点击按钮。这个项目还加入了人工智能：判断岗位与求职者的匹配程度，再根据岗位描述，生成更有针对性的打招呼语。不过，这项人工智能功能目前仅用于 Boss 直聘。

举个使用情境。你先设置目标地区、岗位和薪资条件，程序再按配置筛选岗位。它还提供过滤不活跃招聘人员、猎头岗位等功能，尽量减少不符合目标的投递。遇到合适的岗位后，人工智能可以根据岗位要求生成开场消息，而不是对所有招聘方发送同一段话。

这里要区分能力和效果。项目提供的是匹配判断与消息生成，并没有给出证据，证明使用后一定能获得更多面试，或者找到工作。

另一个具体功能，是自动发送图片简历。在 Boss 直聘上，程序可以先发送打招呼语，再发送提前准备好的简历图片，不必等招聘人员主动索要。要使用这项功能，需要先把自己的简历转换成指定的图片文件，并开启对应配置。作者认为，这样有助于提高回复率，但材料没有提供具体的效果数据。

项目还会在投递结束后更新企业黑名单。例如，招聘人员发送过“不合适”之类的消息，对应公司就可能被加入黑名单，避免继续重复投递。投递情况也可以通过企业微信机器人推送给你。

把这些功能放在一起看，它的重点不是单纯增加投递数量，而是让筛选、打招呼、发送简历和记录结果，尽量形成一套连续的流程。

不过，要让这套流程跑起来，仍然需要一定的配置能力。

项目已经有网页管理界面，用户可以在网页中修改条件、保存配置和运行任务。图形界面降低了操作门槛，但并不等于下载后就能直接使用。

按照材料中的部署方式，你需要在本地电脑准备好运行环境，包括 Java 二十一和 Gradle。Gradle 是构建和运行这类程序的工具。程序会识别电脑的系统环境，下载对应的浏览器驱动，再通过浏览器执行操作。因此，下载驱动时的网络是否正常，也会影响启动。

新用户还有一个容易漏掉的步骤：下载数据库模板。

这个项目不会自动创建数据库表，代码仓库里也没有附带可直接使用的数据库文件。原因是，作者不希望把自己电脑上的配置和登录状态一起发布出去。新用户必须从项目发布页面下载空数据库，按说明重命名，再放到项目指定的数据库文件夹中，否则程序无法启动。

这个空数据库已经包含所需的表结构，以及城市、行业、经验、学历等选项，但个人配置、登录状态和投递记录都是空的，需要自己填写。

如果你是老用户，升级时不要用空模板覆盖已有数据库。否则，原来的配置和登录状态会丢失。简单说，新用户需要补齐数据库，老用户需要保住自己的数据库。

人工智能功能还需要单独配置模型接口，包括接口地址、调用密钥和模型名称。项目支持兼容 OpenAI 接口格式的服务，不绑定某一家第三方服务商。

真正使用时，还要留意几个边界。

第一，这是本地电脑上的辅助工具，不支持服务器部署。作者给出的原因是，招聘网站如果识别到访问来自服务器地址，可能不会返回网站数据。作者还提醒，访问这些国内招聘平台时，应关闭境外代理，以免页面加载缓慢。

第三，免费使用不等于可以任意商用。项目采用的是非商业许可，允许免费的非商业使用，禁止未经授权的商业使用。如果要获得商业授权，需要联系作者。作者同时提醒，已经有人借这个项目推广收费产品，甚至冒充相关服务，使用者需要警惕。

最后，最值得记住的是：这个项目的价值，在于减少求职过程中重复筛选、联系和记录的劳动，而不是保证求职结果。当前应以 Boss 直聘的可用状态为主要参考，把它看作手动投递的补充。决定尝试之前，先确认自己能完成本地配置，也能接受平台限制、兼容性问题和非商业许可的边界。
