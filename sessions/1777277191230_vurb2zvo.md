**Lance Martin**

### Claude 托管代理中的内存

Claude Managed Agents（可在 Claude 平台使用）现在具备了记忆功能。记忆以文件形式存储，并可在不同会话中访问，从而使代理能够从经验中学习。记忆也可通过 API 导出。

---

[@DavidSHershey](https://x.com/DavidSHershey) 和我分享了一个关于代理内存的故事：在他研究 Claude Plays Pokémon 的工作中，他给 Claude 一个工具来读取和写入内存文件到一个文件夹。这些内存文件旨在帮助 Claude 在游戏中导航。

这对早期模型来说效果不太好。Sonnet 3.5 将记忆视为转录文本，记录非玩家角色的对话内容，而非真正重要的信息。经过 14,000 步后，它生成了 31 个记忆文件，但进展甚微（它卡在了第二个城镇）。以下是其中一个文件的示例：

```json
caterpie_weedle_info:
- Caterpie and Weedle are both caterpillar Pokémon.
- Caterpie is a caterpillar Pokémon that does not have poison.
- Weedle is a caterpillar Pokémon that does have poison.
- This information is crucial for future encounters and battles.
- If our Pokémon get poisoned, we should seek healing at a Pokémon
 Center as soon as possible.
```

为了克服这些局限性，许多论文提出了使用工具来管理内存的框架。

[@tedsumers](https://x.com/@tedsumers)

[CoALA paper](https://arxiv.org/pdf/2309.02427)

和

[memGPT work](https://arxiv.org/pdf/2310.08560)

来自

[@sarahwooders](https://x.com/@sarahwooders)

和

[@charlespacker](https://x.com/@charlespacker)

是我最喜欢的两个。这些方法借鉴了认知科学和操作系统的思想来建模智能体的记忆。

但这个宝可梦项目的成果显示了一个有趣的结果：后来的模型学会了使用文件系统更好地组织内存。Opus 4.6 在相同的步数下，有 10 个文件被组织到目录中，三个道馆徽章，以及一个从自身失败中提炼出来的经验文件：

```json
/gameplay/learnings.md:
- Bellsprout Sleep+Wrap combo: KO FAST with BITE before Sleep
 Powder lands. Don't let it set up!
- Gen 1 Bag Limit: 20 items max. Toss unneeded TMs before dungeons.
- Spin tile mazes: Different entry y-positions lead to DIFFERENT
 destinations. Try ALL entries and chain through multiple pockets.
- B1F y=16 wall CONFIRMED SOLID at ALL x=9-28 (step 14557)
```

这个例子突出了一个趋势，我在

[此处](https://claude.com/blog/harnessing-claudes-intelligence)： 为 Claude 提供通用工具来管理其自身的上下文和操作 。Claude 可以学习使用通用工具来解决问题，比如记忆，通过扩展智能。

借助一个通用的文件管理工具，我们看到 Claude 学会了该保存什么以及如何整理自己的记忆。

[@Letta\_AI](https://x.com/@Letta_AI)

[独立地展示了](https://www.letta.com/blog/benchmarking-ai-agent-memory)

文件系统能够超越专门的记忆工具。

这个故事解释了为什么我们在

[Claude 托管代理](https://platform.claude.com/docs/en/managed-agents/overview)（可在 Claude 平台上使用）。文件可以由 Claude 按照其意愿进行组织，

[使用](https://platform.claude.com/docs/en/managed-agents/memory#how-the-agent-accesses-memory)

其标准的

[文件工具](https://platform.claude.com/docs/en/managed-agents/tools#available-tools)

。该平台仅通过内存存储在会话之间持久化文件，内存存储是工作区范围的文本文档集合，其生命周期超出单个会话。

![Image](https://pbs.twimg.com/media/HGrvh1dbYAIL7G5?format=png&name=large)

当你将内存存储附加到会话时，它会作为目录挂载到容器中，路径为/mnt/memory/&lt;store-name&gt;/。关于挂载的简短说明会自动注入系统提示中，以便 Claude 知道它的存在。

多个代理可以访问同一个内存存储，平台将实时同步内存：如果一个代理进行编辑，该编辑将反映在所有挂载了该内存存储的其他代理的文件系统中。它还将处理并发，以确保一个代理不会覆盖另一个代理所做的内存更新。

文件还有一个额外优势——它们是可解读的且可共享的。在宝可梦的例子中，

[@DavidSHershey](https://x.com/DavidSHershey) 能够直接下载并共享记忆文件夹。借助托管代理，你也可以导出记忆：

```python
client.beta.memory_stores.memories.list(store_id, view="full")
```

这为理解 Managed Agents 中的上下文提供了一种简单方式：存在会话日志和内存存储。

[@mc\_anthropic](https://x.com/@mc_anthropic)，

[@gcemaj](https://x.com/@gcemaj)

，以及我在此处写到，

[here](https://www.anthropic.com/engineering/managed-agents)

，Claude 可以在任务过程中获取和转换会话上下文。会话存在于上下文窗口之外，这一特性的优势，

[@a1zhang](https://x.com/@a1zhang)

和

[@lateinteraction](https://x.com/@lateinteraction)

在此处已有很好的阐述。

[here](https://arxiv.org/abs/2512.24601)

。Claude 可以向内存存储写入文件，如果它希望在会话间持久化上下文的话。

要开始使用，请参阅我们的文档或使用我们的 claude-api 技能。此技能内置在 Claude Code 中，可通过运行“/claude-api”来触发。然后您可以询问有关 Claude 托管代理或其他 API 功能的问题。

## 通俗精炼（1）

### 2026-04-27 08:06:31

#### Claude 托管代理中的 “记忆”：让 Agent 学会自我积累经验

##### 核心观点

Claude Managed Agents 现在支持**跨会话记忆**：记忆以文件形式存储，可在不同会话中持续访问，也可通过 API 导出。  
这意味着 Agent 不再只是依赖单次对话上下文，而是可以像人一样把经验沉淀下来，用于后续任务。

---

##### 记忆机制：用 “文件系统” 而不是黑盒记忆

Claude 的记忆被设计成一组可持久化的文本文档，挂载在工作区目录中：

```bash
/mnt/memory/<store-name>/
```

Claude 可以像操作普通文件一样读写、组织这些记忆。平台负责让这些文件跨会话保存，并在多个 Agent 之间实时同步。

这种设计的关键是：**记忆不是隐藏在模型内部，而是外显为文件**，因此更容易理解、调试、共享和导出。

---

##### 宝可梦案例：模型越强，越会 “管理记忆”

早期模型 Sonnet 3.5 在玩 Pokémon 时，虽然也能写记忆文件，但更多是在记录无关对话或事实。例如它会记下 Caterpie 和 Weedle 的区别，却无法提炼真正影响游戏推进的策略。

结果是：跑了 14,000 步，生成了 31 个文件，但仍卡在第二个城镇。

而更强的 Opus 4.6 则表现出明显进步：它会把记忆组织到目录中，并总结真正有用的经验，例如：

- 遇到 Bellsprout 要快速击败，避免被 Sleep + Wrap 控制
- 一代宝可梦背包上限是 20 个物品
- 旋转地砖迷宫需要尝试不同入口
- 某些墙体已确认不可通行

这说明更强的模型不仅会 “存储信息”，还会学习**什么值得记、如何组织、何时复用**。

---

##### 产品意义：通用工具可能优于专用记忆模块

文章强调一个趋势：与其为 Agent 设计复杂的专用记忆系统，不如给它通用工具，让它自己管理上下文和记忆。

文件系统就是一个典型例子：

- 简单通用
- 可读可改
- 支持目录结构
- 可共享、可导出
- 容易被人类审计

这与一些研究方向一致，例如 CoALA、memGPT 等，它们都在探索如何借鉴认知科学和操作系统机制，构建智能体长期记忆。

---

##### 协作能力：多个 Agent 可共享同一记忆库

Claude Managed Agents 支持多个 Agent 挂载同一个 memory store。  
如果一个 Agent 修改了记忆，其他 Agent 可以实时看到更新。

平台还会处理并发冲突，避免一个 Agent 覆盖另一个 Agent 的修改。

这为多 Agent 协作提供了基础：不同 Agent 可以围绕同一个长期知识库持续工作，而不是每次从零开始。

---

##### 可观测性：记忆可以导出和分析

文件形式的记忆还有一个重要优势：**可解释、可导出、可复盘**。

开发者可以通过 API 拉取完整记忆内容：

```python
client.beta.memory_stores.memories.list (store_id, view="full")
```

这让团队能够分析 Agent 到底学到了什么、记住了什么、是否记错了、是否需要人工干预。

---

##### 本质变化：从 “会话智能” 走向 “持续智能”

过去的 Agent 很大程度上依赖单次上下文窗口，容易出现：

- 任务中断后丢失状态
- 需要重复输入背景信息
- 无法长期积累经验
- 难以形成稳定偏好和策略

有了持久记忆后，Agent 可以把会话日志中的重要内容转化为长期文件，逐步形成自己的工作记录、经验库和任务上下文。

这使 Agent 从 “高级脚本” 更接近真正的自主系统。

---

##### 一句话总结

Claude Managed Agents 的记忆功能，本质上是把长期上下文做成可读写、可共享、可导出的文件系统，让 Agent 能够跨会话积累经验，并逐步学会管理自己的知识与行为。
