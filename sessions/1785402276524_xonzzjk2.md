## 分析要点

- **核心高价值点**：小团队与其正面竞争通用Agent，不如寻找传统软件尚未适配Agent的窗口，以插件为入口连接服务，并用行业数据、权限和验收流程形成差异化。
- **留存建议**：选择性浏览并存档其产品竞争与插件机会判断（包含通用Agent入口集中、插件服务机会及垂直产品差异化条件等可复用的产品战略判断。）

**知识要点**

- 通用Agent的竞争壁垒可能更多来自模型能力、推理成本和插件生态，而非短期交互体验。
- 单纯Skill门槛较低，插件若能进一步连接稳定服务、数据或业务流程，才更可能形成商业价值。
- 垂直Agent若仅封装通用模型容易被替代，但行业数据、权限控制、结果验收和责任链可能构成防御条件。

**行动项**

- 用相同任务对比主流通用Agent的模型效果、成本和插件覆盖范围，验证集中化判断。
- 梳理传统软件中尚未针对Agent开放的操作流程，筛选可由插件连接服务的机会。
- 评估垂直Agent项目是否掌握独有数据、权限、验收标准或审批责任链，避免只做模型套壳。

## 结构化（2）

### 2026-07-30 09:03:53

#### 文章总结

作者认为，未来不仅是**通用 Agent 替代大量垂直 Agent**，通用 Agent 市场本身也会高度集中，由少数头部产品占据。真正决定竞争力的，是**模型能力、使用成本和插件生态**；个人及小团队更适合围绕 Agent 开发插件与配套服务。

##### 1. 通用 Agent 市场将“少数赢家通吃”

- Codex、Claude Cowork、Workbuddy 等通用 Agent，会借助 **Skill（技能插件）和 MCP（连接外部工具、数据与服务的协议）**，完成越来越多专业任务。
- 仅针对单一场景、缺乏独特数据或业务壁垒的垂直 Agent，例如部分 Genspark、Skywork 类产品，可能逐渐被通用 Agent 覆盖。
- 市场不只是“通用产品吃掉垂直产品”，通用 Agent 之间也会激烈竞争，最终可能只剩少数头部入口，规模较小的通用 Agent 同样缺乏生存空间。

##### 2. 插件生态比“开源”或“自由换模型”更重要

- 作者认为，Agent 是否真正开放，关键不在于：
  - 是否开源；
  - 是否可以随意切换模型。
- 更重要的是能否形成丰富的**插件生态**，让 Agent 调用不同工具、数据和服务，真正完成复杂任务。
- 例如 Claude Code 和 Codex 默认使用自家模型，但因为支持 API，并拥有较丰富的 Skill、MCP 等扩展能力，并未明显影响其受欢迎程度。
- 当前 Agent 快速普及的重要原因之一，正是插件让它从“聊天工具”变成了能够实际执行任务的工具。

##### 3. 早期 Agent 的主要作用是教育用户

- Agent 产品的用户忠诚度并不高，用户往往会转向能力更强、价格更合适的产品。
- 早期产品即使后来热度下降，也有普及市场的价值。例如“小龙虾”如今较少被提起，但曾帮助大量用户认识和使用 Agent。
- Workbuddy 的价值也在于降低使用门槛，让不了解或无法使用 Codex、Claude Code 的用户接触 Agent。
- 市场迁移速度很快：Claude Code 曾经非常火爆，而 Codex 推出 GUI 图形界面版本后，也迅速吸引了大量用户。
- 因此，所谓“下沉”或“傲慢”较为主观；只要模型足够强，即使公司形象或产品策略不讨喜，用户仍可能选择它。

##### 4. 模型能力与成本才是长期护城河

- Agent 的界面和操作体验容易互相模仿，长期来看会逐渐趋同，因此难以形成深厚壁垒。
- 用户体验最大的差异，最终来自**模型是否足够聪明**。一旦用户体验过能力更强的模型，通常不愿再退回较弱的模型。
- 一些用户接受当前较弱的产品，可能只是因为尚未接触到更好的选择。
- Cursor 的 Agent 体验很好，也支持多种模型，但市场热度仍更多集中在 Codex 和 Claude Code，原因之一是二者提供订阅服务，综合性价比较高。
- 因而，决定 Agent 产品长期竞争力的核心仍是：
  1. 模型智能水平；
  2. 推理与使用成本；
  3. 订阅价格和整体性价比。

##### 5. 小团队更适合做插件和服务，而非直接做 Agent

- 作者判断，个人和小团队继续开发通用 Agent，甚至普通垂直 Agent，机会已经不大。
- 更现实的方向是围绕头部 Agent 开发插件、连接器及后端服务。
- 许多传统软件并非为 Agent 调用而设计，因此仍存在一个改造和接入的时间窗口。
- 单纯制作 Skill 已经门槛较低、供给泛滥，很难构成壁垒。更可行的方式是：
  - 先用 Skill 作为入口；
  - 再连接专有数据、行业流程或后端服务；
  - 通过真实服务能力形成差异化。

##### 6. 对普通用户的建议

- Agent 不一定直接替代人，但可以替代大量在电脑上重复进行的工作。
- 普通用户越早开始使用、使用得越多，越能提前获得效率提升。
- 在经济能力允许的范围内，为更聪明的模型付费通常是值得的，因为它可以节省时间并改善任务完成质量；但没有必要超出自身承受能力消费。

##### 7. 热门回复中的补充与争议

部分回复对“垂直 Agent 没有机会”这一判断持保留态度：

- **品牌黏性问题**：普通用户可能因为使用习惯形成品牌黏性，企业客户更换工具的成本和阻力则可能更大。
- **业务型 Agent 的特殊性**：健康等专业领域不仅依赖通用能力，还需要行业知识、业务流程和责任体系。例如，有回复认为蚂蚁阿福这类健康 Agent，未必会轻易被豆包等通用产品取代。
- **垂直产品仍可能有壁垒**：如果只是给通用模型“套壳”，很容易被替代；但若掌握以下资源，仍可能长期存在：
  - 独有行业数据；
  - 权限与审批流程；
  - 可复现的结果验收机制；
  - 任务失败后的补救方案；
  - 明确的责任链。
- 有回复进一步总结：如果没有数据优势，Agent 产品随时可能被替换。

> 总体而言，作者看好少数头部通用 Agent 成为主要入口，但垂直领域并非绝对没有机会。真正能够留下来的垂直产品，需要掌握通用 Agent 难以复制的数据、服务、验收标准和行业流程。
