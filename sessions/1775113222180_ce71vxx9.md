## 追问（1）

### 提问 · 2026-04-02 06:59:57

如何在项目中使用 ？

### 回答 · 2026-04-02 06:59:57

你可以把这个项目当成 “把 Compound Engineering 工作流装到不同 AI 编码工具里” 的插件 / 转换器来用，最常见有两种方式：

- 直接安装`compound-engineering`插件到某个工具里，比如 Claude Code、Codex、OpenCode
- 把你自己的`~/.claude/`技能、命令、MCP 配置同步到其他工具

**怎么用**

- 如果你用 Claude Code：
  - 添加市场插件：
    ```bash
    /plugin marketplace add EveryInc/compound-engineering-plugin
    /plugin install compound-engineering
    ```
- 如果你用 Cursor：
  - 安装：
    ```bash
    /add-plugin compound-engineering
    ```

- 如果你想装到 Codex：
  - 用 CLI 转换并安装：
    ```bash
    bunx @every-env/compound-plugin install compound-engineering --to codex
    ```
  - 安装后内容会进入`~/.codex/prompts`和`~/.codex/skills`

- 如果你想装到 OpenCode：
  - 执行：
    ```bash
    bunx @every-env/compound-plugin install compound-engineering --to opencode
    ```

- 如果你不确定自己在用哪个工具，也可以自动安装到所有已检测到的目标：
  ```bash
  bunx @every-env/compound-plugin install compound-engineering --to all
  ```

**装完之后怎么在项目里使用**

这个插件的核心不是 “页面组件库”，而是一套工程流程命令。典型使用方式是：

- `/ce:brainstorm`：先梳理需求、方案和边界
- `/ce:plan`：把想法变成可执行的技术计划
- `/ce:work`：按计划执行开发任务
- `/ce:review`：提交前做多代理代码审查
- `/ce:compound`：把本次经验沉淀下来，方便以后复用
- `/ce:ideate`：从代码库里主动挖掘高价值改进点

它推崇的流程是：

```text
Brainstorm -> Plan -> Work -> Review -> Compound -> Repeat
```

也就是：
- 先想清楚
- 再写计划
- 再实施
- 再审查
- 最后沉淀经验

**在你自己的项目里，推荐这样接入**

- 第一步：先安装到你正在使用的 AI 工具
- 第二步：进入你的项目目录
- 第三步：先从`/ce:brainstorm`或`/ce:plan`开始，而不是直接让 AI 写代码
- 第四步：开发完成后跑`/ce:review`
- 第五步：把可复用经验记录到`/ce:compound`

**如果你本地开发这个仓库本身**

仓库也支持 “本地检出直接测试”，适合你修改插件源码后立刻验证：

- Claude Code 本地加载：
  ```bash
  alias cce='claude --plugin-dir ~/code/compound-engineering-plugin/plugins/compound-engineering'
  ```
  然后运行：
  ```bash
  cce
  ```

- 安装本地版本到 Codex：
  ```bash
  bun run src/index.ts install ./plugins/compound-engineering --to codex
  ```

- 安装本地版本到 OpenCode：
  ```bash
  bun run src/index.ts install ./plugins/compound-engineering --to opencode
  ```

**如果你想同步自己的 Claude 配置到其他工具**

比如你已经在`~/.claude/skills/`、`~/.claude/commands/`、`~/.claude/settings.json`里积累了自己的能力，可以这样同步：

- 同步到所有已检测工具：
  ```bash
  bunx @every-env/compound-plugin sync
  ```
- 同步到 Codex：
  ```bash
  bunx @every-env/compound-plugin sync --target codex
  ```
- 同步到 OpenCode：
  ```bash
  bunx @every-env/compound-plugin sync --target opencode
  ```

**如果你是想 “在某个具体项目开发中怎么实际落地”**

可以直接这样用：

1. 先说 “我要做 XX 功能”，运行`/ce:brainstorm`
2. 让它帮你梳理需求、风险、边界条件
3. 再运行`/ce:plan`产出实施计划
4. 按计划开发，必要时用`/ce:work`
5. 完成后运行`/ce:review`
6. 最后用`/ce:compound`记录经验，减少下次重复踩坑
