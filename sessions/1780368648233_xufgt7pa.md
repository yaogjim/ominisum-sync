#### How It Works

Three Specialized Models

Most memory systems use a single LLM for:

- retrieval
- generation
- memory management

Quarq separates these concerns into specialized roles.

Retrieval Planner (gpt-4o-mini)

Before every search, the planner generates a structured retrieval strategy optimized for memory recall.

Instead of relying on a single embedding query, it expands the search into multiple semantically related formulations, extracts important keywords, and selects an appropriate retrieval mode based on the complexity of the question.

这使用了 HyDE（假设文档嵌入） 查询扩展以提高召回率，超越简单的向量相似度搜索。

Generator (gpt-4.1)

The generator receives:

- retrieved memories
- procedural rules
- conversation history

It focuses only on response generation.

Learning Model (gpt-4.1)

The learner does not dump raw text into storage.

Instead, it performs targeted edits:

- adding new facts
- updating outdated facts
- deleting contradictions

It also receives cross-type context to reduce duplication and maintain consistency across memory layers.

#### Hybrid Retrieval

Each retrieval pass combines:

- vector similarity search
- keyword search
- metadata filtering
- temporal validation

Two retrieval modes are used:

![Image](https://pbs.twimg.com/media/HJwmbZCa4AAq6pU?format=png&name=large)

#### Temporal Truth Protocol

One of the hardest problems in long-term memory systems is temporal reasoning.

Quarq separates four independent time concepts:

1. 存储日期： 内存保存时
2. 事件日期： 事件实际发生的时间
3. 叙述日期： 模拟基准测试时间线
4. 相对日期： 在检索过程中动态解析

The rules are hard-coded:

- never use bracketed timestamps as event dates
- never infer dates from neighboring memories
- never assume unrelated memories refer to the same entity
- always resolve “how long ago” relative to the actual event

#### Self-Correcting Two-Pass Retrieval

If the initial retrieval pass does not provide enough evidence to answer confidently, the generator can explicitly request additional retrieval using targeted fallback queries.

The runtime then:

1. Runs secondary searches using a broader deep retrieval threshold (0.28)
2. Merges the newly retrieved memories with the original context
3. Regenerates the response under stricter anti-hallucination constraints

This creates a self-correcting two-pass retrieval system where the model can request better evidence instead of fabricating missing context.

#### Quantitative Fidelity

Long-memory benchmarks punish sloppy numerical reasoning.

For totals, durations, prices, quantities, and counts, Quarq explicitly identifies:

- actor or entity
- measured action
- target event or object
- required exactness

The system excludes merely nearby or topically related numbers and only aggregates values that satisfy exact-match constraints.

#### Background Learning

Learning runs asynchronously after every response to minimize user-facing latency.

Safeguards include:

- semaphore limit of 4 concurrent learning tasks
- persistent retry with exponential backoff
- synchronization barriers during benchmark evaluation

### What the Benchmark Actually Tests

1. 检索记忆： 系统能否从特定的过去交互中调取信息
2. generate\_response: 能否使用检索到的记忆正确回答？
3. single-session-assistant: 它能记住用户随意提到的偏好吗？
4. 知识更新 ：它能否正确解决时间顺序和演化状态？
5. 多会话 ：它能否随时间在多个对话中进行推理？

### Architecture Evolution

The earliest version of Quarq used raw flat .txt files loaded into context on every request.

It worked poorly, but exposed an important constraint:

> A single LLM cannot simultaneously optimize for retrieval quality, generation quality, and cost efficiency.

The architecture evolved through several iterations:

![Image](https://pbs.twimg.com/media/HJwrFpiakAASXry?format=png&name=large)

Each major component emerged from a specific failure mode:

- HyDE 查询扩展来自于观察到单向量检索会遗漏相关记忆
- Temporal Truth 协议来自于时间幻觉，比如回答“三周前”而不是“昨天”
- 双轮回退检索源于模型自信地编造答案而非承认上下文不足

---

###### ① 不让一个模型干所有活

很多 Agent 让一个大模型同时负责：

- 找记忆
- 写回答
- 更新记忆

这容易乱。

Quarq 把任务拆开：

| 模型 | 负责什么 |
|---|---|
| 检索模型 | 想办法找到相关记忆 |
| 生成模型 | 根据证据回答 |
| 学习模型 | 更新、删除、修正记忆 |

好处是：**分工更清楚，错误更少。**

---

###### ② 不是只搜一次，而是会“换问法”搜索

用户问：

> 我上次说喜欢什么咖啡？

系统不会只拿这句话去搜。

它会自动扩展成类似：

- 用户的咖啡偏好
- 之前提到的饮品习惯
- 喜欢的咖啡类型

这就是 **HyDE 查询扩展**。

简单说：

> 不是死搜关键词，而是先猜可能的答案长什么样，再去找。

---

###### ③ 特别重视“时间”

长记忆系统很容易犯这种错：

> 把“记录时间”当成“事件发生时间”。

比如：

- 12月1日系统存了一条记忆
- 但事情其实发生在11月20日

Quarq 明确区分：

- 存储时间
- 事件时间
- 叙事时间
- 相对时间，比如“昨天”“三周前”

这对长期记忆非常关键。

---

###### ④ 找不到证据时，再搜一轮

如果第一次检索不够，系统可以说：

> 我需要更多证据。

然后触发第二轮更宽泛检索。

这比直接编答案更可靠。

---

###### ⑤ 数字必须严格对齐

对于金额、次数、数量、时长等问题，它不会随便把“附近数字”拿来算。

它会检查：

- 是谁的数字？
- 对应哪个事件？
- 是否属于同一对象？
- 是否能精确累加？

这能减少“看起来对，其实乱算”的问题。

##### 4. 三个专用模型：不让一个 LLM 做所有事

传统记忆系统通常让一个 LLM 同时负责：

- 检索
- 生成回答
- 管理记忆

Quarq 认为这会导致效果、成本和稳定性难以兼顾，因此拆分为三个专用模型。

###### 4.1 检索规划器：负责找什么、怎么找

检索规划器使用 **gpt-4o-mini**。

它在每次搜索前生成结构化检索策略，包括：

- 扩展用户问题的多种表达方式
- 提取重要关键词
- 根据问题复杂度选择检索模式
- 使用 **HyDE 查询扩展** 提高召回率

举例来说，用户问：

> “我上次说我想买的那台电脑是什么？”

系统不会只搜索“电脑”，而会扩展为类似：

- “用户曾提到想购买的电脑”
- “用户讨论过的笔记本型号”
- “购买计划中的设备”

这样更容易找回相关记忆。

###### 4.2 生成器：只负责基于证据回答

生成器使用 **gpt-4.1**。

它接收：

- 检索到的记忆
- 程序性规则
- 当前对话历史

然后专注于生成最终回答，避免同时承担检索和记忆维护任务。

###### 4.3 学习模型：负责更新记忆，而不是简单存全文

学习模型同样使用 **gpt-4.1**。

它不会把原始对话一股脑写入数据库，而是进行有针对性的编辑：

- 添加新事实
- 更新过期事实
- 删除矛盾信息
- 结合不同记忆层的信息，减少重复并保持一致性

---

##### 5. 混合检索：向量、关键词、元数据和时间验证一起用

Quarq 的检索不是单纯依赖向量相似度，而是结合多种方法：

- 向量相似度搜索
- 关键词搜索
- 元数据过滤
- 时间验证

这种混合检索可以降低“语义相近但事实不对”的风险。

例如，用户问：

> “我昨天预约的是哪家餐厅？”

系统不能只找“餐厅”相关记忆，还需要确认事件时间确实是“昨天”，并且对象是预约记录。

---

##### 6. 时间真实性协议：避免长期记忆中的时间幻觉

长期记忆系统最容易出错的地方之一是时间推理。

Quarq 将时间拆成四类：

- **存储日期**：记忆被保存的时间
- **事件日期**：事情实际发生的时间
- **叙述日期**：基准测试或模拟对话中的时间线
- **相对日期**：例如“昨天”“三周前”，需要在检索时动态解析

系统设置了硬规则：

- 不能把括号里的时间戳直接当作事件日期
- 不能根据相邻记忆推断日期
- 不能假设无关记忆指向同一个实体
- 回答“多久以前”时必须基于真实事件时间

这能避免类似错误：

> 用户昨天说了一件事，但系统因为存储时间或上下文混淆，错误回答成“三周前”。

---

##### 7. 自我纠错的双轮检索：证据不足时再找一次

如果第一次检索到的信息不足，Quarq 不会强行编答案。

它允许生成器明确请求第二轮检索。

第二轮流程包括：

1. 使用更宽松的深度检索阈值，例如 **0.28**
2. 合并新旧检索结果
3. 在更严格的防幻觉规则下重新生成回答

这种机制让模型在证据不足时能够“再查一次”，而不是自信地编造。

---

##### 8. 定量保真规则：严控数字、价格、数量和时长

LongMemEval-S 会惩罚不精确的数字推理，因此 Quarq 对数字类问题设置了严格规则。

系统会明确识别：

- 参与者或实体
- 被衡量的行为
- 目标事件或对象
- 是否需要精确匹配

例如，用户问：

> “我一共花了多少钱买书？”

系统不能把“买文具”或“讨论预算”的数字也加进去，只能统计精确符合“买书”这一事件的金额。

---

##### 9. 后台学习：降低延迟，同时保证评测一致性

Quarq 的学习过程在每次响应后异步执行，以减少用户等待时间。

同时加入了保护机制：

- 最多 **4 个并发学习任务**
- 失败后使用指数退避重试
- 在基准评测中设置同步屏障，确保最终提问前所有学习任务完成

这样既兼顾响应速度，也保证评测时记忆状态稳定。

- 精确数值判断

##### 2. 高价值信息深挖

##### 2.1 三层记忆结构值得借鉴

Quarq 将记忆分为三类：

###### 语义记忆：发生了什么
例如：

- 用户去年去了日本
- 用户喜欢极简风格
- 用户曾经提到自己在做 SaaS 产品

适合存储事实、偏好、身份、历史事件。

---

###### 程序性记忆：应该怎么做
例如：

- 用户希望回答保持简洁
- 用户讨厌过度营销化语言
- 生成报告时优先使用表格
- 遇到不确定信息时需要明确标注

这类记忆更接近“行为规则”。

---

###### 情景记忆：具体上下文经历
例如：

- 某次讨论中，用户正在评估一个 AI CRM 创业想法
- 上一次对话里，用户担心销售周期太长
- 某个项目曾经因为冷启动数据不足而搁置

这类记忆用于恢复上下文和连续性。

1. 用户是谁  
2. 用户做过什么  
3. 用户偏好什么  
4. 用户希望我如何工作  
5. 当前项目进行到哪一步

##### 2.2 HyDE 查询扩展：提升召回率的实用技巧

普通向量检索通常是：

> 用户问题 → embedding → 找相似记忆

但问题是，用户提问的表达方式可能和历史记忆不一致。

Quarq 使用 HyDE 查询扩展，让模型先生成多个可能相关的“假设文档”或查询变体，再进行检索。

例如用户问：

> 我上次提到的那个客户管理工具后来有什么风险？

系统可能扩展为：

- 用户之前讨论过 CRM 工具
- 用户提到客户管理 SaaS 的风险
- 用户曾经分析过销售周期、冷启动、数据壁垒
- 用户之前讨论的 B2B 工具项目

这样能显著提升召回率。

###### 产品启发
对于知识库、客服、销售助手、投研助手等场景，检索前最好增加一个“检索规划层”，而不是直接 embedding search。

---

##### 2.3 时间真实性协议是长期记忆的核心护栏

Quarq 区分四种时间：

| 时间类型 | 含义 |
|---|---|
| 存储日期 | 记忆被写入系统的时间 |
| 事件日期 | 事情实际发生的时间 |
| 叙述日期 | benchmark 或模拟对话中的时间线 |
| 相对日期 | “昨天”“三周前”“上个月”等动态表达 |

这非常关键。

很多系统会犯这样的错误：

> 某条记忆是在 5 月 10 日存储的，于是系统误以为事件发生在 5 月 10 日。

但用户可能是在 5 月 10 日回忆“三年前的一次经历”。

###### 可迁移原则
在长期记忆系统里，必须明确区分：

- 什么时候说的？
- 什么时候发生的？
- 当前要以哪个时间点为参照？
- 该时间是否由用户明确给出？

如果没有这个机制，系统很容易在长期交互中产生严重时间幻觉。

---

##### 2.4 二次检索机制比“自信回答”更重要

Quarq 的 self-correcting two-pass retrieval 很有价值。

它的逻辑是：

1. 先检索一轮；
2. 如果证据不足，不直接回答；
3. 让模型明确提出缺失什么信息；
4. 用更宽松或更有针对性的策略再检索；
5. 合并上下文；
6. 在更严格的反幻觉约束下生成答案。

###### 启发
优秀 Agent 不是一次性回答所有问题，而是知道：

> 当前证据不够，我需要再查一次。

这对商业产品特别重要，比如：

- 法务 AI
- 医疗 AI
- 投研 AI
- 客服 AI
- 企业知识库问答
- 销售支持助手

因为这些场景里，错误自信比回答慢更危险。

##### 2.5 数值保真度规则是高可信 AI 的必要条件

Quarq 对数字类问题做了专门处理：

- 总价
- 时长
- 数量
- 次数
- 金额
- 计数

它要求系统明确：

- 计算对象是谁？
- 统计的是哪个动作？
- 目标事件是什么？
- 是否需要精确匹配？
- 附近出现的数字是否只是噪音？

###### 例子
用户问：

> 我一共给 A 项目花了多少钱？

系统不能把这些数字全加起来：

- A 项目预算 5000
- B 项目成本 3000
- A 项目实际支付 2000
- A 项目报价 8000

它需要判断哪些数字属于“实际支付”，哪些只是预算、报价或其他项目。

不能完全依赖 LLM 自然语言推理。

##### 4. 反方与张力

##### 4.1 Benchmark 高分不等于真实产品可用
LongMemEval-S 是有价值的测试，但它仍然是基准环境。

真实用户环境会更复杂：

- 用户表达更模糊
- 记忆更脏
- 对话目标经常变化
- 用户可能自相矛盾
- 数据权限和隐私更敏感
- 长期记忆可能产生“被监视感”

所以 98.2% 是强信号，但不能直接等价于商业成功。

---

##### 4.2 三模型架构提升质量，但增加成本和复杂度
Quarq 使用三个专门模型，带来更好效果，但也带来：

- 更高 token 成本
- 更复杂的系统调试
- 更多失败点
- 更难的延迟控制
- 更高工程维护成本

对于早期产品，可能不需要一开始就做完整架构。

更现实的路径是：

1. 先做简单记忆抽取；
2. 再做混合检索；
3. 再加入时间规则；
4. 最后引入多模型分工和二次检索。

---

##### 4.3 本地优先有隐私优势，但不一定适合所有商业场景
Quarq 使用本地 FAISS，有几个优点：

- 数据可控
- 部署简单
- 成本低
- 隐私更好
- 不依赖云向量数据库

但缺点也明显：

- 分布式扩展复杂
- 多租户隔离需要额外设计
- 实时同步不如云数据库方便
- 企业级权限、审计、备份能力需要自己补

所以本地优先适合：

- 个人 Agent
- 原型产品
- 隐私敏感场景
- 小规模团队内部工具

但大型 SaaS 可能仍然需要专业向量数据库和权限系统。

---

##### 4.4 记忆越强，隐私和控制问题越突出
一个真正能记住的 Agent 会带来新的产品张力：

| 能力 | 风险 |
|---|---|
| 记住用户偏好 | 用户可能觉得被过度记录 |
| 记住历史对话 | 涉及隐私和敏感信息 |
| 自动更新用户画像 | 可能产生错误标签 |
| 长期跟踪项目 | 可能记录过期或错误状态 |
| 主动个性化 | 可能让用户失去控制感 |

因此，长期记忆产品必须提供：

- 查看记忆
- 编辑记忆
- 删除记忆
- 关闭记忆
- 选择性记忆
- 记忆来源解释

否则记忆能力越强，用户信任风险越大。
