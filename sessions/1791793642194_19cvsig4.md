## 分析要点

- **核心高价值点**：按内容的准确性需求分工：UI、价格、声明和CTA用代码或后期确保准确，实体产品镜头可用生成式视频，再统一到可控时间线中。
- **留存建议**：重点阅读并保留制作流程，工具版本与排名仅作待核实线索（包含可复用的分镜规划、品牌令牌管理、确定性动画和渲染验证流程，对产品演示与客户交付有直接参考价值。）
- **不足**：不宜直接采信“最佳”排名、模型能力及星标数据：缺少统一比较标准，主要依据社交平台案例，且引用中已有身份归属被纠正。

**知识要点**

- 代码驱动视频应让画面状态由时间确定，并避免无种子的随机数和系统时钟，以支持逐帧定位与可重复渲染。
- 将产品名称、颜色、字体和标志集中到品牌令牌文件，可减少改名换标时的重复修改与视觉不一致。
- 静态快照正常不代表最终视频正常；验证应覆盖转场中间状态、最终成片、音频流和文字可读性。

**行动项**

- 先核对候选仓库的文档、许可证和运行要求，再用真实产品素材制作一个短场景，验证工具是否适合交付。
- 把发布脚本拆成带精确时长的分镜表，建立统一品牌令牌文件，逐场景构建而非一次性生成整片。
- 在最终输出前检查关键帧与转场快照，并用ffprobe和联系表核对成片时长、音频及布局问题。

#### 1\. Claude Code + HyperFrames (HTML + GSAP → MP4)

HeyGen's open-source video framework. Every scene is a web page, animated with GSAP, then rendered to MP4 by a deterministic runtime.

它有一套专门的产品发布工作流 ，可以从一个 URL、一份脚本或一份简报开始。

为什么它排第一： 它是 Opus 5.5 动效浪潮中使用最多的技术栈，而且迭代速度依然很快。v0.8.143 于 10 月 8 日发布，采用 Apache-2.0 许可，已获得 59k 星标。

Prompt pattern:

> Build scene 3 of my launch video in HyperFrames. 1920x1080. Brand tokens are in brand.css. On screen: \[exact text, UI elements\]. Motion: \[enter / hold / exit, timing in seconds\]. Use a GSAP timeline only. Render 6 test frames and critique them before the final render.

#### 2\. Claude Code + Remotion (React → MP4)

You write the video as React components, so every frame is a function of time. Remotion has official agent skills, so Claude writes correct Remotion code.

为什么它排在这里： 它是最成熟的选项，约有 62.7k 星。每次渲染结果都一致，很容易模板化成几十个变体，而且预览工作室很棒。

Prompt pattern:

> Use the remotion skills. Build a 10-second 1920x1080 30fps product reveal for \[product\]. Colors: \[hex\]. Font: Inter. Use only useCurrentFrame, interpolate and spring, no CSS transitions. Scenes: \[timed list\]. Render 8 test frames to check layout before the final render.

#### 3\. /brag: one command, instant launch video

An agent skill that turns the project you just built into a short launch video, with music, motion and share copy included. It decides the story itself, then hands a brief to HyperFrames.

在 Opus 5.5 上，它会自动切换到 /brag-slim，一个精简的单文件版本。

Why it ranks here: It's the fastest route from zero to a video. One command, MIT licensed, 14.8k stars. You can even skip setup entirely at

[letsbrag.app](https://letsbrag.app).

Prompt pattern:

- \`let's /brag\`
- \`/brag --tone "fake Series A launch from 2016"\`
- \`/brag --voice\` adds narration

Repo:

[github.com/latent-spaces/brag](https://github.com/latent-spaces/brag)

#### 6\. Official GSAP skills

[greensock/gsap-skills](https://github.com/greensock/gsap-skills) is a set of 8 official skills: core, timeline, scrolltrigger, plugins, utils, react, frameworks, and performance. MIT licensed, 16k stars.

正是这些让 Claude 的 GSAP 代码正确 ，而非几乎正确 。在任何 HyperFrames 或 HTML + GSAP 工作流之前先安装它们。

限制： 最后一次提交是在 2026 年 4 月，所以它们大约已有六个月未更新。

#### AI 产品动画怎么做：用代码保证准确，用视频模型补足质感

作者为了重做一支需要更换名称、Logo 和脚本的 45 秒发布视频，调研了代码仓库、官方文档及 X 上附有真实视频的案例，整理出 12 种方法。**全文最重要的判断是：产品 UI、文字和品牌信息交给代码；实物、光影和电影感镜头交给视频模型；成片质量则靠分镜、检查和反复修改，而不是“一次提示词生成”。**

需要先说明：这是一份面向产品与 SaaS 发布视频的经验排序，不是统一条件下的性能测评。文中的模型版本、功能、价格、星标数和服务关闭信息，均为原文所述，不能直接视为已经核实的最新状态。

##### 一、这 12 种方法，其实处在制作流程的不同位置

标题看起来是在比较 12 款工具，但实际上混合了四类东西：

- **视频制作底座**：HyperFrames、Remotion，负责把代码画面渲染成视频。
- **自动化入口与创作方法**：`/brag`、作品集式提示词、移植真实 UI，决定如何开始、展示什么。
- **给 AI 的专业指导**：GSAP 官方技能、社区动效技能包，帮助 AI 正确实现动画，并遵守设计规则。
- **生成或编辑视频素材的模型**：Higgsfield、Seedance、Kling、Veo、Runway，负责更接近摄影和实物广告的画面。

**它们不全是替代关系，很多可以一起使用。** 例如，让视频模型生成一个产品特写，再放入 HyperFrames 时间线；产品名称、卖点和行动按钮仍由代码绘制，避免文字失真。

这里的 **Skill（技能）**，可以理解为给 AI 编程助手的一套专业说明书，包含规则、示例和操作步骤，并不是换了一个新模型。

##### 二、首选路线：让 AI 写动画代码，再渲染成视频

###### 1. Claude Code + HyperFrames：适合产品发布片，作者的首选

HyperFrames 是 HeyGen 的开源视频框架。每个场景本质上是一张网页，用 HTML 等描述画面，用 **GSAP——控制元素移动、缩放、透明度及其时间顺序的动画库**——编排动作，再输出 MP4。

它的重要特点是**确定性渲染：给定同一份代码和素材，同一时间点应得到同一画面**。这不同于重新生成一段 AI 视频：改标题、换 Logo 或调整时间，不必让整段画面重新“猜”一次。

作者把它排第一，理由是它在所观察的动效案例中使用广泛、更新较快，而且有专门的产品发布工作流，可以从 URL、脚本或简报开始。原文称其采用 Apache-2.0 许可，约有 5.9 万 GitHub 星标。

几个案例说明了它能做什么，也揭示了实际成本：

- 一支 60 秒发布片完全由 HTML + GSAP 构成，但第一稿很差，展示的是反馈后的第二稿。
- 一位有 20 多年视频经验的导演，在一夜内完成了 SaaS 发布片，输出为 **1080p、60 帧/秒**；音乐也由代码合成。作品经过五轮修改，附带可重新构建的说明，但仍需人工观看才能发现动态故障，并消耗了大量 Claude 周配额。
- 另一支视频的数字直接来自公司数据库。视频不再只是手工剪辑的固定文件，也可以由数据输入驱动画面更新。

作者给出的提示词思路很具体：指定场景编号、分辨率、品牌文件、准确文案和 UI 元素，说明进入、停留、退出的时间，要求只使用 GSAP 时间线，并在最终渲染前抽取六帧进行自我检查。

**局限：**需要 Node.js 22+、FFmpeg 等环境；框架比 Remotion 年轻；只说“给我做一支精彩发布片”，往往得到的是通用炫技集锦，而不是产品故事。

###### 2. Claude Code + Remotion：更成熟，适合模板化与批量变体

Remotion 用 React 组件编写视频。可以把它理解为：**视频中的每一帧，都是代码根据当前时间计算出来的一张画面。**

例如，第 30 帧标题出现，第 90 帧产品卡片放大，第 150 帧展示结果。因为时间与画面明确对应，预览、修改和重复渲染比较可控。

作者认为它是最成熟的选择，约有 6.27 万星标，预览工作室完善，尤其适合把同一套视频模板生成几十个版本。官方 Agent Skills 则帮助 Claude 遵守 Remotion 的编程方式。

原文的提示词强调：明确时长、尺寸、帧率、颜色、字体和逐段场景；使用基于帧数的动画函数，而不是普通 CSS 过渡；最终输出前检查八张测试帧。这样做是为了让动画服从视频时间线，而不是浏览器自由运行的时间。

一个案例结合了 Remotion、Skia 绘图、GSAP 插件和 Tone.js 音频，创作者称第一版完成了约 90%，但仍非一次成型。

**局限：**这条路线主要用于动态图形，不是生成照片级实拍画面；原文提醒，较大公司需要付费许可证。

##### 三、快速起稿、做出惊艳效果，以及保持真实 UI：三种不同办法

###### 3. `/brag`：最快从项目得到短视频，但会替你决定故事

`/brag` 是一个 Agent Skill：读取刚做好的项目，自己决定讲什么，再把创作简报交给 HyperFrames，生成带音乐、动效和分享文案的短发布视频。可用 `--tone` 指定语气，用 `--voice` 加旁白，也有免安装的网页入口。

它采用 MIT 许可，原文称约有 1.48 万星标，并会在所述模型版本上切换到精简的单文件实现。

**适合：快速做一支约 20 秒的初稿，探索节奏与呈现方向。**  
**不适合：你已经有明确脚本，希望逐场准确执行。** 因为它最大的便利，也是最大的限制——故事由它来写。

###### 4. “像求职作品集一样，全力展示动效能力”：适合找视觉方向，不等于发布片脚本

原文引用的一句话提示词，大意是：

> 制作一支 15 秒的动态设计视频，像你提交简历时展示的作品集一样，证明你是一位出色的动效设计师，全力以赴。

它的作用是推动模型做更大胆、更密集的视觉表现。但**“看起来惊艳”与“把产品讲明白”是两件事**：前者可以靠转场和动态字体，后者需要明确的用户问题、真实功能和叙事顺序。

文章中的移动应用版本，加入了大量约束，使它从一句创意口号变成完整制作任务：

- 每一帧由代码绘制，不用现成模板或素材库视频。
- 只使用仓库中的真实素材和事实，不编造功能、数字、推荐语或 UI。
- 音乐由代码合成，剪切、点击和冲击音效与画面准确同步。
- Web 产品使用横屏；移动应用使用竖屏，并遵循应用实际的明暗主题。

移动应用的故事结构也很具体：图标被点击并打开应用 → 展示核心操作步骤 → 处理过程 → 结果揭晓并扩展到全屏 → 以应用图标、名称和商店徽章收尾。

**它适合创造一个“记得住的瞬间”，但仍需要你补上故事与边界。**

###### 5. 把真实产品 UI 移植进视频：避免“演示很好看，产品却不是这样”

这条方法不是让 AI 仿照截图画一个相似界面，而是让它从产品代码中重建或移植真实 UI。这样，视频中的按钮、布局和文案，与实际产品保持一致。

原文的 TourIQ 案例使用 HookMaster Motion MCP 配合 Claude，通过预设的镜头、缓动和节拍规则，在 Remotion 或 HyperFrames 中制作影片。这里的 MCP 是让 AI 助手接入外部工具的接口。

创作者称，自己像给剪辑师提意见一样反馈，Agent 会修改造成问题的规则或代码，而不只是修补某一帧。

**优势是准确与一致；代价是需要访问代码库或设计文件，前期设置比做展示模型稿更重。**

##### 四、技能包解决两件事：动画写得对，画面设计得好

###### 6. GSAP 官方技能：减少“差一点正确”的动画代码

`greensock/gsap-skills` 包含八类官方技能，覆盖基础、时间线、滚动触发、插件、工具函数、React、框架和性能。

它解决的是实现层的问题：AI 可能会写出看似合理、实际却存在冲突或执行差异的动画代码。官方技能为它提供更准确的用法和约束。

作者建议，在 HTML + GSAP 或 HyperFrames 工作流之前先安装。原文称其采用 MIT 许可，约有 1.6 万星标，但最近一次提交距文章所述时间约六个月，因此仍要检查版本兼容性。

###### 7. 社区动效技能包：补上节奏、镜头、排版与自我检查

社区技能包不只是教 API，还尝试把设计师的判断写成规则，例如：

- 怎样选择动作曲线、持续时间和转场方式；
- 怎样安排字体、颜色和镜头；
- 怎样把声音与动作同步；
- 怎样先渲染测试帧，再检查遮挡、裁切和布局。

原文列出了多组资源，包括 `claude-motion`、动效设计技能、Remotion 官方技能，以及 Lottie、Three.js、Manim 等不同方向的工具。它们面向的交付物并不相同：网页动效、MP4、可嵌入应用的动画、3D 场景、数学讲解视频，需要分别选择。

**不要把安装更多仓库等同于提高质量。** 作者明确提醒，社区项目质量参差不齐，应先检查和测试。

原文还保留了一条重要纠正：所谓“Netflix 工程师发布了这 20 个仓库”不准确，这些是独立开发者的开源项目，不能借此获得机构背书。

##### 五、五种视频模型路线：适合实物与摄影感，但不要负责关键文字

以下为作者的第 8—12 项。相关功能与效果判断均按原文转述。

| 方法 | 主要用途与机制 | 关键限制 |
|---|---|---|
| **8. Higgsfield** | 在一个平台上制作包含动态排版和 3D 产品视觉的广告。 | 精细控制不如代码。作者明确建议，不要让它生成价格、声明或 UI 文本。 |
| **9. Seedance 2.5** | 制作电影感产品广告。提示词应分别说明参考图用于锁定产品、风格还是动作，再描述运镜与灯光。 | 主要经不同渠道销售，价格不统一；产品细节可能发生变化。 |

这几条路线的共同取舍是：**更容易得到摄影质感，但较难保证每个细节都准确。**

对于 SaaS 发布片，UI 中一个按钮名称错误，就可能误导观众；对于实物广告，模型改变了接口位置或外形，也可能让产品失真。因此，它们更适合作为受控素材来源，而不是接管整部影片。

##### 六、作者真正推荐的是一套制作流程，而不只是一款工具

长提示词中最值得保留的，不是安装命令，而是以下工作顺序。

###### 1. 先收集真实素材，再写故事

读取 README、品牌颜色、字体、Logo、关键流程和 UI 文案。移动应用优先使用干净的真实截图、预览工具或设备录制，避免把带营销边框的宣传图当成应用界面。

官方商店徽章应使用官方素材，不自行重绘。需要把截图中的按钮或卡片做成动画时，应先测量位置，保证点击、弹出和回落落在真实元素上。

###### 2. 把脚本拆成有时间的场景表，一次制作一场

原文称之为 **beat sheet**：不只写“展示功能”，还要写清何时出现、停留多久、怎样转场，以及对应哪一拍音乐。

基本结构是：

> 前两秒吸引注意 → 揭示产品 → 展示三至四个真实使用亮点 → 明确的行动引导。

文字也要有足够阅读时间。移动应用示例要求标题约五个词以内，可读文字每词至少保留 0.3 秒。它针对英文表达，但原则是明确的：不能为了卡点让观众来不及读。

###### 3. 统一品牌文件，让改名与换 Logo 不必逐场返工

把名称、颜色、字体和 Logo SVG 集中到一份品牌配置中。各场景读取同一份配置，而不是分别写死。

**这样，更名是修改一个信息源，而不是在十几个场景里逐一找遗漏。** 这正对应作者此次重做视频的需求。

###### 4. 让画面与声音共用时间安排

先选音乐速度，再对齐转场、点击、揭晓和音效。例如 120 BPM 表示每拍 0.5 秒，四拍为两秒，可以据此安排场景节奏。

音乐可以由代码合成，但仍要检查音量平衡，不能让鼓点盖住旋律，也不能只确认“有声音”就交付。

###### 5. 保证动画可以按任意时间点稳定重建

原文列出的大量技术坑，背后有同一个问题：最终渲染可能逐帧定位，并不等同于在浏览器里从头播放。

因此，需要让动画状态由时间决定，使用固定种子的随机效果，避免依赖当前日期、不可控随机数或无限循环；字体和脚本尽量从本地加载；不要让 CSS 与 GSAP 同时争夺同一个元素的变换属性。

否则可能出现：浏览器预览正常，导出的 MP4 却缺元素、跳状态或画面不一致。

###### 6. 测试帧检查与完整观看，两者都不能省

先做自动检查，发现布局、遮挡、对比度和动画问题；再对每个场景及转场中间状态截图，检查文字裁切、重叠、空白区域和素材位置。

最后仍要观看完整成片。**静态帧能发现排版问题，却无法充分判断节奏、闪烁、短暂故障和音画同步。**

交付前还要验证时长、音频流、缩略图和文件位置。文章中的“一夜完成”并不意味着无需专业判断或质量检查。

##### 七、按交付物选工具，别把所有动画都做成 MP4

文章还补充了几种不属于上述 12 项主榜的方法：

- **Three.js / React Three Fiber**：适合网站上可以交互的 3D 产品主视觉。作者认为，这类场景可能比固定播放的 MP4 更合适。
- **LottieFiles / Rive**：适合应用内引导、成功状态等动画，需要准备自己的 SVG 素材。
- **Motion AI Kit**：面向实时 React UI 动画；原文所述示例位于付费 Motion+ 层级。

原文另称 Sora 的应用和 API 已关闭，但未提供足以在本文中核实的官方依据。这类服务状态，以及所有模型版本和功能可用性，都应在实际选型前重新确认。

作者最终选择的组合是：

> Claude Code + 所述 Opus 模型 → HyperFrames + GSAP 技能 → 新 Logo 与统一品牌配置 → 分场景时间表 → 渲染、检查、迭代。

这份清单最有价值的地方，不是宣称 AI 已经替代了视频制作，而是展示了一种更可修改的工作方式：**AI 负责生成与实现，人负责真实信息、故事、约束和最终判断；代码保证准确，视频模型提供质感。**
