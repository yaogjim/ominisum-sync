#### 一、深度总结

这条内容分享的是：**用 Codex App + Codex 自带 Chrome 插件，定时自动阅读 X（推特）关注流，并生成中文长报告**。

核心不是“刷推”，而是把 X 信息流改造成一个**自动化情报日报系统**。

##### 1. 作者的具体做法

作者设置了一个 **每小时运行一次的 Codex 定时任务**，让 Codex 通过 Chrome 插件调用用户现有浏览器登录状态，自动打开 X 首页，进入 **Following / 正在关注** 页面，滚动读取至少 200 条帖子，然后去重、分类、总结，最后输出一份中文报告。

提示词设计得很细，重点包括：

- 每次必须新开 Chrome 标签页
- 必须进入 `x.com/home`
- 必须采集 Following，而不是 For You
- 每轮结束后关闭临时标签页
- 只读内容，不做点赞、转发、评论等账号操作
- 至少读取 200 条帖子
- 按帖子链接去重
- 输出不少于 5000 字的中文解释型报告
- 报告要包含分类、热点、代表帖、可信度、风险、学习点、跟进清单等

##### 2. 这套提示词的真正价值

它不是一个简单的“帮我总结推特”的 prompt，而是一套比较完整的**自动信息采集与分析流程规范**。

它解决了几个关键问题：

| 问题 | 解决方式 |
|---|---|
| 读到旧内容 | 每次新建标签页，重新进入首页 |
| 采集源混乱 | 明确只采集 Following，不采集 For You |
| 自动化风险 | 只读不互动，不修改账号 |
| 内容重复 | 按 status 链接去重 |
| 总结太浅 | 要求分类、解释背景、判断价值 |
| 谣言风险 | 要求区分事实、转述、评论、玩梗 |
| 信息不可理解 | 要求解释术语、梗、上下文 |
| 后续行动缺失 | 最后给出值得跟进清单 |

#### 二、深入浅出解读

##### 1. 这件事本质上是什么？

一句话：

> 把社交媒体信息流，从“人刷算法”，变成“AI 定时读、筛、讲、评”。

过去你打开 X，会被动刷信息流：

- 看见什么取决于算法
- 很容易被热点牵着走
- 信息碎片化严重
- 看了很多，但沉淀很少

这套方法则把流程改成：

```text
关注源 → 自动读取 → 去重分类 → 解释背景 → 判断价值 → 输出日报
```

它像是给自己配了一个**私人信息助理**。

##### 2. 为什么作者强调 Following，而不是 For You？

这是非常关键的一点。

- **Following**：来自你主动关注的人，更接近“订阅源”
- **For You**：平台算法推荐，更容易混入情绪化、争议性、广告、陌生热点

如果目标是获取稳定高质量信息，Following 更可控。

如果目标是追热点、看舆论风向，For You 更有价值。

作者默认选 Following，说明他的目的不是娱乐刷屏，而是做**个人信息管理**。

##### 3. 为什么要“每次新开标签页”？

这看似啰嗦，其实很重要。

因为 X 页面是动态加载的，如果复用旧页面，可能出现：

- 读到上一次滚动过的内容
- 页面停在旧位置
- 缓存没有刷新
- 自动化状态残留
- 数据范围混乱

所以作者要求每次重新打开页面，相当于保证采集过程“干净、可重复”。

##### 4. 为什么报告要求这么长、这么细？

因为社交媒体内容有一个问题：

> 信息多，但上下文少；观点多，但可信度不明。

所以作者要求 Codex 不只是总结，还要做：

- 背景解释
- 主题分类
- 代表帖分析
- 热度原因判断
- 可信度区分
- 风险提醒
- 学习价值提炼
- 后续跟进建议

这其实已经不是摘要，而是**情报分析报告**。

##### 1. 把“刷信息”变成“收情报”

普通刷推是消耗注意力。

这套流程把信息流变成结构化输出：

- 今天 AI 圈发生了什么？

##### 2. 提示词写得很有工程意识

它不是单纯告诉 AI“总结一下”，而是规定了：

- 入口

- 禁止动作
- 去重规则
- 输出结构
- 风险判断
- 异常处理

这说明好 prompt 的关键不是“华丽”，而是**把任务边界讲清楚**。

##### 3. 适合知识工作者

尤其适合这些人：

- 投资人

#### 四、潜在问题与风险

##### 1. 平台规则风险

X 对自动化访问、爬取、插件行为可能有限制。

即使只是读取，也可能触发：

- 登录验证
- CAPTCHA
- 限流
- 风控
- 账号异常

作者提醒不要开启 developer mode，本质上也是在降低插件自动化暴露风险。

##### 2. 信息质量仍取决于关注列表

如果你的 Following 本身质量不高，AI 总结得再好，也只是把低质量信息整理得更漂亮。

所以这套系统的上限取决于：

```text
关注源质量 × 采集范围 × AI 分析能力
```

关注列表就是你的“信息数据库”。

##### 3. AI 可能误判上下文

X 上很多帖子依赖：

- 图片
- 视频
- 引用链
- 梗文化
- 反讽语气
- 圈内背景

AI 即使读到正文，也不一定能完全理解。

作者提示词里要求“缺少上下文就明说”，这是必要防护，但不能完全避免误读。

##### 4. 自动日报可能制造“掌控幻觉”

报告很完整，会让人觉得自己“掌握了全局”。

但实际上：

- 只覆盖了你关注的人
- 只覆盖了采集时段
- 只覆盖了模型能读懂的内容
- 只覆盖了页面成功加载的帖子

所以它是辅助工具，不是事实全景。

#### 五、可借鉴的 Prompt 设计方法

这条内容最值得学的，其实是 prompt 结构。

可以抽象成一个通用模板：

```text
1. 明确工具和环境
2. 明确入口和数据源
3. 明确禁止行为
4. 明确采集数量和去重规则
5. 明确异常处理方式
6. 明确输出对象是谁
7. 明确输出结构
8. 明确信息可信度判断

```

这比单纯说“帮我总结一下”强很多。

真正高质量的 AI 自动化任务，往往不是靠一句神奇 prompt，而是靠**流程设计**。

#### 六、我的辩证思考

##### 1. 它提高效率，也可能强化信息茧房

优点是：你能更高效地消化关注列表。

缺点是：如果只读 Following，你可能越来越困在自己选择的信息圈里。

所以可以考虑：

- Following 用于深度跟踪
- For You 用于观察外部热点
- 搜索关键词用于专题研究
- 多语言源用于打破圈层限制

##### 2. 它节省时间，也可能降低一手感知

AI 总结能帮你快速抓重点，但社交媒体的很多信号来自细节：

- 情绪浓度
- 评论风向
- 梗的扩散
- 图片视频语境
- 争议双方的互动

这些未必能被报告完整保留。

所以适合策略是：

> AI 负责初筛，人负责深读重点内容。

##### 3. 它像个人助理，但还不是可靠研究员

这套自动化适合做：

- 日常监控
- 热点发现
- 信息分类
- 初步判断

但不适合直接做：

- 投资决策
- 政治判断
- 医疗建议
- 法律判断
- 重大商业决策

涉及决策的内容，必须二次核验。

##### 4. 真正的核心能力不是自动化，而是定义问题

这条帖子表面是在分享工具，深层是在展示一种能力：

> 把模糊需求，拆成可执行、可检查、可复用的流程。

未来使用 AI 的分水岭，不是“会不会问问题”，而是：

- 能不能定义任务边界
- 能不能设计输入源
- 能不能规定输出格式
- 能不能控制风险
- 能不能建立反馈闭环

---

#### 七、一句话结论

这套方法的价值不在于“自动刷推”，而在于把社交媒体改造成一个**可定时、可控源、可解释、可复盘的个人情报系统**。

但它必须搭配高质量关注源、风险意识和人工核验，否则只是把信息噪音自动整理成更像样的噪音。

##### 2. 采集范围：默认读取 Following，不采集 For You

作者在提示词中特别强调，任务运行时必须：

- 新建一个 Chrome 标签页；
- 直接导航到 `https://x.com/home`；
- 不复用上一轮已经打开或滚动过的 X 页面；
- 页面加载后如有必要刷新一次；
- 目标页面必须是 **“正在关注 / Following”tab**；
- 不要采集 **“为你推荐 / For You”tab**，除非用户明确要求。

这样做是为了避免：

- 读取旧页面；
- 继承旧滚动位置；
- 受到缓存内容影响；
- 使用上一轮自动化任务留下的状态。

也就是说，作者希望每次采集都是一次“干净的新会话”，保证数据尽可能新鲜、准确。

##### 3. 自动化行为限制：只读不互动，降低账号风险

提示词明确要求自动化过程中只能做这些操作：

- 读取内容；
- 滚动页面；
- 打开必要链接。

不能做以下行为：

- 点赞；
- 转发；
- 关注；
- 评论；
- 发帖；
- 修改账号设置。

作者还在回复中提醒：

> 不要打开 Codex Chrome 插件的 developer mode 设置，以降低风险。

这说明作者比较重视账号安全和自动化行为边界，避免被平台识别为异常操作。

##### 4. 数据采集要求：至少读取 200 条帖子，并按链接去重

作者设定的采集标准比较明确：

- 进入 Following 后滚动加载；
- 至少访问或加载 **200 条帖子**；
- 按 `status` 链接去重；
- 如果无法收集满 200 条，需要说明原因；
- 报告中要写明实际读取数量和覆盖范围。

这不是简单截取几条热门推文，而是希望形成一个相对完整的信息采样，用来生成类似“本小时信息简报”的内容。

##### 5. 输出报告要求：不少于 5000 字，面向不了解背景的读者

作者要求 Codex 输出一份：

- 中文；
- 详细；
- 可读；
- 解释型；
- 不少于 **5000 字** 的报告。

默认读者：

- 没看过原帖；
- 不一定懂相关背景；
- 需要解释上下文、术语、人物、产品名和梗。

报告不能只是列数字或简单摘要，而要把事情讲清楚。

---

##### 6. 报告结构：先给采集概况，再按主题分类展开

提示词要求报告开头先说明采集概况，包括：

- 实际读取的唯一帖子数；
- 时间范围；
- 主要分类；
- 最大热点；
- 是否遇到登录、限流、反爬、网络或加载问题；
- 是否重新打开了新标签页；
- 是否确认采集的是 Following 页面。

之后要按主题分类展开，分类可以包括：

- AI / 模型 / 开发工具；
- 社会 / 政治 / 公共议题；
- 商业 / 投资 / 产品；
- 体育 / 赛事；
- 泛社媒 / 娱乐 / 热点；
- 个人动态 / 学习 / 观点；
- 其他值得注意内容。

每一类都要讲清楚：

- 大概发生了什么；
- 背景是什么；
- 为什么值得关注；
- 有哪些重复主题或情绪；
- 哪些只是热闹；
- 哪些有实际信息价值。

---

##### 7. 代表帖子分析：不仅总结，还要判断价值和可信度

作者要求每个分类都列出代表帖子，并尽量包含：

- 作者；
- handle；
- 发布时间；
- 链接；
- 可见互动数据；
- 原帖主旨；
- 上下文解释；
- 可信度判断；
- 该帖子在分类中的意义。

对于热门帖子，还要额外分析“为什么这么火”，可以从以下角度判断：

- 作者影响力；
- 话题时机；
- 争议性；
- 情绪强度；
- 新奇性；
- 实用价值；
- 图片或视频传播效果；
- 梗或身份认同；
- 转帖链路；
- 外部事件背景；
- 互动数据。

也就是说，这个提示词不只是让 AI“复述内容”，而是要求 AI 做一层传播分析和信息判断。

##### 8. 学习价值与风险提示：区分有用信息和噪音

提示词还要求对帖子做进一步筛选：

###### 值得学习的帖子

- 标题或表达方式；
- 选题角度；
- 信息包装；
- 观点锋利度；
- 产品或技术启发；
- 传播策略；
- 可复用的内容结构。

###### 值得警惕的帖子

需要标出风险，例如：

- 未经证实；
- 夸张标题；
- 断章取义；
- 广告推广；
- 投资 FOMO；
- 政治或身份议题情绪化；
- 必须点开图片或视频才能理解。

作者还要求，对于重大或可能影响决策的说法，要区分：

- 可信来源；
- 二手转述；
- 个人评论；
- 玩梗；
- 未核验传闻。

必要时还要建议后续核验对象。
