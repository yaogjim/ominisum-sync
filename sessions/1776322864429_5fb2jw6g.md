**宝玉**

pi 是 OpenClaw 背后的 Agent 底层框架，它的核心维护者 Mario Zechner 最近宣布了一项新的规则：所有未提前申请批准的 issue 和 PR（代码合并请求），提交之后会立刻被机器人自动关闭。

之所以要这么严格是因为他每天都会收到 30 到 50 条 issue，其中绝大部分都是由 AI Agent 自动生成的垃圾信息。

新的规则是这样运行的：  
\- 首先，这些被自动关闭的 issue，维护者每天都会手动再看一遍：  
\* 如果发现写得不错、符合要求，就会重新打开；  
\* 如果写得特别棒，维护者会给你加一个 "lgtmi" 标签，以后你的 issue 都不再自动关闭；  
\* 如果你不仅 issue 写得优秀，还附带了代码修复（PR），那标签会升级为 "lgtm"，以后你的 issue 和 PR 都不会再被机器人关闭；  
\- 但是如果有人反复用 AI 工具刷垃圾内容，他的账号会被永久拉黑，不再接受任何贡献。

其实这种情况并不是个例，而是整个开源社区目前都在面对的问题。AI 编程工具让大家提交 issue 或 PR 的成本几乎降到了零，但维护者审核这些内容的工作量却一点也没有减少。于是，GitHub 上越来越多的项目都开始收紧贡献的门槛，从过去的“欢迎所有人参与”变成了现在的“你先证明你是真人，而且是认真来贡献的”。

## 通俗精炼（1）

### 2026-04-16 06:58:20

#### AI 正在逼开源社区“提高门槛”

##### 核心事件
`pi`（OpenClaw 背后的 Agent 框架）维护者 Mario Zechner 宣布新规：**所有没有提前获批的 issue 和 PR，提交后都会被机器人立即关闭**。

##### 为什么这么做
原因很直接：维护者每天会收到 **30 到 50 条 issue**，其中大部分是 **AI Agent 自动生成的低质量内容**。  
AI 让“提交问题和代码”的成本几乎归零，但**审核成本并没有下降**，反而把维护者拖进了信息垃圾堆里。

##### 新规则怎么运作
这套机制并不是“一刀切拒绝”，而是先拦截、再人工筛选：

###### 1. 默认先关闭
所有未经提前批准的 issue 和 PR，会先被机器人自动关闭。

###### 2. 维护者每天复查
被关闭的内容，维护者仍会手动看一遍：
- 写得合格的，会重新打开
- 写得特别好的，会打上 `lgtmi` 标签，以后 issue 不再被自动关闭
- 如果不仅 issue 写得好，还附带高质量 PR，会升级为 `lgtm`，以后 issue 和 PR 都可直接进入

###### 3. 反复刷垃圾会被封禁
如果有人持续用 AI 工具批量制造低质量内容，账号会被**永久拉黑**。

##### 这背后的趋势
这不是个别项目的问题，而是整个开源社区正在面对的现实：

- 过去：强调“欢迎所有人参与”
- 现在：更强调“先证明你是认真贡献的人”

本质上，开源协作正在从 **低门槛开放**，转向 **有筛选的开放**。

##### 文章想表达的重点
AI 编程工具提升了提交效率，但也制造了大量“看起来像贡献、实际增加负担”的内容。  
结果是：**维护者不得不先防垃圾，再谈协作**。

##### 一句话总结
**AI 降低了贡献门槛，却抬高了治理成本；开源社区因此开始用更严格的规则，重新筛选真正有价值的贡献。**

## 结构化（1）

### 2026-04-17 05:43:24

#### 主旨概括

这篇文章主要讲的是：由于大量 AI 自动生成的低质量 issue 和 PR 涌入，`pi`/`OpenClaw` 的维护者开始提高贡献门槛，用“先审批、后处理”的方式减轻维护压力。  
它反映的不是个别项目的问题，而是整个开源社区正在面对的共同挑战：**提交成本几乎为零，但审核成本依然很高**。

##### 1. 事件背景：`pi` 项目开始收紧贡献规则

- `pi` 是 `OpenClaw` 背后的 Agent 底层框架，其核心维护者 Mario Zechner 宣布了新规则。  
- 新规则的核心是：**所有没有提前申请批准的 issue 和 PR，提交后会被机器人立刻自动关闭**。  
- 采取这种严格策略的原因很直接：维护者**每天会收到 30 到 50 条 issue**，其中绝大多数是 **AI Agent 自动生成的垃圾内容**。  

**通俗理解**：以前是谁都可以先提问题、先发代码；现在变成了“先证明你是认真来贡献的，系统才会认真接住你”。

##### 2. 新规则怎么运行：先拦截，再人工复核

文章介绍了这套机制的具体流程：

- 所有未获预先批准的 issue，会先被机器人自动关闭。  
- 但这并不代表彻底忽略，维护者**每天仍会手动复查一遍**。  
- 如果内容写得不错、符合要求，维护者会**重新打开**。  
- 如果 issue 写得特别好，会加上 **`lgtmi`** 标签；拿到这个标签后，**以后提交的 issue 不会再被自动关闭**。  
- 如果不仅 issue 写得优秀，还附带了高质量修复 PR，则会升级为 **`lgtm`** 标签；之后这个人的 **issue 和 PR 都不会再被机器人自动关闭**。  

**可以把它理解为一种“信誉机制”**：  
第一次先严格筛，贡献质量持续过关后，再逐步给予“免审通行权”。

##### 3. 处罚机制：反复刷 AI 垃圾会被永久拉黑

- 如果有人反复使用 AI 工具批量提交垃圾内容，维护者会**永久封禁其账号**。  
- 被拉黑后，这个人的贡献将**不再被接受**。  

这说明维护者的态度已经不只是“提高门槛”，而是开始把**恶意或低质量 AI 滥用**当成需要严肃处理的问题。

##### 4. 更大的背景：这已经是开源社区的普遍问题

文章进一步指出，这种情况并不是个例，而是整个开源生态都在遇到的难题：

- AI 编程工具让提交 issue/PR 的成本**几乎降到零**。  
- 但维护者审核、验证、沟通的工作量**并没有减少**。  
- 结果就是：项目维护者越来越容易被海量低质量内容淹没。  
- 因此，GitHub 上越来越多项目开始从过去“欢迎所有人参与”，转向现在的：  
  **“先证明你是真人，而且是认真来贡献的。”**

**一个很直观的例子**：  
以前提一个 issue，通常要自己复现、阅读文档、整理描述；  
现在 AI 可以几分钟生成一堆“看起来很像那么回事”的报告，但真正判断它有没有价值，仍然得靠维护者花时间逐条看。

##### 5. 推文与社区反馈：大家普遍感受到“AI 垃圾提交”压力

文中引用了 `@badlogicgames` 的推文，说明这个“pi 贡献模型”已经正式上线，并配合定制化的 PR 处理机制来应对当前局面。  

热门回复也补充了几个现实感受：

- 有人注意到标签名 `lgtmi` 比 `lgtm` 多了个 `i`，说明社区也在关注这套新规则的细节。  
- 有开发者提到，自己本来想修 `hermes` 的 bug，却发现**类似 issue 和 PR 已经一大堆**，而且提交者在提交前**根本不检查是否已有重复内容**。  
- 还有评论直接指出：维护者一天要处理 **30-50 条 AI 生成的 issue**，几乎像被迫给 AI 当“投喂员”。  

这些反馈说明，问题不只是“数量多”，还包括：

- 重复提交严重  
- 缺少基本检索和关联  
- 维护者精力被无效消耗

##### 6. 文章想表达的核心结论

- AI 确实降低了参与开源的门槛，但也同时放大了低质量贡献的数量。  
- 对维护者来说，真正稀缺的不是“有人提交内容”，而是“有人提交可信、经过思考的内容”。  
- 所以，项目开始通过**自动关闭、人工复核、信誉标签、永久封禁**等方式建立新的贡献秩序。  
- 开源社区的协作模式，正在从“默认开放”转向“先过滤、再信任”。  

**一句话总结**：  
这篇文章借 `pi` 项目的新规说明，AI 时代的开源协作正在进入“高门槛筛选”阶段，重点已经不再是“能不能提”，而是“你提的东西值不值得维护者花时间看”。
