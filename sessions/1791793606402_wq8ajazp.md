REA：让 AI 智能体帮你逆向没有源码的软件

开源项目 REA（Reverse Engineer Anything）把逆向分析工具接到了 Claude Code、Codex、Cursor 这类 AI 编程智能体上。看到别人 App 里有个好功能，可以让智能体去拆这个程序，讲清楚功能是怎么实现的，附上证据，再在你自己的项目里写一个类似的。逆向分析指的是手里没有源代码，从编译好的程序反推它是怎么写的。

REA 本身是一个 MCP 服务。MCP 是 AI 智能体调用外部工具的通用接口，接上以后，智能体在对话里就能直接调用 REA 的分析功能。安装只需一行命令 npx rea-agents setup，它会注册到 Claude Code、Codex、Cursor、Gemini CLI、Grok Build 等智能体里，改配置前会先备份并让你确认。不用智能体的话，也可以在终端里直接跑命令。

能分析的东西很多。原生程序（直接编译成机器码的软件）要借助 Hopper、Ghidra 或 IDA 这几款反汇编工具，把机器码还原成汇编和近似 C 语言的伪代码。Electron 应用（用网页技术做的桌面软件，比如 Notion）可以直接拆开安装包里的 ASAR 归档文件，理清模块和进程间通信，不需要额外工具。此外还支持 .NET 程序、安卓 APK、固件、网站、抓包记录、以太坊合约字节码，以及在 Linux 和 macOS 上记录程序运行时的行为。

分析在本机进行，REA 不上传目标程序，但分析结果会交给智能体背后的模型服务商，数据怎么处理看各家政策。

项目给了三个案例。一是经典打砖块游戏 DX-Ball：从一次播放音效的调用，追到根据球的位置计算左右声道的函数，把不完整的伪代码还原成 C 代码，3205 组测试结果和原版一致，编译出的 63 个字节也和原版完全相同。二是 Notion 桌面版：追踪复制粘贴从界面一路经过预加载脚本、进程间通信到主进程的完整链路。三是日本老电脑 PC-98 上的游戏《东方幻想乡》（TH04）：从 16 位指令里还原出弹幕子弹环的角度算法。

对安全研究员、做老游戏复刻和软件保存的人来说，以前要自己对着反汇编工具一行行读、一层层追调用，现在可以让智能体先追，人来核对它给出的证据。普通开发者想研究竞品某个功能的做法，也多了一条路。

README 显示项目在 GitHub 上已有 5 万星。npm 包今年 7 月首次发布，最新的 6.3.0 版今天刚发。

使用前注意两点。项目声明只支持合法的逆向研究，授权和合规由使用者自己负责，逆向别人的软件可能违反用户协议或版权法规。项目还说明从未发行或背书任何加密货币，借用 REA 名字的代币都与它无关。

#### REA：让 AI 帮你分析没有源码的软件，关键在于提供可核对的证据

REA（Reverse Engineer Anything）是一个开源项目，把逆向分析工具接入 Claude Code、Codex、Cursor 等 AI 编程智能体，让它们帮助用户理解现成软件的实现方式。**它的核心价值不是“一键恢复全部源码”，而是让 AI 代替人完成一部分查找、追踪和代码还原工作，再由人核对证据。**文章介绍了它的工作方式、支持范围、三个实际案例，以及隐私、合规和复杂目标的限制。

##### 1. 它解决什么问题：没有源码，也能研究软件如何工作

“逆向分析”是指：拿不到软件的源代码，只能从编译后的程序、安装包或运行行为，反推其内部逻辑。

例如，你看到某个 App 的功能做得很好，想知道它如何实现。传统做法往往需要研究人员打开专业工具，逐条阅读底层指令，寻找相关函数，再一层层追踪调用关系。REA 则让 AI 智能体调用这些工具，先完成一部分分析：

- 找到与目标功能有关的代码或模块；
- 追踪数据如何流转、函数如何调用；
- 解释实现逻辑，并提供对应证据；
- 在理解之后，辅助在自己的项目里实现类似功能。

**“做出类似功能”是后续用途，不等于可以直接复制他人的实现，也不等于 REA 能完整还原任意软件。**

##### 2. 它如何接入 AI：把专业工具变成智能体可调用的能力

REA 本身是一个 **MCP 服务**。MCP 可以理解为 AI 智能体调用外部工具的通用接口：接入后，智能体不仅能回答问题，还能在对话过程中调用 REA 的分析功能。

文章给出的安装命令是：

```bash
npx rea-agents setup
```

安装程序可将 REA 注册到 Claude Code、Codex、Cursor、Gemini CLI、Grok Build 等工具中；修改配置前会先备份，并要求用户确认。不使用智能体，也可以直接在终端运行命令。

这里的分工是：**REA 连接和组织分析能力，专业工具负责解析程序，AI 负责围绕问题追踪、解释和整理结果。**它并不是用一个大模型替代所有逆向工具。

##### 3. 不同软件，分析方法不同

REA 支持的目标很多，但不能用同一种方法处理所有软件。

| 目标类型 | 主要分析方式 |
|---|---|
| 原生程序，即直接编译成机器码的软件 | 借助 Hopper、Ghidra 或 IDA，把机器码转成汇编指令和近似 C 语言的伪代码，再分析逻辑 |
| Electron 桌面应用，如 Notion | 拆开安装包中的 ASAR 归档文件，分析模块和进程间通信，不需要上述反汇编工具 |
| 其他目标 | 还支持 .NET 程序、安卓 APK、固件、网站、网络抓包记录和以太坊合约字节码 |
| 程序运行行为 | 可在 Linux 和 macOS 上记录程序运行时的行为，作为分析依据 |

“伪代码”是工具根据底层指令生成的、便于人阅读的近似代码。它不一定保留原来的变量名、代码结构，也可能不完整，因此仍需要进一步推断和验证。

Electron 应用则不同：它用网页技术构建桌面软件，安装包里通常保留可分析的脚本和资源。研究重点可能不是机器指令，而是“界面触发了什么操作、消息经过哪些模块、最后由哪个进程执行”。

**支持一种文件格式，只说明有分析入口，不代表每个目标都能被完整理解。**

##### 4. 三个案例：从追踪逻辑到验证还原结果

###### DX-Ball：还原一个声音算法，并验证到字节级

在经典打砖块游戏 DX-Ball 中，项目从一次播放音效的调用出发，追踪到根据球的位置计算左右声道的函数，再把不完整的伪代码还原成 C 代码。

验证结果包括：

- **3,205 组测试的结果与原版一致；**
- **编译出的 63 个字节与原版完全相同。**

这比“AI 给出了一段看起来合理的代码”更有说服力：既比较了函数的输出，也比较了编译后的机器码。不过，这些结果针对的是该案例中的函数，不能据此推断整个游戏都已被完整还原。

###### Notion 桌面版：解释复制粘贴经过了哪些层

项目追踪了复制粘贴的完整链路：

**界面 → 预加载脚本 → 进程间通信 → 主进程。**

可以把预加载脚本理解为界面与桌面底层能力之间的一层桥梁；进程间通信则负责在不同进程之间传递消息。这个案例的价值，是把用户看到的一个操作，拆解成内部各层如何协作，而不只是找到某一段代码。

###### 《东方幻想乡》：从老平台指令中还原弹幕算法

项目还分析了日本老电脑 PC-98 上的《东方幻想乡》（TH04），从 16 位指令中还原出弹幕子弹环的角度算法。

这说明它的用途不局限于现代应用，也可以辅助研究老游戏机制和保存旧软件知识。

##### 5. 谁能受益，哪些难题仍然存在

文章认为，比较直接的使用者包括：

- **安全研究人员**：让智能体先追踪调用和行为，人再检查关键证据。
- **老游戏复刻与软件保存者**：研究缺少源码的旧程序，还原具体机制。
- **开发者**：理解现成软件中某个功能的实现方式，作为自己开发的参考。

评论区还有人提出，它可能帮助外包团队在接手缺少文档的老系统前，先了解实现、估算工作量。但这属于使用设想，并非文章已经验证的效果。

###### 混淆过的软件，不一定容易分析

“混淆”是刻意把程序变得难读，但不同类型的混淆需要不同处理方式。

一位评论者特别指出，前端混淆与二进制混淆不能混为一谈。对于混淆过的 JavaScript、WASM、小程序包或请求签名逻辑，仅靠静态查看，可能只能看到大量没有含义的名字和复杂表达式，Ghidra、Hopper 这类工具也未必适用。

这时往往需要**让程序实际运行，再通过断点、拦截函数调用等方式观察真实行为**。该评论者认为，这部分目前仍需要较多手工工作。这个提醒说明：遇到保护措施复杂的目标，不能期待“接上 AI 就自动看懂”；但它也不是对 REA 所有混淆分析能力的完整评测。

##### 6. 使用前必须分清：本地分析、模型数据处理和合法授权

**目标程序不上传，不代表分析内容不会离开本机。**按项目说明，REA 在本机执行分析，不上传目标程序，但分析结果会交给智能体背后的模型服务商。相关数据如何保存和处理，取决于各服务商的政策。分析结果本身也可能包含敏感实现细节。

**技术上能分析，不代表法律或协议上允许分析。**项目声明只支持合法逆向研究，使用者自行承担授权和合规责任。逆向他人的软件可能违反用户协议或版权法规，尤其不能把“研究功能”自动等同于“可以复制实现”。

文章还记录了项目当时的状态：README 显示 GitHub 已有约 **5 万星**，文中称最新版本为 **6.3.0**。这些是发文时的信息，不代表当前状态，也不能仅凭热度判断能力或可靠性。项目同时声明，从未发行或背书任何加密货币，借用 REA 名字的代币与它无关。
