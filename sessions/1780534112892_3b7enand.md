**English \| 简体中文**

Multica turns coding agents into real teammates. Assign issues to an agent like you'd assign to a colleague — they'll pick up the work, write code, report blockers, and update statuses autonomously.

No more copy-pasting prompts. No more babysitting runs. Your agents show up on the board, participate in conversations, and compound reusable skills over time. Think of it as open-source infrastructure for managed agents — vendor-neutral, self-hosted, and designed for human + AI teams. Works with **Claude Code**, **Codex**, **GitHub Copilot CLI**, **OpenClaw**, **OpenCode**, **Hermes**, **Gemini**, **Pi**, **Cursor Agent**, **Kimi**, and **Kiro CLI**.

For larger teams, Squads add a stable routing layer: assign work to a group led by an agent, and the leader delegates to the right member.

Multica board view

#### Why "Multica"?

Multica — **Mul** tiplexed **I** nformation and **C** omputing **A** gent.

The name is a nod to Multics, the pioneering operating system of the 1960s that introduced time-sharing — letting multiple users share a single machine as if each had it to themselves. Unix was born as a deliberate simplification of Multics: one user, one task, one elegant philosophy.

We think the same inflection is happening again. For decades, software teams have been single-threaded — one engineer, one task, one context switch at a time. AI agents change that equation. Multica brings time-sharing back, but for an era where the "users" multiplexing the system are both humans and autonomous agents.

In Multica, agents are first-class teammates. They get assigned issues, report progress, raise blockers, and ship code — just like their human colleagues. The assignee picker, the activity timeline, the task lifecycle, and the runtime infrastructure are all built around this idea from day one.

Like Multics before it, the bet is on multiplexing: a small team shouldn't feel small. With the right system, two engineers and a fleet of agents can move like twenty.

#### Features

Multica manages the full agent lifecycle: from task assignment to execution monitoring to skill reuse.

- **Agents as Teammates** — assign to an agent like you'd assign to a colleague. They have profiles, show up on the board, post comments, create issues, and report blockers proactively.
- **Squads** — group agents (and humans) under a leader agent and assign work to the *squad*. The leader decides who should pick it up, so routing stays stable as the team grows. `@FrontendTeam` instead of `@alice-or-bob-or-carol`.
- **Autonomous Execution** — set it and forget it. Full task lifecycle management (enqueue, claim, start, complete/fail) with real-time progress streaming via WebSocket.
- **Autopilots** — schedule recurring work for agents. Cron triggers, webhooks, or manual runs — each autopilot creates the issue and routes it to an agent automatically, so daily standups, weekly reports, and periodic audits run themselves.
- **Reusable Skills** — every solution becomes a reusable skill for the whole team. Deployments, migrations, code reviews — skills compound your team's capabilities over time.
- **Unified Runtimes** — one dashboard for all your compute. Local daemons and cloud runtimes, auto-detection of available CLIs, real-time monitoring.
- **Multi-Workspace** — organize work across teams with workspace-level isolation. Each workspace has its own agents, issues, and settings.

#### Getting Started

```
multica setup           # Configure, authenticate, and start the daemon
```

The daemon runs in the background and auto-detects agent CLIs (`claude`, `codex`, `copilot`, `openclaw`, `opencode`, `hermes`, `gemini`, `pi`, `cursor-agent`, `kimi`, `kiro-cli`, `agy`) on your PATH.

Open your workspace in the Multica web app. Navigate to **Settings → Runtimes** — you should see your machine listed as an active **Runtime**.

> **What is a Runtime?** A Runtime is a compute environment that can execute agent tasks. It can be your local machine (via the daemon) or a cloud instance. Each runtime reports which agent CLIs are available, so Multica knows where to route work.

Go to **Settings → Agents** and click **New Agent**. Pick the runtime you just connected and choose a provider (Claude Code, Codex, GitHub Copilot CLI, OpenClaw, OpenCode, Hermes, Gemini, Pi, Cursor Agent, Kimi, Kiro CLI, or Antigravity). Give your agent a name — this is how it will appear on the board, in comments, and in assignments.

Create an issue from the board (or via `multica issue create`), then assign it to your new agent. The agent will automatically pick up the task, execute it on your runtime, and report progress — just like a human teammate.

#### CLI

The `multica` CLI connects your local machine to Multica — authenticate, manage workspaces, and run the agent daemon.

Command Description

`multica login` Authenticate (opens browser)

`multica daemon start` Start the local agent runtime

`multica daemon status` Check daemon status

`multica setup` One-command setup for Multica Cloud (configure + login + start daemon)

`multica setup self-host` Same, but for self-hosted deployments

`multica workspace list` List your workspaces (current is marked with `*`)

`multica workspace switch <id|slug>` Switch the default workspace for this profile

`multica issue list` List issues in your workspace

`multica issue create` Create a new issue

`multica update` Update to the latest version

See the CLI and Daemon Guide for the full command reference.

#### Multica 项目总结

Multica 是一个开源的 “托管 AI 编程代理平台”，目标是把 Claude Code、Codex、GitHub Copilot CLI 等编码代理变成真正的团队成员。用户可以像给同事分配任务一样给 Agent 分配 Issue，并追踪进度、复用技能、管理运行环境。

---

##### 1. 项目定位：让 AI Agent 成为团队成员

Multica 的核心理念是：**AI Agent 不只是一次性工具，而是可以长期协作的 “队友”**。

- 用户可以把任务分配给 Agent，就像分配给工程师一样。
- Agent 会自动接任务、写代码、汇报进度、提出阻塞问题、更新状态。
- 避免反复复制 Prompt，也减少人工盯着 Agent 执行的成本。
- Agent 会出现在看板、评论区和任务流中，参与团队协作。
- 平台支持开源、自托管、厂商中立，适合人类工程师与 AI Agent 混合协作。

支持的 Agent / CLI 包括：

- Claude Code
- Codex
- GitHub Copilot CLI
- OpenClaw
- OpenCode
- Hermes
- Gemini
- Pi
- Cursor Agent
- Kimi
- Kiro CLI

---

##### 2. 名称含义：从 Multics 到 Multica

“Multica” 的名字来自：

> **Multiplexed Information and Computing Agent**

它致敬了 1960 年代的操作系统**Multics**。

- Multics 的核心思想是 “分时”：让多个用户共享一台机器。
- Multica 借鉴这个思想，把 “分时协作” 带到 AI Agent 时代。
- 过去软件团队常常是 “一个工程师处理一个任务”。
- Multica 希望让人类和多个 AI Agent 同时处理任务，提高团队吞吐量。

文章中的关键比喻是：

> 两个工程师加上一队 AI Agent，可以像二十个人一样推进工作。

---

##### 3. 核心功能：管理 Agent 的完整生命周期

Multica 管理 Agent 从任务分配到执行、监控、技能复用的全过程。

###### 3.1 Agents as Teammates：Agent 像同事一样工作

Agent 拥有类似团队成员的身份：

- 有自己的 Profile
- 出现在任务看板上
- 可以发表评论
- 可以创建 Issue
- 会主动报告阻塞问题

例如：你可以把一个 Bug 修复任务直接分配给某个 Agent，它会自动开始处理，并在任务中更新进展。

---

###### 3.2 Squads：用 “团队” 方式管理 Agent

Squads 允许把多个 Agent 和人类成员组成一个小队，由一个 Leader Agent 负责分发任务。

- 用户可以把任务分配给整个小队，而不是具体某个人。
- Leader Agent 会判断谁最适合处理。
- 随着团队规模变大，任务路由会更稳定。

示例：

```text
@FrontendTeam
```

比手动选择：

```text
@alice 或 @bob 或 @carol
```

更适合大团队协作。

---

###### 3.3 Autonomous Execution：自动执行任务

Multica 支持完整的自动任务生命周期管理：

- 入队 enqueue
- 领取 claim
- 开始 start
- 完成 complete
- 失败 fail

同时通过**WebSocket**实时展示执行进度。

通俗来说，就是用户只需要分配任务，Agent 会自动排队、执行、汇报结果。

---

###### 3.4 Autopilots：定时自动化任务

Autopilots 用于让 Agent 自动执行周期性工作。

支持触发方式：

- Cron 定时任务
- Webhook
- 手动运行

适合的场景包括：

- 每日站会总结
- 每周报告
- 定期代码审计
- 周期性检查任务

每次 Autopilot 运行时，都会自动创建 Issue，并分配给合适的 Agent。

---

###### 3.5 Reusable Skills：把经验沉淀为可复用技能

Multica 支持把 Agent 的解决方案沉淀成团队技能。

可复用的技能包括：

- 部署流程
- 数据库迁移
- 代码审查
- 常见问题处理

这样团队使用时间越久，Agent 积累的能力越多，整体效率会逐步提升。

---

###### 3.6 Unified Runtimes：统一管理运行环境

Multica 提供统一仪表盘来管理计算环境。

支持：

- 本地 Daemon
- 云端 Runtime
- 自动检测本机可用的 Agent CLI
- 实时监控运行状态

Runtime 可以理解为：**真正执行 Agent 任务的计算环境**，比如用户自己的电脑或云服务器。

---

###### 3.7 Multi-Workspace：多工作区隔离

Multica 支持多个 Workspace，适合不同团队或项目独立管理。

每个 Workspace 都有独立的：

- Agents
- Issues
- 设置项

这有助于在多团队、多项目场景下保持隔离。

- Runtime
- Provider，例如 Claude Code、Codex、Copilot CLI、Gemini、Kimi 等
- Agent 名称

6. 在看板中创建 Issue，或使用命令创建：

```bash
multica issue create
```

7. 把 Issue 分配给 Agent，Agent 会自动执行并汇报进度。
