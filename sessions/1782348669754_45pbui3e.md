## 解读（1）

### 2026-06-25 00:48:40

#### 深度总结

**“Self-harness” 的核心思想：让评测/执行工具自己变好。**

它不是单纯让 Agent 变聪明，而是让围绕 Agent 的 **测试线束、任务环境、评估流程、提示模板、工具调用规则** 等“外部系统”持续优化。

流程很简单：

1. **运行 Agent**  
   观察它在哪里失败、卡住、误判、退化。

2. **挖掘弱点**  
   找出失败原因：提示不清、工具不够、评测不准、流程断裂、上下文不足等。

3. **提出改进**  
   修改 harness：例如加测试、改提示、补工具、增强验证逻辑。

4. **验证改进有效**  
   确认性能提升，同时不能引入新的回归问题。

5. **循环迭代**  
   不断重复，形成自我改进闭环。

一句话：  
> 不是只训练模型，而是让“模型运行的整个系统”自动发现问题、自动修补、自动变强。

---

#### 深入浅出解读

可以把 Agent 看成一个学生，把 harness 看成：

- 考卷
- 答题规则
- 草稿纸
- 工具书
- 评分标准
- 监考与复盘系统

传统做法是：  
**学生考不好，就怪学生不聪明。**

Self-harness 的做法是：  
**学生考不好，要分析是不是题目设计、评分方式、工具支持、复盘机制也有问题。**

例如：

- Agent 经常漏步骤  
  → harness 可以加入 checklist。

- Agent 经常瞎编结果  
  → harness 可以加入验证器。

- Agent 工具调用混乱  
  → harness 可以改进工具说明和调用流程。

- Agent 在某类任务上反复失败  
  → harness 可以自动生成针对性测试集。

所以它的关键不是“单次优化”，而是 **循环工程**：

> 观察失败 → 修改系统 → 验证效果 → 防止回归 → 再观察。

这和软件工程里的 CI/CD、自动化测试、回归测试很像，只是对象变成了 AI Agent 系统。

---

#### 关键价值

##### 1. 把“经验调参”变成“系统迭代”

过去很多 Agent 优化靠人工经验：

- 改 prompt
- 换模型
- 加工具
- 看日志猜问题

Self-harness 试图把这些过程自动化、结构化。

##### 2. 让 Agent 系统越用越好

只要真实运行中不断暴露问题，harness 就能持续吸收失败样本，改善未来表现。

##### 3. 不只优化模型，而是优化“模型+环境”

AI 能力不只来自模型参数，也来自：

- 任务拆解
- 工具编排
- 记忆机制
- 验证机制
- 反馈循环

Self-harness 关注的是完整系统能力。

---

#### 辩证思考

##### 积极面

Self-harness 是 Agent 工程的重要方向。

因为未来 AI 应用的瓶颈，不一定是模型本身，而是：

- 怎么发现失败？
- 怎么定义成功？
- 怎么避免回归？
- 怎么让系统稳定进化？

如果这些能自动完成，AI Agent 会更接近真正可用的工程系统。

##### 风险面

但“自我改进”不等于一定变好。

主要风险有三点：

1. **评估目标错了，优化会越跑越偏**  
   如果评分标准有漏洞，系统可能学会“迎合测试”，而不是真正解决问题。

2. **循环成本很高**  
   不断运行、分析、验证，会消耗大量 token、算力和时间。热门回复里对“循环是否变相增加 token 消费”的质疑并非没有道理。

3. **局部提升可能带来系统退化**  
   某个任务变强，不代表整体更稳。必须有严格的回归测试。

##### 我的判断

Self-harness 的本质不是魔法，而是：

> 把 AI Agent 的优化，从“手工玄学”推进到“自动化工程”。

它真正有价值的地方，不是“AI 自己无限进化”，而是建立一个可靠闭环：

**失败可见 → 改进可控 → 效果可测 → 回归可防。**

如果没有严谨评估，它只是烧 token 的循环；  
如果有高质量验证，它就是 Agent 工程化的基础设施。
