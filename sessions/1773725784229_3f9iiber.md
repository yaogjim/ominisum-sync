作者发现了一个极其反常的现象——如果在使用 Claude Code 时开启系统专门设定的“规划模式 (Planning Mode)”，Opus 的得分只有糟糕的 77% 。

但如果直接切换到“执行模式 (Execution Mode)”并让它去写计划，得分会暴涨 15 分，达到 92% 左右。

这是因为执行模式解除了系统框架对模型的束缚，赋予了 Opus 更多的自由度来构建自己的思维过程。在这种状态下，它会自主衍生子 Agent 或进行内部的差异分析（Gap Analysis），从而产出更严密的规划 。

## 结构化（1）

### 2026-03-17 06:55:20

这篇内容的核心意思是：同一个模型，结果不只取决于模型本身，还强烈取决于“运行方式”或“工具框架”。作者发现，对 Claude Code 来说，看似更适合做规划的“规划模式”，反而可能压制了模型表现。

- 第一部分：作者的核心发现
  - 作者提到一个“反常现象”：在 Claude Code 里开启专门的“规划模式（Planning Mode）”，Opus 得分只有 77%。
  - 但如果改用“执行模式（Execution Mode）”，再让模型自己去写计划，得分会大幅提升到约 92%。
  - 也就是说，只是切换模式，Opus 的表现就提升了约 15 分。

- 第二部分：为什么会出现这种差异
  - 文中解释，执行模式减少了系统框架对模型的限制，给了 Agent 更大的自主空间。
  - 在这种更自由的状态下，Opus 不只是“按指令做规划”，而是会主动组织自己的思考过程。
  - 例如，它可能会自主拆分出子 Agent，或者先做内部“差距分析（Gap Analysis）”，从而形成更严密的规划方案。

- 第三部分：外部案例对这一结论的支持
  - 引用推文中，Matt Maher 比较了前沿模型在 Cursor 和其他 harness（运行框架）中的表现。
  - 结果显示：Cursor 平均可把模型表现提升 11%。
  - 具体数据包括：
    - Gemini：52% → 57%
    - GPT-5.4：82% → 88%
    - Opus：77% → 93%
  - 其测试基准是：看模型完成一个“包含 100 个功能需求的 PRD”实现得如何。
  - 在这个基准下，`Cursor` 持续表现更好。

- 第四部分：文章想传达的实际启示
  - 不要默认“规划任务就该用规划模式”。
  - 对 Agent 类模型来说，过强的系统约束可能反而削弱能力。
  - 更有效的做法，可能是给模型更大的行动自由，让它自己决定如何规划、拆解和分析问题。

如果用一个通俗例子来讲：就像让一个很强的项目经理做方案，若你把流程卡得太死，他只能按模板填表；但如果你只给目标，让他自由组织团队、拆任务、补缺口，最后方案往往更完整。
