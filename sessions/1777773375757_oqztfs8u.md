[Join the Discord](https://discord.gg/6bY6gGX36H)

`codex-plusplus` patches your local Codex.app installation so a small **loader** runs on startup. The loader pulls a **runtime** from your user directory, which discovers and loads **tweaks** (small ESM modules with a manifest + `start/stop` lifecycle). The runtime injects a "Tweaks" tab into Codex's settings UI so you can enable, disable, and configure tweaks in-app.

Everything beyond the one-time install patch lives **outside** the app bundle, so iterating on tweaks is just save-and-reload.

#### Install

Bun:

```
bun install -g github:b-nnett/codex-plusplus
codexplusplus install
```

Source bootstrap (macOS / Linux):

```
curl -fsSL https://raw.githubusercontent.com/b-nnett/codex-plusplus/main/install.sh | bash
```

Windows PowerShell:

```
irm https://raw.githubusercontent.com/b-nnett/codex-plusplus/main/install.ps1 | iex
```

That's it. The installer:

1. Locates your Codex.app (`/Applications/Codex.app`, `%LOCALAPPDATA%/codex/...`, etc.).
2. Backs it up to `~/.codex-plusplus/backup/`.
3. Patches `app.asar` to require our loader.
4. Recomputes the asar header SHA-256 and writes it into `Info.plist` (`ElectronAsarIntegrity`).
5. Flips `EnableEmbeddedAsarIntegrityValidation` in the Electron Framework binary as a belt-and-suspenders.
6. Re-signs the app ad-hoc on macOS (`codesign --force --deep --sign -`).
7. Installs a launch agent / login item that detects app updates and re-runs `repair --quiet`.
8. Installs the default tweak set from their latest GitHub releases unless `--no-default-tweaks` is passed.

The watcher also runs hourly through the GitHub-installed local CLI. If a newer Codex++ GitHub release is available, it downloads the release, rebuilds the local CLI/runtime, and runs `repair` so the runtime in your user directory is refreshed without replacing tweak code. You can turn this off from Settings → Codex Plus Plus → Config.

After source-bootstrap install, the installer adds `codexplusplus` and `codex-plusplus` to a writable PATH directory when possible. Use `codexplusplus` for day-to-day commands:

```
codexplusplus status
codexplusplus repair
codexplusplus update
```

`codexplusplus update` downloads the latest Codex++ GitHub release, rebuilds it, and runs `repair`. If the command is not on PATH yet, rerun the source bootstrap once. Use `codexplusplus update --ref main` only when you intentionally want the current development branch instead of the latest release.

To revert:

```
codexplusplus uninstall
```

Other commands: `status`, `doctor`, `repair`, `tweaks list`, `tweaks open` (opens user tweaks dir).

Codex++ modifies and ad-hoc signs `Codex.app`, so Sparkle cannot safely install an official Codex update while the app is patched. Use:

```
codexplusplus update-codex
```

This restores a Developer ID signed Codex.app for the official updater. After Codex updates and restarts, the watcher re-applies Codex++ to the new app.

Default tweaks currently installed on first run:

- `co.bennett.custom-keyboard-shortcuts` from `b-nnett/codex-plusplus-keyboard-shortcuts`
- `co.bennett.ui-improvements` from `b-nnett/codex-plusplus-bennett-ui`

A tweak is a folder under `<user-data-dir>/tweaks/` with:

```
my-tweak/
├── manifest.json
└── index.js            # or .mjs / .ts (transpiled by runtime)
```

```
{
  "id": "com.you.my-tweak",
  "name": "My Tweak",
  "version": "0.1.0",
  "githubRepo": "you/my-tweak",
  "author": "you",
  "description": "Adds a button.",
  "minRuntime": "0.1.0"
}
```

See `docs/WRITING-TWEAKS.md` for the full API.

#### Tweak updates

Every tweak manifest must include `githubRepo` in `owner/repo` form. Codex++ checks GitHub Releases for each installed tweak at most once per day and shows **Update Available** in Settings → Tweaks when a newer semver release exists.

Codex++ does **not** auto-update tweaks. The manager links to the GitHub release so users can review the diff, release notes, and repository before manually replacing local tweak files.

See `SECURITY.md` for the security model and reporting policy.

Thing Location

Loader stub `Codex.app/Contents/Resources/app.asar` (entry replaced with `loader.cjs`)

Runtime `<user-data-dir>/runtime/` (auto-installed, hot-reloadable)

Tweaks `<user-data-dir>/tweaks/`

Config `<user-data-dir>/config.json`

Backup `<user-data-dir>/backup/`

`<user-data-dir>` per-OS:

- macOS: `~/Library/Application Support/codex-plusplus/`
- Linux: `$XDG_DATA_HOME/codex-plusplus/` (default `~/.local/share/codex-plusplus/`)
- Windows: `%APPDATA%/codex-plusplus/`

See `docs/ARCHITECTURE.md` for details.

#### Codex++：Codex 桌面应用的插件/增强系统

##### 一句话总结

**Codex++ 是一个非官方的 Codex 桌面应用“插件系统”**，通过修改本地 Codex.app，让用户无需重新构建应用，就能注入自定义功能、修复 UI 问题，并在设置中管理插件。

##### 项目定位

Codex++ 面向想要扩展 Codex 桌面端能力的高级用户或开发者。

它的核心价值是：

- 给 Codex 增加「Tweaks」插件管理能力
- 支持启用、禁用、配置自定义插件
- 插件代码独立于 Codex 应用本体，方便快速迭代
- 可用于 UI 优化、快捷键增强、功能补丁等场景

目前项目状态为 **alpha**，架构已设计完成，但安装器还需要更多真实设备测试。

##### 工作原理

Codex++ 会对本地 Codex.app 做一次性补丁：

1. 修改 `app.asar`，让 Codex 启动时加载 Codex++ 的 loader
2. loader 从用户目录加载 runtime
3. runtime 扫描并加载 tweaks 插件
4. 在 Codex 设置页中注入一个「Tweaks」管理标签页

除了一次性的应用补丁外，runtime、插件、配置等都放在用户目录中，因此插件开发和更新不需要反复修改应用包。

##### 安装与使用

项目支持 macOS、Linux、Windows。

常用命令包括：

```bash
codexplusplus status
codexplusplus repair
codexplusplus update
codexplusplus uninstall
```

其中：

- `install`：安装 Codex++ 并 patch Codex.app
- `repair`：修复或重新应用补丁
- `update`：更新 Codex++ runtime
- `uninstall`：卸载并恢复
- `update-codex`：先恢复官方签名版本，再让 Codex 官方更新器工作

安装器还会备份原始应用，并安装一个 watcher，用于检测 Codex 更新后自动重新应用 Codex++ 补丁。

##### 插件机制

每个插件是一个独立目录，包含：

```text
my-tweak/
├── manifest.json
└── index.js
```

`manifest.json` 中定义插件 ID、名称、版本、作者、GitHub 仓库等信息。

插件具备 `start/stop` 生命周期，并以 ESM 模块形式加载。

首次安装时默认包含两个插件：

- 自定义键盘快捷键
- UI 改进插件

##### 更新机制

Codex++ 本身可以自动检测 GitHub Release 并更新 runtime。

但插件不会自动更新。  
Codex++ 只会在设置页提示「Update Available」，用户需要自行查看 GitHub Release、变更说明和代码后手动替换插件文件。

这是一种更偏安全和可控的设计。

##### 风险与限制

这是一个非官方项目，存在明显风险：

- 不隶属于 OpenAI
- 会修改 Codex.app，破坏原始代码签名
- macOS 上可能需要手动允许重新签名后的应用运行
- 官方 Sparkle 更新可能覆盖补丁
- 属于 alpha 阶段，稳定性仍需验证

官方更新 Codex 时，需要通过 `codexplusplus update-codex` 流程处理，避免更新失败或签名冲突。

##### 适合谁使用

适合：

- Codex 桌面端重度用户
- 想增强 Codex UI 或快捷键的人
- 熟悉 Electron、插件机制、GitHub Release 的开发者
- 能接受非官方 patch 风险的技术用户

不太适合：

- 普通用户
- 对安全、稳定性要求极高的生产环境
- 不希望修改应用签名或本地安装包的人

##### 总体评价

Codex++ 本质上是给 Codex 桌面端加了一套类似「插件市场/插件管理器」的能力。  
它解决了官方桌面应用不可扩展的问题，但代价是需要修改应用包、承担签名和兼容性风险。

如果未来稳定性和安全机制成熟，它可能成为 Codex 桌面端生态扩展的重要基础设施。

#### Codex++ 项目解读

##### 一、内容总结

**Codex++** 是一个针对 **Codex 桌面应用** 的第三方插件 / 微调系统。

它的目标是：

- 给 Codex 桌面版增加自定义功能
- 修复 UI 问题
- 添加一个内置的「Tweaks」管理页面
- 不需要重新编译 Codex 应用本身

简单说，Codex++ 会修改本地的 `Codex.app`，让它启动时加载一个外部运行时，然后这个运行时再加载用户安装的各种小插件。

目前项目状态是：

> **Alpha 阶段**，架构已经设计好，但安装器还需要在不同平台上做更多真实设备测试。

---

##### 二、深入浅出解读

###### 1. 它到底做了什么？

Codex++ 的核心思路是：

> 给 Codex 桌面应用“打补丁”，让它支持加载外部插件。

它会在本地 Codex 应用中加入一个很小的加载器。之后真正的插件系统、配置文件、插件代码等，都放在用户目录里，而不是放在 Codex 应用包内部。

这样做的好处是：

- 修改插件时不用重新打包 Codex
- 插件可以热更新或快速调试
- Codex 更新后，可以重新修复补丁

---

###### 2. 安装过程大致做了什么？

安装器会自动执行这些操作：

1. 找到你的 Codex 桌面应用
2. 备份原始应用文件
3. 修改 `app.asar`，让 Codex 启动时加载 Codex++ 的 loader
4. 处理 Electron 的完整性校验
5. 在 macOS 上重新签名应用
6. 安装一个后台 watcher，用来检测 Codex 更新并重新打补丁
7. 默认安装一些官方提供的 tweak 插件

也就是说，它不是普通意义上的“插件安装器”，而是会直接修改 Codex 桌面应用本身。

---

###### 3. Tweak 是什么？

这里的 **tweak** 可以理解为“小插件”或“小功能补丁”。

一个 tweak 通常包含：

```text
my-tweak/
├── manifest.json
└── index.js
```

`manifest.json` 里面声明插件信息，例如：

```json
{
  "id": "com.you.my-tweak",
  "name": "My Tweak",
  "version": "0.1.0",
  "githubRepo": "you/my-tweak",
  "author": "you",
  "description": "Adds a button.",
  "minRuntime": "0.1.0"
}
```

插件可以用于：

- 添加按钮
- 修改快捷键
- 改善界面
- 修复 UI 体验问题
- 增加自定义设置项

---

###### 4. 它支持哪些功能？

Codex++ 提供了一些命令行工具，例如：

```bash
codexplusplus status
codexplusplus repair
codexplusplus update
codexplusplus uninstall
```

常见用途：

| 命令 | 作用 |
|---|---|
| `status` | 查看当前安装状态 |
| `repair` | 修复 Codex++ 补丁 |
| `update` | 更新 Codex++ |
| `uninstall` | 卸载并恢复 |
| `tweaks list` | 查看已安装插件 |
| `tweaks open` | 打开插件目录 |
| `update-codex` | 临时恢复官方 Codex，方便官方更新 |

---

###### 5. 默认安装哪些插件？

首次安装时，Codex++ 会安装一些默认 tweak，例如：

- 自定义键盘快捷键
- UI 改进插件

对应仓库包括：

- `b-nnett/codex-plusplus-keyboard-shortcuts`
- `b-nnett/codex-plusplus-bennett-ui`

---

###### 6. 安全性需要注意什么？

这个项目有一定风险，因为它会：

- 修改 Codex 桌面应用
- 破坏原始代码签名
- 在 macOS 上需要重新签名
- 让应用加载第三方 JavaScript 插件
- 依赖 GitHub Release 检查插件更新

虽然项目会备份原应用，也提供卸载命令，但本质上仍属于“非官方修改”。

官方也明确说明：

> 这是非官方项目，不隶属于 OpenAI，使用风险自负。

---

##### 三、我的意见

我认为 Codex++ 是一个很有潜力的项目，尤其适合以下人群：

- 喜欢折腾桌面应用的开发者
- 想自定义 Codex 使用体验的人
- 想开发 Codex 插件或 UI 改进的人
- 能接受 alpha 软件风险的高级用户

但对于普通用户，我建议谨慎使用。

原因是：

1. **它会修改应用本体**  
   这比普通插件风险更高。

2. **目前还是 alpha 阶段**  
   安装器在不同系统上的稳定性还没有完全验证。

3. **安全风险不可忽视**  
   tweak 本质上是可执行代码，安装第三方 tweak 前应仔细检查来源。

4. **可能影响官方更新机制**  
   Codex 更新时需要用专门命令处理，流程更复杂。

---

##### 四、简短结论

**Codex++ 可以理解为 Codex 桌面版的“插件框架”。**

它让用户可以给 Codex 添加自定义功能，但代价是需要修改本地应用，并承担一定稳定性和安全风险。

如果你是开发者、喜欢自定义工具，可以尝试；  
如果你只是普通用户，建议等项目更成熟后再使用。

###### 摘要
文章介绍了一个名为Codex++的非官方Codex桌面应用插件系统，可通过修改Electron应用包来加载自定义tweak，并提供安装、更新、卸载、插件目录和安全提示等说明。

###### 知识要点
- Codex++通过 patch app.asar 并注入loader来扩展Codex桌面应用
- 插件以ESM模块形式存在，包含manifest和start/stop生命周期
- 项目会备份原应用、重新计算asar完整性、在macOS上重新签名
- 官方Codex更新可能覆盖补丁，需要通过repair或watcher重新应用
