#### OpenWiki：面向 Coding Agent 的开源代码库文档代理

##### 一句话总结

LangChain 推出**OpenWiki**：一个开源 CLI/Agent，可自动为代码库生成、维护文档，并让 Coding Agent 自动读取这些文档，从而在改代码时获得更完整的上下文。

##### 核心价值

OpenWiki 解决的是**AI 编程时代的上下文问题**。

传统文档容易过期，而 Coding Agent 需要理解的不只是 “代码怎么写”，还包括：

- 项目整体结构
- 核心模块职责
- 架构设计逻辑
- 历史变更原因
- PR、Commit、评论中的业务背景

OpenWiki 会把这些信息整理成 repo wiki，让 AI Agent 在开发时自动参考。

##### 使用方式

安装和初始化非常简单：

```bash
npm install -g openwiki
openwiki init
```

初始化过程中可以选择模型提供商，例如 OpenRouter，也支持自定义模型 ID。  
如果配置 LangSmith API Key，还可以追踪 OpenWiki 的每一步运行过程，便于调试和观察 Agent 行为。

##### 文档生成结果

OpenWiki 会在代码库中生成一个`openwiki`目录，其中包含：

- `quickstart.md`：文档入口和项目总览
- 架构说明
- CLI 说明
- Agent 逻辑说明
- 各模块业务逻辑与实现背景
- 文档更新记录

这些文档既包含技术说明，也包含业务决策背景，帮助 Coding Agent 理解 “为什么这样设计”。

##### 自动保持文档更新

OpenWiki 支持通过 GitHub Action 定时更新文档。

它会基于 Git 历史工作：

1. 记录上次文档更新时的 commit hash
2. 扫描之后合并的所有 commit
3. 分析代码变更、PR 描述、评论等信息
4. 自动更新文档
5. 提交 Pull Request

更新频率可按项目节奏调整，例如每天一次、每周一次，或高频项目每几小时一次。

##### 与 Coding Agent 的集成

OpenWiki 会自动创建或更新：

- `AGENTS.md`
- 或 Claude Code 使用的`claude.md`

其中会写入 OpenWiki 文档的位置和使用规则。  
因此，当 Coding Agent 进入代码库时，会自动知道该去读取 OpenWiki 文档，而不需要开发者每次手动提示。

##### 额外能力：直接聊天

除了生成和更新文档，OpenWiki 也可以作为聊天代理使用：

```bash
openwiki
```

用户可以直接询问：

- 当前代码库结构
- 某个模块如何工作
- 文档中有哪些内容
- 如何更新或清理文档

它既是文档生成器，也是 repo 知识问答入口。

##### 产品视角解读

OpenWiki 的关键意义在于：它把 “代码库文档” 从面向人的静态资产，升级为面向 Agent 的动态上下文基础设施。

这类工具未来可能成为 AI 编程工作流的标配，因为：

- Agent 越强，越依赖高质量上下文
- 上下文不能只靠代码本身，还要包含历史和业务逻辑
- 文档维护不能依赖人工，否则一定会过期
- 自动化文档 + 自动注入 Agent 工作流，是更可持续的方案

##### 总结

OpenWiki 是 LangChain 面向 AI 编程场景推出的开源文档代理。  
它通过自动生成、持续更新、集成`AGENTS.md`，让 Coding Agent 始终拥有最新、完整的代码库上下文，从而提升代码修改质量与协作效率。

## 结构化（1）

### 2026-07-22 09:31:11

#### OpenWiki：面向编程智能体的开源代码库文档工具

OpenWiki 是 LangChain 推出的开源智能体与 CLI 工具，可自动为代码库生成、维护文档，并让编程智能体在修改代码时获得更完整的技术背景和业务上下文。它基于 DeepAgents 构建，支持通过 GitHub Action 定期更新文档，也可选用 LangSmith 追踪运行过程。

##### 1. 安装与初始化

- OpenWiki 可通过 NPM 安装，安装后在代码仓库中运行：

  ```bash
  openwiki init
  ```

- 初始化时会进入配置流程：
  1. 选择模型服务商，支持开源与闭源模型提供商。
  2. 填写对应的 API Key。
  3. 选择预设模型，或输入自定义模型 ID。
- 演示中选择了 **OpenRouter** 和 **GLM 5.2**。
- 如果希望官方预设中增加新的模型或服务商，可向开源项目提交 PR。

##### 2. 可选的 LangSmith 运行追踪

- OpenWiki 基于 **DeepAgents** 和 **LangSmith** 构建。
- 用户可以选择填写 LangSmith API Key，将 OpenWiki 的每个操作和运行步骤记录到追踪项目中，方便查看其内部执行过程。
- 此配置不是必需的，可以直接跳过。
- 完成 `init` 配置后，OpenWiki 会立即开始为当前仓库生成初始文档。

##### 3. 生成的文档结构

OpenWiki 会在仓库中创建专门的文档目录，其中包括：

- `quickstart.md`
  - 作为整个文档系统的首页和索引。
  - 概述代码库是什么、解决什么问题，以及哪些文件较为重要。
  - 链接到其他专题文档和实际代码文件。
  - 编程智能体需要了解仓库时，通常会先读取该文件。

- 专题子目录与文档
  - 按代码库的不同部分组织内容。
  - 以 OpenWiki 自身仓库为例，文档涵盖智能体实现、系统架构、CLI、CLI 操作以及文档更新记录等。

这些文档不仅解释代码“如何工作”，还会记录“为什么这样实现”。

##### 4. 补充代码之外的业务背景

- 编程智能体仅阅读代码，通常可以理解具体实现，却未必知道设计决策和业务原因。
- OpenWiki 会结合以下信息生成文档：
  - Git 提交历史；
  - 代码变更；
  - PR 描述；
  - 评论和相关说明。
- 例如，某段代码采用特殊架构可能不是技术限制，而是由历史需求或业务决策造成。OpenWiki 会尽可能将这类背景写入文档，帮助智能体避免做出脱离原始意图的修改。

##### 5. 通过 GitHub Action 自动保持更新

初次生成文档后，无需人工持续维护。OpenWiki 提供可复制的 GitHub Action，默认可设置为**每天运行一次**：

```bash
openwiki update
```

其更新流程为：

1. 记录上一次更新文档时检查到的 Git commit hash。
2. 查找该提交之后合并的所有新 commit。
3. 分析代码变更、PR 描述和评论等信息。
4. 判断哪些文档需要修改。
5. 自动创建一个更新文档的 Pull Request。

运行频率可按仓库活跃程度调整：

- 更新较少的仓库：可改为**每周一次**。
- 每天有数百或数千个提交的仓库：可改为**每 4 小时或 6 小时一次**。

OpenWiki 不依赖固定执行周期，只需读取两个时间点之间的 Git 历史，就能更新文档。

##### 6. 直接与 OpenWiki 智能体聊天

除了初始化和更新命令，还可以直接运行：

```bash
openwiki
```

这会启动交互式聊天界面，用户可以：

- 更换模型服务商；
- 更新或清空文档；
- 查询代码库和现有文档；
- 搜索 OpenWiki 生成的内容；
- 要求智能体对某部分文档进行定向修改；
- 询问类似“你能做什么？”等问题。

因此，OpenWiki 不只是文档生成器，也可以充当代码库文档问答助手。

##### 7. 编程智能体如何自动使用文档

- OpenWiki 会自动创建或修改以下文件：
  - 通用编程智能体使用的 `AGENTS.md`；
  - Claude Code 使用的 `CLAUDE.md`。
- 它会在文件中加入 OpenWiki 文档的引用，并说明智能体应在何时、何处以及如何查阅这些文档。
- 当编程智能体需要代码库上下文时，会先读取上述入口文件，进而找到 `quickstart.md` 和相关专题文档。

完整工作流程是：

1. 运行 `openwiki init`，生成首批文档。
2. 添加 GitHub Action，定期执行 `openwiki update`。
3. 审核并合并 OpenWiki 自动创建的文档更新 PR。
4. 编程智能体读取 `AGENTS.md` 或 `CLAUDE.md`，自动获取 OpenWiki 文档。

这样，开发者无需在每次使用编程智能体时重复提供仓库背景或额外提示。

##### 8. 当前定位与后续计划

- OpenWiki 目前主要面向编程智能体，功能仍较为基础。
- LangChain 计划继续扩展这一“代码库 Wiki”思路。
- 用户可以通过 GitHub 仓库提交：
  - 功能建议；
  - Issue；
  - 代码 PR；
  - 新模型或服务商适配。
