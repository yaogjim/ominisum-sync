Make bare reasonix start interactive sessions

74d0ab6 ·

Reasonix

English · **简体中文** · 指南 · 规格 · [官方网站](https://esengine.github.io/DeepSeek-Reasonix/) · **[Discord](https://discord.gg/XF78rEME2D)**

由配置与插件驱动的极薄 harness——单一静态 Go 二进制，围绕 DeepSeek 的前缀缓存调优，长会话也能把 token 成本压低。

#### 特性

- **配置驱动** ：provider、agent、启用的工具、插件全部在 `reasonix.toml` 中声明， 内核无硬编码模型。
- **多模型 · 可组合** ：DeepSeek（flash/pro）与 MiMo 作为预设内置；任何 OpenAI 兼容 端点都只是一条配置。可选让两个模型协同（执行器 + 规划器），各自独立、缓存稳定的 session。
- **插件驱动** ：外部工具以子进程形式运行，通过 stdio JSON-RPC 通信（MCP 兼容）； 内置工具在编译期自注册。
- **零摩擦分发** ： `CGO_ENABLED=0` 单二进制；一条命令交叉编译到六个目标平台。 唯一依赖是一个 TOML 解析库。

#### 安装

```
npm i -g reasonix                  # 任意系统;自动拉取对应平台的原生二进制
brew install esengine/reasonix/reasonix   # macOS
```

预编译归档(`darwin|linux|windows × amd64|arm64`)和 `SHA256SUMS` 见每个 [GitHub release](https://github.com/esengine/DeepSeek-Reasonix/releases) 。

##### 代码签名

Windows 构建使用 [SignPath 基金会](https://signpath.org/) 提供的免费代码签名证书, 通过 [SignPath.io](https://signpath.io/) 完成签名。

##### 从源码构建

```
make build      # -> bin/reasonix(.exe)
make cross      # -> dist/（darwin|linux|windows × amd64|arm64）
```

#### 快速开始

```
reasonix setup                      # 配置向导 → ./reasonix.toml
export DEEPSEEK_API_KEY=sk-...      # 也可以让 setup 保存到凭据存储
reasonix                            # 然后在会话里运行 /init 生成 AGENTS.md（项目记忆）
reasonix run "把 main.go 里的 TODO 实现掉"
reasonix run --model mimo-pro "给这个函数补单元测试"
echo "解释这段代码" | reasonix run
```

#### 配置

一个最小的 `reasonix.toml` ——一个 provider 加一个默认模型——就够跑起来:

```
default_model = "deepseek-flash"

[[providers]]
name        = "deepseek-flash"
kind        = "openai"
base_url    = "https://api.deepseek.com"
model       = "deepseek-v4-flash"
api_key_env = "DEEPSEEK_API_KEY"
```

优先级为 **flag &gt; `./reasonix.toml` &gt; 用户配置文件 &gt; 内置默认值** ；从 **Reasonix v1.8.1** 开始，用户配置位于 macOS/Linux 的 `~/.reasonix/config.toml` ， Windows 为 `%AppData%\reasonix\config.toml` 。迁移细节见 **配置路径** 。 密钥经环境变量通过 `api_key_env` 注入，绝不写入配置文件；新密钥默认优先保存到系统凭据存储， 不可用时才 fallback 到 Reasonix 管理的凭据文件。项目 `.env` 只作为兼容覆盖读取， Reasonix 不会把新密钥写入项目 `.env` 。权限、沙盒、插件(MCP)、 斜杠命令、 `@` 引用与双模型设置,全部在 **指南** 里。

#### 文档

- **指南** —— 配置、权限与沙盒、插件(MCP)、斜杠命令、 `@` 引用、双模型协同。
- **机器人使用指南** —— 桌面端连接飞书、Lark、微信 Bot，以及 IM 里的审批、YOLO 和命令交互。
- **规格** —— 工程契约:架构、registry、数据类型与路线图。
- **从 0.x 迁移** —— 从 legacy TypeScript 版本迁到 1.0 Go 重写版。
- **Checkpoints 与 rewind** —— 基于快照的编辑安全网 (Esc-Esc / `/rewind`)。

#### DeepSeek-Reasonix 深度总结与解读

##### 一句话总结

**Reasonix 是一个面向 AI 编程/长会话任务的轻量级命令行工具，用 Go 写成，靠配置和插件扩展，重点优化 DeepSeek 的前缀缓存，以降低长对话 token 成本。**

---

##### 深度总结

###### 1. 它是什么

Reasonix 是一个 **极薄 AI Agent Harness**：

- 本体很轻：单个静态 Go 二进制文件；
- 不绑定具体模型：模型、工具、插件都通过 `reasonix.toml` 配置；
- 面向开发场景：可读代码、改代码、补测试、执行命令；
- 适合长会话：围绕 DeepSeek 前缀缓存做优化，降低 token 消耗。

---

###### 2. 核心特点

| 特性 | 含义 |
|---|---|
| 配置驱动 | provider、agent、工具、插件都写在配置里 |
| 多模型支持 | 内置 DeepSeek、MiMo，也支持任意 OpenAI 兼容接口 |
| 双模型协同 | 可用一个模型规划，一个模型执行 |
| 插件化 | 外部工具通过子进程 + JSON-RPC 接入，兼容 MCP |
| 易分发 | Go 单二进制，无复杂依赖 |
| 安全设计 | API Key 优先走环境变量或系统凭据存储 |
| 编辑保护 | 支持 checkpoints 与 rewind，方便回滚修改 |

##### 深入浅出解读

可以把 Reasonix 理解成：

> **一个给程序员用的“AI 命令行工人调度器”。**

它本身不强调“我有多聪明”，而是负责把这些事做好：

1. **接入模型**  
   DeepSeek、MiMo、OpenAI 兼容接口都能接。

2. **管理上下文**  
   尤其适合长项目、长对话，尽量减少重复 token 成本。

3. **调用工具**  
   可以接插件、MCP 工具、内置命令，让 AI 不只是聊天，而是能干活。

4. **保护项目**  
   通过快照和回滚机制，降低 AI 改坏代码的风险。

5. **统一配置**  
   所有能力通过 `reasonix.toml` 管理，避免硬编码。

---

##### 它的价值

###### 对个人开发者

- 快速把 AI 引入本地开发流；
- 可用命令行处理代码任务；
- 成本更可控；
- 配置简单，安装方便。

###### 对团队/工程项目

- 模型供应商可替换；
- 插件体系更适合工程化；
- 支持权限、沙盒、MCP，便于规范使用；
- 双模型模式有利于复杂任务拆分。

---

##### 辩证思考

###### 优点

1. **轻量化方向正确**  
   单二进制、少依赖，降低安装和部署门槛。

2. **配置驱动很适合工程化**  
   不把模型写死，方便切换供应商和内部模型。

3. **重视成本控制**  
   前缀缓存优化切中长会话痛点。

4. **插件/MCP 兼容有前瞻性**  
   AI Agent 的关键不只是模型，而是工具生态。

5. **安全意识较强**  
   API Key 不直接写入项目配置，优先用系统凭据存储。

---

###### 局限

1. **依赖模型能力本身**  
   Reasonix 是 harness，不是模型。模型弱时，结果仍然弱。

2. **配置门槛仍存在**  
   对非技术用户，TOML、provider、MCP、沙盒等概念并不轻松。

3. **插件生态决定上限**  
   工具接口设计得再好，如果插件少，实际能力也有限。

4. **长会话成本只能优化，不能消失**  
   前缀缓存能省钱，但复杂任务依然会消耗大量 token。

5. **AI 改代码仍需审查**  
   checkpoint/rewind 是安全网，不等于 AI 修改一定可靠。

---

##### 总体判断

Reasonix 的定位不是“又一个聊天机器人”，而是：

> **面向开发者的轻量级、可配置、可扩展 AI Agent 运行框架。**

它的核心竞争力在于：

- 轻；
- 可配置；
- 可接多模型；
- 可接工具；
- 适合长会话降成本；
- 更贴近真实开发工作流。

如果你需要的是一个简单聊天工具，它可能偏工程化；  
如果你需要的是一个能嵌入日常开发流程的 AI 命令行助手，它的设计方向很有价值。
