**Nicolas Bustamante**

### 我的个人生活自动化代理栈

我的代理管理我的电子邮件、短信、WhatsApp、Telegram 以及几乎所有事情，以实现我的个人生活自动化。

人们一直问我在现实生活中如何使用助手。我的意思是那些真正无聊的事情，却让一天飞逝而过：阅读 WhatsApp 和 Telegram 的消息，查找某人的电子邮件，上网搜索，撰写介绍内容，更新 Google Drive 中的文档，创建日历事件，查看谁还需要回复，以及在我已经使用的那些同样杂乱的工具中完成所有这些事情。

我的回答令人失望地简单。我将 Codex 用作我实际生活数据之上的操作工具。它具备工具、数据连接器、技能和事实源，拥有足够的本地操作权限，并且设有足够的审批环节以确保不会在公开场合让我难堪。

这基本上就是整个配置了。工具、数据连接器、技能和品味。

我以前在 Claude Code 中更多地做这类工作，但现在我正在将配置转移到 Codex，因为目前 GPT-5.5 是更适合这类工作的模型。从 Claude Code 切换到 Codex 其实并不是重点，重点在于，一旦一个模型足够好，真正的价值在于将其整合到你所处的现实世界中。

```markdown
MY PERSONAL AGENT STACK
=======================

agent:
  Codex

tools:
  Gmail / Drive / Calendar / Docs / Sheets  -> gog
  WhatsApp                                  -> wacli
  Telegram                                  -> Telegram connector
  iMessage / SMS                            -> imsg
  Browser / Chrome                          -> browser automation
  macOS apps                                -> AppleScript / UI automation
  local files                               -> filesystem tools

data:
  Google Drive as source of truth
  contacts in a Google Sheet mirrored as CSV
  Notion exported into Drive
  local memories and instructions

skills:
  inbox-zero
  contacts
  google-workspace
  imessage-cli
  personal admin workflows
```

重要的是，代理能够跨越边界。 我的个人生活并不集中在一个应用中。它分散在 Gmail、WhatsApp、Telegram、iMessage、Google Drive、Calendar、Notion、本地文件、随机 PDF 文件、浏览器会话以及一个联系人电子表格中，而这个电子表格的价值远比看起来要高得多。

#### 一个真实的沟通例子

几天前，一位朋友给我发了一条 WhatsApp 消息。她当时正在帮助一家迅速发展的旧金山人工智能初创公司在法国招聘，并希望将他们的招聘经理与我认识的一位招聘人员对接。我不记得那位招聘人员的邮箱了，也不清楚这家初创公司最新的融资情况。我需要搜索 WhatsApp、搜索 Gmail、找到那位招聘人员的邮箱、上网搜索、了解这家初创公司为何值得信赖、撰写一封介绍邮件、附上两个职位链接、把草稿发给我看、获得批准后发送邮件，然后给朋友发消息告知事情已完成。

那通常是长达二十分钟的令人厌烦的应用切换。从 WhatsApp 到 Gmail，再到 Google 搜索，然后回到 Gmail，再回到 WhatsApp。这并不算是繁重的工作，但这正是那种会消耗注意力的工作，因为每一步都是一次小小的上下文切换。

借助这个代理，我请求得到结果。它读取了 WhatsApp 的对话记录，搜索了 Gmail 中的招聘人员邮箱，研究了这家初创公司的融资情况和网上的最新新闻，起草了介绍内容，等待我的批准，发送了邮件，然后给朋友发消息说介绍内容已经完成。面向用户的部分花了大约十秒钟。这个代理完成了连接性的工作（几秒钟就搞定了！）

这是杀手级模式。代理不是在“回答问题”。它通过我的工具运作，以完成一个小型的现实世界工作流（即“待完成的任务”）

#### 车牌示例

另一个例子更无聊，这正是我喜欢它的原因。我给我的车换了一个新的车牌。我把照片和背景信息发送给了 Codex。它更新了我保存在谷歌云端硬盘中的汽车信息 Markdown 文件，更换了车牌，添加了注册备注，保留了现有的车辆识别码（VIN）、保险、车主和地址信息，然后将文件上传回谷歌云端硬盘。

这本身就很有用，但更好的版本是接下来发生的事情。该代理可以使用浏览器自动化在其他所有地方更新相同的信息：FasTrak、停车应用、保险门户网站、与车辆管理局相关的表格，或任何其他没有清晰 API 的网页应用。对于有清晰 API 的系统，它应该使用 API 或 CLI。对于复杂系统，它可以使用浏览器，而且效果非常好！我现在也使用 Codex 的 Computer Use。

这就是个人代理的用途。不是戏剧性的自主性，而是管理连续性。我一直担心后台的 Openclaw YOLO 模式。我很重视掌控感。

#### Google Drive 是我的真理来源

我做出的最重要的架构决策是将有价值的个人信息集中存储在谷歌云端硬盘中。多年来，我的很多知识都保存在 Notion 中。我喜欢 Notion 作为人类的工作空间，但并不把它当作智能体的主要事实来源。API 虽然可用，但工作空间过于动态：嵌套页面、数据库、属性、权限、格式、反向链接，以及大量原生 UI 结构——这些对人类友好，却对模型不友好。

所以我使用 Notion API 导出了有价值的信息，并将其转移到 Google Drive。我并不试图完美地保留 Notion 的工作区。 我试图让这些信息对智能代理可读。Google Drive 中的大部分有用信息是 Markdown 或 CSV 格式，因为这些格式便于智能代理进行搜索、差异比较、编辑以及无需繁琐操作地重新上传。Google Drive 成为了事实来源，因为 gogcli 为智能代理提供了一个简单的命令行界面，用于访问 Gmail、Drive、Calendar、Docs、Sheets、Contacts 和 Tasks。

这是一个被低估的点。你不应该仅为人类用户界面组织你的知识，而应该为代理的工具路径组织知识。代理需要稳定的文件 ID、文本、表格、Markdown、CSV 文件以及返回 JSON 的命令。如果代理能够搜索、下载、编辑、上传该数据，并引用其来源，那么该数据就是有用的。

我的个人数据层简单得有些寒酸。Google Drive 存储着重要文档，主要以 Markdown 文件和 CSV 文件的形式。联系人存储在一个 Google 表格中，该表格被镜像为 CSV 文件。Notion 导出文件存储在 Drive 中。本地指令存储在 AGENTS.md 中。技能以 Markdown 文件的形式存储在文件夹中。事实的来源并不优雅，但很清晰。

```markdown
DATA LAYER
==========

Google Drive:
  personal docs
  car docs
  family docs
  exported Notion pages
  PDFs
  spreadsheets
Google Sheets / CSV:
  contacts
  phone numbers
  emails
  categories
  locations
  notes

Local files:
  AGENTS.md
  memories
  skills
  scripts
  blog repo
```

很多个人生产力其实就在于整合这些数据。一个信息在 WhatsApp 中，另一个在 Gmail 里。电子邮件地址在通讯录中，日期在日历中，文档在 Drive 中。当这个助手能够跨越这些边界，而不需要我充当粘合剂时，它才变得有用。

我最好的投资之一是创建一个包含我认识的所有人的电话号码、邮箱、LinkedIn 等信息的 contact.csv 文件。

#### 工具

核心工具设计上很枯燥。我使用

[gogcli](https://github.com/steipete/gogcli) 用于 Google Workspace，

[wacli](https://github.com/steipete/wacli)

用于 WhatsApp，

[imsg](https://github.com/openclaw/imsg)

用于 iMessage 和 SMS，

[浏览器使用](https://github.com/browser-use/browser-use)

或者使用浏览器自动化工具处理网页应用，以及在没有更好的界面时使用 AppleScript 或 macOS 界面自动化。

层级结构很简单。API 和 CLI 是最佳选择。本地文件很不错。浏览器自动化是可以接受的。屏幕自动化是最后手段。

```markdown
BEST TOOL SURFACE
=================

API and CLI
  >
local file
  >
browser automation
  >
screen automation
```

这种层级结构很重要，因为代理的可靠性仅取决于其工具界面。让模型在网站上点击操作有时是必要的，但这不是理想路径。像这样的命令 gog gmail messages list 或 wacli messages list --json 对模型来说，检查、重试和推理要容易得多。

这是工具层在实际应用中的样子：

```markdown
# Gmail
gog gmail messages list '"Firstname Lastname"' --max 10 --include-body
gog gmail get <messageId>
gog gmail send --to robin@example.com --subject "Intro" --body-file draft.txt

# Drive
gog drive search "lexus_rx_info.md"
gog drive download <fileId>
gog drive upload ./file.md --replace <fileId>

# WhatsApp
wacli chats list --query "Friend Name" --json
wacli messages list --chat 16282358390@s.whatsapp.net --limit 20 --json
wacli send text --to 16282358390@s.whatsapp.net --message "Done"

# Telegram
# same pattern: list chats, read history, search, draft, send after approval

# Calendar
gog calendar create primary \
  --summary "Picnic in Golden Gate Park" \
  --from "2026-05-31T11:00:00-07:00" \
  --to "2026-05-31T13:00:00-07:00"
```

这一切看起来都不像是科幻。这正是关键所在。个人代理的未来始于一堆命令，这些命令让模型能够操作你已经在使用的工具。你希望最大限度地减少模型与 API 之间的抽象层。

#### 技能

工具赋予代理双手，技能赋予它习惯。一种技能就像是一份小型操作手册，告诉代理如何按照我喜欢的方式完成重复性任务。

我的 inbox-zero 技能是一个很好的例子。它指示代理通过 gog 列出 Gmail 收件箱中的邮件，将自动归档与待审核区分开，向我展示重要的电子邮件，引用内容要点，建议归档或回复，起草回复，等待明确的批准，在原始线程中发送，保留所有收件人，仅在发送后进行归档，保持回复简短，除非我要求，否则绝不建议通话，并以"Nicolas"署名。

那不是一个花哨的架构。它是一个流程。但是这个流程就是产品，而且……它只是文本说明。

没有这项技能时，我每次都得亲自提醒。我得提醒代理不要未经批准就发送邮件，不要遗漏抄送收件人，不要建议打电话，也不要用奇怪的公司签名。有了这项技能后，我只需说 run inbox zero,"，工作流程就已经包含了我的偏好。

重要的习惯是，每次代理出错时我都会提升技能。如果它在我讨厌通话时建议通话，我就添加该规则。如果它忘记保留抄送收件人，我就添加该规则。如果它归档过于激进，我就收紧分类。代理之所以变得更好，是因为流程变得更好了。

这就是个人代理变得个性化的方式。不是靠拥有可爱的声音，而是通过积累操作品味。

```markdown
TOOLS + DATA CONNECTORS + SKILLS + FEEDBACK
===========================================

tool fails once
  v
fix the tool or add a guardrail

agent makes a judgment mistake
  v
update the skill

agent forgets a preference
  v
write it into memory or AGENTS.md

workflow repeats
  v
personal agent improves
```

设置过程会恶化，因为错误变成了指令。

#### 审批关卡是产品

我不想要一个盲目回复所有人的代理。我想要一个能够准备工作、给我看草稿并在合适时机询问的代理。对于大多数沟通工作流程，流程是：读取上下文、草拟回复、给我看、等待审批、发送、确认。

有时，当风险较低时，我会直接发送。“告诉雨果我下周在西雅图”这类消息不需要开董事会。但给投资者的邮件、给客户的回复、介绍性内容，或者任何带有社交含义的内容，都应该先起草。

这是有用和可怕之间的区别。只读扫描是一个信任层级。起草是另一个。发送是另一个。删除、支付、签署或更改账户设置是完全不同的层级。未来不是“代理做所有事情”。未来是“代理做繁琐的工作并在适当的时候询问”。

#### 杀手级工作流：我错过了什么？

杀手级工作流不是电子邮件。它是生活收件箱的优先级分类。每隔几小时，我想询问，“我错过了什么？”并让助手扫描 WhatsApp、Telegram、Gmail、短信、日历以及相关的云端硬盘变更。然后我希望它告诉我谁需要回复、什么是紧急的、什么是过时的、什么可以忽略、什么应该转为日历事件，以及什么需要进行文档搜索。

这是一个完美的代理任务，因为它上下文密集、重复性高、跨工具操作，且充满小决策。人类讨厌做首次尝试，而代理擅长进行首次尝试。决策权仍然在我这里。

结果不是让我的生活变得自主。结果是我不再是那个需要手动在五个应用中查找三件重要事情的人。

如果有人想要复制我的配置，这是清单。安装 Codex。安装

[gogcli](https://github.com/steipete/gogcli) 用于谷歌工作区。安装

[wacli](https://github.com/steipete/wacli)

用于 WhatsApp。如果使用 Telegram，请安装 Telegram 连接器。安装

[imsg](https://github.com/openclaw/imsg)

用于 iMessage 和短信。添加浏览器自动化，理想情况下通过 Browser Use 或 Chrome 控制器实现。通过 AppleScript 和 UI 脚本添加 macOS 自动化。如果你的知识存储在 Notion 中，使用 Notion API 将有价值的部分导出到谷歌云端硬盘。

然后集中数据。让 Google Drive 成为事实的来源。将联系人保存在 Google Sheet 或 CSV 中。将重要的个人文档保存为可搜索的文件。保留本地 AGENTS.md 说明。保留用于重复工作流程的小技能。

然后谨慎地授予权限。本地文件和应用数据库需要完整磁盘访问权限。屏幕录制作为视觉备选方案很有用。在应用中点击和输入需要辅助功能权限。这些是重要的权限，因此需要与严格的审批关卡配合使用。

然后编写操作规则。

```markdown
# Personal Agent Rules

- Draft before sending important messages.
- Sign emails as Nicolas.
- Use gog for Gmail, Drive, Calendar, Docs, and Sheets.
- Use wacli for WhatsApp.
- Use the Telegram connector for Telegram.
- Use imsg for SMS and iMessage.
- Use the contacts CSV for email and phone lookup.
- Prefer APIs and CLIs over browser automation.
- Do not expose private data unless asked.
- Confirm after sending.
```

基本上就是这些了。工具、数据连接器、技能、审批门控和持续改进。

#### 这是新的操作系统

个人电脑过去是通过应用程序操作的。你打开应用、搜索、点击、复制、粘贴、撰写和发送。而由代理操作的电脑则感觉完全不同。你陈述意图，代理收集上下文，提出操作建议，必要时等待批准，执行操作并反馈结果。

一旦体验过这种方式，旧方法就会显得很荒谬。为什么我要手动搜索 WhatsApp、Gmail、Google Drive 和网页来发送一条介绍信息？为什么我要把车牌号复制到五个不同的网站？为什么我要阅读 100 条消息才能找到三条重要的？

计算机应该做那个。

配置仍然很丑陋。CLI 很粗糙。权限很烦人。有些连接器会损坏。浏览器自动化很脆弱。你必须编写脚本。你必须维护一个事实来源。但这就是未来通常的开端方式。

第一个有用的个人代理不会看起来像精致的消费级应用。它们会看起来像终端内部的一个模型，能够访问你的文件、账户、记忆和工具。

这就是我现在使用的东西，每周我都要为它投入更多的生活片段来操作。

8. 如果知识存储在 Notion 中，用 Notion API 导出到 Google Drive；
9. 谨慎授予权限，如完整磁盘访问、屏幕录制、辅助功能权限；
10. 设置严格审批关卡。

作者还建议编写个人代理规则，例如：

```markdown
# Personal Agent Rules

- 重要消息先起草，不要直接发送。
- 邮件署名使用 Nicolas。
- Gmail、Drive、Calendar、Docs、Sheets 使用 gog。
- WhatsApp 使用 wacli。
- Telegram 使用 Telegram connector。
- SMS 和 iMessage 使用 imsg。
- 查找邮箱和电话时使用 contacts CSV。
- 优先使用 API 和 CLI，而不是浏览器自动化。
- 未经要求不要暴露私人数据。
- 发送后要确认。
```

##### 11. 作者的最终判断：这是新的操作系统

作者认为，由代理操作的电脑会带来完全不同的体验。

过去，人要打开应用、搜索、点击、复制、粘贴、撰写、发送。  
现在，人只需要表达意图，代理负责收集上下文、提出操作建议、请求审批、执行并反馈结果。

他认为旧方式会逐渐显得荒谬：

- 为什么要手动搜索 WhatsApp、Gmail、Drive 和网页才能发一封介绍邮件？
- 为什么要把车牌号复制到五个网站？
- 为什么要读 100 条消息才能找到 3 条重要信息？

不过作者也承认，现在的配置还很粗糙：

- CLI 不够精致；
- 权限设置麻烦；
- 连接器会出错；
- 浏览器自动化脆弱；
- 需要写脚本；
- 需要维护事实来源。

但他认为，这通常就是未来技术的早期形态。

作者展示的个人代理并不是一个漂亮的消费级 App，而更像是一个运行在终端里的 AI 模型，能够访问文件、账户、记忆和工具。它的价值在于帮人处理跨应用、重复、琐碎但高频的生活任务，同时通过审批机制保留人的控制权。

##### 二、关键能力，是跨越不同应用之间的边界

因此，个人代理的“杀手级模式”不是单纯回答问题，而是通过工具，完成一个小型的现实世界工作流。

##### 三、另一个案例，是更新一辆车的全部相关信息

更重要的是，代理不只适合沟通，也适合处理那些非常无聊的连续性工作。

作者给自己的车换了一个新车牌。他把车牌照片和背景信息发给 Codex。代理随后更新了 Google Drive 中保存的汽车信息 Markdown 文件，替换车牌号码，添加注册备注，同时保留车辆识别码，也就是 VIN，连同保险、车主和地址等原有信息。

Markdown 是一种结构简单、便于编辑的文本格式。对人来说，它看起来可能不如专门的数据库漂亮，但对代理来说，更容易搜索、比较差异和修改。

更有价值的是，更新文件只是第一步。代理还可以使用浏览器自动化，把新的车牌信息同步到其他系统，比如 FasTrak、停车应用、保险门户网站，以及车辆管理部门的网页表格。

对于提供清晰接口的系统，作者主张优先使用 API 或命令行工具。API，就是软件之间直接交换数据的接口；命令行，则是通过文字指令操作软件。对于复杂、没有清晰 API 的系统，可以使用浏览器自动化。作者还在使用 Codex 的 Computer Use，也就是让代理通过类似人操作电脑的方式完成任务。

作者认为，这就是个人代理的实际用途。它不需要表现出戏剧性的完全自主，而是负责维护生活中的连续性：同一份信息改了之后，能够在相关地方都保持一致。

他同时强调，自己很重视掌控感，也一直担心类似 OpenClaw 这类不受限制的全自动运行模式。对他来说，代理应该帮忙做事，但不能让人失去控制。

##### 四、数据架构的核心，是建立一个清晰的事实来源

然后，作者介绍了整套系统中最重要的架构选择：把有价值的个人信息集中放在 Google Drive 中。

过去，他有很多知识存放在 Notion。作者喜欢 Notion 作为人类使用的工作空间，但不把它当作智能代理的主要事实来源。

原因是，Notion 的结构虽然方便人使用，却比较复杂。它包括嵌套页面、数据库、属性、权限、格式、反向链接，以及大量依赖原生界面的结构。这些内容对人很直观，但对模型来说，不一定容易稳定地搜索和编辑。

因此，作者通过 Notion API，把有价值的信息导出到 Google Drive。这里的 API，可以理解为让一个软件读取或操作另一个软件数据的标准通道。

他并不追求完整保留 Notion 的原始工作区，而是追求让信息更容易被代理理解和处理。导出的内容主要采用 Markdown 和 CSV 格式。

作者把 Google Drive 称为“事实来源”，也就是当不同地方的信息不一致时，优先以它为准。之所以能这样做，还因为 gogcli。它是一个命令行工具，能让代理访问 Gmail、Drive、Calendar、Docs、Sheets、Contacts 和 Tasks，也就是邮件、云端文件、日历、文档、表格、联系人和任务。

作者特别提到，自己做过的一项高价值工作，是建立一个 contact.csv 文件，里面记录认识的人的电话号码、邮箱、LinkedIn 信息，以及其他分类、地点和备注。

这份联系人文件看起来很普通，但作用很大。代理需要写邮件时，可以从里面查邮箱；需要发短信时，可以查电话号码；需要判断某个人是谁时，还可以结合分类和备注。

作者的结论是，很多个人生产力问题，本质上不是写作问题，而是整合问题。一个信息在 WhatsApp，另一个在 Gmail；邮箱在联系人表格里，日期在日历里，背景材料在 Drive 里。只有当代理能够跨越这些边界，而不需要人来充当“粘合剂”，它才真正有用。

##### 五、工具越接近原始接口，代理通常越可靠

接下来是工具层。

作者使用 gogcli 处理 Google Workspace，使用 wacli 处理 WhatsApp，使用 imsg 处理 iMessage 和短信，使用 Telegram 连接器处理 Telegram。网页应用则通过浏览器自动化操作。没有更好接口时，再使用 AppleScript 或 macOS 界面自动化。

AppleScript 是苹果系统中的脚本工具，可以让程序控制部分应用。界面自动化则是让软件模拟点击、输入等电脑操作。

作者给出了一个清晰的工具优先级：

第一选择，是 API 和命令行工具。  
第二选择，是本地文件。  
第三选择，是浏览器自动化。  
最后才是屏幕自动化，也就是让代理像人一样看屏幕、点击和输入。

这个层级很重要，因为代理的可靠性，很大程度上取决于工具接口是否清晰。

例如，通过命令行直接列出 Gmail 邮件，或者以 JSON，也就是结构化数据格式，列出 WhatsApp 消息，模型更容易检查结果、重试操作和进行推理。相比之下，让模型在网页上寻找按钮、点击菜单，虽然有时不可避免，但更容易受到页面变化影响。

作者的原则很简单：尽量减少模型和真实数据之间的抽象层，让模型直接操作它已经在使用的工具。

这套系统听起来并不像科幻。它更像是一组命令，让模型可以读取邮件、搜索文件、查看聊天记录、创建日历事件，以及在批准之后发送内容。但作者认为，个人代理的未来，很可能就是从这些看起来普通的命令开始的。

##### 六、技能不是复杂架构，而是写下你的工作习惯

工具相当于给代理装上了“手”，而技能则赋予它固定的做事习惯。

作者所说的“技能”，本质上是一份小型操作手册，告诉代理应该按照什么方式完成重复任务。它不一定是复杂的软件架构，很多时候只是一些文本说明。

例如，在没有技能之前，作者每次都要提醒代理：重要邮件必须先起草，不能未经批准就发送；不要漏掉抄送收件人；不要建议打电话；不要使用奇怪的公司签名。

有了相应技能之后，他只需要说“运行收件箱清零流程”，代理就能按照已经写好的偏好执行。

“收件箱清零”指的是系统地处理收件箱：判断哪些需要回复，哪些可以归档，哪些需要转成任务，哪些可以忽略，而不是简单地把所有消息都删除。

技能还会通过错误不断改进。

如果代理在作者不喜欢打电话的情况下建议打电话，作者就把这条偏好写进规则。如果代理忘记保留抄送人，也把这条规则补进去。如果代理归档得太激进，就收紧分类标准。

作者总结说，代理越来越好，并不只是因为模型变聪明了，也因为流程变得更清晰了。

这种个性化，不是给代理配一个可爱的声音，而是让它逐渐积累一个人的操作品味。工具失败时，就修工具或增加防护；代理判断错了，就更新技能；代理忘记偏好，就把偏好写入记忆或 AGENTS.md；某项工作反复出现，就把它固化成流程。

##### 七、审批关卡决定了代理是有用，还是令人害怕

再往下，作者把审批机制称为产品的一部分。

他不想要一个自动回复所有人的代理，而是希望代理先准备工作，展示草稿，并在适当时机询问。

大多数沟通工作流程可以分成六步：先读取上下文，再起草回复；然后把草稿展示给人；等待批准；发送；最后确认已经完成。

当然，不是所有消息都需要同样严格的审批。

如果只是告诉朋友“我下周在西雅图”，这类低风险消息可以直接发送，不需要复杂确认。但给投资者的邮件、给客户的回复、介绍性质的邮件，或者任何带有明显社交影响的内容，都应该先起草，再等待批准。

不同操作，也应该处在不同的信任等级。

只读扫描，是一个层级。起草内容，是另一个层级。发送消息，又是更高的层级。删除文件、付款、签署文件，或者更改账户设置，则属于完全不同的高风险层级。

作者的核心判断是：未来不是“让代理做所有事情”，而是“让代理做繁琐的工作，并在合适的时候询问人”。

这样，代理可以承担大量重复劳动，但最终的决策权仍然保留在人手里。

##### 八、最有价值的流程，是定期询问“我错过了什么”

作者认为，最有潜力的工作流甚至不是写邮件，而是管理一个“生活收件箱”。

他希望每隔几个小时问代理一句：“我错过了什么？”

代理随后扫描 WhatsApp、Telegram、Gmail、短信、日历，以及 Google Drive 中相关的变化，再告诉他：

谁还需要回复；  
什么事情紧急；  
哪些内容已经过时；  
哪些消息可以忽略；  
什么内容应该转成日历事件；  
哪些事情需要进一步搜索文件或背景资料。

这是非常适合代理的任务。因为它同时具备几个特点：上下文很多，重复发生，需要跨多个工具，而且包含大量小判断。

人通常不喜欢做这种第一次整理工作。代理却擅长先把材料收集起来，进行初步分类，再提出建议。

但作者仍然保留最终决策权。结果并不是让生活完全自主运行，而是让自己不再需要手动打开五个应用，寻找三件真正重要的事情。

##### 九、复制这套配置，需要工具、权限和规则三部分

如果有人想复制作者的配置，第一步是安装 Codex。

然后，根据自己使用的服务，安装相应工具：用 gogcli 连接 Google Workspace；用 wacli 连接 WhatsApp；用 Telegram 连接器处理 Telegram；用 imsg 处理 iMessage 和短信。

接着，加入浏览器自动化，理想情况下使用浏览器控制器或 Browser Use 一类工具。对于 macOS 应用，则可以加入 AppleScript 和界面脚本。

如果个人知识主要存放在 Notion 中，就通过 Notion API，把有价值的内容导出到 Google Drive，而不是强求代理直接操作复杂的 Notion 工作区。

第二步是谨慎授予权限。

本地文件和应用数据库可能需要完整磁盘访问权限。屏幕录制权限可以作为视觉操作的备选方案。要让代理在应用里点击和输入，还需要辅助功能权限。

这些权限都很重要，因此必须配合严格的审批关卡。权限越大，越不能只依赖模型自己的判断。

第三步是写下具体的操作规则。

比如，重要消息发送前必须先起草；邮件统一使用指定签名；Google 的邮件、云盘、日历、文档和表格优先使用 gogcli；WhatsApp 使用 wacli；Telegram 使用对应连接器；短信和 iMessage 使用 imsg；查找邮箱和电话时使用联系人 CSV；优先使用 API 和命令行，而不是浏览器自动化；除非得到明确要求，不要暴露私人数据；发送完成后，要向用户确认。

作者认为，基本配置就是这些：工具、数据连接器、技能、审批门控，以及持续改进。

##### 十、这代表了一种新的电脑使用方式

最后，作者把这套系统称为一种新的电脑操作方式。

过去，人们通过应用程序操作电脑：打开应用，搜索内容，点击按钮，复制粘贴，写作，然后发送。

由代理操作的电脑则不同。人只需要表达意图，代理负责收集上下文，提出行动方案，在必要时等待批准，执行操作，并反馈结果。

体验过这种方式之后，很多传统操作会显得低效。为什么人要手动搜索 WhatsApp、Gmail、Google Drive 和网页，只为了发送一封介绍邮件？为什么要把一个新车牌号，手动复制到五个不同的网站？为什么要读完一百条消息，才能找到其中三条重要内容？

这些连接和整理工作，本来就应该由计算机来完成。

当然，作者也承认，当前配置还很粗糙。命令行不够友好，权限设置很麻烦，有些连接器会损坏，浏览器自动化不够稳定，还需要自己编写脚本，并且持续维护一个清晰的事实来源。

但作者认为，未来往往就是这样开始的。

第一个真正有用的个人代理，可能不会像精致的消费级应用，而更像是终端里的一个模型。它可以访问你的文件、账户、记忆和工具，并按照你的规则行动。

##### 最后，记住四个结论

第一，个人代理最有价值的地方，不是回答问题，而是跨越多个应用，完成一整段现实世界的琐碎工作流。

第二，清晰的数据层非常重要。作者把 Google Drive 作为事实来源，并用 Markdown、CSV 和联系人表格，让信息更容易被代理搜索、修改和同步。

第三，工具接口有优先级。能用 API 和命令行，就尽量不要依赖浏览器点击；浏览器自动化可以作为补充，屏幕自动化则应该是最后手段。

第四，真正让代理个性化的，不是声音或外观，而是技能、规则、记忆和反馈。每次错误都可以转化为新的防护规则。

第五，代理不应该盲目替人做所有决定。更合理的模式是：代理负责读取、整理、起草和执行低风险任务；涉及发送、删除、付款、签署或账户变更时，再把决定权交还给人。

## 深度解读（1）

### 2026-09-18 00:39:12

#### 个人代理真正的门槛：可操作的数据与分层的信任

文章最有价值的地方，不是展示 Codex 能收邮件、改文档或操作网页，而是明确了个人代理的“杀手级模式”：**它不只是回答问题，而是跨越多个工具，把现实世界中的小任务推进到完成。**

介绍招聘人员的例子很典型。难点并不在写一封邮件，而在于从 WhatsApp 找到意图、去 Gmail 查联系人、上网核实公司信息、附上职位、发送邮件，再回原渠道确认。每一步都很简单，但人必须充当不同应用之间的“胶水”。代理节省的核心也不是打字时间，而是连续切换上下文、恢复记忆和检查遗漏所消耗的注意力。

##### 模型能力只是起点，真正的资产是“代理可读”的生活

作者最重要的架构选择，是把个人资料整理为 Drive 中的 Markdown、CSV、PDF 和表格，并明确事实来源。这里值得迁移的不是“用 Google Drive”，而是三个原则：信息容易搜索与编辑、关键实体有稳定标识、修改结果可以检查。

联系人 CSV 看似简陋，却可能比复杂知识库更有价值，因为它把分散在聊天、邮件和记忆中的身份关系，变成代理可以直接调用的结构化索引。相反，Notion 的嵌套页面、动态数据库和权限结构虽然适合人操作，却增加了代理理解与稳定修改的成本。

这提示了一个常被忽略的事实：**代理普及可能先推动个人信息架构重建，而不是让现有应用简单增加一个聊天框。**数据是否干净、最新且可写，往往比模型再聪明一点更能决定体验。

##### 审批不是对自动化的妥协，而是产品本身

作者把权限分为读取、起草、发送、删除、支付和修改账户，并在重要沟通前要求审批。这比追求“完全自主”更接近真实需求：用户希望机器完成第一次搜索、整理和草拟，但保留涉及关系、金钱与不可逆操作的决策权。

相应地，工具界面也有明确优先级：API 和 CLI 优于本地文件，浏览器自动化次之，屏幕操作最后。原因不是技术洁癖，而是结构化接口更容易检查、重试和审计。炫目的“看屏幕点击”能力，未必比一条返回 JSON 的命令更适合长期运行。

不过，文章展示的仍是高手原型，而非成熟消费产品。它没有充分讨论权限泄露、网页或消息中的提示注入、数据过期、误发后的回滚，以及连接器失效的维护成本。真正可规模化的个人代理，需要默认具备最小权限、操作预览、差异比较、审计记录和快速撤销，而不能只靠用户编写几条规则。

##### 机会不是万能助手，而是个人事务操作层

更现实的产品方向，是先服务数字沟通密集、信息高度分散的人群，完成“我错过了什么”、跨渠道找人、准备回复、同步资料等高频任务。现有替代方案是人工切应用、单应用 AI 和固定自动化流程；代理的优势在于能处理上下文变化，但前提是配置与维护成本低于它节省的注意力。

因此，衡量个人代理的关键指标不应是“自主完成了多少任务”，而应是：**用户需要介入几次、纠错成本多高，以及任务从意图到完成缩短了多少。**所谓新的操作系统，并不是聊天框取代应用，而是人从逐步操作软件，转向声明意图、审核关键节点，并让机器承担其余连接工作。
