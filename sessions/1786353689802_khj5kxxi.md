#### Making your own dithered QR codes

[Make your own](https://www.andrewt.net/dithered-qr-codes/index.html) [The rest of my website](https://www.andrewt.net/) [Source code](https://codeberg.org/andrew-t/dithered-qr-codes)

![A dithered photo of me, with standard QR code alignment patterns superimposed on it](https://www.andrewt.net/dithered-qr-codes/qr.7c4420b7.png)

#### QR codes: the basics

A QR code is really just a way of encoding a few bytes of data in a way that can be easily read froma photo by a smartphone or similar device. They're designed to be very robust to bad focus, bad printing, funny angles, and missing areas. Exactly how they work isn't terribly important, but for the purposes of this page, a QR code is a grid of squares that divide into two parts — the function patterns (which are the bold shapes in the above example) and the data modules (everything else). The function modules are mostly used to let the scanner find the QR code easily, so they have to be very clear and distinct. The data modules are where the actual data is stored, along with some extra header data etc, and since those are only read after the scanner has used the function modules to work out exactly where the QR code is, they can be modified a bit more. This is often used by brands to create QR codes that look a bit distinctive, and while this kind of modification makes them a bit less robust when scanning, but you can generally get away with a fair bit before the codes become unscannable.

#### Putting pictures in QR codes

![A dithered photo of Dave Richeson, with standard QR code alignment patterns superimposed on it, and a smattering of small black and white pixels on top](https://www.andrewt.net/dithered-qr-codes/divbyzero.728b270e.png)

This is [a QR code I saw on Mastodon](https://mathstodon.xyz/@divbyzero/115021806369821862). One of the modifications you can do with the data modules is to shrink them — the scanner will look where the finder patterns say the centres of the pixels should be, and so as long as the code isn't distorted when you try to scan it. That means the rest of the space is yours to play with. Dave divides each pixel into a three-by-three grid, and uses the middle one to store the data, and the others for a photo. The result is a low-res, one-bit photo with some salt-and-pepper noise on it.

#### Dithering

![A dithered gradient](https://www.andrewt.net/dithered-qr-codes/dither.d85f6e00.png)

Obviously when we crush an image into a low colour depth, we don't normally just threshold it — that is, make the dark pixels black and the light pixels white. We normally use a kind of chequerboard effect to create midtones as well. [A Bayer filter](https://en.wikipedia.org/wiki/Dither) can be used to apply this idea across a whole image without having to sacrifice too much fine detail.

![A Bayer dithered picture of Michaelangelo's David](https://www.andrewt.net/dithered-qr-codes/bayer.7d860e57.png)

#### Error diffusion

An attempt to improve on this method was Floyd-Steinberg dithering.

![A Floyd-Steinberg dithered picture of Michaelangelo's David](https://www.andrewt.net/dithered-qr-codes/floyd-steinberg.8961a98e.png)

In this method, you start in the top left and threshold the pixel normally — if it's more than 50% brightness, you make it white, and otherwise you make it black. Say it was 70% brightness — we're going to make it white, which is 100% brightness, which means we've added 30% of a pixel too much brightness. To counteract that, we're going to "diffuse" that error to other pixels — all the nearby pixels that we haven't thresholded yet are made a few percend darker, to a total of 30% of a pixel. When we come to threshold those pixels, we'll take that into account. The idea is that once we've thresholded the entire picture, every part of the image will be, on average, closer to the correct brightness than more regular dithering. The irregular patterns are also a bit less distracting.

#### QR codes with error-diffusion dithering

![A noisy Floyd-Steinberg dithered picture of Michaelangelo's David, with QR code patterns on top](https://www.andrewt.net/dithered-qr-codes/david1.7e489f32.png)

The other advantage of this irregular dithering is that the salt-and-pepper noise caused by the QR code data modules is much harder to spot. But it's still there, and it's why the image looks so noisy. I mean, it would look *fairly* noisy anyway because it's a 147×147 pixel one-bit image, but *some* of that noise is because one in nine of the pixels are effectively random colours.

But we can solve that using *more error diffusion*.

#### Error-diffusing the data modules

In this case, we're doing two passes on the error diffusion. The second is the same as normal, but the first is specifically to mask the data modules. We already know what colour all of those pixels have to be, so we can make them those colours and diffuse that error to the surrounding eight pixels. The error will potentially be quite big — normally we get to choose the colour so the error can never be more than 50%, but here we might have to make a pixel in a dark area pure white and end up creating 95% error. That sounds bad, but that's exactly why it's so important to diffuse this error instead of just accepting it.

![A less noisy Floyd-Steinberg dithered picture of Michaelangelo's David, with QR code patterns on top](https://www.andrewt.net/dithered-qr-codes/david2.a85a7c85.png)

You can see that this makes the image much cleaner.

#### Getting fancy with it

[![A dithered version of Morten Rieger Hannemose's ethically-sourced Lena image, with standard QR code alignment patterns superimposed on it](https://www.andrewt.net/dithered-qr-codes/lena.c347bd89.png)](https://mortenhannemose.github.io/lena/)

[The generator tool](https://www.andrewt.net/dithered-qr-codes/index.html) allows you to do some extra tricks. You can rotate the QR code before adding the image, and tinker with the QR code settings to see if any of the alternative encodings happen to look nicer.

You can also allow the generator to change a few of those 95%-error data modules — QR codes have enough error correction in them that you can afford to change a few pixels and they'll still scan. (That's how QR codes with logos in the middle work.) But in practice that doesn't really affect image quality much if you diffuse the error from the data modules and it seriously affects how well the code scans.

#### Using these in real life

This all works pretty well if you don't take it too far and the code is going to be on a big screen or a poster or something. If it's on, say, a paper flyer that could get crumpled then you're going to need more of that redundancy, robustness and error correction that we gave up to make the QR code pretty. Ultimately it's a trade-off between aesthetics and scannability — and remember that just because a code scans on *your* phone, from a laptop screen, doesn't mean it will scan on a random stranger's potato phone from a printout in bad lighting.

Also bear in mind that the generator tool makes tiny images with no margin — some margin is needed to make a QR code scan reliably, and browsers will normally blur images when upscaling them if you don't [disable that with CSS](https://developer.mozilla.org/en-US/docs/Web/CSS/image-rendering). The margin has to be the opposite colour to the middle of the big three "finder" pattern squares — normally that's white but you can generate inveted QR codes that need a black background instead.

#### 抖动二维码生成器：原理与实践

文章介绍了一种把图片“嵌入”二维码的方法：通过缩小数据模块，并结合误差扩散抖动，让二维码呈现出可辨认的黑白图像。其核心是在**美观与可扫描性之间取舍**，实际使用时还需考虑尺寸、印刷、光线和设备性能。

##### 1. 二维码的基本结构

二维码可以看作由方格组成的网格，主要分为两部分：

- **功能图案**：包括三个醒目的定位方块等，用于帮助扫描器找到二维码并判断位置、角度，必须保持清晰。
- **数据模块**：保存实际数据、头信息和纠错信息。扫描器确定二维码位置后才会读取这些模块，因此可以进行一定程度的视觉修改。

二维码本身能容忍失焦、倾斜、印刷不良和局部缺失，所以品牌常通过改变数据模块来制作更有特色的二维码。但改动越多，扫描稳定性通常越差。

##### 2. 在二维码中加入图片

一种常见思路是缩小数据模块：

- 扫描器主要读取每个模块的中心位置，因此只要二维码没有严重变形，模块周围的空间可以用来显示图片。
- 文中的案例把每个二维码模块划分成 **3×3 网格**：
  - 中间的 1 个像素保存二维码数据；
  - 周围 8 个像素用于呈现图片。

最终得到的是一张低分辨率、仅有黑白两色的图片，但固定的数据像素会形成明显的“椒盐噪声”。

##### 3. 用抖动表现灰度

将彩色或灰度图片转换为纯黑白时，不能只简单地按亮度切分：

- 若直接阈值化，暗像素变黑、亮像素变白，许多中间色调和细节会丢失。
- 抖动技术通过棋盘状或疏密不同的黑白像素，模拟灰色和中间亮度。
- **Bayer 抖动**可以在整张图中应用规则图案，同时保留较多细节。

##### 4. Floyd–Steinberg 误差扩散

Floyd–Steinberg 抖动进一步改善了黑白图像效果，其基本过程是：

1. 从左上角开始处理像素。
2. 以 **50% 亮度**为阈值，把像素变成纯黑或纯白。
3. 计算转换前后的亮度误差。
4. 将误差分配给附近尚未处理的像素。

例如，一个像素原本是 **70% 亮度**，转换成白色后变为 **100%**，相当于多出了 **30% 的亮度**。算法会让邻近像素合计变暗 30%，以补偿这一误差。

这样处理后：

- 局部区域的平均亮度更接近原图；
- 生成的纹理更加不规则；
- 相比规则棋盘图案，不容易干扰视觉。

##### 5. 将误差扩散用于二维码图片

二维码数据模块中的中心像素由编码结果决定，不能自由选择黑白，因此会产生噪声：

- 最终图像只有 **147×147 像素**，且为纯黑白图，本身就比较粗糙；
- 每个 3×3 区域中有 1 个像素由二维码数据决定，即约 **九分之一的像素颜色近似随机**；
- 这些随机黑白点会破坏图片的明暗关系。

不过，不规则的误差扩散纹理能在一定程度上掩盖这些椒盐噪声。

##### 6. 对数据模块单独进行误差补偿

作者采用了两遍误差扩散：

1. **第一遍专门处理二维码数据模块**
   - 先把中心像素设为二维码要求的颜色；
   - 再把产生的亮度误差扩散到周围 8 个像素。

2. **第二遍进行普通误差扩散**
   - 对整张图片继续完成黑白抖动。

普通抖动可以自由选择更接近原始亮度的黑或白，因此误差通常不会超过 **50%**。但二维码数据模块的颜色是固定的，例如可能被迫把暗区中的像素设为纯白，误差最高可能达到 **95%**。

误差越大，越需要扩散到周围像素，而不是直接保留。经过补偿后，图片中的噪声会明显减少，整体更加干净。

##### 7. 生成器提供的额外调整

生成工具还允许用户：

- 旋转二维码后再叠加图片；
- 调整二维码编码参数，寻找视觉效果更好的编码方案；
- 修改少量误差特别大的数据模块。

二维码具有纠错能力，因此改动少量像素后仍可能正常扫描，带中央 Logo 的二维码也是利用了类似原理。但作者指出：

- 在已经对数据模块进行误差扩散后，额外改像素对画质提升不大；
- 却会显著降低二维码的扫描可靠性。

因此，不建议为了微小的视觉改善过度消耗纠错能力。

##### 8. 实际使用时的注意事项

这种二维码更适合显示在：

- 大屏幕；
- 海报；
- 尺寸较大、环境相对稳定的载体上。

如果印在容易褶皱的传单上，就更需要保留二维码原本的冗余度和纠错能力。实际效果始终是**美观与可扫描性之间的权衡**。

测试时还应注意：

- 在自己的手机上扫描笔记本屏幕成功，不代表陌生人的低性能手机能在昏暗环境下扫描印刷品。
- 生成器输出的是没有留白边距的小图，但二维码通常需要足够的边缘“静区”才能稳定识别。
- 图片放大时，浏览器可能默认进行模糊处理，应通过 CSS 禁用平滑插值，避免二维码边缘变糊。
- 边距颜色应与三个大定位方块的中心颜色相反：
  - 普通二维码通常使用白色边距；
  - 反色二维码则可能需要黑色背景。

## 口播总结（1）

### 2026-08-10 09:59:00

#### 抖动二维码：怎样把图片藏进二维码，又尽量保证能扫描

这篇材料讲的是，怎样利用抖动和误差扩散技术，把一张图片融入二维码，同时尽量降低二维码数据带来的杂点。你会了解到它的基本原理、画质为什么能得到改善，以及实际使用时必须注意的扫描风险。

##### 首先，二维码为什么允许一定程度的美化

核心结论是，二维码并不是每一个方块都同样不能改。它大致可以分成两部分：功能图案和数据模块。

功能图案就是二维码里那些醒目的定位结构，包括常见的三个大方框。扫描器主要依靠它们找到二维码，判断二维码的位置、角度和大小。因此，这些图案必须清楚、醒目，不能随意修改。

其余区域大多是数据模块，用来保存真正的数据，以及一些格式信息。扫描器通常会先通过功能图案完成定位，再去读取这些数据模块。所以，与功能图案相比，数据模块可以做更多调整。

二维码本来就被设计得很耐用。即使照片对焦不准、打印质量不好、拍摄角度倾斜，甚至缺失一小部分，它仍可能被识别。很多品牌正是利用这种容错能力，制作带有图案或标志的二维码。不过，修改越多，二维码的可靠性通常就越低。

##### 接下来，怎样把一张图片放进二维码

核心做法是，把每个数据模块缩小，只保留中心位置来承载二维码信息，周围空间则用来表现图片。

原因在于，扫描器根据定位图案推算出每个模块中心应该在哪里。只要二维码没有发生严重变形，扫描器重点读取的仍然是这些中心位置。因此，中心点可以继续保存黑白数据，周围区域则可以用作图像。

材料中介绍的方案，是把每个二维码模块再分成一个三乘三的小网格。正中间的一个小格保存二维码数据，其余八个小格显示照片。

这样做之后，二维码里就能出现一张低分辨率的黑白图片。这里的“黑白”不是灰度，而是每个像素只有黑和白两种选择，也叫一比特图像。不过，由于每九个小像素中，就有一个必须服从二维码数据，图片上会出现明显的黑白杂点，看起来像撒上了盐和胡椒。

##### 然后，用抖动表现黑白之间的灰度

核心结论是，如果直接把照片压缩成纯黑和纯白，很多细节和明暗层次都会丢失。更好的办法是使用“抖动”。

抖动并不是让像素真的变成灰色，而是把黑点和白点按照一定规律交错排列。人眼从正常距离观看时，会把这些小点混合起来，感受到介于黑白之间的灰度。

最简单的处理方式叫“阈值化”。也就是设定一个亮度分界线，暗于分界线的像素变黑，亮于分界线的像素变白。但这样很容易造成大片生硬的黑白区域。

拜耳抖动可以改善这个问题。它使用类似棋盘格的规则，把黑白像素分散开，在表现中间亮度的同时，尽量保留图像中的细小轮廓。不过，这种规则图案有时也会比较显眼。

##### 更进一步，误差扩散让亮度更接近原图

核心结论是，弗洛伊德—斯坦伯格抖动，也就是一种经典的误差扩散算法，可以让黑白图像的平均亮度更接近原图，而且产生的纹理更自然。

它通常从图像左上角开始，依次处理每个像素。假设一个像素的亮度是百分之七十，而分界线是百分之五十，那么它会被变成纯白，也就是百分之百亮度。

这样一来，这个像素就比原图多出了百分之三十的亮度。算法不会直接忽略这部分差异，而是把它分配给附近那些还没有处理的像素，让它们稍微变暗。这就是“误差扩散”的含义。

等到后面的像素被转成黑色或白色时，算法会把前面分配过来的误差也考虑进去。最终，局部区域虽然仍然只有黑白两种像素，但平均亮度会更接近原始照片。与此同时，它产生的纹理没有规则棋盘格那么明显，视觉干扰也更小。

##### 关键改进，是专门处理二维码数据造成的杂点

不过，普通的误差扩散仍然不能完全解决问题。核心原因是，二维码中心的数据像素不能自由选择颜色。

在三乘三的小网格中，每九个小像素就有一个必须按照二维码数据显示。这个颜色可能与照片完全相反。比如，照片中的某个位置本来非常暗，二维码数据却要求中心点必须是纯白。这样的像素就会变成强烈的杂点。

材料中的示例图像只有一百四十七乘一百四十七个像素，而且只有黑白两种颜色，本身就会显得粗糙。再加上大约九分之一的像素颜色由二维码数据决定，噪点就会更加明显。

解决办法是进行两轮误差扩散。

第一轮专门处理二维码数据模块。因为这些中心像素的颜色已经确定，所以先把它们设成二维码要求的黑色或白色，再把产生的亮度误差扩散到周围八个像素。

这种误差可能很大。普通抖动可以在黑白之间选择更接近原图的颜色，所以误差最多通常只有百分之五十。但二维码的颜色不能随便选。如果一个原本只有百分之五亮度的深色位置被迫变成纯白，误差就可能达到百分之九十五。

误差虽然大，却更不能直接忽略。把它分散到周围像素后，附近区域可以用略暗或略亮的黑白分布进行补偿。

完成这一步之后，再进行第二轮普通的误差扩散，把整张图转换成黑白图像。这样，二维码中心点造成的突兀杂点会被周围区域吸收，最终图片看起来会干净很多。

##### 生成器还能做哪些调整

接下来，生成工具还允许用户尝试一些额外变化。

首先，可以在加入图片之前旋转二维码。其次，可以调整二维码的编码设置。即使保存的是同一段内容，不同编码方式也可能产生不同的黑白分布，其中某一种或许更适合当前图片。

工具还可以修改少量原本固定的数据模块。二维码内部带有纠错信息，也就是即使少数模块出错，扫描器仍可能恢复原始数据。常见的二维码中间加标志，就是在利用这种能力。

不过，材料特别提醒，这种做法实际带来的画质改善并不明显。只要已经对固定数据像素进行误差扩散，继续改变这些像素的收益就比较小，反而会明显降低二维码的扫描可靠性。

##### 最后，实际使用要在美观和可靠之间取舍

核心结论是，这类二维码适合大屏幕、海报等显示条件较好的场景，但不适合不加测试地用于所有印刷品。

如果二维码印在容易折皱的传单上，或者尺寸很小、光线不好，那么扫描器会更加依赖二维码原本的冗余和纠错能力。而为了让二维码与图片融合，这些安全余量已经被部分牺牲。

因此，审美效果和可扫描性之间存在直接取舍。二维码越像一张图片，通常就越可能失去一部分稳健性。

还要注意，二维码在自己的手机上能够扫描，并不代表它在现实环境中一定可靠。电脑屏幕显示清晰，测试手机的摄像头也可能很好。但陌生人可能使用摄像头较差的手机，在昏暗环境中扫描一张打印效果一般、甚至已经折皱的纸张。

此外，生成工具输出的图片很小，而且没有自动添加空白边距。但二维码周围通常需要保留一圈干净区域，才能稳定识别。

如果把小图片放大，浏览器还可能自动进行平滑处理，让原本边缘清楚的黑白方块变得模糊。因此，显示时要避免这种模糊缩放。

边距颜色也不能随便选。它应该与三个大定位方框的中心颜色相反。普通二维码的定位方框中心是黑色，所以周围通常要留白。如果生成的是黑白反转的二维码，就可能需要黑色背景。

##### 最值得记住的几点

最后，回顾五个关键结论。

第一，二维码的功能图案必须保持清晰，而数据模块可以在一定范围内进行美化。

第二，把每个模块分成三乘三的小网格，并用中心点保存数据，就能把周围空间留给图片。

第三，抖动可以用黑白点模拟灰度，而误差扩散能让局部平均亮度更接近原图。

第四，最关键的画质改进，是先处理二维码固定数据像素产生的误差，再对整张图片进行普通误差扩散。

第五，这种技术始终是在美观和可扫描性之间做取舍。真正投入使用前，必须在不同尺寸、打印条件、光线和手机设备上反复测试，并保留合适的边距。

## 深度解读（1）

### 2026-09-18 00:09:14

#### 漂亮二维码的关键，不是隐藏约束，而是消化约束

这篇文章真正有价值的地方，不是教人给二维码“加一张图”，而是展示了一种更普遍的设计方法：**当系统中存在不能改变的元素时，不要把它们当作最终结果里的噪声，而应把它们造成的误差分摊到仍可调整的部分。**

##### 把二维码数据纳入图像生成过程

二维码由两类区域组成：负责定位的功能图案必须清晰；其余数据模块虽然更可调整，但仍要保留编码信息。一种常见做法，是把每个模块拆成 3×3 像素，只用中心像素保存数据，周围八个像素表现图片。问题是，这意味着图像中约九分之一的像素颜色由二维码决定，与原图明暗无关，于是产生明显的椒盐噪声。

普通抖动只能把灰度图转换成黑白点阵，却不知道哪些像素已被二维码锁死。作者的改进是做两遍误差扩散：第一遍先固定必须承载数据的像素，再把它们与目标图像之间的亮度误差扩散给周围八个可调像素；第二遍再执行正常的 Floyd–Steinberg 抖动。

例如，暗部中的一个数据位被迫显示为白色，局部可能多出 95% 的亮度。与其接受这个突兀白点，算法会把邻近像素调暗，使区域的平均亮度重新接近原图。**它没有消除强制像素，而是让视觉系统在更大范围内补偿它。**

这比简单叠加图片更值得借鉴：硬约束不一定只能降低质量，只要目标允许局部互相补偿，就可以把约束直接写进生成过程。类似思路也适用于带固定广告位的页面布局、受品牌色限制的图形生成，以及必须保留特定字段的数据压缩。不过，它依赖“局部误差可以由邻域吸收”这一前提；若单点本身必须准确，就不能这样迁移。

##### 纠错能力不是免费的美化预算

二维码本身允许部分数据损坏，因此还可以故意改掉少量模块，让图片更自然。但作者测试后发现，图像改善有限，扫码可靠性却明显下降。原因是误差扩散已经消化了大部分视觉冲突，而被提前消耗的纠错余量，原本要应对打印模糊、折痕、角度、光照和低端摄像头。

这提醒了一个常被忽略的产品判断：**系统冗余首先是为真实环境的不确定性准备的，不应因为演示环境成功，就被当成功能预算用掉。**在笔记本屏幕上被自己的手机扫出来，只证明了理想链路可用，并不代表陌生用户拿着普通手机，面对一张低质量打印件也能成功。

因此，这类工具的核心指标不该只是“生成效果好看”和“当前可扫码”，而应是在目标尺寸、介质、距离、光照与设备分布下的扫码成功率。真正成熟的产品甚至应根据使用场景提供不同安全档位，并自动补足留白、避免浏览器缩放插值。美观与可靠性并非抽象取舍，而是一个可以通过场景化压力测试量化的风险预算。
