## 正文

**Cat Chen, @catchen@mastodon.world**

Vercel 开源项目最大的问题是弃坑。我做基于 JavaScript 的 GitHub Actions，从一开始 GitHub 官方示例推荐的打包工具就是 @vercel/ncc。这个项目已经进入了有 bug 没人修的状态。

我三个月前给他们开了个 issue，过了好久才有人来看，看完后发现不知道怎么修，打了个「help wanted」的标签就跑路了。最近社区有好心人为此开了个 PR，等了十天没有人来看一眼。 [https://github.com/vercel/ncc/issues/1312…](https://github.com/vercel/ncc/issues/1312)

我怀疑 Vercel 的企业文化跟大多数科技公司一样：奖励开坑，但长期维护得不到回报。于是员工不停地发布新的开源项目，每一次都成为社区热点，但火爆一轮后就弃坑。这些开源项目对 Vercel 的盈利没有贡献，用户也不花钱，掉坑里之后也不能要求 Vercel 怎样。

> **@ZaynHao**
>
> So sad, 也不怪大家总是吐槽 Vercel，推出了很多框架、库，但是却不维护啥的。 这个 zero-native 看起来也是这样的命运了。

```markdown
## 一、深度总结

这条内容的核心判断很明确：

- **Vercel 的开源项目，常见问题不是“没人知道”，而是“没人维护”。**
- 以 `vercel/ncc` 为例：  
  - issue 长期没人处理，  
  - 讨论后无人明确修复，  
  - 社区 PR 也迟迟没人审。
- 作者据此推测：  
  **Vercel 更擅长“开新坑”，不擅长“填旧坑”。**
- 背后的机制可能是：
  - **发布新项目更能带来声量、热点和品牌收益**
  - **长期维护却难以直接变现**
  - 所以开源项目容易“火一阵，冷下去，最后弃坑”

---

## 二、深入浅出地解读

你可以把它理解成一句大白话：

> **公司爱做“上热搜的事”，但不一定愿意做“没人夸却很累的事”。**

### 为什么会这样？
因为开源维护很“吃力不讨好”：

- 新项目上线：容易被关注，利于宣传
- 老项目维护：  
  - 费时间  
  - 费人力  
  - 很少直接带来收入  
  - 出问题还可能被社区反向催责

所以很多公司会出现一种模式：

- **先做一个很亮眼的开源项目**
- **吸引开发者使用**
- **热度过去后，维护跟不上**
- **最后社区自己填坑**

### 这件事为什么让人失望？
因为开源用户默认会期待：

- 你既然开源了，就会持续维护
- 既然很多人用了，就应该有基本责任感

但现实常常是：

- **开源不等于长期承诺**
- **社区热情，不等于公司资源投入**

---

## 三、辩证思考

### 这条批评有道理的地方
- 它点出了一个真实问题：  
  **“开源做展示，维护靠社区”** 的现象很普遍。
- 对开发者来说，最怕的不是项目不好，而是**项目坏了没人管**。
- 对基础工具而言，维护质量往往比“首发时多惊艳”更重要。

### 但也要看到另一面
- 公司不是公共机构，**不会天然承担无限维护义务**
- 开源项目的维护成本很高，**长期投入确实需要资源**
- 不是所有项目都能成为“长期主线产品”
- 有些项目停更，不一定是恶意，可能是：
  - 团队调整
  - 优先级变化
  - 商业重心转移

### 更现实的结论
- **不要只看一个开源项目“发布时多风光”，更要看它“是否有人持续维护”**
- **对企业开源要降低浪漫预期，提高工程判断**
- **对社区而言，最好建立对项目健康度的评估习惯：**
  - 最近是否还在更新
  - issue 是否有人响应
  - PR 是否有人 review
  - 维护者是否稳定

---

## 一句话结论

**这不是单个项目的抱怨，而是对“企业开源重发布、轻维护”现象的提醒：热度能带来关注，维护才决定命运。**
```
