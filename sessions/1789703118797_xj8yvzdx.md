### 如何自动化生成导语（完整指南）

在本指南结束时，你将知道如何自动生成任何东西的导语。无论是你在网上销售的数字产品，还是为自己生成导语的业务，或者完全没有业务的人，生成导语并将其出售给企业。

其实就一个方法。你找到已经在付费的人，提取他们的数据，构建能触达他们的东西，然后把它放在他们会看到的地方。唯一变化的是最终谁拿到这个导语。

到结束时你将拥有：

- 一个确切知道谁购买你产品的代理
- 一份基于他们自己三个月语气的买家画像
- 根据该画像构建的广告创意，每个角度多个
- 一个 whop 广告活动，将潜在客户引导至你的产品
- 一个扫描器，找出谁拥有交易能解决的问题
- 一个本地企业按月付费的潜在客户管道
- 所有这些都按计划进行，只有少数几件事保持手动操作

#### 哪个代理？grok bot 还是 hermes

两者都能运行本文中的所有内容，而且无论用哪个，系统都是一样的。区别在于你想做多少设置工作。

grok bot 很容易设置。它已经自带一台计算机，里面有终端、浏览器和文件系统，你可以像聊天一样和它交流。所以它的工作方式是，你先用 claude 把整个系统构建成一个 skill 文件，然后把这个文件连同 api keys 和它所需的工具访问权限一起交给 grok bot。它会读取这个 skill 并运行它。你可以用 chatgpt 或 grok bot 本身来构建这个 skill，不过我一直都是用 claude 来做这件事。

这意味着随便一个人都能运行这个。你不需要设置任何东西，只要给 grok bot 一个文件和几个 keys，它就会开始运行。

hermes 启动时更偏技术性，但一旦运行起来就更容易。它按附表运行，grok bot 也能做到这一点，但 hermes 就是为此而构建的。hermes 的设置只需要向 claude 输入一个 prompt。你把 hermes 文档和一个来自

[@BotFather](https://x.com/@BotFather) 的 telegram bot token 交给它，它就会在 railway 上把 hermes 配置为一个持续运行的服务。然后你把同样的 skill 文件、同样的 api keys 和同样的工具访问权限交给 hermes，从那以后，prompts 就通过 telegram 发给它。

所以技能文件才是核心。用 Claude 构建它，然后任意一个 agent 都能运行它。本文中的每一条提示词都是要写进那个技能文件里的内容。

从现在开始，我说 agent 时指的都是两者中的任意一个。

#### 技能文件

技能文件基本上就是一份文档，告诉智能体如何完成一项工作。步骤是什么、按什么顺序执行、使用哪些工具、记录什么内容。你只需编写一次，任何读取它的智能体都能运行这项工作。

你用 Claude 来构建它（也可以用 codex）。你把本文中的提示词粘贴到一个新对话里，告诉 Claude 你正在运行哪条 pipeline，然后让它把这些提示词整合成一个技能文件，规则放在顶部，步骤放在下面。它会返回一个 .md 文件，你保存下来，交给 grok bot 或 hermes 使用。

```text
turn these into a skill file for [pipeline one / two / three].

- here are the prompts: [paste them]
- put the operating rules at the top. one table per trade or niche, never read across tables, stop and ask before anything that contacts a real person or spends money, mark anything uncertain as review rather than guessing
- then the steps in order, each one saying what tool it uses, what it reads, what it writes, and what it hands to the next step
- list every api key and tool access the agent needs to run this, so i can give them all at once
- write it so an agent that has never seen this article can run it from the file alone
- tell me anything in here you think is underspecified and would make an agent guess
```

#### 哪一半是你的

这篇文章是为三类人写的，每一类人负责运行其中不同的部分。

如果你销售数字产品，或者想要销售，你就运行管道一。导语是你的，广告是你的，买家落在你的页面上。

如果你拥有一家企业，你为自己运行管道二。你找到需要你所做之事的人，你在他们自己的属性上向他们展示解决方案，然后导语就来找你。如果你是企业的所有者，就跳过管道三。

如果你没有产品也没有企业，你就运行管道二进入管道三。你在一个城市为某个行业生成导语，然后把它们卖给做这项工作的企业。

#### pipeline 1，数字线索

这是在你拥有一个产品，或者有一个产品想法的情况下：你确切地找出谁会购买它以及他们在哪里，你把他们三个月内说过的一切都提取出来，然后据此构建广告。（你不需要担心自己以前是否投放过哪怕一条广告，因为现在用 whop ads 投放广告很容易）

#### 从产品开始

智能体需要先理解产品，然后才能找到买家/客户。它做什么、价格是多少、解决什么问题，以及一个人必须对自己抱有什么样的信念才会想要它。

所以第一个提示是产品，返回的是买家/客户。他们的人口统计特征是谁，以及他们的心理特征是谁。例如：一个34岁的德克萨斯州男人是人口统计特征。一个34岁的男人，尝试过不同的东西，感到沮丧，没有一个奏效，这是心理特征。

```text
here's my product: [describe it, or paste the page].

- tell me who buys this. age, situation, what they do, where they are in life
- tell me who they are underneath that. what they've tried, what they're afraid of, what they'd never admit wanting, what they tell themselves about why it hasn't worked yet
- tell me where these people are online. the specific subreddits, facebook groups, youtube channels, tiktok accounts, discords, forums. not the category, the actual names
- for each place, tell me why they're there and what they talk about when they're there
- tell me which of these places has the buyers and which has people who just talk about it
- if you're not sure a place is real or active, say so rather than listing it
```

#### 提取三个月的数据

现在智能体前往那些地方，抓取过去三个月的所有内容。帖子、评论、回复、人们提出的问题、他们抱怨的事情、他们使用的词语。Apify 为每个平台都有抓取器，智能体通过 Apify MCP 运行它们。

三个月足以看出哪些内容会重复，又不至于过时。

```text
scrape the last three months from every place you listed as having buyers.

- use the apify mcp. reddit, facebook groups, youtube comments, tiktok comments, whichever scraper fits each place
- pull posts, top comments and replies. keep the source url, the date and the engagement on each
- write down every question that comes up more than three times, in their own words, with a count
- write down every complaint about what they've tried, in their own words, with a count
- write down the phrases they use to describe the problem, and the phrases they use to describe what they want instead
- tell me what they've already paid for and what they say about it
- write it as one profile with the quotes and counts in it, sorted by count
- mark anything you're guessing rather than quoting
```

代理的工作就是找出最常见的内容。

![Image](https://pbs.twimg.com/media/HSG4FPGaIAEiBrZ?format=jpg&name=large)

#### 创意计划

在我们构建广告之前，个人资料会先变成一份计划。智能体会读取其中的内容，找出各个角度，也就是数量最多的那个抱怨或需求，以及每个角度下的钩子，也就是个人资料中明确表达该角度的原话。

然后它会分析出 whop ads 需要什么。whop ads 在 Meta、Facebook 和 Instagram 上运行，所以创意素材是竖版视频和静态图片，采用 Meta 使用的三种宽高比。代理通过阅读 whop 的文档了解到这一点，而计划则说明了哪个创意放在哪里。

```text
build the creative plan from the profile.

- take the three complaints or wants with the highest counts and make each one an angle
- for each angle, write three hooks using the exact phrases from the profile, their words not mine
- for each hook, say what the video shows and what the still shows. the outcome they described wanting, not the product
- read whop's ads docs and tell me what formats and sizes meta needs through whop ads
- for each creative, say which placement it's for. feed, stories, reels
- every creative ends with the same offer and the same checkout link
- if an angle doesn't have enough in the profile to write three hooks from, drop it and say why rather than padding it
```

三个角度，九个创意。足够用来学习，又不会多到让预算被稀释得所剩无几。智能体通过 replicate 或 fal 生成它们，取决于你给它配置了哪个的密钥。目前 GPT Image 2.5 是最好的图像模型，Seedance 2.5 是最好的视频模型，所以它调用的就是这两个，而且两者都直接来自计划，无需再次提示。

#### 运行 whop 广告

whop ads 运行在 whop 自己的代理账户上，依托 meta。你从 whop 仪表盘启动，而不是原生广告管理器，广告系列通过处于 meta 顶级层级的账户在 facebook 和 instagram 上运行。这意味着在竞价中拥有优先权、规模化时更低的千次展示成本，以及比新账户少得多的拒登。这真的很酷。

像素已经在你 whop 页面上，并且从真实支付数据中进行归因。所以当一次转化被计入时，是因为有人付款了。whop 还会将转化转发给 Meta 的优化系统，因此 Meta 会从相同的数字中学习。

代理会根据计划进行设置。一个广告系列包含三个广告组，每个角度一个，每个广告组包含三个创意。每个广告组每天从 \[placeholder\] 开始。需要关注的数字是每笔销售成本与产品价格的对比。如果某个广告组的每笔销售成本连续三天高于产品价格，就暂停它。代理每天从广告仪表板中提取支出，并从 whop 中提取净收入，将它们并排展示，这是真正看到这一点的唯一方式。

资金可以在同一天从你待处理的 whop 余额中获取。广告带来买家，买家为广告提供资金。

来自代理的每日报告是每个广告组四个数字。花费、点击量、销售额、单次销售成本。以及哪个角度正在胜出，是否有任何内容应该暂停。

使用 whop ads 无需付费。你只需为花费付费，仅此而已。

#### 收集导语

广告将他们发送到你的页面，产品就是你在第一个提示中提供给代理的那个。页面以他们自己的语气表达广告所说的内容。

代理会跟进那些点击了但没有购买的人。whop 会向你显示谁访问了以及谁结账了。

这就是第一条管道。产品、买家、三个月的他们所说的内容、计划、创意、广告。导语始终是你的。

#### 第二条管道，实体线索

这是线索属于本地商家的版本。你从公开数据中找到一个有明显问题的房产或商家，把修复方案渲染到那个实际房产上，让那个渲染图出现在业主面前，谁回应谁就是线索。

#### 选择行业

人人都懂的单字行业。太阳能、屋顶、景观、泳池、遮阳篷、围栏、车道、标牌。买家必须在信息到达之前就已经想要这个东西，这就是为什么这个行业必须是那种房产或商家本身就能告诉你他们需要它的行业。你不是在创造需求，而只是在发现需求。

其中一些是房主，一些是企业，而方法并不在意。带泳池的房子是房主。没有招牌的咖啡馆是企业。屋顶平坦空置的仓库是企业。屋顶老旧的房子是房主。 重要的是，交易锁定的东西可以从公开数据中看到，这样代理就能找到它。

所以第一个提示是交易，返回的是数据所在的位置。

```text
i'm generating leads for [trade] in [city].

- tell me what the property or the business looks like when it needs this trade. what's visible, from where
- tell me which public data source shows that. satellite imagery, street view, listing photos, business listings, permit records, property records. the actual source, and what it returns
- tell me whether the buyer is a homeowner or a business, and what contact data i'll have for each. address only, or email and phone too
- tell me what one qualifier i should use. one thing, not a stack
- tell me what the render needs to show, and which image the render goes into
- if this trade doesn't have a visible signal in public data, say so rather than inventing one
```

#### 检测候选对象

限定条件只有一件事。就是交易锁定的东西。你在上面叠加的每一个过滤器都会削减列表并增加一个猜测，而这些猜测会不断累积。 第一批货发出后，行业会告诉你哪些值得做，这确实是非常有价值的信息。

数据是公开的，而且大部分是免费的。来源取决于具体行业，这就是为什么会有前一个提示词。智能体会选择第一个提示词指定的那个来源并读取它。在限定条件中加入第二个来源，就是名单缩小的方式。

大多数影像 API 都提供免费的元数据查询，可以在你付费获取图像之前告诉你影像是否存在以及有多旧。智能体会先对每个地址运行这个查询，只对返回结果为近期数据的地址付费。

```text
build the candidate list for [trade] in [city].

- pull every address in [area] from the property records or the business listings, whichever the trade needs, with the owner name where it's public
- for each one, check whether imagery or a listing photo exists before pulling anything, and drop anything with nothing or with imagery older than three years
- for the ones that pass, pull the one source we chose and check it for the one qualifier
- for the ones that pass the qualifier, pull the reference images the render will need
- write a table with address, owner, contact data, source urls, and a flag for whether the qualifier is clear or borderline
- mark borderline as review rather than in or out
- tell me what the batch cost in api calls when you're done
```

#### 渲染修复方案

图像模型把修复效果放到他们实际的属性上。

它必须是一次编辑。模型接收参考图像，只改变交易修复的那部分内容。

这里有几个参考帧很重要，原因与我在圣诞灯饰文章中所述相同。一张图像会让模型对图像之外的一切进行猜测。三到四张参考图，它就有足够的依据来工作了。

#### 联系所有者

你可以用三个渠道来做这件事。电子邮件、短信、明信片。三者的渲染图是一样的，指向的地址也一样，都是为那一处房产专门构建的页面，渲染图放在顶部，还有一个表单询问他们希望何时收到报价。

使用哪个渠道取决于你手头有什么。对于企业，你通常能从列表中获取电子邮件和电话，所以电子邮件和短信都可以使用，代理会通过你提供的任何发送器来发送它们。 或者作为房主，你通常只有一个地址，没有其他信息，所以就是邮寄。在我自己的测试中，明信片的表现远远超过了电子邮件和短信。 对于邮寄，有多家明信片公司提供 API，你可以让你的代理访问这些 API。一旦你批准了批次，代理就会自行发送。

```text
prepare the outreach batch for [city], [trade].

- for each property in the table, pick the channel from what we have. address only means post. email or phone means email or sms as well
- the render goes with every message. for post it's full bleed on the front, for email it's the image, for sms it's the link to the page
- one line with it, in plain words, saying this is their property with the fix done and where to see what it takes
- build one page per property with the render at the top, the address, and a form asking when they'd like a quote. every channel points there
- for post, the qr corner stays blank in the artwork, i composite the real one in
- validate every address, email and number before it's in the batch
- prepare the batch and stop. show me the count per channel and one sample of each
```

业主打开页面，再次看到自己的房产，填写一个时间，而该表单提交会带有时间戳并与其地址绑定。

#### 捕获响应

二维码扫描、表单填写、回复。这就是导语。它包含一个地址、一个业主姓名、他们希望获得报价的时间，以及该房产的渲染图。代理会在其到达的那一刻将其记录到表格中，而这张表格就是你在下一个流程中出售的东西。

即使没有填写表单，打开或扫描仍然值得记录。有人看了自己房产上带有修复方案的内容，但还没有要求报价，这就是潜在客户，第二批会跟进他们。

如果你是亲自为自己经营这项业务的老板，流程到此为止。代理已经完成了寻找、渲染和发送的工作，剩下的唯一事情就是由你来处理的对话。

这就是管道二。交易、检测、渲染、触达、捕获。

#### 管道三，销售线索

现在，导语流向真正做这项工作的企业，而你从中获得报酬。

#### 寻找企业

Google Places、交易、城市。筛选出由所有者主导的公司，而不是加盟店，因为所有者才是会阅读帖子的人，评论数在 15 到 200 条之间，有真实地址等等，

代理拉取列表，并针对每个线索记录其覆盖的区域。

#### 触达商家

你其实不用推销。发给商家的消息里附上已经在其区域内生成的线索样本。老板看到的是已经完成的线索，他脑子里想的是这样的线索还有多少，而不是这玩意儿到底管不管用。有地址就邮寄，有邮箱就发邮件，两者都有就都做。

```text
prepare the outreach to [trade] companies in [city].

- pull every [trade] company from google places in [city] with 15 to 200 reviews and no franchise markers, and note the area each one covers
- for each one, pick the three closest leads from the table that haven't been sold yet
- build a one page pdf with those three: the street and area, the render, and the form fill with the time they asked for
```

#### 自动获客的核心不是提示词，而是把需求信号变成可审计的流水线

##### Skill 文件本质上是可执行的 SOP

文章最成熟的设计，是把任务写成一个可移植的 Skill 文件：每一步规定读取什么、调用什么工具、产出什么，以及交给下一步什么。更重要的是，它明确设置了三个边界：不确定就标记复核，不跨表混用数据，凡是联系真人或花钱都先停下来等待批准。

不过，运行这套系统，最重要的并不是选哪个人工智能工具，而是写好一份“技能文件”。

你可以把技能文件理解成给人工智能的操作手册。它要写清楚：任务按什么顺序完成，每一步用什么工具，读取什么数据，产出什么结果，以及结果怎样交给下一步。

手册里还要有几条硬规则。不同城市或行业的数据分开存放，不要混用。信息不确定，就标记为需要复核，而不是猜一个答案。凡是要花钱，或者联系真实的人，都先停下来，等待批准。

这样，自动化才不是一句“帮我找客户”，而是一套能够检查、重复运行的工作流程。

先看数字产品这条路。作者强调，广告创意不应该从卖家的想象出发，而应该从买家的真实表达出发。

比如，你卖一项课程。只知道买家年龄多大、住在哪里，还不够。更重要的是，他们试过什么，为什么失望，担心什么，又怎样描述自己想要的改变。

人工智能先根据产品介绍，寻找这些人聚集的具体社区。这里还要区分：哪些地方有真正购买过相关产品的人，哪些地方只是大家在讨论。

接着，收集这些社区过去三个月的帖子、评论和回复。作者选择三个月，是希望既能看出反复出现的问题，又不至于让信息太陈旧。

收集的重点，不是堆出一大包文字，而是保留原话、来源、日期和出现次数。哪些问题反复被问？哪些方法被抱怨最多？用户已经为什么付过钱？他们用什么词描述痛苦，又用什么词描述理想结果？

这些证据汇总起来，才形成买家画像。引用和推测必须分开。

理解这一点，再看广告怎么做，就很清楚了。作者建议，从出现次数最多的抱怨或愿望中，选出三个广告角度。每个角度再用用户原话，写出三个吸引注意的开场，总共九个创意。如果某个角度缺少足够的原话，就删掉，不要硬凑。

画面重点展示用户想要的结果，而不只是产品本身。所有创意使用同一个优惠和购买链接，方便比较不同角度的表现。

作者使用的广告平台叫 Whop。具体素材尺寸和投放要求，要让人工智能读取平台文档，而不是凭记忆填写。

广告上线后，人工智能每天汇报花费、点击、销售和每笔成交成本。原文给出的暂停规则是：某个广告组的每笔成交成本，连续三天高于产品价格，就暂停。与此同时，还要把广告支出和实际净收入放在一起看。预算由人决定，广告不能编造收入、推荐或效果承诺。

这条路的核心，就是先听懂买家，再用买家的语言测试广告，而不是让人工智能凭空写几句漂亮文案。

本地服务走的是另一条路：不先研究人说了什么，而是寻找公开资料里看得见的需求信号。

比如，咖啡馆缺少招牌，房屋屋顶显得老旧，或者某处房产适合展示景观改造。前提是，这个行业确实存在可以从公开影像或记录中识别的信号。如果看不出来，人工智能就应该直说，不能硬编。

作者建议，第一批只使用一个明确的筛选条件。因为每增加一个条件，就可能引入一次猜测，也会缩小候选名单。先做出一批，再根据实际回应调整。

筛选时，先检查有没有影像，以及影像有多旧，再决定是否付费获取。原文的候选流程会排除超过三年的影像。即使影像通过检查，也不能保证房产现在没有变化，所以新区域的第一批仍要抽样核对。看不清、拿不准的对象，单独留待复核。

找到候选房产后，人工智能生成一张改造效果图。这里不是随便画一栋更漂亮的房子，而是在原始照片上编辑，只改变服务涉及的部分。作者建议使用三到四张参考图，减少模型对看不见区域的猜测。

这张图的作用，是让业主一眼明白：这项服务放到自己的房产上，大概会是什么样。

接着，为每处房产建立一个专属页面。页面顶部放效果图，再放地址和询价表单，询问业主希望什么时候收到报价。

有邮箱或电话，可以准备邮件、短信；只有邮寄地址，就准备明信片。所有渠道都指向同一个页面。作者说，在他自己的测试里，明信片表现更好，但这只是他的测试经验，不是普遍保证。

发送前，要校验联系方式，检查效果图，并让人工智能展示各渠道的数量和样例。批准之后，才能发送。

这里还要区分两种回应。扫描二维码、打开页面，表示有人产生了兴趣；填写表单、提出报价时间，才是更明确的询价。人工智能应把这些行为和地址、时间戳一起记录，不要把浏览直接当成成交。

如果你自己经营这项服务，流程到这里，接下来就是与客户沟通。如果你只负责获客，下一步才是把线索交给当地企业。

作者建议，向商家展示已经获得的、位于其服务范围内的询价样本，而不是只说“我能帮你找到客户”。例如，展示附近三位业主的改造图，以及他们希望收到报价的时间。覆盖范围内没有足够线索，就跳过，不要拿远处的客户来凑数。

收费可以先按条计算，让商家看到线索能否成交，以及一条线索究竟值多少钱。效果得到验证后，再讨论固定月费，或者指定区域的独家合作。持续交付的内容，是一个不断更新的线索面板，而不是一份卖完就结束的名单。

最值得记住的是：人工智能擅长把查找、整理、生成和记录连成流程，但需求有没有被识别准确，还得靠真实回应验证。先做小批次，检查图像和数据，再根据反馈调整；联系真人、承诺效果和决定预算，始终保留人工把关。
