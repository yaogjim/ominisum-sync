**Daniel San**

### 使用子代理保持你的 Claude 代码上下文整洁

长时间的 Claude 代码会话很快就会变得杂乱无章。每一个 grep、find 和 ls 命令都会留在你的会话上下文中，占用你再也不会查看的空间。子代理解决了这个问题：它们在自己的窗口中执行任务，只返回结果。

本文直入主题：什么是子代理、如何创建一个子代理、Claude Code 附带的内置功能，以及如何通过 CLAUDE\_CODE\_FORK\_SUBAGENT=1

#### 什么是分代理

子代理是一种专业助手，它在自身的上下文窗口中运行，拥有自己的系统提示、工具和权限。 主代理调用它，子代理独立完成工作，并返回摘要。

![Image](https://pbs.twimg.com/media/HG2dPKkXcAEFdnu?format=png&name=large)

你可以用一个 Markdown 文件和前置元数据来创建一个：

```markdown
---
name: code-reviewer
description: Reviews code for quality, security, and maintainability. Use after writing or modifying code.
tools: Read, Grep, Glob, Bash
model: sonnet
---

You are a senior code reviewer. When invoked:
1. Run git diff to see recent changes
2. Focus on modified files
3. Start the review immediately
```

Claude Code 自动识别它并在描述匹配任务时调用它。

#### 子代理的所在地

你可以根据范围将文件保存在不同位置。当两个子代理名称相同时，优先级更高的位置胜出。

![Image](https://pbs.twimg.com/media/HG2it8wakAAcOfu?format=jpg&name=large)

在大多数情况下，你会使用 .claude/agents/（将其提交到版本控制，与你的团队共享）或 \~/.claude/agents/（个人使用，在任何地方可用）。

![Image](https://pbs.twimg.com/media/HG2h12BagAAlLhK?format=jpg&name=large)

#### 问题：一个窗口处理一切

没有子代理时，主代理在单一上下文中完成所有操作。你让它检查控制器、查找模式、验证某些内容。它会执行 grep、find、ls、glob、cd、更多的 grep、另一个 find，每次调用都保持在你的上下文中。

![Image](https://pbs.twimg.com/media/HG2jzwPWwAA9Fld?format=png&name=large)

30 分钟后，你会有 80k 个你永远不会读的噪声 token。

当 Claude 压缩上下文时，这些信息会被扁平化。重要细节会在总结中丢失。

![Image](https://pbs.twimg.com/media/HG2k2i-aQAESJ6v?format=jpg&name=large)

#### 内置的子代理：探索和规划

Claude Code 随附适用于常见场景的子代理。您最常使用的两个是：

探索 : 在不污染主上下文的情况下搜索代码库。在其独立窗口中执行所有的 grep 和 find 调用，并仅返回相关结果。

计划 ：调查并制定实施计划。读取文件，理解架构，并返回一份分步文档。你的主要上下文永远不会看到中间读取的内容。 流程看起来是这样的：

![Image](https://pbs.twimg.com/media/HG2lXxzbQAAxYxb?format=png&name=large)

不再是窗口中50次工具调用，你会得到3行带有答案的内容。其余的被丢弃。

[![视频](https://pbs.twimg.com/amplify_video_thumb/2048475670343467008/img/4nYUD5CEUMv65i4l.jpg)](https://x.com/dani_avila7/status/2048486242321662189)[![视频](https://pbs.twimg.com/amplify_video_thumb/2048475670343467008/img/4nYUD5CEUMv65i4l.jpg)](https://x.com/dani_avila7/status/2048486242321662189)

#### 分叉上下文:

默认情况下，子代理会从空白上下文开始。这对保持简洁很有利，但当你已经投入了 100k 个 token 来构建对代码库的理解，并且希望子代理继承所有这些理解时，这就不好了。

![Image](https://pbs.twimg.com/media/HG2tsNjasAAO8Hy?format=png&name=large)

分叉解决了这个问题：子代理在分叉的那一刻会从父代理的上下文的完全相同副本开始。

export CLAUDE\_CODE\_FORK\_SUBAGENT=1

#### 它是如何工作的

一旦设置了 CLAUDE\_CODE\_FORK\_SUBAGENT=1，每个子代理生成时默认继承完整的父上下文。

你也可以使用 /fork 斜杠命令按需分叉：

![Image](https://pbs.twimg.com/media/HG2rKsIXoAA38ET?format=jpg&name=large)

该 fork 的工具调用保持隔离，只有其最终结果会返回到你的对话中。

![Image](https://pbs.twimg.com/media/HG2ra1ObQAAvOdS?format=jpg&name=large)

分叉的子代理：

- 在分叉时继承父进程的完整会话
- 与父级共享提示词缓存前缀（子级 2 到 N 的输入 token 成本约低 10 倍）
- 独立运行，其工具调用不会污染父进程
- 仅返回最终总结

#### 实时查看：上下文-时间线钩子

从控制台跟踪主代理的上下文以及并行运行的子代理很难。我构建了一个钩子来解决这个问题：context-timeline。

链接：

[https://www.aitmpl.com/component/hook/monitoring/context-timeline](https://www.aitmpl.com/component/hook/monitoring/context-timeline)

![Image](https://pbs.twimg.com/media/HG2tdzUXIAAKaa6?format=jpg&name=large)

安装：

```bash
npx claude-code-templates@latest --hook monitoring/context-timeline
```

它的作用：当你开启一个会话时开始，并展示一条时间线，其中包含主代理的上下文窗口，以及子代理如何在它们各自独立的上下文中开始工作。

你正在运行的每个子代理都会实时显示，连同它完成时返回给主代理的上下文。

我的建议是，从 .claude/agents/ 中的一个简单子代理开始。你会在第一次长时间会话中感受到差异。

## 通俗精炼（1）

#### 使用子代理保持 Claude Code 上下文整洁：核心总结

##### 一句话概括

Claude Code 的**子代理（Subagent）**可以把搜索、审查、探索等任务放到独立上下文中执行，只把最终结果返回主会话，从而减少上下文污染、降低噪声、提升长会话效率。

---

##### 核心问题：长会话会快速 “上下文污染”

在 Claude Code 中，长时间开发会话会产生大量工具调用记录：

- `grep`
- `find`
- `ls`
- `glob`
- `cd`
- 各类文件读取与搜索命令

这些内容都会留在主会话上下文中，占用 token。  
一段时间后，可能积累数万甚至 80k+ 的无用 token。

当上下文被压缩时，真正重要的信息可能会在摘要中丢失，影响后续推理质量。

---

##### 子代理是什么

子代理是一个独立运行的专业助手，具备：

- 独立上下文窗口
- 独立系统提示词
- 独立工具权限
- 独立任务执行过程

主代理只负责调用它，子代理完成任务后，只返回最终摘要。

简单理解：  
**主代理负责决策，子代理负责脏活累活。**

---

##### 如何创建子代理

子代理可以通过 Markdown 文件定义，例如：

```markdown
---
name: code-reviewer
description: Reviews code for quality, security, and maintainability. Use after writing or modifying code.
tools: Read, Grep, Glob, Bash
model: sonnet
---

You are a senior code reviewer. When invoked:
1. Run git diff to see recent changes
2. Focus on modified files
3. Start the review immediately
```

Claude Code 会根据`description`自动判断何时调用该子代理。

---

##### 子代理文件放在哪里

常见位置有两类：

###### 团队共享

```bash
.claude/agents/
```

适合提交到版本控制中，团队成员共享统一代理能力。

###### 个人使用

```bash
~/.claude/agents/
```

适合个人全局配置，在不同项目中复用。

如果不同位置存在同名子代理，优先级更高的位置会覆盖低优先级配置。

---

##### 内置子代理：探索与规划

Claude Code 自带一些常用子代理，其中最典型的是：

###### Explore：代码库探索

用于搜索代码、查找模式、理解结构。

它会在独立上下文中执行大量`grep`、`find`等操作，最后只返回关键信息。

效果是：

- 主上下文不再堆满工具调用
- 搜索过程被隔离
- 结果更简洁
- 后续推理更干净

---

##### 分叉上下文：让子代理继承主会话理解

默认情况下，子代理从空白上下文开始。

这有利于保持干净，但如果主会话已经积累了大量对项目的理解，子代理无法继承这些上下文可能会影响效果。

这时可以开启分叉模式：

```bash
export CLAUDE_CODE_FORK_SUBAGENT=1
```

开启后，子代理会在启动时继承父会话的完整上下文。

---

##### 分叉子代理的优势

分叉后的子代理具备几个特点：

- 继承主会话在分叉时的完整上下文
- 工具调用仍然隔离，不污染主会话
- 只把最终总结返回主代理
- 可共享提示词缓存前缀，后续子代理 token 成本更低

适合在已经深度理解代码库之后，让多个子代理并行处理专项任务。

---

##### 监控工具：context-timeline

作者还提供了一个钩子工具`context-timeline`，用于实时查看：

- 主代理上下文变化
- 子代理何时启动
- 子代理各自独立上下文
- 子代理完成后返回了什么

安装方式：

```bash
npx claude-code-templates@latest --hook monitoring/context-timeline
```

它可以帮助开发者观察复杂 Claude Code 会话中的上下文流动。

---

##### 实践建议

建议从一个简单子代理开始，例如放在：

```bash
.claude/agents/
```

先让它承担代码审查、代码搜索、模块探索等高噪声任务。

在第一次长时间 Claude Code 会话中，就能明显感受到：

- 主上下文更干净
- 回答质量更稳定
- 长任务更易维护
- 多任务协作更清晰

---

##### 产品视角总结

子代理本质上是在 Claude Code 中引入了 “任务隔离” 和 “上下文治理” 机制。

它解决的不是单次回答能力问题，而是长周期 AI 编程协作中的核心瓶颈：

> 如何让 AI 在复杂任务中持续保持清晰、低噪声、可控的工作记忆。

对于复杂代码库、多人协作项目、长期 AI 编程会话，子代理会成为非常关键的基础能力。

##### 5. 分叉上下文：让子代理继承主会话理解

默认情况下，子代理从空白上下文开始。

这有利于保持简洁，但也有缺点：

如果你已经花了很多时间让 Claude 理解项目，比如主会话已经积累了**100k token**的代码库背景信息，普通子代理无法继承这些理解。

为了解决这个问题，可以使用 “分叉上下文”。

开启方式：

```bash
export CLAUDE_CODE_FORK_SUBAGENT=1
```

开启后，子代理在生成时会继承父代理当前完整上下文。

也可以使用`/fork`命令按需创建分叉子代理。

---

##### 6. 分叉子代理的工作方式

开启分叉后，子代理具备以下特点：

- 在分叉时继承父会话的完整上下文
- 与父代理共享提示词缓存前缀
- 从第 2 个到第 N 个子代理开始，输入 token 成本大约降低**10 倍**
- 子代理独立运行
- 子代理的工具调用不会污染父会话
- 最终只返回结果总结

简单来说，分叉子代理既能理解主会话已有背景，又不会把搜索、分析过程塞回主上下文。
