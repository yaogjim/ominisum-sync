### 你需要从 claw-code 仓库学习什么

![Image](https://pbs.twimg.com/media/HE2psIVbcAA6VLz?format=jpg&name=large)

### 停止盯着文件

人们对从零开始编写 claw-code 的 Python 代码耗时 2 小时感到抓狂。而我们用 Rust 重写仅用了一天（0.1.0 版本已发布！）

一个复杂的智能体系统，在3月31日日出前被逆向工程并从零开始重新实现。该代码仓库在两小时内达到了50,000星标。现在已经超过117,000。

开发者们很兴奋。不少人却感到恐惧。看着如此规模的代码库以那样的速度被重建，感觉就像时间线出了问题。对一些人来说，这像是他们想学习的超能力；对另一些人来说，这却像是一张解雇通知。

但是如果你盯着生成的 Python 文件看，你是在看错误的层。

代码是副产品。随后的 Rust 移植版本也是副产品。在 claw-code 代码仓库中值得研究的是产生了所有这些内容的系统。claw-code 一直是一个展示项目。重点从来不是 Python 文件或 Rust 包。重点是基于 clawhip 的智能体协调系统，它在开发者睡着的时候构建了这些文件和包。

该系统在实际运行中的真实情况如下：一个人在手机上打开 Discord，输入一句话，然后放下手机。他们可能去冲咖啡，也可能去睡觉。代理们读取消息，将工作分解为任务，互相分配角色，编写代码，测试代码，为此争论，修复故障，一切通过后进行提交。第二天早上，这个人再次查看，发现端口已完成。

没有终端。没有 IDE。没有 SSH 会话。没有分屏 Vim 配置。Discord。一款聊天应用。

这是大多数人会跳过的部分。README 包含 OmX 工作流程在终端窗格中运行的截图，人们会认为开发者一直坐在那些窗格前，手动操控每一步。终端会话属于代理。人类的界面是一个 Discord 频道、一个文本框和一个发送按钮。

三个工具使这项工作得以完成，并且它们各自处理问题的不同部分。

oh-my-codex，通常被称为 OmX，是一个位于 OpenAI 的 Codex CLI 之上的工作流层。它为你提供可重用的关键字，如

[$architect](https://x.com/search?q=%24architect&src=cashtag_click) 用于分析，

[$executor](https://x.com/search?q=%24executor&src=cashtag_click)

用于实施，

[$plan](https://x.com/search?q=%24plan&src=cashtag_click)

用于结构化规划。它还提供更复杂的工作流模式：

[$ralph](https://x.com/search?q=%24ralph&src=cashtag_click)

运行持续执行循环，直到任务被验证为完成，并且

[$team](https://x.com/search?q=%24team&src=cashtag_click)

协调多个代理在同一问题的不同部分并行工作。 当开发人员输入

[$team](https://x.com/search?q=%24team&src=cashtag_click)

"实现核心运行时" 在 Discord 中，OmX 将这句话转化为一个结构化的多步骤工作流并进行了分配。

clawhip 是作为后台守护进程运行的通知和事件路由器。它会监控 Git 提交、GitHub 问题和 PR、tmux 会话以及代理生命周期事件，然后将状态更新发送到正确的 Discord 频道。这里的重要设计决策是，clawhip 将所有监控工作都放在代理的上下文窗口之外进行。正在执行复杂实现任务的代理不需要让其有限的内存被通知逻辑和消息格式设置占用。clawhip 负责消息发送，因此代理可以专注于实际的代码。

oh-my-openagent 提供多个代理之间的协调逻辑。当架构代理的计划与执行代理构建的内容发生冲突时，oh-my-openagent 会处理该分歧。它处理代理之间的信息共享、任务交接以及输出验证循环。

单独使用这些工具中的任何一个都无法在一小时内完成 claw-code 的交付。当它们协同工作时，就形成了一个闭环开发循环。人类通过 Discord 提供指导，代理则负责执行工作。

代理团队已经定义了角色，并且他们在一个循环中运作。

![Image](https://pbs.twimg.com/media/HE2qxFja0AA2Uf6?format=jpg&name=large)

架构师读取指令并制定计划。它分析目标系统的结构，确定需要构建的内容，并写出一系列步骤。执行者获取该计划并开始构建。它编写代码、运行工具、生成测试。审查者检查执行者的输出，发现问题并发送反馈。如果反馈足够严重，流程返回到架构师进行重新规划。此循环重复，直到输出通过所有检查。

![Image](https://pbs.twimg.com/media/HE2qzFqbAAAYszc?format=jpg&name=large)

整个过程中，发起这件事的人可能一直在睡觉。代理人员将更新提交到 Discord 频道。如果有内容被拦截，他们会在消息中提及开发者；如果没有内容被拦截，他们会继续进行。

![Image](https://pbs.twimg.com/media/HE2qkbgbsAA3bQF?format=jpg&name=large)

如果你参加了 Ralphthon（

[https://luma.com/kxoq82yq](https://luma.com/kxoq82yq)）或 OmOCon（

[https://luma.com/omocon-sf](https://luma.com/omocon-sf)

）你已经了解这个理念了。这些活动背后的理念具体且实用：不要再在黑客马拉松熬夜手工编写代码了。那个时代已经结束了。相反，把精力花在设计智能体系统和设置它们之间的协调上。你休息，它们工作。

Ralphthon 的参与者中，那些始终理解这一点并持续交付更多成果的人，比那些试图超越机器打字速度的人表现更好。那些建立了良好的代理协调、给出明确指导并随后放手的人，在第二天早上就有了可用的产品。而那些试图对每一行代码都进行微观管理的人，在半夜就已精疲力尽，交付的成果也更少。

这门课程很简单，在活动结束时就显而易见了。瓶颈不再是你的手指能多快地输入语法了。

当一个系统能够在六十分钟内移植整个代码库时，什么变得昂贵了？知道要构建什么，知道为什么构建，理解各个部分应该如何组合在一起，拥有对目标架构的清晰心智模型，能够将其分解为代理可以执行的任务，并且知道如何建立协调机制，以便多个代理能够并行保持高效工作。

这些技能会随着代理变得更强而变得更有价值。更快的代理不会减少对清晰思考的需求，反而会增加这种需求。如果快速代理组成的团队缺乏良好的指导，会很快产生大量错误代码。

我们对最终系统应该是什么样子有清晰的认识。他知道哪些部分可以并行化，哪些部分有依赖关系。他设定了约束条件，给了执行者发挥的空间，然后不再干涉。这就是产生结果的原因。Python 文件就是证据。

现在开发者社区中流传着一种特定的担忧。这种担忧是，AI 将比人类打字更快，让人类变得多余。claw-code 表面上似乎证实了这种担忧。一小时。整个系统被重建。

但看看那位开发者在那一小时内实际做了什么。他可能在 Discord 频道里输入了大约十句话。产出“claw-code”的技能并非打字速度，而是架构清晰度、任务分解和系统设计。这些技能并不会随着 AI 代理的改进而变得更廉价，反而会变得稀缺。

当你查看 claw-code 代码仓库时，跳过 src/ 目录。去了解构建了它的 OmX 工作流。去看看 clawhip 是如何通过将通知路由出代理的上下文来保持代理专注的。去研究架构师、执行器和审核者代理是如何通过 oh-my-openagent 进行协调的，而无需人工在每一步都照看。

这个人从未打开过终端。他们在 Discord 里输入了内容。到了早上，claw-code 成了一个梗。一个大多数人都读错的代码仓库获得了 117,000 颗星。他们看到了一个快速移植版本。他们本应看到的是一个演示。claw-code 是一个基于 clawhip 的协调系统在一位有清晰愿景的人将其指向一个难题并放手后所能实现的功能的展示。代码从来不是产品，编写代码的系统才是。

#### 哲学问题 - 还剩什么

在 claw-code 获得 10 万星标后，发生了一些奇怪的事情。那些我从未交谈过的人开始给我发消息。数月来无视我私信的老熟人突然在几分钟内回复了。之前拒接我电话的投资者现在开始询问我这周是否有空。我还是两周前的那个人。我没有一夜之间变聪明。代码仓库走红了，社交规律也发生了变化。

我目睹了这一切的发生，想起了 Cluely。一位哥伦比亚大学辍学生打造了一款病毒式传播的产品，突然之间，所有关于他的讨论都围绕着融资轮次和媒体报道展开。产品本身几乎变成了次要的东西。重要的是人们在谈论它。这种喧嚣产生了引力，而引力又吸引来了资金、关注和地位。这是一种如今在旧金山不断重复的模式。

过去一年里，城市中发生了一些变化。开发者过去会比拼自己能构建什么。代码质量、基础设施的可靠性、架构的优雅性，这些过去是区分人的标准。现在这些标准不再能区分人了。当每个人都能通过相同的 API 获取相同的智能时，代码本身不再是差异化因素。拥有良好提示直觉和清晰规范的初级开发者现在能在一个下午产出原本需要高级工程师一周才能完成的成果。“能构建”与“不能构建”之间的差距正在迅速缩小。

那么人们转而竞争什么呢？是“噪音”、曝光度和社会地位。旧金山的科技圈已经变成了一场地位游戏，目标是让自己足够高调，以至于人们会认为你一定很重要。你不断发布内容，受邀参加晚宴，在讨论会上发言，积累粉丝，然后将这种关注度转化为资金。资金让你能够招聘，招聘让你能够推出产品，产品推出后你又有更多东西可以发布，如此循环往复。实际推出的产品质量远不如人们是否关注它重要。

GitHub 星标过去有特定含义。在 AI 辅助开发成为常态之前，建立一个拥有数千星标的代码仓库需要真正的工程投入。人们必须亲自编写代码、调试、维护，并响应问题。星标数量和分叉数量是产品质量粗略但诚实的指标。如果一个代码仓库有 10,000 星标，你可以合理地认为有经验的团队开发出了有用的东西。这种假设正在失效。claw-code 在两小时内达到了 50,000 星标。代码可用，但星标数量反映的是传播性，而非数月的精心工程投入。关注这一趋势的人都明白这意味着什么：旧信号正在失去其可靠性。

有一篇帖子在流传，称未来科技公司中只有四种工作会留存下来。这四种工作分别是：懂氛围的程序员——他们能快速运用 AI 工具，以产品思维思考；负责安全和基础设施的人员，他们整合一切并保持系统稳定，因为 AI 生成内容的庞大数量将需要大量的运营关注；面向用户的岗位，即那些善于沟通、能为用户提供良好体验的人；以及“房间里的成年人”——那些能适度放慢节奏，防止快速扩张的组织分崩离析的人，如法律、财务和人事管理者。

我考虑这个列表，感觉大致是对的，尽管表述有些生硬。这四个类别有一个共同点：它们都不涉及编写代码，而是关于判断、品味、稳定性和人际连接。这些是 AI 不擅长的事情，也是无法被简化为提示词的事情。

当智能成为一种商品时，科技行业还剩下什么？我总是回到同一个答案。那就是：对值得构建的事物的信念，审视问题并辨别哪些部分重要、哪些是噪音的能力，即使在无人关注时也能设计出正确运行的系统的耐心，以及坦诚承认某事物是演示还是真实产品的诚实。

claw-code 是一个演示。我从一开始就这么说过。它展示了协调层能实现什么。117,000 颗星是个梗。有趣的问题是，当这个梗消退、私信互动减少后，你会构建什么。那才是真正的工作开始的时候，而这项工作与你的代理能多快打字无关。

## 通俗精炼（1）

### 2026-04-02 02:35:29

#### 你需要从 claw-code 仓库学习什么

##### 一句话结论

**不要只盯着代码本身，更值得学习的是 “让代码自动被产出” 的智能体协作系统。**

##### 核心观点：代码已经不是重点

文章想表达的核心很明确：`claw-code`爆火，不是因为那几份 Python 或 Rust 代码本身有多神奇，而是因为它背后展示了一种新的开发方式 ——**人负责定义目标与约束，智能体负责拆解、执行、验证和协同交付。**

换句话说，**代码只是结果，系统设计才是产品。**

##### 这套系统到底厉害在哪

真正值得研究的，不是`src/`目录，而是三层能力的配合：

###### 1. 工作流层：OmX

它把一句自然语言指令，转成结构化开发流程。  
比如：分析、规划、执行、并行协作、持续验证，不再靠人手工盯流程。

###### 2. 路由层：clawhip

它负责监控提交、问题、PR、会话状态，并把更新同步到 Discord。  
关键价值在于：**把通知和状态管理从智能体上下文里剥离出去**，让智能体专注做事，而不是浪费上下文处理杂讯。

###### 3. 协调层：oh-my-openagent

它解决多智能体之间的分工、交接、冲突和复核问题。  
本质上，它让 “架构师 — 执行者 — 审查者” 形成闭环，而不是各干各的。

##### 开发范式的变化：人不再亲自敲每一行代码

文章强调了一个非常重要的转变：

过去，开发者的价值常常体现在 “写得快、写得多、熬得久”；  
现在，更有价值的是：

- 知道该做什么
- 知道为什么做
- 能把目标拆成可执行任务
- 能设计好多智能体协作机制
- 能在关键处给出清晰约束，而不是事无巨细地干预

也就是说，**瓶颈正在从 “写代码” 转向 “定义问题与组织系统”。**

##### 对产品经理 / 管理者最有启发的点

这篇文章其实特别像在讲一种新的 “产品交付模型”：

###### 1. 从 “自己做” 转向 “设计做事的系统”

未来高价值角色，不是最会敲代码的人，而是最会搭建流程、设定规则、定义标准的人。

###### 2. 清晰表达能力变得更值钱

智能体越强，越需要清晰目标。  
因为方向一旦错了，系统只会更快地产生更多错误结果。

###### 3. 微观管理会成为低效行为

那些试图盯每一步、管每一行的人，反而更慢。  
真正高效的人，是先把架构、依赖、验收标准想清楚，然后放手让系统执行。

##### 更深一层：未来竞争的焦点不再只是 “能不能做出来”

文章后半部分提出了一个更现实的判断：

当 AI 让 “构建能力” 快速普及后，单纯 “会做产品、会写代码” 不再足够稀缺。  
行业竞争会转向这些更难替代的东西：

- 判断力
- 品味
- 系统稳定性
- 与用户沟通的能力
- 组织协同与节奏控制能力
- 对 “什么值得做” 有清晰信念

这意味着，**未来真正拉开差距的，不是产出速度，而是认知质量。**

##### 作者真正想提醒你的事

`claw-code`是一个很成功的演示，但它不是全部。  
它真正证明的不是 “AI 会写代码”，而是：

**未来最重要的能力，是设计一个能持续产出结果的协作系统。**

当 “生成代码” 越来越便宜后，真正昂贵的将是：

- 对问题的定义
- 对方向的判断
- 对系统的编排
- 对产品价值的识别
- 对真实需求的理解

##### 最后总结

`claw-code`给人的最大启发不是 “AI 写代码有多快”，而是：

**软件开发正在从 “手工生产代码” 升级为 “设计并管理智能体协作系统”。**

所以，这个仓库最值得学的不是某个实现细节，而是背后的方法论：

**人负责愿景、架构和判断；系统负责执行、迭代和交付。**

## 结构化（1）

### 2026-04-02 02:36:35

#### 主旨概括

这篇文章想说明：`claw-code`真正值得学习的，不是它 “1 小时重建代码库” 这件事本身，而是背后的智能体协作系统。作者认为，在 AI 时代，真正稀缺的能力不再是 “手写代码有多快”，而是架构设计、任务拆解、协调机制和判断力。

#### 1. 不要只盯着生成出来的代码

- 很多人被`claw-code`的速度震撼：Python 版本从零写出让人觉得 “要花 2 小时”，而 Rust 重写只用了 1 天，`0.1.0`版本已经发布。
- 这个仓库传播极快：在**2 小时内达到 50,000 星标**，后来又超过**117,000 星标**。
- 但作者强调，**代码文件只是结果，不是重点**。真正应该研究的是：什么样的系统，能在开发者休息时自动把这些代码做出来。
- 换句话说，`src/`目录只是 “证据”，真正的 “产品” 是生产这些代码的协作系统。

#### 2. 这个系统的真实工作方式

- 作者描述的使用场景非常简单：人只需要在**Discord**里发一句话，然后离开。
- 接下来，代理会自动完成一整套流程：  
  - 读取消息  
  - 拆解任务  
  - 分配角色  
  - 编写代码  
  - 运行测试  
  - 互相争论和修复问题  
  - 最后通过检查后提交
- 人类不需要一直守在终端前，也不需要 IDE、SSH、分屏 Vim。
- 关键点是：**人类的界面是聊天框，终端属于代理。**

**例子：**
如果开发者在 Discord 输入`$team" 实现核心运行时 "`，系统会自动把这句自然语言转成一个可执行的多步骤协作任务。

#### 3. 三个核心工具分别解决什么问题

##### 3.1 OmX：把一句话变成工作流

- `oh-my-codex`（简称**OmX**）是构建在 OpenAI Codex CLI 之上的工作流层。
- 它提供可复用指令，例如：
  - `$architect`：做分析
  - `$executor`：负责实现
  - `$plan`：生成结构化计划
- 它还有更复杂的模式：
  - `$ralph`：持续执行，直到任务验证完成
  - `$team`：让多个代理并行处理同一个问题的不同部分
- 作用可以理解为：**把人的一句高层指令，翻译成可执行的代理协作流程。**

##### 3.2 clawhip：把通知从代理上下文中剥离出去

- `clawhip`是后台守护进程，负责监控：
  - Git 提交
  - GitHub issue / PR
  - tmux 会话
  - 代理生命周期事件
- 然后把这些状态更新路由到对应的 Discord 频道。
- 最重要的设计点是：**通知逻辑不占用代理的上下文窗口**。
- 这样代理在做复杂实现时，不需要浪费有限上下文去处理消息格式、状态广播等杂事。

**通俗理解：**
就像让程序员专心写核心逻辑，而把 “发进度汇报”“同步群消息” 交给一个专门的助理去做。

##### 3.3 oh-my-openagent：处理代理之间的分歧与交接

- `oh-my-openagent`负责多个代理之间的协调。
- 它处理的事情包括：
  - 信息共享
  - 任务交接
  - 输出验证
  - 架构计划和执行结果冲突时的协调
- 单个工具本身都不足以在 1 小时内交付整个项目，但这三个工具组合起来，形成了一个**闭环开发系统**。

#### 4. 代理团队是如何循环工作的

- 作者把整个流程概括为一个角色分工明确的循环：
  - **架构师**：理解目标，制定计划
  - **执行者**：按计划写代码、跑工具、生成测试
  - **审查者**：检查结果、挑出问题、给反馈
- 如果反馈问题严重，就回到架构师重新规划；否则继续迭代，直到通过全部检查。
- 在这个过程中，真正发起任务的人甚至可能一直在睡觉。
- 只有在遇到关键阻塞时，代理才会在 Discord 里提醒开发者；没问题就继续自动推进。

#### 5. 作者想强调的真正 “新能力”

- 作者提到，参加过**Ralphthon**或**OmOCon**的人，通常会更容易理解这个理念：
  - 不要再在黑客马拉松里熬夜手写代码
  - 应该把精力放在设计智能体系统和代理协作上
- 实践结果也很明显：
  - 那些**给出清晰目标、搭好协作机制、然后放手**的人，往往第二天能拿到可用产品
  - 那些还在**逐行微观管理**的人，通常半夜就已经疲惫不堪，产出反而更少
- 作者因此得出结论：**瓶颈已经不是打字速度，而是清晰思考能力。**

#### 6. 在 AI 时代，什么能力反而更值钱

- 当系统能在**60 分钟内移植整个代码库**，真正昂贵的就不再是 “写代码” 本身，而是：
  - 知道应该构建什么
  - 知道为什么要这样构建
  - 理解各部分如何组合
  - 能把目标拆成代理可执行的任务
  - 能设计多代理并行又不混乱的协调机制
- 作者特别强调：**代理越强，这些能力越值钱。**
- 因为如果没有清晰指导，强大的代理只会更快地产生大量错误代码。

**核心观点：**
AI 并没有让 “思考” 更便宜，反而让 “高质量思考” 更稀缺。

#### 7. 对 “AI 让人类开发者失业” 的回应

- 社区里常见担忧是：AI 会比人类打字更快，所以人类会变得多余。
- `claw-code`看起来像是在证明这一点：**1 小时，整个系统被重建。**
- 但作者提醒大家看另一面：那位开发者在这一小时里，并不是疯狂写代码，而可能只是在 Discord 里输入了**大约十句话**。
- 所以真正创造产出的能力，不是手速，而是：
  - 架构清晰度
  - 任务分解能力
  - 系统设计能力
- 这些能力不会随着 AI 进步而贬值，反而会更稀缺。

#### 8. 从`claw-code`延伸出的 “技术圈变化”

- 在仓库超过**10 万星标**后，作者观察到一件事：社交反馈突然发生变化。
- 过去不回私信的人开始迅速回复，之前不接电话的投资人也开始主动联系。
- 作者借此指出：现在科技圈越来越像一个**注意力和地位驱动的系统**。
- 他还提到一个相似案例：**Cluely**。产品爆红后，外界讨论的重点很快从产品本身转移到了融资、媒体曝光和话题热度。
- 也就是说，今天很多时候真正带来资源的，不一定是产品质量本身，而是它有没有形成 “声量”。

#### 9. 为什么 GitHub 星标正在失去原来的意义

- 过去，一个拥有几千星标的仓库，往往意味着团队投入了大量真实工程工作：
  - 写代码
  - 调试
  - 维护
  - 响应 issue
- 所以星标数虽然粗糙，但曾经是一个相对诚实的质量信号。
- 但现在这个假设开始失效。
- `claw-code`在**2 小时内拿到 50,000 星标**，说明这些星标更多反映的是**传播性和话题性**，而不一定是数月工程沉淀。
- 作者的判断是：**旧的评价信号正在失真。**

#### 10. 未来哪些能力可能更难被替代

- 文中提到一篇流传很广的观点：未来科技公司里可能主要剩下四类工作：
  - 能快速用 AI 工具并具备产品感的 “氛围程序员”
  - 负责安全和基础设施的人
  - 面向用户、擅长沟通的人
  - 能防止组织失控的 “房间里的成年人”，比如法务、财务、人事
- 作者认为这个说法虽然有点生硬，但大方向是对的。
- 因为这些岗位共同依赖的不是 “写代码” 本身，而是：
  - 判断
  - 品味
  - 稳定性
  - 人际连接
- 这些恰恰是 AI 目前最不擅长、也最难被压缩成提示词的部分。

#### 11. 作者最后给出的答案：真正剩下的是什么

- 当 “智能” 越来越像商品，真正重要的能力变成了：
  - 对什么值得构建有信念
  - 能分辨什么重要、什么只是噪音
  - 有耐心把系统设计对，即使没人关注
  - 有诚实去区分：这是一个 demo，还是一个真实产品
- 作者再次强调：`claw-code` **是一个演示（demo）**，而不是一个被包装成终局产品的东西。
- **117,000 星标**更像一个梗、一种传播现象。
- 真正的问题不是 “代理打字有多快”，而是：**热度过去之后，你还能构建什么真正有价值的东西。**

#### 结论

- `claw-code`给人的最大启发，不是 “AI 写代码太快了”，而是**软件开发的核心已经从 “亲手写代码” 转向 “设计会写代码的系统”**。
- 对个人和团队来说，未来最关键的能力将是：清晰的目标、合理的架构、有效的任务分解、稳定的多代理协作，以及对产品价值的判断。
