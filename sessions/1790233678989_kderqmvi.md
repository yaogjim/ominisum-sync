> **摘要**：项目介绍了面向 Android 10+ 手机和比亚迪 DiLink 3.0+ 车机的开源投屏方案：以虚拟显示、H.264 视频流和触控回传实现车机操作，并说明安装条件、模块划分、已实现功能及兼容性限制。性能与适配情况主要来自项目自述。

## 分析要点

- **核心高价值点**：将车机应用和虚拟显示服务打包进手机 APK，由手机端负责向车机部署，降低车机侧安装门槛。
- **留存建议**：浏览项目概况；有车机交互或Android投屏需求时保留参考（包含可复用的手机端、车机端与虚拟显示服务分工，以及安装部署思路。）

**知识要点**

- 方案由手机端、车机端、虚拟显示服务和共享协议模块组成，分别承担部署与转发、交互与解码、画面生成及通信职责。
- 视频流从手机虚拟显示器传向车机，车机触控事件再回传手机并注入。
- 使用条件包括 Android 10+、DiLink 3.0+、USB 调试及可用的车机 USB-A 接口；部分机型还有额外限制。

**行动项**

- 试用前核对手机系统、车机版本、USB 调试和机型限制。
- 需要自行构建时，使用文中提供的 Gradle 命令生成手机端调试 APK。
- 在目标设备上实测投屏延迟、触控和断线恢复，不直接将项目自述性能视为通用结果。

#### DiLink-Auto

在汽车内置屏幕上使用手机应用。开源，无需 Google 服务。

适用于任何 Android 10+ 手机与比亚迪 DiLink 3.0+ 信息娱乐系统配对的开源 Android Auto 替代方案。最初源于小米 HyperOS / 中国 ROM 的空白，但通用适用。

DiLink-Auto 将你手机上的应用镜像到车载显示屏上，并支持完整的触控交互。可直接从车载屏幕启动导航、音乐、消息——你手机上的任何应用。通知会显示在车载导航栏上，并带有进度指示器。H.264 视频最高可达 60fps、8Mbps CBR，同时关闭手机屏幕以节省电量。

最初的动机：当你的手机无法运行 Android Auto（中国 ROM、没有 Google Play Services），而你的车只支持 Android Auto（没有 CarWith、CarPlay 或 Carlife）时，弥合这一差距。但 DiLink-Auto 适用于任何 Android 手机——无论有没有 Google Services。

Device Issue

Xiaomi 17 Pro Max（HyperOS 3，中国 ROM） 没有 Android Auto——没有 Google Play Services

比亚迪驱逐舰 05 / 国王（巴西市场） 车机仅支持 Android Auto

Samsung Galaxy (One UI 5+) Auto Blocker 阻止 USB ADB，严格的电池限制

Any Android 10+ phone 无论 ROM 或 Play 服务如何均可运行

#### Requirements

**Phone:**

- Any Android 10+ phone
- USB 调试已启用（开发者选项）
- 所有文件访问权限（首次启动时提示）

**Car:**

- BYD DiLink 3.0 or newer
- One free USB-A port

手机在虚拟显示器上运行你的应用，将屏幕编码为 H.264 视频，并将其流式传输到车机。车机屏幕上的触摸操作会被发送回手机，并作为真实的触摸事件注入。手机的物理屏幕保持关闭（节省电量），并且可以独立使用。

#### Install

下载最新发布版本或从源代码构建：

1. **Build:**`./gradlew :app-client:assembleDebug`

汽车 APK 和 VD 服务器 JAR 捆绑在手机 APK 内——你无需在汽车上安装任何东西，安装汽车应用也不需要互联网连接。只需将手机连接到汽车的 USB 端口，然后点击“安装到汽车”。

#### Current Status

**Working:**

- 60fps H.264 视频流（8Mbps CBR，Main profile，可通过握手配置）
- 全触摸输入（多点触控、双指缩放）
- 带搜索、字母排序、64dp 图标、自适应网格的应用启动器
- 车机屏幕上的通知，带进度条，点击打开
- 通过 GitHub Releases（发布）或预发布版（调试）进行自更新
- 自动更新：手机检测到车机应用版本过旧（版本名称比较），并通过 WiFi ADB 进行更新
- 投屏期间手机屏幕关闭（节省电量）
- 针对所有必需权限的引导式入门
- 国际化：英语、葡萄牙语、俄语、白俄罗斯语、法语、哈萨克语、乌克兰语、乌兹别克语
- USB 断开后恢复显示（v0.14.0+）
- 已在 BYD DiLink 3.0（1920x990）+ Xiaomi 17 Pro Max（Android 16）+ POCO F5 + Galaxy S24 上测试

**Known limitations:**

- 必须禁用 Samsung Auto Blocker 才能使用 USB ADB（设置 → 安全 → 自动拦截器 → 关闭）。
- Samsung Knox 在首次访问虚拟显示器时可能会显示安全提示。
- VD 服务器进程在 USB 断开时重启（自动重新连接）。
- 必须手动启用热点（Android 16 限制）。
- 偶发视觉伪影——解码器重启竞态，在下一个关键帧（约 1 秒）恢复。
- 负载下 \~ 的流式传输延迟为 100-200ms。CBR 8Mbps。
- USB 突然断开后，显示屏可能会保持关闭状态（已在 v0.14.0 中修复）。

#### Project Structure

手机 APK（ `app-client` ）内嵌了车机 APK（ `app-server` ）和 VD 服务器 JAR。安装手机应用时，所需的一切都已打包在内。

```
DiLink-Auto/
├── protocol/       Shared library (framing, messages, discovery, USB ADB)
├── app-client/     Phone APK — relay, VD deploy, car auto-update, FileLog
├── app-server/     Car APK — UI, connection state machine, video decoder
├── vd-server/      VirtualDisplay server (compiled to JAR, deployed by phone)
├── docs/           Documentation
└── gradle/         Build system
```

#### DiLink-Auto：用安卓手机在比亚迪车机屏幕上运行应用

**DiLink-Auto 是一个开源的 Android Auto 替代方案：即使手机没有 Google 服务，也能把手机应用显示在比亚迪车机上，并用车机触屏操作。**它不是让车机直接运行这些手机应用，而是由手机运行、车机显示和控制。目前项目已实现投屏、触控、应用启动和通知等功能，但使用前需要满足设备与调试条件。

##### 它为什么出现，怎样工作

项目最初要解决的是一种设备不匹配：部分中国版安卓手机没有 Google Play 服务，无法运行 Android Auto；而有些比亚迪车机只提供 Android Auto 入口，没有其他可用的手机互联方案。DiLink-Auto 为这种组合提供了另一条路。项目称它也适用于有 Google 服务的安卓手机，并非仅限中国版系统。

连接后，**手机会在一个“虚拟显示器”上运行应用**，把画面编码为 H.264 视频传给车机；车机上的触摸、双指缩放等操作再传回手机，变成手机应用能接收的触控事件。因此，导航、音乐、消息及其他手机应用可以从车机屏幕启动和操作。投屏时手机实体屏幕可关闭以省电，也可独立使用。

##### 已实现的功能与使用条件

项目列出的现有功能包括：最高 60fps、8Mbps 的 H.264 视频流；多点触控；带搜索和排序的应用启动器；显示在车机上的通知及进度条；以及手机端检测车机应用版本过旧后，通过 WiFi ADB 更新车机应用。界面提供英语、葡萄牙语、法语、俄语等多种语言。

使用前需要：

- **手机：**Android 10 或更高版本，开启开发者选项中的 USB 调试，并授予首次启动时请求的所有文件访问权限。
- **车机：**比亚迪 DiLink 3.0 或更新版本，并有一个可用的 USB-A 接口。

项目提供发布版本下载，也可从源码构建手机 APK。车机 APK 和负责虚拟显示器的程序已打包在手机 APK 中：用户不必另行下载车机安装包或为安装车机应用连接互联网。这里的“无需在汽车上安装任何东西”，更准确地说是**无需用户手动安装**；连接 USB 后，仍需在手机上点击“安装到汽车”，由程序完成部署。

##### 当前边界：可用，但并非所有组合都已验证

项目报告已在 DiLink 3.0 车机，以及 Xiaomi 17 Pro Max、POCO F5、Galaxy S24 等手机上测试。它提出的兼容目标是“任何 Android 10+ 手机”，但**已测试设备范围不等于所有机型都得到验证**。

已知限制也会影响实际体验：三星手机需要关闭 Auto Blocker，否则 USB ADB 会被拦截；首次访问虚拟显示器时，Samsung Knox 可能弹出安全提示。Android 16 下热点需要手动开启。USB 断开后，虚拟显示器服务进程会重启并自动重连；突然断线导致手机屏幕持续关闭的问题，项目称已在 v0.14.0 修复。此外，偶发画面伪影通常要等下一个关键帧、约一秒后恢复；负载下视频传输延迟约为 100–200 毫秒。

**理解这个项目的关键是：它用“手机运行应用＋视频传到车机＋触控传回手机”的方式绕开对 Google 服务的依赖。**能否顺利使用，则取决于车机版本、USB 调试是否可用，以及具体手机的系统限制。
