> 后续会持续更新更多模板。

在无显示器的 Linux 服务器上渲染（实测环境：2 核、Node 22）会遇到三个坑， 都可以一个参数解决：

1. **并发上限** —— 低核机器上 `remotion still/render` 会报 "Maximum for --concurrency is 2"。解决：加 `--concurrency=1` 。
2. **旧版 Headless 被移除** —— 新版 Chrome/Chromium 已删除旧 headless 模式， 让 Remotion 指向系统 chromium 会启动失败。解决：改用 chrome-headless-shell 二进制，而不是完整版 Chrome。
3. **CDN 被墙** —— 如果 remotion.media 无法访问，headless-shell 的自动下载 会失败。解决：用 `--browser-executable=<本地 chrome-headless-shell 路径>` 指定本地二进制。

加上这三个参数后，内置模板即可正常渲染。

##### 4. Linux 无显示器环境的渲染问题

在无显示器 Linux 服务器上渲染时，实测环境为 **2 核、Node 22**，主要有三个问题：

1. **低核机器并发受限**
   - Remotion 可能提示：`Maximum for --concurrency is 2`
   - 解决：添加参数：

   ```bash
   --concurrency=1
   ```

2. **新版 Chromium 移除了旧 Headless 模式**
   - 如果 Remotion 直接使用系统完整版 Chrome/Chromium，可能启动失败。
   - 解决：改用 `chrome-headless-shell` 二进制。

3. **CDN 无法访问**
   - 如果 `remotion.media` 无法访问，Headless Shell 自动下载会失败。
   - 解决：手动指定本地浏览器路径：

   ```bash
   --browser-executable=<本地 chrome-headless-shell 路径>
   ```

同时配置以上参数后，内置模板即可在低配置服务器上正常渲染。
