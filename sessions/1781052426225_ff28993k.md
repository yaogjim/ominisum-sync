该文档应作为后续功能更新的持续记录基础，并在完成后沉淀为可复用的 Skill，方便之后按同一流程继续生成或更新产品说明。

验收标准

\- 成功启动虚拟机或本地运行环境，并打开当前项目 App。

最后总结并沉淀为一个可复用 Skill，包含运行、截图、梳理、撰写和更新文档的标准流程。

## 结构化（1）

##### 主旨概括

这篇内容分享了一些 `/goal` 的实际用例，帮助用户更充分地利用 Codex 的能力。核心思路是：把复杂、可重复的产品/工程任务，整理成有明确目标、流程和验收标准的长期任务，并最终沉淀为可复用的 Skill。

##### 1. 用例一：生成产品说明文档

作者提出的第一个 `/goal` 用例是：基于当前代码 commit，运行真实 App、模拟器或通过 CDP 检查页面，生成一份面向普通用户的产品说明文档。

关键点包括：

- 需要真实启动项目 App，而不是只读代码。
- 使用 CDP 或浏览器调试能力查看页面、获取截图。
- 文档要覆盖当前版本已有的主要页面、按钮、功能和交互。
- 说明语言要面向普通用户，避免技术细节。
- 要解释：
  - 每个主要页面是做什么的；
  - 每个按钮有什么作用；
  - 用户应该如何操作；
  - 点击后会发生什么；
  - 这个功能为什么有用。

例如，一个设置页面的说明不应写成“调用接口更新配置”，而应写成“点击保存后，你的设置会立即生效，下次打开应用时会继续保留”。

##### 2. 产品说明文档的验收标准

作者给出了较明确的验收标准，确保 `/goal` 执行结果不是泛泛而谈：

- 成功启动虚拟机或本地运行环境，并打开当前项目 App。
- 使用 CDP 或浏览器调试能力获取关键页面截图。
- 覆盖当前 commit 中已有的主要功能、页面和交互。
- 逐项说明按钮、入口、状态变化和点击后的结果。
- 文案要简洁清楚，面向普通用户，避免技术实现细节。
- 文档应支持后续持续追加功能更新，而不是一次性说明。

也就是说，这不是单纯写一份文档，而是建立一个可以长期维护的产品说明体系。

##### 3. 沉淀为可复用 Skill

作者强调，任务完成后应总结并沉淀为可复用的 Skill。

这个 Skill 应包含标准流程：

- 如何运行项目；
- 如何打开 App；
- 如何截图和检查页面；
- 如何梳理页面、按钮和交互；
- 如何撰写面向用户的说明；
- 后续功能更新时如何继续追加文档。

这样以后项目更新时，就可以按同一流程快速生成或更新产品说明文档。

##### 4. 用例二：Design System 抽象

热门回复中，作者还补充了另一个 `/goal` 用例：将项目中分散的 UI 组件、样式规范和交互模式抽象成统一的 Design System。

核心目标是：

- 梳理当前项目内已有 UI 组件和样式；
- 建立统一、可复用、可维护的组件库；
- 让业务页面优先使用标准组件；
- 逐步移除独立手写组件；
- 减少重复实现、视觉不一致和交互错误。

这个用例适合用于大型项目中 UI 混乱、组件重复、样式不统一的场景。

##### 5. 用例三：可访问性与多端适配

另一个用例是检查并优化产品在不同设备、屏幕尺寸和辅助使用场景下的体验。

重点关注的用户包括：

- 普通用户；
- 低视力用户；
- 键盘用户；
- 使用不同设备的用户。

目标是让这些用户都能稳定、清晰、顺畅地完成核心操作。

这类任务适合用 `/goal` 做系统性检查，例如检查移动端布局、键盘导航、文字对比度、按钮可点击区域等。

##### 6. 用例四：网络安全代码审查

还有用户补充了一个更偏工程安全的用例：对当前项目进行面向真实上线风险的网络安全代码审查。

审查范围包括：

- 当前 commit 的代码；
- 依赖；
- 配置；
- 接口；
- 运行环境。

重点检查可能影响以下方面的问题：

- 用户数据安全；
- 账号安全；
- 权限边界；
- 服务稳定性；
- 供应链安全。

具体审查方向包括认证鉴权、会话管理、输入校验、权限控制、敏感信息处理、数据库访问等。

##### 7. 其他讨论

原推中提到：“如果你会用 `/goal`，你真的不会觉得 Codex 够用！”意思是 `/goal` 可以承载很多长期、复杂、系统性的任务，很容易消耗大量 token。

评论中也有人开玩笑说，防止 token 用不完的冷门方法是“不用就不会用完”。还有人提到，之前 Codex 曾有一个 bug：用量达到上限后 `/goal` 仍会继续执行直到完成，但现在已经修复。

##### 总结

整体来看，这篇内容是在介绍如何把 `/goal` 用于真实项目中的复杂任务，例如产品说明文档、Design System 抽象、可访问性优化和安全审查。它的价值不只是完成一次任务，而是通过明确目标、验收标准和执行流程，把任务沉淀成可持续复用的 Skill。
