## 正文

Web agents – systems that can navigate and complete tasks in a browser on your behalf – are one of the most promising applications of multimodal AI. They represent a natural next step for vision-language models, moving from understanding images through captions and visual question answering to actually using that understanding to take action in the world. But the most capable web agents today are proprietary, trained on undisclosed data with undisclosed methods. The open-source community lacks not just the models but the training data, infrastructure, and evaluation tools needed to build competitive alternatives. That gap limits reproducibility, slows research progress, and makes it difficult to understand how these systems actually work. In many ways, web agents today are where LLMs were before [Olmo](https://allenai.org/olmo) —the community needs an open foundation to build on.

Today we're announcing [**MolmoWeb**](https://huggingface.co/collections/allenai/molmoweb), an open visual web agent built on our [Molmo 2](https://allenai.org/molmo) multimodal model family in two sizes (4B and 8B parameters) along with the weights, training data, code (training code coming soon), and evaluation tools used to build it. Designed for self-hosted deployment – whether locally or on cloud services – MolmoWeb can operate a browser by interpreting the same visual interface that humans see, connecting perception and action: given a task instruction and a live webpage, the model observes the page through screenshots, predicts the next step, and executes browser actions such as clicking, typing, or scrolling.

[https://youtube.com/watch?v=rzkBE8J7mXQ](https://youtube.com/watch?v=rzkBE8J7mXQ)

Unlike other open-weight web agents, MolmoWeb was trained without distilling from proprietary vision-based agents—our data comes from synthetic trajectories generated by text-only accessibility-tree agents and human demonstrations.

Alongside the model we’re releasing **MolmoWebMix**, a large and diverse dataset for training web agents, along with a complete training and evaluation pipeline, reproducible model checkpoints, and tools for collecting web-interaction data. Together these provide a full recipe for building web agents – from data collection to deployment – enabling researchers and developers to inspect and improve every part of the stack.

##### From looking to doing

Molmo models are trained for multimodal understanding, excelling at tasks such as captioning, visual reasoning, and grounding language in images. MolmoWeb extends these capabilities to browser control.

The system works in a simple loop—look at the screen, decide what to do, do it. At each step it receives a task instruction (e.g., "Find the cheapest nonstop flights from Seattle to Tokyo"), a screenshot of the current browser view, and the history of recent actions. The model then produces a short natural-language thought describing its reasoning, followed by the next browser action to execute.

Supported actions include navigating to URLs, clicking at screen coordinates, typing text into fields, scrolling pages, opening or switching browser tabs, and sending a message back to the user. These actions operate directly in the browser viewport, with click locations represented as normalized coordinates and converted to pixels when executed.

This design allows MolmoWeb to interact with websites the same way people do—by interpreting visual layout rather than relying on structured page representations like HTML or accessibility trees. Working from screenshots brings practical advantages. A single screenshot is far more compact than a serialized page representation, which can consume tens of thousands of tokens. Visual interfaces also remain stable even when underlying page structures change, and because the model reasons about the same interface the user sees, its behavior is easier to interpret and debug.

In practice, this means MolmoWeb can carry out a wide range of everyday web tasks – navigating multi-page websites, filling out forms, searching and filtering product listings, or retrieving information from a target webpage – all without needing a dedicated API for any particular website or service. The model decomposes instructions into sequences of actions, maintaining context about previous steps while responding to what appears on the page.

A typical interaction might involve navigating to a website, identifying a search field, entering a query, interpreting the results, opening the relevant page by clicking on links, and extracting or presenting the answer. Throughout, the agent's internal reasoning and action trace remain visible, allowing users to inspect the process and intervene if needed.

##### A dataset for training web agents

One major challenge in building web agents is the lack of public training data. Most prior systems rely on undisclosed training data. To address this, we created MolmoWebMix, a large open dataset that combines synthetically generated data with human-annotated examples—designed specifically for training multimodal web agents.

MolmoWebMix combines several complementary components.

**Human demonstrations.** Crowdworkers performed various browsing tasks using a custom Chrome extension that recorded actions and screenshots, capturing realistic behavior across tasks such as search, navigation, and form filling. The resulting dataset includes 36K human task trajectories – the largest publicly released dataset of human web task execution to date – spanning over 623K individual subtask demonstrations across more than 1.1K websites.

**Synthetic trajectories.** To scale beyond what human annotation alone can provide, we generated additional trajectories using automated agents that operate on webpage accessibility trees. These include single-agent runs filtered for task success, multi-agent pipelines that decompose tasks into subgoals and verify completion, and deterministic navigation paths constructed by systematically exploring link structures across hundreds of websites. Together, these methods produce a large and diverse set of browsing trajectories without requiring further manual effort.

**GUI perception data.** Finally, MolmoWebMix includes training data that teaches the model to interpret webpage screenshots. This covers element grounding tasks – identifying where a UI element appears on screen – and screenshot question-answering tasks that require reading and reasoning about page content. The screenshot QA portion alone contains over 2.2 million question-answer pairs drawn from nearly 400 websites.

For a detailed breakdown of each data source, including collection methodology and filtering criteria, see our technical report.

##### Benchmarks

We evaluate MolmoWeb on four widely used web-agent benchmarks that require interacting with live websites: WebVoyager, Online-Mind2Web, DeepShop, and WebTailBench. WebVoyager tests general web navigation across 15 popular websites such as arXiv and GitHub. Online-Mind2Web covers a more diverse range of multi-step tasks spanning 136 websites. DeepShop focuses on complex shopping-related queries on Amazon, such as comparing products and filtering listings. WebTailBench evaluates instruction-following across a curated set of tasks designed to stress-test agent reliability.

In each, a VLM judge evaluates whether the agent successfully completed the task.

Despite their compact size, both the 4B and 8B MolmoWeb models achieve state-of-the-art results among open-weight web agents. MolmoWeb (8B) scores 78.2% on WebVoyager, 42.3% on DeepShop, and 49.5% on WebTailBench, outperforming leading open-weight models like Fara-7B across all four benchmarks. On DeepShop, even the smaller 4B model outperforms Fara-7B at matching step budgets—and still wins when limited to just 30 steps against Fara's 100. MolmoWeb also outperforms agents built on much larger proprietary models like GPT-4o that rely on annotated screenshots and structured page data—a striking result given that those models enjoy substantially richer input representations and orders-of-magnitude higher parameters.

Beyond task completion, MolmoWeb also demonstrates strong visual grounding—the ability to precisely locate UI elements on screen. On the ScreenSpot and ScreenSpot v2 benchmarks, a dedicated 8B grounding model trained on our data outperforms both open-weight models like Fara-7B and much larger proprietary systems including Claude 3.7 and OpenAI CUA. Even MolmoWeb (4B), trained as a general web agent rather than a grounding specialist, scores competitively on these benchmarks while also handling full task completion.

We also find that running multiple independent agent rollouts and selecting the best result significantly improves performance. With this test-time scaling approach, the 8B model reaches 94.7% pass@4 on WebVoyager and 60.5% on Online-Mind2Web (compared to 78.2% and 35.3% with a single rollout), demonstrating that additional compute at inference time can substantially improve reliability.

##### Limitations and safety considerations

MolmoWeb has several known limitations. As a purely vision-based model, it can make mistakes when reading text from screenshots. It can also be thrown off track by incorrect actions—for example, scrolling before a page has finished loading and missing relevant content. Performance degrades as instructions become more ambiguous or involve many constraints, and certain actions like scrolling within a specific page element or drag-and-drop remain challenging. Additionally, MolmoWeb is not trained on tasks that require logins or financial transactions, due to safety and privacy concerns. These are all active areas for improvement.

On the safety side, MolmoWeb was designed with transparency as a core goal—every component is open for inspection and audit. Our [hosted demo](https://molmoweb.allen.ai) includes additional safeguards: it is restricted to a set of whitelisted websites, uses the [Google Cloud Natural Language API](https://docs.cloud.google.com/natural-language/docs/moderating-text) to flag and reject unsafe queries, checks input field types before typing, and blocks actions on password and credit card fields. These restrictions are specific to the demo environment rather than built into the model itself, and we encourage the research community to develop and experiment with additional safety mechanisms as the field matures.

##### What this unlocks

MolmoWeb is available through [Hugging Face](https://huggingface.co/collections/allenai/molmoweb) and [GitHub](https://github.com/allenai/molmoweb), along with all [training data](https://huggingface.co/collections/allenai/molmoweb-data), evaluation tools, and an inference library for running the model locally. Developers can start self-hosting MolmoWeb to automate everyday browser tasks—running routine tasks on a fixed schedule, executing templated queries with different parameters to gather information across websites or products, and chaining simpler queries into complex workflows where each step picks up from the last browser state.

Because the full training pipeline is open, developers can also fine-tune the model on their own data to work well for their specific use cases. Researchers, meanwhile, can inspect and build on every component to advance the science of multimodal web agents, from improving the models and expanding the training data to developing new training methods.

Deploying capable agents on the open web raises important unsolved questions. How should agents respect the terms and conditions of websites they interact with? How do we prevent agents from accessing illegal or inappropriate content? How do we ensure safe financial transactions and protect users' personal information? How do we prevent irreversible actions? Making the full system open allows more people to participate in answering these questions and developing the safety practices needed for trustworthy automation on the web.

Just as importantly, MolmoWeb represents a step in an exciting scientific direction—pushing multimodal models beyond passive understanding of images toward systems that can act on what they see.

#### MolmoWeb：开源网页智能体的关键一步

##### 一、这是什么

MolmoWeb 是 Ai2 推出的一个开源网页智能体，可以像人一样 “看网页、理解界面、执行操作”，完成点击、输入、滚动、切换标签页等浏览器任务。

它的核心意义不只是发布了一个模型，而是把**模型、数据、训练流程、评测工具**一起开源，补上了当前开源网页智能体生态最缺的一块基础设施。

##### 二、它解决了什么问题

当前最强的网页智能体大多是闭源的：模型、训练数据、方法都不透明。  
这带来三个直接问题：

- **难复现**：外界无法验证效果是怎么来的  
- **难研究**：学术和开发社区很难持续改进  
- **难普及**：开发者无法真正自建和定制

MolmoWeb 的价值就在于：它试图把网页智能体从 “黑箱能力” 变成 “开放底座”。

##### 三、它是怎么工作的

MolmoWeb 采用非常直观的工作方式：**看屏幕 → 判断下一步 → 执行动作**。

每一步它会接收：

- 用户任务指令
- 当前网页截图
- 最近操作历史

然后输出一段简短推理，再执行下一步动作，比如：

- 打开网址
- 点击页面坐标
- 输入文字
- 滚动页面
- 切换标签页
- 把结果返回给用户

它不依赖 HTML 或无障碍树等结构化表示，而是直接基于截图理解页面。这种方式更接近真实用户操作，也更容易调试和解释。

##### 四、它为什么值得关注

MolmoWeb 最大的亮点，不只是 “能用”，而是**开放且完整**：

- 发布了 4B 和 8B 两个模型
- 提供训练数据集`MolmoWebMix`
- 开源评测与推理工具
- 支持本地或云端自部署
- 不依赖从闭源视觉智能体蒸馏数据

这意味着开发者和研究者不仅能 “调用能力”，还能真正理解、复现、修改和优化整个系统。

##### 五、数据和效果如何

Ai2 为此构建了一个大规模开源数据集`MolmoWebMix`，主要包括三类数据：

###### 1. 人类操作数据
由人工执行真实浏览任务，记录截图和操作轨迹。  
规模达到**3.6 万条任务轨迹**，覆盖**1100+ 网站**。

###### 2. 合成轨迹数据
用自动化智能体在网页上生成大量训练轨迹，用来扩大数据规模、降低人工成本。

###### 3. 界面感知数据
训练模型识别网页元素位置、理解截图内容，提升 “看懂页面” 的能力。

在多个网页智能体基准测试上，MolmoWeb 的 4B 和 8B 模型都达到了开源阵营的领先水平，甚至在部分任务上超过了一些更大的闭源系统。

##### 六、它的实际意义

对开发者来说，MolmoWeb 让网页自动化从传统脚本驱动，走向了**视觉理解驱动**。  
这意味着很多没有 API、页面经常变化的网站，也有机会被智能体操作。

典型应用包括：

- 自动完成重复网页任务
- 批量查询不同网站信息
- 搜索、筛选商品或内容
- 填表、导航、多页面信息提取
- 将多个简单操作串成完整流程

本质上，它把 “网页” 变成了 AI 可以直接操作的通用软件界面。

##### 七、目前的局限和风险

MolmoWeb 仍然存在明显限制：

- 纯视觉方式下，读图和识字仍可能出错
- 页面加载时机判断不准，容易误操作
- 复杂、多约束指令下表现会下降
- 对局部滚动、拖拽等操作仍不稳定
- 未训练登录、支付等高风险任务

安全方面，Ai2 在演示环境中加入了白名单网站、敏感输入拦截等机制，但这些更多是部署层保护，不是模型本身已经彻底解决了安全问题。

##### 八、核心结论

MolmoWeb 的真正突破，不只是 “又一个网页智能体”，而是它第一次把**开源网页智能体所需的整套基础能力**—— 模型、数据、训练、评测、部署 —— 尽可能完整地公开出来。

这件事的意义在于：

- 对产业：降低网页自动化的开发门槛  
- 对研究：推动多模态智能体从 “看懂” 走向 “会做”  
- 对生态：让更多人参与定义网页智能体的能力边界与安全规范  

一句话概括：**MolmoWeb 不是单点产品，而是开源网页智能体生态的基础设施级补位。**

##### 深入浅出地解读

##### 1. 它解决了什么问题？
可以把网页智能体理解成“会自己上网办事的 AI 助手”。

过去很多大模型会“看图说话”，但还不能真正**在网页上动手操作**。MolmoWeb 往前走了一步：  
它不只是理解网页内容，而是能根据目标去执行动作，比如：

- 打开网页
- 找到输入框
- 输入关键词
- 点击搜索结果
- 滚动页面继续找信息
- 最后把结果告诉用户

换句话说，它想解决的是：**让 AI 从“会看”变成“会做”**。

---

##### 2. 为什么它强调“看截图”而不是“读网页代码”？
这点很关键。

很多网页智能体会读取 HTML、DOM、Accessibility Tree 等结构化信息。这样做有好处，但也有问题：

- 页面代码很长，消耗很多 token
- 网站底层结构一改，模型可能就不适应
- 用户看到的页面，和模型“理解”的页面，不一定是同一个东西

MolmoWeb 选择更像人的方式：**直接看网页截图**。

这有几个直观优势：

- **更像人类操作网页**
- **输入更紧凑**，不需要塞进海量网页源码
- **更好调试**，因为模型看到的就是你看到的
- **更通用**，不用为每个网站专门适配 API 或页面结构

简单说：  
它不是在“读网页内部代码”，而是在“看网页表面长什么样，并直接操作”。

---

##### 3. 它为什么值得关注？
真正让 MolmoWeb 有分量的，不只是模型本身，而是它把整套东西都开放了。

现在很多先进的网页智能体研究有个大问题：  
**模型闭源、数据不公开、训练方式不透明**。  
这样会导致：

- 别人很难复现
- 社区难以改进
- 大家只知道结果好，不知道为什么好

MolmoWeb 的价值在于，它不只是给你一个“成品”，而是给了你一套“配方”：

- 模型权重
- 训练数据
- 评测工具
- 推理库
- 数据采集工具
- 训练流程（部分即将开放）

这意味着，研究者和开发者可以真正接着往下做，而不是只能“围观”。

---

##### 4. 它的数据为什么特别重要？
训练网页智能体最难的一点之一，就是**缺少公开数据**。

MolmoWebMix 试图补上这个缺口，它大致分三类：

###### 人类演示数据
让真人去浏览网页、完成任务，把操作过程录下来。  
优点是：真实、自然、贴近用户行为。

###### 合成轨迹数据
用自动化 agent 去大量生成网页操作路径。  
优点是：可扩展、成本低、覆盖更多场景。

###### GUI 感知数据
训练模型理解截图，比如：
- 某个按钮在哪
- 页面里写了什么
- 用户界面元素之间是什么关系

你可以把这理解成：  
它既学“怎么做任务”，也学“怎么看懂界面”。

##### 5. 它的成绩说明了什么？
文章给出的重点结论是：

- 在多个网页任务 benchmark 上，MolmoWeb 在**开源模型里表现领先**
- 小模型 `4B` 也很能打
- 某些任务上甚至超过了一些更大的闭源系统

这说明两件事：

###### 第一，参数大不一定绝对赢
如果数据和训练方式设计得好，小一些的模型也能做得很强。

###### 第二，开源方案开始有真正竞争力
过去很多人默认“最强 Web Agent 一定得是大厂闭源模型”，  
MolmoWeb 说明：**开源社区已经不只是追赶，而是在部分方向上具备了挑战能力。**

---

##### 6. 它现在还不擅长什么？
文章也比较坦诚，提到不少限制：

- 读截图里的文字时仍会出错
- 页面没加载完就滚动，可能错过关键信息
- 指令过于复杂、约束太多时，表现会下降
- 精细操作（如局部滚动、拖拽）还比较难
- 没有训练登录、支付等高风险任务

这意味着，MolmoWeb 现阶段更适合：

- 信息检索
- 表单填写
- 商品搜索与筛选
- 多步网页导航

但不太适合直接处理高风险、强责任场景。

## 结构化（1）

### 2026-03-25 10:24:28

#### MolmoWeb 文章精炼总结

MolmoWeb 是 Ai2 推出的一个开源网页智能体系统，目标是让 AI 像人一样“看网页、理解页面、再执行操作”。这篇文章的核心在于：Ai2 不只开源了模型，还同时开源了训练数据、评测工具和完整流程，试图为开源网页智能体建立一个可复现、可改进的基础。

##### 1. 为什么要做 MolmoWeb：补齐开源网页智能体的基础设施

- 网页智能体（Web agents）是多模态 AI 很有前景的应用方向，能代替用户在浏览器中完成任务。
- 目前最强的网页智能体大多是闭源的，训练数据、方法和评测细节都不公开。
- 这带来几个问题：
  - 难以复现结果；
  - 研究进展被拖慢；
  - 社区很难真正理解这些系统如何工作。
- Ai2 认为，当前网页智能体的状态，有点像 Olmo 出现之前的大语言模型生态：开源社区缺少一个完整、公开、可搭建的底座。

##### 2. MolmoWeb 是什么：一个“看屏幕操作浏览器”的开源代理

- MolmoWeb 基于 Molmo 2 多模态模型家族，提供 **4B** 和 **8B** 两个参数规模版本。
- 它不仅开源了：
  - 模型权重，
  - 训练数据，
  - 代码（训练代码即将发布），
  - 评测工具。
- 设计目标是支持**本地或云端自托管部署**。
- 它的工作方式很像人使用浏览器：
  - 接收任务指令；
  - 读取当前网页截图；
  - 结合最近的操作历史；
  - 预测下一步动作并执行。
- 可执行的动作包括：
  - 打开 URL，
  - 点击页面坐标，
  - 输入文本，
  - 滚动页面，
  - 打开或切换标签页，
  - 给用户返回消息。

##### 3. 它和传统方法的不同：直接看截图，而不是依赖 HTML 或无障碍树

- MolmoWeb 不是依赖结构化网页表示（如 HTML、accessibility tree）来操作，而是直接根据**截图**理解页面。
- 这种方式有几个明显优点：
  - **更贴近人类使用网页的方式**；
  - 截图比序列化网页结构更紧凑，后者可能会消耗**数万 token**；
  - 即便网页底层结构变化，视觉界面通常更稳定；
  - 用户能看到模型看见的内容，因此更容易调试和解释其行为。
- 文章举的任务例子是：
  - “找从西雅图到东京最便宜的直飞航班”。
- 一个典型执行流程可能是：
  - 打开目标网站；
  - 找到搜索框；
  - 输入查询；
  - 阅读结果；
  - 点击相关链接；
  - 提取答案并返回。
- 整个过程中，模型的推理和动作轨迹是可见的，方便用户查看和干预。

##### 4. 训练数据是关键：MolmoWebMix 解决了开源数据缺失问题

- 文章指出，构建网页智能体的一大难点，是**缺少公开训练数据**。
- 为此，Ai2 发布了 **MolmoWebMix**，这是一个大规模开源数据集，结合了**合成轨迹**和**人工标注样本**，专门用于训练多模态网页智能体。

###### 4.1 人类演示数据

- 研究团队让众包人员使用定制 Chrome 扩展执行浏览任务，并记录操作与截图。
- 覆盖任务包括：
  - 搜索，
  - 页面导航，
  - 表单填写等。
- 数据规模很大：
  - **36K** 条人工任务轨迹；
  - 超过 **623K** 个子任务演示；
  - 覆盖 **1.1K+** 个网站。
- 文中强调：这是**目前公开发布的最大规模人类网页任务执行数据集**。

###### 4.2 合成轨迹数据

- 为了扩大数据规模，Ai2 使用基于无障碍树的自动代理生成更多浏览轨迹。
- 这些轨迹来源包括：
  - 单代理执行并按任务成功过滤；
  - 多代理流水线，把任务拆成子目标并验证完成情况；
  - 系统化探索数百个网站链接结构得到的确定性导航路径。
- 好处是：可以在**不增加人工成本**的情况下，大幅扩充训练样本。

###### 4.3 GUI 感知数据

- MolmoWebMix 还包含训练模型“看懂网页截图”的数据。
- 主要包括：
  - 元素定位（grounding）：识别某个 UI 元素在屏幕上的位置；
  - 截图问答：读取并理解页面内容。
- 其中截图问答部分就有：
  - **220 万+** 问答对；
  - 来源于接近 **400** 个网站。

##### 5. 评测结果：小模型也能超过很多开源和闭源方案

- Ai2 在 4 个常用网页智能体基准上评测了 MolmoWeb：
  - **WebVoyager**
  - **Online-Mind2Web**
  - **DeepShop**
  - **WebTailBench**
- 这些基准分别覆盖：
  - 通用网页导航；
  - 多步跨网站任务；
  - Amazon 购物场景复杂查询；
  - 强调可靠性的指令跟随任务。
- 评测方式是：由一个视觉语言模型（VLM judge）判断任务是否完成。

###### 5.1 主要成绩

- **MolmoWeb 8B** 的成绩为：
  - **WebVoyager：78.2%**
  - **DeepShop：42.3%**
  - **WebTailBench：49.5%**
- 它在 4 个基准上都超过了领先的开源模型 **Fara-7B**。
- 在 **DeepShop** 上，连更小的 **MolmoWeb 4B** 都超过了 Fara-7B：
  - 在相同步数预算下更强；
  - 即使限制 MolmoWeb 只用 **30 步**，而 Fara 用 **100 步**，MolmoWeb 仍然胜出。
- 文章还特别强调，MolmoWeb 甚至超过了一些基于更大闭源模型（如 **GPT-4o**）构建的代理系统；
  - 而这些系统通常还能使用标注截图和结构化页面数据，
  - 输入信息更丰富、参数量也大得多。

###### 5.2 界面定位能力也很强

- 在 **ScreenSpot** 和 **ScreenSpot v2** 基准上，
  - 一个专门训练的 **8B grounding 模型** 超过了 Fara-7B，
  - 也超过了更大的闭源系统，如 **Claude 3.7** 和 **OpenAI CUA**。
- 即使是通用网页代理版本的 **MolmoWeb 4B**，在这些定位任务上也表现有竞争力，同时还能完成完整网页任务。

###### 5.3 多次尝试能显著提高成功率

- 研究还发现：让代理**独立运行多次**，再从结果中选最好的一次，会明显提升性能。
- 使用这种 test-time scaling 方法后，**8B 模型**达到：
  - **WebVoyager：94.7% pass@4**（单次运行是 **78.2%**）
  - **Online-Mind2Web：60.5%**（单次运行是 **35.3%**）
- 这说明：只要推理时增加一些计算量，系统可靠性还能进一步提高。

##### 6. 局限与安全：能力强，但仍有明显边界

###### 6.1 已知局限

- 由于它是**纯视觉模型**，在读截图中的文字时仍可能出错。
- 如果操作时机不对，也容易跑偏，例如：
  - 页面还没加载完就滚动，
  - 从而错过重要内容。
- 当任务描述更模糊、约束更多时，性能会下降。
- 某些复杂动作仍然困难，比如：
  - 在某个特定页面元素内部滚动；
  - 拖拽操作。
- 出于安全和隐私考虑，MolmoWeb **没有训练登录或金融交易类任务**。

###### 6.2 安全设计

- Ai2 把“可审查、可透明”作为安全基础：系统各组件都开放检查。
- 在官方托管演示中，还加了一些额外限制：
  - 只允许访问白名单网站；
  - 使用 **Google Cloud Natural Language API** 检测并拒绝危险请求；
  - 输入前检查字段类型；
  - 禁止对密码框和信用卡字段执行操作。
- 文章也特别说明：
  - 这些限制主要是演示环境的保护措施，
  - **并不是模型本身内置的永久安全机制**。
- 作者希望社区继续探索更完善的安全方法。

##### 7. 这意味着什么：既能落地应用，也推动研究开放

- MolmoWeb 已通过 **Hugging Face** 和 **GitHub** 提供下载，同时开放训练数据、评测工具和本地推理库。
- 对开发者来说，它可以用于：
  - 定时执行固定网页任务；
  - 用不同参数批量查询网站或商品信息；
  - 将多个简单查询串联成复杂工作流。
- 由于训练流程完整公开，开发者还可以基于自己的数据做**微调**，适配具体业务场景。
- 对研究者来说，MolmoWeb 提供了一个可以真正拆解和改进的全开源系统，有利于推进多模态网页智能体研究。

##### 8. 文章最后的观点：开放不仅是技术问题，也是治理问题

- 作者认为，开放一个可操作网页的智能体系统，会带来一些尚未解决的重要问题，例如：
  - 智能体如何遵守网站的服务条款？
  - 如何避免访问违法或不当内容？
  - 如何安全处理金融交易和个人隐私？
  - 如何防止不可逆操作？
- 他们的立场是：
  - 把系统完整开放出来，能让更多研究者和开发者一起参与这些问题的解决，
  - 从而推动更可信的网页自动化实践。
- 结尾强调，网页是世界上最大的“软件平台”，如果智能体能可靠地在其中导航和执行任务，就可能显著扩大人们获取信息和数字服务的能力。
- 同时，MolmoWeb 也代表了一个更大的方向：让多模态模型从“看懂图像”走向“根据所见采取行动”。

##### 一句话总结

MolmoWeb 的真正价值，不只是“做出了一个开源网页代理”，而是首次把**模型、数据、训练流程、评测工具**一起公开，给开源社区提供了一套较完整的网页智能体基础设施；而从成绩看，它已经在多个任务上达到甚至超过许多现有开源和部分闭源方案。

## 产品-最佳实践（1）

### 2026-03-25 10:30:03

#### 基于 MolmoWeb 的具体实例与最佳实践

##### 具体实例：自动完成“查找最便宜的西雅图到东京直飞航班”

假设你要基于 **MolmoWeb** 构建一个自托管网页代理，帮助用户完成如下任务：

> “在旅游网站上查找从西雅图飞往东京的最便宜直飞航班，并返回航班价格、起飞时间和预订链接。”

这是一个非常适合 MolmoWeb 的场景，因为它符合文章中描述的网页代理工作方式：

- 接收自然语言任务指令
- 观察当前网页截图
- 结合最近动作历史进行推理
- 执行点击、输入、滚动、切换标签页等浏览器操作
- 在多步页面跳转中持续完成任务

---

##### 这个实例下的推荐工作流

###### 1. 任务拆解

让代理不要直接执行“大任务”，而是拆成明确子目标：

1. 打开目标旅游网站
2. 定位出发地、目的地输入框
3. 输入 “Seattle” 和 “Tokyo”
4. 选择“Nonstop / 直飞”筛选项
5. 提交搜索
6. 读取搜索结果页中的价格和时间信息
7. 找到最低价的直飞选项
8. 返回结构化结果给用户

这种拆解方式非常符合 MolmoWeb “look-decide-act” 的机制，也能降低模型因长链路决策而出错的概率。

---

##### 最佳实践

###### 1. 指令要具体、可验证、低歧义

MolmoWeb 在文章中提到：当任务指令变得模糊、约束过多时，性能会下降。  
因此最佳实践是把任务写成“可判断是否完成”的形式。

###### 好的指令示例

```markdown
请在 Expedia 上搜索从 Seattle 到 Tokyo 的机票，出发日期为 2025-10-10，返回最便宜的直飞航班，并输出：
1. 价格
2. 起飞时间
3. 航空公司
4. 对应结果链接
如果页面未加载完成，请等待后再继续。
```

###### 不够好的指令示例

```markdown
帮我看看最近去东京什么航班比较合适。
```

前者的优点：

- 网站明确
- 城市明确
- 日期明确
- “最便宜”和“直飞”标准明确
- 输出格式明确
- 加入等待页面加载的约束

---

###### 2. 优先让代理处理“信息检索型任务”，避免高风险动作

文章明确提到 MolmoWeb **未针对登录、金融交易等任务训练**，并且公开演示中还限制了密码框、信用卡字段等输入。  
因此在这个航班实例中，最佳实践是：

- 让代理负责搜索、筛选、比较和整理信息
- 不让代理自动付款
- 不让代理输入信用卡信息
- 不让代理执行不可逆确认操作

###### 推荐边界

```markdown
代理负责：
- 搜索航班
- 应用筛选条件
- 比较价格
- 整理结果

用户负责：
- 登录账号
- 填写乘客身份信息
- 支付与最终确认
```

这既符合 MolmoWeb 的能力边界，也能显著降低安全和责任风险。

---

###### 3. 在执行层加入“页面稳定性检查”

文章中指出一个典型问题：

> 模型可能会因为页面尚未加载完成就滚动，导致错过关键信息。

所以在这个实例中，最重要的工程实践之一是：

- 每一步动作后做页面状态确认
- 等待关键元素出现
- 页面截图连续两次变化很小时，再继续下一步

###### 例如

在点击“Search”之后，不应马上滚动，而应先检查：

- 是否出现了结果列表
- 是否出现了价格信息
- 是否出现了“Stops / 直飞”筛选器
- 页面顶部 loading 是否消失

###### 推荐策略

```markdown
动作后等待规则：
- 点击后等待 1~3 秒并重新截图
- 若关键区域仍在变化，继续等待
- 连续两次截图差异很小，再开始读取或滚动
```

这类“稳定性门控”对视觉网页代理尤其关键。

---

###### 4. 对关键步骤使用多次 rollout，提高可靠性

文章中一个非常重要的信息是：

> 多次独立 agent rollout 并选择最佳结果，可以显著提高成功率。

因此，对于“找最便宜直飞航班”这种容易受页面广告、排序、弹窗干扰的任务，最佳实践不是只跑一次，而是：

- 独立执行 3~4 次
- 比较每次返回结果是否一致
- 选择最可信的一条结果

###### 适合在本例中这样做

```markdown
策略：
- 运行 4 次独立搜索流程
- 若 4 次中有 3 次返回同一个最低价航班，则视为高置信结果
- 若结果冲突，则把前 3 个候选项都返回给用户，并标记“需人工确认”
```

这比依赖单次执行更稳，尤其在复杂网站中更实用。

---

###### 5. 输出要结构化，方便用户审查与接管

MolmoWeb 的优势之一是过程可见、可调试。  
所以在这个实例中，最佳实践不是只返回一句“我找到了最便宜航班”，而是返回结构化结果和执行痕迹。

###### 推荐输出格式

```markdown
### 搜索结果
- 网站：Expedia
- 路线：Seattle -> Tokyo
- 日期：2025-10-10
- 条件：直飞
- 最低价格：$742
- 航空公司：ANA
- 起飞时间：10:35 AM
- 结果链接：[链接]

### 执行动作摘要
1. 打开 Expedia
2. 输入出发地和目的地
3. 设置直飞筛选
4. 提交搜索
5. 读取并比较结果列表

### 置信说明
- 本结果来自 4 次独立执行中的 3 次一致结果
- 建议用户在付款前人工复核最终价格与退改规则
```

这样做的好处：

- 用户更容易验证
- 工程上更方便排错
- 更适合接入业务系统或日志系统

---

###### 6. 为视觉识别误差准备回退机制

文章提到 MolmoWeb 作为纯视觉模型，**可能在截图文本读取上出错**。  
在航班搜索场景里，这可能表现为：

- 错读价格
- 误认“1 stop”为“nonstop”
- 没看清日期或航司信息

因此最佳实践是加入交叉验证：

- 用 OCR 或规则对价格字段复核
- 对“Nonstop”筛选结果再做一次文本确认
- 读取结果卡片时，抽取多个候选，再排序而不是只信第一个

###### 推荐方案

```markdown
回退与校验机制：
- 价格字段至少读取两次
- “直飞”条件通过筛选标签 + 结果文本双重确认
- 若页面文本过密，则截图分区域读取，而不是一次性全页解析
```

这能有效缓解视觉模型在小字、拥挤 UI 上的脆弱性。

---

###### 7. 限制网站范围，建立白名单

文章中的官方 demo 使用了 **whitelisted websites**。  
这在生产场景里同样是最佳实践。

对于航班查询任务，不要让代理“自由上网搜索”，而应该只允许访问：

- Expedia
- Kayak
- Google Flights
- Skyscanner

###### 原因

- 页面结构更可预测
- 风险更低
- 更容易调试
- 更方便做站点级适配和评估

###### 推荐策略

```markdown
仅允许代理访问预定义站点；
若用户请求跳转到白名单外网站，则要求人工确认。
```

这对于任何自托管网页代理都很重要。

---

###### 8. 保留完整动作日志，方便审计和复现

MolmoWeb 的开放价值之一就在于：训练数据、评估工具、执行过程都尽量透明。  
因此在这个实例中，最佳实践是记录：

- 每一步截图
- 每一步模型思考摘要
- 每一步动作
- 每一步页面状态变化
- 最终结果提取依据

###### 推荐日志字段

```markdown
- task_id
- instruction
- timestamp
- screenshot_id
- model_thought
- predicted_action
- executed_action
- action_result
- extracted_candidates
- final_answer
```

这样你可以：

- 快速定位失败步骤
- 比较不同模型版本效果
- 构建自己的评估集
- 为后续微调收集高质量数据

---

##### 针对这个实例的完整最佳实践模板

```markdown
## 任务
在 Expedia 上搜索从 Seattle 到 Tokyo、2025-10-10 出发的最便宜直飞航班，并返回价格、起飞时间、航空公司和结果链接。

## 执行原则
1. 仅允许访问白名单网站
2. 不执行登录、支付、下单等高风险动作
3. 每次关键点击后等待页面稳定
4. 对搜索流程执行 4 次独立 rollout
5. 对“直飞”和“价格”进行双重校验
6. 输出结构化结果和动作日志
7. 若结果冲突，返回多个候选并提示人工确认

## 成功判定
- 已找到至少一个直飞航班
- 已确认其价格、起飞时间、航空公司
- 已给出可点击结果链接
- 至少 2 次以上执行得到一致结果
```

##### 结论

以“查找最便宜的西雅图到东京直飞航班”为例，MolmoWeb 最适合的不是“完全自主替用户完成一切”，而是：

- 在受控网站范围内
- 处理可验证的多步信息检索任务
- 通过页面稳定检查、多次 rollout、结构化输出和人工接管机制
- 提供透明、可审计、可复现的网页自动化能力

这也是基于文章内容可以提炼出的核心最佳实践：

> **让视觉网页代理先成为一个可靠、可审查、可回退的信息执行助手，而不是一个无边界的全自动操作员。**
