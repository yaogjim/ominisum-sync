## 正文

**Jiayuan (JY) Zhang**

开源 Multica：专为 AI-native 团队设计的 Agent + 人的协作平台

[https://github.com/multica-ai/multica/…](https://github.com/multica-ai/multica/)

为什么做 Multica？

Multica 最初是为了解决我们团队自己的问题：

1\. 团队间的知识无法共享。 每个人都在用 coding agent，但产出的上下文全部散落在各自的 agent session 里。A 做完了一件事，B 不知道；agent 跑完了一轮，结果只有发起人看得到。团队知识变成了一座座孤岛。

2\. 多人 + 多 Agent 的协作缺乏中枢。 当团队同时有多个 agent 在跑任务，谁在做什么、做到哪了、卡住了没有——没有一个地方能看到全貌。人和 agent 之间、agent 和 agent 之间，缺少一个共同的协作界面。

Multica 是什么？

一句话：像 Linear 一样管理任务，但 AI agent 是一等公民。

你可以像分配任务给同事一样，把 issue 分配给 agent。agent 会自动领取任务、在你的本地机器上执行代码、提交结果、更新状态、发表评论——一切都发生在同一个看板里，所有人实时可见。

核心思路很简单：每个人把自己的 coding agent（Claude Code / Codex）注册到团队 workspace，之后就可以像分配任务给同事一样分配给 agent。agent 自动执行、更新状态、发表评论，所有人实时可见。

适合谁？

\- 1-10 人的 AI-native 小团队  
\- 正在大量使用 coding agent 但缺少协作中枢的团队  
\- 希望让 agent 融入日常工作流而不是当作独立工具的团队

官网: [http://multica.ai](http://multica.ai)

欢迎 star、试用、提 issue，也欢迎 PR。

## 通俗精炼（1）

### 2026-05-04 13:34:13

#### Multica：面向 AI-native 团队的「人 + Agent」协作平台

##### 一句话总结

Multica 是一个开源协作平台，目标是让 AI Agent 像团队成员一样参与任务管理与执行，类似「Linear + Coding Agent」，适合高度依赖 AI 编程工具的小团队。

##### 为什么做 Multica？

###### 1. 团队知识被困在个人 Agent 会话里

现在很多团队成员都在使用 Claude Code、Codex 等 coding agent，但 Agent 的执行过程、上下文和结果往往只存在个人 session 中。

结果是：

- A 做了什么，B 不知道
- Agent 跑完了什么，只有发起人看到
- 团队知识分散在不同人的工具里，无法沉淀和复用

###### 2. 多人多 Agent 缺少统一协作中枢

当团队中多个成员、多个 Agent 同时处理任务时，很难知道：

- 谁在做什么
- Agent 执行到哪一步
- 是否遇到阻塞
- 当前任务整体进展如何

人和 Agent、Agent 和 Agent 之间缺少一个统一的工作界面。

##### Multica 是什么？

###### 像 Linear 一样管理任务，但 Agent 是一等公民

Multica 允许团队像给同事分配任务一样，把 issue 分配给 AI Agent。

Agent 可以：

- 自动领取任务
- 在本地机器或云端环境执行代码
- 提交执行结果
- 更新任务状态
- 在看板中发表评论

所有过程都在同一个 workspace 中实时可见，团队成员可以统一查看进展。

##### 核心工作方式

###### 将个人 Coding Agent 注册到团队 Workspace

团队成员可以把自己的 Claude Code、Codex 等 Agent 注册进 Multica workspace。

之后，团队就可以：

- 把任务分配给 Agent
- 统一追踪 Agent 执行状态
- 查看 Agent 输出和评论
- 让 Agent 融入日常协作流程

###### 支持本地或云端 Agent Runtime

可以在本机或专用机器上安装 Multica CLI，将本地算力注册到 workspace 中。

基本流程包括：

```bash
brew tap multica-ai/tap
brew install multica-cli

multica login
multica daemon start
```

##### 适合哪些团队？

Multica 主要适合：

- 1-10 人的 AI-native 小团队
- 已经大量使用 coding agent，但缺少协作中枢的团队
- 希望把 Agent 纳入正式工作流，而不是单独作为个人工具使用的团队

##### 部署方式

Multica 提供两种使用方式：

1. 使用官方云服务：multica.ai
2. 自行通过 Docker 部署，适合有一定技术能力的团队

##### 产品价值

Multica 的核心价值在于：把 AI Agent 从「个人工具」升级为「团队成员」。

它解决的不是单个 Agent 的能力问题，而是团队在规模化使用 Agent 后出现的协作、可见性和知识沉淀问题。对于 AI-native 团队来说，这是一个很实际的基础设施方向。

##### 一、内容总结

Multica 是一个开源的 **“人 + AI Agent” 协作平台**，主要面向 AI-native 小团队。

它想解决的问题是：

1. **团队知识分散**
   - 每个人都在用 Claude Code、Codex 等 coding agent。
   - 但 agent 的执行过程、上下文、结果都散落在个人 session 里。

   - 多个 agent 同时执行任务时，很难知道：
     - 谁在做什么？
     - 任务进度如何？
     - 是否卡住？
     - 结果在哪里？
   - 人和 agent 之间缺少一个共同的工作界面。

Multica 的定位是：

> 像 Linear 一样管理任务，但把 AI Agent 当作“一等公民”。

团队可以把 Claude Code / Codex 等 coding agent 注册到 workspace 中，然后像给同事分配任务一样，把 issue 分配给 agent。Agent 会自动执行代码任务、更新状态、发表评论、提交结果，所有过程都在看板中实时可见。

适合对象：

- 1～10 人 AI-native 小团队
- 大量使用 coding agent 的开发团队
- 希望把 agent 融入日常协作流程的团队

---

##### 二、深入浅出解读

###### 1. Multica 想做的是“Agent 时代的项目管理工具”

传统项目管理工具，比如 Linear、Jira、Trello，主要管理的是“人”的任务。

而 Multica 的核心变化是：

> 不只管理人，也管理 AI Agent。

以前你可能是这样工作：

```text
我打开 Claude Code → 让它改代码 → 看结果 → 自己同步给团队
```

但问题是，其他人很难知道：

- 你让 agent 做了什么？
- agent 改了哪些东西？
- 中间有没有失败？
- 最终结论是什么？

Multica 想把这个过程变成：

```text
创建 issue → 分配给 agent → agent 自动执行 → 状态同步到看板 → 团队成员都能看到
```

这就像把 AI Agent 从“个人工具”变成了“团队成员”。

---

###### 2. 它解决的是团队协作中的“黑盒问题”

现在很多 coding agent 的使用方式，本质上还是个人化的。

比如：

- A 用 Claude Code 修了一个 bug；
- B 用 Codex 重构了一个模块；
- C 又让另一个 agent 写测试。

每个人都很高效，但团队层面可能很混乱：

```text
A 不知道 B 做了什么
B 不知道 C 的 agent 是否完成
C 不知道 A 的上下文是什么
```

Multica 的价值在于，把这些 agent 的行为放到统一的 workspace 中。

也就是说：

- Agent 的任务可见；
- Agent 的状态可见；
- Agent 的评论可见；
- Agent 的结果可追踪。

这对小团队尤其重要，因为小团队往往没有复杂的流程，但又需要很高的协作效率。

---

###### 3. 它不是单纯的 Agent，而是 Agent 协作层

Multica 本身并不是替代 Claude Code 或 Codex。

它更像是一个“调度和协作平台”。

可以理解为：

```text
Claude Code / Codex：负责干活
Multica：负责分配任务、跟踪进度、展示结果
```

类比一下：

| 工具 | 作用 |
|---|---|
| Claude Code / Codex | 写代码、改代码、执行任务 |
| Linear / Jira | 管理人的任务 |
| Multica | 管理人和 Agent 的任务 |

所以它的核心价值不是“让 AI 更聪明”，而是“让团队更好地使用 AI”。

---

##### 三、我的意见

我认为 Multica 的方向是有价值的，尤其适合正在重度使用 coding agent 的小团队。

###### 优点

1. **抓住了真实痛点**
   - AI Agent 越来越多，但团队协作方式还停留在人工同步阶段。
   - Multica 解决的正是“Agent 产出的上下文如何被团队共享”的问题。

2. **定位清晰**
   - 不是泛泛地做 AI 工具，而是做“Agent + 人”的协作平台。
   - “像 Linear 一样，但 Agent 是一等公民”这个表达很直观。

3. **适合 AI-native 团队**
   - 对 1～10 人小团队来说，如果每个人都在用 agent，确实需要一个统一中枢。

###### 可能的挑战

1. **安全和权限问题**
   - Agent 会在本地机器上执行代码，这涉及代码仓库、环境变量、密钥等敏感信息。
   - 团队是否放心接入，是一个关键问题。

2. **Agent 执行质量不可控**
   - Agent 可能跑偏、失败、误改代码。
   - Multica 需要有清晰的状态、日志、回滚和审查机制。

3. **是否能融入现有工作流**
   - 很多团队已经在用 GitHub Issues、Linear、Jira。
   - 如果 Multica 不能很好集成这些工具，迁移成本可能会比较高。

---

##### 四、简短结论

Multica 可以理解为：

> 一个面向 AI-native 团队的“Agent 工作台”和“协作看板”。

它的价值不在于创造新的 AI 模型，而在于把分散的 coding agent 使用过程，变成团队可见、可管理、可追踪的协作流程。

如果一个团队已经频繁使用 Claude Code、Codex 等 coding agent，那么 Multica 值得关注和试用。  
但如果团队目前还没有形成稳定的 agent 使用习惯，它的价值可能暂时不会特别明显。
