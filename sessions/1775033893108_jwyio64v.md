#### Backstory

2026 年 3 月 31 日凌晨 4 点，我醒来时，手机通知疯狂地弹出。Claude Code 的源代码被泄露了，整个开发者社区陷入一片混乱。我在韩国的女朋友真的很担心，就因为我电脑里有这些代码，我可能会面临 Anthropic 的法律诉讼——于是我做了任何一个工程师在压力下都会做的事：坐下来，从零开始将核心功能移植到 Python 中，并在太阳升起前就提交了代码。

整个项目是通过 [oh-my-codex (OmX)](https://github.com/Yeachan-Heo/oh-my-codex) 端到端编排的，由 [@bellman\_ych](https://x.com/bellman_ych) 完成 — 这是一个构建在 OpenAI 的 Codex ([@OpenAIDevs](https://x.com/OpenAIDevs)) 之上的工作流层。我使用了 `$team` 模式进行并行代码审查，并使用 `$ralph` 模式进行架构级验证的持久执行循环。整个移植会话 — 从读取原始工具框架结构到生成包含测试的可运行 Python 代码树 — 均通过 OmX 编排驱动完成。

结果是一个从零开始重写的 Python 版本，该版本捕捉了 Claude Code 的代理工具框架的架构模式，且未复制任何专有源代码。我现在正与 [@bellman\_ych](https://x.com/bellman_ych) （OmX 的创建者本人）积极合作，以进一步推进这项工作。基本的 Python 基础架构已经搭建完成且可用，但我们才刚刚开始。 **请持续关注——更强大的版本即将推出。**

#### Porting Status

主源代码树现在以 Python 为优先。

- `src/` 包含活跃的 Python 移植工作区
- `tests/` 验证当前的 Python 工作区
- 已暴露的快照不再属于被跟踪的代码仓库状态

目前的 Python 工作区尚未能完全一对一替换原始系统，但主要实现部分现在是 Python。

我最初研究了这个公开的代码库，以了解其工具链、工具连接和代理工作流程。在处理法律和伦理问题上花费了更多时间之后——并且在阅读了下面链接的文章之后——我不希望这个公开的快照本身继续作为主要的跟踪源代码树。

这个代码仓库现在转而专注于 Python 移植工作。

新的 Python `src/` 代码树目前提供：

- **`port_manifest.py`** — 总结当前 Python 工作区结构
- **`models.py`** — 数据类，用于子系统、模块和待办事项状态
- **`commands.py`** — Python 端命令端口元数据
- **`tools.py`** — Python 端工具移植元数据
- **`query_engine.py`** — 呈现来自当前工作区的 Python 移植总结
- **`main.py`** — 一个用于清单和摘要输出的 CLI 入口点

#### Quickstart

渲染 Python 移植总结：

```
python3 -m src.main summary
```

打印当前 Python 工作区清单：

```
python3 -m src.main manifest
```

列出当前的 Python 模块：

```
python3 -m src.main subsystems --limit 16
```

Run verification:

```
python3 -m unittest discover -s tests -v
```

对本地被忽略的归档文件（当存在时）运行奇偶校验审计：

```
python3 -m src.main parity-audit
```

检查镜像的命令/工具清单

```
python3 -m src.main commands --limit 10
python3 -m src.main tools --limit 10
```

现在的移植版本比之前更加紧密地镜像复制归档的根入口文件结构、顶层子系统名称以及命令/工具清单。然而，它 **尚未** 成为原始 TypeScript 系统的完整运行时等效替换；Python 代码树中仍包含比归档源代码更少的可执行运行时部分。

该代码仓库的重组和文档工作由 AI 辅助完成，并借助 Yeachan Heo 开发的 [oh-my-codex（OmX）](https://github.com/Yeachan-Heo/oh-my-codex) 进行协调，构建在 Codex 之上。

- **`**` $team** 模式：\*\* 用于协调的并行评审和架构反馈
- **`$ralph` 模式：** 用于持久执行、验证和完成规范
- **Codex 驱动的工作流** ：用于将主 `src/` 目录树转换为 Python 优先的移植工作区

#### 文章主旨

这篇文章主要介绍了`instructkr/claw-code`项目的来历、定位和当前进展：它并不是简单保存泄露代码的仓库，而是试图在法律与伦理边界内，重建一个可用的代理工具框架。文章同时强调，这个项目因极高关注度在发布后仅**2 小时突破 50K stars**，并正从 Python 版本继续推进到 Rust 重写。

##### 1. 项目定位与核心卖点

- `claw-code`被描述为 “**史上最快突破 50K 星标的仓库**”，在发布后仅**2 小时**达成这一里程碑。
- 项目目标不是 “存档泄露的 Claude Code”，而是 “**更好地利用工具，真正把事情做成**”。
- 当前方向是：先完成**Python 移植版**，再继续推进**Rust 重写**。
- 仓库信息显示：
  - 总提交数为**129 commits**
  - 语言占比为**Rust 89.3%**、**Python 10.7%**

##### 2. 项目起源：从泄露事件到重写

- 作者提到，**2026 年 3 月 31 日凌晨 4 点**，得知 Claude Code 源代码被泄露，社区迅速陷入混乱。
- 出于法律风险和现实压力，作者没有直接使用泄露代码，而是选择 “**从零开始把核心功能移植到 Python**”。
- 他强调，结果是一个**重新实现（reimplementation）**版本：
  - 借鉴了 Claude Code 的**架构模式**
  - 但**没有复制专有源代码**
- 文章传递的核心态度是：这不是 “搬运泄露代码”，而是一次**独立重建**。

##### 3. 开发方式：借助 oh-my-codex（OmX）端到端编排

- 整个项目由**oh-my-codex（OmX）**进行端到端编排，OmX 是建立在**OpenAI Codex**之上的工作流层。
- 作者具体提到两种模式：
  - **`$team`模式**：用于并行代码审查
  - **`$ralph`模式**：用于架构级验证和持续执行循环
- 也就是说，这个项目本身就是一个 “**AI 编排开发工作流**” 的案例。
- 文章强调，从读取原始工具框架结构，到生成带测试的 Python 代码树，整个过程都由 OmX 协调完成。

##### 4. 作者背景与外部报道

- 作者表示，自己长期关注 “**工具编排工程**”，研究代理系统如何连接工具、组织任务、管理运行时上下文。
- 文中引用了《华尔街日报》在**2026 年 3 月 21 日**的报道，说明作者并非偶然参与这一方向，而是长期深度使用者。
- 其中最关键的数据和案例包括：
  - 作者去年独自使用了**250 亿 Claude Code tokens**
  - 他认为：
    - **Codex 更擅长推理**
    - **Claude Code 更擅长生成简洁、易分享的代码**
- 报道还举了两个典型用户例子，说明这类工具的受众已超出程序员群体：
  - 一位**比利时心脏病医生**开发了帮助患者管理医疗护理的应用
  - 一位**加州律师**开发了自动化建筑许可审批的工具
- 作者总结这些用户画像时提到：现场不只有工程师，还有**律师、医生、牙医**等没有软件工程背景的人。

##### 5. 当前移植状态：仓库已转向 Python 优先

- 文章明确说明：仓库当前的**主代码树以 Python 为优先**。
- 目前结构包括：
  - `src/`：活跃的 Python 移植工作区
  - `tests/`：Python 验证测试
  - `assets/omx/`：OmX 工作流截图
- 作者特别说明：
  - **泄露快照已不再是被跟踪的主代码仓库状态**
  - 仓库已经转向专注于**Python 移植工作**
- 这表明项目在定位上做了切换：从 “研究公开快照” 转到 “建设独立实现”。

##### 6. 目前 Python 版本能做什么

- 新的 Python `src/`代码树已提供一套基础功能：
  - `port_manifest.py`：总结当前 Python 工作区结构
  - `models.py`：数据类，描述子系统、模块和待办状态
  - `commands.py`：命令端口元数据
  - `tools.py`：工具移植元数据
  - `query_engine.py`：生成移植总结
  - `main.py`：CLI 入口
- 文章给出了具体使用示例：
  - 查看移植总结：`python3 -m src.main summary`
  - 打印工作区清单：`python3 -m src.main manifest`
  - 查看模块：`python3 -m src.main subsystems --limit 16`
  - 运行测试：`python3 -m unittest discover -s tests -v`
  - 运行奇偶校验审计：`python3 -m src.main parity-audit`
  - 查看命令 / 工具清单：
    - `python3 -m src.main commands --limit 10`
    - `python3 -m src.main tools --limit 10`

##### 7. 项目现阶段的能力边界

- 作者很明确地提醒：当前 Python 版本**还不能完全一对一替代原始 TypeScript 系统**。
- 虽然它已经更贴近原始归档中的：
  - 根入口文件结构
  - 顶层子系统名称
  - 命令 / 工具清单
- 但它仍然**缺少完整运行时等效能力**，可执行部分比原始归档更少。
- 简单说，现在更像是：
  - **结构和框架已经搭好**
  - 但还不是完整可替换的成品
