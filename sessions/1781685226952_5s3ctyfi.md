## 追问（2）

### 提问 · 2026-06-17 08:33:04

如何在 codex 中 高质量使用 impeccable

### 回答 · 2026-06-17 08:33:04

在 Codex 里高质量使用 Impeccable，核心不是 “让 AI 随便美化一下”，而是把它当成一套**可执行的设计语言 + 前端质量闸门**来用。推荐按下面流程。

---

##### 1. 先安装并检查版本

在项目根目录运行：

```bash
npx impeccable install
```

如果已经装过：

```bash
npx impeccable update
```

检查是否落后：

```bash
npx impeccable skills check
```

如果你是在 Codex CLI 里工作，安装后它会为当前环境准备对应的 Impeccable skill /command 配置。

---

##### 2. 先让 Impeccable 读懂你的产品，而不是直接改 UI

高质量结果的关键是：先给它上下文。

在项目根目录创建或完善：

```txt
PRODUCT.md
DESIGN.md
```

###### `PRODUCT.md`写产品语境

例如：

```md
# Product

## Users
值班中的 SRE，需要快速阅读告警、定位问题，经常在暗光环境里使用。

## Context
产品型工具。设计服务于任务完成，不追求炫技。

## Brand voice
冷静、临床感、准确、零夸张。

## Anti-reference
不要紫色渐变。
不要玻璃拟态。
不要 “提升你的生产力” 这类空泛文案。
不要过度圆角和无意义卡片堆叠。
```

这样每次你在 Codex 里调用 Impeccable 时，它会先理解产品语境，而不是套一套 “AI 默认审美”。

---

##### 3. 让 Impeccable 记录你的视觉系统

如果项目已有 token、组件、Tailwind 配置，先让它整理设计系统：

```txt
/impeccable document
```

它会生成或更新`DESIGN.md`，把你的颜色、字号、间距、组件规则等写成可迁移的设计说明。

之后你再让 Codex 改页面时，可以明确要求：

```txt
请先读取 PRODUCT.md 和 DESIGN.md。
不要发明新的设计系统。
基于现有 token、组件和约定优化这个页面。
```

这是避免 AI 把项目改成 “另一个模板站” 的关键。

---

##### 4. 在 Codex 中推荐的工作流

###### 第一轮：让 Codex 诊断，而不是直接改

可以这样问：

```txt
读取 PRODUCT.md、DESIGN.md 和当前首页代码。
请用 Impeccable 的设计视角诊断这个页面：
1. 信息层级是否清楚
2. 字阶和排版是否有对比
3. 色彩是否克制
4. 留白和节奏是否合理
5. 是否有 AI slop 或模板感
先不要改代码，只给修改计划。
```

先看计划，避免它乱动。

---

###### 第二轮：指定设计维度改，不要笼统说 “变好看”

不要说：

```txt
帮我美化一下
```

应该说：

```txt
使用 Impeccable 的设计原则优化首页 hero：
- 强化标题和副标题的层级
- 减少无意义装饰
- 使用现有 DESIGN.md 里的颜色和字号 token
- 保持产品语气冷静、专业
- 不要紫色渐变、玻璃拟态、过度阴影
- 改动要落在现有组件结构里
```

如果你知道要改的维度，可以更具体：

```txt
/typeset 优化这个页面的排版层级和字阶
/colorize 重新整理颜色使用，保持单一主色相
/animate 让交互动效更自然，不要弹跳和夸张过渡
/impeccable craft 把当前视觉方向实现成生产级代码
```

---

##### 5. Codex 特别适合的高级用法：先发散，再 craft

网页里提到的高质量路径是：

> Codex 先用图像生成起草视觉方向，再由`/impeccable craft`变成上线代码。

你可以这样用：

###### Step 1：让 Codex 生成视觉方向

```txt
基于 PRODUCT.md 和 DESIGN.md，为这个落地页生成 3 个视觉方向。
每个方向说明：
- 排版气质
- 色彩策略
- 留白节奏
- 组件风格
- 适合的 hero 构图
不要写代码，先给方向。
```

选一个方向后：

```txt
采用方向 2，但降低装饰性，增强产品可信度。
请生成一个高保真页面方案描述，包含 hero、features、proof、CTA 的布局。
```

###### Step 2：让 Impeccable craft 落到代码

```txt
/impeccable craft

根据上面的高保真方案，实现到当前 Next.js/Tailwind 代码中。
要求：
- 遵守 DESIGN.md
- 复用已有 Button、Card、Badge 组件
- 不引入新的 UI 库
- 不破坏响应式
- 移动端优先
- 文案直接，不要营销废话
```

---

##### 6. 改完后立刻跑检测，拦住 AI slop

Impeccable 有 deterministic detector，不依赖 LLM，可放进 CI。

本地先跑：

```bash
npx impeccable detect src/
```

如果你想要 JSON：

```bash
npx impeccable detect src/--json
```

它会检测类似：

- `gradient-text`
- `side-stripe-border`
- `ai-color-palette`
- 模板感强的卡片堆叠
- 过度 AI 风格的视觉反模式

如果检测失败，它会返回非零退出码，适合放进 PR check。

你也可以让 Codex 修：

```txt
运行 npx impeccable detect src/ 后，根据报告逐项修复。
不要为了通过检测而删除功能。
优先用现有设计系统替换反模式。
```

---

##### 7. 高质量 prompt 模板

你可以直接复制这段给 Codex：

```txt
你现在是我的前端设计实现 Agent。

请先读取：
- PRODUCT.md
- DESIGN.md
- tailwind.config.ts
- src/styles/tokens.css
- 相关组件代码

目标：优化当前页面的 UI 质量，而不是重写成模板站。

设计要求：
1. 尊重现有 token、组件和品牌规则
2. 强化信息层级、排版对比和留白节奏
3. 色彩克制，避免默认紫色渐变、玻璃拟态、彩虹渐变
4. 移动端优先，断点根据内容而不是模板设定
5. 动效自然，有物理感，不弹跳、不抖动
6. 文案直接说明产品价值，不要空泛营销话术
7. 保持代码可维护，尽量小步修改
8. 改完后运行 npx impeccable detect src/ 并修复问题

先给我修改计划，等我确认后再改代码。
```

---

##### 8. 常用命令思路

虽然具体命令可以看完整参考，但使用时可以按设计维度来拆：

| 目标 | 推荐说法 |
|---|---|
| 排版变高级 | `/typeset`：调整字阶、行高、间距、标题层级 |
| 色彩更克制 | `/colorize`：减少颜色数量，建立主色、辅助色、状态色 |
| 页面更有结构 | 要求它基于留白和节奏重组，而不是继续套卡片 |
| 动效更自然 | `/animate`：缓入缓出、稳定落点、避免弹跳 |
| 生产级实现 | `/impeccable craft` |
| 输出设计文档 | `/impeccable document` |
| 检查 AI slop | `npx impeccable detect src/` |

---

##### 9. 最佳实践：每次只改一个设计维度

不要一次说：

```txt
重做整个应用，让它高级一点
```

更好的方式：

```txt
第一步，只优化 dashboard 的信息层级和排版。
不要改颜色，不要改组件 API。
```

确认后再来：

```txt
第二步，优化颜色和状态表达。
保留刚才的布局结构。
```

再来：

```txt
第三步，优化移动端和交互动效。
```

这样 Codex + Impeccable 的输出会稳定很多。

---

##### 10. 一个完整落地流程

```bash
# 1. 安装
npx impeccable install

# 2. 检查
npx impeccable skills check

# 3. 生成 / 更新设计文档
# 在 Codex 中执行：
/impeccable document

# 4. 让 Codex 读上下文并给计划
# 5. 确认后使用 /typeset/colorize /impeccable craft 分步实现

# 6. 检测反模式
npx impeccable detect src/

# 7. 修复检测问题

# 8. 提交
git diff
git commit -m "Improve UI with Impeccable design pass"
```

---

一句话总结：

**在 Codex 里用 Impeccable，不要把它当 “美化按钮”，而要当 “设计系统执行器”。先写清`PRODUCT.md`和`DESIGN.md`，再用`/typeset`、`/colorize`、`/impeccable craft`分维度迭代，最后用`npx impeccable detect src/`把 AI slop 拦在提交前。**

### 提问 · 2026-06-17 08:51:44

如何在已有的项目上 高质量使用 Impeccable（在 codex 环境中 ）

### 回答 · 2026-06-17 08:51:44

在**已有项目**里高质量使用 Impeccable，重点是：  
**不要让它 “重做 UI”，而是让它先理解你的产品、设计系统和代码约束，再分步骤做设计增强。**  
尤其在 Codex 环境中，推荐按下面流程来。

---

#### 一、先不要直接让它改页面

很多人一上来就对 Codex 说：

```txt
用 Impeccable 帮我把这个页面变好看
```

这通常会导致：

- 设计系统被覆盖
- 新增一堆不一致的颜色、阴影、圆角
- 页面看起来像 AI 模板
- 组件结构被改乱
- Tailwind class 爆炸
- 移动端被破坏

在已有项目中，正确方式是：

> 先让 Impeccable 读懂现有项目，再让它小步增强。

---

#### 二、推荐工作流总览

```txt
1. 新建分支
2. 安装 / 更新 Impeccable
3. 让 Codex 扫描项目设计系统
4. 建立或补全 PRODUCT.md
5. 建立或补全 DESIGN.md
6. 先做 UI 诊断，不改代码
7. 分维度改：排版、色彩、布局、动效、文案
8. 运行 impeccable detect
9. 让 Codex 根据检测结果修复
10. Review diff，再提交
```

---

#### 三、第一步：在已有项目中新建分支

先保证可回滚。

```bash
git checkout -b improve-ui-with-impeccable
```

确认当前工作区干净：

```bash
git status
```

---

#### 四、安装或更新 Impeccable

在项目根目录执行：

```bash
npx impeccable install
```

如果已经装过：

```bash
npx impeccable update
```

检查版本：

```bash
npx impeccable skills check
```

如果你在 Codex CLI / Codex 环境里，它会为对应 Agent 环境准备可用的 skill /command。

---

#### 五、让 Codex 先扫描已有项目

在 Codex 中先发这个 prompt，不要让它改代码：

```txt
请先扫描这个已有项目的前端结构，但不要修改代码。

重点查看：
- package.json
- tailwind.config.*
- src/styles/*
- src/app 或 src/pages
- src/components
- 已有 Button、Card、Input、Dialog 等基础组件
- 颜色 token、字号、间距、圆角、阴影
- 当前页面中的重复 UI 模式

请输出：
1. 当前项目使用的技术栈
2. 已有设计系统的线索
3. 已有组件规范
4. UI 风格现状
5. 主要设计债务
6. 哪些文件适合后续修改
7. 哪些文件不应该轻易动

只做分析，不要改代码。
```

这个步骤非常重要。  
它能避免 Codex 乱动你已有项目的基础结构。

---

#### 六、补一个 PRODUCT.md

Impeccable 很依赖产品上下文。  
在已有项目中，最好加一个`PRODUCT.md`。

示例：

```md
# PRODUCT

## Product
这是一个面向 B2B 团队的运维监控平台，用于查看告警、事件、服务状态和排障信息。

## Users
主要用户是 SRE、后端工程师和技术负责人。他们通常在高压场景下快速扫描信息。

## Context
这是生产力工具，不是营销型官网。设计应优先服务清晰、速度和可靠性。

## Brand Voice
冷静、准确、专业、克制。避免夸张、娱乐化和过度营销。

## Design Goals
- 快速读懂状态
- 降低告警噪音
- 强化信息层级
- 保持专业和可信
- 支持暗色环境

## Anti-reference
不要紫色渐变。
不要玻璃拟态。
不要大面积发光。
不要无意义 3D 图形。
不要过度圆角。
不要泛泛而谈的文案，比如 “提升你的生产力”。
```

如果你的项目是 SaaS 官网，则可以这样写：

```md
# PRODUCT

## Product
这是一个面向中小团队的 AI 自动化工具官网，目标是解释产品价值并引导用户注册。

## Users
创业者、运营负责人、增长团队、技术负责人。

## Context
这是转化型落地页。设计需要清楚表达产品价值，建立可信度，并推动试用。

## Brand Voice
直接、聪明、克制、有信心。不使用浮夸语气。

## Design Goals
- 让用户 5 秒内理解产品做什么
- 明确 CTA
- 增强可信度
- 减少模板感
- 移动端体验优秀

## Anti-reference
不要默认紫色渐变。
不要空泛口号。
不要 “欢迎来到我们的平台”。
不要堆叠太多相似卡片。
不要看起来像通用 AI 生成页面。
```

---

#### 七、生成或整理 DESIGN.md

如果项目已经有一定视觉规范，可以让 Impeccable 帮你文档化。

在 Codex 中运行：

```txt
/impeccable document
```

或者直接对 Codex 说：

```txt
请使用 Impeccable 的方式，为这个已有项目整理 DESIGN.md。

要求：
- 读取现有 tailwind config、CSS token 和组件实现
- 总结已有颜色、字号、间距、圆角、阴影
- 记录 Button、Card、Input、Badge 等组件的视觉规则
- 不要发明新的设计系统
- 不要改代码，只生成或更新 DESIGN.md
```

理想的`DESIGN.md`应该记录：

```md
# DESIGN

## Color
- Primary: ...
- Background: ...
- Surface: ...
- Border: ...
- Text primary: ...
- Text secondary: ...
- Success / Warning / Error: ...

## Typography
- Font family
- Display size
- Heading sizes
- Body size
- Caption size
- Line height rules

## Spacing
- Page padding
- Section spacing
- Card padding
- Form spacing

## Components
### Button
- Primary
- Secondary
- Ghost
- Danger

### Card
- Default
- Interactive
- Dense

### Input
- Default
- Error
- Disabled

## Motion
- Duration
- Easing
- Hover rules

## Anti-patterns
- 不使用紫色渐变
- 不使用玻璃拟态
- 不新增随机阴影
- 不新增不在 token 中的颜色
```

---

#### 八、第一次使用时，只让它做诊断

不要直接改。  
先让 Codex + Impeccable 做设计审计。

```txt
请基于 PRODUCT.md、DESIGN.md 和当前代码，对这个已有项目做一次 Impeccable 设计审计。

重点检查：
1. 信息层级是否清楚
2. 字体大小和字重是否有足够对比
3. 颜色是否克制并符合设计系统
4. 间距是否有节奏
5. 是否存在 AI slop 或模板感
6. 是否过度使用卡片、渐变、阴影、边框
7. 移动端布局是否自然
8. CTA 是否明确
9. 文案是否具体
10. 哪些地方风险最高

请输出：
- 问题列表
- 优先级
- 建议修改范围
- 建议先改哪些文件
- 不要修改代码
```

这个步骤可以帮你确定改动范围。

---

#### 九、改造时不要一次性全局重做

已有项目最适合用**分层改造**。

推荐顺序：

```txt
1. typeset：排版和层级
2. layout：布局、留白、节奏
3. colorize：颜色和状态
4. component polish：组件细节
5. copy：文案
6. animate：动效
7. detect：检测反模式
```

---

#### 十、第一轮：只优化排版

在 Codex 中：

```txt
/typeset

请只优化当前页面的排版层级，不要重做布局，不要改颜色系统。

要求：
- 读取 PRODUCT.md 和 DESIGN.md
- 使用现有字体、字号 token 和 Tailwind 规则
- 强化 H1、H2、正文、说明文字之间的层级
- 减少无意义的大字和弱对比文本
- 改善行高、字距、段落宽度
- 不要引入新的字体
- 不要改组件 API
- 不要大规模重构

请先给修改计划，等我确认后再改代码。
```

确认后再说：

```txt
按计划修改代码。
```

---

#### 十一、第二轮：优化布局和留白

```txt
请基于 Impeccable 的设计原则，优化当前页面的布局节奏和留白。

限制：
- 不改变路由结构
- 不引入新的 UI 库
- 不重写页面
- 优先调整 spacing、section rhythm、container width、grid
- 避免继续堆叠一排相似卡片
- 移动端优先
- 断点根据内容需要设置，不要机械套模板
- 保持现有设计系统

先输出计划，不要直接改。
```

确认后：

```txt
执行这个布局优化。
```

---

#### 十二、第三轮：优化颜色

```txt
/colorize

请优化当前页面的颜色使用。

要求：
- 严格遵守 DESIGN.md 中已有 token
- 不新增随机 hex 色值
- 减少颜色数量
- 强化主色、背景、边框、文本、状态色的分工
- 确保文字对比度接近或满足 WCAG
- 不使用紫色渐变
- 不使用大面积渐变背景
- 不使用玻璃拟态
- 保持产品气质克制、专业

先说明你会改哪些颜色角色，再修改。
```

---

#### 十三、第四轮：组件级 polish

已有项目中最值得改的是基础组件，而不是每个页面手搓。

可以这样说：

```txt
请审查已有 Button、Card、Input、Badge、Dialog 组件的视觉一致性。

目标：
- 让组件更符合 DESIGN.md
- 减少重复 Tailwind class
- 保持 API 兼容
- 不破坏现有调用
- 不引入新依赖
- 不大规模重构

请先列出每个组件的问题和最小修改方案。
```

确认后：

```txt
按最小修改方案优化这些组件。
```

这一步对已有项目收益很高，因为基础组件一改，全站都会变干净。

---

#### 十四、第五轮：文案优化

Impeccable 的一个重要点是：文案要直接，而不是 AI 味。

```txt
请基于 PRODUCT.md 优化当前页面文案。

要求：
- 直接说明产品做什么
- 删除空泛表达
- 避免 “欢迎来到我们的平台”
- 避免 “提升你的生产力” 这类泛化口号
- CTA 要具体
- 标题、副标题和按钮文案要形成清晰转化路径
- 不改变业务含义
- 不编造不存在的功能
```

例如把：

```txt
欢迎来到我们的平台
```

改成：

```txt
在一个视图里排查告警、服务状态和事故影响
```

把：

```txt
提升你的生产力
```

改成：

```txt
把告警分组、降噪并指向可执行的排障步骤
```

---

#### 十五、第六轮：动效，不要过度

```txt
/animate

请优化现有交互动效。

要求：
- 动效应服务可理解性，不要炫技
- 使用自然的 ease-out 或 ease-in-out
- 不要弹跳、不抖动、不过度缩放
- hover/focus/active 状态要明确
- 尊重 prefers-reduced-motion
- 不引入大型动画库
- 保持性能友好
```

---

#### 十六、使用`/impeccable craft`做生产级落地

当你已经确认方向，可以用：

```txt
/impeccable craft

请把当前设计优化方案落到生产代码中。

要求：
- 读取 PRODUCT.md 和 DESIGN.md
- 复用现有组件
- 遵守现有 token
- 不引入新 UI 库
- 不新增随机颜色
- 不大规模重构
- 保持 TypeScript 类型正确
- 保持响应式
- 移动端优先
- 修改后运行 lint/typecheck，如果项目有对应脚本
- 最后总结修改了哪些文件
```

---

#### 十七、改完后跑 Impeccable 检测

在终端中执行：

```bash
npx impeccable detect src/
```

如果项目代码不在`src`，比如是`app`或`packages/web`：

```bash
npx impeccable detect app/
```

或：

```bash
npx impeccable detect packages/web/
```

如果你要 CI 用 JSON：

```bash
npx impeccable detect src/--json
```

检测可能会发现类似：

```txt
gradient-text
side-stripe-border
ai-color-palette
```

然后让 Codex 修：

```txt
请根据 npx impeccable detect 的结果修复这些设计反模式。

要求：
- 不要简单删除功能
- 不要用新的反模式替代旧反模式
- 优先使用 DESIGN.md 中已有 token 和组件
- 保持视觉层级和可读性
- 修复后再次说明每一项如何处理
```

---

#### 十八、建议把 detect 接进 CI

在`package.json`里加一个 script：

```json
{
  "scripts": {
    "design:check": "impeccable detect src/"
  }
}
```

或者直接：

```json
{
  "scripts": {
    "design:check": "npx impeccable detect src/"
  }
}
```

然后在 PR 检查里运行：

```bash
npm run design:check
```

这样可以把 AI slop 拦在合并前。

#### 十九、Codex 中的高质量总 Prompt

你可以直接复制这段作为已有项目的起手 prompt：

```txt
你现在在一个已有前端项目中工作。请使用 Impeccable 的设计方法，但必须尊重现有代码和设计系统。

工作规则：
1. 先读取 PRODUCT.md、DESIGN.md、tailwind config、全局样式和基础组件
2. 不要发明新的设计系统
3. 不要引入新的 UI 库
4. 不要新增随机颜色、阴影、圆角、字体
5. 优先复用已有 Button、Card、Input、Badge 等组件
6. 小步修改，不要重写整个页面
7. 每次只优化一个维度：排版、布局、颜色、组件、文案或动效
8. 移动端优先
9. 避免 AI slop：紫色渐变、玻璃拟态、渐变文字、无意义卡片堆叠、空泛文案
10. 修改前先给计划，等我确认后再改代码
11. 修改后总结 diff，并建议运行哪些检查

现在请先扫描项目，输出当前设计系统和主要设计债务，不要修改代码。
```

---

#### 二十、已有项目中的推荐节奏

##### 第一天：只做基础理解

```txt
- 扫描项目
- 写 PRODUCT.md
- 生成 DESIGN.md
- 做设计审计
```

不要急着改 UI。

---

##### 第二步：只改一个页面

优先选：

```txt
首页
Dashboard
Pricing
登录页
核心工作流页面
```

不要一开始就全站改。

---

##### 第三步：沉淀组件

如果发现多个页面都有类似问题，回到组件层修：

```txt
Button
Card
Input
Table
Tabs
Dialog
Navigation
```

组件层修好后，再处理页面。

---

##### 第四步：加检测

```bash
npx impeccable detect src/
```

通过后再提交。

---

#### 二十一、在已有项目里最重要的原则

##### 1. 不要让 Impeccable 覆盖你的系统

应该说：

```txt
遵守 DESIGN.md 和现有 token
```

不要说：

```txt
重新设计整个视觉风格
```

---

##### 2. 不要一次性让 Codex 改太多

好的请求：

```txt
只优化 hero 的排版层级和 CTA 区域。
```

差的请求：

```txt
把整个网站做得更高级。
```

---

##### 3. 不要跳过 PRODUCT.md

没有产品上下文，AI 很容易默认生成：

- 大标题
- 渐变背景
- 发光按钮
- 一排 feature cards
- 空泛 slogan

---

##### 4. 让它先计划，再执行

每次都要求：

```txt
先给计划，不要改代码。
```

确认后再让它动手。

---

##### 5. 用检测器做最后闸门

```bash
npx impeccable detect src/
```

这一步很适合已有项目，因为它能防止后续迭代重新引入 AI 味设计。

---

#### 最短可执行版本

如果你只想快速开始，可以按这个来：

```bash
git checkout -b improve-ui
npx impeccable install
npx impeccable skills check
```

然后在 Codex 里输入：

```txt
请先扫描这个已有项目的设计系统，不要改代码。
读取 package.json、tailwind config、全局样式、src/components、主要页面。
总结现有 token、组件规则、视觉风格和设计债务。
```

接着：

```txt
/impeccable document
```

然后：

```txt
请基于 PRODUCT.md 和 DESIGN.md，只优化首页的排版层级和留白节奏。
不要改颜色，不要引入新组件，不要重写页面。
先给计划，等我确认后再改。
```

最后：

```bash
npx impeccable detect src/
```

---

总结一句：

> 在已有项目的 Codex 环境中，高质量使用 Impeccable 的关键是：**先文档化上下文，再分维度小步改造，始终尊重现有设计系统，最后用 detect 做质量闸门。**
