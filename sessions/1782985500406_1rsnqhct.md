- Remotion 适合结构高度重复、视觉风格稳定的知识类和教程类短视频批量生成。

**Rachel**

### 用 Codex + Remotion 实现无痛自媒体视频日更，涨粉过万：把剪视频变成维护一条生产线

最近两个月，我开始一个人做视频，拿到了抖音8k多粉丝，小红书2k粉丝的结果，总结了这套用codex做视频的方法论。

很多人做不到经常更新视频，因为每一条视频都要重复做一堆低价值动作：

写脚本、拆分镜、找素材、做封面、排字幕、调动画、导出不同尺寸、检查错字、修时间轴、再导出一遍。

如果你每天都从空白剪辑工程开始，日更一定会痛苦。

我现在更推荐另一种思路：不要把视频当成一次性剪辑项目，而是把它当成一个可维护的代码项目。

这就是 Codex + Remotion 最适合自媒体创作者的地方。

Codex 负责把你的想法、脚本、修改意见，转成可运行、可复用、可检查的代码和数据；Remotion 负责把 React 组件、JSON 数据、字幕、图片、音频渲染成视频。

一句话：人负责观点和判断，Codex 负责搭生产线，Remotion 负责稳定出片。

#### 为什么不是继续用剪映？

剪映当然好用。

如果你每天做的是强依赖实拍素材、情绪剪辑、现场感的内容，剪映仍然是最直接的工具。

但如果你做的是下面这些内容，Remotion 会越来越有优势：

知识卡片视频；AI 工具教程；数据可视化视频；新闻解读；金句/观点短视频；播客切片包装；产品更新视频；课程切片等等。

这些视频有一个共同点：它们每天都不同，但结构高度相似。

比如一条 60 秒 AI 工具干货视频，可能永远是这个结构：

- 3 秒钩子
- 8 秒问题
- 20 秒方法
- 20 秒案例
- 9 秒总结和行动建议

每天shuo de内容变了，但版式、字幕、动画、节奏、转场、封面风格、品牌色都不应该每天重做。

Remotion 的逻辑是“维护一个模板，然后每天喂新数据”。

这就是日更痛苦程度的分水岭。

#### Codex 在这里到底做什么？

Codex 不是一个“帮你想标题”的聊天机器人，而是一个软件开发智能体。

OpenAI 官方对 Codex 的定位是：它可以写代码、理解代码库、审查代码、调试问题，并自动化重复开发任务。

放到自媒体视频生产里，它的角色就很清楚：

帮你搭 Remotion 项目；把视频模板写成 React 组件；把你的脚本拆成 JSON 数据；根据账号风格修改动画和版式；生成渲染脚本；检查字幕是否溢出；批量导出不同平台版本；把重复流程沉淀成 \`AGENTS.md\` 或 Skill；每次出错时读报错、改代码、重新渲染

关键的是，Codex 可以在一个真实项目里持续工作。你不是每天重新教它一次“我的视频要什么风格”，而是把风格、规则、命令、验收标准写进项目。

比如在项目根目录放一个 \`AGENTS.md\`：

```markdown
# AGENTS.md

## 视频账号规则

- 默认做 1080x1920 竖屏视频，30fps。
- 每条视频控制在 45-75 秒。
- 字幕必须在安全区内，不能遮挡主视觉。
- 标题最多两行，每行不超过 14 个中文字符。
- 动画要干净，不要花哨转场。
- 每次改模板后，先渲染第 30 帧 still 检查布局。
- 最终导出 mp4 到 outputs/。
```

这样你下次只要说：“用今天这篇文章生成一条 60 秒视频”，Codex 就知道项目规则，而不是从零开始猜。

#### Remotion 在这里到底做什么？

Remotion 的核心很简单：用 React 写视频。

官方文档里讲得很直白：Remotion 给你一个帧号和一块空白画布，你可以用 React 在每一帧渲染任何内容。一个视频本质上就是一组随时间变化的图像。

这件事对自媒体很重要。

因为一旦视频变成代码，你就可以做这些事：

\- 用同一套组件生成 100 条不同视频

\- 用 JSON 控制文案、字幕、图片、音频和时长

\- 用变量控制颜色、字体、品牌元素

\- 用函数控制动画节奏

\- 用脚本批量渲染不同平台尺寸

\- 用 Git 保存每次模板改动

\- 用 Codex 维护、重构、修复整个生产线

Remotion 不是“更复杂的剪映”，它更像一个视频生成引擎。

剪映适合手工剪一条视频。Remotion 适合批量生产同一类高一致性视频。

#### 最小可行生产线长什么样？

一开始不要做复杂系统。你只需要一个能稳定日更的最小生产线。

目录可以这样设计：

```markdown
daily-video/
  AGENTS.md
  package.json
  src/
    Root.tsx
    compositions/
      DailyExplainer.tsx
      ToolTutorial.tsx
      QuoteCard.tsx
    components/
      TitleCard.tsx
      Caption.tsx
      ProgressBar.tsx
      SceneCard.tsx
      BrandMark.tsx
    styles/
      theme.ts
  content/
    2026-07-01-codex-remotion.json
    2026-07-02-ai-editing.json
  public/
    assets/
      avatar.png
      logo.png
      bg/
  scripts/
    render-daily.mjs
    make-content-from-md.mjs
  outputs/
```

每天真正变化的，不是 \`DailyExplainer.tsx\`，而是 \`content/2026-07-01-codex-remotion.json\`。

比如一条视频的数据可以长这样：

```markdown
{
  "title": "用 Codex + Remotion 做到视频日更",
  "durationSec": 60,
  "hook": "日更最痛的不是写脚本，而是每天从零剪一遍。",
  "scenes": [
    {
      "type": "problem",
      "text": "如果你每天都打开一个空白剪辑工程，日更一定会越来越累。"
    },
    {
      "type": "insight",
      "text": "真正的解法，是把视频变成可复用模板，把内容变成数据。"
    },
    {
      "type": "workflow",
      "bullets": ["Codex 写模板", "Remotion 渲染视频", "每天只换 JSON"]
    },
    {
      "type": "ending",
      "text": "自媒体日更，不是拼意志力，是搭生产线。"
    }
  ]
}
```

Remotion 读取这个 JSON，自动生成画面、字幕、进度条、场景切换和结尾卡。

这时你每天要做的事就变成：

1\. 写今天的主题和脚本

2\. 让 Codex 转成结构化 JSON

3\. 预览或渲染 still 检查画面

4\. 渲染 mp4

5\. 发布

这才叫无痛。

#### 一条视频可以拆成 5 个可复用模块

媒体视频日更的关键，不是让 AI 每天自由发挥，而是把视频拆成稳定模块。

我建议先做 5 个模块。

第一，开场钩子模块。

它只负责前 3 秒。可以是大标题、快速缩放、关键词高亮、问题句。这个模块的目标不是好看，而是让用户知道“这条视频跟我有关”。

第二，主体场景模块。

它负责展示观点、步骤、案例、工具名称、对比表。这里不要追求每天不同的炫酷效果，而要追求稳定可读。

第三，字幕模块。

字幕必须是独立组件，不要散落在每个场景里。字号、行高、安全区、描边、背景、强调词颜色，都应该统一。

第四，素材模块。

包括截图、Logo、头像、产品界面、B-roll。Remotion 可以用 \`staticFile()\` 引用 \`public/\` 里的静态资源，也可以读取远程资源。日更阶段建议先用本地素材，减少不可控因素。

第五，结尾模块。

结尾不要每天重新想。固定成一句总结 + 一个轻行动就够了，比如“收藏这套流程，下一条讲自动字幕模板”。

只要这 5 个模块稳定，视频生产就不会每天散架。

#### Codex + Remotion 的每日工作流

真正可执行的日更流程可以这样跑。

第一步，写一段原始想法。

不用完整脚本，只要把今天想表达的观点写清楚。例如：

```markdown
今天想写 Codex + Remotion 怎么让自媒体视频日更。
核心观点：不是让 AI 替你剪视频，而是把视频模板代码化。
受众：想做知识类短视频，但被剪辑拖住的人。
风格：直接、实用、不要玄学。
```

第二步，让 Codex 变成脚本和结构化数据。

你可以这样提示：

```markdown
请把这段想法改成一条 60 秒竖屏视频脚本。
要求：
1. 开头 3 秒必须有冲突。
2. 分成 4 个 scene。
3. 每个 scene 给 title、voiceover、caption、visual。
4. 输出为 content/YYYY-MM-DD-topic.json。
5. 不要改 Remotion 模板代码，除非字段不够用。
```

第三步，让 Codex 检查模板是否支持这条内容。

```markdown
读取 content/2026-07-01-codex-remotion.json 和 DailyExplainer.tsx，
检查所有字段是否被正确渲染。
如果字幕可能溢出，请调整 Caption 组件，不要改文案。
```

第四步，渲染单帧检查。

Remotion 支持用 CLI 渲染视频，也可以渲染 still 图片。日更流程里，先渲染一张关键帧图片非常重要，因为它能快速发现标题太长、字幕遮挡、Logo 位置不对、颜色太淡。

第五步，渲染完整视频。

Remotion 官方文档给出的 CLI 渲染形式是：

```markdown
px remotion render HelloWorld
```

实际项目里可以封装成：

```markdown
npm run render:daily -- --input content/2026-07-01-codex-remotion.json
```

第六步，复盘这条视频。

日更不是每天机械发，而是每天让系统变好一点。今天发现标题容易溢出，就让 Codex 改标题组件；发现字幕节奏太慢，就改字幕切分规则；发现封面点击率差，就新增一套封面 composition。

每天只改一个小地方，30 天后你会拥有一条非常顺手的视频生产线。

#### 三种最适合先做的 Remotion 视频模板

第一种：观点解释型。

第二种：工具教程型。

第三种：金句卡片型。

#### 真正的无痛，来自把规则写进项目

很多人用 AI 做视频失败，是因为每天都在同一个聊天框里重新描述需求。

“帮我做得高级一点。”

“字幕别太大。”

“风格像小红书。”

“节奏快一点。”

这种提示词没法积累。今天说一次，明天还要再说一次。

Codex + Remotion 的正确用法，是把重复规则写进项目。

比如：

\- 账号视觉规范写进 \`src/styles/theme.ts\`

\- 字幕规则写进 \`Caption.tsx\`

\- 场景结构写进 JSON schema

\- 渲染命令写进 \`package.json\`

\- 协作规则写进 \`AGENTS.md\`

\- 每日视频流程写成 Codex Skill

当流程稳定以后，你甚至可以给自己做一个 \`.agents/skills/daily-video/SKILL.md\`

#### 结论：日更不是靠自律，而是靠系统

过去做视频，创作者每天都要打开剪辑软件，从零开始搭一条时间线。

Codex + Remotion 给了另一种可能：把视频变成代码，把脚本变成数据，把风格变成组件，把重复劳动变成命令。

这并不会替代创作者。

它替代的是那些每天重复、消耗注意力、但并不产生观点价值的动作。

真正值得你亲自做的，是选题判断、观点表达、案例选择、情绪分寸。

至于字幕怎么排、标题怎么进场、进度条怎么动、不同平台怎么导出、模板报错怎么修，这些都应该交给系统。

自媒体日更的终点，不是让你变成更能熬夜的剪辑师。

而是让你拥有一条属于自己的视频生产线。

#### 用 Codex + Remotion 做视频日更：深度总结、解读与思考

##### 一、深度总结

文章核心观点：

> **自媒体视频日更的关键，不是更努力剪视频，而是把视频生产变成一条可维护的“代码化生产线”。**

传统剪辑的问题在于：  
每条视频都像一个新项目，反复做脚本、分镜、字幕、动画、封面、导出、检查等低价值重复劳动。

作者提出的新方法是：

> **人负责观点与判断，Codex 负责搭建和维护流程，Remotion 负责稳定生成视频。**

---

##### 二、方法论核心

###### 1. 视频不再是“一次性剪辑项目”

而是一个长期维护的代码项目。

每天变化的是内容，不变的是：

- 版式
- 字幕样式
- 动画节奏
- 品牌色
- 封面风格
- 转场逻辑
- 导出规则

本质是：

> **模板固定，数据更新。**

---

###### 2. Codex 的作用

Codex 不是简单“帮你写标题”的 AI，而是一个开发智能体。

它负责：

- 搭建 Remotion 项目
- 编写 React 视频组件
- 把脚本转成 JSON
- 检查字幕溢出
- 修改动画和布局
- 批量导出不同尺寸
- 根据报错修代码
- 把流程规则沉淀进项目

关键在于：

> **规则不是每天重新说，而是写进项目文件里。**

例如通过 `AGENTS.md` 固化账号规则、字幕规则、导出规则和验收标准。

---

###### 3. Remotion 的作用

Remotion 的本质是：

> **用 React 写视频。**

它把视频拆成代码组件，用 JSON 驱动画面、字幕、图片、音频和动画。

适合这些内容：

- 知识卡片视频
- AI 工具教程
- 数据可视化
- 新闻解读
- 金句短视频
- 播客切片包装
- 产品更新视频
- 课程切片

这些内容的共同点是：

> **每天内容不同，但结构高度相似。**

---

##### 三、最小可行生产线

最简单的日更流程是：

1. 写今天的主题和观点
2. 让 Codex 转成结构化脚本 JSON
3. Remotion 根据模板生成视频
4. 渲染关键帧检查画面
5. 导出完整视频
6. 发布并复盘
7. 每天优化生产线中的一个小问题

核心不是一次做完美，而是：

> **每天内容更新，系统也微调进化。**

---

##### 四、视频可拆成 5 个稳定模块

###### 1. 开场钩子

负责前 3 秒，目标是让用户立刻知道：

> “这条视频和我有关。”

###### 2. 主体场景

展示观点、步骤、案例、工具、对比等内容。  
重点不是炫酷，而是清晰稳定。

###### 3. 字幕模块

字幕应是独立组件，统一控制：

- 字号
- 行高
- 安全区
- 描边
- 背景
- 强调色

###### 4. 素材模块

管理截图、Logo、头像、产品界面、背景图等。  
日更阶段优先用本地素材，降低不确定性。

###### 5. 结尾模块

固定为一句总结加一个轻行动：

> 收藏、关注、下一条讲什么。

---

##### 五、深入浅出解读

这套方法可以理解成：

> **以前你每天都在“手工做饭”，现在你在搭一条“自动化厨房”。**

传统剪辑像这样：

- 每天重新开火
- 每天重新切菜
- 每天重新摆盘
- 每天重新收拾

Codex + Remotion 像这样：

- 菜谱固定
- 厨具固定
- 摆盘固定
- 每天只换食材

这里的“食材”就是今天的脚本、观点和素材。  
“厨房”就是 Remotion 模板。  
“厨师助手”就是 Codex。

所以真正的变化不是“AI 替你创作”，而是：

> **AI 帮你减少重复劳动，让你把精力放在选题、观点和表达上。**

---

##### 六、这套方法真正解决了什么？

它解决的不是“不会剪辑”的问题，而是：

###### 1. 降低日更阻力

不必每天从空白时间线开始。

###### 2. 提高内容一致性

账号视觉、节奏、字幕、封面更统一。

###### 3. 提升复用能力

一个模板可以生成几十条、上百条视频。

###### 4. 方便持续优化

发现问题后，不是手动修一条，而是改组件，之后所有视频都受益。

###### 5. 把经验沉淀成系统

提示词会丢失，但代码、规则、模板可以积累。

---

##### 七、辩证思考

###### 值得肯定的地方

这套方法非常适合“结构化内容创作者”。

尤其适合知识类、工具类、观点类账号。  
因为这类视频的竞争力主要不在复杂剪辑，而在：

- 选题是否准确
- 观点是否清楚
- 信息是否有用
- 表达是否高效
- 更新是否稳定

对这类创作者来说，把剪辑流程代码化，确实能显著提高产能。

---

###### 但它不是万能方案

它不适合所有视频类型。

如果内容强依赖：

- 实拍素材
- 情绪节奏
- 复杂镜头语言
- 人物表演
- 现场氛围
- 精细化剪辑手感

那么剪映、PR、Final Cut 这类传统剪辑工具仍然更直接。

Remotion 更像“视频生成引擎”，不是万能剪辑软件。

---

###### 最大门槛不是技术，而是结构化能力

表面看门槛是 React、JSON、Remotion、Codex。  
但更深的门槛其实是：

> **你能不能把自己的内容拆成稳定结构。**

如果创作者自己都不知道视频结构是什么，每天风格大变、表达混乱，即使有 Codex 和 Remotion，也很难稳定产出。

工具放大的是能力，不是替代能力。

---

###### 自动化也可能带来同质化

模板化提高效率，但也可能让内容变得机械。

如果所有视频都是：

- 3 秒钩子
- 20 秒方法
- 20 秒案例
- 9 秒总结

短期高效，长期可能审美疲劳。

所以创作者仍要定期更新：

- 表达方式
- 视觉风格
- 内容结构
- 叙事节奏
- 选题角度

生产线要稳定，但不能僵化。

---

##### 八、最终结论

这篇文章真正有价值的地方，不是推荐了 Codex 和 Remotion 两个工具，而是提出了一种内容生产思维：

> **不要把日更当成体力活，要把日更变成系统工程。**

对自媒体创作者来说，最重要的转变是：

- 从“每天剪一条视频”
- 变成“维护一条视频生产线”

人应该专注于：

- 判断什么值得讲
- 提炼观点
- 选择案例
- 控制情绪和分寸

系统负责：

- 字幕
- 动画
- 排版
- 导出
- 检查
- 复用

一句话总结：

> **日更不是靠死磕自律，而是靠搭建可复用、可迭代、可维护的生产系统。**

## 结构化（1）

### 2026-07-02 11:06:27

##### 主旨概括

作者分享了自己用 **Codex + Remotion** 做自媒体视频日更的方法：不要把每条视频当成一次性剪辑项目，而要把视频生产变成一条可维护、可复用的“代码生产线”。

##### 1. 为什么日更视频会痛苦？

很多人无法坚持视频日更，不是因为没有想法，而是因为每条视频都要重复大量低价值动作：

- 写脚本
- 拆分镜
- 找素材
- 做封面
- 排字幕
- 调动画
- 导出不同尺寸
- 检查错字
- 修时间轴
- 反复导出

如果每天都从一个空白剪辑工程开始，日更就会非常累。

作者过去两个月一个人做视频，取得了：

- 抖音：**8000+ 粉丝**
- 小红书：**2000+ 粉丝**

他的经验是：与其每天重新剪一条视频，不如把视频当成一个可以长期维护的代码项目。

##### 2. Codex + Remotion 的基本分工

作者把这套方法总结为一句话：

> 人负责观点和判断，Codex 负责搭生产线，Remotion 负责稳定出片。

具体来说：

- **Codex**：把想法、脚本、修改意见转成代码和结构化数据，并维护整个项目。
- **Remotion**：用 React 组件、JSON 数据、字幕、图片、音频来渲染视频。

也就是说，创作者不用每天重复做版式、字幕、动画、导出等工作，而是维护一套模板，每天只更新内容数据。

---

##### 3. 为什么不是继续用剪映？

作者认为，剪映依然适合很多场景，尤其是：

- 强依赖实拍素材
- 情绪剪辑
- 现场感内容
- 需要手工精剪的视频

但如果你做的是结构高度相似的内容，Remotion 会更有优势，比如：

- 知识卡片视频
- AI 工具教程
- 数据可视化视频
- 新闻解读
- 金句/观点短视频
- 播客切片包装
- 产品更新视频
- 课程切片

这些视频每天主题不同，但结构往往很相似。

例如一条 60 秒 AI 工具干货视频，结构可能一直是：

- 3 秒钩子
- 8 秒问题
- 20 秒方法
- 20 秒案例
- 9 秒总结和行动建议

内容每天变，但版式、字幕、动画、节奏、转场、封面风格、品牌色不应该每天重做。

---

##### 4. Remotion 的核心价值：维护模板，每天喂新数据

Remotion 的逻辑不是“手工剪视频”，而是：

> 维护一个视频模板，然后每天输入新的数据。

它用 React 写视频，可以把一个视频理解成“随时间变化的一组画面”。

一旦视频变成代码，就可以做到：

- 用同一套组件生成 100 条不同视频
- 用 JSON 控制文案、字幕、图片、音频和时长
- 用变量控制颜色、字体、品牌元素
- 用函数控制动画节奏
- 用脚本批量导出不同平台尺寸
- 用 Git 保存模板改动
- 让 Codex 维护、重构和修复项目

作者强调：

> Remotion 不是更复杂的剪映，而是一个视频生成引擎。

剪映适合手工剪一条视频，Remotion 适合批量生产同一类高一致性视频。

---

##### 5. Codex 在视频生产中具体做什么？

Codex 不是简单的“帮你想标题”的聊天机器人，而是一个软件开发智能体。

在自媒体视频生产中，它可以做：

- 搭建 Remotion 项目
- 把视频模板写成 React 组件
- 把脚本拆成 JSON 数据
- 根据账号风格修改动画和版式
- 生成渲染脚本
- 检查字幕是否溢出
- 批量导出不同平台版本
- 把重复流程沉淀成 `AGENTS.md` 或 Skill
- 出错时读取报错、修改代码、重新渲染

关键在于，Codex 可以在一个真实项目里持续工作。

创作者不需要每天重新告诉它视频风格，而是把规则写进项目里。

例如在项目根目录放一个 `AGENTS.md`，规定：

- 默认做 1080×1920 竖屏视频
- 30fps
- 每条视频控制在 45-75 秒
- 字幕必须在安全区内
- 标题最多两行，每行不超过 14 个中文字符
- 动画干净，不要花哨转场
- 每次改模板后先渲染第 30 帧检查布局
- 最终导出 mp4 到 `outputs/`

这样下次只要说“用今天这篇文章生成一条 60 秒视频”，Codex 就能按项目规则执行。

---

##### 6. 最小可行的视频生产线长什么样？

作者建议一开始不要做复杂系统，只需要搭一条能稳定日更的最小生产线。

项目目录可以包括：

- `AGENTS.md`：项目规则
- `src/`：视频代码
- `compositions/`：不同视频模板
- `components/`：标题、字幕、进度条、场景卡片等组件
- `styles/`：主题样式
- `content/`：每天的视频内容 JSON
- `public/`：图片、Logo、背景等素材
- `scripts/`：渲染和内容生成脚本
- `outputs/`：最终视频输出

每天真正变化的不是模板代码，而是类似这样的 JSON 内容文件：

```json
{
  "title": "用 Codex + Remotion 做到视频日更",
  "durationSec": 60,
  "hook": "日更最痛的不是写脚本，而是每天从零剪一遍。",
  "scenes": [
    {
      "type": "problem",
      "text": "如果你每天都打开一个空白剪辑工程，日更一定会越来越累。"
    },
    {
      "type": "insight",
      "text": "真正的解法，是把视频变成可复用模板，把内容变成数据。"
    },
    {
      "type": "workflow",
      "bullets": ["Codex 写模板", "Remotion 渲染视频", "每天只换 JSON"]
    },
    {
      "type": "ending",
      "text": "自媒体日更，不是拼意志力，是搭生产线。"
    }
  ]
}
```

Remotion 读取这个 JSON 后，自动生成：

- 画面
- 字幕
- 进度条
- 场景切换
- 结尾卡

于是每天的工作就简化成：

1. 写今天的主题和脚本
2. 让 Codex 转成结构化 JSON
3. 预览或渲染单帧检查画面
4. 渲染 mp4
5. 发布

##### 7. 一条视频可以拆成 5 个可复用模块

作者认为，视频日更的关键不是让 AI 每天自由发挥，而是把视频拆成稳定模块。

###### 1）开场钩子模块

负责前 3 秒，形式可以是：

- 大标题
- 快速缩放
- 关键词高亮
- 问题句

目标不是炫酷，而是让用户立刻知道“这条视频和我有关”。

###### 2）主体场景模块

用于展示：

- 观点
- 步骤
- 案例
- 工具名称
- 对比表

重点是稳定、清晰、可读，而不是每天追求不同效果。

###### 3）字幕模块

字幕应该是独立组件，而不是散落在每个场景里。

需要统一管理：

- 字号
- 行高
- 安全区
- 描边
- 背景
- 强调词颜色

###### 4）素材模块

包括：

- 截图
- Logo
- 头像
- 产品界面
- B-roll

Remotion 可以引用本地素材，也可以读取远程资源。日更阶段建议优先用本地素材，减少不稳定因素。

###### 5）结尾模块

结尾不需要每天重新想，固定成：

- 一句总结
- 一个轻行动建议

例如：

> 收藏这套流程，下一条讲自动字幕模板。

只要这 5 个模块稳定，视频生产就不会每天“散架”。

##### 8. Codex + Remotion 的每日工作流

作者给出了一套可执行的日更流程。

###### 第一步：写原始想法

不需要完整脚本，只要写清楚今天的观点。

例如：

```markdown
今天想写 Codex + Remotion 怎么让自媒体视频日更。
核心观点：不是让 AI 替你剪视频，而是把视频模板代码化。
受众：想做知识类短视频，但被剪辑拖住的人。
风格：直接、实用、不要玄学。
```

###### 第二步：让 Codex 生成脚本和结构化数据

可以提示 Codex：

```markdown
请把这段想法改成一条 60 秒竖屏视频脚本。
要求：
1. 开头 3 秒必须有冲突。
2. 分成 4 个 scene。
3. 每个 scene 给 title、voiceover、caption、visual。
4. 输出为 content/YYYY-MM-DD-topic.json。
5. 不要改 Remotion 模板代码，除非字段不够用。
```

###### 第三步：检查模板是否支持内容

让 Codex 读取 JSON 和模板代码，检查字段是否被正确渲染。

如果字幕可能溢出，就调整字幕组件，而不是随便改文案。

###### 第四步：渲染单帧检查

在完整导出前，先渲染关键帧图片，快速检查：

- 标题是否太长
- 字幕是否遮挡
- Logo 位置是否正确
- 颜色是否太淡

这一步可以避免完整视频导出后才发现问题。

###### 第五步：渲染完整视频

Remotion 支持 CLI 渲染，可以封装成命令，例如：

```bash
npm run render:daily -- --input content/2026-07-01-codex-remotion.json
```

最终导出 mp4 文件。

###### 第六步：复盘并优化系统

日更不是机械发布，而是每天让生产线变好一点。

比如：

- 标题容易溢出，就改标题组件
- 字幕节奏太慢，就改字幕切分规则
- 封面点击率差，就新增封面模板

每天只改一个小地方，30 天后就会拥有一套很顺手的视频生产系统。

##### 9. 最适合先做的三类 Remotion 视频模板

作者建议先从三种模板开始：

1. **观点解释型**  
   适合讲认知、方法论、行业观察。

2. **工具教程型**  
   适合 AI 工具、软件功能、操作流程演示。

3. **金句卡片型**  
   适合观点摘录、短句传播、情绪价值内容。

这些类型结构清晰，适合模板化和批量生产。

---

##### 10. 真正的无痛，来自把规则写进项目

很多人用 AI 做视频失败，是因为每天都在聊天框里重复描述需求，例如：

- “帮我做得高级一点”
- “字幕别太大”
- “风格像小红书”
- “节奏快一点”

这些提示词无法积累，今天说一次，明天还要重新说。

正确做法是把重复规则沉淀进项目：

- 账号视觉规范写进 `src/styles/theme.ts`
- 字幕规则写进 `Caption.tsx`
- 场景结构写进 JSON schema
- 渲染命令写进 `package.json`
- 协作规则写进 `AGENTS.md`
- 每日视频流程写成 Codex Skill

当流程稳定后，甚至可以做一个专门的：

```text
.agents/skills/daily-video/SKILL.md
```

让 Codex 更稳定地执行每日视频生产流程。

作者最后强调，自媒体日更的核心不是让创作者变成更能熬夜的剪辑师，而是让创作者拥有一条自己的视频生产线。

最终目标是：

> 不再每天从零剪视频，而是维护一条稳定的视频生产线。

如果你的内容高度依赖实拍素材、情绪剪辑和现场氛围，剪映仍然是很直接的选择。

但如果你制作的是知识卡片、人工智能工具教程、数据可视化、新闻解读、金句观点、播客切片、产品更新或课程切片，Remotion 会越来越有优势。

因为这些视频每天讲的内容虽然不同，但结构通常高度相似。

比如一条六十秒的人工智能工具视频，可以固定成这样的节奏：前三秒提出钩子，八秒说明问题，二十秒讲方法，二十秒展示案例，最后九秒总结并给出行动建议。

每天变化的是文字和案例。字幕样式、动画节奏、转场方式、封面风格和品牌颜色，则不需要每天重新制作。

Remotion 的核心逻辑，就是维护一个模板，然后每天给这个模板输入新的数据。这往往就是日更能否持续的分水岭。

##### 更重要的是，把视频模板和内容分开

核心结论是：视频的结构应该写成代码，具体内容则应该保存成数据。

在 Remotion 里，你可以用同一套组件生成一百条不同的视频。文案、字幕、图片、音频和时长，都可以通过结构化数据控制。颜色、字体和品牌元素，可以用变量统一管理。动画节奏，则可以用函数来控制。

这里的“结构化数据”，可以简单理解为一份格式统一的内容清单。比如，一条视频的数据可以包括标题、时长、开场钩子，以及几个场景。每个场景再写明它属于问题、观点、流程还是结尾，并填入相应的文字。

Remotion 读取这份数据之后，就能自动生成画面、字幕、进度条、场景切换和结尾卡。

这样一来，每天真正需要修改的，通常不是视频模板文件，而是当天的内容数据文件。

一个最小的项目，可以包含这些部分：项目规则文件、视频模板、标题和字幕组件、主题样式、内容数据、图片和头像等素材，以及渲染脚本和最终输出目录。

这种结构带来的好处是，模板可以长期复用，内容可以每天替换，历史版本也可以保存。之后如果要调整风格或修复问题，只需要修改一次模板，就能影响后续所有视频。

##### 一开始，只需要搭建一条最小可行生产线

核心结论是：不要一开始就做复杂系统，先保证每天能够稳定完成一条视频。

一条最小生产线可以这样工作：

第一步，写下当天的主题和脚本。

第二步，让 Codex 把这些想法转换成结构化数据。

第三步，让 Remotion 预览或渲染关键帧，检查画面布局。

第四步，渲染完整的 MP4 视频。

第五步，发布视频。

这里特别重要的是“关键帧检查”。所谓关键帧，就是先只生成某一帧画面的图片，而不是马上渲染完整视频。这样可以快速发现标题是否太长，字幕有没有遮挡主视觉，Logo 是否放错位置，以及颜色是不是太淡。

确认布局没有问题之后，再渲染完整视频，可以节省很多时间。

原文给出的账号规则也很具体。比如默认使用一千零八十乘一千九百二十的竖屏尺寸，每秒三十帧；视频时长控制在四十五到七十五秒；字幕必须处于安全区内，不能遮住主视觉；标题最多两行，每行不超过十四个中文字符；动画要干净，避免花哨的转场；每次修改模板后，先检查第三十帧的画面；最后把视频导出到指定的输出目录。

##### Codex 的关键作用，是记住项目规则

核心结论是：不要每天在聊天框里重复描述账号风格，而要把规则写进项目。

很多人使用人工智能做视频时，每天都要重新说一遍：“做得高级一点”“字幕别太大”“风格像小红书”“节奏快一点”。这些要求很难积累，也很容易前后不一致。

更稳定的做法，是在项目根目录放一个叫作“AGENTS.md”的规则文件。这个文件可以理解为项目说明书，里面写清楚视频尺寸、时长、字幕要求、动画风格、检查步骤和导出方式。

以后你只需要告诉 Codex：“用今天这篇文章生成一条六十秒视频。”它就能根据项目中已经写好的规则执行，而不是每次从零猜测。

除了规则文件，还可以把视觉规范写进主题样式，把字幕规则写进字幕组件，把场景结构写进数据格式，把渲染命令写进项目配置文件。等流程稳定以后，还可以把每日视频流程整理成一个专门的技能文件，让 Codex 按固定步骤执行。

##### 一条视频，最好先拆成五个可复用模块

核心结论是：不要让人工智能每天自由发挥，而要先把视频拆成稳定的模块。

第一个模块是开场钩子。

它只负责最开始的三秒，可以使用大标题、快速缩放、关键词高亮或问题句。它的目标不是炫技，而是让观众立刻知道，这条视频和自己有关。

第二个模块是主体场景。

它用来展示观点、步骤、案例、工具名称和对比内容。这里不需要每天追求不同的动画效果，更重要的是稳定、清楚、容易阅读。

第三个模块是字幕。

字幕应该作为独立组件存在，而不是散落在每个场景里。字号、行高、安全区、描边、背景，以及重点词的颜色，都应该统一管理。

第四个模块是素材。

素材可以包括截图、Logo、头像、产品界面和视频片段。Remotion 可以引用项目里的本地素材，也可以读取远程资源。但在日更阶段，原文建议优先使用本地素材，以减少网络和资源失效带来的不确定性。

第五个模块是结尾。

结尾不需要每天重新设计。固定成一句总结，加一个轻量行动建议就够了。比如先总结今天的观点，再提示观众收藏，或者预告下一条视频。

只要这五个模块稳定下来，视频生产就不容易每天散架。

##### 一套真正可执行的每日工作流

接下来，按照实际操作顺序，完整走一遍每日流程。

第一步，写下原始想法。

不需要一开始就写成完整脚本。只要说清楚今天想表达什么、核心观点是什么、目标观众是谁，以及整体风格是什么。

例如，主题是“Codex 加 Remotion 如何帮助视频日更”；核心观点是“不是让人工智能替你剪视频，而是把视频模板代码化”；目标观众是想做知识类短视频、却被剪辑拖住的人；风格则是直接、实用，不讲玄学。

第二步，让 Codex 把想法变成脚本和结构化数据。

可以要求它生成一条六十秒竖屏视频，开头三秒要有冲突，全文分成四个场景，每个场景都包含标题、旁白、字幕和画面说明，并把结果保存成当天的内容文件。

同时，要明确告诉它：除非现有字段不够用，否则不要随意修改 Remotion 模板。

第三步，让 Codex 检查模板是否支持这条内容。

它需要读取当天的数据文件和视频模板，确认所有字段都被正确渲染。如果字幕可能溢出，就调整字幕组件，而不是直接删改文案。

第四步，先渲染一张关键帧图片。

重点检查标题长度、字幕位置、Logo 位置和颜色对比度。

第五步，渲染完整视频。

Remotion 可以通过命令行渲染视频，实际项目里也可以把命令封装起来，只需要指定当天的内容文件，就能生成对应的视频。

第六步，复盘并改进系统。

日更不是每天机械地发布，而是每天让生产线变好一点。今天发现标题容易溢出，就改进标题组件；发现字幕节奏太慢，就修改字幕切分规则；发现封面点击率不理想，就增加一套新的封面模板。

如果每天只改进一个小地方，三十天之后，就可能拥有一条非常顺手的视频生产线。

##### 最适合先做的三类模板

原文建议优先从三种视频模板开始。

第一种是观点解释型，用来讲清一个判断、一个现象或一个方法。

第二种是工具教程型，用来展示软件、人工智能工具或具体操作步骤。

第三种是金句卡片型，用来包装一句观点、结论或值得传播的话。

这三类内容共同的特点是，结构容易固定，文字和素材每天可以更换，因此特别适合用模板加数据的方式批量生产。

##### 最后，日更靠的不是意志力，而是系统

过去做视频，创作者每天都要打开剪辑软件，从零搭建一条时间线。

Codex 加 Remotion 提供了另一种思路：把视频变成代码，把脚本变成数据，把风格变成组件，把重复劳动变成命令。

这套方法并不是要替代创作者。它真正替代的，是那些每天重复、消耗注意力，却不产生观点价值的动作。

选题判断、观点表达、案例选择和情绪分寸，仍然应该由创作者亲自完成。

至于字幕怎么排、标题怎么进场、进度条怎么移动、不同平台如何导出，以及模板报错如何修复，这些工作则更适合交给系统。

自媒体日更的终点，不是让自己变成一个更能熬夜的剪辑师，而是拥有一条属于自己的视频生产线。

##### 重点回顾

最后，记住五个结论。

第一，不要每天从空白剪辑工程开始，要维护一个可以长期复用的视频模板。

第二，Codex 负责理解项目、编写和维护代码，Remotion 负责把模板和数据渲染成视频。

第三，视频模板和当天内容要分开管理，模板负责结构，数据负责文案、素材和时长。

第四，先从开场钩子、主体场景、字幕、素材和结尾这五个模块开始，建立最小可行生产线。

第五，真正的日更，不是靠更强的意志力，而是把重复规则写进项目，让系统持续替你完成低价值工作。

## 深度解读（1）

### 2026-09-18 00:42:20

#### Codex + Remotion 的价值，不是“AI 剪视频”，而是把创作经验变成可执行系统

作者两个月获得抖音 8 千多、小红书 2 千粉丝，说明这套方法至少具备实践可行性，但还不足以证明增长由工具带来：选题质量、账号基础、发布频率和平台分发都可能影响结果。文章真正值得保留的，不是涨粉数字，而是一个更普遍的生产观念：**当内容高度重复时，工作对象不应再是某一条视频，而应是持续生产视频的系统。**

##### 从“复制工程”到“复用规则”

传统模板通常只是复制一条时间线，创作者仍要手工替换字幕、移动素材、调整时长。这里更进一步：把视频拆成三层——内容是 JSON 数据，视觉与动画是 React 组件，账号规范与验收条件则写进代码库和 `AGENTS.md`。

这意味着“字幕不能越过安全区”“标题最多两行”“先检查关键帧”等经验，不再依赖创作者每次记得，而成为可重复执行的规则。Codex 的关键作用也因此不是生成一次脚本，而是**在同一个项目中持续修改、调试和积累生产知识**；Remotion 则提供确定性的渲染环境。两者结合，自动化的不只是操作，更是团队或个人的“生产记忆”。

这种思路可以迁移到很多内容工作：报告生成、营销物料、产品发布视频乃至数据周报。只要输入经常变化、输出结构相对稳定，就有机会把一次性交付改造成“模板 + 数据 + 验收”的流水线。

##### 是否值得代码化，取决于重复密度

这套方案并不天然优于剪映。它以更高的前期搭建和维护成本，换取更低的边际生产成本，因此最适合知识卡片、工具教程、新闻解读、产品更新等**高频、同构、强调一致性**的内容。强依赖实拍、情绪节奏和临场素材的视频，人工时间线仍然更直接。

真正的判断变量不是“会不会写代码”，而是三个问题：

1. 同一种结构会重复多少次？
2. 跨平台尺寸、品牌规范等一致性要求有多高？
3. 每次手工调整究竟消耗多少时间？

如果一个栏目只做三期，搭生产线可能得不偿失；如果每周发布五条、同时适配多个平台，模板化很快就会摊薄成本。Codex 降低了开发门槛，却没有消除系统维护成本。

##### 生产提速后，瓶颈会转移到内容与反馈

视频变成 JSON 后，效率提高了，但也容易出现另一种问题：**形式稳定，内容开始同质化。**固定的“3 秒钩子—问题—方法—案例—总结”能降低制作成本，却不能保证可信度、信息密度和叙事张力。生产线越顺，越可能快速放大平庸选题。

因此，成熟系统不能只自动渲染，还要形成反馈闭环：不同开场模块对应完播率，封面版本对应点击率，字幕密度对应跳出点；复盘结果再沉淀进组件、内容 schema 和检查规则。与此同时，应增加字幕溢出、时长异常、素材缺失、渲染失败等自动检查，避免 Codex 为适配某一期内容而破坏其他模板。

最稳妥的起点不是先建一个复杂平台，而是选择一个已经重复出现的栏目，用过去十几条内容提炼稳定结构，先做一个模板、一套数据格式和几个明确的验收条件。**只有当生产规则能被写清、效果能被比较，所谓“视频生产线”才不是换一种方式折腾工具，而是真正可积累的内容资产。**
