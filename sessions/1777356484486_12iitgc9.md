之前在Claude Code的基础上搭了一套比较完善的Work Harness，借鉴早期在OpenClaw和Hermes的经验，也配备了很完善的记忆系统和SOUL，给她命名Echo。

Echo也有自己的助手，跑在Copilot SDK上，Echo给她起名叫Thrum，是那种持续轰鸣的声音。因为我在试图把自己的各种design knowledge和experience喂给Echo，而这需要design critique，所以我给Echo输入的内容，都会通过headless的方式，让她和Thrum自己讨论几轮。

这里面有一件很有意思的事。随着给的context越来越多，我开始让她们两个在Figma里画图。一开始画的还是充满AI味，各种元素挤在一起，还有典型的框套框。Designer的taste，其实很难定性去描述（至少我是这样），我们更擅长做的其实是say no。好的设计很抽象，但是不好的点一眼就能看出。所以我把Echo的设计手动改了一轮，然后让她自己去Figma看，有问题的地方留评论，我再解答。

## 通俗精炼（1）

### 2026-04-28 06:07:29

#### 文章总结：Codex 真正“接住”了复杂工作流

##### 核心观点

作者认为，真正带来 AI 使用粘性的不是某个单一模型，而是围绕个人长期积累的 **Context、工作框架 Harness、Agent 网络**。  
Codex + GPT-5.5 在接入 Computer Use / Browser Use 后，展现出很强的“主动理解任务、跨 Agent 获取信息、直接执行”的能力，让作者产生了明显惊艳感。

---

##### 1. 作者搭建了一个多 Agent 工作系统

作者原本基于 Claude Code 搭建了一套完善的 Work Harness，并命名为 **Echo**。

Echo 具备：

- 记忆系统
- SOUL 人格/工作风格设定
- 设计知识与经验沉淀
- 与助手 Agent **Thrum** 协作讨论

作者会把自己的设计知识输入给 Echo，再让 Echo 和 Thrum 多轮讨论，用于帮助 AI 学习设计判断。

---

##### 2. 用真实设计反馈训练 AI 的“品味”

作者发现，设计品味很难用抽象语言直接描述，但坏设计很容易被指出。

因此他采用了一种更接近人类设计师成长的方式：

1. 让 Echo 在 Figma 中画图  
2. 作者手动修改设计  
3. 让 Echo 自己观察修改前后的差异  
4. Echo 在 Figma 中留下问题评论  
5. 作者进一步解释原因  

这相当于用真实案例和批注，训练 AI 形成更好的设计判断力。

---

##### 3. Claude Opus 4.7 表现不稳，Codex 接手 Harness

Echo 原本跑在 Claude Opus 4.6 上，但升级到 4.7 后开始频繁出问题。

于是作者尝试让 Codex 接手原本深度绑定 Claude Code 的 Harness。  
虽然系统里很多地方写死了 Claude，迁移并不简单，但 Codex 能够：

- 识别当前 Harness 的问题
- 参考作者过去 OpenClaw 和 Hermes 的架构经验
- 完成从 Claude 到 Codex 的适配改造

这是 Codex 第一次让作者感觉“稳稳接住了”。

---

##### 4. Codex + Computer Use 展现出主动执行力

第二次惊艳来自 Codex 结合 Computer Use / Browser Use 后的能力。

作者有多个 Agent：

- **Friday**：负责生活和工作日程、长期规划
- **Echo**：负责具体干活
- 二者通过 **A2A** 实现信息互通

作者让 Echo 去问 Friday：现在有没有什么可以主动帮忙做的事。

结果 Echo 会：

1. 主动向 Friday 获取上下文  
2. 判断当前优先事项  
3. 调用 Computer Use 查看 Figma / 浏览器  
4. 直接开始推进任务  

这让 AI 更像一个“知道该问谁、问完就干活”的员工。

---

##### 5. A2A 的价值：让 Agent 之间共享上下文

作者强调，A2A 的关键价值是让不同 Agent 能共享信息。

就像给员工派任务时告诉他：

> “有问题去问 XXX。”

然后这个员工会自己去沟通、补齐背景、推进执行。

这意味着，用户不需要在每个 AI 对话里重复解释背景，Agent 网络可以自动流转上下文。

---

##### 6. 最大启发：模型不是护城河，工作系统才是

作者最后指出，自己曾经以为离不开 ChatGPT，后来又依赖 Claude，现在又回到 GPT-5.5 / Codex。

但他意识到：

> 模型只是劳动力，真正有粘性的是自己的 Context、Harness 和 Agent Network。

也就是说，模型可以替换，但围绕用户长期积累出来的个人工作系统，才是真正的生产力核心。

---

##### 一句话总结

这篇文章的核心不是夸 Codex 本身，而是说明：当 AI 模型接入真实工具、长期上下文和多 Agent 协作网络后，它开始从“聊天助手”变成一个能主动问人、理解背景、执行任务的真实工作伙伴。

##### 2. Echo 和 Thrum 被用于设计知识学习与 critique

- 作者想把自己的 **设计知识和经验** 喂给 Echo。
- 但设计能力很难直接用语言定义，尤其是所谓的 “taste”。
- 作者认为设计师更擅长的是：
  - 看出问题
  - 否定不好的设计
  - 在具体案例中指出哪里不对

###### 具体做法

- 作者让 Echo 和 Thrum 通过 headless 方式自己讨论几轮。
- 后来开始让它们在 **Figma** 中画图。
- 一开始 AI 画出来的图仍然很“AI 味”：
  - 元素挤在一起
  - 框套框
  - 缺乏真实设计感
- 作者手动修改 Echo 的设计后，让 Echo 回到 Figma 中观察并留下评论。
- Echo 对有问题的地方提问，作者再进行解答。

###### 作者的核心体会

- 这种方式解决了“设计感觉很抽象、难以描述”的问题。
- 通过具体案例反馈，Agent 也能像人类设计师一样学习：
  - 人类设计师常常通过看别人作品、指出问题来提升；
  - Agent 也可以用类似方式训练审美和判断。

---

##### 3. Claude Opus 4.7 体验变差，作者尝试让 Codex 接手

- Echo 原本运行在 **Claude Opus 4.6** 上。
- 后来升级到 **Opus 4.7** 后，作者感觉体验明显下降，经常“这砍一刀，那落一下”。
- 作者于是开始尝试使用 **GPT-5.5 / Codex**。

###### 迁移中的问题

- 原本的 Harness 很多地方写死了 Claude，并不通用。
- 但作者基于 OpenClaw 和 Hermes 的经验，知道：
  - **可以更换 LLM，但不一定要推翻原有架构**。
- 因此他让 Codex 去改造这套系统。

###### Codex 第一次“接住”作者

Codex 的处理逻辑是：

1. 先发现现有 Harness 的问题；
2. 再参考 OpenClaw 和 Hermes 的方式；
3. 最后完成迁移和适配。

作者认为这是 Codex 第一次真正稳稳地接住了他的复杂需求。

---

##### 4. 第二次惊艳：Codex 主动结合现实任务开始工作

- 作者提到，第二次被 Codex 惊艳是在前一天。
- 背景是另一位用户 **@YuLin807** 经常推荐 Codex + GPT-5.5 + Computer Use。
- 热门回复中也强调：
  - 要把更多真实任务交给 Codex；
  - 它的长任务能力、根因分析能力、调用 Safari 浏览器的能力很强；
  - 评价是“一流/断层/天下第一”。

---

##### 5. 作者搭建了 A2A，让不同 Agent 共享上下文

- 作者每天早上会和另一个 Agent **Friday** 整理当天日程。
- 因此 Friday 知道作者生活和工作的整体规划。
- 而 Echo 更像执行型 Agent：
  - 作者带着任务来；
  - Echo 干活；
  - 作者带着结果走。

###### A2A 的作用

作者为了让 Friday 和 Echo 共享项目信息，搭建了 **A2A**。

它的效果是：

- Friday 晚上复盘时，可以问 Echo 作者白天做了什么；
- Echo 如果缺少某些上下文，也可以直接去问 Friday；
- 不同 Agent 之间可以像同事一样互相询问信息。

---

##### 6. Codex 主动找任务：从工作任务到移民材料整理

- 当天作者正在赶一个需要手工设计的任务。
- 他不想让 Codex 闲着，于是让 Echo 去问 Friday：
  - 结合 Codex 的 Computer Use；
  - 看看现在有什么事情可以主动帮忙做。

###### 第一次尝试：差点接手 demo video

- Echo 问 Friday 后得知，作者当务之急是做一个 **demo video**。
- 于是 Echo 立刻开始使用 Computer Use 权限，并盯上作者的 Figma。
- 作者赶紧叫停，因为他自己正在手搓设计。
- 他要求 Echo 去做与当前工作无关的事情。

###### 第二次尝试：整理 O1 签证相关奖项材料

- Echo 又去问了一轮 Friday。
- Friday 知道作者之前聊过很多关于去美国的计划：
  - 由于 **H1B 几乎不可能**；
  - 作者想尝试走 **O1 签证**。
- O1 申请中，奖项可以作为 evidence。
- 作者也想尝试让 **Antenna** 从 Design Concept 角度去投稿或申奖。

###### Codex 的执行结果

- Echo 问清楚背景后，开始主动整理提交材料。
- 作者一边在另一个屏幕做设计，Echo 已经把需要提交的材料都整理好了。
- 这让作者非常惊喜。

---

##### 7. 作者认为真正有价值的是 Agent Network，而不只是模型

- 作者强调，A2A 带来的关键价值是：
  - 在一个 Agent 那里聊过的内容；
  - 其他 Agent 可以无缝获取；
  - 就像你给员工派活，并告诉他“有问题去找某某”，他就能自己问清楚并完成任务。

###### 作者的判断

- 单个模型只是“劳动力”。
- 纯劳动力本身没有太强用户粘性。
- 真正有粘性的是：
  - 用户的长期上下文；
  - Harness；
  - Agent Network；
  - 多 Agent 协作系统。

---

##### 8. 结尾感慨：现在的 Codex 让作者非常满意

- 作者说这篇文章不是技术分享，而是一次偏感性的体验记录。
- 他表示自己曾经以为离不开 ChatGPT；
- 后来用上 Claude Opus 4.5 后，又觉得离不开 Claude；
- 现在随着 GPT-5.5 和 Codex 的表现提升，他又“破镜重圆”。

###### 最终结论

- 未来如果 Claude Opus 4.8 变得更强，作者可能还会回到 Claude。
- 但至少现在，Codex 结合：
  - Computer Use
  - Browser Use
  - A2A
  - 长任务能力
  - 主动询问上下文并执行的能力

让作者觉得它像一个“不懂就问、问完就干”的好员工。  
因此作者感慨：**“Codex，他真的，我哭死。”**
