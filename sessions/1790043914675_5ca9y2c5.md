## 分析要点

- **核心高价值点**：将模型输出的局部条件概率固化为显式图模型，可以在不追加模型调用的情况下处理多种新证据与查询，但推理可信度仍取决于图结构和概率参数的质量。
- **留存建议**：保留建模流程与实验限制，作为概率推理系统的原型设计参考（提供了模型生成局部概率、图模型复用推理的明确流程，以及结构生成方法和评估注意事项，具有可复用的技术设计价值。）

**知识要点**

- 贝叶斯网络利用条件依赖结构分解联合分布；文中的八个二元变量对应256种联合赋值，却只需18行条件概率表进行表示。
- 可将每个父节点赋值组合转写为一个概率问题，批量生成条件概率表，再交由传统图模型引擎计算后验，实现知识获取与推理计算的分工。
- 结构生成可先询问变量对之间的两个方向及无直接边的概率，再结合无环约束和稀疏惩罚选择图；熟悉基准和事后选择惩罚参数会限制评估结论。

**行动项**

- 按文中流程复现八变量示例：将各行条件概率表转写为问题，生成概率后导入GTSAM，测试逐步加入证据时的后验变化。
- 在模型不熟悉的网络上评估结构恢复和概率校准，并检验参数误差对最终推理结果的影响。
- 复现结构搜索时预先确定边惩罚的选择规则，避免依据参考图调参后再将恢复结果当作泛化证据。

### Jev + 图形模型：一次范式转变？

Jev + 图形模型是否会从根本上改变我们构建在不确定性下进行推理的系统的方式？除非你这周与世隔绝，否则你现在应该知道，

[Jev](https://typesafe.ai/blog/introducing-system-one-models-and-jev) 是

[@typesafeai](https://x.com/@typesafeai)

用于结构化决策的新模型：给它一个问题以及一组可能的结果，它就会返回这些结果的概率。这种能力与图形模型（我的专长领域！）相结合，在我看来可能具有革命性。

[GTSAM](https://gtsam.org/)

[离散](https://borglab.github.io/gtsam/discrete/)

[混合](https://borglab.github.io/gtsam/hybrid/)

[求解数独谜题](https://github.com/borglab/gtsam/blob/develop/gtsam_unstable/discrete/tests/testSudoku.cpp)

当我在课堂上介绍贝叶斯网络时，我通常会解释获取其条件概率表 （CPT）的三种方法：我们自己的判断、专家访谈，或从数据中估计。即使推理机制已经就绪，汇集这些知识也可能是一项艰巨的任务。

在 Astra 的一些帮助下，我使用 Jev+GTSAM 进行了两个实验，我觉得非常酷！ 而且它们总共只花了我 0.03 美分！ 在第一个实验中， 一个 Jev 请求为我提供了一个八变量网络中的每个条件概率表。然后 GTSAM 使用这些表来回答新的证据查询。在第二个实验中，我使用 Jev 来阐明贝叶斯网络拓扑本身：它根据变量描述提出了关系，并且非常接近我使用的示例。两个实验都是零样本的：它们利用模型中已有的知识，无需专家访谈或专门的训练数据集。

A quick AI-assisted literature search also turned up quite some prior work on using language models to build probabilistic models. I’ve collected some papers at the end, but should note I have not (yet) read them carefully - and this is not quite my home turf.

#### Bayesian Networks

![Image](https://pbs.twimg.com/media/HSswpq4WcAAiE3F?format=jpg&name=large)

Figure 1. A Bayes network and one CPT. The arrows specify the dependencies, while CPTs specify a conditional probability distribution for each parent assignment. A CPT can also be seen as a factor in factor graph, which is how GTSAM treats them. In my first experiment, Jev supplies the probabilities for the classic Asia/Chest Clinic graph.

A

[贝叶斯网络](https://borglab.github.io/gtsam/discretebayesnet/)通过局部依赖图表示不确定量。我将使用经典的亚洲/胸科诊所网络（

[Lauritzen &amp; Spiegelhalter, 1988](https://doi.org/10.1111/j.2517-6161.1988.tb01721.x)

），这是一个历史性的（且刻意过度简化的）基准，包含八个变量，涵盖旅行史、吸烟、疾病和症状。每个变量都是二元的：真或假。箭头标识了一个父节点，其值是子节点条件概率表的输入。

> [GTSAM's own example](https://borglab.github.io/gtsam/discretebayesnetexample)

条件概率表（CPT）为变量的父节点每一种赋值给出一个分布。对于 tuberculosis，该图只使用一个父节点：患者是否去过 Asia。因此该表有两行。在没有去过 Asia 的情况下，Jev 表为 tuberculosis 不存在的概率分配 97%，存在的概率分配 3%。去过 Asia 则分别为 68%和 32%。每一行之和为 1。

将所有局部 CPT 相乘，就在本例中定义了覆盖全部 256 种二元赋值的联合分布 。由图引入的稀疏性让我们能够仅用 18 行 CPT 来指定该分布。依赖结构使这种紧凑表示成为可能。 推断在贝叶斯网络中让我们能够从疾病预测症状，并根据观察到的症状更新疾病概率。

#### The “Jev” opportunity

Jev 的

[Choice 界面](https://docs.typesafe.ai/primitives/choice) 正是我们想要查询每个 CPT 行所需结果概率的工具：我们定义选项，它便为每个选项返回一个概率。在这里，这些选项是 false 和 true，而每个问题都描述了一个父项赋值下的一个子变量。

![Image](https://pbs.twimg.com/media/HSswwmEXsAEjM0x?format=jpg&name=large)

Figure 2. Jev supplies eight CPTs from 18 questions in one API request. Teal shows P(true); the remainder is P(false). Each condition identifies a particular row, and the graph in Figure 1 defines the variable letters.

我使用了

[这个笔记本](https://gist.github.com/dellaert/ed9c8ed6bbfa22a4f027474b9c3e32b5)来演示这一想法：每个 CPT 行都变成一个关于子变量的语言问题 ，给定特定的父变量赋值。例如，笔记本询问在患者最近没有访问亚洲的条件下，患者是否患有结核病。共享指令指定了总体，并说明将未指定的事实视为未知。我们对每个所需的父变量赋值重复此过程。

One API request supplied all 18 CPT rows, without example tables or task-specific training data. I just provided the graph and variable descriptions; Jev supplied the numbers. That is zero-shot CPT generation for the entire network.

![Image](https://pbs.twimg.com/media/HSssm2jW8AAjtOp?format=jpg&name=large)

Figure 3. Add no Asia visit, then an abnormal X-ray, then shortness of breath. Each row accumulates the listed observations. The three disease columns share the same 0–50% scale; other variables remain unknown and are summed over.

The graph computes these joint evidence updates from local distributions, without sending the combined questions to Jev. In my case, I used GTSAM with Jev’s tables to compute new posteriors - without any further model calls! The same tables support a whole family of queries.

例如，在亚洲保持为 False 的情况下，随着我们添加异常 X 光片和呼吸急促，结核病后验概率上升 3.00% → 17.98% → 35.26%。肺癌从 2.40% → 14.38% → 28.39%，支气管炎从 17.80% → 21.47% → 40.21%。这并非新事物：贝叶斯网络中的推断已经非常成熟。

新的是什么（尽管参见末尾的相关工作），以及一个潜在的范式转变，是将 Jev 的预训练知识转化为图形模型中显式、可重用的组件。

#### Can Jev give us the Bayes Net itself?

是的！！！Jev 还可以提出图本身：在第二个实验中，我只提供了变量含义，并询问了所有 28 个无序对，同样是在一个 API 请求中。每个问题现在提供了三种可能性：任一方向的边，或没有直接边。因此，提示要求 Jev 考虑由其他变量介导的关系。然后我将这些答案组合成一个无环图，对其对数概率进行评分，并对每条边施加惩罚以倾向于稀疏结构。

![Image](https://pbs.twimg.com/media/HSss27wXAAEseOn?format=jpg&name=large)

图 4。恢复的图包含 11 条边：全部八个参考方向以及三条额外边，没有缺失或反向的边。即 72.7%的有向精确率和 100%的召回率 。橙色虚线边标记了额外的依赖关系。

The figure above shows the result: Compared to the Asia network, Jev wants to add three extra edges, connecting diseases directly to symptoms that the reference graph reaches through “either disease.” They are lung cancer → abnormal X-ray, tuberculosis → abnormal X-ray, and tuberculosis → shortness of breath.

[该 notebook](https://gist.github.com/dellaert/ed9c8ed6bbfa22a4f027474b9c3e32b5) 的穷举图搜索具有阶乘复杂度，但机器学习提供了大量关于更具可扩展性替代方案的文献。不过，对于八个变量，检查所有 8! = 40,320 种排序是相当可行的：在我的 MacBook Air 上只花了 38 毫秒 😃。

### 2026-09-30 12:19:43

语言模型能不能不只是回答问题，而是把已有知识变成一个可以反复使用的概率模型？这篇文章提出的可能性是：让语言模型提供局部知识，再让成熟的图模型负责推理。不过，这是一组令人期待的初步实验，还不是已经得到验证的范式转变。

作者使用的模型叫 Jev。它的工作方式很直接：你给出一个问题和几种可能的结果，它为每种结果返回一个概率。

这种能力为什么值得关注？因为构建概率模型时，难点往往不只是推理算法，而是获得推理所需的知识。过去，这些知识通常来自建模者的判断、专家访谈，或者专门收集的数据。即使推理工具已经准备好了，把知识整理进去，也可能是一项艰巨的任务。

作者想尝试的是：能不能让 Jev 承担一部分知识整理工作？

先看第一个实验。作者选用了一个经典的贝叶斯网络，叫作亚洲与胸科诊所网络。它是一个刻意简化的教学基准，不是真实的临床诊断模型。网络只有八个变量，涉及旅行史、吸烟、疾病和症状。每个变量都只有两种状态，比如有没有吸烟，有没有患病。

所谓贝叶斯网络，可以理解成一张描述变量之间依赖关系的图。图中的箭头说明，计算某个变量的概率时，需要考虑哪些其他变量。

但光有箭头还不够，还要给出具体数字。这些数字放在“条件概率表”里。简单说，条件概率表回答的是：在某些条件已经确定的情况下，一个结果发生的概率是多少。

比如，这个简化网络把是否去过亚洲，作为计算结核病概率的一个条件。于是就需要分别回答两个问题：去过亚洲时，患结核病的概率是多少？没去过亚洲时，又是多少？

作者把这样的表格行，逐一改写成自然语言问题。同时说明讨论的是哪类人群，并要求把没有交代的事实视为未知，而不是擅自补全。

结果，只用一次模型请求，Jev 就给出了整个网络所需的十八行条件概率。作者没有提供示例概率表，也没有为这个任务准备专门的训练数据。这就是这里所说的“零样本”：直接调用模型已经具备的知识。

接下来，真正的推理交给图模型工具 GTSAM 完成。

这一步才是实验最值得注意的地方。八个二元变量，总共有二百五十六种状态组合。但利用网络中的依赖结构，只需要十八行局部概率，就能定义这些组合的联合概率分布。也就是说，不必把每一种完整情形都单独列出来。

有了这套表格，推理工具就能不断接收新证据，更新判断，而不必再次询问 Jev。

例如，在患者没有去过亚洲的条件下，模型给出的结核病概率是百分之三。加入异常的胸部 X 光结果后，这个概率升到大约百分之十八。再加入呼吸急促，概率进一步升到大约百分之三十五。

这些数字展示的是实验模型怎样随证据更新，不代表真实患者的诊断概率。关键在于，后面这些组合问题都由图模型计算完成，没有额外调用 Jev。

所以，新的地方不是贝叶斯推理本身。贝叶斯推理早已成熟。作者看重的是：语言模型的一次判断，可以被转化为明确、可重复使用的组件，支持后续一整类问题，而不只是生成一条用完就结束的回答。

理解了概率表，再看第二个实验：如果连变量之间该怎么连接都不知道，Jev 能不能帮助提出网络结构？

这一次，作者只提供八个变量的含义，然后询问所有二十八对变量。每一对都有三种选择：从一个变量指向另一个变量，反方向连接，或者没有直接连接。

这里，“直接”很重要。两个变量可能通过第三个变量产生联系，但这不一定意味着它们之间还需要一条直接的边。

Jev 给出各个选择的概率后，作者并没有直接照单全收，而是把这些判断交给搜索程序，组合成一个没有循环的网络。搜索时还会对多出来的边施加惩罚，倾向于选择更简洁的结构。

最后得到的网络有十一条边。经典参考网络中的八条边全部被保留下来，方向也都正确，但额外增加了三条边。例如，模型建议把肺癌直接连到异常 X 光结果。在参考网络里，这种联系原本是通过一个中间变量表达的。

这个结果说明，语言模型或许能为网络结构提供有用的线索。但它也说明，找到了参考关系，不等于找到了完全正确的结构。多加连接，同样可能带来建模误差。

那么，这是不是一次范式转变？

作者认为有这个潜力，但也明确承认，现有实验还不足以支撑强结论。使用的是一个著名基准，模型可能早就接触过它。结构搜索中，对额外连接的惩罚也是经过选择的。这些条件都可能影响实验表现。

更严格的研究，需要在陌生网络上测试，还要检查概率是否校准。所谓校准，就是模型反复给出某个概率时，实际发生的频率是否与之相符。同时，还需要研究：局部概率或网络结构中的错误，会怎样影响最终推理。

作者也发现，已有多项研究探索过类似方向。因此，这并不是一个完全没有先例的想法。相关研究还提示，网络变大后，结构生成的表现可能下降；语言模型也不擅长仅凭抽象的相关性信息，可靠地完成因果推断。

最值得记住的是这种分工：让语言模型提供它从语言中学到的局部知识，再让传统图模型完成明确的概率计算。它的吸引力，在于把一次性的回答变成可复用的模型。至于模型是否可信，仍要靠独立评估，而不能只看它给出的数字是否像那么回事。
