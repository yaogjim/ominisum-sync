## 正文

**Voltex**

鲍里斯·切尔尼，Anthropic Claude Code 负责人：

你可以定义一个停止钩子，就像，如果测试不通过，继续执行。本质上，这就像是你可以让模型一直运行直到完成。

那个配置是帖子的循环 #1，直接来自构建该工具的人。每次迭代结束时，停止钩子会触发，因此直到测试和代码检查（lint）通过，工作才算完成。这是一个确定性的、零工作量的循环，大多数人都会跳过它。

Cherny 也用他自己的话描述了验证循环：对于重大变更，他的团队生成子代理以找出所有问题，其中一个检查 claude.md 合规性，一个梳理 Git 历史，一个追踪漏洞，然后还有五个子代理，它们的唯一任务是消除误报。一个全新的、上下文干净的批评者会捕捉构建者自己阐述过但被忽略的内容。

而且关于记忆循环，他说：如果你发现错误，只需告诉 Claude 将其添加到 claude.md 中，这样下次它就已经知道了。这个修正会比它发生时的会话更持久。

四个循环，没有什么奇特的。每个循环要么是几行配置，要么是一条指令。资深人士在发布上比其他人都强，因为他们同时运行这四个循环，而不是因为他们的模型更智能。

## 解读（1）

### 2026-07-03 11:55:37

#### 深度总结

这篇内容的核心不是“更强提示词”，而是：**高手用 Claude Code 提效，靠的是工程化循环，而不是模型本身更聪明。**

文中提到 4 类关键循环：

##### 1. 停止钩子循环：不通过就继续

可以配置 stop hook：

> 如果测试、lint、检查不通过，就不要停止，继续让模型修。

这相当于给 AI 加了一个自动闭环：

```text
写代码 → 跑测试/检查 → 失败 → 继续修 → 再检查 → 直到通过
```

重点是：  
**完成的标准不是“模型说完成了”，而是“测试和检查真的通过了”。**

---

##### 2. 验证循环：让多个子代理挑错

对于重大改动，团队会生成多个子代理：

- 一个检查 `claude.md` 是否合规
- 一个查看 Git 历史
- 一个追踪潜在漏洞
- 多个代理专门消除误报
- 一个“干净上下文”的批评者重新审查

核心思想是：

> 写代码的代理容易忽略自己犯过的错，所以要让新的、独立的审查者来挑毛病。

这类似工程里的 code review、测试、安全扫描，只是交给了 AI 子代理。

---

##### 3. 记忆循环：把错误写入长期规则

如果 Claude 犯了错，不只是当场纠正，而是让它：

> 把这个教训写进 `claude.md`

这样下次它就会提前知道规则，避免重复犯错。

这不是“聊天记忆”，而是**项目级知识沉淀**。

---

##### 4. 结构循环：高手强在流程，不强在魔法

作者强调：

> 资深工程师不是因为掌握了神秘提示词，而是因为他们把 AI 放进了稳定流程。

这些循环大多很简单：

- 几行配置
- 几条指令
- 一份规则文件
- 一套自动验证流程

但组合起来，效果会远高于单次对话式使用。

---

#### 深入浅出解读

普通人用 AI 写代码，像这样：

```text
我：帮我写个功能
AI：写好了
我：看起来不错，结束
```

高手用 AI 写代码，像这样：

```text
我：帮我写功能
AI：写代码
系统：跑测试
测试失败 → AI 继续修
lint 失败 → AI 继续修
安全检查失败 → AI 继续修
子代理审查 → 继续修
经验写入 claude.md
下次自动避免
```

区别在于：

| 普通用法 | 高手用法 |
|---|---|
| 靠一次回答 | 靠持续循环 |
| 相信模型自述 | 相信测试结果 |
| 错了就手动改 | 错了就沉淀规则 |
| 单一 AI 完成任务 | 多个 AI 分工检查 |
| 提示词驱动 | 工程流程驱动 |

一句话概括：

> AI 编程的关键，不是“问得多聪明”，而是“有没有让它自动验证、自动纠错、自动记住”。  

---

#### 辩证思考

##### 价值：AI 编程正在从“聊天”走向“系统”

这篇内容真正重要的地方在于，它揭示了 AI 编程的方向：

> AI 不再只是一个问答工具，而是可以变成工程流水线的一部分。

尤其是 stop hook 这种机制，本质上是在给模型加“约束”：

- 不能只生成代码
- 必须接受测试
- 不能自称完成
- 必须满足客观条件

这能显著降低 AI 的不可靠性。

---

##### 局限：循环不等于正确

不过也不能过度神化这些循环。

测试通过，不代表代码一定正确；  
lint 通过，不代表设计合理；  
多个子代理审查，也可能集体遗漏问题。

AI 循环能提高下限，但不能完全替代：

- 架构判断
- 产品理解
- 安全责任
- 边界条件设计
- 人类最终把关

所以它更适合当“自动化执行层”，而不是“最终决策者”。

---

##### 风险：循环会消耗成本，也可能陷入无效修复

评论里有人说“别把额度也循环没了”，这很现实。

如果规则写得不好，AI 可能：

- 反复修改无关代码
- 为了通过测试而硬凑
- 陷入死循环
- 消耗大量 token 和费用
- 修一个问题引入三个问题

所以循环必须有边界：

```text
最多重试次数
明确验收标准
保留人工确认点
限制修改范围
记录变更原因
```

---

#### 最精炼结论

这篇内容讲的不是 Claude Code 的某个技巧，而是一个更大的原则：

> **AI 提效的核心不是“更会提示”，而是“更会设计反馈循环”。**

真正高效的 AI 编程流程，应该包含：

1. **自动执行**
2. **自动验证**
3. **自动纠错**
4. **自动沉淀经验**
5. **必要时人工把关**

高手不是让 AI 一次做对，  
而是让 AI 在一套流程里，**不断逼近正确**。

## 结构化（1）

### 2026-07-06 00:02:17

##### 主旨概括

文章认为，Claude Code 高效产出的关键不是“神奇提示词”或更聪明的模型，而是资深工程师会在工作流中设置多个自动化循环。通过停止钩子、验证、记忆等机制，模型可以持续迭代直到任务真正完成。

##### 1. 停止钩子循环：让模型持续运行到通过检查

- Anthropic Claude Code 负责人 Boris Cherny 提到，可以定义一个“停止钩子”：
  - 如果测试没有通过，就继续执行；
  - 直到测试和代码检查（lint）都通过，任务才算完成。
- 这个机制本质上是一个确定性的自动循环：
  - 每次迭代结束时都会触发停止钩子；
  - 不需要人工反复提醒；
  - 但很多人会忽略这种简单配置。

**例子：**  
如果 Claude 修改代码后测试失败，停止钩子会让它继续修复，而不是直接结束任务。

##### 2. 验证循环：用子代理找问题、减少遗漏

- 对于重大代码变更，Cherny 的团队会生成多个子代理来审查问题。
- 不同子代理负责不同检查：
  - 一个检查是否符合 `claude.md` 规范；
  - 一个梳理 Git 历史；
  - 一个追踪潜在漏洞；
  - 另外五个子代理专门负责排除误报。
- 文章强调，新的、上下文干净的“批评者”往往能发现原构建者忽略的问题。

**核心意思：**  
不要只让一个 Claude 完成所有工作，而是让多个角色从不同角度审查结果。

##### 3. 记忆循环：把错误写入 claude.md，避免重复犯错

- Cherny 提到，如果发现 Claude 犯了错误，可以直接告诉它把修正规则写入 `claude.md`。
- 这样下次 Claude 再处理类似任务时，就会提前知道相关要求。
- 这种修正不会只停留在当前会话，而是能长期保留下来。

**例子：**  
如果 Claude 总是忘记某个项目的命名规范，就让它把规范加入 `claude.md`，之后生成代码时会自动参考。

##### 4. 四个循环的价值：结构比提示词更重要

- 文章总结说，所谓“四个循环”并不复杂：
  - 可能只是几行配置；
  - 或者是一条明确指令。
- 资深工程师之所以发布能力更强，不是因为他们拥有更强模型，而是因为他们同时运行这些循环。
- 这些循环让 Claude Code 更像一个可持续改进的工程系统，而不是一次性问答工具。

## 通俗精炼（1）

### 2026-09-18 11:01:43

#### Claude Code 的高产关键不是提示词，而是持续验证的工作流

Claude Code 负责人 Boris Cherny 认为，资深工程师效率更高，主要不是因为模型更聪明或掌握“神奇提示词”，而是建立了自动执行、验证和沉淀经验的循环，让代理持续工作到满足明确标准。

##### 用停止钩子把“完成”变成可验证条件

可配置停止钩子（stop hook）：每次模型准备结束任务时，自动检查测试和代码规范检查（lint）。若未通过，就让模型继续修复，直到全部达标。相比依赖模型自行判断“做完了”，这种机制以确定性规则控制退出，配置成本仅需几行。

##### 用独立子代理交叉审查重大改动

对于重要变更，Cherny 的团队会启动多个子代理，从不同角度检查问题：核对 `claude.md` 规范、梳理 Git 历史、追踪漏洞，并安排多个代理专门排除误报。全新上下文中的批评者不受开发过程影响，更容易发现主代理已经提到、却没有真正解决的问题。

##### 把错误写入项目记忆，避免重复踩坑

发现错误后，可以要求 Claude 将经验补充进 `claude.md`。这样修正不会随当前会话结束而消失，而会成为后续任务的长期约束。

帖子将这类方法概括为“四个循环”，但所给内容未完整展开全部类型。其核心意义是：AI 编程的产出差距更多来自工程化流程——明确验收、自动反馈、独立复核和持续记忆——而非单次提示技巧；代价则是更多代理调用可能带来额外额度和成本。
