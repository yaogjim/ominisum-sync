Enzyme 是一个 Hermes 插件和 OpenClaw 技能，它赋予代理对 Obsidian 知识库、markdown 知识库以及任何积累的文档语料库的结构化记忆。它会在对话开始前，将你的工作空间编译为一个具备 8 毫秒本地语义搜索的概念图。

每个代理会话都从头开始。RAG 嵌入并检索每个查询。记忆工具存储对话事实并运行 LLM 推理以对这些事实进行推理。两者在查询时都会消耗 token。两者都需要模型决定发起、正确构造并等待工具调用。两者从第一天起初始状态都为空。

Enzyme 是一个编译步骤。它读取你的工作区的标签、链接、文件夹和时间戳，从完整时间线生成主题问题（催化剂），并预计算每一个关系。在查询时：进行数据库查询。无 LLM 调用。无 API 调用。设备上约 8 毫秒。

```
> "Why do we keep rewriting the auth layer?"

  → reaches across the ADR from six months ago, a retro note about scope creep,
    and a journal entry connecting them — none share keywords with the query.
    A catalyst bridged them.
```

一次 `enzyme petri` 调用在会话开始时会向模型提供热门话题、主题张力以及搜索词汇，这些搜索词汇能触达用户原始词汇无法匹配的内容——相比暴力代理搜索，token 数量减少 80%。代理一进入就了解场景。

11 MB 二进制文件。23 MB 嵌入模型。在 20 秒内处理 1000 多个文档。每次查询 0 美元。

这个仓库将 enzyme 打包为 [Hermes](https://github.com/NousResearch/hermes-agent) 和 [OpenClaw](https://docs.openclaw.ai) 的插件，并带有自安装二进制引导程序。核心 CLI 为： [jshph/enzyme](https://github.com/jshph/enzyme) 。文档和架构： [enzyme.garden](https://enzyme.garden) 。

##### First session

在你的知识库目录中启动 Hermes：

```
cd ~/your-vault
hermes
```

在你的第一次会话中，enzyme 将会：

1. **初始化二进制文件** 如果 `enzyme` 不在 PATH 环境变量中 (\~38 MB 下载，需要 10-30 秒)
2. **刷新索引** 以捕获自上次会话以来的任何库变更
3. **注册工具** — 五个工具可供模型使用

直接开始说就好。当模型需要 vault 上下文时，它会自动调用 enzyme 工具——你无需专门请求它。

这是它在实际中的样子。三次交互，没有明确的工具请求：

```
You:     What's been active across my notes lately?
Hermes:  [calls enzyme_petri] Three threads are trending...
         positioning (messaging keeps shifting — "tool" → "layer" → "engine"),
         Q1-retro (two team leads flagged the same onboarding bottleneck
         independently), customer-research (three interviews last week all
         circled back to trust)...

You:     What's the throughline in those customer interviews?
Hermes:  [calls enzyme_catalyze "customer interviews trust recurring theme"]
         [reads notes/2026-03-25-sarah-call.md, notes/2026-03-27-marcus-call.md]
         All three conversations started on pricing but ended on trust.
         Sarah said "I need to know it won't break mid-quarter." Marcus
         described evaluating tools as "trying to figure out who's still
         going to be here in a year." The word "trust" doesn't appear in
         any of the transcripts — but the concern runs through all of them...

You:     Did we land on final messaging for the launch?
Hermes:  [calls enzyme_catalyze "launch messaging positioning decided"]
         [greps for "final", "approved", "go with"]
         Not yet. The March 20 strategy doc proposed "compile-time memory"
         as the anchor. The March 28 meeting notes show the team liked it
         but wanted a customer-facing version. No follow-up after that...
```

该模型构造了自己的搜索查询，将 enzyme 与 grep 结合，并读取了实际文件——所有这些都无需被告知应该使用哪些工具或如何构造查询。

该插件注册了三个生命周期钩子和五个工具。

**Hooks** run automatically:

Hook When What it does

`on_session_start` Session begins 如果二进制文件缺失则进行自举，运行 `enzyme refresh`

`pre_llm_call` First user message 使用用户的消息运行 `enzyme petri --query` ，注入相关实体和催化剂作为临时上下文

`on_session_end` Session closes normally 运行 `enzyme refresh` 以索引会话期间写入的笔记

The `pre_llm_call` hook is triggered in the first turn to initialize the model with vault context. After that, the model explicitly uses enzyme tools when it needs to go deeper — it does not run petri on every turn.

**工具** 可供模型按需调用：

Tool What it does

`enzyme_petri` Vault 概览 — 带有催化剂和活动趋势的热门实体。开放式（无查询）以获取完整图景，或输入查询以按相关性排序。

`enzyme_catalyze` 语义搜索 — 返回笔记摘录、文件路径以及促成匹配的触发因素。

`enzyme_refresh` 增量重新索引。当没有变化时，速度很快（约100毫秒）。

`enzyme_status` 文档数量，实体数量，嵌入覆盖率，API 密钥状态

`enzyme_init` 首次建立知识库。构建概念图，生成催化剂，创建嵌入向量。

工具受 `check_fn` 控制 — 在安装 enzyme 二进制文件并将其添加到 PATH 之前，对模型隐藏。

Enzyme 使用 LLM 生成催化剂。没有 API 密钥时，除了催化剂再生外，一切都能正常运行。

SKILL.md 为代理提供了完整的会话生命周期指令：

Phase What the agent does

同样的有机行为适用——代理构造自己的 Enzyme 查询，将它们与文件读取和 grep 结合，并在无需你指定工具的情况下呈现库内容。

#### 编译时语义搜索如何工作

Enzyme 是一个编译步骤。耗时工作（实体提取、催化剂生成、相似度预计算）只在初始化时执行一次，之后的所有操作都是快速查询。

**1. 结构阅读** (\~2s)。遍历语料库并提取实体——标签、链接、文件夹——并附带时间元数据，包括每个实体的出现时间、最后活跃时间，以及是否处于活跃加速或休眠状态。

**2. 嵌入** （约 5 秒）。文档被分割成片段并使用本地 ONNX 模型进行嵌入。不调用 API。数据不会离开机器。

**3. 催化剂生成** （约 10 秒）。对于每个实体，引擎会在不同时间周期中采样上下文，并生成催化剂——即用于探究内容实际主题的主题性问题。针对一个跨度为 18 个月的实体，其催化剂不会问“发生了什么？”，而是会问类似这样的问题： *“团队三次重新讨论了缓存问题——一次是作为性能修复，一次是出于成本考虑，一次是出于可靠性问题。每次调整之间有什么变化？”*

**4. 相似度预计算** (\~3s)。每个催化剂与每个块进行比较。存储最佳匹配。这就是查询速度快的原因——在查询时，无需进行向量搜索。相似度已预先计算。

随着工作区的增长，催化剂会重新生成。同一实体在六个月后会产生不同的催化剂。在总结变得陈旧的地方，问题依然鲜活。当代理将笔记写回工作区时，它会进入同一个索引——循环不断叠加。

Command Purpose

`enzyme petri` 知识库概览：带有催化剂和活动趋势的热门实体

`enzyme petri --query "..."` 同样，按与查询的相关性排序

`enzyme catalyze "query"` 语义搜索 — 返回摘录、文件路径、贡献催化剂

`enzyme init` 首次设置（约10-30秒，具体取决于库的大小）

`enzyme refresh` 增量重新索引（快速，若未改变则跳过）

#### Enzyme Skill：让 AI 代理 “读懂” 你的知识库

##### 一句话概括

`enzyme-skill`是一个给 AI 代理用的知识库增强插件：它能把你的 Obsidian 或 Markdown 文档库预处理成 “概念图 + 语义索引”，让代理在本地、低成本、极快地理解上下文，而不是每次都靠现查现算。

##### 它解决了什么问题

###### 传统方案的问题
常见的 RAG、向量检索或记忆工具，通常都有几个问题：

- 每次会话都像 “从零开始”
- 查询时要调用模型或检索工具，消耗 token
- 工具是否调用、怎么构造查询，依赖模型临场发挥
- 初始阶段没有上下文，代理容易 “看不懂全局”

###### Enzyme 的核心思路
Enzyme 不把 “理解上下文” 放在查询时，而是前置到 “编译阶段”：

- 先读取知识库里的标签、链接、文件夹、时间信息
- 生成主题问题（Catalyst，催化剂）
- 预计算内容之间的关系
- 查询时直接查本地数据库，不再调用 LLM 或外部 API

结果是：代理一进入会话，就已经对你的知识库有整体认知。

##### 核心价值

###### 1. 更快
- 本地语义搜索大约`8ms`
- 1000+ 文档可在约`20 秒`内完成处理

###### 2. 更便宜
- 查询阶段几乎零额外成本
- 相比暴力搜索，token 使用可减少约`80%`

###### 3. 更聪明
它不只找 “关键词匹配”，还能通过 “催化剂” 把分散、表面不相关的内容串起来，找到真正的主题脉络。

比如用户问：
> 为什么我们总在重写认证层？

即使相关笔记里没有相同关键词，它也可能连到：
- 半年前的架构决策记录
- 一次复盘里提到的范围蔓延
- 一篇日记里的隐性关联

##### 怎么工作

##### 编译式语义搜索流程

###### 1. 结构读取
扫描整个知识库，提取：
- 标签
- 双链 / 链接
- 文件夹
- 时间元数据

###### 2. 本地嵌入
把文档切块后，用本地 ONNX 模型做 embedding，不上传数据。

###### 3. 生成催化剂
围绕实体生成 “主题问题”，不是简单总结，而是帮助跨时间、跨文档理解问题演化。

###### 4. 预计算相似度
提前算好催化剂和内容块之间的最佳匹配，所以查询时不需要再做昂贵的向量检索。

##### 在代理里的使用方式

##### Hermes 集成
Hermes 中，Enzyme 通过插件自动接入，主要做三件事：

###### 会话开始
- 检查并安装二进制
- 刷新索引

###### 第一轮对话前
- 自动运行`enzyme petri`
- 给模型注入当前知识库里的热点、张力和搜索词汇

###### 会话结束
- 自动重新索引本次会话新增内容

也就是说，用户不需要手动说 “请调用工具”，代理会自动拿到上下文。

##### OpenClaw 集成
OpenClaw 版本已经设计完成，但作者明确说：

- 规范和说明文档已具备
- 逻辑上应可工作
- 但还没有做完整端到端验证

与 Hermes 不同，OpenClaw 没有生命周期钩子，所以更多依赖技能指令驱动，而不是自动触发。

##### 主要工具能力

###### `enzyme_petri`
给出知识库概览，展示：
- 热门主题
- 活跃趋势
- 催化剂线索

###### `enzyme_catalyze`
做深度语义搜索，返回：
- 相关摘录
- 文件路径
- 匹配背后的催化剂原因

###### `enzyme_refresh`
增量刷新索引，没变化时非常快。

###### `enzyme_status`
查看索引状态、实体数量、嵌入覆盖率、API key 状态。

###### `enzyme_init`
首次初始化知识库。

##### 产品上的亮点

##### 为什么它像 “编译器”，不是 “搜索器”
这套设计最有意思的地方在于：它把 AI 使用知识库的过程，从 “每次现搜” 变成了 “先编译、后秒查”。

这意味着：

- 更像软件工程里的预处理，而不是实时拼装
- 更适合长期积累的个人 / 团队知识库
- 更适合作为 AI 代理的 “结构化长期记忆底座”

本质上，它是在给代理补一层 “知识操作系统”。

##### 当前限制与风险

###### 1. Catalyst 生成仍依赖 LLM
虽然查询过程本地化，但催化剂生成仍需要 OpenRouter 或 OpenAI API Key；没有 Key 也能运行，只是无法再生催化剂。

###### 2. OpenClaw 集成未完全验证
包括：
- `kind:"download"`安装方式
- `always: true`的 token 成本
- clone 后目录结构兼容性

###### 3. 平台支持有限
当前主要支持：
- macOS Apple Silicon
- Linux x86_64 /arm64

##### 适合谁用

###### 最适合的场景
- Obsidian 重度用户
- 有大量 Markdown 知识沉淀的团队
- 想让 AI 代理真正理解项目历史、讨论脉络和决策背景的人

###### 不太适合的场景
- 文档很少、更新频率低的轻量用户
- 只需要简单关键词搜索的人
- 不愿引入初始化 / 索引步骤的场景

##### 总结判断

###### 这是什么
它不是一个普通搜索插件，而是一个 “让 AI 代理拥有知识库上下文感” 的基础设施。

###### 它最大的价值
不是 “查得更快”，而是让代理：
- 一开始就理解你的知识库全局
- 能跨文档、跨时间、跨语义发现关联
- 以更低 token 成本完成更像人的检索与推理

###### 一句话评价
Enzyme 的本质，是把个人 / 团队知识库从 “文档堆” 升级成 “可被 AI 理解和调用的结构化记忆层”。
