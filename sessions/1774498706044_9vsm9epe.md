## 正文

**Frad**

在公司里和同事分享了好几次，关于为什么我的 vibe coding 大家觉得又快又好，而且写的前端质量也肯起来不错的秘诀。我总结了一下，分享给大家。

第一个阶段我叫做全自动模式。先使用类似 superpowers 的工具，整体的流程其实没有什么新鲜的，先分析需求，然后写计划，最后再执行。我用的是自己魔改的版本 ，主要的区别是为了防止在每一个阶段 AI 因为幻觉可能会漏掉细节，在每个阶段都会强制启动一个 loop 去校验。 并且使用 BDD 部分替代 TDD 。[https://github.com/FradSer/dotclaude/tree/main/superpowers…](https://github.com/FradSer/dotclaude/tree/main/superpowers)

上面的阶段收完菜之后，进入第二个阶段，我叫做半自动模式。主要靠发现问题，先用 /plan 模式，然后再去执行，如此反复。

这里面有一些技巧，多使用 git commit，类似于游戏的存档保存。所以我做了 [https://git-agent.dev](https://git-agent.dev) 。  
如果有问题超过两次没有改好，有两种做法：  
1\. 让 AI 从 git 的历史记录里去查看改动了什么东西，然后让它反思为什么会出现这种情况；  
2\. 换一个新的模型，甚至新的工具。  
还有就是，多使用 N 个窗口并行地去执行任务，但是要记得靠 prompt 手动地去区分范围。我不习惯使用 git worktree ，因为同时进行 N 个任务时，使用 worktree 最后 merge 的压力很大，容易出错。类似的流程应该在第一个步骤使用 superpowers 去解决。

关于提示词的小技巧，我很赞成 Claude Code 的观点，就是使用最少的限制，充分利用工具去让它自动获取上下文。但是人为地补充一些上下文也是非常关键的。  
换到我们执行的操作来说，你可以随时打断，然后说类似于“你之前改了xxx”，或者“应该有xxx，你先看看，再执行”。  
还有一个观点就是：把 AI 当老师，多去问“你做了什么事情”、“我应该怎么做”，推荐多使用 /btw ，在必要的时候打断，修改你的任务。

happy hack😘

#### Frad 的高效 Vibe Coding 方法总结

##### 核心观点

Frad 的方法本质上不是“让 AI 一把梭”，而是把 AI 开发拆成不同阶段，并通过校验、回溯、并行和及时纠偏，提升速度与前端质量。

##### 第一阶段：全自动模式

这一阶段强调“先想清楚，再执行”：

- 先分析需求
- 再制定计划
- 最后执行开发

关键不在流程新，而在于 **每个阶段都加入强制校验 loop**，防止 AI 因为幻觉遗漏细节。  
同时，他用 **BDD 部分替代 TDD**，让开发过程更贴近真实业务行为和结果。

##### 第二阶段：半自动模式

当第一轮自动化产出完成后，进入“发现问题—规划—执行”的循环：

- 先识别问题
- 用 `/plan` 重新梳理
- 再执行修正
- 反复迭代

这意味着 AI 不只是“生成代码”，更像一个持续配合修正的开发助手。

##### 提升效果的几个关键技巧

###### 1. 多做 Git Commit，当作“存档点”

频繁提交代码，就像游戏存档。  
这样一旦出问题，可以快速回看历史，定位问题来源，也方便让 AI 基于历史记录反思。

###### 2. 同一个问题超过两次没修好，就换方法

如果 AI 连续两次都没改对，不要死磕，可以：

- 让 AI 回看 git 历史，分析自己改了什么、为什么出错
- 直接换一个模型，甚至换一个工具

核心思想是：**不要在错误路径上反复消耗。**

###### 3. 多窗口并行，但要明确任务边界

可以同时开多个窗口并行处理任务，以提升效率。  
但前提是通过 prompt 明确每个窗口的范围，避免上下文混乱。

他不太依赖 `git worktree`，因为多任务并行后合并压力大、容易出错。

##### 提示词使用原则

Frad 认为提示词不该加太多限制，而应该：

- 尽量少约束
- 更多利用工具自动获取上下文
- 但在关键时刻，人要主动补充必要背景

例如可以随时打断 AI，提醒它：

- “你之前改了 xxx”
- “这里应该有 xxx，你先检查再继续”

这能显著减少 AI 跑偏。

##### 更重要的心法：把 AI 当老师

除了让 AI 干活，还要多问它：

- 你刚刚做了什么？
- 为什么这样做？
- 如果是我，应该怎么做？

也就是说，AI 不只是执行者，还是学习对象。  
边用边学，才能真正把效率优势沉淀成自己的能力。

##### 一句话总结

Frad 的秘诀不是单纯“会用 AI”，而是建立了一套 **分阶段开发 + 强校验 + Git 回溯 + 并行协作 + 及时打断纠偏** 的工作流，所以才能做到又快又稳、前端质量也更好。
