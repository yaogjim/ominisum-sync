## 正文

**宝玉**

browser-use 团队开源了一个叫 video-use 的 Claude Code 技能，让你对着摄像头录完素材，跟 Claude Code 聊两句，就能拿到剪好的成品视频。

听起来像个噱头，但它解决的问题很实际：你录了一堆素材，里面全是“嗯”“呃”和重录的片段，传统流程是打开剪辑软件一刀一刀切。video-use 的做法是你把素材丢进文件夹，告诉 Claude：“把这些剪成一个发布视频”，它会自动裁掉口头语和空白段、调色、加字幕、甚至用 Manim 或 Remotion 生成动画叠加层，最后输出 final.mp4。

技术上有个巧妙的地方：大模型从头到尾不“看”视频。它读的是 ElevenLabs 转写出来的逐词时间戳文本，整个素材压缩成大约 12KB 的文本文件。只有在需要做判断的节点，比如不确定某个停顿该不该切，才会调用一张时间轴合成图来辅助决策。按项目作者的算法，直接把帧喂给模型要烧掉 4500 万 token，而这套方案只需要一份文本加几张图。思路跟 browser-use 做网页代理一样，给模型结构化的 DOM 而不是截图。

渲染完还有一轮自检：在每个剪切点上重新生成时间轴视图，检查画面跳变、音频爆音、字幕遮挡，通过了才给你看预览。最多自动修三轮。

项目完全开源免费，装好 ffmpeg 和 Python 依赖后把仓库软链接到 Claude Code 的技能目录就能用，不过转写部分依赖 ElevenLabs API，需要自己配 key。对于经常录屏、录教程、拍 vlog 但又嫌剪辑软件太重的人来说，可以尝试下。

项目地址：[https://github.com/browser-use/video-use…](https://github.com/browser-use/video-use)

## 通俗精炼（1）

### 2026-04-17 04:14:49

#### video-use 是什么

##### 一句话总结
`video-use` 是 browser-use 团队开源的一个 Claude Code 技能：你把拍好的原始素材放进文件夹，简单下指令，它就能自动剪出可发布的视频成品。

##### 它解决了什么问题
传统剪视频最麻烦的，不是创意，而是大量重复劳动：删“嗯”“呃”、去空白、切掉重录片段、加字幕、做基础调色。  
`video-use` 试图把这些高频、标准化的工作自动化，尤其适合录屏、教程、vlog 这类内容生产者。

##### 它是怎么做到的
它的核心思路很巧：**大模型并不直接逐帧看视频**，而是主要读取转写后的逐词时间戳文本。  
这样，原本非常昂贵的视频理解问题，被压缩成低成本的文本处理问题；只有在少数不确定的节点，才调用时间轴合成图辅助判断，大幅降低 token 消耗。

##### 它能自动做哪些事
基于素材和转写结果，它可以自动：
- 裁掉口头语和空白段
- 拼接出完整成片
- 调色
- 添加字幕
- 叠加 Manim 或 Remotion 动画
- 输出最终 `final.mp4`

##### 为什么这个方案值得关注
它的价值不只是“AI 会剪视频”，而是提供了一种更实用的产品路径：  
**先把视频转成结构化信息，再让模型做编辑决策。**  
这和 browser-use 用 DOM 而不是截图来理解网页是同一种思路，本质上是在用更高效的数据表示，降低 AI 执行复杂任务的成本。

##### 当前使用门槛
项目已经开源免费，但要真正跑起来，仍有一些技术门槛：
- 需要安装 `ffmpeg` 和 Python 依赖
- 需要接入 Claude Code 技能目录
- 转写依赖 ElevenLabs API，需要自己配置 key

##### 适合谁尝试
如果你经常做录屏、课程、演示视频，或者是轻量创作者，但又不想深度使用传统剪辑软件，这个项目很值得试。  
它未必替代专业剪辑，但很可能先替代掉大量基础剪辑工作。

## 结构化（1）

### 2026-04-17 05:44:33

#### 主旨概括

这篇内容主要介绍了 `browser-use` 团队开源的 `video-use`：一种把视频剪辑流程交给 Claude Code 自动完成的工具。它的核心价值不在“炫技”，而在于用更轻量的方式，解决了口头语删除、空白裁剪、加字幕、调色等实际剪辑痛点。

#### 1. 这个项目解决了什么问题

- 很多人录教程、录屏、拍 vlog 时，会留下大量无效片段，比如“嗯”“呃”、停顿、重录内容。
- 传统处理方式通常要手动打开剪辑软件，一刀一刀地剪，流程繁琐、费时间。
- `video-use` 的思路是：用户只要把素材放进文件夹，然后告诉 Claude Code “把这些剪成一个发布视频”，工具就会自动完成主要剪辑工作。
- 它能做的事情包括：
  - 自动裁掉口头语和空白段
  - 调色
  - 添加字幕
  - 用 `Manim` 或 `Remotion` 生成动画叠加层
  - 最终输出成品 `final.mp4`

#### 2. 它的关键技术思路是什么

- 这个项目最巧妙的地方在于：**大模型并不是从头到尾直接“看视频”**。
- 它主要读取的是 `ElevenLabs` 转写出来的**逐词时间戳文本**，把整段视频素材压缩成大约 **12KB** 的文本文件。
- 只有在少数需要判断的节点，比如某个停顿到底该不该剪掉时，才会额外调用一张**时间轴合成图**来辅助决策。
- 这样做的好处是极大节省模型消耗：
  - 如果直接把视频帧喂给模型，按项目作者算法，要消耗大约 **4500 万 token**
  - 而这套方案只需要**一份文本 + 几张图片**
- 文章把这种思路类比为 `browser-use` 处理网页的方式：  
  - 不是给模型看网页截图  
  - 而是给模型看结构化的 `DOM` 信息  
- 通俗地说，就是**先把视频变成模型更容易理解、也更便宜处理的结构化信息**，而不是让模型硬啃原始画面。

#### 3. 它如何保证剪辑结果可用

- 视频渲染完成后，系统还会进行一轮**自动自检**。
- 它会在每个剪切点重新生成时间轴视图，重点检查：
  - 画面是否跳变明显
  - 音频是否出现爆音
  - 字幕是否遮挡内容
- 如果发现问题，会自动继续修正，**最多可自动修 3 轮**。
- 这意味着它不是“剪完就结束”，而是加入了一层质量检查流程，尽量避免成片出现明显瑕疵。

#### 4. 使用门槛和适合人群

- 这个项目是**完全开源免费**的。
- 想使用的话，需要先安装：
  - `ffmpeg`
  - Python 相关依赖
- 然后把仓库软链接到 Claude Code 的技能目录即可运行。
- 需要注意的是，转写功能依赖 `ElevenLabs API`，所以用户需要自己配置 `key`。
- 文章认为，它比较适合这类人：
  - 经常录屏的人
  - 做教程视频的人
  - 拍 vlog 的人
  - 觉得传统剪辑软件太重、太复杂的人

#### 5. 文中的评价与补充观点

- 作者认为，这个项目虽然听上去像“噱头”，但实际上解决的是非常真实的剪辑场景问题。
- 热门回复里也有人提到：**通过音频波形图来裁剪视频是个很聪明的思路**。
- 还有评论把它看作是李沐老师当年 `AutoCut` 思路的一种 **agent 升级版**，说明它并不是凭空出现，而是在已有自动剪辑思路上做了更进一步的智能化整合。

#### 重要信息汇总

- 项目名：`video-use`
- 开源地址：`https://github.com/browser-use/video-use`
- 核心输入：`ElevenLabs` 转写的逐词时间戳文本
- 文本压缩规模：约 **12KB**
- 若直接喂视频帧给模型：约需 **4500 万 token**
- 自动修复上限：**最多 3 轮**
- 输出结果：`final.mp4`
