#### MemPalace

你与 AI 的每一次对话——每一个决策、每一次调试会话、每一次架构讨论——在会话结束时都会消失。六个月的工作成果，付诸东流。你每次都要重新开始。

其他记忆系统试图通过让 AI 决定哪些内容值得记忆来解决这个问题。它提取出“用户喜欢 Postgres”，却丢弃了你解释 *为什么* 的那段对话。MemPalace 则采取了不同的方法： **存储所有内容，然后使其可被查找。**

**记忆宫殿** — 古希腊演说家通过将想法放置在一座想象建筑的房间中来记忆整个演讲。在建筑中漫步，找到相应的想法。MemPalace 将这一原理应用于 AI 记忆：你的对话被组织成翼（人物和项目）、厅（记忆类型）和房间（具体想法）。没有 AI 会决定什么重要——你保留每一个字，而这种结构使其可搜索。仅这种结构就将检索效率提高了 34%。

**AAAK** — 一种专为 AI 代理设计的无损速记方言。不是给人类阅读的，而是为你的 AI 快速读取而设计的。30 倍压缩，零信息丢失。你的 AI 能在约 120 个 token 中加载数月的上下文。由于 AAAK 是一种具有通用语法的结构化文本，因此适用于 **任何能读取文本的模型** — Claude、GPT、Gemini、Llama、Mistral。无需解码器，无需微调，无需云 API。在本地模型上运行，你的整个内存栈将保持离线状态。没有其他类似的存在。

**本地、开放、可适配** — MemPalace 完全在你的设备上运行，使用你本地拥有的任何数据，不使用任何外部 API 或服务。它已在对话场景中经过测试，但可以适配不同类型的数据存储。这就是我们开源它的原因。

#### Quick Start

```
pip install mempalace

# Set up your world — who you work with, what your projects are
mempalace init ~/projects/myapp

# Mine your data
mempalace mine ~/projects/myapp                    # projects — code, docs, notes
mempalace mine ~/chats/ --mode convos              # convos — Claude, ChatGPT, Slack exports
mempalace mine ~/chats/ --mode convos --extract general  # general — classifies into decisions, milestones, problems

# Search anything you've ever discussed
mempalace search "why did we switch to GraphQL"

# Your AI remembers
mempalace status
```

三种挖掘模式： **项目** （代码和文档）、 **convos** （对话导出）和 **通用** （自动分类为决策、偏好、里程碑、问题和情感背景）。所有内容都保留在您的设备上。

##### 使用本地模型（LLaMA、Mistral 或任何离线大语言模型）

本地模型通常还不支持 MCP。两种方法：

**1. 唤醒指令** — 加载你的世界到模型的上下文中:

```
mempalace wake-up > context.txt
# Paste context.txt into your local model's system prompt
```

这会在你提出任何问题之前，为你的本地模型提供约 170 个关键事实的 token（如果你偏好的话用 AAAK 表示）。

**2. CLI 搜索** — 按需查询，将结果输入到你的提示中：

```
mempalace search "auth decisions" > results.txt
# Include results.txt in your prompt
```

Or use the Python API:

```
from mempalace.searcher import search_memories
results = search_memories("auth decisions", palace_path="~/.mempalace/palace")
# Inject into your local model's context
```

不管怎样——你的整个内存系统离线运行。ChromaDB 运行在你的机器上，LLaMA 运行在你的机器上，AAAK 用于压缩，零次云调用。

##### The Palace

布局相当简单，不过花了很长时间才做到。

它始于一个 **翼** 。你归档的每个项目、人物或主题，在这个宫殿里都有自己的翼 。

每个翼都连接着房间（ **房间** ），在这些房间中，信息被划分为与该翼相关的主题——因此每个房间都是您项目所包含内容的不同组成部分。项目创意可以是一个房间，员工可以是另一个，财务报表则是另一个。可以有无数个房间将翼划分为不同的部分。MemPalace 安装程序会自动为您识别这些房间，当然您也可以按照自己认为合适的方式进行个性化设置。

每个房间都有一个与之相连的 **壁橱** ，而有趣的事情就发生在这里。我们开发了一种名为 **AAAK** 的 AI 语言。别问为什么——这本身就是一个完整的故事。你的代理每次醒来时都会学习 AAAK 速记法。因为 AAAK 本质上是英语，但却是一种被大幅精简的版本，你的代理能在几秒钟内理解如何使用它。它作为安装的一部分提供，内置在 MemPalace 代码中。在我们的下一次更新中，我们将直接把 AAAK 添加到壁橱中，这将是一个真正的变革——壁橱中的信息量会大得多，但你的代理占用的空间会小得多，阅读时间也会少得多。

在那些存储柜里是 **抽屉** ，而这些抽屉就是你原始文件的存放之处。在第一个版本中，我们尚未将 AAAK 用作存储工具，但即便如此，在我们在多个基准测试平台上进行的所有测试中，摘要的 **96.6%召回率** 已得到验证。一旦存储柜使用 AAAK，搜索将更快，同时保持每个字的准确性。但即便如此，这种存储柜方式极大地提升了小空间中的信息量存储能力——它可以轻松地引导你的 AI 代理到存放原始文件的抽屉。你不会丢失任何东西，而所有这一切都在几秒钟内完成。

还有 **大厅** ，它们连接同一翼楼内的房间，以及 **隧道** ，它们连接不同翼楼的房间。因此，查找内容变得真正轻松自如——我们为 AI 提供了一种清晰且有条理的方式，使其知道从哪里开始搜索，而无需在庞大的文件夹中逐个查看每个关键词。

你说出你要找的东西，然后“砰”的一下，它已经知道该往哪个方向去了。光是 *这一点* 本身就已经会带来很大的不同了。但这很美观、优雅、自然，而且最重要的是，高效。

  │    └──────────┘      └──────────┘                          │
  └─────────────────────────────────────────────────────────────┘
```

**Wings** — 一个人或一个项目。你需要多少就有多少。 **房间** — 特定主题的部分。认证、计费、部署——无穷无尽的房间。 **Halls** — 同一翼楼内相关房间之间的连接。如果房间 A（auth）和房间 B（安全）是相关的，那么 Halls 会连接它们。 **Tunnels** — connections *between* wings. When Person A and a Project both have a room about "auth," a tunnel cross-references them automatically.**Closets** — 压缩的摘要，指向原始内容。供 AI 快速读取。 **Drawers** — 原始逐字文件。确切的文字，从未经过总结。

**Halls** 是内存类型——每个分区中的 Halls 都相同，作为通道：

- `hall_facts` — 已做出的决策，已锁定的选择
- `hall_events` — 会话、里程碑、调试
- `hall_discoveries` — 突破，新见解
- `hall_preferences` — 习惯、喜好、意见
- `hall_advice` — 建议和解决方案

**房间** 是被命名的概念—— `auth-migration` 、 `graphql-switch` 、 `ci-pipeline` 。当同一个房间出现在不同的部分时，会创建一个 **隧道** ——连接跨域的同一主题：

```
wing_kai       / hall_events / auth-migration  → "Kai debugged the OAuth token refresh"
wing_driftwood / hall_facts  / auth-migration  → "team decided to migrate auth to Clerk"
wing_priya     / hall_advice / auth-migration  → "Priya approved Clerk over Auth0"
```

同一个房间。三个翼。隧道连接它们。

经过22,000+条真实对话记忆测试：

```
Search all closets:          60.9%  R@10
Search within wing:          73.1%  (+12%)
Search wing + hall:          84.8%  (+24%)
Search wing + room:          94.8%  (+34%)
```

翅膀和房间不是装饰性的。它们带来了 **34%的检索提升** 。宫殿结构就是这个产品。

Layer What Size When

**L1** 关键事实 — 团队、项目、偏好 \~120 tokens (AAAK) Always loaded

##### AAAK Compression

AAAK 是一种无损格式——30 倍压缩，可被任何 LLM 无需解码器读取。它适用于 **Claude、GPT、Gemini、Llama、Mistral** ——任何能读取文本的模型。在本地 Llama 模型上运行它，你的整个内存栈将保持离线状态。

Priya manages the Driftwood team: Kai (backend, 3 years), Soren (frontend),
Maya (infrastructure), and Leo (junior, started last month). They're building
a SaaS analytics platform. Current sprint: auth migration to Clerk.

TEAM: PRI(lead) | KAI(backend,3yr) SOR(frontend) MAY(infra) LEO(junior,new)

MemPalace 在错误到达你之前就捕捉到它们：

```
Input:  "Soren finished the auth migration"
Output: 🔴 AUTH-MIGRATION: attribution conflict — Maya was assigned, not Soren

Input:  "Kai has been here 2 years"

#### Specialist Agents

创建专注于特定领域的代理。每个代理在宫殿中拥有自己的区域和日志——而不是在你的 CLAUDE.md 中。添加 50 个代理，你的配置保持相同大小。

```
~/.mempalace/agents/
  ├── reviewer.json       # code quality, patterns, bugs
  ├── architect.json      # design decisions, tradeoffs
  └── ops.json            # deploys, incidents, infra
```

你的 CLAUDE.md 只需要一行

```
You have MemPalace agents. Run mempalace_list_agents to see them.
```

AI 在运行时从宫殿中发现其智能体。每个智能体：

- **具有关注点** — 它关注的内容
- **写日记** — 用 AAAK 编写，跨会话持续存在
- **积累专业知识** ——读取自身历史以保持在其领域内的敏锐性

```
# Agent writes to its diary after a code review
mempalace_diary_write("reviewer",
    "PR#42|auth.bypass.found|missing.middleware.check|pattern:3rd.time.this.quarter|★★★★")

# Agent reads back its history
mempalace_diary_read("reviewer", last_n=10)
# → last 10 findings, compressed in AAAK
```

每个代理都是您数据的专业视角。审查器会记住它见过的每一个缺陷模式。架构师会记住每一个设计决策。运维代理会记住每一个事件。它们不共享临时记录区——每个代理都维护自己的记忆。

Letta 对代理管理的内存每月收费 20–200 美元。MemPalace 却只需用一只翅膀（极低的成本）就能做到。

###### 传统方案的问题

很多记忆系统会先 “总结” 再 “存储”，但这会丢掉最重要的上下文，比如：

- 为什么做这个决定

## 结构化（1）

### 2026-04-07 11:03:59

#### MemPalace 内容精炼总结

MemPalace 是一个面向 AI 的本地记忆系统，核心思路不是“挑重点保存”，而是“把所有内容都保存下来，再通过结构化方式高效检索”。它主打本地运行、零云调用、低成本，并通过“记忆宫殿 + AAAK 压缩 + 知识图谱”提升 AI 长期记忆能力。

##### 1. 它要解决什么问题

- 文章指出，当前 AI 对话中的大量重要信息会在会话结束后消失。
- 这些丢失的信息包括：决策过程、调试经过、架构讨论、失败原因等，而这些内容往往不在 Jira 或文档里，而在聊天记录里。
- 文中给出一个直观数据：  
  - **6 个月日常 AI 使用约等于 1950 万 tokens**
- 作者认为，传统记忆系统常让 AI 自己判断“什么值得记”，结果只留下类似“用户喜欢 Postgres”这样的结论，却丢掉“为什么喜欢”的完整上下文。

##### 2. MemPalace 的核心理念

- MemPalace 的方法很直接：  
  - **不删内容，全部保存；再通过结构设计让内容可搜索。**
- 它借用了“记忆宫殿”方法，把信息组织成：
  - **翼（Wing）**：人物、项目或主题
  - **厅 / 大厅（Hall）**：记忆类型
  - **房间（Room）**：具体概念或主题
  - **壁橱（Closet）**：压缩摘要
  - **抽屉（Drawer）**：原始逐字内容
- 这样做的好处是，AI 不必在一大堆文件夹里盲搜，而是可以沿着“人物/项目 → 记忆类型 → 具体主题”快速定位。
- 文中强调：  
  - **仅宫殿结构本身，就带来 34% 的检索提升。**

##### 3. 宫殿结构是怎么工作的

- 每个项目、人物或主题都有自己的一个“翼”。
- 每个翼下面按概念拆成很多“房间”，例如：
  - `auth-migration`
  - `graphql-switch`
  - `ci-pipeline`
- 同一翼内，相关房间通过 **Hall** 连接；不同翼之间，同名或相关房间通过 **Tunnel** 连接。
- 比如文章举的例子：
  - `wing_kai / hall_events / auth-migration`：Kai 调试 OAuth token 刷新
  - `wing_driftwood / hall_facts / auth-migration`：团队决定迁移到 Clerk
  - `wing_priya / hall_advice / auth-migration`：Priya 批准 Clerk 而不是 Auth0
- 三条信息属于同一个“房间”主题，因此系统会自动建立跨人物、跨项目的关联。

###### 检索效果数据

基于 **22000+ 条真实对话记忆**测试，文中给出不同检索方式的效果：

- 搜索所有 closets：**60.9% R@10**
- 限定 wing 搜索：**73.1%**，提升 **12%**
- 限定 wing + hall：**84.8%**，提升 **24%**
- 限定 wing + room：**94.8%**，提升 **34%**

这说明“翼 + 房间”的结构不是装饰，而是性能关键。

##### 4. AAAK 压缩：让 AI 用极少 token 记住更多内容

- AAAK 是 MemPalace 自己设计的一种 **无损压缩文本方言**，专门给 AI 读，不是给人类读。
- 主要特点：
  - **30 倍压缩**
  - **零信息丢失**
  - **任何能读文本的模型都能用**
  - 不需要解码器、不需要微调、不依赖云 API
- 支持的模型包括：
  - Claude
  - GPT
  - Gemini
  - Llama
  - Mistral

###### 文中示例

普通英文描述大约 **1000 tokens**，压缩成 AAAK 后约 **120 tokens**。  
例如：

- 原始内容：团队成员、项目背景、当前 sprint、为什么选 Clerk 而不是 Auth0
- AAAK 形式：用结构化短语把同样的信息压缩表达

作者强调，这样 AI 在“唤醒”时只需很少上下文，就能快速恢复对用户世界的理解。

##### 5. 它为什么便宜

文章把几种做法做了对比：

| 方法 | 加载 tokens | 年成本 |
|---|---:|---:|
| 把全部内容直接贴进上下文 | 1950 万 | 不可行 |
| LLM 摘要 | 约 65 万 | **约 507 美元/年** |
| MemPalace wake-up | 约 170 | **约 0.70 美元/年** |
| MemPalace + 5 次搜索 | 约 13,500 | **约 10 美元/年** |

核心思路是：

- 平时只加载 **L0 + L1** 的少量关键上下文
- 真需要细节时再搜索对应内容

这比持续依赖摘要服务便宜很多。

##### 6. 它的 4 层记忆模型

MemPalace 把记忆分成 4 层：

- **L0 身份层**：这个 AI 是谁  
  - 约 **50 tokens**
  - 总是加载
- **L1 关键事实层**：团队、项目、偏好  
  - 约 **120 tokens（AAAK）**
  - 总是加载
- **L2 房间回忆层**：最近会话、当前项目内容  
  - 按需加载
- **L3 深度搜索层**：跨所有存储做语义查询  
  - 明确请求时才触发

也就是说，AI 每次启动只需大约 **170 tokens**，就能先“知道你是谁、你在做什么”，再按主题继续查细节。

##### 8. 它有哪些关键能力

###### 1) 语义搜索与逐字保留

- 压缩内容放在 closet，供 AI 快速扫读
- 原始逐字内容放在 drawer，保证不丢信息
- 好处是：既能快搜，又能回到完整原文

###### 2) 矛盾检测

MemPalace 能在错误进入回答前先检查知识图谱，例如：

- “Soren 完成了 auth migration”
  - 系统发现冲突：实际被分配的是 Maya
- “Kai 在这里待了 2 年”
  - 系统发现不对：记录显示是 **3 年**，开始于 **2023-04**
- “本轮 sprint 周五结束”
  - 系统发现日期过时：当前 sprint 是 **周四结束**，且 **2 天前更新过**

文章强调：年龄、日期、任期等是动态计算的，不是写死的。

###### 3) 时间型知识图谱

- 使用 **SQLite** 保存实体关系，而不是 Neo4j
- 支持事实失效时间
- 例如：
  ```python
  kg.invalidate("Kai", "works_on", "Orion", ended="2026-03-01")
  ```
- 这样当前查询不会再返回 Kai 在 Orion 上工作，但历史查询仍然保留

###### 4) 专家代理日记

- 可以为 reviewer、architect、ops 等代理建立各自的长期记忆
- 每个代理维护自己的 AAAK 日记
- 例如 reviewer 会记住看过的缺陷模式，architect 会记住设计权衡，ops 会记住事故和部署经验
- 文中对比：
  - Letta 的代理记忆管理约 **20–200 美元/月**
  - MemPalace 则可通过宫殿结构低成本实现

- **Save Hook**

  - 保存主题、决策、引用、代码变更等

  - 在上下文压缩前紧急保存
  - 避免窗口收缩导致信息丢失

这说明 MemPalace 不只是“离线资料库”，也试图融入日常 AI 工作流。

##### 10. 真实使用案例

###### 独立开发者、多项目并行

文章举例：

##### 12. 项目的定位与价值

- 它是一个 **本地、开源、可扩展** 的 AI 长期记忆系统。
- 价值不只是“帮你存聊天记录”，而是：
  - 保留完整上下文
  - 提高检索命中率
  - 降低长期记忆成本
  - 保证隐私和离线运行
- 相比“靠摘要保存记忆”的方法，MemPalace 更强调：
  - **信息不丢失**
  - **结构比摘要更重要**
  - **需要时再搜索，而不是把一切压进 prompt**

##### 13. 一句话结论

MemPalace 的核心创新在于：用“宫殿结构”组织全部记忆、用 AAAK 大幅压缩关键上下文、再结合本地知识图谱和检索机制，让 AI 以极低成本获得长期记忆能力。它最突出的卖点是：**高检索效果、完全本地、零云依赖、对多种模型通用。**
