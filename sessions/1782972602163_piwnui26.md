## 解读（1）

### 2026-07-02 06:10:02

#### 深度总结

郭宇提出一个思路：

> 对于**闭源 / 敏感信息**，是否可以用 “本地虚拟机 + Computer Use + MCP” 来连接第一层 AI 编程 / 执行框架，如 Codex、Claude Code 等，从而兼顾**信息安全**与**顶级模型能力**。

核心问题是：

- 数据不直接上传云端，留在本地虚拟机中；
- AI 通过 “看屏幕、点鼠标、敲键盘” 的方式操作本地环境；
- 通过 MCP 等协议，把本地工具能力接入外部模型；
- 既避免敏感信息泄露，又能使用 SOTA 大模型的推理与执行能力。

热门回复提到：`openshell？`  
意思是可能已有类似方向的工具或方案。

---

#### 通俗解读

可以理解为：

> 让最强 AI 当 “远程大脑”，但让敏感数据待在 “本地保险箱” 里。

传统方式：

```text
把代码 / 文件 / 数据发给云端 AI → AI 分析 → 返回结果
```

问题是：  
闭源代码、公司文档、客户数据可能不能上传。

郭宇设想的方式：

```text
云端大模型负责思考
本地虚拟机负责保存和执行
AI 只通过受控界面操作本地环境
```

类似于：

- 人坐在安全房间里；
- AI 不能直接拿走文件；
- 但可以通过屏幕、终端、工具接口帮你操作；
- 所有敏感数据仍在本地。

---

#### 关键价值

##### 1. 信息安全

敏感数据不直接暴露给云端模型，理论上更安全。

##### 2. 能力不降级

不用完全依赖本地小模型，仍可借助 GPT、Claude、Codex 等强模型。

##### 3. 自动化效率高

AI 可以操作本地 IDE、浏览器、终端、文件系统，完成复杂任务。

##### 4. 适合闭源场景

比如：

- 私有代码库；
- 企业内部系统；
- 本地数据库；
- 安全审计；
- 自动化测试；
- 私有知识库处理。

---

#### 辩证思考

##### 可行，但不是 “天然安全”

这种方案降低了数据上传风险，但不等于没有风险。

风险包括：

- 屏幕内容可能被模型 “看到”；
- 操作日志可能泄露信息；
- Prompt 注入可能诱导 AI 读取敏感文件；
- 本地工具权限过大，可能造成误操作；
- MCP 插件链路本身也可能成为攻击面。

所以关键不是 “本地虚拟机” 本身，而是：

> 权限控制、审计机制、隔离边界、最小可见原则。

---

#### 我的判断

这是一个很有潜力的方向。

未来 AI 工具可能会分成两层：

```text
云端强模型：负责推理、规划、决策
本地安全沙箱：负责数据、执行、验证
```

真正成熟的产品形态，应该不是简单的 “AI 远程操控电脑”，而是：

- 本地沙箱隔离；
- 可回滚虚拟机快照；
- 精细权限管理；
- 敏感信息脱敏；
- 操作全程可审计；
- AI 动作需人类确认关键步骤。

---

#### 一句话结论

> “本地虚拟机 + Computer Use + MCP” 可能是闭源信息时代使用强 AI 的重要路径：既借云端大脑，也守本地数据；但安全不靠概念，靠隔离、权限和审计。

## 产品-最佳实践（1）

#### 实例：用「本地虚拟机 + Computer Use + MCP」安全分析闭源企业系统

##### 背景

假设你在一家企业内部，需要让 SOTA 模型辅助分析一个**闭源内部系统**：

> 一个只能在公司内网访问的 Windows 桌面版 ERP 客户端，包含业务数据、合同信息、供应商报价等敏感内容。

你希望 AI 能帮你完成：

- 阅读 ERP 页面内容
- 根据操作手册完成查询
- 自动点击、复制、导出报表
- 总结业务异常
- 生成代码或脚本辅助处理数据

但你不希望：

- 把 ERP 客户端直接暴露给云端模型
- 把数据库、源代码、账号密码上传到外部
- 让 AI 获得无限制的本机权限
- 让模型直接操作真实生产环境

因此可以采用：

> **本地虚拟机 + Computer Use Agent + 本地 MCP Server + 第一层 Harness，例如 Codex / Claude Code / 自研 Agent Harness**

---

#### 推荐架构

```text

│     GPT / Claude / Gemini / Qwen 等           │

                    │

└───────────────────▲──────────────────────────┘
```

#### 具体实例：让 AI 在本地 VM 中导出 ERP 销售异常报表

##### 目标任务

让 AI 帮助完成：

> 登录公司 ERP，进入「销售管理 → 订单查询」，筛选最近 30 天订单，导出金额大于 50 万且毛利率低于 5% 的订单列表，并生成一份异常原因初步分析。

---

#### 最佳实践

##### 1. 使用虚拟机隔离闭源系统

闭源 ERP 不应直接运行在宿主机，也不应暴露给云端工具。

推荐使用：

- VMware Fusion / Workstation
- Parallels Desktop
- VirtualBox
- UTM
- Hyper-V
- QEMU/KVM

###### VM 配置建议

```yaml
vm:
  os: Windows 11 Enterprise
  network: internal-only or allowlist
  clipboard: controlled
  shared_folder: read-only input, write-only output
  snapshot: enabled
  usb_passthrough: disabled
  screen_recording: enabled
```

###### 原则

| 项目 | 建议 |
|---|---|
| 网络 | 默认禁止外网，仅允许访问 ERP / 内网服务 |
| 剪贴板 | 禁止双向自动同步，改为 MCP 工具受控读取 |
| 文件共享 | 输入目录只读，输出目录单独隔离 |
| 快照 | 每次任务前创建快照，任务后可回滚 |
| 账号 | 使用低权限机器人账号，不使用个人管理员账号 |

---

##### 2. Computer Use 只操作 VM，不操作宿主机

Computer Use Agent 的鼠标、键盘、截图能力应该只绑定到虚拟机窗口。

不要让它操作：

- 宿主机桌面
- 浏览器个人账号
- 密码管理器
- 终端
- SSH 客户端
- 邮件客户端

###### 推荐方式

```text
Computer Use Agent
       │
       ▼
仅捕获和控制 VM 窗口
       │
       ▼
Windows ERP Client
```

如果工具支持区域限制，应只允许操作 VM 窗口坐标区域。

---

##### 3. 用 MCP 暴露最小工具集

不要给模型一个全能 Shell。

推荐暴露**任务相关、能力有限、可审计**的 MCP 工具。

例如：

```json
{
  "tools": [
    "vm.screenshot",
    "vm.click",
    "vm.double_click",
    "vm.type_text",
    "vm.hotkey",
    "vm.read_selected_text",
    "vm.read_clipboard",
    "vm.write_clipboard",
    "vm.export_file",
    "vm.list_output_files",
    "security.redact_text",
    "security.request_human_approval"
  ]
}
```

不建议默认暴露：

```text
shell.exec
fs.read_all
fs.write_all
network.request
browser.open_external_url
credential.read
```

除非有明确沙箱和审批机制。

---

##### 4. 对模型可见信息做分层

不要把所有截图、文本、文件原样发给云端模型。

可以分成三层：

| 层级 | 内容 | 是否可发给云端模型 |
|---|---|---|
| L0 | 密码、Token、个人身份信息、合同原文 | 不可发送 |
| L1 | 脱敏后的字段、表格摘要、统计值 | 可发送 |
| L2 | 操作步骤、按钮名称、页面结构 | 可发送 |

###### 示例

ERP 页面中原始内容：

```text
客户名称：深圳市某某科技有限公司
联系人：张三
手机号：138****1234
订单金额：¥780,000
毛利率：3.2%
```

发送给模型前应转换为：

```json
{
  "customer": "CUSTOMER_001",
  "contact": "REDACTED",
  "phone": "REDACTED",
  "amount": 780000,
  "gross_margin": 0.032
}
```

---

##### 5. 让本地 MCP Server 负责脱敏，而不是让云端模型自觉脱敏

错误做法：

> 把完整截图发给模型，然后让模型 “不要泄露敏感信息”。

正确做法：

> 本地 MCP Server 先 OCR / 解析 / 脱敏，再把结果传给模型。

流程：

```text
VM 截图
  ↓
本地 OCR
  ↓
敏感字段识别
  ↓
脱敏
  ↓
结构化 JSON
  ↓
发送给模型
```

示例 MCP 返回：

```json
{
  "page": "订单查询",
  "table": [
    {
      "order_id": "ORDER_10231",
      "customer": "CUSTOMER_001",
      "amount": 780000,
      "gross_margin": 0.032,
      "salesperson": "EMPLOYEE_014"
    },
    {
      "order_id": "ORDER_10232",
      "customer": "CUSTOMER_002",
      "amount": 920000,
      "gross_margin": 0.041,
      "salesperson": "EMPLOYEE_021"
    }
  ]
}
```

---

##### 6. 敏感操作必须 Human-in-the-loop

以下操作不要让模型自动执行：

- 登录
- 提交订单
- 删除数据
- 修改价格
- 发送邮件
- 上传文件
- 批量导出敏感数据
- 访问高权限菜单
- 执行脚本或命令

应加入人工确认工具：

```json
{
  "tool": "security.request_human_approval",
  "arguments": {
    "action": "export_erp_report",
    "reason": "需要导出最近 30 天高金额低毛利订单",
    "data_scope": "last_30_days, amount > 500000, margin < 5%"
  }
}
```

只有人工批准后，MCP Server 才允许执行下一步。

---

##### 7. 文件导出采用隔离目录

导出的 ERP 报表不应直接给模型读取完整内容。

推荐目录结构：

```text
/vm_shared/
  input_readonly/
    task_instruction.md
  output_raw/
    erp_export_2026_07_02.xlsx
  output_sanitized/
    erp_export_sanitized.json
    summary.md
  logs/
    operation_log.jsonl
```

处理流程：

```text
ERP 导出 Excel
  ↓
保存到 output_raw
  ↓
本地脚本解析 Excel
  ↓
脱敏 / 聚合
  ↓
生成 output_sanitized/*.json
  ↓
模型只读取 sanitized 结果
```

---

##### 8. Harness 层负责规划，MCP 层负责执行和约束

第一层 Harness，例如 Codex / Claude Code / 自研 Orchestrator，不应直接拥有所有权限。

推荐职责划分：

| 组件 | 职责 |
|---|---|
| SOTA 模型 | 推理、规划、解释、生成报告 |
| Harness | 管理任务流、调用 MCP、记录日志 |
| MCP Server | 暴露受限工具、权限判断、脱敏 |
| VM | 承载闭源软件和敏感数据 |
| 人类 | 审批高风险操作 |

#### 推荐 MCP 工具设计

##### `vm.screenshot`

只返回低分辨率或脱敏截图。

```json
{
  "name": "vm.screenshot",
  "description": "Capture screenshot from the isolated VM window.",
  "input_schema": {
    "type": "object",
    "properties": {
      "redact": {
        "type": "boolean",
        "default": true
      }
    }
  }
}
```

---

##### `vm.click`

限制只能点击 VM 窗口范围内。

```json
{
  "name": "vm.click",
  "description": "Click inside the VM window only.",
  "input_schema": {
    "type": "object",
    "properties": {
      "x": { "type": "integer" },
      "y": { "type": "integer" }
    },
    "required": ["x", "y"]
  }
}
```

---

##### `erp.export_filtered_orders`

比通用点击更安全的高级工具。

```json
{
  "name": "erp.export_filtered_orders",
  "description": "Export filtered order data from ERP with approval and sanitization.",
  "input_schema": {
    "type": "object",
    "properties": {
      "date_range_days": {
        "type": "integer",
        "maximum": 90
      },
      "min_amount": {
        "type": "number"
      },
      "max_gross_margin": {
        "type": "number"
      }
    },
    "required": ["date_range_days", "min_amount", "max_gross_margin"]
  }
}
```

推荐优先使用这种**领域工具**，少用裸鼠标键盘操作。

```markdown
共发现 12 笔异常订单。

- 特定区域竞争激烈

## 建议

1. 复核折扣率超过 20% 的订单审批链路
2. 检查相关产品最新成本数据
3. 对高金额低毛利订单增加二级审批
```

> **让最强模型负责推理，让本地 MCP 负责执行，让虚拟机承载敏感环境，让人工审批控制风险。**

最推荐的落地形态是：

```text
SOTA Model
  → Harness
  → Local MCP Server
  → Isolated VM
```

- 看不到不该看的
- 点不到不该点的
- 导不出不该导的
- 传不走不该传的
