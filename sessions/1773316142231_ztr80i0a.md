> **A note from the developer:** The open-source community already has many OpenClaw alternatives — some rewritten in faster languages, others easier to deploy — but most come with trade-offs: reduced features or a steeper barrier for secondary development. As heavy AI users who have tried most of the alternatives, we identified real pain points and built Aurogen as a complete reimplementation of the OpenClaw paradigm with the following characteristics.

#### ✨ Features

**🗂️ Fully Modular** — Aurogen completely modularizes, instantiates, and parallelizes every OpenClaw concept — **Agents, Channels, Providers, Skills, and more** — so you can compose and orchestrate them however you like. In Aurogen, a single deployment can run **many lobsters at once**, which is exactly what *More OpenClaws* means.

**💡 Easy Configuration** — Aurogen ditches CLI interaction and config files entirely. After installation, just open the web panel → set a password → configure your first Provider, and you're ready to go in the Web Channel. All modules are loaded dynamically, so every setting takes effect immediately — **no restart required**.

**🦀 Ecosystem Compatible** — Aurogen is fully compatible with the OpenClaw ecosystem. You can download any skill from [clawhub.ai](https://clawhub.ai/) and import it directly into Aurogen. The built-in public skills also include native ClaWHub integration.

> **Etymology:***Aurogen* = *Aurora* (dawn / aurora borealis, the Roman goddess of dawn) + *generation*. The pronunciation kind of sounds like an orange 🍊 — so come grow an orange tree full of 🍊!

##### One-click Installer

Download the package for your platform from [Releases](https://github.com/UniRound-Tec/Aurogen/releases). Each package includes Python and Node.js runtimes — no additional software installation required.

Platform Architecture File

macOS Apple Silicon (M1/M2/M3/M4) `aurogen-x.x.x-macos-arm64.tar.gz`

Linux ARM64 `aurogen-x.x.x-linux-arm64.tar.gz`

Linux x86\_64 `aurogen-x.x.x-linux-x64.tar.gz`

Windows x64 `aurogen-x.x.x-windows-x64.zip`

**macOS / Linux:**

```
tar -xzf aurogen-x.x.x-<platform>.tar.gz
cd aurogen-x.x.x-<platform>
bash start.sh
```

**Windows:** Extract the zip, then double-click `start.bat`.

Open `http://localhost:8000` in your browser. All configuration is done through the web interface.

##### Docker

Build the image:

```
docker build -t aurogen .
```

Run Aurogen with a persistent workspace:

```
docker run --rm -p 8000:8000 \
  -v "$(pwd)/aurogen/.workspace:/app/aurogen/.workspace" \
  aurogen
```

Then visit `http://localhost:8000`.

##### Docker Compose

From the project root directory:

```
docker compose up -d --build
```

##### Development Setup

**Prerequisites:**[conda](https://docs.conda.io/) (or another Python environment manager) and [Node.js](https://nodejs.org/).

From the project root directory:

**1. Start the backend:**

```
# Create the environment
conda create -n aurogen python=3.12

# Install dependencies
conda activate aurogen && cd ./aurogen && pip install -r requirements.txt

# Start the server
uvicorn app.app:app --host 0.0.0.0 --port 8000 --reload
```

**2. Start the frontend:**

```
cd ./aurogen_web && npm i
npm run dev
```

1. After deployment, open the web panel and set your password (especially useful when deploying on a cloud server / VPS):

Set Password

You will see the main dashboard:

Dashboard

Use the top-right corner to switch themes and languages:

Theme &amp; Language

1. The left sidebar contains all feature panels. First, click **Providers**:

Providers Panel

1. Edit the default Provider — fill in your API Key and Base URL, then click Save.
2. Next, click **Agent** in the sidebar:

Agent Configuration

1. Make sure the Provider is set to the one you just configured, then set the Model ID. You can choose whether to enable Thinking.
2. (Optional) Click the **Channel** panel to confirm the Web Channel is using the Agent you just configured:

Channel Configuration

1. You're all set — start chatting in the Web Channel!

Web Channel Chat

## 结构化（1）

### 2026-03-12 11:50:18

Aurogen🍊 是一个对 OpenClaw 体系进行**完整重构**的开源项目，目标是同时做到：**功能完整、部署简单、方便扩展**。  
它主打**模块化、多 Agent 并行、Web 配置、兼容 OpenClaw 生态**，适合想快速搭建和扩展 AI Agent 系统的人。

---

##### 1. 项目背景与定位
- 开发者认为，社区里已经有很多 OpenClaw 替代品，但常见问题是：
  - 要么功能缩水；
  - 要么部署和二次开发门槛高。
- Aurogen 的目标是：**完整重写 OpenClaw 模式**，尽量避免这些取舍。

---

##### 2. 核心特性
###### 2.1 全模块化
- Aurogen 把 OpenClaw 中的核心概念都做成模块，包括：
  - **Agents**
  - **Channels**
  - **Providers**
  - **Skills**
- 这些模块可以被**实例化、组合、并行运行**。
- 一个部署里可以同时运行多个 agent（原文用 “many lobsters” 形容）。

**例子：**  
你可以在同一个系统里，同时配置多个 Agent，分别接不同模型、不同任务，而不是只能跑一个固定流程。

###### 2.2 配置简单
- 不再依赖**CLI 命令行**和**配置文件**。
- 安装后只需要：
  1. 打开 Web 面板；
  2. 设置密码；
  3. 配置第一个 Provider；
  4. 就能在 Web Channel 里开始使用。
- 所有模块都是**动态加载**，改设置后**立即生效，不用重启**。

###### 2.3 生态兼容
- Aurogen 与**OpenClaw 生态完全兼容**。
- 可以直接从**clawhub.ai**下载 skill 并导入。
- 内置公共技能也支持原生 ClaWHub 集成。

## 产品-最佳实践（1）

### 2026-03-12 11:55:37

下面给你一个**基于 Aurogen 的具体实例**，并在这个实例之上提炼出一套**最佳实践（精炼版）**。

---

##### 具体实例：搭建一个 “多 Agent 客服知识助手”

###### 场景
一家小团队希望快速部署一个内部 AI 助手，用来处理：

- 产品文档问答
- 工单初筛
- FAQ 自动回复
- 复杂问题转交人工

###### 用 Aurogen 的配置方式
利用它的**模块化、多 Agent、Web 配置、动态生效**特性，设计如下：

###### 1. Provider
配置一个主模型 Provider：
- Base URL：企业已有的兼容 OpenAI API 服务
- API Key：团队统一管理

###### 2. Agents
创建 3 个 Agent：

- **Agent A：FAQ 助手**
  - 负责标准问题、常见问答
  - 关闭 Thinking，追求低成本和高响应速度

- **Agent B：知识库助手**
  - 负责文档检索、产品说明、操作指引
  - 开启 Thinking，用于稍复杂的推理

- **Agent C：升级路由助手**
  - 判断问题是否需要人工介入
  - 输出 “自动答复 / 转人工 / 需要补充信息”

###### 3. Channels
- Web Channel：给内部员工或客服直接使用
- 后续可以扩展更多 Channel，复用同一套 Agent 体系

###### 4. Skills
从兼容生态中导入：
- FAQ 查询技能
- 工单总结技能
- 知识库搜索技能

---

#### 在这个实例上的最佳实践

##### 1）按职责拆 Agent，不要一个 Agent 包打天下
**最佳实践：**
将 “问答、检索、路由” 拆成不同 Agent。

**原因：**
Aurogen 的优势就在于模块化和多 Agent 并行 / 组合。  
如果所有任务都堆到一个 Agent：
- Prompt 会越来越臃肿
- 调试困难
- 成本更高
- 结果稳定性更差

**建议：**
先拆成最小可用的 2～3 个角色，再逐步扩展。

---

##### 2）把 “快响应” 和 “强推理” 分层配置
**最佳实践：**
- 高频简单任务 → 便宜、快的模型，关闭 Thinking
- 复杂分析任务 → 更强模型，按需开启 Thinking

**原因：**
Aurogen 支持 Agent 级配置，这正适合做成本 / 性能分层。  
不要所有 Agent 都用最高配置。

**建议：**
优先优化 80% 的常见请求，把高成本能力留给少数复杂场景。

---

##### 3）优先通过 Web 面板迭代配置，而不是频繁改代码
**最佳实践：**
先用 Web 面板完成：
- Provider 配置
- Agent 绑定
- Model ID 调整
- Channel 关联

**原因：**
Aurogen 的一大优势就是**动态加载、配置即时生效、无需重启**。  
这非常适合业务快速试错。

**建议：**
只有当流程稳定后，再考虑沉淀成标准化部署文档或自动化脚本。

---

##### 4）先从单一 Channel 跑通，再扩展多入口
**最佳实践：**
第一阶段只启用 Web Channel 验证全链路。

**原因：**
多 Channel 虽然是 Aurogen 的强项，但早期同时铺开会增加排障复杂度。  
应先验证：
- Provider 是否稳定
- Agent 分工是否合理
- Skills 是否可用
- 输出质量是否达标

**建议：**
遵循 “单 Channel 成功 → 多 Channel 复制” 的路线。

---

##### 5）使用兼容生态时，先做 Skill 白名单管理
**最佳实践：**
从 clawhub.ai 导入 Skill 后，不要直接全量开放，先建立白名单。

**原因：**
生态兼容是优点，但外部 Skill 的质量、权限范围、输出格式可能不一致。  
尤其在客服 / 企业场景中，技能失控会影响稳定性。

**建议：**
每个导入 Skill 都做 3 件事：
- 明确用途
- 小范围测试
- 指定可调用 Agent

---

##### 6）生产环境一定先做密码和工作区持久化
**最佳实践：**
部署后第一件事：
- 设置 Web 面板密码
- 持久化`.workspace`

**原因：**
Aurogen 默认通过 Web 管理，若部署到 VPS / 云服务器，不做安全和持久化会有明显风险。

**建议：**
Docker 运行时务必挂载持久卷，例如：
- 配置持久化
- 导入技能持久化
- 历史状态保留

---

##### 7）把 “默认 Provider” 当作模板，不要直接长期裸用
**最佳实践：**
编辑默认 Provider 后，尽快按用途复制出多个 Provider 配置，例如：
- 通用对话 Provider
- 高质量推理 Provider
- 低成本 Provider

**原因：**
这样后续 Agent 调优时更灵活，也方便切换底层模型供应商。

**建议：**
命名规范统一，例如：
- `provider_fast`
- `provider_reasoning`
- `provider_backup`

---

##### 8）先建立最小闭环，再追求多实例与复杂编排
**最佳实践：**
第一版目标只做：
“用户提问 → Agent 处理 → 返回答案”

不要一上来就追求：
- 多实例并发编排
- 复杂子 Agent 树
- 大量 Skill 串联

**原因：**
Aurogen 功能很多，但最佳落地方式是先做可验证闭环。  
复杂编排应建立在稳定基线上。
