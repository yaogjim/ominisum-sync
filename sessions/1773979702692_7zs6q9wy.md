## 解读（1）

### 2026-03-20 06:25:02

#### 总结

这段内容的核心观点是：

- **开源代码已经不稀奇，真正稀缺的是“判断力”的开源。**
- 过去很多人在教 AI **怎么完成任务**，而 Garry Tan 这类做法是在教 AI **怎么思考、怎么做决策**。
- 一个普通 `skill` 只是提升某个具体环节；而一套好的认知框架，能提升**所有决策质量**，价值更大。
- 作者亲身体验后发现，这种 AI 不只是“帮你改代码”，而是在像 CEO 一样反问：**这件事到底值不值得做？**
- 因此，`skill` 不只是给人用的工作流，更像是 **AI agent 的应用模块**，而且未来还可能具备**自我迭代、自我进化**能力。

#### 解读

##### 1. 这篇内容真正想强调什么？

表面上在说 `skill`，本质上在说：

> **AI 的上限，不只是执行能力，而是判断能力。**

以前大家对 AI 的期待，多半是：

- 写代码
- 改 Bug
- 生成文案
- 自动化流程

这些都属于“做事”。

但 Garry Tan 这类方法更进一步，关注的是：

- 这个问题是否值得解决？
- 优先级怎么排？
- 如果不做，会怎样？
- 有没有更简单的路径？
- 这个方向是不是伪需求？

这已经不是“干活”了，而是“做判断”。

##### 2. 为什么说“开源判断力”更厉害？

因为代码可以复制，但**判断标准**很难复制。

比如一个高手厉害，不一定是因为他会写某段代码，而是因为他知道：

- 什么该做，什么不该做
- 什么先做，什么后做
- 哪些是关键问题，哪些只是噪音
- 怎样避免把时间浪费在错误方向上

如果这些思考框架被写成 prompt 或 skill，相当于把一个人的经验、视角、方法论“打包”给 AI。这样 AI 就不是工具，而更像一个有经验的顾问。

##### 3. 为什么这比单个 skill 更有价值？

文中有一句话很关键：

- **一个 skill 解决一个任务，是线性的**
- **一个 skill 让每个决策都变好，是指数的**

意思很简单：

- 普通 skill：帮你省一次力
- 判断型 skill：帮你持续少走弯路

前者提升效率，后者提升方向感。

而现实里，很多失败并不是因为执行差，而是因为：

- 选错问题
- 判断失误
- 方向偏了
- 做了很多“无效努力”

所以，能提升判断质量的 AI，长期价值往往比“多快好省地干活”更大。

##### 4. “这不是 code review，这是 CEO 在 challenge 你”是什么意思？

这句话很有画面感。

普通 code review 往往关注：

- 语法对不对
- 逻辑有没有 bug
- 性能是否优化
- 风格是否一致

但“CEO 式 review”会追问更上层的问题：

- 你为什么要做这个脚本？
- 它真的在解决核心问题吗？
- 有没有更便宜、更稳的办法？
- 如果这个系统今天停了，损失到底多大？
- 你是在修问题，还是在制造复杂度？

这说明 AI 从“技术审查”升级成了“业务和战略层面的挑战者”。

##### 5. 为什么说 Skill 是 AI agent 自己的 App？

这个比喻很形象。

过去 App 是给人点的，Skill 更像是给 AI 调用的“能力插件”。

也就是说：

- 人不必亲自操作每一步
- AI agent 会根据任务自己选择 skill
- skill 不只是执行，还能联动、组合、迭代

文中提到：

- 先审查脚本
- 找出 6 个 bug
- 再触发 self-improvement skill 继续优化

这就说明 Skill 不再只是静态工具，而是在往“自主协作的能力系统”走。

#### 我的意见

我认同这段内容的判断，而且我觉得它点出了 AI 应用的一个关键趋势：

- **短期看，AI 拼的是功能**
- **中期看，AI 拼的是工作流**
- **长期看，AI 拼的是判断模型和认知框架**

不过也要注意两点：

- **判断力不等于权威感。** AI 很会“说得像有道理”，但不代表判断一定对。
- **认知框架有价值，但不能迷信。** YC、Bezos、Munger、Jobs 的思路很强，但也有适用边界，不是所有场景都能直接套。

所以我更建议把这类 skill 当成：

> **高质量“思考陪练”**，而不是绝对正确的“最终裁判”。

如果用得好，它最有价值的地方不是替你做决定，而是逼你回答那些你原本不会主动问自己的关键问题。

一句话说：

> **真正高级的 AI，不是帮你把事情做完，而是帮你先想明白什么事情值得做。**
