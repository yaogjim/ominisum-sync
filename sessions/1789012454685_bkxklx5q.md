CAE Agent Hub 是一个面向主流工程仿真软件的 MCP server、Agent Skill、求解器自动化脚本和浏览器结果查看器集合。目标是让 Codex、Cursor、Claude Code、Claude Desktop 等 AI 客户端连接真实 CAE 软件，而不是只生成离线示例。

当前仓库包含：

- Abaqus/CAE、ANSYS Fluent、ANSYS Workbench Mechanical、Ansys Electronics Desktop / HFSS 的 MCP server。
- 按工作流阶段组织的 Abaqus 有限元 skill。
- 原 Text to CAE 浏览器 viewer，用于查看导出的 `result_mesh.json` 仿真结果。
- 示例工作流和模板；求解器二进制文件、许可证、私有路径和生成结果不进入源码仓库。

#### 仓库地址

```
https://github.com/Cai-aa/CAE-Agent-Hub
```

部分示例目录仍保留旧名称 `text-to-cae` ，用于兼容已有 viewer 案例。

#### 架构

```
AI client
  -> MCP server 或 skill instruction
  -> 正在运行的 CAE 应用或求解器脚本
  -> 原生求解结果
  -> 轻量 viewer 数据
  -> 浏览器检查或报告工作流
```

职责划分：

- **MCP servers** ：给 AI 客户端提供真实 CAE 软件的 live tool access。
- **Skills** ：提供可复用的建模、设置、求解、后处理和验证指令。
- **CAE applications** ：执行真实求解。
- **Viewer modules** ：在不打开求解器的情况下查看导出的结果数据。

#### 安装

##### 克隆仓库

```
git clone https://github.com/Cai-aa/CAE-Agent-Hub.git
Set-Location .\CAE-Agent-Hub
```

如果你之前克隆的是旧仓库名，GitHub redirect 通常仍然可用，但建议更新 remote：

```
git remote set-url origin https://github.com/Cai-aa/CAE-Agent-Hub.git
```

每个 MCP 目录都有自己的 README 和环境变量模板。通用本地安装方式：

```
Set-Location ".\MCP\<vendor>\<server folder>"
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -U pip
.\.venv\Scripts\python.exe -m pip install -e .
```

然后根据该 MCP 目录中的示例配置，把 server 注册到支持 MCP 的客户端。

##### 使用 skills

Skill 是 instruction module，不是求解器二进制文件。请复制完整 skill 目录到 agent 的 skill 目录，或把相关 `SKILL.md` 作为项目上下文。

Codex 示例：

```
New-Item -ItemType Directory -Force -Path "$env:USERPROFILE\.codex\skills" | Out-Null
Copy-Item -Recurse -Force ".\Skill\abaqus\analysis\abaqus-static-analysis" "$env:USERPROFILE\.codex\skills\abaqus-static-analysis"
```

示例提示词：

```
Use the abaqus-static-analysis, abaqus-mesh, abaqus-job, and abaqus-odb skills. Build a complete Abaqus static-analysis workflow, run it if the Abaqus MCP or local Abaqus CLI is available, and report the exact files and commands used.
```

Viewer 仍作为浏览器结果检查层保留。只要案例包含 `result_mesh.json` ，即使没有安装求解器也可以查看。

```
Set-Location .\viewer
npm.cmd install
npm.cmd run dev
```

#### CAE Agent Hub：让 AI 真正操作工程仿真软件

##### 一句话概括

CAE Agent Hub 是一个面向计算机辅助工程（CAE）的开源集成平台，通过**MCP Server、Agent Skills、自动化脚本和浏览器 Viewer**，让 Codex、Cursor、Claude Code 等 AI 客户端直接连接并操作真实仿真软件，而不只是生成示例代码。

##### 核心架构

整体工作流为：

> AI 客户端 → MCP / Skill → CAE 软件或求解器 → 原生计算结果 → 轻量结果数据 → 浏览器查看或报告

各模块职责明确：

- **MCP Server**：为 AI 提供实时软件操作能力。
- **Agent Skill**：沉淀建模、求解、后处理和验证流程。
- **CAE 软件 / 求解器**：执行真实工程计算。
- **Viewer**：无需安装或打开求解器，即可查看导出的仿真结果。

##### 已支持的仿真生态

平台已覆盖多类商业与开源工具：

- **结构与有限元**：Abaqus、ANSYS Mechanical、CalculiX、Elmer FEM
- **流体仿真**：ANSYS Fluent
- **电磁仿真**：Ansys AEDT / HFSS
- **前后处理与多物理场**：HyperWorks、FreeCAD、ParaView
- **原子与分子尺度**：LAMMPS、OVITO

典型能力包括模型检查、参数设置、任务提交、运行监控、结果读取、截图、结果导出和优化计算。

##### Skills 工作流体系

Skills 不是求解器，而是供 AI 使用的标准化操作说明与流程模块。

Abaqus Skills 最为完整，覆盖：

- 几何、材料、网格、接触、载荷与边界条件
- 静力、动力、模态、热分析及热 — 结构耦合
- Job 提交、ODB 读取和结果导出
- 疲劳、形状优化、拓扑优化和尺寸优化

此外还提供 CalculiX、FEniCS、LAMMPS、OVITO、AEDT、Mechanical、COMSOL 电机 NVH 等专用工作流。

##### 特色能力

###### 真实软件闭环

AI 不仅生成脚本，还能连接正在运行的 CAE 软件，完成建模、求解、监控和结果读取。

###### 证据优先

多个工作流强调日志、结果文件、物理门禁和验证记录，降低 “AI 声称已完成、实际未执行” 的风险。

###### 自动优化

CalculiX 支持基于**拉丁超立方采样（LHS）+ 坐标下降**的两阶段尺寸优化，可在应力、位移和固有频率约束下实现减重与避共振。

###### 轻量结果查看

仿真结果可导出为`result_mesh.json`，通过浏览器 Viewer 查看应力、位移、振型等结果，无需本地安装求解器。

##### 使用方式

基本使用流程为：

1. 克隆仓库。
2. 在目标 MCP 目录中创建 Python 虚拟环境并安装服务。
3. 将 MCP 注册到支持该协议的 AI 客户端。
4. 将完整 Skill 目录复制到 Agent 的 Skills 目录。
5. 通过自然语言要求 AI 执行建模、求解和结果分析。
6. 使用 Viewer 检查导出的结果。

需要注意：**MCP 和 Skills 只负责连接与编排，商业 CAE 软件、许可证及运行环境仍需用户自行准备。**

##### 工程管理原则

仓库只保存可复用的：

- 源码、文档和测试
- 示例、模板与 Skills
- 自动化及验证脚本

明确不保存：

- CAE 软件二进制文件和许可证
- 私有路径、账号与凭据
- 虚拟环境和依赖缓存
- ODB、日志、截图及大型求解结果
- 可重新生成的工程数据

##### 产品价值与发展方向

CAE Agent Hub 的本质，是为工程仿真构建一层统一的**AI 操作与工作流协议层**，将分散的软件 API、脚本和专业流程封装为可复用能力。

后续规划包括：

- 接入更多主流 CAE 求解器
- 扩展产品化 Skill Pack
- 建立统一的结果导出格式
- 完善安装、验证与报告生成流程

其长期价值在于推动 CAE 从 “人工操作专业软件”，逐步转向 “AI 编排、软件求解、证据验证” 的自动化工程模式。

这套分层修正了一个常见误解：工程领域的 AI 自动化，不等于把自然语言转换成一段仿真脚本。脚本能运行，也不意味着模型正确；求解器正常结束，也不意味着结果可信。真正完整的链路至少包括建模、材料与边界条件设置、网格、求解、状态监控、结果提取和验证，并且要保留文件、命令、日志等证据。

##### 从“代码助手”进入真实工程系统

README 中最有分量的信号，是 Agent 已不只提供建议，而是能通过本地桥接控制正在运行的 CAE 应用：检查模型、提交任务、读取 ODB、执行 Fluent TUI、操作 Mechanical，甚至围绕 CalculiX 完成“修改设计变量—求解—读取结果—继续优化”的闭环。

这意味着 AI 的角色正在从**生成工程代码**转向**编排工程操作**。后者价值更大，因为大量 CAE 成本并不来自单次求解，而来自跨软件操作、参数传递、失败重跑和结果整理。CalculiX 的两阶段尺寸优化尤其能说明这一点：LHS 粗扫加坐标下降并不是什么全新的算法，但把它可靠地接入应力、位移和固有频率约束后，Agent 才开始成为可重复执行的工程流程，而不是一次性问答工具。

##### Skill 的核心不是提示词，而是组织知识

仓库把 Abaqus Skill 按几何、材料、网格、载荷、分析类型、后处理和优化拆分。这种设计的意义不只是方便复用，而是把工程知识放在正确的阶段：例如模态分析需要检查固有频率和振型，接触分析需要关注摩擦、收敛与装配关系，不能依赖一个通用 Agent 临场猜测。

因此，Skill 更接近**可执行的标准作业程序**。它应当承载适用条件、检查项、失败处理和验收标准，而不只是告诉模型调用哪些 API。未来真正形成壁垒的，可能也不是 MCP 接口数量，而是哪一套工作流能稳定识别单位错误、边界条件缺失、网格不收敛和“数值上成功、物理上荒谬”的结果。

##### 产品机会在“验证控制层”，不在统一聊天入口

CAE 软件高度碎片化，又受许可证、本地部署、版本差异和私有工程数据约束，因此一个完全云端化、统一替代所有工具的平台并不现实。更可信的机会，是建立横跨现有软件的**自动化与验证控制层**：在本地执行求解，统一记录输入、版本、命令、日志、结果摘要和审批状态，再通过轻量格式让非求解器用户查看关键结果。

这个项目目前更像一张有价值的技术路线图，而不是已经得到商业验证的平台。它提示的关键判断是：**工程 Agent 的竞争终点不会是“支持多少求解器”，而是谁能把真实执行、专业约束和可审计证据连成一个可信闭环。**

CAE Agent Hub 要解决的核心问题是：怎样让人工智能真正连接并操作工程仿真软件，而不只是生成一段无法验证的示例代码。

## 深度解读-口播（1）

### 2026-09-30 11:56:42

让人工智能帮你做工程仿真，关键不只是让它写出一段代码，而是让它连接真正的仿真软件，执行求解，再拿到可检查的结果。CAE Agent Hub 这个项目，想搭建的就是这样一条完整链路。

CAE 指计算机辅助工程，常见用途包括分析零件的应力、变形、振动，以及流体和电磁现象。这个项目并不是一个新的求解器，而是把人工智能客户端、现有工程软件、自动化流程和结果查看工具连接起来。

理解这个项目，先要分清三个角色：连接软件的接口，指导操作的流程，以及真正执行计算的求解器。

项目使用的 MCP，可以理解为人工智能客户端调用外部工具的一种连接协议。这里的 MCP 服务，负责让人工智能访问真实的工程软件。例如，查看当前模型、运行软件内部的脚本、提交计算任务，再读取任务状态和结果。

真正的数值计算，仍然由工程软件完成。求解之后，结果还可以转换成轻量数据，交给浏览器查看器展示。

所以，这条链路可以概括为：人工智能负责调用和组织流程，工程软件负责计算，查看器负责帮助人检查结果。它要解决的，不是“能不能生成一个看起来像仿真的示例”，而是“能不能把任务真正运行起来”。

以 Abaqus 的结构分析为例，这种分工会更具体。

项目里的 Abaqus 接口，可以连接正在运行的 Abaqus 软件，在软件内执行 Python 脚本，检查模型，提交求解任务，监控状态，并读取原生结果数据库。它还支持对模型视窗截图。

与接口配套的技能模块，则按工作阶段组织。比如，几何模块负责建立零件和装配；材料模块负责定义弹性、塑性和密度；网格模块负责划分有限元网格，也就是把连续结构拆成用于数值计算的小单元。

在这些基础设置之上，还有完整的分析工作流。静力分析关注应力、位移和反力；模态分析提取固有频率与振型，用于振动和共振检查；热与结构耦合分析，则研究温度变化带来的应力和变形。

这些模块的价值，在于可以围绕一个具体任务组合起来。比如，要做静力分析，就可以把静力分析、网格、任务管理和结果读取几个技能配合使用。原文给出的示例还明确要求：只有在本地接口或命令行求解器可用时才运行，并报告实际使用的文件和命令。

这就把“描述一个分析流程”和“实际完成一次分析”区分开了。

项目并不只面向 Abaqus。它还为 Fluent 的流体计算、Workbench Mechanical 的结构分析，以及 HFSS 的电磁分析等软件提供接口。不同软件采用的连接方式并不完全一样，但目标一致：让人工智能操作真实软件，并保留任务状态、日志或结果等证据。

其中一个值得单独理解的例子，是开源有限元求解器 CalculiX。它不需要商业许可证，项目为它提供了从输入文件检查、设计变量修改，到运行求解和导出结果的一条工作流。

在这条链路上，项目还加入了尺寸优化。所谓尺寸优化，就是调整壳或梁等结构的尺寸参数，在满足约束的前提下，尽量降低质量。

这里的重点是“满足约束”。如果只追求减重，结构可能变得太软，或者应力太高。因此，优化可以设置应力或位移限制。对于模态分析模型，还可以设置固有频率的下限，用于避共振相关的设计要求。

固有频率，可以简单理解为结构自身容易振动起来的频率；振型，则描述结构在相应频率下怎样变形。项目不仅能提取这些频率，还能把指定阶次的振型导出到浏览器查看器。

它采用的尺寸优化方法分成两阶段：先用一种叫拉丁超立方采样的方法，在参数范围内做较广的探索；再用坐标下降，逐个调整参数，进一步寻找更好的方案。

这个例子说明，连接求解器之后，人工智能参与的就不只是一次计算，还可以是“修改参数、重新求解、检查约束、继续改进”的循环。

不过，要真正使用这些能力，有一个不能忽略的前提：连接工具不等于拥有工程软件。

仓库提供的是可复用源码、文档、技能、示例和模板，不包含商业软件本体，也不包含许可证。各个接口还需要按照自己的说明，安装运行环境，并注册到支持 MCP 的人工智能客户端里。

技能模块也要完整安装，或者把相关操作说明放入项目上下文。只复制一个名字，并不会自动获得建模和求解能力。

这里要分清两件事：没有求解器，可以查看已经导出的结果；要生成新的计算结果，仍然需要相应的求解环境。

项目对源码管理也做了明确区分。可复用的程序、测试和模板应该进入仓库；许可证、凭据、私有机器路径，以及生成的求解结果、日志和截图，不应进入源码仓库。计算过程可以保留证据，但这些本地证据不等于都要公开提交。

最值得记住的是，CAE Agent Hub 的核心不是让人工智能替代工程求解器，而是让它通过接口和技能，参与真实、可检查的仿真流程。理解它时，要始终分清操作说明、软件连接和实际求解这三个层次；而判断一次任务是否完成，关键要看真实运行和结果证据，而不只是生成了多少代码。
