#### Chrome插件

乔木快捷提示词

发现身边很多朋友还是不太会写提示词。

于是写了个Chrome插件，把我和姚老师过去一年多写的提示词都放进去了。

另外收录了好友苍何（canghe）整理的几百套 GPT-Image-2 提示词，自带效果预览。

最后从 Github 精选了500个常用提示词，覆盖开发、设计、营销场景。

![Image](https://pbs.twimg.com/media/HJu2X4OaIAAUIcU?format=jpg&name=large)

你只需要一键复制粘贴，或简写自动补全就能在任意网站和 AI 平台用。

也能添加日常快捷语，比如收货地址、邮箱等，任何有输入框的地方都能用。

果然，能让人偷懒的东西才是好工具。

一周过去，已有1000多人安装，全五星好评。

插件安装地址：

乔木 Tab

每天上网，打开浏览器的次数是最多的，每次都要新开 Tab，这个页面值得好好利用。

![Image](https://pbs.twimg.com/media/HJu2ZXWasAAw8VC?format=jpg&name=large)

除了添加常用网站，也支持创建Todo、添加便签、查看天气预报、搜索查看最近关掉的 Tab页面、收藏夹等。

![Image](https://pbs.twimg.com/media/HJu2ap4boAEhesV?format=jpg&name=large)

每个模块都可以控制显示与否，也支持 Command + K 唤起，快速搜索或设置。

如果选了ChatGPT，输入内容后按Enter，自动跳转官网获得答案，不需要二次复制回车。

一个输入框解决了传统搜索、AI对话、添加Todo等操作，交互优雅。

#### 各种网站

艺术家风格网

不知道你有没有类似困惑，写生图提示词时经常词穷，只能复制别人的提示词。

对于生图模型来说，一个艺术家名字就是一种风格的高度压缩。

这是非常好的学习素材，也是最好的提示词类型之一。

于是，调用 GPT-image-2 API，用几百个艺术家名字生图，然后整理成一个网站。

[https://style.qiaomu.ai/](https://style.qiaomu.ai/)

提示词相同，变量只有艺术家名字。

> 远处是山，近处是深林和小溪，{artist} 风格的一幅画

远山近水和小树林，据说这种画面最能给人带来安全感，意味着食物、水源和庇护所。

网站可点击任意一张图片，按左右方向键查看图片，收藏艺术家和提示词。

上面都是风景画，不知道生成人物效果。

另外也想对比下即梦 4.5，换了一个包含人物和动物的新提示词，又做了个网站。

[https://jm-style.qiaomu.ai/](https://jm-style.qiaomu.ai/)

> 一个女子坐在窗边读书，一只猫趴在她腿上，窗外是花园，用｛artist｝的风格绘制

你也可以换提示词，调用 API 生图制作自己的提示词对比参考网，开源代码：

#### 两个小技巧

让你的Codex越来越聪明

灵感来自于跟tw93的直播访谈，让Codex更理解你的编程偏好。

打开Codex，设定目标或直接对话，提示词如下：

```text
阅读并检索我们所有的 Codex 对话记录与执行日志，进行系统性复盘，提炼出可复用的经验文档。
文档需要涵盖以下内容：
一、执行经验总结：记录哪些做法导致了问题、最终正确的执行方式是什么，以及从中得出的教训。
二、我的偏好与理念提炼：从对话中识别并归纳我的 UI 设计偏好、产品设计理念、交互原则等，形成结构化的个人风格档案。
三、可复用规则清单：将上述内容整理为 Codex 未来可直接遵循的行为准则。
完成文档后，将其保存为独立文件，并在 .agent 配置中以地址引用的方式加载该文档.
使后续所有 Codex 会话默认继承这些经验，无需重复说明。
```

制作PPT小技巧

最近受邀参加一些线下分享，需要制作PPT，目前实践下来效果比较满意的方法。

```text
1. GPT 5.5 Pro和Grok搜索获取参考资料；通过大模型提问，回答添加自己的理解和想法。
2. 让 Codex 或 CC 基于这些信息加工，提炼方法论、添加金句，写成一篇经验贴，输出 Markdown。
3. 把 Markdown 上传到 Youmind，用自己写的PPT提示词，先生成大纲，再生成20页高清PPT页面和3张不同样式的空白背景页。
4. 导出zip图片压缩包，依次粘贴到Keynote中，用空白背景，制作自我介绍、FAQ、联系二维码。
```

#### 解读

这篇文章本质上不是单纯“晒工具”，而是在展示一种新的工作方式：

##### 1. AI 让个人开发能力放大了

以前一个人要做插件、网站、脚本、CLI 工具，成本很高。

现在借助 Codex、Claude Code 这类工具，一个人可以快速做出很多“小而实用”的产品。

> 重点不是技术多复杂，而是能不能解决真实小问题。

---

##### 2. 好工具往往来自“偷懒需求”

这些工具都有一个共同点：

- 不想反复写提示词
- 不想手动发 X
- 不想复制字幕
- 不想整理单词
- 不想手动做 PPT
- 不想手动处理论文

所以作者把重复劳动自动化。

这也是 AI 工具最适合切入的方向：

> 把高频、琐碎、重复的事交给 AI 和脚本。

---

##### 3. 开源是一种影响力放大器

作者说的“幸运公式”很关键：

> 做很多事 × 让很多人知道

工具开源后，不只是帮助别人，也会带来：

- 用户反馈
- 社群关注
- 技术合作
- 个人品牌积累
- 新需求和新机会

这其实是“产品型个人”的典型打法。

---

##### 4. Skill 是未来趋势

文中多次提到 Skill，本质上是把一套复杂流程封装起来。

比如：

- 论文解读
- 音乐生成
- 读书辅助
- MV 制作

用户不需要知道背后怎么实现，只要调用即可。

这说明未来 AI 应用会从“聊天”走向“流程工具化”。

#### 我的意见

##### 值得学习的地方

1. **从自己的真实需求出发**
   - 不是为了炫技，而是解决自己每天遇到的问题。

2. **小工具也有价值**
   - 不一定非要做大产品，能节省时间就是好工具。

3. **开源 + 分享很聪明**
   - 工具本身解决问题，分享带来影响力。

4. **AI 编程适合快速试错**
   - 想法不必等团队、不必等融资，先做出来再说。

---

##### 需要注意的地方

1. **Vibe Coding 质量不一定稳定**
   - AI 写代码快，但仍需要测试、安全审查和维护。

2. **工具太多容易分散**
   - 如果长期维护，最好筛选出真正高频、用户多的项目。

3. **依赖外部平台有风险**
   - Chrome、X、Suno、NotebookLM、Cloudflare 等平台规则一变，工具可能失效。

##### 6. 两个实用技巧

###### 6.1 让 Codex 越来越懂你

作者建议让 Codex 复盘过往对话和执行日志，形成长期记忆式的经验文档。

**核心做法：**

- 让 Codex 阅读和检索所有历史对话与执行记录。
- 总结：
  - 哪些做法容易出问题。
  - 正确执行方式是什么。
  - 用户的 UI 偏好、产品理念、交互原则。
  - 后续可复用的规则清单。
- 将文档保存为独立文件，并在 `.agent` 配置中引用。

**目的：**

- 让之后的 Codex 会话默认继承你的经验和偏好。
- 避免每次重复说明需求。

   - 20 页高清 PPT 页面
   - 3 张不同样式的空白背景页
6. 导出 zip 图片包，粘贴到 Keynote。

##### 4. 反方与张力

###### 4.1 Vibe Coding 的速度与工程质量之间有张力

作者自己也提到，有些官方项目质量可能比自己 Vibe Coding 的版本更好。

这说明：

> AI 能快速做出可用工具，但不等于一定具备长期稳定性、可维护性和安全性。

潜在问题包括：

- 代码质量不稳定
- 安全边界不足
- 权限设计粗糙
- 浏览器插件隐私风险
- API 成本不可控
- 缺乏异常处理
- 后续维护压力大

适合自用或小范围使用，但如果商业化，需要补齐工程化能力。

---

###### 4.2 开源传播很好，但商业闭环未必自然出现

开源可以带来：

- 关注
- 声誉
- 用户
- 反馈
- 合作机会

但不必然带来收入。

如果目标是商业系统，需要进一步设计：

- 哪些免费
- 哪些收费
- 谁是付费用户
- 是插件订阅、服务费还是咨询费
- 是否有团队版
- 是否能接入企业流程
- 是否具备持续维护能力

否则容易陷入：

> 做了很多工具，获得很多点赞，但没有稳定商业回报。

---

###### 4.3 工具多可能带来注意力分散

作者做了很多东西，这是优势，也可能是风险。

风险在于：

- 每个工具都浅尝辄止
- 用户不知道核心产品是什么
- 维护成本分散
- 品牌定位过宽
- 难形成单一强商业飞轮

但反过来，早期多做也有价值：

> 多做是探索，精选是战略。

关键在于后续是否能识别出：

- 哪个工具用户最多
- 哪个工具复购最高
- 哪个工具最能沉淀数据
- 哪个工具最适合商业化
- 哪个工具能成为入口

文中涉及：

- 下载 Suno 歌曲
- 生图风格参考

如果只是学习和展示问题不大，但若商业化，需要谨慎处理授权和合规。
