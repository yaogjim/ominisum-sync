#### 🚀 Install

One line. No global install, no `npm i -g`. Always use `npx`:

```
npx lazycodex-ai install
```

This is shorthand for `npx --yes --package oh-my-openagent omo install --platform=codex`. For a fully autonomous, no-TUI setup:

```
npx lazycodex-ai install --no-tui --codex-autonomous
```

The npx installer above stays the primary path. As an additive, experimental alternative you can install from inside Codex itself: type `/plugins`, open the **Add Marketplace** tab ("Add a marketplace from a Git repo or local root."), and enter `https://github.com/code-yeongyu/lazycodex`, then install `omo` from the `sisyphuslabs` marketplace. Or from the CLI:

```
codex plugin marketplace add https://github.com/code-yeongyu/lazycodex
codex plugin add omo@sisyphuslabs
```

On the next launch, approve the omo hooks in Codex's startup review — hooks never run before approval. The first approved session prints `LazyCodex bootstrap running in background — restart the session when it completes` while a background worker finishes the setup (config blocks, agent roles, bin links, a pinned `sg` binary for the `ast_grep` MCP); restart when it is done. The marketplace path never touches Codex permission settings — autonomous mode remains the explicit `npx lazycodex-ai install --no-tui --codex-autonomous` choice.

Upgrade with `codex plugin marketplace upgrade sisyphuslabs`. The next startup review shows the hooks as **Modified** — expected after every upgrade — re-approve them and the following session re-runs bootstrap on the new version. If anything looks pending or degraded, `npx lazycodex-ai doctor` explains what and why. Full details: [lazycodex.ai/docs](https://lazycodex.ai/docs).

```
npx lazycodex-ai doctor
```

`doctor` prints the installation health report: plugin cache, hooks, MCP servers, agents, and config state. Inside Codex, type `$` in the composer to browse every installed skill — `init-deep`, `ulw-loop`, `ulw-plan`,`start-work`, and the rest — and hooks announce themselves with `LazyCodex(<version>): ...` status messages during a session.

##### Uninstall

```
npx lazycodex-ai uninstall
```

Removes the installed plugin cache, bin links, agent roles, and the managed sections of `~/.codex/config.toml`.

#### ⚡ Commands

LazyCodex installs these as OmO commands for Codex. Invoke them with the `$command` syntax shown by the installer.

Command Type this What it does

`$ulw-loop` `$ulw-loop "task" [--completion-promise=TEXT] [--strategy=reset|continue]` Self-referential loop that runs until Oracle-verified completion. Caps at 500 iterations in ultrawork mode, 100 in normal mode.

`$ulw-plan` `$ulw-plan "what to build"` Prometheus strategic planner. Writes a plan to `plans/<slug>.md`. Never writes product code.

`$start-work` `$start-work [plan-name] [--worktree <path>]` Executes a plan until every checkbox is done. Prints **ORCHESTRATION COMPLETE**.

Full documentation lives at [lazycodex.ai/docs](https://lazycodex.ai/docs).

LazyCodex should be judged by the features it actually installs. It is the Codex distribution for OmO's agent harness: project memory, planning, execution, verified completion, skills, hooks, model routing, and diagnostics.

`$init-deep` generates hierarchical `AGENTS.md` context. It scores complex directories, writes local guidance near the code that needs it, and gives future agents landmarks before they edit. Type `$init-deep` in the Codex composer — the `$` prefix is how every installed skill is invoked.

Use it when the repository is too large to explain from memory. Run it again when the shape of the codebase changes.

Use `$ulw-plan` when the work needs decisions before implementation. It writes a plan to `plans/<slug>.md` and does not touch product code.

Use `$start-work` when a plan is ready. It executes the checklist with durable Boulder progress and stops only when the plan is complete.

Use `$ulw-loop` when the task should keep moving until the result is verified by evidence instead of a hopeful status update.

The command layer stays simple. The skill layer adds specialist judgment for the actual work:

Feature Use it for

`$init-deep` Hierarchical project memory through `AGENTS.md`

`$ulw-plan` Decision-complete planning before code changes

`$start-work` Durable plan execution with Boulder progress

`$ulw-loop` Verified completion for open-ended tasks

`review-work` Multi-angle post-implementation review

`remove-ai-slops` Behavior-preserving cleanup of AI-looking code

`frontend-ui-ux` Polished UI surfaces

`programming` Strict TypeScript, Rust, Python, or Go discipline

`LSP` Diagnostics, definitions, references, symbols, and renames

`AST-grep` Structural search and rewrite across code

`rules` Project instructions from AGENTS, rules, and instruction files

`comment-checker` Feedback after edit-like operations

LazyCodex installs selectable agent roles into `~/.codex/agents/`: `explorer`,`librarian`, `plan`, `momus`, `metis`, and `codex-ultrawork-reviewer`. Pick one by passing `agent_type` to Codex's `spawn_agent` tool — the child agent runs with that role's model and instructions:

The installer exposes `agent_type` on `multi_agent_v2` sessions (Codex hides it by default). If your Codex build's spawn tool has no `agent_type` parameter, describe the role inside `message` instead — the skills are written to fall back to that form automatically.

Start at [https://lazycodex.ai](https://lazycodex.ai).

Feature Description

🤖 **Discipline Agents** Sisyphus orchestrates Hephaestus, Oracle, Librarian. A full AI dev team

🔀 **Parallel Execution** Multiple agents working simultaneously on subtasks

🎯 **Multi-Model Routing** Automatic model selection per task category

🛠️ **Skills System** Extensible skill library for specialized tasks

📋 **Hooks &amp; Lifecycle** Pre/post hooks for every agent action

🔧 **Zero Config** Sensible defaults, override when you want

Do not be surprised if an OmO/LazyCodex run shows models like `gpt-5.2` with `xhigh`, `gpt-5.4-mini`, `gpt-5.3-codex`, or newer equivalents like `gpt-5.5` with `xhigh`. That is intentional.

OmO does not blindly spend your best model on every subtask. Its source defines task categories and fallback chains so the agent can pick the most appropriate model for the job: `quick` routes to `gpt-5.4-mini` for small edits, `ultrabrain` uses a high-reasoning GPT model for hard logic, and agentic coding paths can use Codex-tuned GPT models when available. See `openai-categories.ts` and `model-requirements.ts`.

The point is quota discipline: use the strongest model when the task needs deep reasoning, use a cheaper/faster model when that is enough, and keep parallel agent work efficient instead of burning premium quota on routine steps. This is benchmark-driven routing, not random model churn:

- [GPT-5.2](https://openai.com/index/introducing-gpt-5-2/) is documented by OpenAI as stronger at code review, bug finding, and complex tool use; the announcement notes that its maximum API reasoning effort uses `xhigh`.
- [GPT-5.3-Codex](https://developers.openai.com/api/docs/models/gpt-5.3-codex) is OpenAI's Codex-tuned model for agentic software engineering, with public coding-agent benchmarks such as SWE-Bench Pro, Terminal-Bench 2.0, and OSWorld Verified reported in the [GPT-5.3-Codex announcement](https://openai.com/index/introducing-gpt-5-3-codex).
- [GPT-5.4 mini](https://openai.com/index/introducing-gpt-5-4-mini-and-nano/) is positioned for efficient everyday coding, computer use, and subagents; that is why lightweight OmO tasks can land there instead of spending a frontier reasoning model.

#### LazyCodex 项目总结

##### 一句话概括

LazyCodex 是一个面向复杂代码库的 Codex Agent 工作流套件，目标是把 Codex 从“聊天式写代码工具”升级为具备项目记忆、规划、执行、审查和验证闭环的 AI 开发团队。

官网：&lt;https://lazycodex.ai>  
GitHub：&lt;https://github.com/code-yeongyu/lazycodex>

---

##### 它解决什么问题？

在大型代码库中，AI 编程常见问题包括：

- 不理解项目结构和上下文
- 只会局部修改，缺少完整计划
- 执行过程不可持续，容易半途而废
- 结果缺少验证，只给“看起来完成”的反馈
- 多 Agent、多模型、工具链配置复杂

LazyCodex 试图通过一套预设好的 Agent Harness，把这些能力标准化、自动化。

---

##### 核心定位

LazyCodex 本质上是 OmO（oh-my-openagent）在 Codex 上的发行版。

可以理解为：

> LazyVim 让 Neovim 更易用，LazyCodex 让 Codex 更适合复杂工程项目。

它不是单一代码生成工具，而是一套围绕 Codex 的 Agent 编排系统，包含：

- 项目记忆
- 任务规划
- 多 Agent 协作
- 自动执行
- 代码审查
- 验证完成
- 模型路由
- Hooks 生命周期管理
- 诊断与健康检查

---

##### 关键能力

###### 1. 项目记忆

通过 `$init-deep` 生成分层的 `AGENTS.md`，为复杂目录建立本地上下文说明。

适合用于：

- 大型仓库初始化
- 新 Agent 理解项目结构
- 代码结构发生变化后的上下文更新

---

###### 2. 规划与执行分离

LazyCodex 强调先规划、再执行。

常用命令包括：

| 命令 | 作用 |
|---|---|
| `$ulw-plan` | 生成实施计划，写入 `plans/&lt;slug>.md`，不直接改代码 |
| `$start-work` | 按计划执行，直到清单完成 |
| `$ulw-loop` | 针对开放任务持续推进，直到有证据验证完成 |
| `$init-deep` | 生成项目级上下文记忆 |

这种设计降低了 AI 直接改代码带来的不确定性。

---

###### 3. 多 Agent 协作

LazyCodex 会安装多个可选 Agent 角色，例如：

- explorer：探索代码库
- librarian：整理信息与上下文
- plan：制定计划
- momus / metis：审查、判断与辅助决策
- codex-ultrawork-reviewer：深度工作审查

这些角色可以通过 Codex 的 `spawn_agent` 工具调用，实现类似“AI 开发团队”的协作模式。

---

###### 4. 验证式完成

LazyCodex 的重点不是“AI 说完成”，而是强调：

> 通过证据验证任务是否真的完成。

例如 `$ulw-loop` 会循环执行任务，直到 Oracle 验证完成，而不是仅停留在主观状态汇报。

---

###### 5. 多模型路由

OmO 会根据任务类型选择不同模型：

- 简单任务使用更快、更便宜的模型
- 复杂推理任务使用高推理模型
- Agentic coding 使用 Codex 优化模型

其目标是提升效率，同时控制高阶模型的消耗。

##### 产品价值判断

LazyCodex 的核心价值是把 Codex 从“单点代码助手”变成“可编排、可验证、可持续执行”的工程协作系统。

适合人群包括：

- 维护复杂代码库的开发团队
- 希望用 AI 执行长期任务的工程师
- 想把 Codex 工作流标准化的技术团队

---

---

##### 总结

LazyCodex 是一个面向复杂软件工程场景的 Codex 增强套件。它通过项目记忆、计划生成、多 Agent 执行、模型路由和验证闭环，让 AI 编程从“临时生成代码”走向“系统化完成任务”。

如果说普通 Codex 更像一个聪明的编码助手，LazyCodex 则试图把它包装成一个能理解项目、制定计划、分工执行并验证结果的 AI 工程团队。

```bash

检查安装状态：

```

诊断内容包括：

- 插件缓存
- hooks 状态
- MCP 服务
- 智能体角色

##### 2. 三个核心命令

LazyCodex 的命令通过 Codex 输入框中的 `$命令` 形式调用。

| 命令 | 作用 |
|---|---|
| `$ulw-plan "要构建的内容"` | 在编码前完成关键决策，将计划写入 `plans/&lt;slug>.md`，不会修改产品代码 |
| `$start-work [plan-name]` | 按计划持续执行，保存进度，直到所有复选项完成，并输出 `ORCHESTRATION COMPLETE` |
| `$ulw-loop "任务"` | 反复执行任务，直到结果通过 Oracle 的证据验证，而不是仅依赖智能体口头宣称完成 |

`$ulw-loop` 支持：

```bash
$ulw-loop "task" \
  [--completion-promise=TEXT] \
  [--strategy=reset|continue]
```

循环次数上限为：

- **Ultrawork 模式：500 次**
- **普通模式：100 次**

##### 3. 推荐工作流程

###### 第一步：建立项目记忆

使用：

```text
$init-deep
```

该命令会分析复杂目录，在适合的位置生成分层 `AGENTS.md`，为后续智能体提供代码结构、项目规则和编辑指引。

适用场景：

- 仓库规模过大，难以靠上下文完整描述。
- 代码库结构发生明显变化，需要更新项目记忆。

###### 第二步：先规划再编码

使用 `$ulw-plan` 梳理实现方案和关键决策。规划器会输出独立计划文件，但不会直接编写产品代码，从而降低边规划边修改导致的偏差。

###### 第三步：按计划持续执行

使用 `$start-work` 执行计划中的检查清单。它通过持久化的 **Boulder progress** 保存进度，直到计划中的每一项都完成。

###### 第四步：验证真正完成

对于边界开放、容易“看似完成”的任务，可使用 `$ulw-loop`。它会持续推进，并要求通过证据和 Oracle 审核验证结果，而不是接受乐观的完成声明。

##### 4. 技能系统与开发能力

除核心命令外，LazyCodex 还提供面向实际开发工作的专门技能：

| 技能 | 用途 |
|---|---|
| `review-work` | 从多个角度进行实现后的代码审查 |
| `remove-ai-slops` | 在不改变行为的前提下，清理明显的 AI 风格或冗余代码 |
| `frontend-ui-ux` | 构建和优化精致的前端界面 |

| `rules` | 读取 `AGENTS.md`、规则文件及其他项目指令 |
| `comment-checker` | 在编辑类操作后提供反馈和检查 |

在 Codex 输入框中键入 `$`，可以浏览已安装的全部技能。

##### 5. 多智能体协作

LazyCodex 会在 `~/.codex/agents/` 中安装以下可选角色：

- `explorer`：探索代码库和定位实现
- `librarian`：检索文档及背景信息
- `plan`：制定实施计划
- `momus`：审查与质疑方案
- `metis`：分析问题及隐藏风险
- `codex-ultrawork-reviewer`：对高强度执行结果进行复核

调用 Codex 的 `spawn_agent` 工具时，可以通过 `agent_type` 选择角色。若当前 Codex 版本不支持该参数，也可以直接在 `message` 中描述需要的角色，相关技能会自动采用这种降级方式。

整体协作模式由 Sisyphus 负责调度 Hephaestus、Oracle、Librarian 等角色，并支持多个智能体并行处理子任务。

##### 6. 核心特性

LazyCodex 实际安装并提供的能力包括：

- **项目记忆**：通过分层 `AGENTS.md` 保存代码库背景。
- **决策式规划**：在修改代码前完成关键设计选择。
- **持久执行**：计划进度可以持续记录，不因单次会话中断而丢失。
- **验证式完成**：要求用测试、诊断或审核证据确认任务完成。
- **并行执行**：多个智能体同时处理不同子任务。
- **生命周期 hooks**：在智能体操作前后运行相应逻辑。
- **技能扩展**：根据前端、审查、结构化搜索等场景调用专业技能。
- **零配置默认值**：开箱即用，同时允许用户覆盖配置。
- **诊断工具**：检测插件、配置、MCP 和智能体状态。

##### 7. 多模型路由与配额控制

OmO 不会让所有任务都使用成本最高、推理能力最强的模型，而是根据任务类别和回退链自动选择模型。例如：

- 小型编辑和轻量子任务可路由到 **GPT-5.4 mini**。
- 高难度逻辑任务由 `ultrabrain` 路由到高推理等级 GPT 模型。
- 智能体编程任务优先使用 Codex 调优模型，如 **GPT-5.3-Codex**。
- 复杂代码审查、缺陷发现和工具调用可能使用 **GPT-5.2 + xhigh**。
- 未来也可能出现 **GPT-5.5 + xhigh** 等更新的等价模型。

其目标是实现“配额纪律”：

- 深度推理任务使用最强模型。
- 日常编辑使用更快、更便宜的模型。
- 并行子任务避免不必要地消耗高端模型配额。

项目称这一机制基于模型能力和公开基准，而不是随机切换模型。例如，GPT-5.3-Codex 的参考指标包括 **SWE-Bench Pro、Terminal-Bench 2.0 和 OSWorld Verified**。
