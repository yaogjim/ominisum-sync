## 正文

**Indie Fox**

还没体验过 Pi 或 Craft agent 的朋友，建议现在就去试一次。你会立刻明白我上个月说那句话时是什么心情。

我之前就讲过：未来程序员不再主要“做需求”，而是“做 agent”。agent 用来把你的能力蒸馏出来：你只要把需求说清楚，剩下的交给它完成。

如果你要研究怎么做一个 code agent，别从 0 开始，直接从 Pi agent 起步。它的可扩展性很好，集成进现有业务会省掉大量时间。

如果你要研究怎么做一个类似 codex desktop 的产品，那就从 Craft agent 入手。它基于 Pi agent 和 Claude agent，功能完整、覆盖面也足。

觉得复杂也没关系：能裁就裁。Claude agent sdk、messaging-gateway 这些都可以精简掉，留下的就是实打实的核心能力。

我已经基于它二开了一个新产品，叫 Echo，接入了技能市场，流程非常顺滑。它现在就是我的独立开发搭子，后续开发、运营我都在它上面跑。

## 解读（1）

### 2026-07-03 11:55:37

#### 深度总结

这条内容的核心观点是：

> **AI 时代，程序员的工作重心正在从“亲自实现需求”，转向“构建能实现需求的 Agent”。**

作者推荐两类开源 Agent：

| 工具 | 定位 | 适合研究方向 |
|---|---|---|
| **Pi agent** | 开源 coding agent，类似 Claude Code | 做代码 Agent、集成到现有业务 |
| **Craft agent** | 更完整的桌面/协作 Agent，类似 Codex Desktop / Claude Cowork | 做 Agent 产品、桌面开发助手 |

作者认为：

- **不要从 0 开始做 Agent**，应基于成熟开源项目二次开发。
- Agent 的价值在于把人的能力、流程、经验“蒸馏”成可复用工具。
- 企业或个人不一定要和大厂竞争通用 Agent，而是应做**结合自身业务的定制化 Agent**。
- 作者已基于这些工具开发了自己的产品 **Echo**，并接入技能市场，用于日常开发和运营。

一句话概括：

> **未来的独立开发者，不只是写代码的人，而是训练、组装、运营 Agent 的人。**

---

#### 深入浅出解读

以前的开发模式是：

> 人提出需求 → 程序员理解 → 程序员写代码 → 交付功能

未来可能变成：

> 人说清楚目标 → Agent 拆任务、写代码、执行流程 → 人审核和优化

所以程序员的价值会发生变化：

##### 过去：会写代码很重要

你要懂框架、语法、数据库、部署。

##### 现在：会用 AI 写代码很重要

你要会提示词、会拆任务、会审查 AI 输出。

##### 未来：会做 Agent 更重要

你要把某类工作流程封装成一个能反复执行的“数字员工”。

例如：

- 写代码 Agent
- 做客服 Agent
- 做运营 Agent
- 做数据分析 Agent
- 做教育辅导 Agent
- 做医疗问诊辅助 Agent

真正的机会不一定在“做一个万能 Agent”，而在：

> **围绕具体行业、具体业务、具体流程，做能落地的专用 Agent。**

---

#### 关键启发

##### 1. Agent 不是玩具，而是生产力容器

Agent 不只是聊天机器人。

它可以连接：

- 代码仓库
- 文件系统
- 浏览器
- 数据库
- 第三方 API
- 企业内部系统
- 工作流工具

一旦接入真实业务，它就从“会聊天”变成“会干活”。

---

##### 2. 不要重复造轮子

作者强调：

> 研究 code agent，不要从 0 开始。

因为 Agent 系统涉及很多复杂能力：

- 任务规划
- 上下文管理
- 工具调用
- 文件读写
- 代码执行
- 多轮反馈
- 权限控制
- UI 交互

普通开发者最好的方式是：

> **基于 Pi、Craft 这类开源基座，裁剪、改造、接入业务。**

---

##### 3. 真正的壁垒在业务，不只在技术

热门回复里有人提到：

> 复杂业务里，把需求说清楚本身就很难。

这是重点。

未来不是“人人一句话做软件”，而是：

> 谁更懂业务，谁更能做出好 Agent。

因为 Agent 只是执行器，业务理解才是方向盘。

---

#### 辩证思考

##### 我认同的部分

###### 1. “做 Agent”确实会成为新趋势

AI 编程工具已经从“代码补全”进化到“任务执行”。

程序员会越来越像：

- 产品经理
- 架构师
- 流程设计师
- Agent 训练师
- 质量审核员

写代码仍重要，但不再是唯一核心。

---

###### 2. 定制化 Agent 比通用 Agent 更现实

普通团队很难和 OpenAI、Anthropic、Google 竞争底层模型和通用 Agent。

但可以在垂直场景里做深：

- 公司内部研发流程
- 行业知识库
- 特定审批流程
- 特定客户服务
- 特定数据处理任务

这类 Agent 不需要最强模型，只需要最懂场景。

---

##### 需要警惕的部分

###### 1. “需求说清楚”本身就是高门槛

很多项目失败，不是因为程序员不会写，而是因为：

- 需求模糊
- 业务变化快
- 用户真实痛点不清楚
- 边界条件复杂
- 责任归属不明确

Agent 可以提升执行效率，但不能自动解决混乱的业务问题。

---

###### 2. Agent 不是越复杂越好

很多人容易陷入技术堆叠：

- 多 Agent 协作
- 复杂工作流
- 各种 SDK
- 各种插件市场
- 各种自动化框架

但真正有用的 Agent，往往先解决一个小而明确的问题。

更好的路径是：

> 先做窄，再做深；先可用，再智能。

---

###### 3. 开源基座有红利，也有风险

基于开源 Agent 二开很高效，但也要注意：

- 项目是否长期维护
- 架构是否稳定
- 安全边界是否清晰
- 是否适合商业化
- 与自身业务是否匹配

不要因为“热门”就盲目迁移核心业务。

---

#### 最终判断

这条内容真正有价值的地方，不是简单推荐 Pi 或 Craft，而是指出了一个方向：

> **AI 编程的下一阶段，不是更会写代码，而是更会构建能替你工作的系统。**

对独立开发者和小团队来说，最佳策略可能是：

1. 选择成熟开源 Agent 做基座  
2. 裁剪掉不必要复杂功能  
3. 接入自己的业务流程  
4. 打磨一个高频、明确、可交付的场景  
5. 让 Agent 成为自己的“数字搭子”  

一句话：

> **未来竞争的不是谁写代码更快，而是谁能把经验、流程和业务理解封装成可持续运转的 Agent。**

## 结构化（1）

### 2026-07-23 10:08:11

##### 主旨概括

作者认为，程序员未来的核心工作将从亲自“做需求”转向构建和使用 **Agent**，把个人能力沉淀为可复用、自动执行任务的系统。对于想开发代码 Agent 或桌面 Agent 的人，他建议直接基于 **Pi** 或 **Craft** 二次开发，而不是从零起步。

##### 1. 编程工作正在转向“做 Agent”

- 作者建议尚未体验过 **Pi** 或 **Craft Agent** 的开发者尽快尝试，以直观感受 Agent 带来的开发方式变化。
- 在他看来，未来程序员不再主要负责逐项实现需求，而是：
  1. 将需求描述清楚；
  2. 把自己的经验和能力“蒸馏”进 Agent；
  3. 让 Agent 自动完成后续工作。
- 换言之，开发者的价值将更多体现在**业务理解、任务设计和 Agent 定制**上。

##### 2. 不同产品应选择不同的开源基座

###### 开发代码 Agent：从 Pi 起步

- **Pi** 是开源 Coding Agent，可类比 **Claude Code**。
- 作者认为它的可扩展性较好，适合接入现有业务。
- 相比从零开发，基于 Pi 构建能节省大量时间。

###### 开发桌面 Agent：从 Craft 起步

- **Craft** 是较完整的开源 Agent，可类比 **Claude Cowork / Codex Desktop** 一类产品。
- 它基于 **Pi Agent** 和 **Claude Agent**，功能与覆盖面相对完整。
- 如果目标是开发桌面端智能工作助手，Craft 是更直接的起点。

##### 3. 项目太复杂时，可以主动裁剪

- 不必完整保留 Craft 的所有组件，可根据实际业务删除不需要的部分。
- 例如，作者提到可以精简：
  - **Claude Agent SDK**
  - **messaging-gateway**
- 裁剪之后，可以留下最核心的 Agent 能力，降低集成与维护成本。

##### 4. 实践案例：基于 Craft 二次开发 Echo

- 作者已基于上述方案开发了新产品 **Echo**。
- Echo 接入了**技能市场**，整体使用流程顺滑。
- 它目前充当作者的“独立开发搭子”，后续的：
  - 产品开发
  - 日常运营
  - 工作流程执行  
  都计划在 Echo 上完成。

##### 5. 作者推荐的技术组合

作者列出了当前实践效果较好的 4 项工具：

1. **Pi**：开源 Coding Agent，可理解为 Claude Code。
2. **Craft**：开源通用 Agent，可理解为 Claude Cowork。
3. **Cloudflare**：拥有许多实用但尚未被充分发现的服务。
4. **TanStack**：作者认为它是比 Next.js 更好、更快的全栈框架。

作者认为，将这几项技术结合起来，可以显著提升独立开发和产品构建效率。

##### 6. 评论区的主要讨论

- 有人指出，复杂业务中，**把需求说清楚本身就需要大量精力**。未来开发者仍必须深入理解业务，不同领域会产生不同的定制 Agent，例如编程、教育和医疗 Agent。
- 也有人认为，基础 Agent 层已有大量大厂投入，普通企业很难正面竞争，更现实的机会可能在 Agent 之上的应用层。
- 作者回应称，普通企业没有必要与大厂竞争底层模型或通用 Agent，而应：
  - 基于开源 Agent；
  - 结合自身业务；
  - 搭建定制化 Agent；
  - 利用 AI 提升效率。
- 另有开发者原本打算用 **Claude Agent SDK + Electron** 自行搭建，看到 Pi 与 Craft 后认为可以少走很多弯路。
- 关于 Echo 是否开放，作者表示目前仍在边用边开发，未来可能开放，但尚未确定。
