## 通俗精炼（1）

### 2026-06-15 09:58:21

#### 宝玉：Skill 扩展配置不该只用 Markdown

##### 核心观点

宝玉在做 **baoyu-skills** 时，曾尝试用 `EXTEND.md` 文件保存用户自定义设置，初衷是让 Agent / LLM 更容易读取和理解。

但实践后发现：**Markdown 适合给 LLM 看，不适合给程序稳定解析。**

##### 主要问题

###### 1. Markdown 不是严格结构化数据

Markdown 更像自然语言文档，格式灵活，但缺少强约束。

LLM 可以理解其中含义，但程序很难稳定、准确地解析。

###### 2. 格式一致性难以保证

用户或 Agent 修改 Markdown 时，容易出现格式不统一、字段缺失、层级混乱等问题。

这会导致后续自动化处理变得不可靠。

##### 更好的设计方向

如果重新设计，宝玉更倾向于使用：

- `JSON`
- `YAML`

作为 Skill 的扩展配置格式。

这样既能让 LLM 读取理解，也能让程序方便解析、校验、保存。

##### 评论区共识

热门回复基本认同这一判断：

- Markdown 适合表达上下文和说明
- JSON / YAML 更适合配置、结构化数据和自动化流程
- 结构化输出后，可以用固定脚本处理，稳定性更高，也更省 token

##### 一句话总结

**Markdown 适合做人机协作的上下文界面，但涉及配置、状态和自动化处理时，JSON / YAML 才是更可靠的选择。**
