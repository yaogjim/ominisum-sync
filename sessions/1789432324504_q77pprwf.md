## 分析要点

- **核心高价值点**：针对企业私有数据和垂直任务交付可本地部署的小模型，可能形成区别于通用SaaS的授权与维护收入。
- **留存建议**：可作为商业机会线索浏览，但应在验证成本、效果和真实需求后再决定是否保留
- **不足**：核心判断主要基于作者个人经历，缺少任务基准、成本明细、客户案例和持续收入数据，不足以长期归档。

**知识要点**

- 小模型可以通过领域数据和LoRA等方式针对特定任务微调，并导出为GGUF或MLX等部署格式。
- 垂直小模型的潜在卖点包括本地部署、数据隐私、较低推理成本和更快响应。
- 商业模式可从单纯销售软件订阅转向模型微调、部署授权及持续维护服务。

**行动项**

- 选择一个边界明确的垂直任务，用小模型微调后与主流通用模型进行效果、速度和成本对比。
- 访谈有本地部署或数据隐私需求的企业，验证其对模型授权和维护服务的付费意愿。
- 在形成商业判断前核实文中成本降低95%、速度提升5倍等主张的适用条件。

**CJ Zafir**

软件变现现在已经死了。

任何人都可以在几个小时内克隆你的应用，复制你的广告，照搬你的定位。

我现在看到了一个新的机会。

SLM（小型语言模型）的变现

你可以针对特定用例微调 0.5B 到 12B 的模型。

然后像销售 SaaS 一样销售这些模型的许可证。

像 Deepseek v4 pro、GLM 5.3、Kimi k3 甚至 GPT 6 Astra 这样的模型非常擅长理解微调任务。

从准备数据集、LoRA 适配器，到将模型导出为 GGUF 或 MLX，这些模型可以为你完成端到端的工作。

在过去一年里，我微调了 20 多个模型，我很惊讶 X 上竟然没有多少人讨论这个。

一个经过微调的 SLM 在特定用例上可以击败 SoTA 模型。

这可以将 API 成本降低 95%，速度提升 5 倍，而且它是你的模型，可以私有托管。

自定义 SLM &gt; SaaS，现在就是如此。深入研究这个领域吧。

## 深度解读（1）

### 2026-09-15 09:06:24

#### 软件没有失去变现能力，稀缺性正从代码转向数据、评测与交付

“软件变现已死” 显然言过其实。能在几小时内复制的，通常只是界面、文案和一部分标准功能，而不是 Photoshop 的复杂能力、Gmail 的基础设施，更不是既有产品积累的用户关系、数据和工作流。AI 降低的是**生产相似软件的成本**，并未自动解决可靠性、分发、迁移成本与持续运营。

但这条推文仍捕捉到一个真实变化：当通用模型足够强、微调和部署工具日益成熟后，一些原本依赖昂贵 API 的垂直任务，确实可以被小模型接管。值得关注的不是 “SLM 取代 SaaS”，而是**软件能力的交付边界正在重新划分**。

##### 小模型成立，需要同时满足四个条件

一个 0.5B—12B 的模型可能在特定任务上胜过通用大模型，但这里的 “特定” 非常关键。任务通常要足够窄、输出可验证、业务模式相对稳定，并且有高质量私有数据。例如固定格式的工单分类、行业文本抽取、内部知识路由，比开放式咨询或复杂决策更适合。

所谓成本下降 95%、速度提升 5 倍，也不能脱离调用规模与运维成本讨论。若调用量很小，直接购买 API 往往更便宜；若模型需要频繁重训、监控漂移、处理异常和维护推理基础设施，节省的 token 成本可能转化为新的工程成本。私有部署的真正购买者，更可能是**调用量大、延迟敏感，或因合规不能把数据送到外部 API 的企业**。

因此，判断机会时不能只比较 benchmark，而要比较完整替代方案：模型效果、失败代价、推理成本、部署难度和更新频率。一个平均准确率更高的模型，如果在关键少数案例中稳定性更差，商业上仍可能不可用。

##### 作者验证的是服务需求，而非 “模型许可证” 模式

推文中最有分量的证据，并不是花 15 美元完成一次 4B 模型训练，而是作者称已有十多家公司主动寻求微调和维护，并愿意签订 1 万 —5 万美元的合同。这说明企业确有 “用自己的数据获得本地模型” 的需求，但它验证的主要是**咨询、定制与长期运维需求**，尚未验证像 SaaS 一样规模化销售模型许可证。

两者的商业性质不同。模型权重或 LoRA 适配器容易被替代，客户数据又各不相同，导致每次交付都可能重新清洗数据、定义标签和建立评测。真正形成复购与壁垒的，往往不是某个权重文件，而是数据管线、任务评测集、部署工具、反馈闭环和更新责任。换句话说，产品可能不是 “卖一个模型”，而是提供一套可持续达到业务指标的垂直模型系统。

##### 稀缺资源正在迁移，而不是消失

大模型既能帮助复制软件，也能帮助生成训练数据、编写微调脚本和完成格式转换。这意味着工具本身会迅速普及，单纯 “会微调” 很难长期保持溢价。新的稀缺资源更可能是：**拿得到的真实业务数据、定义得清楚的成功标准，以及进入客户工作流的能力**。

对产品判断而言，最值得验证的问题不是 “哪个行业需要 SLM”，而是：是否存在一个高频、昂贵、可明确验收的任务；现有方案是否受制于 API 成本、隐私或延迟；客户是否愿意提供数据并承担持续维护。只有这三点同时成立，小模型才可能从一次性的技术项目，变成可复制的产品。

## 通俗精炼（1）

### 2026-09-18 10:36:27

#### 定制小模型可能成为 SaaS 之外的新变现路径

作者认为，通用软件的功能、广告和定位越来越容易被复制，单靠 SaaS 产品建立壁垒正在变难；新的机会是为企业特定场景微调小型语言模型（SLM），并像软件一样授权和持续维护。不过，“软件变现已死”是作者的激进判断，并非已被验证的行业结论。

##### 小模型用专用能力换取成本与控制力

SLM 通常指参数规模较小的模型。作者建议针对具体任务微调 0.5B～12B 参数模型：从准备数据集、训练 LoRA 适配器，到导出为 GGUF、MLX 等本地部署格式，越来越多环节可由更强的通用模型辅助完成。

作者声称，经过微调的小模型在特定任务上可以超过最先进的通用模型，同时降低约 95% 的 API 成本、将速度提升 5 倍，并支持私有化部署。其核心价值不是“更通用”，而是在边界清晰的场景中提供更低成本、更快响应和更强的数据控制。

##### 商业模式更像“模型定制服务”，尚未证明可规模化

作者称自己一年内微调了 20 多个模型，并服务过 15 家以上主动联系他的企业；其中约 90% 提供了工作或合同，金额为 1万～5万美元，需求主要是基于企业私有数据训练并在本地运行模型。

这些案例说明企业确有定制和维护需求，但目前更接近高客单价咨询与交付，而非成熟的标准化模型订阅。评论区也追问其是否真正售出过 SLM 订阅，原文没有给出答案。因此，机会可能真实存在，但可复制性、维护成本和规模化授权能力仍待验证。
