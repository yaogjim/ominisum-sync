## 分析要点

- **核心高价值点**：将规则明确、要求稳定的代码审查环节交给确定性程序，只让智能体处理上下文推理与业务歧义，可降低成本并改善信噪比。
- **留存建议**：浏览核心架构与仓库实现，作为AI代码审查工具选型资料保留（包含可迁移的人机分工架构，并提供可进一步验证的开源仓库。）

**知识要点**

- 混合式代码审查可由确定性程序负责文件覆盖、打包、规则匹配和评论定位，由智能体负责仓库上下文与语义推理。
- 官方200个PR基准显示，该工具以较低召回率为代价，换取更高精度、F1和约九分之一的Token消耗。
- 大型、多文件PR可能暴露稳定性与缺陷问题，基准结果不能直接替代真实项目验证。

**行动项**

- 在同一批真实PR上对比Open Code Review、Claude Code或现有审查工具的精度、召回率和Token成本。
- 优先使用包含大量文件的大型PR进行压力测试，并检查开源仓库中的未解决问题。
- 评估现有代码审查流程中哪些环节可固定为规则引擎，哪些环节确实需要模型推理。

#### 阿里开源代码审查工具：规则系统保确定性，智能体负责推理

阿里巴巴开源了 Open Code Review。据其介绍，该工具已在内部服务数万名开发者、发现数百万个缺陷。核心思路不是把代码审查全部交给大模型，而是让传统程序与 AI 分工，以降低成本并提高结果的准确性和可定位性。

##### 混合架构避免让大模型包办一切

确定性代码负责文件覆盖、内容打包、规则匹配和评论定位等可由规则稳定处理的任务；智能体则用于理解代码仓库上下文、分析改动影响和判断业务逻辑问题。这种设计旨在把模型能力集中于需要推理的环节，减少 token 消耗与无效评论。

##### 精度和成本占优，但漏检更多

阿里在覆盖 50 个开源仓库、包含 200 个 PR 的基准测试中报告：使用相同模型时，Open Code Review 的精度和 F1 均高于 Claude Code，token 消耗约为后者的九分之一。不过其召回率较低，意味着误报可能更少，但也可能漏掉更多问题。相关结论来自项目方测试，仍需更多独立验证。

##### 开源带来替代可能，工程成熟度仍待观察

该项目可能成为 CodeRabbit、PR-Agent 等自动审查产品的开源替代方案。但有试用者反馈，它在包含大量文件的大型 PR 中仍存在较多问题，代码仓库内也有未解决的 issue。其方向体现了一个实用原则：规则引擎处理确定任务，大模型处理语义和影响面判断；真正落地时仍需权衡覆盖率、成本、信噪比与大型项目稳定性。
