## 正文

**Barret李靖**

研究了一下过去几年芯片和算力的供给情况。目前，市场上大约有 2000 万张 H100 等效卡的算力。按 Token 计算，年消耗量已经达到几十万亿亿 Token，相比去年增长了接近一个数量级。

过去三年，AI 芯片的算力供给每年大约增长 3 倍。但考虑到卡的数量增加、单卡性能提升，以及推理效率不断优化，实际能够对外提供的 Token 算力，年增长幅度可能接近 10 倍。

从 Chat 到 Coding，再到 Agent，每次产品形态升级，都会带来一轮新的需求增长。早期的 Chat，一次推理可能只需要几千 Token；到了 Coding，用户通过 Agent 完成一项任务，一次可能消耗几十万到几百万 Token；而 Agent 需要处理更长的上下文、调用工具，并进行多轮推理和验证，复杂任务的消耗可能达到千万甚至上亿 Token。

按照这个趋势，未来 Token 的需求大概率仍会保持指数级增长。那市场上会不会出现 Token 供不应求的情况？答案是会，而且现在其实已经长期处于紧平衡状态。需求突然上升时，市场通常会通过价格和延迟来调节：高价模型先涨价，低价模型则出现排队，同时也会有更多算力从训练逐步转向推理。

Token 的供给可以从四个层面来看：

1）电力和数据中心。这是最慢的一层。一个大型数据中心从电力指标、选址建设到最终投产，通常需要两三年。

2）芯片供给。Nvidia、Google、AMD 等厂商都在持续扩大产能，同时新一代芯片的性能也在不断提升。

3）模型和推理效率。同样一张卡，通过量化、缓存、推测解码等技术，可以生成更多 Token，单位算力的产出还会继续提高。

4）算力分配。目前仍有大量算力用于训练、RL 和各种实验。随着推理需求继续增长，部分存量算力会逐步从训练转向对外提供 Token。

从这个角度看，未来的 Token 可能会越来越像今天的电力和带宽。算力供给每增加一轮，很快就会有新的应用把这部分增量消耗掉。Chat 吃掉了第一波，Coding 吃掉了第二波，接下来 Agent 还会继续消耗新增的算力。

## 结构化（1）

### 2026-09-17 03:16:51

#### AI Token 算力：供给十倍增长，仍难追上 Agent 需求

作者判断，过去三年 AI 芯片和推理效率快速提升，使可对外提供的 Token 算力每年可能增长近 10 倍；但从 Chat、Coding 到 Agent，单次任务的 Token 消耗也在急剧上升，因此市场已长期处于供需 “紧平衡”。

##### 算力供给快速增长

据作者估算，目前市场约有**2000 万张 H100 等效卡**的算力，Token 年消耗量已达到 “几十万亿亿” 级，较上年增长接近一个数量级。

过去三年，AI 芯片算力供给每年约增长**3 倍**。如果再考虑以下因素，实际 Token 产出能力的年增幅可能接近**10 倍**：

- 芯片数量增加；
- 单卡性能提升；
- 量化、缓存、推测解码等推理优化，让同一张卡生成更多 Token。

##### 产品升级推动需求成倍放大

AI 产品每升级一种形态，完成任务所需的 Token 都会大幅增加：

- **Chat（聊天）**：一次推理通常只需几千 Token；
- **Coding（编程）**：通过 Agent 完成任务，一次可能消耗几十万至几百万 Token；
- **Agent（智能体）**：需要读取更长上下文、调用工具，并进行多轮推理和验证，复杂任务可能消耗千万甚至上亿 Token。

因此，作者认为未来 Token 需求大概率仍将呈指数级增长，新增算力很快就会被新应用消耗掉。

##### 市场处于紧平衡，靠价格和等待时间调节

作者认为，Token 供不应求不仅可能发生，实际上已经长期存在。当需求突然上升时，市场通常通过三种方式缓解：

- 高价模型涨价；
- 低价模型排队、延迟增加；
- 更多算力从训练、强化学习（RL）和实验转向推理服务。

##### Token 供给受四个层面制约

1. **电力和数据中心**  
   这是扩张最慢的环节。大型数据中心从获取电力指标、选址建设到投产，通常需要**两三年**。

2. **芯片产能与性能**  
   Nvidia、Google、AMD 等厂商持续扩大产能，新一代芯片也在提升单卡性能。

3. **模型和推理效率**  
   量化、缓存、推测解码等技术能提高单位算力的 Token 产出，仍有进一步优化空间。

4. **现有算力的重新分配**  
   当前大量算力仍用于训练、强化学习和实验。随着推理需求上升，一部分存量算力可能转向对外提供 Token。

##### Token 可能成为类似电力和带宽的基础资源

作者将未来 Token 类比为今天的电力和带宽：供给每扩张一轮，都会迅速催生或满足新的应用需求。Chat 消耗了第一波增量，Coding 消耗了第二波，而 Agent 很可能继续吸收后续新增算力。

## 深度解读（1）

### 2026-09-17 03:23:22

#### 真正稀缺的不是 Token，而是 “可接受成本下的有效推理”

这篇文章最有价值的地方，不是 “算力仍然短缺” 这个结论，而是把供给拆成了四个速度不同的变量：**电力与数据中心、芯片数量与性能、推理效率、训练和推理之间的算力分配**。这能修正一个常见误解：芯片出货量并不等于市场实际可用的 Token 供给。硬件增加、单卡升级、量化与缓存优化、存量算力迁移会叠加，最终产能可能远快于卡数增长。

不过，文中的 “约 2000 万张 H100 等效卡”“年消耗几十万亿亿 Token”“有效供给年增近 10 倍” 等数字没有给出来源和计算口径，量级也值得核验。因而更适合把它看成一个**供需分析框架和趋势主张**，而不是可靠的市场测算。

##### Agent 改变的不是调用次数，而是单个任务的计算预算

从 Chat 到 Coding，再到 Agent，需求增长的关键并非用户数，而是一次任务允许消耗多少推理。聊天通常是一问一答；编程 Agent 会读代码、修改、运行测试、根据报错重试；更复杂的 Agent 还要搜索、调用工具、维护长上下文并验证结果。**产品每向 “代用户完成任务” 迈进一步，计算过程就从一次生成变成一条不确定长度的执行链。**

这解释了为什么推理效率提升未必降低总需求。单位 Token 变便宜后，产品会使用更长上下文、更多候选方案和更多验证轮次，以换取更高的任务成功率。这类似带宽升级后视频清晰度和使用时长同步增长：效率节省很快被新用法吸收。

但 “Agent 必然带来指数级需求” 仍缺少一个关键前提：任务创造的价值必须覆盖推理成本。千万乃至上亿 Token 的任务，只有在能替代高成本劳动、提升高价值决策质量，或被大量复用时才成立。否则，价格上涨、延迟增加和失败率都会让用户退回人工流程或更轻量的模型。

##### 产品竞争会从模型能力转向计算预算管理

因此，Token 不会完全像电力那样成为同质商品。相同数量的 Token，经过不同模型、上下文组织和验证流程，产生的结果价值可能相差很大。对产品更重要的指标不是 “每百万 Token 价格”，而是**完成一个可信任务需要多少成本、时间和人工介入**。

这会形成一类明确但需要验证的产品机会：在模型与业务任务之间管理计算预算，例如模型路由、上下文压缩、缓存、循环终止、失败恢复和结果验证。客户是推理费用已经显著影响毛利或响应时间的 AI 产品团队；现有替代方案是工程团队自建规则与监控。真正需要验证的不是能否减少 Token，而是：**在不降低任务成功率的情况下，能否稳定降低单次有效完成成本。**

文章最终提醒的是，未来的瓶颈可能不断迁移：短期卡在模型和调度，中期卡在芯片，长期卡在电力和数据中心。对产品决策而言，与其押注 Token 永久短缺，不如持续追踪一个更可靠的变量 —— 新增算力究竟被哪些能产生足够经济价值的任务消耗掉。

- **算力分配**可在训练、强化学习、实验与推理之间调整。
