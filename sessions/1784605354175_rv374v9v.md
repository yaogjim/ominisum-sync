#### OpenChatCut 是什么

OpenChatCut 是 **开源 ChatCut 替代方案** ：把 **对话式 Agent** 和 **专业时间线编辑** 放在同一工作区的 AI 视频编辑器。独立开源（AGPL），与商业版 ChatCut 无隶属关系。

**OpenChatCut = 本地视频工程 + 多轨时间线 + AI Agent + MCP + 可交付导出。**

它不是只生成一段不可修改的视频。每次编辑都会落到真实工程中的轨道、片段、转场、字幕、特效和素材上；你可以继续手动调整，也可以撤销、重做、保存版本或交给另一个 Agent 接着完成。

它适合希望让 AI 真正参与剪辑流程、同时保留专业编辑控制权的创作者和开发者，而不是每次都从一个空白聊天框或不可修改的生成结果重新开始。

传统编辑器擅长精细操作，一次性 AI 生成器擅长快速出片。OpenChatCut 把两者连成同一个可持续编辑的工程：

能力 传统时间线编辑器 一次性 AI 视频生成 **OpenChatCut**

精确到轨道和片段 ✅ ❌ **✅**

修改可检查、可撤销 ✅ 通常不可 **✅**

文字稿与画面联动 部分支持 ❌ **✅**

Codex / Claude Code 直接操作 ❌ ❌ **✅ MCP**

本地工程与 BYOK 视产品而定 通常云端 **✅**

核心编辑循环：

```
描述目标 → Agent 读取工程 → 生成可验证编辑 → 写入时间线
         → 预览 / 调整 / 撤销 → 字幕与混音 → 导出
```

#### 典型使用场景

- **口播与访谈精剪** ：转写音视频，按文字删除口误、停顿和冗余内容，再自动生成字幕。
- **多素材快速成片** ：导入视频、图片和音频，让 Agent 完成粗剪、转场、配乐和节奏调整。
- **短视频与社交内容** ：重构画幅，生成标题、字幕、旁白、音乐和视觉包装。
- **Motion Graphics** ：使用内置模板或让 Agent 生成可继续编辑的动态图形片段。
- **开发者自动化** ：通过 MCP 让 Codex、Claude Code 或其他兼容客户端读取并修改真实工程。

#### 使用流程

1. 创建工程并导入本地素材。
2. 在时间线上手动剪辑，或直接描述想要的结果。
3. Agent 读取工程上下文并调用编辑工具。
4. 检查提案、预览画面，再应用、调整或撤销。
5. 完成字幕、音频、特效和色彩处理。
6. 导出视频、音频、字幕、FCPXML 或完整工程。

#### 快速开始

##### 桌面安装包

从 [GitHub Releases](https://github.com/0xsline/OpenChatCut/releases/latest) 下载最新的 macOS 与 Windows 构建。目前提供 Apple Silicon、Intel Mac 的 DMG，以及 Windows x64 安装包。

这些仍是早期构建。macOS 安装包尚未签名和公证，首次启动时可能需要在系统设置中手动允许。

##### 从源码运行

需要 Node.js 24.x 和 npm。 `package.json` 会约束支持的 Node.js 范围，`.nvmrc` 可供 Node 版本管理器直接选择对应主版本。

```
git clone https://github.com/0xsline/OpenChatCut.git
cd OpenChatCut
npm install
cp .env.example .env.local
npm run dev
```

打开：

```
http://localhost:5199
```

`.env.local` 中只需填写你实际使用的模型或素材服务。没有配置的第三方能力会明确提示缺少对应 Key，不影响本地时间线编辑、内置素材和已配置的其他能力。

本地 H.264 导出会在 macOS 上优先使用 VideoToolbox，在兼容的 Windows 设备上优先使用 NVENC，失败时自动回退软件编码。可用 `OPENCHATCUT_RENDER_CONCURRENCY` 和 `OPENCHATCUT_MAX_ACTIVE_EXPORTS` 调整渲染并发及重型导出上限，用 `OPENCHATCUT_DISABLE_HARDWARE_ENCODING` 关闭硬件编码，或用 `OPENCHATCUT_H264_ENCODER` 覆盖 FFmpeg 侧的编码器选择；详见 `.env.example` 。

##### 桌面端开发

```
npm run desktop:dev
```

桌面端使用 Electron 壳层和同一套内嵌服务，Web 开发版与桌面版共享工程、Agent、生成和导出逻辑。

#### 项目状态

OpenChatCut 目前处于积极开发阶段，编辑器、工程格式和 Agent 工具仍会持续迭代。预构建的 macOS 与 Windows 安装包已发布到 [GitHub Releases](https://github.com/0xsline/OpenChatCut/releases) ；开发和排障时，从源码运行仍是最透明的方式。

基础时间线、本地工程、内置素材和手动编辑不依赖云服务。AI 模型、在线素材、生成、转写等联网能力只在你配置对应服务后启用。

---

OpenChatCut 暴露 Streamable HTTP MCP：

```
http://localhost:5199/api/external-mcp/mcp
```

仓库根目录的 `.mcp.json` 已包含本地连接。使用时间线工具前，先运行 OpenChatCut 并打开目标工程；工程列表、创建和定位工具不要求编辑器保持打开。

##### Codex

在 Codex 配置中加入：

```
[mcp_servers.openchatcut]
url = "http://localhost:5199/api/external-mcp/mcp"
```

##### Claude Code

```
claude mcp add --transport http openchatcut \
  http://localhost:5199/api/external-mcp/mcp
```

然后可以直接对 Agent 描述编辑任务：

```
读取当前工程，在第二条音频轨的 8 秒处添加划盘音效，
给相邻视频添加故障转场，检查 1、6、11 秒三帧后导出竖屏 MP4。
```

外部 Agent 调用的仍是编辑器内部同一套工具和 `EditorCore` 命令，不存在两套互相漂移的工程格式。

##### MCP 访问保护

自行暴露 MCP 入口时可配置：

```
OPENCHATCUT_MCP_TOKEN=your-token
OPENCHATCUT_EDITOR_URL=https://your-editor.example.com
```

客户端使用 `Authorization: Bearer <token>` 。当前桥接面按单机单用户设计，不作为多租户服务。

OpenChatCut 运行时架构：Agent、MCP、EditorCore、本地存储、预览与渲染导出

同一套 Agent 工具和 EditorCore 命令连接内置 Agent、外部 MCP、真实时间线、本地数据与交付导出。

`desktop/` Electron 主进程与内嵌服务

`remotion/` 无头渲染和导出管线

#### 数据与隐私

- 工程、聊天记录和版本数据保存在 `~/.openchatcut` 下的本机共享工程库中；IndexedDB 用于浏览器端缓存和旧数据迁移。
- 用户媒体保存在本地素材目录，可自行备份和迁移。
- AI 请求是否离开本机，取决于你配置的模型、生成或素材服务。
- 未配置的云端能力不会影响本地时间线和已有素材编辑。
- 对外开放 MCP 时，应配置 Bearer Token，并限制编辑器入口的网络范围。

---

#### 安全模型

- 密钥只进入服务端配置；浏览器端禁止使用 `VITE_` 暴露供应商密钥。
- LLM 输出、插件包、模板代码和用户输入都在信任边界处校验。
- MG 与 shader 代码进入受限沙箱，恶意模板由专门检查脚本拦截。
- Agent 只经 `EditorCore` 命令改工程，编辑可追踪、可撤销。
- MCP 默认绑定本机；公网入口支持 Bearer Token。
- 本地素材目录和 R2 凭据由服务端管理，不写入工程 JSON。

##### 1. 产品定位

- 定位为 **开源 ChatCut 替代方案**，采用 **AGPL v3.0 或更高版本**，与商业版 ChatCut 无隶属关系。

  **本地视频工程 + 多轨时间线 + AI Agent + MCP + 可交付导出**
- 适合希望 AI 深度参与剪辑、同时保留专业控制权的创作者和开发者。
- 工程和素材优先保存在本机；AI、在线素材和生成能力按需配置，未配置云服务也不影响基础剪辑。

##### 8. Agent 与 MCP 接入

OpenChatCut 提供 Streamable HTTP MCP：

```text
http://localhost:5199/api/external-mcp/mcp
```

使用时间线工具前，需要先启动 OpenChatCut 并打开目标工程；工程列表、创建和定位工具则不要求编辑器一直打开。

###### Codex 配置

```toml
[mcp_servers.openchatcut]
url = "http://localhost:5199/api/external-mcp/mcp"
```

###### Claude Code 配置

```bash
claude mcp add --transport http openchatcut \
  http://localhost:5199/api/external-mcp/mcp
```

外部 Agent 与内置 Agent 调用的是同一套工具和 `EditorCore` 命令，因此不会产生两套相互不兼容的工程格式。

如需对外暴露 MCP，可配置：

```env
OPENCHATCUT_MCP_TOKEN=your-token
OPENCHATCUT_EDITOR_URL=https://your-editor.example.com
```

客户端通过以下请求头认证：

```text
Authorization: Bearer <token>
```

当前 MCP 桥接按 **单机、单用户** 设计，不适合作为多租户服务。

##### 10. 数据、隐私与安全

- 工程、聊天记录和版本数据保存在本机的 `~/.openchatcut`。
- IndexedDB 主要用于浏览器缓存及旧数据迁移。
- 用户媒体存放在本地素材目录，可自行备份与迁移。
- AI 请求是否离开本机，取决于用户配置的模型、生成或素材服务。
- 供应商密钥只进入服务端配置，禁止通过 `VITE_` 暴露到浏览器。

- Agent 只能通过 `EditorCore` 命令修改工程，因此修改可追踪、可撤销。
- MCP 默认仅绑定本机；公网开放时应使用 Bearer Token 并限制网络访问范围。
- 本地素材路径和 R2 凭据由服务端管理，不会写入工程 JSON。

#### OpenChatCut：让 AI 直接参与真实视频剪辑

这份材料介绍了 OpenChatCut，一个开源、优先本地运行的 AI 视频编辑器。听完后，你可以了解它的核心定位、主要功能、使用方式、Agent 和 MCP 能力，以及它在数据隐私、技术架构和项目状态方面的特点。

##### 一、OpenChatCut 是什么

首先，OpenChatCut 的核心结论是：它想把“对话式 AI”和“专业时间线剪辑”放进同一个视频工程里。

通俗来说，用户不只是对着聊天框生成一段不能修改的视频。OpenChatCut 会把每次编辑真正写入工程中的视频轨道、音频轨道、片段、字幕、转场和特效。之后，用户可以继续手动调整，也可以撤销、重做、保存版本，或者让另一个 AI Agent 接着完成。

这里的“Agent”，可以理解为能够读取工程、调用工具并执行编辑任务的智能助手。OpenChatCut 既有内置 Agent，也支持外部 Agent。它还支持 MCP，也就是“模型上下文协议”，一种让 Codex、Claude Code 等外部 AI 客户端访问编辑器工具和工程数据的标准方式。

项目采用 AGPL，也就是 GNU Affero 通用公共许可证，是一个独立开源项目，与商业版 ChatCut 没有隶属关系。

简单概括，OpenChatCut 由几部分组成：本地视频工程、多轨时间线、AI Agent、MCP，以及最终可以交付的视频和工程文件。

##### 二、它有哪些主要能力

接下来，OpenChatCut 的主要能力可以分成几个方面。

第一，是 Agent 原生设计。内置 Agent 和外部 MCP Agent 使用同一套编辑工具。这样，AI 不只是给建议，而是可以真正读取工程、修改时间线，并把结果交给用户检查。

第二，是完整的真实时间线。它支持多条视频轨和音频轨，也支持移动、裁剪、切分、波纹编辑、吸附、关键帧、标记、撤销和重做。关键帧，简单说，就是让某个参数随时间变化，比如让画面逐渐放大，或者让声音慢慢变小。

第三，是文字稿驱动的剪辑。视频转写后，可以精确到词语进行编辑。用户可以直接删掉口误、停顿和多余句子，画面和字幕也能跟着联动。系统还支持说话人识别、查找和片段视图。

第四，是生成和素材管理。它可以处理图片、视频、语音、音乐和音效的生成任务，也支持在线检索图片、视频和音频素材。

第五，是动态图形和视觉特效。动态图形通常简称 MG，指的是标题动画、包装动画和其他运动设计。OpenChatCut 支持动态图形模板、自定义模板，以及基于 WebGL 的视觉效果。WebGL 是一种让浏览器或编辑器利用图形硬件实时显示效果的技术。具体效果包括像素化、双色调、鱼眼、万花筒、柔化和漏光，也支持自定义 shader。Shader 可以理解为控制画面如何计算和呈现的小程序。

最后，是多种交付格式。除了常见的 MP4，还能导出音频、字幕、SRT 字幕文件、FCPXML，以及完整的视频工程数据。FCPXML 是一种用于交换专业视频剪辑工程信息的格式。

##### 三、它如何把传统剪辑和一次性生成结合起来

更重要的是，OpenChatCut 试图解决传统编辑器和一次性 AI 视频生成之间的断层。

传统时间线编辑器擅长精确操作。你可以逐轨道、逐片段地修改，但通常不能直接用自然语言让 AI 修改工程。一次性 AI 视频生成工具则擅长快速出片，但生成结果往往难以检查、撤销或继续精细调整。

OpenChatCut 想把这两种方式连起来。它既保留轨道级和片段级的精确控制，也允许用户用自然语言修改真实工程。每次修改都可以预览、检查、调整和撤销。文字稿和画面能够联动，Codex 和 Claude Code 也能直接操作工程。

它的基本编辑循环是这样的：用户先描述目标，Agent 读取工程，然后生成一个可以检查的编辑提案。提案写入时间线后，用户可以预览、调整或撤销。接着，再完成字幕、混音，最后导出成品。

也就是说，AI 不是一次性替用户“生成完就结束”，而是参与一个可以持续修改的编辑过程。

##### 四、产品中的典型编辑功能

在实际编辑状态下，OpenChatCut 可以管理多个真实工程。用户能够创建、导入、复制、导出工程，也可以之后继续编辑。

在视频画面方面，它支持镜头推拉、慢速推进、快速缩放和缓动效果。缓动指的是让运动的开始和结束更自然，而不是突然加速或停止。

在色彩方面，它支持 LUT。LUT 可以理解为一套预设的色彩转换或风格方案。用户可以比较相机转换效果和胶片风格，并实时查看统一参考画面。

在音频方面，它支持多音轨、音效、背景音乐、旁白录制、响度调整、自动闪避和人声隔离。自动闪避，就是在人声出现时自动压低背景音乐的音量，让讲话更清楚。

在字幕方面，它支持自动字幕、命名样式、翻译、时间线叠加显示，以及 SRT 导出。

在生成任务方面，图片、视频、语音、音乐和音效都可以提交任务，并查看处理进度。

在导出方面，它支持硬件感知的 H.264 加速。H.264 是常见的视频编码格式。在 macOS 上，系统会优先尝试使用 VideoToolbox；在兼容的 Windows 设备上，会优先尝试使用 NVENC。如果硬件编码失败，系统会自动回退到软件编码。

如果从源码运行，需要 Node.js 24 版本系列和 npm。基本步骤是：先克隆项目，进入项目目录，安装依赖；然后复制环境变量示例文件，配置本地环境；最后启动开发服务。开发服务默认在本机的 5199 端口运行，浏览器打开本地地址即可使用。

环境文件中，只需要填写你实际使用的模型或素材服务。没有配置的第三方能力，会明确提示缺少对应的密钥，但不会影响本地时间线编辑、内置素材，以及已经配置好的其他功能。

如果需要调整导出性能，还可以设置渲染并发数、重型导出的最大并发数，也可以关闭硬件编码，或手动指定 FFmpeg 使用的 H.264 编码器。

##### 八、如何连接 Codex、Claude Code 等外部 Agent

OpenChatCut 暴露了一个本地的 Streamable HTTP MCP 接口。简单理解，这个接口允许外部 AI 客户端通过网络请求访问 OpenChatCut 的编辑工具。

仓库根目录已经提供了 MCP 配置示例。连接时间线工具之前，需要先运行 OpenChatCut，并打开目标工程。不过，工程列表、创建工程和定位工程等工具，不要求编辑器始终保持打开。

在 Codex 中，可以把 OpenChatCut 的本地 MCP 地址加入配置。在 Claude Code 中，也可以通过命令添加一个名为 OpenChatCut 的 HTTP MCP 服务。

连接完成后，用户就能用自然语言提出具体剪辑任务，而 Agent 会调用编辑器内部工具完成操作。

如果把 MCP 接口暴露到外部网络，还需要配置 Bearer Token。Bearer Token 可以理解为访问接口时携带的一串身份凭证。同时，还可以设置编辑器访问地址。客户端请求时，需要使用“Authorization Bearer”方式携带这个令牌。

材料特别说明，当前 MCP 桥接面是按单机、单用户设计的，不是面向多租户的在线服务。

##### 九、项目状态和技术架构

目前，OpenChatCut 处于积极开发阶段。编辑器、工程格式和 Agent 工具还会持续迭代。macOS 和 Windows 的预构建安装包已经发布，但在开发和排障时，从源码运行仍然是最透明的方式。

它的基础时间线、本地工程、内置素材和手动编辑，不依赖云服务。AI 模型、在线素材、生成和转写等联网能力，只有在用户配置相应服务之后才会启用。

在技术架构上，前端使用 React 19、TypeScript 6 和 Vite 8。编辑核心采用不可变的时间线状态、命令层和提案式应用机制。内置 Agent 使用 Vercel AI SDK 7，并兼容多种模型和接口，包括 Anthropic、OpenAI、Gemini、Kimi、Qwen、GLM、DeepSeek、MiniMax、Mistral，以及兼容这些接口的其他服务。

预览和渲染主要使用 Remotion Player、WebGL 和 GLSL。桌面端基于 Electron 43。数据持久化主要使用本机用户目录下的共享工程库，以及浏览器端 IndexedDB 缓存。IndexedDB 是浏览器保存本地数据的一种机制。导出则使用 Remotion、FFmpeg 和 FCPXML 等技术。

##### 十、数据隐私和安全设计

在隐私方面，项目采取“本地优先”策略。

工程、聊天记录和版本数据，默认保存在本机用户目录下的 OpenChatCut 工程库中。用户媒体保存在本地素材目录，也可以自行备份和迁移。

AI 请求是否离开本机，取决于用户配置的模型、生成或素材服务。没有配置的云端能力，不会影响本地时间线和已有素材编辑。

密钥只进入服务端配置，浏览器端不允许通过以“VITE_”开头的变量暴露供应商密钥。LLM，也就是大语言模型，生成的内容、插件包、模板代码和用户输入，都会在信任边界处接受校验。

动态图形和 shader 代码会进入受限沙箱。沙箱可以理解为一个隔离运行环境，用来限制代码能访问的资源。恶意模板还会经过专门的检查脚本拦截。

Agent 不能直接随意改写工程，而是必须通过 EditorCore 命令进行修改。这样，编辑行为可以追踪，也可以撤销。MCP 默认绑定本机；如果开放到公网，则应配置 Bearer Token，并限制编辑器入口的网络范围。

此外，本地素材目录和 Cloudflare R2 凭据由服务端管理，不会写入工程 JSON 文件。R2 是一种可选的云端对象存储服务。

如果参与开发，项目建议在提交前完成类型检查、自动化测试、代码检查和生产构建。核心命令包括 TypeScript 类型检查、npm test、npm run lint，以及 npm run build。

##### 最后，记住这五点

第一，OpenChatCut 是一个开源的 AI 视频编辑器，重点不是一次性生成视频，而是让 AI 直接参与一个真实、可持续编辑的工程。

第二，它把自然语言 Agent、多轨时间线、文字稿剪辑、字幕、音频、动态图形、特效和多种导出格式放在同一个工作区里。

第三，它支持 MCP，因此 Codex、Claude Code 等外部 Agent 也能读取和修改真实工程，并且使用的是编辑器内部同一套工具。

第五，项目仍在积极开发中。虽然已经提供 macOS 和 Windows 安装包，但编辑器、工程格式和 Agent 工具还会继续变化，开发者从源码运行和参与贡献，仍然是项目的重要使用方式。

## 深度解读（1）

### 2026-09-18 00:25:37

#### OpenChatCut 的真正价值：让 Agent 操作工程，而不是生成结果

OpenChatCut 最值得关注的，不是“用一句话剪视频”，而是它把 AI 的输出对象从**一段成品视频**改成了**一组可检查、可撤销的工程操作**。Agent 添加的片段、字幕、转场、关键帧和音轨都会进入真实时间线，用户可以继续手调，也能交给另一个 Agent 接手。

这看似是实现细节，实际决定了 AI 能否进入专业工作流。

##### 可编辑状态，才是专业 Agent 的基础设施

一次性生成工具擅长快速得到“像样的结果”，但修改成本很高：用户通常只能重新描述、再次生成，并期待模型不要破坏已经满意的部分。视频越长、素材越多，这种交互越不可控。

OpenChatCut 采用了更可靠的路径：让内置 Agent、外部 MCP Agent 和人工编辑共用同一套 EditorCore 命令。也就是说，“删除第 8 秒的停顿”和用户在界面上执行裁剪，本质上修改的是同一个工程模型，而不是两套容易漂移的状态。

这套设计可以迁移到许多复杂生产工具：设计、音频、CAD、数据分析甚至软件开发。**Agent 真正适合接管的不是界面，而是稳定、细粒度、可组合的命令层；真正需要保存的也不是聊天记录，而是可持续演化的工作状态。**

##### “提案—预览—应用—撤销”比全自动更接近真实需求

README 中一个容易被忽略的能力是“提案式编辑”。对专业用户而言，价值未必来自完全自动化，而是降低高频机械劳动，同时保留最终判断权。转写后删除口误、压缩停顿、生成字幕、整理素材和调整画幅，都比“理解什么内容值得留下”更适合先交给 Agent。

因此，它更可能首先在口播、访谈和社交视频中成立：这些场景规则相对明确、重复劳动多，结果也容易逐段验收。复杂叙事、节奏审美和跨镜头语义仍难靠工具调用解决。功能清单再长，也不能证明 Agent 能稳定做出好的剪辑。

判断产品是否有效，应看几个更实际的指标：提案被直接接受或轻微修改的比例、完成同类任务节省的时间、长工程中的状态一致性，以及失败后能否准确回退，而不是只看“一句话出片”的演示效果。

##### Local-first 同时解决隐私、成本与可接管性

视频素材体积大、渲染昂贵，也常包含未发布内容。工程和素材保存在本机、云端能力按需配置、导出优先使用本地硬件编码，这不仅是隐私卖点，也避开了云端上传延迟和持续算力成本。MCP 则把编辑器变成可被 Codex、Claude Code 等调用的本地能力节点。

不过，目前它仍是早期项目：工程格式和 Agent 工具持续变化，安装包尚未完整签名，MCP 按单机单用户设计，README 也主要证明了架构完整度，而非稳定性和用户需求。AGPL 还会影响商业团队的集成方式。

所以，OpenChatCut 当前最重要的信号不是它已经成为成熟替代品，而是它展示了一条更可信的 AI 应用路线：**对复杂创作工具，竞争壁垒可能不在模型入口，而在可被人和 Agent 共同操作、验证和恢复的工程系统。**
