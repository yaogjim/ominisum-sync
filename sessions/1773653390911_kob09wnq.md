Track your tweets' growth and detect viral moments — inspired by semiconductor ETCH Endpoint Detection.

```
New tweet posted
    │
    ▼
Fast sampling (every 15min for 48h)
    │
    ├── dV/dt spike? ──────── Candidate burst
    │                              │
    │                    3 consecutive? ── ★ BURST CONFIRMED
    │                              │
    │                    RT/view ratio ── Influencer vs Algorithm
    │
    ▼
Normal sampling (hourly)
    │
    └── 6× growth < 2%/h ── Long tail
```

##### Detection Algorithm

Component Method Purpose

**Derivative detection** dV/dt per hour Spot sudden acceleration

**Sliding window** 5-sample moving average Filter noise

**Multi-signal fusion** views×1 + likes×1 + bookmarks×1.5 + RT×3 Weighted composite score

**Burst confirmation** 3 consecutive windows above threshold Prevent false positives

**Surge override** Single window +100%/h Catch massive spikes

**Saturation** 6 samples &lt; 2%/h growth Detect long tail

**Propagation** RT-per-1k-views ratio Influencer vs algorithm driven

- **WeChat search**: Sogou search (direct HTTP, no browser)
- **Tweet discovery**: DuckDuckGo with Camofox Google fallback
- **Chinese platforms**: Direct HTTP for WeChat; Camofox for others

这篇文章介绍了`x-tweet-fetcher`这个开源工具：它能在不登录 X/Twitter、也不用 API Key 的情况下，抓取推文、回复、时间线、长文等内容，并直接输出结构化 JSON，方便 AI Agent 或自动化脚本使用。  
核心价值是 “低门槛 + 可自动化”：一条命令即可获取数据，还支持定时监控、增长分析和多平台扩展。

- **1. 项目定位：解决 X/Twitter 数据获取难题**
  - 作者指出，X 没有免费 API，传统爬虫容易被封，浏览器自动化也不稳定。
  - 这个工具的目标是：用 “单条命令 + JSON 输出” 替代手工复制内容，适合 AI 和脚本直接消费。
  - 特色很明确：`无登录`、`无 API Key`、`零配置`、`适合 cron 定时任务`。

- **2. 主要能力：不只是抓单条推文**
  - 支持抓取的内容很多：
    - 单条推文：文本、点赞、转推、浏览量、媒体等；
    - 回复评论：支持线程化评论树；
    - 用户时间线：最多可分页抓取`200`条；
    - X Articles：抓取长文全文；
    - X Lists：抓取列表推文；
    - `@mentions`监控：适合增量监测新提及；
    - 微信文章搜索：返回标题、链接、作者、日期；
    - 推文发现：按关键词发现相关推文；
    - Google 搜索替代方案：`零 API Key`；
    - 中文平台部分支持：微博、B 站、CSDN、微信；
    - 用户画像分析：还能结合 LLM 做`MBTI`、`Big Five`、话题图谱分析；
    - `X-Tracker`：用于推文增长监控和传播分析。
  - 也就是说，它从 “抓内容” 扩展到了 “搜内容、监控内容、分析传播”。

- **3. 使用方式：CLI 和 Python 都能直接接入**
  - 命令行非常直接，例如：
    - 抓单条推文：`python3 scripts/fetch_tweet.py --url"..."`
    - 抓回复：加`--replies`
    - 抓用户时间线：`--user elonmusk --limit 50`
    - 搜微信文章：`python3 scripts/sogou_wechat.py --keyword"AI Agent"--limit 10 --json`
  - Python 里也能直接导入模块，例如：
    - `fetch_tweet ()`抓推文；
    - `sogou_wechat_search ()`搜微信文章；
    - `discover_tweets ()`按关键词找推文；
    - `camofox_search ()`做无 API Key 搜索。
  - 输出以结构化 JSON 为主，适合程序继续处理，而不只是给人看。

- **4. 自动化设计：对定时任务很友好**
  - 工具专门设计了 cron 友好的退出码：
    - `0` = 没有新内容；
    - `1` = 发现新内容；
    - `2` = 出错。
  - 文中给了几个典型自动化场景：
    - 每`30`分钟检查一次`@mentions`；
    - 每天早上`9`点发现新推文；
    - `X-Tracker`支持双频采样：新推文每`15`分钟采样，全部推文每小时采样。
  - 这意味着它不仅适合手动查询，也适合长期监控和通知。

- **5. X-Tracker：文章里最有特色的分析功能**
  - 这是一个 “推文增长监控” 模块，用来判断一条推文是否进入爆发期，灵感来自半导体中的`ETCH Endpoint Detection`。
  - 它的分析逻辑包括：
    - 看每小时增长斜率`dV/dt`，识别突然加速；
    - 用`5`个样本的滑动平均降噪；
    - 用多信号加权融合：浏览`×1`、点赞`×1`、收藏`×1.5`、转推`×3`；
    - 连续`3`个时间窗超过阈值，才确认 “爆点”，避免误报；
    - 单窗口增长`+100%/h`时直接判定大幅激增；
    - 连续`6`个样本增长低于`2%/h`，视为进入长尾；
    - 用 “每千次浏览的转推数” 判断传播更像是 “达人带动” 还是 “算法推荐”。
  - 关键阈值也写得很清楚：
    - `ETCH_SPIKE_RATE = 0.30`，即`30%/h`触发候选爆点；
    - `ETCH_CONFIRM_COUNT = 3`，连续`3`次才确认；
    - 收藏权重`1.5x`；
    - 转推权重`3.0x`。

- **6. 具体案例：增长报告展示了它的分析结果**
  - 示例报告中，一条推文`my launch tweet`的表现是：
    - 浏览：`4,560 → 11,245`，增长`+146.6%`；
    - 点赞：`40 → 73`，增长`+82.5%`；
    - 收藏：`35 → 88`，增长`+151.4%`。
  - 它识别出的爆点窗口为：
    - 开始：`2026-02-20 12:00`
    - 结束：`2026-02-21 08:00`
    - 持续：`20.0h`
    - 新增浏览：`+4,898`
    - 峰值增速：`103%/h`
  - 最后判断其传播模式为：`混合传播（平均 0.53‰ RT / 千次浏览）`。
  - 这个案例说明，它不只是记录数据，还能给出 “何时爆发、为什么爆发” 的解释。

- **7. 底层实现：不同任务走不同抓取路径**
  - 基础推文抓取主要依赖`FxTwitter`公共 API，无需认证。
  - 回复、时间线、提及监控等复杂场景依赖`Camofox`：这是基于 Camoufox 的 Firefox 变体，具备更强的指纹伪装能力，文中称可绕过 Google、Cloudflare 和多数反爬检测。
