#### smux

单命令 tmux 配置，支持 AI 代理的终端自动化。

- **为你** — 键盘驱动的 tmux 配置，带有 Option 键绑定、鼠标支持和窗格标签
- **针对代理** — `tmux-bridge` CLI 让任何代理能够读取、输入并向任何窗格发送按键
- **代理间** — Claude Code 可以在下一个窗格中提示 Codex，Codex 进行回复。任何能运行 bash 的代理都可以参与。

```
tmux-bridge read codex 20          # read the pane
tmux-bridge type codex "review src/auth.ts"  # type into it
tmux-bridge keys codex Enter       # press enter
```

#### Install

```
curl -fsSL https://shawnpana.com/smux/install.sh | bash
```

This installs:

- **tmux** 如果尚未安装（通过 Homebrew、apt、dnf、pacman 或 apk）
- **tmux.conf** 带有 Option 键绑定、鼠标支持、窗格标签以及极简状态栏
- **tmux-bridge** 用于跨窗格代理通信的 CLI

Everything lives in `~/.smux/`.

#### Keybindings

所有按键绑定都使用 **Option (Alt)** ，无需前缀键。

##### Panes

Key Action

`Option+i/k/j/l` 导航上/下/左/右（无换行）

`Option+n` New pane (split + auto-tile)

`Option+w` Close pane

`Option+o` Cycle layouts

`Option+g` Mark pane

`Option+y` Swap with marked pane

##### Windows

Key Action

`Option+m` New window

`Option+u` Next window

`Option+h` Previous window

##### Scrolling

Key Action

`Option+Tab` Toggle scroll mode

`i/k` Scroll up/down

`Shift+I/K` Half-page up/down

`q` or `Escape` Exit scroll mode

##### Mouse

- Click to select panes
- 拖动以选择文本（自动复制到剪贴板）
- Scroll wheel to scroll

#### tmux-bridge

一个用于跨窗格通信的命令行界面。任何能够运行 bash 的工具都可以使用它——Claude Code、Codex、Gemini CLI 或一个简单的 shell 脚本。

Command Description

`tmux-bridge list` 显示所有带有目标、进程、标签的窗格

`tmux-bridge read <target> [lines]` Read last N lines from a pane

`tmux-bridge type <target> <text>` 在窗格中输入文本（无需按回车键）

`tmux-bridge keys <target> <key>...` 发送按键（Enter、Escape、C-c 等）

`tmux-bridge name <target> <label>` 标记窗格以便于引用

`tmux-bridge resolve <label>` Look up a pane by label

`tmux-bridge id` Print this pane's ID

#### smux：让 tmux 变成 “可被 AI 代理协作操作” 的终端工作台

##### 一句话概括

`smux`是一套开箱即用的`tmux`配置，不只是优化人工操作体验，更重要的是让 AI 代理能够直接跨窗格读取、输入和发送按键，从而实现终端自动化与代理协作。

##### 核心价值

###### 1. 对人：更顺手的 tmux
它提供了一套默认可用的`tmux`配置，特点是：
- 全部使用`Option/Alt`快捷键，不依赖传统前缀键
- 支持鼠标操作
- 支持窗格标签和极简状态栏
- 开箱即用，适合键盘驱动工作流

本质上，它降低了`tmux`的使用门槛，让终端多窗格管理更高效。

###### 2. 对 AI 代理：终端可编程
`smux`自带`tmux-bridge` CLI，任何能运行`bash`的代理或脚本都可以：
- 读取某个窗格内容
- 向某个窗格输入文本
- 发送回车、退出、`Ctrl+C`等按键
- 给窗格命名，方便跨窗格调用

这意味着终端窗格不再只是 “给人看”，也能成为 AI 代理之间协作的标准接口。

###### 3. 对多代理协作：打通工作流
它最有意思的地方在于支持 “代理调用代理”：
- 一个代理可以读取另一个代理所在窗格的输出
- 也可以直接向对方发送任务
- 例如 Claude Code 提示 Codex，Codex 再返回结果

本质上，`smux`把`tmux`从 “终端分屏工具” 升级成了 “多代理协作总线”。

##### 主要功能

###### 快捷键与交互
`smux`提供一套简洁的默认操作：
- 窗格导航、创建、关闭、交换
- 窗口切换
- 滚动模式
- 鼠标选中与自动复制

重点不是功能多，而是默认配置已经足够完整，不需要用户自己重新折腾。

###### tmux-bridge 命令能力
核心命令包括：
- `list`：查看所有窗格
- `read`：读取窗格最近内容
- `type`：向窗格输入文本
- `keys`：发送按键
- `name`：给窗格打标签
- `resolve`：通过标签找窗格
- `id`：获取当前窗格 ID

这些命令让代理、脚本和终端环境之间形成标准化交互方式。

##### 安装与适用环境

###### 安装方式
项目主打 “单命令安装”，会自动安装：
- `tmux`（如果系统里没有）
- 预设好的`tmux.conf`
- `tmux-bridge`

所有内容都放在`~/.smux/`目录中，便于管理。

###### 适用平台
支持：
- macOS（需 Homebrew）
- Linux
- `tmux 3.2+`

此外，还可以通过`npx skills add ShawnPana/smux`给各类 AI 代理补充相关技能，兼容 Claude Code、Codex、Cursor、Copilot 等 40 多种代理。

##### 产品视角看它的意义

###### 它解决的不是 “tmux 配置” 问题
表面上看，这是一个`tmux`配置工具；但更深层看，它解决的是：
- 人与 AI 共用终端的问题
- 多个 AI 代理之间协作的问题
- 终端工作流如何被自动化编排的问题

所以它的价值不在 “配置好不好看”，而在于把终端变成了一个可操作、可协作、可编排的执行环境。

###### 它的潜力在 AI 原生开发工作流
随着 AI 编程代理增多，未来开发者很可能不只操作一个助手，而是同时调度多个不同能力的代理。  
`smux`提供的，正是这种多代理并行协作的基础设施雏形。

##### 总结

###### 适合谁
`smux`特别适合：
- 重度终端用户
- 使用`tmux`的开发者
- 希望让 AI 代理参与终端工作流的人
- 需要多代理协作的 AI 开发场景

###### 最终判断
一句话说，`smux`不只是 “更好用的 tmux 配置”，而是在尝试把终端升级成一个 “人机协同 + 多代理协作” 的操作系统级工作台。
