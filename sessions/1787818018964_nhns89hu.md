## 分析要点

- **核心高价值点**：以本地CLI和既有账户为执行基础，结合tmux持久会话、回环地址绑定与Tailscale私网访问，形成了兼顾代理统一管理、移动控制和凭据私有性的部署架构。
- **留存建议**：建议精读并存档，作为多代理本地控制、移动访问和安全部署的实施参考（包含完整的安装验证流程、代理接入方式、MCP工具目录、远程访问方案及明确的安全边界，具有较强实践和复用价值。）

**知识要点**

- 多种AI编程代理可通过统一控制平面管理，同时继续使用本机仓库、既有CLI、订阅和认证凭据。
- 长期任务通过tmux会话保持运行，MCP工具负责会话查询、消息发送、工件展示、人工输入及带谱系的子代理委派。
- 无认证控制API应仅绑定回环地址，并通过Tailscale等受控私网提供远程访问，不应直接暴露到公共互联网。

**行动项**

- 在非root普通用户下安装控制平面，并分别运行omg computer status与omg doctor验证服务、代理和认证状态。
- 连接至少一个已认证的编程代理CLI，并通过设置界面为支持的代理注册omg.dev MCP。
- 需要手机远程访问时启用Tailscale Serve，同时保持OMG\_HOST为127.0.0.1，避免直接公网暴露。

在终端中运行一个编程代理没问题。但运行五个就不行了：关闭笔记本电脑时它们就会终止，你无法分辨哪个代理卡在等待权限提示上，而且你必须坐在办公桌前才能回应。

omg.dev 将 Linux 主机或 macOS 工作站转变为 Claude Code、Codex、OpenCode、Jcode、Cursor、Grok、fx、Pi 和 GitHub Copilot 的私有控制平面。每个代理都在一个长期运行的 `tmux` 会话中运行，即使断开连接也能存活。会话记录会流式传输到网页界面，您可以将其安装为 PWA——这样您就可以随时查看工作进度、回复提示，并从手机上进行操控。

您自带代理账户。omg.dev 驱动您已拥有并已认证的 CLI 工具。它不转售令牌，也没有自己的模型。

#### Quick start

两种接入方式。两者安装的内容相同，只需在 `PATH` 上放置一条 `omg` 命令，即可为您启动本地控制平面。

```
curl -fsSL https://raw.githubusercontent.com/BennyKok/omg.dev/main/scripts/setup.sh | bash
```

```
bun install --global @omg-dev/cli && omg computer setup
```

然后打开 http://localhost:8766。

npm 包是一个 `omg` 二进制文件。 `omg computer setup` 安装本地控制平面； `omg create` 、 `omg deploy` 和 `omg login` 启动托管应用流程。

无需 omg.dev 账户 — `omg computer setup` 提供纯本地安装。它会获取最新发布版本，写入 `.env` ，并将 omg.dev 作为绑定到回环地址的用户服务启动。在 Linux 上，它还会安装 Bun、 `git` 、 `tmux` 、 `curl` 和 `jq` ；在 macOS 上，这些必须已预先存在。安装目录之外不会有任何更改，也不会启动任何你未要求的守护进程。可选附加功能均为自愿启用。

安装过程是幂等的，且不会询问任何问题，因此可以安全地重新运行，也可以安全地编写脚本。请参阅无人值守安装。

安装位于 `~/omg` ，并以 `omg.service` 身份运行（launchd： `dev.omg.serve` ）。

安装程序会下载一个针对你的操作系统和 CPU 架构预构建的安装包，其中已包含所有依赖，因此无需在你的机器上解析、编译或从 npm 获取任何内容。了解安装包如何保持小巧。

下一步：连接一个编码代理，这样你就有东西可以运行了，然后从你的手机上访问它。

##### Unattended installs

安装程序不会从标准输入读取任何答案，并且所有可选功能在设置相应的环境变量之前都保持关闭状态。它需要宿主机提供的内容：

- 不要以 root 身份运行它。它拒绝 uid 0，因为代理绝不能以 root 身份运行。请使用一个可以 `sudo` 的普通用户。
- Linux 需要 `sudo` 。安装程序会为 `git` 、 `tmux` 、 `curl` 、 `ca-certificates` 和 `jq` 运行 `sudo apt-get` ，并执行 `sudo loginctl enable-linger` ，以便服务在注销后仍然存活。要实现完全无人值守的运行，用户需要免密码的 `sudo` 。如果没有它， `sudo` 会在终端上要求输入密码。
- macOS 不需要 `sudo` 。基础包必须已经存在。添加 `OMG_INSTALL_SYSTEM_DEPS=1` 可让安装程序使用 Homebrew 安装缺失的包，添加 `OMG_INSTALL_BUN=1` 可让它安装 Bun。

控制平面、代理 CLI 和远程访问的无打扰安装：

```
bun install --global @omg-dev/cli
OMG_INSTALL_CLAUDE=1 OMG_TAILSCALE_SERVE=1 TS_AUTHKEY=tskey-auth-... omg computer setup
```

安装程序会传递其环境变量，因此这些变量应设置在 `omg computer setup` 本身，而不是设置在其前面的 `bun install` 上。

将以下提示词提供给编码代理，以便在其运行的机器上安装 omg.dev：

```
Install the omg.dev local control plane on this machine, then confirm it runs.

Command:
  bun install --global @omg-dev/cli && omg computer setup

If bun is not installed, use the installer instead:
  curl -fsSL https://raw.githubusercontent.com/BennyKok/omg.dev/main/scripts/setup.sh | bash

Rules:
- Do not run it as root. It refuses uid 0. Use a normal user that can sudo.
- It asks no questions. On Linux it calls sudo for apt-get and for
  loginctl enable-linger. If sudo needs a password and you cannot supply one,
  stop and report that instead of guessing.
- Do not add flags or environment variables that I did not ask for. Every
  optional feature is off by default and stays off.
- It is idempotent. If it fails, read the error, fix that one thing, re-run.

Verify, and report the output of each:
  omg computer status
  omg doctor

Report the install directory, the service name, the URL, and any agent CLI it
found. Do not claim it works from a successful install alone.
```

`omg doctor` 会从其输出中移除 API 密钥、令牌以及你的主目录，因此代理报告的任何内容都可以安全地粘贴到问题或 Discord 中。

##### Optional extras

所有超出安装目录的外部访问默认处于关闭状态，可以在 omg.dev 已经运行后随时开启。

一个命名的本地 URL。为 UI 提供一个易于记忆的地址，而无需将服务器绑定到任何非回环接口。安装过程会采用最经济可行的方式：

- 如果公共 DNS 名称已经指向 `127.0.0.1` — `local.omg.dev` — 则直接使用，无需 sudo、无需修改 hosts 文件、卸载时无需清理任何内容，且在 macOS 和 Linux 上行为一致。仅当其解析到的每个地址都是回环地址时才可信。
- 否则，可选择添加 `/etc/hosts` 条目，该条目可离线使用，适用于任意名称，但需要 root 权限：

```
OMG_LOCAL_HOSTNAME=omg.local omg setup   # needs sudo: /etc/hosts is root-owned
```

无论哪种方式， `http://localhost:8766` 都能正常工作。 `omg uninstall` 会移除该条目。请注意，浏览器仅将"安全上下文"授予 `https://` 、 `localhost` 和回环 IP — 因此请从 `localhost:8766` 安装 PWA，而不是从 `omg.local` 安装，否则 Service Worker 将无法注册。

远程访问。安装 Tailscale，加入您的 tailnet，并仅通过 HTTPS 在您的 tailnet 内提供 UI 服务：

```
OMG_TAILSCALE_SERVE=1 TS_AUTHKEY=tskey-auth-... omg setup
```

这样你就获得了一个无端口的 `https://` URL，可以从手机直接访问，带有公开有效的证书，且不会暴露到你的局域网或互联网。

#### Why omg.dev?

- 在你代码所在的地方运行代理。会话在你的机器上、你的仓库中、使用你本地的 CLI 和凭据执行——而不是需要保持同步的远程沙箱。
- 自带账户。Claude、Codex、OpenCode、Cursor、Grok、fx、Copilot 和 Pi 都运行在你已有的订阅和密钥上。
- 一个界面管理所有工具。在每个会话中切换代理和模型、恢复工作、响应权限提示，并通过可安装的 PWA 管理项目。
- **在盖子合上后继续运行。** `tmux` 支持的会话在断开连接后仍会持续运行，并在你回来时精确恢复到之前的状态。
- 保持私密。服务器默认绑定到回环地址，设计上通过 Tailscale 暴露，而非公共互联网。
- 带谱系委派。omg.dev MCP 工具会生成子代理，这些子代理在界面中保持可见，继承父级上下文，并回报进度。
- 展示成果。代理可以显示核实媒体、发布可更新的 HTML 仪表板，并将完成的结果发布到 Shipped 动态中。
- 自动化仓库检查。可选的基于 Markdown 定义的代理收集 git、仓库、GitHub、模型或安全上下文，并生成定时报告。

omg.dev 驱动您拥有并认证的代理 CLI。在 Web UI 中打开“设置”→“编码代理”以安装一个代理，检查其二进制路径和认证状态，并将 omg.dev 的 MCP 服务器注册到其中。

#### Security

omg.dev 可在您的机器上启动具有 Shell 访问权限的 AI 代理。控制 API 默认不进行认证，这是设计使然，因为它旨在回环地址上运行，并通过 Tailscale 进行私有访问。

请勿将 omg.dev 直接暴露于公共互联网。在共享访问权限之前，请阅读 SECURITY.md。

omg.dev 是托管版本，由同一作者运营——一台已运行 omg.dev 的云机器，因此无需安装任何内容，也无需配置服务器。它提供免费套餐，且完全可选：上述所有功能无需账户即可永久使用。

一键即可获得已启动 omg.dev Web 界面的工作区。工作区空闲时自动休眠，并在同一 URL 上唤醒。

> 我该选哪个？如果你希望代理直接在你机器上已有的仓库和已认证的 CLI 上工作，那就选择本地安装——这正是 omg.dev 的用途。使用 omg.dev 可以在几秒内试用，或者当你完全不想运行服务器时。全新的托管工作区没有登录任何代理 CLI，代理在你克隆到其中的仓库上工作。实时启动命令是 `omg serve` 。更多详情请参阅 deploy/omg。

`omg` CLI 封装了整个生命周期：

```
omg computer setup                     # install omg.dev (no omg.dev account needed)
omg computer status                    # inspect the local install and pairing
omg computer update                    # update an existing installation
omg computer uninstall                 # remove omg.dev; preserve sessions and config
omg computer uninstall --purge --yes   # also permanently delete local omg.dev data
```

`update` 从不安装缺失的计算机， `uninstall` 将清理工作委托给 omg.dev，而不是猜测它拥有哪些文件。卸载会停止服务并删除其命令、MCP 注册、 `/etc/hosts` 条目和发布文件。共享的依赖项（如 Bun、Tailscale、 `tmux` 和编码代理 CLI）会被保留；源码检出会被保留，除非明确清除。

安装内部同样提供这些操作：

```
omg setup                     # update and re-run idempotent provisioning
omg uninstall                 # remove omg.dev; keep sessions and config for reinstall
omg uninstall --purge --yes   # also permanently delete sessions and config
```

#### Commands

除上述生命周期命令外：

从源码检出目录中，使用 `bun run <command>` （例如 `bun run serve` ）——操作界面完全相同。

运行 `omg doctor` 并粘贴其输出内容。

```
omg doctor          # a fenced block: versions, agents, accounts, server, recent errors
omg doctor --json   # the same facts, machine-readable
```

它回答了通常需要多轮沟通才能从错误报告中确定的问题：哪个版本、存在哪些代理 CLI、是否有账户已连接、服务器是否在运行，以及最近看起来像失败的日志行。即使 omg.dev 出现故障，它也能正常工作——它不需要服务器，而且探测失败会被报告，而不会中止其余操作。

API 密钥、令牌和您的主目录会在打印前被移除，因此输出内容可以安全地粘贴到公开的问题或 Discord 中。

如果会话从未启动， `doctor` 通常能直接指出原因：未安装编码代理，或没有代理已登录。

#### MCP tools

`omg mcp` 与本地 `omg serve` API 通信，并将 omg.dev 的会话工具暴露给任何 MCP 客户端。这些工具驱动本地编码代理会话。它们不会创建或部署应用。优先使用 omg.dev 自己的子代理工具，而不是客户端的通用“生成代理”辅助工具，这样子代理在 UI 中保持可见，继承父级和用户上下文，并能在任何配置的框架上运行。

Area Tools

Sessions `omg_list_sessions`, `omg_find_sessions`, `omg_get_session_tree`, `omg_get_session_messages`, `omg_send_session_message`, `omg_close_session`

Origin delivery `omg_send_to_origin`

Presentation `omg_display_image`, `omg_display_video`, `omg_publish_artifact`, `omg_refresh_artifact`, `omg_delete_artifact`, `omg_ship`

Delegation `omg_create_subagent`, `omg_delegate_to_agent`, `omg_delegate_design_task`, `omg_delegate_backend_task`, `omg_list_subagents`, `omg_reparent_session`

Auto agents `omg_list_auto_agents`, `omg_compose_auto_agent`, `omg_save_auto_agent`, `omg_run_auto_agent`, `omg_delete_auto_agent`, `omg_list_findings`, `omg_update_finding`

Human input `omg_ask_user`, `omg_input`

Catalog `omg_capabilities`, `omg_list_repos`, `omg_list_models`

通过初始任务启动的托管会话会获得一份带版本号的 omg.dev 运行时契约（用于规定何时显示媒体、发布工件、询问用户、委派任务或交付成果）。在旧契约下启动的会话会在界面中标记出来，以便用户关闭并重新启动，从而获取当前的工具目录。

子代理最多可嵌套四级。每个子代理会向其父代理发送 `[subagent progress]` 更新以及一条终端 `[subagent complete]` / `[subagent blocked]` / `[subagent failed]` 消息。

#### Configuration

配置位于 `.env` 中。 **`.env.example` 对每个变量进行了内联说明。**

变量使用 `OMG_` 前缀。以下是大多数人会接触到的变量：

Variable Purpose

`OMG_HOST` 绑定地址。除非你了解风险，否则保持 `127.0.0.1` 不变。

`OMG_PORT` Web UI 和 API 端口。默认为 `8766` 。

`OMG_LOCAL_HOSTNAME` 映射到回环地址的命名本地 URL，例如 `omg.local` 。留空（默认）则跳过 hosts 文件。

`OMG_INSTALL_TAILSCALE` 安装并加入 Tailscale。默认关闭；由 `OMG_TAILSCALE_SERVE` 隐含启用。

`OMG_REPOS_ROOT` 已扫描目录中的 Git 仓库。

`ANTHROPIC_API_KEY` Claude / Pi 流程的可选 API 密钥。

`OMG_<AGENT>_PATH` 覆盖 CLI 的二进制路径（ `OMG_CLAUDE_PATH` 、 `OMG_CODEX_PATH` 、 `OMG_OPENCODE_PATH` 、 `OMG_JCODE_PATH` 、 `OMG_CURSOR_PATH` 、 `OMG_FX_PATH` 、 `OMG_PI_PATH` 、 `OMG_COPILOT_PATH` ）。

`OMG_RELAY_URL` `omg connect` 的中继 WebSocket URL。请参阅 docs/remote-access.md。

`OMG_INSTALL_CHANNEL` 安装渠道： `source` 、 `release` 或 `container` 。通常由安装/部署流程设置。

其他分组：代理特定行为（ `OMG_COPILOT_ALLOW_ALL_TOOLS` 、 `OMG_PI_PROFILE_DIR` — 参见自定义代理配置文件）、中继事件转发（ `OMG_CONNECT_EVENTS*` ）以及后端追踪（ `OMG_TRACE_RETENTION_DAYS` 、 `OMG_TRACE_TRANSCRIPT_*` ）。

后端诊断信息追加到 `data/logs/trace-YYYY-MM-DD.jsonl` （API 计时、转录索引、实时流停滞、发送队列状态）。

每次发布都会为每个平台发布一个捆绑包 — `omg-linux-x64.tar.gz` 、 `omg-linux-arm64.tar.gz` 、 `omg-darwin-x64.tar.gz` 、 `omg-darwin-arm64.tar.gz` — 其中已为该目标平台预装 `node_modules` 。安装程序会下载与您的机器匹配的版本，并完全跳过依赖解析。

首次安装过去需要拉取约 2 GB 并在本地解析依赖图。现在只需 43 MB，且您的机器上无需解析任何内容。有两项内容被移除了：

机器无法执行的构建（667 MB）。npm 通过 `os` 、 `cpu` 和 `libc` 清单字段对平台包进行门控。Bun 在解析 `optionalDependencies` 时遵循 `os` 和 `cpu` ，但不遵循 `libc` ，且没有 `bun install --libc` 可选择退出——因此每次 glibc Linux 安装也会下载 musl 版本的 Claude agent SDK、两种 opencode 变体以及 sharp 的 libvips。

omg.dev 不需要的 agent 运行时（约 1 GB）。Claude、Codex 和 OpenCode SDK 各自捆绑了该 agent 二进制的私有副本，作为没有 CLI 的机器的后备方案。omg.dev 已经优先使用您机器上的 CLI—— `pathToClaudeCodeExecutable` 、 `codexPathOverride` 以及针对 opencode 的 `PATH` 查找——这正是自带 agent 账户的核心理念。因此捆绑副本被移除，您只需安装实际需要的 agents：

```
# from the UI: Settings → Coding agents → Install
OMG_INSTALL_CLAUDE=1 OMG_INSTALL_OPENCODE=1 omg setup   # or headless
OMG_INSTALL_PI=1 omg setup          # pi, plus its provider SDKs
```

这也是托管镜像预装 agents 的方式——相同的精简包，再加上其所需的 agents。Pi 也可按需安装（ `OMG_INSTALL_PI=1 omg setup` ）：它没有单独可安装的二进制文件，其提供商层会拉取 \~115 MB。

`scripts/prune-modules.ts` 在发布时同时执行两项移除操作，并清理遗留的符号链接。为其他平台构建捆绑包之所以可行，是因为 `bun install --os --cpu` 会解析另一个目标的可选依赖，因此 Linux CI 机器可以生成正确的 macOS 捆绑包。

```
scripts/release.sh                                 # neutral bundle + all platforms
LFG_RELEASE_PLATFORMS="linux-x64" scripts/release.sh
LFG_BUNDLE_AGENT_RUNTIMES=1 scripts/release.sh     # keep the bundled agent binaries
LFG_SKIP_PLATFORM_BUNDLES=1 scripts/release.sh     # neutral bundle only
```

平台中立的 `omg-bundle.tar.gz` 仍会发布，当没有匹配的平台捆绑包时，安装程序会回退到该版本——不常见的架构仍可安装，只是会以旧方式在本地解析依赖。

每次发布都会将 `@omg-dev/cli` 、 `@omg-dev/protocol` 、 `@omg-dev/client` 、 `@omg-dev/react` 和 `@omg-dev/app` 发布到 npm——其中最后一个正是独立 Web UI 所运行的完整应用程序。 `@omg-dev/cli` 是控制平面引导程序，同一个 `omg` 用于启动创建、部署和登录操作。React 宿主通过自己的传输层和资源源挂载 `@omg-dev/app` ：

```
npm install @omg-dev/app @omg-dev/client
```

See **docs/embedding.md**.

#### omg.dev：用手机统一操控本地 AI 编程代理

- 不同代理的会话、模型和任务缺少统一入口。

###### 统一管理多种代理

支持 Claude Code、Codex、OpenCode、Jcode、Cursor、Grok、fx、GitHub Copilot 和 Pi，可在同一界面中：

- 创建、恢复和关闭会话。

- 按项目管理并行任务。

- 回复问题和授权提示。
- 管理项目与会话。
- 查看图片、视频、HTML 仪表盘及最终交付成果。

###### 多代理协作与自动化

通过 MCP 工具，主代理可以创建可追踪的子代理，并：

- 继承父任务和用户上下文。
- 实时汇报进度和最终状态。
- 支持最多四层嵌套委派。
- 执行定时仓库、GitHub、模型和安全检查。

##### 产品与技术定位

###### 本地优先，自带账号

omg.dev 不提供模型，也不转售 Token，而是调用用户已经安装、认证或付费订阅的代理 CLI。代码、仓库、凭据和执行环境都留在用户自己的机器上。

- 向下兼容多种现有 CLI 和用户订阅。
- 向上提供会话管理、移动控制、任务委派和成果展示。

- 对普通用户而言，安装、网络与权限配置仍有一定门槛。

omg.dev 可以理解为**“AI 编程代理版的本地任务控制中心”**。它以本地执行、会话持久化、多代理统一管理和手机远程操控为核心，尤其适合已经深度使用 Claude Code、Codex 等工具，并希望让多个代理长期并行工作的用户。

## 结构化（1）

#### 文章主旨

**omg.dev 是一个开源的 AI 编程代理控制平面**：它让 Claude Code、Codex、Cursor、OpenCode 等代理在自己的 Linux/macOS 机器上持续运行，并可通过网页或手机远程查看进度、回复提示和管理任务。它支持完全本地、自托管或可选托管服务，用户继续使用自己已有的代理账户、订阅和 API 密钥。

##### 1. 它解决了什么问题

单独运行一个终端代理很简单，但同时运行多个代理时，会遇到几个问题：

- 合上笔记本或断开终端后，任务可能中断。
- 不容易发现哪个代理正在等待权限确认或用户输入。
- 必须守在电脑前才能回复代理。
- 不同代理需要分别管理，缺少统一入口。

omg.dev 的解决方式是：

- 将每个代理放入长期运行的**tmux 会话**，断开连接后仍继续执行。
- 把会话内容实时传输到 Web UI。
- Web UI 可安装为**PWA**，方便从手机查看和控制。
- 在一个界面中管理多个项目、代理和模型，并恢复历史会话。
- 代理直接在本机代码仓库中运行，使用本机已认证的 CLI，不需要远程沙箱同步代码。

> omg.dev 自身不提供模型，也不转售 Token；它只是驱动用户已经安装和认证的代理 CLI。

---

##### 2. 快速安装与本地运行

有两种安装方式，最终都会提供一个`omg`命令并启动本地控制平面。

```bash
curl -fsSL https://raw.githubusercontent.com/BennyKok/omg.dev/main/scripts/setup.sh | bash
```

或：

```bash
bun install --global @omg-dev/cli
omg computer setup
```

安装完成后打开：

```text
http://localhost:8766
```

###### 本地安装的特点

- **不需要 omg.dev 账户**。
- 默认只绑定回环地址，不对局域网或互联网开放。
- 安装目录为`~/omg`。
- Linux 服务名为`omg.service`。
- macOS 的 launchd 服务名为`dev.omg.serve`。
- 安装程序会下载适配当前操作系统和 CPU 的预构建包，无需本机重新解析或编译依赖。
- 安装过程是**幂等的**：可安全重复执行，也适合脚本化部署。
- 默认不会安装或开启未明确要求的可选功能。

Linux 安装程序可安装 Bun、Git、tmux、curl、jq 等依赖；macOS 默认要求这些工具已提前安装。

---

##### 3. 无人值守安装的要求

安装程序不会从标准输入询问问题，所有可选功能默认关闭，但宿主机需要满足以下条件：

###### Linux

- **不能以 root 身份运行**，安装器会拒绝 UID 0。
- 应使用可执行`sudo`的普通用户。
- 安装器会通过`sudo apt-get`安装依赖。
- 会执行：

```bash
sudo loginctl enable-linger
```

这样用户退出登录后，服务仍能继续运行。

- 如需完全无人值守，用户必须拥有免密码`sudo`；否则安装过程仍会等待输入系统密码。

###### macOS

- 默认不需要`sudo`。
- Git、tmux、curl 等基础工具必须已存在。
- 可通过以下变量允许安装器使用 Homebrew 补齐依赖：

```bash
OMG_INSTALL_SYSTEM_DEPS=1
OMG_INSTALL_BUN=1
```

###### 示例：同时安装 Claude 和 Tailscale 远程访问

```bash
bun install --global @omg-dev/cli
OMG_INSTALL_CLAUDE=1 \
OMG_TAILSCALE_SERVE=1 \
TS_AUTHKEY=tskey-auth-... \
omg computer setup
```

环境变量应设置在`omg computer setup`命令上，而不是前面的`bun install`上。

---

##### 4. 可选的本地域名与远程访问

所有超出安装目录和回环地址的访问能力，默认均处于关闭状态。

###### 本地域名

如果公共 DNS 名称已经解析到`127.0.0.1`，例如`local.omg.dev`，可以直接使用，不需要修改系统文件。

也可以手动设置本地域名：

```bash
OMG_LOCAL_HOSTNAME=omg.local omg setup
```

这会修改`/etc/hosts`，因此需要`sudo`。卸载时，omg.dev 会移除对应条目。

不过，浏览器通常只把以下地址视为安全上下文：

- `https://`
- `localhost`
- 回环 IP

因此安装 PWA 时，应使用：

```text
http://localhost:8766
```

而不是`http://omg.local`，否则 Service Worker 可能无法注册。

###### Tailscale：推荐的远程访问方案

```bash
OMG_TAILSCALE_SERVE=1 \
TS_AUTHKEY=tskey-auth-... \
omg setup
```

这样会得到一个可从手机访问的 HTTPS 地址，特点是：

- 不需要手动开放端口。
- 只在自己的 Tailnet 内访问。
- 使用公开有效的 HTTPS 证书。
- 不会直接暴露到局域网或公共互联网。

###### 实验性中继

在 Tailscale 无法使用时，可连接第三方中继：

```bash
OMG_RELAY_URL=wss://your-relay.example/connect \
omg connect ABC123
```

该连接仅需出站访问，不需要开放入站端口。omg.dev 仓库本身不提供中继服务，但其协议可由其他运营方实现。

---

##### 5. 为什么选择 omg.dev

omg.dev 的核心优势包括：

1. **代理在代码所在位置运行**  
   会话直接使用本机仓库、CLI 和凭据，不依赖远程沙箱。

2. **自带账户与密钥**  
   用户继续使用已有的 Claude、OpenAI、Cursor、GitHub Copilot 等订阅或 API Key。

3. **统一管理多个代理**  
   可在一个 Web UI 中切换代理和模型、恢复任务、回复权限提示。

4. **断开连接后继续执行**  
   依靠 tmux，即使关闭终端或合上笔记本，代理仍能持续运行。

5. **默认私密**  
   服务默认绑定`127.0.0.1`，推荐通过 Tailscale 私有访问。

6. **支持可追踪的子代理委派**  
   子代理会显示在界面中，继承父级上下文，并持续反馈进度。

7. **支持结果展示与交付**  
   代理可以显示图片、视频，发布可更新的 HTML 仪表板，并将成果发布到 Shipped 动态。

8. **支持自动化仓库检查**  
   可通过 Markdown 定义自动代理，定期收集 Git、GitHub、模型或安全信息并生成报告。

- 检查认证状态。
- 为支持的代理注册 omg.dev MCP 服务。

安装器检测到 Claude 和 Codex 后，会自动完成对应 MCP 设置。Copilot 和 Pi 没有 MCP 注册入口；fx 会在 ACP 会话启动时直接接收 MCP 服务。

##### 7. 安全原则

omg.dev 可以启动具有 Shell 权限的 AI 代理，因此安全边界非常重要。

- 控制 API **默认没有认证机制**。
- 这是因为它设计为只监听回环地址，并由 Tailscale 等私有网络保护。
- **绝对不要在没有额外认证的情况下直接暴露到公共互联网。**
- 与他人共享访问前，应先阅读项目的`SECURITY.md`。

建议保持默认配置：

```text
OMG_HOST=127.0.0.1
```

如需远程控制，优先使用 Tailscale，而不是直接把`8766`端口映射到公网。

##### 8. 本地安装与托管服务如何选择

项目提供两种使用模式：

###### 本地安装

适合以下需求：

- 希望代理直接操作本机已有仓库。
- 已经在本机登录 Claude、Codex、Cursor 等 CLI。
- 希望数据和会话留在自己机器上。
- 愿意自行运行本地服务。

###### omg.dev 托管服务

托管版本由同一作者运营，特点包括：

- 无需本地安装或配置服务器。
- 提供免费套餐，且完全可选。
- 一键创建带 Web UI 的工作区。
- 工作区空闲时自动休眠，再次访问同一 URL 时唤醒。
- 新建工作区默认没有登录任何代理 CLI，需要用户自行配置。
- 代理只会操作克隆到托管工作区中的仓库。

本地功能无需注册账户即可永久使用；托管服务只是方便用户快速试用或免去运维。

##### 9. 生命周期管理命令

`omg` CLI 封装了安装、更新、检查和卸载流程：

```bash
omg computer setup
omg computer status
omg computer update
omg computer uninstall
omg computer uninstall --purge --yes
```

含义分别为：

- `setup`：安装本地 omg.dev。
- `status`：查看安装状态和配对信息。
- `update`：更新已有安装，不会自动安装缺失的实例。
- `uninstall`：卸载程序，但保留会话和配置。
- `uninstall --purge --yes`：永久删除本地会话和配置。

安装目录内部也提供较短的命令：

```bash
omg setup
omg uninstall
omg uninstall --purge --yes
```

卸载时会清理：

- omg.dev 服务与命令。
- MCP 注册。
- `/etc/hosts`条目。
- 发布文件。

但会保留共享依赖，例如：

- Bun
- Tailscale
- tmux
- 编程代理 CLI

源码检出目录通常也会保留，除非明确要求清除。

##### 10. 故障诊断：`omg doctor`

遇到问题时，可运行：

```bash
omg doctor
```

或获取机器可读的 JSON：

```bash
omg doctor --json
```

它会集中报告：

- omg.dev 版本。
- 已安装的代理 CLI。
- 哪些代理账户已连接。
- 服务是否正在运行。
- 最近疑似失败的日志。
- 二进制路径和环境状态。

该命令不依赖 omg.dev 服务器正常运行；即使部分探测失败，也会继续检查其他项目。

为方便公开反馈问题，输出前会自动移除：

- API Key
- Token
- 用户主目录路径

如果会话从未启动，`doctor`往往可以直接指出原因，例如：

- 没有安装任何编码代理。
- 已安装代理，但尚未登录账户。

##### 11. MCP 工具与子代理能力

`omg mcp`会连接本地`omg serve` API，并向支持 MCP 的客户端提供会话管理能力。

主要工具类别包括：

| 类别 | 能力 |
|---|---|
| 会话 | 列出、查找、读取、发送消息、关闭会话 |
| 结果交付 | 将结果发送回原始任务 |
| 内容展示 | 显示图片 / 视频、发布和更新工件、发布成果 |
| 任务委派 | 创建子代理、委派设计或后端任务、调整会话层级 |
| 自动代理 | 创建、运行、保存和删除定时代理 |
| 人工输入 | 主动向用户提问或请求输入 |
| 资源目录 | 查询仓库、模型和系统能力 |

项目建议优先使用 omg.dev 自己的子代理工具，而不是客户端提供的通用 “生成代理” 功能，因为前者能够：

- 在 Web UI 中保持可见。
- 继承父代理和用户上下文。
- 持续向父代理报告进度。
- 在不同代理框架上运行。

子代理最多可嵌套**4 级**。执行过程中会向父代理发送：

```text
[subagent progress]
```

结束时则会发送以下状态之一：

```text
[subagent complete]
[subagent blocked]
[subagent failed]
```

##### 13. 安装包体积优化

旧版首次安装需要下载约**2 GB**，并在用户机器上解析依赖；目前预构建包只需约**43 MB**，且无需本地解析依赖。

主要移除了两类内容：

1. **当前机器无法执行的平台构建：约 667 MB**  
   例如 glibc Linux 安装中可能被额外下载的 musl 版本、不同平台的 OpenCode 变体和 Sharp/libvips。

2. **omg.dev 不需要的代理运行时：约 1 GB**  
   Claude、Codex、OpenCode SDK 原本各自包含代理二进制副本。由于 omg.dev 的理念是优先使用用户本机已有的 CLI，这些重复运行时被移除。

每次发布会提供四种预构建包：

```text
omg-linux-x64.tar.gz
omg-linux-arm64.tar.gz
omg-darwin-x64.tar.gz
omg-darwin-arm64.tar.gz
```

如果没有匹配当前架构的预构建包，安装器会回退到平台中立的：

```text
omg-bundle.tar.gz
```

此时仍能安装，但需要像旧版一样在本机解析依赖。

## 深度解读（1）

### 2026-09-18 10:17:07

#### omg.dev 的真正价值：把 AI 编程从“聊天”变成可调度的长期任务

omg.dev 没有创造新的编程代理，也不销售模型能力。它解决的是一个更靠近实际工作流的问题：**当开发者同时运行多个代理时，瓶颈开始从代码生成能力转向任务存活、状态识别与人工介入。**

一个代理放在终端里尚可管理；五个代理并行后，开发者需要知道谁已完成、谁在报错、谁正等待权限，以及关闭电脑后任务是否还活着。omg.dev 用长期运行的 tmux 会话保存任务，通过统一网页界面汇集记录和提示，再让用户从手机处理异常。这意味着手机端的核心价值不是“移动编程”，而是成为一个**低频但及时的人工审批与异常处理入口**。

##### 多代理产品需要的是控制平面，而不只是更好的对话框

这个项目最值得关注的设计，是把不同厂商的 Claude Code、Codex、Cursor、Grok 等 CLI 当成可替换执行器，而把会话、委派、进度、产物和人工输入抽到统一层。其 MCP 工具还保留父子代理关系，让子任务的来源和结果在界面中可追踪。

这比简单聚合多个聊天窗口更进一步。真正可持续的多代理体验，至少需要三类状态：

- 任务是否仍在运行，卡在哪里；
- 某个子任务由谁发起，结果应返回给谁；
- 哪些节点必须等待人类授权或补充信息。

README 提到安装包从约 2GB 缩至43MB，也印证了它的定位：删除各 SDK 重复内置的代理运行时，优先调用用户已经安装和认证的 CLI。**控制平面越薄，越可能跨模型存在；但代价是必须持续适配各家不断变化的 CLI、认证和协议。**

##### “本地运行”减少了迁移成本，却没有自动解决安全问题

代码、仓库和凭据留在用户机器上，既避免同步远程沙箱，也能复用现有订阅，这是务实优势。但这个控制平面可以启动拥有 Shell 权限的代理，且 API 本身没有认证，只依赖回环地址和 Tailscale 隔离。它因此成为一个高度敏感的权限汇聚点。

项目拒绝以 root 运行、默认关闭外部访问、诊断信息主动脱敏，这些边界设计是加分项；但如果产品走向团队共享，仅靠网络隔离并不够，还需要身份认证、细粒度授权、操作审计和凭据边界。自行托管也不等于天然安全，安装脚本、依赖供应链和远程控制入口仍需被审查。

##### 更大的机会是“代理运维台”，但需求强度仍待验证

omg.dev 暗示了一类可能成立的产品：面向高频使用 AI 编程工具的人，提供跨代理的任务队列、异常通知、审批、恢复和成果交付。它的竞争对象不只是厂商控制台，也包括 tmux、SSH、通知脚本这些廉价替代方案。

真正应验证的不是“用户是否喜欢手机遥控”，而是：开发者每天有多少并行长任务、等待人工提示浪费了多少时间、移动端介入能挽回多少任务。若这些频率不高，它只是精致的个人工具；若代理逐渐承担数十分钟乃至数小时的自主工作，**统一控制平面就会从便利功能变成必要基础设施。**

## 口播总结（1）

### 2026-09-20 00:21:44

omg.dev 解决的是一个很实际的问题：当你同时运行多个 AI 编程代理时，怎样让它们持续工作，并且能用手机远程查看和操控，而不必一直守在电脑前。

它的定位，是一个开源、可自行托管的 AI 编程代理控制平面。它支持 Claude Code、OpenAI Codex、OpenCode、Cursor、Grok、GitHub Copilot、Pi 等工具。代理仍然运行在你的电脑、你的代码仓库和你已经登录的命令行工具中。omg.dev 不提供自己的模型，也不转售令牌。你使用的，仍然是自己已有的订阅、账号和 API 密钥。

为什么需要这样一层控制平面？单独在终端里运行一个代理，通常没有问题。但同时运行五个代理，管理成本就会迅速上升。你可能不知道哪个代理已经完成，哪个卡在权限确认，哪个正在等待你回答问题。电脑断开连接或合上盖子之后，普通终端任务还可能中止。

omg.dev 的做法，是把每个代理放进一个长期运行的 tmux 会话。tmux 可以理解为不会因为终端断开而消失的后台终端。即使你离开电脑，会话仍能继续运行。之后重新连接时，也能回到原来的状态。

这些会话的输出会实时传到网页界面。这个界面可以安装成 PWA，也就是接近原生应用体验的网页应用。于是，你可以在手机上查看代理进度、回复问题、批准权限请求，或者继续给代理下达任务。一个界面还能管理不同的代理和模型，不必分别盯着多个终端窗口。

这里最重要的设计原则是，代理在代码所在的地方工作。如果代码就在你的工作站上，代理就直接使用本地仓库、本地文件和本机已经认证的命令行工具，而不是把项目复制到一个需要额外同步的远程沙箱。这既减少了同步问题，也保留了原有的开发环境。

本地安装不需要 omg.dev 账户。典型做法是先安装它的命令行工具，再运行“omg computer setup”。安装完成后，可以通过本机的八七六六端口打开网页界面。默认安装目录是用户主目录下的 omg 文件夹，服务会作为当前用户的后台服务运行。

安装程序不会提问，而且可以重复执行。也就是说，如果安装中断，修复具体问题后可以直接重新运行，不容易破坏已有状态。它还会根据操作系统和处理器架构下载预先构建好的安装包，不需要在本机重新解析和编译整套依赖。

这项优化带来的差别很大。旧版首次安装大约需要下载两 GB 内容。现在匹配平台的安装包只有大约四十三 MB。被移除的主要是当前机器无法运行的平台构建，以及 Claude、Codex、OpenCode 等软件开发工具包中自带的代理副本。因为 omg.dev 本来就优先使用用户机器上真正安装并登录过的命令行工具，所以没有必要再附带一套备用代理。

安装时有几个条件必须注意。不要使用 root，也就是最高权限账户运行。omg.dev 会直接拒绝这种做法，因为能够操作 Shell 的 AI 代理不应该拥有系统最高权限。Linux 安装需要一个可以使用 sudo 的普通用户，用来安装 git、tmux、curl 等基础依赖，并允许用户服务在注销后继续运行。macOS 通常不需要 sudo，但相关基础工具需要预先存在，或者明确允许安装程序通过 Homebrew 补齐。

代理账户也需要单独准备。基于 OAuth 的工具，通常要先在终端或浏览器中完成一次登录。使用 API 密钥的工具，则从环境配置中读取对应密钥。安装成功本身，并不代表代理已经可以运行。还要确认至少安装了一个受支持的代理命令行工具，并且相应账户已经登录。

为此，omg.dev 提供了“omg doctor”诊断命令。它会检查当前版本、已经发现的代理工具、账户连接状态、服务器是否运行，以及近期看起来像错误的日志。即使 omg.dev 的服务器已经故障，这个诊断命令仍然可以独立工作。输出前，它会移除 API 密钥、令牌和用户主目录等敏感信息，因此诊断结果可以较安全地粘贴到公开问题或社区讨论中。

除了管理单个会话，omg.dev 还支持通过 MCP，也就是模型上下文协议，让代理创建和管理子代理。它推荐使用自身提供的委派工具，而不是客户端里通用的“生成代理”功能。原因是，通过 omg.dev 创建的子代理会继续显示在统一界面中，继承父代理和用户上下文，并定期向父代理报告进度。

子代理最多可以嵌套四级。任务结束时，它会明确报告完成、受阻或失败。这样，多代理协作不再是几个彼此看不见的后台进程，而是一棵可以追踪来源、上下文和进度的任务树。代理还可以展示图片和视频、发布可更新的网页成果，或者把最终结果放入成果动态中。

不过，远程控制能力也带来了最需要认真对待的风险。omg.dev 可以启动具有 Shell 访问权限的 AI 代理，而它的控制接口默认没有自身的登录认证。这不是疏忽，而是因为它被设计成只绑定到本机回环地址，也就是只允许本机访问。

因此，绝对不要把 omg.dev 直接暴露到公共互联网。官方推荐使用 Tailscale，把电脑和手机加入同一个私有网络，再通过 HTTPS 访问。这样既不需要开放公网端口，也不会把服务暴露给整个局域网或互联网。另一个实验性方案是使用中继，由本机主动建立向外连接，但中继服务并不包含在这个项目中。

如果完全不想维护自己的机器，也可以使用托管版本。托管服务会提供一个已经运行 omg.dev 的云端工作区，空闲时自动休眠，并能在同一个地址重新唤醒。但新的托管工作区不会自动登录你的代理账户，而且代理只能处理你克隆到工作区里的仓库。对于希望直接使用本机代码、本地凭据和现有开发环境的人，本地安装仍然是这个项目最核心的使用方式。

理解 omg.dev，可以记住三个重点。它不是新的 AI 模型，而是管理现有编程代理的控制平面。它通过长期运行的终端会话和手机网页，让多个代理在你离开电脑后仍能持续工作。更重要的是，它默认只信任本机和私有网络；方便远程控制的前提，是绝不能把没有额外认证的控制接口直接开放到公网。
