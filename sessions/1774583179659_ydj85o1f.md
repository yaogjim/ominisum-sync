如何使用 Paperclip 运营一家 AI 代理公司

Paperclip 解决的问题

[@dotta](https://x.com/@dotta)，创作者，正在使用 Claude Code 构建他的公司。他同时打开了 20 或 30 个窗口。

Paperclip 是他用来修复那个的工具。

Paperclip 究竟是什么

![Image](https://pbs.twimg.com/media/HEXAnG1bYAAw4H2?format=jpg&name=large)

一个用于 AI 代理的开源编排层。您定义业务目标，组建代理团队，审批他们的工作，然后他们执行。

可以把它看作是介于“我有一个想法”和“AI 代理正在构建它”之间的那一层。

它不像 Pulsia 那样完全自动化（在 Pulsia 中你只需交出信用卡然后祈祷），也不像管理单个编码标签页那样手动。你从业务目标、组织结构图和任务跟踪的层面进行管理。

步骤 01: 建立你的公司

![Image](https://pbs.twimg.com/media/HEXAyfWbEAARab1?format=jpg&name=large)

命名你的公司。描述它试图实现的目标。创建你的第一个智能体：CEO。

Paperclip 在本地运行时效果最佳。你可以使用自己的模型。Claude Code、Codex、OpenCode：任何一个都适用。

Dotta 的小贴士：为您的 CEO 使用前沿模型。对于更简单的任务，使用更便宜的模型（或者 OpenRouter 提供的免费模型）。

您的 CEO 代理将获得一个默认角色、一个记忆系统以及一个心跳检查清单。

步骤02：理解备忘录问题

![Image](https://pbs.twimg.com/media/HEXA1p7bYAEO2sg?format=jpg&name=large)

这是 Dotta 针对 AI 代理的心智模型：

你的代理就像《记忆碎片》里的那个人。他们醒来时就具备能力，知道如何编程、写作和花钱。但他们不知道自己是谁、在哪里，也不知道应该做什么。

你必须给他们留下宝丽来照片。在他们的手臂上纹身。告诉他们他们是谁以及计划是什么。

这就是核心。当代理唤醒时，它会查看：我是谁，我今天的工作是什么，分配给我的任务有哪些，质量标准是什么。

当代理执行了您不喜欢的操作时，您可以进入心跳配置并添加一条规则。例如：“为每个任务设置成功条件。在关闭前要求 QA 进行审核。”

你以指导员工的同样方式来迭代提示。

步骤 03：招聘你的团队

你的 CEO 雇佣其他员工。工程师。QA。视频编辑。内容策略师。

您批准招聘（或一旦您信任系统，开启自动招聘）

每个代理可以安装不同的技能。技能来自像

skills.sh.安全审计存在但并非万无一失。GitHub 星标是方向性指标，而非保证。

Dotta 自己的 Paperclip 组织：首席执行官、首席营销官、用户体验设计师、首席技术官、质量保证工程师、评估工程师、博主、内容策略师。不同的代理根据任务使用不同的模型。

步骤 04：使用例程处理重复性工作

![Image](https://pbs.twimg.com/media/HEXA9RIbYAEi6Eb?format=jpg&name=large)

例程是可重复使用的问题模板，按计划运行。

每次运行都会被跟踪。你可以查看消耗的 token、代理发现的内容以及它所写的内容。没有不可见的后台任务。

## 通俗精炼（1）

### 2026-03-27 03:44:54

#### 用 Paperclip 搭建 AI Agent 公司的核心思路

##### 一句话总结
Paperclip 本质上是一个面向 AI Agent 团队的“管理层工具”：你不再直接盯单个 AI 干活，而是像经营公司一样，设定目标、搭团队、定规则、做审批，让一群 Agent 协同完成工作。

##### Paperclip 解决了什么问题
当你同时运行大量 AI Agent 时，最大的问题不是“它们不会做事”，而是你很快会失去控制：不知道谁在做什么、做到了哪一步、花了多少 token、结果是否达标。  
Paperclip 的价值，就是把这种混乱的“多窗口 AI 打工”模式，变成可管理、可追踪、可复用的组织化协作。

##### 它到底是什么
它是一个开源的 AI Agent 编排层，介于“我有一个业务想法”和“AI 开始真正执行”之间。  
你可以把它理解为：给 AI 建组织架构、分配角色、设定流程、定义验收标准，并持续监督执行。

##### 怎么运作：像经营公司一样经营 Agent
使用 Paperclip 的核心流程很像搭建一家公司：

###### 1. 先定义公司和 CEO
先明确公司目标，再创建第一个 Agent——CEO。  
CEO 负责理解目标、拆分任务、协调团队。复杂任务可以用更强模型，简单任务可以用更便宜模型，以控制成本。

###### 2. 给 Agent “记忆”和规则
AI Agent 最大短板不是能力，而是缺少持续上下文。  
所以必须明确告诉它：你是谁、负责什么、当前任务是什么、什么叫做好。  
如果 Agent 经常犯某类错误，就把规则写进“心跳检查清单”，让它每次执行前都自查。

###### 3. 按岗位扩张团队
CEO 可以继续招聘工程师、QA、内容策略师、视频编辑等不同角色的 Agent。  
不同 Agent 可以配不同技能、不同模型，形成一个分工明确的 AI 团队。

###### 4. 用例程处理重复工作
对于每天、每周重复发生的任务，可以做成“例程”。  
比如每天检查 GitHub 更新、生成 Discord 公告、汇总进展。  
这样所有执行过程、token 消耗和输出结果都可追踪，而不是黑盒运行。

###### 5. 直接导入成熟团队模板
Paperclip 还支持导入别人已经验证过的 Agent 公司结构。  
也就是说，你不一定要从零设计团队，可以直接拿现成的组织模板、技能配置和角色分工来用，并保持持续更新。

##### 它最重要的认知：AI 会做事，但不懂你的价值观
作者最核心的观点是：  
今天的大模型已经能写代码、写内容、做设计、做规划，但它们并不天然理解你的品味、标准和价值判断。

所以，创始人/管理者的新职责，不再是亲自做每件事，而是：
- 清晰定义目标
- 明确质量标准
- 把价值观写进角色设定、技能和检查规则里

换句话说，未来管理 AI Agent，本质上还是在做管理，只是“员工”变成了 Agent。

##### 目前适合谁
Paperclip 已经被一些早期用户用于：
- 自动化安全审计
- 家庭和个人事务管理
- 销售线索挖掘
- 营销团队协作

这说明它不只是写代码工具，更像一个通用的 AI 组织运行框架。

##### 现阶段的局限
虽然增长很快、关注度很高，但大规模、多 Agent 团队是否真正稳定有效，仍然没有被充分验证。  
尤其是导入大型 Agent 仓库后，实际效果如何，仍需要更多评估和实践。

##### 可直接照着做的行动路径
如果你想上手，可以按这个顺序：
1. 本地安装 Paperclip  
2. 创建你的公司和 CEO Agent  
3. 写清楚 Agent 的身份、职责和质量标准  
4. 先招聘工程师和 QA 两个基础角色  
5. 配置一个高频重复任务的例程  
6. 再尝试导入现成团队模板，加速扩张

##### 最后结论
Paperclip 不是在“替你自动创业”，而是在帮你把 AI 从单点工具升级成一个可运营的组织系统。  
它最有价值的地方，不是让 AI 更聪明，而是让你能像管理公司一样管理 AI。

## 结构化（1）

### 2026-03-27 03:54:26

#### 文章主旨

Paperclip 是一个面向 AI Agent 的开源编排层，核心作用不是“让 AI 自己乱跑”，而是帮助你像管理公司一样管理一群 AI 代理：设目标、搭团队、定规则、做审批。  
这篇文章重点讲了：Paperclip 解决了什么问题、具体怎么搭建一套 AI Agent 公司，以及它目前的应用场景、局限和未来方向。

##### 1. Paperclip 想解决什么问题

- 创作者 Dotta 在用 Claude Code 搭建公司时，会同时开着 **20 到 30 个窗口**。
- 问题在于：  
  - 代理都在并行工作，但他**记不清每个窗口在做什么**；  
  - 周末让它们持续运行，到了周一，**不知道完成了什么**；  
  - token 成本已经花掉，但过程和结果**缺乏可追踪性**。
- Paperclip 就是为了解决这种“AI 在干活，但人无法有效管理”的问题。

**通俗理解：**  
它不是单个 AI 工具，而更像是 AI 公司的“中控台”或“管理层系统”。

---

##### 2. Paperclip 是什么

- Paperclip 被定义为：**AI Agent 的开源编排层**。
- 使用方式是：  
  - 先定义业务目标；  
  - 再组建代理团队；  
  - 对他们的工作进行审批；  
  - 然后让他们执行。
- 它位于“**我有一个想法**”和“**AI 代理真的开始帮我搭建业务**”之间。
- 它既不是完全放手式自动化，也不是纯手工盯着一个个编码标签页操作，而是站在**业务目标、组织结构、任务跟踪**的层面进行管理。

**关键点：**  
Paperclip 的价值，不在于让 AI 更聪明，而在于让 AI 的工作流程更像一家真正可管理的公司。

---

##### 3. 第一步：先建立一家“AI 公司”

- 先给公司命名，并描述它要实现的目标。
- 第一个创建的代理通常是 **CEO**。
- Paperclip **更适合本地运行**，并支持使用自己的模型，例如：  
  - `Claude Code`  
  - `Codex`  
  - `OpenCode`
- Dotta 的建议是：  
  - **CEO 用最强的前沿模型**；  
  - 简单任务交给更便宜的模型，甚至可以用 **OpenRouter 的免费模型**。
- CEO 代理默认会拥有：  
  - 一个角色设定  
  - 一个记忆系统  
  - 一个心跳检查清单

**例子：**  
如果你要做一家内容营销公司，可以先创建一个 CEO，负责拆解目标、招人、分配任务，而不是一开始就让一堆 AI 混乱地同时工作。

---

##### 4. 第二步：理解“备忘录问题”

这是文章里最核心的认知模型。

- Dotta 认为，AI 代理像电影《记忆碎片》里的人：  
  - 醒来后有能力；  
  - 会编程、写作、花钱；  
  - 但**不知道自己是谁、为什么在这、今天该做什么**。
- 所以你必须不断给它“留备忘录”：  
  - 它是谁  
  - 它负责什么  
  - 今天的任务是什么  
  - 成功标准和质量标准是什么
- 当代理行为不符合预期时，你就去修改“心跳配置”，加入更明确的规则。

**文中的具体例子：**  
- 比如增加一条规则：  
  - “每个任务都必须定义成功条件”  
  - “关闭任务前必须经过 QA 审核”

**通俗理解：**  
管理 AI 代理，本质上和带员工很像：  
不是一次性下命令，而是不断补充规则、澄清标准、迭代提示。

---

##### 5. 第三步：招聘你的代理团队

- CEO 可以继续招聘其他角色，例如：  
  - 工程师  
  - QA  
  - 视频编辑  
  - 内容策略师
- 招聘可以由你手动审批；当你足够信任系统后，也可以开启**自动招聘**。
- 每个代理都可以安装不同技能，这些技能可以来自类似 `skills.sh` 的来源。
- 不同代理可以根据任务类型，调用不同模型。

**Dotta 自己的团队配置包括：**
- CEO
- CMO（首席营销官）
- UX 设计师
- CTO（首席技术官）
- QA 工程师
- 评估工程师
- 博主
- 内容策略师

**需要注意：**
- 安全审计功能虽然有，但**并非绝对可靠**。
- GitHub 星标只能算**方向性指标**，不是质量保证。

---

##### 6. 第四步：用例程处理重复性工作

- Paperclip 提供“例程（Routine）”，即**可复用、可定时运行的问题模板**。
- 适合把重复性工作交给代理自动完成。

**文中的具体案例：**
- 每天查看合并到主分支的 GitHub 变更；
- 自动撰写一条 Discord 消息，庆祝社区贡献者；
- 并在**每天上午 10 点**触发。

**它的好处：**
- 每次运行都会被追踪；
- 你可以看到：  
  - 消耗了多少 token  
  - 代理发现了什么  
  - 最终写出了什么
- 没有“看不见的后台任务”，过程更透明。

**核心价值：**  
把 AI 从“偶尔帮忙”升级为“稳定执行日常运营任务”。

---

##### 7. 第五步：导入现成团队，快速复制组织能力

这是文章里比较“有想象力”的部分。

- Paperclip 正在推出“导入/导出公司”的功能。
- 你不仅能自己搭团队，还能直接导入别人已经验证过的团队结构。
- 文中提到的例子包括：  
  - Gary Tan 的 `G-Stack`  
  - 一个有 **60,000 星标、100+ 代理**的 `agency-agents` 仓库  
  - 一个包含创意总监、制作人、技术总监的游戏工作室模板

**这意味着：**
- 你可以直接“雇佣”一个成熟团队到自己的 Paperclip 实例里；
- 技能和代理配置都从远程仓库引用，因此可以持续更新。

**但作者也坦诚指出局限：**
- 这种大规模代理仓库的效果，**目前还没有被充分验证**；
- 缺少大规模评估；
- Paperclip 更像是第一个真正可以拿来测试这些团队结构的运行时平台。

##### 9. 核心观点：AI 能做很多事，但不懂你的价值观

这是全文最重要的判断。

- 作者认为，模型已经能做很多事情：  
  - 编码  
  - 写作  
  - 设计  
  - 规划
- 但它们做不到的是：**天然理解你的品味、价值观和质量标准**。
- 因此，创始人的角色发生了变化：  
  - 不再只是亲自干活；  
  - 而是要把自己的标准讲清楚；  
  - 再把这些标准编码进代理的角色设定、技能和心跳检查清单中。

**一句话概括：**  
AI 代理能执行，但“什么叫好”这件事，仍然要由人来定义。
