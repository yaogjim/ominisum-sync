## 分析要点

- **核心高价值点**：在同一组20任务并发测试中，Ante显著降低内存、CPU和磁盘读取量，同时明确暴露相对Claude Code慢约50%的代价，为低配设备上的Agent选型提供了具体权衡依据。
- **留存建议**：精读关键操作与测试口径，存档供低配环境和多Agent方案选型参考（直接涉及AI编程Agent选型，包含跨Agent调度、本地模型管理、配置复用及资源测试数据，具有明确实践价值。）

**知识要点**

- Ante通过tmux持久会话调度Claude Code与Codex，可让实现、测试等角色并行工作，并允许用户观察和接管终端。
- Ante可兼容AGENTS.md与CLAUDE.md，并通过profile限定工具集合和系统提示词，从而复用既有配置或构造极简Agent。
- 资源效率与任务速度需要联合评估；低内存和低CPU并不必然意味着更快，应同时记录峰值内存、CPU、磁盘读写和墙钟时间。

**行动项**

- 在隔离项目中安装Ante，验证其对CLAUDE.md、AGENTS.md及现有Skills配置的兼容情况。
- 用/term分别启动实现与测试Agent，检验会话持久化、权限审批和人工接管流程。
- 使用自己的典型任务复测内存、CPU、磁盘读写、完成时间和任务质量，再决定是否替换现有CLI。

#### 一、产品与接入：接入成本极低，无缝继承用户的习惯

> 本节结论：安装一行命令、配置零迁移、模型即切即用。

1.1 软件体积大小极小

Ante 是单个约 15MB 的 Rust 二进制，零运行时依赖，无 Node、无 npm。而且每次升级的时候，只显示下载了 12MB 的更新。是真的超级小了。

![Image](https://pbs.twimg.com/media/HPfya__bgAAdf7v?format=jpg&name=large)

1.2 安装

```shell
curl -fsSL https://ante.run/install.sh | bash
```

安装耗时约数秒，产物为单一二进制。安装后在项目目录执行 ante 即可。

![Image](https://pbs.twimg.com/media/HPfywNnbQAAn8jK?format=jpg&name=large)

1.3 配置兼容：零迁移成本

当我们安装一个全新的 Agent 产品的时候，最容易被忽略的细节其实是配置兼容性。Ante 会在项目无 AGENTS.md 时，逐级 fallback 读取 CLAUDE.md（含全局 \~/.claude/CLAUDE.md）；已有的项目规则、skills、subagents 、memory等等配置，无需修改路径或者手工迁移，直接运行 Ante 即可使用，无缝衔接，用起来依然顺手。

![Image](https://pbs.twimg.com/media/HPfzMMTbgAA0alI?format=jpg&name=large)

迁移成本为零，这是其配置设计上最突出的优势。

> 温馨提示：安装运行 Ante 不会删除、修改、移动用户 Claude Code、Codex 以及其他 Agent 原有的 Skill 以及其他配置。

Ante 通过标准 Bash 工具发送 tmux 命令，将会创建一组 ante- 前缀的持久命名会话，并且可以驱动其他 CLI agent，比如 Claude Code、Codex。现在我的日常工作，已经不会直接打开 Claude Code 或者 Codex，都是通过另外一个可以统筹这些 CLI Agent 的 Ante 进行操作。

> 温馨提示：我用的是 Ghostty，所以需要先在 tmux 的环境下运行，这样就可以自动分屏。iTerm 可以直接支持。实际上就算没有直接显示出分屏效果，后台也是真实启动了 Claude Code 跟 Codex 进程的，不影响真正的工作。

具体操作就是直接在 Ante 说：

> 创建两个会话：一个运行 Claude Code 编写实现，一个运行 Codex 补充测试，并监控执行过程。

也可以直接运行下面的命令直接创建对应的窗口。

```text
/term claude
```

两个会话在同一窗口左右并排显示：

![Image](https://pbs.twimg.com/media/HPf0EGEbwAEMpG_?format=jpg&name=large)

![Image](https://pbs.twimg.com/media/HPf0IbZbIAAYiDk?format=jpg&name=large)

在整个多 Agent 协作过程中，里面有很多细节：

- 我使用 /term 打开其他 Agent 窗口：如果 ante 已在 tmux 中运行，将会创建分屏，否则打开一个新的系统终端，比如一个新的 Ghostty 窗口。用户与 agent 共享同一终端，可以看到 agent 敲进去的每一条命令，并随时接管。
- 再次执行 /term 仅关闭视图，会话不中断：Ante 退出并重启后会话仍然存在，运行中的 dev server 不受影响。这样随时可以恢复对话，并且保证所有的任务不会被中断，任务持续进行。
- 方便的安全审批机制：agent 向会话发送的每次按键均需通过标准 Bash 权限审批，不存在绕过审批的通道。

最终花了 1 个多小时完成任务。时间这么长基本上就是 Opus 5 跟 GPT-5.6 Sol 太慢了，现在已经无力吐槽了。

横向结论：目前的终端 agent 里，Claude Code 与 Codex 是顶级大厂的模型专属 Agent，Pi 与 Opencode 是开源自由度的答案。

2.4 Ante 一秒变 Pi —— 可高度定制化的 setting.json

我是第一次见到还能直接通过启动配置直接初始化配置好 Tool、SystemPrompt 的 Agent，这个功能真的十分新颖。

> 最近 Pi Agent 莫名爆火，最核心的就是极度简洁的 Tools 以及 System Prompt。而 Ante 支持一键启动直接讲核心换成 Pi 的核心，关键就是这个配置文件：
>
> [pi.setting.json](https://github.com/AntigmaLabs/ante/blob/main/curated/profiles/pi.settings.json)

```json
{
  "has_completed_onboarding": true,
  "short_prompt": true,
  "tips": false,
  "ambient_thinking_phrase": false,
  "ambient_prompt_suggestion": false,
  "auto_memory": false,
  "skills": false,
  "tools": [
    "Read",
    "Write",
    "Edit",
    "Bash"
  ],
  "system_prompt": "You are a coding agent operating in the current working directory. Be direct and concise: do what is asked, verify it, and report plainly.\n\nYou have four tools: Read, Write, Edit, and Bash. Everything else goes through Bash:\n\n- File search: prefer `rg` when available; fall back to `grep`/`find`.\n- Subagents: spawn one-shot workers with `ante -p \"<task>\"`. For persistent interactive agents (ante, claude, codex), drive them in `tmux` sessions.\n- Web fetch, web search, and large-scale edits: write small programs instead of many manual steps — `curl` for fetching, a script (python, jq, sed/awk) for bulk transformations.\n\nBefore editing, read the surrounding code and match its style. After changing, run the project's build or tests when that is cheap."
}
```

直接保存这个配置文件，然后执行下面的启动命令，直接指定 pi.setting.json 配置文件启动。

```shell
ante --profile pi
```

这个配置文件就是直接规定了，ante 只能使用 Read、Write、Edit、Bash 这个四个极简的工具，以及跟 Pi 一模一样的 System Prompt。

3.1 Agent 执行任务质量：同模型对比第一

先说清楚这是个什么东西。Terminal-Bench 2.1 是一套终端任务集：89 个任务，每个跑 5 遍（共 445 次），全部在容器里执行，由验收脚本判定做没做成。装依赖、改代码、跑测试、看报错再改——这些都是日常真实会遇到的事。

还是不理解 Terminal-Bench 2.1 没关系。我们可以通俗的理解成，大模型是发动机，Agent 是车。这套评测就是固定用 Ante 这辆车，只换发动机，测试每个模型在 Ante 手里能跑出多少分。

3.2 最炸裂的点！优化到极致的资源占用：内存约七分之一，CPU 约九分之一

实测：相同 20 个并行任务、相同容器约束，对 Ante、Claude Code、Opencode 各执行一遍并记录资源。

[![视频](https://pbs.twimg.com/amplify_video_thumb/2087411477787602944/img/lku8SU5mZIeD0p_D.jpg)](https://x.com/LawrenceW_Zen/status/2087464432330768579)[![视频](https://pbs.twimg.com/amplify_video_thumb/2087411477787602944/img/lku8SU5mZIeD0p_D.jpg)](https://x.com/LawrenceW_Zen/status/2087464432330768579)

三个 Agent 执行的完整数据：

最值得看的指标是内存占用：峰值 1968 MiB 意味着 20 个任务并行跑完，Ante 全程没有超过 2GB，而 Claude Code 峰值接近 14GB——这是一台 8GB 内存的机器能不能跑得动的分界线。CPU 平均占用 1.3% 对 12.1%，差了 9 倍多。

另外，磁盘读取的差距：24MB 对 17.4GB，相差整整 700 多倍。

原因也很简单：Ante 用 Rust 单二进制常驻，几乎不重复读盘；而 Claude Code 基于 Node.js 运行时，每启动一个进程都要重新加载依赖树。20 个任务并行，这个差异就被成倍放大了。

测试结果真实！Ante 牺牲的速度代价慢约 50%

同一组测试里的数据：跑完同样 20 个并行任务，Ante 用 940 秒，Claude Code 用 627 秒，Ante 慢约 50%。

但是 Ante 做到了稳扎稳打。 Opencode 用了 1076 秒，比 Ante 还慢 14%，峰值内存却是 Ante 的 6.6 倍。在同类工具里，Ante 处在唯一一个既没有拿速度换资源、也没有拿资源换速度落到下风的位置。

## 通俗精炼（1）

### 2026-08-13 09:35:01

#### Ante CLI 评测总结：轻量、多模型、可编排的 Agent 控制台

##### 一句话结论

Ante 是一款处于 Preview 阶段的轻量级 Agent CLI。它并非单纯复制 Claude Code，而是试图成为一个**兼容既有配置、连接多种模型、调度其他 Agent，并支持本地离线运行的统一入口**。

其核心优势是资源占用低、迁移成本小、模型选择开放；主要代价是执行速度相对较慢，产品成熟度仍待验证。

##### 产品与接入：安装轻，迁移成本低

Ante 采用 Rust 开发，是约 15MB 的单一二进制文件，无需 Node.js、npm 等运行时依赖，一行命令即可完成安装。

它兼容`AGENTS.md`和 Claude Code 的`CLAUDE.md`，可复用已有的项目规则、Skills、Subagents 和 Memory，无需修改或迁移原配置。用户通过`/welcome`配置 API Key，并可用`/providers`在会话中切换不同模型。

##### 核心差异：从单 Agent 工具走向调度层

###### 1. 原生调度多个 Agent

通过`/term`，Ante 可以借助 tmux 启动和管理 Claude Code、Codex 等 CLI Agent。例如：

- Claude Code 负责方案设计与实现；
- Codex 负责测试或代码审查；
- Ante 负责任务编排、过程监控与会话恢复。

这些会话可持续运行，即使关闭视图或重启 Ante，任务也不会中断。用户能看到 Agent 执行的命令，并可随时接管，同时保留 Bash 权限审批机制。

###### 2. 托管本地模型

通过`/offline-mode`，Ante 会根据当前硬件推荐可运行模型，并负责下载、资源预估、加载、启动和停止。

这降低了本地模型的使用门槛，也让 Ante 更适合断网、隐私敏感或不希望依赖云端 API 的环境。

###### 3. 高度可定制

Ante 可以通过`settings.json`自定义工具集、System Prompt、记忆和 Skills 等能力。例如将工具限制为`Read`、`Write`、`Edit`、`Bash`，即可模拟 Pi Agent 的极简工作方式。

这意味着 Ante 不只是固定形态的编码 Agent，也可以被配置成不同风格的执行框架。

##### 性能表现：资源效率突出，但速度有所牺牲

文章引用 Terminal-Bench 2.1 数据称，Ante 在使用相同模型时取得了较好的任务成绩，说明其 Agent 执行框架能够较充分地发挥模型能力。但这些数据主要来自 Ante 官方评测，仍需更多独立测试验证。

在 20 个并行任务的实测中：

| 指标 | Ante | Claude Code | OpenCode |
|---|---:|---:|---:|
| 峰值内存 | 1.9GB | 13.9GB | 12.9GB |
| 平均 CPU | 1.3% | 12.1% | 3.8% |
| 磁盘读取 | 24MB | 17.4GB | 2.2GB |
| 完成时间 | 940 秒 | 627 秒 | 1076 秒 |

Ante 的峰值内存约为 Claude Code 的七分之一，平均 CPU 约为九分之一，磁盘读取量也显著更低。原因主要在于 Rust 单二进制架构减少了运行时与重复依赖加载。

代价是：同一测试中，Ante 比 Claude Code 慢约 50%，但仍快于 OpenCode。

##### 产品定位

不同工具解决的问题有所不同：

- **Claude Code、Codex CLI**：围绕自家顶级模型打造的一体化 Agent；
- **Pi、OpenCode**：强调开放性、简洁性和可定制；
- **Ante**：强调低资源运行、多模型接入、本地模型管理及跨 Agent 编排。

因此，Ante 更像是一个轻量级的**Agent Runtime 与调度控制台**，而不只是另一款终端编码助手。

##### 适用场景

Ante 尤其适合以下用户和环境：

- 希望同时使用 Claude、Codex 及其他模型；
- 已有 Claude Code 配置，不想重新迁移；
- 需要多个 Agent 并行协作；
- 在低配 VPS 或有限内存设备上运行；
- 需要离线、本地或隐私敏感部署；
- 希望深度定制工具、提示词和执行流程。

##### 综合判断

Ante 的价值不在于全面替代 Claude Code，而在于把**模型开放、配置兼容、本地运行和多 Agent 调度**整合到一个极轻的 CLI 中。

它目前最大的优势是工程效率与架构差异化，最大的风险则是 Preview 阶段的稳定性、生态成熟度，以及官方评测能否被独立复现。若后续在速度、可靠性和多 Agent 工作流上继续完善，Ante 有机会成为开发者管理多个模型与 Agent 的统一入口。

## 深度解读（1）

### 2026-09-18 10:19:22

#### Ante 的价值不只在“更轻”，而在成为 Agent 的控制层

Ante 最值得关注的，并不是 15MB 的 Rust 单文件，也不是“同模型跑分第一”，而是它把终端 Agent 从一个封闭工具，重新定义成了**兼容现有配置、调度多个执行器、管理本地模型的控制层**。这可能比单项性能优势更持久。

##### Agent 的竞争开始从模型能力转向任务编排

Ante 可以通过 `/term` 启动并操控 Claude Code、Codex 等 CLI，让一个 Agent 负责规划，其他 Agent 分别编码、测试和审查。它没有重新实现这些工具，而是借助 tmux 的持久会话、分屏和进程控制，把它们组合起来。

这透露出一个重要变化：随着模型能力逐渐接近，开发者真正缺少的可能不再是“另一个会写代码的 Agent”，而是一个能根据任务、额度和模型特长分配工作的入口。例如，让高价模型做架构判断，便宜模型执行批量修改，再由另一个模型补测试。模型由主产品退到可替换的执行器，**上下文、权限、任务状态和验收流程才成为稳定资产**。

不过，Ante 当前实现更接近“进程编排”，还不等于成熟的多 Agent 协作。启动三个终端不难，难的是任务如何拆分、共享哪些上下文、怎样识别冲突，以及由谁判断结果合格。文章展示了人工可见、可接管的执行过程，却没有证明编排本身能稳定提高成功率。这里既是它的潜力，也是最需要验证的部分。

##### 真正有效的迁移策略，是继承用户已有资产

Ante 会优先读取 `AGENTS.md`，也能回退兼容 `CLAUDE.md`，保留既有规则、skills、subagents 和 memory。这个细节比“一行安装”更有产品价值：用户迁移 Agent 的成本，主要不在安装软件，而在重建项目规则、提示词和工作习惯。

这是一种值得借鉴的进入策略——**不要求用户放弃原工具，而是先兼容其资产，再成为上层入口**。`setting.json` 还能把工具集和系统提示词收缩成类似 Pi 的形态，说明 Agent 产品正在从固定体验转向可配置运行时。未来真正形成锁定效应的，未必是某个 CLI，而可能是可移植的项目规则、技能定义、权限策略和任务记录。

##### 资源效率只有在并发场景下才会变成商业优势

文章给出的测试中，20 个并行任务下，Ante 峰值内存约 2GB，Claude Code 接近 14GB；平均 CPU 和磁盘读取也明显更低，但完成时间慢约 50%。这说明它优化的不是单次交互体验，而是**低配 VPS、离线设备和批量并发任务的可运行性**。当 Agent 从个人偶尔调用变成后台持续运行，内存、进程启动和磁盘 I/O 会直接决定一台机器能容纳多少执行单元，进而影响单位任务成本。

这些数字仍需谨慎看待：测试来自作者及官方材料，20 路并发会放大 Node.js 多进程加载的劣势；磁盘读取相差数百倍，也可能受缓存、依赖安装和测量口径影响。“同模型质量第一”同样需要结合具体模型、提示词、失败重试和榜单覆盖范围判断，不能直接推导出 Ante 全面强于 Claude Code。

因此，Ante 当前最有分量的机会不是替代头部 Agent，而是验证一种新位置：**做模型与 Agent 之上的轻量控制面**。接下来真正决定它能否成立的，不是再接入多少模型，而是能否可靠地分工、传递上下文、验收结果，并让多 Agent 协作的收益稳定大于协调成本。

## 口播总结（1）

### 2026-09-20 00:19:45

Ante 是一款运行在终端里的编程智能体，也就是 Agent CLI。它目前还处在预览阶段，但已经表现出一个很鲜明的方向：体积小、资源占用低，同时尽量兼容现有配置，还能调度其他智能体。它尤其适合低配服务器、离线环境，以及需要自由切换多个模型的用户。

先看使用门槛。Ante 用 Rust 编写，安装后是一个大约十五兆字节的单一程序，不依赖 Node.js 或 npm。安装只需要一条命令，通常几秒就能完成。

更重要的是，它尽量避免让用户重新配置项目。很多 Claude Code 用户已经在项目里积累了规则、技能、子智能体和记忆配置。Ante 会优先读取自己的配置文件。如果项目里没有，就继续读取 Claude Code 使用的 CLAUDE 点 M D 文件，包括全局配置。原来的文件不会被删除、移动或修改。

这意味着，用户不必手工迁移大量规则，进入原来的项目目录就能开始使用。对于开发工具来说，这种配置兼容性往往比安装速度更重要。

模型接入也比较直接。用户选择模型供应商，填入应用程序接口密钥，也就是 API Key，就能完成配置。会话过程中还可以切换供应商，不需要重启 Ante。它不是只服务某一家模型，而是把多模型选择作为基础能力。

Ante 最有辨识度的功能，是跨智能体协作。它可以通过名为 term 的命令，启动并控制 Claude Code、Codex 等其他终端智能体。

底层使用的是 tmux。可以把 tmux 理解成一个终端会话管理器。它能让多个命令行程序在不同窗口中持续运行。比如，可以让 Claude Code 负责实现功能，让 Codex 补充测试，再由 Ante 统一监控执行过程。

这些会话是持久的。关闭分屏视图，不等于终止任务。即使 Ante 退出后重新启动，原来的会话仍然可以继续存在，正在运行的开发服务器也不会因此停止。用户还能看到其他智能体输入的每条命令，并随时接管终端。

安全方面，Ante 向其他会话发送按键时，仍然需要经过标准的 Bash 权限审批。按照原文的描述，它没有额外绕过审批的通道。不过，不同终端软件的分屏体验可能不同。即使没有显示出分屏，后台进程也可能已经正常启动。

第二个差异化能力，是本地离线模型。执行离线模式命令后，Ante 会根据当前电脑的硬件和可用内存，列出适合下载的模型，并标明可用性。模型的下载、加载前估算、启动和停止，都由 Ante 管理。

原文作者使用的是一台搭载 M4 Max 芯片的 MacBook Pro。Ante 根据可用内存，推荐了体积约十七吉字节的 Qwen 三点六、二百七十亿参数模型。这个例子说明，本地模型不只是“理论上支持”，而是被做成了有安装引导和资源提示的完整流程。对于断网环境，或者不希望把代码发到云端的场景，这一点很有价值。

Ante 还允许通过配置文件限制工具和系统提示词。例如，只开放读取、写入、编辑和 Bash 四种工具，就能把它调整成类似 Pi Agent 的极简工作方式。也就是说，Ante 不仅能更换模型，还能更换智能体的行为框架。

接下来是最值得关注的性能。

任务质量方面，原文引用了 Terminal-Bench 二点一测试。这是一套终端任务基准，包含八十九个任务，每个任务运行五遍，总计四百四十五次。任务包括安装依赖、修改代码、运行测试，以及根据报错继续修正。

可以把大模型看成发动机，把 Agent 看成汽车。固定模型以后，不同 Agent 的工具设计和执行策略，会影响最终完成任务的能力。根据 Ante 官方公布、可复算的测试数据，在若干相同模型的比较中，Ante取得了领先结果。

但这个结论不能理解成 Ante 已经全面超过 Claude Code。原文也明确指出，这组数据更适合说明：Ante 有可能把较便宜模型的能力上限继续向前推，而不是证明它在所有场景都更强。

资源占用的差异更加明显。在相同容器约束下，同时执行二十个任务时，Ante 的峰值内存约为一点九吉字节。Claude Code 接近十三点九吉字节，约为 Ante 的七倍。

平均处理器占用方面，Ante 约为百分之一点三，Claude Code 约为百分之十二点一，差距超过九倍。磁盘读取量的差别更夸张。Ante 总计约二十四兆字节，Claude Code 约十七点四吉字节，相差七百多倍。

原文给出的解释是，Ante 使用 Rust 单一程序常驻，较少重复加载依赖。Claude Code 基于 Node.js 运行时，并行启动多个进程时，需要反复加载依赖树，因此差距会被放大。

不过，低资源占用并不是没有代价。完成同样二十个并行任务，Ante 用了九百四十秒，Claude Code用了六百二十七秒。Ante 慢了大约百分之五十。作为参照，OpenCode 用了约一千零七十六秒，比 Ante 更慢，峰值内存却约为 Ante 的六点六倍。

这些数据来自特定测试环境，不能直接代表所有项目。但它们清楚地展示了 Ante 的取舍：它不是一味追求最快，而是希望用更少的内存、处理器和磁盘资源，稳定地并行运行更多任务。

最值得记住的是，Ante 的价值不只在于“又一个编程智能体”。它把配置兼容、多模型切换、离线模型管理和跨智能体调度，放进了一个约十五兆字节的单一程序里。它目前仍处在预览阶段，成熟度还需要时间验证；但对于低配服务器、断网开发和多智能体协作，它已经展现出很明确的独特性。
