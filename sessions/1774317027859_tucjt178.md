#### 主旨概括

这篇内容的核心观点是：作者最近把工作重心转向了 Claude Code，并开始重新搭建一套适合自己的“记忆系统”。  
他认为，很多人把这件事做复杂了，而基于 Obsidian + Markdown + Claude Code 的方案，其实已经足够简单、高效，而且几乎零配置。

#### 1. 背景：从 OpenClaw 转向 Claude Code

- 作者从上周开始，逐步把重心从原来的体系转移到 Claude Code。
- 转移后的第一件事，不是换模型本身，而是思考：**如何重建自己在 OpenClaw 里的记忆架构和记忆系统**。
- 这说明对作者来说，AI 工具的价值不只是“对话”，更重要的是能否持续积累、调用、整理个人知识。

#### 2. 为什么选择 Obsidian：因为足够简单

- 作者调研后发现，当前呼声最高的方案是 **Obsidian**，于是专门花了一个周末研究。
- 他的结论很明确：**大部分人把这件事弄复杂了**。
- 作者选择 Obsidian 的关键原因不是“功能多”，而是它的底层非常朴素：
  - `vault` 本质上就是一个文件夹
  - 里面存的基本都是 `.md` 文件
- 这意味着 Claude Code 天然就能直接处理这些内容，不需要额外转换格式。

可以理解为：
- Obsidian 负责“以笔记形式存知识”
- Claude Code 负责“直接读、写、改、引用这些知识”
- 两者之间几乎没有中间层

#### 3. 作者反对复杂方案：不需要数据库、向量存储和 RAG

- 作者强调，在这个场景里，**不需要数据库**
- 也**不需要向量存储**
- 甚至**不需要 RAG（检索增强生成）**
- 原因很直接：Claude Code 本来就能直接读写 Markdown 文件

作者的意思是：
- 你在 Obsidian 里写的笔记，Claude Code 可以直接看到、修改、引用
- 反过来，Claude Code 生成的内容，你也能在 Obsidian 里继续浏览、整理

这形成了一种很顺畅的**双向工作流**：
- 人写笔记 → AI 读取和处理
- AI 写内容 → 人回到笔记工具里继续管理

作者用一句话概括这种体验：**双向的，零配置**。

#### 4. 实际使用方式：部署门槛很低

- 作者认为，这套方案的上手过程非常简单，甚至**根本不用装插件**。
- 最直接的做法就是：
  1. 进入 Obsidian 的 `vault` 目录
  2. 在终端里输入 `claude`
  3. 开始使用

这说明作者推崇的是一种“文件夹即知识库”的思路，而不是先搭一大堆复杂基础设施。

#### 5. 作者当前唯一安装的扩展：`obsidian-claude-pkm`

#### 6. 作者最重要的判断：写好 `CLAUDE.md` 比折腾工具重要 10 倍

#### 深入浅出地解读

##### 1. 作者到底在说什么？

说白了，作者是在强调一个思路：

> **不要一上来就把“AI 记忆系统”做成大型工程，先把它做成 AI 能直接读懂、你自己也方便维护的笔记系统。**

很多人一提“记忆系统”，就会想到：

- 向量数据库
- 检索增强生成（RAG）
- embedding
- 各种自动化管线

这些东西当然有用，但作者觉得：**对于个人知识管理场景，往往太重了。**

##### 2. 为什么 Obsidian 会特别适合？

因为它足够“朴素”。

Obsidian 的核心不是某种神秘系统，本质就是：

- 一个普通文件夹
- 一堆 Markdown 文件

这有几个非常大的好处：

###### 人能看懂
你的笔记就是 `.md` 文本，打开就能看，不被某个专有软件绑死。

###### AI 能直接用
Claude Code 本来就擅长处理文本文件，所以不需要额外“翻译层”。

###### 双向协作自然
- 你在 Obsidian 里写内容
- Claude Code 能读取、整理、续写
- Claude Code 生成的内容
- 你又能回到 Obsidian 里继续看、继续改

这就形成了一个很顺畅的闭环。

##### 3. 为什么他说“别把事情搞复杂”？

因为很多人的问题不是“工具不够强”，而是：

- 结构没想清楚
- 规则没写清楚
- 笔记没有统一格式
- AI 不知道该怎么配合你工作

所以作者才会强调：

> **写好 `CLAUDE.md`，比折腾工具重要 10 倍。**

这句话的意思是：

- 你要先告诉 AI：
  - 你的笔记怎么分类
  - 命名规则是什么
  - 日记怎么写
  - 周报怎么回顾
  - 目标怎么追踪
- 一旦规则清楚，AI 才能长期稳定协作

否则，哪怕工具再高级，最后也容易越用越乱。

##### 4. 这背后的本质是什么？

本质上，这是一种 **“文件即记忆”** 的思路。

不是把记忆放进黑盒系统里，而是放进：

- 可读
- 可改
- 可迁移
- 可搜索

的文本里。

这套方法特别适合：

- 个人知识管理
- 写作积累
- 工作日志
- 项目复盘
- 目标追踪

因为这些场景更看重的是：

- 持续记录
- 结构清晰
- 方便复用

而不是追求一套很炫但很重的 AI 基础设施。

#### 我的意见

##### 我认为这个思路是对的，而且很实用

优点很明显：

- **门槛低**：不用搭复杂系统
- **可持续**：Markdown 不容易过时
- **可控性强**：数据就在自己手里
- **和 AI 协作自然**：Claude Code 可直接处理

##### 但也要注意边界

这套方案很适合 **个人 PKM（个人知识管理）**，但如果场景变成：

- 大规模团队知识库
- 海量文档检索
- 跨库语义搜索要求很高
- 复杂权限管理

那单靠 Markdown 文件夹可能就不够了，后面还是可能需要数据库、索引或 RAG。

##### 最实在的建议

如果你是个人用户，或者只是想先把 AI 记忆系统跑起来，我建议：

1. **先用 Obsidian + Markdown 跑通**
2. **先写清楚 `CLAUDE.md` 规则**
3. **先建立固定模板，比如 daily / weekly / project**
4. **等真实遇到瓶颈，再考虑更复杂的技术栈**

一句话说：

> **先把“能长期用”的简单系统搭起来，再谈高级架构。**

如果你愿意，我也可以进一步帮你把这段内容整理成：
1. **适合发朋友圈/公众号的短评版**
2. **适合团队分享的观点版**
