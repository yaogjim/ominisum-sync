## 分析要点

- **核心高价值点**：评估Agent不能只看单项能力或一次成功，而应以真实工作流的最终系统状态、完整交付结果和多次重复成功率作为核心标准。
- **留存建议**：选择性浏览并存档评测框架，具体模型成绩需另行核验（汇总了多个真实工作任务评测集，并提供了端到端结果检查、全量通过判定和重复运行稳定性等可复用评测视角。）

**知识要点**

- 真实工作任务往往包含跨工具操作、杂乱数据整合、条件变更和多项交付物，单项能力强不等于端到端完成率高。
- RealReplicaBench采用最终状态检查，并要求同一任务的多组检查项全部通过才计分，体现商业任务中局部错误可能导致整体失败。
- 平均运行得分与连续多次全部成功是不同指标，后者更能反映Agent在实际部署中的稳定性。

**行动项**

- 为目标业务收集真实端到端工作流，按可复现性、商业价值和结果可判定性筛选评测任务。
- 评测Agent时检查邮箱、文件、日历或业务系统的最终状态，而不只评价推理过程或文字回答。
- 对同一任务独立运行多次，同时记录平均得分和连续全部成功率。

**数字生命卡兹克**

### 说一个反常识的真相，Agent如今在真实工作场景的成功率依然很低。

上周一，我发了自己做的AIHOT大模型排行榜。

有很多朋友感兴趣，在文章下面评论，最高赞的一条，是在问能不能有个分类测评，能够评估不同模型做不同任务的表现。

![Image](https://pbs.twimg.com/media/HP4sLkea0AErtfO?format=jpg&name=large)

讲道理，这其实一直是我想做的，也是我觉得特别特别核心的痛点。

现在的大模型榜单很多，比如LiveBench、DeepSWE之类的，可以很快知道哪个模型在某一个能力维度上更强，像Coding、数学、浏览器操作等等。

但是有一类评测集，其实是最稀缺的。

就是模型在真实工作中的实际完成效果。

比如金融领域、法律领域、电商领域、生活领域等等等等，就是直接给它一份真实工作，让它自己从头干到尾，最终看工作效果，而这些，我觉得其实才更符合真实用户的日常工作和生活，也对大家更有用。

所以，在分类上，我一直想把这些场景给补上，把这个排行榜的维度，变得更加丰富和多维化。

于是，这个周末，我几乎把所有的评测集都翻了一遍，不翻不知道，一翻才吓一跳，这块的评测集，真的少的太可怜的，真的可以用寥寥无几来形容。

而且绝大多数的模型的跑分，在这些真实场景下任务的成功率，也是真的低的可怜，跟大家在Coding领域的体感完全不一样。

我用一个周末我翻到的比较成熟的电商评测的评测集来举例子，正好也是上周开源的，比较新，一些最新的模型也都有。

这个评测集叫RealReplicaBench，团队来自阿里国际站，因为他们就是做外贸的，所以内部的数据我觉得还是比较权威的，从这个案例，也可以看看Agent在真实的电商场景下能完成什么样子。

Github地址：

[https://github.com/Accio-org/RealReplicaBench](https://github.com/Accio-org/RealReplicaBench)

![Image](https://pbs.twimg.com/media/HP4sMDfbMAAI1kS?format=jpg&name=large)

这套评测一共有107个任务，阿里国际站因为直接做了Accio Work这个电商Agent，然后他们就从大概过去160万条完整对话中整理出20万条工作流，再归纳出约2000条商业价值高的，最后按照可复现性和结果可判定性，最终整理出来107个任务。

![Image](https://pbs.twimg.com/media/HP4sMqKaUAAH5MF?format=jpg&name=large)

基本把电商领域涉及到的工作场景都覆盖了，像供应商采购、商品发布、店铺经营、订单对账、国际物流、售后争议等等等等。

任务具体内容的分布我让GPT做了张图，方便大家更直观的看一下。

![Image](https://pbs.twimg.com/media/HP4sNQ_b0AAq-s6?format=jpg&name=large)

每一个，都是真实世界里面的电商任务。

简单看几个例子的案例，大家就知道大概都是什么样的任务了。

比如，有一个任务是让模型在店铺上上线一款定制瑜伽垫。

![Image](https://pbs.twimg.com/media/HP4sN7WaQAAVmTE?format=jpg&name=large)

模型拿到的信息有发品计划、三家供应商的报价和一堆实拍图片。

然后呢，它要找出计划指定的供应商，填好类目、销售国家、差异定价和描述，再从一堆相机自动编号的照片里挑出正确、清晰的商品图上传。

还有一个，是给东莞到达拉斯的消费级电子产品规划运输路线。

![Image](https://pbs.twimg.com/media/HP4sOa9aMAAXBNC?format=jpg&name=large)

在30天的运输时间的限制下，模型需要计算保险、清关、海关担保和平台费，找出总成本最低的路线，再在仿真的货代平台里完成海运段订舱和货件验证。

还有处理电商退货争议。

![Image](https://pbs.twimg.com/media/HP4sO-ea4AA1ejE?format=jpg&name=large)

这个任务里面模型需要把订单记录、物流扫描、仓库质检、客户对话、现场照片、平台政策和截止时间全对起来，然后逐单决定接受退货、部分退款、全额退款、向平台申诉，还是继续补充证据。

甚至还有跨平台月度对账。

![Image](https://pbs.twimg.com/media/HP4sPjAbgAA6lxB?format=jpg&name=large)

它要把天猫、京东、拼多多三套格式不同的原始订单清洗到一张表里，统一SKU和订单状态，核对发货与结算差异，再算出每个SKU在各个平台的收入、成本、佣金和利润，最后把这些信息按照指定格式进行交付。

从这几个例子就能看到，这基本都是现实世界的电商交易的真实任务，商品上架、物流规划，到售后和经营分析，基本全都有，而且讲道理，这些任务看着就是脏活累活，理论上都应该交给Agent干对吧。

然后呢，我们来看看，现在在Coding上感觉已经大杀四方，感觉什么都能干出来的这些牛逼模型，在这个真实任务场景上的成功率有多少。

![Image](https://pbs.twimg.com/media/HP4sQG4bAAA4fNS?format=jpg&name=large)

这些模型，是在PI这个开源Harness框架下跑的，所以准确性我觉得没啥问题。

百分制下，只有排名第一的Claude Opus 5刚刚过了及格线。

107个任务，它完成了65个，通过率60.75%。

Qwen 3.8 Max和DeepSeek V4 Pro以49.53%的通过率并列第三。

也就是说，现在大部分模型的任务通过率甚至连50%都过不去，107个任务，你让AI去做，有一半是全失败的。

这就是现在的模型，在真实世界工作中，非常真实的现状。

我也详细看了看他们是怎么去衡量模型到底完没完成，以及给不给分的，看完以后，我感觉比我想象的还要复杂一些。

我随机挑一道供应商采购题，来给大家看看评测过程。

![Image](https://pbs.twimg.com/media/HP4sQmKaMAAW6kS?format=jpg&name=large)

比如这个题，任务的主角Dana是一名采购经理。

她离开几天后回来，邮箱里已经堆了大约300封邮件。

但是呢，她有一个铝合金笔记本支架项目，必须在当天完成推进。

模型需要从这些邮件里还原项目相关的需求、最新的规格和数量，从20家供应商里找出真正合格、单件落地成本最低的一家。

选好供应商以后，它还需要进行一系列的规范化操作，比如只给最终选中的那封报价打标签，标出3封要求更换收款账户的可疑邮件，保存给供应商的回复草稿，创建启动会议，并交付一份规定格式的JSON总结。

这个任务量你想一想都知道有多大，而且这些任务的原始数据也非常乱，充分体现了现在人类的混乱性。

比如项目的最终需求零零碎碎的散在10封邮件里面，中途还改过数量，改过要求，改的乱七八糟的。

而且供应商也不是只看公司名，因为现实世界中，也经常会有同一家供应商会换着联系人、邮箱、域名和显示名称来发报价，所以题目中，同时还混进了4组名字很像、实际却是不同公司的供应商。

模型得综合工厂地址、电话、银行收款人和出口许可证等多个信号交叉核对，才能判断哪些报价来自同一家。

说实话，这个过程，看得我都要力竭了，至少我是一丁点都不想干的状态。。。

而模型的得分，要这23组全部通过，才算答对，才能得到这1分，一旦有1个检验出来错误就0分，非常严格。

也就是说，没有过程分这个东西，你只有所有检测项全对才有分，因为模型去解决真实的电商问题的时候，这差一步，可能就会让你丢了单子，这才是真实的商业世界。

于是，最终就是上文看到的排行榜，几乎没有及格的。

## 结构化（1）

### 2026-08-21 09:53:27

#### 文章精炼总结

大模型虽然在编程、数学等标准化任务上表现亮眼，但在真实工作场景中，Agent 的任务成功率依然很低。核心原因是现实工作往往流程长、信息混乱、涉及多工具协作，而且任何一个环节出错都可能导致整个任务失败。

##### 1. 当前评测缺少“真实工作能力”这一维度

现有榜单如 **LiveBench、DeepSWE**，主要衡量编程、数学、浏览器操作等单项能力，但很少测试模型能否独立完成一份真实工作，例如：

- 金融、法律、电商等专业任务；
- 从理解需求到执行、交付的完整流程；
- 需要跨邮箱、表格、日历、业务平台等多个工具协作的任务。

作者调研后发现，这类评测集数量极少，而且大多数模型在其中的成功率远低于编程任务。

##### 2. RealReplicaBench：用真实电商任务测试 Agent

阿里国际站团队推出的 **RealReplicaBench**，用于评估 Agent 在真实电商工作中的能力。

###### 数据与任务来源

该团队从：

1. 约 **160 万条完整对话**中整理出；
2. **20 万条工作流**；
3. 再筛选出约 **2000 条高商业价值任务**；
4. 最终依据可复现性和结果可判定性，形成 **107 个评测任务**。

任务覆盖供应商采购、商品发布、店铺经营、订单对账、国际物流和售后争议等主要电商场景。

###### 典型任务案例

- **商品上架**：根据发品计划、3 家供应商报价和大量实拍图片，选择指定供应商，填写类目、销售国家、差异化定价与描述，并挑选正确清晰的商品图上传。
- **物流规划**：为东莞到达拉斯的消费电子产品制定运输方案，在 **30 天**限制内计算保险、清关、海关担保和平台费，选择总成本最低的路线并完成订舱。
- **退货争议处理**：综合订单、物流、质检、客户对话、照片、平台政策和期限，决定接受退货、部分退款、全额退款、申诉或补充证据。
- **跨平台月度对账**：清洗天猫、京东、拼多多三套不同格式的订单，统一 SKU 和订单状态，并计算各平台的收入、成本、佣金与利润。

这些任务不是单纯“回答问题”，而是要求 Agent 完整执行真实业务流程。

##### 3. 真实电商任务中，大多数模型连 50% 都达不到

所有模型均在开源的 **PI Harness** 框架下测试。结果显示：

- **Claude Opus 5** 排名第一，完成 **65/107 个任务**，通过率为 **60.75%**，仅刚过及格线。
- **Qwen 3.8 Max** 和 **DeepSeek V4 Pro** 的通过率均为 **49.53%**，并列第三。
- 大部分模型的任务通过率不足 **50%**，意味着让 AI 完成 107 项真实工作时，约一半任务会彻底失败。

这与用户在编程场景中感受到的“模型什么都能做”形成明显反差。

##### 4. 为什么真实工作评测如此困难？

文章以一道供应商采购题说明其复杂性：

- 采购经理 Dana 回来后面对约 **300 封邮件**；
- 必须在当天推进一个铝合金笔记本支架项目；
- Agent 要从邮件中还原最新需求、规格和数量；
- 从 **20 家供应商**中选出合格且单件落地成本最低的一家；
- 给最终报价加标签，识别并标记 **3 封要求更换收款账户的可疑邮件**；
- 保存供应商回复草稿、创建启动会议，并交付指定格式的 JSON 总结。

难点在于，最终需求分散在约 **10 封邮件**中，期间还多次修改。部分供应商会使用不同联系人、邮箱、域名和显示名称发送报价，题目还混入了 **4 组名称相似但实际不同的公司**。模型必须结合工厂地址、电话、银行收款人和出口许可证等信息交叉判断。

##### 5. 评测采用严格的“全对才得分”规则

Agent 可以直接使用 Shopify、Gmail、日历和商品发布工具。任务结束后，评测程序会检查邮箱、草稿、日历和 JSON 文件的最终状态。

该采购任务包含：

- **23 组结果检查**
- 共 **42 项检查内容**

检查内容包括：

- 是否给正确报价加了标签；
- 3 封可疑邮件是否全部标记；
- 草稿收件地址和会议日期是否正确；
- JSON 中的供应商、价格、数量和淘汰原因是否完全一致。

只有 **23 组全部通过**，任务才得到 1 分；任何一项错误，整题均为 0 分。因为在真实商业中，即使只差一步，也可能造成损失或丢单。

使用专门面向电商的 **Accio Agent 框架**后，通过率超过 50% 的模型从 **2 个增加到 6 个**，说明领域化工具和工作流能够改善表现。此外，现实中通常是人与 Agent 协作，因此实际完成率可能高于全自动评测。

##### 6. 与编程任务相比，差距十分明显

文章对比了软件工程评测 **DeepSWE**：

- 包含 **113 个任务**；
- 要求 AI 在真实开源代码仓库中完成复杂、跨文件的软件工程修改；
- 模型需自行阅读代码、定位问题、修改文件、运行测试并提交结果；
- 使用统一的 **mini-swe-agent** 框架后，排名靠前的模型通过率均超过 **70%**。

这说明模型在结构相对清晰、反馈明确、可通过测试验证的编程任务上表现较好，但在琐碎、混乱、多步骤的现实业务中明显更弱。

##### 7. 其他真实场景评测也显示成功率和稳定性不足

###### 腾讯 E-Bench

腾讯混元联合清华大学、东南大学发布的 **E-Bench**，模拟了：

- 王者荣耀；
- QQ 音乐；
- 腾讯会议。

评测共包含 **323 个操作任务**，测试了 **11 个模型**。任务包括整理好友和比赛记录、搜索歌曲和管理歌单、筛选参会人员及预定会议等。

最好成绩来自 **Kimi-K3**：

- **Avg@3 为 73.79%**，即同一任务独立运行 3 次后的平均得分；
- 但同一道题连续 3 次全部完成的比例只有 **58.82%**；
- 11 个模型在这一稳定性指标上均未超过 **60%**。

这意味着模型偶尔能做对，不代表它能稳定、重复地完成工作。

###### 小红书 VibeLifeBench

偏生活场景的 **VibeLifeBench** 包含：

- **200 个持续数周的生活任务**；
- 覆盖职业、健身、租房、购物、差旅等 **10 个领域**。

排名第一的 **Claude Opus 5**，其 **Avg@3 也只有 32.5%**，显示模型在长期、开放且缺少标准答案的生活任务中表现更差。

> 这几套评测的任务和指标不同，不能直接横向比较，但共同说明：大模型在真实世界任务中仍有很大的提升空间。

##### 8. 作者的后续计划

作者认为，仅靠模型公司还不够，掌握真实业务流程的平台和厂商也应持续：

- 提炼并开放真实工作任务；
- 滚动更新评测数据；
- 改进 Agent 框架和模型路由；
- 加快新模型的评测速度。

由于现有评测偏研究性质，更新往往不够及时，暂时难以直接纳入 AIHOT 排行榜。作者计划未来收集 **RealReplicaBench、E-Bench、VibeLifeBench** 等真实工作评测集，自行搭建环境并付费运行，在新模型发布后及时测试，再将成绩更新到 AIHOT。

##### 结论

**“会解题”不等于“会工作”。** 大模型已经擅长编程等规则清晰、结果可验证的任务，但面对现实中信息分散、流程冗长、工具众多、要求稳定且不容出错的工作时，Agent 依然不够可靠。

真正的人类工作，恰恰由那些琐碎、混乱且没有标准答案的事情构成，而这正是当前 AI 最需要突破的能力边界。

## 通俗精炼（1）

### 2026-09-18 10:38:51

#### 会解题不等于会工作：真实场景中的 Agent 仍不可靠

大模型在编程等标准化任务上表现亮眼，但面对信息混乱、跨工具操作且要求结果完全正确的真实工作，成功率仍然偏低。文章认为，衡量 Agent 价值的关键不只是单项能力，而是能否稳定完成端到端任务。

##### 电商实测：最强模型也仅刚过及格线

阿里国际站发布的 RealReplicaBench，从约 160 万条对话中提炼出 107 个可复现任务，覆盖采购、商品发布、物流、售后和对账等场景。据该榜单，Claude Opus 5 通过率为 60.75%；多数模型不足 50%。相比之下，DeepSWE 编程基准中，领先模型通过率普遍超过 70%。

##### 真实工作的难点是“全链路不能出错”

例如采购任务要求模型从约 300 封邮件中还原多次变更的需求，识别同一供应商的不同身份，比较成本、标记可疑邮件、创建会议并输出 JSON。评测会检查 23 组、42 项结果，全部正确才得分；任何一步出错即判失败。这反映了商业任务的真实约束：局部正确不等于交付成功。

##### 稳定性和长期任务同样薄弱

腾讯 E-Bench 中，最佳模型三次运行的平均得分为 73.79%，但同一任务连续三次都成功仅 58.82%；小红书 VibeLifeBench 覆盖数周生活任务，最高 Avg@3 也只有 32.5%。三套基准不可直接横向比较，但都显示 Agent 在复杂性与稳定性上仍有明显短板。

专用电商框架可让更多模型突破 50%，人机协作也可能提高实际完成率。其意义是：当前产品更适合“辅助执行与人工复核”，而非完全自治；行业也需要更多持续更新的真实任务评测，避免用解题能力替代工作能力。
