#### 快速开始

**第一步：安装**

```
/plugin marketplace add https://github.com/Yeachan-Heo/oh-my-claudecode
/plugin install oh-my-claudecode
```

**第二步：配置**

```
/omc-setup
```

**第三步：开始构建**

```
autopilot: build a REST API for managing tasks
```

就这么简单。其余都是自动的。

##### 不确定从哪里开始？

如果你对需求不明确、有模糊的想法，或者想要精细控制设计：

```
/deep-interview "I want to build a task management app"
```

深度访谈使用苏格拉底式提问在编写任何代码之前帮你理清思路。它揭示隐藏假设并通过加权维度衡量清晰度，确保你在执行前明确知道要构建什么。

#### Team 模式（推荐）

从 **v4.1.7** 开始， **Team** 是 OMC 的标准编排方式。 **swarm** 和 **ultrapilot** 等旧版入口仍受支持，但现在 **在底层路由到 Team** 。

```
/team 3:executor "fix all TypeScript errors"
```

Team 按阶段化流水线运行：

`team-plan → team-prd → team-exec → team-verify → team-fix (loop)`

在 `~/.claude/settings.json` 中启用 Claude Code 原生团队：

```
{
  "env": {
    "CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS": "1"
  }
}
```

> 如果团队被禁用，OMC 会发出警告并在可能的情况下回退到非 Team 执行模式。

**v4.4.0 移除了 Codex/Gemini MCP 服务器** （ `x` 、 `g` 提供商）。请改用 `/omc-teams` 在 tmux 分屏中启动真实的 CLI 进程：

```
/omc-teams 2:codex   "review auth module for security issues"
/omc-teams 2:gemini  "redesign UI components for accessibility"
/omc-teams 1:claude  "implement the payment flow"
```

如需在一个命令中混合使用 Codex + Gemini，请使用 **`/ccg`** 技能：

```
/ccg Review this PR — architecture (Codex) and UI components (Gemini)
```

技能 工作者 最适合

`/omc-teams N:codex` N 个 Codex CLI 窗格 代码审查、安全分析、架构

`/omc-teams N:gemini` N 个 Gemini CLI 窗格 UI/UX 设计、文档、大上下文任务

`/omc-teams N:claude` N 个 Claude CLI 窗格 通过 tmux 中的 Claude CLI 处理通用任务

`/ccg` 1 个 Codex + 1 个 Gemini 并行三模型编排

工作者按需生成，任务完成后自动退出 — 无空闲资源浪费。需要安装 `codex` / `gemini` CLI 并有活跃的 tmux 会话。

> **注意：包命名** — 项目品牌名为 **oh-my-claudecode** （仓库、插件、命令），但 npm 包以 [`oh-my-claude-sisyphus`](https://www.npmjs.com/package/oh-my-claude-sisyphus) 发布。通过 npm/bun 安装 CLI 工具时，请使用 `npm install -g oh-my-claude-sisyphus` 。

#### 为什么选择 oh-my-claudecode？

- **无需配置** - 开箱即用，智能默认设置
- **Team 优先编排** - Team 是标准的多智能体界面（swarm/ultrapilot 是兼容性外观）
- **自然语言交互** - 无需记忆命令，只需描述你的需求
- **自动并行化** - 复杂任务自动分配给专业智能体
- **持久执行** - 不会半途而废，直到任务验证完成
- **成本优化** - 智能模型路由节省 30-50% 的 token
- **从经验中学习** - 自动提取并复用问题解决模式
- **实时可见性** - HUD 状态栏显示底层运行状态

关键词 效果 示例

`team` 标准 Team 编排 `/team 3:executor "fix all TypeScript errors"`

`omc-teams` tmux CLI 工作者 (codex/gemini/claude) `/omc-teams 2:codex "security review"`

`ccg` 三模型 Codex+Gemini 编排 `/ccg review this PR`

`autopilot` 全自动执行 `autopilot: build a todo app`

`ralph` 持久模式 `ralph: refactor auth`

#### 实用工具

##### 速率限制等待

当速率限制重置时自动恢复 Claude Code 会话。

```
omc wait          # 检查状态，获取指导
omc wait --start  # 启用自动恢复守护进程
omc wait --stop   # 禁用守护进程
```

**需要：** tmux（用于会话检测）

##### 通知标签配置 (Telegram/Discord/Slack)

你可以配置 stop 回调发送会话摘要时要 @ 谁。

```
# 设置/替换标签列表
omc config-stop-callback telegram --enable --token <bot_token> --chat <chat_id> --tag-list "@alice,bob"
omc config-stop-callback discord --enable --webhook <url> --tag-list "@here,123456789012345678,role:987654321098765432"
omc config-stop-callback slack --enable --webhook <url> --tag-list "<!here>,<@U1234567890>"

# 增量更新
omc config-stop-callback telegram --add-tag charlie
omc config-stop-callback discord --remove-tag @here
omc config-stop-callback discord --clear-tags
```

标签规则：

- Telegram： `alice` 会规范化为 `@alice`
- Discord：支持 `@here` 、 `@everyone` 、纯数字用户 ID、 `role:<id>`
- Slack：支持 `<@MEMBER_ID>` 、 `<!channel>` 、 `<!here>` 、 `<!everyone>` 、 `<!subteam^GROUP_ID>`
- `file` 回调会忽略标签选项

变量 说明

`OMC_OPENCLAW=1` 启用 OpenClaw

`OMC_OPENCLAW_DEBUG=1` 启用调试日志

`OMC_OPENCLAW_CONFIG=/path/to/config.json` 覆盖配置文件路径

**支持的钩子事件（bridge.ts 中 6 个活跃）：**

事件 触发时机 主要模板变量

`session-start` 会话开始时 `{{sessionId}}`, `{{projectName}}`, `{{projectPath}}`

`stop` Claude 响应完成时 `{{sessionId}}`, `{{projectName}}`

`keyword-detector` 每次提交提示词时 `{{prompt}}`, `{{sessionId}}`

`ask-user-question` Claude 请求用户输入时 `{{question}}`, `{{sessionId}}`

`pre-tool-use` 工具调用前（高频） `{{toolName}}`, `{{sessionId}}`

`post-tool-use` 工具调用后（高频） `{{toolName}}`, `{{sessionId}}`

**回复通道环境变量：**

变量 说明

`OPENCLAW_REPLY_CHANNEL` 回复通道（例如 `discord` ）

`OPENCLAW_REPLY_THREAD` 线程 ID

## 结构化（1）

### 2026-04-01 09:29:39

##### 主旨概括

`oh-my-claudecode`（OMC）是一个为 Claude Code 提供 “多智能体编排” 的工具，目标是让用户几乎不用学习复杂命令，就能直接用自然语言完成开发、评审、设计和调试任务。  
它的核心价值在于：**开箱即用、自动分工、支持多模型协作，并尽量降低 token 成本与使用门槛。**

##### 1. 这是什么：一个 “零学习曲线” 的 Claude Code 编排系统

- OMC 主打 “**不用先学 Claude Code，直接开始做事**”。
- 它提供多智能体协作能力，把复杂任务拆给不同角色处理，例如规划、执行、验证、修复。
- 对 Codex 用户，官方还特别提示可查看`oh-my-codex`，提供类似的编排体验。
- 核心定位可以概括为：
  - **自然语言驱动**
  - **自动并行处理**
  - **持续执行直到验证完成**
  - **多模型按需协作**

##### 2. 如何快速开始：安装、配置、执行三步走

###### 2.1 安装与初始化

- 第一步，安装插件：
```bash
/plugin marketplace add https://github.com/Yeachan-Heo/oh-my-claudecode
/plugin install oh-my-claudecode
```

- 第二步，运行配置：
```bash
/omc-setup
```

- 第三步，直接开始任务：
```bash
autopilot: build a REST API for managing tasks
```

- 文档强调：**“就这么简单，其余都是自动的。”**

###### 2.2 如果需求还不清楚

- 如果你只是有一个模糊想法，比如 “我想做一个任务管理应用”，可以先用：
```bash
/deep-interview "I want to build a task management app"
```

- 这个功能会用**苏格拉底式提问**帮助用户澄清目标。
- 它还能：
  - 揭示隐藏假设
  - 按 “加权维度” 评估清晰度
  - 在写代码前明确需求边界

- 通俗理解：  
  这像是先让 AI 当产品经理，帮你把 “我大概想做个东西” 变成 “我确切知道要做什么”。

##### 3. 核心编排方式：Team 模式已成为标准方案

###### 3.1 Team 是当前推荐的主入口

- 从**v4.1.7**开始，`Team`成为 OMC 的**标准编排方式**。
- 旧入口如`swarm`、`ultrapilot`仍可用，但本质上都会**路由到底层的 Team**。
- 典型命令：
```bash
/team 3:executor "fix all TypeScript errors"
```

###### 3.2 Team 的执行流程

- Team 采用阶段化流水线，依次为：
  - `team-plan`
  - `team-prd`
  - `team-exec`
  - `team-verify`
  - `team-fix (loop)`

- 这意味着它不仅会 “做”，还会 “验” 和 “反复修”。

###### 3.3 如何启用 Claude Code 原生团队功能

- 需要在`~/.claude/settings.json`中配置：
```json
{
  "env": {
    "CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS": "1"
  }
}
```

- 如果 Team 被禁用，OMC 会：
  - 发出警告
  - 尽可能退回到非 Team 的执行模式

##### 4. 多模型协作：Codex、Gemini、Claude 可以分工合作

###### 4.1 `omc-teams`：在 tmux 中启动真实 CLI 工作者

- 从**v4.4.0**起，OMC 移除了 Codex/Gemini MCP 服务器（`x`、`g`提供商）。
- 官方建议改用：
```bash
/omc-teams 2:codex "review auth module for security issues"
/omc-teams 2:gemini "redesign UI components for accessibility"
/omc-teams 1:claude "implement the payment flow"
```

- 这些命令会在`tmux`分屏里启动真实的 CLI 进程。

###### 4.2 `ccg`：一个命令同时调用 Codex + Gemini

- 如果想同时让 Codex 和 Gemini 协作，可使用：
```bash
/ccg Review this PR — architecture (Codex) and UI components (Gemini)
```

- 分工很明确：
  - **Codex**：代码审查、安全分析、架构
  - **Gemini**：UI/UX、文档、大上下文任务
  - **Claude**：通用任务和最终整合

###### 4.3 资源使用方式

- 工作者是**按需生成**的，任务完成后会**自动退出**。
- 好处是：**不会浪费空闲资源**。
- 但前提是：
  - 已安装`codex` / `gemini` CLI
  - 当前有活跃的`tmux`会话

##### 5. 为什么值得用：官方强调的几个核心优势

文中给出的主要卖点包括：

- **无需配置**：开箱即用，默认设置智能
- **Team 优先编排**：统一的多智能体接口
- **自然语言交互**：不需要背命令
- **自动并行化**：复杂任务会自动分配给专业智能体
- **持久执行**：不会半途停下，直到验证完成

##### 6. 支持哪些执行模式：从全自动到最大并行

OMC 提供多种工作模式，覆盖不同开发场景：

  - 三模型并行
  - Codex 负责分析，Gemini 负责设计，Claude 负责综合

  - 全自动端到端开发
  - 适合快速生成完整功能

- `Ultrawork`
  - 最大并行化
  - 适合并发修复、重构

- `Ralph`
  - 持久模式
  - 适合 “必须做完” 的任务

- `Pipeline`
  - 严格顺序执行
  - 适合多阶段转换任务

- `Swarm / Ultrapilot`
  - 已是旧版入口
  - 现在实质上还是由 Team 执行

- 想省心：用`autopilot`

### 回答 · 2026-04-02 07:28:17

使用`omc`可以分成 3 步：安装、初始化、开始下任务。

**快速开始**
- 安装插件：
```bash
/plugin marketplace add https://github.com/Yeachan-Heo/oh-my-claudecode
/plugin install oh-my-claudecode
```
- 初始化配置：
```bash
/omc-setup
```
- 直接开始做事：
```bash
autopilot: build a REST API for managing tasks
```

**最常用的几种用法**
- `autopilot`：全自动执行，适合 “直接帮我做”
```bash
autopilot: build a todo app
```
- `team`：推荐模式，适合规范地拆分规划、执行、验证
```bash
/team 3:executor "fix all TypeScript errors"
```
- `deep-interview`：需求还不清楚时先澄清
```bash
/deep-interview "I want to build a task management app"
```
- `plan`：先让它帮你规划
```bash
plan the API
```
- `ralph`：持久模式，适合 “必须做完”
```bash
ralph: refactor auth
```
- `ulw`：最大并行，适合批量修复
```bash
ulw fix all errors
```

**如果你想用 Codex / Gemini 一起协作**
- 用`omc-teams`在`tmux`里启动真实 CLI 工作者：
```bash
/omc-teams 2:codex "review auth module for security issues"
/omc-teams 2:gemini "redesign UI components for accessibility"
/omc-teams 1:claude "implement the payment flow"
```
- 一个命令同时用 Codex + Gemini：
```bash
/ccg Review this PR — architecture (Codex) and UI components (Gemini)
```

**推荐你这样理解**
- 不知道怎么开始：用`deep-interview`
- 已经知道要做什么：用`autopilot`
- 想按流程稳一点：用`team`
- 想让它一定完成：用`ralph`
- 想多模型一起看：用`omc-teams`或`ccg`

**使用前最好确认**
- 如果要用 Team，建议在`~/.claude/settings.json`开启：
```json
{
  "env": {
    "CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS": "1"
  }
}
```
- 如果要用`omc-teams`：
  - 需要有活跃的`tmux`
  - 需要安装对应 CLI，比如`codex`或`gemini`

**更新 OMC**
```bash
/plugin marketplace update omc
/omc-setup
```
- 如果更新后异常，可运行：
```bash
/omc-doctor
```

**一个最简单的上手流程**
1. 运行`/omc-setup`
2. 先试：
```bash
/deep-interview "我想做一个任务管理系统"
```
3. 明确需求后再执行：
```bash
autopilot: build a task management app
```
