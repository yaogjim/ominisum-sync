**@levelsio**

我觉得我已经几乎完全独自在我的虚拟专用服务器(VPS)上使用 Claude Code 编程快一年了

我只能说，这简直太棒了：  
无需一直开着笔记本电脑  
无笔记本电脑电池耗电  
可以随时切换到手机或任何你喜欢的其他设备继续使用（比如当你在外面的时候）  
它会在你睡觉时整夜持续运行（尤其是使用/goal 的时候）  
你可以从零开始开发项目，并在几秒钟内上线，因为你已经在服务器上了，这很棒，因为可以快速部署并让人们快速使用（而不是被困在本地笔记本电脑的 web 服务器上）  
这感觉就像生活在未来一样

我过去常常在笔记本电脑上编码，在本地测试，然后推送到 GitHub，然后它自动拉取并部署到生产环境，这会让我大约 1 分钟就能推出一个新功能

但几年前我买了一台新的 MacBook Pro 时，我懒得安装本地 Nginx 环境，于是直接开始推到生产环境，一切都很顺利。而且我把从笔记本到服务器的部署速度加快到了大约 3 秒，这也让别人觉得我疯了

但在过去一年中，我在 VPS 上使用 Claude Code 时，它会在生产服务器上进行实时编辑。这听起来本该出问题，但实际上没有。它非常谨慎，12 个月内只出错两次，这意味着我的网站有 10 秒无法加载，但这没问题

如果我不是一个人工作，比如在大公司里，我会推荐同样的工作流程，但会加上一个测试服务器，这样就不会影响到生产环境，出于安全和法规等原因。不过对我来说没问题。

我完全同意 @theo  
完全，我很清楚这就是发展方向，同时看到 @karpathy  
随着 Claude 向云端迁移（通过 Slack 等方式），我认为 AI "agents" 和 AI 编程将首先在服务器上/从云端运行

附言：我有 3-2-1 备份，多个本地和异地备份，即使你不用 AI 编程，你也应该拥有这些备份，安全第一！

## 通俗精炼（1）

#### AI 编程的新范式：把 Coding Agent 放到云端服务器

##### 核心观点

作者认为：未来 AI 编程代理不会主要运行在开发者笔记本上，而会逐步迁移到云端 / VPS 上运行。  
他自己已经近一年几乎完全在 VPS 上使用 Claude Code 编程，体验非常好，甚至直接在生产服务器上实时修改代码。

##### 他的实际工作流

过去的流程是：

1. 本地笔记本写代码  
2. 本地测试  
3. 推送到 GitHub  
4. 自动部署到生产环境  

后来他逐渐简化为：

1. 直接 SSH 到 VPS  
2. 在服务器上用 Claude Code 编程  
3. 直接修改、测试、上线  

因为代码本来就在服务器上，所以从开发到部署几乎是秒级完成。

##### 主要优势

###### 1. 设备解耦

不再依赖笔记本电脑：

- 不需要一直开着电脑
- 不耗笔记本电池
- 可以随时用手机、平板或其他设备接入继续工作

###### 2. AI 可以持续运行

Claude Code 可以在服务器上长时间执行任务，甚至在人睡觉时继续跑。  
尤其适合使用`/goal`这类长期目标型任务。

###### 3. 部署速度极快

因为开发环境和生产环境都在服务器上，项目可以从零开始快速上线。  
作者认为这比传统 “本地开发 → GitHub → CI/CD → 生产” 的流程更快。

###### 4. 更接近未来形态

作者认同 Theo 的判断：大多数开发者会把代码代理从本地电脑迁到云端。  
随着 Claude、Slack 等工具云端化，AI Agent 和 AI 编程很可能优先在服务器 / 云端运行。

##### 风险与边界

###### 直接改生产环境有风险

作者承认，直接在生产服务器上实时编辑代码听起来很危险。  
但他过去一年只出现过两次问题，每次网站大约 10 秒不可用，对他个人项目来说可以接受。

###### 团队 / 公司不应直接照搬

如果是在大公司或多人协作环境，他建议增加测试服务器或预发布环境，避免直接影响生产。  
原因包括：

- 安全风险
- 合规要求
- 多人协作冲突
- 生产稳定性要求更高

##### 安全建议

作者特别强调备份和网络安全：

- 使用 3-2-1 备份策略
- 本地和异地多份备份
- VPS 配合 Tailscale、Cloudflare Tunnel
- 防火墙阻断不必要的入站流量

即使不使用 AI 编程，也应该做好备份。

##### 产品与行业启示

###### 1. 开发环境正在从 “本地 IDE” 转向 “云端工作台”

AI Agent 不只是辅助写代码，而是在改变开发基础设施。  
未来开发者可能只需要一个终端入口，真正的计算、执行、部署都在云端完成。

###### 2. AI 编程产品会更偏 Agent + DevOps

下一代 AI 编程工具不只是补全代码，而是要能：

- 访问服务器
- 修改配置
- 执行命令
- 部署服务
- 监控结果
- 自动修复问题

这会让 AI 编程工具与云服务器、CI/CD、安全、监控系统深度融合。

###### 3. 独立开发者会率先采用激进流程

个人开发者对稳定性和流程规范的要求较低，更看重速度。  
因此 “AI + VPS + 直接部署” 的模式会先在独立开发者、小团队中流行，再逐步被企业以更规范的方式吸收。

##### 一句话总结

这篇内容本质上是在说：AI 编程的主战场正在从本地电脑迁移到云端服务器，开发、运行、部署将越来越一体化，而 AI Agent 会成为云端开发流程的核心执行者。
