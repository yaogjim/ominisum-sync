## 通俗精炼（1）

### 2026-05-04 13:34:13

#### AI 抓取工具清单：按场景选工具，而不是靠记忆试错

##### 核心内容

作者整理了一批自己用过的网页与数据抓取工具，主要用于给 Claude Code / AI Agent 配置外部信息获取能力。  
这些工具覆盖网页抓取、社交平台、搜索、浏览器交互、JS 渲染、反爬、文档查询等场景。

作者的核心观点是：**工具太多后，真正的问题不是有没有工具，而是 AI 面对一个链接或任务时该选哪个工具。**  
解决方式是：**写一套路由规则，让 AI 根据任务类型自动选择合适工具。**

---

##### 工具分类与适用场景

###### 1. 多平台结构化抓取

- **opencli**  
  适合抓取 50+ 平台的结构化数据。

###### 2. X / Twitter 数据

- **xreach**  
  适合读取推文、搜索内容、抓 timeline。
- **6551 MCP**  
  面向 X 数据与 Crypto 新闻场景。

###### 3. 通用网页读取

- **Jina Reader**  
  适合公开网页内容提取，偏轻量、通用。
- **XCrawl**  
  作为“终极兜底”方案，用于其他工具不好处理的网页。

###### 4. 浏览器与网页交互

- **web-access**  
  通过 CDP 直连 Chrome，适合日常浏览器级访问。
- **Chrome MCP**  
  通过 Chrome 扩展实现浏览器交互。
- **Playwright MCP**  
  适合需要 JS 渲染、页面自动化操作的场景。

###### 5. 反爬与复杂网页

- **Scrapling**  
  适合处理有反爬机制的网站。
- **Apify**  
  适合特定平台的深度爬取，也有现成抓取器生态。

###### 6. 搜索与文档查询

- **Grok Bridge**  
  用于 Grok 搜索能力接入。
- **Context7**  
  适合查询技术文档、上下文资料。

---

##### 产品视角总结

这条内容本质上不是简单的“工具推荐”，而是在讲 **AI Agent 的工具编排问题**：

> 当工具数量变多，关键能力从“会调用工具”升级为“会选择工具”。

对产品和 AI 应用设计来说，重点有三个：

1. **按任务场景拆分工具能力**  
   不同工具解决不同类型的信息获取问题。

2. **建立工具路由规则**  
   让 AI 根据链接类型、网站特征、是否需要登录、是否需要 JS 渲染等条件自动选工具。

3. **保留兜底方案**  
   当前置工具失败时，需要有浏览器交互、Playwright、Apify、XCrawl 等兜底路径。

---

##### 一句话总结

作者分享了一套 AI 抓网页/抓数据的工具栈，并指出真正高效的做法不是人工记住每个工具，而是让 AI 通过路由规则自动选择最合适的抓取工具。

## 结构化（1）

### 2026-05-04 13:41:35

##### 主旨概括

这篇帖子整理了一批作者实际安装和使用过的网页/数据抓取工具，覆盖结构化抓取、推文读取、公开网页解析、浏览器自动化、反爬、JS 渲染、文档查询等场景。作者的核心建议是：工具很多、能力重叠，最好写一套路由规则，让 AI 根据任务自动选择合适工具。

##### 1. 背景：工具太多，选择成了新问题

作者之前给 Claude Code 安装了 **19 个抓网页工具**，但发现最大问题不是“能不能抓”，而是：

- 拿到一个链接后，不知道该用哪个工具；
- 很多工具能力重叠，比如 xreach、Jina、Chrome MCP、Playwright、Apify、Scrapling 等；
- 同一个需求经常有四五个工具都能做；
- 如果靠记忆手动选择，选错就会多一轮试错成本。

因此，作者把自己装过的工具整理出来，方便大家按需求自选。

##### 2. 按用途整理的抓取工具

###### 结构化抓取：opencli

- 用途：支持 **50+ 平台结构化抓取**
- 链接：&lt;http://github.com/jackwener/opencli>
- 适合场景：需要从多个平台提取结构化数据时使用。

###### X / Twitter 数据：xreach

- 用途：读推文、搜索、获取 timeline
- 链接：&lt;http://github.com/Panniantong/Agent-Reach>
- 适合场景：抓取或分析 X 平台内容。

###### 公开网页读取：Jina Reader

- 用途：读取公开网页内容
- 链接：&lt;http://github.com/jina-ai/reader>
- 适合场景：把网页转换成更适合 AI 阅读的文本内容。

###### Chrome 直连：web-access

- 用途：通过 CDP 直连 Chrome
- 链接：&lt;http://github.com/eze-is/web-access>
- 适合场景：需要直接控制浏览器、访问网页内容时使用。

###### 反爬场景：Scrapling

- 用途：应对反爬机制
- 链接：&lt;http://github.com/D4Vinci/Scrapling>
- 适合场景：普通抓取工具无法稳定访问的网站。

###### JS 渲染网页：Playwright MCP

- 用途：处理需要 JavaScript 渲染的网页
- 链接：&lt;http://github.com/executeautomation/mcp-playwright>
- 适合场景：网页内容必须通过浏览器渲染后才能看到。

###### Grok 搜索：Grok Bridge

- 用途：调用或桥接 Grok 搜索
- 链接：&lt;http://github.com/ythx-101/grok-bridge>
- 适合场景：需要使用 Grok 相关搜索能力时。

###### 文档查询：Context7

- 用途：文档查询
- 链接：&lt;http://github.com/upstash/context7>
- 适合场景：查询技术文档、库文档等。

###### X 数据 + Crypto 新闻：6551 MCP

- 用途：X 数据和加密货币新闻
- 链接：&lt;http://6551.io/login?code=y5ECeG>
- 适合场景：关注 X 舆情和 Crypto 新闻信息流。

###### 特定平台深度爬取：Apify

- 用途：特定平台的深度爬取
- 链接：&lt;http://console.apify.com/sign-up?fpr=xgahwh>
- 适合场景：需要成熟爬虫模板或深度采集特定平台数据。

###### 浏览器交互：Chrome MCP

- 用途：浏览器交互
- 获取方式：Chrome 扩展商店搜索 **Claude in Chrome**
- 适合场景：让 AI 操作浏览器完成点击、输入、读取页面等任务。

###### 终极兜底：XCrawl

- 用途：兜底抓取方案
- 链接：&lt;http://xcrawl.com>
- 适合场景：前面工具都不合适或失败时尝试。

##### 3. 作者的使用建议

作者提到，这些工具 **全部免费或有免费额度**，因此可以组合使用。

关键建议是：

- 不要完全靠人工记忆选择工具；
- 可以写一套路由规则；
- 让 AI 根据任务类型自动判断该用哪个工具。

例如：

- 抓普通公开网页：优先用 Jina Reader；
- 抓 X 推文：用 xreach；
- 页面需要 JS 渲染：用 Playwright MCP；
- 遇到反爬：尝试 Scrapling；
- 需要真实浏览器操作：用 Chrome MCP 或 web-access；
- 不确定时：用 XCrawl 兜底。
