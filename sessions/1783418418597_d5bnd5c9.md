#### MarkItDown

MarkItDown is a lightweight Python utility for converting various files to Markdown for use with LLMs and related text analysis pipelines. To this end, it is most comparable to [textract](https://github.com/deanmalmgren/textract), but with a focus on preserving important document structure and content as Markdown (including: headings, lists, tables, links, etc.) While the output is often reasonably presentable and human-friendly, it is meant to be consumed by text analysis tools -- and may not be the best option for high-fidelity document conversions for human consumption.

MarkItDown currently supports the conversion from:

- PDF
- PowerPoint
- Word
- Excel
- Images (EXIF metadata and OCR)
- Audio (EXIF metadata and speech transcription)
- HTML
- Text-based formats (CSV, JSON, XML)
- ZIP files (iterates over contents)
- Youtube URLs
- EPubs
- ... and more!

#### Why Markdown?

Markdown is extremely close to plain text, with minimal markup or formatting, but still provides a way to represent important document structure. Mainstream LLMs, such as OpenAI's GPT-4o, natively " *speak* " Markdown, and often incorporate Markdown into their responses unprompted. This suggests that they have been trained on vast amounts of Markdown-formatted text, and understand it well. As a side benefit, Markdown conventions are also highly token-efficient.

#### Prerequisites

MarkItDown requires Python 3.10 or higher. It is recommended to use a virtual environment to avoid dependency conflicts.

With the standard Python installation, you can create and activate a virtual environment using the following commands:

```
python -m venv .venv
source .venv/bin/activate
```

If using `uv`, you can create a virtual environment with:

```
uv venv --python=3.12 .venv
source .venv/bin/activate
# NOTE: Be sure to use 'uv pip install' rather than just 'pip install' to install packages in this virtual environment
```

If you are using Anaconda, you can create a virtual environment with:

```
conda create -n markitdown python=3.12
conda activate markitdown
```

#### Installation

To install MarkItDown, use pip: `pip install 'markitdown[all]'`. Alternatively, you can install it from the source:

```
git clone git@github.com:microsoft/markitdown.git
cd markitdown
pip install -e 'packages/markitdown[all]'
```

#### Usage

##### Command-Line

```
markitdown path-to-file.pdf > document.md
```

Or use `-o` to specify the output file:

```
markitdown path-to-file.pdf -o document.md
```

You can also pipe content:

```
cat path-to-file.pdf | markitdown
```

##### Optional Dependencies

MarkItDown has optional dependencies for activating various file formats. Earlier in this document, we installed all optional dependencies with the `[all]` option. However, you can also install them individually for more control. For example:

```
pip install 'markitdown[pdf, docx, pptx]'
```

will install only the dependencies for PDF, DOCX, and PPTX files.

At the moment, the following optional dependencies are available:

- `[all]` Installs all optional dependencies
- `[pptx]` Installs dependencies for PowerPoint files
- `[docx]` Installs dependencies for Word files
- `[xlsx]` Installs dependencies for Excel files
- `[xls]` Installs dependencies for older Excel files
- `[pdf]` Installs dependencies for PDF files
- `[outlook]` Installs dependencies for Outlook messages
- `[az-doc-intel]` Installs dependencies for Azure Document Intelligence
- `[az-content-understanding]` Installs dependencies for Azure Content Understanding
- `[audio-transcription]` Installs dependencies for audio transcription of wav and mp3 files
- `[youtube-transcription]` Installs dependencies for fetching YouTube video transcription

##### Plugins

MarkItDown also supports 3rd-party plugins. Plugins are disabled by default. To list installed plugins:

```
markitdown --list-plugins
```

To enable plugins use:

```
markitdown --use-plugins path-to-file.pdf
```

To find available plugins, search GitHub for the hashtag `#markitdown-plugin`. To develop a plugin, see `packages/markitdown-sample-plugin`.

###### markitdown-ocr Plugin

The `markitdown-ocr` plugin adds OCR support to PDF, DOCX, PPTX, and XLSX converters, extracting text from embedded images using LLM Vision — the same `llm_client` / `llm_model` pattern that MarkItDown already uses for image descriptions. No new ML libraries or binary dependencies required.

**Installation:**

```
pip install markitdown-ocr
pip install openai  # or any OpenAI-compatible client
```

**Usage:**

Pass the same `llm_client` and `llm_model` you would use for image descriptions:

```
from markitdown import MarkItDown
from openai import OpenAI

md = MarkItDown(
    enable_plugins=True,
    llm_client=OpenAI(),
    llm_model="gpt-4o",
)
result = md.convert("document_with_images.pdf")
print(result.text_content)
```

If no `llm_client` is provided the plugin still loads, but OCR is silently skipped and the standard built-in converter is used instead.

See `packages/markitdown-ocr/README.md` for detailed documentation.

[Azure Content Understanding](https://learn.microsoft.com/azure/ai-services/content-understanding/) provides higher-quality conversion with structured field extraction (YAML front matter), multi-modal support (documents, images, audio, video), and configurable analyzers.

Install: `pip install 'markitdown[az-content-understanding]'`

Content Understanding is ideal when you need capabilities beyond what built-in or Document Intelligence converters provide:

- **Audio and video files** — CU is the only option for video, and the higher-quality cloud option for audio. Built-in converters have no video support and only basic audio transcription.
- **Structured field extraction** — [Prebuilt](https://learn.microsoft.com/azure/ai-services/content-understanding/concepts/prebuilt-analyzers) or [custom-built](https://learn.microsoft.com/azure/ai-services/content-understanding/how-to/customize-analyzer-content-understanding-studio?tabs=portal) analyzers extract domain-specific fields (invoice amounts, receipt dates, contract clauses) serialized as YAML front matter. Neither built-in nor Doc Intel integration exposes fields.
- **Higher-quality document extraction** — Cloud-based layout analysis and OCR for scanned PDFs, complex tables, and multi-page documents.
- **Single API for all modalities** — One `cu_endpoint` handles documents, images, audio, and video with automatic analyzer routing.

**CLI:**

```
markitdown path-to-file.pdf --use-cu --cu-endpoint "<content_understanding_endpoint>"
```

**Python API:**

```
from markitdown import MarkItDown

# Zero-config — auto-selects analyzer per file type
md = MarkItDown(cu_endpoint="<content_understanding_endpoint>")
result = md.convert("report.pdf")   # documents → prebuilt-documentSearch
result = md.convert("meeting.mp4")  # video → prebuilt-videoSearch
result = md.convert("call.wav")     # audio → prebuilt-audioSearch
print(result.markdown)
```

**With a custom analyzer** (for domain-specific field extraction):

```
md = MarkItDown(
    cu_endpoint="<content_understanding_endpoint>",
    cu_analyzer_id="my-invoice-analyzer",
)
result = md.convert("invoice.pdf")
print(result.markdown)
# Output includes YAML front matter with extracted fields:
# ---
# contentType: document
# fields:
#   VendorName: CONTOSO LTD.
#   InvoiceDate: '2019-11-15'
# ---
# <!-- page 1 -->
# ...
```

When `cu_analyzer_id` is set, the converter automatically scopes it to compatible file types based on the analyzer's modality. Incompatible types (e.g., audio files with a document analyzer) auto-route to default prebuilt analyzers.

**Cost note:** Each `convert()` call for a CU-routed format is a billable Azure API call. Use `cu_file_types` to restrict which formats route to CU:

```
from markitdown.converters import ContentUnderstandingFileType

md = MarkItDown(
    cu_endpoint="<content_understanding_endpoint>",
    cu_file_types=[ContentUnderstandingFileType.PDF],  # only PDFs use CU
)
```

More information about Azure Content Understanding can be found [here](https://learn.microsoft.com/azure/ai-services/content-understanding/).

To use Microsoft Document Intelligence for conversion:

```
markitdown path-to-file.pdf -o document.md -d -e "<document_intelligence_endpoint>"
```

More information about how to set up an Azure Document Intelligence Resource can be found [here](https://learn.microsoft.com/en-us/azure/ai-services/document-intelligence/how-to-guides/create-document-intelligence-resource?view=doc-intel-4.0.0)

##### Security Considerations

MarkItDown performs I/O with the privileges of the current process. Like `open()` or `requests.get()`, it will access resources that the process itself can access.

**Sanitize your inputs:** Do not pass untrusted input directly to MarkItDown. If any part of the input may be controlled by an untrusted user or system, such as in hosted or server-side applications, it must be validated and restricted before calling MarkItDown. Depending on your environment, this may include restricting file paths, limiting URI schemes and network destinations, and blocking access to private, loopback, link-local, or metadata-service addresses.

**Call only the conversion method you need:** Prefer the narrowest conversion API that fits your use case. MarkItDown's `convert()` method is intentionally permissive and can handle local files, remote URIs, and byte streams. If your application only needs to read local files, call `convert_local()` instead. If you need more control over URI fetching, call `requests.get()` yourself and pass the response object to `convert_response()`. For maximum control, open a stream to the input you want converted and call `convert_stream()`.

You can also contribute by creating and sharing 3rd party plugins. See `packages/markitdown-sample-plugin` for more details.

#### Microsoft MarkItDown 项目总结

MarkItDown 是微软开源的轻量级 Python 工具，用于把 PDF、Office 文档、图片、音频、网页等多种文件转换成 Markdown，主要服务于 LLM 和文本分析流程。它更重视保留标题、列表、表格、链接等结构信息，而不是追求面向人类阅读的高保真排版还原。

##### 1. 项目定位与支持格式

MarkItDown 类似`textract`，但核心目标是把文档内容结构化为 Markdown，方便大语言模型和文本分析工具处理。

**当前支持转换的内容包括：**

- PDF
- PowerPoint
- Word
- Excel
- 图片：支持 EXIF 元数据和 OCR
- 音频：支持 EXIF 元数据和语音转写
- HTML
- 文本类格式：CSV、JSON、XML
- ZIP：会遍历压缩包内容
- YouTube URL
- EPUB
- 以及更多格式

需要注意的是，MarkItDown 的输出通常具备一定可读性，但主要面向机器处理，不一定适合需要精细排版的人类阅读场景。

##### 2. 为什么选择 Markdown？

项目认为 Markdown 非常适合 LLM 场景，原因包括：

- **接近纯文本**：格式简单，便于处理。
- **能表达文档结构**：如标题、列表、表格、链接等。
- **LLM 友好**：主流大模型如 GPT-4o 经常自然生成 Markdown，说明模型对 Markdown 理解较好。
- **Token 效率高**：Markdown 标记简洁，有利于节省上下文成本。

##### 7. Azure Content Understanding：更高质量的云端转换

Azure Content Understanding，简称 CU，适合需要更强结构化能力和多模态处理的场景。

安装：

```bash
pip install 'markitdown [az-content-understanding]'
```

适用场景：

- **音频和视频处理**：CU 是文中提到的视频处理唯一方案，音频质量也高于内置基础转写。
- **结构化字段抽取**：例如从发票中提取金额、日期、供应商，从合同中提取条款。
- **复杂文档解析**：适合扫描 PDF、复杂表格、多页文档。
- **统一多模态 API**：一个`cu_endpoint`可处理文档、图片、音频、视频。

能力对比：

| 能力 | 内置转换器 | Azure Document Intelligence | Azure Content Understanding |
|---|---|---|---|
| 文档转换 | 离线、按格式提取 | 云端版面提取 | 云端多模态提取 |
| 结构化字段 | 不支持 | 当前集成未暴露 | 支持，输出 YAML front matter |
| 自定义分析器 | 不支持 | 当前集成不可配置 | 支持`cu_analyzer_id` |
| 音视频 | 基础音频，无视频 | 不支持 | 支持音频和视频 |
| 成本 | 本地计算 | Azure API 计费 | Azure API 计费 |

CLI 示例：

```bash
markitdown path-to-file.pdf --use-cu --cu-endpoint "<content_understanding_endpoint>"
```

Python 示例：

```python
from markitdown import MarkItDown

md = MarkItDown (cu_endpoint="<content_understanding_endpoint>")

result = md.convert ("report.pdf")    # 文档
result = md.convert ("meeting.mp4")   # 视频
result = md.convert ("call.wav")      # 音频

print (result.markdown)
```

使用自定义分析器提取字段：

```python
md = MarkItDown (
    cu_endpoint="<content_understanding_endpoint>",
    cu_analyzer_id="my-invoice-analyzer",
)

result = md.convert ("invoice.pdf")
print (result.markdown)
```

示例输出会包含 YAML 元数据：

```yaml
---
contentType: document
fields:
  VendorName: CONTOSO LTD.
  InvoiceDate: '2019-11-15'
---
```

成本提醒：每次使用 CU 路由的`convert ()`调用都是一次可计费 Azure API 调用。可用`cu_file_types`限制哪些格式走 CU，例如只让 PDF 使用 CU。

#### MarkItDown：把各种文件转换成适合人工智能处理的 Markdown

这份材料介绍的是微软开源的 MarkItDown。它是一个轻量级的 Python 工具，可以把 PDF、Word、Excel、演示文稿、图片、音频等文件，转换成结构清晰的 Markdown 文本。接下来，你会了解它适合什么场景、怎么安装和使用，以及插件、云服务和安全方面需要注意什么。

##### 一、它解决的核心问题：让文件更容易被人工智能理解

首先，MarkItDown 的核心作用，是把不同格式的文件转换成 Markdown，供大语言模型，也就是通常所说的 LLM，以及其他文本分析工具使用。

通俗地说，很多资料原本分散在 PDF、幻灯片、表格、网页或音频里。MarkItDown 会尽量保留这些资料的重要结构，比如标题、列表、表格和链接，再统一整理成接近纯文本的 Markdown。这样，人工智能处理起来会更方便。

它目前支持的类型很多，包括 PDF、PowerPoint 演示文稿、Word 文档、Excel 表格、图片、音频、HTML 网页，以及 CSV、JSON、XML 等文本格式。它还可以处理 ZIP 压缩包，逐个转换其中的内容，也支持 YouTube 地址和 EPUB 电子书等格式。

图片方面，它可以读取 EXIF，也就是图片中记录的拍摄时间、设备等元数据；在配置相应能力后，还可以使用 OCR，也就是光学字符识别，从图片里提取文字。音频则可以读取元数据，并进行语音转写。

不过要注意，MarkItDown 的目标不是做面向人类阅读的高保真排版转换。它更看重内容和结构能否被文本分析工具使用。转换结果通常已经比较清晰、易读，但不一定能完全还原原文件的视觉样式。

##### 二、为什么选择 Markdown

接下来，材料解释了 MarkItDown 为什么使用 Markdown 作为统一输出格式。

核心原因是，Markdown 很接近普通文本，但又能用很少的标记表达标题、列表、表格等结构。这样既保留了文档的组织方式，又不会像复杂排版格式那样难以处理。

许多主流大语言模型，例如 GPT-4o，都能直接理解 Markdown，而且经常会在回答中主动使用 Markdown。这说明模型接触过大量 Markdown 格式的文本，也比较熟悉它的表达方式。

另一个好处是，Markdown 使用的标记很少，因此比较节省 token。Token 可以简单理解为人工智能处理文本时使用的基本文字单位。标记越简洁，相同内容通常就越容易被模型高效处理。

所以，MarkItDown 的定位很明确：它不是单纯追求“看起来和原文件一模一样”，而是希望把文件变成结构清楚、适合人工智能分析的文本。

这个插件使用大语言模型的视觉能力，也就是让模型理解图片中的内容。它沿用了 MarkItDown 已有的 `llm_client` 和 `llm_model` 配置方式，不需要额外安装新的机器学习库或二进制依赖。

##### 七、Azure Content Understanding：更强的云端多模态转换

对于更复杂的文档，材料还介绍了 Azure Content Understanding，也就是微软 Azure 提供的内容理解服务。

它的核心特点，是使用云端能力完成更高质量的结构化提取。它不仅能处理文档和图片，还能处理音频和视频，并可以根据分析器自动选择适合的处理方式。

与内置转换器相比，它主要增加了几类能力。

第一，是音频和视频处理。内置转换器只能进行基础的音频转写，并且不支持视频；Azure Content Understanding 可以处理音频和视频，并使用相应的分析器。

第二，是结构化字段提取。比如，它可以从发票中提取供应商名称和金额，从收据中提取日期，也可以提取合同条款。这些字段会以 YAML front matter 的形式放在 Markdown 开头。YAML front matter 可以理解为一小段结构化的元数据区域。

第三，是更高质量的文档提取。它更适合扫描版 PDF、复杂表格，以及多页文档中的布局分析和 OCR。

第四，是统一的多模态接口。只需要配置一个内容理解服务端点，就可以根据文件类型处理文档、图片、音频和视频。

不过，使用 Azure Content Understanding 的代价也更明确：每一次由它处理的 `convert` 调用，都会产生一次需要付费的 Azure API 调用。

命令行中，可以这样使用：

```bash
markitdown path-to-file.pdf \
  --use-cu \
  --cu-endpoint "<content_understanding_endpoint>"
```

在 Python 中，可以配置服务端点：

```python
from markitdown import MarkItDown

md = MarkItDown(
    cu_endpoint="<content_understanding_endpoint>"
)

result = md.convert("report.pdf")
print(result.markdown)
```

材料给出的例子是，报告 PDF 会自动选择文档分析器；会议视频会选择视频分析器；通话音频会选择音频分析器。

如果要提取特定领域的字段，还可以指定自定义分析器。例如使用发票分析器处理发票：

```python
md = MarkItDown(
    cu_endpoint="<content_understanding_endpoint>",
    cu_analyzer_id="my-invoice-analyzer",
)

result = md.convert("invoice.pdf")
print(result.markdown)
```

输出中可能包含这样的结构化信息：内容类型是文档，供应商名称是某家公司，发票日期是某一天。

如果指定的自定义分析器与文件类型不兼容，MarkItDown 会根据分析器支持的模态自动调整。例如，文档分析器不能处理音频文件时，音频会自动转到默认的预置分析器。

如果只希望某些格式使用 Azure Content Understanding，还可以通过 `cu_file_types` 限制范围。比如，只让 PDF 走云端服务，其他格式继续使用本地转换器。这样有助于控制费用。

#### MarkItDown 的真正价值：为 AI 建立统一的“文档输入层”

MarkItDown 表面上是一个格式转换工具：把 PDF、Word、Excel、PPT、图片、音频、网页乃至 ZIP 转成 Markdown。更值得关注的并不是支持格式的数量，而是它体现了一个正在成形的工程共识：**在把企业内容交给大模型之前，需要先将异构文件归一化为保留结构、又便于机器消费的中间表示。**

##### Markdown 正在成为模型侧的通用文档接口

传统文档转换通常追求视觉还原，关心字体、分页和排版；MarkItDown 明确放弃这一目标，优先保留标题、列表、表格、链接等语义结构。它输出的内容“适合文本分析工具”，却未必适合人直接阅读。

这一区分很重要。对问答、摘要、检索增强生成等任务来说，一份文档最有价值的往往不是“看起来像原件”，而是模型能否识别章节边界、表格关系和内容层级。Markdown 恰好位于纯文本与复杂文档模型之间：标记少、Token 开销低，又能表达基本结构，而且主流模型对它已经高度熟悉。

因此，MarkItDown 更像 AI 数据管道里的**适配层**，而不是另一个文件导出功能。上游可以是几十种文件，下游则统一接向切块、索引、字段提取、Agent 或知识库。这种统一接口能显著减少每个 AI 应用重复处理文件格式的成本。

##### 真正困难的不是“能否转换”，而是如何分配质量、成本与隐私

项目给出的能力分层比转换本身更有启发：简单文件可用本地解析器，扫描件和复杂表格可交给 Azure Document Intelligence，更复杂的多模态内容及领域字段则使用 Azure Content Understanding；还可以用视觉模型处理嵌入图片和 OCR。

这意味着文档理解不应采用单一方案。理想的产品策略是按任务动态路由：

- 普通 DOCX、结构清晰的 PDF，本地解析，低成本且数据不出域；
- 扫描件、宽表格、复杂版面，调用付费云端解析；
- 发票、合同等场景，直接按预定义 Schema 提取字段，而非先得到长文本再让模型猜测。

关键指标也就不只是“转换成功率”，而是**字段准确率、结构保真度、调用成本、处理时延和隐私要求**。README 展示了能力边界，却没有给出跨格式评测或准确率对比，因此它证明的是一种合理架构，而不是某个解析方案已经全面领先。

##### 产品机会在编排与评测，而非再做一个转换器

对企业 AI 产品而言，更可能形成价值的不是支持更多扩展名，而是建立一套可观测的文档摄取系统：自动判断文件类型和质量，选择解析路径，标记页码与来源，发现低置信度结果，并用下游任务验证转换效果。例如，合同系统真正需要验证的是关键条款能否稳定召回，而不是生成的 Markdown 是否整洁。

这里也有一个容易被忽视的安全边界。MarkItDown 的通用 `convert()` 可以处理本地文件、远程 URI 和字节流；在服务端直接接收不可信输入，可能带来任意文件访问或内部网络请求风险。项目因此建议限制路径、协议和网络目标，并优先使用 `convert_local()`、`convert_stream()` 等更窄的接口。**当“万能转换”被包装成 SaaS 能力时，输入权限控制本身就是产品设计的一部分。**

MarkItDown 最值得保留的判断是：面向 AI 的文档处理正在从“把文件转成文本”，转向“以可控成本生成带结构、可追溯、适合下游任务的模型输入”。Markdown 是一个实用接口，但真正的竞争力将来自路由、评测、安全与领域 Schema。
