- **核心高价值点**：将“完成”定义为基于测试、检查和证据的完成合约，而不是由智能体主观声称任务完成。
- **留存建议**：短期参考后可删除
- **不足**：内容主要是发布公告和功能清单，营销性较强，技术实现细节不足，贡献者名单占用大量篇幅，长期知识价值有限。

**知识要点**

- MoA 多智能体混合被集成为可直接选择的虚拟模型预设，并支持查看各参考模型输出与聚合流式响应。

- 桌面端强化编码项目组织、Git 工作树管理、评审面板和记忆图谱。

**行动项**

- 如果正在使用 Hermes Agent，可查看 v0.18.0 的 MoA、/goal、/learn 和 /journey 是否适合纳入工作流。
- 借鉴完成合约思路，为 AI 编码任务定义明确验收标准和自动化验证步骤。

#### Hermes Agent v0.18.0 (v2026.7.1)

**Release Date:** July 1, 2026  
**Since v0.17.0:** \~1,720 commits · 998 merged PRs · 2,215 files changed · \~251,000 insertions · \~41,000 deletions · **949 issues closed** · **370+ community contributors**

> **The Judgment Release.** Over the last week and a half the team put nearly all of its effort into one goal: resolve **every P0 and P1 issue and PR in the entire Hermes Agent repo** — and as of this release, **100% of them are closed.** Zero open P0s. Zero open P1s. That's **\~700 highest-priority items** cleared as part of **\~1,950 total issues and PRs closed** this window. We intend to keep P0/P1 at zero from here on.
>
> On top of that clean-sweep, v0.18.0 is about how *well* Hermes thinks and how it *knows when its work is actually done*. Mixture-of-Agents became a first-class citizen — named ensembles of models you can pick like any other model, with every reference model's reasoning shown to you and the aggregator's answer streamed live. The agent learned to verify its own work against evidence instead of vibes, `/goal` gained completion contracts, and `/learn` + `/journey` turned self-improvement into something you can see and steer. Underneath, the gateway became genuinely deployable-at-scale (scale-to-zero, drain coordination), the desktop grew first-class coding projects and a playable memory graph, and subagents can now fan out in the background.

#### ✨ Highlights

- **Mixture-of-Agents is now a first-class model you can pick** — MoA used to be a mode you toggled; now every named MoA preset shows up as a selectable model under a `moa` provider, right alongside Claude, GPT, and Grok in every model picker (CLI, TUI, desktop, gateway). Pick "my-council" the same way you'd pick any model, and Hermes routes your prompt through that ensemble automatically. An ensemble of frontier models deliberating on your hardest questions is now one selection away, on every surface. ([#46081](https://github.com/NousResearch/hermes-agent/pull/46081), [#53548](https://github.com/NousResearch/hermes-agent/pull/53548), [#53561](https://github.com/NousResearch/hermes-agent/pull/53561) — [@teknium1](https://github.com/teknium1))
- **See every model's reasoning, then watch the answer stream in** — When a MoA ensemble runs, each reference model's full output now renders as its own labelled block — you can read what GPT-5 thought, what Claude thought, and what Grok thought, before the aggregator synthesizes them into one answer. And that final answer now streams to you live instead of appearing all at once after a long silence. This works in the CLI, the TUI, and the desktop app. You get to watch the committee deliberate, not just read the verdict. ([#53793](https://github.com/NousResearch/hermes-agent/pull/53793), [#53855](https://github.com/NousResearch/hermes-agent/pull/53855), [#55625](https://github.com/NousResearch/hermes-agent/pull/55625), [#56101](https://github.com/NousResearch/hermes-agent/pull/56101) — [@teknium1](https://github.com/teknium1))
- **The agent verifies its own work — "done" means proven, not claimed** — Hermes now records verification evidence for coding work and can decide it's finished by actually running your project's checks, not by asserting success. `/goal` gained **completion contracts**: you state what "done" looks like, and the standing-goal loop judges completion against that evidence instead of stopping when the model feels like it. There's a `pre_verify` hook for wiring in custom checks and a one-time migration that tunes the defaults sensibly. The difference between "I think I fixed it" and "the tests pass, here's proof." ([#50501](https://github.com/NousResearch/hermes-agent/pull/50501), [#52285](https://github.com/NousResearch/hermes-agent/pull/52285), [#55413](https://github.com/NousResearch/hermes-agent/pull/55413), [#53552](https://github.com/NousResearch/hermes-agent/pull/53552) — [@teknium1](https://github.com/teknium1), [@OutThisLife](https://github.com/OutThisLife))
- **`/learn` — turn anything into a reusable skill by describing it** — Run `/learn <anything>` and Hermes distills a reusable skill out of whatever you point it at — a directory, a URL, or just the workflow you walked it through five minutes ago. It writes the skill to the standards in your CONTRIBUTING.md automatically. The next time you need that workflow, it's already there. Teaching Hermes a new trick is now a single command, not a manual skill-authoring session. ([#51506](https://github.com/NousResearch/hermes-agent/pull/51506), [#52372](https://github.com/NousResearch/hermes-agent/pull/52372) — [@teknium1](https://github.com/teknium1))
- **`/journey` — a playable timeline of everything Hermes has learned about you** — The CLI and TUI gained `/journey`, a learning timeline that shows the memories and skills Hermes has accumulated over time — and you can edit or delete any of them right from the view. Pair it with the desktop's new **memory graph** (a top-down, playable radial timeline of memories and skills) and for the first time you can actually *see* what your agent knows, watch it grow, and prune what's wrong. Your agent's memory stops being a black box. ([#55555](https://github.com/NousResearch/hermes-agent/pull/55555), [#55859](https://github.com/NousResearch/hermes-agent/pull/55859), [#55226](https://github.com/NousResearch/hermes-agent/pull/55226) — [@OutThisLife](https://github.com/OutThisLife))
- **Delegate a pile of work and keep going — background fan-out** — `delegate_task` can now fan out multiple subagents that all run in the **background**: your chat is never blocked, and when every subagent finishes, their results come back as a single consolidated turn. Kick off "research these five competitors in parallel" or "audit these three modules," then carry on with something else while a small fleet works. When it's all done, you get one clean summary instead of babysitting each one. ([#49734](https://github.com/NousResearch/hermes-agent/pull/49734) — [@teknium1](https://github.com/teknium1))
- **First-class coding Projects in the desktop app** — The desktop app gained real, per-profile **Projects** — a sidebar of your codebases, a coding rail, a review pane, git worktree management, and agent-facing project tools, all backed by a proper `project → repo → lane` model. Instead of scattered chat sessions, your coding work is organized into projects the agent understands and can act on. It's the desktop turning into an actual coding cockpit. ([#49037](https://github.com/NousResearch/hermes-agent/pull/49037), [#54385](https://github.com/NousResearch/hermes-agent/pull/54385), [#54517](https://github.com/NousResearch/hermes-agent/pull/54517) — [@OutThisLife](https://github.com/OutThisLife))
- **Run Hermes at scale — scale-to-zero and drain coordination** — The gateway can now go **dormant when idle** and quiesce cleanly before a restart, migration, or auto-update — without dropping in-flight conversations. A hosted or relay-only Hermes can scale to zero when nobody's talking to it and wake back up on demand, and disruptive lifecycle actions coordinate an external drain so nobody gets cut off mid-turn. Running Hermes for a team or as a hosted service just got a lot more production-grade. ([#52243](https://github.com/NousResearch/hermes-agent/pull/52243), [#52937](https://github.com/NousResearch/hermes-agent/pull/52937), [#54824](https://github.com/NousResearch/hermes-agent/pull/54824) — [@teknium1](https://github.com/teknium1), [@benbarclay](https://github.com/benbarclay))
- **Cheaper self-improvement — smarter background review** — The post-turn self-improvement fork (the one that decides whether to save a memory or skill) now routes to an auxiliary model, digests context instead of replaying the whole conversation, and adapts its cadence — so the "learn from what just happened" loop that runs after your turns costs a fraction of what it used to. You keep the self-improvement, you stop paying full main-model price for it. ([#49252](https://github.com/NousResearch/hermes-agent/pull/49252) — [@teknium1](https://github.com/teknium1))
- **Compose your next prompt in your editor — `/prompt`** — `/prompt` opens your `$EDITOR` so you can hand-write a long, multi-line prompt in real markdown instead of fighting a one-line input box. Draft a detailed spec, a structured question, or a big paste, save, and it's queued as your next message. Small thing, huge quality-of-life win for anyone who writes Hermes more than a sentence at a time. ([#50509](https://github.com/NousResearch/hermes-agent/pull/50509) — [@teknium1](https://github.com/teknium1))
- **Google Vertex AI — Gemini through your GCP service account, no static key** — Vertex AI is now a first-class provider for Gemini models over Vertex's OpenAI-compatible endpoint. The reason a plain custom-provider setup always died mid-session is that Vertex has no static API key — every request needs a short-lived OAuth2 access token (\~1h TTL) minted from a service-account JSON or Application Default Credentials. Hermes now mints and auto-refreshes those tokens for you, so if your org runs Gemini through Google Cloud, you point Hermes at your service account and it just works — no token-pasting, no mid-session expiry. ([#56363](https://github.com/NousResearch/hermes-agent/pull/56363) — [@teknium1](https://github.com/teknium1), [@slawt](https://github.com/slawt))
- **Security round** — This window hardened several surfaces: MCP-config persistence attack surface locked down, cron `base_url` overrides that could exfiltrate provider credentials blocked, a non-reusable sentinel for prefix secrets in file reads, Slack app-level (`xapp-`) token redaction, a browser cloud-metadata floor enforced on every backend, and an `aiohttp` CVE floor across the lazy messaging paths. Fewer ways for a prompt-injected or misconfigured session to leak a credential. ([#50476](https://github.com/NousResearch/hermes-agent/pull/50476), [#56196](https://github.com/NousResearch/hermes-agent/pull/56196), [#54166](https://github.com/NousResearch/hermes-agent/pull/54166), [#56227](https://github.com/NousResearch/hermes-agent/pull/56227), [#52349](https://github.com/NousResearch/hermes-agent/pull/52349), [#56237](https://github.com/NousResearch/hermes-agent/pull/56237) — [@teknium1](https://github.com/teknium1), [@kshitijk4poor](https://github.com/kshitijk4poor), [@claudlos](https://github.com/claudlos))

##### 版本核心亮点

###### 1. 清空 P0/P1：工程质量进入稳定期

本次发布最大的信号是：团队在约 12 天内清理了全部 P0/P1 高优先级问题。

关键数据：

- 约 1,720 次 commit
- 998 个 PR 合并
- 949 个 issue 关闭
- 约 700 个最高优先级问题处理完成
- 当前 P0/P1 数量为 0

这意味着 Hermes Agent 正从快速迭代阶段，进入更注重稳定性、可靠性和生产可用性的阶段。

---

##### 智能能力升级

###### 2. MoA 成为一等公民：多模型 “专家委员会”

Mixture-of-Agents 不再只是一个模式，而是变成了可直接选择的 “虚拟模型”。

用户可以像选择 GPT、Claude、Grok 一样，选择一个 MoA 组合模型。Hermes 会自动把问题分发给多个模型，再由聚合模型生成最终答案。

产品价值：

- 适合复杂问题、决策分析、代码审查等高价值场景
- 用户可以看到每个模型的独立输出
- 最终聚合答案支持流式返回，体验更自然

这让 Agent 从 “单模型回答” 变成 “多模型协同判断”。

---

###### 3. Agent 会验证结果：从 “我觉得完成了” 到 “有证据证明完成”

Hermes 现在可以基于证据判断任务是否完成，而不是仅依赖模型自我声明。

主要能力包括：

- `/goal`支持定义完成标准
- Agent 可运行项目检查、测试或自定义验证脚本
- 编码任务会记录验证证据
- 支持`pre_verify`钩子接入自定义检查

这对产品和工程场景很重要：Agent 不只是执行任务，还能证明任务真的完成。

---

##### 自我学习与记忆透明化

###### 4. `/learn`：把经验沉淀成技能

用户可以通过`/learn &lt;anything>`，让 Hermes 从目录、URL 或刚刚完成的工作流中提炼可复用技能。

它会自动遵循项目中的`CONTRIBUTING.md`规范，把经验沉淀为标准化技能。

本质上，这是把一次性对话变成可复用能力。

---

###### 5. `/journey`：让 Agent 的记忆可见、可编辑

新增`/journey`命令，用于查看 Hermes 过去学习到的记忆和技能。

用户可以：

- 查看学习时间线
- 编辑错误记忆
- 删除无用内容
- 在桌面端通过记忆图谱可视化查看

这解决了 Agent 记忆长期以来的黑盒问题，让用户能管理 “它知道什么”。

##### 工作流与产品体验升级

###### 6. 后台子 Agent 并行：复杂任务可异步推进

例如：

- 同时调研 5 个竞品
- 并行审查 3 个代码模块
- 后台执行多个分析任务

用户不用等待，可以继续对话；所有子任务完成后，系统会汇总成一个结果返回。

这是 Agent 从 “单线程助手” 向 “任务调度系统” 演进的重要一步。

- 多终端面板

## 结构化（1）

### 2026-07-22 09:42:23

#### Hermes Agent v0.18.0（2026.7.1）更新摘要

Hermes Agent v0.18.0 于 **2026 年 7 月 1 日**发布，核心目标是清空全部最高优先级问题，并提升智能体的推理、任务验收、自我学习和规模化部署能力。该版本已实现 **P0/P1 问题全部归零**，同时将多智能体协作（MoA）、项目开发、记忆管理和后台子任务升级为正式能力。

##### 一、版本规模：集中清理高优先级积压

相较 v0.17.0，本次版本包含：

- 约 **1,720 次提交**
- 合并 **998 个 PR**
- 修改 **2,215 个文件**
- 新增约 **25.1 万行**、删除约 **4.1 万行**
- 关闭 **949 个 Issue**
- 超过 **370 名社区贡献者**参与

在约 12 天的集中处理期内，团队共关闭约 **1,950 个 Issue 和 PR**，其中近 **700 项**属于最高优先级。

###### P0/P1 清零结果

| 优先级 | 关闭 Issue | 合并 PR | 合计 |
|---|---:|---:|---:|
| P0（严重） | 3 | 8 | 11 |
| P1（高） | 493 | 188 | 681 |
| **总计** | **496** | **196** | **692** |

- 发布时整个仓库的开放 P0、P1 数量均为 **0**。
- 最后解决的关键问题是“中断保护压缩”中的 sibling-fork 缺陷（Issue `#56391`，修复 PR `#56416`）。
- 团队计划今后继续将 P0/P1 积压维持在零。

##### 二、Mixture-of-Agents：多模型协作成为正式模型

MoA（Mixture-of-Agents，多智能体混合）不再只是临时模式，而是模型系统中的一等能力。

###### 主要变化

- 每个命名的 MoA 预设都会显示为 `moa` 提供商下的虚拟模型。
- 用户可以像选择 Claude、GPT 或 Grok 一样，在 CLI、TUI、桌面端和网关中直接选择 MoA。
- `/moa` 改为一次性快捷命令：用默认组合处理当前提示，之后自动恢复原模型。
- 每个参考模型的输出会以独立、带标签的区块展示。
- 汇总模型的最终答案支持实时流式输出，不再长时间等待后一次性出现。

例如，选择名为 `my-council` 的组合后，用户可以先分别查看 GPT-5、Claude、Grok 的判断，再观看汇总模型实时生成综合结论，相当于看到“委员会讨论过程”，而不只是最终裁决。

###### 可靠性与调试改进

- 参考模型和汇总模型均通过各自真实的提供商路由调用。
- 上下文窗口按汇总模型实际能力计算，不再默认使用 256K。
- 可通过 `moa.save_traces` 将完整调用轨迹保存为 JSONL，用于调试和评测。
- 能容忍手工编辑过的预设配置，并阻止不合适的虚拟提供商被用作参考或汇总模型。

##### 三、任务验收：让“完成”有证据

Hermes 开始通过实际检查判断任务是否完成，而不是仅凭模型口头声称“已经修好”。

###### `/goal` 完成契约

用户可以预先定义“完成标准”，持续目标循环会根据证据验收。

例如：

> “修复登录错误，并确保单元测试和类型检查全部通过。”

Hermes 会实际执行项目检查，再决定目标是否完成，而不是仅回复“问题已修复”。

其他改进包括：

- `/goal wait &lt;pid>`：等待后台进程结束，避免反复唤醒智能体询问状态。
- 建立项目级“验证证据账本”，记录检测到的标准检查项及结果。
- 网关可以暴露当前验证状态。
- 新增 `pre_verify` 钩子，可接入自定义测试或检查脚本。
- 验证会跳过仅修改文档的情况，并限制在适合的交互界面中运行。
- “停止前自动验证”默认关闭，并通过一次性 v32 配置迁移调整旧设置。

核心变化可以概括为：从“我认为已经修好”，升级为“测试已通过，这里是证据”。

##### 四、自我学习：`/learn` 与 `/journey`

###### `/learn`：把经验变成可复用技能

执行 `/learn <内容>` 后，Hermes 可以从以下来源提炼技能：

- 一个目录
- 一个网页 URL
- 刚刚完成的一段操作流程

生成的技能会自动遵循项目 `CONTRIBUTING.md` 中的规范。用户不再需要手工编写完整技能文件，只需让 Hermes 从现有材料或操作经验中学习。

###### `/journey`：查看和管理学习历程

CLI 和 TUI 新增 `/journey`，以时间线形式展示 Hermes 累积的：

- 记忆
- 技能
- 学习变化

用户可直接编辑或删除不准确的内容。桌面端还加入可交互的径向“记忆图谱”，使智能体的知识不再是黑箱。

###### 降低自我改进成本

每轮对话后的后台学习审查现在：

- 使用较便宜的辅助模型；
- 只处理压缩后的上下文摘要，而非重放整段对话；
- 根据实际情况动态调整审查频率。

这样可以保留持续学习能力，同时显著减少主模型调用成本。

##### 五、后台子智能体：并行委派且不阻塞对话

`delegate_task` 现在支持在后台并行启动多个子智能体：

- 主聊天不会被阻塞；
- 用户可以继续处理其他事情；
- 所有子任务完成后，系统会一次性返回综合结果；
- CLI 和 TUI 状态栏可显示后台子智能体状态。

例如，用户可以要求：

> “并行研究五个竞争对手，并审计三个代码模块。”

Hermes 会让多个子智能体分别处理，最终给出一份统一摘要，而不要求用户逐个跟进。

##### 六、桌面端：升级为完整的“编码驾驶舱”

###### 一等公民级项目管理

桌面应用新增按用户配置隔离的 Projects，采用：

> 项目（Project）→ 仓库（Repo）→ 工作通道（Lane）

主要能力包括：

- 代码项目侧边栏
- 编码操作区与审查面板
- Git 状态、代码审查和 worktree 管理
- 面向智能体的项目工具
- 支持远程网关的目录选择
- 多终端面板
- 重启后恢复终端标签和滚动记录

这使开发工作不再散落于多个聊天会话，而是被组织成智能体可理解、可操作的项目。

###### 代码与内容展示改进

- 聊天中显示类似 PR 的文件差异。
- 文件预览区支持直接编辑。
- Markdown 支持富媒体嵌入、图表和提示信息。
- 大型 `/learn` 结果采用受限渲染，避免界面卡顿。
- 高负载下可更快切换会话。

###### 交互体验改进

新增或优化：

- 长对话时间线导航
- 上下文占用明细
- 子智能体只读旁观窗口
- 可拖动的独立输入框
- 自动朗读回复（TTS）
- 窗口大小、位置和最大化状态记忆
- 更清晰的澄清问题界面
- 备份创建、导入与下载
- 主题安装状态提示
- Electron 启动参数及 GPU 策略配置

此外，桌面端的可选“宠物”功能也改进了移动、缩放、孵化动画、弹出层和通知效果，并降低了 CPU 消耗。

##### 七、网关与规模化部署

Hermes 网关现在更适合团队及托管服务场景。

###### Scale-to-zero

- 无人使用时，服务可自动缩容至零。
- 有请求时再按需唤醒。
- 适用于托管版或仅承担中继功能的 Hermes。

###### Drain 协调

在重启、迁移或自动更新前，网关可以：

- 停止接收新的工作；
- 等待正在进行的会话完成；
- 避免用户在回答生成到一半时被强制中断。

这使 Hermes 从个人工具进一步走向生产级、多用户部署。

##### 八、Google Vertex AI 支持

Hermes 新增对 Google Vertex AI 的一等支持，可以通过 GCP 服务账号使用 Gemini。

Vertex AI 没有长期有效的静态 API Key，而是要求每次请求使用有效期约 **1 小时**的 OAuth2 访问令牌。Hermes 现在可以：

- 从服务账号 JSON 或 Application Default Credentials 获取凭证；
- 自动生成短期令牌；
- 在令牌过期前自动刷新；
- 避免手工粘贴令牌或会话中途因令牌失效而中断。

##### 九、安全加固

本版本集中修复了多类凭证泄露和配置攻击风险，包括：

- 限制 MCP 配置持久化的攻击面；
- 阻止 cron 通过恶意 `base_url` 覆盖来外传提供商凭证；
- 对文件读取中的前缀型秘密使用不可复用的哨兵值；
- 自动遮蔽 Slack 应用级 `xapp-` Token；
- 对所有浏览器后端强制实施云元数据访问安全下限；
- 提高 `aiohttp` 版本下限，以覆盖相关 CVE 修复。

目标是减少提示注入、错误配置或后台任务导致密钥泄露的可能性。

##### 十、Web Dashboard 与底层架构

###### Web Dashboard

主要改进包括：

- 未登录时自动跳转门户 SSO；
- 非本地地址启动且未配置认证时，提供交互式认证设置；
- 自托管 OIDC 支持带 `client_secret` 的机密客户端；
- 统一列出记忆提供商所需的可选环境变量；
- Keys 页面支持添加任意自定义 `.env` 键；
- 展示 cron 任务执行字段；
- 支持备份创建、导入和下载；
- 将 PTY 创建、关闭操作移出事件循环，减少阻塞；
- 非交互式提供商不再出现在交互登录界面。

###### 架构重构

桌面端对多个过大的“god file”进行拆分：

- 将输入框逻辑拆成独立引擎与 Hook；
- 分离分支、Esc、URL、占位符和弹窗逻辑；
- 拆分线程、侧边栏、新手引导和提示操作模块；
- 建立共享 WebSocket 层，降低桌面端与 Dashboard 的耦合。

总体而言，v0.18.0 不只是增加功能，也在通过模块化重构、性能优化和安全修复，为后续扩展打基础。
