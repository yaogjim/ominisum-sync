## 正文

**AprilNEA**

在 Claude Code 的虚拟机里，我们发现了什么

起点

我们对 Claude Code 运行环境做了一次完整的逆向工程。起点很简单：用 strace 追踪 PID 1，然后顺藤摸瓜。

运行环境

Claude Code 跑在 Firecracker MicroVM 里——这是 AWS 开源的轻量虚拟机，Lambda 和 Fargate 底层用的就是它。证据是 ACPI 表里写死的 OEM ID FIRECK\`。整个虚拟机极其精简：4核 CPU、16GB 内存、252GB 磁盘，没有 systemd，没有 sshd，没有 cron，PID 1 是一个自研的 \`/process\_api \` 二进制，同时充当 init 进程和 WebSocket API 网关。

关键发现：environment-runner

虚拟机里有一个 27MB 的 Go 二进制 \`/usr/local/bin/environment-runner\`，没有做 strip，保留了完整的调试信息和符号表。源码路径指向 github\[.\]com/anthropics/anthropic/api-go/environment-manager/——这是 Anthropic 内部的私有仓库。

通过 go tool objdump\`、\`strings\`、\`objdump \`等工具，我们从中提取出了完整的包结构、所有函数签名、嵌入资源和关键字符串。

三个重大发现

1\. Antspace —— Anthropic 自建的 PaaS 平台

在部署模块中，我们发现了两个部署目标：公开的 Vercel 和完全未公开的 Antspace。Antspace 拥有完整的部署协议（创建部署 → 上传 tar.gz → 流式状态推送），有独立的控制面 URL 和认证体系。互联网上关于它的公开信息为零。

命名来源推测："Ant"是 Anthropic 员工的内部昵称（他们拥有域名 ant\[.\]dev)。

2\. Baku —— Claude 网页版应用构建器的内部代号

当你在 claude\[.\]ai 上让 Claude "帮我做一个网页应用"时，后台启动的就是 Baku 环境。它预装了 Vite + React + TypeScript 模板，自动配置 Supabase 数据库（含 6 个 MCP 工具：查询、迁移、类型生成、Edge Function 部署等），构建完成后默认部署到 Antspace。

3\. BYOC —— 自带容器的企业部署模式

environment-runner 支持两种环境类型：\`anthropic\`（Anthropic 托管）和 \`byoc\`（Bring Your Own Cloud，客户自己的基础设施）。这意味着企业客户可以在自己的 Kubernetes 集群里运行 Claude Code 的完整环境，而会话编排仍由 Anthropic API 控制。

战略含义：Anthropic 正在构建一个从 AI 模型到应用托管的完整闭环：  
用户用自然语言描述需求  
→ Claude 在 Baku 环境中生成应用代码  
→ 自动配置 Supabase 数据库  
→ 一键部署到 Antspace  
→ 应用上线，用户全程不离开 Anthropic 生态

这不只是一个 AI 编程助手，而是一个 AI 原生的 PaaS 平台的雏形。它的竞争对手不仅是 Cursor 和 GitHub Copilot，更是 Vercel、Netlify、Replit、Lovable 和 Bolt。而 Anthropic 的独特优势在于：他们拥有从大模型到运行时到部署平台的完整垂直整合，这是目前任何竞品都不具备的。

方法论：全部发现来自对一个未 strip 的 Go 二进制的静态分析和运行时追踪。没有任何网络攻击、权限提升或越权操作——这个二进制就在虚拟机里，带着完整的符号表，等着被读取。

这篇文章的主旨是：作者通过对 Claude Code 运行环境做逆向分析，发现 Anthropic 不只是做 AI 编程助手，而是在搭建一套 “从生成代码到部署上线” 的完整 AI 应用平台。核心结论是：Claude Code 背后已经出现了内部 PaaS 雏形，包括应用构建、数据库配置和托管部署能力。

- **起点：怎么发现的**
  - 作者从最基础的方法入手：用`strace`跟踪`PID 1`，一步步摸清 Claude Code 的运行环境。
  - 分析方法主要是两类：运行时追踪 + 对 Go 二进制做静态分析。
  - 作者特别强调：整个过程没有网络攻击、提权或越权，只是读取了虚拟机里本来就存在、且未做 strip 的二进制文件。

- **运行环境：Claude Code 跑在什么上面**
  - Claude Code 运行在`Firecracker MicroVM`里，这是 AWS 开源的轻量虚拟机，`Lambda`和`Fargate`也是基于它。
  - 关键证据是 ACPI 表中的 OEM ID 写着`FIRECK`。
  - 虚拟机配置非常精简：`4 核 CPU`、`16GB 内存`、`252GB 磁盘`。

- **关键入口：发现了一个重要二进制**
  - 虚拟机中存在一个`27MB`的 Go 二进制：`/usr/local/bin/environment-runner`。
  - 这个文件没有 strip，保留了完整的调试信息和符号表，相当于把很多内部实现 “暴露” 出来了。

  - 作者通过`go tool objdump`、`strings`、`objdump`等工具，提取出了包结构、函数签名、嵌入资源和关键字符串。

  - 它还有独立的控制面 URL 和认证体系，说明成熟度不低。
  - 作者提到，互联网上几乎查不到它的公开资料，因此这是一个很关键的隐藏线索。

  - `environment-runner`支持两种环境类型：`anthropic`和`byoc`。
  - `byoc`即`Bring Your Own Cloud`，表示企业客户可以在自己的基础设施中运行 Claude Code 的完整环境。

  - 这说明 Anthropic 并不只想做公有云托管，也在为企业级私有化 / 半私有化场景做准备。

- **战略意义：Anthropic 想做什么**
  - 作者认为，Anthropic 正在打造一条完整闭环：
    - 用户用自然语言提需求
    - Claude 在`Baku`中生成应用代码
    - 自动配置`Supabase`
    - 一键部署到`Antspace`

- **文章结论**
  - 这次逆向工程最重要的价值，不在于挖到单个内部代号，而是看到了 Anthropic 的产品方向：从 AI 写代码，走向 AI 直接交付应用。

##### 解读

可以把这件事理解成一句话：

**Anthropic 可能在做 “AI 版的一站式应用工厂”。**

###### 1. 这次发现说明了什么？

过去很多人把 Claude Code 理解成 “高级代码助手”，类似更聪明的 Copilot。  
但这篇文章认为，它背后已经不只是 “写代码” 了，而是在往更大的方向走：

- 帮用户生成应用
- 自动配数据库和后端能力
- 自动部署上线
- 尽量让用户不离开 Anthropic 生态

也就是说，Anthropic 可能想从 “模型提供商” 升级成 “应用平台提供商”。

###### 2. 为什么`Antspace / Baku / BYOC`这几个点重要？

###### Antspace
如果它真是内部 PaaS 平台，那意义很大。  
因为这说明 Anthropic 不只想输出模型能力，还想自己掌握 “应用最终落地” 的那一步。

###### Baku
这意味着 Claude 在网页上帮你 “做个应用” 时，背后可能已有标准化开发环境，不是临时拼凑，而是产品化流程。

###### BYOC
这点对企业尤其关键。  
很多公司最在意的是数据、合规和控制权。如果 Claude Code 能跑在客户自己的云环境里，那么它就更容易进入大企业场景。

###### 3. 这对行业意味着什么？

如果这个判断成立，Anthropic 的对手就不只是 Cursor、Copilot 这种代码助手，  
还包括：

- Vercel / Netlify：部署平台
- Replit：在线开发环境
- Lovable / Bolt：AI 应用生成工具

换句话说，竞争维度从 “谁会写代码” 变成了：

**谁能把 AI 生成、运行、部署、托管整成一个闭环。**

## 综合-启发一下（1）

### 2026-03-19 01:53:39

这段内容最有价值的，不是 “Claude Code 跑在什么虚拟机里” 这个八卦本身，而是它泄露出了一个更大的方向：AI 编程产品正在从 “辅助写代码工具” 进化为 “需求输入 → 代码生成 → 数据层配置 → 托管部署 → 持续运行” 的闭环式生产系统。对长期关注 AI、产品开发和商业系统构建的人来说，这比单点功能强太多。

**启发**
- 真正的竞争单位已经不是 “模型能力” 或 “IDE 插件体验”，而是 “完整工作流闭环”。
- Anthropic 显然不满足于做一个 coding assistant，而是在往 AI Native PaaS 走：模型、运行时、应用模板、数据库、部署平台一体化。
- 产品形态的跃迁点在于：用户不再购买 “代码生成能力”，而是购买 “从想法到上线” 的压缩路径。
- 基础设施细节本身也是战略信号；`Firecracker`、`environment-runner`、`BYOC`这些词说明其目标客户同时覆盖个人开发者和企业级合规场景。
- 这类逆向工程内容的启发，不只是 “别人怎么做”，更是 “哪些能力值得你提前布局”，尤其是运行环境、部署控制面、数据工具链的组合。

**高价值信息深挖**
- 闭环价值远大于模型价值  
  从`Baku + Supabase + Antspace`这个链条看，Anthropic 在构建的是 “默认可运行” 的应用生产线。模型输出不是终点，能不能自动接数据库、生成类型、部署上线，才决定用户是否真能完成任务。
- 企业市场的真正抓手是`BYOC`  
  `Bring Your Own Cloud`暗示了一个关键现实：很多企业不是不想用 agent，而是不能把代码和运行环境完全交给第三方。谁能做到 “模型云端 + 环境本地 / 私有云”，谁更有机会进入大客户核心流程。
- 应用生成的未来不是 “自由生成”，而是 “受约束模板化生成”  
  Baku 预装`Vite + React + TypeScript`，不是保守，而是产品化。因为可维护、可部署、可接数据库、可排错，比 “理论上什么都能生成” 更有商业价值。
- 自研 PaaS 的信号很强  
  `Antspace`的出现意味着 Anthropic 在试图掌握最终交付面，而不是把价值让给 Vercel/Netlify。这背后是商业模式升级：从 API 收费走向基础设施、部署、运行、企业环境管理的复合收费。
- 运行环境本身正在成为产品的一部分  
  `/process_api`、`environment-runner`说明 agent 不只是 “会说话的模型”，而是一套受控执行系统。未来 AI 产品差异化，很大一部分不在 prompt，而在 execution layer。

**可迁移清单**
- 设计产品时，把 “生成” 改成 “交付” 视角  
  问自己：用户得到的是代码片段，还是一个可运行、可部署、可维护的结果？
- 优先做固定栈闭环  
  先选一套默认技术栈，比如`Next.js/React`或`FastAPI/Postgres`，把脚手架、数据库、部署串起来，比支持十种栈更重要。
- 预埋数据层工具  
  schema 迁移、类型生成、测试数据、权限模板，这些往往比 UI 生成更决定交付效率。
- 提前规划 “托管版 + 私有化版” 双路径  
  即便暂时做不到 BYOC，也应该在架构上预留控制面与执行面的分离。
- 把环境管理当成产品能力  
  沙箱、依赖安装、构建、日志、回滚、状态流式反馈，都是 agent 产品核心，不是运维附属品。
- 重视 “模板化约束”  
  好的 AI 产物不是最自由的，而是最可预测、最可维护、最容易二次接手的。

**反方与张力**
- 闭环越完整，用户锁定越强  
  一旦从生成代码到部署上线都在同一生态完成，迁移成本会快速上升，这对用户是效率，对平台是护城河，对生态开放性则未必是好事。
- 垂直整合很强，但也很重  
  模型、运行时、数据库适配、部署平台、企业交付，这不是一个轻资产产品故事，而是极重的工程与运维体系。
- “能上线” 不等于 “能维护”  
  AI 生成应用的最大风险，不是首次交付，而是三个月后的可维护性、团队接手成本、排障链路和架构一致性。
- 企业 BYOC 解决了合规的一部分，不解决责任归属全部问题  
  就算环境在客户云上，模型决策、代码质量、数据访问边界、审计责任依然复杂。
- 逆向推断战略有价值，但不能替代市场验证  
  从内部二进制能看出方向，不代表这些能力已经成熟、可规模化，或真的能形成商业壁垒。

**情境化落地**
- 如果你在做 AI Coding 产品  
  优先思考怎么把 “代码建议” 升级成 “任务完成系统”。例如：一句话需求 → 生成项目 → 连上数据库 → 预览 → 一键部署，而不是继续卷补全质量。
- 如果你在做 SaaS / 内部工具平台  
  可以借鉴`Baku`思路，围绕某类高频场景做 “受约束的应用工厂”，比如 CRM 后台、数据看板、活动页、运营工具，而不是追求通用应用生成。
- 如果你在服务企业客户  
  重点准备三件事：私有执行环境、审计日志、权限隔离。企业真正买单的不是 “智能”，而是 “可控地使用智能”。
- 如果你是技术负责人  
  这条信息说明未来团队生产方式会变：低代码、脚手架、数据库建模、部署流水线会被 agent 吃掉更多。团队更需要能定义边界、验收标准、系统约束的人。
- 如果你在搭建自己的商业系统  
  可以把产品拆成三层：需求理解层、受控生成层、托管交付层。很多创业机会不在做最强模型，而在把这三层压缩成一个体验。

**一句话提炼**
- 这不是一次 “Claude Code 内部实现揭秘”，而是一张路线图：AI 产品的下一阶段，不是更像工程师，而是更像一整家软件工厂。
