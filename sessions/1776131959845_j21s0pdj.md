## 正文

**宝玉**

开发者 Can Vardar 发现，Claude Code 里如果关闭遥测（telemetry，即向 Anthropic 回传使用数据），提示缓存时间会从 1 小时骤降到 5 分钟，他算了笔账说这相当于隐私换 12 倍性能，给 Anthropic 扣了个邪恶公司的帽子。

这条推文传开后，Anthropic 工程师 Boris Cherny 出来做了详细回应。

Claude Code 的缓存策略一直是个黑盒子，Boris 的这条推文把里面的细节讲的比较清楚了，推荐可以仔细看看。

他先澄清了一个误解：1 小时缓存并不是无条件更好。缓存写入成本更高、读取成本更低，划不划算取决于你怎么用。如果你只是跑了一次查询就走了，1 小时缓存反而浪费钱，因为你付了写入的高价却没享受到反复读取的便宜价。

实际上 Anthropic 一直在根据使用场景做精细化调整。比如子任务（subagent）很少被恢复，给它 1 小时缓存纯属白花钱，所以这类查询就保留 5 分钟。API 用户目前也没有默认开启 1 小时缓存，还在测试阶段。

关掉遥测导致缓存变短，Boris 说这其实是个连带效应：遥测关闭后，客户端的实验开关也跟着失效了，系统读到的就是默认值 5 分钟。换句话说，这不是故意惩罚，是技术实现上的耦合问题。

Boris 还透露了后续计划：很快会把部分查询的客户端默认值改成 1 小时，同时提供环境变量让用户自己强制切换 1 小时或 5 分钟。

至于12 倍性能差距，Boris 说远没有那么夸张，实际节省的 Token 量并不大。

## 结构化（1）

#### 主旨概括

这篇内容主要讲的是：**Claude Code 在关闭遥测后，提示缓存时间从 1 小时变成 5 分钟**，引发了“是否用隐私换性能”的争议。  
Anthropic 工程师随后解释称，这**更像是实验开关与遥测设置耦合造成的技术问题**，并非有意惩罚关闭遥测的用户。

##### 1. 争议是怎么来的

- 开发者 **Can Vardar** 发现：在 Claude Code 中关闭遥测（telemetry，即不向 Anthropic 回传使用数据）后，**提示缓存时间会从 1 小时降到 5 分钟**。
- 他据此认为，这相当于用户在“**用隐私换性能**”，并形容这是“**12 倍性能差距**”。
- 这一说法在社交平台上传播后，引发了不少讨论，也让 Claude Code 的缓存机制受到关注。

##### 2. Anthropic 工程师的核心回应

- Anthropic 工程师 **Boris Cherny** 出面解释了 Claude Code 的缓存逻辑。
- 他先澄清一个关键误解：**1 小时缓存并不一定总是更好**。
- 原因是：
  - **缓存写入成本更高**
  - **缓存读取成本更低**
- 所以值不值得开启更长缓存，取决于具体使用方式，而不是时间越长越划算。

**通俗理解：**
如果你只是问一次问题就结束了，那么系统先花较高成本去写入缓存，但你并没有反复利用这份缓存，**反而可能更浪费**。  
只有在同一上下文会被多次复用时，长时间缓存才更有意义。

##### 3. 为什么不同场景会有不同缓存策略

- Boris 表示，Anthropic 一直在按不同使用场景做细分调整，而不是统一给所有请求 1 小时缓存。
- 文中举了两个重要例子：

###### 子任务（subagent）
- 子任务通常**很少被再次恢复使用**。
- 因此，如果给它们统一配置 **1 小时缓存**，往往是**白白增加成本**。
- 所以这类请求通常保留 **5 分钟缓存**。

###### API 用户
- Boris 还提到，**API 用户目前默认也没有开启 1 小时缓存**。
- 这说明 **1 小时缓存本身仍处于测试和优化阶段**，并不是一个全面默认、绝对更优的方案。

##### 4. 关闭遥测后为什么缓存会缩短

- Boris 的解释是：**关闭遥测并不是直接触发“惩罚”机制**。
- 真正原因是：
  - 遥测关闭后，
  - **客户端上的实验开关（experiment flags）也一起失效了**，
  - 系统于是退回到默认值，
  - 而这个默认值正好是 **5 分钟缓存**。

也就是说，问题本质上是：

> **遥测设置和实验开关之间存在技术耦合。**

- 因此，表面上看像是“关掉遥测就被降级”，
- 但 Anthropic 的说法是：**这不是故意设计，而是实现方式带来的连带效应**。

##### 5. 后续会怎么改

Boris 还透露了后续计划，主要有两点：

- **很快会把部分查询的客户端默认值改成 1 小时**
- **会提供环境变量**，让用户可以自己强制切换：
  - **1 小时**
  - 或 **5 分钟**

这意味着之后用户对缓存策略的控制权会更明确，也能减少这类误解。

##### 6. 关于“12 倍性能差距”的说法

- 对于外界关注的“**12 倍性能差距**”，Boris 明确表示：**实际情况没有这么夸张**。
- 他的观点是，真实节省下来的 **Token 数量并不大**。
- 换句话说，这件事确实会影响体验和成本，但未必像最初批评里说得那么严重。

##### 7. 这篇内容想说明什么

- Claude Code 的提示缓存机制此前比较像“黑盒”，这次回应让外界第一次更清楚地看到其中的判断逻辑。
- 文章传达的重点不是单纯替 Anthropic 辩护，而是强调：
  - **长缓存不一定总更好**
  - **缓存策略依赖具体场景**
  - **关闭遥测导致缓存变短，主要是技术耦合问题**
  - **官方后续会开放更明确的用户控制方式**

##### 8. 文中补充案例

- 文末还提到宝玉自己的一个观察：
  - 他在测试一款 Markdown 编辑器时，发现自己的 **Claude Code 5 小时额度很快耗尽**。
  - 后来用 `claude --resume` 查看，发现有**一大批 Claude Code CLI 请求**，它正在尝试分析目录下所有 Markdown 文档。
- 这个案例说明，除了缓存策略外，**工具本身的请求行为和上下文处理方式**，也会明显影响额度消耗与使用体验。
