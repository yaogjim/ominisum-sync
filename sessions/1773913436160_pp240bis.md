#### lazycut

Terminal-based video trimming tool. Mark in/out points and export trimmed clips with aspect ratio control.

lazycut demo

#### Install

##### macOS

```
brew tap emin-ozata/homebrew-tap
brew install lazycut
```

##### Windows

Download the latest Windows binary from the [releases page](https://github.com/emin-ozata/lazycut/releases):

- `lazycut_X.X.X_windows_amd64.zip`

Extract and add to your PATH, or run directly.

**Dependencies:**

- ffmpeg: `winget install ffmpeg` or download from [ffmpeg.org](https://ffmpeg.org)
- chafa: Install via [Scoop](https://scoop.sh): `scoop install chafa`

Or build from source:

```
git clone https://github.com/emin-ozata/lazycut.git
cd lazycut
go build
./lazycut video.mp4
```

#### Usage

```
lazycut <video-file>
```

##### Keyboard Shortcuts

Key Action

`Space` Play/Pause

`h` / `l` Seek ±1s

`H` / `L` Seek ±5s

`i` / `o` Set in/out points

`Enter` Export

`?` Help

`q` Quit

Repeat counts work: `5l` = seek forward 5 seconds.

## 产品-产品技术PMF（1）

### 2026-03-19 09:43:56

以下是基于你提供的项目内容，对`emin-ozata/lazycut`做的产品、技术、PMF 视角精炼分析报告。

**项目判断**
- `lazycut`本质上不是一个 “视频编辑器”，而是一个 “面向开发者 / 效率用户的命令行快速裁剪工具”。
- 它切中的不是大众视频创作市场，而是一个更窄但明确的场景：用最低交互成本完成 “视频截取片段” 这件事。
- 从产品定位看，它更像`mpv + ffmpeg`之间的轻量交互层：降低命令行裁剪门槛，但不追求专业剪辑能力。
- 这是一个典型的 “小而美工具型产品”，有较强开源传播潜力，但商业化空间依赖后续场景扩展。

**一句话定义**
- 一个基于 Terminal UI 的视频粗剪工具，让用户通过键盘快速标记`in/out`点，并导出裁剪视频。

**核心用户与场景**
- 目标用户：
  - 开发者、CLI 重度用户
  - 技术内容创作者
  - 需要批量截取视频片段的运营 / 研究人员
  - 不想打开 Premiere/CapCut 这类重工具的轻量用户
- 高频场景：
  - 从长视频中快速截取 demo /bug 复现片段
  - 从录屏中裁掉无效头尾
  - 为社媒 / 文档 /issue 附件生成短视频片段
  - 服务器或远程环境下做简单视频处理
- 不适合的场景：
  - 多轨编辑、字幕、转场、滤镜
  - 精细逐帧剪辑
  - 大众消费级创作用户

**产品价值分析**
- 明确价值：
  - 比纯`ffmpeg`命令更易用
  - 比 GUI 视频编辑器更轻、更快启动
  - 键盘优先，操作路径短
  - 适合远程开发环境、SSH、无桌面环境
- 真正优势不在 “功能多”，而在：
  - 极低心智负担
  - 安装后即用
  - 单任务闭环非常清晰
- 当前产品卖点里，最能成立的是：
  - “5 秒内开始剪”
  - “不用学 ffmpeg 参数”
  - “在 terminal 里完成视频粗剪”

**产品完成度判断**
- 从 README 信息看，MVP 已成立：
  - 支持播放 / 暂停
  - 支持 seek
  - 支持 in/out 标记
  - 支持导出
  - 支持宽高比控制
  - 提供 macOS / Windows 安装路径
- 说明它已经不是 demo，而是 “可交付的工具原型”
- 但距离 “被广泛推荐的效率工具” 还差几个关键能力：
  - 导出参数透明度不足
  - 精度与稳定性认知不足
  - 批处理与自动化能力信息不足
  - 用户对依赖安装仍有门槛

**PMF 分析**
- 当前 PMF 状态：`弱 PMF / 强问题契合，小众明确`
- 为什么不是强 PMF：
  - 问题真实，但用户群体窄
  - 用户替代方案很多：`ffmpeg`、`mpv`、`VLC`、QuickTime、CapCut、Premiere、LosslessCut
  - 该产品目前更像 “体验优化器”，不是 “不可替代品”
- 为什么又有 PMF 潜力：
  - 对 CLI 人群，体验差异很明显
  - 如果 “快、稳、无脑” 做到极致，这类工具会形成强口碑
  - 视频裁剪是高频基础动作，进入点正确
- PMF 的关键验证信号：
  - 用户是否把它加入自己的日常工具链
  - 用户是否在 issue / 社媒中主动说 “我已经替代了 xxx”
  - 是否出现脚本化调用、批量处理、与工作流集成需求
  - 是否有用户因它而降低使用 GUI 编辑器频次
- 当前更像 “很好用的开源 utility”，尚未形成 “必须用它” 的网络效应或工作流锁定

**竞品与差异化**
- 直接竞品：
  - `ffmpeg`：能力最强，但门槛高
  - `LosslessCut`：最接近，面向快速无损裁剪
  - `mpv` + 手写脚本：极客用户可替代
  - `VLC` / QuickTime：更通用，但交互效率一般
- `lazycut`差异化：
  - Terminal UI
  - 键盘驱动
  - 极简模型：播放、标记、导出
  - 更符合开发者工作流
- 最大威胁：
  - `LosslessCut`功能和品牌都更成熟
  - 一旦用户不执着于 terminal，`lazycut`的优势会缩小很多
- 所以它不能走 “大而全”，应强化：
  - CLI-first
  - 可脚本化
  - 远程环境可用
  - 与开发 / 内容生产链路深度集成

**技术实现推断**
- 技术栈：
  - `Go 100%`
  - 依赖`ffmpeg`做视频导出 / 裁剪
  - 依赖`chafa`在终端做视频帧 / 图像预览相关呈现
  - 自研 TUI 交互层
- 这条技术路线是合理的：
  - Go 适合单文件分发、跨平台 CLI 发布
  - `ffmpeg`作为底层处理引擎，可靠且无需重复造轮子
  - TUI 对键盘交互、效率工具定位非常匹配
- 工程优点：
  - 发布链路完整，已有 GoReleaser / CI / Homebrew
  - 跨平台意识较好，已考虑 Windows
  - 依赖检测和错误提示已有基础
- 技术风险：
  - 终端视频预览体验强依赖`chafa`和终端能力，效果可能不稳定
  - 不同平台的`ffmpeg`行为、编码器支持差异会影响导出稳定性
  - 精确 seek 与帧级裁剪体验可能受底层封装方式影响
  - terminal 渲染性能、播放流畅度、音视频同步可能存在平台差异

**技术壁垒判断**
- 当前壁垒不高，属于 “产品体验壁垒 > 算法壁垒 > 技术壁垒”
- 真正难的是：
  - 把 terminal 中的视频交互做得顺滑
  - 把不同平台依赖和导出异常处理好
  - 让用户信任 “裁出来是对的”
- 如果未来加入这些能力，壁垒会提升：
  - 无损裁剪智能判断
  - 帧精度模式与关键帧模式双导出
  - 批量任务与脚本 API
  - 自动检测社媒比例与最佳导出策略
  - 工作流集成能力

**产品短板**
- 从信息呈现上看，当前缺少几个会影响转化的点：
  - 没有明确展示 “比 ffmpeg 简单在哪”
  - 没有 GIF /demo 视频证明交互体验

**增长与传播潜力**

  - 话题有趣：terminal 里剪视频

## 产品-商业落地客户交付（1）

### 2026-03-19 09:49:08

这个项目本质上不是 “卖一个命令行剪辑工具”，而是 “把视频粗剪这件高频、重复、可标准化的工作，做成可交付的效率产品”。真正能赚钱的关键，不在工具本身，而在于你把它包装成谁愿意付费、为什么现在付费、交付后能持续续费的解决方案。

**先说结论**
- `lazycut`作为开源 CLI 工具，本身适合做 “能力底座”，不适合直接做大收入来源
- 真正的商业化方向，是在它上面叠加 AI 能力、工作流、协作和交付服务
- 最容易赚钱的客户，不是个人开发者，而是有批量视频处理需求的小团队和企业客户
- 最靠谱的收费方式，不是一次性卖软件，而是 “订阅 + 用量 + 企业服务” 三层收费

**这个项目能卖什么**
- 当前能力：视频截取、标记 in/out、导出、比例控制，适合 “粗剪”
- 商业价值：帮客户减少人工剪辑时间，提高素材处理效率
- AI 延展空间：自动识别精彩片段、静音片段删除、字幕切分、内容打标签、多平台比例自动裁切
- 所以它不是最终产品，而是一个 “视频预处理引擎”

**谁会付钱**
- 短视频代运营公司：每天大量切素材，最关心效率
- MCN 和内容团队：需要批量从长视频切出多个短视频
- 教培 / 知识付费公司：课程录播后要快速切片分发
- 播客 / 访谈团队：从长内容中提炼高光片段
- 企业培训 / 销售团队：会议、演示视频需要快速裁剪整理

这些客户有一个共同点：视频不是艺术创作，而是生产流程，所以愿意为 “提效” 买单。

**赚钱过程怎么讲清楚**
- 第一步，找到一个高频刚需场景：比如 “把 1 小时访谈快速切成 10 条短视频”
- 第二步，用`lazycut`解决 60% 基础流程：快速标记、裁切、导出
- 第三步，叠加 AI 提升价值：自动找高光、自动去停顿、自动字幕、自动封面建议
- 第四步，把工具变成流程：支持批量处理、模板、团队协作、审核导出
- 第五步，把流程变成收费：按账号订阅、按视频时长收费、按企业部署收费

一句话概括：
你卖的不是 “剪刀”，你卖的是 “让一个运营团队每天多产出 30 条视频，还不用多招 2 个剪辑”。

**最现实的商业化路径**
- 开源版：保留 CLI 基础能力，吸引开发者和技术团队
- 专业版：做桌面端或 Web 控制台，提供更低门槛 UI、批量处理、模板管理
- AI 增值版：自动切片、语音转字幕、内容识别、爆点推荐
- 企业版：私有化部署、权限管理、API 接入、SLA 服务

这四层的逻辑是：
开源获客，专业版变现，AI 版拉高客单价，企业版做利润。

**定价怎么定**
建议不要一开始就卖太便宜，否则很难覆盖交付成本。

可参考：
- 个人版：39-99 美元 / 月，面向独立创作者
- 团队版：199-499 美元 / 月，支持多人协作和批量处理
- AI 用量包：按视频分钟数收费，比如 0.05-0.2 美元 / 分钟
- 企业私有化：3 万 - 20 万人民币 / 年，视部署、定制、支持而定
- 定制集成项目：5 万 - 30 万人民币 / 单，含接入内部系统、流程改造、培训

**客户为什么愿意买**
客户不会因为 “你用了 Go、ffmpeg、chafa” 买单，他们只关心三件事：
- 能不能省人
- 能不能更快出片
- 能不能稳定跑批量任务

所以对外的话术要从技术描述，改成业务结果：
- 从 “Terminal-based video trimming tool”
- 改成 “把长视频批量切成可分发短视频，交付效率提升 3-10 倍”

**客户对接怎么做**
你不要先讲产品功能，要先问业务流程：
- 你们一天处理多少小时视频
- 现在谁在切，花多少人天
- 最痛的环节是找片段、加字幕，还是多平台适配
- 交付结果是给抖音、视频号、YouTube，还是内部培训
- 你们更需要 SaaS，还是本地 / 私有化

这一步的目的不是 “收需求”，而是算 ROI。
如果客户现在 3 个剪辑师每月成本 6 万，而你的工具能替代其中 1 人 50% 工作量，你就有定价空间。

**销售成交逻辑**
- 先卖试点，不要一开始卖大单
- 先选一个垂直行业，比如 MCN 或教培
- 用 2 周做 PoC，拿真实视频素材验证效率提升
- 用结果签首单：比如 “导出效率提升 70%，单条内容处理时间从 20 分钟降到 5 分钟”
- 再从工具费升级到流程费，再升级到企业年度合同

简单说：
先证明能省时间，再证明能省钱，最后证明能规模化。

**产品交付怎么设计**
如果你真要落地，产品不能停在 CLI。
最小可交付版本建议是：

- `底层引擎`：继续用`lazycut + ffmpeg`
- `桌面端 / 网页端`：给非技术用户使用
- `AI 服务层`：语音识别、镜头切分、静音检测、字幕生成、精彩片段推荐
- `任务系统`：批量上传、排队处理、失败重试、导出记录
- `模板系统`：横版转竖版、短视频切片模板、平台导出参数
- `协作能力`：审核、备注、版本记录、权限管理

客户真正买单的，是 “能进团队流程”，不是 “你能在终端里 trim 视频”。

**AI 怎么加才真正值钱**
不要泛泛地说 “AI 剪辑”，要加在能直接提升转化的节点上：
- 自动找高能片段：减少人工浏览时长
- 自动去静音和口头禅：提升粗剪效率
- 自动字幕和分句：降低后期成本
- 多平台智能裁切：提升分发效率
- 内容标签与检索：让旧素材可复用
- 标题 / 摘要生成：直接连接内容运营环节

AI 在这里不是噱头，而是把 “粗剪工具” 升级成 “内容生产系统”。

**最适合的创业路径**
如果资源有限，建议走这条线：

- 第 1 阶段：开源积累口碑，用 GitHub、开发者社区获客
- 第 2 阶段：做一个轻量 GUI，降低使用门槛
- 第 3 阶段：选择一个行业做深，比如播客切片或教培录播
- 第 4 阶段：加 AI 自动化能力，形成可收费升级包
- 第 5 阶段：做企业 API / 私有化，拿高毛利合同

不要一开始做 “大而全视频平台”，那会把研发和销售都拖死。
先把一个场景打穿，比如：
“播客团队 1 小时节目，10 分钟内自动切出 8 条短视频候选片段。”

**这项目的优势**
- 技术栈简单，交付快，成本低
- 基于`ffmpeg`，底层能力成熟
- 开源能带来信任和早期用户
- CLI 适合做自动化和企业流程集成

**这项目的短板**
- 终端工具门槛高，普通客户不会直接买
- 功能偏基础，缺少显著差异化
- 没有协作、云端、AI，就很容易被替代
- 单靠安装包和本地工具，很难做高续费

所以你必须从 “工具思维” 切到 “场景思维” 和 “流程思维”。

- 面向内容团队的视频粗剪自动化引擎

- 帮客户把长视频快速切成可发布内容的工作流产品
