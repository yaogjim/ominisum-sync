## 正文

**凡人小北**

今年有个明显的趋势，大家不约而同地从更工程、更现实的角度去思考 AI Coding。

模型能力的军备竞赛是其一，其二是 Agent 怎么协作。

分享个 @AutoJunjie2023  
的 Agent Harness 项目 Chorus，这个名字含义就很组织范儿。

核心理念：Reversed Conversation  
PM Agent 分析需求、拆解任务、出 PRD  
Dev Agent 认领任务、写代码、提交验证  
Admin 审批方案、验收成果

解决的都是 Agent 实战痛点：  
\- Agent 重启后丢进度 → Session 持久化  
\- 任务状态不统一 → 严格状态机流转  
\- 新上下文从零开始 → checkin 自动恢复  
\- 多 Agent 协作混乱 → 生命周期钩子编排  
\- 看不到 Agent 在干嘛 → Kanban 实时展示  
\- 任务卡住阻塞流水线 → 空闲 Session 自动过期

还有几个关于人的问题：  
\- Task DAG：任务依赖可视化，支持并行  
\- 需求澄清：PM Agent 先问问题再出方案  
\- @Mention  
—— 人和 Agent 互相 @  
\- 50+ MCP 工具，按角色分权限

值得尝试下。

## 解读（1）

### 2026-03-17 08:17:14

#### 内容总结

这段内容的核心观点是：

- 今年大家看待 AI Coding，开始从“拼模型能力”转向“拼工程落地”
- 重点不只是模型有多强，还包括多个 Agent 如何协作完成真实开发流程
- 文中推荐了一个 Agent Harness 项目 `Chorus`，强调用“反向对话（Reversed Conversation）”组织 AI 与人的协作
- 它把开发流程拆成不同角色：`PM Agent` 负责分析需求和写 PRD，`Dev Agent` 负责开发与验证，`Admin` 负责审批和验收
- 这个系统主要解决多 Agent 实战中的常见问题，比如进度丢失、状态混乱、上下文断裂、协作失序、过程不可见、任务卡死等
- 同时也考虑了“人如何参与”，如任务依赖图、需求澄清、@提及协作、按角色分配工具权限等

#### 深入解读

##### 1. 为什么这是个“明显趋势”

以前很多人关注 AI Coding，常常先看两件事：

- 模型够不够聪明
- 生成代码快不快

但真正到了团队协作和项目落地阶段，问题会变成：

- 任务怎么拆
- 谁先做、谁后做
- 中途断了怎么接上
- 多个 Agent 会不会互相打架
- 人怎么介入和兜底

所以，AI Coding 正在从“单点能力展示”，走向“完整研发流程设计”。这就是文中说的“更工程、更现实”。

##### 2. `Reversed Conversation` 的意义

它的思路不是让一个万能 Agent 从头包到尾，而是模拟真实团队分工：

- `PM Agent` 先理解需求、补问题、拆任务
- `Dev Agent` 再按任务实现
- `Admin` 做审批和验收

这其实是在把 AI 协作流程“产品化、流程化”。  
好处是：

- 职责更清晰
- 出错时更容易定位问题
- 更适合多人、多任务、长周期项目

换句话说，它不是在追求“一个超级 AI”，而是在追求“一套可运行的 AI 研发组织”。

##### 3. 它解决的是哪些真问题

文中列的问题都很典型，而且很实际：

- `Session 持久化`：Agent 重启后还能接着干，避免“失忆”
- `状态机流转`：任务状态统一，减少混乱
- `checkin 恢复`：新上下文下快速续上任务，不必从零解释
- `生命周期钩子`：让多 Agent 协作有顺序、有规则
- `Kanban 展示`：人能实时看到进展，不再黑盒
- `空闲过期`：避免卡住的任务长期占资源

这些能力听起来不像“很炫的 AI”，但恰恰是能不能在真实团队里用起来的关键。

##### 4. 为什么“人的问题”更重要

文中最后提到的几个点，说明作者并没有把人排除在外，而是在设计“人机协作”：

- `Task DAG`：让依赖关系清楚，便于并行推进
- `需求澄清`：先问清楚再做，减少返工
- `@Mention`：让人和 Agent 像在团队聊天一样协作
- `按角色分权限`：避免工具乱用、权限失控

这说明一个现实：  
AI Coding 不是“用 AI 替代人”，而是“让 AI 成为团队中的一个可管理成员”。

#### 我的意见

我认为这个方向很对，而且比单纯讨论“哪个模型更强”更有价值。

- 短期看，AI Coding 的瓶颈往往不是写不出代码，而是流程不稳定、协作不顺、上下文容易断
- 中期看，真正能进入团队生产环境的，不是最会秀能力的 Agent，而是最可控、可追踪、可协作的系统
- 长期看，AI 开发平台的竞争，可能会越来越像“组织系统能力”的竞争，而不只是模型能力竞争

不过也要注意两点：

- 流程设计太重，可能会拖慢小项目效率
- Agent 分工越细，越依赖好的任务拆解和状态管理，否则容易变成“流程很多，产出一般”

一句话说：  
`Chorus` 这类项目的价值，不在于让 AI 更像天才程序员，而在于让 AI 更像一个能被团队管理、协作和验收的开发成员。
