## 分析要点

- **核心高价值点**：最有价值的是将“先读取真实品牌上下文再生成设计”的理念落成可执行的五步品牌资产协议。
- **留存建议**：短中期保留，适合作为AI设计工作流与Agent产品形态的案例参考（包含可复用的Agent-first设计思路、品牌资产抽取流程和若干实际用例，便于后续参考）
- **不足**：论证主要依赖作者自述与案例展示，宣传成分偏重，缺乏独立验证与量化对比

**知识要点**

- Agent-first设计工作流强调由代理自动完成品牌读取、规范生成、产物验证，而非人手动操作图形界面
- 品牌资产协议可拆为提问、搜集官方素材、兜底下载、提取真实色值、固化为spec五步
- 在设计生成前加入Playwright自动点击验证，可提升原型交付稳定性
- 多风格并行生成与本地多Agent协作适合做设计方向探索

**行动项**

- 借鉴文中的五步品牌资产协议，为自己的设计或前端生成流程补一个brand-spec生成环节
- 评估是否将原型生成后的自动化验证纳入现有AI产物工作流中

#### Agent-first vs GUI-first 代理优先 vs GUI 优先

先说一个我最近越来越坚定的判断。

Claude Design的本质，是把设计师塞进了Claude里面。它让你像和Canva、和Figma对话一样，用自然语言告诉设计师你想要什么，它给你生成出来，你再在它的画布上微调。这是一个更好的图形工具。

huashu-design的本质不一样。它不想做图形工具，它想让图形工具这一层消失。

你告诉agent你要什么，agent自己去读你的品牌资产、自己去建design spec、自己生成HTML结果、自己跑Playwright验证交付物没坏。整个过程你不打开任何界面。最后你看到的是一个能直接用的MP4、一张可以截图发朋友圈的PPT、一个能给产品经理演示的iOS原型。

这两条路的差别，不是「哪个功能更强」，是 谁来操作工具。

Claude Design是给Figma这代工具续命。huashu-design是让Figma这代工具自然消亡。

我不是在说Figma会被杀死。Photoshop也没有被杀死，但今天大部分内容创作者已经不打开PS了，他们用Canva、用Midjourney、

[用Remove.bg 使用 Remove.bg](http://xn--remove-2w4o.bg/)。PS没死，但PS的工作流被绕开了。Figma也会经历同样的事情。

我不是设计师，我是一个让agent帮我做东西的人。真正的设计师可能会更喜欢Claude Design，那里有熟悉的画布、图层、组件变体。但对独立开发者、内容创作者、在终端里做产品的人来说，一个装在agent里的skill，比一个装在浏览器里的产品更顺手。

![Image](https://pbs.twimg.com/media/HGaXcHZbwAEvEtf?format=jpg&name=large)

#### 案例一 · 一次生成4个设计风格的演讲PPT

我前几天要去准备一场关于AI心理学的演讲。

按过去的习惯，这种事我会先打开Keynote，然后在里面挣扎大半天：到底用什么风格？学术一点还是活泼一点？黑白简约还是大胆配色？

这次我在终端里只说了一句话。

「我要做AI心理学的演讲PPT，内容大纲在这个文件里。不知道用什么风格，你推荐4个差异化方向给我选。」

huashu-design启动了它的 设计方向顾问模式。从20种预置的设计哲学里（Pentagram的信息建筑、Field.io的运动诗学、Kenya Hara的东方极简、Sagmeister的实验先锋……），挑出4个互相差异最大的方向，然后并行启动4个agent，各自做了一套完整的演讲PPT。

40分钟后，4套17页的PPT摆在我面前。

北大学术版：克制的serif字体、大量留白、信息层级严格分明，像一篇学术海报。

博尔赫斯文学版：深色背景、金色点缀、引用排版带有书籍感，每一页都像是从一本小说里撕下来的一章。

投行严肃版：高对比黑白配色、图表驱动、右上角带页码和版权声明，一眼就知道是要给董事会看的。

禅意极简版：大块负空间、一页一个关键字、配色只用米白和一种墨色，像日本平面设计师做的海报。

![Image](https://pbs.twimg.com/media/HGaXfpebIAARKp6?format=jpg&name=large)

我没打开任何设计软件。我不需要去试那20种字体、不需要去挑配色方案、不需要自己搭版式。agent帮我做了所有的预设工作，我只需要做一件事： 选哪一套。

最后我选了北大学术版。但另外3套也不会浪费。博尔赫斯版我可能留着做下一次读书分享，投行版可以改成商单的汇报PPT。一次生成，多次复用。

这个体验在Claude Design里也能做，只是你需要跟它说4次、生成4次、消耗4次token。在skill里走的是API消耗，没有订阅quota的天花板，4个agent并行在本地的Claude Code里跑，可以随便试。

#### 案例二 · 可点击的iOS App原型

接下来是我这几天测的几个小原型。先说清楚：我自己不写代码，这些原型不是要上线的产品，是让skill拉练的验证demo，所有交互细节都是agent自己跑出来的。

一个是AI番茄钟。当然了，我想任何独立开发者都搞过番茄钟。我们就试试吧。

在终端里说：「我要做一个AI番茄钟iOS App的原型，核心是动态时长调整，给我4个核心屏幕，要真的可以点击切换。」

十几分钟后，一个带真iPhone bezel（不是那种Web mockup感）的原型打开了。4个屏幕：首页任务选择、专注中的倒计时、被AI中断后的重新评估、专注总结。每个屏幕的tab和按钮都可以点，状态自动在屏幕之间流转。

我想要的所有细节都在里面：图标用的是SF Symbols、字体是SF Pro、按钮的圆角是iOS 18的标准值、连底部的Home Indicator都画了。

这还不是最值得说的。最值得说的是，它在交付前自己跑了一遍Playwright点击测试，确保我点每一个按钮都不会导致白屏或崩溃。这是我在skill里加的一条硬规则：App原型交付前必须跑自动点击测试，否则一半的「可点击原型」最后都是不能点的。

我还用同样的方式做了Habit Tracker、Running追踪App、一个浮世绘主题的博物馆App。流程一模一样，交付质量也一样。

#### 方法论 · 品牌资产协议是我从Anthropic偷来的

到这里我想大大方方承认一件事：huashu-design里最核心的一个理念，是从Claude Design流传出来的提示词里偷师的。

那份提示词里反复强调一个核心原则： 好的高保真设计不是从白纸开始，而是从已有的设计上下文长出来。优先读用户的codebase、读design system、读UI kit，颜色优先从品牌系统里拿而不是凭空发明。

原版prompt只给了这个哲学，没有给具体怎么做。但它给的已经够了——凭空画hi-fi一定是generic的，这是 区分65分作品和90分作品的分水岭。

我在这个哲学之上，把它落成了skill里的一套5步硬流程，专门处理「用户提了一个品牌名，但没给资料」的场景：

Step 1 · 问。一句话问清楚：「这个品牌有brand guidelines吗？有的话直接给我，没有的话我去搜。」

Step 2 · 搜官方品牌页。典型路径是 &lt;brand&gt;.com/brand 或 brand.&lt;brand&gt;.com，没有就 &lt;brand&gt;.com/press。这些页面一般藏着最权威的logo和色值。

Step 3 · 下载资产，三条兜底路径。真实世界里SVG logo经常拿不到，2026年的官网大多是Next.js SSR inline SVG，或者Cloudflare反爬返回403。按成功率递减：独立SVG文件 → 官网HTML全文（inline SVG会藏在里面）→ 产品截图取色。前一条失败立刻走下一条，绝不停。

Step 4 · grep提取真实色值。绝对不能从记忆里猜品牌色。从下载的资产里用正则抓所有

[#xxxxxx](https://x.com/search?q=%23xxxxxx&src=hashtag_click) 的6位hex，按频率排序，过滤黑白灰。这里有个反直觉的点：产品截图里常有用户演示的其他品牌色（比如某个工具的截图里在演示喜茶红），那不是这个工具本身的色。同时出现两种强色时必须区分。

Step 5 · 固化为 brand-spec.md 。前四步抽完的色值，如果只留在内存里，下一页就忘。必须写一份spec文件到项目根目录，让所有CSS变量引用这份文件。

这5步每一步都有兜底，但 绝不可以静默跳过。agent是否走通这个协议，直接决定输出质量是65分还是90分。

我做了一次v1和v2的A/B测试，同一批任务6个agent各跑一遍。结果是：v2的稳定性方差比v1低5倍。不是均值变高了很多，是更加稳定。稳定性的稳定性，这才是skill真正的护城河。

![Image](https://pbs.twimg.com/media/HGaXujVbkAADtkp?format=jpg&name=large)

#### 我能做什么，做不到什么

我不想装，这个skill做不到Claude Design的所有能力，把差距列出来。

它能做：PPT（17+页完整deck，1920×1080可直接演示）、App原型（真iPhone bezel、可点击交互、自带Playwright验证）、动画Demo（时间轴驱动、60fps插帧、可导出MP4/GIF、带BGM和自动fade）、信息图和数据可视化、设计变体探索（并排对比多方向、或者用Tweaks实时调参）、品牌延伸物料（海报、卡片、社交媒体配图）。

它做不到的：

图层级可编辑的PPTX。Claude Design能导出到Figma，我做不到。我的产物是HTML，你可以截图、可以录屏、可以导出图片，但没法拖进Keynote改一个文字位置。这是我的skill的真实缺点。

复杂的Framer Motion级别动画。我用的是React + Babel内联脚本，能做的是「时间轴驱动的slide动画」「60秒以内的叙事动画」。再复杂的（3D、物理模拟、粒子系统），超出skill边界。

品牌资产完全空白的情况。如果你的需求是「帮我设计一个完全原创的品牌」，而我又拿不到任何参考，fallback的质量会掉到60-65分。不是skill的问题，是凭空画hi-fi本来就是last resort。

我做的是一个80分的skill，不是一个100分的产品。但对不愿意打开图形界面的人， 80分的skill比100分的产品好用。

### 2026-04-22 05:05:40

#### 《我逆向了 Claude Design！免费开源！设计逻辑全公开》总结

##### 核心观点

作者做了一个开源设计技能`huashu-design`，本质上不是再造一个设计软件，而是把 “设计能力” 直接装进 AI agent 里。  
用户只需要在终端里提需求，agent 就会自动补品牌资产、生成设计规范、产出可用结果，尽量不让人再打开 Figma、Keynote 这类图形界面。

##### 为什么要做

###### 1. Claude Design 很强，但不适合所有人
作者认可 Claude Design 是目前很成熟的 AI 设计产品，但它依然是一个 “需要人去操作的工具”。  
对于习惯在终端里工作、喜欢让 agent 代劳的人来说，哪怕产品再强，只要还要自己点界面，效率就不够高。

###### 2. 目标不是优化工具，而是绕过工具
Claude Design 是 “GUI-first”（图形界面优先），本质上是把设计师搬进 Claude。  
`huashu-design`则是 “agent-first”（代理优先），目标是让 agent 自己完成设计流程，人只负责提要求和做选择。

##### 它解决了什么问题

###### 1. 自动完成设计前置工作
过去做 PPT 或原型，最耗时间的往往不是内容本身，而是选风格、定字体、配色、搭版式。  
现在 agent 会先做这些预设工作，用户只需要挑选结果，不用自己一遍遍试错。

###### 2. 一次生成多个方案
作者展示了一个典型场景：做 AI 心理学演讲 PPT 时，agent 一次给出 4 套差异明显的设计方向。  
这意味着设计从 “手工探索” 变成 “批量生成 + 人工筛选”，效率更高，也更容易复用。

###### 3. 输出更接近可交付物
它不只是生成静态页面，而是能做：
- 完整 PPT
- 可点击 iOS 原型
- 动画 Demo
- 信息图和品牌物料

尤其原型部分，还会在交付前自动跑点击测试，避免 “看起来能点、实际上不能用” 的问题。

##### 方法论亮点

###### 1. 高质量设计不能凭空生成
作者借鉴 Claude Design 的核心理念：  
好的高保真设计，不应该从白纸开始，而应该基于已有的品牌资产、设计系统和上下文来生成。

###### 2. 把品牌资产处理做成硬流程
作者把这套逻辑落成了 5 步协议：
- 先问用户有没有品牌规范
- 没有就去找官网品牌页
- 下载 logo、页面源码或截图
- 提取真实品牌色值
- 固化成`brand-spec.md`

重点不是 “会不会做”，而是 “不能跳步骤”。  
作者认为，设计输出能否稳定达到高质量，关键就在于这套流程有没有严格执行。

##### 和 Claude Design 的差异

###### 1. Claude Design 更像产品
它更完整、更成熟，有画布、组件、品牌资产管理，也更适合专业设计师使用。

###### 2. huashu-design 更像工作流插件
它没有复杂界面，甚至不追求替代所有设计软件，而是专门服务于 “用 agent 做事” 的人。  
对独立开发者、内容创作者、终端工作流用户来说，这种形态反而更顺手。

##### 能做什么，不能做什么

###### 能做的
- 生成完整 PPT
- 生成可点击 App 原型
- 做动画和 Demo
- 做信息图和设计变体
- 做海报、卡片、社媒配图等品牌延伸物料

###### 做不到的
- 导出可编辑图层级的 PPTX/Figma 文件
- 做特别复杂的高阶动画
- 在完全没有品牌资产和参考的情况下，稳定做出高质量原创品牌设计

也就是说，它更适合 “快速生成可用成果”，不适合 “深度手工编辑”。

##### 作者的最终判断

作者并不认为 Figma 会被彻底消灭，而是认为它会像 Photoshop 一样继续存在，但越来越多人的工作流会绕开它。  
未来的变化可能不是 “工具没了”，而是 “人不再频繁打开它了”。

##### 一句话总结

这篇文章真正想表达的是：  
**AI 设计的下一步，不一定是更强的设计软件，而可能是让设计软件在工作流里逐渐隐身。**

## 结构化（1）

#### 文章主旨

这篇文章的核心是在讲：作者把自己逆向拆解的`Claude Design`设计逻辑，做成了一个可装进`Claude Code`的开源 skill——`huashu-design`。

##### 一、为什么要做`huashu-design`

- 作者最初在 X 上预告开源这个项目后，获得了**20 多万阅读**，而且评论区不只是中文用户，连日本、韩国等不同国家的用户都很期待。

- 作者承认自己刚接触`Claude Design`时非常兴奋，甚至玩到**凌晨四点**，因为它已经能在对话里直接生成网页和可点击的 iOS 原型。
- 但几天后，作者发现自己**不再使用 Claude Design**，原因不是产品差，而是自己更习惯 “让 agent 在终端里干活”，不想打开图形界面操作工具。

##### 二、作者的核心判断：`Agent-first`和`GUI-first`是两条不同路线

- 作者认为，`Claude Design`本质上是把 “设计师工作流” 放进 Claude 里：你用自然语言描述需求，它生成结果，你再去画布里继续调。
- 而`huashu-design`的目标不是做另一个图形工具，而是**让图形工具这一层直接消失**。
- 在`huashu-design`里，用户只需要说需求，agent 会自动完成这些步骤：
  - 读取品牌资产
  - 建立 design spec
  - 生成 HTML 结果
  - 用 Playwright 验证交付物是否可用
- 最终交付的不是半成品，而是**可以直接用的结果**，比如：
  - 可导出的 MP4 动画
  - 可以截图发出去的 PPT
  - 能点击演示的 iOS 原型
- 作者认为，两者差别不在于 “谁功能更强”，而在于：**到底是谁在操作工具**。
- 他还用 Photoshop 做类比：PS 没消失，但很多创作者早已绕过 PS，改用 Canva、Midjourney、Remove.bg；作者判断 Figma 未来也会经历类似变化。

##### 三、案例一：一次生成 4 套不同风格的演讲 PPT

- 作者要准备一场关于**AI 心理学**的演讲，以前这种任务通常要先打开 Keynote，花大量时间纠结风格。
- 这次他只在终端输入一句话：  
  “我要做 AI 心理学的演讲 PPT，内容大纲在这个文件里。不知道用什么风格，你推荐 4 个差异化方向给我选。”
- `huashu-design`会启动 “设计方向顾问模式”，从**20 种预置设计哲学**中挑选差异最大的方向，例如：
  - Pentagram 的信息建筑
  - Field.io 的运动诗学
  - Kenya Hara 的东方极简
  - Sagmeister 的实验先锋
- 然后并行启动**4 个 agent**，各自做出一整套 PPT。
- **40 分钟后**，作者拿到了**4 套、每套 17 页**的完整演讲稿设计，分别是：
  - **北大学术版**：serif 字体、留白多、层级清晰，像学术海报
  - **博尔赫斯文学版**：深色背景、金色点缀、引用排版像书页
  - **投行严肃版**：黑白高对比、图表驱动、适合董事会汇报
  - **禅意极简版**：大面积负空间、米白加墨色，像日本平面海报
- 这个过程最大的价值在于：作者不需要自己反复试字体、配色和版式，只需要**在多套方案中做选择**。
- 最后作者选了 “北大学术版”，但另外 3 套也可以留作后续复用。
- 作者还强调，相比 Claude Design 需要用户手动生成多次，这个 skill 走的是**API 消耗**，没有订阅配额的上限，并且支持**4 个 agent 本地并行运行**。

##### 四、案例二：生成可点击的 iOS App 原型

- 作者还用它测试了多个 App 原型，虽然自己不写代码，但这些原型能作为 skill 能力的验证 demo。
- 其中一个例子是**AI 番茄钟 App**。作者在终端中输入：
  “我要做一个 AI 番茄钟 iOS App 的原型，核心是动态时长调整，给我 4 个核心屏幕，要真的可以点击切换。”
- **十几分钟后**，系统生成了一个带真实 iPhone 边框的原型，而不是普通网页 mockup。
- 原型包含**4 个核心屏幕**：
  - 首页任务选择
  - 专注倒计时
  - 被 AI 中断后的重新评估
  - 专注总结
- 这些页面之间可以真实点击切换，按钮和 tab 都是可用的，状态也能在页面间流转。
- 作者特别提到一些细节都被处理好了：
  - 图标使用**SF Symbols**
  - 字体使用**SF Pro**
  - 按钮圆角符合**iOS 18 标准值**
  - 连底部**Home Indicator**都做出来了
- 更关键的是，这些原型在交付前会自动跑一遍**Playwright 点击测试**，确保点击后不会白屏或崩溃。
- 作者认为这是非常重要的硬规则，因为很多所谓 “可点击原型” 实际上并不能真正稳定点击。
- 同样的方法还做过：
  - Habit Tracker
  - Running 追踪 App
  - 浮世绘主题博物馆 App

##### 五、方法论重点：品牌资产协议是质量分水岭

- 作者坦率承认，`huashu-design`最核心的方法论之一，是从流传出来的`Claude Design`提示词中 “偷师” 来的。
- 那套提示词强调一个重要原则：  
  **好的高保真设计不是从白纸开始，而是从已有设计上下文中长出来。**
- 也就是说，做设计时应优先读取：
  - 用户现有 codebase
  - design system
  - UI kit
  - 品牌颜色与素材
- 作者进一步把这个理念落成了一套**5 步硬流程**，专门处理 “用户只给品牌名、没给资料” 的情况：

###### 1）先问清品牌资料是否存在
- 用一句话确认：品牌有没有 brand guidelines。
- 如果有，直接让用户提供；如果没有，再去网上搜。

###### 2）优先找官方品牌页
- 常见路径包括：
  - `&lt;brand>.com/brand`
  - `brand.&lt;brand>.com`
  - `&lt;brand>.com/press`
- 因为这些页面往往藏着最权威的 logo 和颜色值。

###### 3）下载资产时设置 3 层兜底
- 现实里 SVG logo 经常拿不到，因为会遇到：
  - Next.js SSR inline SVG
  - Cloudflare 403 反爬
- 所以按成功率递减依次尝试：
  - 独立 SVG 文件
  - 官网完整 HTML（从 inline SVG 里提取）
  - 产品截图取色
- 一条失败就立刻切下一条，**不能停住**。

###### 4）用正则提取真实色值
- 不能靠记忆猜品牌色，必须从下载的素材中抓取真实的`#xxxxxx`六位十六进制颜色。
- 然后按频率排序，并过滤掉黑白灰。
- 作者还提醒了一个很实际的问题：  
  产品截图里可能会出现其他品牌的颜色，比如某个工具演示页面里用了 “喜茶红”，这并不代表它本身的品牌色。

###### 5）固化为`brand-spec.md`
- 提取出的品牌规范不能只留在上下文记忆里，必须写成项目根目录的`brand-spec.md`。
- 之后所有 CSS 变量都基于这份 spec 来引用，这样后续页面不会 “忘掉” 品牌信息。

- 作者强调：这 5 步**不能静默跳过**，因为它直接决定作品是**65 分**还是**90 分**。
- 他还做过一次 v1 和 v2 的 A/B 测试：  
  同一批任务让**6 个 agent**各跑一遍，结果是**v2 的稳定性方差比 v1 低 5 倍**。
- 也就是说，真正重要的不只是平均质量更高，而是输出**更稳定、更可预测**。

##### 六、它能做什么，做不到什么

###### 能做的
- **PPT**：支持**17 页以上**的完整 deck，分辨率**1920×1080**，可以直接演示
- **App 原型**：带真实 iPhone bezel、可点击交互、附带 Playwright 验证
- **动画 Demo**：时间轴驱动、**60fps**插帧，可导出**MP4/GIF**，还能带 BGM 和自动 fade
- **信息图与数据可视化**
- **设计变体探索**：支持多方向并排对比，或通过 Tweaks 实时调参
- **品牌延伸物料**：如海报、卡片、社交媒体配图

###### 做不到的
- **图层级可编辑的 PPTX**
  - Claude Design 可以导出到 Figma
  - `huashu-design`的产物主要是 HTML
  - 可以截图、录屏、导图片，但不能像在 Keynote 里那样随手拖动某个文本框
- **复杂到 Framer Motion 级别的动画**
  - 当前技术路线是`React + Babel`内联脚本
  - 适合做 “时间轴驱动的 slide 动画” 和**60 秒以内**的叙事动画
  - 对于 3D、物理模拟、粒子系统等复杂效果，超出了边界
- **完全从零创造品牌**
  - 如果没有任何品牌资产，也没有可参考内容，只能 fallback 到较弱方案
  - 在这种情况下，质量可能会掉到**60–65 分**

- 作者对这个 skill 的定位很明确：  
  它不是一个 100 分的完整产品，而是一个**80 分但足够好用的 skill**。  
  对那些不想打开图形界面的人来说，80 分的 skill 可能比 100 分的产品更有价值。

##### 七、结尾观点：不是工具被杀死，而是工作流被绕开

- 作者最后的观点是：Figma 这类工具不一定会 “被消灭”，但人们可能会在某一天突然发现，自己已经很久没打开它了。
- 他感谢 Anthropic 把`Claude Design`的提示词写得足够清晰，让社区得以流传出足够完整的 spec，也让自己可以把这些精华吸收到个人工作流中。
- 作者认为，这种基于现有产品逻辑进行再创造的方式，在 agent 时代会越来越常见，也是 AI 时代开源文化的一种新形态。

  - `npx skills add alchaincyf/huashu-design`

这篇文章本质上不是单纯介绍一个开源项目，而是在提出一种新的设计工作流：**未来很多设计需求，可能不再通过 “打开 Figma” 完成，而是通过 “对 agent 说一句话” 完成。**

### 回答 · 2026-04-22 06:45:23

#### 基于「Agent-first 设计工作流」的最佳实践示例

下面我用一个具体场景，结合你提供的文章内容，给出一套可直接复用的最佳实践。

---

##### 实例场景

**目标**：为一家 AI 笔记产品做一套「融资路演 PPT 首屏 + 产品演示原型」  
**使用方式**：不打开 Figma / Keynote，只在终端里向 agent 下达任务

###### 假设你的输入指令是：

```bash
请为我的 AI 笔记产品生成一套融资路演视觉方案：
1. 先读取 docs/brand/ 下的品牌资料和官网文案
2. 输出 3 个差异化设计方向
3. 选定方向后生成 PPT 首页和 3 页核心内容页
4. 再生成一个可点击的 iOS 产品原型首页
5. 最后用 Playwright 检查页面是否可用，并输出截图
```

---

##### 为什么这个实例最能体现文中的方法论

这个例子正好覆盖了文章里最重要的几件事：

- **不是先画图，而是先理解品牌**
- **不是让人手动调界面，而是让 agent 串起设计流程**
- **不是只生成静态视觉，而是生成可验证的交付物**
- **不是只有一个方向，而是先做风格分叉，再收敛执行**

也就是说，这不是“AI 帮你画一张图”，而是“AI 帮你跑完整个设计任务链路”。

---

#### 最佳实践

##### 1. 不要一上来就让 agent 直接出图

很多人最容易犯的错是：

```bash
帮我做一个很高级的融资 PPT
```

这种提示词太粗，结果通常会落入“看起来还行，但不像你的品牌”。

###### 最佳做法

先让 agent 分三步做：

1. **识别品牌资产**
2. **生成设计 spec**
3. **再开始产出视觉结果**

###### 推荐指令结构

```bash
先不要生成页面，先完成以下工作：
1. 提取品牌名、口号、目标用户、产品定位
2. 从官网/文档中提取真实品牌色、字体倾向、视觉语气
3. 生成一份 brand-spec.md
4. 基于该 spec 提出 3 个设计方向
```

###### 为什么这是最佳实践

因为文章里最有价值的点，不是“能生成 PPT”，而是：

> 先把品牌资产协议化，再让 agent 在 spec 约束下生成内容。

这样做的好处是：

- 风格不会漂
- 后续 PPT、原型、海报可以复用同一套规范
- 设计结果更像“一个品牌系统”，而不是“一次性图片”

---

##### 2. 先做「多方向探索」，不要过早收敛

文章提到的一点非常关键：  
**让 agent 一次生成多个差异化风格方向，再从中选择。**

这比传统做法更高效，因为很多设计问题并不是“做不出来”，而是“方向选错了”。

###### 在这个实例里，建议 agent 先给出 3 个方向：

###### 方向 A：理性科技型
- 黑白灰 + 冷色强调
- 强信息层级
- 适合融资、B 端、专业叙事

###### 方向 B：未来产品型
- 明亮渐变 + 轻拟物界面
- 强调产品体验和创新感
- 适合产品演示和发布会

###### 方向 C：克制高端型
- 留白大、排版节制、字体气质强
- 强品牌感和审美辨识度
- 适合高价值品牌叙事

###### 最佳实践建议

让 agent 输出时必须包含以下字段：

```md
- 方向名称
- 核心视觉比喻
- 适用场景
- 主色/辅色
- 字体建议
- 页面节奏
- 风险点
```

###### 为什么这样做更好

因为这会把“我觉得这个风格不错”  
变成  
“这个方向为什么适合融资场景、为什么适合这个品牌”。

这一步本质上是在让 agent 先做 **设计策略顾问**，再做 **执行设计师**。

---

##### 3. 设计产出前，先固化一份 `brand-spec.md`

这是整个流程最值得长期保留的资产。

###### 一个好的 `brand-spec.md` 应该至少包含：

```md
# Brand Spec

## Brand Core
- 品牌名：
- Slogan：
- 产品定位：
- 目标用户：
- 不希望出现的表达：

## Visual System
- 主色：
- 辅色：
- 背景色：
- 字体策略：
- 图形语言：
- 动效倾向：

## Tone
- 关键词：
- 应避免的风格：
- 页面气质：

## Layout Rules
- 栅格倾向：
- 圆角规则：
- 卡片规则：
- 阴影规则：
- 留白密度：

## Output Constraints
- PPT 适配比例：
- iPhone 原型尺寸：
- 是否需要暗色版本：
```

###### 最佳实践

无论你后面做的是：

- PPT
- 官网首页
- App 原型
- 海报
- 动画短片

都让 agent **优先读取这份 spec**。

###### 为什么

因为真正高质量的 AI 设计，不是靠一次提示词爆发，而是靠：

> 同一品牌规范，在多个任务中保持一致。

这才是文章里“品牌资产协议”的真正价值。

---

##### 4. 把任务拆成「策略层」和「执行层」

不要把所有事情塞进一条长指令里直接跑。

###### 错误做法

```bash
读取我的品牌资料，设计 3 个方向，生成 PPT，做 iPhone 原型，跑测试并导出所有文件
```

这个做法的问题是：

- 中间过程不可控
- 容易在前面的判断出错后一路错下去
- 很难复用中间成果

###### 最佳流程

###### 阶段一：策略层
- 提取品牌资产
- 输出 `brand-spec.md`
- 生成 3 个方向
- 人来选方向

###### 阶段二：执行层
- 生成 PPT 页面
- 生成原型页面
- 导出视觉稿
- 跑自动化验证

###### 最佳实践指令范式

```bash
第一阶段只做策略，不生成最终页面。
完成 brand-spec.md 和 3 个方向提案后暂停，等我确认。
```

确认后再继续：

```bash
基于方向 B 和 brand-spec.md，生成融资路演 PPT 的前 4 页，
并补一个 iOS 首页原型。所有页面风格必须统一。
```

###### 为什么这样最好

因为设计本质上是高成本收敛过程。  
先在低成本阶段判断方向，远比生成一堆精美但方向不对的页面更重要。

---

##### 5. 交付物必须是「可验证」的，而不是「看起来差不多」

你提供的内容里有一个非常强的信号：

> agent 不只是生成 HTML / 原型，还会自己跑 Playwright 验证。

这一步是很多 AI 设计流目前最缺的。

###### 在这个实例中，应该验证什么？

###### 对 PPT 页面验证
- 是否有文字溢出
- 标题是否被裁切
- 页脚/页码是否错位
- 深浅背景下对比度是否足够

###### 对 iOS 原型验证
- 按钮是否可点击
- 页面跳转是否正常
- 首屏是否超出安全区域
- 导航栏、底部栏是否遮挡内容

###### 最佳实践

让 agent 在生成后自动执行：

```bash
1. 启动本地预览
2. 用 Playwright 截图每一页
3. 点击关键交互路径
4. 输出 qa-report.md
5. 标记问题页面并自动修复一次
```

###### 为什么这是最佳实践

因为 AI 生成设计最大的问题之一不是“丑”，而是：

- 看图很像成品
- 一运行就有细节问题
- 一截图就露馅

加入验证环节后，交付物才从“演示品”升级为“可用件”。

---

##### 6. 明确要求 agent 输出「设计理由」，不要只要结果

如果只是要页面，agent 很容易生成一个“趋势感很强”的方案。  
但如果你要长期复用这个流程，就必须让它解释：

- 为什么选这个方向
- 为什么这样排版
- 为什么用这个配色
- 为什么这个页面适合融资叙事

###### 推荐补充要求

```bash
每个页面生成后，请同时输出：
1. 页面目标
2. 视觉策略
3. 信息层级逻辑
4. 为什么这样设计
```

###### 示例

```md
### Page 1: 封面页
- 页面目标：建立品牌可信度与技术前景
- 视觉策略：深色大留白 + 单一发光主视觉
- 信息层级：品牌名 > 一句话价值 > 演讲标题
- 设计理由：融资场景优先传达确定性和高级感，避免过度炫技
```

###### 为什么这一点重要

因为你最终想积累的，不只是“几个页面文件”，而是：

> 一套可以持续训练 agent 的设计决策模式。

---

##### 7. 让 agent 生成时优先使用真实素材，避免“伪品牌感”

这是文章里一个很容易被忽略，但极重要的点：  
**从真实品牌资产里提取颜色、语气、组件规律，而不是临时脑补。**

###### 在这个实例里，真实素材包括：

- 官网 hero 文案
- App Store 截图
- Logo SVG
- 产品主界面截图
- 创始人介绍页
- 过往融资 deck 中的品牌表述

###### 最佳实践指令

```bash
优先使用以下真实素材建立品牌认知：
- docs/brand/logo.svg
- docs/brand/website-copy.md
- docs/brand/screenshots/
- docs/brand/founder-bio.md

如果素材缺失，再进行合理推断，并明确标注哪些是推断项。
```

###### 为什么要这么做

因为“像品牌”这件事，本质上不是靠审美，而是靠证据。

真实素材越多，设计结果越稳定；  
推断越少，后期返工越少。

---

#### 一套推荐的完整执行流程

下面是这个实例最推荐的落地流程：

##### Step 1：准备输入材料

整理到一个目录里：

```bash
project/
├── docs/
│   ├── outline.md
│   ├── brand/
│   │   ├── logo.svg
│   │   ├── website-copy.md
│   │   ├── screenshots/
│   │   └── founder-bio.md
```

---

##### Step 2：先生成品牌规范

```bash
请读取 docs/brand/ 下全部资料，生成一份 brand-spec.md。
要求：
- 提取真实品牌资产
- 区分事实与推断
- 给出视觉语气和禁用风格
```

---

##### Step 3：做 3 个方向提案

```bash
基于 brand-spec.md，为融资路演场景提出 3 个差异化设计方向。
每个方向需要包含：
- 命名
- 核心概念
- 适用理由
- 配色
- 字体建议
- 页面节奏
- 风险点
```

---

##### Step 4：确认一个方向后再生成页面

```bash
选择方向 B。
请生成：
- 1 页封面
- 1 页市场机会
- 1 页产品能力
- 1 页商业模式
- 1 个 iOS 首页原型
要求统一视觉语言，并输出 HTML 预览文件。
```

---

##### Step 5：自动验证和修复

```bash
请启动预览并执行自动化检查：
- 截图全部页面
- 检查文字溢出
- 检查点击热区
- 输出 qa-report.md
- 自动修复一次明显问题
```

---

#### 这个实例中的最终最佳实践原则

总结成几条最关键的原则，就是：

##### 1. 先理解品牌，再生成视觉
没有品牌理解的生成，只是“好看的模板拼装”。

##### 2. 先做方向探索，再做高保真执行
方向判断错了，后面做得越精细，浪费越大。

##### 3. 设计规范要文件化
`brand-spec.md` 是整个工作流的中枢资产。

##### 4. 把 agent 当成流程执行者，而不只是出图工具
它应该负责提取、推理、生成、验证，而不只是“画图”。

##### 5. 交付物必须经过自动验证
能运行、能点击、能截图，才是实际可交付成果。

##### 6. 让每个设计决策都可解释
这样你才能复用、优化、沉淀成长期能力。

---

#### 一个可以直接复用的最佳实践提示词模板

```md
你现在不是直接出图的设计工具，而是一个 agent-first 设计执行系统。

请按以下流程工作：

1. 先读取 `docs/brand/` 和 `docs/outline.md`
2. 提取品牌资产，并生成 `brand-spec.md`
3. 基于 spec 提出 3 个差异化设计方向
4. 等我确认方向后，再生成页面
5. 输出 HTML 版本的 PPT 页面和 iOS 原型
6. 使用 Playwright 自动截图和点击验证
7. 输出 `qa-report.md`
8. 对明显的布局/交互问题自动修复一次

设计要求：
- 优先使用真实品牌素材，不足处再推断
- 所有推断项单独标注
- 每个页面附带设计理由
- 风格统一，避免模板感和伪高级感
- 融资场景优先强调可信度、信息层级和品牌辨识度
```
