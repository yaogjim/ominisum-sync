### AI 智能体领域的下一个重大突破是一个 12 行的 YAML 文件（技能包）

The next big unlock in AI agents isn't a bigger model.

It's a 12-line YAML file.

Hermes Agent calls them skill bundles. And it's a big release from

[@NousResearch](https://x.com/@NousResearch) .

Here's why they're about to change how everyone uses AI.

The setup tax nobody talks about

Open any chat with any AI agent today.

What's the first thing you do?

You paste a doc. Then another doc. Then the example of the thing you want. Then a reminder of your tone. Then a constraint you forgot the last three sessions.

By the time you actually ask the agent to do the work, you've burned 4 minutes on context paste.

You'll do it again tomorrow.

This is the setup tax. Everyone pays it. Nobody talks about it.

The pitch of AI agents was always "delegate work." The reality has been "re-onboard your agent every morning, then maybe delegate."

Skill bundles are the first feature I've seen that actually kills this.

First, what a skill is

Before we get to bundles, the 30-second version.

In Hermes, a skill is a markdown file (SKILL.md) that lives in \~/.hermes/skills/. Every installed skill is automatically a slash command.

→ /gif-search funny cats — loads the gif-search skill → /plan refactor the auth layer — loads the planning skill → /excalidraw — loads the diagram skill, then asks what you need

The skill is on-demand knowledge. The agent doesn't load it until you call it. Progressive disclosure — minimum tokens until you need them.

You can write skills yourself, install them from the Skills Hub (

skills.sh,

agentskills.io

, GitHub repos), or let the agent create its own after it solves a hard problem.

That alone is a big deal. But it's not the unlock.

What a skill bundle actually is

A skill bundle is a YAML file that groups several skills under one slash command.

That's it. That's the whole thing.

Here's a real one straight from the docs:

yaml

name: backend-dev description: Backend feature work — review, test, PR workflow. skills: - github-code-review - test-driven-development - github-pr-workflow instruction: \| Always start by writing failing tests, then implement. Open the PR through the standard workflow with co-author tags.

Save that to \~/.hermes/skill-bundles/backend-dev.yaml and now you have:

/backend-dev refactor the auth middleware

One command. Three skills loaded. Plus the standing instruction about how you always work.

The agent now has — in one shot — your testing philosophy, your code review checklist, your PR conventions, and the actual task to execute.

The part that gets glossed over: that instruction field is where you encode the meta-process. The "how I always do this thing" layer.

It's a frozen, named version of your working style.

The bundle I actually live in

Here's mine.

I produce X Articles constantly. The old workflow: open chat, paste my voice doc, paste the article frameworks, paste the viral hooks database, paste the story extraction prompts, then explain what I want to write about.

第一句之前有五个附件。

所以我建了这个：

yaml

名称: handsome-x 描述：X 文章创作——语气、钩子、结构、故事提炼。 技能: x-文章 安托万-语音 故事内容系统 病毒式钩子数据库 指令: \| 在起草之前，询问2-3个澄清问题。 在撰写完整内容之前，生成5个钩子选项。 将钩子与一个经过验证的病毒式传播公式相匹配。 以“保持帅气”结束每篇文章。

现在我输入：

/handsome-x 关于 Hermes 技能包的文章，\~1200 字，个人证明角度

And I get back: clarifying questions, five hook options, then the full article in my voice, with my structure, ending the way I always end.

Setup time: 0 seconds.

The agent isn't smarter. The agent is pre-loaded.

Why this compounds

One bundle is convenient. The library of bundles is the unlock.

Every workflow you do more than twice deserves a bundle.

→ /handsome-x — X Articles → /youtube-package — title + thumbnail + hook validation → /polymarket-scan — onchain research workflow before any trade → /shopify-ops — product copy + listing + image briefs → /cold-outreach — partner emails in your tone with your usual ask

You stop thinking "let me set up a session" and start thinking "I have a tool for that."

Bundles are slash-callable workflows. The slash command is the API surface to your own process.

The hidden upgrade: bundles are just YAML. You can drop them in a dotfiles repo. You can ship them to your team. You can hand someone a 12-line file and replicate years of process iteration.

That's not a chat product. That's an operating system layer.

The part SaaS founders aren't pricing in

Here's what nobody's saying out loud yet.

A skill bundle is a software workflow that doesn't pay $30/mo.

The /handsome-x bundle replaces:

→ A writing app with stored prompts → A "brand voice" SaaS → A content calendar with templates → A swipe file tool → The five Notion tabs I used to keep open

That's $80–150/mo of subscriptions, condensed into a file in \~/.hermes/skill-bundles/.

I'm not saying every SaaS dies. I'm saying the workflow layer — the part most SaaS actually sells you — moves into bundles. The SaaS becomes the data store. The bundle becomes the brain.

If you're building anything in the AI space and you haven't internalized this shift, you'll wake up one day wondering why your usage curve went sideways.

How to actually build one

Install Hermes Agent. It's free, MIT, from Nous Research.

Make sure you have at least 2–3 skills installed. Pull them from the Hub, or write your own — a skill is just a markdown file with frontmatter and instructions.

Then run:

bash

hermes bundles create handsome-x \\ --skill x-articles \\ --skill antoine-voice \\ -d "X Article production stack"

Or run hermes bundles create handsome-x with no flags and it walks you through it interactively.

That's it. The bundle is live.

The slash command works in the CLI, in the dashboard, and on every messaging platform you've connected Hermes to — Telegram, Discord, Slack. Same command, every surface.

Your workflow follows you.

The takeaway

The next 12 months of AI isn't about better models.

It's about who builds the best library of personal slash commands.

Skill bundles are the primitive that lets that library exist.

Twelve lines of YAML. A name. A list of skills. A standing instruction.

That's the unlock.

Most people will keep pasting docs into chat windows. Some will quietly build their bundle library and look like they're operating at 5x speed by Q3 2026.

If you want to have your Hermes Agent running in the cloud, no API key, no SSH, no headaches, check out:

[https://www.flyhermes.ai/](https://www.flyhermes.ai/) It it helped you, I appreciate you sharing it.

#### 1. 内容总结

文章认为：**AI 智能体的突破，不一定来自更强模型，而是来自“技能包”这种工作流封装方式。**

所谓技能包，就是一个很短的 YAML 文件，把多个 AI 技能、固定指令、个人习惯组合成一个命令。

例如：

```yaml
名称: backend-dev
技能:
  - 代码审查
  - 测试驱动开发
```

```bash
/backend-dev 重构认证模块
```

AI 就会自动加载对应技能和工作方式。

- 现在用 AI 最大的问题是：每次都要重复粘贴背景、风格、规范、示例。

- 它让 AI 从“聊天工具”变成“个人工作流工具”。

---

##### 1. 当前 AI 智能体的痛点：反复“重新培训”很浪费时间

作者指出，现在使用 AI 智能体时，很多人每次都要重复做一遍准备工作：

- 粘贴背景文档
- 粘贴示例
- 说明语气风格
- 补充限制条件
- 重复解释工作流程

这被称为 **“setup tax（设置税）”**。

也就是说，AI 智能体原本承诺的是“帮你代理工作”，但现实中常常变成了：

> 每天先重新给 AI 交代一遍背景，然后才能开始让它干活。

作者认为，Hermes Agent 的 **skill bundles（技能包）** 是第一个真正能解决这个问题的功能。

---

##### 2. 什么是 Skill：按需加载的知识和能力

在 Hermes 中，一个 **skill（技能）** 本质上是一个 Markdown 文件，通常叫 `SKILL.md`，存放在：

```bash
~/.hermes/skills/
```

每个安装好的技能都会自动变成一个斜杠命令，例如：

```bash
/gif-search funny cats
/plan refactor the auth layer
/excalidraw
```

关键特点是：

- 技能不会一开始就全部加载，只有调用时才加载
- 这样可以节省 token，减少无关上下文
- 用户可以自己写技能，也可以从 Skills Hub、GitHub 等地方安装
- AI 智能体甚至可以在解决复杂问题后，自己生成新技能

作者认为，skill 已经很有价值，但真正的突破是 **skill bundle**。

---

##### 3. 什么是 Skill Bundle：把多个技能打包成一个命令

**Skill bundle（技能包）** 是一个 YAML 文件，用来把多个技能组合到一个斜杠命令下。

示例：

```yaml
name: backend-dev
description: Backend feature work — review, test, PR workflow.
skills:
  - github-code-review
  - test-driven-development
  - github-pr-workflow
instruction: |
  Always start by writing failing tests, then implement.
  Open the PR through the standard workflow with co-author tags.
```

保存到：

```bash
~/.hermes/skill-bundles/backend-dev.yaml
```

之后就可以直接调用：

```bash
/backend-dev refactor the auth middleware
```

这个命令会一次性加载：

- 代码审查技能
- 测试驱动开发技能
- GitHub PR 工作流技能
- 固定的工作习惯和流程要求

作者强调，`instruction` 字段非常重要，因为它记录的是：

> “我通常怎么做这类事情”的元流程。

换句话说，技能包不仅是工具集合，也是个人工作方式的固化版本。

---

##### 4. 作者自己的案例：用技能包写 X 文章

作者经常创作 X 平台文章。过去他的流程很繁琐，需要先粘贴很多资料：

- 个人语气文档
- 文章结构模板
- 爆款钩子数据库
- 故事提炼提示词
- 文章主题说明

他形容为：

> 第一句话之前有五个附件。

于是他创建了一个名为 `handsome-x` 的技能包：

```yaml
名称: handsome-x
描述: X 文章创作——语气、钩子、结构、故事提炼。
技能:
  - x-文章
  - 安托万-语音
  - 故事内容系统
  - 病毒式钩子数据库
指令: |
  在起草之前，询问2-3个澄清问题。
  在撰写完整内容之前，生成5个钩子选项。
  将钩子与一个经过验证的病毒式传播公式相匹配。
  以“保持帅气”结束每篇文章。
```

现在他只需要输入：

```bash
/handsome-x 关于 Hermes 技能包的文章，~1200 字，个人证明角度
```

AI 就会自动：

- 先问 2-3 个澄清问题
- 给出 5 个文章钩子
- 按他的语气和结构写完整文章
- 结尾使用他固定的表达方式

结果是：

> 设置时间从几分钟变成 0 秒。

作者总结说，这不是 AI 变聪明了，而是 AI 被“预加载”好了。

#### AI 智能体的下一个突破：不是更大模型，而是「可复用工作流文件」

这篇内容的核心观点是：  
未来 AI Agent 的效率提升，不一定来自模型能力本身，而可能来自一种更轻量、更可迁移、更可复用的「工作流封装方式」——例如 Hermes Agent 的 **Skill Bundle 技能包**。

它本质上是一个很小的 YAML 文件，把多个技能、流程规则、个人偏好、团队规范组合成一个可调用的 slash command。

例如：

```yaml
name: backend-dev
description: Backend feature work — review, test, PR workflow.
skills:
  - github-code-review
  - test-driven-development
  - github-pr-workflow
instruction: |
  Always start by writing failing tests, then implement.
  Open the PR through the standard workflow with co-author tags.
```

之后只需要输入：

```bash
/backend-dev refactor the auth middleware
```

Agent 就能自动加载对应技能、流程规范和任务上下文。

##### 一、启发

###### 1. AI Agent 的瓶颈不只是「智力」，而是「上手成本」

很多人使用 AI 的真实体验并不是：

> 我把任务交给 AI，它直接完成。

而是：

> 我先重新告诉它背景、语气、格式、限制条件、案例、偏好，然后它才开始工作。

这篇文章把这个问题称为 **setup tax，设置税**。

这个概念非常重要。  
今天大量 AI 产品的问题不在于模型不会做，而在于每次做之前都要重新「入职」一次。

对于高频工作来说，这个成本会极大削弱 AI 的价值。

---

###### 2. Prompt 不应该只是一次性文本，而应该产品化、资产化

过去我们说「提示词工程」，很多时候指的是写一段好 prompt。  
但 Skill Bundle 指向的是更深一层：

> 把 prompt、知识、流程、偏好、规范，封装成一个可调用的工作流资产。

这意味着 prompt 不再只是聊天窗口里的临时输入，而变成类似：

- 一个命令
- 一个模块
- 一个工作流 API
- 一个团队标准操作程序
- 一个可复制的知识产品

这对个人效率、团队协作和 AI 产品形态都有启发。

---

###### 3. 未来的个人效率优势，可能来自「个人命令库」

文章里有一句很关键：

> The slash command is the API surface to your own process.

也就是说，slash command 是你个人工作流的 API。

未来高效的人，不一定是每次都把 AI 用得很巧的人，而是提前把自己的高频工作封装成一组命令的人。

例如：

```bash
/x-article
/youtube-package
/cold-outreach
/code-review
/investment-research
/product-strategy
/customer-support
```

每个命令背后都是一套已打磨过的流程。

这其实是把个人经验变成了可执行系统。

##### 二、高价值信息深挖

###### 1. Skill Bundle 的真正价值不是「聚合技能」，而是封装「元流程」

表面上看，Skill Bundle 只是把几个技能放到一起。

但真正有价值的是：

```yaml
instruction: |
  在起草之前，询问 2-3 个澄清问题。
  在撰写完整内容之前，生成 5 个钩子选项。
  将钩子与一个经过验证的病毒式传播公式相匹配。
  以某种固定方式结尾。
```

这个 `instruction` 字段封装的是：

- 你如何开始一项任务
- 你如何判断质量
- 你有哪些固定原则
- 你有哪些不希望重复解释的偏好
- 你过往经验里沉淀下来的流程

换句话说，它保存的不是知识，而是 **工作方式**。

这比单纯保存文档更有价值。

---

###### 2. Skill Bundle 是「低代码版 SOP」

传统 SOP 通常是文档，人需要阅读并执行。

Skill Bundle 不同，它是：

> 可被 Agent 直接调用和执行的 SOP。

这意味着组织里的经验可以从：

```text
写在 Notion 里的流程
```

变成：

```text
一个可以直接执行的命令
```

例如销售团队可以有：

```bash
/enterprise-outreach
/demo-followup
/proposal-draft
/renewal-risk-analysis
```

产品团队可以有：

```bash
/user-research-synthesis
/prd-draft
/competitor-analysis
/feature-prioritization
```

工程团队可以有：

```bash
/bug-triage
/code-review
/security-audit
/release-checklist
```

这会让 SOP 从「被动文档」变成「主动工具」。

---

###### 3. 这对 SaaS 的冲击点在「工作流层」

文章里有一个很重要的判断：

> SaaS becomes the data store. The bundle becomes the brain.

也就是说，很多 SaaS 的护城河并不是真正的数据，而是它帮用户固化了一套工作流。

比如一个内容创作 SaaS 可能提供：

- 品牌语气管理
- 选题模板
- 标题生成
- 钩子库
- 内容日历
- 发布流程

但如果这些都能被一个 Skill Bundle 替代，那么 SaaS 的价值会被重新拆分：

| 层级 | 过去 SaaS 提供 | 未来可能迁移到 |
|---|---|---|
| 数据层 | 文件、客户、内容、图片、交易记录 | SaaS / 数据库 |
| 工作流层 | 模板、提示词、流程、规范 | Skill Bundle / Agent |
| 执行层 | 生成、分析、操作 | Agent |
| 界面层 | Dashboard / 表单 / 编辑器 | Chat / CLI / 多平台命令 |

这意味着很多 AI SaaS 如果只是在卖「固定 prompt + UI」，风险会变大。

---

###### 4. 这其实是 AI 时代的「dotfiles」

开发者早就有一个习惯：把自己的配置文件、命令行工具、编辑器配置放进 dotfiles 仓库。

Skill Bundle 类似于 AI 工作流时代的 dotfiles。

它可以：

- 本地保存
- Git 管理
- 版本控制
- 团队共享
- 快速迁移
- 被复制、修改、组合

这使得个人和组织的 AI 使用能力可以被沉淀为资产，而不是散落在聊天记录里。

##### 三、可迁移清单

如果你是 AI/产品开发/商业系统构建者，可以把这篇文章抽象成以下清单。

---

###### 1. 识别高频工作流

问自己：

- 哪些任务我每周做超过 2 次？
- 哪些任务每次都要重复说明背景？
- 哪些任务有固定风格、格式或流程？
- 哪些任务依赖多个文档、模板、案例？
- 哪些任务交给新人时需要反复培训？

符合这些条件的任务，都适合被封装成 Bundle。

---

###### 2. 把任务拆成四层

每个 Bundle 可以拆为：

| 层级 | 问题 | 示例 |
|---|---|---|
| 任务目标 | 我要完成什么？ | 写 X 长文、做竞品分析、生成 PRD |
| 所需技能 | 需要哪些能力？ | 写作、研究、代码审查、数据分析 |
| 过程规则 | 必须怎么做？ | 先提问、先测试、先列假设 |
| 输出标准 | 最终交付什么？ | Markdown、表格、邮件、代码、计划 |

---

###### 3. 每个 Bundle 应该包含这些要素

```yaml
name: 命令名称

instruction: |
```

###### 5. 一个实用 Bundle 模板

```yaml
name: prd-draft
description: 从用户问题和业务目标出发生成产品需求文档。
skills:
  - user-research-synthesis
  - product-requirement-writing
  - prioritization-framework
instruction: |
  先询问 2-3 个澄清问题。
  明确用户、场景、问题、目标指标。
  输出结构包括：背景、用户问题、目标、非目标、核心功能、用户流程、边界情况、指标、风险。
  如果信息不足，标记为“待验证假设”。
  不要直接跳到解决方案，先分析问题。
```

调用方式：

```bash
/prd-draft 为一个 AI 客服质检系统写 PRD，目标是帮助客服主管发现低质量对话
```

##### 四、反方与张力

###### 1. 不是所有任务都适合 Bundle 化

Skill Bundle 适合高频、相对稳定、有流程的任务。

但不适合：

- 极度开放的探索
- 一次性的复杂问题
- 高度依赖实时判断的任务
- 需要大量跨系统权限的任务
- 还没有形成稳定方法论的任务

如果过早封装，可能会把错误流程固化下来。

---

###### 2. Bundle 会降低设置成本，但不会自动提高判断力

文章强调「Agent isn't smarter. The agent is pre-loaded.」

这点很重要。

Skill Bundle 解决的是上下文加载和流程复用问题，不等于 Agent 具备真正更强的推理能力。

如果底层技能、数据、模型能力不足，Bundle 只是让错误更快发生。

---

###### 3. 个人风格可复制，但商业优势不一定可复制

作者说可以用一个 12 行 YAML 复制多年流程经验。

这个说法有启发，但也有夸张成分。

因为真正的经验不只在流程里，还包括：

- 判断力
- 取舍能力
- 语境理解
- 对质量的敏感度
- 失败经验
- 数据反馈
- 人际关系和组织约束

Bundle 可以复制流程，但未必能复制品味和决策质量。

---

###### 4. SaaS 不会简单死亡，而是价值重构

文章说 Bundle 会替代一部分 SaaS 订阅，这有一定道理。

但 SaaS 仍然有价值，尤其是：

- 数据存储
- 权限管理
- 协作流程
- 审计日志
- 合规
- 支付
- 可视化
- 系统集成
- 企业级稳定性

更准确的判断是：

> 轻量工作流 SaaS 会被压缩，深数据/强协作/强合规 SaaS 仍然有护城河。

---

###### 5. YAML 对普通用户仍有门槛

对开发者来说，12 行 YAML 很简单。

但对普通用户来说，配置文件仍然不是自然入口。

因此真正的大规模普及，可能需要：

- 可视化 Bundle Builder
- 自动从聊天记录生成 Bundle
- 一键分享和安装
- 团队模板市场
- 版本管理和权限控制
- 质量评分系统

也就是说，底层可以是 YAML，但用户体验不能停留在 YAML。

##### 五、情境化落地

###### 情境 1：个人创作者

如果你是内容创作者，可以建立自己的内容生产 Bundle。

例如：

```yaml
name: creator-post
description: 个人社交媒体长文创作工作流。
skills:
  - writing-style
  - hook-generation
  - story-extraction
  - audience-positioning
instruction: |
  先询问主题、目标读者、发布平台。
  生成 5 个开头钩子。
  每个钩子标注使用的传播机制。
  正文使用我的个人语气。
  结尾给出一个明确行动号召。
```

可封装的内容资产：

- 个人语气文档
- 爆款结构
- 过往文章
- 案例库
- 禁用表达
- 目标读者画像

---

###### 情境 2：AI 产品团队

如果你在做 AI 产品，可以重点思考：

> 用户是不是每次使用你的产品都在重新设置上下文？

如果是，你的产品应该提供：

- 用户可保存的工作流
- 可组合的技能模块
- 可共享的团队模板
- 自动从历史任务中提取流程
- 一键调用的命令入口

这可能比单纯做一个更好看的聊天界面更有价值。

---

###### 情境 3：企业内部知识管理

企业知识库常见问题是：

> 文档很多，但员工不会用。

Skill Bundle 的思路可以把知识库变成可执行命令。

例如：

```bash
/customer-complaint-handle
/security-incident-response
/legal-contract-review
/new-employee-onboarding
```

每个命令都绑定：

- 对应政策
- 标准流程
- 输出模板
- 审批规则
- 风险提示
- 相关负责人

这会把知识管理从「搜索文档」升级为「调用流程」。

---

###### 情境 4：垂直 SaaS 创业者

如果你正在做 AI SaaS，需要判断自己产品的哪一层是护城河。

可以问：

1. 我的产品只是固定 prompt + UI 吗？
2. 用户能否用一个 Bundle 替代我的核心流程？
3. 我的数据是否有不可替代性？
4. 我的协作、权限、合规是否足够强？
5. 我是否应该提供用户自定义 workflow 的能力？
6. 我能否把自己从 SaaS 变成 Bundle/Agent 的基础设施？

如果你的价值主要是「模板化流程」，就要警惕被 Agent Bundle 化。

---

###### 情境 5：团队效率系统

一个团队可以建立自己的 Bundle Library。

例如：

```bash
/product-prd
/design-review
/engineering-review
/customer-feedback-summary
/weekly-business-review
/launch-plan
```

每个 Bundle 都是团队经过验证的工作方式。

团队成员不再靠口头传承，而是直接调用标准流程。

这会带来三个结果：

1. 新人更快上手；
2. 老人少做重复解释；
3. 团队方法论可以版本化迭代。

---

##### 六、总结

这篇文章最有价值的观点不是「Hermes Agent 很厉害」，而是指出了一个更大的趋势：

> AI 的下一阶段竞争，不只是模型能力竞争，而是工作流封装能力竞争。

Skill Bundle 的本质是：

- 把上下文保存下来；
- 把个人偏好保存下来；
- 把工作流程保存下来；
- 把团队 SOP 变成可执行命令；
- 把一次性 prompt 变成可复用资产。

对于个人，它是效率杠杆。  
对于团队，它是流程标准化工具。  
对于 SaaS，它是潜在的解构力量。  
对于 AI 产品，它是一种新的产品原语。

最值得带走的一句话是：

> 每个你做过两次以上的高频任务，都值得被封装成一个可调用的工作流。
