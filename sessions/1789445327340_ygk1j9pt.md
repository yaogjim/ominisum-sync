## 正文

Vercel Labs creates tools and experiments for developers.We release projects early,learn from how people use them,and keep investing in the ones that prove useful.

#### Classifications

Each project is classified by its current stage, so you know what’s actively maintained, what’s still taking shape, and what’s no longer in development.

- Labs products Projects that have proven useful over time. Maintained, built to be relied on, and distinct from Vercel’s core products.
- Active experiments Projects we are building and learning from right now. Expect fast iteration, rough edges, and breaking changes.
- Past experiments Projects no longer in development. Some became products, some folded into existing ones, and some showed us what to build next.

## 深度解读（1）

### 2026-09-15 04:11:11

#### 核心判断

**这页最值得关注的，不是 Vercel 发布了哪些具体工具，而是它的项目组合共同指向一个变化：AI 开发工具的瓶颈正在从 “模型能不能写代码”，转向 “能不能让不确定的 Agent 安全、稳定、可控地操作真实环境”。**

这不是文章明说的结论，而是从项目分布推断出的方向：浏览器操作、Shell、代码执行、API 模拟、安全测试、工具发现、结构化 UI，几乎都在补 Agent 从 “给答案” 走向 “执行任务” 时缺失的基础设施。相比再做一个聊天界面或通用 Agent，这个控制层更可能形成长期需求。

不过，这个页面本质上是产品目录，不是市场研究。它没有用户量、留存、收入或失败数据。“proven useful” 只是 Vercel 的分类口径，不能直接视为 PMF 证据。

##### 1. Agent 的核心竞争正在下沉到 “执行边界”

页面中最密集的一组项目都围绕执行环境：

- `agent-browser`：让 Agent 操作浏览器
- `just-bash`：让 Agent 使用 Bash
- `run`：Agent 的安全代码执行
- `deepsec`：由编码 Agent 运行的安全测试工具
- `emulate`：在 CI 和沙箱中模拟外部 API
- `opensrc`：让 Agent 获取 npm 包源码
- `CallScript`：让模型以代码方式调用能力
- `skills`：组织和分发 Agent 可使用的技能

这些并不是在提升模型 “智力”，而是在解决四个更现实的问题：

1. Agent 能访问什么；
2. 操作是否隔离、可限制；
3. 外部环境是否可复现；
4. 失败之后能否定位和恢复。

原因是模型能力提升并不会自动消除执行风险。即便模型更聪明，删除文件、泄露凭据、误调用生产 API、被网页内容提示注入等问题依然存在；某些情况下，能力越强，错误执行的破坏力反而越大。

###### 对你有什么用

如果你正在做 AI 工具或开发者产品，优先寻找的可能不是 “用户还缺什么 Agent”，而是：

> 用户已经让 Agent 做了哪些真实操作，但目前不敢把权限完全交出去？

这比询问 “你想要什么 AI 功能” 更容易发现刚性需求。

一个低成本验证方式是：选取 10～20 次真实 Agent 任务，记录失败原因，而不是只看任务完成率。将失败归入：

- 权限或凭据问题
- 环境不一致
- 工具选择错误
- 浏览器状态错误
- 外部 API 不稳定
- 无法审计或复现
- 执行成本失控

如果失败集中在某一类，才值得做专门工具。

**会让我改变判断的证据**：如果这些项目长期只有开发者试用，没有进入持续 CI、内部自动化或生产流程，那么它们可能只是 Vercel 围绕 AI 热点做的开发者营销，而不是新的基础设施层。

---

##### 2. 更耐久的机会是权限、策略和审计，而不是再造一个通用 Agent 循环

“Past experiments” 比新品列表更有判断价值：

- `ralph-loop-agent`：长时运行循环已由现代 harness 处理
- `autoship`：发布工作流直接由编码 Agent 处理
- `next-skills`：并入 Next.js
- `vercel-open`：核心能力并入 Vercel CLI

这反映出一个规律：**通用循环、提示模板、框架适配和薄包装很容易被更上层的 Agent 或既有平台吸收。**它们可能有使用量，却不一定拥有长期独立的产品边界。

相对而言，以下能力更难被一句 “模型进步了” 所替代：

- 跨工具统一授权
- 凭据隔离与最小权限
- 操作审批和风险分级
- 完整执行轨迹
- 可重放、可回滚
- 成本与资源限制
- 面向合规的证据输出

###### 一个值得验证的产品方向

适用对象是已经在使用编码或浏览器 Agent 的团队，尤其是拥有生产系统、客户数据或合规要求的公司。

可以验证的需求不是泛泛的 “Agent 安全”，而是：

> 为浏览器、Shell、代码执行和 API 调用提供统一的策略、审批、记录与重放层。

现有替代方案通常是各工具自带沙箱、CI 权限设置、云 IAM 和人工审批。问题在于它们相互割裂，团队难以回答：“这个 Agent 为什么获得权限、具体做了什么、产生了哪些副作用？”

但页面只能证明 Vercel 在分别建设执行工具，**不能证明统一控制层一定有人付费**。验证时应寻找强信号：

- 团队是否因风险而禁止或限制 Agent；
- 是否已经投入人力自建审计和权限方案；
- 是否出现过实际事故或近失误；
- 是否愿意把生产任务接入一个最小原型，而不只是表达兴趣。

最低成本的原型可以只是：为一个浏览器工具和一个 Shell 工具加统一策略文件、操作日志与高风险动作审批，不必先造完整平台。

---

##### 3. Vercel Labs 真正可迁移的方法，是把 “独立产品” 当成实验结果，而不是实验前提

页面明确区分：

- 已被证明有用、继续维护的 Labs products
- 仍在迭代、允许破坏性变化的 Active experiments
- 已停止、并入其他产品或被替代的 Past experiments

这里有价值的不是 “公开发布” 本身，而是它接受多种成功结果：

1. 成为独立产品；
2. 并入核心产品；
3. 被更通用的能力取代；
4. 仅帮助团队发现下一步该做什么。

这可以避免一个常见错误：项目一旦公开，就为了维护叙事而长期续命。特别是在 Agent 工具变化很快的阶段，“被平台吸收” 往往不是失败，而是说明能力已经成为标准组件。

###### 对你有什么用

如果你在做产品实验，可以在开发前就写清楚三种退出条件：

- **继续独立**：存在重复使用，且用户单独认知、单独配置这项能力；
- **并入主产品**：它能提升主流程，但没有独立购买或选择价值；
- **停止**：模型或现有框架已经低成本覆盖它，继续维护不再划算。

例如，一个 Agent 技能管理 CLI 可能短期受欢迎，但如果主流框架原生支持相同格式，它就很容易被吸收。相反，包含企业策略、审计记录和组织权限的服务更可能保持独立边界。

需要注意，Vercel 有品牌、开发者分发渠道和云平台作为承接方，普通团队不能机械照搬 “开源实验 — 观察采用 — 产品化” 模式。没有既有流量时，公开发布不等于有效需求验证；真正应关注的是重复使用、工作流嵌入程度和付费替代成本，而不是 GitHub 星数。

##### 页面没有提供、但决定结论的关键信息

在把这些信号当作趋势之前，还缺少：

- 各项目的实际活跃用户和留存；
- 哪些由 Vercel 内部团队真实使用；
- 从实验晋升为产品的具体标准；
- 项目是否带来云资源消费或其他商业收益；
- “Past experiments” 是因需求不足，还是因被平台吸收；
- 安全执行工具是否真的减少事故，而不只是增加隔离层。

因此，最稳妥的解读不是 “这些方向已经被市场验证”，而是：

> Vercel 正在用一组公开实验测试 Agent 执行基础设施的产品边界，其中安全、环境与工具接口被反复下注。

##### 如果只保留一个认识

**不要把主要赌注押在 “更聪明的 Agent 外壳” 上；更值得关注的是让 Agent 获得真实权限之后，如何限制、观察、复现和追责它的行为。**这是模型能力提升不会自动消失、反而可能随 Agent 使用扩大而变得更重要的问题。

## 通俗精炼（1）

### 2026-09-18 10:35:25

#### Vercel Labs：以公开实验筛选开发者与 AI 工具

Vercel Labs 是 Vercel 面向开发者的公开实验平台：项目会被提前发布，通过真实使用反馈快速迭代；被长期验证有价值的工具将持续投入，其他项目则可能并入现有产品或停止开发。其核心不是展示概念，而是建立一套“实验—验证—产品化”的筛选机制。

##### 三类状态明确项目成熟度

- **Labs 产品**：已证明长期有用、持续维护，可被开发者依赖，但独立于 Vercel 核心产品。
- **活跃实验**：仍在开发和验证，迭代快，可能存在缺陷或破坏性变更，不宜默认用于稳定生产环境。
- **历史实验**：不再开发；部分已产品化或并入其他工具，部分则为后续方向提供了经验。

这种分类同时向用户传递维护承诺和采用风险，避免“实验项目”被误解为成熟产品。

##### 项目重点转向 AI Agent 的开发基础设施

已形成产品的项目多围绕智能体能力，包括浏览器自动化 CLI `agent-browser`、安全测试工具 `deepsec`、面向 Agent 的 Bash 环境 `just-bash`、生成式 UI 框架 `json-render`，以及开放技能生态 CLI `skills`。其他工具覆盖本地开发、编码 Agent 和跨运行时 WebGPU。

活跃实验继续探索 Agent 编程语言、安全代码执行、API 模拟、原生桌面应用、Web 终端和 UI 性能等方向。历史项目则显示其退出机制：例如部分能力已被 Vercel CLI 或 Next.js 接管，说明 Labs 也承担核心产品的前置研发与能力孵化。
