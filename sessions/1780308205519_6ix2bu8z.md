**agent multiplexer that lives in your terminal.**

workspaces, tabs, panes. mouse-native: click, drag, split. every agent at a glance: blocked, working, done. detach and reattach, agents keep running. no gui app, no electron, no mac-only native wrapper. you see the agent's own terminal, not someone's interpretation of it.

#### install

```
curl -fsSL https://herdr.dev/install.sh | sh
```

or install with homebrew:

```
brew install herdr
```

or download the binary from [releases](https://github.com/ogulcancelik/herdr/releases). requires linux or macos.

#### quick start

Start Herdr in the directory where the work lives:

```
herdr
```

Herdr starts or attaches to one background session server. Press `ctrl+b`, then `shift+n` to create a workspace. Run an agent in the root pane. Press `ctrl+b`, then `v` or `minus` to split panes, `ctrl+b`, then `c` to create a tab, and `ctrl+b`, then `w` to switch workspaces.

Press `ctrl+b q` to detach the client. The server and pane processes keep running. Open another terminal and run `herdr` again to reattach.

#### core concepts

**Server and client.** By default, `herdr` attaches to a background server. Detaching closes only the client. `herdr server stop` stops the default server and kills its panes. Named sessions are separate server namespaces: use `herdr session attach work`, `herdr session stop work`, and `herdr session list` when you want fully separate runtime state.

**Workspaces, tabs, panes.** A workspace is the project-level container. Tabs group panes inside a workspace. Panes are real terminal processes, not rewritten agent views.

**Copy.** Herdr copies pane text, not the sidebar. Drag-select inside a pane, double-click a word or token, or press `prefix+[` for keyboard copy mode. In copy mode, move with `h/j/k/l`, `w/b/e`, and `{` / `}`, start selection with `v` or Space, copy with `y` or Enter, and leave with `q` or Esc. In PuTTY and some SSH terminals, hold `Shift` while dragging to use the terminal's own selection, and `Shift` + right click to paste.

**Update and restore.**`herdr update` installs a new binary, but a running server keeps using the old process until it is stopped or handed off. Stop the old server to use the new version. Stopping exits pane processes. Run `herdr server stop`, then run `herdr` again for the default session. For a named session, run `herdr session stop <name>`, then run `herdr session attach <name>` again. `herdr update --handoff` is experimental and tries to move live panes, including foreground processes such as dev servers, from the old server to the new one. If `[session] resume_agents_on_restore = true` is enabled and current official integrations are installed, supported agent panes can restart from their native agent sessions after a server restart or update.

**Keybindings.** Herdr uses explicit keybinding strings. `prefix+n` means press the configured prefix, then `n`. `ctrl+alt+n`, `cmd+k`, `alt+1`, and function-key chords are direct terminal-mode shortcuts and do not need the prefix. Plain direct printable keys such as `n` steal normal typing, so use `prefix+n` unless you intentionally want a modifier-gated direct binding.

**Agent awareness.** The sidebar shows blocked, working, done, and idle states. Detection works with process names and terminal output by default. Official integrations make state reporting and native agent session restore more reliable, but Herdr still works as a terminal multiplexer without them.

#### update

herdr update

`herdr update` is for installs managed by Herdr's own installer. tmux gives you persistence and panes, but it was built before agents existed. gui managers show agent state, but they make you leave your terminal and use their wrapped view. herdr is persistence and awareness in one tool that stays out of your way.

Herdr works over normal SSH. Run it on the remote host, detach, and reattach later:

```
ssh you@yourserver
herdr
```

You can also attach from your local terminal without opening a shell first:

```
herdr --remote workbox
herdr --remote ssh://you@yourserver:2222
```

Direct attach connects your current terminal to one server-owned terminal:

```
herdr agent attach <target>
herdr terminal attach <terminal_id>
```

See [persistence and remote docs](https://herdr.dev/docs/persistence-remote/) for remote keybinding, named-session, and handoff details.

#### agent awareness

the sidebar shows which agents are blocked, working, or done. workspaces roll up to their most urgent state so you can scan the full list at a glance.

states:

- 🔴 **blocked** — agent needs input or approval
- 🟡 **working** — agent is actively running
- 🔵 **done** — work finished, you have not looked at it yet
- 🟢 **idle** — done and seen

detection works by reading foreground process and terminal output. zero config, no hooks required. for agents that expose hooks, the socket api integration gives more robust state reporting.

not a gui window, not a web dashboard, not electron. herdr runs inside whatever terminal you already use. single rust binary, no dependencies. works inside tmux.

- **workspaces** — organized around git repos or folder names, each with its own tabs and panes
- **tabs** — first-class in the socket api and cli
- **copy-friendly** — drag-select pane text, double-click tokens, or use keyboard copy mode with `prefix+[`, `h/j/k/l`, `{` / `}`, `v`, and `y`
- **notifications** — sounds and toasts for background events; tab-aware suppression
- **18 built-in themes** — catppuccin, terminal, tokyo night, gruvbox, one, solarized, kanagawa, rosé pine, vesper, and light variants for the main palettes
- **session persistence** — pane processes survive client detach; sessions restore panes after full restart, with opt-in recent screen history

The local Unix socket lets agents create workspaces, split panes, spawn helpers, read output, and wait for state changes. Start with the [socket API docs](https://herdr.dev/docs/socket-api/) and `SKILL.md`.

##### 一、总结

**Herdr** 是一个运行在终端里的“AI Agent 多路复用器”。

简单说：  
它像 **tmux + AI Agent 状态看板**，可以在一个终端里同时管理多个 AI 编程助手、多个项目、多个窗口，并显示它们是：

- 🔴 等你输入 / 授权
- 🟡 正在工作
- 🔵 已完成但你还没看
- 🟢 空闲

它支持：

- 终端内运行，不是 GUI / Electron
- 工作区、标签页、分屏
- 断开后后台继续运行，再次连接可恢复
- 支持 SSH 远程使用
- 支持 Claude Code、Codex、OpenCode、GitHub Copilot CLI、Kimi Code CLI 等多种 Agent
- 鼠标操作、复制、主题、通知
- Socket API，方便 Agent 主动创建窗口、读输出、汇报状态

##### 二、深入浅出解读

###### 1. 它解决什么问题？

现在很多人会同时跑多个 AI 编程 Agent：

- 一个修 bug
- 一个写测试
- 一个重构代码
- 一个跑命令
- 一个等你批准操作

问题是：  
**终端一多，就乱；Agent 一多，就不知道谁卡住了。**

Herdr 的目标就是：

> 让你在一个终端里管理一群 AI Agent，并一眼看出谁在干活、谁卡住、谁完成了。

---

###### 2. 它和 tmux 有什么区别？

tmux 主要解决：

- 分屏
- 会话保持
- 断开重连

但 tmux 不知道 AI Agent 在干嘛。

Herdr 在此基础上加了：

- Agent 状态识别
- 工作区级别管理
- AI 工具集成
- 更友好的鼠标操作
- 状态侧边栏

可以理解为：

> tmux 是“终端窗口管理器”，Herdr 是“面向 AI Agent 的终端工作台”。

很多 GUI 工具会把 Agent 包在自己的界面里。

Herdr 不这么做。  
它让你看到的仍然是：

> Agent 原本的真实终端输出。

优点是：

- 不改变原有工作流
- 适合命令行重度用户
- 能在 SSH 远程机器上用
- 更轻量，不依赖 Electron

## 结构化（1）

#### Herdr 项目精炼总结

Herdr 是一个运行在终端里的“智能代理多路复用器”，可以像 tmux 一样管理会话、工作区、标签页和分屏，同时还能识别 AI Agent 的状态。它的核心特点是：不需要 GUI、不用 Electron、不离开终端，就能同时管理多个 Agent 并保持任务持续运行。

---

##### 1. 项目定位：终端里的 Agent 管理器

Herdr 主要解决在终端中同时运行多个 AI Agent 时难以管理的问题。

- 支持 **workspaces（工作区）/ tabs（标签页）/ panes（分屏）**。
- 支持鼠标操作：点击、拖拽、分屏。
- 可以在侧边栏看到每个 Agent 的状态：
  - 🔴 blocked：需要输入或批准
  - 🟡 working：正在工作
  - 🔵 done：已完成但还没查看
  - 🟢 idle：已完成且已查看
- 支持 **detach / reattach**：关闭客户端后，后台 Agent 仍继续运行。
- 不提供 GUI 窗口或网页面板，而是直接运行在你已有的终端中。
- 你看到的是 Agent 自己的真实终端输出，而不是二次包装后的视图。

---

##### 2. 安装方式与运行环境

Herdr 支持 Linux 和 macOS，提供多种安装方式。

常用安装命令：

```bash
curl -fsSL https://herdr.dev/install.sh | sh
```

也可以通过 Homebrew 安装：

```bash
brew install herdr
```

还可以从 GitHub Releases 下载二进制文件。

---

##### 3. 快速开始：创建工作区、分屏和后台会话

在项目目录中启动 Herdr：

```bash
herdr
```

启动后，Herdr 会连接到一个后台 session server。

常用操作包括：

| 操作 | 快捷键 |
|---|---|
| 新建工作区 | `ctrl+b` 后按 `shift+n` |
| 垂直分屏 | `ctrl+b` 后按 `v` |
| 水平分屏 | `ctrl+b` 后按 `-` |
| 新建标签页 | `ctrl+b` 后按 `c` |
| 切换工作区 | `ctrl+b` 后按 `w` |
| 分离客户端 | `ctrl+b` 后按 `q` |

分离后，后台服务和 pane 中的进程会继续运行。重新打开终端后再次执行：

```bash
herdr
```

即可重新连接。

---

##### 4. 核心概念：Server、Client、工作区、标签页和分屏

Herdr 采用 server/client 模式。

- **Client**：你当前看到的终端界面。
- **Server**：后台持续运行的服务，负责保存会话和进程。
- 关闭 client 不会停止 server。
- 执行以下命令会停止默认 server，并结束其中的 pane 进程：

```bash
herdr server stop
```

Herdr 还支持命名 session，用于隔离不同项目或运行状态：

```bash
herdr session attach work
herdr session stop work
herdr session list
```

结构上：

- **Workspace**：通常对应一个项目或仓库。
- **Tab**：工作区内的标签页。
- **Pane**：真实的终端进程，不是模拟或重写的 Agent 视图。

---

##### 5. 复制与终端交互

Herdr 支持直接复制 pane 中的文字，而不是复制侧边栏内容。

可用方式包括：

- 鼠标拖拽选择 pane 文本。
- 双击选择单词或 token。
- 使用键盘复制模式：

```text
prefix + [
```

复制模式中的常用按键：

| 操作 | 按键 |
|---|---|
| 移动 | `h/j/k/l` |
| 按词移动 | `w/b/e` |
| 按段落移动 | `{ / }` |
| 开始选择 | `v` 或 `Space` |
| 复制 | `y` 或 `Enter` |
| 退出 | `q` 或 `Esc` |

在 PuTTY 或部分 SSH 终端中，可以按住 `Shift` 拖拽使用终端自带选择功能。

---

##### 6. 更新、恢复与会话迁移

Herdr 会提示新版本，手动更新命令为：

```bash
herdr update
```

注意：

- `herdr update` 适用于 Herdr 自带安装器安装的版本。
- Homebrew 安装的版本应使用：

```bash
brew upgrade herdr
```

- Nix 安装则通过对应 Nix 流程更新。

如果后台 server 仍在运行，即使二进制文件已更新，旧 server 仍使用旧版本。需要停止后重新启动：

```bash
herdr server stop
herdr
```

命名 session 则使用：

```bash
herdr session stop <name>
herdr session attach <name>
```

Herdr 还提供实验性功能：

```bash
herdr update --handoff
```

它会尝试将正在运行的 pane，包括前台进程如开发服务器，从旧 server 迁移到新 server。

如果启用：

```toml
[session]
resume_agents_on_restore = true
```

并安装官方集成，部分 Agent 可以在 server 重启或更新后从原生 Agent session 中恢复。

##### 7. 与 tmux 和 GUI Agent 管理器的区别

Herdr 的定位介于 tmux 和 GUI Agent 管理器之间。

| 能力 | tmux | GUI 管理器 | Herdr |
|---|---|---|---|
| 持久会话 | ✓ | — | ✓ |
| detach / reattach | ✓ | — | ✓ |
| panes / tabs / workspaces | ✓ | ✓ | ✓ |
| Agent 状态感知 | — | ✓ | ✓ |
| 运行在终端中 | ✓ | — | ✓ |
| 真实终端视图 | ✓ | — | ✓ |
| 鼠标原生支持 | — | ✓ | ✓ |
| 轻量二进制 | ✓ | — | ✓ |

简单来说：

- tmux 有持久会话和分屏，但不是为 AI Agent 设计的。
- GUI 管理器能显示 Agent 状态，但需要离开终端。
- Herdr 结合了持久会话、分屏管理和 Agent 状态识别，并保持在终端内运行。

##### 8. 远程使用：支持 SSH 场景

Herdr 可以在远程服务器上运行。

常见方式：

```bash
ssh you@yourserver
herdr
```

也可以直接从本地终端连接远程 Herdr：

```bash
herdr --remote workbox
herdr --remote ssh://you@yourserver:2222
```

还支持直接连接某个 Agent 或终端：

```bash
herdr agent attach <target>
herdr terminal attach <terminal_id>
```

这适合在远程机器上长期运行 Agent、开发服务器或自动化任务。

##### 9. Agent 状态感知机制

Herdr 通过前台进程名和终端输出判断 Agent 状态，默认零配置即可工作。

状态包括：

- 🔴 blocked：Agent 需要用户输入或审批。
- 🟡 working：Agent 正在执行任务。
- 🔵 done：任务完成，但用户尚未查看。
- 🟢 idle：已查看，处于空闲状态。

对于支持 hooks 的 Agent，可以通过 Herdr 的 socket API 提供更可靠的状态汇报。

##### 12. 默认快捷键

Herdr 默认使用 `ctrl+b` 作为 prefix，整体风格类似 tmux。

| 快捷键 | 功能 |
|---|---|
| `prefix+c` | 新建标签页 |
| `prefix+n / prefix+p` | 下一个 / 上一个标签页 |
| `prefix+1..9` | 切换到指定标签页 |
| `prefix+w` | 工作区导航 |
| `prefix+g` | session 导航器 |
| `prefix+shift+n` | 新建工作区 |
| `prefix+shift+g` | 新建 worktree |
| `prefix+shift+w` | 重命名工作区 |
| `prefix+shift+d` | 关闭工作区 |
| `prefix+h/j/k/l` | 切换 pane 焦点 |
| `prefix+v / prefix+-` | 分屏 |
| `prefix+x` | 关闭 pane |
| `prefix+b` | 显示 / 隐藏侧边栏 |
| `prefix+z` | 放大 pane |
| `prefix+r` | 调整大小模式 |
| `prefix+q` | detach |

鼠标操作也在整个界面中受支持。
