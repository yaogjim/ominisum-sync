**关木**

现在使用 vibe coding 的流程

1\. 脑暴，先扩大自己的思想微光  
2\. 收敛，确定到底要做什么  
3.目标设定，探讨怎么评价这个任务是否完成，可以是分数也可以是具体评测集  
4\. 做设计，包括架构设计，技术设计，视觉设计，交互设计  
5\. 制定 plan 计划，如何推进目标完成  
6./goal 朝着目标和计划开始实施

Coding 的时候保证主控 Agent 只抓重点，不应该消耗主控 Agent 的注意力，探索性的，调研类的，测试类的都让 Subagent 来做。

#### 关木：Vibe Coding 流程总结与解读

##### 一、深度总结

这条内容讲的是：**用 AI 编程不能一上来就写代码，而要像“产品经理 + 架构师 + 项目经理 + 技术负责人”一样，先把方向、目标、设计和执行路径理清楚。**

核心流程是：

1. **脑暴**  
   先发散想法，不急着定方案，扩大可能性。

2. **收敛**  
   从众多想法中选出真正要做的东西，明确边界。

3. **设定目标与评价标准**  
   不只是说“做完”，而是要定义：  
   - 什么叫完成？
   - 如何打分？
   - 有没有测试集、验收标准或指标？

4. **做设计**  
   包括：
   - 架构设计
   - 技术设计
   - 视觉设计
   - 交互设计

5. **制定计划**  
   把目标拆成步骤，明确推进路径。

6. **执行 Coding**  
   真正写代码时，主控 Agent 不要被琐事消耗。  
   探索、调研、测试等任务交给 Subagent，主 Agent 只负责关键决策和方向控制。

一句话总结：

> Vibe Coding 的关键不是“让 AI 写代码”，而是“让 AI 在清晰目标和合理分工下协作完成项目”。

---

##### 二、深入浅出解读

很多人理解的 Vibe Coding 是：

> 我有个想法，直接告诉 AI：帮我写一个 App。

但这种方式很容易失败，因为 AI 会：

- 理解偏差
- 写着写着跑题
- 代码堆起来但不可维护
- 功能看似完成，实际不可用
- 改一个地方坏三个地方

关木这套流程，本质是在说：

> 不要把 AI 当许愿机，要把 AI 当团队成员。

如果把一次 AI 编程比作盖房子：

| 阶段 | 对应含义 |
|---|---|
| 脑暴 | 想盖什么房子 |
| 收敛 | 确定盖别墅、公寓还是小屋 |
| 目标设定 | 什么标准算交付：能住？抗震？预算？面积？ |
| 设计 | 出图纸、定结构、定风格 |
| 计划 | 先打地基，再建主体，再装修 |
| Coding | 开始施工，并让不同工人分工 |

最重要的一点是第 6 步：

> 主控 Agent 要抓重点，Subagent 处理杂活。

这其实是 AI 时代的新型开发管理方式：

- 主 Agent：像项目负责人，管目标、架构、决策
- Subagent：像实习生或专员，负责调研、测试、修 bug、查资料

这样可以避免主 Agent 的上下文被污染，也避免它在细节里迷失方向。

---

##### 三、关键价值

这套流程的价值在于：

###### 1. 把“随手生成”变成“工程化生产”

AI 编程不是简单 prompt，而是完整工作流。

###### 2. 降低返工

前期目标和设计越清楚，后期越少反复推倒重来。

###### 3. 提高 AI 输出质量

AI 最怕模糊任务。  
目标、约束、验收标准越明确，结果越靠谱。

###### 4. 适合复杂项目

小脚本可以直接写，但复杂产品必须有：

- 架构
- 设计
- 计划
- 测试
- 评估

否则很快失控。

---

##### 四、辩证思考

###### 1. Vibe Coding 不是不要规划，而是更需要规划

很多人误以为 Vibe Coding 是“凭感觉写代码”。  
但真正有效的 Vibe Coding 恰恰相反：

> 越想用 AI 快速开发，越要先把问题定义清楚。

AI 提高的是执行速度，不会自动替你解决方向混乱的问题。

---

###### 2. AI 能放大能力，也会放大混乱

如果人有清晰判断，AI 会极大提升效率。  
如果人没有目标、没有审美、没有技术判断，AI 只会快速制造一堆“看似能跑的垃圾代码”。

所以，未来开发者的核心能力会变化：

从：

> 我会不会写代码

变成：

> 我会不会定义问题、设计系统、拆解任务、评估结果

---

###### 3. Subagent 分工很重要，但不能迷信自动化

多 Agent 协作听起来很美，但也有风险：

- 子任务之间可能不一致
- 调研结果可能错误
- 测试可能覆盖不足
- 主 Agent 可能误判 Subagent 输出

所以人仍然要做最终把关：

> AI 可以执行，不能完全代替责任。

---

###### 4. “评价标准”可能是最容易被忽略、但最重要的一步

很多项目失败，不是因为代码写不出来，而是因为没人说清楚：

> 到底什么叫做好？

没有验收标准，AI 就只能猜。  
有了标准，AI 才能迭代优化。

---

##### 五、最终结论

关木这条内容真正表达的是：

> AI 编程的核心竞争力，不是 prompt 技巧，而是工程化流程。

最简版方法论：

```text
先发散 → 再收敛 → 定目标 → 做设计 → 拆计划 → 分工执行
```

最关键原则：

```text
人控方向，AI 执行；主 Agent 抓重点，Subagent 做杂活。
```

这不是“让 AI 替你编程”，而是：

> 用 AI 组织一个高效的小型虚拟开发团队。
