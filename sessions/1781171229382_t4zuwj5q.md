上次推荐的 Zara Zhang 的开源项目 feishu-claude-code-bridge ，可以把飞书和你本机的 Claude Code 连接起来，解决了用飞书保存所有消息历史，以及随时将飞书的信息转发给Claude的问题，相当使用的一个功能。

现在有个问题是再过几天到 6 月 15 日，Claude 订阅计划对 claude -p 和 Agent SDK 的使用将独立计费，不走订阅额度。

好在 Zara Zhang 这几天刚把项目升级了，也能支持飞书连接 Codex 了，只要你本机装了 codex cli，登录了 ChatGPT 账号或者配置了 API，就能使用，不用担心 claude -p 收费的问题了。另外还带来一个好处，就是 Codex 是有调用 GPT Image 2 画图能力的，所以你现在可以从飞书指挥 Codex 画图，画完的图片直接就到飞书，插入文档。

比如我的一个常用指令如下：  
&gt; 请帮我抓取并翻译 {url}  
&gt; 然后根据翻译的内容画一张中文手绘教育风信息图  
&gt; 最后把文章和图片一起创建一份飞书文档

连接步骤和之前介绍的连接 Claude Code 方法一致，只是运行的命令行变成了：

&gt; lark-channel-bridge run --profile codex

## 解读（1）

### 2026-06-11 09:46:04

#### 深度总结

这条内容的核心是：**用一个开源桥接工具，把飞书变成 Claude Code / Codex 的前端操作入口。**

项目原名偏向 `feishu-claude-code-bridge`，现在升级为支持更多编码 Agent 的 `lark-coding-agent-bridge`。它可以让用户：

- 在飞书里直接指挥本机的 Claude Code 或 Codex；
- 把飞书消息、文章、资料转发给 AI 处理；
- 让 AI 自动新建、编辑飞书文档；
- 使用 Codex 时，还能调用 GPT Image 2 生成图片；
- 最终实现：抓取网页 → 翻译 → 生成中文信息图 → 创建飞书文档，全流程自动化。

关键变化是：  
**Claude 从 6 月 15 日后，`claude -p` 和 Agent SDK 将独立计费，不再走订阅额度。**  
因此，作者推荐改用支持 Codex 的新版桥接方案，以降低对 Claude 计费变化的依赖。

运行方式变为：

```bash
lark-channel-bridge run --profile codex
```

---

#### 深入浅出解读

可以把这个工具理解成：

> **飞书 = 工作台**  
> **Codex / Claude Code = 本机 AI 助手**  
> **桥接工具 = 两者之间的遥控器**

以前你可能要这样工作：

1. 在浏览器打开文章；
2. 复制内容；
3. 粘贴到 AI；
4. 让 AI 翻译；
5. 再让 AI 生成图片；
6. 下载图片；
7. 打开飞书；
8. 手动创建文档、插图、排版。

现在可以变成一句飞书指令：

```text
请帮我抓取并翻译这个 URL，
根据内容画一张中文手绘教育风信息图，
最后把文章和图片一起创建一份飞书文档。
```

AI 就能在本机执行任务，并把结果回填到飞书。

它的价值不只是“能聊天”，而是把 AI 嵌入工作流：

- 飞书负责沉淀信息；
- AI 负责处理和生成；
- 本机环境负责执行能力；
- 文档系统负责交付结果。

---

#### 关键价值

##### 1. 降低操作成本

不用在多个工具之间来回复制粘贴，飞书直接成为 AI 工作入口。

##### 2. 保留上下文

飞书本来就是团队沟通和文档沉淀工具，消息、资料、讨论都在那里，AI 可以直接围绕这些上下文工作。

##### 3. 规避 Claude 计费变化

Claude 的部分命令行和 Agent SDK 能力即将单独计费，支持 Codex 后，用户多了一个替代选择。

##### 4. 扩展到图文生成

Codex 可调用 GPT Image 2，意味着它不只是写代码或处理文本，还能生成图片并插入飞书文档。

##### 5. 接近“个人自动化助理”

它不只是问答工具，而是能完成连续任务：读取、理解、翻译、制图、建文档。

---

#### 辩证思考

##### 好的一面

这个项目代表了一种趋势：  
**AI 不再只是聊天框，而是进入真实办公流程。**

它让飞书、Claude Code、Codex、本机环境连接起来，把 AI 从“回答问题”升级为“完成任务”。  
对于内容生产、资料整理、团队协作、知识管理来说，非常实用。

尤其是飞书这类协作工具，本来就承载了大量上下文。AI 如果能直接接入，就能显著提升信息处理效率。

---

##### 需要警惕的一面

但也不能只看到便利。

###### 1. 成本并没有消失，只是转移

从 Claude 切到 Codex，可能暂时避开某些计费变化，但 API、订阅、图像生成、本机算力、网络调用仍然可能产生新成本。

###### 2. 数据安全要重视

飞书里往往有公司文档、会议纪要、客户信息。  
一旦接入本机 Agent 和外部模型，需要明确：

- 哪些数据会被发送出去？
- 是否经过 API？
- 是否会被模型服务商记录？
- 团队权限如何控制？

###### 3. 自动化越强，错误传播越快

AI 可以自动翻译、总结、制图、建文档，但如果理解错了，也会把错误包装成“完整交付物”。  
效率提高的同时，审核责任不能省。

###### 4. 工具链依赖会增加

飞书、CLI、模型账号、API、桥接工具、本机环境，任何一环出问题，整个流程都可能中断。  
对普通用户来说，安装和维护仍有门槛。

---

#### 我的判断

这个项目的真正意义不是“飞书能连 Codex”这么简单，而是展示了一个方向：

> **未来的办公入口可能不是单独的 AI App，而是嵌入到飞书、Slack、Notion、GitHub 这类工作场景里的 AI Agent。**

短期看，它适合技术用户、内容团队、知识管理重度用户尝鲜。  
长期看，这类“工作流型 AI 桥接工具”会越来越重要。

但最理想的使用方式不是完全托管给 AI，而是：

> **让 AI 做苦活、杂活、重复活；  
> 让人负责判断、审校和决策。**

## 结构化（1）

##### 主旨概括

这篇内容介绍了 Zara Zhang 的开源项目 **lark-coding-agent-bridge** 的升级：它不仅能把飞书连接到本机的 Claude Code，现在也支持连接 **Codex**。这样用户可以继续在飞书里指挥 AI 完成抓取、翻译、写文档、画图等任务，并避免即将到来的 Claude 相关独立计费影响。

##### 1. 原项目功能：连接飞书与 Claude Code

- 之前推荐的开源项目 **feishu-claude-code-bridge**，可以把 **飞书** 和本机的 **Claude Code** 连接起来。
- 主要解决两个问题：
  - 飞书可以保存所有消息历史；
  - 可以随时把飞书里的信息转发给 Claude 处理。
- 用户可以直接在飞书中指挥 Claude Code，也可以让 Claude Code 新建或编辑飞书文档。

##### 2. 新问题：Claude 相关功能即将独立计费

- 从 **6 月 15 日** 起，Claude 订阅计划中：
  - `claude -p`
  - Agent SDK  
  的使用将开始 **独立计费**，不再消耗原有订阅额度。
- 这意味着继续依赖 Claude Code 的部分功能，可能会带来额外成本。

##### 3. 项目升级：现在支持飞书连接 Codex

- Zara Zhang 最近将项目升级，现在也支持通过飞书连接 **Codex**。
- 使用条件：
  - 本机安装了 **codex cli**；
  - 登录了 ChatGPT 账号，或配置了 API。
- 这样用户就可以用 Codex 替代部分 Claude Code 的工作，不必担心 `claude -p` 独立收费带来的影响。

##### 4. 新能力：可在飞书中指挥 Codex 画图

- 使用 Codex 还有一个额外好处：它可以调用 **GPT Image 2** 进行图片生成。
- 因此用户可以：
  - 在飞书中给 Codex 下达画图指令；
  - Codex 生成图片后，图片会直接返回到飞书；
  - 用户可以把图片插入飞书文档中。

##### 5. 示例工作流：抓取、翻译、画图、生成文档

作者给出了一个常用指令示例：

> 请帮我抓取并翻译 {url}  
> 然后根据翻译的内容画一张中文手绘教育风信息图  
> 最后把文章和图片一起创建一份飞书文档

这个例子体现了该工具可以完成一整套自动化流程：

- 抓取网页内容；
- 翻译文章；
- 根据内容生成中文手绘教育风信息图；
- 将文章和图片整合成飞书文档。

##### 6. 使用方式：命令行切换到 Codex 配置

- 连接步骤与之前连接 Claude Code 的方法基本一致。
- 区别在于运行命令改为：

```bash
lark-channel-bridge run --profile codex
```

- 项目说明文档提供了中英文版本，介绍较详细。
- 文档链接：  
  [https://github.com/zarazhangrui/lark-coding-agent-bridge/blob/main/README.zh.md](https://github.com/zarazhangrui/lark-coding-agent-bridge/blob/main/README.zh.md)

##### 7. 总结

这个项目的核心价值是把飞书变成一个 AI 工作入口：用户可以在飞书里保存上下文、发出指令，并让 Claude Code 或 Codex 完成文档、翻译、图片生成等任务。随着 Claude 部分功能即将独立计费，新增的 Codex 支持为用户提供了一个更灵活的替代方案。
