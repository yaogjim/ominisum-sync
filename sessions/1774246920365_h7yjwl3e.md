**Matt Stockton**

我认为这可能是一个演进。可以肯定的是，使用 Claude Agents SDK 或 DeepAgents SDK 构建智能体软件确实效果很好。

如果您能够将代理会话中的学习成果体现为对代理下次运行有用的上下文，那么显然会产生复利效应。

这里有很多方法可以处理这个问题，但我认为，在许多行业中，能够自动捕捉用户偏好核心要素的自更新软件肯定会出现。

实际上所有的构建模块都已存在，使得它（相关事物）已经可以实现了。我认为我们只是缺少一套“协调一致的方法/模式”，这些方法/模式已被确立并被软件团队一致采用。但我们可能很快就能实现这一点，老实说，这里有大量的机会来找出实现它的正确方法。

像 Claude Code / Deep Agents / Claude Agents SDK 这样的系统，只是一套乐高积木。有很多种组合方式。

## 解读（1）

### 2026-03-23 06:36:18

#### 一句话总结

Matt Stockton 的核心观点是：**AI 智能体软件的下一步，不只是“能帮你做事”，而是“能记住你、持续学习你、自动变得更懂你”**；一旦这种学习结果能沉淀成下次可用的上下文，软件就会出现明显的“复利效应”。

#### 深入浅出地解读

##### 1. 他到底在说什么？

他说的不是单纯的聊天机器人，而是一类更进一步的软件：

- 用 Claude Agents SDK、DeepAgents SDK 这类工具搭建智能体应用
- 智能体在一次次与用户互动中，逐渐学会用户偏好、工作方式、常见需求
- 这些“学到的东西”不会丢，而是会被自动保存，变成下次继续工作的基础
- 久而久之，软件会越来越贴合用户，甚至能自己更新、自己优化

通俗讲，就是：

> 未来的软件不再只是“你来使用它”，而是“它在使用过程中不断理解你”。

---

##### 2. 为什么这件事重要？

关键在于一个词：**复利**。

普通软件通常是这样的：

- 每次打开都差不多
- 你重复做设置、重复说明需求
- 软件本身不会因为你用了很多次就明显变聪明

但如果 AI 软件能积累上下文：

- 它知道你偏好的输出格式
- 知道你常做哪些操作
- 知道你在什么场景下要什么结果
- 甚至能自动调整流程、界面、功能组合

那它就会像一个越来越熟悉你的助手，而不是一个固定菜单工具。

这就是“复利效应”：
**每一次使用，都会提高下一次使用的效率和质量。**

---

##### 3. 为什么他说“技术其实已经差不多齐了”？

他的意思是：

- 模型有了
- 智能体框架有了
- 调用工具、执行任务、保存上下文这些能力也有了
- 甚至用户反馈回流产品的路径也有了

**缺的不是零件，而是“统一的做法”**。

也就是说，现在像一堆乐高积木都摆在桌上了，但行业还没有形成一套大家都认同的标准拼法，比如：

- 用户偏好该怎么存
- 哪些记忆该长期保留，哪些该丢弃
- 软件如何安全地自更新
- 用户修改的内容如何回流到主产品版本
- 如何避免“越学越乱”

所以他判断：**机会就在这里**。谁先把这套方法论跑通，谁就可能做出下一代软件形态。

---

##### 4. 引用推文在补充什么？

被引用的推文其实是在描述一个很有画面感的未来：

- 软件内置 Claude Code SDK
- 用户不是被动使用，而是直接“配置、修改、重塑”软件
- 用户做出的优秀改动，会被开发团队吸收回主版本
- 软件因此形成“用户共创 + AI 加速迭代”的循环

这有点像：

- 软件不再是封闭成品
- 而是一个可以被持续 remix（重组、改造）的系统
- 用户、AI、开发团队三方一起进化产品

---

##### 5. 热门回复为什么值得注意？

这些回复虽然角度不同，但都在强化同一个信号：**AI 正在从“回答问题”进入“自动试验、自动优化、自动工程化”的阶段。**

比如：

- 有人提到 AI 自动做了 70 多轮实验，把国际象棋引擎性能大幅拉高  
  → 说明 AI 已经不只是辅助写代码，而是在主动做优化搜索。
- 有人提到硬件和集群能力提升  
  → 说明本地或小规模高性能 AI 系统会更容易落地。
- 有人提到论文搜索、知识检索  
  → 说明“让 AI 借助外部知识持续变强”的基础设施正在成熟。
- 有人提到 remix app、可 remix 软件  
  → 说明“软件可修改、可继承、可持续更新”的产品形态已经开始出现。

这些都在说明：  
**不是某一个单点技术爆发，而是整条链路都在逐渐补齐。**

#### 我的意见

##### 我认同的部分

我基本赞同他的判断，尤其是这两点：

- **“上下文积累”会成为下一代 AI 软件的核心竞争力**
- **真正的门槛不只是模型能力，而是产品层面的记忆机制与协作模式**

因为未来很多 AI 产品的差距，未必在“模型参数更大”，而在于：

- 谁更懂用户
- 谁能把每次交互沉淀成长期价值
- 谁能把用户修改、安全机制、产品迭代连接起来

---

##### 我觉得真正难的地方

这件事虽然方向对，但落地并不轻松，难点主要有 3 个：

1. **记忆不等于价值**  
   AI 记住很多东西，不代表真的有用。垃圾记忆、错误偏好、过时信息都会污染系统。

2. **个性化和通用性会冲突**  
   给某个用户优化得很好，不一定适合所有用户；如何把个体修改提炼成公共产品能力，非常考验产品判断。

3. **安全和可控性是硬门槛**  
   会自更新、会自学习的软件很强，但如果改错了、学歪了、泄露了隐私，风险也会很大。

---

##### 我给出的结论

我认为这条路大概率会发生，但真正跑出来的，不会只是“接了个 SDK 的 AI 应用”，而会是那些同时做好这几件事的产品：

- 能持续记忆用户偏好
- 能把记忆转化为更好执行
- 能让修改可追踪、可回滚、可审核
- 能把个体经验提炼成产品进化

**一句话说：未来最强的软件，不只是“会用 AI”，而是“会从每次使用中成长”。**
