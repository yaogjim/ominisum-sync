**凡人小北**

腾讯开源了一个 TeamAI-CLI，做法很简单：把团队使用 Agent 的规则、Skill 和文档，直接放进一个 Git 仓库。

谁摸索出了一套更好用的方法，就像改代码一样提交；团队评审之后再合并，下一次对话便同步给每个人。哪条规则是谁改的、为什么改、效果不好怎么退回去，也都有记录可查。

我觉得这个思路挺正。

现在一提团队知识共享，很多人上来就想搭知识库、设计复杂的分类体系，再做一套管理后台。  
但真正的问题往往没有那么复杂，大家各自在电脑上踩坑。

知识一旦进入协作，首先需要解决的其实就是变更、评审、版本和溯源。而这些问题，Git 已经解决得很好了。

过去我们用 Git 管理团队共同生产的代码，现在开始用它管理团队共同使用 AI 的方法。

方案看起来很轻，抓住的却是最核心的问题。

#### 腾讯开源 TeamAI-CLI：用 Git 管理团队使用 AI 的方法

腾讯开源了内部使用的 TeamAI-CLI。它不试图先建设复杂的知识库，而是把 Agent 所需的规则、Skill 和文档统一放进 Git 仓库，让团队成员与各个 Agent 都基于同一套、可持续更新的“操作手册”工作。

##### 把 AI 使用经验当作代码协作

成员探索出更有效的方法后，可以像修改代码一样提交变更，经合并请求评审后纳入团队版本，并在后续对话中同步给其他人。Git 同时提供了几项关键能力：

- 记录规则由谁修改、为何修改；
- 通过评审控制团队规范；
- 保留版本历史，支持追溯和回退；
- 让分散在个人电脑上的实践经验进入团队协作。

##### 轻量方案抓住了知识共享的核心

作者认为，团队知识管理的首要问题往往不是分类和后台功能，而是变更、评审、版本与溯源，这些恰好是 Git 已成熟解决的问题。TeamAI-CLI 的意义在于，将 Git 从“管理共同生产的代码”延伸到“管理共同使用 AI 的方法”。

不过，评论也提出两个现实问题：若不同方案都要集体评审，可能增加协作成本；如果团队原本已用 Git 管理相关文件，CLI 能带来多少额外价值，还要看其同步和集成能力。
