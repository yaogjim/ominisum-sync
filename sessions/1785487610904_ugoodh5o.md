Unofficial Linux build wrapper for [OpenAI ChatGPT Desktop](https://chatgpt.com/features/desktop/). The official ChatGPT app is available for macOS and Windows; this repository covers Linux by converting the upstream macOS `Codex.dmg` into a runnable Linux Electron app.

The project builds native `.deb`, `.rpm`, and `.pkg.tar.zst` packages, supports local AppImage self-builds and Nix, and can install a local update manager that rebuilds future Linux packages from newer upstream DMGs.

Install · Uninstall · Features · Updates · Build · Troubleshooting · Docs · [Discord](https://discord.gg/skCB3DXqgw)

Before opening a pull request, read CONTRIBUTING.md. For implementation details, see AGENTS.md.

ChatGPT Desktop for Linux is built locally from the upstream `Codex.dmg`: the installer downloads or reuses the DMG, extracts the Electron app, applies Linux compatibility patches, rebuilds native modules, stages the Linux runtime, and packages the result. Optional Linux-only integrations live in `linux-features/` and stay disabled unless you enable them before building.

For native packages and AppImage self-builds, start from a checkout:

```
git clone https://github.com/ilysenko/codex-desktop-linux.git
cd codex-desktop-linux
```

Platform Recommended path Notes

Debian, Ubuntu, Pop!\_OS, Mint, Elementary `make bootstrap-native` Builds and installs a `.deb`

Fedora `make bootstrap-native` Builds and installs an `.rpm`

openSUSE `make bootstrap-native` Builds and installs an `.rpm`

Arch, Manjaro, EndeavourOS `make bootstrap-native` Builds and installs a pacman package

NixOS / Nix `nix run github:ilysenko/codex-desktop-linux` See Nix docs

Atomic desktops / other distros `make build-app && make appimage` Local self-build; no bundled updater

Recommended native install:

```
make bootstrap-native
```

If dependencies are already installed:

```
make install-native
```

`make bootstrap-native` installs build dependencies, validates the cached upstream `Codex.dmg`, downloads it only when missing or stale, builds `codex-app/`, packages it for your distro, and installs the newest artifact from `dist/`.

If you are installing dependencies manually on Fedora:

```
# Fedora 41+
sudo dnf install python3 7zip curl unzip rpm-build make gcc-c++ @development-tools

# Fedora < 41
sudo dnf install python3 p7zip p7zip-plugins curl unzip rpm-build make gcc-c++
sudo dnf groupinstall 'Development Tools'
```

For a guided first-run checklist and optional feature picker:

```
make setup-native
```

See Native setup for the wizard, non-interactive feature selection, cleanup flow, and `PACKAGE_WITH_UPDATER=0`.

#### Uninstall

Close ChatGPT Desktop first, then remove the native package with your distro's package manager:

```
# Debian / Ubuntu
sudo apt remove codex-desktop

# Fedora
sudo dnf remove codex-desktop

# openSUSE
sudo zypper remove codex-desktop

# Arch / Manjaro
sudo pacman -R codex-desktop
```

Native package removal stops and disables `codex-update-manager.service` when the service is installed. If the service was left behind by an older package or a manual install, disable it explicitly:

```
systemctl --user disable --now codex-update-manager.service
```

AppImage builds are not installed system-wide by this repository; delete the AppImage file you created. A repo-only generated app can be removed from the checkout with:

```
rm -rf codex-app
```

`nix run github:ilysenko/codex-desktop-linux` is ephemeral. If you installed the flake through a Nix profile, Home Manager, or a NixOS module, remove that profile or configuration entry and rebuild your profile/system.

User data is preserved for reinstall. To remove only this wrapper's local app state, logs, launcher flags, and updater state, delete these paths.

If you enabled Remote Mobile Control, `~/.config/codex-desktop` can contain the private `remote-control-device-keys/` directory. Revoke paired devices in Codex Settings/Connections or ChatGPT before deleting it or removing the whole `codex-desktop` directory. For feature-owned data, prefer the cleanup flow in Native setup.

```
rm -rf \
  ~/.config/codex-desktop \
  ~/.local/state/codex-desktop \
  ~/.cache/codex-desktop \
  ~/.config/codex-update-manager \
  ~/.local/state/codex-update-manager \
  ~/.cache/codex-update-manager
```

Do not remove `~/.codex` unless you also want to delete your Codex CLI configuration and project state.

The generated app and native packages bundle a managed Linux Node.js runtime. You do not need a distro `nodejs` / `npm` package for normal installs, Browser Use, Codex CLI install/update, or local auto-update rebuilds.

The Codex CLI is still required at runtime. The first launch can install or update `@openai/codex` with the bundled `npm`, or you can manage the CLI yourself. If you install the CLI manually through npm, include optional dependencies with `npm i -g --include=optional @openai/codex` so the Linux platform binary is present. The launcher does not rank installed CLIs by version; it uses an explicit `CODEX_CLI_PATH` first, then the normal lookup order, and logs the resolved CLI path plus best-effort version so GUI PATH issues are visible. Set `CODEX_CLI_PATH=/path/to/codex` when you want to pin a specific binary.

Local AppImage builds can optionally embed that CLI and its matching Linux platform package. Set `CODEX_CLI_BUNDLE_SOURCE` to an installed `node_modules/@openai/codex` directory when running `make appimage`; explicit `CODEX_CLI_PATH` values still take precedence at runtime. See Build and packaging.

X11 and Wayland sessions are supported. The launcher prefers XWayland on Wayland when available for better Electron popup positioning, then falls back to Electron's automatic Wayland handling. See Troubleshooting for GPU, Vulkan, and `/tmp noexec` workarounds.

#### Updates

Default native packages install `codex-update-manager`, a `systemd --user` service that checks for newer upstream DMGs, rebuilds a local native package, and installs it after ChatGPT Desktop exits. The final install uses `pkexec`. Minimal window-manager sessions need a graphical polkit authentication agent for the in-app install button; otherwise the updater keeps the package ready and reports a terminal `sudo /usr/bin/codex-update-manager ... --path ...`command.

Manual-update package:

```
PACKAGE_WITH_UPDATER=0 make package
make install
```

Manual rebuild from a trusted checkout:

```
PACKAGE_WITH_UPDATER=0 make update-native
```

AppImage builds and repo-only generated apps do not include the native-package updater. See Updater.

Generate the local Electron app:

```
make build-app-fresh
make run-app
```

Use a local DMG:

```
make build-app DMG=/path/to/Codex.dmg
```

Local builds are transactional: the candidate must pass the same upstream DMG acceptance profile used by the scheduled GitHub workflow before it replaces the working `codex-app/`. Only configured Linux Features are checked; drift in an enabled feature keeps the current app installed until that feature is disabled or repaired.

Build and install a package:

```
make package
make install
```

Build a specific artifact:

```
make deb
make rpm
make pacman
make appimage
```

The package scripts only repackage the already-generated `codex-app/`. They do not download or extract the DMG themselves. See Build and packaging.

#### Troubleshooting

Problem First thing to try

`/tmp` is mounted `noexec` Set `TMPDIR` and `XDG_CACHE_HOME` to executable directories under `$HOME`

Blank window or splash stuck Check `~/.cache/codex-desktop/launcher.log` and whether port `5175` is already in use

`CODEX_CLI_PATH` or CLI install error Check `~/.cache/codex-desktop/launcher.log`, set `CODEX_CLI_PATH=/path/to/codex` to pin a binary, or install `@openai/codex` manually with optional dependencies

Wayland / GPU / Vulkan hang Try `CODEX_LINUX_RENDERING_MODE=wayland-gpu ./codex-app/start.sh` or persistent launch flags

UI oversized or blurry (HiDPI / fractional scaling) Try `CODEX_FORCE_DEVICE_SCALE_FACTOR=1 ./codex-app/start.sh` or `CODEX_OZONE_PLATFORM=x11 ./codex-app/start.sh`; see `./codex-app/start.sh --diagnose-scaling`

Resize ghosting or stale frame trails Try `CODEX_ELECTRON_DISABLE_GPU_COMPOSITING=1 ./codex-app/start.sh` or `--disable-gpu-compositing`

Computer Use UI is hidden Enable the UI opt-in; account/server rollouts may still hide upstream-gated parts

Computer Use has no input backend Check `/dev/uinput`, portal support, or `ydotoold` / `ydotool.service`

Updater seems stuck Check `codex-update-manager status --json` and service logs

Full list: Troubleshooting.

## 深度解读（1）

### 2026-09-18 10:19:58

#### 这不只是 Linux 移植：桌面 AI 的真正成本在系统集成层

这个项目最值得关注的，不是“Linux 用户终于能运行 ChatGPT Desktop”，而是它具体展示了：**一个看似跨平台的 Electron 应用，距离真正支持另一套桌面系统，仍隔着相当厚的工程层。**

项目并未重写客户端，而是让用户自行取得官方 macOS DMG，再在本地完成解包、Linux 兼容性补丁、原生模块重编译、运行时装配和发行版打包。它同时处理 Debian、Fedora、Arch、Nix、AppImage，兼容 Wayland 与 X11，并补上更新、托盘、文件管理器、浏览器插件和 CLI 路径等问题。Electron 解决的是大部分界面复用，却没有消除安装、权限、窗口行为、输入控制、系统服务和更新机制的差异。

##### AI 桌面产品的重心正在从聊天框移向操作系统

功能列表里更有信号意义的是 Computer Use、浏览器操作、全局听写、远程移动控制、任务工作区和录制回放。这说明桌面 AI 已不只是一个网页外壳，而是在逐渐成为**连接模型与本机环境的执行层**。

一旦 AI 要读取文件、控制浏览器、模拟键鼠、调用 CLI 或保持后台任务，产品质量便取决于操作系统适配：Wayland 下能否获得输入能力，`/dev/uinput` 和 portal 是否可用，窗口焦点是否可靠，权限提升如何完成，进程退出后是否残留。这些问题不够“智能”，却直接决定代理能否稳定完成工作。对产品团队而言，模型能力相近时，真正拉开体验差距的可能是这套本地执行基础设施。

项目把 Linux 专属能力做成默认关闭、可组合的 feature framework，也很值得借鉴：核心兼容层尽量稳定，实验功能通过补丁、资源和运行时钩子独立接入。它让社区可以快速验证需求，又避免把所有实验永久塞进主流程。代价则是上游应用一变，补丁就可能漂移；项目因此设置了 DMG 校验、候选构建检测和事务式替换，说明**基于闭源上游做扩展，持续兼容本身就是主要成本**。

##### 它证明了缺口，但还没有证明商业需求

Linux 用户与开发者、AI 工具重度用户高度重合，这使官方平台缺席显得格外醒目。不过，这个仓库只能证明有人愿意投入解决问题，不能单独证明市场规模、付费意愿或官方客户端的 PMF。OpenAI 不支持 Linux，也可能不是忽视需求，而是判断多发行版、图形栈和权限模型带来的支持成本高于收益。

更现实的机会未必是再做一个客户端，而是提供可复用的 Linux agent runtime：统一处理输入控制、浏览器连接、权限、后台服务、诊断和打包，让不同 AI 产品不必重复踩坑。需要验证的关键假设是：其他代理产品是否也在承担相同适配成本，以及企业 Linux 环境是否愿意信任这类执行层。

最后还要看到风险边界：它是非官方项目，涉及下载上游 DMG、重编译原生模块、安装用户级更新服务，并在最终安装时使用提权机制。README 中“不重分发官方二进制”的设计降低了版权与分发风险，却不自动解决许可、安全和供应链信任问题；服务端控制的模型与功能也不会因重建客户端而解锁。**它最有价值的启示不是绕过平台限制，而是把桌面 AI 被聊天界面遮住的系统工程暴露了出来。**

## 口播总结（1）

### 2026-09-20 00:18:59

如果你想在 Linux 上使用完整的 ChatGPT 桌面界面，这个项目提供了一条可行路径。但要先明确：它不是 OpenAI 官方发布的 Linux 客户端，而是一个社区维护的兼容和打包工具。它会在本地取得官方 macOS 应用，把其中的 Electron 桌面程序转换成可在 Linux 上运行的版本，并提供聊天、Work 和 Codex 等功能。

这个项目最值得关注的地方，是它不直接分发 OpenAI 的应用程序或修改后的二进制文件。构建时，安装器会下载或复用用户自己的 Codex 点 DMG 文件，也就是 macOS 安装镜像。接着，它提取 Electron 应用，应用 Linux 兼容补丁，重新编译原生模块，再加入 Linux 运行环境，最后生成适合当前发行版的软件包。

因此，它更像一套自动化转换流水线，而不是一个重新开发的客户端。项目采用 MIT 许可证，但这个许可证只适用于转换工具、打包脚本、文档和 Linux 兼容代码，不适用于 OpenAI 的软件、商标或服务。使用者仍然需要通过官方渠道取得授权副本，并遵守 OpenAI 的相关条款。

安装方式取决于 Linux 发行版。Debian、Ubuntu、Linux Mint 和 Pop! OS 等系统，可以生成并安装点 DEB 软件包。Fedora 和 openSUSE 使用点 RPM。Arch、Manjaro 和 EndeavourOS 使用 Pacman 软件包。Nix 和 NixOS 有单独的运行方式。其他发行版，或者不可变的原子化桌面，可以在本地构建 AppImage。

对大多数受支持的发行版，推荐做法是先克隆项目仓库，进入项目目录，然后运行“make bootstrap-native”。这条命令会安装构建依赖，检查缓存里的上游 DMG 是否有效，只在缺失或过期时重新下载，随后构建应用、生成当前发行版的软件包，并安装最新产物。如果希望通过向导选择可选功能，可以运行“make setup-native”。

安装后的应用自带受管理的 Linux 版 Node.js 运行环境。正常使用、浏览器自动化、Codex 命令行工具的安装更新，以及本地自动更新，都不要求系统另外安装 Node.js 或 NPM。

不过，Codex 命令行工具本身仍然是运行时依赖。第一次启动时，应用可以使用内置的 NPM 安装或更新它。用户也可以自行管理。如果系统里存在多个 Codex 命令行程序，启动器不会自动选择版本最高的那个。它会先检查名为“CODEX_CLI_PATH”的环境变量，然后按照正常路径查找。出现图形界面找不到命令行工具的问题时，最直接的办法就是用这个变量指定可执行文件的完整路径。启动器也会把最终使用的路径和可识别到的版本写入日志，方便排查。

在桌面环境方面，项目同时支持 X11 和 Wayland。Wayland 会话中，如果系统提供 XWayland，启动器通常优先使用它，以改善 Electron 弹窗的位置；否则再交给 Electron 自动处理 Wayland。Linux 文件管理器集成、浏览器标注、托盘和快速再次启动等能力，已经包含在核心适配中。Linux 版 Computer Use，也就是让模型操作电脑的能力，包含一个默认注册的后台接口，但相关界面需要用户主动开启，而且部分能力仍可能受到账号或服务器端开放范围的限制。

这一点非常重要：重新构建这个 Linux 封装，并不能解锁 OpenAI 尚未向当前账号开放的模型或功能。客户端是否显示某些模型，最终仍可能由 OpenAI 按账号控制。这个项目解决的是 Linux 兼容问题，不是服务权限问题。

项目还提供了大量 Linux 专属扩展，例如全局语音输入、朗读按钮、远程移动控制、代理认证、无边框标题栏、录制与回放、工作区增强，以及多种 Computer Use 适配。不过，这些功能大多默认关闭。用户需要在构建前修改 Linux Features，也就是 Linux 功能配置文件，然后重新构建。这样的设计可以让核心构建流程保持稳定，也避免实验功能在默认状态下影响所有用户。

原生软件包通常还会安装一个自动更新管理器。它以用户级 systemd 服务运行，定期检查是否出现新的上游 DMG。如果有新版本，它会在本地重新构建 Linux 软件包，并等 ChatGPT 桌面应用退出后再安装。最后的安装步骤通过系统权限工具完成。如果桌面环境缺少图形化权限确认程序，更新器不会强行安装，而是保留已经构建好的软件包，并提示用户在终端中执行相应命令。AppImage 和只在仓库中生成的应用，默认不包含这套原生软件包更新器。

本地构建还采用了事务式替换。新的候选应用必须通过项目设定的上游镜像检查，才会替换当前可用版本。如果已经启用的 Linux 扩展与新版发生冲突，系统会保留现有应用，直到相关扩展被修复或关闭。这可以降低一次失败更新直接破坏可用安装的风险。

遇到问题时，可以先看几个高频原因。空白窗口或启动画面卡住，应检查缓存目录中的 launcher 日志，并确认五千一百七十五端口是否被占用。Wayland、显卡或 Vulkan 导致卡死时，可以切换渲染模式或尝试 X11。高分辨率和非整数缩放造成界面过大、模糊时，可以强制缩放比例为一，或者指定使用 X11。窗口缩放后残留旧画面，可以尝试关闭 GPU 合成。如果 Computer Use 无法输入，则要检查系统的 uinput 设备、桌面门户支持，以及 ydotool 后台服务。

卸载原生软件包时，应先关闭应用，再通过发行版的软件包管理器删除。删除软件包通常会同时停止自动更新服务，但用户数据会被保留，方便以后重装。如果还启用了远程移动控制，删除本地配置前应先撤销已经配对的设备，因为配置目录中可能保存私人设备密钥。也不要随意删除用户目录下的“.codex”文件夹，除非确实想一并清除 Codex 命令行工具的配置和项目状态。

总的来说，这个项目的价值，是把官方 macOS Electron 应用转换成 Linux 可运行版本，并进一步补上发行版打包、更新、Wayland 与 X11 兼容等环节。它提供了接近原生软件的安装体验，但本质上仍是非官方社区方案。使用前最该记住三点：应用是在本地从官方镜像转换出来的；Codex 命令行工具仍然必需；账号功能是否开放，依旧由 OpenAI 的服务器端规则决定。
