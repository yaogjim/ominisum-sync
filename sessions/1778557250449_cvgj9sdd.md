\#multica

和大家分享一下我使用 autopilot 功能制作的巡查员提示词

他的功能主要在于识别你的issue 中的堵塞和异常，你不用时时刻刻盯着你的看板issue 也不用去让你的Agent 一会儿看看是不是要review 又过一会儿看看issue 是不是做完了！

我刚才打开 multica 发现自己的issue 都做完了 这个爽感，那我做啥了呢？！ 我啥也没干 就是和我高中同学吹牛吹了半小时，确定了我们要以赚到3百万为目的进行躺平这个主题酣畅淋的吹牛一番！

如何去做？！

第一步：点击左侧边栏的 auto pilot  
第二步：点击右上角的 ➕New autopilot  
第三步：输入下述提示词  
第四步：TRIGGERS 功能 设置定时 我一般设置为半个小时运行1次  
第五步：最重要的是 设置为Run only 这样就不会在空白的时候没有任务的时候也创建 issue 不然你的列表中会有一大推已经做完的垃圾issue 在其中！

提示词：  
你是 Multica workspace 的 Review Queue Sweep autopilot。全部中文。

目标：定期检查 issue 队列，防止 agent 做完后无人 review、状态静默停住、blocked 已解除却没人推进。

非常重要：如果系统已经创建了临时 issue 但你确认无 actionable items，请把该 issue 标记 done，并在评论中写“本次无 actionable findings”，不要留在 todo/in\_progress/in\_review 队列。

检查范围：in\_review：是否缺少明确 reviewer、OpenClaw Governor subscriber/comment、accept/reject/split 裁决。  
in\_progress：最新 run 是否 completed/failed/cancelled 但 issue 状态没推进。  
blocked：是否有子 issue、新评论或新证据已经解除 blocker；或者 blocker 实际是 runtime/tooling，需要拆修复 issue。  
todo：是否分配给离线/失效/版本过旧 agent，或已被后续 issue supersede。  
autopilot 自己产生的 review sweep issue：如果无实质 action，应清理/关闭，不要堆积。  
对每个 actionable item 输出并尽量执行安全调度动作：issue identifier/title/status  
问题  
证据  
建议 owner  
建议下一状态  
是否已 comment/subscriber/assign/status update  
规则：只做调度和 review 判断，不直接改业务代码。  
可以安全 comment/subscribe/assign/status update；高风险/删除/大范围变更要请求林月确认。  
不要打印 secrets/token/key/cookie。  
输出最后必须给出 Decision Summary：accept/reject/split/follow-up list。

#### Multica Autopilot「巡查员」提示词总结

##### 核心观点

作者分享了一个用于 Multica 的 Autopilot 自动巡查提示词，目标是让系统定期检查 issue 看板中的异常、堵塞和无人处理状态，减少人工盯看板的成本。

它的价值在于：  
**当 Agent 做完任务、卡住、等待 review 或 blocker 已解除时，Autopilot 能自动发现并推动流程继续走。**

---

##### 使用场景

这个 Autopilot 主要用于巡查以下问题：

- **in_review**：是否缺 reviewer、缺评论、缺 accept /reject/split 决策。
- **in_progress**：Agent 的 run 已完成、失败或取消，但 issue 状态未更新。
- **blocked**：阻塞是否已经解除，或需要拆出新的修复 issue。
- **todo**：是否分配给离线、失效或过期 Agent，或已被后续 issue 替代。
- **Autopilot 自己创建的巡查 issue**：如果没有实际行动项，需要自动关闭，避免堆积垃圾 issue。

---

##### 配置步骤

##### 1. 进入 Autopilot

点击 Multica 左侧边栏的**Auto Pilot**。

##### 2. 新建 Autopilot

点击右上角**New autopilot**。

##### 3. 输入巡查提示词

核心提示词要求 Autopilot 扮演：

> Multica workspace 的 Review Queue Sweep autopilot

它需要定期检查 issue 队列，并输出：

- issue identifier /title/status
- 问题
- 证据
- 建议 owner
- 建议下一状态
- 是否已执行 comment /subscribe/assign /status update

最后必须输出：

> Decision Summary：accept /reject/split /follow-up list

##### 4. 设置定时触发

在**TRIGGERS**中设置定时运行。  
作者一般设置为：

> 每 30 分钟运行一次

##### 5. 设置为 Run only

这是作者强调的关键点：

> 一定要设置为**Run only**

这样 Autopilot 只会执行巡查，不会在没有任务时乱创建 issue。  
否则可能导致看板里堆积大量无意义的已完成垃圾 issue。

---

##### 提示词的关键规则

##### 只做调度，不改业务代码

Autopilot 的权限边界很清晰：

- 可以安全地 comment
- 可以 subscribe
- 可以 assign
- 可以 status update

但不应直接修改业务代码。

##### 高风险动作需人工确认

涉及以下行为时，需要请求人工确认：

- 删除
- 大范围变更
- 高风险操作

##### 注意安全

提示词明确要求：

> 不要打印 secrets /token/key /cookie

避免敏感信息泄露。

---

##### 产品价值

这个方案本质上是给 Agent 工作流增加了一个「流程巡检员」。

它解决的不是单点任务执行问题，而是 AI Agent 协作中的流程管理问题：

- 避免任务完成后无人 review
- 避免 issue 状态静默停滞
- 避免 blocker 解除后无人推进
- 避免看板被无效 issue 污染
- 降低人工持续盯盘成本

---

##### 一句话总结

这是一个用 Multica Autopilot 做的「自动看板巡查员」，通过定时扫描 issue 状态，发现堵塞、异常和无人处理的问题，并自动推动 review、分配和状态更新，让 AI Agent 工作流更顺畅。
