## 追问（1）

### 提问 · 2026-04-02 07:27:50

如何使用OMX

### 回答 · 2026-04-02 07:27:50

OMX 的定位是：不替代 Codex，而是在 Codex CLI 外面加一层更强的工作流、角色调用和运行时能力。

你可以把它理解成：

- Codex 负责真正执行任务
- OMX 负责把常见角色、计划流程、团队协作、状态记录组织得更顺手
- 项目相关的计划、日志、记忆会放在`.omx/`里

**最推荐的用法**

先装好 Codex CLI 和 OMX，然后直接用 OMX 启动一个更强的 Codex 会话。

1. 安装 Codex CLI
```bash
npm install -g @openai/codex
```

2. 安装 OMX
```bash
npm install -g oh-my-codex
```

3. 初始化 OMX
```bash
omx setup
```

4. 用推荐方式启动
```bash
omx --madmax --high
```

启动后，就可以在 Codex 里直接用 OMX 提供的角色和技能。

**最常用的两个入口**

- 分析问题：
```bash
$architect "analyze the authentication flow"
```

- 先做规划：
```bash
$plan "ship this feature cleanly"
```

如果你更习惯中文，可以直接写中文，例如：

```bash
$architect "分析当前登录鉴权流程"
$plan "规划这个功能最稳妥的实现路径"
```

**常见能力怎么用**

- `$architect"..."`：做分析、边界梳理、权衡方案
- `$executor"..."`：聚焦执行某个实现任务
- `$plan"..."`：在动手前先出计划
- `$ralph"..."`：持续串行推进复杂任务
- `$team"..."`：任务很大时做并行协作
- `$deep-interview"..."`：当需求还很模糊时，先连续追问澄清

适合这样理解：

- 需求不清楚：先用`$deep-interview`
- 要先想清楚方案：用`$architect`或`$plan`
- 已经很明确，要直接做：用`$executor`
- 任务很大、要持续推进：再考虑`$ralph`或`$team`

**一个推荐工作流**

你可以按这个节奏来：

1. 启动 OMX
```bash
omx --madmax --high
```

2. 先分析
```bash
$architect "分析这个仓库的认证流程和潜在风险"
```

3. 再规划
```bash
$plan "给出最安全的修改步骤，避免回归"
```

4. 然后执行
```bash
$executor "按计划实现并验证修改"
```

这也是 OMX 文档里强调的主路径：  
先 “强启动”，正常在 Codex 里工作，只有任务变复杂时，再让代理决定是否升级到`$team`、`$ralph`等更重的流程。

**团队模式怎么用**

如果你明确需要持久化的 tmux/worktree 协作，可以用 team runtime，但这不是默认起步方式。

例如：

```bash
omx team 3:executor "fix the failing tests with verification"
```

其他团队命令：

```bash
omx team status <team-name>
omx team resume <team-name>
omx team shutdown <team-name>
```

这个模式更适合：

- 大任务拆成多人 / 多代理并行
- 需要长期保留运行状态
- 需要 tmux 协调多个工作面板

**辅助命令**

这些更偏 “运维 / 辅助”，不是主要工作入口：

- `omx setup`：安装 prompts、skills、配置和 AGENTS 脚手架
- `omx doctor`：检查安装是否正常
- `omx hud --watch`：查看监控 / 状态
- `omx explore --prompt"..."`：只读地查仓库
- `omx sparkshell &lt;command>`：做 shell 检查或有限验证

例如：

```bash
omx explore --prompt "find where team state is written"
omx sparkshell git status
```

**使用前要求**

至少需要：

- Node.js 20+
- 已安装 Codex CLI
- 已完成 Codex 登录认证

如果你之后要用 team runtime：

- macOS / Linux 需要`tmux`
- 原生 Windows 需要`psmux`
- WSL2 可用`tmux`

**一句话建议**

如果你是第一次用 OMX，最简单的开始方式就是：

```bash
omx setup
omx --madmax --high
$architect "分析我的任务"
$plan "规划实现路径"
```
