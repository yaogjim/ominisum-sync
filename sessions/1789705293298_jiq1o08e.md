## 正文

**炎朗 Gavin**

Pi agent是真香，hermess什么的都可以抛一边了，就用它作为桌面 work主力，速度快、还省token

推荐几个必装的扩展，装上后性能、生产力飞起:

\- pi-web-access  
网络访问全家桶：网页搜索、URL 抓取、GitHub 仓库克隆、PDF 提取、YouTube/本地视频理解。支持 OpenAI、 Brave、Tavily、Kagi、Exa、Perplexity 等众多搜索后端

\- pi-memory  
记忆系统：长时记忆（MEMORY.md）、每日日志、scratchpad，支持 qmd 语义检索（memory\_search 等）

\- juicesharp/rpiv-todo  
模型可用的待办清单（todo 工具），以实时 overlay 形式渲染，跨 /reload 和上下文压缩存活

\- pi-subagents  
子代理编排：可派生并行/串行子 agent 处理多步任务，带 worktree 隔离、工作流脚本、任务预算等能力

\- pi-mcp-adapter  
MCP 适配器：让 Pi 接入 Model Context Protocol 服务器（mcp / mcpScript 工具即来自这里），而且是动态判断接入MCP Server，不会塞爆上下文

\- context-mode  
本质上是通过MCP Server方式接入，将tool calling result 和文件读写内容进行执行压缩，区分出主context，有效节省ctx空间

#### Pi Agent：以极简内核配扩展，打造高效桌面工作流

作者认为，Pi Agent 速度快、Token 消耗低，可替代 Hermes 成为桌面工作主力；其价值在于按需安装扩展，补齐联网、记忆、任务管理和多代理协作能力。但评论区也指出，扩展过多可能背离 Pi 的极简设计，实际收益取决于个人工作流。

##### 六类扩展补齐核心能力

- **pi-web-access**：提供搜索、网页抓取、GitHub 仓库克隆、PDF 提取及视频理解，兼容 Brave、Tavily、Kagi、Exa、Perplexity 等后端。热门回复普遍认为它最实用，甚至值得官方内置。
- **pi-memory**：通过长期记忆、每日日志和 scratchpad 保存信息，并支持语义检索。
- **rpiv-todo**：把待办事项直接提供给模型，以实时浮层展示，且能跨重载和上下文压缩保留。
- **pi-subagents**：支持并行或串行派生子代理，提供工作区隔离、流程脚本和任务预算，适合复杂多步任务。
- **pi-mcp-adapter**：按需连接 MCP 服务器，避免一次性加载大量工具信息、挤占上下文。
- **context-mode**：压缩工具调用结果和文件读写内容，把关键信息留在主上下文中，进一步节省上下文空间。

##### 模块化灵活，但存在“重新拼装”争议

作者推崇的是“轻量内核＋按需扩展”的组合：用户可控制功能与上下文成本。反对者则认为，六个扩展中部分价值有限，安装过多既增加复杂度，也可能只是把 Hermes 的现成功能重新拼装一遍。因此，Pi 的优势更适合通过最小化配置验证，而非默认全装。
