## 正文

**土豆本豆**

张小珺和真格基金戴雨森最新一期播客，两个多小时，聊了AI行业复盘、创业机会和投资思考。

一、Return问题没有被解决，只是下推了一层

Anthropic的收入大涨让很多人觉得回报问题已经解决了。

戴雨森的看法是：Anthropic的收入其实是它客户的投入。客户买了token烧了token，是要做出软件、降本增效、最终产生利润的。

现在进来尝鲜的人远多于发现token没有带来价值离开的人，所以收入涨得很快。但这个漏水最终是要堵住的：来吃螃蟹的人得能赚到钱，而且赚钱的周期不能太长。

投入→产出→结果，这是一个三步的链条。现在所有人都在拼命投入，产出多了一些，但产出还没带来结果。

二、Coding不是垂直领域，是水平能力

去年以前很多人把coding和医疗、金融并列，当作一个垂直方向。连一些研究员如果自己不做coding，也觉得coding就是垂直方向中的一个。

现在大家发现coding是horizontal的，它能加强办公、医疗、研究等所有领域。这个认知的转变让coding的意义完全不一样了。

三、Harness更像OS，模型更像CPU

三年前做一个AI应用，得自己处理agentic loop、memory、guardrail。

现在在Claude Code或Codex上做一个Skill，这些都不用管了，harness帮你处理。

就像Windows出现之后开发者不用自己跟硬件通信了。而且用户可以在harness里插拔模型：哪个便宜用哪个，哪个新用哪个。

用户对harness的忠诚度反而比对模型高，因为记忆和context存在harness里。

四、Agent网络效应可能正在出现

六个月前大家都用同一个Claude Code，没有理由交换。但现在每个人的harness里沉淀了不同的context、skills和记忆。

同一个任务交给不同人的agent会得到不同结果。这就出现了一种可能：我的agent雇佣你的agent来做某件事，其中一部分是token费用，另一部分是你的agent积累的专有知识的溢价。这可能是一种agent之间的marketplace。

五、下一个字节跳动级的公司不会长得像字节

很多人在找下一个字节，做一个AI信息流，刷来刷去，里面是AI生成的内容。

戴雨森觉得在字节的游戏规则里打败字节是极难的。Agent时代的关键指标已经从attention（用户看屏幕的时长）变成了agent能持续完成有价值任务的时长。

如果为了优化DAU让用户多上来看一看，反而说明产品不能让用户省心。

六、AI毁灭旧价值的速度远高于创造新价值的速度

降本在发生（裁员），但增效还需要时间：因为增效需要新产品、新需求，而这需要人的想象力，不是多了十倍工程师就能立刻多出十倍收入。

移动互联网后期大家已经不知道该做什么了，这是产品创新的问题。现在硅谷有的公司因为编程能力过剩开始互相进入对方领地，但复制已有功能和创造全新品类是两回事。

七、三步走：Agent的落地路径

第一步，让人类拥有更多更好的agent：现在各家都在做这件事。

第二步，让agent更好地适应人类的数字世界：支付、身份验证、使用人类软件。

第三步，建设agent专属的数字基础设施：agent之间的支付、通信、协作方式可能跟人类完全不同。

八、思考需要刻意练习，创新也需要刻意练习

戴雨森有一个观察：作为一个快40岁的人，想法比20岁创业时少了很多。虽

然坐拥各大coding agent的订阅，每天有很多AI等着打工，但做什么呢？他有个朋友每月烧一万美金token，做了个扫描器检测每天哪些域名到期没人注册，然后让AI给这些域名做产品。

这有点像Omakase：今天鱼市上看到什么鱼，就做什么菜。听起来荒唐，但其实是在刻意练习用AI创新。

#### 总结

这期播客核心在讲：**AI 很热，但真正的商业闭环还没完全跑通。**

主要观点：

1. **AI 收入高，不等于客户赚到钱**  
   Anthropic 收入增长，本质是客户在买 token、烧 token。问题是：客户最终能不能靠 AI 降本增效、赚回钱。

2. **Coding 不是垂直行业，而是基础能力**  
   AI 编程不是“医疗、金融、教育”中的一个赛道，而是能赋能所有行业的“横向能力”。

3. **Harness 像操作系统，模型像 CPU**  
   Claude Code、Codex 这类工具会沉淀记忆、上下文、技能。用户可能更依赖这些平台，而不是某个具体模型。

4. **Agent 可能形成网络效应**  
   每个人的 agent 会积累不同知识和能力，未来可能出现“我的 agent 雇你的 agent”的市场。

5. **下一个字节不会像字节**  
   AI 时代不再比拼用户刷屏时长，而是比拼 agent 能持续完成多少有价值任务。

6. **AI 破坏旧价值很快，创造新价值较慢**  
   裁员、降本来得快，但真正的新产品、新需求、新收入，需要更长时间。

7. **Agent 落地分三步**  
   - 人拥有更多 agent  
   - agent 适应人类数字世界  
   - 建设 agent 专属基础设施

8. **创新需要练习**  
   有 AI 工具不等于有好想法。未来更稀缺的是：知道让 AI 做什么。

#### 解读

##### 1. AI 还没真正证明“能赚钱”

现在很多 AI 公司收入暴涨，但这只是说明：

> 有很多人在尝试 AI。

还不能说明：

> AI 已经帮客户稳定赚到了钱。

就像公司买了一堆健身卡，不代表员工真的变健康了。  
关键要看最后有没有结果：**省了钱、赚了钱、提高了效率。**

---

##### 2. AI 编程的意义被低估了

以前大家以为 AI Coding 只是程序员工具。  
现在发现它更像“电力”：

- 办公软件需要它
- 医疗系统需要它
- 科研工具需要它
- 企业管理也需要它

所以 AI Coding 不是一个小赛道，而是整个 AI 应用的基础设施。

---

##### 3. 真正的入口可能不是模型，而是工具层

模型像发动机，harness 像汽车。

普通用户不会天天关心发动机型号，  
但会依赖自己熟悉的车、座椅、导航、驾驶习惯。

所以未来用户可能不忠诚于某个模型，而忠诚于：

- 我的上下文
- 我的工作流
- 我的 agent 记忆
- 我的插件和技能

谁掌握这些，谁就更接近入口。

---

##### 4. Agent 时代的产品逻辑会变

过去互联网抢的是：

> 你每天看我多久？

AI 时代抢的是：

> 我每天帮你做成多少事？

所以 DAU、停留时长这些指标可能会变弱。  
一个好 AI 产品，甚至应该让用户少打开它。

因为它已经自动把事情办好了。

---

##### 5. 最大问题不是 AI 不够强，而是人不知道做什么

现在工具越来越强，编程越来越便宜。  
但新需求、新产品、新商业模式，不会自动出现。

真正稀缺的是：

- 好问题
- 好场景
- 好产品判断
- 好商业想象力

AI 可以放大执行力，但不能自动替代方向感。

---

#### 我的意见

我觉得这篇内容最重要的一句话是：

> AI 毁灭旧价值的速度，快于创造新价值的速度。

短期看，AI 会先带来裁员、降本、工具替代。  
长期看，真正的大机会在于创造新工作流、新产品、新组织方式。

对创业者来说，不要只问：

> 用 AI 做个什么应用？

更应该问：

> 哪个真实问题，因为 AI 的出现，第一次可以被解决？

对普通人来说，最该练的不是“会不会用某个工具”，而是：

- 能不能提出好问题
- 能不能拆解任务
- 能不能设计流程
- 能不能判断结果好坏

未来不是“会用 AI 的人”淘汰“不会用 AI 的人”。  
而是：

> 会指挥 AI 做成事的人，淘汰只会试工具的人。

## 结构化（1）

### 2026-06-01 09:54:05

#### 文章精炼总结

这篇内容总结了张小珺与真格基金戴雨森一场两小时播客的核心观点，重点围绕 AI 行业的商业回报、Agent 形态、创业机会与投资判断展开。戴雨森认为，AI 目前仍处在“投入大于结果”的阶段，真正的机会可能不在复制旧互联网产品，而在 Agent 时代的新基础设施和新工作方式中。

---

##### 一、AI 的 Return 问题并没有真正解决，只是被下推了一层

- Anthropic 收入大涨，让很多人认为 AI 商业回报问题已经解决。
- 戴雨森认为，这只是客户在购买和消耗 token，本质上是“客户的投入”，还不等于最终产生利润。
- 目前很多客户是在“尝鲜”，真正的问题是：
  - 这些 token 是否能帮助客户做出软件？
  - 是否能降本增效？
  - 是否能最终带来利润？
  - 赚钱周期是否足够短？

**核心逻辑：**

> 投入 → 产出 → 结果

现在大家都在拼命投入，产出有所增加，但“产出是否真正转化为结果”还没有被证明。

---

##### 二、Coding 不是垂直领域，而是水平能力

过去很多人把 AI Coding 和医疗、金融等并列，视为一个垂直赛道。

戴雨森认为，这个认知已经发生变化：

- Coding 不是单一垂直场景；
- 它是一种 horizontal capability，即“水平能力”；
- 可以增强办公、医疗、科研、金融等几乎所有领域。

也就是说，AI Coding 的价值不只是“帮程序员写代码”，而是成为所有行业数字化能力的底层增强器。

---

##### 三、Harness 更像操作系统，模型更像 CPU

戴雨森用“操作系统”和“CPU”的关系来解释 AI 应用的新架构：

- 以前做 AI 应用，需要自己处理：
  - agentic loop；
  - memory；
  - guardrail；
  - 上下文管理等。
- 现在在 Claude Code 或 Codex 上做 Skill，很多基础能力都由 harness 处理。

类比来看：

- **Harness 像 OS 操作系统**；
- **模型像 CPU**。

开发者不再需要直接和底层模型或复杂流程打交道，就像 Windows 出现后，开发者不用直接和硬件通信。

更重要的是：

- 用户可以在 harness 中切换模型；
- 哪个便宜用哪个，哪个新用哪个；
- 用户真正沉淀的记忆、context、工作流在 harness 里。

因此，用户对 harness 的忠诚度可能会高于对某个具体模型的忠诚度。

---

##### 四、Agent 网络效应可能正在出现

六个月前，大家使用的可能都是同一个 Claude Code，因此没有太多交换价值。

但现在不同用户的 agent 已经开始沉淀差异化资产，包括：

- 不同的 context；
- 不同的 skills；
- 不同的记忆；
- 不同的任务经验。

这意味着，同一个任务交给不同人的 agent，可能会得到不同结果。

戴雨森提出一种可能性：

> 我的 agent 可以雇佣你的 agent 来完成某件事。

其中费用可能包括两部分：

1. token 成本；
2. 你的 agent 积累的专有知识溢价。

这可能发展成一种 **agent 之间的 marketplace**，即 Agent 市场。

---

##### 五、下一个字节跳动级公司，不会长得像字节跳动

很多人寻找“下一个字节”，会想到做 AI 信息流，让用户不断刷 AI 生成内容。

但戴雨森认为，在字节跳动的规则里打败字节极难。

Agent 时代的关键指标已经发生变化：

- 过去互联网重视 **attention**，也就是用户看屏幕的时长；
- Agent 时代更重要的是：agent 能持续完成有价值任务的时长。

如果一个产品还在追求 DAU、让用户频繁打开来看，反而可能说明它没有真正让用户省心。

新的机会不在“让用户多看”，而在“让用户少操心”。

---

##### 六、AI 毁灭旧价值的速度，快于创造新价值的速度

AI 正在快速带来降本效果，例如裁员、减少人力需求。

但“增效”并不会马上出现，因为它依赖：

- 新产品；
- 新需求；
- 新商业模式；
- 人的想象力。

戴雨森指出，即使工程师能力提升十倍，也不等于收入能立刻增长十倍。

这背后的关键问题是产品创新：

- 移动互联网后期，很多公司已经不知道还能做什么新产品；
- 现在硅谷一些公司因为编程能力过剩，开始互相进入对方领域；
- 但复制已有功能和创造全新品类是两回事。

AI 可以快速降低旧系统成本，但创造新价值仍然需要时间和想象力。

---

##### 七、Agent 落地可能分三步走

戴雨森提出 Agent 落地的三个阶段：

###### 第一步：让人类拥有更多、更好的 Agent

这是当前大多数公司正在做的事情。

例如：

- 编程 Agent；
- 办公 Agent；
- 研究 Agent；
- 客服 Agent。

###### 第二步：让 Agent 更好适应人类数字世界

Agent 需要能处理人类已有互联网系统中的任务，例如：

- 支付；
- 身份验证；
- 登录账号；
- 使用人类软件；
- 操作网页和 App。

###### 第三步：建设 Agent 专属数字基础设施

未来 Agent 之间可能不再按照人类方式协作，而需要新的基础设施，包括：

- Agent 之间的支付；
- Agent 之间的通信；
- Agent 之间的协作协议；
- Agent 专属的市场和身份系统。

这可能是更长期、更底层的创业机会。

---

##### 八、思考和创新也需要刻意练习

戴雨森提到一个个人观察：

- 自己快 40 岁了，感觉想法比 20 岁创业时少了很多；
- 虽然现在有大量 coding agent 可用，但关键问题变成了：到底要让 AI 做什么？

他举了一个朋友的例子：

- 每月花 **1 万美元 token**；
- 做了一个扫描器，检测每天有哪些域名到期没人注册；
- 然后让 AI 基于这些域名自动做产品。

这个方法有点像日料中的 **Omakase**：

> 今天市场上有什么鱼，就用什么鱼做菜。

听起来荒诞，但本质是在训练一种能力：如何用 AI 持续发现机会、生成产品、练习创新。

##### 总结

戴雨森的核心判断是：AI 行业还没有真正完成商业闭环，收入增长不等于客户已经赚到钱；但 AI Coding、Harness、Agent 网络效应和 Agent 基础设施，正在孕育新的平台级机会。

#### 高价值信息提取

##### 1. 一句话判断

> 最值得保留的是：**AI 的价值链正在从“模型能力”转向“harness / agent / context / workflow”，真正的竞争不在谁生成得更好，而在谁能持续完成有价值任务。**

价值评级：**A**

精炼理由：文章不是在复述 AI 热潮，而是在重新定义几个关键判断：**收入不等于回报、Coding 不是垂直赛道、模型可能像 CPU 被抽象掉、Agent 可能形成新市场、AI 产品指标从注意力转向任务完成。**

---

##### 2. 最重要的洞见

###### 洞见 1：AI 的 Return 问题没有解决，只是被下推给客户

###### **核心观点：**  
> Anthropic 收入暴涨，不代表 AI 商业闭环成立；那只是客户把钱先投入进来了，最终还要看客户能不能用 token 赚回利润。

**为什么重要：**  
现在 AI 公司收入增长，很大一部分来自“尝鲜投入”，而不是已经被验证的稳定 ROI。

真正链条是：

> 投入 token → 产出软件 / 效率 → 形成利润结果

目前多数行业只走到第二步，甚至只在第一步狂奔。

**反常识之处：**  
常见判断是：“AI 公司收入增长 = AI 价值已被验证。”  
文章的判断是：“AI 公司收入增长，可能只是客户承担了尚未验证的成本。”

**可迁移价值：**  
判断任何新技术，不要只看供应商收入，要看客户侧是否形成：

- 可衡量收益
- 可持续复购
- 足够短的回本周期
- 不依赖尝鲜预算的刚需

**我应该记住什么：**  
> 技术公司的收入，可能只是客户的成本；客户的利润，才是产业的闭环。

---

###### 洞见 2：Coding 不是垂直应用，而是水平能力

###### **核心观点：**  
> Coding 不应和医疗、金融、办公并列，它更像一种底层生产力，会增强所有行业。

**为什么重要：**  
如果把 Coding 当垂直赛道，容易低估它的扩散能力；如果把它看成水平能力，就会发现它类似“电力”“云计算”“搜索”“数据库”。

它不只是“帮程序员写代码”，而是让每个行业都能更快生成、改造、自动化自己的数字系统。

**反常识之处：**  
常见分类是：

> AI 医疗、AI 金融、AI 教育、AI 编程

但更准确的结构是：

> Coding 能力 × 医疗 / 金融 / 教育 / 办公 / 科研

**可迁移价值：**  
识别一个技术机会时，要区分它是：

- 垂直场景：只能服务某个行业
- 水平能力：能增强所有行业

水平能力通常更容易产生平台级公司。

**我应该记住什么：**  
> 不要按“用户是谁”判断赛道大小，要按“能力能嵌入多少价值链”判断。

---

###### 洞见 3：模型可能像 CPU，harness 更像操作系统

###### **核心观点：**  
> 未来用户未必忠诚于某个模型，而会忠诚于承载记忆、上下文、技能和工作流的 harness。

**为什么重要：**  
模型越来越可替换：哪个便宜用哪个，哪个新用哪个。  
但用户的：

- context
- memory
- skills
- workflow
- agentic loop
- guardrail

会沉淀在 harness 里。

这使得 harness 可能成为真正的用户入口和锁定层。

**反常识之处：**  
常见认知是：“模型最强，模型公司吃掉一切。”  
文章暗示的是：“模型可能被抽象成算力组件，真正的粘性在操作层。”

类似于：

> CPU 很重要，但用户每天感知的是 Windows / macOS / iOS。

**可迁移价值：**  
看 AI 应用时，不只问“调用了什么模型”，更要问：

- 是否沉淀用户上下文？
- 是否管理任务流程？
- 是否积累专属技能？
- 是否能切换底层模型？
- 是否成为用户日常工作入口？

**我应该记住什么：**  
> 模型提供智能，harness 承载关系；关系比单次能力更容易形成护城河。

---

###### 洞见 4：Agent 时代的核心指标，不是用户停留时长，而是任务完成时长

###### **核心观点：**  
> 下一个字节跳动级公司不会长得像字节，因为 Agent 时代不再争夺 attention，而是争夺“持续替用户完成有价值任务”的能力。

**为什么重要：**  
移动互联网的核心指标是：

> DAU、时长、点击、留存、信息流消费

但 Agent 产品的理想状态恰恰是：

> 用户少打开，事情多完成。

如果一个 Agent 产品还在想办法让用户反复打开刷一刷，可能说明它没有真正替用户省心。

**反常识之处：**  
过去互联网产品追求“让用户回来”。  
Agent 产品可能追求“让用户不用回来”。

**可迁移价值：**  
AI 产品的指标体系可能要重写：

| 旧指标 | 新指标 |
|---|---|
| 使用时长 | 任务完成时长 |
| DAU | 被委托任务数 |
| 点击率 | 自动完成率 |
| 内容消费 | 价值交付 |
| 留住注意力 | 释放注意力 |

**我应该记住什么：**  
> AI 产品不是更会吸引人，而是更会替人做事。

---

###### 洞见 5：AI 先毁灭旧价值，再创造新价值

###### **核心观点：**  
> AI 降本很快，但增效很慢；因为裁员可以立刻发生，新需求和新品类却需要想象力。

**为什么重要：**  
很多人以为 AI 能力提升后，收入会同步增长。  
但现实可能是：

- 旧岗位先被压缩
- 旧流程先被自动化
- 旧产品先被复制
- 新品类却迟迟没有出现

生产力提升不自动等于商业创新。

**反常识之处：**  
常见说法是：“有了十倍工程师，就会有十倍产品。”  
文章指出：“工程能力过剩，不等于想象力过剩。”

**可迁移价值：**  
企业采用 AI 时，要分清两类收益：

1. **降本型收益**：自动化、裁员、提效  
2. **增收型收益**：新品类、新需求、新商业模式

前者快，后者慢；前者确定，后者依赖创造力。

**我应该记住什么：**  
> AI 放大执行力，但不自动生成方向感。

---

##### 3. 底层逻辑

###### **逻辑一：收入增长 ≠ 价值闭环**

- 表层现象：AI 公司收入快速增长，客户大量购买 token。
- 深层原因：大量客户仍处于试验、尝鲜、抢占窗口期阶段。
- 推导结论：真正判断 AI 商业化，要看客户是否通过 AI 获得可持续利润，而不是看模型厂商短期营收。

---

###### **逻辑二：真正的护城河从“能力层”迁移到“上下文层”**

- 表层现象：模型不断升级，用户可在不同模型之间切换。
- 深层原因：底层模型趋向商品化，但用户记忆、上下文、技能和工作流难以迁移。
- 推导结论：未来更强的入口可能不是模型本身，而是管理 agent、context、workflow 的 harness。

---

###### **逻辑三：Agent 改变产品评价标准**

- 表层现象：传统互联网用时长、DAU、点击衡量成功。
- 深层原因：传统产品靠占用注意力创造商业价值，Agent 产品靠替用户完成任务创造价值。
- 推导结论：Agent 时代的优秀产品，可能不是让用户更沉迷，而是让用户更少操心。
