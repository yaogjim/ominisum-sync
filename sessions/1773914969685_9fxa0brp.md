##### Prerequisites

- **Node.js 22+** — [nodejs.org](https://nodejs.org/)
- **Python 3.11+** — [python.org](https://www.python.org/)
- **Hermes Agent (with WebAPI)** — see below

> **⚠️ Important:** Hermes Workspace requires the **WebAPI backend** (`hermes webapi`), which provides the FastAPI server with session management, chat streaming, skills, and memory endpoints. The upstream NousResearch/hermes-agent does not include this yet — use our fork which adds the WebAPI layer.

```
# Clone the fork with WebAPI support
git clone https://github.com/outsourc-e/hermes-agent.git
cd hermes-agent
python -m venv .venv
source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -e .

# Run the interactive setup (configures your API keys)
hermes setup

# Start the WebAPI server on port 8642
hermes webapi
# Or manually: uvicorn webapi.app:app --host 0.0.0.0 --port 8642
```

> **Using upstream hermes-agent?** The workspace will still load — it auto-detects which API endpoints your gateway supports and gracefully disables features that aren't available. You'll see a log message listing which APIs are missing. For full functionality (chat, sessions, skills, memory), use our fork.

> **API keys:** Hermes supports Anthropic (Claude), OpenAI, OpenRouter, and local models via Ollama. Run `hermes setup` to configure your provider, or set `ANTHROPIC_API_KEY` / `OPENAI_API_KEY` in `~/.hermes/.env`.

```
# In a new terminal
git clone https://github.com/outsourc-e/hermes-workspace.git
cd hermes-workspace
pnpm install
cp .env.example .env
printf '\nHERMES_API_URL=http://127.0.0.1:8642\n' >> .env
pnpm dev                   # Starts on http://localhost:3000
```

> **Verify:** Open `http://localhost:3000` — you should see the chat interface. If you get connection errors, make sure Hermes Agent is running on port 8642 (`curl http://localhost:8642/health` should return `{"status": "ok"}`).

##### Environment Variables

```
# Anthropic key for Hermes Agent (optional for demo mode, required for chat)
ANTHROPIC_API_KEY=your-key-here

# Hermes FastAPI backend URL
HERMES_API_URL=http://127.0.0.1:8642

# Optional: password-protect the web UI
# HERMES_PASSWORD=your_password
```

1. Open Hermes Workspace in **Chrome** or **Edge** at `http://localhost:3000`
2. Click the **install icon** (⊕) in the address bar
3. Click **Install** — Hermes Workspace opens as a standalone desktop app
4. Pin to Dock / Taskbar for quick access

> **macOS users:** After installing, you can also add it to your Launchpad.

1. Open Hermes Workspace in **Safari** on your iPhone
2. Tap the **Share** button (□↑)
3. Scroll down and tap **"Add to Home Screen"**
4. Tap **Add** — the Hermes Workspace icon appears on your home screen
5. Launch from home screen for the full native app experience

##### 🤖 Android

1. Open Hermes Workspace in **Chrome** on your Android device
2. Tap the **three-dot menu** (⋮) → **"Add to Home screen"**
3. Tap **Add** — Hermes Workspace is now a native-feeling app on your device

##### Setup

1. **Install Tailscale** on your Mac and mobile device:
   - Mac: [tailscale.com/download](https://tailscale.com/download)
   - iPhone/Android: Search "Tailscale" in the App Store / Play Store
2. **Sign in** to the same Tailscale account on both devices
3. **Find your Mac's Tailscale IP:**
   ```
   tailscale ip -4
   # Example output: 100.x.x.x
   ```
4. **Open Hermes Workspace on your phone:**
   ```
   http://100.x.x.x:3000
   ```
5. **Add to Home Screen** using the steps above for the full app experience

> 💡 Tailscale works over any network — home wifi, mobile data, even across countries. Your traffic stays end-to-end encrypted.

#### 🔧 Troubleshooting

The workspace auto-detects your gateway's capabilities on startup. Check your terminal for a line like:

```
[gateway] http://127.0.0.1:8642 available: health, models; missing: sessions, skills, memory, config, jobs
[gateway] Missing Hermes APIs detected. Update Hermes: cd hermes-agent && git pull && pip install -e . && hermes gateway
```

**Fix:** You need the WebAPI backend. Use our fork:

```
git clone https://github.com/outsourc-e/hermes-agent.git
cd hermes-agent && pip install -e . && hermes webapi
```

Your Hermes gateway isn't running. Start it:

```
cd hermes-agent
source .venv/bin/activate
hermes webapi
```

Verify: `curl http://localhost:8642/health` should return `{"status": "ok"}`.

The upstream hermes-agent doesn't include the WebAPI server yet. The workspace will load but with limited functionality. For full features, switch to our fork (`outsourc-e/hermes-agent`).

## 结构化（1）

### 2026-03-19 10:09:29

这篇文章主要介绍了`Hermes Workspace`这个开源项目：它不是普通的聊天界面，而是一个把聊天、文件、终端、记忆、技能管理整合在一起的 AI 代理工作台。文章重点说明了它的核心功能、安装方式、适用场景、移动端体验、安全设计，以及后续开发路线。

- **1. 项目定位：一个 “AI 代理指挥中心”**
  - `Hermes Workspace`的目标，是把 AI 代理使用过程中常见的几个入口整合到一个界面里，包括聊天、文件浏览、终端操作、记忆管理和技能查看。
  - 作者特别强调：它 “不是一个聊天壳子”，而是一个完整工作空间，适合用来统一调度和管理 AI Agent。
  - 这个项目来自`Nous Research hackathon`，当前已开源，并且仓库已有`1,276`次提交，说明迭代比较活跃。

- **2. 核心功能：覆盖 Agent 使用全流程**
  - **聊天能力**：支持和 Hermes Agent 直接连接，通过 FastAPI 后端实现实时`SSE`流式输出，还能渲染工具调用结果。
  - **多会话管理**：支持多 session 历史记录，消息按时间顺序整理，并带去重合并能力。
  - **文件与终端**：内置文件浏览器和完整 PTY 终端，可直接进入工作区操作文件，编辑器还集成了`Monaco editor`。
  - **记忆与技能**：
    - 可浏览、搜索、编辑 agent memory；
    - 可查看超过`2,000+ skills`，并按 session 管理技能。
  - **检查面板（Inspector）**：可查看 session 活动、memory 和 skills，方便理解 Agent 当前状态。

- **3. 界面与体验：强调 “原生感”**
  - 项目提供`8`套主题：`Official`、`Classic`、`Slate`、`Mono`，每套都有亮色和暗色版本。
  - 主题会跨 session 持久保存，移动端暗黑模式也完整支持。
  - 它还是一个`PWA（渐进式 Web 应用）`，安装后可以像原生应用一样运行：
    - 桌面端可去掉浏览器边框；
    - 支持快捷键；
    - 支持离线能力；
    - 可以固定到 Dock / 任务栏。
  - 文章给了具体安装方式：
    - **Chrome / Edge 桌面端**：点击地址栏安装图标；
    - **iPhone Safari**：通过 “分享”→“添加到主屏幕”；
    - **Android Chrome**：通过菜单→“添加到主屏幕”。

- **4. 技术依赖与运行前提：核心是 WebAPI 后端**
  - 使用这个工作台需要：
    - `Node.js 22+`
    - `Python 3.11+`
    - Hermes Agent 的`WebAPI`后端
  - 这里有一个非常重要的限制：上游官方`NousResearch/hermes-agent` **暂时不包含**这个 WebAPI 层。
  - 因此，作者建议使用他们自己的分支：`outsourc-e/hermes-agent`，它增加了 FastAPI 服务、session 管理、聊天流、skills 和 memory 接口。
  - 如果用户坚持使用上游版，也不是完全不能用：
    - 前端仍然能启动；
    - 系统会自动检测哪些 API 可用；
    - 缺失的功能会被 “优雅降级” 关闭。
  - 但如果想要完整体验聊天、session、skills、memory，还是必须用作者 fork 的版本。

- **5. 安装方式：本地开发和 Docker 两种路径**
  - **本地方式**
    - 先安装并启动 Hermes Agent WebAPI：
      - 克隆`outsourc-e/hermes-agent`
      - 创建虚拟环境
      - `pip install -e .`
      - 运行`hermes setup`
      - 再执行`hermes webapi`
    - 默认后端端口是`8642`
    - 然后启动前端：
      - 克隆`outsourc-e/hermes-workspace`
      - `pnpm install`
      - 复制`.env.example`到`.env`
      - 加入`HERMES_API_URL=http://127.0.0.1:8642`
      - `pnpm dev`
    - 前端默认运行在`http://localhost:3000`
  - **验证方式**
    - 打开`http://localhost:3000`，应该能看到聊天界面；
    - 如果报连接错误，可用`curl http://localhost:8642/health`检查后端；
    - 正常返回应为`{"status":"ok"}`
  - **Docker 方式**
    - 只需：
      - 克隆仓库
      - 复制`.env.example`
      - `docker compose up`
    - 然后访问`http://localhost:3000`
  - 文章还说明：支持多种模型提供商，包括`Anthropic`、`OpenAI`、`OpenRouter`，以及本地`Ollama`。

- **6. 环境变量与模型支持：配置比较灵活**
  - 关键环境变量包括：
    - `ANTHROPIC_API_KEY`
    - `HERMES_API_URL=http://127.0.0.1:8642`
    - 可选的`HERMES_PASSWORD`
  - 如果用 Hermes Agent，可通过`hermes setup`配置 API key。
  - 也可以直接在`~/.hermes/.env`中设置，如：
    - `ANTHROPIC_API_KEY`
    - `OPENAI_API_KEY`
  - 本地模型场景下，使用`Ollama`时甚至可以不需要云端 key。

- **7. 移动访问方案：通过 Tailscale 实现 “随时连回家里的 Agent”**
  - 文章非常强调移动端使用体验，提出了一个具体方案：用`Tailscale`访问本机上运行的 Hermes Workspace。
  - 操作步骤大致是：
    - 在 Mac 和手机都安装 Tailscale；
    - 用同一个账号登录；
    - 在 Mac 上运行`tailscale ip -4`获取内网地址；
    - 然后在手机上访问`http://100.x.x.x:3000`
  - 作者给出的优势是：
    - 不需要端口转发；
    - 不用复杂 VPN 配置；
    - 可跨 Wi-Fi、蜂窝网络甚至跨国家访问；
    - 流量是端到端加密的。
  - 这部分说明项目不仅适合桌面，也考虑了 “移动设备远程操控 Agent” 的真实使用场景。

- **8. 安全设计：并不是只顾功能**
  - 文章专门列出了一组安全能力，说明作者对这个 “可执行终端 + 文件访问” 的产品风险有考虑：
    - 所有 API 路由都加了认证中间件；
    - 使用`CSP headers`限制内容安全；
    - 文件和 memory 路由做了路径穿越防护；
    - 接口有速率限制；
    - Web UI 可选密码保护；
    - 执行操作前还有 approval prompt（批准提示）。
  - 对于一个带终端、文件系统和 Agent 执行能力的工作台来说，这些安全设计是非常关键的。

## 解读（1）

### 2026-03-19 10:31:43

#### 总结

`Hermes Workspace`是一个给`Hermes Agent`配套的原生 Web 工作台，目标不是单纯 “聊天界面”，而是把**聊天、文件、终端、记忆库、技能管理、检查面板**集成到一个统一界面里。

它的核心特点是：

- 直接连接`Hermes Agent`的后端，支持实时流式输出
- 提供完整工作区能力：聊天、文件浏览编辑、终端、记忆、技能
- 支持`PWA`，可在电脑和手机上像本地应用一样使用
- 有较完整的安全设计，如鉴权、中间件、路径防护、限流等
- 目前已开源，桌面版和云版本还在开发中

不过，它**依赖一个带 WebAPI 的 Hermes Agent 分支**。如果只用官方上游版，界面虽然能打开，但很多功能会被自动降级或禁用。

---

#### 解读

##### 这东西本质上是什么？

可以把它理解成：

> **给 AI Agent 用的 “控制台” 或 “作战中心”**

普通 AI 工具通常只有一个聊天框，但这个项目想做的是一个完整操作台。你不只是和 AI 对话，还可以：

- 看它当前会话和历史
- 管理技能库
- 查看和编辑记忆内容
- 浏览工作目录和文件
- 直接开终端执行任务

所以它更像一个**Agent IDE / Agent 操作系统前端**，而不是普通聊天产品。

##### 它适合谁？

比较适合这几类人：

- 想长期把 AI Agent 当生产工具的人
- 需要在一个界面里同时处理聊天、代码、文件、终端的人
- 希望手机上也能管理本地 Agent 的用户
- 喜欢折腾本地部署、工作流自动化、智能体开发的人

如果你只是偶尔和模型聊聊天，这个项目就显得有点 “重”。

##### 它最大的亮点

###### 1. 不只是聊天，而是完整工作区
这是它和很多 AI Web UI 最大的区别。  
它把 Agent 的常用能力都聚合了，减少来回切换工具的成本。

###### 2. 移动端支持很认真
它不是简单做个响应式页面，而是明确按`PWA + Tailscale`的思路来做，想让你在手机上也能像本地 App 一样使用。

这点很实用：  
你可以在外面直接从手机访问家里 / 电脑上的 Agent。

###### 3. 对 “工程化使用” 考虑较多
比如：

- SSE 实时输出
- 多会话
- 技能和记忆管理
- 文件编辑器和终端
- 安全防护
- Docker / Codespaces 支持

说明它不是演示玩具，而是往 “可日常使用” 方向走。

##### 它的门槛和限制

###### 1. 依赖特定后端分支
这是最现实的问题。  
它强调必须配合`outsourc-e/hermes-agent`这个带 WebAPI 的 fork，官方上游暂时还不完整。

通俗说就是：

- 前端做得不错
- 但你要想 “满血运行”，后端得用作者的定制版本

这会提高使用门槛，也带来一点生态分裂风险。

###### 2. 还在开发中
虽然很多功能已经 “Shipped”，但桌面版、云端版、模型切换、取消任务等还没完全成熟。

所以它目前更像：

> **一个很有潜力、已经能用，但仍在快速迭代的项目**

###### 3. 更偏进阶用户
安装过程涉及：

- Node.js
- Python
- 虚拟环境
- Hermes 配置
- API Key
- WebAPI 服务
- Docker / Tailscale（可选）

这对开发者还好，但对普通用户并不友好。

---

#### 我的意见

这是一个**方向很对、定位很清晰、完成度也不低**的项目。

我认为它最有价值的地方，不是 “又一个 AI 聊天页”，而是它在认真回答一个问题：

> **如果 AI Agent 真的成为日常工作伙伴，界面应该长什么样？**

从这个角度看，它做得挺有想法，尤其是把聊天、文件、终端、记忆、技能整合起来，非常像真正的 “Agent 工作台”。

但也要客观看：

- 它目前更适合开发者和重度玩家
- 真正普及还需要降低部署复杂度
- 对定制后端分支的依赖，是现阶段最大门槛之一

一句话评价：

> **这是一个很像 “未来 AI Agent 操作台雏形” 的项目，实用性强，野心也大，但现阶段更适合技术用户。**

如果你关注本地 Agent、AI 工作流、个人智能中控台，这个项目值得重点看看。
