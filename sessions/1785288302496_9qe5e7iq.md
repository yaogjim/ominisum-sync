## 正文

[Ruff v0.16.0](https://github.com/astral-sh/ruff) is available now! Install it from [PyPI](https://pypi.org/project/ruff/), or with your package manager of choice:

```
uv tool install ruff@latest
```

As a reminder: **Ruff is an extremely fast Python linter and formatter, written in Rust.** Ruff can be used to replace Black, Flake8 (plus dozens of plugins), isort, pydocstyle, pyupgrade, and more, all while executing tens or hundreds of times faster than any individual tool.

#### Migrating to v0.16 #

Ruff v0.16 has a small number of breaking changes, allowing most users to update without significant changes to code or configuration. The main exception is described below.

##### Better default rule set #

Ruff now enables 413 rules by default, up from 59 in previous versions.

Since Ruff's default rule set was last modified in [v0.1.0](https://github.com/astral-sh/ruff/blob/main/changelogs/0.1.x.md#breaking-changes), the number of rules in Ruff has grown from 708 to 968. Many of these rules catch severe issues, including [syntax errors](https://docs.astral.sh/ruff/rules/load-before-global-declaration) and [immediate runtime errors](https://docs.astral.sh/ruff/rules/yield-in-init/) but were not previously enabled by default. With the new rule set, Ruff will bring these issues and many others to your attention without any Ruff configuration. Even if you're already using [`select`](https://docs.astral.sh/ruff/settings/#lint_select) or [`extend-select`](https://docs.astral.sh/ruff/settings/#lint_extend-select), we hope that this will draw your attention to helpful rules that you previously hadn't discovered.

The full listing of enabled rules is too long to include here, but you can find it on our new [Default Rules](https://docs.astral.sh/ruff/default-rules/) page in the documentation. A few of the highlights include rules from the popular flake8-bugbear (`B`) and pyupgrade (`UP`) linters, as well as rules from our own `RUF` category.

Note that this is primarily an expansion, but 18 of the more opinionated pycodestyle (`E`) and pyflakes (`F`) rules have been removed from the default set: `E401`, `E402`, `E701`, `E702`, `E703`, `E711`, `E712`, `E713`, `E714`, `E721`, `E731`, `E741`, `E742`, `E743`, `F403`, `F405`, `F406`, and `F722`.

If you want to revert to the old default set, you can easily `select` the old rules with this configuration:

```
[lint]
select = ["E4", "E7", "E9", "F"]
```

We view this work as closely tied to our longstanding goal of [rule recategorization](https://github.com/astral-sh/ruff/issues/1774), so look forward to upcoming developments in this area.

#### New features in v0.16 #

Ruff v0.16 also includes several newly stabilized features that are highlighted below.

##### Markdown code block formatting #

Ruff can now format Python code blocks embedded in Markdown files.

In these files, Ruff v0.16 will format [fenced code blocks](https://spec.commonmark.org/0.30/#fenced-code-blocks) with a `python`, `py`, `python3`, `py3`, `pyi`, or `pycon` [info string](https://spec.commonmark.org/0.30/#info-string). `pyi` blocks are formatted like stub files, `pycon` blocks as REPL sessions, and the others use normal Python file formatting. For example:

````
# README

Here's an example:

```py
import ruff

ruff_binary = (
    ruff.find_ruff_bin()
)
```
````

will be reformatted when running `ruff format`:

![Ruff formatter output showing a Markdown code block that would be reformatted](https://astral.sh/static/PNG/Ruff_v_0_16_0_format_markdown.png)

This can also be used to format [Quarto](https://quarto.org/) notebooks because Ruff still recognizes the language when surrounded by curly braces (e.g. ```` ```{python} ````). Note that you may need to configure your [`extension`](https://docs.astral.sh/ruff/settings/#extension) mapping if your Quarto files use the `.qmd` extension.

If you need to suppress formatting, you have several options. If you want the suppression comments to appear in the code block, you can use normal `fmt: off` and `fmt: on` comments within the code block itself, or you can use similar HTML comments to disable formatting for a whole region of the document:

````
# README

<!-- fmt: off -->

```py
x =      "this will be suppressed"
```

<!-- fmt: on -->
````

To suppress Markdown formatting entirely, you can use the normal [`extend-exclude`](https://docs.astral.sh/ruff/settings/#extend-exclude) setting to exclude all Markdown files with a glob like `*.md`.

See the [full documentation](https://docs.astral.sh/ruff/formatter/#markdown-code-formatting) for more details.

##### `ruff: ignore` comments offer new suppression features #

Ruff now has its own suppression comment format that can be used on its own line.

In v0.15, the Ruff linter gained a range suppression mechanism through paired `ruff: disable` and `ruff: enable` comments, much like the `fmt: off` and `fmt: on` pair described above:

```
# ruff: disable[N803]
def foo(
    legacyArg1,
    legacyArg2,
    legacyArg3,
    legacyArg4,
): ...
# ruff: enable[N803]
```

Ruff v0.16 builds on this to add two additional `ruff` suppression comments. `ruff: ignore` can be used to suppress a diagnostic on the same line, like `noqa`, or on the following logical line:

```
import math  # ruff: ignore[F401]

# ruff: ignore[N803]
def foo(
    legacyArg1,
    legacyArg2,
    legacyArg3,
    legacyArg4,
): ...
```

In this case, the logical line spans the whole function header (from `def` to the colon), so the `ruff: ignore` suppresses all of the same [`N803`](https://docs.astral.sh/ruff/rules/invalid-argument-name/) diagnostics as the `disable`/`enable` pair above.

`ruff: file-ignore` comments can be used to suppress diagnostics for the entire file, just like `ruff: noqa` comments:

```
# ruff: file-ignore[F401] Allow unused imports in this file

import foo
import bar
import baz
```

As this example also shows, each of these comment kinds can have an associated "reason" explaining why they were added, in this case `Allow unused imports in this file`.

`ruff: ignore` comments can be added automatically with the new `--add-ignore` CLI flag, and in [preview](https://docs.astral.sh/ruff/preview/), all of these `ruff` suppression comments support rule names instead of codes:

```
❯ echo 'import math' > try.py
❯ uvx ruff@latest check --preview --add-ignore try.py
Added 1 ignore comment.
❯ cat try.py
import math  # ruff: ignore[unused-import]
```

You can find the full specification for all of these comments in the [documentation](https://docs.astral.sh/ruff/linter/#comments).

##### Fixes are now shown in `check` and `format --check` output #

Ruff now shows the diff for linter and formatter fixes when rendering diagnostics.

Both the `check` and `format` subcommands have long supported the `--diff` flag for showing the changes introduced by applying fixes with `check --fix` or `format`, but this was separate from the normal output and suppressed the accompanying explanatory diagnostics. In v0.16, available fixes are now shown as part of the default `full` output format, rendered below the `help` subdiagnostic:

![Ruff check output showing the diff for an unused-import fix](https://astral.sh/static/PNG/Ruff_v_0_16_0_check_fixes.png)

The same is true for `format --check`. Given the following input:

```
# example.py

if True:
    pass
elif     False:
    pass
```

The formatter produces:

![Ruff formatter output showing the diff for an unformatted file](https://astral.sh/static/PNG/Ruff_v_0_16_0_format_fixes.png)

`format --check` also now supports the full selection of output formats supported by the linter. You can use this to obtain machine-readable JSON output or produce the formats expected by GitHub and GitLab to render annotations in CI, as just a couple of examples. See the CLI help or [documentation](https://docs.astral.sh/ruff/settings/#output-format) for the full list of supported formats.

One final note on output formats is that there is a small breaking change to the JSON output in v0.16. The `filename`, `location`, `end_location`, `fix.edits[].location`, and `fix.edits[].end_location` fields may now be `null` rather than defaulting to the empty string and row 1, column 1, respectively. This should affect very few of Ruff's existing diagnostics but better reflects the internal diagnostic representation and may become more common in future rules.

#### Rule stabilizations #

The following rules have been stabilized and are no longer in [preview](https://docs.astral.sh/ruff/preview/):

- [`airflow3-incompatible-function-signature`](https://docs.astral.sh/ruff/rules/airflow3-incompatible-function-signature) (`AIR303`)
- [`missing-copyright-notice`](https://docs.astral.sh/ruff/rules/missing-copyright-notice) (`CPY001`)
- [`unnecessary-from-float`](https://docs.astral.sh/ruff/rules/unnecessary-from-float) (`FURB164`)
- [`sorted-min-max`](https://docs.astral.sh/ruff/rules/sorted-min-max) (`FURB192`)
- [`implicit-string-concatenation-in-collection-literal`](https://docs.astral.sh/ruff/rules/implicit-string-concatenation-in-collection-literal) (`ISC004`)
- [`log-exception-outside-except-handler`](https://docs.astral.sh/ruff/rules/log-exception-outside-except-handler) (`LOG004`)
- [`invalid-bool-return-type`](https://docs.astral.sh/ruff/rules/invalid-bool-return-type) (`PLE0304`)
- [`too-many-positional-arguments`](https://docs.astral.sh/ruff/rules/too-many-positional-arguments) (`PLR0917`)
- [`stop-iteration-return`](https://docs.astral.sh/ruff/rules/stop-iteration-return) (`PLR1708`)
- [`none-not-at-end-of-union`](https://docs.astral.sh/ruff/rules/none-not-at-end-of-union) (`RUF036`)
- [`access-annotations-from-class-dict`](https://docs.astral.sh/ruff/rules/access-annotations-from-class-dict) (`RUF063`)
- [`duplicate-entry-in-dunder-all`](https://docs.astral.sh/ruff/rules/duplicate-entry-in-dunder-all) (`RUF068`)

#### Other behavior stabilizations #

This release also stabilizes some additional behavior, previously only available in [preview mode](https://docs.astral.sh/ruff/preview/):

- [`blind-except`](https://docs.astral.sh/ruff/rules/blind-except) (`BLE001`) is now suppressed when the exception is logged via `logging` methods other than `critical`, `error` and `exception`.
- [`future-required-type-annotation`](https://docs.astral.sh/ruff/rules/future-required-type-annotation) (`FA102`) now checks for additional [PEP 585](https://peps.python.org/pep-0585/)-compatible APIs, such as those from `collections.abc`.
- [`f-string-in-get-text-func-call`](https://docs.astral.sh/ruff/rules/f-string-in-get-text-func-call) (`INT001`), [`format-in-get-text-func-call`](https://docs.astral.sh/ruff/rules/format-in-get-text-func-call) (`INT002`), and [`printf-in-get-text-func-call`](https://docs.astral.sh/ruff/rules/printf-in-get-text-func-call) (`INT003`) now check for additional common ways of using the `gettext` module, such as assigning it to `builtins._`.
- [`suspicious-url-open-usage`](https://docs.astral.sh/ruff/rules/suspicious-url-open-usage) (`S310`) now resolves local string literal bindings to avoid more false positives.
- [`snmp-insecure-version`](https://docs.astral.sh/ruff/rules/snmp-insecure-version) (`S508`) and [`snmp-weak-cryptography`](https://docs.astral.sh/ruff/rules/snmp-weak-cryptography) (`S509`) now support the recommended API from newer versions of PySNMP.
- [`typing-text-str-alias`](https://docs.astral.sh/ruff/rules/typing-text-str-alias) (`UP019`) now recognizes `typing_extensions.Text` in addition to `typing.Text`.

#### Ruff v0.16.0：默认规则扩展，Markdown 格式化与诊断能力增强

##### 版本概览

Ruff v0.16.0 正式发布。Ruff 是使用 Rust 编写的高性能 Python Linter 和 Formatter，可替代 Black、Flake8、isort、pyupgrade、pydocstyle 等多种工具，执行速度通常快几十到数百倍。

可通过以下方式安装：

```bash
uv tool install ruff@latest
```

##### 一、默认检查规则大幅增加

###### 默认启用规则从 59 条增至 413 条

Ruff 当前总规则数已从 708 条增长至 968 条。v0.16.0 将更多此前未默认启用、但可能发现严重问题的规则加入默认规则集，例如：

- `flake8-bugbear` 规则
- `pyupgrade` 规则
- Ruff 自有的 `RUF` 规则
- 语法错误和潜在运行时错误检查

这意味着很多项目无需额外配置，就能发现更多问题。

###### 部分规则被移出默认集合

为了减少过于主观或风格化的检查，18 条 `pycodestyle` 和 `pyflakes` 规则不再默认启用，包括部分：

- 不必要的分号或语句拆分检查
- 布尔值比较检查
- 通配符导入检查
- 变量命名相关检查

如果希望恢复旧版默认规则集，可配置：

```toml
[lint]
select = ["E4", "E7", "E9", "F"]
```

> 对大多数用户而言，升级不会带来大量代码或配置改动，但 CI 中可能出现更多新的诊断结果，建议升级后重新检查项目。

##### 二、Markdown 代码块格式化

Ruff 现在可以格式化 Markdown 文件中的 Python 代码块，支持以下标记：

- `python`
- `py`
- `python3`
- `py3`
- `pyi`
- `pycon`

不同类型会采用对应格式：

- `pyi`：按 Python 类型存根文件格式化
- `pycon`：按 Python REPL 会话格式化
- 其他标记：按普通 Python 文件格式化

这也支持 Quarto Notebook，例如：

````markdown
```{python}
import ruff
```
````

如需关闭格式化，可以使用：

```python
# fmt: off
...
# fmt: on
```

或在 Markdown 中使用：

```html
<!-- fmt: off -->
...
<!-- fmt: on -->
```

也可以通过 `extend-exclude` 排除所有 Markdown 文件。

##### 三、新增更灵活的忽略注释

Ruff v0.16 增加了专属的诊断抑制注释：

###### 1. 忽略一段代码

```python
# ruff: disable[N803]
def foo(legacy_arg):
    ...
# ruff: enable[N803]
```

###### 2. 忽略当前行或下一条逻辑语句

```python
import math  # ruff: ignore[F401]
```

也可以忽略下一条逻辑语句：

```python
# ruff: ignore[N803]
def foo(legacy_arg):
    ...
```

###### 3. 忽略整个文件

```python
# ruff: file-ignore[F401] 允许本文件存在未使用导入
```

###### 4. 自动生成忽略注释

新增 CLI 参数：

```bash
ruff check --preview --add-ignore try.py
```

在 Preview 模式下，这些注释还可以使用规则名称，而不仅是规则编号：

```python
import math  # ruff: ignore[unused-import]
```

##### 四、修复结果直接显示在诊断输出中

以前需要显式使用 `--diff` 才能查看 Ruff 的修复内容。现在：

- `ruff check` 默认输出中会展示可用修复
- `ruff format --check` 也会显示格式修复差异
- `format --check` 支持与 Linter 相同的多种输出格式
- 支持 JSON、GitHub、GitLab 等适合 CI 的输出格式

###### JSON 输出存在兼容性变化

v0.16.0 中，以下 JSON 字段可能返回 `null`，不再默认返回空字符串或第 1 行第 1 列：

- `filename`
- `location`
- `end_location`
- `fix.edits[].location`
- `fix.edits[].end_location`

依赖 Ruff JSON 输出的工具需要确认是否能正确处理 `null`。

##### 五、更多规则正式稳定

以下规则不再处于 Preview 状态，正式成为稳定规则，覆盖：

- Airflow 函数签名兼容性
- 版权声明缺失
- 不必要的浮点转换
- `min`/`max` 排序问题
- 集合字面量中的隐式字符串拼接
- 异常日志记录位置
- 布尔返回类型
- 位置参数过多
- `StopIteration` 返回问题
- Union 类型定义问题
- 类字典中的类型注解
- `__all__` 重复项

此外，多个既有规则的行为也完成稳定化，例如：

- 更准确地识别异常日志记录
- 扩展 PEP 585 类型检查范围
- 改进 gettext 调用识别
- 减少 URL 检查误报
- 支持新版 PySNMP API
- 更好识别 `typing_extensions.Text`

##### 总结

Ruff v0.16.0 的核心变化可以概括为：

1. **默认检查更严格**：默认规则从 59 条增加到 413 条，能发现更多潜在问题。
2. **文档工程能力增强**：支持格式化 Markdown 和 Quarto 中的 Python 代码。
3. **忽略机制更完善**：支持按行、按逻辑语句、按代码范围或按文件忽略问题。
4. **修复反馈更直观**：诊断输出直接展示自动修复内容，并增强 CI 输出支持。
5. **升级需关注兼容性**：主要风险是新增默认规则带来的新告警，以及 JSON 输出中的 `null` 字段变化。

## 结构化（1）

### 2026-07-30 09:21:27

#### Ruff v0.16.0 精炼总结

Ruff v0.16.0 已正式发布，重点是**大幅扩充默认检查规则**，并加入 Markdown 代码块格式化、新的诊断抑制注释、修复差异展示等功能。此次升级只有少量破坏性变更，大多数用户无需大幅修改代码或配置。

##### 1. 发布与升级概况

- Ruff 是一个使用 Rust 编写的高性能 Python 检查器和格式化工具，可替代 Black、Flake8 及其插件、isort、pydocstyle、pyupgrade 等工具。
- 其执行速度通常比上述单个工具快数十倍甚至数百倍。
- 可从 PyPI 安装，也可使用以下命令安装最新版：

```bash
uv tool install ruff@latest
```

- v0.16 仅有少量破坏性变更，主要影响来自默认规则集调整，以及 JSON 输出字段的变化。

##### 2. 默认规则从 59 条扩展到 413 条

这是 v0.16 最重要的变化：

- 默认启用规则由此前的 **59 条增加到 413 条**。
- 自 v0.1.0 上次调整默认规则以来，Ruff 的规则总数已经从 **708 条增长到 968 条**。
- 新默认规则可以发现更多严重问题，包括：
  - Python 语法错误；
  - 代码运行后会立即触发的错误；
  - 来自 `flake8-bugbear`（`B`）、`pyupgrade`（`UP`）以及 Ruff 自有分类（`RUF`）的常用规则。
- 即使项目已经配置了 `select` 或 `extend-select`，此次调整也有助于发现过去未关注的规则。

###### 移出默认集的规则

此次调整以扩充为主，但以下 **18 条较具主观性的 `pycodestyle`（E）和 `pyflakes`（F）规则**不再默认启用：

```text
E401, E402, E701, E702, E703,
E711, E712, E713, E714, E721,
E731, E741, E742, E743,
F403, F405, F406, F722
```

###### 如何恢复旧版默认规则

如果希望继续使用原来的默认规则集，可配置：

```toml
[lint]
select = ["E4", "E7", "E9", "F"]
```

这一变化也与 Ruff 长期推进的“规则重新分类”工作相关，后续还会继续调整。

##### 3. 支持格式化 Markdown 中的 Python 代码块

Ruff 现在可以格式化 Markdown 文件内的 Python 围栏代码块，支持以下语言标识：

```text
python、py、python3、py3、pyi、pycon
```

不同代码块的处理方式如下：

- `pyi`：按 Python 类型存根文件格式化；
- `pycon`：按 Python REPL 会话格式化；
- 其他标识：按普通 Python 文件格式化。

例如，Markdown 中格式混乱的代码：

````markdown
```py
import ruff
ruff_binary = ( ruff.find_ruff_bin()
)
```
````

执行 `ruff format` 后，会按正常 Python 风格重新排版。

###### 支持 Quarto

- Ruff 也能识别带花括号的语言标记，例如：

````markdown
```{python}
...
```
````

- 因此可以用于格式化 Quarto 文档。
- 如果 Quarto 文件使用 `.qmd` 扩展名，可能需要配置 Ruff 的扩展名映射。

###### 禁止格式化的方法

可以在代码块内部使用：

```python
# fmt: off
x = "this will be suppressed"
# fmt: on
```

也可以在 Markdown 中用 HTML 注释禁用一整段：

````markdown
<!-- fmt: off -->

```py
x = "this will be suppressed"
```

<!-- fmt: on -->
````

如果希望完全不格式化 Markdown 文件，可通过 `extend-exclude` 排除：

```toml
extend-exclude = ["*.md"]
```

##### 4. 新增 `ruff: ignore` 系列抑制注释

Ruff v0.15 已支持使用成对注释关闭和恢复指定规则：

```python
# ruff: disable[N803]
def foo(
    legacyArg1,
    legacyArg2,
):
    ...
# ruff: enable[N803]
```

v0.16 在此基础上新增两种抑制方式。

###### `ruff: ignore`

用于忽略当前行或下一条“逻辑行”的诊断，作用类似 `noqa`：

```python
import math  # ruff: ignore[F401]
```

也可以单独放在待检查代码之前：

```python
# ruff: ignore[N803]
def foo(
    legacyArg1,
    legacyArg2,
    legacyArg3,
):
    ...
```

这里整个函数头——从 `def` 到冒号——被视为一条逻辑行，因此该注释可以忽略函数头中的所有 `N803` 诊断。

###### `ruff: file-ignore`

用于忽略整个文件中的指定诊断，作用类似 `ruff: noqa`：

```python
# ruff: file-ignore[F401] Allow unused imports in this file

import foo
import bar
import baz
```

注释中还可以写明忽略原因，例如上面的：

```text
Allow unused imports in this file
```

###### 自动添加忽略注释

新增 CLI 参数 `--add-ignore`，可以自动插入抑制注释：

```bash
echo 'import math' > try.py
uvx ruff@latest check --preview --add-ignore try.py
```

生成结果：

```python
import math  # ruff: ignore[unused-import]
```

在预览模式下，这些注释不仅支持规则代码，如 `F401`，也支持更易读的规则名称，如 `unused-import`。

##### 5. 默认展示检查与格式化修复差异

过去，`ruff check --diff` 和 `ruff format --diff` 可以展示修改内容，但差异输出与正常诊断信息相互独立，且会隐藏部分解释性诊断。

从 v0.16 开始：

- `check` 和 `format --check` 会在默认完整输出中直接展示可用修复的差异；
- 修复内容会显示在 `help` 子诊断下方；
- 用户无需单独切换到 `--diff` 才能查看具体修改。

例如，以下代码：

```python
if True: pass
elif False: pass
```

格式化检查会展示其应被拆分为规范缩进结构的差异。

###### `format --check` 支持更多输出格式

`format --check` 现在支持与 linter 相同的完整输出格式，可用于：

- 输出机器可读的 JSON；
- 生成 GitHub CI 可识别的注解；
- 生成 GitLab CI 可识别的注解；
- 适配其他自动化工具。

###### JSON 输出存在小幅破坏性变更

以下 JSON 字段现在可能为 `null`：

- `filename`
- `location`
- `end_location`
- `fix.edits[].location`
- `fix.edits[].end_location`

此前这些字段通常会默认填充为空字符串，或使用“第 1 行、第 1 列”。新行为更符合 Ruff 的内部诊断模型，虽然当前只会影响少量诊断，但未来可能更加常见。

##### 7. 其他从预览转为稳定的行为

- `BLE001`：如果异常通过 `critical`、`error`、`exception` 之外的其他日志方法记录，也可抑制 `blind-except` 告警。
- `FA102`：新增检查更多兼容 PEP 585 的 API，例如 `collections.abc` 中的类型。
- `INT001`、`INT002`、`INT003`：支持更多常见的 `gettext` 使用方式，例如将其赋值给 `builtins._`。
- `S310`：能够解析局部字符串字面量绑定，减少对 `urlopen` 用法的误报。
- `S508`、`S509`：支持较新 PySNMP 版本推荐的 API。
- `UP019`：除 `typing.Text` 外，也能识别 `typing_extensions.Text`。

##### 总结

Ruff v0.16 的核心方向是“**开箱即用地发现更多问题**”：默认规则数量增长近 7 倍，同时增强了 Markdown、诊断抑制、修复展示和 CI 输出能力。升级整体较平滑，但用户应重点检查新增默认规则带来的诊断变化，以及依赖 JSON 输出的工具是否能正确处理 `null` 字段。
