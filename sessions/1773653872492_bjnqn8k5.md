#### nanoAgent

中文 \| English

> *"The question is not what you look at, but what you see."* — Henry David Thoreau

The simplest way to build an agent that can interact with your system.

A minimal implementation of an AI agent using OpenAI's function calling. The agent can execute bash commands, read files, and write files.

If you want to learn more (e.g. what MCP is, and how to fetch tools in a more modern way), see: [https://github.com/sanbuphy/nanoMCP](https://github.com/sanbuphy/nanoMCP)

#### install

```
pip install -r requirements.txt
```

Set your environment variables:

**macOS/Linux:**

```
export OPENAI_API_KEY='your-key-here'
export OPENAI_BASE_URL='https://api.openai.com/v1'  # optional
export OPENAI_MODEL='gpt-4o-mini'  # optional
```

**Windows (PowerShell):**

```
$env:OPENAI_API_KEY='your-key-here'
$env:OPENAI_BASE_URL='https://api.openai.com/v1'  # optional
$env:OPENAI_MODEL='gpt-4o-mini'  # optional
```

**Windows (CMD):**

```
set OPENAI_API_KEY=your-key-here
set OPENAI_BASE_URL=https://api.openai.com/v1
set OPENAI_MODEL=gpt-4o-mini
```

#### quick start

```
python agent.py "list all python files in current directory"
python agent.py "create a file called hello.txt with 'Hello World'"
python agent.py "read the contents of README.md"
```

The agent uses OpenAI's function calling to:

1. Receive a task from the user
2. Decide which tools to use (bash, read\_file, write\_file)
3. Execute the tools
4. Return results to the model
5. Repeat until task is complete

That's it. \~100 lines of code.

```
# Define tools
tools = [{"type": "function", "function": {...}}]

# Agent loop
for _ in range(max_iterations):
    response = client.chat.completions.create(model=model, messages=messages, tools=tools)
    if not response.choices[0].message.tool_calls:
        return response.choices[0].message.content

    # Execute tool calls
    for tool_call in response.choices[0].message.tool_calls:
        result = available_functions[tool_call.function.name](**args)
        messages.append({"role": "tool", "content": result})
```

The core is just a loop: call model → execute tools → repeat.

Recent hardening keeps the loop running even when a tool call contains malformed JSON arguments or references an unknown tool; those cases are returned to the model as explicit tool errors instead of crashing the agent.

#### capabilities

- `execute_bash`: Run any bash command
- `read_file`: Read file contents
- `write_file`: Write content to files

#### examples

```
# System operations
python agent.py "what's my current directory and what files are in it?"

# File operations
python agent.py "create a python script that prints hello world"

# Combined tasks
python agent.py "find all .py files and count total lines of code"
```

这篇文章介绍了 `nanoAgent`：一个用约 100 行 Python 写成的极简 AI Agent。核心观点是：如果你能读懂这点代码，就能理解“Agent”到底是怎么工作的。

- **项目定位：用最少代码解释 Agent 原理**
  - `nanoAgent` 是一个最小化实现的 AI Agent，基于 OpenAI 的 function calling。
  - 它的目标不是做复杂框架，而是用非常少的代码，让人直接看懂 Agent 的运行机制。
  - 项目口号很明确：这是“能与系统交互的最简单 Agent 构建方式”。

- **使用方式：安装简单，开箱即用**
  - 安装只需要执行：`pip install -r requirements.txt`
  - 运行前需要设置环境变量，核心包括：
    - `OPENAI_API_KEY`
    - 可选：`OPENAI_BASE_URL`
    - 可选：`OPENAI_MODEL`，默认示例是 `gpt-4o-mini`
  - 支持 macOS/Linux、Windows PowerShell、Windows CMD 三种环境配置方式。

- **怎么运行：直接给自然语言任务**
  - 用户可以直接把任务作为命令行参数传给脚本，例如：
    - 列出当前目录所有 Python 文件
    - 创建 `hello.txt`，内容为 `Hello World`
    - 读取 `README.md`
  - 这说明它面向的是“用自然语言驱动工具执行”的场景，而不是传统手写脚本流程。

- **核心逻辑：Agent 本质上就是一个循环**
  - 文章把 Agent 逻辑压缩成一个非常清晰的循环：
    1. 接收用户任务
    2. 让模型决定要调用哪些工具
    3. 执行工具
    4. 把结果返回给模型
    5. 重复，直到任务完成
  - 原文直接强调：**核心就是 `call model → execute tools → repeat`**
  - 也就是说，Agent 的本质并不神秘，核心只是“模型决策 + 工具调用 + 结果回传”的闭环。

- **工具能力：目前聚焦 3 个基础能力**
  - `execute_bash`：执行任意 bash 命令
  - `read_file`：读取文件内容
  - `write_file`：向文件写入内容
  - 这 3 个能力已经足以覆盖很多典型任务，比如：
    - 查询当前目录和文件
    - 创建一个打印 `hello world` 的 Python 脚本
    - 查找所有 `.py` 文件并统计总代码行数

- **工程改进：最近增强了健壮性**
  - 项目最近特别加强了错误处理，避免 Agent 因异常工具调用而直接崩溃。
  - 重点处理了两类问题：
    - 工具调用参数里有格式错误的 JSON
    - 模型调用了不存在的工具
  - 改进后的行为是：把这些情况作为**明确的工具错误返回给模型**，而不是让整个 Agent crash。
  - 这说明项目虽然极简，但已经开始考虑真实使用中的稳定性问题。

- **补充信息：项目状态与扩展方向**
