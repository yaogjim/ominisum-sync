## 正文

**凡人小北**

正好最近在设计 AI-Native 的理赔系统，补充几点：  
1\. 真正重要的并非后台持续运行，而是无需人工重新启动。很多高价值 Agent 并不会 24 小时不停地烧 token，大部分应该是 event-driven 的。  
2\. workflow reengineering 不只是把 Agent 接入现有 SaaS。如果只是让 Agent 模仿员工点击 CRM、复制邮件、填写表格，它仍然继承了原流程全部的低效。真正的重新设计应该把企业变成一套 Agent 可消费的事件与状态系统。  
3\. 不应以职能为单位判断 Agent readiness，如果还没切换到 workflow 为单位那就慢世界很多步了。Sales 和医疗也是如此。未来的扩散路径大致不是所有行业复制 agentic coding，企业会围绕 Agent 的人机分工重新设计组织和流程。

技术面最大的商业机会可能是成为某类业务的 agentic system of action，掌握事件入口、业务状态、权限、评估、执行和异常处理。

## 通俗精炼（2）

### 2026-08-10 10:01:03

#### AI-Native 企业的核心：重构工作流，而非叠加 Agent

##### 核心观点

Agent 的真正价值，不是代替员工操作现有软件，而是推动企业重构底层工作流。未来企业将围绕 Agent 重新设计数据、流程、权限及人机分工。

##### 三个关键判断

###### 1. Agent 应由事件驱动，而非持续运行

高价值 Agent 不需要全天候消耗 Token。关键在于它能被业务事件自动触发、持续推进任务，并在异常或关键节点请求人工介入，无需人工反复启动。

###### 2. 流程重构不等于自动操作 SaaS

让 Agent 点击 CRM、复制邮件、填写表格，只是自动化旧流程，也会继承原有低效。

真正的 AI-Native 流程，应将企业改造成一套 Agent 可以直接理解和操作的**事件与状态系统**，并重新定义数据供给、跨部门协作和人工审核节点。

###### 3. 应按工作流评估 Agent 成熟度

Agent 是否适用，不能笼统地按销售、医疗、理赔等职能或行业判断，而应拆解到具体工作流，分析其中哪些任务适合 Agent、哪些需要人工决策。

未来 Agent 的扩散不会简单复制“智能编程”，而会伴随组织结构、业务流程及人机边界的系统性调整。

##### 商业机会

最大的技术与产品机会，是成为垂直业务中的 **Agentic System of Action（智能行动系统）**，掌握完整的任务执行闭环：

- 事件入口与任务触发
- 业务状态与上下文
- 数据及权限管理
- Agent 执行与效果评估
- 人工审核与异常处理

##### 结论

企业级 Agent 的长期增量，不在“多一个可对话的 AI”，而在让 Agent 真正被部署到工作流中执行任务。谁能掌控业务事件、状态和执行闭环，谁就更有机会成为下一代企业软件的核心平台。

### 2026-08-10 10:07:02

#### AI Agent 的真正价值：重构工作流，而非替代人工操作

##### 核心观点

企业引入 AI Agent 的重点，不是让它模仿员工操作现有软件，而是围绕 Agent 重新设计业务流程、系统能力与人机分工。

##### 1. Agent 应由事件驱动，而非持续运行

高价值 Agent 不需要全天候消耗 Token。更合理的模式是：

- 由业务事件自动触发
- 根据状态持续推进任务
- 遇到异常时请求人工介入
- 无需人工重新启动流程

关键不在“持续运行”，而在“自主完成”。

##### 2. 接入现有 SaaS 不等于流程重构

如果 Agent 只是点击 CRM、复制邮件、填写表格，本质上仍在继承旧流程的低效。

真正的 AI-Native 工作流，应将企业系统改造成一套 Agent 可直接理解和调用的体系，包括：

- 业务事件与状态
- 数据与权限
- 执行动作
- 效果评估
- 异常处理机制

##### 3. 应按工作流判断 Agent 落地条件

企业不应笼统讨论“销售、医疗或理赔是否适合 Agent”，而应拆解具体工作流，判断其中哪些环节可以自动化、哪些需要人工审核。

未来，组织会围绕 Agent 重新划分人机职责，并调整跨部门协作和 Human-in-the-loop 节点。

##### 4. 最大机会是成为业务执行系统

更有价值的商业机会，不是做一个可对话的 AI 助手，而是成为某类业务的 **Agentic System of Action**，掌握：

- 事件入口
- 业务状态
- 权限控制
- 任务执行
- 质量评估
- 异常处理

##### 总结

Agent 的长期上限，不是提高现有流程的操作效率，而是改变流程本身。未来企业的大部分 Token 消耗，也将来自真正部署在业务工作流中、持续执行任务的 Agent。
