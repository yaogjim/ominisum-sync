## 正文

I have been interested in machine-assisted ways to do and teach mathematics from as far back as 1999, when I started coding [several applets in Java 1.0](https://terrytao.wordpress.com/applets/), both for my complex analysis and linear algebra courses, as well as to visualize various mathematical objects I was interested in (such as honeycombs or Besicovitch sets). This was moderately successful; but the applets were time-consuming to program. Eventually, the standards for web pages stopped supporting this version of Java, and [the applets became non-functional.](https://terrytao.wordpress.com/2008/12/01/upgrading-old-java-applets/)

However, in the last few days I have begun the process of migrating much of my old web page and blog data to a [more maintainable repository](https://teorth.github.io/tao-web/), using modern AI assistance. As an experiment, I asked the agent to port my old applets to a modern supported language (we landed on Javascript), and it [managed to do so](https://teorth.github.io/tao-web/apps/porting-legacy-applets.html) in a matter of hours, with [all of my old applets now functional again](https://teorth.github.io/tao-web/applets.html), with even a few graphical upgrades (for instance, the [Besicovitch set applet](https://teorth.github.io/tao-web/apps/besicovitch-sets.html) is now colorized, in contrast to my original monochrome version). I am particularly pleased to see the honeycomb applet that I wrote with [Allen Knutson](https://pi.math.cornell.edu/~allenk/) in 1999 [come back to life](https://teorth.github.io/tao-web/apps/honeycombs.html), as this was a particularly tricky one to code by hand:

[![](https://terrytao.wordpress.com/wp-content/uploads/2026/07/image.png?w=613)](https://terrytao.wordpress.com/wp-content/uploads/2026/07/image.png)

Notoriously, LLM-based coding agents can create various blatant or subtle bugs in their code; but in the porting of these two dozen or so applets, I could only find one minor bug (the handling of a drag event in one of the complex analysis applets had unwanted behavior when dragging outside of the main box), and in fact the agent identified two bugs in the original code that I was not aware of, so it ended up being a net wash as far as code quality was concerned. In any event, as these applets are meant to be secondary visual aids rather than critical components of a mathematical argument, the downside risk of such bugs is relatively low.

The process was [painless enough](https://teorth.github.io/tao-web/apps/porting-legacy-applets.html) that I decided to also try coding some new apps, in addition to porting the old ones. Back in 1999 I had an ambitious idea for a visualization tool for special relativity; this was before the release of the software tool Inkscape, but the idea I had in mind was basically “Inkscape, but in Minkowski space”. I had even started [writing Java code for this app](https://www.math.ucla.edu/~tao/java/Relativity/), but the code complexity became too much for me, and I abandoned the project. However, after a couple hours of “vibe coding” with an AI agent, I was finally able to generate an applet that matched the vision I had back in 1999, which [can now be found here](https://teorth.github.io/tao-web/apps/spacetime-diagram.html). A summary of the conversation I had with the agent to generate this code [can be found here](https://teorth.github.io/tao-web/apps/spacetime-diagram-making-of.html) (it has been edited down to remove a large number of tedious technical implementation reports). While I have playtested the app somewhat, I would be interested in receiving further feedback on this “alpha” version of the applet, as I am sure (especially given the LLM-generated nature of the code) that there are still some bugs and rough edges to be ironed out.

[![](https://terrytao.wordpress.com/wp-content/uploads/2026/07/image-1.png?w=947)](https://terrytao.wordpress.com/wp-content/uploads/2026/07/image-1.png)

After writing my blog post on the Gilbreath conjecture paper earlier today, I realized that I could similarly ask the agent to code a visualization tool for the Gilbreath conjecture to accompany the paper and blog post. After another few hours of conversation, this is now done; you can [try out the visualization here](https://teorth.github.io/tao-web/apps/gilbreath.html). Again, the procedure was quite painless (see [this transcript of the process](https://teorth.github.io/tao-web/apps/gilbreath-making-of.html)), and I think I may add such interactive visualizations as supplements for future papers; as such supplements are not mission-critical to the core of the paper, I again feel that the downside risk of using guided interaction with LLM agents to generate such visualizations is acceptable.

## 通俗精炼（1）

### 2026-07-30 01:59:01

#### 现代 AI 编程智能体：让旧应用复活，也让新想法快速落地

##### 核心观点

现代 AI 编程智能体显著降低了软件开发与维护成本：它不仅能把多年失效的旧程序迁移到现代技术栈，还能在数小时内将长期搁置的创意变成可用原型。

##### 旧应用：从 Java 迁移到 JavaScript

作者早在 1999 年就为数学教学和研究编写了约二十多个 Java Applet，用于可视化复分析、线性代数、蜂巢结构和 Besicovitch 集等内容。

随着浏览器停止支持旧版 Java，这些工具逐渐失效。借助 AI 编程智能体，作者在数小时内将它们迁移至 JavaScript，不仅恢复了功能，还完成了彩色化等视觉升级。

##### 代码质量：有错误，但总体可控

LLM 生成的代码可能包含明显或隐蔽的 Bug，但此次迁移中，作者只发现了一个较小的问题。与此同时，AI 还发现了两处原代码中未被察觉的错误，因此整体代码质量并未下降。

关键在于，这些应用只是辅助性的数学可视化工具，并非数学证明或核心系统。即使存在缺陷，潜在损失也相对有限。

##### 新应用：将多年构想快速产品化

作者曾设想开发一款“运行在闵可夫斯基空间中的 Inkscape”，用于可视化狭义相对论，但因开发复杂度过高而放弃。

如今，通过数小时与 AI 智能体进行“氛围编程”（Vibe Coding），作者完成了符合当年设想的 Alpha 版本。随后，他又以同样方式快速开发出 Gilbreath 猜想的交互式可视化工具。

##### 产品与研发启示

- **AI 降低了历史系统迁移成本**：旧资产不必推倒重来，可以快速适配现代平台。
- **AI 大幅压缩原型验证周期**：过去因复杂度而搁置的想法，如今可在数小时内形成可体验产品。
- **应优先用于低风险场景**：教学辅助、交互演示和论文补充材料，适合容忍一定的不确定性。
- **人仍需负责验收**：AI 可以编码和发现问题，但测试、反馈与最终质量判断仍依赖专家。
- **内容形态正在升级**：未来的论文和知识传播可能不再只有文字与图表，而会更多配套交互式可视化工具。

##### 总结

AI 编程智能体的价值不只是“写代码更快”，而是让大量过去不值得开发、难以维护或超出个人能力边界的软件项目重新变得可行。其最佳实践是：在专业人士指导下，将 AI 用于高价值、低风险、可验证的应用场景。

## 结构化（1）

### 2026-07-30 09:21:27

#### 文章精炼总结

作者分享了利用现代 AI 编程代理，将 1999 年开发、现已失效的数学 Java 小程序迁移到 JavaScript，并快速开发全新数学可视化工具的经历。其核心观点是：对于不影响数学论证主体、风险较低的辅助工具，AI 编程能显著降低开发成本，但仍需人工测试与检查。

##### 1. 早期数学可视化尝试

- 作者从 **1999 年**起探索用计算机辅助数学研究与教学，为复分析、线性代数课程开发了多个 **Java 1.0** 小程序。
- 这些程序也用于展示蜂巢结构、Besicovitch 集等数学对象。
- 虽然效果不错，但手工编程耗时较长；后来网页标准不再支持旧版 Java，导致这些小程序全部失效。

##### 2. AI 帮助旧程序“复活”

- 作者近期借助现代 AI，将旧网页和博客资料迁移到更容易维护的代码仓库，并尝试把旧 Java 程序移植到 **JavaScript**。
- AI 仅用**数小时**便完成了约 **20 多个小程序**的移植，使它们重新运行起来。
- 新版本还获得了一些视觉升级，例如：
  - 原本黑白的 **Besicovitch 集**程序增加了彩色显示；
  - 作者与 Allen Knutson 于 1999 年共同开发、手工实现难度较高的**蜂巢小程序**也成功恢复。

##### 3. 代码质量与风险评估

- AI 生成代码通常可能包含明显或隐蔽的错误，但此次移植中，作者只发现了 **1 个小问题**：某个复分析程序在鼠标拖出主区域后，拖动事件行为异常。
- 与此同时，AI 还发现了原始代码中作者此前未察觉的 **2 个错误**。
- 因此，从整体结果看，AI 带来的新问题与发现的旧问题大致抵消，代码质量并未明显下降。
- 这些程序只是数学内容的辅助可视化工具，不承担核心证明或关键计算，因此即使存在少量错误，风险也相对可控。

##### 4. 用 AI 实现搁置多年的新构想

- 1999 年，作者曾设想开发一个狭义相对论可视化工具，理念类似于：**“在闵可夫斯基时空中运行的 Inkscape”**。
- 当时由于代码过于复杂，项目最终被放弃。
- 如今通过与 AI 进行约**数小时的“氛围编程”（vibe coding）**，作者终于做出了符合当年设想的程序。
- 目前该程序仍属于 **Alpha 版本**，虽然已经过初步试用，但考虑到代码主要由大语言模型生成，作者预计仍有漏洞和体验问题，希望获得更多用户反馈。

##### 5. 快速开发 Gilbreath 猜想可视化工具

- 在撰写关于 **Gilbreath 猜想**论文的博客文章后，作者又让 AI 为该猜想开发配套的交互式可视化程序。
- 经过又一次**数小时的对话与迭代**，工具便开发完成，整个过程同样较为顺利。
- 作者因此考虑今后为更多论文增加交互式可视化补充材料。

##### 6. 总体结论

- AI 编程代理能够把过去需要大量时间、甚至因复杂度而被放弃的项目，压缩到数小时内完成。
- 但 AI 代码仍须人工试用、审查和修正，尤其不能默认其完全可靠。
- 对于论文的非核心补充内容，如教学演示和交互式可视化，采用“人类引导 + AI 生成”的开发方式具有较高性价比，且潜在风险可以接受。
