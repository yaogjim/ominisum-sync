- **核心高价值点**：将任务卡、Git worktree、代理终端和依赖链自动化结合起来，让多个代理能在隔离环境中并行推进复杂任务。

- 通过为每个任务创建临时 Git worktree，可降低并行代理工作的合并冲突风险

- 在看板内集成差异查看、评论回传和Git操作，可减少在多个工具之间切换

**行动项**

```
# Run directly (no install required)
npx kanban

# Or install globally
npm i -g kanban
kanban
```

从任何 Git 仓库的根目录运行此命令。Kanban 将检测您已安装的 CLI 代理，并在您的浏览器中启动本地运行的 Web 服务器。无需帐户或设置，开箱即用。

您可以手动创建任务卡，也可以打开侧边栏聊天窗口，让您的客服人员帮您将工作分解成多个任务。看板会在会话中自动添加看板管理指令，因此您只需要求系统添加任务、关联任务或在看板上开始工作即可。

`⌘` + 点击卡片即可将其链接到其他任务。当卡片完成并移至回收站后，链接的任务会自动启动。结合自动提交功能，即可实现完全自主的依赖链：一个任务完成 → 提交 → 启动下一个任务 → 循环往复。让智能体将一个大型任务分解成多个自动提交的子任务，这本身就是一种非常神奇的体验——它会巧妙地并行处理，从而最大限度地提高效率，并将各个子任务链接起来，实现端到端的自主性。

点击卡片上的播放按钮。看板会为该任务创建一个临时工作树，这样代理就可以并行工作，避免合并冲突。此外，它还会对诸如 `node_modules` 之类的.gitignore 文件创建符号链接，这样您就不必担心为每个项目副本执行缓慢的 `npm install` 命令。

代理工作时，看板使用钩子在每张卡片上显示最新的消息或工具调用，这样您就可以一目了然地监控数百名代理，而无需打开每张卡片。

点击卡片即可查看代理的 TUI 以及该工作树中所有更改的差异。看板包含自身的检查点系统，因此您还可以查看与上次发送的消息之间的差异。点击行即可添加评论并将其发送给代理。

为了方便地测试和调试您的应用，请在设置中创建一个脚本快捷方式。使用类似 `npm run dev` 命令，这样您只需点击导航栏中的播放按钮，而无需记住命令或让客服人员代劳。

当工作看起来没问题时，点击 **“提交”** 或 **“打开 PR”** 。看板会动态提示代理将工作树转换为基础引用上的提交或新的 PR 分支，并智能地处理任何合并冲突。或者，您可以启用自动提交/自动 PR 功能来跳过审核，代理会在完成后立即发布。将卡片移至回收站以清理工作树（您始终可以稍后恢复工作，因为看板会跟踪恢复 ID）。

点击导航栏中的分支名称，即可打开完整的 Git 界面，浏览提交历史、切换分支、执行拉取、推送和可视化 Git 操作，所有操作均无需离开看板。随时掌握代理在各个分支上的工作进度。

#### `cline/kanban` 内容精炼总结

`cline/kanban` 是一个在本地浏览器中运行的 Web 看板工具，核心目标是让多个 CLI 智能体在同一 Git 仓库里并行工作。它通过“任务卡 + 独立工作树 + 自动提交/自动衔接”这套机制，把大任务拆成可并行、可追踪、可连续执行的流程。

##### 1. 项目定位：本地运行的多代理协作看板

- `kanban` 可以直接运行：`npx kanban`，也支持全局安装：`npm i -g kanban` 后执行 `kanban`。
- 它需要在任意 Git 仓库根目录启动，启动后会自动检测本机已安装的 CLI 智能体，并在浏览器中打开一个本地 Web 服务。
- 整个工具强调“本地运行、无需账号、无需复杂配置、开箱即用”。

**通俗理解：**
它像是一个专门给 AI 编程代理准备的本地任务管理面板，你不用频繁开多个终端或手动切分分支，它会帮你把这些都组织起来。

##### 2. 任务拆解方式：手动建卡，也可以让智能体帮你拆任务

- 用户可以自己手动创建任务卡。
- 也可以打开侧边栏聊天窗口，让智能体把一个大任务拆解成多个小任务。
- 系统会自动在会话中加入“看板管理指令”，因此你只需要用自然语言提出需求，例如：
  - 添加任务
  - 关联任务
  - 开始执行某个任务

**例子：**
如果你要做“新增支付功能”，可以让智能体拆成：
- 前端支付页开发
- 后端支付接口开发
- 支付状态回调处理
- 测试与文档补充

这样每一项都可以成为独立任务卡，便于并行处理。

##### 3. 核心能力：用任务依赖链实现自动化推进

- 支持用 `⌘ + 点击卡片` 将一个任务链接到另一个任务，形成依赖关系。
- 当某张卡片完成并被移入回收站后，后续被链接的任务会自动启动。
- 如果再结合“自动提交”功能，就能形成完整的自动化依赖链：

  **一个任务完成 → 自动提交 → 启动下一个任务 → 持续循环**

- 文中强调，这种方式很适合让智能体把大任务拆成多个“自动提交的子任务”，并自行完成端到端工作。

**通俗理解：**
这相当于把 AI 工作流程做成了“流水线”。前一个子任务一结束，后一个就自动接上，减少人工干预。

##### 4. 并行工作的实现：每张卡片都有独立工作树和终端

- 点击任务卡上的播放按钮后，看板会为该任务创建一个临时 `worktree`（Git 工作树）。
- 这样每个智能体都能在自己的隔离环境里并行工作，减少合并冲突。
- 对于像 `node_modules` 这类被 `.gitignore` 忽略的大目录，系统会创建符号链接，而不是为每个副本重新安装依赖。

**重要价值：**
- 多个代理可以同时处理不同任务，不互相覆盖代码。
- 避免每个工作副本都重复执行慢速 `npm install`，提升速度。

**例子：**
一个仓库里同时开 3 个任务：
- A 改前端页面
- B 写 API
- C 补测试

它们各自运行在独立工作树中，既能并行开发，又不容易彼此冲突。

##### 5. 监控与审查：可以看到代理状态、终端和差异

- 看板会通过钩子机制，在每张卡片上展示该代理最近的消息或工具调用。
- 这意味着即使有很多代理同时运行，用户也不必逐个点开查看，就能大致掌握工作进展。
- 点击卡片后，可以查看：
  - 代理的 TUI 界面
  - 当前工作树里的全部代码差异
- 系统还内置了检查点机制，可以对比“自上次发送消息以来”的变更。
- 用户点击具体代码行后，还可以添加评论并直接发给代理。

**通俗理解：**
它不仅是“派任务”的地方，也是“查进度、看代码、给反馈”的地方，像把终端、diff 和批注能力合并到同一个界面里。

##### 6. 调试与运行：支持脚本快捷方式

- 为了方便测试和调试，用户可以在设置里创建脚本快捷方式。
- 例如配置 `npm run dev` 这类命令后，就能直接点击导航栏播放按钮启动项目。
- 这样不用每次记命令，也不用再让智能体代你输入。

**例子：**
如果你的项目平时靠 `npm run dev` 启动开发环境，只要配置一次，以后在看板里一键即可运行。

##### 7. 提交与协作：可提交、开 PR，也支持全自动发布

- 当任务结果检查无误后，可以点击“提交”或“打开 PR”。
- 看板会提示代理把当前工作树整理为：
  - 基于基础引用的提交
  - 或新的 PR 分支
- 系统还能智能处理合并冲突。
- 如果启用“自动提交”或“自动 PR”，则可以跳过人工审核，让代理完成后直接发布结果。
- 将任务卡移到回收站后，会清理对应工作树；但系统会保留恢复 ID，之后仍可恢复工作。

**关键点：**
这让整个流程从“开发”进一步延伸到“提交代码”和“发起协作”，形成完整闭环。

##### 8. Git 操作集成：不用离开看板也能管理分支

- 点击导航栏中的分支名称，可以打开完整 Git 界面。
- 支持的操作包括：
  - 浏览提交历史
  - 切换分支
  - 拉取和推送
  - 可视化 Git 操作
- 用户可以直接在看板里掌握各分支和各代理的工作状态，无需切到其他工具。
