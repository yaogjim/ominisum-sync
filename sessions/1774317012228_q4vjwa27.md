#### Reward functions

We now define some basic formatting rewards functions to see if reasoning starts and ends, and also another to see if the answers were written correctly.

We also try to fix the `addCriterion` issue as described in our [blog post](https://www.google.com/url?q=https%3A%2F%2Funsloth.ai%2Fdocs%2Fnew%2Fvision-reinforcement-learning-vlm-rl%23qwen-2.5-vl-vision-rl-issues-and-quirks)

Gemini

```
# Reward functions
import re

def formatting_reward_func(completions,**kwargs):
    import re
    thinking_pattern = f'{REASONING_START}(.*?){REASONING_END}'
    answer_pattern = f'{SOLUTION_START}(.*?){SOLUTION_END}'

    scores = []
    for completion in completions:
        if isinstance(completion, list):
            completion = completion[0]["content"] if completion else ""
        score = 0
        thinking_matches = re.findall(thinking_pattern, completion, re.DOTALL)
        answer_matches = re.findall(answer_pattern, completion, re.DOTALL)
        if len(thinking_matches) == 1:
            score += 1.0
        if len(answer_matches) == 1:
            score += 1.0

        # Fix up addCriterion issues
        # See https://unsloth.ai/docs/new/vision-reinforcement-learning-vlm-rl#qwen-2.5-vl-vision-rl-issues-and-quirks
        # Penalize on excessive addCriterion and newlines
        if len(completion) != 0:
            removal = completion.replace("addCriterion", "").replace("\n", "")
            if (len(completion)-len(removal))/len(completion) >= 0.5:
                score -= 2.0

        scores.append(score)
    return scores

def correctness_reward_func(prompts, completions, answer, **kwargs) -> list[float]:
    answer_pattern = f'{SOLUTION_START}(.*?){SOLUTION_END}'

    completions = [(c[0]["content"] if c else "") if isinstance(c, list) else c for c in completions]
    responses = [re.findall(answer_pattern, completion, re.DOTALL) for completion in completions]
    q = prompts[0]
    print('-'*20, f"Question:\n{q}", f"\nAnswer:\n{answer[0]}", f"\nResponse:{completions[0]}")
    return [
        2.0 if len(r)==1 and a == r[0].replace('\n','') else 0.0
        for r, a in zip(responses, answer)
    ]
```

- 笔记把原始样本改造成适合强化学习的数据格式，核心加入了两个标签：
  - `&lt;REASONING> ... &lt;/REASONING>`
  - `&lt;SOLUTION> ... &lt;/SOLUTION>`
- 提示词要求模型：
  1. 先输出解题过程或推理
  2. 再输出最终答案
  3. 最终答案必须放在 `&lt;SOLUTION>` 标签中，并且是**单个浮点数**
- 每条样本被整理成多模态对话格式：

    - 一段文字问题

##### 5. 奖励函数设计：格式奖励 + 正确性奖励

笔记为强化学习设计了两类奖励函数。

###### 5.1 格式奖励 `formatting_reward_func`

- 检查模型输出是否正确包含：
  - 一组 `&lt;REASONING>...&lt;/REASONING>`
  - 一组 `&lt;SOLUTION>...&lt;/SOLUTION>`
- 奖励规则：
  - 有且仅有一个 reasoning 段：`+1.0`
  - 有且仅有一个 solution 段：`+1.0`
- 还加入了一个特殊惩罚：
  - 如果输出里 `addCriterion` 和换行过多，占内容 **50% 以上**，则 `-2.0`
- 这是因为笔记提到模型推理时可能出现 `addCriterion` 或乱码样输出，这被视为模型内部的一类异常现象。

###### 5.2 正确性奖励 `correctness_reward_func`

- 从 `&lt;SOLUTION>` 中抽取最终答案
- 如果答案和标准答案完全一致，则给：
  - `+2.0`
- 否则：
  - `0.0`
- 这个函数还会打印：
  - 问题
  - 标准答案
  - 模型回复
- 方便训练时观察模型是否真的学会了按要求答题。

###### 5.3 设计思路

- 这两个奖励配合起来，目的很直观：
  - 先让模型学会“按规定格式输出”
  - 再让模型学会“答对题”
- 这也是强化学习训练中常见的方法：**格式约束 + 任务正确性**双重驱动。

#### 深入浅出地解读

##### 1. 这份笔记到底在做什么？

简单说，它是在教你：

> 让一个“会看图的大模型”，通过“答题拿奖励”的方式，学会更好地做图像数学题。

这不是普通的监督微调（SFT），而是 **强化学习（RL）**。  
也就是：模型先自己生成答案，系统再根据“答得好不好”给分，模型再慢慢往高分方向优化。

---

##### 2. 为什么是 Vision + GRPO？

这里的模型是 **视觉语言模型**，输入不仅有文字，还有图片。  
比如：

- 看尺子测钉子的长度
- 看物理图解做计算
- 看图形做逻辑推理

而 **GRPO** 可以理解成一种适合大模型训练的强化学习方法。  
它不像传统 RL 那么强调复杂环境交互，而是更适合这种：

- 给定题目
- 模型生成回答
- 根据回答打分
- 再优化模型

所以它很适合“图文问答 + 答案奖励”这种场景。

##### 3. 代码流程可以怎么理解？

##### 环节一：安装环境

前面一大段 `pip install`，是在准备训练所需组件：

- `torch`、`transformers`
- `trl`
- `unsloth`
- `bitsandbytes`
- `xformers`
- 以及一些加速和导出工具

目的很明确：  
**把训练视觉大模型所需的运行环境搭起来。**

---

##### 环节二：加载模型并加 LoRA

代码中用了：

- `FastVisionModel.from_pretrained(...)`
- `FastVisionModel.get_peft_model(...)`

意思是：

- 先加载一个已经预训练好的视觉语言模型
- 再给它挂上 **LoRA 适配器**，这样训练成本更低、显存占用更小

这里还有一个关键点：

- **不微调视觉层**
- 主要微调 **语言层、注意力层、MLP 层**

原因是：
- 成本更低
- 更稳定
- vLLM/某些推理支持对视觉层 LoRA 还有限制

所以这是一个比较实用的折中方案。

##### 4. 数据是怎么处理的？

数据来自 `MathVista`，但不是全用，而是做了筛选：

- 只保留 **答案是数字** 的题

这样做的好处是：

- 奖励函数更容易写
- 对错更容易判断
- 强化学习反馈更直接

然后又做了两步图像预处理：

- 统一缩放到 `512x512`
- 转成 `RGB`

目的就是让图片输入更统一，减少训练时的麻烦。

---

##### 5. 为什么要强制模型输出“推理 + 答案”？

提示词要求模型按这种格式回答：

```text
<REASONING>...</REASONING>
<SOLUTION>...</SOLUTION>
```

这样设计有两个作用：

###### 第一，方便奖励函数打分
程序可以直接用正则表达式检查：

- 有没有推理标签
- 有没有答案标签
- 最终答案是不是数字、是不是正确

###### 第二，让模型形成固定输出习惯
也就是所谓“格式对齐”。

不过要注意：  
**模型是否真的“会推理”，不完全等于它写出了 `&lt;REASONING>`。**  
有时这只是格式上的“看起来像推理”。

---

##### 6. 奖励函数是这份笔记的核心

这份笔记里最关键的，不是模型本身，而是 **奖励怎么设计**。

它有两个主要奖励：

###### 1）格式奖励 `formatting_reward_func`
看输出是否包含：

- 一个 `&lt;REASONING>...&lt;/REASONING>`
- 一个 `&lt;SOLUTION>...&lt;/SOLUTION>`

如果满足，就加分。

还额外处理了一个问题：  
模型可能会输出很多奇怪重复内容，比如 `addCriterion` 或大量换行。  
如果这种垃圾内容占比太高，就扣分。

###### 2）正确性奖励 `correctness_reward_func`
看 `&lt;SOLUTION>` 里的最终答案，是否和标准答案完全一致。

答对就给 `2.0`，否则 `0.0`。

---

##### 7. 这套方法的优点是什么？

这份笔记的优点很明显：

- **上手快**：直接给出完整 Colab 流程
- **工程实用**：用 LoRA，节省资源
- **任务聚焦**：只做数值答案，降低难度
- **奖励清晰**：格式对错 + 答案对错，简单直接
- **适合演示 RL 微调**：能比较直观地看到 reward 变化

对初学者来说，这是一份非常典型的“**可跑通的视觉 RL 微调样例**”。

---

##### 8. 但它也有明显局限

这部分很重要。

###### 1）奖励设计偏“硬规则”
它主要检查：

- 格式对不对
- 最终数值对不对

但它并不能真正判断：

- 推理过程是否合理
- 中间步骤是否可信
- 模型是不是“蒙对了”

也就是说，模型可能学会的是：

> “把输出写得像标准答案，并尽量猜中数字”

而不一定是真的提升了深层推理能力。

###### 2）答案匹配有点机械
代码里对正确答案的判断，本质上接近“字符串式匹配”。  
这会带来一些问题：

- `2` 和 `2.0` 可能被当成不同
- 多一点空格、换行，可能影响判定
- 浮点数精度问题可能误伤正确答案

###### 3）训练步数很少
示例里 `max_steps = 60`，更像是教学演示，不像完整训练。  
所以效果提升可能有限。

###### 4）数据规模和任务范围较窄
只筛选数字答案题，虽然方便训练，但泛化能力有限。  
模型未必能因此学会更广泛的图文推理。

###### 5）“推理可见”未必等于“推理更强”
让模型输出思维链，不代表它真的更会推理。  
有时只是更会“写推理文本”。

总体看，这份笔记很适合当作 **入门范例和实验模板**，但不应把它理解成“完整、严谨、可直接工业化”的方案。

- **如果你是初学者**：这份内容很有价值，能帮你快速理解“视觉模型 + 强化学习 + LoRA”的基本流程。
- **如果你想做研究或产品**：这只是起点，后面还需要补很多东西，比如：
  - 更稳健的奖励设计
  - 更合理的答案归一化
  - 更长时间训练
  - 更严格的评估集
  - 对“推理质量”而不只是“答案正确”的评估

一句话评价：

> 这是一个“非常适合学习和试验”的 notebook，但它更像演示版，而不是最终版方案。
