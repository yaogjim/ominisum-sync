#### Impeccable

AI 编码代理的设计指南。1 项技能、23 条命令、实时浏览器迭代，以及 41 条针对 AI 生成的前端设计的确定性检测规则。

> **快速入门：** 从你的项目根目录，运行 `npx impeccable skills install` ，然后在你的 AI 编码工具中运行 `/impeccable init` 。完整文档： [impeccable.style](https://impeccable.style) 。

#### Why Impeccable?

Anthropic 的 [前端设计](https://github.com/anthropics/skills/tree/main/skills/frontend-design) 是首个针对 Claude 广泛使用的设计技能。Impeccable 从那里开始。

每个在相同 SaaS 模板上训练的模型，跳过指导后，每个项目都会出现同样的那几个设计特征：所有内容都用 Inter 字体，紫到蓝的渐变，卡片嵌套卡片，彩色背景上的灰色文字，以及每个标题上方的圆角方形图标块。

Impeccable adds:

- **一个设置流程。** `/impeccable init` 写入 `PRODUCT.md` 并提供 `DESIGN.md` ，以便后续命令了解目标受众、品牌/产品路线、语调、反参考、颜色、字体和组件。
- **23 个命令。** 与你的 AI 共享的设计词汇： `润色` 、 `审核` 、 `评析` 、 `提炼` 、 `动画化` 、 `加粗` 、 `减淡` ，以及更多。
- **41 确定性检测规则** plus 仅 LLM 的批评性检查。命令行界面和浏览器扩展在不使用 LLM 且不使用 API 密钥的情况下执行确定性检测规则。

#### What's Included

该技能可通过一条命令安装：

```
/impeccable <command> <target>
```

Start every new project with:

```
/impeccable init
```

`init` 询问该界面是品牌（营销、落地页、作品集）类型还是产品（应用界面、仪表盘、工具）类型，然后写入项目上下文，供后续所有命令读取。

##### 23 Commands

所有命令都通过 `/impeccable` 访问：

Command What it does

`/impeccable craft` 完整的先造型后构建流程，带有视觉迭代

`/impeccable init` 一次性设置：收集设计背景，编写 PRODUCT.md 和 DESIGN.md，配置实时模式，推荐后续步骤

`/impeccable document` 从现有项目代码生成根 DESIGN.md

`/impeccable extract` 将可复用组件和设计令牌引入设计系统

`/impeccable shape` 在编写代码之前规划 UX/UI

`/impeccable critique` 用户体验设计评审：层级、清晰性、情感共鸣

`/impeccable audit` 执行技术质量检查（无障碍、性能、响应式）

`/impeccable polish` 最终检查、设计系统对齐以及发布就绪

`/impeccable bolder` Amplify boring designs

`/impeccable quieter` Tone down overly bold designs

`/impeccable distill` Strip to essence

`/impeccable harden` 错误处理, 国际化, 文本溢出, 边界情况

`/impeccable onboard` 首次运行流程、空状态、激活路径

`/impeccable animate` Add purposeful motion

`/impeccable colorize` Introduce strategic color

`/impeccable typeset` 调整字体选择、层级和字号

`/impeccable layout` 调整布局、间距、视觉节奏

`/impeccable delight` Add moments of joy

`/impeccable overdrive` 添加技术上卓越的特效

`/impeccable clarify` Improve unclear UX copy

`/impeccable adapt` Adapt for different devices

`/impeccable optimize` Performance improvements

`/impeccable live` 视觉变体模式：在浏览器中迭代元素

使用 `/impeccable pin <command>` 来创建独立快捷方式（例如， `pin audit` 创建 `/audit` ）

###### Usage Examples

```
/impeccable audit blog           # Audit blog hub + post pages
/impeccable critique landing     # UX design review
/impeccable polish settings      # Final pass before shipping
/impeccable harden checkout      # Add error handling + edge cases
```

或者直接使用 `/impeccable` 并附带描述：

```
/impeccable redo this hero section
```

##### Anti-Patterns

这项技能包括关于要避免什么的明确指导：

- 不要使用过度使用的字体（Arial、Inter、系统默认字体）
- 不要在彩色背景上使用灰色文本
- 不要使用纯黑/纯灰（始终带色调）
- 不要把所有内容都用卡片包裹，也不要在卡片内部嵌套卡片
- 不要使用弹跳/弹性缓动（感觉过时了）

访问 [impeccable.style](https://impeccable.style#casestudies) 以查看通过 Impeccable 命令改造的真实项目的改造前后案例研究。

#### Installation

##### 选项 1：命令行安装程序（推荐）

从项目的根目录，运行：

```
npx impeccable skills install
```

这会自动检测你的 AI 工具，并将为其编译的构建产物写入正确位置（`.claude/skills/` 、`.cursor/skills/` 等）。支持与 Cursor、Claude Code、Gemini CLI、Codex CLI 以及其他所有支持的工具搭配使用。之后重新加载你的 AI 工具。

Claude Code 用户可以选择使用 `/plugin marketplace add pbakaus/impeccable` 安装插件。通用的 `npx skills add pbakaus/impeccable` 命令也可使用，不过它会为所有工具安装一个共享构建，而非为你的工具编译的构建。

对于希望通过 Git 保持 Impeccable 作为依赖项并保持更新的团队，请将此仓库添加为子模块，并将编译后的 provider 构建链接到您的 harness 文件夹中

```
git submodule add https://github.com/pbakaus/impeccable .impeccable
npx impeccable skills link --source=.impeccable --providers=claude,cursor
git add .gitmodules .impeccable .claude .cursor
git commit -m "Add Impeccable skills"
```

使用项目所需的工具，例如 `Claude` 、 `cursor` 、 `Gemini` 、 `codex` 、 `github` 、 `opencode` 、 `pi` 、 `qoder` 、 `trae` 、 `trae-cn` 或 `rovo-dev` 。该命令从 `.impeccable/dist/universal/` 链接各个技能文件夹，并保留现有的真实技能目录不变，除非你传递 `--force` 。

To update later:

```
git submodule update --remote .impeccable
npx impeccable skills link --source=.impeccable --providers=claude,cursor
```

#### Usage

安装完成后，每条命令都会通过单一的 `/impeccable` 技能：

```
/impeccable audit        # Find issues
/impeccable polish       # Final cleanup
/impeccable distill      # Remove complexity
/impeccable critique     # Full design review
```

仅输入 `/impeccable` 即可查看完整的命令列表。

大多数命令接受一个可选参数以聚焦于特定区域：

```
/impeccable audit the header
/impeccable polish the checkout form
```

如果你经常使用某个命令，可以用 `/impeccable pin audit` 固定它，这样就能将 `/audit` 作为独立的快捷方式。

**注意：** Codex 在此处使用技能，而非 `/prompts:` 命令。打开 `/skills` 或输入 `$impeccable` 。仓库本地安装位于 `.agents/skills/` ；用户级安装位于 `~/.agents/skills/` 。GitHub Copilot 使用 `.github/skills/` 。如果新安装的技能未出现，请重启工具。

#### CLI

Impeccable 包含一个独立的 CLI，用于在无需 AI 框架的情况下检测反模式：

```
npx impeccable detect src/                   # scan a directory
npx impeccable detect index.html             # scan an HTML file
npx impeccable detect https://example.com    # scan a URL (Puppeteer)
npx impeccable detect --fast --json .        # regex-only, JSON output
```

该检测器在 AI 设计问题（侧边标签栏边框、紫色渐变、弹跳缓动、深色发光效果）和整体设计质量（行长度、紧凑内边距、小触摸目标、跳过的标题等）中发现了 41 个确定性问题。

## 结构化（1）

### 2026-03-11 10:57:17

**主旨概括：**  
Impeccable 是一套专门帮助 AI 做出更好前端设计的 “设计语言工具包”。它通过**更细的设计知识、17 个指令和明确的反模式约束**，减少 AI 常见的审美套路和低级设计问题。

---

##### 1. 这是什么：一个让 AI 更会做设计的工具
- 项目名叫**Impeccable**，核心定位是：  
  **“你原本不知道自己需要的设计词汇表”**。
- 它主要包含：
  - **1 个设计 skill**
  - **17 个命令**
  - **一套整理好的反模式规则**
- 目标是提升 AI 在**前端界面设计**上的表现，让生成结果更专业、更有控制力。

---

##### 2. 为什么要做：解决 AI 设计输出 “千篇一律” 的问题
- 文章指出，大模型都学过很多相似的通用模板，所以如果没有额外引导，常会犯类似问题：
  - 爱用**Inter**字体
  - 爱用**紫色渐变**
  - 喜欢**卡片套卡片**
  - 喜欢在彩色背景上放**灰色文字**
- Impeccable 的作用就是对抗这种 “默认偏见”，方法包括：
  - 提供**扩展版设计 skill**
  - 加入**7 个领域参考文件**
  - 提供**17 个可操控命令**
  - 明确告诉 AI **哪些设计不要做**

---

##### 3. 核心内容：7 个设计参考模块
Impeccable 把前端设计拆成 7 个关键领域，帮助 AI 更系统地理解设计：

- **typography（字体排版）**  
  包括字体系统、字体搭配、比例尺、OpenType。
- **color-and-contrast（颜色与对比）**  
  包括 OKLCH、带色中性色、深色模式、可访问性。
- **spatial-design（空间设计）**  
  包括间距系统、网格、视觉层级。
- **motion-design（动效设计）**  
  包括缓动曲线、错峰动画、减少动态效果。
- **interaction-design（交互设计）**  
  包括表单、焦点状态、加载模式。
- **responsive-design（响应式设计）**  
  包括移动优先、流式设计、容器查询。
- **ux-writing（UX 文案）**  
  包括按钮文案、报错信息、空状态提示。

---

##### 4. 17 个命令：让 AI 按需审查、优化和润色
文章给出了**17 个命令**，可以针对不同设计任务精确操作。重点包括：

- **/teach-impeccable**：一次性初始化，收集设计上下文并保存配置
- **/audit**：检查技术质量，如无障碍、性能、响应式
- **/critique**：做 UX 设计评审，看层级、清晰度、情绪表达
- **/normalize**：统一到设计系统标准
- **/polish**：上线前最后润色
- **/distill**：去掉多余复杂性，保留本质
- **/clarify**：优化不清楚的 UX 文案
- **/optimize**：提升性能
- **/harden**：处理错误、国际化和边界情况
- **/animate**：加入有目的的动效
- **/colorize**：更策略性地使用颜色
- **/bolder**：让无聊设计更有冲击力
- **/quieter**：让太激进的设计更克制
- **/delight**：增加 “惊喜感”
- **/extract**：提炼成可复用组件
- **/adapt**：适配不同设备
- **/onboard**：设计引导流程

**例子：**
- `/audit`：查找界面问题
- `/normalize`：修复不统一样式
- `/polish`：最终清理细节
- `/distill`：删掉多余设计元素

部分命令还支持指定范围，比如：
- `/audit header`
- `/polish checkout-form`

---

##### 5. 反模式规则：明确告诉 AI “不要这样设计”
这是文章很重要的一部分。Impeccable 不只是教 AI “该怎么做”，还强调 “不要怎么做”：

- 不要使用**过度滥用的字体**，如 Arial、Inter、系统默认字体
- 不要在**彩色背景上放灰色文字**
- 不要使用**纯黑或纯灰**，而是建议带一点色调
- 不要把所有内容都放进卡片，也不要**卡片里再套卡片**
- 不要使用**bounce /elastic**这类过时的弹跳缓动效果

这类规则很实用，因为很多 AI 设计问题正是来自这些 “常见但俗套” 的选择。

---

##### 6. 安装和使用方式：支持多种 AI 工具
Impeccable 可用于多个 AI 开发工具，文章列出了安装方式，支持：

- **Cursor**
- **Claude Code**
- **Gemini CLI**
- **Codex CLI**

使用方式很直接：安装后，在 AI 环境中输入命令即可，例如：
- `/audit`
- `/normalize`
- `/polish`
- `/distill`

其中：
- **Codex CLI**的语法不同，要写成：
  - `/prompts:audit`
  - `/prompts:polish`

---

#### Impeccable 最佳实践

##### 1. 先做一次初始化
首次在项目里使用时，先执行：

- `/teach-impeccable`

目的：

**建议提供的信息：**
- 品牌气质：专业 / 极简 / 年轻 / 高端

- 参考产品：你喜欢和不喜欢的案例
- 技术约束：组件库、设计系统、是否要兼容深色模式

---

##### 2. 不要一上来就`/polish`
很多人会直接要求 “美化一下”，这通常效果一般。  
**更好的顺序是：**

1. `/audit` —— 先找问题  
2. `/normalize` —— 统一设计系统  
3. `/distill` —— 去掉冗余  
4. `/polish` —— 最后润色

这个流程比直接 polish 更稳定。

---

##### 3. 用 “小范围命令”，不要总是改全站
优先聚焦具体模块，而不是整页一起改。

例如：
- `/audit header`
- `/polish checkout-form`
- `/clarify empty-state`
- `/animate onboarding`

**好处：**
- 改动更可控
- 更容易回滚
- 不会把原本正常的区域一起改坏

---

##### 4. 一次只追求一个目标
不要在一条命令里同时要求：
- 更高级
- 更活泼
- 更极简
- 更有品牌感
- 还要提升转化

这样容易让结果冲突。  
**最佳做法：单轮只解决一个核心问题。**

例如：
- 先`/distill`，减少复杂度
- 再`/colorize`，增加品牌识别
- 最后`/polish`，统一细节

---

##### 5. 把它当 “设计评审器”，不只是 “美化器”
Impeccable 最强的地方，不只是生成样式，而是**指出问题**。

优先多用：
- `/audit`：查无障碍、性能、响应式问题
- `/critique`：看层级、清晰度、情绪表达
- `/clarify`：优化按钮、提示、报错文案
- `/harden`：补齐异常、边界状态、i18n

这比单纯 “做得更好看” 更有价值。

---

##### 6. 先收敛，再增强
如果当前页面已经很乱，先用：

- `/normalize`
- `/distill`

- `/animate`
- `/colorize`
- `/delight`
- `/bolder`

**原则：**  
先解决秩序，再追求惊艳。

- 让 onboarding 更自然

**原则：**  
动效应该服务理解，而不是炫技。

## 总结（1）

### 2026-06-12 11:00:12

#### Impeccable 深度总结

##### 1. 它是什么？

**Impeccable 是一套给 AI 编码工具使用的前端设计语言 / 技能包。**

它不是单纯的 UI 组件库，也不是普通 lint 工具，而是让 Claude、Cursor、Gemini、Codex 等 AI 编码代理在生成前端界面时：

- 更懂产品背景
- 更懂品牌调性
- 更会做设计判断
- 更少产出 “AI 味” 界面
- 能自动检查常见设计问题

一句话：

> **Impeccable 试图把 “设计审美、设计流程、设计规则” 注入 AI 编码工作流。**

---

##### 2. 核心价值

###### 解决的问题

现在很多 AI 生成的前端页面高度同质化：

- 默认 Inter 字体
- 紫蓝渐变
- 卡片套卡片
- 彩色背景上放灰字
- 每个标题旁边都有圆角图标块
- 看似现代，实际模板味很重

Impeccable 的目标是：

> **让 AI 不只是 “会写界面”，而是 “更会设计界面”。**

---

##### 3. 它提供了什么？

###### ① 初始化设计上下文

运行：

```bash
/impeccable init
```

它会生成类似：

- `PRODUCT.md`
- `DESIGN.md`

用于记录：

- 产品定位
- 用户群体
- 品牌风格
- 语气
- 色彩
- 字体
- 组件规范
- 反面参考

这让后续 AI 操作不再 “凭空设计”。

---

###### ② 23 个设计命令

它把设计工作拆成一组清晰指令，例如：

| 命令 | 作用 |
|---|---|
| `/impeccable craft` | 从造型到实现的完整设计流程 |
| `/impeccable critique` | 做 UX / UI 评审 |
| `/impeccable audit` | 检查无障碍、性能、响应式 |
| `/impeccable polish` | 发布前精修 |
| `/impeccable bolder` | 让设计更有冲击力 |
| `/impeccable quieter` | 降低过度设计 |
| `/impeccable distill` | 去繁就简 |
| `/impeccable harden` | 补充异常、边界、国际化 |
| `/impeccable animate` | 添加有目的的动效 |
| `/impeccable typeset` | 优化字体和排版 |
| `/impeccable layout` | 优化布局和节奏 |
| `/impeccable live` | 浏览器中实时调视觉变体 |

本质上，它给 AI 和人类之间建立了一套共同的设计词汇。

---

###### ③ 41 条确定性检测规则

它可以不用 LLM、不用 API Key，直接扫描代码或网页：

```bash
npx impeccable detect src/
npx impeccable detect https://example.com
```

能识别常见问题：

- 紫蓝渐变滥用
- 卡片嵌套
- 弹跳动效
- 深色发光特效
- 行长过长
- 点击区域过小
- 标题层级跳跃
- 内边距过紧
- 可访问性问题

这部分更像是：

> **面向 AI 生成前端的设计 lint。**

---

##### 4. 通俗解读

如果把 AI 编码工具比作一个很快的装修工：

- 它会铺地板
- 会刷墙
- 会装灯
- 会做柜子

但问题是，它经常照着同一套 “网红样板房” 装修。

Impeccable 的作用像是给它配了一本：

> **设计说明书 + 审美规范 + 质检清单 + 现场设计总监。**

它会先问：

- 这是营销页还是产品后台？
- 用户是谁？
- 品牌应该克制还是张扬？
- 哪些设计风格不要碰？
- 颜色、字体、组件该怎么统一？

然后再让 AI 去做设计、改设计、审设计。

所以它不是替代设计师，而是让 AI 少犯低级审美错误。

---

##### 5. 最重要的创新点

###### 不是 “生成更多 UI”，而是 “约束 AI 生成 UI”

很多工具追求：

> 快速生成页面。

Impeccable 更强调：

> 生成之前先定方向，生成之后再做判断。

它把设计流程结构化了：

```text
理解产品 → 建立设计上下文 → 生成方案 → 检查反模式 → 精修 → 发布
```

这比单纯一句 “帮我做个好看的页面” 可靠得多。

---

#### 辩证思考

##### 优点

###### 1. 降低 AI 设计同质化

它明确反对常见 AI 审美套路，能减少模板味。

###### 2. 让设计过程可复用

`PRODUCT.md`和`DESIGN.md`让项目风格沉淀下来，而不是每次重新解释。

###### 3. 适合工程团队

它能接入 Cursor、Claude Code、Gemini CLI、Codex、Copilot 等工具，天然贴近开发流程。

###### 4. 确定性规则很有价值

不用依赖大模型也能检测问题，适合 CI、代码审查和团队规范化。

---

##### 局限

###### 1. 它不能真正替代高级设计判断

规则能发现 “常见错”，但不能保证 “真正美”。

好的设计还需要：

- 商业理解
- 用户洞察
- 品牌感知
- 情绪拿捏
- 文化语境

这些仍然依赖人。

###### 2. 反模式也可能变成新套路

今天反对 Inter、紫蓝渐变、卡片套卡片是合理的。

但如果所有人都用 Impeccable，新的 “Impeccable 风格” 也可能再次同质化。

###### 3. 对复杂品牌系统帮助有限

对于成熟品牌、复杂设计系统、大型产品矩阵，它更像辅助工具，而不是完整设计治理方案。

###### 4. 审美规则存在主观性

“不用弹跳动效”“不用纯灰”“不用 Inter” 并非永远正确。

规则有价值，但不能僵化。

---

#### 结论

**Impeccable 的本质，是给 AI 前端开发加上一层设计认知和质量控制。**

它最适合：

- AI 生成页面后需要精修的团队
- 缺少设计师的独立开发者
- 想降低 AI 审美套路的产品团队
- 希望把设计规范融入编码流程的工程团队

但它不是 “设计师替代品”。

更准确地说：

> **Impeccable 让 AI 更像一个有规范意识的初级设计执行者，而不是一个真正成熟的设计负责人。**
