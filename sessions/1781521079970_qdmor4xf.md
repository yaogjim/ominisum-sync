## 通俗精炼（1）

### 2026-06-15 10:54:39

#### 文章总结：用同一个 Prompt 测试各大 LLM 的前端生成能力

##### 核心观点

作者分享了一个自己认为“最强的 LLM 面试官 Prompt”，用于测试不同大模型在 **一次性生成 HTML 页面** 时的能力表现。

测试主题是：**“皇后镇景色特点 tree.js”**。  
作者将同一个较长 Prompt 分别投喂给不同 LLM，不做追加提示，直接比较它们输出的 HTML 源码与最终效果。

##### 测试方法

- 使用统一 Prompt，保证标准一致。
- 每个模型只调用一次，属于 **one-shot 测试**。
- 对比内容主要是：
  - HTML / DOM 结构复杂度
  - 页面渲染效果
  - 是否能正常运行
  - 控制台是否报错
  - 响应速度与稳定性

##### 各模型表现

###### Claude 3 Opus

从评论反馈看，Claude 3 Opus 效果较好。  
有人指出它生成的 DOM 元素数量比其他模型多约 30%，说明内容更丰富、结构更细。

###### Grok

作者评价 Grok 初看效果不错，虽然控制台有一个错误，但整体能够运行。

###### GPT

GPT 表现相对中规中矩，没有特别突出，也没有明显翻车。

###### Fable

Fable 生成的元素更多一些，可能在页面细节和结构丰富度上更积极。

###### Gemini 3.5 Flash

速度最快，但作者提到结果“搞半天不刷新出来”，说明虽然响应快，但实际渲染或稳定性存在问题。

##### 热门评论观点

评论区普遍认可这种测试方式：

- **统一标准，结果说话**，不同模型能力差异会比较直观。
- 这种复杂前端生成任务可能非常消耗 token。
- 有人建议作者升级调用的 AI，以获得更好效果。

##### 简要结论

这篇内容本质上是在用一个复杂 Prompt 对大模型进行“前端生成能力面试”。

它体现出几个关键信息：

1. **同一个 Prompt 下，不同 LLM 的执行质量差异明显。**
2. **Claude 3 Opus 在复杂 HTML / DOM 生成上可能更强。**
3. **速度快不等于效果好，Gemini Flash 就是典型例子。**
4. **one-shot 前端生成是检验 LLM 综合能力的有效方式**，能同时测试理解、规划、代码生成、视觉表达和运行稳定性。
