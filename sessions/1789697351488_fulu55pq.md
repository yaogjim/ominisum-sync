- **留存建议**：作为安全事件简报速览，无需长期保留
- **不足**：主要是厂商事件声明，缺少攻击细节、可核验证据和完整复盘方法。

**知识要点**

- 源代码泄露的影响评估应区分公开仓库、私有业务代码、客户数据与可用于横向移动的凭据。
- 第三方组件一旦接触CI/CD令牌，可能借助其仓库读取权限批量提取私有代码。
- 源码暴露后的基础处置包括排查敏感信息、轮换令牌与凭证，并持续监控异常活动。

**行动项**

- 盘点CI/CD组件持有的代码仓库访问令牌及其权限范围。
- 对可能受影响的令牌和凭证立即执行轮换与吊销。
- 检查私有仓库历史内容中的密钥、连接器配置及可用于横向移动的信息。

## 正文

2026 年 9 月 16 日，CrowdSec 获悉一起涉及我们 GitHub 代码仓库的源代码泄露事件，该事件发生于 2026 年 5 月。我们的团队已核实并确认了该报告。CrowdSec 源代码由两部分组成：一部分为私有代码，另一部分托管我们的自由开源软件（即安全引擎），后者按设计即为公开，因此不在本次事件范围内。然而，私有部分包含我们 SaaS 控制台的源代码、一些 AWS Cloud 例程、一些连接器以及自动化脚本。

声称涉及 300 个不同代码仓库的新闻标题是准确的（当包含 130 多个公开代码仓库时），不过这一数字主要反映的是代码的细分情况，而非具体数量。我们不确认任何“包含其他文件”或“内部开发材料”的说法，因为所有代码均已发布在这些代码仓库中。与 API 相关的信息是 CI/CD 组件本身所使用的令牌。（见下文）

没有任何客户数据、登录名/密码、姓名、组织或其他任何信息被泄露，CrowdSec 不存储 PII 或客户日志；影响仅限于 CrowdSec 自身。我们的团队迅速排查了任何可能促成横向移动的令牌、凭据或敏感信息泄露，但迄今为止未发现任何此类情况。

这些私有代码仓库中包含的代码具有价值，但无法真正对 CrowdSec 造成危害，因为我们的效率取决于我们的网络效应和规模，仅凭代码无法复制这一点。我们定期对 SaaS 源代码进行审计，其泄露也不应构成直接威胁。大部分泄露的代码在这四个月中已经发生了显著变化，但我们将密切监控任何异常活动。此外，在 CrowdSec 之外使用这些代码似乎不太可能，因为它仅与我们的数据和工具交互，无法真正在其他场景中加以利用。

我们将继续调查并随时向您通报最新进展，但 Tanstack 入侵事件极有可能就是泄露途径（更多详情见此），正如 Mistral AI 事件的情况一样。该组件于五月在我们组织中被使用，似乎已被植入后门，用于提取具有读取私有代码库授权的 API 密钥。该泄露仅在 2026 年五月的一个短暂时间窗口内可被利用。

尽管如此，我们仍立即轮换了所有必要的令牌和凭证，以防止进一步的事件发生。

团队谨此感谢 Fuites Infos 在报告该问题时所展现的及时、专业的联系。
