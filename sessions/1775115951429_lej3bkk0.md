#### Codeany

一个用于软件工程的开源 AI 驱动终端代理。使用 Go 语言构建，配合 [气泡茶](https://github.com/charmbracelet/bubbletea) TUI 和 [开放代理 SDK](https://github.com/codeany-ai/open-agent-sdk-go) 。

41 斜杠命令 \| 技能 &amp; 插件 \| MCP 支持 \| 中文/输入法输入 \| 自更新

#### Quick Install

```
curl -fsSL https://raw.githubusercontent.com/codeany-ai/codeany/main/install.sh | sh
```

Or install from source:

```
go install github.com/codeany-ai/codeany/cmd/codeany@latest
```

#### Setup

Set your API key:

```
export ANTHROPIC_API_KEY="sk-ant-..."
# Or for OpenRouter / custom providers:
export CODEANY_API_KEY="sk-or-..."
export CODEANY_BASE_URL="https://openrouter.ai/api"
export CODEANY_MODEL="anthropic/claude-sonnet-4-5"
```

#### Usage

```
# Interactive mode
codeany

# With initial prompt
codeany "explain this codebase"

# Pipe mode
echo "what is 2+2" | codeany -p

# Print mode (non-interactive)
codeany --print -y "list files in src/"

# JSON output
echo "hello" | codeany -p -y --output-format json

# Skip permission prompts
codeany -y

# Use specific model
codeany -m opus-4-6
```

#### Configuration

Config directory: `~/.codeany/`

```
~/.codeany/
├── settings.json      # Main config (model, permissions, MCP, hooks)
├── config.yaml        # YAML config (alternative)
├── permissions.json   # Persisted permission rules
├── memory/            # Memory files
├── sessions/          # Session history
├── skills/            # User skills
│   └── my-skill/
│       └── SKILL.md
└── plugins/           # Plugins
    └── my-plugin/
        ├── plugin.json
        └── skills/
```

##### settings.json

```
{
  "model": "sonnet-4-6",
  "permissionMode": "default",
  "maxTurns": 100,
  "mcpServers": {
    "filesystem": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "/tmp"]
    }
  },
  "hooks": {
    "preToolUse": [],
    "postToolUse": []
  }
}
```

#### Project Configuration

在你的项目根目录中创建 `CODEANY.md` （或 `CLAUDE.md` ）：

```
# Project Instructions

## Commands
- `npm test` to run tests
- `npm run build` to build

## Code Style
- Use TypeScript strict mode
- Prefer functional components
```

Also supports:

- `CODEANY.local.md` / `CLAUDE.local.md` — 个人的，已被 Git 忽略
- `.codeany/rules/*.md` / `.claude/rules/*.md` — 模块化规则

#### Skills

Create custom skills in `.codeany/skills/<name>/SKILL.md`:

```
---
name: deploy
description: Deploy to production
argumentHint: <environment>
---

Deploy the application to $ARGUMENTS environment.
Run the deployment script and verify health checks.
```

Invoke with: `/deploy staging`

#### MCP Servers

配置 MCP 服务器在 `settings.json` 中或使用 `/mcp` 进行管理：

```
/mcp              # List servers
/mcp tools        # List available tools
/mcp reconnect X  # Reconnect server
```

#### Codeany 是什么

Codeany 是一个**开源的 AI 终端代理**，面向软件工程场景打造。它基于 Go 开发，结合 TUI 交互界面和 Agent SDK，核心目标是：**让开发者直接在终端里用 AI 完成代码理解、修改、测试、审查和自动化操作**。

#### 核心价值

##### 1. 面向开发流程，而不是单点问答
它不是普通聊天机器人，而是一个嵌入开发工作流的 AI 工具。用户可以直接在终端里让它：
- 理解代码库
- 生成执行计划
- 做 Code Review
- 调试 Bug
- 跑测试
- 辅助提交代码

本质上，它想做的是一个 “**开发者副驾驶**”。

##### 2. 开源 + 本地终端，强调可控性
Codeany 采用开源模式，运行在终端环境中，配置、权限、历史会话、技能插件都由用户掌控。相比封闭式 AI IDE，它更适合：
- 注重可定制性的团队
- 希望接入自有模型 / 代理协议的开发者
- 重视透明度和可控性的技术组织

#### 产品能力

##### 1. 功能覆盖很完整
它提供了较丰富的斜杠命令，覆盖开发中的关键动作，例如：
- `/plan`：任务规划
- `/review`：代码审查
- `/bug`：问题排查
- `/test`：运行测试
- `/commit`：辅助 Git 提交
- `/mcp`：管理 MCP 服务
- `/config`、`/session`、`/permissions`：管理配置、会话和权限

这说明它不只想解决 “能不能生成代码”，而是想覆盖 “**从理解到交付**” 的全链路。

##### 2. 支持插件、技能和 MCP 扩展
Codeany 的扩展能力是亮点。它支持：
- **Skills**：把常用任务封装成可复用技能
- **Plugins**：通过插件扩展能力
- **MCP Servers**：接入外部工具和上下文源

这意味着它具备平台化潜力，不只是一个工具，更像一个可扩展的 AI Agent 框架。

#### 使用方式

##### 1. 上手门槛较低
安装方式很直接：
- 一键脚本安装
- Go 源码安装

使用方式也很灵活：
- 交互模式
- 传入初始 prompt
- 管道模式
- 非交互打印模式
- JSON 输出模式

对开发者来说，接入现有命令行习惯几乎没有障碍。

##### 2. 模型与服务商适配灵活
它支持通过环境变量配置：
- API Key
- Base URL
- 模型名称

既可以用 Anthropic，也可以接 OpenRouter 或其他自定义提供商。这意味着产品策略上，它并不绑定单一模型，而是强调**多模型兼容**。

#### 配置与治理能力

##### 1. 项目级规则明确
用户可以在项目根目录下通过`CODEANY.md`或`CLAUDE.md`写项目规则，比如：
- 如何运行测试
- 如何构建项目
- 代码风格要求

这让 AI 行为可以更贴近团队规范，而不是每次重复提示。

##### 2. 权限、会话、记忆都有沉淀
它内置了：
- 权限规则持久化
- 会话历史保存
- Memory 目录
- Hooks 机制

这代表 Codeany 不只是 “即时响应”，而是在往 “**持续协作型 Agent**” 方向发展。

#### 产品判断

##### 1. 适合谁
Codeany 更适合：
- 熟悉命令行的开发者
- 希望把 AI 深度融入研发流程的团队
- 想基于开源工具做二次定制的组织

##### 2. 它的真正竞争点
它的竞争力不在 “界面炫酷”，而在三点：
- **开源可控**
- **终端原生工作流**
- **可扩展的 Agent 架构**

如果说很多 AI 编程产品是在做 “更聪明的编辑器助手”，那 Codeany 更像是在做 “**开发终端里的通用 AI 操作系统**”。

#### 一句话总结

Codeany 是一个以软件工程为核心场景的开源 AI 终端代理，重点不只是生成代码，而是通过命令、规则、权限、插件和 MCP 扩展，把 AI 真正嵌入开发工作流。
