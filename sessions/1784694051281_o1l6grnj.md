## 结构化（1）

##### 主旨概括

Zane Chee 逆向分析了 OpenAI Codex 的计算机操作方式，并开发出 **pi-computer-use**：一款面向 macOS、可适配不同模型的计算机自动化工具。该工具优先使用无障碍接口（AX）进行操作，并在模型支持时通过视觉能力作为备用方案。

##### 工具的核心特点

- **与模型无关**：不限定使用某个特定 AI 模型，理论上可接入多种模型。
- **面向 macOS 用户**：主要为使用 pi 的 macOS 爱好者设计。
- **AX 优先导航**：优先通过 macOS 的 Accessibility（无障碍）接口识别和操作界面元素。
- **视觉回退机制**：对于具备视觉能力的模型，当 AX 无法完成操作时，可改用屏幕视觉识别。
- **提供源代码**：作者表示已在评论区附上源代码，并希望获得用户反馈。

##### 社区反馈与实际问题

###### 1. 无障碍权限与代码签名较复杂

有开发者指出，macOS 的**无障碍权限和代码签名配置较麻烦**。让用户自行编译，可以减少分发已编译二进制程序时遇到的签名、权限和安全限制问题。

###### 2. 前台与后台应用操作需要区分

社区建议为以下场景提供独立工具：

- 操作当前位于前台的应用；
- 操作处于后台的应用；
- 或至少增加一个“将指定应用窗口切换到前台”的功能。

作者也认同，前台与后台应用的自动化存在许多此前未预料到的复杂情况。

###### 3. 自动化过程可能抢占焦点

有用户反馈，当要求工具在 macOS 的“提醒事项”中创建内容时，应用会**抢走当前操作焦点**。这说明工具在后台执行和窗口焦点管理方面仍需改进。

###### 4. Windows 方案可作为参考

另一位开发者分享了 Windows 端的 **WinUI 自动化工具**实现，位于 `piclaw` 项目的 Windows 平台扩展中，可为跨平台适配提供思路。

###### 5. 模型兼容性仍待确认

有用户询问能否搭配 **Grok 4.5** 使用。虽然项目定位为“与模型无关”，但原文中没有给出明确答复，因此具体兼容性仍取决于模型接口及其视觉、工具调用能力。
