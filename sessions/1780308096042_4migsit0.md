## 分析要点

- **核心高价值点**：AI Agent不会自动消灭工作，反而会催生“管理自动化本身”的新职责。
- **留存建议**：短期参考后可选择性保留（包含AI Agent在真实工作场景中的组织形态、SaaS变化和岗位演化判断，可作为趋势观察材料。）

**知识要点**

- 高级工程师与AI模型的差距在于能否主动重新定义问题，而不只是执行已定义任务。
- 公司级通用Agent可能先于个人Agent普及，因为Agent需要持续维护和上下文照料。
- 未来SaaS的机会可能不是内置AI，而是让产品对人类和Agent都友好。
- 产品经理和设计师可借助AI编程工具直接把洞察转化为可运行产品。

**行动项**

- 选择一个真实工作痛点，用最新AI工具完整尝试解决一次。
- 评估现有工作流中哪些环节适合由公司级或团队级Agent统一处理。
- 检查产品或工具是否对Agent友好，例如是否易于访问、复现、提交问题和协作。
- 持续测试新模型在核心任务上的表现，而不是只看通用榜单。

## 正文

**向阳乔木**

### AI越强，人越忙：一个住在未来的人说了什么

著名PM人Lenny访谈了Every公司的CEO，很多观点犀利且反共识，让AI写一篇总结。

> 原始视频：
>
> [https://www.youtube.com/watch?v=4D3hDmGhFhA](https://www.youtube.com/watch?v=4D3hDmGhFhA)

一家 30 人的公司，全员 AI 重度用户，人人用 Codex 和 Claude Code 干活。

按理说，这种公司应该越来越精简才对。

但过去一年，他们的员工人数翻了一倍。

这家公司叫 Every，CEO 叫 Dan Shipper。

他不是在硅谷的实验室里预测未来，他是真的住在未来。

工程师、编辑、销售、客服，所有人都在用最新的AI工具干活，然后 Dan 会把他们实战的经验和观察写出来。

去年他说 Claude Code 被严重低估，没人信，后来 Anthropic 围绕这个方向建了整个产品线。

所以当他说"AI 越强，人反而越忙"，值得认真听一听。

#### 自动化是个谎言

![Image](https://pbs.twimg.com/media/HJX1T_jaYAAyXCf?format=jpg&name=large)

Dan 说这不是在抱怨，他是在描述一个他亲身经历的悖论。

他自己做了一个Benchmark，叫"高级工程师基准测试"。

起因很狼狈：他把自己的写作工具 Proof 用 vibe coding 做出来，上线第二天服务器每隔 10 分钟就崩一次。

他让 Codex 修，Codex 说修好了，然后又冒出四个新 bug，循环往复，一晚上没睡着。

后来他请了两位真正的高级工程师，分别独立重写了这个代码库。

于是他有了这个"高级工程师基准测试"：让 AI 接手同一个烂摊子，从头重写。

结果：几乎所有模型得分在 30 分左右。人类高级工程师能到 85 到 90 分。

GPT-5.5 是唯一的异类，跳到了 62 分。

而且它是唯一一个真的敢推倒重来的模型，其他模型接到"去修这些 bug"的指令，就真的去一个一个修 bug 了。

人类高级工程师会怎么做？

他会先扫一眼代码库，然后说："这玩意儿是坨屎，我们得重写，我知道你不想听，但就是这样。"

他自己判断出来的。

模型能解决被定义清楚的问题，但"发现这个问题需要被重新定义"这件事，模型还不会主动做。

基准测试的分数在涨，但它永远只能测量人类已经想清楚、能打分的那部分工作。

剩下那部分，没法打分，因为你得先想到要问这个问题。

这就是为什么 Every 的人越招越多。

每一个 Agent 背后，都需要一个真正关心它在做什么的人。

自动化没有消灭工作，它创造了新的工作：管理自动化本身。

Dan 把这叫做"每个 Agent 都需要一个人"。

#### 工作会分裂成两种形态

![Image](https://pbs.twimg.com/media/HJX1G_iasAAO-u4?format=jpg&name=large)

Dan 的预测是：未来一年内，大多数人的工作方式会朝两个方向同时演化。

第一种：公司共用一个超级 Agent。

不是每个人一个私人助理，而是整个公司共用一个 Agent，挂在 Slack 里，所有人都能调用。

Shopify 已经有了，Ramp 也有了。

Dan 最初以为每个人都会有自己的私人 Agent，像《黄金罗盘》里每个人肩上的精灵，是灵魂的一部分。

> 黄金罗盘一口气解读版
>
> [https://www.bilibili.com/video/BV156421c74o/](https://www.bilibili.com/video/BV156421c74o/)

他对这个图景着迷了很久，然后彻底改变了看法。

原因很简单：Agent 需要有人照料它。

OpenClaw 刚出来的时候，Every 所有人都兴冲冲地设置了自己的 Agent，然后一个个放弃了。

因为它会坏，要 SSH 进服务器，要不停地调整，大多数人坚持不了多久。

一旦没人关心它在做什么，它就会悄悄变得没用。

所以现实的路径是：先有一个公司级别的通用 Agent，由专人负责维护，再随着模型变得更可靠，逐渐向下分裂出团队级别、个人级别的 Agent。

这个专门负责维护 Agent 的人，Dan 叫他"前沿部署工程师"，Every 内部已经有这样的岗位了。

> 前沿部署工程师模式（Forward Deployed Engineer，FDE）起源于Palantir，其核心在于通过“驻场工程师+业务专家”的协同模式，将技术能力与业务需求深度融合.

第二种：Codex 或 Claude Code 成为新的工作操作系统。

这是 Dan 更兴奋的部分，也是更难一句话说清楚的部分。

他现在处理邮件的方式是：让 Codex 打开内置浏览器，把所有邮件聚合到一个页面，然后他对着屏幕说话。

"这封律师的问题，去把过去四年的文件整理成报告发过去。"

Codex 就去做了。

他已经连续 10 天保持收件箱清零，这对他来说是从没有过的事。

写文章也一样。

他在 Codex 的内置浏览器里打开 Proof，Codex 能看到他在写什么，他也能看到 Codex 在做什么，两者实时协作。

招人也是，他想找一个在 General Assembly 做过技术教育、现在又对 AI 感兴趣的人，直接跟 Codex 说。

然后他就做别的事了，回来发现 Codex 找到了一个完全符合条件的人，还在 Twitter 上关注了他。

Dan 直接发了私信，约了顿饭。

过去我们把 AI 嵌进 SaaS 工具，未来是把 SaaS 工具放进 AI Agent 里跑。

他在 Codex 里用 Proof，用的是他自己的 token，不是 Proof 这个产品的 token。

SaaS 厂商不需要烧钱堆 AI 功能，用户把 AI 带过来，SaaS 只需要让自己对人和 Agent 都友好就够了。

利润率反而可能回升。

#### CLI 时代已经结束了

![Image](https://pbs.twimg.com/media/HJX1INjaAAA50fM?format=jpg&name=large)

Dan 说得很直接：CLI 的时代过去了，我们把它速通了。

Claude Code 火起来的时候，很多人以为是终端命令行的魔力让它好用。

Dan 认为这个判断是错的。

真正的原因是 Agent 在本地机器上有完整的访问权限，以及网上有大量关于如何使用终端的内容，让模型学得很好。这和 CLI 本身没什么关系。

Every 内部，大多数技术人员已经不把终端当主要工作界面了。

偶尔还会切进去，但主战场是 Codex、Claude Code、Cursor 这些有真正界面的工具。

GUI 本来就是为了让人更舒服而发明的，这个逻辑没有变过。

#### SaaS 不会死，Agent 会给它带来更多用户

![Image](https://pbs.twimg.com/media/HJX1JtSaEAAZMlq?format=jpg&name=large)

Dan 说他现在会买 SaaS 股票。

大家都在说 Agent 会让人绕过 SaaS，直接用 AI 干活。

但 Dan 的观察是反过来的：Agent 不会替代 SaaS 的用户，它会成为 SaaS 新的用户。

Every 内部人人都用 Codex 和 Claude Code，但他们的 SaaS 支出比去年还高。

因为 Agent 在用 SaaS，大量的 Agent，高频次地调用。

需求在爆炸，不是萎缩。

他还提到一个细节：Every 的 Proof 是开源的，用户遇到问题，不是自己发邮件给客服，而是他们的 Agent 直接发一份 bug 报告，里面有精确的复现步骤，有对代码库的分析，直接变成 GitHub issue，然后 Every 的 Agent 去修。

这个闭环，比任何人工客服流程都快。

对 SaaS 公司来说，真正需要做的事情变了：不是把 AI 塞进自己的产品，而是让产品同时对人和 Agent 友好，两者能在同一个界面上协作，各自看到对方在做什么。

#### PM 和设计师，迎来最好的时代

![Image](https://pbs.twimg.com/media/HJX1LxVbIAALjND?format=jpg&name=large)

Dan 对这两个角色极度看好。

Marcus，PM 出身，之前在 Axios 负责写作产品，带大团队做到了几千万 ARR。

后来他休息了一年，专门学会了用 Cursor。

现在他在 Every 负责写作应用 Spiral，是团队里出货最快的人之一。

Dan 说，哪怕一年前，他们也没办法安排 Marcus 做这个工作，因为那时候模型还不够好。

但现在，Marcus 的产品感和用户洞察，配上足够好的编程模型，变成了一种超强组合。

他不需要组织一整个团队来实现自己的想法，他直接去做。

设计师也一样。

以前最大的痛苦是：想到了一个绝妙的交互，工程师不想做，或者做出来不是那个味。

现在他们可以自己发 Pull Request，自己把想法变成现实。

而且，当所有人都在用 vibe coding 批量生产千篇一律的界面时，真正懂审美、懂交互的设计师反而更值钱。

能让东西看起来不像 AI 做的，本身就是一种稀缺能力。

#### AI 不会让你失业，但不用 AI 会

![Image](https://pbs.twimg.com/media/HJX1MUJaEAA97om?format=jpg&name=large)

Dan 的判断是：大规模失业不会发生。

那些被归因于 AI 的裁员，大多数是过度招聘的修正，AI 只是一个方便的借口。

但这不意味着可以躺平。

他给出的建议只有一条，叫"骑上（驾驭）模型"。

不是因为 FOMO，不是因为害怕，而是因为好奇。

每次有新模型出来，把它用在你真正在乎的事情上。

哪怕上次试过不行，这次再试一次看看。

他自己就是这么做的，GPT-5.5 出来，他把高级工程师基准重新跑了一遍，从 30 分跳到了 62 分。

他还说了一件让人意外的事：AI 的真正前沿不在旧金山，而在每一个把 AI 用在真实工作场景里的人那里。

硅谷的人在造它，但不一定知道怎么用好它。

每次新模型出来，你是世界上最早一批发现它能做什么的人之一。

Every 在布鲁克林，不在硅谷。

但 Dan 觉得他们比大多数硅谷公司都更靠近未来，原因只有一个：他们把所有工具都真的用在真实的工作上。

这是他给出的最后一个建议：别争论 AI 会不会改变世界，去找一件你真正头疼的事，试着用 AI 解决它。

当你第一次感受到"这也行？"的那一刻，你就不需要别人再来说服你了。

#### AI越强，人越忙：精炼解读

##### 一、内容总结

核心观点：**AI 没有让人变闲，反而让人更忙。**

原因不是 AI 没用，而是：

- AI 能做事，但需要人判断方向。
- AI 能执行任务，但需要人维护、监督、纠偏。
- AI 自动化了旧工作，同时创造了新工作。

Every CEO Dan Shipper 的观察是：

> 每一个 AI Agent 背后，都需要一个真正关心它的人。

文章主要讲了几件事：

1. **AI 还不等于高级工程师**  
   AI 会修 bug，但不一定会判断“这套东西该推倒重来”。

2. **未来公司会有公共 AI Agent**  
   不是人人一个私人助理，而是公司先养一个“公司级 Agent”，由专人维护。

3. **AI 会变成新的工作入口**  
   未来不是在 SaaS 里加 AI，而是在 AI 里调用 SaaS。

4. **SaaS 不会死**  
   Agent 会成为 SaaS 的新用户，反而增加使用量。

5. **PM 和设计师机会变大**  
   会用 AI 的产品经理、设计师，可以直接把想法做出来。

6. **AI 不会让你失业，不用 AI 才危险**  
   真正的建议是：别观望，直接拿 AI 解决你手头真实的问题。

---

##### 二、深入浅出解读

###### 1. AI 越强，为什么人越忙？

因为 AI 像一个很强的实习生：

- 你让它做事，它能做很多。
- 但它可能理解错。
- 它可能修一个问题，带来四个新问题。
- 它不会总是主动判断“这件事根本不该这么做”。

所以人的工作从“亲自干活”，变成了：

> 定目标、拆任务、检查结果、纠正方向、维护系统。

这不是工作消失，而是工作升级。

---

###### 2. 自动化不是终点，管理自动化才是新工作

很多人以为：

> 有了 AI，公司就不需要那么多人了。

但现实可能是：

> 有了 AI，公司能做更多事，所以反而需要更多人管理这些 AI。

AI 带来的不是简单裁员，而是工作密度上升。

以前一个人做 3 件事，现在 AI 帮你做 30 件事。  
但你要负责判断这 30 件事做得对不对。

---

###### 3. 未来的核心能力不是“会不会写代码”

文章里最重要的变化是：

PM、设计师、运营这些角色，只要会用 AI，就能直接做产品。

以前：

> 有想法 → 找工程师 → 排期 → 开发 → 修改

现在：

> 有想法 → 跟 AI 说 → 自己做出原型甚至产品

所以真正值钱的能力会变成：

- 判断力
- 审美
- 用户理解
- 产品感觉
- 问题定义能力
- 驾驭 AI 的能力

---

###### 4. SaaS 不会被 AI 吃掉，而是会被 AI 使用

以前用户是人。  
以后用户可能是：

- 人
- AI Agent
- 人和 AI 一起协作

所以 SaaS 公司真正要做的，不只是“加个 AI 按钮”，而是让产品变得：

> 人好用，AI 也好用。

谁能让 Agent 更方便调用，谁就可能获得更多流量和收入。

---

##### 三、我的意见

我认同文章的大方向：**AI 不是让人躺平的工具，而是放大人的工具。**

但它放大的不是所有人，而是这几类人：

- 会提问的人
- 会判断的人
- 会拆解问题的人
- 愿意反复试的人
- 有真实业务场景的人

AI 最怕两种人：

1. **只等答案的人**  
   他们会被 AI 的错误带偏。

2. **完全不用 AI 的人**  
   他们会被会用 AI 的同行拉开差距。

最实际的建议是：

> 不要空谈 AI。  
> 找一个你每天都烦的问题，用 AI 反复试。  
> 试到它真的帮你省时间、提质量、扩能力。

AI 时代，最重要的不是“懂 AI”，而是：

> 把 AI 用进真实工作里。

## 结构化（1）

### 2026-06-01 10:07:15

#### 《AI越强，人越忙：一个住在未来的人说了什么》精炼总结

文章通过 Every CEO Dan Shipper 的实践观察指出：AI 并没有简单地“消灭工作”，反而让人类承担起更多管理、判断和协作的任务。未来真正有价值的人，不是被 AI 替代的人，而是能驾驭 AI、把它用在真实问题上的人。

---

##### 1. Every 的反常现象：AI 用得越深，公司反而越扩张

Every 是一家约 **30 人**的公司，全员重度使用 AI 工具，如 **Codex、Claude Code**。

按常理，AI 应该让公司更精简，但 Every 过去一年员工数量反而**翻了一倍**。

关键原因是：

- AI 能提升效率，但也会带来新的工作；
- 每个 AI Agent 背后，都需要人来维护、判断和管理；
- 自动化没有消灭工作，而是创造了“管理自动化”的新工作。

Dan Shipper 将其概括为：**“每个 Agent 都需要一个人。”**

---

##### 2. “自动化是个谎言”：AI 还不会主动重新定义问题

Dan 做了一个“高级工程师基准测试”。

起因是他用 vibe coding 做了写作工具 **Proof**，上线第二天服务器每隔 **10 分钟崩一次**。他让 Codex 修复，结果是：

- Codex 修了一个 bug；
- 又冒出四个新 bug；
- 问题反复出现，无法彻底解决。

后来他请了两位高级工程师独立重写代码库，并据此设计测试：让 AI 接手同一个烂摊子，从头处理。

测试结果：

- 大多数模型得分约 **30 分**；
- 人类高级工程师能达到 **85-90 分**；
- **GPT-5.5** 是例外，达到 **62 分**。

差异在于：

- 普通 AI 会按指令逐个修 bug；
- 高级工程师会先判断：“这套代码已经不值得修，应该重写。”

也就是说，AI 擅长解决被清楚定义的问题，但还不擅长主动发现：**这个问题本身需要被重新定义。**

---

##### 3. 未来工作形态之一：公司级超级 Agent

Dan 认为，未来一年内，很多公司的 AI 使用方式会分化出一种形态：**全公司共用一个超级 Agent**。

它不是每个人一个私人助理，而是挂在 Slack 等工作流中的公司级 Agent，所有人都能调用。

已有类似实践的公司包括：

- **Shopify**
- **Ramp**

Dan 最初也相信“每个人都有一个私人 Agent”，但后来改变了看法。

原因是：

- Agent 需要持续维护；
- 它会出错、会坏、需要配置服务器；
- 如果没人持续关心，它很快就会变得没用。

Every 曾尝试让每个人配置自己的 Agent，但大家后来陆续放弃，因为维护成本太高。

因此更现实的路径是：

1. 先出现公司级通用 Agent；
2. 由专人维护；
3. 随着模型更可靠，再分化成团队级、个人级 Agent。

Every 内部已经出现了这种岗位，Dan 称其为 **“前沿部署工程师”**。

---

##### 4. 未来工作形态之二：Codex / Claude Code 成为新的操作系统

Dan 更看好的另一种趋势是：**Codex、Claude Code 这类工具会成为新的工作操作系统。**

它们不只是写代码工具，而是承载各种工作任务的入口。

例如 Dan 处理邮件时：

- 让 Codex 打开内置浏览器；
- 聚合所有邮件；
- 他直接对屏幕说话，下达任务；
- Codex 根据邮件内容整理文件、生成报告并发送。

他提到，自己已经连续 **10 天收件箱清零**，这是以前从未做到过的事。

在写文章时：

- 他在 Codex 里打开 Proof；
- Codex 能看到他正在写什么；
- 他也能看到 Codex 在做什么；
- 双方像同事一样实时协作。

在招聘时：

- 他告诉 Codex 想找“曾在 General Assembly 做过技术教育、现在对 AI 感兴趣的人”；
- 之后自己去做别的事；
- Codex 找到了符合条件的人，并在 Twitter 上关注了对方；
- Dan 最后直接私信约饭。

这说明未来的趋势可能是：

> 过去是把 AI 嵌进 SaaS 工具里，未来是把 SaaS 工具放进 AI Agent 里运行。

---

##### 5. CLI 时代已经过去，真正重要的是 Agent 的权限和界面

Dan 认为，很多人误解了 Claude Code 的成功原因。

有人以为它好用是因为终端命令行 CLI 很强，但 Dan 认为不是。

真正原因是：

- Agent 在本地机器上拥有完整访问权限；
- 互联网上有大量关于如何使用终端的资料，模型学得很好；
- 这不代表 CLI 本身是未来。

在 Every 内部，大多数技术人员已经不再把终端作为主要工作界面。

他们更多使用：

- Codex
- Claude Code
- Cursor

这些带有真实界面的工具。

Dan 的判断是：**CLI 的时代被快速越过了，GUI 仍然重要，因为它更适合人类使用。**

---

##### 6. SaaS 不会死，Agent 反而会成为 SaaS 的新用户

很多人认为 Agent 会绕过 SaaS，让 SaaS 公司失去用户。

Dan 的观察恰好相反：**Agent 会成为 SaaS 的新用户。**

Every 内部人人都用 Codex 和 Claude Code，但他们的 SaaS 支出不降反升。

原因是：

- 人在用 SaaS；
- Agent 也在用 SaaS；
- 大量 Agent 会高频调用 SaaS 服务；
- SaaS 的需求不是萎缩，而是在爆发。

Dan 还举了 Proof 的例子：

- Proof 是开源产品；
- 用户遇到问题时，不再是人写邮件给客服；
- 用户的 Agent 会自动生成 bug 报告；
- 报告包含复现步骤和代码库分析；
- 直接变成 GitHub issue；
- Every 的 Agent 再去修复。

这个闭环比传统人工客服更快。

因此，SaaS 公司未来真正要做的不是盲目把 AI 塞进产品，而是：

- 让产品对人友好；
- 也让产品对 Agent 友好；
- 让人和 Agent 能在同一个界面里协作。

---

##### 7. PM 和设计师迎来好时代

Dan 特别看好产品经理和设计师。

他举了 Marcus 的例子：

- Marcus 是 PM 出身；
- 曾在 Axios 负责写作产品；
- 带团队做到数千万美元 ARR；
- 后来花一年学习 Cursor；
- 现在在 Every 负责写作应用 Spiral；
- 成为团队里出货最快的人之一。

过去，PM 想做产品需要依赖工程团队；现在，产品感强的人可以借助 AI 直接把想法做出来。

设计师也类似。

以前设计师的痛苦是：

- 想出好交互；
- 工程师不愿做；
- 或者做出来不是原来的感觉。

现在设计师可以：

- 自己写代码；
- 自己发 Pull Request；
- 自己把想法变成现实。

当大量人用 vibe coding 生产同质化界面时，真正懂审美、懂交互的设计师会更稀缺。

能做出“不像 AI 生成”的产品，反而成为一种重要能力。

---

##### 8. AI 不一定让人失业，但不用 AI 会让人落后

Dan 不认为 AI 会导致大规模失业。

他认为，很多被归因于 AI 的裁员，其实是过去企业过度招聘后的修正，AI 只是一个方便的理由。

但这不代表人可以无视 AI。

他的建议是：**“骑上模型”**，也就是主动驾驭模型。

具体做法是：

- 每次有新模型出来，都亲自试试；
- 不要只是围观或争论；
- 把它用在自己真正关心、真正头疼的问题上；
- 哪怕上次试失败了，下次模型更新后也再试一次。

比如 GPT-5.5 出来后，Dan 重新跑了高级工程师基准测试，发现分数从约 **30 分**跃升到 **62 分**。

这说明模型能力会突然跨越，持续尝试很重要。

---

##### 9. AI 的真正前沿在真实工作场景中

Dan 认为，AI 的前沿不只在旧金山或实验室里。

硅谷的人可能在制造 AI，但不一定最懂如何使用 AI。

真正的前沿在每一个把 AI 用到真实工作中的人那里。

Every 位于布鲁克林，不在硅谷，但 Dan 认为他们更接近未来，因为他们：

- 不只是讨论 AI；
- 而是真的把 AI 用进工程、编辑、销售、客服等日常工作；
- 从真实问题中发现 AI 的能力边界和新机会。

他的最后建议是：

> 不要只争论 AI 会不会改变世界，去找一件你真正头疼的事，试着用 AI 解决它。

当你第一次感受到“这也行？”的时刻，就不再需要别人说服你相信 AI 的价值了。
