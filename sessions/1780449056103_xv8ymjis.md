## 解读（1）

#### 深度总结

这条内容讨论的是一种新的 AI 工程实践：**Code Mode / Search as Code**。

核心意思是：

> 不再让 AI Agent 一步步调用复杂 API，而是让它直接生成并运行代码，通过代码调用底层能力栈。

以 Perplexity 的 **Search as Code** 为例：

- 传统方式：Agent 反复调用搜索函数、解析结果、再调用下一步。
- 新方式：Agent 直接写 Python 代码，调用 Perplexity 的搜索栈完成任务。
- 结果：减少中间步骤，提高效率、稳定性和输出质量。

郭宇认为，这类模式类似 **Cloudflare Dynamic Worker**，也可以看作把复杂 API 封装成不同的 **micro agent runtime**。

它的特点是：

| 模式 | 特点 |
|---|---|
| REST API | 固定接口，适合传统软件 |
| MCP | 标准化工具协议，能力强但成本较高 |
| Skill 即时生成 | 灵活但输出质量不稳定 |
| Code Mode | 用代码组织调用，成本较低，适应性和质量较好 |

一句话总结：

> Code Mode 是让 Agent 从“调用工具”升级为“写代码调度能力”。

---

#### 深入浅出解读

可以把它理解成三种工作方式。

##### 1. 传统 API：像填表

你告诉系统：

```text
调用搜索接口
参数是 A
返回结果 B
```

优点是稳定，缺点是不够灵活。  
复杂任务需要反复调用很多接口，像一层层填表。

---

##### 2. Agent 调工具：像请助理跑腿

Agent 会想：

```text
我先搜索一下
再总结一下
再继续查
再对比一下
```

这种方式更智能，但容易出现：

- 步骤太多
- 成本变高
- 上下文变乱
- 中间结果噪音多
- 长任务稳定性下降

---

##### 3. Code Mode：像让工程师写脚本

Agent 不再一步步“跑腿”，而是直接写一段代码：

```python
results = search(query)
filtered = rank(results)
summary = summarize(filtered)
```

它把多个动作组织成一个可执行流程。

好处是：

- 少绕弯
- 更确定
- 更容易复用
- 更适合长任务
- 输出质量更稳定

所以 Perplexity 的 **Search as Code** 本质上是：

> 把搜索能力变成 Agent 可编程调用的运行环境。

---

#### 关键价值

##### 1. 降低 Agentic Loop 噪音

传统 Agent 会不断：

```text
思考 → 调工具 → 观察 → 再思考 → 再调工具
```

循环越长，越容易失控。

Code Mode 把这些步骤压缩成代码流程，减少无效循环。

---

##### 2. 提升确定性

代码比自然语言步骤更明确。

自然语言可能含糊：

```text
帮我查一下最重要的信息
```

代码可以明确：

```python
top_results = search(query, limit=10)
```

这让系统更可控。

---

##### 3. 比 MCP 更轻

MCP 偏协议化、标准化，适合连接各种工具。  
但它也意味着接入、维护和运行成本更高。

Code Mode 更像：

> 给 Agent 一个可运行的小型能力环境。

不一定要完整协议，但足够实用。

---

##### 4. 比 Skill 更稳

Skill 通常是临时生成或调用某种能力。  
灵活，但可能不稳定。

Code Mode 把能力写成代码逻辑，结构更清晰，质量更可控。

---

#### 我的辩证思考

##### Code Mode 是趋势，但不是万能解

它确实解决了当前 Agent 的一个核心问题：

> Agent 太爱“绕圈子”，而代码能让流程更短、更稳。

尤其适合：

- 搜索
- 数据分析
- 报表生成
- 工作流自动化
- 多步骤工具调用
- 长任务执行

但它也有风险。

---

##### 风险一：代码生成带来安全问题

让 Agent 写代码并执行，天然存在风险：

- 越权调用
- 数据泄露
- 代码注入
- 无限循环
- 资源滥用

所以 Code Mode 必须配套：

- 沙箱
- 权限控制
- 日志审计
- 资源限制
- 可回滚机制

否则它不是生产力工具，而是事故放大器。

---

##### 风险二：调试难度可能上升

表面上看，代码更清晰。  
但当 Agent 生成的代码越来越复杂时，问题会变成：

> 谁来理解这些 AI 写出来的流程？

如果缺少可观测性，Code Mode 也可能变成新的黑箱。

---

##### 风险三：可能削弱 API 标准化

REST API、MCP 的价值在于标准化。  
Code Mode 更灵活，但也可能导致每家公司都搞自己的 runtime。

短期效率高，长期可能产生新的碎片化。

---

#### 最精炼结论

**Code Mode / Search as Code 的本质：**

> 让 AI Agent 不再机械调用工具，而是通过代码直接编排底层能力。

它的优势是：

- 更快
- 更稳
- 更便宜
- 更适合复杂任务

但前提是：

- 安全可控
- 可观测
- 可调试
- 有清晰边界

最终它可能不会完全取代 REST API 或 MCP，而是成为 AI 时代新的中间层：

> API 给人类软件用，Code Mode 给 AI Agent 用。
