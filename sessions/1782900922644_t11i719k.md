## 正文

Two [MCP](https://modelcontextprotocol.io) (Model Context Protocol) servers are available for working with X from AI tools:

---

#### X MCP — X API

Connect any MCP-compatible AI tool (Grok Build, Cursor, Claude, VS Code, and others) directly to the **X API**. The model can then search the full archive, look up users, manage bookmarks, fetch trends and news, and draft Articles — all with your own X account’s permissions.The X API exposes a hosted **Streamable HTTP** MCP server at **`https://api.x.com/mcp`** (protocol `2025-06-18`, `serverInfo: xmcp`). You reach it through the open-source **`xurl mcp`** bridge, which handles OAuth for you and injects a fresh Bearer token on every call.

##### Capabilities at a glance

##### How it works

X’s OAuth requires *your own* developer app. There is no dynamic client registration, and `api.x.com/mcp` does not advertise native MCP OAuth discovery. Instead of pointing your client at the URL directly, you run a tiny local bridge. The bridge owns the app identity, performs the one-time login, and keeps the token fresh.

- The bridge runs via the **npm launcher** (`npx`), so there is **no separate install step**.
- On **first run with no cached token**, it opens your browser for a one-time OAuth2 login, then caches and **auto-refreshes** the token forever after.
- All diagnostics go to **stderr**; **stdout stays a clean JSON-RPC channel**.

##### Getting started

Pick one of two routes:

- **Simple — App-only Bearer.** Paste your app’s Bearer token into an `Authorization` header on the MCP client. No bridge, no browser login. Read-only endpoints; no user context (can’t act as you). Works with clients that support remote MCP with custom headers.
- **Full — `xurl mcp` bridge (OAuth 2.0 user context).** A local bridge handles the OAuth 2.0 PKCE login and auto-refreshes tokens, so the model acts with your account’s scopes. Required for writes (bookmarks, Articles) and any user-context tool.

###### Simple route (app-only Bearer)

1. **Create an X app** in the [X Developer Portal](https://developer.x.com).
2. **Copy your App-only Bearer token** from the app’s “Keys and tokens” page.
3. Point your client at `https://api.x.com/mcp` with the token as an `Authorization` header — see App-only (direct URL, no bridge) below for the snippet.

###### Full route (xurl bridge)

1. **Create an X app** with **OAuth 2.0** enabled.
2. **Register the redirect URI** `http://localhost:8080/callback` on the app (required for the first-run browser login). To use a different one, set `REDIRECT_URI` and register that instead.
3. **Copy your `CLIENT_ID` and `CLIENT_SECRET`** — you’ll put them in the client config.
4. **Have Node.js installed** (for `npx`).
5. We recommend you **install [xurl](https://github.com/xdevplatform/xurl)**:

##### Authentication

###### OAuth 2.0 user context (default)

The bridge authenticates as **you** (PKCE flow), so tools act with your account’s scopes. Resolution order for credentials: **`CLIENT_ID` / `CLIENT_SECRET` env vars → the active app in `~/.xurl`**. The bridge caches tokens in `~/.xurl` and refreshes them automatically (including a forced refresh after a `401`).

###### First-run browser login

With no cached token, the bridge prints to stderr and opens your browser:The MCP handshake is held until you finish — that’s why clients need a generous `startup_timeout_sec`.

###### Headless / remote machines

No reachable browser? Authenticate once out-of-band, then start the client:

###### App-only (direct URL, no bridge)

For read endpoints, you can skip the bridge and point a client straight at the URL with a **static App-only Bearer token**. This is useful for clients that support remote MCP with custom headers:Trade-off: no auto-refresh and no user context (no actions as you). The bridge is recommended for full functionality.

###### Multiple apps &amp; accounts

In a client config, add `"--app", "my-app"` or `"-u", "alice"` to `args`.

##### Configuration reference

Advanced env overrides (rarely needed): `AUTH_URL`, `TOKEN_URL`, `API_BASE_URL`, `INFO_URL`.

##### Verify &amp; troubleshoot

Symptom Cause / Fix

Client times out on startup Raise `startup_timeout_sec` to 300+; the bridge is waiting on your browser login

Browser never opens No display (headless) → run `xurl auth oauth2 --headless` first; ensure `npx` resolves

`401` / `token refresh failed` App credentials wrong, or refresh token revoked → re-run the login (`xurl auth oauth2 [--app NAME]`)

Redirect/callback error in browser `http://localhost:8080/callback` not registered on the app (or `REDIRECT_URI` mismatch)

`client-not-enrolled` after login App isn’t in the right X package/environment → in the portal move it to **Pay-per-use** + **Production**

`npx` pulls a stale version A private registry mirror is default → pin `--registry=https://registry.npmjs.org/` in `args`

Empty/garbled tool output Don’t run the client with `--verbose`; stdout must stay a clean JSON-RPC channel

##### Security &amp; best practices

- **Treat `~/.xurl` and access tokens as secrets** — don’t paste them into chats, logs, or shared configs. Prefer per-project `.mcp.json` /`.grok/config.toml` that reference env vars over committing raw secrets.
- **Use a dedicated app** for MCP with only the scopes you need.
- **Writes count against rate limits** (bookmarks, `article_publish`) and are stricter than reads; expect occasional `429` s and back off.
- **The bridge is local** — your credentials never leave your machine except as a Bearer token sent over TLS to `api.x.com`.

#### X 的 MCP Servers：深度总结、通俗解读与辩证思考

##### 一、深度总结

X 提供了两个 MCP（Model Context Protocol）服务器，让 AI 工具可以直接连接 X 生态：

###### 1. X API MCP Server

地址：

```text
https://api.x.com/mcp
```

作用：让支持 MCP 的 AI 工具直接调用 X API。

可做的事包括：

- 搜索 X 全量历史内容
- 查询用户信息
- 获取趋势和新闻
- 管理书签
- 起草或发布 Articles
- 按你的账号权限执行操作

它有两种连接方式：

| 方式 | 特点 | 适合场景 |
|---|---|---|
| App-only Bearer | 直接用 App Bearer Token，简单，只读，无用户身份 | 查询、搜索、读数据 |
| xurl MCP Bridge | 本地桥接 OAuth 2.0，支持用户身份、自动刷新 token | 写操作、书签、Articles、完整能力 |

官方更推荐 **xurl bridge**，因为它能处理 OAuth 登录、token 缓存和自动刷新。

---

###### 2. X Docs MCP Server

地址：

```text
https://docs.x.com/mcp
```

作用：让 AI 工具直接查询 X API 文档。

适合在开发时快速查：

- API endpoint
- 认证方式
- 参数说明
- 代码示例
- OpenAPI 规范

---

###### 3. 两个 MCP 可以一起用

同时连接：

- `api.x.com/mcp`：实际调用 X API
- `docs.x.com/mcp`：查询官方文档

这样 AI 助手既能“查文档”，也能“执行操作”。

---

##### 二、深入浅出解读

可以把 MCP 理解成：

> AI 工具和外部服务之间的“标准插座”。

以前 AI 想操作 X，需要你写代码、调 API、处理认证。

现在通过 MCP：

```text
AI 工具 → MCP → X API / X 文档
```

AI 可以像使用插件一样使用 X。

---

##### 三、两种连接方式怎么选？

###### 简单模式：App-only Bearer

你只需要：

1. 在 X Developer Portal 创建 App
2. 复制 Bearer Token
3. 配到 MCP 客户端请求头里

优点：

- 配置简单
- 不需要浏览器登录
- 适合只读查询

缺点：

- 不能代表你操作
- 不能写入
- 没有用户上下文
- token 不自动刷新

适合：

> 只想让 AI 查 X 数据。

---

###### 完整模式：xurl bridge

流程大致是：

```text
AI 工具
  ↓ stdio JSON-RPC
本地 xurl bridge
  ↓ HTTPS + Bearer Token
X API MCP Server
  ↓
X OAuth 登录
```

第一次使用时会打开浏览器，让你登录 X 授权。

之后 token 会缓存并自动刷新。

优点：

- 支持你的账号身份
- 支持写操作
- 自动刷新 token
- 更完整、更安全

缺点：

- 配置稍复杂
- 需要 Node.js / npx
- 首次登录可能导致客户端超时，需要调大 timeout

适合：

> 想让 AI 真正“代你操作 X”。

##### 四、关键注意事项

###### 1. 必须自己创建 X Developer App

X 不支持动态客户端注册，所以不能简单把 MCP URL 填进去就完事。

你需要自己的：

###### 4. 写操作有更严格限制

如：

- 管理书签

- 修改用户相关数据

这些会受到更严格的 rate limit，可能遇到 `429`，需要重试和退避。

### 2026-07-22 09:36:33

#### X MCP Servers 精炼总结

X 提供两个 MCP（模型上下文协议）服务器：**X API MCP** 用于搜索、读取及操作 X 数据，**文档 MCP** 用于查询 X API 文档。二者可同时接入 Grok Build、Cursor、Claude Desktop、VS Code 等 MCP 客户端，让 AI 一边查文档、一边调用 API。

##### 1. X API MCP：让 AI 直接使用 X API

- 服务地址：`https://api.x.com/mcp`
- 协议版本：`2025-06-18`
- Server Info：`xmcp`
- 主要能力包括：
  - 搜索 X 的完整历史内容
  - 查询用户
  - 获取趋势和新闻
  - 管理书签
  - 起草或发布 Articles
- 实际可用功能取决于当前 X 账号拥有的权限与授权范围。

##### 2. 两种接入方式

###### 简单模式：App-only Bearer Token

适合只需读取公开数据的场景。

1. 在 X Developer Portal 创建应用。
2. 从应用的 **Keys and tokens** 页面复制 App-only Bearer Token。
3. MCP 客户端直接连接 `https://api.x.com/mcp`，并添加请求头：

   `Authorization: Bearer YOUR_APP_ONLY_BEARER_TOKEN`

**优点：**

- 无需本地桥接程序
- 无需浏览器登录
- 配置相对简单

**限制：**

- 仅支持只读接口
- 没有用户身份上下文，不能以你的账号执行操作
- Token 不会自动刷新
- 客户端必须支持远程 MCP 和自定义 HTTP 请求头

###### 完整模式：`xurl mcp` 本地桥接

适合需要用户身份、写入操作或完整功能的场景。

其调用链路为：

`MCP 客户端 → 本地 xurl mcp → api.x.com/mcp → X OAuth`

本地桥接程序负责：

- 承载 X 开发者应用身份
- 执行 OAuth 2.0 PKCE 登录
- 缓存并自动刷新 Token
- 每次请求注入最新的 Bearer Token
- 在遇到 `401` 时强制刷新 Token

这种方式可让 AI 按照你的账号授权范围执行操作，是管理书签、发布 Articles 等写入功能的必需方案。

##### 3. 为什么需要本地桥接

X OAuth 有以下特点：

- 必须使用用户自己的开发者应用
- 不支持动态客户端注册
- `api.x.com/mcp` 不提供原生 MCP OAuth 发现机制

因此，不能仅把 API 地址交给客户端完成全部认证，而需要通过本地 `xurl mcp` 桥接。

桥接程序通过 `npx` 启动，通常不需要单独安装；首次运行时会打开浏览器，要求用户完成一次 OAuth 2.0 登录。此后 Token 会保存在 `~/.xurl` 中并自动刷新。

此外：

- 诊断信息写入 `stderr`
- `stdout` 始终保持为干净的 JSON-RPC 通道
- 首次登录期间 MCP 握手会暂停，因此客户端应设置较长的启动超时时间

##### 4. 完整模式的准备工作

使用 `xurl` 桥接前需要：

1. 创建并启用 OAuth 2.0 的 X 应用。
2. 注册回调地址：

   `http://localhost:8080/callback`

3. 如需使用其他地址，可设置 `REDIRECT_URI`，并确保开发者后台登记的地址完全一致。
4. 获取应用的 `CLIENT_ID` 和 `CLIENT_SECRET`。
5. 安装 Node.js，以便运行 `npx`。

认证凭据的读取顺序为：

1. 环境变量 `CLIENT_ID`、`CLIENT_SECRET`
2. `~/.xurl` 中当前激活的应用配置

##### 5. 支持的 MCP 客户端

X API MCP 可接入以下工具：

- **Grok Build**：通过命令添加 `xurl` 桥接服务；首次调用工具或运行检查时会打开浏览器登录。
- **Cursor**：配置全局 `~/.cursor/mcp.json`，或项目级 `.cursor/mcp.json`；设置页面显示绿点代表连接成功。
- **Claude Desktop**：修改 `claude_desktop_config.json`，重启后可在工具菜单中看到 X 工具。
- **VS Code**：可通过 `.vscode/mcp.json` 接入 GitHub Copilot 或 Agent 模式。
- **其他 MCP 客户端**：可通过 stdio 启动 `xurl mcp`，也可在只读场景下直接使用远程 HTTP 地址。

如果已原生安装 `xurl`，可以直接运行：

`xurl mcp https://api.x.com/mcp`

而不必通过 `npx` 启动。

##### 6. 无浏览器、多个应用与账号

###### 无头或远程环境

如果机器无法打开浏览器，可先通过 `xurl auth oauth2 --headless` 在外部完成认证，再启动 MCP 客户端。

###### 多应用与多账号

可以在客户端参数中指定：

- `--app my-app`：选择特定开发者应用
- `-u alice`：选择特定用户账号

这适合同时管理多个 X 应用或账号的场景。

##### 7. 常见问题排查

| 问题 | 原因与解决方法 |
|---|---|
| 客户端启动超时 | 桥接程序正在等待浏览器登录；将 `startup_timeout_sec` 提高到 **300 秒以上** |
| 浏览器未打开 | 可能是无图形界面的远程环境；先运行 `xurl auth oauth2 --headless` |
| 出现 `401` 或 Token 刷新失败 | 应用凭据错误或 Refresh Token 已撤销；重新运行 OAuth 登录 |
| 浏览器提示回调地址错误 | 未注册 `http://localhost:8080/callback`，或与 `REDIRECT_URI` 不一致 |
| 登录后出现 `client-not-enrolled` | 应用不在正确的 X 套餐或环境中；需切换至 **Pay-per-use + Production** |
| `npx` 拉取旧版本 | 默认使用了私有 npm 镜像；可指定 `--registry=https://registry.npmjs.org/` |
| 工具输出为空或乱码 | 不要使用 `--verbose` 启动客户端，以免污染 stdout 的 JSON-RPC 数据 |

##### 8. 安全与使用建议

- 将 `~/.xurl`、Access Token 等视为敏感信息，不要粘贴到聊天、日志或共享配置中。
- 优先在项目级 `.mcp.json` 或 `.grok/config.toml` 中引用环境变量，不要直接提交密钥。
- 建议为 MCP 单独创建开发者应用，只授予必要权限。
- 写入操作的速率限制比读取操作严格，例如：
  - 管理书签
  - `article_publish`
- 遇到 `429` 时应降低请求频率并进行退避重试。
- `xurl` 桥接运行在本机；凭据不会离开本机，只有 Bearer Token 会通过 TLS 发送至 `api.x.com`。

##### 9. X API 文档 MCP

`https://docs.x.com/mcp`

它可让 AI 在开发过程中直接查找：

- API 端点说明

- 请求与响应格式

例如，开发者在 Cursor 中编写 X API 调用代码时，可让 AI 即时查询某个端点需要哪些参数，而不必离开当前工作流打开浏览器。

##### 10. 同时使用两个 MCP 服务器

这种组合可形成完整工作流：AI 先查询接口文档，再按文档要求调用 X API。

#### X 推出两类 MCP Server，让 AI 工具直接调用 API 与查询文档

X 提供两类 MCP（模型上下文协议）服务：一类连接 X API，让 Cursor、Claude、VS Code、Grok Build 等 AI 工具搜索历史内容、查询用户和趋势，并在授权后管理书签、起草或发布文章；另一类用于检索 X API 文档。两者可同时接入，使 AI 既能查文档，也能实际执行 API 操作。

##### 两种 API 接入方式对应不同能力

X API MCP 的托管地址为 `https://api.x.com/mcp`，接入分为两条路径：

- **App-only Bearer**：客户端携带应用令牌直接访问，无需本地桥接或浏览器登录；配置简单，但仅支持只读接口，不能以用户身份操作。
- **xurl 本地桥接**：通过 OAuth 2.0 PKCE 完成一次浏览器登录，之后自动缓存、刷新令牌。模型可在账号授权范围内执行写入操作，是完整功能的推荐方案。

由于 X 不支持动态客户端注册，开发者仍需自行创建 X 应用、启用 OAuth，并配置本地回调地址。`xurl` 负责在 MCP 客户端与 X 服务之间注入最新 Bearer Token。

##### 可嵌入主流 AI 开发工作流

`xurl` 可通过 `npx` 启动，无需单独安装，并支持 Grok Build、Cursor、Claude Desktop、VS Code 及其他兼容 MCP 的客户端。首次调用时会等待用户完成登录，因此客户端可能需要将启动超时调至 300 秒以上；无浏览器的远程环境可提前以无头模式授权。

##### 文档服务补齐“查询—执行”闭环

位于 `https://docs.x.com/mcp` 的文档 MCP 可查询接口说明、认证指南和代码示例。结合 API MCP，AI 助手能够边确认接口规范边发起调用，减少开发中切换文档与工具的成本。X 还提供 OpenAPI 规范，可用于生成客户端、导入 Postman或校验请求结构。

##### 权限、密钥与限流仍需谨慎管理

X 建议为 MCP 单独创建最小权限应用，通过环境变量保存凭证，避免将令牌写入聊天、日志或共享配置。写操作受更严格的速率限制，可能出现 `429`，调用方需要退避重试。桥接程序在本地运行，凭证不会离开设备，只有 Bearer Token 会通过 TLS 发往 X API。
