- **核心高价值点**：循环是否值得构建的四项判断：高频重复、可自动拒绝错误输出、代理能端到端完成、完成标准客观。

**知识要点**

- AI循环的核心流程包括发现、计划、执行、验证、迭代，其中验证门和停止条件决定循环是否可靠。
- 编码类任务适合循环化，因为测试、类型检查、构建结果能提供客观反馈。
- 生产级循环需要自动化触发、可复用技能、子代理分工、连接器和验证器。
- 循环成本应关注每次被接受变更的成本，而不仅是token消耗或运行次数。
- 在普通LLM中也可通过目标、成功标准和自检协议模拟轻量循环。

**行动项**

- 将常用重复任务按目标、成功标准、验证方式、停止条件四部分重新描述。
- 先手动跑通一次可靠流程，再沉淀为可复用提示或技能，最后再考虑自动化调度。
- 对AI输出任务设置明确验收标准，避免模型仅自我确认导致低质量迭代。

---

#### 什么是循环？

提示是一个单一指令。循环是 AI 持续追求直到达成的目标。可以将其视为一个递归目标：你定义一个目的，AI 会迭代直到完成。

一个提示会给出一个答案，然后等待你决定下一步。一个循环会自动完成整个周期：

```text
DISCOVER  →  work out what needs doing
PLAN      →  decide how to do it
EXECUTE   →  do the work
VERIFY    →  check it against the goal
ITERATE   →  not there yet? feed the result back in and repeat
```

这五个里面有三个做了所有实际工作，而这三个正是人们在循环处理中出错的地方。

---

验证是循环的核心。 如果没有对结果进行真正的检查，你就不会有循环，而是会有代理不断地自我认同。检查是将重复转化为进步的关键。它可以是一个严格的测试（“代码是否通过”）、一个可衡量的条件（“数字是否大于 X”），或者模型评分的标准。没有门槛意味着代理会给自己的作业打分，而完成工作的模型是一个过于宽容的评分者。

状态是让循环学习的关键。 每次迭代，AI 都必须记住它已经尝试过的内容，否则它会永远重复同样的错误。真正的循环会在一旁保留一个小记录：做了什么、哪里失败了、下一步是什么。明日的运行会从上次结束的地方继续，而不是从零开始。这也正是它开始变得昂贵的地方，我们稍后会详细讨论。

停止条件是使其保持正常运行的关键。 没有退出条件的循环会一直运行直到成功、中断或耗尽你的账户。每个重要的循环都有两种停止方式：成功终止和硬限制（例如：8 次尝试后停止并报告）。如果忽略这一点，你构建的机器会整夜空转。

提示向 AI 传递一条指令。循环向 AI 传递一个任务、一种判断任务完成的方式，以及何时放弃的规则。

---

#### 你真的需要一个吗？

大多数文章在告诉你循环何时是个错误之前，就先兜售这个循环。以下是专业人士实际使用的测试方法：只有当以下四个条件都满足时，构建一个循环才是值得的：

- 该任务每周至少重复一次。 频率低于此，设置成本永远无法回本。一次性操作最好还是通过一个好的提示来完成。
- 有东西可以自动拒绝错误输出。 测试、类型检查、构建、代码检查器、硬性规则。如果没有什么能让你的工作失败，循环就会一直空转。
- 代理实际上可以自己完成工作， 端到端，而不是只把一半的工作交还给你。
- "完成"是客观的，不是主观判断。 如果质量是个人喜好问题，人仍然会胜出。

漏选一个方框，将其保留为手动提示。关于整个主题的真实情况是：循环工程是真实存在的，而大多数人目前还不需要完整版。 每个人都能用的是轻量版，我们会讲到它。 但你应该知道界限在哪里。

#### 为代码构建的版本

循环在软件领域率先流行起来，因为代码是世界上最容易验证的东西。测试要么通过，要么失败，无法对此进行争论，因此 AI 总能知道是否完成了。

一个编码循环被赋予一个目标以及一种严格的检查方法：

```text
▸ LOOP SPEC
GOAL: every test in /tests/auth passes, lint is clean, no type errors.

EACH ITERATION:
  1. run the test suite and read every failure
  2. pick the single highest-impact failure
  3. write the smallest change that fixes it
  4. re-run the tests, lint, and type checker

VERIFY: green tests + zero lint warnings + zero type errors
STOP WHEN: verify passes, OR 8 iterations reached
ON STOP: summarize what changed and what still fails
```

在底层，一个真正的循环由五个构建模块组装而成。Claude Code 和 Codex 现在已包含这五个构建模块。

---

1\. 自动化（心跳）

这是使其成为循环而非一次性运行的触发器。你定义一个提示、一个节奏和一个目标，它会按计划运行，无需你手动启动。在 Claude Code 中，/loop 按间隔重新运行提示，/goal 保持会话持续到你设置的条件实际满足为止，钩子在代理生命周期的特定节点触发命令，将其推送到定时任务（cron job）或 GitHub Actions 后，即使你合上笔记本电脑，它也会继续运行。发现结果会主动呈现给你。你不需要再四处检查。

---

2\. 技能（可重复使用的指令）

Instead of pasting a large block of instructions into each run, you can save them once as a file that the loop reads each time: the rules, the patterns to follow, and a strict list of what it must never touch. Now the automation just calls the skill by name, and the recurring job stays maintainable instead of rotting in a schedule nobody updates.

---

3\. 子代理（使制作者远离检验者）

在循环中最有用的单一结构技巧是将执行工作的代理与检查工作的代理分离。编写代码的模型在批改自己的作业时过于宽容。第二个代理拥有不同的指令，有时在更高要求下使用更强的模型，能够发现第一个代理自己陷入的问题。你的撰写者可以快速且廉价，你的审阅者可以缓慢且严格。这种分离构成了质量的主要部分。

---

4\. 连接器（因此它起作用，而非暗示）

这是一个声称“这是修复方案”的代理与一个循环之间的区别：该循环会自动打开拉取请求、关联工单，并在构建成功后自动通知频道。连接器能让循环在实际环境中运行，而不仅仅是描述它如果能够的话会做什么。

---

5\. 验证器（门）

自动拒绝不合格工作的测试、类型检查或构建。这是决定这个循环是帮助你还是仅仅浪费你的钱的那个关键环节。其他的一切都是管道。这是让它变得真实的部分。

把这些组合起来，你就能得到现在大团队大规模运行的东西：由大量代理组成的集群同时循环执行同一任务，一次数十或数千个。有位工程师使用了这样的循环，在大约六天内将整个代码库从一种编程语言转换到另一种，而手动完成这项工作原本需要近一年时间。这确实改变了严肃软件的构建方式。而且这其中存在演示中从未展示的陷阱。

---

#### 没人提及的成本

循环基于代币运行，而代币即货币。问题不在于每一步都有成本，而在于成本如何累积。

每次循环时，代理都会重新读取其上下文：目标、代码、上次结果、失败的原因。这整个内容在每次迭代时都会再次通过模型处理，并且每次处理都会变大。一个运行十次的循环不会消耗十次提示，而是消耗十次提示，每次提示都在不断变大。提升质量的“生成-检查”技巧也会使成本翻倍，因为现在是两个模型处理该任务，而不是一个。

---

```text
▸ ROUGH COST OF ONE LOOP
single agent, one medium task:      ~50,000 – 200,000 tokens
context re-sent every iteration:    grows each pass
a fleet of agents in parallel:      multiply all of the above
```

---

真正重要但几乎没人追踪的指标是每次接受变更的成本。不是消耗的 token 数量或执行的循环次数。如果一个循环给你十个结果，你却舍弃六个，那么你正在做本应节省的审查工作。接受率低于 50%时，成本将超过回报。

循环也会悄无声息地失败。工程师杰弗里·亨特利将其称为“Ralph Wiggum 循环”：代理认为任务过早完成，在任务完成一半时退出，循环继续运行并消耗资源却一无所获。如果没有能够使任务失败的硬性检查点，循环不会崩溃，而是会悄无声息地向你收费。

这就是为什么重版本属于那些有预算和运行所需限制条件的团队：迭代上限、token 预算、在常规步骤中使用低成本模型、监控。如果这不是你的情况，你并没有错失什么——核心思路的成本仅为其几分之一，且无需任何设置。

---

#### 实际有效的顺序

如果你确实要构建一个，顺序比工具更重要。那些交付在生产环境中稳定运行的循环的人，都以同样的方式做这件事：

```text
1. Get ONE manual run reliable first.
2. Turn that into a skill (save the instructions).
3. Wrap the skill in a loop (add the gate + stop condition).
4. THEN put it on a schedule.
```

跳过步骤，安排你尚未手动验证可靠性的任务，正是循环在你睡觉时出问题的原因。验证一次，加固它，然后自动化它。

#### 你自己构建一个基本循环（任何 LLM）

你不需要编码代理也能理解其工作原理。现在你可以在任何 LLM 中手动运行一个简单的循环，仅通过一个提示词即可。关键在于一次性向模型提供循环的三个部分：一个目标、严格的成功标准，以及一个迫使它在允许停止前进行自我检查的协议。

```text
▸ SELF-CHECKING LOOP  (paste into Claude or ChatGPT)
You will work in a loop until the task meets the bar.

TASK:
[describe exactly what you want produced]

SUCCESS CRITERIA (be strict, no soft passes):
- [criterion 1]
- [criterion 2]
- [criterion 3]

LOOP PROTOCOL, repeat every turn:
1. PLAN   - state the single next step.
2. DO     - produce or improve the work.
3. VERIFY - score the result 1-10 on each criterion.
            Be brutally honest. List exactly what is still weak.
4. DECIDE - if every criterion is 8+, print "FINAL" and stop.
            Otherwise print "ITERATING" and go again, fixing
            the weakest point first.

RULES:
- Never call it done until every criterion is 8 or higher.
- Each pass must fix the weakest score from the last VERIFY.
- Do not ask me questions. Make a sensible assumption, note it,
  and keep going.

Begin. Run the loop until FINAL.
```

看看会发生什么。模型会先起草内容，根据你的标准对自己的作品进行评分，找出薄弱环节，然后反复重写，直到它真正达到标准，而不是直接给你第一个看起来接近的东西。这就是一个循环。你刚刚用一个段落构建了这样一个循环。

但请注意，还有什么是缺失的，因为这正是接下来内容的核心所在。你是那个触发点。你打开了聊天窗口，粘贴了提示词，就坐在那里看着它迭代。关闭标签页，它就消失了。没有任何日程安排。没有“每天早上执行这个操作”，也没有“收到邮件时唤醒”的功能。它无法主动联系你，因为它只会在你注视它的时候存在。

要得到一个能够自主运行、按计划执行、由真实事件触发且无需你费心管理的循环，你通常需要从一开始就踏入这个复杂的领域：工具、托管、代码、网关和账单。

这在处理真正繁重的任务时是合理的。但对于99%的日常任务来说，已经有了现成的、极其简单的解决方案。

---

#### 同样的想法，适用于你的实际生活

去除代码和成本后，剩下的是一个简单而真正有用的概念：一项能够自行运行的任务——它可以按计划执行，也可以在特定事件发生时触发，无需你记住或亲自在场。你不需要是工程师。你只需要为生活而非代码库构建的循环。

有一个免费选项，您可以通过用简单的语言描述来创建一个。无需代码，无需托管，无需密钥，无需保持打开标签页，无需构建命令出错。

它叫 Mira，存在于你可能已经打开的应用 Telegram 中。你像和朋友聊天一样给它发消息，它运行的循环被称为“技能”。每个“技能”都悄无声息地包含一个真实循环所需的相同部分：一个触发器、一个动作、一种自动运行的方式，而你永远不需要将这些部分连接起来。你只需要说出你想要的即可。

---

```text
▸ SKILL
"Every weekday at 7am, check my Gmail and Google Calendar.
Send me a short brief: my 3 most important meetings, anything
urgent in the inbox, and one thing I said I'd follow up on but
haven't. Keep it under 120 words."
```

---

那是一个真实的循环。一个时间触发器，一个跨两个已连接应用的多步骤操作，自主运行并自动到达你这里。你把它写成了一条消息。

#### Mira 实际上能做什么

这就是让它脱颖而出的关键之处。Mira 不是一个更智能的聊天机器人。它与 ChatGPT 的区别很简单：ChatGPT 只是回答，而 Mira 会行动。你不需要让它写邮件，而是直接让它发送邮件。你不会得到一个草稿，而是在 Linear 中获得一张已分配负责人的真实工单。它会在后台完成这些事情，并且在每次对话之间都记得你。

它通过 Composio 连接到 500 多个应用（Notion、Gmail、Google Calendar、GitHub、Figma、Stripe 以及数百个其他应用），拥有跨会话和群聊的长期记忆，并且是模型无关的，可根据任务运行 GPT、Claude、Gemini。这就转化为以下内容。

---

为了工作 这就是循环思想无需编写一行代码就能发挥作用的地方。

```text
▸ SKILLS
"An hour before each meeting, remind me with the context and
decisions from our last conversation with that person."

"When I forward a message here, turn it into a Linear ticket
with the right priority and assign the owner."

"Every Friday at 4pm, collect the team's task status and metrics
and post a clean weekly digest in our chat."

"Summarize everything I missed in this group chat while I was
away, in 5 bullets."
```

它能在几秒钟内让你快速了解一个包含200条消息的对话线程，在你继续交谈时记录工单，并且进入会议时已经了解情况。在群聊中，它会记住团队的决策和任务，而不仅仅是你的。

---

面向创作者 这是大多数人低估的部分。Mira 在聊天中端到端地创作内容。

```text
▸ SKILLS
"I'll send a voice note with a raw idea. Turn it into a finished
post with a caption and hashtags."

"Take this one idea and write versions for X, Instagram, LinkedIn,
Email, and a newsletter, each in the right format."

"Generate 3 image options for this post."
```

#### 《循环详解》深度总结与解读

##### 一句话总结

这篇文章讲的是：**AI 的高级用法不是反复“提示”，而是设计“循环”——让 AI 围绕目标自动计划、执行、检查、修正，直到完成或停止。**

---

##### 1. 深度总结

###### 1.1 核心观点

传统 AI 使用方式是：

> 人输入 → AI 回答 → 人判断 → 人再输入

问题是：**人始终是发动机，AI 只是工具。**

更高级的方式是：

> 人设定目标 → AI 自动执行 → 自检/外检 → 修正 → 重复 → 达成目标

这就是所谓的 **Loop，循环**。

---

##### 2. 什么是 AI 循环？

一个真正的循环通常包含五步：

```text
DISCOVER  发现问题
PLAN      制定计划
EXECUTE   执行任务
VERIFY    验证结果
ITERATE   失败则迭代
```

但最关键的是三件事：

###### 2.1 验证器：判断对不对

没有验证，就不叫循环，只是 AI 自说自话。

好的验证可以是：

- 测试是否通过
- 代码是否编译
- 指标是否达标
- 是否符合明确标准

###### 2.2 状态：记住做过什么

循环必须记住：

- 尝试过什么
- 哪里失败了
- 下一步该修什么

否则 AI 会反复犯同一个错。

###### 2.3 停止条件：知道何时停

必须有两种停止方式：

- 成功：达到目标
- 失败：达到最大次数或预算后停止

否则循环可能一直跑，最后只消耗钱。

---

##### 3. 什么时候值得用循环？

文章给了四个判断标准：

| 条件 | 含义 |
|---|---|
| 每周至少重复一次 | 一次性任务不值得搭循环 |
| 能自动判断失败 | 没有验收标准就不要自动化 |
| AI 能端到端完成 | 不能总把问题丢回给人 |
| 完成标准客观 | 主观审美类任务不适合强循环 |

简单说：

> **重复、可验证、可自动完成、标准清晰的任务，才适合循环。**

---

##### 4. 为什么循环最先在编程里爆发？

因为代码天然适合验证。

代码任务有明确标准：

- 测试通过
- 类型无错误
- lint 无警告
- 构建成功

所以 AI 可以知道自己到底有没有完成。

一个典型代码循环是：

```text
目标：让所有测试通过

每轮：
1. 运行测试
2. 找最大问题
3. 做最小修改
4. 再运行测试

成功条件：
测试、lint、类型检查全部通过

停止条件：
成功或最多尝试 8 次
```

---

##### 5. 真正的 AI 循环由什么组成？

文章提到五个模块：

###### 5.1 自动化

让任务定时或被事件触发，而不是人手动启动。

###### 5.2 技能

把固定指令保存下来，反复复用。

###### 5.3 子代理

让一个 AI 做事，另一个 AI 审查。

避免“自己写、自己判、自己放水”。

###### 5.4 连接器

让 AI 不只是说“我可以做”，而是真的去：

- 发邮件
- 开工单
- 提 PR
- 通知团队
- 更新文档

###### 5.5 验证器

这是最重要的门槛。

没有验证器，循环很容易变成昂贵的幻觉机器。

---

##### 6. 被忽略的成本问题

循环很强，但不便宜。

每次迭代，AI 都要重新处理：

- 目标
- 上下文
- 上一轮结果
- 错误信息
- 修改记录

所以成本不是线性增加，而是越跑越贵。

真正该关注的指标不是：

> 跑了多少次、用了多少 token

而是：

> **每个被接受的有效结果花了多少钱。**

如果 10 个结果里只接受 4 个，说明循环并没有真正节省工作。

正确顺序是：

```text
2. 固化成可复用技能
3. 加入验证和停止条件
4. 最后再定时自动化
```

不要一开始就自动化。

否则就是：

> 把一个不可靠流程，变成一个自动烧钱机器。

这就是最简单的人工触发式循环。

##### 主旨概括

文章认为，AI 使用方式正在从“人一步步提示 AI”转向“给 AI 一个目标，让它在循环中自主执行、检查、修正”。真正有价值的循环不是简单重复，而是具备目标、验证、记忆状态和停止条件的自动化工作流。

##### 1. 传统 AI 使用方式的问题：人仍是“发动机”

大多数人使用 AI 的方式仍然是：

- 输入一个请求；
- 等待回答；
- 人工判断好坏；
- 再继续追问或修改。

这种方式的问题是：**AI 不会主动推进任务**。只要用户停下来，工作就停止。  
因此，AI 只是一个被动工具，真正驱动流程的仍然是人。

文章提出，更高效的方式是：  
**不再逐步指挥 AI，而是给它一个目标，让它自己规划、执行、检查、修复，并反复迭代直到完成。**

---

##### 2. 什么是“循环”：不是一个提示，而是一套持续执行机制

文章将“提示”和“循环”做了区分：

- **提示**：给 AI 一个单次指令，AI 回答后等待用户下一步。
- **循环**：给 AI 一个目标，它会持续推进，直到达到标准或触发停止条件。

一个完整循环通常包含五步：

1. **DISCOVER：发现任务需求**  
   判断要做什么。

2. **PLAN：制定计划**  
   决定怎么做。

3. **EXECUTE：执行任务**  
   产出结果或修改内容。

4. **VERIFY：验证结果**  
   检查是否达到目标。

5. **ITERATE：继续迭代**  
   如果没达标，把结果反馈回去继续改。

文章强调，循环真正有效的关键不是“重复”，而是：  
**验证、状态记录、停止条件。**

---

##### 3. 循环的三个核心要素：验证、状态、停止条件

###### 3.1 验证：决定循环是否真的进步

验证是循环的核心。

如果没有可靠检查，AI 可能只是不断“自我感觉良好”，而不是实际变好。

验证可以是：

- 代码测试是否通过；
- 数值是否大于某个阈值；
- 是否满足明确规则；
- 由另一个模型按标准评分。

例如，代码任务中可以设定：

> 所有测试通过、无 lint 警告、无类型错误。

如果没有这种“硬门槛”，AI 就像自己给自己批作业，往往会过于宽松。

---

###### 3.2 状态：让 AI 记住已经尝试过什么

循环要有效，AI 必须记住：

- 已经做了什么；
- 哪里失败了；
- 下一步该修什么。

否则它可能反复犯同样的错。

文章指出，真正的循环会维护一个“小记录”，让下一轮从上一轮继续，而不是每次从零开始。  
但这也会带来成本，因为上下文会越来越长。

---

###### 3.3 停止条件：防止无限运行

每个重要循环都必须有退出规则：

- **成功停止**：任务达标后结束；
- **硬性限制**：比如最多尝试 8 次，仍失败就报告。

如果没有停止条件，循环可能会整夜运行，持续消耗 token 和费用。

---

##### 4. 什么时候值得构建循环：必须满足四个条件

文章提醒，不是所有任务都适合循环。专业人士通常会用四个条件判断：

1. **任务每周至少重复一次**  
   如果只是一次性任务，设置循环的成本不值得。

2. **有办法自动拒绝错误结果**  
   比如测试、类型检查、构建检查、硬规则等。

3. **AI 能够端到端完成任务**  
   不能做一半就必须交还给人。

4. **“完成”是客观标准，不是主观喜好**  
   如果结果好坏主要取决于个人审美，人类仍然更适合把关。

只要缺少其中一个条件，文章建议：  
**继续用普通提示，不要强行做循环。**

## 通俗精炼（1）

### 2026-09-18 11:04:15

#### AI 循环：让模型从“回答问题”转向“自主完成任务”

文章认为，AI 的关键进化不是更会写提示词，而是构建“循环”：用户只设定目标，AI 自行规划、执行、验证和修正，直到达标或触及停止条件。其价值在于减少人工逐步推动，但并非所有任务都值得自动化。

##### 有效循环依赖验证、状态与停止条件

循环通常包含“发现—规划—执行—验证—迭代”。真正决定效果的是：

- **验证器**：用测试、规则或量化指标拒绝错误结果，避免模型自我认可。
- **状态记录**：保留历次尝试与失败原因，防止重复犯错。
- **停止条件**：成功即结束，同时设置迭代次数或 token 预算上限。

在软件开发中，测试、类型检查和构建结果都可客观判定，因此循环最成熟。执行与审查最好交给不同代理，减少“自己批改自己”的宽松偏差。

##### 只在任务可重复、可验收时使用

作者建议，任务需同时满足四点：每周至少重复一次、有自动拒错机制、代理能端到端完成、“完成”可客观判断。否则，一个好提示通常更省事。

循环成本会随上下文反复读取而累积；单个中等任务可能消耗约 5万—20万 token，多代理审查还会进一步放大。比循环次数更重要的指标是“每次被接受的变更成本”；接受率低于 50%时，自动化可能得不偿失。

##### 先验证流程，再安排自动运行

可靠顺序是：先手动跑通一次，再把指令固化为可复用技能，随后加入验证门槛和停止条件，最后才设置定时或事件触发。普通用户也可在 Claude、ChatGPT 中用“目标＋严格标准＋反复自检”体验轻量循环，但它仍需人工启动，且模型自评分不等于外部硬验证。

文章后半部分以 Telegram 工具 Mira 为推广案例，称其可连接 500 多个应用，按时间或事件自动处理邮件、日历、工单和内容。核心意义不在具体产品，而在交互范式变化：AI 正从被动回答，转向持续执行；是否值得采用，取决于任务能否被可靠验证，以及节省的人力是否超过运行与审查成本。
