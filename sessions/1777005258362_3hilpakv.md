**Yangyi**

其实小龙虾原生的抓取机制一直不是很完善。  
抓取比较慢，token消耗也多。很多人会配合用firecrawl或者JINA来抓。

其实还有一个平替叫xcrawl，安装更方便，只需要把文档丢给小龙虾，  
[https://docs.xcrawl.com/zh/doc/developer-guides/openclaw/…](https://docs.xcrawl.com/zh/doc/developer-guides/openclaw/)

小龙虾自己读完，Skill 自动装好，然后按照指示再给它Key即可。ClawHub 里搜「xcrawl」也行，一键导入。

xcrawl有四种场景可以使用：  
\- Search：搜索引擎查询，标题 / URL / 摘要 / 排名结构化直出  
\- Map：扫一个站点，先把所有 URL 列出来，前置规划用  
\- Scrape：指定 URL 抓一次，干净的 Markdown 直接喂 LLM  
\- Crawl：全站递归批量爬，搭知识库 / 做 RAG 专用

平时网页抓取的 90% 需求，基本都落在这四种里。

比如可以让小龙虾做 changelog 总结  
每天定时抓一遍 [https://code.claude.com/docs/en/changelog…](https://code.claude.com/docs/en/changelog)  
再给它配一个 ccc 快捷指令。敲一下 ccc，就知道 Claude Code 今天又卷出什么新功能。

有了这些数据采集工具，Agent就有能力获得更多上下文信息，更好服务人类。  
当然，如果你不在意性能和token消耗，其实browser-use也是个选择。

xcrawl给新用户 1000 积分试用额度，方便进行试用体验

## 通俗精炼（1）

### 2026-04-24 04:32:54

#### 小龙虾抓取能力的实用补充：`xcrawl`

##### 核心观点

作者认为，小龙虾原生的网页抓取能力并不算完善，主要问题是**抓取速度偏慢、Token 消耗偏高**。因此，很多人在实际使用中，会额外搭配 `firecrawl` 或 `JINA` 这类工具。

##### 推荐方案：`xcrawl` 作为低门槛替代

文中重点推荐了 `xcrawl` 作为一个更方便的平替方案。它的特点是：

- 安装和接入更简单
- 只需把文档交给小龙虾读取
- Skill 可以自动安装
- 按提示配置 Key 即可使用
- 也可以直接在 `ClawHub` 搜索 `xcrawl` 一键导入

整体上，作者强调的是：**上手门槛低，适合普通用户快速接入网页抓取能力。**

##### 四类核心使用场景

`xcrawl` 覆盖了绝大多数网页采集需求，主要有四种模式：

- `Search`：做搜索引擎查询，直接返回标题、URL、摘要和排名等结构化结果
- `Map`：扫描整站，先列出所有 URL，适合做前置规划
- `Scrape`：对指定 URL 抓取一次，并输出干净的 Markdown，方便直接喂给 LLM
- `Crawl`：递归抓取整个网站，适合搭知识库或做 RAG

作者判断，**日常 90% 的网页抓取需求，基本都可以落在这四类里。**

##### 一个典型案例

作者举了一个很实用的例子：让小龙虾**每天定时抓取 Claude Code 的 changelog**，再配一个快捷指令，比如 `ccc`。这样只要执行一次指令，就能快速知道 Claude Code 当天更新了什么功能。

这说明，抓取工具不仅是“拿数据”，更可以直接嵌入工作流，变成**持续更新的信息助手**。

##### 更大的意义

作者最后表达的核心判断是：有了这类数据采集工具后，Agent 就能获得更多上下文信息，因此也能**更好地服务人类**。如果不太在意性能和 Token 消耗，`browser-use` 也可以作为备选方案。

##### 一句话总结

这篇内容本质上是在说：**如果你觉得小龙虾原生抓取不够高效，`xcrawl` 是一个更轻量、易接入、覆盖主流场景的补充工具。**

  - `firecrawl`

**通俗理解**：就像自带浏览器能用，但打开网页慢、还费流量，所以很多人会换更顺手的工具。

##### 2. 作者推荐的替代方案：`xcrawl`

- 作者认为，除了常见的 `firecrawl` 和 `JINA`，还有一个“平替”选择：`xcrawl`。

  - `Skill` 会自动装好
  - 然后再按提示填写 `Key`

  - 直接在 `ClawHub` 搜索 `xcrawl`

**关键点**：作者强调的不是功能绝对最强，而是**上手门槛低、配置方便**。

##### 3. `xcrawl` 的四种核心使用场景

作者把 `xcrawl` 的用途归纳为 4 类，并认为**平时网页抓取 90% 的需求，基本都落在这四种里**。

###### 3.1 Search：搜索引擎查询

- 用来做搜索引擎查询。
- 可以直接输出结构化结果，包括：
  - 标题
  - URL
  - 摘要
  - 排名

**适合场景**：比如让 Agent 帮你搜“某个产品最近的官方更新”，结果会比普通搜索更容易给模型直接使用。

###### 3.2 Map：站点 URL 扫描

- 用来扫描某个网站。
- 作用是先把**全站 URL 列出来**。
- 适合做抓取前的**前置规划**。

**举例**：如果你想抓一个文档站，不一定要直接全站爬取，先用 `Map` 看清楚有哪些页面，再决定抓哪些内容。

###### 3.3 Scrape：单页面抓取

- 用来抓取指定的单个 URL。
- 输出结果是**干净的 Markdown**。
- 可以直接喂给 LLM 使用。

**通俗理解**：就是把原本杂乱的网页内容，整理成模型更容易读懂的文本格式。

###### 3.4 Crawl：全站递归抓取

- 用来对整个网站进行**递归批量爬取**。
- 适合：
  - 搭建知识库
  - 做 `RAG`

**关键点**：如果你要长期积累某个网站的资料，而不是只抓一两页，`Crawl` 会更合适。

##### 4. 具体应用案例：自动追踪 Claude Code 更新

- 作者举了一个实际例子：
  - 每天定时抓取 `Claude Code` 的 changelog 页面  
    `https://code.claude.com/docs/en/changelog`
- 然后再给小龙虾配置一个 `ccc` 快捷指令。
- 这样只要输入一次 `ccc`，就能快速知道：
  - **Claude Code 今天新增了什么功能**

**这个案例说明了什么：**
- 抓取工具不只是“把网页存下来”
- 更重要的是，它能和 Agent 工作流结合，变成一个**自动更新、自动总结的信息系统**

##### 5. 作者对工具选择的整体看法

- 作者认为：有了这些数据采集工具，**Agent 就能拿到更多上下文信息**，从而更好地服务人类。
- 如果用户**不太在意性能和 token 消耗**，也可以考虑：
  - `browser-use`

也就是说，作者并不是说只有 `xcrawl` 能用，而是认为：
- 如果你在乎**效率、成本、接入方便**，`xcrawl` 更值得试
- 如果你不太在乎这些，其他方案也能满足需求
