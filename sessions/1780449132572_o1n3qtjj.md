## 正文

**范凯说 AI \| Kai on AI**

我越来越看清一件事：传统企业软件正在退化成 API。

以前做企业服务，你得做一整套产品——界面、流程、权限、报表，然后卖 License 或者 SaaS 订阅。但在智能体生态里，这些东西的存在形态完全变了。底层是模型，直接售卖 Token；中间层是通用智能体，Codex 这类工具大家已经在用了；而传统的企业软件，最终大多会退化成 API 服务，由 Agent 直接调用。界面不重要了，因为 Agent 就是界面。

在这种生态下，真正稀缺的不是做软件的人，而是能在智能体之上提供整体企业解决方案的人。我给这个角色起了个名字：FDE，前线部署工程师。他们不写底层模型，不做通用平台，而是站在客户的业务现场，用智能体搭建端到端的解决方案。

今晚在活动上遇到两个大学生创业者，做的就是这件事——虽然他们自己可能还没意识到，但他们已经是最早期的 FDE 了。用 Codex 配 GPT，帮企业客户落地智能体方案，一个项目一个项目地交付。没有什么宏大叙事，就是扎在一线硬干。

我说的 OPC，本质上就是 FDE 在智能体平台上为企业开发和交付解决方案。这不是什么遥远的未来，已经在发生了。

#### 1. 深度总结

作者的核心判断是：

> **AI Agent 会成为新的企业软件入口，传统企业软件将从“完整产品”退化为“可被调用的 API”。**

过去企业软件要做完整闭环：

- UI 界面
- 业务流程
- 权限体系
- 报表系统
- SaaS / License 商业模式

但在智能体时代，结构可能变成：

```text
底层：大模型，卖 Token
中层：通用 Agent / 工具，如 Codex、Cursor、Claude
上层：企业业务解决方案
传统软件：变成 Agent 可调用的 API
```

因此，作者认为未来最稀缺的不是单纯“做软件的人”，而是能在客户现场用 Agent 组合工具、流程、数据、系统，交付完整业务结果的人。

他把这类人称为：

> **FDE：前线部署工程师**

他们不造大模型，也不做通用平台，而是深入企业场景，把智能体真正落地成解决方案。

作者认为，这不是未来概念，而是已经发生：一些年轻创业者已经在用 Codex + GPT 给企业做智能体项目交付，本质上就是早期 FDE。

---

#### 2. 通俗解读

以前企业买软件，就像买一台“完整机器”：

> 有按钮、有屏幕、有流程、有说明书。

以后可能变成：

> 企业有很多“零件 API”，真正操作它们的是 AI Agent。

比如以前员工要打开 CRM、ERP、OA、财务系统，一个个点界面。

未来可能是对 Agent 说：

> “帮我查一下这个客户的历史订单，生成报价单，走审批，然后通知销售。”

Agent 自动调用：

- CRM API
- ERP API
- 财务 API
- 邮件 / Slack / 飞书 API
- 审批系统 API

用户不再直接面对复杂软件界面，而是面对一个能办事的智能体。

所以作者说：

> **界面不重要了，因为 Agent 就是界面。**

而 FDE 的价值，就是把这些系统、流程、权限、数据、Agent 组织起来，让它真的能在企业里跑通。

一句话理解：

> **传统软件卖“工具”，FDE 卖“结果”。**

---

#### 3. 关键洞察

##### 3.1 企业软件的价值重心在迁移

过去价值在：

- 功能多
- 界面完整
- 流程复杂
- 系统封闭

未来价值可能在：

- API 是否好用
- 数据是否可访问
- Agent 是否能稳定调用
- 能否解决真实业务问题

软件不一定消失，但形态会变。

---

##### 3.2 实施服务会重新变得重要

评论里有人说：

> “这不就是实施么？”

这句话有道理，但也不完全对。

传统实施主要是：

- 配系统
- 导数据
- 培训用户
- 调流程

AI 时代的 FDE 更像是：

- 理解业务
- 设计 Agent 工作流
- 连接多个系统
- 调模型能力
- 处理异常场景
- 持续优化自动化效果

所以它像实施，但不只是实施。

更准确地说：

> **FDE = AI 时代的实施顾问 + 解决方案架构师 + 自动化工程师。**

---

##### 3.3 “产品”可能被“项目化解决方案”重新挑战

SaaS 时代强调标准化产品。

但 Agent 时代，企业需求可能重新走向定制化：

- 每家公司流程不同
- 数据结构不同
- 权限边界不同
- 风控要求不同
- 人机协作方式不同

因此，谁能快速拼装、部署、迭代，谁就有机会。

这也是作者看好 FDE 的原因。

---

#### 4. 辩证思考

##### 4.1 “界面不重要”说得太绝对

Agent 会减少很多界面操作，但不会彻底消灭 UI。

原因很简单：

- 异常情况需要人工确认
- 审批需要可视化留痕
- 风控需要审计页面
- 复杂数据需要图表展示
- 用户需要理解 Agent 做了什么

所以更准确的说法是：

> **普通操作界面会弱化，监督、审批、配置、审计类界面会更重要。**

未来不是“没有界面”，而是：

> **界面从操作入口，变成控制台和仪表盘。**

---

##### 4.2 传统企业软件不会全部退化成 API

有些软件会被 API 化，比如：

- 数据查询
- 表单录入
- 报表生成
- 订单处理
- 消息通知

但有些系统仍会长期保留强界面和强流程，比如：

- 银行系统
- 政府系统
- 医疗系统
- 财务审计系统
- 高风险工业系统

因为这些场景要求：

- 合规
- 安全
- 可追责
- 可解释
- 强权限控制

Agent 可以辅助，但不一定能完全接管。

---

##### 4.3 FDE 是机会，也是苦活

FDE 听起来很性感，但本质很“重”：

- 要懂客户业务
- 要懂技术实现
- 要会沟通需求
- 要能现场救火
- 要持续维护
- 还要对结果负责

它不像纯软件产品那样容易规模化。

所以 FDE 最大的问题是：

> **能否从项目交付，沉淀出可复用产品。**

否则就容易变成新瓶装旧酒：AI 外包、AI 实施、AI 集成。

---

#### 5. 我的判断

这篇内容最有价值的地方，不是“传统软件会死”，而是指出了一个趋势：

> **企业软件的入口正在从人点击 UI，转向 Agent 调用能力。**

但更现实的未来不是二选一，而是三层共存：

```text
人：负责目标、判断、审批、兜底
Agent：负责理解、编排、执行、自动化
软件/API：负责数据、权限、交易、记录
```

真正有价值的公司或个人，不是单纯做一个聊天机器人，而是能把 Agent 放进真实业务链路里，产生可衡量结果。

最终赢家可能不是“最会讲 AI 故事的人”，而是：

> **最懂业务、最懂系统、最能交付结果的人。**
