### Pi Agent 配置指南：打造你的专属 AI 编程助手

> 在玩 pi 的过程中，感觉又回到了折腾 neovim 的时期，这种自己构建乐高玩具的过程，无论何时都深深吸引着我。

#### 什么是 Pi ？

pi 又叫 pi coding agent，如果你没有听说过它，那你一定听说过 openclaw。而 pi 则是 openclaw 背后的编码智能体框架。极简的设计哲学，是大家对它最大的共识。

所以我们先来了解一下，pi 的能力边界是什么。

一切都围绕着极简二字，0 配置的 pi agent 只支持 4 种工具：bash、read、write 和 edit，没有 mcp 、没有 sub-agents、没有 plan mode 、没有 permision popups。一切都没有，都需要自己配置。看到这，如果你想要一个开箱即用的 coding agent ，那么可以转向 Codex 和 Claude Code。

![Image](https://pbs.twimg.com/media/HJkchSaaYAAVSc9?format=jpg&name=large)

正如作者的设计原则中所说，Pi 保持内核精简，将工作流相关行为推向了拓展、skills、提示词模板以及包中。后文中我将重点介绍这些可定制化的部分，以及如何搭建起属于自己的 Harness。

#### 什么是 Extension ？

这是 Pi 框架中的第一个抽象，扩展是 TypeScript 模块，用于扩展 Pi 的行为。它们可以订阅生命周期事件、注册可由 LLM 调用的自定义工具、添加命令等。位置在 .pi/agent/extensions/\* 目录下，Pi 会自动发现这些拓展，或者可用 /reload 命令进行热更新。

下面会重点讲拓展的关键能力：

1. 自定义工具/自定义命令：分别通过 pi.registerTool() 和 pi.registerCommand() 注册大模型自定义工具和斜杠命令。
2. 事件拦截：阻止或修改工具调用、注入上下文、自定义压缩。Pi 提供了非常丰富的生命周期（LifeCycle）事件用来注册，基本可以满足大部分需求。
   [官方文档](https://pi.dev/docs/latest/extensions#events)
3. 用户交互/界面渲染：Pi 也允许用户自定义交互逻辑和渲染逻辑，比如写一个提问 QA 的问答框、自定义 Editor 样式或者写一个等待模型输出时的小游戏（例如：贪吃蛇、飞机大战等）
4. 会话持久化：通过 pi.appendEntry() 存储重启后仍保留的状态。可以用来做一个类似 todo 的拓展。

如何写一个 Pi 拓展？

在 AI 时代，我们不必再像 neovim 时期，自己动手写 lua 代码，最简单的方式或许就是和 Pi 说清楚你的需求，让它自己去写一个，并且通过热加载马上生效。所以你可以对 Pi 说：

> 我想写一个叫做 permision-gate 的树莓派扩展，其作用是在危险的 bash 命令（rm -rf、sudo 等）之前提示确认。

再比如，我想通过插件形式，完全实现像 Claude Code 格式的 hooks 功能，你可以对 Pi 说：

> 我想写一个叫做 CC-hooks 的插件，用来将 Pi 原生的事件拦截能力，包装成像 Claude Code Hooks 一样的用法。

#### 什么是提示模板？

其实这个更像 Claude Code 的自定义斜杠命令，而上面拓展中的自定义命令更加的强大，可以调用 Pi 内部提供的 API。

格式：一个带 front-matter 的 markdown 文件

front-matter：包括 description 和 argument-hint，这两个都是可选的，会显示在下拉菜单中的描述和参数。

模板还支持位置参数和切片，比如用 $1 和 $2 以及 ${@:N} 这种使用方式，具体说明见

[模板参数](https://pi.dev/docs/latest/prompt-templates#arguments) 。

#### 什么是 Pi Package ？

Pi Package 是 Pi 的另一抽象，简单来说就是 extensions, skills, prompt templates, or themes 的集合，这让 Pi 的配置可以很方便的通过 git 或者 npm 分享和安装。说起来有点像发行版的概念，但又不完全是，因为 Pi Package 可以多个共存，这是 Pi 配置可分享的最小单元。

但是便捷背后也意味着可能出现的安全隐患，Pi 作者特意强调了安全问题：Pi 包以完整系统权限运行。扩展程序可执行任意代码，技能则能指示模型执行包括运行可执行文件在内的任何操作。所以安装第三方包前请务必先审查源代码。

![Image](https://pbs.twimg.com/media/HJkcobKbEAEtp7a?format=jpg&name=large)

当然，Pi 包的创建也可以直接通过 Pi 去完成，官方文档

[参考这里](https://pi.dev/docs/latest/packages)

#### Pi 包推荐

截至 2026 年 5 月，

[pi.dev/packages](https://pi.dev/packages) 已收录 3,328+ 个包。这里我推荐 10 个自己安装的。文末会给出我搜集的 awesome-pi-list 仓库供大家选择。

1. context-mode：节省 98% 上下文窗口，提供沙箱代码执行、FTS5 知识库和意图驱动搜索，Pi 用户几乎必装。
2. pi-subagents：子代理任务委派，支持链式调用、并行执行和 TUI 交互确认，让一个主代理调度多个子代理协作完成复杂任务。
3. pi-mcp-adapter：MCP (Model Context Protocol) 适配器，让 Pi 能连接外部 MCP 服务器，扩展工具能力（数据库、API、文件系统等）。
4. pi-web-access：Web 搜索、URL 抓取、GitHub 仓库克隆、PDF 提取、YouTube 视频理解，弥补 Pi 无法访问网络的短板。
5. pi-lens：实时代码反馈 —— LSP、linter、formatter、类型检查、结构分析。
6. pi-simplify：自动审查最近变更代码的清晰度、一致性和可维护性，代码质量守门员。
7. [@juicesharp/rpiv-todo](https://x.com/@juicesharp/rpiv-todo)：给模型一个持久化 TODO 列表，以实时覆盖层渲染，即使 /reload 或上下文压缩也能保留。
8. [@plannotator/pi-extension](https://x.com/@plannotator/pi-extension)：交互式计划审查与批注，支持对代理消息做标注、审查代码/PR，适合复杂任务前的方案评审。
9. [@narumitw/pi-goal](https://x.com/@narumitw/pi-goal)：/goal 模式，保持代理工作直到任务完成。
10. [@narumirw/statusline](https://x.com/@narumirw/statusline)：丰富的状态栏，显示模型、工具、git 分支、上下文使用、token 总计、费用和时间。

#### Pi Agent 配置指南：深度总结与解读

##### 一句话总结

**Pi Agent 是一个“极简内核 + 高度可扩展”的 AI 编程助手框架，适合喜欢自己搭建工作流的人，不适合追求开箱即用的人。**

---

##### 1. 深度总结

###### 1. Pi 是什么？

Pi，也叫 **Pi Coding Agent**，是 OpenClaw 背后的编码智能体框架。

它的核心特点是：

> **默认极简，能力靠自己扩展。**

0 配置状态下，Pi 只有 4 个基础工具：

- `bash`
- `read`
- `write`
- `edit`

它默认没有：

- MCP
- Sub-agents
- Plan mode
- 权限确认弹窗
- 复杂工作流

所以，Pi 更像是一个 **AI Agent 搭建框架**，而不是一个完整成品。

---

###### 2. Pi 的核心设计哲学

Pi 的思想类似 Neovim：

> 不预设你的工作方式，只提供一个干净内核，让你自己拼装。

它把复杂能力交给：

- Extensions：扩展
- Skills：技能
- Prompt Templates：提示模板
- Packages：插件包 / 配置包
- Themes：主题

因此，Pi 的价值不在“默认多强”，而在于：

> 你可以把它改造成完全适合自己的 AI 编程环境。

---

###### 3. Extension：Pi 的关键抽象

Extension 是 Pi 最重要的扩展机制，本质是 TypeScript 模块。

它可以做到：

| 能力 | 作用 |
|---|---|
| 自定义工具 | 给大模型增加新工具 |
| 自定义命令 | 增加类似 `/xxx` 的命令 |
| 事件拦截 | 在工具调用前后修改、阻止或注入逻辑 |
| UI 交互 | 自定义问答框、编辑器样式、等待动画 |
| 会话持久化 | 保存状态，例如 TODO 列表 |

最典型的例子：

- 执行 `rm -rf` 前要求确认
- 模仿 Claude Code Hooks
- 保存长期任务状态
- 自定义模型执行流程

---

###### 4. Prompt Template：轻量提示词命令

提示模板类似 Claude Code 的自定义斜杠命令。

它是带 front-matter 的 Markdown 文件，可以定义：

- 描述
- 参数提示
- 位置参数
- 参数切片

适合做轻量任务模板，例如：

```md
/commit
/review
/explain
/refactor
```

但它不如 Extension 强大，因为不能直接调用 Pi 内部 API。

---

###### 5. Pi Package：可分享的配置单元

Pi Package 是一组资源的集合，可以包含：

- extensions
- skills
- prompt templates
- themes

它有点像“发行版”，但更灵活，因为多个 package 可以共存。

它的意义在于：

> 让 Pi 的配置可以通过 Git 或 npm 传播、安装、复用。

但风险也很明显：

> Pi 包拥有完整系统权限，安装前必须审查代码。

因为扩展可以执行任意代码，技能也可能引导模型执行危险操作。

---

###### 6. 推荐 Package 的本质分类

作者推荐的 10 个包，其实可以分成几类：

###### 上下文与知识增强

- `context-mode`
- TODO 持久化插件

作用：减少上下文浪费，让 Agent 更“记得住”。

###### 多 Agent 协作

- `pi-subagents`

作用：让主 Agent 调度多个子 Agent，处理复杂任务。

###### 外部工具连接

- `pi-mcp-adapter`
- `pi-web-access`

作用：补齐网络、数据库、API、文件系统等能力。

###### 代码质量增强

- `pi-lens`
- `pi-simplify`

作用：引入 LSP、lint、formatter、类型检查、代码审查。

###### 任务管理与体验优化

- `pi-goal`
- `plannotator`
- `statusline`

作用：增强任务持续性、计划审查和状态可视化。

##### 2. 通俗解读

如果把 AI 编程助手比作“车”：

| 工具 | 类比 |
|---|---|
| Claude Code / Codex | 买来就能开的量产车 |
| Pi Agent | 给你发动机、底盘和零件，让你自己改装 |

Pi 的优势不是“马上能用”，而是：

> 你想怎么开，它就可以怎么改。

它适合这样的人：

- 喜欢折腾工具链
- 想定制自己的 AI 工作流
- 不满足于默认 Agent 行为
- 希望掌控权限、安全、上下文、工具调用
- 有一定工程能力或愿意让 AI 帮自己写插件

它不适合这样的人：

- 只想快速写代码
- 不想配置
- 不想审查插件
- 不想理解 Agent 工作机制
- 希望开箱即用

简单说：

> Claude Code 是“产品”，Pi 是“平台”。  
> Codex 是“助手”，Pi 是“助手生成器”。

##### 3. 文章真正想表达的重点

这篇文章表面是在讲 Pi 配置，实际在讲一种新的 AI 工具观：

> 未来强大的 AI 编程助手，不一定是一个封闭产品，而可能是一个可组合、可扩展、可分发的个人智能体系统。

Pi 的核心价值在于：

1. **极简内核降低复杂度**
2. **扩展机制释放自由度**
3. **Package 生态促进复用**
4. **提示模板降低定制门槛**

这和 Neovim 时代很像：

- 初始很简陋
- 配置很折腾
- 生态很丰富
- 上限非常高
- 用户越懂，收益越大

##### 4. 辩证思考

###### Pi 的价值

Pi 最大的优点是 **可塑性**。

它不是试图替你决定最佳工作流，而是让你定义自己的最佳工作流。

这对高级开发者很有吸引力，因为每个人的编码习惯、项目结构、安全要求、审查流程都不同。

在这一点上，Pi 比封闭式 Agent 更自由。

---

###### Pi 的问题

但自由也意味着成本。

Pi 的问题主要有三个：

###### 1. 配置成本高

要真正用好 Pi，需要理解：

- Agent 工具调用
- 生命周期事件
- 插件权限
- 上下文管理
- Prompt Template
- Package 生态

这不是普通用户愿意承担的成本。

###### 2. 安全风险高

Pi Package 可以执行任意代码。

这意味着安装一个恶意包，可能等于给陌生人系统权限。

所以 Pi 的生态越繁荣，安全问题越重要。

###### 3. 生态可能碎片化

不同插件可能：

- 工具名不统一
- Harness 不兼容
- 工作流设计冲突
- 安全策略不一致

这会让用户从“自由组合”变成“自己排雷”。

---

###### 我的判断

Pi 的方向很有前景，但它不会取代 Claude Code 或 Codex。

更可能的格局是：

| 用户类型 | 更适合 |
|---|---|
| 普通开发者 | Claude Code / Codex |
| 高级开发者 | Pi |
| 团队工程平台 | Pi + 自定义 Harness |
| 安全敏感场景 | 自建 Pi 生态 |
| 快速原型开发 | 开箱即用 Agent |

Pi 最适合成为：

> 高级开发者和团队内部的“AI 编程基础设施”。

而不是面向所有人的通用 AI 编程产品。

---

##### 5. 最精炼结论

Pi Agent 的本质是：

> 一个极简、可编程、可扩展的 AI Coding Agent 框架。

它的优点是：

- 自由
- 灵活
- 可定制
- 可组合
- 上限高

它的缺点是：

- 不开箱即用
- 学习成本高
- 安全风险大
- 生态可能混乱

最终建议：

> 如果你想要“马上帮我写代码”，用 Claude Code / Codex。  
> 如果你想要“打造一个完全属于自己的 AI 编程系统”，Pi 值得折腾。

#### 《Pi Agent 配置指南：打造你的专属 AI 编程助手》精炼总结

本文介绍了 **Pi Agent** 的核心理念、能力边界和可扩展配置方式。Pi 的特点是“极简内核 + 高度可定制”，它不像 Claude Code 或 Codex 那样开箱即用，更适合喜欢自己搭建工作流、打造专属 AI 编程助手的用户。

---

##### 1. Pi 是什么：极简的 AI 编程智能体框架

Pi 又叫 **Pi Coding Agent**，是 **OpenClaw 背后的编码智能体框架**。

它的设计哲学非常极简：

- 默认几乎没有复杂功能；
- 核心只保留最基础的能力；
- 其他能力通过扩展、技能、提示词模板和包来实现。

作者将 Pi 类比为过去折腾 **Neovim** 的体验：不是直接使用一个完整产品，而是像拼乐高一样，自己搭建属于自己的开发环境。

---

##### 2. Pi 的默认能力边界：0 配置只支持 4 种工具

默认情况下，Pi Agent 只支持 4 个基础工具：

- `bash`
- `read`
- `write`
- `edit`

它默认没有：

- MCP
- sub-agents 子代理
- plan mode 计划模式
- permission popups 权限确认弹窗

因此，如果你想要的是“装好就能用”的 AI 编程助手，作者建议选择：

- **Claude Code**
- **Codex**

Pi 更适合愿意自己配置工作流的人。

---

##### 3. Extension：Pi 的核心扩展机制

**Extension 是 Pi 框架中的第一个重要抽象**，本质上是 TypeScript 模块，用来扩展 Pi 的行为。

扩展文件放在：

```bash
.pi/agent/extensions/*
```

Pi 会自动发现这些扩展，也可以通过：

```bash
/reload
```

进行热更新。

###### Extension 可以做什么？

主要能力包括：

###### 1）自定义工具和命令

可以通过：

- `pi.registerTool()` 注册大模型可调用的工具；
- `pi.registerCommand()` 注册自定义斜杠命令。

###### 2）事件拦截

可以在工具调用前后进行干预，例如：

- 阻止危险命令；
- 修改工具调用；
- 注入上下文；
- 自定义上下文压缩逻辑。

###### 3）自定义交互和界面

Pi 允许用户自定义界面和交互，例如：

- 做一个问答框；
- 自定义 Editor 样式；
- 在等待模型输出时写一个小游戏，比如贪吃蛇、飞机大战。

###### 4）会话持久化

可以通过：

```ts
pi.appendEntry()
```

保存重启后仍然存在的状态。

例如可以做一个类似 TODO List 的扩展，即使重启或热加载后任务仍然保留。

---

##### 4. 如何写 Pi 扩展：可以直接让 Pi 帮你生成

在 AI 时代，不一定要像折腾 Neovim 时手写 Lua 配置一样手动开发扩展。作者建议可以直接告诉 Pi 需求，让 Pi 自己写扩展并热加载生效。

###### 示例 1：权限确认插件

可以对 Pi 说：

> 我想写一个叫做 `permission-gate` 的树莓派扩展，其作用是在危险的 bash 命令，比如 `rm -rf`、`sudo` 等之前提示确认。

###### 示例 2：Claude Code Hooks 风格插件

也可以说：

> 我想写一个叫做 `CC-hooks` 的插件，用来将 Pi 原生的事件拦截能力，包装成像 Claude Code Hooks 一样的用法。

这体现了 Pi 的可塑性：底层提供事件和 API，用户可以自行封装成自己熟悉的工作流。

---

##### 5. Prompt Template：类似 Claude Code 的自定义斜杠命令

Pi 的 **提示模板 Prompt Template** 更像 Claude Code 中的自定义斜杠命令。

它的格式是一个带有 **front-matter** 的 Markdown 文件。

front-matter 可包含：

- `description`：命令描述；
- `argument-hint`：参数提示。

这两个字段都是可选的，会显示在下拉菜单中。

模板还支持参数写法，例如：

```bash
$1
$2
${@:N}
```

用于读取位置参数或参数切片。

不过，作者也提到：相比提示模板，Extension 里的自定义命令更强大，因为它可以调用 Pi 内部 API。

---

##### 6. Pi Package：可分享、可安装的配置单元

**Pi Package 是 Pi 的另一个重要抽象**，可以理解为一组配置能力的集合。

一个 Pi Package 可以包含：

- extensions
- skills
- prompt templates
- themes

它的作用是让 Pi 配置可以通过：

- Git
- npm

方便地分享和安装。

作者认为它有点像“发行版”，但又不完全一样，因为多个 Pi Package 可以共存。它更像是 Pi 配置分享的最小单位。

---

##### 7. 安全提醒：第三方 Pi Package 需要审查源码

Pi Package 虽然方便，但也有安全风险。

作者特别强调：

- Pi 包以完整系统权限运行；
- Extension 可以执行任意代码；
- Skill 可以指示模型执行包括运行可执行文件在内的操作。

因此，安装第三方包前一定要先审查源码，避免安全隐患。

##### 8. Pi Package 推荐：官方已收录 3,328+ 个包

截至 **2026 年 5 月**，`pi.dev/packages` 已经收录了 **3,328+ 个 Pi Package**。

作者推荐了 10 个自己安装的包：

###### 1）context-mode

- 可节省 **98% 上下文窗口**；
- 支持沙箱代码执行；
- 支持 FTS5 知识库；
- 支持意图驱动搜索；
- 作者认为几乎是 Pi 用户必装。

###### 2）pi-subagents

- 支持子代理任务委派；
- 支持链式调用、并行执行；
- 支持 TUI 交互确认；
- 适合让一个主代理调度多个子代理完成复杂任务。

###### 3）pi-mcp-adapter

- MCP 适配器；
- 让 Pi 能连接外部 MCP Server；
- 可扩展数据库、API、文件系统等工具能力。

###### 4）pi-web-access

补足 Pi 默认无法访问网络的问题，支持：

- Web 搜索；
- URL 抓取；
- GitHub 仓库克隆；
- PDF 提取；
- YouTube 视频理解。

###### 5）pi-lens

提供实时代码反馈，包括：

- LSP；
- linter；
- formatter；
- 类型检查；
- 代码结构分析。

###### 6）pi-simplify

自动审查最近变更代码，关注：

- 清晰度；
- 一致性；
- 可维护性。

可作为代码质量守门员。

###### 7）@juicesharp/rpiv-todo

- 给模型一个持久化 TODO 列表；
- 以实时覆盖层方式渲染；
- 即使 `/reload` 或上下文压缩后也能保留。

###### 8）@plannotator/pi-extension

- 支持交互式计划审查与批注；
- 可对代理消息做标注；
- 可审查代码或 PR；
- 适合复杂任务前做方案评审。

###### 9）@narumitw/pi-goal

- 提供 `/goal` 模式；
- 让代理持续工作，直到任务完成。

###### 10）@narumirw/statusline

提供丰富状态栏，可显示：

- 当前模型；
- 工具；
- Git 分支；
- 上下文使用情况；
- token 总量；
- 费用；
- 时间。

Pi Agent 的核心价值不在于“开箱即用”，而在于提供一个极简、可扩展、可组合的 AI 编程智能体框架。它适合喜欢深度定制工具链的开发者，通过 Extension、Prompt Template 和 Pi Package，可以逐步搭建出自己的专属 AI 编程助手。

#### Pi Agent：以极简内核换取高度可定制的 AI 编程工作流

Pi 是 OpenClaw 背后的编码智能体框架，核心取舍是“少做预设、开放扩展”。默认仅提供 bash、read、write、edit 四种工具，不内置 MCP、子代理、计划模式或权限弹窗。它适合愿意自行搭建工作流的用户；若追求开箱即用，Claude Code 或 Codex 更合适。

##### 扩展是 Pi 的核心能力

Extension 是自动加载的 TypeScript 模块，可通过热更新快速生效，主要用于：

- 注册模型可调用的工具和斜杠命令；
- 拦截或修改工具调用、注入上下文、自定义压缩；
- 定制问答框、编辑器和状态界面；
- 持久化 TODO 等跨会话状态。

用户也可直接让 Pi 编写扩展，例如为 `rm -rf`、`sudo` 等危险命令增加确认，或复刻 Claude Code Hooks。

##### 模板与 Package 让配置可复用

提示模板是带 front-matter 的 Markdown 文件，类似自定义斜杠命令，支持参数传递。Pi Package 则把扩展、技能、模板和主题打包，可通过 Git 或 npm 安装、分享，并允许多个包共存，相当于可组合的配置单元。

但 Package 拥有完整系统权限：扩展可执行任意代码，技能也可能引导模型运行程序，因此第三方包必须先审查源码。

##### 生态正在补齐极简内核的缺口

文章称截至 2026 年 5 月，生态已有 3,328+ 个包。推荐能力包括：压缩上下文、子代理协作、MCP 接入、联网与 PDF/视频解析、LSP 和代码检查、计划评审、持久化任务及费用状态栏。Pi 的价值不在默认功能丰富，而在于用户可像配置 Neovim 一样，组合出自己的 Agent Harness（运行与协作工作流）。
