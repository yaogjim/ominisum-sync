## 分析要点

- **核心高价值点**：将难以直接数字化的模拟旋钮抽象为 MQTT Cover，再接入 Home Assistant Generic Thermostat，是兼顾无损改造与系统集成的实用方案。
- **留存建议**：建议保留，作为模拟设备无损智能化和低成本物联网原型的实践案例（包含方案权衡、物料清单、MQTT Discovery 配置、恒温控制集成及长期运行反馈，具有较强的复用参考价值。）

**知识要点**

- 面对市电设备时，可优先评估外置机械执行方案，避免改线带来的安全、施工和租赁风险。
- Home Assistant 的 MQTT Discovery 可通过标准配置消息自动创建设备实体，减少定制集成和 YAML 配置工作。
- 低成本原型的长期可靠性往往受机械结构而非软件限制，固定件变形、轴线偏移和摩擦会导致步进电机失速。

**行动项**

- 为类似模拟设备建立继电器、智能插座和机械执行器三类方案的安全性与实施成本对比。
- 先用步进电机、轴联器和临时支架验证旋钮扭矩、转动范围及失速情况，再设计正式固定结构。
- 通过 MQTT Discovery 接入 Home Assistant，并结合温度传感器和 Generic Thermostat 验证迟滞控制与长期稳定性。

我租的公寓的空调只能用这种老式的 *旋钮* 式控制器控制，就装在空调机上。没有单独的壁挂式温控器，没有遥控器……一点花哨的功能都没有。

这些旋钮确实能用……但是总是要站起来摆弄它们，很快就会让人觉得烦躁。

幸运的是，普里里克家族有一句古老的谚语，大意是：“记住儿子——人生中最棘手的问题通常只需要一个步进电机、一个 ESP32 和一个梦想就能解决。”

果不其然，在花了 15 美元购买零件、等待零件从中国发货，并花费几个小时反复调试硬件和固件之后……我拼凑出了这个美丽的混乱之作：

你现在看到的是一个用 **esp32 控制的简易步进电机** ，通过 **轴联器** 连接到我的空调机组的一个旋钮上，所有部件都用一个 **廉价的 L 型支架** 和一个 **文件夹夹子** 固定在空调机组的背板上（为了保险起见，还加了一些工业级 **纸板衬垫** ）。

这个用麦克盖弗式方法拼凑起来的装置通过 **MQTT** 与我的 **Home Assistant** 实例通信，根据位于同一房间的温度传感器的状态来打开/关闭空调。

#### 🎛️ 找到正确的方法⌗

观察该装置，我们发现有两个旋钮：

1. **模式控制：** 一个坚硬的、独立的旋钮，可在 6 种操作“模式”之间切换（关闭、低制冷、高制冷 2 、通风、排气和制热）
2. **温度控制：** 一个平滑的模拟旋钮，连接到一个简单的基于双金属片的恒温器。

幸运的是，这两个塑料旋钮都可以轻松取下，露出一根轴，将其机械连接起来应该不会 *太难* ：

这让我有了两种打开和关闭空调的方法：

**方案一：** 连接到 **模式控制** 旋钮

- 将温度控制旋钮设置为“最大制冷”
- 购买一台扭矩足够的步进电机，以克服旋钮的阻力。
  - ……这可能需要 12V 直流（甚至更高）电源，因此需要额外的电路来供电。
  - ……并且需要更坚固的安装硬件，以抵消扭矩，并确保步进电机保持在正确的位置。
- 精确校准步进电机，使旋钮在“关闭”状态和“冷却”状态之间旋转正确的角度。

**方案二：** 连接到 **温度控制** 旋钮

- 将模式控制旋钮保持在“低温制冷” 3
- 购买一个便宜、低扭矩、低功率的步进电机，功率 *只需* 足以转动那个比较松动的旋钮即可。
  - ……由于扭矩相当低，所以它不需要太多的安装硬件就能固定在正确的位置。
- 不精确地将步进电机向左/向右推到底，使目标温度在“非常非常热”或“非常非常冷”之间切换。

希望你能猜到我选了哪个🥰

> 方案 2 显然是两个方案中比较“粗糙”的，因为它依赖于二阶属性（目标温度）来控制设备的开/关……但是，嘿——哪个更简单就用哪个，对吧？

话虽如此，虽然看到它在网页界面上运行 *很酷* ……但要真正发挥作用，我需要将其与 Home Assistant 集成。

如果你还不熟悉， [Home Assistant](https://www.home-assistant.io/) 是一个开源的家庭自动化平台，它就像你所有智能设备的“大脑”。它非常棒，如果你有 *任何* 稍微复杂一点的智能家居需求，那就 *绝对* 应该安装它。

我没有编写任何自定义 API 集成脚本，而是利用了 Home Assistant 对 **MQTT Discovery** 的出色支持。

> 如果您不熟悉 MQTT，可以将其视为一种超轻量级的发布/订阅消息协议，专为资源受限的物联网设备而设计。
>
> 设备可以向特定路径（称为主题，例如 `living_room/ac/state` ）“发布”消息，其他设备（例如 Home Assistant）可以“订阅”这些主题来监听更新或发送命令。

对于这样的旋钮控制器，我决定将其作为 [MQTT Cover](https://www.home-assistant.io/integrations/cover.mqtt/) 集成对外开放。虽然“cover”通常用于窗帘、电动窗帘或车库门之类的设备……但它的协议支持打开、关闭和停止，这与我们的旋转旋钮的功能非常契合。

ESP32 启动时，会自动连接到 MQTT 代理并发送以下发现 JSON 有效负载：

```json
{
  "name": "AC Stepper Cover",
  "unique_id": "ac_stepper_esp32_01",
  "object_id": "ac_stepper_cover",
  "command_topic": "homeassistant/cover/ac_stepper_cover/set",
  "state_topic": "homeassistant/cover/ac_stepper_cover/state",
  "position_topic": "homeassistant/cover/ac_stepper_cover/position",
  "set_position_topic": "homeassistant/cover/ac_stepper_cover/position/set",
  "payload_open": "OPEN",
  "payload_close": "CLOSE",
  "payload_stop": "STOP",
  "device_class": "damper",
  "device": {
    "identifiers": "ac_stepper_esp32",
    "name": "AC Control Stepper"
  }
}
```

Home Assistant 注册到盖子后，会监听用户界面上的用户交互，并将相应的命令发布到 `command_topic` 。在 ESP32 上，MQTT 回调函数会解析消息并驱动步进电机：

```cpp
void mqttCallback(char* topic, byte* payload, unsigned int length) {
  String message = extractMessageFromPayload(payload, length);
  if (String(topic) == COMMAND_TOPIC) {
    handleCoverCommand(message);
  }
}

void handleCoverCommand(const String& command) {
  if (command == "OPEN") {
    motorState.isOpening = true;
    moveMotor(STEPS_PER_REVOLUTION, motorState.currentSpeed);
  } else if (command == "CLOSE") {
    motorState.isOpening = false;
    moveMotor(-STEPS_PER_REVOLUTION, motorState.currentSpeed);
  } else if (command == "STOP") {
    stopMotor();
  }
}
```

发送 `OPEN` 有效载荷会使步进电机向前旋转一整圈，将旋钮转到“最冷”位置，而 `CLOSE` 载荷会使步进电机向后旋转以将其关闭。

就这样——Home Assistant 就能控制电机了！

通过 Home Assistant 控制旋钮后，最后一步就是告诉它 *何时* 打开和关闭。

幸运的是，Home Assistant 内置了一个名为 [“通用恒温器”](https://www.home-assistant.io/integrations/generic_thermostat/) 的集成功能。它非常简单——只需将其对准要切换的开关/盖板和要监控的温度传感器，它就会自动处理所有滞后逻辑！

温度传感器我使用的是 [AirGradient ONE](https://www.airgradient.com/indoor/) ，这是一款高质量的智能空气质量监测器，碰巧和空调机放在同一个房间里。

将这两者连接起来非常简单，只需将以下内容添加到我的 `configuration.yaml` 中即可：

```yaml
climate:
  - platform: generic_thermostat
    name: Living Room AC
    heater: cover.ac_stepper_cover
    target_sensor: sensor.airgradient_temperature
    min_temp: 65
    max_temp: 80
    ac_mode: true
    cold_tolerance: 0.5
    hot_tolerance: 0.5
```

就这样，我的空调就通过全自动智能恒温器控制起来了！

## 结构化（1）

#### 把老式空调变 “智能”，还不损伤出租屋

##### 1. 问题：空调能用，但控制方式太原始

- 作者于**2025 年 4 月**搬到纽约，公寓条件不错，但安装的是常见的壁挂式**PTAC 空调**。
- 空调没有壁挂温控器和遥控器，只能操作机身上的两个旋钮：
  - **模式旋钮**：在关闭、低速制冷、高速制冷、通风、排气、制热等模式间切换。
  - **温度旋钮**：通过双金属片恒温器设定目标温度。

##### 2. 常见改造方案为什么不可行

###### 向房东申请升级

- 作者询问房东能否换成更现代的控制方式，但被拒绝。

- 拆开外壳后，作者发现了设备电路图，但空调内部基本都在**市电电压**下运行，缺少容易接入的低压数字信号。
- 相关线路深藏在机组内部，可能需要把整台空调从墙里拆出。
- 对没有电工经验的人来说，这既危险，也可能引发房东不满，因此放弃。

###### 智能插座

- 直接切断空调电源可能导致频繁启停，尤其发生快速循环时，可能损坏压缩机。
- 这台空调还使用不常见的**NEMA 5-20P 插头**，很难买到适配的智能插座。
- 因此作者转向一个更安全、可逆的思路：**不改电路，只让机器人代替人拧旋钮。**

##### 3. 核心方案：用步进电机转动温度旋钮

拆下塑料旋钮后，内部轴杆可以直接连接电机。作者比较了两种方案：

###### 方案一：转动模式旋钮

- 在 “关闭” 和 “制冷” 之间切换。
- 模式旋钮阻力较大，需要：
  - 高扭矩步进电机；
  - 可能达到**12V 或更高**的供电；
  - 更牢固的安装结构；
  - 精确控制旋转角度。

###### 方案二：转动温度旋钮

- 将模式固定在 “低速制冷”。
- 用低功率步进电机，把温度旋钮推到两个极端：
  - 转到 “最冷”：空调启动制冷；
  - 转到 “最热”：空调认为无需制冷并停止。
- 该方案无需精确定位，电机和支架要求也更低。

作者选择了更简单的**方案二**。虽然它不是直接切换电源，而是借助目标温度间接控制开关，但足够实用。

##### 5. 固件：ESP32 接收命令并驱动电机

ESP32 固件的功能很简单：

- 在手机上手动开关空调。

基本控制验证成功后，作者进一步将设备接入 Home Assistant。

##### 6. 接入 Home Assistant：把旋钮模拟成 “窗帘”

###### 为什么使用 MQTT Cover

- **MQTT**是适合物联网设备的轻量级发布 / 订阅协议。
- Home Assistant 的 MQTT Discovery 可以自动发现和注册设备，无需额外开发自定义集成。
- 作者把旋钮控制器注册为**MQTT Cover**：
  - `OPEN`：电机向前转一圈，把温度调到最冷；
  - `CLOSE`：电机反向转动，把温度调到最热；
  - `STOP`：停止电机。
- 虽然 Cover 通常用于窗帘、百叶窗或车库门，但其 “打开、关闭、停止” 的模型正好适合旋钮电机。

ESP32 启动后会连接 MQTT 代理，向 Home Assistant 发布发现信息；Home Assistant 随后通过指定的`command_topic`发送控制命令。

##### 7. 自动恒温：根据室温决定何时制冷

只有远程控制还不够，作者还需要系统自动判断何时启停空调。

- 使用 Home Assistant 内置的**Generic Thermostat（通用恒温器）**。
- 温度数据来自同一房间内的**AirGradient ONE**空气质量监测器。
- 关键配置包括：
  - 最低温度：**65°F**
  - 最高温度：**80°F**
  - 制冷模式：开启
  - 冷、热容差：均为**0.5°F**

通用恒温器会处理温度滞后逻辑，避免空调在临界温度附近频繁开关。最终流程为：

> 温度传感器检测室温 → Home Assistant 判断是否需要制冷 → 通过 MQTT 发送命令 → ESP32 驱动电机 → 旋钮转到最冷或最热位置。

## 口播总结（1）

### 2026-08-03 00:54:48

#### 把老式空调变智能，而且不丢押金

这篇文章讲的是，一名软件工程师如何用不到十五美元左右的零件，把没有遥控器、只能手动拧旋钮的老式空调，改造成自动恒温的智能设备。你会听到他为什么放弃改电路和智能插座，又如何用步进电机、ESP32 和家庭自动化软件，做出一个不完美但确实有用的解决方案。

##### 首先，问题不是空调不能用，而是它太不方便

作者搬到纽约后，公寓整体很满意，唯一明显的问题是空调。

房间里安装的是 PTAC 空调，也就是常见于公寓和酒店的壁挂式一体空调。这种设备噪音较大、耗电也不低。更麻烦的是，房东选择了最便宜的控制方案：没有壁挂温控器，没有遥控器，只有机身上的两个模拟旋钮。

一个旋钮负责切换关闭、制冷、通风、制热等六种模式；另一个旋钮负责调节目标温度。想开关空调或改变温度，就必须走到机器旁边手动操作。

作者先问房东能不能升级控制器，得到的答复基本是否定的。于是，他决定自己解决，但有一个重要前提：不能对空调和公寓做永久改动，否则可能影响租房押金。

##### 接下来，常见的智能化方案都不太合适

核心结论是，直接改电路风险太高，使用智能插座也不现实，所以只能从机械旋钮入手。

作者拆开空调外壳后，发现了完整的接线图。但从图上看，设备内部主要使用市电电压，也就是插座直接提供的高电压，而不是适合普通电子设备接入的低压控制信号。

他首先考虑过智能继电器，也就是用电子开关直接控制空调内部线路。但作者没有电工经验，而且相关电线藏在机组深处。想接触这些线路，可能要把整台空调从墙里拆出来。无论安全、工作量，还是房东的接受程度，都不值得冒险。

他又考虑用智能插座直接切断电源。但空调运行时频繁断电，尤其是短时间内反复开关，可能损坏设备。此外，这台空调使用的是 NEMA 5-20P 插头，也就是一种带横向插脚的大功率插头，对应的智能插座很难找到。

既然不能安全地改电路，也不方便控制总电源，剩下的办法就很直接了：做一个小机器人，替人拧旋钮。

##### 然后，关键选择是控制哪个旋钮

作者最终选择了温度旋钮，而不是模式旋钮。原因很简单：温度旋钮更松，需要的力量更小，安装也容易得多。

如果控制模式旋钮，就要让电机在“关闭”和“制冷”之间准确切换。这个旋钮阻力较大，需要高扭矩电机，可能还要十二伏甚至更高的电源。支架必须足够结实，转动角度也要精确校准。

相比之下，温度旋钮可以轻松转动。作者只要把模式固定在“低速制冷”，再用一个便宜的低功率步进电机，把温度旋钮推到两个极端即可。

步进电机是一种能够按固定小角度转动的电机，很适合控制旋钮。需要开机时，电机把温度旋到“非常冷”；需要关机时，就把温度旋到“非常热”。由于这台空调在达到目标温度后会完全停止运行，所以把目标温度调得足够高，实际效果就接近关机。

这种方法不精细，甚至有些绕。但它不需要碰高压线路，也不用精确判断旋钮角度，明显更适合低预算的租房改造。

##### 第一个版本，重点是证明这个思路能用

作者制作的 V0，也就是第一个验证版本，总成本大约十六美元。

主要零件包括一块六美元的 ESP32 开发板、一只约六点七美元的轴联器，以及一套约两点七美元的步进电机和控制器。ESP32 是一款自带 Wi-Fi 的小型控制芯片，相当于整个装置的大脑。轴联器则负责把电机轴和空调旋钮的轴连接起来，让电机能够真正拧动旋钮。

为了避免在空调外壳上打孔，作者使用了宜家书架剩下的 L 型金属支架、旧显示器支架上的螺丝，以及闲置的 USB 电源线。

他的安装方式很粗糙，但原理有效。电机旋转时，L 型支架会顶住空调控制舱的后壁，抵消电机自身的扭转力。这样，旋转力量就能通过轴联器传到旋钮上。

整个过程并不顺利。作者买错过多次轴联器，也曾用旧 Arduino 开发板和长 USB 线先做测试。最早的安装方案甚至用到了木签、胶棒和剪开的纸箱，结果完全失败。

但这些尝试证明了一件事：只要固定得住，便宜的步进电机确实可以转动空调的温度旋钮。

##### 更重要的是，软件让它从遥控装置变成了自动恒温器

硬件能转动旋钮之后，作者为 ESP32 写了固件。固件就是运行在小型硬件里的控制程序。

它主要做三件事：连接 Wi-Fi，提供一个本地网页界面，并接收 HTTP 或 MQTT 命令来控制电机。MQTT 是一种轻量级消息协议，常用于物联网设备。简单来说，设备可以向某个固定的“频道”发送状态，也可以监听这个频道里的控制命令。

作者使用 Claude 和 Gemini 这两种大语言模型来生成一次性代码。大语言模型，也就是 LLM，是能够理解和生成代码及文字的人工智能系统。生成的程序不仅能驱动电机，还提供了一个简单网页，可以填写 Wi-Fi 信息、调整电机参数，并用手机直接测试开关。

不过，网页遥控还不是真正的自动化。于是作者把装置接入了 Home Assistant。Home Assistant 是一个开源家庭自动化平台，可以理解为家里所有智能设备的统一控制大脑。

作者没有编写复杂的专用接口，而是使用 MQTT Discovery，也就是让设备主动告诉 Home Assistant：“我是什么设备，我接受哪些命令，我会在哪里报告状态。”

他把这个旋钮控制器伪装成一种“Cover”设备。Cover 原本通常代表窗帘、车库门或风门，因为它天然支持打开、关闭和停止三个动作，刚好适合控制旋钮。

当 Home Assistant 发送“打开”命令时，步进电机向前转动一整圈，把温度旋到最冷；收到“关闭”命令时，电机反向转动，把温度旋到最热。

##### 自动开关的依据，来自房间里的温度传感器

有了远程控制后，最后一步是让系统自己判断何时制冷。

作者使用了 Home Assistant 内置的“通用恒温器”功能。它会同时观察一个温度传感器和一个可控制的设备。当房间太热时，它发出开启命令；温度降下来后，再发出关闭命令。

为了避免温度在临界点附近波动时，空调频繁开关，系统还会使用“滞后”逻辑。通俗地说，就是开机和关机不会卡在完全相同的温度点，而是留出一个小缓冲区。作者设置的冷热容差都是零点五度。

房间温度来自 AirGradient ONE 空气质量监测器，它正好与空调放在同一个房间。把传感器、旋钮控制器和通用恒温器连接起来后，这台原本完全模拟的老空调，就实现了自动恒温。

##### 随后，第二个版本更整洁，但仍然很“手工”

客厅改造成功后，作者还想控制卧室里的另一台同型号空调。由于旧支架和螺丝已经用完，他重新采购零件，制作了 V1 版本。

这一版总成本约十四美元。作者换用了更小的 ESP32 开发板，价格约三点三美元；轴联器约两点四美元；步进电机和控制器仍然约两点七美元。新的可调节 L 型支架单个约五十美分，USB 线和充电器则花了五美元。

新支架带有长槽，可以用螺母和螺栓把电机牢牢固定上去。相比第一个版本让支架顶住后壁，V1 使用一个大号文件夹夹子，再加纸板调整间距，把整个组件夹在空调内部的垂直金属板上。

ESP32 被塞进控制舱里，USB 线也经过隐藏布置。盖上外壳后，从空调外面几乎看不出它已经被改造成智能设备。更关键的是，整个安装仍然没有打孔，也没有永久改变空调，因此符合作者保住押金的目标。

##### 最后，长期使用结果是：不完美，但值得

经过大约一个半夏季的实际使用，作者给出的评价是：它大概有百分之八十的时间表现不错。

最大的故障并不来自软件，而是固定结构。文件夹夹子和纸板没有想象中牢固。时间一长，步进电机会逐渐下垂，使电机、轴联器和旋钮之间产生过多摩擦。装置有时会卡住，需要人工重新调整位置。

这确实令人烦恼，但和每天反复走到空调旁手动调节相比，仍然省事得多。作者认为，如果以后继续住在这套公寓里，可能会考虑使用三维打印支架，把可靠性进一步提高。

这套装置谈不上精密。它使用廉价零件、简单固件、文件夹夹子和纸板，可靠性也只有大约八成。但它解决了一个非常具体的问题，单套成本不到十五美元左右，还通过更合理的自动控温节省了可观的电费。

##### 最值得记住的几点

最后，回顾五个核心结论。

第一，面对老式空调，直接改市电线路风险高，智能插座也不一定兼容。控制外部旋钮，反而可能是最安全、最适合租房的办法。

第二，选择温度旋钮比控制模式旋钮简单。它需要的扭矩更小，不必精确校准，也不需要复杂电源和重型支架。

第三，ESP32、步进电机和轴联器，就能组成基本的机械控制装置。V0 成本约十六美元，改进后的 V1 约十四美元。

第四，真正让装置“智能”的不是电机本身，而是 Home Assistant、MQTT 和温度传感器的配合。它们共同完成远程控制、状态通信和自动恒温。

第五，这个项目的可靠性只有大约百分之八十，夹子和纸板也绝不是理想结构。但它没有破坏公寓设备，降低了日常操作负担，还节省了电费。对作者来说，一个粗糙但能解决实际问题的方案，已经足够成功。

## 深度解读（1）

### 2026-09-18 00:15:42

#### 旧设备智能化的关键，不是改造内部，而是找到最便宜的控制接口

这篇文章最值得保留的，不是“用 ESP32 控制空调”本身，而是作者在一组现实约束下做出的架构选择：租客不能破坏设备，市电线路危险且难以接近，特殊插头又让智能插座不可行。最终，他没有试图理解和重做空调内部系统，而是让步进电机直接旋转原有旋钮。

##### 好方案往往来自主动降低控制精度

空调有模式和温度两个旋钮。直接转动模式旋钮更符合直觉，却需要更大扭矩、精确角度和牢固支架；作者转而控制阻力较小的温度旋钮，只在“极冷”和“极热”两个端点间切换，把它间接当成开关。

这看似粗糙，实质上是一次有效的复杂度交换：**放弃精确复现人的操作，改为寻找能达到同一结果的最简单变量。** 外部温度传感器和 Home Assistant 负责判断何时制冷，原旋钮只承担执行动作。端点控制还减少了校准要求，即使步进电机不知道绝对位置，也可以通过“转到底”获得近似确定状态。

这种方法可迁移到许多遗留设备：当内部接口封闭、改造风险高时，按钮、旋钮、拉杆等人机界面本身就是兼容性最广的 API。前提是机械操作不会绕过关键安全机制，而且故障后仍能手动接管。

##### 软件正在变便宜，现实世界的可靠性没有

作者用 Claude 和 Gemini 生成一次性固件，再借助 MQTT Discovery 和 Home Assistant 的通用恒温器，几乎没有开发专用集成。甚至把空调旋钮抽象成“窗帘”：系统只需要打开、关闭、停止这些能力，并不在意设备究竟是什么。对产品设计而言，这提示了一个实用原则：**优先复用稳定的能力模型，不必为每个对象建立完美而专属的语义。**

但一年多的使用暴露出真正瓶颈：文件夹夹和纸板会松动，电机下垂后产生摩擦并卡死。固件能跑不等于系统可靠；无位置、扭矩或动作结果反馈的开环控制，也无法知道命令是否真正执行。LLM 降低了“胶水代码”的成本，却没有降低固定、磨损、公差和异常恢复的成本。要从原型走向产品，至少还需要稳定支架、限位或状态检测、手动接管和压缩机防频繁启停机制。

##### 存在改装市场，但价值取决于约束密度

它指向一种明确需求：租客或老旧楼宇用户无法更换设备，却希望获得远程控制、恒温和节能能力。机会不是再造一个通用智能家居平台，而是提供**免破坏、可拆卸、适配旧设备的执行器**。

不过，作者所称“节省了可观电费”没有数据支持，不能直接视为商业价值证明。真正需要验证的是：有多少设备共享相似轴径与空间、安装能否在几分钟内完成、长期成功率是否足够高，以及用户愿意为可靠性支付多少。这个案例证明了需求真实存在，也同时解释了为什么这类产品难做——代码可以通用，物理世界往往每台都不一样。

## 默认总结（1）

### 2026-09-18 01:19:48

##### 一句话看懂

作者用不到 15 美元的 ESP32、步进电机和简陋支架，机械转动老式空调旋钮，在不改线路、不破坏租房设备的前提下接入智能家居。

##### 关键内容

- 空调没有遥控器，内部又涉及市电；智能继电器需要拆机接线，智能插座也不适配，因此作者改为让电机直接“拧旋钮”。
- 他将空调固定在低速制冷模式，用步进电机把温度旋钮推到最冷或最热，间接实现开关控制。ESP32 通过 MQTT 接入 Home Assistant，再结合房间温度传感器自动启停。
- 两版装置成本约 14—16 美元，且无需打孔：支架、文件夹夹子和纸板负责固定，固件则主要借助 Claude、Gemini 生成。
- 实测约“80%可用”：长期使用后电机会下垂、摩擦并卡住，需要手动复位。作者仍认为它比频繁手调方便，并称节省了电费，但未提供具体数据。

##### 通俗解读

这不是把空调真正改造成智能设备，而是给旋钮装了一只联网的“机械手”。方案便宜、可拆卸，但可靠性一般。若你想看租房友好的 DIY 思路、Home Assistant/MQTT 接入细节，值得细读；若想找成熟、安全且免维护的成品方案，参考价值有限。
