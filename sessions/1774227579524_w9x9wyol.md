David Singleton，前 Stripe CTO 最近有个观点很炸裂：

当我们所有人都觉得 AI 时代最危险的是 manager，因为不需要中间层了嘛，agent 直接干了。

结果他现在优先招那些以前当过 manager 但现在想回来写代码的人。

原因是他认为 manager 天然擅长拆解任务、协调资源、知道什么时候该推一把什么时候该放手，他认为这才是驾驭 coding agent 最核心的能力。

不知道大家怎么看？

## 解读（1）

### 2026-03-23 03:22:14

#### 总结

David Singleton（前 Stripe CTO）提出了一个反直觉观点：

- 很多人觉得 AI 时代最危险的是中层 manager，因为 agent 能直接执行任务。
- 但他反而更愿意招“做过 manager、现在想回去写代码的人”。
- 理由是：manager 更擅长拆解任务、分配资源、把握节奏、做过程管理。
- 而这些能力，恰恰是用好 coding agent 的关键。

一句话概括：**AI 可能不会先淘汰 manager，反而会抬高“会管理任务的人”的价值。**

---

#### 解读

##### 这个观点为什么有道理？

因为 AI 写代码，难点越来越不是“敲代码”，而是：

- 问题能不能拆清楚
- 目标能不能说明白
- 过程能不能持续校正
- 多个任务能不能协调推进

这些事，本质上都很像 manager 平时在做的事。

简单说：

- 程序员强在“自己下场解决”
- manager 强在“让系统把事做成”

而在 agent 时代，**你越像一个“指挥系统的人”，越容易放大 AI 的能力。**

##### 为什么这对很多纯 IC 很刺痛？

因为很多优秀工程师的直觉是：

> “这段我自己改更快。”

这在过去通常是对的。  
但在 agent 场景里，这种直觉可能变贵，因为：

- 你一旦频繁自己接管，agent 就学不到完整反馈
- 你会不断打断自动执行闭环
- 最后变成“AI 只是辅助补全”，而不是“AI 真正替你干活”

所以问题不是“你会不会写代码”，而是：

**你能不能忍住亲自上手，先把任务设计好、监督好、迭代好。**

##### 但这个观点也不是绝对正确

它成立，有一个前提：

- 这个 manager 不是只会开会、汇报、做 PPT
- 而是真的会拆任务、懂技术边界、能判断结果质量

如果只是“形式化管理者”，那在 AI 时代确实更危险。  
真正值钱的，不是 manager 头衔，而是 **任务编排能力**。

所以更准确地说，未来吃香的不是传统 manager，而是：

- 懂业务
- 懂工程
- 会拆解
- 会验收
- 会与 agent 协作的人

---

#### 我的意见

我认为这个判断 **大体是对的，但容易被说过头**。

##### 我赞同的部分

- AI 会削弱“纯执行型写代码”的稀缺性。
- 会放大“任务定义、流程控制、结果判断”的价值。
- 因此，具备管理思维的人，确实可能更容易成为高效的 agent 使用者。

##### 我保留的部分

- 不是“manager 更有优势”，而是“会管理复杂任务的人更有优势”。
- 很多顶级工程师其实也具备这种能力，只是以前没被当成核心竞争力。
- 真正的门槛不是管理经历，而是 **能否把模糊目标变成可执行系统**。

##### 最后一句判断

未来更值钱的人，可能不是“最会写代码的人”，也不是“最会管人的人”，而是：

**最会把人、AI、流程组织起来，把结果稳定做出来的人。**
