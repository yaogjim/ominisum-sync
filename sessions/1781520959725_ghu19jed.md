## 正文

**nazha**

\#分享 相比于 Loop， 还有一个词 “backpressure” 所传递的概念更为准确。至今 Agent 的基础都来自 ReAct，其本身隐含 Loop 的概念。

&gt; backpressure 最初是指流体在管道中流动时遇到的阻力。  
&gt; 在系统工程中，背压是一种下游组件向上游组件发出信号、表明无法继续接收更多工作的机制，迫使生产者放慢速度、缓冲或丢弃负载。

这反应的是目前大多数的 AI 编码流程中， 我们自己成为 Agent 的 backpressure ：人提前进入到 ReAct 的反馈循环，对 LLMs 的生成结果执行检查、手动验证，成为 Agent 在“流动”时遇到的阻力。

把人从这一循环中解脱出来。对于 AI 编程来说，就是用 Harness 来加固这一层：Agent 理清意图、约束、测试、主动 issue 探测和修复，交付给我们一个「直接」投入生产的版本。

## 通俗精炼（1）

### 2026-06-15 10:54:39

#### 文章总结：AI 编程中的“背压”问题

##### 核心观点

相比用 **Loop（循环）** 来描述当前 Agent 的工作方式，作者认为 **Backpressure（背压）** 更准确。

在 AI 编程流程中，人类开发者往往提前介入 Agent 的工作循环，不断检查、验证、修正 LLM 的输出。此时，人就变成了 Agent 工作流中的“阻力”。

---

##### 什么是 Backpressure？

**Backpressure** 原本来自流体力学，指管道中流体遇到阻力。

在系统工程中，它指的是：

> 下游系统处理不过来时，向上游发出信号，要求其放慢、缓存或丢弃任务。

也就是说，背压本质上是一种 **系统处理能力不足时的反馈机制**。

---

##### 对 AI Agent 的启发

当前大多数 AI Agent，尤其是 AI 编程 Agent，仍建立在 **ReAct 框架**之上：

- 推理
- 行动
- 观察反馈
- 再推理
- 再行动

这本质上是一个循环。

但问题是，很多时候人类提前进入这个循环：

- 检查代码是否正确
- 手动运行测试
- 判断是否符合需求
- 修复 Agent 没发现的问题

于是，人类不再只是使用者，而成为了 Agent 流程中的“背压”。

---

##### 真正的目标：把人从循环中解放出来

作者认为，AI 编程的关键方向不是让人持续监督 Agent，而是让 Agent 自己完成更多闭环工作。

具体来说，需要通过 **Harness（测试与约束框架）** 来加固流程，让 Agent 能够：

- 理解用户意图
- 明确约束条件
- 自动编写和运行测试
- 主动发现 issue
- 主动修复问题
- 最终交付可直接投入生产的版本

---

##### 一句话总结

当前 AI 编程的瓶颈，不只是 Agent 在循环中工作，而是人类成为了这个循环中的“背压”；未来的关键是通过更强的测试、约束和自动验证机制，让 Agent 独立完成从理解到交付的闭环。

## 结构化（1）

### 2026-06-15 11:11:53

##### 主旨概括

文章认为，相比用 “Loop（循环）” 描述 AI Agent 的工作方式，“backpressure（背压）” 更能准确表达当前 AI 编程流程中的核心问题：人类开发者正在成为 Agent 工作流中的阻力和反馈节点。作者提出，应通过更强的自动化验证与约束机制（Harness）把人从这个循环中解放出来。

##### 1. Agent 的基础来自 ReAct，天然包含循环机制

- 当前许多 Agent 的基础模式来自 **ReAct**。
- ReAct 本身隐含一种 **循环流程**：  
  Agent 思考 → 执行动作 → 观察结果 → 再继续思考和行动。
- 因此，人们常用 “Loop” 来描述 Agent 的运行方式。

##### 2. “backpressure” 比 “Loop” 更准确

- 作者认为，“Loop” 只强调循环过程，但不足以描述 AI 编程中的实际阻塞问题。
- “backpressure（背压）” 原本指流体在管道中流动时遇到的阻力。
- 在系统工程中，背压指的是：
  - 下游组件无法继续接收更多任务；
  - 于是向上游组件发出信号；
  - 迫使上游生产者放慢速度、缓存任务，甚至丢弃负载。

##### 3. 当前 AI 编程中，人类成了 Agent 的背压

- 在很多 AI 编码流程里，人类开发者会提前进入 Agent 的反馈循环。
- 开发者需要对 LLM 生成的代码进行：
  - 检查；
  - 手动验证；
  - 判断是否正确；
  - 发现问题并要求修改。
- 这意味着，Agent 的“流动”并不顺畅，人类成为了它继续推进时遇到的阻力。

##### 4. 解决方向：用 Harness 解放人类

- 作者提出，关键是把人从 ReAct 的反馈循环中解脱出来。
- 对 AI 编程来说，需要用 **Harness（测试与约束框架）** 加固这一层。
- Harness 应帮助 Agent 自动完成：
  - 理清用户意图；
  - 明确约束条件；
  - 编写和执行测试；
  - 主动探测 issue；
  - 自动修复问题。

##### 5. 最终目标：让 Agent 交付可直接上线的结果

- 理想状态下，Agent 不应只是生成一段需要人反复检查的代码。
- 它应该在完成自我验证和修复后，交付一个可以“直接”投入生产的版本。
- 也就是说，AI 编程的目标不是让人不断充当审核者，而是让系统自身具备足够的验证、约束和修复能力。
