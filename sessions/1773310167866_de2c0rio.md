### Day 5：自建本地反代，五分钟教你把多个 Claude 账号串起来

相信不少订阅 Claude Pro 的朋友都学会了要精打细算。 为什么？

因为 Claude Code 每五个小时有固定的 token 额度，一旦用完了，就得等到下一轮刷新后才能继续用。如果你不想要做任务一半被限额，你只能在脑子里计算额度与时间分配的问题，争取做到效率最大化。

不得不说，这是很讨厌的事情😔任务做到一半停了，思绪被迫中断。

这样的情况，我遇到过好几次。

![Image](https://pbs.twimg.com/media/HC7F3axWsAAcoVT?format=jpg&name=large)

在这期间，我也有想过去中转站买 API，但是因为担心数据泄露、以及服务跑路的问题，而花一两百刀去订阅max目前感觉又还不到时候，所以最终！

我决定自己寻找解决方案——于是，在花了一些时间寻找合适的开源项目并跑通了整个流程后，有了本章的教程。

本教程非常容易上手，不烧脑。

那么，让我们一起来看看吧！

#### 🧠 思路

我们需要在本地启动一个反代服务，把所有 Claude 账号接进去。而 Claude Code 之后的请求将会统一打到本地地址，由它来决定用哪个账号发出去。

整个过程中，你对官方来说还是正常的 OAuth 授权流量，请求行为没有异常，账号不在别人手里，数据全在本地 SQLite，不上云。

我用的这个工具叫 better-ccflare，GitHub 开源，专门针对 Claude Code 设计。当然，也支持一些别的 API，比如 OpenAI、OpenRouter、VertexAI 等。

Credit to：

[https://github.com/tombii/better-ccflare?tab=readme-ov-file](https://github.com/tombii/better-ccflare?tab=readme-ov-file)

#### 🛠️ 搭建步骤

（这里以 Mac - Apple Silicon 为例）

第一步 - 下载二进制

我们需要去 better-ccflare 的 GitHub Release 页面，下载对应平台的二进制文件。懒人版可以打开终端，复制粘贴下面命令即可（自动下载 + 授权 + 启动）：

```markdown
cd ~ && chmod +x better-ccflare-macos-arm64 && (xattr -d com.apple.quarantine better-ccflare-macos-arm64 || true) && BETTER_CCFLARE_HOST=127.0.0.1 ./better-ccflare-macos-arm64
```

第二步 - 启动进程

直接输入以下代码启动：

```markdown
BETTER_CCFLARE_HOST=127.0.0.1 ./better-ccflare-macos-arm64
```

运行后你会看到类似的代码，就说明你成功了：

```markdown
Server running on http://127.0.0.1:8080
Dashboard: http://127.0.0.1:8080/dashboard
```

如果觉得这样启动太麻烦，也可以让 CC 给你写一个比较简单的脚本，用来快速启动。脚本例子：

[Github链接](https://github.com/scratchy1234/day-100-materials/blob/main/day5/ccflare.sh)🔗

BTW，有地方不懂，亦或者卡住了，可以直接问 AI。

![Image](https://pbs.twimg.com/media/HC7DyCjXQAAtEYS?format=jpg&name=large)

第三步 - 添加 Claude 账号

浏览器打开 http://127.0.0.1:8080/dashboard，在 Account 标签页中点 Add Account，OAuth 直接授权账号就可以。

多个账号重复这一步就行，每个都会出现在列表里。

![Image](https://pbs.twimg.com/media/HC7EA_dbYAA1jCP?format=jpg&name=large)

此外，也推荐把 Auto Fallback 和 Auto Refresh 打开。前者的功能是自动切换可用账号，后者是自动刷新 OAuth 授权，避免授权失效。

第四步 - 改 Claude Code 的 Base URL

Claude Code 配置文件 settings.json 里把 apiBaseUrl 改成本地地址，改完之后所有请求就走代理了。类似这样👇

```json
{
 "env": {
 "ANTHROPIC_BASE_URL": "http://127.0.0.1:8080",
 "ANTHROPIC_DEFAULT_OPUS_MODEL": "claude-opus-4-6",
 "ANTHROPIC_DEFAULT_SONNET_MODEL": "claude-sonnet-4-6",
 "ANTHROPIC_DEFAULT_HAIKU_MODEL": "claude-haiku-4-5-20251001"
 }
}
```

第五步 - 生成 API Key（可选，建议做）

浏览器中进入 Dashboard，选择 API Keys 页面，Generate API Key，把生成的 key 填进 Claude Code 配置。

为什么要这一步：现在代理完全没门禁，只靠 127.0.0.1 的网络层隔离，有了 Key 之后所有请求必须带上才能过，两层加起来更稳。

127.0.0.1 是把大门焊死，API Key 是内部门禁卡。

具体流程不知道怎么做的，可以问一下 AI。

---

#### 🌞 配好之后

全部配置完后，Claude Code 照常用，感知不到区别，但是使用体验会更好一点，因为不用太在意限额的问题了。当一个账号被限流时，session 切换后自动用下一个，两个账号错峰，节奏也会比以前平滑很多。

![Image](https://pbs.twimg.com/media/HC7GG3cXwAAeYlD?format=jpg&name=large)

还有一点值得注意：不要频繁切换账号。

频繁切账号对 Anthropic 来说是异常行为，有风控风险，每一个聊天窗口（session）在一段时间内建议用同一个账号。

## 结构化（1）

### 2026-03-12 10:11:46

**主旨概括：**  
这篇文章介绍了一个**本地反代方案**：用开源工具**better-ccflare**把多个 Claude 账号接到同一个本地代理里，让 Claude Code 在某个账号额度用完时自动切换，减少被限额打断工作的情况。  
核心优势是：**账号和数据都留在本地，不依赖第三方中转站**，部署也比较简单，几分钟可跑通。

---

##### 一、为什么要这么做：解决 Claude Pro 的额度中断问题
- Claude Code **每 5 个小时有固定 token 额度**。  
- 一旦某个账号额度用完，就要等下一轮刷新，任务可能被迫中断。  
- 作者不想：
  - 一边做任务一边计算额度和时间；
  - 去买不放心的第三方 API 中转服务；
  - 直接花更多钱升级到更高档订阅。  
- 所以最后选择：**自己搭一个本地代理，把多个 Claude 账号串起来轮流用。**

**举例：**  
如果你有 2 个 Claude Pro 账号，当账号 A 限额后，代理可以自动切到账号 B，使用体验会比只用一个账号更平滑。

---

##### 二、整体思路：本地反代统一转发多个账号
- 在本地启动一个反代服务，Claude Code 之后的请求都先打到本地地址。  
- 再由这个代理决定：**当前请求该走哪个 Claude 账号**。  
- 对官方来说，仍然是**正常的 OAuth 授权流量**，不是把账号托管给别人。  
- 数据存储在**本地 SQLite**，**不上云**。  

###### 使用的工具
- 工具名：**better-ccflare**
- 特点：
  - GitHub 开源；
  - 主要为**Claude Code**设计；
  - 也支持其他 API，例如：
    - OpenAI
    - OpenRouter
    - VertexAI

---

##### 三、具体搭建步骤：以 Mac（Apple Silicon）为例

###### 1）下载并启动二进制文件
- 作者提供的是**Mac - Apple Silicon**场景。  
- 可以直接在终端运行命令完成：
  - 下载 / 授权 / 启动（文中给的是一条懒人命令）；
  - 或手动运行：
```bash
BETTER_CCFLARE_HOST=127.0.0.1 ./better-ccflare-macos-arm64
```

###### 2）确认服务是否启动成功
- 成功后会看到类似提示：
```bash
Server running on http://127.0.0.1:8080
Dashboard: http://127.0.0.1:8080/dashboard
```
- 说明本地代理已经跑起来了。  
- 如果每次手动启动太麻烦，可以让 AI 帮你写个快速启动脚本。

---

##### 四、添加 Claude 账号：多个账号重复授权即可
- 打开浏览器进入：
  - `http://127.0.0.1:8080/dashboard`
- 在**Account**页面点击**Add Account**。  
- 通过**OAuth**授权 Claude 账号。  
- 如果有多个账号，就重复添加。  

###### 建议开启两个功能
- **Auto Fallback**：自动切换到可用账号。  
- **Auto Refresh**：自动刷新 OAuth 授权，避免失效。

**关键作用：**
- 某个账号限流或额度耗尽时，系统能更顺畅地切换到其他账号继续工作。

---

##### 五、修改 Claude Code 配置：让请求走本地代理
- 在 Claude Code 的`settings.json`里，把`apiBaseUrl`改为本地地址。  
- 文中实际给的是环境变量方式，示例为：
```json
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://127.0.0.1:8080",
    "ANTHROPIC_DEFAULT_OPUS_MODEL": "claude-opus-4-6",
    "ANTHROPIC_DEFAULT_SONNET_MODEL": "claude-sonnet-4-6",
    "ANTHROPIC_DEFAULT_HAIKU_MODEL": "claude-haiku-4-5-20251001"
  }
}
```

###### 配完后的效果
- Claude Code 表面上**用法不变**；  
- 但底层请求已经先走本地代理，再由代理决定使用哪个账号。

---

##### 六、可选但推荐：生成 API Key 增加一层保护
- 在 Dashboard 的**API Keys**页面点击**Generate API Key**。  
- 把生成的 Key 填回 Claude Code 配置中。  

###### 为什么建议做
- 仅靠`127.0.0.1`，主要是网络层隔离；  
- 加上 API Key 后，请求还必须带 Key 才能通过，安全性更高。  

###### 作者的类比
- `127.0.0.1`：像是把大门焊死；  
- API Key：像是内部门禁卡。  

---

##### 七、最终效果与注意事项
###### 效果
- 日常使用时，Claude Code 基本**感知不到区别**；  
- 但体验更稳定，因为：
  - 不必过度担心单账号限额；
  - 一个账号被限流后，可以切到下一个账号；
  - **两个账号错峰使用**，节奏更平滑。

###### 注意事项
- **不要频繁切换账号。**
- 因为对 Anthropic 来说，频繁切账号可能属于**异常行为**，有风控风险。  
- 建议：**同一个聊天窗口（session）在一段时间内尽量固定使用同一个账号。**

---

这篇文章的核心是在本地用**better-ccflare + 多个 Claude 账号 + Claude Code 配置改 Base URL**，做出一个**安全、低成本、可自动切换账号的本地代理方案**，重点解决**Claude Pro 每 5 小时额度限制带来的工作中断问题**。
