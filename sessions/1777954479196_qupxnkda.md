#### 为什么需要指纹浏览器

本框架不是传统的裸 HTTP 调用脚本，而是通过指纹浏览器维持一个更接近真人使用的浏览器环境：

1. 每个任务绑定一个独立的浏览器窗口、Cookie、LocalStorage、UA、代理和浏览器指纹。
2. 用户可以先在指纹浏览器中手动登录目标站点、完成必要验证或订阅准备。
3. 后端再通过指纹浏览器暴露的 CDP 地址连接到该窗口，在页面上下文中执行 `fetch` 、上传文件、轮询状态、读取结果。
4. 当遇到 Cloudflare/Turnstile 等挑战页时，执行器会检测页面、等待自动放行、尝试点击验证控件，必要时关闭并重开指纹窗口进行自愈。

#### 如何连接指纹浏览器

本项目当前以 RoxyBrowser 为主要适配对象，核心链路如下：

```
管理后台配置浏览器服务器
  -> FPBrowserClient 调 RoxyBrowser 本地/局域网 API
  -> 同步空间(workspaceId)、项目(projectIds)、窗口(dirId)
  -> 任务类型绑定具体窗口
  -> TaskService 根据任务类型和额度选择窗口
  -> PlaywrightBrowserContext 打开/复用窗口并连接 CDP
  -> 站点执行器在页面上下文中 fetch / 上传 / 轮询 / 读取结果
```

1. 下载并登录 RoxyBrowser： [https://roxybrowser.com?code=0416Z62A](https://roxybrowser.com?code=0416Z62A) 。
2. 在 RoxyBrowser 中创建空间（Workspace）、项目和浏览器窗口。
3. 为窗口配置代理、账号信息、目标站点登录态，并确保窗口可以正常访问目标站点。
4. 启用 RoxyBrowser 的本地 API / 局域网 API，并记录：
   - API 地址，例如 `http://127.0.0.1:xxxxx` 或局域网地址。
   - API token（如 RoxyBrowser 侧开启了 token 校验）。
   - `workspaceId` ：本项目中对应 `space_id` ，必须是纯数字。
   - `dirId` ：本项目中对应 `window_key` ，代表具体浏览器窗口。

在管理后台中按顺序配置：

1. **项目管理** ：创建一个本地项目。
2. **浏览器服务器** ：填写 RoxyBrowser API 地址：
   - `vendor` ： `roxy`
   - `lan_addr` ：RoxyBrowser API base URL
   - `access_key` ：RoxyBrowser token，可为空
3. **空间** ：填写 RoxyBrowser `workspaceId` ，可选填写 Roxy 项目 ID 过滤条件。
4. **同步窗口** ：后台会调用：
   - `GET /browser/list_v3` 获取窗口列表。
   - `GET /browser/detail` 获取窗口明细。
   - 提取 `dirId` 、窗口名称、平台账号、代理 IP、国家、内核版本等信息写入本地数据库。
5. **任务类型绑定窗口** ：创建任务类型并选择处理器，例如：
   - `sora_gen_video`
   - `veo_workflow`
   - `grok_workflow`
   - `dreamina_workflow`

##### 3\. 运行时连接过程

连接逻辑主要在以下文件中：

- `src/services/fp_browser_client.py` ：RoxyBrowser API 适配层。
- `src/services/playwright_broswer_context.py` ：通用 Playwright + 指纹浏览器上下文。
- `src/services/task_service.py` ：任务调度、窗口池、额度和并发控制。

运行时会先查询窗口是否已经打开：

1. 调用 RoxyBrowser `GET /browser/connection_info` 获取已打开窗口的 `http/ws` 调试地址。
2. 若窗口未打开，则调用 `POST /browser/open` ，传入 `workspaceId` 、 `dirId` 、启动参数、headless/pure\_mode 等。
3. RoxyBrowser 返回 `data.http` 或 `data.ws` 后，框架会规范化为 CDP endpoint。
4. 使用 `playwright.chromium.connect_over_cdp(endpoint)` 连接到真实指纹浏览器窗口。
5. 执行器选择可用页面或打开目标页面，并通过页面上下文执行 `fetch` 、文件上传、Cookie/Token 读取等操作。
6. 任务完成后通常只断开本地 Playwright/CDP 连接，不立即关闭指纹窗口，以便保留登录态并降低频繁开关窗口带来的风控风险。

#### 核心服务一：src/services/sora\_task\_executor.py

`sora_task_executor.py` 是 Sora 站点侧执行器，入口函数是 `sora_gen_video` ，由 `task_service.py` 根据任务类型分发调用。

##### 职责边界

- 不负责管理 RoxyBrowser API 细节，这部分由 `fp_browser_client.py` 和 `playwright_broswer_context.py` 处理。
- 专注 Sora 站点逻辑：鉴权抓取、任务创建、进度轮询、草稿发布、余额检查、邀请码读取、角色创建等。

##### 关键能力

- **窗口级会话缓存** ： `SoraSession` 按 `vendor + base_url + space_id + window_key` 缓存，复用同一个指纹窗口和 CDP 连接。
- **登录态/Token 获取** ：在指纹窗口页面上下文中访问 `/api/auth/session` ，读取 `accessToken` 和过期时间。
- **页面内接口调用** ：使用页面上下文 `fetch` 调 Sora 后端接口，继承窗口 Cookie、UA、代理和指纹。
- **生成任务提交** ：调用 `/backend/nf/create` 创建视频生成任务，支持 prompt、首帧图、比例/方向、时长帧数等参数。
- **进度轮询** ：轮询 pending / drafts 等接口，持续回写任务进度。
- **草稿发布与结果提取** ：任务完成后从 drafts 中找到对应生成结果，发布并返回 `share_url` 、 `watermark_free_url` 、 `thumb_url` 等。
- **角色创建** ：支持通过 `video_url` 或 `generation_id + head_url` 创建 Sora 角色，包含上传、状态轮询、头像处理、finalize、公开设置等步骤。
- **额度/会员辅助** ：支持 `nf_check` 、订阅信息、邀请码、清空 drafts 等管理端操作。
- **Cloudflare 自愈** ：检测 “Just a moment”、 `/cdn-cgi/` 、Turnstile 等页面特征，等待放行、尝试 checkbox 点击，必要时重启指纹窗口。
- **并发保护** ：创建任务使用会话级锁串行化，避免同一窗口同时提交多个创建请求；不同窗口可并发工作。

#### 核心服务二：src/services/veo\_workflow\_executor.py

`veo_workflow_executor.py` 是 VEO / Google Labs / Flow 工作流执行器，入口函数是 `veo_workflow` ，同样由 `task_service.py` 分发调用。

##### 职责边界

- 使用通用指纹浏览器上下文打开或复用 Google Labs / Flow 页面。
- 在页面上下文中执行 Flow / aisandbox / media API 请求。
- 管理项目 ID、access token、reCAPTCHA token、图片上传、视频轮询、图片放大等 VEO 相关逻辑。

##### 关键能力

- **VeoSession 会话缓存** ：按窗口缓存，减少重复打开浏览器和重复登录。
- **Google 登录辅助** ：管理端提供打开/连接窗口能力，可在 Google 登录页中辅助选择账号、输入凭据、进入 Flow。

- **Flow 项目管理** ：支持从 payload 指定 `veo_project_id/project_id/current_project_id` ，也支持从 `veo_url` 解析，或从绑定窗口的 `veo_flow_projects` 随机选择项目。
- **VEO 视频生成** ：
  - T2V：文生视频。
  - I2V：首帧/首尾帧图生视频。
  - R2V / Ingredients：多图参考生成视频，最多按执行器逻辑处理多张参考图。
  - 支持横版/竖版模型、会员档位模型修正、任务提交重试与状态轮询。
- **AI 图片生成** ：当 `n_frames` 显式为 `1` 时进入图片模式，支持文生图、图生图、多图参考图生图；默认 NARWHAL，也支持 GEM\_PIX\_2 / Banana 类图片模型路径。

- **Cloudflare 自愈** ：与 Sora 类似，具备挑战页检测、等待、点击、重启窗口和恢复目标页能力。

#### 任务类型与窗口池

- 任务类型配置决定一个任务由哪个执行器处理，例如 `sora_gen_video` 、 `veo_workflow` 、 `grok_workflow` 、 `dreamina_workflow` 。
- 一个任务类型可以绑定多个指纹浏览器窗口，实现多账号、多代理、多窗口并发。
- `TaskService` 会根据窗口启用状态、剩余额度、冷却时间、错误次数和并发槽位选择合适窗口。
- 窗口池可以预先打开并维护目标页面，减少任务启动耗时；巡检逻辑会周期性检测 Cloudflare/登录态等异常。
- 管理端支持手动打开、保持打开、重启窗口、刷新 access token、刷新额度、清缓存、创建 VEO Flow 项目等操作。

#### 二、深入浅出解读

##### 1. 它解决的是什么问题？

普通自动化脚本通常直接请求网站接口，比如：

```text
脚本 → 网站接口
```

但很多 AI 平台有：

- 登录态校验
- Cookie 校验
- 浏览器环境检测
- 风控系统
- 验证页
- 额度限制
- Token 过期

所以直接 HTTP 请求很容易失败。

这个项目换了一种方式：

```text
真实浏览器登录 → 保留 Cookie / 指纹 / 代理 → 程序连接浏览器 → 在网页里发请求
```

简单理解就是：

> 不是 “伪装成浏览器”，而是 “真的控制一个浏览器”。

---

##### 2. 什么是指纹浏览器？

指纹浏览器可以给每个窗口配置独立环境，例如：

- Cookie
- LocalStorage
- User-Agent
- 代理 IP
- 时区
- 浏览器指纹
- 登录账号

这样每个窗口看起来像不同的真实用户设备。

项目推荐使用**RoxyBrowser**，用户先在里面手动登录目标网站，然后这个框架再接管浏览器窗口执行任务。

##### 3. 它的核心架构

```text
用户 / API

任务系统 TaskService

指纹浏览器窗口池
   ↓
各平台执行器：Sora / VEO / Grok / Dreamina
```

#### FPBrowser2API 项目总结：指纹浏览器驱动的 AI 生成自动化框架

##### 1. 项目定位

**FPBrowser2API**是一个基于 “指纹浏览器 + 页面上下文执行” 的半自动化框架，用于研究 AI 视频、AI 图片生成网站的自动化调用流程。

它不是传统的直接 HTTP API 脚本，而是通过真实浏览器环境模拟真人操作，再在页面内部执行请求、上传文件、轮询任务和读取结果。

当前重点适配方向包括：

- **Sora**
- **VEO / Google Flow / Google Labs**
- **Grok Imagine**
- **Banana / GEM_PIX_2 图片生成**
- **Dreamina / 即梦国际站 / Seedance2.0**

项目声明仅供技术研究、学习验证和私有测试环境使用，不建议用于商业化、批量滥用或违反平台规则的场景。

---

##### 2. 核心思路

###### 用指纹浏览器模拟真实用户环境

项目依赖指纹浏览器来维护更接近真人访问的环境，包括：

- 独立浏览器窗口
- Cookie、LocalStorage
- UA、代理、浏览器指纹
- 已登录账号状态
- 目标站点访问上下文

用户可以先在指纹浏览器中手动完成登录、验证、订阅等准备，后端再通过 CDP 连接该窗口，复用真实会话完成自动化任务。

###### 在页面上下文中执行请求

框架连接浏览器后，会在网页内部执行`fetch`、上传、轮询等操作。

这样可以继承页面已有的：

- 登录态
- Cookie
- Token
- 浏览器指纹
- 代理网络环境

本质上是把 “浏览器里的人类会话” 包装成后端可调度的任务接口。

---

##### 3. 系统架构

###### 指纹浏览器层

当前主要适配**RoxyBrowser**。

核心流程是：

1. 在 RoxyBrowser 创建空间、项目和浏览器窗口  
2. 配置代理、账号、目标站点登录态  
3. 后台同步窗口信息  
4. 任务类型绑定具体窗口  
5. 任务调度服务选择可用窗口  
6. Playwright 通过 CDP 连接真实浏览器  
7. 执行器在页面上下文中完成具体任务

###### 后端调度层

核心模块包括：

- `fp_browser_client.py`：适配 RoxyBrowser API
- `playwright_broswer_context.py`：Playwright/CDP 浏览器上下文
- `task_service.py`：任务队列、窗口池、并发与额度调度
- `sora_task_executor.py`：Sora 执行器
- `veo_workflow_executor.py`：VEO / Flow 执行器
- `grok_workflow_executor.py`：Grok 执行器
- `jimeng_task_executor.py`：Dreamina / Seedance 研究方向

---

##### 4. 任务与窗口池机制

###### 任务类型

系统通过任务类型决定使用哪个执行器，例如：

- `sora_gen_video`
- `veo_workflow`
- `grok_workflow`
- `dreamina_workflow`

每种任务类型可以绑定多个指纹浏览器窗口，从而支持多账号、多代理、多窗口并发。

###### 窗口调度

`TaskService`会根据以下因素选择合适窗口：

- 是否启用
- 是否有剩余额度
- 冷却时间
- 错误次数
- 并发槽位
- 登录态是否正常

窗口可预先打开并保持目标页面，减少任务启动延迟。

---

##### 5. Sora 执行器能力

`sora_task_executor.py`主要负责 Sora 相关自动化逻辑。

###### 主要能力

- 获取登录态和 accessToken
- 创建视频生成任务
- 支持 prompt、首帧图、比例、时长等参数
- 轮询生成进度
- 从 drafts 中提取生成结果
- 发布草稿并返回结果链接
- 创建 Sora 角色
- 查询额度、订阅、邀请码
- 清理 drafts
- 检测并处理 Cloudflare / Turnstile 挑战页

###### 产品视角理解

它把 Sora 网页端能力抽象成了一个后端 API，可以让外部系统以任务形式提交生成需求，并自动完成等待、发布、结果提取。

---

##### 6. VEO / Google Flow 执行器能力

`veo_workflow_executor.py`面向 Google Labs / Flow / VEO 工作流。

###### 视频生成能力

支持多种模式：

- 文生视频 T2V
- 图生视频 I2V
- 首尾帧生成
- 多图参考 Ingredients / R2V
- 横版、竖版模型
- 生成状态轮询
- 任务失败重试

###### 图片生成能力

当`n_frames = 1`时进入图片模式，支持：

- 文生图
- 图生图
- 多图参考图生图
- Banana / GEM_PIX_2 类图片模型
- 2K 放大
- OSS 存储大图结果

###### 辅助能力

还包括：

- Google 登录辅助
- Access Token 获取与缓存
- Flow 项目管理
- 额度刷新
- Cloudflare 挑战页检测与恢复

---

##### 7. 管理后台与 API

项目提供管理后台，用于配置和运维：

- 系统配置
- 项目管理
- 任务类型管理
- 任务列表
- 测试页面
- 请求日志
- 用户管理
- 浏览器窗口同步与管理

对外 API 使用 Bearer Token 鉴权，支持：

- 获取任务类型
- 创建任务
- 查询任务状态
- 指定窗口执行任务

从产品形态看，它更像是一个 “AI 生成任务中台”，把多个网页端 AI 工具统一封装为异步任务接口。

---

##### 8. 项目价值

###### 技术价值

该项目展示了一种通用的自动化研究范式：

> 指纹浏览器真人环境 + 页面上下文请求 + 窗口池调度 + 执行器插件化

这种方式理论上可扩展到更多复杂网站，尤其是没有公开 API、但网页端能力较完整的产品。

###### 产品价值

如果放在合规测试环境中，它可以用于：

- 多账号任务调度研究
- AI 生成链路自动化验证
- 视频 / 图片生成工作流封装
- 前端站点接口逆向分析
- 浏览器自动化稳定性研究

###### 风险与限制

项目明确不保证稳定性，也不承诺绕过第三方风控的成功率。

实际效果高度依赖：

- 账号质量
- 代理质量
- 浏览器环境
- 目标站点策略
- 平台风控变化
- 合规边界

---

##### 9. 一句话总结

**FPBrowser2API 是一个将指纹浏览器中的真实登录会话封装成后端任务 API 的自动化研究框架，重点用于 Sora、VEO、Grok、Seedance 等 AI 生成网站的任务提交、状态轮询和结果提取，但应严格限定在授权、研究和私有测试场景中使用。**
