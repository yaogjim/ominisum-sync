#### 1\. 项目概述

CASR GUI 是一个桌面应用，用于在不同 AI 编码代理之间浏览、查看并转换会话。

项目基于 `casr` 核心库，提供了图形化能力：

- 可视化 Provider 检测
- 会话列表浏览
- 单会话内容预览
- 一键跨 Provider 转换
- 一键复制恢复命令和对话 ID

当前支持 14 个 Provider：

- Claude Code
- Codex (OpenAI)
- Gemini
- Cursor
- Cline
- Aider
- Amp
- OpenCode
- ChatGPT
- ClawdBot
- Vibe
- Factory
- OpenClaw
- Pi Agent

#### 2\. 技术栈

- 前端：React 19 + TypeScript + Tailwind CSS + Vite
- 桌面框架：Tauri v2
- 后端：Rust（ `src-tauri/` ）
- 核心转换逻辑：本地 `casr` 依赖（`../../session-resumer` ）

#### 3\. 目录结构

```
casr-gui/
  src/                        # React 前端
    App.tsx
    components/
      ProviderSidebar.tsx
      SessionList.tsx
      SessionDetail.tsx
    hooks/
      useTauri.ts             # Tauri invoke 封装
    types/
      index.ts

  src-tauri/                  # Rust 后端
    src/
      main.rs
      lib.rs
      commands/
        providers.rs          # get_providers
        sessions.rs           # list_sessions + get_session
        convert.rs            # convert_session
    tauri.conf.json
```

#### 4\. 环境要求

- Node.js 18+
- Rust 稳定版工具链
- 对应操作系统下的 Tauri 运行依赖
- Windows 建议安装 WebView2 Runtime（多数系统默认已具备）

#### 5\. 本地开发

安装依赖：

```
npm install
```

启动开发模式：

```
npm run tauri dev
```

执行过程：

- Vite 启动在 `http://localhost:1420`
- Tauri 启动桌面壳并连接 Vite
- `src-tauri/` 变更会触发 Rust 端热重建

#### 6\. 生产构建

执行：

```
npm run tauri build
```

产物目录：

- `src-tauri/target/release/bundle/`

#### 7\. 使用流程

1. 启动应用
2. 在左侧选择 Provider
3. 在中间列表选择会话
4. 在右侧查看会话元信息和消息预览
5. 选择目标 Provider 并点击 `Convert`
6. 复制 `resume command` 到目标代理继续会话
7. 如需记录会话标识，可点击 `Copy ID`

前端通过 Tauri 调用以下命令：

##### get\_providers

- 请求：无参数
- 返回： `ProviderInfo[]`

##### list\_sessions

- 请求参数：
  - `provider?: string`
  - `limit?: number`
  - `sort?: "date" | "messages" | "provider"`
- 返回： `SessionSummary[]`

##### get\_session

- 前端 payload 键：
  - `sessionId: string`
  - `sourceHint?: string`
- Rust 侧命令签名：
  - `session_id: String`
  - `source_hint: Option<String>`
- 返回： `SessionDetail`

##### convert\_session

- 前端 payload 键：
  - `target: string`
  - `sessionId: string`
  - `force?: boolean`
  - `enrich?: boolean`
- 返回： `ConvertResult`

#### 10\. 前端类型模型

定义位置： `src/types/index.ts`

- `ProviderInfo`
- `SessionSummary`
- `SessionDetail`
- `MessagePreview`
- `ConvertResult`

当你修改后端返回结构时，应同步更新该文件并验证前端调用。

#### 11\. 性能设计与优化

近期已落地的优化：

- 稳定化 invoke 方法引用：
  - `useTauri` 使用 `useCallback` + `useMemo` ，避免 effect 依赖误触发循环请求
- 会话列表缓存：
  - 按 `provider|limit|sort` 作为 key 做内存缓存
  - TTL：60 秒
  - 最大条目数：24
- 后端扫描保护：
  - fallback 目录扫描使用 `max_depth(4)` ，避免深层目录拖垮性能
- 预览截断安全：
  - 消息预览按字符截断，避免 UTF-8 中文字符边界 panic

#### 12\. 常见问题排查

排查建议：

- 是否出现会话重复加载循环（旧版本常见）
- 是否目录规模过大导致扫描成本高
- 是否同时启动了多个 `tauri dev`

处理建议：

- 仅保留一个开发进程
- 使用当前已包含缓存与扫描深度限制的版本
- 重启应用后复测

原因：

- 前端 invoke 参数名与 Tauri 期望不一致

处理：

- 使用 `sessionId` / `sourceHint` 作为前端 payload 键名

原因：

- 使用字节切片截断 UTF-8 字符串（中文、emoji 会触发）

处理：

- 使用 `.chars().take(n)` 截断而非 `[..n]`

建议检查：

- 是否选对 Provider
- 源会话文件是否仍存在
- Provider 的会话目录是否可访问

#### 13\. 安全与隐私说明

- 本工具读取本地 Provider 会话目录中的数据。
- 查看和转换本身不强制上传云端。
- 转换结果可能包含消息历史和上下文增强内容（视转换参数而定）。

#### 14\. 贡献建议（简版）

推荐流程：

3. 提交 PR，说明：
   - 行为变化
   - UI 变更截图
   - 协议或数据结构改动说明

- **1. 项目定位与核心能力**
  - `CASR GUI` 是一个桌面应用，用来在不同 AI 编码代理之间浏览、查看、转换会话。
  - 它基于 `casr` 核心库，重点提供图形化操作，包括：
    - 可视化识别 Provider
    - 浏览会话列表
    - 预览单个会话内容
    - 一键转换到其他 Provider
    - 一键复制恢复命令和对话 ID
  - 当前支持 `14 个 Provider`，包括：Claude Code、Codex、Gemini、Cursor、Cline、Aider、ChatGPT 等。

- **2. 技术方案与目录结构**
  - 前端使用 `React 19 + TypeScript + Tailwind CSS + Vite`，桌面框架是 `Tauri v2`，后端使用 `Rust`。
  - 核心转换逻辑依赖本地 `casr` 库（`../../session-resumer`）。
  - 项目结构分工明确：
    - `src/` 放 React 前端
    - `src-tauri/` 放 Rust 后端
    - 前后端通过 Tauri 命令通信
  - 例如：
    - `providers.rs` 负责获取 Provider
    - `sessions.rs` 负责列出会话、获取会话详情
    - `convert.rs` 负责执行会话转换

- **3. 环境要求与开发/构建方式**
  - 开发环境要求较直接：
    - `Node.js 18+`
    - Rust 稳定版工具链
    - Tauri 对应系统依赖
    - Windows 建议安装 `WebView2 Runtime`
  - 本地开发命令：
    - `npm install`
    - `npm run tauri dev`
  - 开发时会发生：
    - Vite 启动在 `http://localhost:1420`
    - Tauri 启动桌面壳并连接前端
    - Rust 代码变更会触发热重建
  - 生产构建命令是 `npm run tauri build`，产物在 `src-tauri/target/release/bundle/`。

- **4. 实际使用流程**
  - 使用路径是一个标准的“三栏式操作”：
    - 启动应用
    - 左侧选 Provider
    - 中间选会话
    - 右侧看元信息和消息预览
    - 选择目标 Provider 后点击 `Convert`
    - 再复制 `resume command` 去目标代理继续会话
  - 如果只想记录会话标识，还可以点击 `Copy ID`。
  - 文中还提到已有产品界面截图，展示了“全局总览、会话详情、转换结果”三类界面。

- **5. 前后端接口与类型约束**
  - 前端通过 Tauri 调用 4 个核心命令：
    - `get_providers`
    - `list_sessions`
    - `get_session`
    - `convert_session`
  - 这些接口分别返回：
    - `ProviderInfo[]`
    - `SessionSummary[]`
    - `SessionDetail`
    - `ConvertResult`
  - 重要细节是：前端 payload 的键名必须和约定一致。
    - 例如 `get_session` 要用 `sessionId`、`sourceHint`
    - `convert_session` 要用 `target`、`sessionId`
  - 前端类型统一定义在 `src/types/index.ts`；如果后端返回结构改了，前端类型也必须同步更新，否则容易出错。

- **6. 性能优化与常见问题**
  - 文档列出了几项已经落地的优化，说明项目重点关注“请求稳定性”和“目录扫描性能”：
    - `useTauri` 用 `useCallback + useMemo` 稳定 invoke 引用，避免 effect 误触发导致循环请求
    - 会话列表做了内存缓存，缓存 key 为 `provider|limit|sort`
    - `TTL = 60 秒`
    - 最大缓存条目数为 `24`
    - 后端目录扫描限制 `max_depth(4)`，避免深层目录拖慢性能
    - 消息预览按字符截断，防止 UTF-8 中文边界导致 panic
  - 常见问题也给出了明确原因和处理方式，例如：
    - **会话重复加载循环**：通常是旧版本问题，建议只保留一个 `tauri dev` 进程，并使用带缓存和扫描限制的版本
    - **前后端参数不一致**：前端要使用 `sessionId / sourceHint`
    - **中文或 emoji 截断报错**：不能用字节切片 `[..n]`，要用 `.chars().take(n)`
    - **看不到会话**：检查 Provider 是否选对、源文件是否存在、目录是否可访问

- **7. 安全、贡献与许可证**
  - 工具读取的是本地 Provider 会话目录数据，查看和转换过程本身**不强制上传云端**。
  - 但转换结果可能会包含消息历史和上下文增强内容，这点需要用户自行留意。
  - 贡献建议很简洁：
    - 新建分支
    - 本地验证 `npm run build`、`cargo check`
    - 提交 PR 时说明行为变化、UI 截图、协议或数据结构改动
  - 项目许可证是 `MIT`。
