## 正文

**Barret李靖**

Claude Code 的核心是一个 while 循环：模型生成响应 → 如果包含工具调用，执行 → 结果返回 → 模型生成下一个响应 → 持续循环。

就这么一个循环，被工程化成一个完整的产品，写了将近 30 多万行代码。

从整体代码设计来看，可以认为，Claude Code = 模型 + Harness，而 Harness = 工具系统 × 上下文工程 × 自主循环。

其中，工具系统和上下文工程做了大量的设计。

CC 的工具系统有着自己的标准化设计，它会明确约束模型不要执行 find、grep、cat、head 通用操作，而是走 GrepTool、GlobTool 等专用工具，因为这些内建工具会输出可审计、结构化的日志，让操作更加透明可控。

同时，工具本身也带有权限级别和验证逻辑。例如 Edit 工具为了避免交叉覆盖，会要求先 Read；Git 工具对 push force 类高风险操作会做 prompt 约束和 UI 警告。

类似的设计很多，目的是在工具层建立清晰的边界和反馈机制，让模型在调用时有约束、有校验，减少越界操作和错误扩散。

而在上下文管理上，CC 的管控也无所不用其极。它通过多种压缩策略和动态机制，确保模型在任何时刻只接触当前任务最相关的信息。

压缩策略的核心机制包括 MicroCompact、AutoCompact，以及不同触发条件下的会话压缩、记忆替换和裁剪策略。

在文件加载机制上，针对工具定义与能力暴露，也设计了 Just-In-Time 策略，文件不预加载，只保留路径，需要时再通过工具读取。

此外，还有 Sub-Agent 的设计，它通过上下文隔离的方式，让不同子任务的相关信息互不干扰，进一步降低了主循环的认知负载，确保主循环逻辑干净且稳定。

Claude Code 不仅是在工具系统和上下文管理上做文章，模型为了 Harness 效果更好，也开始配合对 Agentic 行为做专项优化。

例如 Opus 4.7 在指令遵循上就明确提到 "Opus 4.7 takes the instructions literally"，这对 Agent 来说非常关键。Agent 的行为边界往往写在 system prompt 里，模型层做了增强学习后，模型在指令遵守方面会表现更出色，这对 Agent 的稳定性和可靠性会有极大提升。

OpenClaw/Hermes Agent/Claude Code 产生了大量 Agent 调用数据，这些数据也会继续反哺模型能力的迭代。

从当前发展趋势可以推断，未来模型的进化，一定也会逐步内化工具调用策略、上下文压缩策略，甚至学会自我约束行为边界。

那么，今天 CC 里写的这些 Harness 逻辑，注定也会被模型吃掉。也就是说，Harness 也是一个过渡性的产物。🐶

## 通俗精炼（1）

#### Claude Code 的本质：一个被工程化到极致的 Agent 循环

##### 核心观点

Claude Code 的底层逻辑并不神秘，本质上是一个简单的 `while` 循环：

> 模型生成响应 → 如果有工具调用就执行 → 工具结果返回给模型 → 模型继续生成下一步 → 不断循环

但真正的价值在于：这个简单循环被工程化成了一个完整产品，背后包含大量工具设计、上下文管理和安全约束。

---

##### Claude Code = 模型 + Harness

作者认为，Claude Code 可以拆成两部分：

- **模型**：负责理解、推理、生成代码与决策
- **Harness**：负责把模型组织成可执行、可控、可靠的 Agent 系统

其中 Harness 又可以理解为：

> Harness = 工具系统 × 上下文工程 × 自主循环

也就是说，Claude Code 的强大不只是模型强，而是围绕模型搭建了一整套执行框架。

---

##### 工具系统：让模型“可控地干活”

Claude Code 不鼓励模型直接使用 `find`、`grep`、`cat` 等通用命令，而是要求使用专门设计的工具，例如：

- `GrepTool`
- `GlobTool`
- `Edit`
- `Read`
- Git 相关工具

这样做的原因是：专用工具可以输出结构化、可审计的日志，让模型行为更透明、更可控。

同时，工具本身也有权限和校验机制：

- `Edit` 前必须先 `Read`，避免覆盖错误
- Git 高风险操作如 `force push` 会触发提示和警告
- 不同工具有不同安全边界

本质上，这是在给 AI Agent 加“护栏”，减少误操作和风险扩散。

---

##### 上下文工程：让模型只看该看的信息

Claude Code 在上下文管理上投入很大，目标是：

> 让模型在任何时刻只接触当前任务最相关的信息。

它使用了多种机制：

- **MicroCompact**：小粒度压缩上下文
- **AutoCompact**：自动压缩会话内容
- **记忆替换与裁剪**：避免无关信息占用窗口
- **Just-In-Time 文件加载**：文件不提前全部加载，只保留路径，需要时再读取
- **Sub-Agent 上下文隔离**：不同子任务互不干扰

这些设计降低了主循环的认知负担，让 Agent 更稳定。

---

##### 模型也在适配 Agent 化趋势

作者提到，模型本身也在变得更适合 Agent 场景。

例如 Opus 4.7 强调更严格地遵循指令，这对 Agent 非常重要。因为 Agent 的行为边界通常写在 system prompt 里，模型越能遵守指令，系统就越稳定、越可靠。

同时，Claude Code、OpenClaw、Hermes Agent 等产品产生的大量 Agent 调用数据，也会反过来训练模型，让模型更懂如何调用工具、压缩上下文和控制行为边界。

---

##### 未来判断：Harness 终将被模型“吃掉”

当前 Claude Code 中大量 Harness 逻辑，包括：

- 工具调用策略
- 上下文压缩策略
- 权限约束机制
- 行为边界控制

未来可能会逐步被模型能力内化。

也就是说，今天需要工程系统显式实现的 Agent 框架，未来可能变成模型自身能力的一部分。

因此，Harness 是一个重要但过渡性的产物。

---

##### 一句话总结

Claude Code 的底层只是一个“模型 + 工具调用”的循环，但真正厉害的是它围绕这个循环构建了强大的工具系统、上下文管理和安全护栏；未来这些工程化能力可能会被模型逐步内化。

##### 1. Claude Code 的核心：一个被工程化的 while 循环

原文认为，Claude Code 的基础逻辑可以简化为：

> 模型生成响应 → 如果包含工具调用就执行 → 工具结果返回给模型 → 模型继续生成下一个响应 → 不断循环

这个循环本身很简单，但 Claude Code 将其工程化成了完整产品。

可以概括为：

```text
Claude Code = 模型 + Harness
Harness = 工具系统 × 上下文工程 × 自主循环
```

其中，“Harness”可以理解为包裹在模型外部的一套执行框架，负责让模型更安全、更稳定、更可控地完成任务。

---

##### 2. 工具系统：用专用工具约束模型行为

Claude Code 并不鼓励模型随意执行通用命令，比如：

- `find`
- `grep`
- `cat`
- `head`

而是要求模型使用专门设计的工具，例如：

- `GrepTool`
- `GlobTool`

这样做的原因是：内建工具可以输出**可审计、结构化的日志**，让模型的操作过程更加透明，也更容易被系统监控和约束。

###### 关键设计

- 工具有标准化接口；
- 工具调用过程可记录、可追踪；
- 工具权限有分级；
- 高风险操作会触发验证或警告。

例如：

- `Edit` 工具为了避免覆盖冲突，会要求模型先执行 `Read`；
- Git 工具面对 `push force` 等高风险操作时，会通过 prompt 约束和 UI 警告提醒用户。

这些设计的目的，是在工具层建立清晰边界，减少模型越权操作和错误扩散。

---

##### 3. 上下文管理：只让模型看到最相关的信息

Claude Code 在上下文管理上也做了大量优化，目标是让模型在任意时刻只接触当前任务最相关的信息，避免信息过载。

原文提到的压缩与管理机制包括：

- `MicroCompact`
- `AutoCompact`
- 会话压缩
- 记忆替换
- 上下文裁剪

这些机制会根据不同触发条件动态调整上下文内容。

###### 文件加载采用 Just-In-Time 策略

Claude Code 不会一开始就预加载所有文件，而是：

- 只保留文件路径；
- 需要时再通过工具读取文件内容。

这类似“用到再打开”，可以减少无关信息进入模型上下文，提高效率和准确性。

---

##### 4. Sub-Agent：通过上下文隔离降低干扰

Claude Code 还设计了 `Sub-Agent` 机制。

它的作用是将不同子任务的上下文隔离开，让各个任务相关信息互不干扰。

这样可以：

- 降低主循环的认知负担；
- 避免不同任务信息混杂；
- 保持主循环逻辑更干净、更稳定。

简单说，主 Agent 负责调度，Sub-Agent 负责处理具体子任务，各自维护自己的上下文。

---

##### 5. 模型本身也在适配 Agent 行为

文章指出，Claude Code 不只是依赖外部 Harness，模型本身也在朝 Agent 场景优化。

例如，`Opus 4.7` 在指令遵循方面强调：

> “Opus 4.7 takes the instructions literally”

也就是说，它会更严格地按照指令执行。

这对 Agent 很重要，因为 Agent 的行为边界通常写在 system prompt 中。如果模型更擅长遵守指令，就能显著提升 Agent 的稳定性和可靠性。

##### 6. Agent 调用数据会继续反哺模型

原文提到，类似以下产品或系统会产生大量 Agent 调用数据：

- OpenClaw

- Claude Code

- 工具调用策略；

- 自我约束行为边界。

也就是说，今天写在 Claude Code 外部工程系统里的逻辑，未来可能会被模型自身学会。
