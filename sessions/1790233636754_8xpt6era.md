## 正文

**Jaya Gupta**

如果市场将 DeepSeek 视为对前沿实验室的严重威胁，那么他们应该更加重视 Jev（以及类似 Jev 的模型）。原因如下：

1\. 它为每一位开发者而构建，而不仅仅是机器学习团队。

迄今为止，降低模型成本意味着使用开放权重模型：选择基础模型、托管、微调、评估和重新训练。这是机器学习团队的工作，而大多数公司并没有这样的团队。Jev 是一个 API——第一天就能使用，无需 GPU，无需训练。

2\. 它如此便宜，以至于每个人都在尝试，而每个人突然都发现了其中的浪费。

每次决策的成本仅为几分之一美分，没有理由不去测试它。任何人都可以将 API 密钥粘贴到 Claude 或 ChatGPT 中，让它寻找节省成本的机会，包括非技术人员（许多人才团队已经在这样做了）。好奇心正在转化为发现：公司看到了自己一直在为“是或否”的答案支付旗舰级价格。以前从不关心推理成本的团队现在开始关心了，包括非科技公司。

3\. 它触及前沿收入公式的每一项。

前沿收入等于（调用次数）×（每次调用的 token 数）×（每 token 价格）。决策/Jev 模型对这三者都构成压力。

a.) 更少的调用次数。 前沿估值假设实验室将捕获智能体热潮：数百万个智能体产生数十亿次调用。但大多数智能体步骤都是决策：选择哪个工具、是否完成/安全/升级/分类/标记/路由。简单的生成任务转向更便宜和开源的模型。重试、浪费的步骤和升级都消失了！

b.) 更少的调用。 路由器会剥离过时的上下文和不需要的工具，因此仍然到达前沿的调用成本更低。

c.) 更便宜的调用。 一旦路由器并排展示每项任务的成本，旗舰级定价在常规工作上就站不住脚了。

4\. 它把路由器置于每个 AI 产品的前面以及内部。

路由器以前就存在，但难以构建且不可靠。决策模型同时解决了这两个问题。它们是理想的路由器：快速、几乎免费，并且会报告自己的置信度，因此路由器知道何时该升级。路由器如今正成为开发者已在使用的工具中的一项内置设置，因此公司无需构建任何东西就能获得一个。

如今，前沿模型负责运行智能体：它决定下一步做什么并调用工具。有了决策模型，普通代码和廉价决策负责运行循环，而前沿模型则成为软件在需要重度推理时调用的一个函数

5.) 实验室拥有的每一种防御都会加速这一进程。 降价证实了客户此前支付了过高费用。推出自己的路由器教会了客户如何路由，并且让他们更容易路由到竞争对手那里！廉价的决策层级将实验室自己的客户转移到更便宜的产品上，并蚕食收入。

6.) 它们让后训练变得经济可行，同时增加了对后训练的需求。 在真实企业工作上做 RL 时，较高的成本之一一直是对没有可核查答案的任务进行评分。一个廉价、经过校准的评分器消除了这项成本。环境的运行成本变得更低，路由器日志显示出哪些昂贵工作负载值得替换，而每一个发现自身超支的团队都会变成好奇的买家。训练、服务并重新训练定制模型的公司，同时获得了更便宜的输入和一条充满动力的客户管道。

如果说 DeepSeek 让市场对供给侧产生了质疑：预训练的成本、模型护城河的持久性，以及一个前沿模型能保持前沿地位多久，那么决策模型则让市场对需求侧产生了质疑：究竟有多少调用真正需要一个前沿模型……

## 通俗精炼（1）

### 2026-09-24 07:09:56

#### Jev 的潜在冲击：前沿模型未必需要处理每一次 AI 决策

文章的核心判断是：**DeepSeek 让市场质疑“最强模型能否一直昂贵地造出来”，Jev 这类廉价决策模型则提出另一个问题——AI 产品产生的大量调用，究竟有多少需要交给最强、最贵的前沿模型？**作者认为，后一个问题也可能动摇前沿实验室的收入预期。

##### 廉价能力第一次变得容易用

过去，公司若想用开放权重模型降低成本，通常需要有人选模型、部署、微调、评估，并在效果变化后重新训练。这更像机器学习团队的工作，许多公司没有相应的人手。

Jev 则以 API 提供服务：开发者无需自己准备 GPU 或训练模型，就能把它接入产品。作者认为，这种**“便宜且容易试”**的组合很重要。单次决策成本低到几分之一美分后，团队更愿意检查现有流程；他们可能发现，自己一直在用昂贵的旗舰模型回答简单的“是或否”、分类或路由问题。原本不关注推理成本的非技术团队，也开始寻找这类开支。

##### 它可能从三个方向挤压前沿模型收入

作者用一个简化公式描述前沿模型收入：**调用次数 × 每次调用的 token 数 × 每 token 价格**。Jev 一类模型可能同时影响这三项。

首先是**减少发给前沿模型的调用**。市场对前沿实验室的乐观预期，部分来自智能体将产生海量调用。但智能体运行时，并非每一步都需要复杂推理：选择工具、判断是否完成、决定是否升级处理、分类和打标签，都可能交给便宜的决策模型。简单生成任务也可交给其他廉价模型。若路由更准确，无效步骤和重试也可能减少。

其次是**减少仍需调用前沿模型时输入的 token**。路由器可以先剔除过时的上下文、当前任务用不到的工具说明，再把必要信息交给前沿模型。调用仍然发生，但消耗更少。

最后是**压低常规任务的价格**。当路由器能并排展示同一任务使用不同模型的成本与效果，客户就更容易判断哪些工作不值得支付旗舰价格。这并不意味着前沿模型没有价值，而是其高价可能更难覆盖大量常规工作。

##### 决策模型可能改变智能体的“指挥方式”

路由器并不是新概念；难点在于过去构建麻烦，也不够可靠。作者认为，决策模型适合承担这项工作：它快速、成本低，还能报告对自身判断的置信度。把握不足时，路由器就可以将任务升级给更强的模型。

由此，智能体的结构可能发生变化：**原先由前沿模型反复决定下一步、调用工具；以后则由普通代码和廉价决策模型维持流程，只在需要深度推理时调用前沿模型。**如果开发者常用工具直接内置路由功能，公司甚至不必自行搭建路由器。

作者进一步指出，前沿实验室的应对也可能带来两难：降价会让客户重新审视过去的支出；推出自家路由器，会教会客户按任务选择模型，也可能方便他们选用竞争对手；推出廉价决策产品，则可能把原本由旗舰模型处理的任务转移到自家低价产品上。

##### 它还可能推动企业定制模型

文章提出了另一条链路：企业要用真实业务任务训练定制模型，往往需要先判断模型的回答好不好。对于没有标准答案的任务，评分成本尤其高。作者认为，**廉价且置信度经过校准的评分模型**能降低这项成本；路由器留下的记录，则能显示哪些昂贵任务最值得用定制模型替换。

与此同时，发现自己在简单任务上花费过高的团队，可能成为定制模型的潜在客户。这是作者对训练和服务定制模型市场的推演，而非文中已证实的结果。

##### 争议：它会替代前沿模型，还是只承担辅助工作？

评论区提出了关键反对意见：Jev 的速度和低成本，可能恰恰限制了它处理长时间、多步骤复杂任务的能力；如果前沿实验室的主要收入最终集中在这类任务上，Jev 的威胁就会小得多。另有评论认为，Jev 更像一种容易被 Google 等大公司复制的设计选择，而非难以追赶的突破。

作者的回应是：**Jev 不必独立完成长任务，仍可作为组件参与长任务中的数百次小决策。**她讨论的也不只是一款产品，而是 Jev 及同期类似模型所代表的做法。因此，文章真正要追问的不是“廉价模型能否全面取代前沿模型”，而是：**当大量日常决策都能被更便宜的模型接管，前沿模型还能保留多少调用量与定价权？**
