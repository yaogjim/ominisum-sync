## 分析要点

- **核心高价值点**：将上下文、人格规则、记忆和技能都沉淀为可读写的文件资产，是构建可持续AI工作流的关键思路。
- **留存建议**：短期参考后可保留方法论部分（包含关于AI上下文管理、Workspace、AGENTS.md、Memory、Skill与自动化工作流的可复用思路，可作为搭建个人或组织AI工作台的参考。）

**知识要点**

- AI工作空间应尽量使用 Markdown、CSV、HTML 等模型友好的原生格式，减少格式噪音。
- AGENTS.md、MEMORY.md 和 Skills 目录可以把人格、偏好、流程和能力沉淀为可维护资产。
- Context 的质量比数量更重要，过时和矛盾信息会污染 AI 输出。
- Cron、Webhook、MCP 等机制可以让 AI Agent 从被动问答转向主动处理事件。
- Agent 能力可理解为工具、上下文、人格、记忆和技能的组合结果。

**行动项**

- 整理自己的核心工作流，将常用规则、偏好和写作风格写成 Markdown 文件。
- 检查现有知识库中过时、重复、矛盾的内容，建立定期归档机制。
- 尝试把一个重复性内容生产流程拆成多个可复用 Skill。
- 评估是否需要使用 Moxt 或类似工具，将分散在 Notion、飞书、本地文件和聊天记录中的上下文统一管理。

### Moxt 实测：把你的组织，折叠进一堆文件夹

上周四下午，我同时在做五件事。

周刊选题整理到一半、CodePilot 新冒了两个 Issue、Twitter 收藏夹里躺着三条想存的推、微信里有好几条待回的信息、一篇长文的草稿卡在开头。

一直以来我常工作见的问题就是：我的 Context 散在五个地方。

飞书、Notion、本地文件夹、微信聊天记录、我自己的脑子。

切任务的时候，一半时间花在搬运。

这只是散。更麻烦的是脏。

就算把东西汇到一起，AI 读起来也费劲：

飞书的 block、Notion 的 toggle、PDF 的视觉排版、Slack 截图，每种格式都要先剥一层壳。

![Image](https://pbs.twimg.com/media/HHEhr_PaMAAidl6?format=jpg&name=large)

散加脏，就是现在大多数 AI 产品在上下文上的主要问题。

Agent 能做到什么程度，不靠模型，靠你给它的工具和上下文。

正好前段时间 Moxt 发布了，我就试了一下，发现它在这两个问题的解决上做得非常好。

#### 一、给 AI 一个自己的家

Moxt 上来就回答了一件事：AI 需要一个自己的工作空间。

它的答案挺"笨"的。让 AI 在 md、csv、html 这些母语里工作，让它在文件系统里导航。听着不性感，但特别对。

Markdown 是 AI 的母语。

你给它一份 md，它秒懂；给它一份 Word，要先转一道。

Word 本质上就是 Markdown 的 GUI，那层 GUI 为人眼而设，对 AI 来说全是噪音。

Moxt 会把这些对于 AI 来说的脏信息，转成 AI 原生的格式：

- 导入 Word/PDF/Notion，后台自动转 md
- 导入 Excel，自动转 csv
- 生成的可视化报告，一律是 html

文件系统是 AI 的图书馆。能 grep、能树状浏览的结构，正好是它训练时熟悉的那种，读起来天生就顺。

![Image](https://pbs.twimg.com/media/HHEhwWgaUAIvQqT?format=jpg&name=large)

这种设计带来一个搬家爽点。

我在 Claude Code 里攒了十几个 Skill：

humanizer-zh 去 AI 味、writing-rewriter 做小绿书和推特风格改写、wechat-formatter 做公众号排版、document-illustrator 做配图。每一个就是一个 md 文件加几个资源。

搬到 Moxt 的 Skills 目录，一个不用改，全都跑得通。

它们本来就是 md，Moxt 的 Skill 也是 md。说是集成，其实就是复制粘贴。

![Image](https://pbs.twimg.com/media/HHEh1WxaoAAVOrY?format=jpg&name=large)

Workspace 还有一个好处：把 Context 从一次性输入变成可以累积的资产。

现在我写 AIGC Weekly，不用重新贴前几期选题、不用重新解释写作偏好、不用重新说我关注哪些方向。

背景默认已知。

别的 AI 产品，每次都是新一轮对话，Context 得一次性喂；Moxt 里的 Context 是往上攒的。

#### 二、把"你是谁"写进一份 md

每个 Moxt 用户都有一个专属个人 AI，叫 momo。

momo 的行为规则写在一份 AGENTS.md 里，放在你的个人空间。

用过 Claude Code 的朋友一看就懂。就是 CLAUDE.md 那套思路，产品化了。

![Image](https://pbs.twimg.com/media/HHEiDzpaAAAWXyT?format=jpg&name=large)

而且除了 Momo 以外，你还能创建自己的 AI 同事。

我做的第一件事，创建了一个我自己的 AI 分身"AI 藏师傅"。

具体方式就是把我所有的历史语录和写的内容都传了上去，然后它帮我创建了一个总结文档和规则。

涵盖了从 agents.md 到时间线等各种资料，以及语气内容等各个方面。

给它写了完整的身份书：

- 网名和平台矩阵
- 口头禅(「朋友们」「这太顶了」等)
- 感叹号用法
- 对话模式和写稿模式的切换规则
- 还有其他的要求

甚至从我的内容里总结出了 6 个我的核心信条：

1. 没亲手用过就没有发言权
2. 松弛是生产力，不用数据审判自己
3. AI 是赋能工具，不是替代品
4. 开放生态 &gt; 平台封闭
5. 只要敢花钱、敢放权，AI 就是许愿机
6. 朋友关系高于流量关系

![Image](https://pbs.twimg.com/media/HHEiMVjb0AAIWrE?format=jpg&name=large)

比方说，我现在如果写稿子或者写内容，就完全可以直接让这个 AI 同事帮我写。

因为它已经几乎蒸馏了我所有的内容和信息，某种程度上，它就是我的分身。

AI 藏师傅在我的个人空间里有完整的工作文件：

- drafts/：它帮我起草的内容
- MEMORY.md：它积累的关于我的偏好
- Skills/：它能调用的所有技能

我随时能打开看、能改、能删。

整个记忆库可以随时打开改，没有黑盒。

AI 的"记忆"不该是玄学，就是几个你能读懂的 md 文件而已。

![Image](https://pbs.twimg.com/media/HHEiQPBawAAv8jW?format=jpg&name=large)

这时候我才反应过来。Rules 也是 Context，而且是密度最高的那种。一份 AGENTS.md 里装着你的人格、价值观、写作品味，是你给 AI 最浓缩的 Context。

#### 三、做加法之前，先做减法

Moxt 有一个引导案例让我特别有感触。它的第一个 AI 同事模板叫"熵减官"。

这家公司专门造了这么一个角色，它手里没有写作、分析、生成这类产出任务。它只做三件事：

- 扫 Workspace 里过时的文档
- 发现内容之间的矛盾
- 把死内容归档

他们那句 slogan 我很喜欢：做少是能力，做多是本能。

![Image](https://pbs.twimg.com/media/HHEiW-DbsAElfW3?format=jpg&name=large)

我手里有 300 多篇剪藏、几十份项目笔记、上百条 Twitter 收藏，真正能用上的远没这么多。

更糟的是，废墟会污染 AI。

你问它"我之前对某个问题怎么看"，它能把三年前已经被我推翻的观点翻出来，一本正经地告诉你。

Context 的价值，不只在量，更在质。

Moxt 想做的是会自己精简的地方。无限塞东西的仓库，市面上已经够多了。

#### 四、读得懂，还得会动、会记、有人格

AI 读懂你的 Context 只是第一步。接下来它还得会自己动、会记住发生过的事、有一个承载这一切的人格。

将 Skill 组合完成复杂任务

必不可少的是现在 Agent 里的 Skills 能力。

大家知道我做了很多 Skills（比如最近很火的 PPT 生成）。

比如我的公众号写作流水线：

humanizer-zh(去 AI 味) → writing-rewriter(风格重写) → wechat-formatter(公众号排版)

以前在 Claude Code 里手动走三步，每步复制粘贴；

现在丢一份初稿进去，十几分钟拿到可以直接贴公众号的终稿。

所有中间版本都在 Workspace 里，回看改动一目了然。

![Image](https://pbs.twimg.com/media/HHEiaNJbcAEMLVM?format=jpg&name=large)

定时任务：让信息来找我

同样，Moxt 还支持定时任务。

我建了个"热点监控员"，每天早上跑一个 Cron，扫过去 24 小时的 Twitter、Newsletter、Hacker News，按主题聚类，输出当天的"科技热点日报"。

这个对于我们的内容生产其实非常有帮助，我不建议大家全看 AI 总结的内容，但是 AI 能让我们不漏掉一些比较重要的信息。

![Image](https://pbs.twimg.com/media/HHEidstbsAARgBb?format=jpg&name=large)

Webhook：让事件来找它

比 Cron 更猛的是 Webhook。

我自己有一个 vibe coding 的项目，叫做 Codepilot 。

这种项目其实用户多了以后，管理和上下文的处理都非常麻烦。

因为你的本地环境和线上的 GitHub 是两个完全不同的环境。

CodePilot 的 GitHub 仓库一旦有新 Issue，Webhook 推给 AI 同事，它先归类：

- 是 bug?归到待修复
- 是功能建议?排进路线图候选
- 是用户不会用?生成一条 FAQ 草稿

做完再决定要不要叫我。一个人没法 7×24 在线，AI 同事可以。

![Image](https://pbs.twimg.com/media/HHEijjNacAAzFfp?format=jpg&name=large)

自主性是一把刻度尺

由于是给组织用，所以安全性很重要。

而且大家不同的文件夹也有不同的权限，所以 Moxt 也做了很多安全上的处理。

Moxt 自己讲得很到位：不同场景需要不同的放手程度。

![Image](https://pbs.twimg.com/media/HHEiq-VboAAWjiQ?format=jpg&name=large)

连外部系统：用好 MCP

除了 Slack、GitHub 原生集成，Moxt 也支持 MCP：

- Sentry MCP：直接问"最近线上有什么报错"
- Figma MCP：问设计稿里某个按钮的颜色
- Linear MCP：「创建一个 bug ticket，优先级 high」

对于组织来说，这个功能还是更需要的。

因为我个人用的 MCP 很少有需要在不同地方流转的需求。

但对于组织而言，经常需要从原来的 Notion 里查东西，或者从 Slack 去同步一些信息，这些流转过程都很重要。

![Image](https://pbs.twimg.com/media/HHEitfcb0AA1q9_?format=jpg&name=large)

#### 五、AI 不只会写字，还会画图

Moxt 最惊艳我的一点，是它把 AI 的输出从文字拓展到了完整的视觉形态。

同样一份数据，momo 能输出三种东西：

可交互数据看板

基于 ECharts。下拉能筛选、悬浮有提示、多图联动。一个独立 html，打开就是完整的可视化。

比如我这里在连接了 GitHub 以后，我就让它基于我 GitHub 这个项目，做一个可交互的数据看板。

![Image](https://pbs.twimg.com/media/HHEixSKbUAAZCHq?format=jpg&name=large)

结构完整的 PPT

Moxt 也能实时生成结构完整的 PPT。

你也可以安装其他的一些 PPT Skills 来生成，都能正常生成预览。

我这里使用的是我自己的 PPT Skills，也是支持的。

封面、目录、内容页、图表、结尾。风格可选。html 格式，键盘翻页。

![Image](https://pbs.twimg.com/media/HHEi0yQasAElqbo?format=jpg&name=large)

产品也是可以的

由于它有很多的上下文，所以它生成的效果肯定是比一些没有上下文、或者上下文非 AI 原生的产品要强很多的。

表单、列表、后台 dashboard 常见页面结构。Tailwind CSS，一个文件，可以直接当 demo 演示。

![Image](https://pbs.twimg.com/media/HHEi3umbMAASwlo?format=jpg&name=large)

三种产出都是 html，落在 Workspace 里双击就看。

对靠视觉内容吃饭的人来说，AI 的交付物从"一段文字"升级成了"一份可以直接发出去的成品"。

而且对于组织来说，这种可视化的内容更适合理解和交付，比看纯文字要清晰、直观非常多。

#### 六、Agent 公式

我其实以前提过一个公式。Agent 到底什么决定它有多强?

> Agent 能力 = 工具 × 上下文 × (人格 + Memory + Skill)

- 工具决定它能做什么。Moxt 给的是 sandbox、浏览器、Cron、Webhook、MCP、外部集成
- 上下文决定它知道什么。Moxt 给的是 Workspace 里一路累积的 md 文件加外部数据通道
- 人格 + Memory + Skill 决定它像不像你。Moxt 给的是 AGENTS.md、MEMORY.md、Skills/，三件都是你能直接读和改的纯文本

![Image](https://pbs.twimg.com/media/HHEi7Lub0AAhMtT?format=jpg&name=large)

这是个乘法。任何一个因子为 0，输出就是 0。模型再强也救不回来。

Moxt 把这几个因素结合、实现的非常好，而且易于理解。

重要的是，回答了在组织层面应该怎么去使用这些元素。

#### 最后

Moxt 在 AI 藏师傅的身份书里写了六条信条，第三条是「AI 是赋能工具，不是替代品」。

Moxt 这个产品想做的事，说到底也是一句话：放大人的能力。

这个同频来得很自然。我认这个产品，是因为我本来就这么想。

"一人公司"里的"一人"，重点落在"决策和品味不被稀释"这几个字上，跟"一个人硬扛"没什么关系。

真正稀缺的是判断、审美、执念。这些 AI 学不来，也不该由 AI 来做。

AI 该做的，是把你从搬运 Context、切换任务、重复性看一眼这些琐碎里解放出来，让那份稀缺的判断被放大。

一个人的品味 × AI 同事的执行带宽，才是 OPC 真正的意思。

## 通俗精炼（1）

#### Moxt 实测：把组织上下文折叠进文件夹

##### 核心观点

作者认为，当前多数 AI 产品的关键瓶颈不是模型能力，而是 **上下文太散、格式太脏、记忆不可控**。  
Moxt 的价值在于：把个人或组织的知识、规则、任务和 AI 同事，统一放进一个 AI 原生的 Workspace，让 AI 真正“读得懂、用得上、能持续工作”。

---

##### 1. AI 需要一个自己的工作空间

过去工作中的 Context 分散在飞书、Notion、本地文件、微信、脑子里，切任务时大量时间浪费在搬运信息。

Moxt 的解决方式很朴素：让 AI 在文件系统里工作，用 AI 更容易理解的格式承载内容。

它会把不同来源的资料转成 AI 友好的格式：

- Word / PDF / Notion → Markdown
- Excel → CSV
- 可视化报告 → HTML

作者认为，Markdown、CSV、HTML 这些格式比复杂 GUI 文档更适合 AI 理解。  
Workspace 的意义在于：Context 不再是每次对话临时喂给 AI，而是可以持续累积的知识资产。

---

##### 2. 用 AGENTS.md 定义“你是谁”

Moxt 中每个用户都有个人 AI“momo”，其行为规则写在 `AGENTS.md` 中。

作者创建了一个自己的 AI 分身“AI 藏师傅”，把历史内容、语录、写作风格、价值观都沉淀进去，包括：

- 网名与平台矩阵
- 常用口头禅
- 写作语气
- 内容偏好
- 核心信条
- 写稿与对话模式切换规则

作者的体感是：  
AI 的“记忆”不该是黑盒，而应该是可以打开、修改、删除的 Markdown 文件。

其中最重要的判断是：  
**Rules 也是 Context，而且是最高密度的 Context。**

---

##### 3. Context 不只是越多越好，还要会减法

Moxt 有一个 AI 同事模板叫“熵减官”，专门负责：

- 清理过时文档
- 发现内容矛盾
- 归档无效资料

作者认为，很多人的知识库不是不够多，而是太乱、太旧。  
旧观点、无效资料、废弃项目会污染 AI 的判断。

所以好的 AI Workspace 不只是无限存东西，而应该能帮助用户持续“熵减”。

---

##### 4. AI 同事要会行动、会记忆、会协作

Moxt 不只是让 AI 读资料，还让 AI 能执行工作。

典型能力包括：

###### Skill 组合

作者把自己在 Claude Code 中积累的 Skills 直接迁移到 Moxt，例如：

- 去 AI 味
- 风格改写
- 公众号排版
- PPT 生成

这些 Skill 本质也是 Markdown 文件，因此迁移成本很低。

###### 定时任务

例如每天早上自动抓取 Twitter、Newsletter、Hacker News，生成科技热点日报。

###### Webhook

例如 GitHub 仓库有新 Issue 时，AI 自动分类：

- Bug → 待修复
- 功能建议 → 路线图候选
- 使用问题 → FAQ 草稿

###### MCP 与外部系统连接

Moxt 支持连接 Slack、GitHub、Sentry、Figma、Linear 等外部系统，让 AI 能跨工具查询和执行任务。

---

##### 5. AI 输出不只是文字，还能直接交付成品

作者对 Moxt 最惊艳的一点，是它能把输出从文字扩展到视觉化成品。

同一份数据，Moxt 可以生成：

- 可交互数据看板
- 结构完整的 PPT
- 产品页面 Demo
- 后台 Dashboard
- HTML 可视化报告

这些内容都以 HTML 形式保存在 Workspace 中，可以直接打开预览和交付。

这对组织尤其有价值，因为视觉化内容比纯文字更容易理解、汇报和协作。

---

##### 6. 作者总结的 Agent 能力公式

作者提出：

> Agent 能力 = 工具 × 上下文 ×（人格 + Memory + Skill）

其中：

- 工具：决定 AI 能做什么
- 上下文：决定 AI 知道什么
- 人格 / Memory / Skill：决定 AI 是否像你、懂你、能按你的方式工作

这是乘法关系，任何一项缺失，整体能力都会大幅下降。

Moxt 的优势在于，把这些要素都产品化，并且用文件系统和纯文本方式让用户可控、可理解。

---

##### 最终判断

作者认为，Moxt 的核心不是替代人，而是放大人的能力。

AI 应该承担的是：

- 搬运上下文
- 整理资料
- 执行重复任务
- 自动监控信息
- 生成初稿和可视化交付物

而人真正稀缺的是：

- 判断
- 审美
- 品味
- 决策
- 执念

所以 Moxt 更适合那些 Context 分散、任务频繁切换、希望沉淀方法论和 AI 工作流的个人或组织。  
它的本质是：用 AI 同事扩大人的执行带宽，同时保留人的判断和品味。

## 结构化（1）

### 2026-05-03 02:09:13

##### 主旨概括

作者实测 Moxt 后认为，它解决了当前 AI 产品最核心的两个上下文问题：**信息太散、格式太脏**。Moxt 通过文件夹式 Workspace、Markdown 原生上下文、AI 同事、Skills、定时任务和可视化输出，把个人或组织的知识、流程和执行能力整合进一个可持续累积的 AI 工作空间。

---

##### 1. 当前 AI 使用的核心问题：Context 又散又脏

作者一开始描述了自己的真实工作状态：同时处理周刊选题、CodePilot Issue、Twitter 收藏、微信消息、长文草稿等多个任务。

关键问题有两个：

- **Context 太分散**  
  信息散落在飞书、Notion、本地文件夹、微信聊天记录和脑子里，切换任务时大量时间都花在搬运资料上。

- **Context 太脏**  
  即使把资料集中起来，AI 也不一定好读。  
  例如：
  - 飞书有 block 结构
  - Notion 有 toggle
  - PDF 有复杂视觉排版
  - Slack 截图需要识别和解析

作者认为：  
> Agent 能做到什么程度，不只靠模型，更靠工具和上下文。

---

##### 2. Moxt 的核心设计：给 AI 一个自己的工作空间

Moxt 首先解决的是：**AI 应该在哪里工作**。

它的答案是让 AI 在自己熟悉的格式和文件系统中工作：

- Word / PDF / Notion 自动转成 Markdown
- Excel 自动转成 CSV
- 可视化报告统一生成 HTML
- AI 可以在文件系统中浏览、搜索、调用资料

作者认为这看起来“不性感”，但非常正确，因为：

- **Markdown 是 AI 的母语**  
  AI 读 Markdown 很顺，读 Word、PDF 则需要先去掉大量为人类视觉设计的“壳”。

- **文件系统是 AI 的图书馆**  
  树状目录、grep 搜索等结构，正好符合 AI 训练中熟悉的信息组织方式。

一个具体案例是：作者在 Claude Code 里积累了十几个 Skill，比如：

- `humanizer-zh`：去 AI 味
- `writing-rewriter`：改写成小红书或 Twitter 风格
- `wechat-formatter`：公众号排版
- `document-illustrator`：做配图

这些 Skill 本质上就是 Markdown 文件和资源包，所以搬到 Moxt 的 Skills 目录后，不用改就能运行。

更重要的是，Moxt 让 Context 从“一次性输入”变成“长期资产”。  
例如作者写 AIGC Weekly 时，不用每次重新贴历史选题、解释写作偏好或关注方向，因为这些背景已经沉淀在 Workspace 中。

---

##### 3. 把“你是谁”写进 Markdown：AI 分身与 AGENTS.md

Moxt 中每个用户都有一个专属个人 AI，叫 **momo**。  
它的行为规则写在 `AGENTS.md` 文件中，类似 Claude Code 里的 `CLAUDE.md`，但被产品化了。

作者还创建了自己的 AI 分身：**AI 藏师傅**。

创建方式是：

- 上传自己的历史语录和内容
- 让 Moxt 总结身份文档和行为规则
- 生成包括 `agents.md`、时间线、语气风格、内容偏好等资料

这个 AI 分身包含了作者的完整身份设定，例如：

- 网名和平台矩阵
- 口头禅，如“朋友们”“这太顶了”
- 感叹号用法
- 对话模式和写稿模式的切换规则
- 写作和表达要求

Moxt 还从作者内容中总结出 6 个核心信条：

1. 没亲手用过就没有发言权  
2. 松弛是生产力，不用数据审判自己  
3. AI 是赋能工具，不是替代品  
4. 开放生态 > 平台封闭  
5. 只要敢花钱、敢放权，AI 就是许愿机  
6. 朋友关系高于流量关系  

这个 AI 同事的工作文件也很清晰：

- `drafts/`：起草内容
- `MEMORY.md`：记录作者偏好
- `Skills/`：可调用的技能

作者强调：  
> AI 的“记忆”不该是玄学，而应该是几个你能读懂、能修改、能删除的 Markdown 文件。

---

##### 4. 做加法前先做减法：Context 需要熵减

Moxt 中有一个 AI 同事模板叫 **“熵减官”**，作者对此印象很深。

它不负责写作、分析或生成内容，只做三件事：

- 扫描 Workspace 中过时的文档
- 发现内容之间的矛盾
- 把无用内容归档

Moxt 的一句 slogan 是：

> 做少是能力，做多是本能。

作者举了自己的例子：

- 有 300 多篇剪藏
- 几十份项目笔记
- 上百条 Twitter 收藏

但真正能用的内容并没有那么多。

更严重的是，废弃信息会污染 AI。  
比如你问 AI“我以前怎么看某个问题”，它可能会翻出三年前你已经推翻的观点，并一本正经地回答。

所以作者认为：  
**Context 的价值不只在数量，更在质量。**  
Moxt 不只是无限存资料，而是试图让工作空间能自我清理、自我精简。

---

##### 5. AI 不只要读懂，还要会行动、会记忆、有人格

作者认为，AI 读懂上下文只是第一步，接下来还需要执行能力。

###### 5.1 用 Skills 串联复杂任务

作者以公众号写作为例，原来的流程是：

```text
humanizer-zh 去 AI 味
→ writing-rewriter 风格重写
→ wechat-formatter 公众号排版
```

以前在 Claude Code 中需要手动执行三步，每一步都要复制粘贴。

现在在 Moxt 中，只要丢入一份初稿，十几分钟后就能拿到可以直接发公众号的终稿。  
而且所有中间版本都会保存在 Workspace 里，方便回看和修改。

---

###### 5.2 定时任务：让信息主动找人

Moxt 支持 Cron 定时任务。

作者创建了一个“热点监控员”，每天早上自动扫描过去 24 小时的：

- Twitter
- Newsletter
- Hacker News

然后按主题聚类，输出当天的“科技热点日报”。

作者认为，虽然不建议完全依赖 AI 总结，但它能帮助内容生产者不漏掉重要信息。

---

###### 5.3 Webhook：让外部事件主动找 AI

作者还提到自己的项目 **CodePilot**。  
当 GitHub 仓库出现新 Issue 时，Webhook 会把事件推给 AI 同事，由 AI 先判断类型：

- Bug：归入待修复
- 功能建议：排进路线图候选
- 用户不会用：生成 FAQ 草稿

AI 处理完后，再决定是否通知作者。

这对个人项目或组织协作很有价值，因为人无法 7×24 小时在线，但 AI 同事可以。

---

###### 5.4 MCP 与外部系统连接

Moxt 除了支持 Slack、GitHub 原生集成，也支持 MCP。

例子包括：

- Sentry MCP：查询最近线上报错
- Figma MCP：查询设计稿中按钮颜色
- Linear MCP：创建高优先级 bug ticket

作者认为，这对组织尤其重要，因为组织常常需要在 Notion、Slack、GitHub 等多个系统之间流转信息。

---

##### 6. AI 输出不只是文字，还能生成可交付的视觉内容

Moxt 让作者惊艳的一点是：它能把 AI 输出从文字扩展到完整视觉成品。

同一份数据，momo 可以生成三类内容：

###### 6.1 可交互数据看板

基于 ECharts，可实现：

- 下拉筛选
- 悬浮提示
- 多图联动
- 独立 HTML 文件打开即用

作者连接 GitHub 后，让 Moxt 基于项目数据生成了一个可交互看板。

###### 6.2 结构完整的 PPT

Moxt 可以生成完整 PPT，包括：

- 封面
- 目录
- 内容页
- 图表
- 结尾

输出为 HTML 格式，可以键盘翻页，也支持安装作者自己的 PPT Skills。

###### 6.3 产品 Demo 页面

Moxt 还能生成表单、列表、后台 dashboard 等常见产品页面结构。  
使用 Tailwind CSS，一个 HTML 文件就可以直接当 demo 展示。

作者认为，这对组织非常有价值，因为可视化内容比纯文字更直观，也更适合交付。

---

##### 7. 作者总结的 Agent 公式

作者提出一个公式：

```text
Agent 能力 = 工具 × 上下文 ×（人格 + Memory + Skill）
```

其中：

- **工具**决定 AI 能做什么  
  Moxt 提供 sandbox、浏览器、Cron、Webhook、MCP、外部集成等。

- **上下文**决定 AI 知道什么  
  Moxt 通过 Workspace 中持续累积的 Markdown 文件和外部数据通道来提供。

- **人格 + Memory + Skill**决定 AI 像不像你、能不能延续你的方法  
  对应 Moxt 中的 `AGENTS.md`、`MEMORY.md` 和 `Skills/`。

作者强调这是乘法关系：  
任何一个因素为 0，最终能力都会大打折扣，模型再强也救不回来。

---

##### 8. 最后的判断：Moxt 是在放大人的能力

作者认同 Moxt 的原因，是它与自己的理念一致：

> AI 是赋能工具，不是替代品。

他认为，“一人公司”的重点不是一个人硬扛所有事，而是：

- 决策不被稀释
- 品味不被稀释
- 判断、审美和执念仍由人掌握

AI 应该做的是把人从这些琐碎事务中解放出来：

- 搬运 Context
- 切换任务
- 重复检查
- 整理信息
- 初步归类和执行

最终形成：

```text
一个人的品味 × AI 同事的执行带宽
```

作者认为，如果你或你的组织也存在以下问题，可以尝试 Moxt：

- 每天在多件事之间切换
- Context 散在七八个地方
- 有大量写作方法论、项目资料和经验想沉淀
- 希望 AI 不只是聊天，而是真正参与工作流执行
