## 通俗精炼（1）

### 2026-05-03 01:51:06

#### Claude Code 多模型配置技巧：用 Shell Alias 快速切换模型

##### 核心内容

文章介绍了一种给 **Claude Code 配置中转站或第三方大模型** 的简单方法：  
在 `~/.zshrc` 或 `~/.bashrc` 等 Shell 启动配置文件中，提前写好不同的命令别名，然后通过不同命令启动 Claude Code，对应使用不同模型。

例如：

- `claude`：使用官方 Claude 模型
- `claude-ling`：使用蚂蚁百灵 / Ling 模型
- `claude-ds`：使用 DeepSeek 模型

本质上是通过 **环境变量 + alias** 的方式，为不同模型配置不同的 API 地址、Key 或模型参数。

##### 价值亮点

###### 1. 切换模型更简单

过去切换 Claude Code 模型可能需要改配置、重启、折腾插件。  
这种方式只需要打开不同终端窗口，输入不同命令即可。

###### 2. 适合多项目、多模型场景

可以根据项目需要选择不同模型：

- 官方 Claude 适合通用编码
- DeepSeek 适合性价比或特定代码任务
- Ling 等第三方模型适合测试新模型能力

###### 3. 配置灵活，可扩展

这种方式不仅能切模型，也可以扩展到：

- 按需开启代理
- 配置不同 API 中转站
- 为不同项目绑定不同模型服务

##### 评论区补充观点

###### 上下文无法共享

有人指出：  
如果每个终端窗口使用一个模型，那么不同窗口之间的 Claude Code 上下文无法共享。

###### 可用 LangCLI 等工具增强体验

评论中提到 `langcli` 这类工具，可以在不丢失上下文的情况下切换模型，并兼容 Claude Code。

###### 本质是 Alias 配置

也有人总结得很直接：  
这套方案本质上就是给不同模型配置多个 `alias`，简单但实用。

##### 一句话总结

这是一个通过 Shell Alias 给 Claude Code 快速配置多模型入口的小技巧，优点是简单、灵活、低成本，适合经常在 Claude、DeepSeek、Ling 等模型之间切换的开发者。

## 解读（1）

### 2026-05-03 02:15:10

#### 一、内容总结

这条推文主要分享了一个 **给 Claude Code 快速切换不同大模型/中转站的简单方法**：

- 在 `~/.zshrc` 或 `~/.bashrc` 这类 Shell 启动配置文件里，提前写好不同的配置。
- 通过不同命令启动 Claude Code：
  - `claude`：使用官方 Claude 模型
  - `claude-ling`：使用蚂蚁百灵 / Ling 模型
  - `claude-ds`：使用 DeepSeek 模型
- 本质上是给不同模型配置不同的启动命令，方便在不同终端窗口里分别使用。

评论区也补充了几点：

- 有人指出：不同窗口使用不同模型时，**上下文无法共享**。
- 有人推荐 `langcli`，可以在不丢上下文的情况下切换模型。
- 也有人认为这就是配置 `alias`，但确实简单实用。
- 还有人提到类似方法也可以用于一键开启/关闭终端代理。

---

#### 二、深入浅出解读

##### 1. 这个方法到底是什么？

简单说，就是：

> 给 Claude Code 配几套“启动方式”，每套启动方式对应一个模型服务。

比如你平时输入：

```bash
claude
```

默认可能走官方 Claude。

但你可以自己加几个命令：

```bash
claude-ds
claude-ling
```

让它们分别使用 DeepSeek、Ling 或其他第三方兼容服务。

这类配置一般会放在：

```bash
~/.zshrc
```

或：

```bash
~/.bashrc
```

里面。

---

##### 2. 为什么这样能切换模型？

很多 AI CLI 工具都会读取环境变量，比如：

- API Key
- Base URL
- Model Name
- 代理地址
- 自定义服务入口

你可以给不同命令设置不同环境变量。

概念上类似这样：

```bash
alias claude-ds='使用 DeepSeek 配置启动 claude'
alias claude-ling='使用 Ling 配置启动 claude'
```

所以你输入不同命令时，Claude Code 实际连接的是不同的大模型服务。

---

##### 3. 这个方法的优点

###### 简单

不需要复杂插件，也不用频繁改配置文件。

###### 灵活

可以给每个模型单独起一个命令：

```bash
claude
claude-ds
claude-ling
claude-qwen
```

想用哪个就开哪个。

###### 适合多项目

比如：

- 项目 A 用 Claude
- 项目 B 用 DeepSeek
- 项目 C 用国产模型或中转站

可以很方便地按项目选择模型。

---

##### 4. 这个方法的缺点

###### 上下文不共享

如果你开三个终端：

- 窗口一用 Claude
- 窗口二用 DeepSeek
- 窗口三用 Ling

它们之间通常不会共享对话历史。

也就是说，你在 Claude 里聊过的内容，DeepSeek 不知道。

###### 兼容性不一定完美

不是所有第三方模型都能 100% 兼容 Claude Code 的调用方式。

可能会遇到：

- 工具调用不稳定
- 上下文长度不同
- 输出格式不一致
- 代码编辑能力有差异

###### API Key 安全问题

如果把 Key 明文写进 `.zshrc` 或 `.bashrc`，要注意不要误传到 GitHub 或截图泄露。

---

#### 三、我的意见

这个方法很实用，尤其适合经常用 Claude Code、又想尝试不同模型的人。

我的看法是：

> 如果你只是想快速切换模型，这种 alias / 环境变量方案非常值得用；  
> 如果你需要在同一个上下文里无缝切换模型，那就需要更专业的路由工具。

推荐使用场景：

| 场景 | 是否适合 |
|---|---|
| 快速体验 DeepSeek、Ling、Qwen 等模型 | 适合 |
| 每个项目使用不同模型 | 适合 |
| 临时切换中转站 | 适合 |
| 多模型共享同一段上下文 | 不太适合 |
| 企业级统一管理模型调用 | 需要更专业方案 |

总结一句话：

> 这是一个很朴素但很好用的技巧，本质就是“给不同模型配不同启动命令”。不高级，但高效。
