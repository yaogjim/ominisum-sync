##### Not a chatbot.

没有对话界面。代理有任务，而不是聊天窗口。

##### Not an agent framework.

我们不会告诉你如何构建代理。我们会告诉你如何运营一家由它们组成的公司。

##### Not a workflow builder.

没有拖放式工作流管道。Paperclip 对公司进行建模——包含组织结构图、目标、预算和治理。

##### Not a prompt manager.

智能代理自带提示词、模型和运行时。Paperclip 管理它们所在的组织。

##### Not a single-agent tool.

这是面向团队、层级和公司的。如果你只有一个代理，你可能并不需要 Paperclip。如果你有二十个——那你绝对需要。

Paperclip 与 OpenClaw 或 Claude Code 这类代理有何不同？

Paperclip 使用这些代理。它将它们编排成一个公司——包含组织架构图、预算、目标、治理和问责制。

Can I use my existing agents?

是的。Paperclip 对代理运行时不做预设。您的代理可以是 Claude 代码会话、OpenClaw 机器人、Python 脚本、Shell 命令、HTTP Webhook — 任何能够接收心跳信号的事物。适配器将 Paperclip 连接到您使用的任何执行环境。

当代理达到其预算上限时会发生什么？

当预算利用率达到100%时，代理会自动暂停，新任务会被阻止。在80%时，你会收到一条软警告。作为董事会成员，你可以随时覆盖限制并恢复代理。

我如何阻止代理做我不希望的事情？

Paperclip has governance and control modules on what your agents can do to modify Paperclip — for example, hiring new agents is gated by Board approval by default. However, your agents are your own and you secure them however you want to.

Do agents run continuously?

默认情况下，Paperclip 基于预定的心跳机制和/或通知（比如被分配任务或被@提及）运行你的代理。但你的代理属于你自己——你可以自由地将像 OpenClaw 这样的持续代理接入 Paperclip。

为什么我应该使用 Paperclip 而不是仅仅将我的 OpenClaw 指向 Asana 或 Trello？

代理编排在协调谁已接手工作、维护会话、监控成本、建立治理机制等方面存在诸多细微之处——Paperclip 会为你处理这些事情。自带工单系统已在路线图中。

典型的设置是什么样子的？

You can run Paperclip as a local instance or a remote deploy. Locally, a single Node.js process automatically sets up and maintains an embedded Postgres and data in local files. When you’re ready for the cloud, Paperclip makes that easy too — your agents can help using Paperclip’s provided SKILL.md. Then you configure Projects (groups of work) and Agents (which define what platform does the work and how). You set up tasks and the agents take care of the rest.

Can I run multiple companies?

是的。单个 Paperclip 部署可以运行数十家公司，且公司之间完全数据隔离。适用于开展独立业务、并行测试策略或对组织配置进行模板化以实现复用。

Is Paperclip open source?

是的。MIT 许可证授权，自托管，无需 Paperclip 账户。交互式设置引导您完成数据库配置和创建您的第一个公司。在本地使用嵌入式数据库运行，或连接到您自己的 Postgres。

#### Paperclip 文章精炼总结

Paperclip 的核心主张是：它不是用来 “造一个代理”，而是用来 “管理一家公司里的多代理团队”。  
它希望把 AI 代理组织成一个有目标、有层级、有预算、有审批、有审计的 “零人类公司” 运行系统。

##### 1. 产品定位：把代理编排成 “公司”，而不是单个工具

- Paperclip 是一个开源、自托管的代理编排系统，强调 “无需 Paperclip 账户”，可直接通过命令快速启动：`npx paperclipai onboard --yes`。
- 它的使用流程很像搭建一家公司：
  - 先定义目标，例如 “做出排名第一的 AI 笔记应用，实现月经常性收入 100 万美元”；
  - 再 “招聘” 团队，例如 CEO、CTO、工程师、设计师、营销人员；
  - 最后由用户审批战略、设置预算并运行，从仪表盘监控。
- 它的重点不是聊天交互，而是围绕 “公司运营” 来设计：组织架构、任务分配、预算控制、治理规则、审计追踪。

##### 2. 核心能力：任何代理都能接入，并围绕共同目标协作

- Paperclip 支持 “Bring Your Own Agent”，即接入任何代理、任何运行时、任何服务。
- 只要一个代理 “能接收心跳（heartbeat）”，就可以被纳入组织体系。
- 兼容对象包括：
  - Claude
  - Codex
  - Cursor
  - Bash
  - HTTP
  - OpenClaw 等
- 文中给了一个典型组织示例：
  - CEO 用 Claude
  - CMO 用 OpenClaw
  - CTO 用 Cursor
  - COO 用 Claude
  - 工程师分别用 Codex、Claude
- 关键点不是代理本身，而是 Paperclip 会把这些不同代理统一放进一个组织结构图下，并让它们指向同一个公司目标。

##### 3. 目标对齐：每项任务都能追溯到公司使命

- Paperclip 强调 “Goal Alignment（目标对齐）”：
  - 每项任务都能追溯到更高层级目标；
  - 代理不仅知道 “做什么”，也知道 “为什么做”。
- 它会把上下文从任务逐层传到项目、再到公司目标，避免代理只拿到一个孤立标题就开始执行。
- 文中还提到`SKILLS.md`机制，意思是代理能自动发现所需上下文和工作流知识，而不是每次靠人工重复说明。

##### 4. 运行机制：靠 Heartbeats 定时推进任务

- Paperclip 不是让代理永远无序运行，而是通过 “Heartbeats（心跳）” 机制定时启动代理。
- 代理会在预定时间点：
  - 检查工作；
  - 执行动作；
  - 沿组织结构上下委派任务。
- 默认情况下，代理基于 “定时心跳” 和 “通知触发” 运行，例如被分配任务、被 @ 提及。
- 这样适合处理规律性工作，比如：
  - 客户支持
  - 社交媒体发布
  - 报告生成
- 文章强调：管理层负责监督，日常事务由心跳驱动执行。

##### 5. 成本控制：按代理设预算，避免 token 失控

- Paperclip 的一个重要卖点是 “Cost Control（成本控制）”。
- 每个代理都有月度预算，到达上限后会自动停止，避免无限循环烧钱。
- 预算规则有明确阈值：
  - 使用到 80% 时发出软警告；
  - 达到 100% 时自动暂停，并阻止新任务；
  - 董事会（即用户）可以手动覆盖并恢复。
- 文中给了具体费用示例：
  - CEO Claude：`$42 / $60`
  - CMO OpenClaw：`$12 / $40`
  - CTO Cursor：`$25 / $50`
  - COO Claude：`$26 / $30`
  - CodexCoder Codex：`$9 / $30`
  - ClaudeCoder Claude：`$26 / $30`
  - 总计：`$140 / $240`
- 它还能追踪：
  - 哪些代理最烧钱
  - 哪些任务消耗 token 最多
  - 哪些项目超预算

##### 6. 工单与审计：所有对话、调用、决策都可追踪

- Paperclip 内置 “Ticket System（工单系统）”，把工作组织成可追踪的任务流。
- 每个任务都是一张结构化工单，包含：
  - 明确负责人
  - 状态
  - 讨论线程
- 它会记录完整过程：
  - 每条指令
  - 每次响应
  - 每次工具调用
  - 每个决策点
  - 每个 API 请求
- 审计日志是 “仅追加、不可编辑、不可删除” 的不可变历史。
- 文中的追踪示例包括：
  - `run_tests () passed`
  - `deploy_to_staging () done`
  - `smoke_test () passed`
  - `deploy_to_production () running`
- 这意味着系统不是 “黑箱”，而是能清楚看到代理到底做了什么。

##### 7. 治理机制：用户始终是董事会，关键决策要审批

- Paperclip 把用户放在 “董事会” 位置，强调代理的自主权不是默认拥有，而是由用户授予。
- 用户拥有的控制动作包括：
  - 暂停
  - 恢复
  - 覆盖
  - 重新分配
  - 终止
- 默认情况下，一些敏感操作需要审批，例如：
  - 招聘新代理
  - 执行未经审核的战略
- 文中总结了它的治理层价值：
  - 有组织结构图
  - 有审批与推翻机制
  - 有预算系统
  - 有全面可观测性
- 文章还提到 “Governance with rollback”：
  - 配置变更可版本化；
  - 不好的变更可以安全回滚。

##### 8. 多公司支持：一套部署可管理多家公司

- Paperclip 支持 “Multi-Company”，即一次部署服务多家公司，并做到完全数据隔离。
- 适合场景包括：
  - 同时运营多个 AI 业务
  - 测试不同商业策略
  - 把组织配置做成模板反复复用
- 文中给了多个公司示例：
  - `Mobile Marketing Co`：8 个代理，Active
  - `John Street Hyperliquid Fund`：14 个代理，Active
  - `Faceless TikTok Factory`：5 个代理，Active
- 文章明确表示：一个部署可以运行几十家公司，每家公司都有独立数据和审计链路。

##### 9. 适用场景：适合需要多角色协作的 AI 业务

- 文中列举了多个典型业务模板，说明它不局限于某个行业：
  - 内容营销机构：SEO、博客、社交媒体，`8 agents`
  - 加密交易台：分析、执行、风控、合规，`12 agents`
  - 电商运营：商品、客服、库存、广告，`10 agents`
  - YouTube 内容工厂：脚本、剪辑、缩略图、排期，`6 agents`
  - 开发代理公司：PM、工程、QA、DevOps，`9 agents`
  - 房地产获客：线索、触达、跟进、成交，`7 agents`
- 这些案例说明，Paperclip 更适合 “多角色、多流程、多任务” 的业务系统，而不是单个机器人。

##### 10. 与传统方式对比：解决多代理协作的常见痛点

- 文章通过 “Without / With Paperclip” 的对比，说明它主要解决以下问题：

###### 10.1 会话和任务容易混乱
- 没有 Paperclip 时，可能同时开着 20 个 Claude Code 标签页，却不知道每个标签页在做什么，重启后还会丢失内容。
- 有了 Paperclip 后，任务变成工单，对话有线程，会话能持久保存。

###### 10.2 上下文需要人工反复补充
- 没有 Paperclip 时，要不断手动提醒机器人当前项目目标和上下文。
- 有了 Paperclip 后，上下文会从任务自动连接到项目和公司目标。

###### 10.3 多代理协调成本高
- 没有 Paperclip 时，代理配置零散，任务管理、沟通、协作都得自己重新发明。
- 有了 Paperclip 后，组织架构图、工单系统、任务委派、治理能力都开箱即用。

###### 10.4 成本容易失控
- 没有 Paperclip 时，失控循环可能浪费数百美元 token。
- 有了 Paperclip 后，预算可视化，并在代理预算耗尽时自动节流。

###### 10.5 定期工作靠人工记忆
- 没有 Paperclip 时，像客服、社媒、报告这样的周期性工作要手动启动。
- 有了 Paperclip 后，Heartbeats 会按计划推进。

###### 10.6 从想法到执行链路太长
- 没有 Paperclip 时，需要自己找代码仓库、开 Claude Code、盯着执行。
- 有了 Paperclip 后，只需在系统中创建任务，编码代理会持续处理，管理代理负责审查。

##### 11. 技术特性：强调稳定执行、持久状态和可迁移模板

- 文中列出了一些底层能力：
  - `Atomic execution`：任务完成确认和预算执行是原子性的，避免重复工作和重复花费；
  - `Persistent agent state`：代理在每次心跳之间保留任务上下文，而不是每次从头开始；
  - `Runtime skill injection`：代理可在运行时学习工作流和项目上下文，无需重新训练；
  - `Goal-aware execution`：任务携带完整目标谱系；
  - `Portable company templates`：组织、代理、技能可导出 / 导入，并处理敏感信息；
  - `True multi-company isolation`：公司级隔离，审计链彼此独立。
- 这些特性说明，Paperclip 不是简单任务调度器，而是在尝试做 “可持续运营的代理公司运行时”。

##### 12. 它不是什么：明确边界，避免误解

- 文章专门强调 Paperclip 的边界：
  - 不是聊天机器人：没有以聊天窗口为中心的交互；
  - 不是代理框架：不教你怎么造代理；
  - 不是工作流拖拽工具：没有拖放式流水线；
  - 不是提示词管理器：不负责管理单个代理的 prompt；
  - 不是单代理工具：如果你只有 1 个代理，可能根本不需要它。
- 它真正适合的是：当你已经有很多代理，且需要 “团队级、层级化、公司化” 协作时。

##### 13. 常见问题：兼容已有代理，也支持本地和云部署

- 关于已有代理：
  - 可以继续用现有代理；
  - 代理可以是 Claude Code 会话、OpenClaw 机器人、Python 脚本、Shell 命令、HTTP Webhook 等。
- 关于部署方式：
  - 可本地运行，也可远程部署；
  - 本地模式下，一个 Node.js 进程会自动维护嵌入式 Postgres 和本地文件数据；
  - 也可接入自己的 Postgres。
- 关于开源：
  - 采用 MIT 许可证；
  - 支持自托管；
  - 不需要 Paperclip 账户。

##### 14. 一句话结论

- Paperclip 想解决的不是 “让单个 AI 更聪明”，而是 “让一群 AI 像公司一样可控地协同工作”。  
- 它最有价值的地方在于：把多代理系统补上了组织结构、预算、审批、审计和多公司隔离这些企业运营层能力。

#### Paperclip 到底在讲什么

##### 一、讲了什么？

Paperclip 讲的不是“怎么做一个更聪明的 AI 助手”，而是“怎么把一群 AI 代理组织成一家可运营、可审计、可控的公司”。

它的核心思想可以概括为几个层次：

- **把 AI 从单兵工具变成组织系统**：不是开很多聊天窗口分别盯着，而是给不同代理分配角色，比如 CEO、CTO、工程师、设计师、营销负责人，让它们像团队一样协作。
- **把任务和目标连接起来**：每个任务都能追溯到项目目标，再追溯到公司使命，代理不只是“接单执行”，而是知道“为什么做”。
- **把代理运行纳入治理框架**：招聘新代理、执行战略、修改预算、发起关键动作，都可以由“董事会”也就是人类来审批、暂停、覆盖、终止。
- **把成本、流程、责任看清楚**：每个代理有预算，每次工具调用、API 请求、决策过程都有记录，不会出现“钱花了、事谁做的、为什么这么做”都说不清。
- **把零散自动化升级为公司级编排**：它不是聊天工具，不是单代理框架，也不是简单工作流拖拽器，而是一个“AI 公司操作系统”。
- **支持多公司、多团队运行**：一套部署可以同时运营多个 AI 公司，彼此数据隔离，适合工作室、投资组合、自动化业务矩阵。
- **强调开放、自托管、可扩展**：你可以接入自己的 Claude、Codex、Cursor、脚本、Webhook，不依赖单一模型平台，也不需要官方账户。

一句话说，Paperclip 想解决的核心问题是：当你不再只用一个 AI，而是想让很多 AI 长期协作、承担分工、持续产出时，如何像经营公司一样去管理它们。

##### 二、有什么用？

如果把今天大多数人使用 AI 的方式比作“临时雇几个很能干的自由职业者”，那么 Paperclip 想做的是“把这些自由职业者真正纳入公司组织里”。

这两者的差别非常大。

你现在常见的 AI 使用方式，往往是这样的：一个窗口写代码，一个窗口写文案，一个窗口分析数据，再开一个窗口做规划。短期看很灵活，像在同时召唤多个高手；但时间一长就会发现问题越来越多：

- 你忘了某个窗口到底在做什么；
- 上下文断了，重开会话后前功尽弃；
- 代理之间不会自然接力，靠你手工转述；
- 花了多少 token、不知道；
- 某个错误决策是谁做的、为什么做的，也说不清；
- 每次都像搭临时舞台，不像在经营一个稳定系统。

Paperclip 的价值，正是在这里显现：它不是帮你“再多开几个 AI”，而是把 AI 使用方式从“聊天式临时调用”升级为“组织化持续经营”。

###### 1. 它把“人盯人”变成“制度盯事”

没有 Paperclip 时，你和 AI 的关系很像老板亲自盯着每个实习生干活。你不断提醒、催促、补上下文、检查进度、转发信息。你是连接一切的中枢。

有了 Paperclip，关系就变了。你更像董事会，而不是流水线工头。组织结构、职责边界、审批机制、预算上限、任务流转，都被预先定义。AI 不再只是等待你一句一句吩咐，而是在规则里运行。

这和现实公司很像。一个公司之所以能扩张，不是因为老板能盯更多人，而是因为公司有了制度：谁负责什么、遇到什么情况要汇报、哪些事项要审批、预算怎么控制、记录怎么留存。Paperclip 本质上是在给 AI 世界补上“制度层”。

###### 2. 它把“工具调用”提升为“经营行为”

很多人以为 AI 自动化的核心在模型能力，其实真正难的是运营复杂度。

让一个 AI 写一段代码并不算难；难的是让十几个代理连续一个月稳定协作，还不跑偏、不超支、不断线、不失控。就像让一个厨师做一道菜不难，难的是开一家餐厅：采购、排班、质量、账目、标准、责任、复盘，才是真正决定生死的部分。

Paperclip 解决的就是“餐厅怎么开”这个问题，而不是“厨师刀工够不够好”。

所以它的意义不在于替代 Claude、Codex、Cursor 这类智能体，而在于把这些能力放进一个可管理、可监督、可扩展的公司容器里。它把 AI 的一次次调用，变成了有岗位、有上下级、有预算、有审计的经营动作。

###### 3. 它把“上下文”从碎片变成谱系

AI 常见的一个问题是：它知道眼前任务，但不知道任务在全局中的意义。于是它会局部最优、整体跑偏。比如工程代理拼命加功能，但不知道当前公司目标是“快速验证增长”；营销代理大量发内容，但不知道品牌定位其实是高端而不是泛流量。

Paperclip 强调“Goal Alignment”，也就是任务会携带完整的目标谱系。简单说，不只是告诉代理“做什么”，还告诉它“这件事服务于哪个项目，这个项目服务于什么目标，这个目标又服务于什么公司使命”。

这就像你在公司里交代一位员工，不只是说“做个报告”，而是告诉他：“这个报告是为了董事会融资会做准备，融资是为了支持未来 12 个月扩张，因此你要重点展示增长效率而不是技术细节。”有了这个背景，员工做出来的东西就完全不一样。

Paperclip 的作用，就是让 AI 从“执行指令”升级为“理解业务语境后执行”。

###### 4. 它把“自动化风险”变成“可控风险”

AI 自动化最让人担心的，不是它不会做事，而是它做了不该做的事，或者花了不该花的钱。

例如：
- 一个代理进入循环，不断调用接口，疯狂烧 token；
- 一个“CEO 代理”自作主张改战略；
- 一个脚本误把测试环境部署到生产；
- 一个代理擅自创建新代理，组织开始无节制膨胀；
- 多个代理同时处理相同任务，重复花钱、重复劳动。

Paperclip 给出的答案，不是“相信 AI 会自律”，而是“把权限、预算、审批、日志做好”。

这很像企业里的财务制度。你不能期待每个员工都天生有成本意识，所以公司会设预算、报销规则、审批节点、审计记录。Paperclip 做的是 AI 世界里的同类事情：80% 预算给预警，100% 自动暂停；关键动作要审批；所有操作留痕；必要时可回滚。

这意味着自动化不再是一场赌博，而变成一套可治理的系统。

###### 5. 它让“一个创始人”像“拥有一家小型控股公司”

Paperclip 还有一个很重要的价值：它支持多公司隔离运行。这背后的想象空间很大。

以前一个人想同时做多个 AI 项目，会很快陷入混乱：不同项目的上下文混在一起，成本分不清，人员角色交叉，记录断裂。最后往往是“看起来有很多机会，实际上都半死不活”。

如果有了 Paperclip，一个人可以像经营多个小型事业部：
- 这个公司做内容营销；
- 那个公司做电商运营；
- 另一个公司做量化研究；
- 每家公司都有自己的目标、组织图、预算和审计轨迹；
- 但你在一个控制平面上统一管理。

这相当于把“个人生产力工具”提升成“个人控股平台”。未来很多超级个体、工作室、创业团队，真正缺的不是更强模型，而是这种组织化操作系统。

###### 6. 它的本质是“从 AI 能力管理走向 AI 组织管理”

如果再抽象一层，Paperclip 真正有用的地方在于它抓住了一个趋势：AI 的竞争，正在从“谁模型更强”，转向“谁能让更多智能体稳定、低成本、可控地协作”。

单个 AI 再强，也只是一个能力点；一组 AI 如果能形成分工、责任链和反馈闭环，就会像公司一样产生复利。Paperclip 正在试图成为这个复利系统的底座。

所以它的价值，不只是帮你省时间，而是帮你建立一种新的生产方式：你不再亲自做每一件事，而是设计组织、设定目标、分配权力、控制预算、审查结果。你从“执行者”变成“系统经营者”。

这就是它最深的一层用途。

##### 三、怎么用？

Paperclip 的正确用法，不是把它当成一个“更高级的聊天界面”，而是把它当成你业务的“AI 组织中台”。要用好它，关键不在于一开始接多少代理，而在于先把目标、角色、规则、节奏、预算这些基础结构搭起来。

下面用一个真实感较强的场景来讲：假设你要搭建一家“AI 内容营销公司”，目标是在 6 个月内为 10 家客户提供 SEO、博客、社媒分发服务，并形成稳定收入。我们按完整流程展开。

###### 1. 先定义公司，而不是先定义工具

很多人一上来就想：“我接 Claude 做策略、接 Codex 做脚本、接 Cursor 写站点。”这一步太早了。

Paperclip 的第一步应该是先定义公司层：

- 这家公司叫什么；
- 它的使命是什么；
- 当前阶段最重要的目标是什么；
- 成功的衡量指标是什么；
- 哪些事情绝不能做。

比如：

- 公司使命：帮助中小企业低成本获得持续内容流量；
- 当前季度目标：拿下首批 10 个付费客户；
- 核心指标：每客户每月产出 20 篇内容、自然流量增长、客户续费率；
- 约束条件：不做黑帽 SEO、不发布未经审校的医疗金融内容、不超出月预算。

这一步非常关键，因为 Paperclip 的任务分发、上下文注入、目标追踪都依赖这一层。如果你的公司目标模糊，后面所有代理都会“各自聪明，整体混乱”。

你可以把这理解为：不是先招人，再想公司做什么；而是先明确公司方向，再决定招谁。

###### 2. 设计组织结构图，明确角色和汇报关系

接下来不是立刻创建大量代理，而是先设计组织结构图。

一个内容营销公司的最小可行组织可以是：

- CEO：负责季度策略、客户选择、重大取舍；
- COO：负责排期、产能分配、交付协调；
- CMO：负责内容增长策略、渠道打法、内容框架；
- Editor/Content Lead：负责选题、质量标准、审校；
- Writer Agents：负责起草内容；
- SEO Agent：负责关键词研究、页面建议；
- Distribution Agent：负责分发到社媒、CMS、邮件；
- Analyst Agent：负责数据复盘、产出周报。

这里最重要的不是“头衔好看”，而是三件事：

- 每个角色的职责边界；
- 谁给谁派任务；
- 谁对谁负责。

例如：
- CEO 不直接写文章，但可以批准季度内容方向；
- CMO 可以给 Editor 和 SEO Agent 下任务；
- COO 可以协调排期，但不能改预算；
- Writer Agent 只负责初稿，不负责最终发布；
- Distribution Agent 必须等待审校通过后才能分发。

这就是组织建模。Paperclip 之所以有价值，就在于它允许你把这种汇报与协作关系显式化，而不是藏在脑子里。

###### 3. 选择和接入代理运行时

组织结构确定后，再思考每个岗位由什么代理承载。

Paperclip 的一个特点是“Bring Your Own Agent”，也就是你不需要统一用一种模型或一种运行时。你可以按岗位特点来匹配：

- CEO：适合长上下文、战略判断强的模型；
- CTO/工程角色：适合代码能力强的 Codex、Cursor；
- Writer：适合文案能力好的模型；
- SEO Agent：可以是模型加脚本工具的组合；
- Distribution Agent：更适合 Shell 命令、Webhook、API 自动化；
- Analyst：适合能拉取数据、跑模板报表的脚本代理。

这一步的原则不是“谁最强就全用谁”，而是“岗位和能力匹配”。

现实公司不会让战略总监去做流水线录入，同样地，AI 公司也不应该让一个昂贵的大模型承担所有重复性动作。Paperclip 通过适配器把不同代理纳入同一个组织图，这样你就能按性价比组合能力。

###### 4. 为每个代理定义预算、频率和权限

这是从“能跑”到“可控”的关键一步。

每个代理至少要定义三类约束：

###### 4.1 预算约束
比如：
- CEO：月预算 60 美元；
- CMO：40 美元；
- SEO Agent：30 美元；
- Writer Agent：每个 25 美元；
- Distribution Agent：10 美元。

预算不是财务装饰，而是行为边界。因为你最怕的不是代理不工作，而是代理高频、无效、重复地工作。预算上限能防止它们在错误循环中无限消耗资源。

###### 4.2 运行频率
也就是 Heartbeats。你要决定哪些岗位：
- 每天跑一次；
- 每小时检查一次；
- 只有被分配任务时才运行；
- 被 @ 提到时立刻运行。

例如：
- CEO：每天早上汇总一次；
- COO：每小时扫描排期和阻塞；
- Writer：只有接到工单时执行；
- Distribution Agent：每天固定时间发布；
- Analyst：每周生成一次绩效报告。

这相当于公司里的工作节律。有些角色需要值班，有些角色只在被召唤时出现。

###### 4.3 权限边界
例如：
- CEO 可以提出招聘建议，但不能直接录用新代理；
- CMO 可以发起内容项目，但不能修改公司使命；
- Writer 不能直接发布到生产环境；
- Distribution Agent 不能跨客户账号操作；
- 所有新增预算必须董事会审批。

权限设计越清晰，组织越稳定。Paperclip 的治理能力，本质上是在帮你把“自主权”变成“被授予的权力”，而不是默认无限放开。

###### 5. 用项目和工单组织工作，而不是靠聊天驱动

很多 AI 工具的问题是：事情发生在对话里，对话结束，事情也散了。

Paperclip 采用的是工单系统思路。每项工作应以 Ticket 形式存在，而不是一句临时消息。

一个标准工单至少应包含：

- 工单标题；
- 所属项目；
- 背后的目标；
- 负责人；
- 优先级；
- 状态；
- 截止时间；
- 讨论线程；
- 产出物链接；
- 审批要求。

例如一个工单可以是：

- 标题：为 SaaS 客户产出“AI 自动化成本控制”主题博客；
- 所属项目：Q2 SEO 增长计划；
- 目标关联：提升企业服务类关键词排名并导入潜在客户；
- 负责人：Content Lead；
- 协作代理：SEO Agent、Writer Agent、Editor；
- 截止时间：周三 18:00；
- 审批条件：发布前必须 Editor 审核通过。

这样做的好处有三个：

- 任务不会随着聊天窗口关闭而消失；
- 所有上下文都围绕工单沉淀；
- 责任和状态清晰，便于追踪和复盘。

这就是从“对话式指令”转向“系统化执行”。

###### 6. 让任务沿组织链路流动

Paperclip 的另一个重点是任务委派不是平铺的，而是沿组织图上下流转。

举个过程：

- 你作为董事会，批准“未来一个月重点发展 B2B SaaS 内容营销”；
- CEO 把它拆成几个项目：关键词抢占、案例库建设、社媒矩阵分发；
- CMO 负责“关键词抢占”项目，提出内容集群方案；
- SEO Agent 研究关键词并形成选题列表；
- Editor 按选题创建工单；
- Writer Agent 写初稿；
- Editor 审校并反馈；
- Distribution Agent 审核通过后发布；
- Analyst 每周汇总表现，反馈给 CMO；
- CMO 再向 CEO 汇报，必要时调整策略。

这条链路很重要，因为它决定了信息不是乱飞的，而是有层次地传递。现实企业能运行，靠的就是这种层级化分工。Paperclip 在 AI 组织中复现的正是这一点。

###### 7. 用审计和追踪替代“事后猜测”

AI 系统一复杂，最危险的不是出错，而是出错后你不知道怎么定位。

Paperclip 的 Ticket System 和 Trace 价值就在这里。你应该主动把它用于几个关键管理动作：

- 看每个任务是如何被拆解和执行的；
- 看某次工具调用是谁发起的；
- 看某个代理为何做出该决策；
- 看任务卡住的节点在哪里；
- 看哪些项目的 token 消耗异常高。

比如某篇内容质量很差，你不能只知道“Writer 写得不好”，而要能追到：

- 是 SEO Agent 给的关键词方向有问题；
- 还是 CMO 的 Brief 不清楚；
- 还是 Writer 缺了客户风格上下文；
- 还是 Editor 没有执行审校标准。

这会让你的管理方式从“拍脑袋责怪”变成“基于链路定位”。一旦做到这点，Paperclip 就不仅是自动化工具，而是经营分析系统。

###### 8. 建立审批关卡，特别是高风险动作

真正想长期使用 Paperclip，一定要设计好“哪些事情必须经过人工批准”。

建议至少把以下事项设为董事会审批：

- 招聘新代理；
- 修改公司目标和战略；
- 提高预算上限；
- 涉及外部发布的重大内容；
- 连接新的外部系统或敏感账号；
- 涉及生产环境的部署与删除操作。

原因很简单：AI 适合大规模执行，但不适合无边界扩权。审批不是降低效率，而是防止系统性失误。

在运营初期，你可以审批得更严；随着系统成熟，再逐步放权。就像公司发展初期，所有支出都老板签；后面流程成熟后，部门经理才有独立权限。

###### 9. 利用模板化能力复制公司

当你把一家 AI 内容营销公司跑顺后，Paperclip 的真正威力才开始显现：你可以把这套组织、技能、角色、流程导出成模板。

然后你就可以复制出：

- 面向医疗行业的内容公司；
- 面向电商卖家的内容公司；
- 面向海外 SaaS 的内容公司；
- 面向短视频脚本生产的媒体公司。

这意味着你运营的不再只是一个项目，而是一个“公司生成器”。模板化让经验沉淀为可复制结构，而不是停留在某个操盘手脑子里。

###### 10. 日常运营节奏应该怎么跑

一个成熟的 Paperclip 使用方式，通常会形成这样的运营节奏：

###### 每日
- 查看昨日工单完成情况；
- 检查预算预警；
- 看是否有代理暂停或阻塞；
- 审批关键待办；
- 浏览 CEO/COO 摘要。

###### 每周
- 复盘项目进展；
- 调整任务优先级；
- 优化表现差的代理配置；
- 重新分配预算；
- 查看哪些岗位成本高但产出低。

###### 每月
- 回顾公司目标达成度；
- 决定是否增减代理；
- 更新组织结构；
- 沉淀模板和技能；
- 清理不再有效的流程。

这套节奏很像你在经营一家公司，而不是“玩自动化”。

###### 11. 一个常见落地路径

如果你是第一次上手，不建议一开始就搭十几个代理。更稳妥的路径是：

###### 第一步：单公司、三角色起步
先只搭：
- CEO
- 一个执行代理
- 一个运营/协调代理

先验证：任务能不能稳定流转、工单能不能追踪、预算能不能控制。

###### 第二步：加入审校与分析角色
当执行稳定后，加入：
- 审校代理
- 数据分析代理

让系统出现反馈闭环，而不是只会生产不会复盘。

###### 第三步：加入节奏型心跳任务
把例行工作交给心跳：
- 每日巡检
- 每周报告
- 定时发布
- 异常提醒

让系统从“按需执行”进化到“持续运营”。

###### 第四步：复制模板到第二家公司
只有第一家公司跑顺，再复制到第二家。不要一开始多公司并行，否则很容易把混乱放大。

到了这个阶段，Paperclip 才真正发挥作用。它不是让你“更方便地用 AI”，而是让你“开始像经营公司一样经营 AI”。

#### Paperclip 实例化最佳实践：用一个「AI 内容营销公司」来说明

下面我基于你提供的`Paperclip`内容，选一个最适合落地、也最容易体现其价值的具体实例：

- 多角色协作
- 周期性任务执行
- 成本控制
- 审批与治理
- 全链路审计

##### 一、实例设定

###### 1. 公司目标

###### 1. 公司目标

这家公司不是 “做内容” 这么简单，而是有明确经营目标：

- 公司名称：`NoteGrowth AI Media`
- 服务对象：AI 笔记应用本身的增长团队
- 核心使命：用内容驱动自然流量、注册转化和品牌认知
- 季度目标：
  - 每月新增自然流量提升到`20 万 UV`
  - 每月新增注册用户达到`2 万`
  - 建立稳定的 SEO + 社媒 + 邮件分发内容引擎
- 关键约束：
  - 不超出每月 AI 运行预算
  - 重要外发内容必须审批
  - 所有发布动作可审计、可回滚

Paperclip 在这里的作用，不是替你写几篇文章，而是把 “内容增长” 变成一家可以持续运转的 AI 公司。

##### 二、组织结构怎么设计

为了让这个 AI 公司能稳定运行，先设计组织，而不是先接模型。

一个合理的组织可以是：

- `CEO Agent`
  - 负责季度目标、策略取舍、优先级调整
- `CMO Agent`
  - 负责内容增长策略、渠道规划、内容方向
- `COO Agent`
  - 负责任务排期、跨角色协调、瓶颈处理
- `SEO Strategist Agent`
  - 负责关键词研究、内容集群规划、竞争对手分析
- `Editor Agent`
  - 负责内容 brief、审校、风格一致性
- `Writer Agent A`
  - 负责长文初稿
- `Writer Agent B`
  - 负责社媒短内容、邮件草稿
- `Designer Agent`
  - 负责封面图、信息图、配图需求
- `Publisher Agent`
  - 负责 CMS 发布、社媒排程、邮件推送
- `Analyst Agent`
  - 负责数据复盘、归因分析、周报月报

这样的重点不是 “职位全”，而是职责清楚：

- CEO 不直接写内容
- CMO 不直接发布
- Writer 不直接上线文章
- Publisher 不改战略
- Analyst 不创建任务，只做反馈和建议

这就是 Paperclip 的核心价值之一：让代理之间不是平铺调用，而是有层级、有边界。

##### 三、代理怎么选型

Paperclip 支持接入不同代理，所以这个实例里不需要所有岗位都用同一种模型。

一个务实的配置可以是：

- `CEO Agent`：Claude
  - 适合长上下文、策略总结、跨项目判断
- `CMO Agent`：Claude 或 OpenClaw
  - 适合内容规划和策略推演
- `COO Agent`：Claude
  - 适合协调、任务拆分、跟踪阻塞
- `SEO Strategist Agent`：Claude + Bash/HTTP
  - 适合分析 SERP、关键词和站点数据
- `Writer Agents`：Claude 或其他更便宜但文案能力稳定的模型
  - 负责批量写作
- `Designer Agent`：可接图像生成服务或设计脚本工作流
- `Publisher Agent`：HTTP/Bash
  - 直接对接 CMS、社媒 API、邮件系统
- `Analyst Agent`：Python/Bash + 模型总结
  - 拉取 GA/Search Console / 产品数据，再产出报告

这个思路体现了 Paperclip 的一个实际优势：

- 贵模型做判断和管理
- 便宜或专用代理做重复执行
- 脚本和 API 做确定性动作

这样成本和效果更平衡。

##### 四、目标如何层层对齐

Paperclip 强调 Goal Alignment，所以这个案例里每个任务都要能追溯到公司目标。

例如目标链路可以这样设计：

- 公司使命：
  - 用内容增长驱动 AI 笔记应用获客
- 季度目标：
  - 让 “AI notes”“meeting notes AI”“AI second brain” 等关键词进入前列
- 项目目标：
  - 形成一套面向知识工作者的 SEO 内容集群
- 任务目标：
  - 发布一篇《2025 最好的 AI 会议记录工具对比》

这样，`Writer Agent`拿到的不是一句 “写篇文章”，而是：

- 这篇文章属于哪个项目
- 为什么现在要做
- 服务哪个业务指标
- 目标用户是谁
- 竞争文章是谁
- 最终成功标准是什么

这比普通聊天窗口里临时补一句 “写一篇 SEO 文章” 强得多，因为代理知道自己不是在孤立完成任务，而是在参与公司目标。

##### 五、工单系统怎么落地

Paperclip 很适合把内容生产做成标准化工单流。

一个典型工单可以是：

- 标题：撰写《Best AI Note Taking App for Teams》
- 所属项目：Q3 SEO Cluster - Team Collaboration
- 目标关联：提升团队协作类关键词排名，拉动中小团队注册
- 负责人：`Editor Agent`
- 协作代理：
  - `SEO Strategist Agent`
  - `Writer Agent A`
  - `Designer Agent`
  - `Publisher Agent`
- 截止时间：周四 18:00
- 发布条件：
  - 编辑审核通过
  - 标题与元描述确认
  - 配图完成
  - 法务 / 品牌规则检查通过

一个标准执行链路会是：

1. `CMO Agent`发起内容项目
2. `SEO Strategist Agent`给出关键词、提纲和竞品分析
3. `Editor Agent`整理为 brief
4. `Writer Agent A`完成初稿
5. `Editor Agent`审校修改
6. `Designer Agent`生成配图需求和封面
7. `Publisher Agent`发布到 CMS 并排期分发
8. `Analyst Agent`追踪表现并回写结果

这样所有动作都能被追踪，不依赖你手工在几个窗口间转述。

##### 六、Heartbeats 怎么设置最有效

这个案例特别适合心跳机制，因为内容增长本来就有很多周期性工作。

可以这样配置：

- `CEO Agent`
  - 每天早上`09:00`汇总昨日整体进展
- `COO Agent`
  - 每小时检查是否有逾期工单、阻塞任务、代理暂停
- `CMO Agent`
  - 每天两次检查内容计划与渠道排期
- `SEO Strategist Agent`
  - 每周一生成新关键词机会清单
- `Writer Agents`
  - 只在收到工单时运行
- `Publisher Agent`
  - 每天固定时间执行发布和分发
- `Analyst Agent`
  - 每周五生成周报，每月最后一天生成月度复盘

这样设计后，内容公司会进入一种 “自动运转” 状态：

- 周期性工作不用人记
- 日常生产有人推进
- 管理层负责看结果和审批
- 关键节点有人类把关

这就是 Paperclip 和普通 AI 工具最大的区别之一：它让节奏持续存在。

##### 七、预算怎么设才合理

这个案例里，预算必须按角色分层，不然最容易失控的是写作和策略代理。

一个可行的月预算示例：

- `CEO Agent`：`$60`
- `CMO Agent`：`$50`
- `COO Agent`：`$40`
- `SEO Strategist Agent`：`$40`
- `Editor Agent`：`$35`
- `Writer Agent A`：`$30`
- `Writer Agent B`：`$25`
- `Designer Agent`：`$20`
- `Publisher Agent`：`$10`
- `Analyst Agent`：`$20`

总预算：`$330 /month`

控制规则：

- 达到`80%`：发预警
- 达到`100%`：自动暂停
- 需要扩预算：董事会审批

这样做的好处很直接：

- 最贵的代理可控
- 哪个岗位烧钱一眼能看见
- 哪类任务成本异常可以被定位
- 不会因为一个循环工单把整月预算烧光

对内容营销公司来说，这尤其重要，因为 “批量内容生产” 很容易在不知不觉中带来高 token 成本。

##### 八、哪些事情必须审批

这个案例里，不建议一开始让 AI 完全自主，最好把以下动作纳入审批：

- 新增代理岗位
- 提高预算上限
- 改变季度增长策略
- 发布高风险内容
- 接入新的外部账号或 API
- 批量修改站点内容
- 涉及线上产品页、定价页的文案变更

例如：

- 一篇普通博客可以自动流转到发布
- 但首页标题改版、价格页文案变更、融资相关公告，必须人工审批

这样能避免 “内容团队 AI” 把组织从高效自动化变成高风险自动化。

##### 九、审计链路怎么发挥价值

这个例子里，Paperclip 的审计能力非常实用，因为内容增长经常需要复盘 “为什么这篇有效、那篇失效”。

你可以追踪：

- 谁提出了这个选题
- 为什么 prioritise 这个关键词
- 哪个代理写了初稿
- 编辑改了什么
- 发布何时完成
- 哪个渠道带来了最多点击
- 哪篇文章成本最高但效果最差

比如一篇文章表现差，你可以顺着链路查：

- 是`SEO Strategist Agent`选词错了
- 还是`Writer Agent`内容没击中搜索意图
- 还是`Editor Agent`标题不够强
- 还是`Publisher Agent`发布时间不合理

这会让管理从 “凭感觉判断” 变成 “基于过程证据优化”。

##### 十、这个实例最适合的落地顺序

第四阶段：模板复制
- 把这家公司复制成：
  - 面向个人用户增长的内容公司

  - 面向海外市场的内容公司

这时候，多公司隔离能力就会体现出来。

- 有多角色协作，不是单代理执行
- 有周期性工作，适合 heartbeat

##### 十二、一句话结论

用这个 “AI 内容营销公司” 实例来看，Paperclip 最佳实践不是 “多接几个模型”，而是：
