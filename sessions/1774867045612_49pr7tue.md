## 正文

**宝玉**

你日常用 Claude Code，用了多少功能？手机上写代码？语音编程？让 Claude 每 5 分钟自动帮你处理代码审查？

Claude Code 的创建者 Boris Cherny 列了 15 个他觉得被低估的功能。

【1】Claude Code 有移动端

Boris 说他有很多代码是在 iOS 上写的，不用开电脑就能改代码。操作方式：下载 Claude App（iOS 或 Android），左侧菜单里有个 Code 标签页。

【手机端更适合轻量级修改和任务下发，比如在地铁上让 Claude 开始跑一个任务，不是真的在 6 寸屏幕上写复杂逻辑。】

【2】会话可以在手机、网页、桌面端和终端之间来回切换

在终端运行 \`claude --teleport\` 或输入 \`/teleport\`，可以把云端会话拉到本地继续。反过来，用 \`/remote-control\` 可以从手机或网页远程控制本地正在运行的会话。

Boris 在设置里开启了"为所有会话启用远程控制"。

文档：[https://code.claude.com/docs/en/remote-control…](https://code.claude.com/docs/en/remote-control)

【解决的是一个真实痛点：工位上启动了长时间任务，人需要出门，但想随时看进度、追加指令。目前 Remote Control 还是研究预览阶段，同一时间只能远程控制一个会话。】

【3】/loop 和 /schedule：定时自动化

Boris 说这是 Claude Code 最强大的两个功能。可以设定 Claude 按固定间隔自动运行任务，最长持续一周。

他自己在本地跑着一堆循环：

\- \`/loop 5m /babysit\`：每 5 分钟自动处理代码审查意见、自动 rebase、把 PR 护送到合并上线  
\- \`/loop 30m /slack-feedback\`：每 30 分钟根据 Slack 反馈自动提 PR  
\- \`/loop /post-merge-sweeper\`：自动补提 PR，处理之前审查中遗漏的评论  
\- \`/loop 1h /pr-pruner\`：每小时清理过时或不再需要的 PR

Boris 的建议：把工作流变成 skill + loop 的组合。

文档：[https://code.claude.com/docs/en/scheduled-tasks…](https://code.claude.com/docs/en/scheduled-tasks)

【这可能是整个帖子里最有想象力的部分，把 Claude 从"你问它答"变成了后台持续运行的自动化工人。但有几个限制要注意：终端必须保持开启，/loop 任务最长跑三天（一周是通过桌面端的 /schedule 实现的），电脑不能休眠。另外，babysit 这种自动处理审查并推到生产的做法，前提是你有充分的测试覆盖，不建议在测试薄弱的项目里照搬。】

【4】Hooks：在代理生命周期中插入确定性逻辑

Hooks（钩子）可以在 Claude 运行过程中的特定节点自动执行预设逻辑：

\- SessionStart：每次启动时动态加载上下文  
\- PreToolUse：每次执行 bash 命令前记录日志  
\- PermissionRequest：把权限请求发到 WhatsApp，远程批准或拒绝  
\- Stop：Claude 停下来时自动催它继续

文档：[https://code.claude.com/docs/en/hooks](https://code.claude.com/docs/en/hooks)

【Hooks 类似 Git 的 pre-commit hook，但作用于 AI 代理的整个生命周期。这是 Claude Code 作为"代理平台"而非"编程助手"的关键设计，高级用户会喜欢，但学习成本不低。】

【5】Cowork Dispatch：远程操控桌面端

Boris 说他每天都用 Dispatch 来处理 Slack 消息、邮件、管理文件，不在电脑前也能用。

Dispatch 是 Claude 桌面应用的安全远程控制功能，可以使用你的 MCP 服务器、浏览器和电脑，前提是授权。

产品页面：[http://claude.com/product/cowork#dispatch…](http://claude.com/product/cowork#dispatch)

【Dispatch 和前面的 Remote Control 容易混淆。简单区分：Remote Control 控制的是终端里的 Claude Code 会话，Dispatch 控制的是桌面端的 Claude 应用，后者能操作浏览器、文件系统，能做的事更多。Dispatch 目前只支持 macOS。】

【6】前端开发一定要装 Chrome 扩展

Boris 说，用 Claude Code 最重要的一点是给 Claude 一个验证输出的方式。

他的类比：让一个工程师做网站但不让他用浏览器，结果能好看吗？给他浏览器，他会自己写代码、自己看效果、自己迭代到满意。

Boris 每次做前端项目都装 Chrome 扩展，说比其他类似的 MCP 工具更稳定。

下载地址（Chrome/Edge）：[https://code.claude.com/docs/en/chrome](https://code.claude.com/docs/en/chrome)

【"给 AI 一个验证自己输出的方式"这条原则不只适用于前端。任何能让 Claude 看到自己工作结果的机制，跑测试、检查编译、预览效果，都能显著提升输出质量。可能是整个帖子里最值得记住的一条。】

【7】桌面端内置 Web 服务器预览

Claude 桌面端可以自动运行 Web 服务器并在内置浏览器里测试，不需要手动配置。命令行和 VSCode 通过 Chrome 扩展也能实现类似效果。

文档：[https://code.claude.com/docs/en/desktop#preview-your-app…](https://code.claude.com/docs/en/desktop#preview-your-app)

【8】会话分叉

两种方式：在当前会话里运行 \`/branch\`，或从命令行运行 \`claude --resume --fork-session\`。

【探索不同方案时有用。让 Claude 做到一半，想试另一个方向，分叉出去两边互不影响。】

【9】/btw：边工作边问问题

Claude 执行任务的过程中，用 \`/btw\` 可以插入快速问题，不打断正在进行的工作。单轮问答，不会调用工具，但能看到当前会话的完整上下文。

【小功能但实用。相当于 Claude 在干活时你在旁边问了一句"顺便问一下……"。】

【10】Git Worktrees：并行开发的基础设施

Git 工作树（worktrees）允许你在同一个仓库里同时检出多个分支到不同目录，互不干扰。Claude Code 对工作树有深度支持。

Boris 说他随时有几十个 Claude 实例在跑，靠的就是工作树。用 \`claude -w\` 启动新的工作树会话，或在桌面端勾选"worktree"。不用 git 的用户可以通过 WorktreeCreate hook 自定义创建逻辑。

【"几十个实例同时跑"这种用法对订阅额度和机器性能都有要求。但即使只跑 2-3 个并行会话，工作树也比反复切分支高效得多。】

【11】/batch：大规模并行修改

/batch 先和你沟通需求，然后把任务扇出给多个工作树代理并行执行，数量可以是几十个、几百个甚至上千个。适用于大规模代码迁移和其他可并行化的工作。

【对"全仓库 API 改名""所有文件从格式 A 迁移到格式 B"这类批量操作很有价值，前提是你的任务确实可以并行化，而且有足够的测试来验证批量修改没出问题。】

【12】--bare：SDK 启动提速最多 10 倍

默认情况下，\`claude -p\`（或 TypeScript/Python SDK）启动时会搜索本地的 CLAUDE.md、settings 和 MCP 配置。但在非交互式场景下，你通常会通过 \`--system-prompt\`、\`--mcp-config\` 等参数显式指定加载内容，默认的搜索流程就成了浪费。

Boris 说这是最初设计 SDK 时的失误，未来版本会把 --bare 设为默认，现在需要手动加。

【写自动化脚本和 CI/CD 集成的人注意这条。加上 --bare 跳过不必要的配置加载，速度提升明显。】

【13】--add-dir：跨仓库工作

在一个仓库启动 Claude，用 \`--add-dir\`（或 \`/add-dir\`）让它看到并操作另一个仓库。也可以在团队的 settings.json 里配置 \`additionalDirectories\`，所有人启动时自动加载。

文档：[https://code.claude.com/docs/en/cli-reference…](https://code.claude.com/docs/en/cli-reference)

【14】--agent：自定义代理

在 \`.claude/agents\` 目录下定义代理，用 \`claude --agent=&lt;名字&gt;\` 启动。可以给代理设定专属的系统提示词和工具集。

文档：[https://code.claude.com/docs/en/sub-agents…](https://code.claude.com/docs/en/sub-agents)

【自定义代理的价值在于专业化。与其让一个通用 Claude 处理所有事，不如为代码审查、写测试、写文档各创建一个专用代理，每个加载不同的上下文和工具。这和前面 skill + loop 的思路是一脉相承的。】

【15】/voice：语音编程

Boris 说他大部分代码是用语音说给 Claude 的，不是打字。

操作方式：命令行里运行 \`/voice\` 然后按住空格键说话；桌面端按语音按钮；iOS 上启用听写功能。目前支持 20 种语言。

【语音编程的效果取决于任务类型。描述功能需求、解释 bug、口述重构方案，语音可能比打字更快。但精确描述代码结构或变量命名时，打字更高效。】

Boris 在最后说他其实还想继续写但强迫自己停了，后续会发更多。

#### Claude Code 15 个隐藏功能，一句话看懂

##### 核心结论

这篇内容的重点不是“又多了 15 个功能”，而是：**Claude Code 正在从一个代码助手，变成一个可跨端、可并行、可自动化运行的 AI 开发平台**。  
它最有价值的，不是帮你写几行代码，而是**持续接任务、自动执行、自己验证结果，并在多个环境里协同工作**。

##### 一、最值得关注的能力

###### 1. 从“对话式助手”变成“后台自动化员工”
最重要的是 `/loop` 和 `/schedule`。  
你可以让 Claude 按固定时间自动处理代码审查、清理 PR、根据反馈提新 PR。也就是说，Claude 不再只是“你问一句，它答一句”，而是能像一个持续运转的自动化执行者。

###### 2. 跨设备无缝接力
Claude Code 支持**手机、网页、桌面、终端**之间切换。  
你可以在电脑上启动任务，出门后在手机上继续查看进度、补充指令，解决了长任务必须守在电脑前的问题。

###### 3. 并行能力很强
借助 **Git Worktrees**、`/batch` 和自定义代理，Claude 可以同时在多个分支、多个任务上并行工作。  
这特别适合大规模迁移、批量改代码、同时推进多个开发方向。

##### 二、具体能力可以分成 5 类

###### 1. 移动与远程控制
包括手机端使用、`/teleport`、`/remote-control`、Dispatch。  
本质上是让 Claude 的工作不受设备限制，适合远程查看、发起任务、接管正在运行的会话。

###### 2. 定时与自动执行
包括 `/loop`、`/schedule`、Hooks。  
这是整套体系里最有想象力的部分：你可以把固定流程沉淀成自动化任务，让 Claude 定时执行，甚至在生命周期节点插入规则。

###### 3. 自我验证与前端调试
包括 Chrome 扩展、桌面端 Web 预览。  
核心思想是：**要让 AI 能看到自己做出来的结果**。只有能运行、能预览、能检查反馈，Claude 才更可能把结果做对。

###### 4. 并行开发与批量修改
包括会话分叉、Worktrees、`/batch`。  
适合探索多个方案，或在大仓库里同时推进大量改动，效率远高于传统单线程开发。

###### 5. 高级定制与性能优化
包括 `--bare`、`--add-dir`、`--agent`、`/voice`。  
分别对应：启动更快、跨仓库协作、专业化代理、语音输入。对于重度用户，这些功能能明显提升效率和工作流灵活度。

##### 三、真正有价值的方法论

###### 1. 让 AI 能验证自己的输出
这是全文最值得记住的一点。  
无论是前端预览、跑测试、检查编译，还是查看执行结果，**只要 Claude 能验证自己的产出，质量就会明显提升**。

###### 2. 把工作流拆成“技能 + 自动循环”
作者强调的不是单个命令，而是组合方式：  
把常见任务沉淀成 skill，再用 loop 定时执行，Claude 就能持续接管重复性工作。

###### 3. 专业化比通用化更有效
通过自定义 agent，可以把 Claude 分成不同角色，比如专门做代码审查、写测试、写文档。  
这比让一个通用助手处理所有事情更高效、更稳定。

##### 四、要注意的现实限制

###### 1. 自动化不是无风险
像自动处理代码审查、自动 rebase、自动推进上线，前提是**测试足够完善**。  
如果项目测试薄弱，盲目自动化反而会放大风险。

###### 2. 很多能力依赖运行环境
例如 `/loop` 需要终端一直开着、电脑不能休眠；某些远程能力还在预览阶段；Dispatch 目前只支持 macOS。  
也就是说，功能很强，但离“完全无感托管”还有距离。

###### 3. 并行能力对资源有要求
多工作树、多实例运行会消耗订阅额度和机器性能。  
普通团队不一定需要“几十个实例并行”，但 2 到 3 个并行会话已经足够带来明显收益。

##### 五、用一句话总结

**Claude Code 的进化方向，不是更像聊天机器人，而是更像一个可远程操控、可自动运行、可并行协作的 AI 开发操作系统。**  
对普通用户来说，最值得优先尝试的是：**跨端接力、自动循环任务、结果验证、并行工作树**。

## 结构化（1）

#### 文章主旨

这篇文章总结了 Claude Code 创建者 Boris Cherny 认为“被低估但很实用”的 15 个功能，核心观点是：Claude Code 不只是一个写代码的聊天工具，更像一个可持续运行、可远程控制、可并行扩展的“自动化编程代理平台”。  
文章尤其强调两点：一是让 Claude 能“看到并验证自己的结果”，二是把日常开发流程逐步改造成自动化工作流。

##### 1. 多端协同：不只是在电脑上用 Claude Code

- Claude Code 支持移动端，Boris 说自己有很多代码是在 iOS 上完成的，不用开电脑也能改代码。
- 使用方式是安装 Claude App（iOS 或 Android），在左侧菜单进入 `Code` 标签页。
- 更适合手机端的场景是轻量修改、下发任务、查看进度，而不是在 6 寸屏幕上写复杂逻辑。
- 会话还能在手机、网页、桌面端、终端之间来回切换：
  - 用 `claude --teleport` 或 `/teleport`，可把云端会话拉到本地继续。
  - 用 `/remote-control`，可从手机或网页远程控制本地终端中的会话。
- 这解决了“长任务在工位跑，人离开后还想查看进度和追加指令”的真实痛点。
- 限制是 `Remote Control` 仍处于研究预览阶段，而且同一时间只能远程控制一个会话。

##### 2. 自动化能力：把 Claude 变成持续工作的后台助手

- Boris 认为 `/loop` 和 `/schedule` 是 Claude Code 最强大的两个功能，可以按固定间隔自动执行任务。
- 自动运行最长可持续一周，但有区分：
  - `/loop` 最长跑 3 天；
  - 一周级别需要桌面端的 `/schedule`。
- Boris 给出的实际案例包括：
  - `/loop 5m /babysit`：每 5 分钟自动处理代码审查意见、自动 rebase、推进 PR 合并上线。
  - `/loop 30m /slack-feedback`：每 30 分钟根据 Slack 反馈自动提 PR。
  - `/loop /post-merge-sweeper`：自动补提 PR，处理漏掉的审查评论。
  - `/loop 1h /pr-pruner`：每小时清理过时或不需要的 PR。
- 他的建议是：把工作流拆成 `skill + loop` 的组合，让 Claude 持续在后台干活。
- 这意味着 Claude 不再只是“你问它答”，而是能像自动化工人一样持续执行任务。
- 但要注意现实限制：终端必须一直开着、电脑不能休眠；像 `babysit` 这种自动审查并推到生产的做法，前提是测试覆盖足够强，不适合测试薄弱的项目直接照搬。

##### 3. Hook 与 Agent：把 Claude 变成可编排的平台

- `Hooks` 可以在 Claude 生命周期的关键节点插入预设逻辑，类似 AI 代理版的 Git hook。
- 典型触发点包括：
  - `SessionStart`：启动时动态加载上下文。
  - `PreToolUse`：执行 bash 命令前先记录日志。
  - `PermissionRequest`：把权限请求发到 WhatsApp，远程批准或拒绝。
  - `Stop`：Claude 停下来时自动催它继续。
- 这说明 Claude Code 的定位不只是“编程助手”，而是“代理平台”，更适合高级用户，但学习成本也更高。
- 另一个重要能力是 `--agent`：可在 `.claude/agents` 下定义专用代理，并通过 `claude --agent=<名字>` 启动。
- 这种做法适合把不同任务专业化，例如：
  - 一个代理专门做代码审查；
  - 一个代理专门补测试；
  - 一个代理专门写文档。
- 文章认为，这和前面的 `skill + loop` 思路是一脉相承的：不是让一个通用 Claude 包办所有事情，而是让多个专用代理协同工作。

##### 4. 远程操作能力：不仅能控会话，还能控整台桌面环境

- `Cowork Dispatch` 是 Claude 桌面应用的安全远程控制能力，Boris 说自己每天都用它处理 Slack、邮件和文件管理。
- 它和 `Remote Control` 的区别很关键：
  - `Remote Control` 控制的是终端里的 Claude Code 会话；
  - `Dispatch` 控制的是桌面端 Claude 应用，可进一步调用浏览器、文件系统和 MCP 服务器。
- 也就是说，`Dispatch` 能做的事情更多，更接近“远程调度整台工作环境”。
- 目前 `Dispatch` 只支持 macOS。

##### 5. 前端开发重点：一定要给 Claude 验证结果的能力

- Boris 认为，前端开发最重要的一点，是让 Claude 能验证自己生成的结果。
- 他的类比很直观：如果让一个工程师做网站，却不让他打开浏览器看效果，结果通常不会好。
- 因此他每次做前端项目都会安装 Claude Code 的 Chrome 扩展，并认为它比其他类似 MCP 工具更稳定。
- Claude 桌面端还内置 Web 服务器预览能力，能自动运行 Web 服务并在内置浏览器测试；命令行和 VSCode 也可借助 Chrome 扩展实现类似能力。
- 文章特别强调：这条原则不只适用于前端。凡是能让 Claude“看到自己工作结果”的机制，比如跑测试、检查编译、预览页面，都会显著提升输出质量。
- 这可以看作全文最值得记住的一个方法论。

##### 6. 会话与交互体验：更灵活地探索、提问和切换思路

- `会话分叉` 支持两种方式：
  - 在当前会话运行 `/branch`
  - 或用 `claude --resume &lt;session-id> --fork-session`
- 适合的场景是：Claude 已经做到一半，但你想试另一种方案，又不想破坏当前上下文。
- `/btw` 则是一个小而实用的功能：Claude 在执行任务时，你可以顺手插入一个问题，不打断正在进行的工作。
- 它是单轮问答，不会调用工具，但能读取当前会话的完整上下文。
- 这相当于 Claude 正在干活时，你在旁边顺便问一句“对了，这里为什么这么写？”

##### 7. 并行开发基础设施：Worktrees 和 Batch 非常关键

- Git `worktrees` 允许在同一仓库同时检出多个分支到不同目录，彼此互不干扰。
- Claude Code 对 worktrees 有深度支持：
  - 用 `claude -w` 启动新的工作树会话；
  - 或在桌面端勾选 `worktree`。
- Boris 说自己常年同时跑几十个 Claude 实例，依赖的就是 worktrees。
- 即使普通开发者做不到“几十个实例并行”，只要能稳定并行 2 到 3 个会话，效率也会比反复切分支高很多。
- `/batch` 则是在此基础上进一步放大并行能力：它会先确认需求，再把任务分发给多个工作树代理并行处理，数量可以是几十、几百，甚至上千个。
- 这特别适合大规模代码迁移，例如：
  - 全仓库 API 改名；
  - 所有文件从格式 A 迁移到格式 B。
- 前提仍然是两个条件：任务本身适合并行拆分，而且必须有足够测试来验证批量修改是否出错。

##### 8. SDK、跨仓库与性能优化：偏高级但很实用

- `--bare` 是给非交互式场景提速的重要参数。
- 默认情况下，`claude -p` 或 TypeScript/Python SDK 启动时，会搜索本地 `CLAUDE.md`、`settings` 和 MCP 配置。
- 但在自动化脚本、CI/CD 等场景中，这些内容往往会通过 `--system-prompt`、`--mcp-config` 等参数显式传入，默认搜索反而成了额外开销。
- Boris 直言这是早期设计失误，并表示未来可能把 `--bare` 设为默认；目前需要手动加。
- 按他的说法，使用 `--bare` 后，SDK 启动速度最多可提升 10 倍。
- `--add-dir` 则解决跨仓库协作问题：可以在一个仓库中启动 Claude，再通过 `--add-dir` 或 `/add-dir` 让它访问另一个仓库。
- 团队还可以在 `settings.json` 中配置 `additionalDirectories`，让所有成员启动时自动加载这些目录。

##### 9. 语音编程：适合表达需求，不一定适合精细编码

- Boris 说自己大部分代码是“说给 Claude 听”的，而不是手打出来的。
- 使用方式包括：
  - 命令行执行 `/voice` 后按住空格说话；
  - 桌面端点击语音按钮；
  - iOS 端启用听写功能。
- 当前支持 20 种语言。
- 语音编程的优势在于表达需求、解释 bug、口述重构思路，往往比打字更快。
- 但如果要精确描述代码结构、变量命名或细节实现，打字通常仍然更高效。

##### 10. 文章结论：Claude Code 的真正价值在于“工作流化”

- 这 15 个功能表面上看是零散技巧，实际上背后是一套很清晰的使用思路：
  - 多端接力；
  - 远程控制；
  - 持续调度；
  - 生命周期钩子；
  - 多代理分工；
  - 并行工作树；
  - 批量迁移；
  - 结果验证。
- 文章最重要的启发，不是单个命令怎么用，而是如何把 Claude 从“聊天式工具”升级成“长期运行的自动化开发系统”。
- 如果只记住一个原则，那就是：一定要让 Claude 有办法验证自己的输出，比如看页面、跑测试、查编译结果。
- 如果只记住一个实践方向，那就是：把高频重复工作逐步固化成 `skill + loop + agent` 的自动化组合。
