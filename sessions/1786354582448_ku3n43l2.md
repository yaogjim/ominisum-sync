我觉得像视频转录剪辑这样的 App 应该是被 Agent 调用的，App 主要是用来确认结果和微调的。

所以我在设计的时候，砍掉了内置的 Harness，只保留了复制 prompt，然后去 Agent 操作。另外最新版本提供了网页界面，这样可以在 Agent 内置浏览器内打开，直接从对话或者网页标记二次编辑。

我坚信未来 Agent 才是入口，要做什么事是先打开 Agent 而不是打开 App。

#### Agent 将成为软件入口，App 退居“执行与校准层”

##### 核心观点

未来用户完成任务时，首先打开的可能不再是某个垂直 App，而是 **AI Agent**。Agent 负责理解意图、规划流程并调用工具；App 则主要承担具体执行、结果确认和人工微调。

##### 产品实践：BaoCut 的设计取舍

以视频转录剪辑工具 BaoCut 为例，其能力包括：

- YouTube、X 视频转录、翻译与剪辑
- GUI 与 CLI 分离，支持 Skill 调用
- 可由 Agent 直接完成视频转文本、问答等任务

在最新设计中，产品砍掉了内置 Agent Harness，转而：

1. 保留 Prompt，方便用户复制到外部 Agent 执行；
2. 提供网页界面，可在 Agent 的内置浏览器中打开；
3. 支持通过对话或网页标记进行二次编辑。

这让 App 更聚焦于专业能力，而不必重复建设 Agent 入口。

##### 产品范式的变化

软件设计正在从 **“Human Can Do It”** 转向 **“Agent Can Do It”**：

- 复杂配置可由 Agent 自动完成；
- 新用户引导和操作教学可交给 Agent；
- App 不必承载完整交互流程，只需提供稳定、可调用的能力；
- 人主要负责提出目标、确认结果和处理例外。

本质上，产品正在从“面向人操作的界面”，转变为“面向人机协作的工具”。

##### 挑战与兜底

完全依赖外部 Agent，也会提高对可靠性和容错能力的要求。Agent 误操作时，需要通过两种方式兜底：

- **Agent 自修复**：检测异常并重新执行；
- **人工微调**：由用户确认、修改最终结果。

因此，App 即使退居后台，仍需具备可预览、可撤销、可编辑和结果校验能力。

##### 结论

未来工具型 App 的竞争力，可能不再是拥有多复杂的界面，而是能否被 Agent **发现、理解、调用和纠错**。不支持 Agent 操作的产品，除非拥有强垄断或不可替代性，否则可能逐渐失去入口价值。
