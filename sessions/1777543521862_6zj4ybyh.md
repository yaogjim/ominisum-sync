## 通俗精炼（1）

### 2026-04-30 10:05:21

#### 信息焦虑的解法：把信息流变成可执行清单

##### 核心观点

作者 Leo 分享了一个个人信息处理工作流：  
通过 Claude Code 和自定义 skills，把每天来自 X、KOL、GitHub、TG、PM 平台、AI 行业等外部信息，整理成明确的行动清单，从而缓解信息过载带来的焦虑。

本质上，这不是减少信息，而是把信息 “结构化、决策化、行动化”。

---

##### 之前的问题：信息太多，但无法决策

在没有工作流之前，作者每天打开 X 就会焦虑：

- 爆款内容看不完
- KOL 推文跟不上
- 产品管理平台持续更新
- 不知道哪些内容该跟进
- 不知道哪些信息值得投入时间

真正造成焦虑的不是信息量本身，而是每条信息都悬而未决。

---

##### 现在的方案：每天 30 分钟跑工作流

作者每天运行两个 Claude Code skill：

###### `/today`：看内部状态

用于梳理自己的：

- 当前策略
- 在途任务
- 本周目标
- backlog 和优先级

###### `/morning`：扫外部信息

用于扫描外部信息源，包括：

- KOL 爆款内容
- GitHub Trending
- Telegram 频道
- PM 平台变化
- AI 行业动态
- 私聊信息
- 深度文章

最终输出一份当天信息清单。

---

##### 关键价值：每条信息都有动作

工作流会把当天信息拆成明确动作，例如：

- 写推文
- 评估是否安装 / 使用
- 扫一眼后跳过
- 分享给付费读者
- 放入 backlog
- 推迟到周日处理

这让作者从 “我还有很多没看” 转变为 “每条信息我都知道怎么处理”。

---

##### 情绪变化：焦虑消失的原因

作者强调，焦虑消失并不是因为信息变少了，而是因为信息被安排好了。

核心变化是：

> 信息从开放状态，变成了已决策状态。

对偏理性、结构化思维的人来说，这种状态会带来很强的掌控感。

---

##### 延伸发现：AI Skill 的描述方式很重要

热门回复中，作者提到自己发现大量 Claude Code skill 其实 “装废了”。

原因是 skill 的 description 如果只是写：

> 用于某某 workflow

AI 主线程并不知道什么时候该调用它。

更好的写法应该是：

- Use when：什么时候使用
- NOT when：什么时候不要使用

这说明 AI 工具配置的关键，不只是功能本身，而是触发条件是否清晰。

---

##### 产品与 AI 启发

###### 1. 信息产品的价值不只是聚合

真正有价值的是帮用户完成：

- 筛选
- 判断
- 排期
- 行动建议

也就是从 “内容流” 升级为 “决策流”。

###### 2. AI 工作流的核心是降低认知负担

好的 AI agent /workflow 不只是回答问题，而是帮用户减少未决事项，形成可执行计划。

###### 3. Prompt / Skill 设计要面向触发场景

AI 工具不是 “有功能就会被用”，必须告诉 AI：

- 什么场景调用
- 什么场景不调用
- 输入是什么
- 输出应该是什么

---

##### 一句话总结

Leo 的方法本质上是用 AI 把混乱的信息流转化为可执行任务流：不是让世界变安静，而是让每条信息都有归宿。

## 高价值（1）

### 2026-04-30 10:05:52

#### 高价值信息提取

##### 1. 一句话判断

> 最值得保留的是：**信息焦虑的解法不是减少信息，而是把信息流转化为 “已判定、已排程、可执行” 的决策流。**

**价值评级：A**  
**精炼理由：**文章本身很短，但击中了 AI 时代个人工作流的关键：外部信息不会减少，真正的杠杆是建立一套 “输入 → 判断 → 动作 → 排程” 的处理系统；同时，关于 Claude Code skill 描述方式的细节也很有迁移价值。

---

##### 2. 最重要的洞见

###### 洞见 1：信息焦虑的本质不是信息过载，而是 “未决事项过载”

###### **核心观点：**  
> 焦虑不是因为看到的信息太多，而是因为每条信息都悬而未决：该不该看、该不该做、什么时候做、值不值得跟进，都没有被判断。

**为什么重要：**  
大多数人面对信息流的默认反应是继续刷、收藏、稍后看，结果不是消化信息，而是在制造更多心理债务。Leo 的工作流把信息处理成几类明确动作：

- 写推
- 评估装不装
- 扫一眼跳过
- 私享给付费读者
- 进 backlog
- 推到周日

这不是 “整理信息”，而是在做**决策清算**。

**反常识之处：**  
常见建议是 “少刷信息”“断舍离”“减少输入”。但文章真正展示的是：  
> 你可以继续面对大量信息，只要每条信息都被归档到一个明确动作里，焦虑就会显著下降。

**可迁移价值：**  
适用于任何高输入职业：

- 投资人：项目流不是问题，未判断的项目才是问题
- 产品经理：用户反馈不是问题，未归类的反馈才是问题
- 创作者：选题多不是问题，未排程的选题才是问题
- 管理者：消息多不是问题，未分派责任和时点的事项才是问题

**我应该记住什么：**  
> 信息只有三种状态：现在做、安排做、明确不做。除此之外都是焦虑源。

---

###### 洞见 2：好的工作流不是 “提高效率”，而是提前替未来的自己做判断

###### **核心观点：**  
> /today 和 /morning 的价值，不是把信息汇总得更快，而是把当天外部世界与内部目标对齐，提前生成行动清单。

Leo 的两个 skill 分工很关键：

- `/today`看内部：策略、在途任务、本周目标
- `/morning`看外部：KOL 爆款、GitHub Trending、TG 频道、PM 平台变更、AI 行业、私聊、深读文章

真正有价值的不是 “扫外部信息”，而是把外部变化放进内部目标框架里判断。

**为什么重要：**  
很多人的信息流是外部驱动的：今天看到什么，就被什么牵着走。  
这个工作流的结构是内部驱动的：先知道自己本周要什么，再判断外部信息是否值得进入系统。

**可迁移价值：**  
这是一种通用的信息处理架构：

```text
内部目标 / 当前战略
        ↓
外部信息流
        ↓
相关性判断
        ↓
动作分类
        ↓
时间排程
```

如果没有 “内部目标” 这一层，任何信息流工具都会变成更高效的分心机器。

**我应该记住什么：**  
> 信息系统的核心不是 “收集更多”，而是 “用目标过滤世界”。

---

###### 洞见 3：AI 工具的关键不是让它更聪明，而是让它知道 “什么时候该出手”

###### **核心观点：**  
> Skill 写得好不好，不只看功能强不强，更看 AI 主线程能否识别它的触发场景。

热门回复里最有价值的细节是：Leo 发现自己大量 Claude Code skill “装废了”，原因可能是 description 写成了功能介绍型：

> “用于 X / X workflow”

但 AI 主线程真正需要的是：

> “Use when…”  
> “NOT when…”

也就是明确告诉模型：

- 什么时候用这个 skill
- 什么时候不要用这个 skill
- 触发边界是什么

**为什么重要：**  
这揭示了 AI Agent / Skill / Workflow 设计中的一个底层问题：  
工具存在，不等于工具会被正确调用。  
调用率低，很多时候不是工具没用，而是**触发条件没有被表达清楚**。

**反常识之处：**  
很多人优化 AI 工作流时，会继续堆工具、写功能、加能力。  
但真正的瓶颈可能不是能力不足，而是：

> AI 不知道何时该调用哪个能力。

**可迁移价值：**  
这条原则非常适合迁移到：

- AI Agent 设计
- Prompt 工程
- 自动化流程
- 团队 SOP
- 产品功能引导
- 知识库检索

好的说明不是 “这个东西能干什么”，而是：

```text
Use when：什么情况下使用
NOT when：什么情况下不要使用
Input：需要什么输入
Output：产出什么结果
Boundary：边界和禁区是什么
```

**我应该记住什么：**  
> 对 AI 来说，功能说明不如触发条件重要；“能做什么” 不如 “何时该做” 重要。

---

###### 洞见 4：工作流的成熟标志，是每个输入都有默认去向

###### **核心观点：**  
> Leo 的舒服感来自于系统已经定义好了输入的出口：每条信息不会停留在脑子里，而会被自动分配到某个处理路径。

文章里轻描淡写的一句很关键：

> “每条都明确动作。”

这意味着他的系统不是简单的信息聚合，而是建立了 “默认动作路由”。

比如：

| 信息类型 | 默认处理 |
|---|---|
| 值得表达的观点 | 写推 |
| 工具更新 | 评估装不装 |
| 低价值信息 | 扫一眼跳过 |
| 有付费价值 | 私享给付费读者 |
| 有潜力但不紧急 | 进 backlog |
| 需要深度处理 | 推到周日 |

**为什么重要：**  
很多工作流失败，是因为只完成了 “收集” 和 “整理”，没有完成 “去向设计”。  
没有出口的信息系统，最终会变成更精致的垃圾堆。

**可迁移价值：**  
任何系统都可以问一个问题：

> 当一个新输入进入系统，它默认会流向哪里？

如果没有答案，系统就会堵塞。

**我应该记住什么：**  
> 成熟系统不是没有杂音，而是每种杂音都有归宿。

---

##### 3. 底层逻辑

###### **逻辑一：焦虑来自未完成决策，而不是任务数量本身**

- **表层现象：**  
  每天打开 X、KOL、PM 平台、GitHub、TG 后感到焦虑。

- **深层原因：**  
  信息没有被判断，也没有被安排，全部以 “可能重要” 的形态悬浮在脑中。

- **推导结论：**  
  降低焦虑的关键不是减少输入，而是把输入转化为明确状态：做、不做、什么时候做、交给谁、放到哪里。

---

###### **逻辑二：外部信息必须经过内部目标过滤，才有行动价值**

- **表层现象：**  
  Leo 同时跑`/today`和`/morning`。

- **深层原因：**  
  单看外部信息会被热点牵引；单看内部计划又容易封闭。真正有效的是把外部变化放进内部目标中重新排序。

- **推导结论：**  
  高质量工作流应该同时包含两套输入：  
  **内部目标系统 + 外部变化系统**。  
  只有二者交叉处，才是真正值得行动的事项。

---

###### **逻辑三：AI 工作流的瓶颈往往在 “调用判断”，不在 “功能能力”**

- **表层现象：**  
  52 个 skill 里大量是 “装废的”，subagent 调用率很低。

- **深层原因：**  
  Skill 描述如果只是功能介绍，AI 主线程无法判断调用时机；工具虽然存在，但没有进入决策路径。

- **推导结论：**  
  设计 AI 工具时，最重要的不是罗列能力，而是定义触发条件、禁用条件和边界。
