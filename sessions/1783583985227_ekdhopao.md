#### 核心功能

##### 内置引擎与生成原语

OfficeCLI 是自包含的。下列能力全部内置在二进制中—— **无需 Office** 。

OfficeCLI 的基石：一个从零实现、高保真的 HTML 渲染引擎，让 AI 智能体能"看见"渲染后的文档，而不是凭 DOM 瞎猜。它覆盖形状、图表（趋势线、误差线、瀑布、K 线、sparkline）、公式（OMML → LaTeX，KaTeX 渲染）、通过 Three.js 渲染的 3D `.glb` 模型、morph 过渡、幻灯片缩放、形状效果。按页 PNG 截图是把渲染出的 HTML 通过无头浏览器截出来的。三种模式：

- **`view html`** —— 独立 HTML 文件，资源内联。任何浏览器打开即可看。
- **`view screenshot`** —— 按页 PNG，供多模态智能体读图检查。
- **`watch`** —— 本地 HTTP 服务 + 自动刷新预览；每次 `add` / `set` / `remove` 立即更新浏览器。Excel watch 还支持单元格内联编辑、图表拖动定位。

```
officecli view deck.pptx html -o /tmp/deck.html
officecli view deck.pptx screenshot -o /tmp/deck.png # 多页用 --page 1-N
officecli watch deck.pptx                            # http://localhost:26315
```

> 没有可视化，生成 PPT 的智能体就是在盲跑——它能读 DOM，但分辨不出标题溢出、两个形状重叠。因为渲染引擎内置在二进制里，"渲染 → 看 → 改"循环在 CI、Docker、无显示器的服务器——只要二进制能跑的地方都能用。

###### 公式与透视引擎

350+ Excel 函数写入即自动求值——写 `=SUM(A1:A2)` ， `get` 单元格，值已经在那。不需要回到 Office 重算。覆盖可溢出的动态数组（ `FILTER` / `SORT` / `UNIQUE` / `SEQUENCE` / `LET` / `LAMBDA` / `MAP` ， `_xlfn.` 自动加前缀）、 `VLOOKUP` / `XLOOKUP` / `INDEX` / `MATCH` 、财务与债券函数（ `XIRR` / `PRICE` / `YIELD` / `DURATION` / `COUPNUM` ）、统计分布/检验/回归（ `NORM.DIST` / `T.TEST` / `LINEST` ）、日期与文本函数等。

外加从源数据范围一条命令生成原生 OOXML 数据透视表——多字段行/列/筛选器、10 种聚合方式、 `showDataAs` 多种模式、日期分组、计算字段、Top-N、布局选项。透视表缓存和定义都写入 OOXML，Excel 打开即看到聚合后的结果：

```
officecli add sales.xlsx '/Sheet1' --type pivottable \
  --prop source='Data!A1:E10000' --prop rows='Region,Category' \
  --prop cols=Quarter --prop values='Revenue:sum,Units:avg' \
  --prop showDataAs=percentOfTotal
```

`merge` 把任意 `.docx` / `.xlsx` / `.pptx` 中的 `{{key}}` 占位符替换为 JSON 数据——段落、表格单元格、形状、页眉页脚、图表标题都支持。智能体一次性设计版式（昂贵），生产代码填充 N 次（廉价、确定、零 token 成本）。避免了"每份报告都从头重生成、产出 N 份版式不一致"的失败模式。

```
officecli merge invoice-template.docx out-001.docx '{"client":"Acme","total":"$5,200"}'
officecli merge q4-template.pptx q4-acme.pptx data.json
```

`dump` 把任意 `.docx` 、`.pptx` 、`.xlsx` —— 整个文档 **或任意子树** （单段、单表、单页幻灯片、单个工作表、styles、numbering、theme、settings）——序列化为可重放的 batch JSON， `batch` 重放回去。给一份用户想模仿的范本，智能体读结构化规格而不是原始 OOXML XML，修改后重放。打通"我有一份现成模板"和"给我生成 100 份变体"之间的链路。

```
officecli dump existing.docx -o blueprint.json                  # 整个文档
officecli dump existing.docx /body/tbl[1] -o table.json         # 任意子树
officecli dump existing.xlsx /Sheet1 -o sheet.json              # 单个工作表
officecli batch new.docx --input blueprint.json
```

##### 驻留模式与批量执行

驻留模式将文档保持在内存中，批量模式在一次打开/保存周期内执行多条命令。

```
# 驻留模式 — 通过命名管道通信，延迟接近零
officecli open report.docx
officecli set report.docx /body/p[1]/r[1] --prop bold=true
officecli set report.docx /body/p[2]/r[1] --prop color=FF0000
officecli close report.docx

# 批量模式 — 原子化多命令执行（默认遇到第一个错误即停止）
echo '[{"command":"set","path":"/slide[1]/shape[1]","props":{"text":"Hello"}},
      {"command":"set","path":"/slide[1]/shape[2]","props":{"fill":"FF0000"}}]' \
  | officecli batch deck.pptx --json

# 内联 batch，无需标准输入
officecli batch deck.pptx --commands '[{"op":"set","path":"/slide[1]/shape[1]","props":{"text":"Hi"}}]'

# 使用 --force 跳过错误继续执行
officecli batch deck.pptx --input updates.json --force --json
```

> **要用其他工具读这个文件?先落盘。** OfficeCLI 自己的读(`get` / `query` / `view`)永远能看到最新改动,所以在 officecli 内部无需操心保存。但常驻进程会延迟写盘,因此 **在非-officecli 程序读取该文件之前** ——python-docx/openpyxl、Microsoft Word、渲染器、交付/上传——先落盘:
>
> ```
> officecli set report.docx /body/p[1] --prop bold=true
> officecli save report.docx           # 落盘, 保留常驻进程(或 `close` = 落盘 + 释放)
> python my_reader.py report.docx      # 此时才能看到改动
> ```
>
> 常驻进程闲置约 10s 后也会自动落盘一次。完整落盘模型(auto-save / auto-close / save / close、环境变量调节):[wiki → open / close](https://github.com/iOfficeAI/OfficeCLI/wiki/command-open#when-the-file-on-disk-is-refreshed) 。

##### 三层架构

从简单开始，仅在需要时深入。

层 用途 命令

**L1：读取** 内容的语义视图 `view` （text、annotated、outline、stats、issues、html、svg、screenshot）

**L2：DOM** 结构化元素操作 `get` 、 `query` 、 `set` 、 `add` 、 `remove` 、 `move` 、 `swap`

**L3：原始 XML** XPath 直接访问 — 通用兜底 `raw` 、 `raw-set` 、 `add-part` 、 `validate`

```
# L1 — 高级视图
officecli view report.docx annotated
officecli view budget.xlsx text --cols A,B,C --max-lines 50

# L2 — 元素级操作
officecli query report.docx "run:contains(TODO)"
officecli add budget.xlsx / --type sheet --prop name="Q2 Report"
officecli move report.docx /body/p[5] --to /body --index 1

# L3 — L2 不够时用原始 XML
officecli raw deck.pptx '/slide[1]'
officecli raw-set report.docx document \
  --xpath "//w:p[1]" --action append \
  --xml '<w:r><w:t>Injected text</w:t></w:r>'
```

1. **安装二进制文件** -- 一条命令（见 安装 ）
2. **完成。** OfficeCLI 自动检测您的 AI 工具（Claude Code、GitHub Copilot、Codex），通过检查已知配置目录并安装技能文件。您的智能体可以立即创建、读取和修改任何 Office 文档。

**手动配置（可选）**

如果自动安装未覆盖您的环境，可以手动安装技能文件：

**直接将 SKILL.md 提供给智能体：**

```
curl -fsSL https://officecli.ai/SKILL.md
```

**安装为 Claude Code 本地技能：**

```
curl -fsSL https://officecli.ai/SKILL.md -o ~/.claude/skills/officecli.md
```

**其他智能体：** 将 `SKILL.md` 的内容添加到智能体的系统提示词或工具描述中。

- **确定性 JSON 输出** —— 每条命令都支持 `--json` ，schema 一致。无需正则解析、无需抓 stdout。
- **基于路径的寻址** —— 每个元素都有稳定路径（ `/slide[1]/shape[2]` ）。智能体无需理解 XML 命名空间即可导航文档。（OfficeCLI 自己的语法：1-based 索引、元素本地名——不是 XPath。）
- **渐进式复杂度（L1 → L2 → L3）** —— 智能体从只读视图入手，升级到 DOM 操作，仅在必要时降到 raw XML。最大限度节省 token。
- **自愈式工作流** —— `validate` 、 `view issues` 、以及结构化错误码（ `not_found` 、 `invalid_value` 、 `unsupported_property` ）会返回 suggestion 和有效范围。智能体无需人工介入即可自纠错。
- **内置 agent 友好渲染引擎** —— `view html` / `view screenshot` / `watch` 原生输出 HTML 和 PNG。无需 Office。智能体能"看见"自己的产出，并在 CI / Docker / 无头环境里修复排版问题。
- **内置公式与透视引擎** —— 350+ Excel 函数写入即自动求值（含可溢出动态数组、财务/债券与统计函数族）；从源数据范围一条命令生成原生 OOXML 数据透视表。智能体立刻读到计算值和聚合结果，不需要回到 Office 重算。
- **模板合并** —— 智能体一次性设计版式，下游代码把 `{{key}}` 占位符填充 N 次。避免每份报告都烧 token 重生成。
- **Dump 往返** —— `dump` 把任意 `.docx` 、`.pptx` 、`.xlsx` 转成可重放的 batch JSON。智能体通过读结构化规格学习人类范本，而不是从原始 OOXML XML 反推。
- **内置帮助** —— 属性名或取值格式不确定时，智能体跑 `officecli <format> set <element>` ，不靠猜。
- **自动安装** —— OfficeCLI 自动识别您的 AI 工具（Claude Code、Cursor、VS Code…）并完成配置。无需手动放 skill 文件。

不确定属性名时，用分层帮助查询：

```
officecli pptx set              # 全部可设置元素与属性

##### JSON 输出格式

所有命令均支持 `--json` 。常见响应格式：

**单个元素** （ `get --json` ）：

```
{"tag": "shape", "path": "/slide[1]/shape[1]", "attributes": {"name": "TextBox 1", "text": "Hello"}}
```

**元素列表** （ `query --json` ）：

```
[
  {"tag": "paragraph", "path": "/body/p[1]", "attributes": {"style": "Heading1", "text": "Title"}},
  {"tag": "paragraph", "path": "/body/p[5]", "attributes": {"style": "Heading1", "text": "Summary"}}
]
```

**错误** 返回结构化错误对象，包含错误码、建议修正和可用值：

```
{
  "success": false,
  "error": {
    "error": "Slide 50 not found (total: 8)",
    "code": "not_found",
    "suggestion": "Valid Slide index range: 1-8"
  }
}
```

错误码： `not_found` 、 `invalid_value` 、 `unsupported_property` 、 `invalid_path` 、 `unsupported_type` 、 `missing_property` 、 `file_not_found` 、 `file_locked` 、 `invalid_selector` 。属性名支持自动纠错 -- 拼错属性名时会返回最接近的匹配建议。

**错误恢复** -- 智能体通过检查可用元素自行修正：

```
# 智能体尝试无效路径
officecli get report.docx /body/p[99] --json
# 返回: {"success": false, "error": {"error": "...", "code": "not_found", "suggestion": "..."}}

# 智能体通过查看可用元素自行修正
officecli get report.docx /body --depth 1 --json
# 返回可用子元素列表，智能体选择正确路径
```

**变更确认** （ `set` 、 `add` 、 `remove` 、 `move` 、 `create` 使用 `--json` ）：

```
{"success": true, "path": "/slide[1]/shape[1]"}
```

运行 `officecli --help` 查看退出码和错误格式的完整说明。

#### 端到端工作流示例

典型的智能体自愈式工作流：创建演示文稿、填充内容、验证并修复问题 -- 全程无需人工干预。

```
# 1. 创建
officecli create report.pptx

# 2. 添加内容
officecli add report.pptx / --type slide --prop title="Q4 Results"
officecli add report.pptx '/slide[1]' --type shape \
  --prop text="Revenue: $4.2M" --prop x=2cm --prop y=5cm --prop size=28
officecli add report.pptx / --type slide --prop title="Details"
officecli add report.pptx '/slide[2]' --type shape \
  --prop text="Growth driven by new markets" --prop x=2cm --prop y=5cm

# 3. 验证
officecli view report.pptx outline
officecli validate report.pptx

# 4. 修复发现的问题
officecli view report.pptx issues --json
# 根据输出修复问题，例如：
officecli set report.pptx '/slide[1]/shape[1]' --prop font=Arial
```

#### OfficeCLI 深度精炼解读

##### 一句话总结

**OfficeCLI 是给 AI 智能体用的 “Office 操作系统”：不用安装 Office，就能用命令创建、读取、编辑、渲染 Word / Excel / PowerPoint，并让 AI 看见结果、自动修正。**

---

##### 深度总结

###### 1. 核心定位

OfficeCLI 不是传统 Office 编辑器，而是：

> **面向 AI Agent 的 Office 文档自动化工具链。**

它把`.docx/.xlsx/.pptx`变成 AI 能理解、能操作、能验证的对象。

---

###### 2. 最大创新：让 AI “看见” 文档

过去 AI 修改 Office 文档，多半是在改 XML / DOM，容易 “盲改”：

- 标题是否溢出？
- 图片是否遮挡？
- 表格是否错位？
- PPT 是否美观？

AI 看不到。

OfficeCLI 内置 HTML / PNG 渲染引擎，可以把文档渲染出来：

```bash
officecli view deck.pptx html
officecli view deck.pptx screenshot
officecli watch deck.pptx
```

这形成了闭环：

> **生成 → 渲染 → 查看 → 修正**

这是它最关键的 AI 原生能力。

---

###### 3. 它能做什么

覆盖三大 Office 格式：

| 格式 | 创建 | 读取 | 修改 | 渲染 |
|---|---:|---:|---:|---:|
| Word | ✅ | ✅ | ✅ | ✅ |
| Excel | ✅ | ✅ | ✅ | ✅ |
| PowerPoint | ✅ | ✅ | ✅ | ✅ |

能力包括：

- 创建文档、幻灯片、表格、图表
- 修改文字、样式、颜色、布局
- 读取结构化 JSON
- 批量处理文档
- 模板变量替换
- Excel 公式计算与数据透视表
- 实时预览
- MCP 接入 Claude、Cursor、Copilot 等 AI 工具

---

###### 4. 三层操作架构

OfficeCLI 设计得很适合 AI：

| 层级 | 作用 | 命令 |
|---|---|---|
| L1 | 看内容 | `view` |
| L2 | 改结构元素 | `get /query/set /add/remove` |
| L3 | 直接改底层 XML | `raw /raw-set` |

简单任务用 L1 / L2，复杂边角问题再进 L3。

这避免 AI 一上来就陷入复杂 OOXML。

---

###### 5. AI 友好设计

它对 AI 友好的地方主要有：

- **稳定路径寻址**：如`/slide [1]/shape [2]`
- **统一 JSON 输出**：方便 AI 解析
- **结构化错误提示**：告诉 AI 哪里错、怎么改
- **自动安装技能文件**
- **MCP 集成**
- **实时预览与截图**
- **模板合并与 dump 往返**

本质上，它把 Office 文件变成了 AI 可编程对象。

##### 辩证思考

###### 1. 它很强，但不是完整 Office 替代品

OfficeCLI 适合自动化与 AI 操作，不等于替代 Word / Excel / PowerPoint 的人工编辑体验。

##### 6. 模板合并与文档复用

###### `merge`：批量填充模板

可将 `.docx`、`.xlsx`、`.pptx` 中的 `{{key}}` 占位符替换为 JSON 数据，适用于段落、表格单元格、形状、页眉页脚和图表标题。

```bash
officecli merge invoice-template.docx out-001.docx \
  '{"client":"Acme","total":"$5,200"}'

officecli merge q4-template.pptx q4-acme.pptx data.json
```

核心思路是：AI 只设计一次版式，后续代码重复填充数据，从而减少 Token 成本，并避免批量报告风格不一致。

###### `dump` 与 `batch`：复制现有范本

`dump` 可把整个文档或任意子树序列化为可重放的 Batch JSON，例如单个表格、幻灯片、工作表、主题或样式；随后通过 `batch` 重建或修改。

```bash
officecli dump existing.docx -o blueprint.json
officecli dump existing.docx /body/tbl[1] -o table.json
officecli dump existing.xlsx /Sheet1 -o sheet.json

officecli batch new.docx --input blueprint.json
```

这适合将已有人工范本转化为结构化规格，再自动生成大量变体。

批量模式能减少 I/O，也适合原子化更新多个元素。

##### 8. 三层操作架构

OfficeCLI 采用从简单到复杂的三层设计：

| 层级 | 用途 | 主要命令 |
|---|---|---|
| **L1：语义读取** | 快速查看内容和质量问题 | `view text`、`outline`、`annotated`、`stats`、`issues`、`html`、`screenshot` |
| **L2：DOM 操作** | 对结构化元素增删改查 | `get`、`query`、`set`、`add`、`remove`、`move`、`swap` |
| **L3：原始 XML** | L2 无法覆盖时直接操作 OOXML | `raw`、`raw-set`、`add-part`、`validate` |

示例：

```bash
# L1：读取语义内容
officecli view report.docx annotated

# L2：查找和移动元素
officecli query report.docx "run:contains(TODO)"
officecli move report.docx /body/p[5] --to /body --index 1

# L3：直接修改 XML
officecli raw-set report.docx document \
  --xpath "//w:p[1]" \
  --action append \
  --xml '<w:r><w:t>Injected text</w:t></w:r>'
```

AI 可先使用低成本的 L1，在需要精确修改时进入 L2，只有特殊需求才使用 L3，从而减少上下文和 Token 消耗。

这个技能文件可以理解为一份使用说明。AI 智能体读取它之后，就知道 OfficeCLI 支持哪些命令、如何定位文档元素，以及遇到错误时怎样修正。

README 还提供了一个很直观的 PowerPoint 流程。先用 `officecli create deck.pptx` 创建空白演示文稿。然后用 `officecli add` 添加一页幻灯片，再添加标题、文本框、背景色、字体和位置。接着运行 `officecli watch deck.pptx`，浏览器会自动打开本地预览页面。

之后，只要继续执行添加、设置或删除命令，浏览器就会即时刷新。也就是说，你可以边修改，边观察最终效果，而不需要反复手动打开文件。

除了命令行，普通用户还可以使用 AionUi。这是一款桌面应用，用户只要用自然语言描述想制作的文档，AionUi 就会在后台调用 OfficeCLI，完成 Office 文档的创建和编辑。

README 展示过一个案例：PowerPoint、Word 和 Excel 文档都由 AI 智能体全自动生成，没有使用模板，也没有人工编辑。

##### 三、支持三类主要 Office 文档

接下来，OfficeCLI 覆盖的文件类型包括 Word 文档，也就是 `.docx`；Excel 电子表格，也就是 `.xlsx`；以及 PowerPoint 演示文稿，也就是 `.pptx`。

它们都支持三类基本操作：创建、读取和修改。

这里的“读取”不只是提取纯文本。OfficeCLI 还可以读取文档结构、样式、公式、图表和其他元素，并且可以输出结构化 JSON。JSON 是一种机器容易理解的数据格式，适合 AI 智能体继续分析和处理。

“分析”功能则可以帮助发现格式问题、样式不一致和文档结构缺陷。“修改”功能更加细致，能够处理文本、字体、颜色、布局、公式、图表和图片，还可以添加、删除、移动，甚至跨文档复制元素。

在 Word 方面，它支持段落、文本片段、表格、样式、页眉页脚、图片、公式、批注、脚注、水印、书签、目录、图表、超链接和表单域等内容。

它还特别强调国际化和从右向左书写，也就是 RTL。RTL 是 Right to Left 的缩写，指阿拉伯语、希伯来语等从右向左排版的文字。README 提到，OfficeCLI 可以处理不同文字系统的字体、语言标签、粗体、斜体、段落方向，以及页眉、页脚、表格和样式之间的方向设置。

在 Excel 方面，它支持单元格、工作表、表格、排序、条件格式、图表、数据验证、图片、自动筛选、命名范围和数据透视表。

数据透视表是一种把大量数据按地区、类别、季度等维度快速汇总的工具。OfficeCLI 不只是生成普通表格，还能生成原生的 Office 数据透视表，让 Excel 打开文件时直接看到聚合结果。

在 PowerPoint 方面，它支持幻灯片、形状、图片、表格、图表、动画、主题、连接线、视频、音频、组合对象、备注、批注、占位符、公式和三维模型等内容。三维模型支持 `.glb` 文件格式。

这些能力意味着，OfficeCLI 不仅能“写文字”，还可以控制完整的文档结构和视觉布局。

##### 四、最关键的能力：让 AI 看见自己的排版

更重要的是，OfficeCLI 内置了一个从零实现的 HTML 渲染引擎。

渲染，简单说，就是把文档中的结构和内容，转换成用户实际看到的页面效果。传统的 AI 文档工具，可能只能读取文档对象模型，也就是 DOM。DOM 可以理解成文档的结构树，但 AI 只看结构，并不一定知道页面最终长什么样。

例如，AI 可能知道标题存在，却不知道标题已经超出页面范围；它也可能知道两个形状都存在，却看不出两个形状发生了重叠。

OfficeCLI 会把 `.docx`、`.xlsx` 和 `.pptx` 渲染成 HTML 或 PNG。HTML 是浏览器可以打开的网页格式，PNG 则是图片格式。这样，AI 就能完成“渲染、查看、修改”的循环。

它提供三种主要方式。

第一种是 `view html`。它会生成一个资源内嵌的 HTML 文件，直接用浏览器打开即可查看。

第二种是 `view screenshot`。它会按页生成 PNG 图片，方便多模态 AI，也就是能够理解图片的 AI 模型，逐页检查文档效果。

第三种是 `watch`。它会启动一个本地 HTTP 服务，也就是让浏览器访问的本地预览服务，并在每次修改后自动刷新。默认预览地址是本机的二六三一五端口。

这个渲染引擎还覆盖了图表趋势线、误差线、瀑布图、K 线图和迷你图等效果，也支持公式、三维模型、Morph 平滑切换、幻灯片缩放和形状效果。

公式方面，OfficeCLI 可以把 Office 使用的 OMML 公式格式转换成 LaTeX，再交给 KaTeX 渲染。OMML 是 Office 文档里的数学公式标记格式，LaTeX 则是学术界常用的公式排版语言，KaTeX 是一种在网页中显示 LaTeX 公式的工具。

因为渲染能力内置在程序里，所以它不需要真正打开 Office。即使是在 CI、Docker 或没有显示器的服务器上，只要二进制程序能够运行，就可以生成预览并检查排版。

CI/CD 是持续集成和持续交付的自动化流程，常用于软件开发中的自动测试、构建和发布。Docker 则是一种容器化技术，可以把程序和运行环境封装在一起。

##### 五、Excel 公式和数据透视能力

接下来，OfficeCLI 在 Excel 计算方面也有一个重点：超过三百五十个函数可以在写入后自动求值。

也就是说，当你写入 `SUM` 这类公式后，OfficeCLI 不需要再回到 Excel 里重新计算，读取单元格时就能直接得到结果。

支持的范围包括常见的查找函数，例如 `VLOOKUP`、`XLOOKUP`、`INDEX` 和 `MATCH`；动态数组函数，例如 `FILTER`、`SORT`、`UNIQUE` 和 `SEQUENCE`；还有财务、债券、统计、回归、日期和文本函数。

动态数组可以理解为：一个公式能够自动产生一整片结果区域，而不是只返回一个单元格。README 还提到，部分动态数组函数会自动添加 `_xlfn` 前缀，以保持文件兼容性。

除此之外，它可以从源数据范围一条命令生成原生数据透视表。比如，针对一万行销售数据，可以按照地区和类别分组，按季度展开，再分别统计收入总和和销量平均值。

这意味着，AI 不只是在表格里填数字，还能直接生成带有真实汇总逻辑的 Excel 报表。Excel 打开文件时，数据透视表的缓存和定义也已经写进 Office 文件格式中。

##### 六、模板合并：一次设计，多次生成

另一个重要能力是模板合并，也就是 `merge` 命令。

它的核心思路是：让 AI 先设计一次文档版式，之后由程序批量填充数据。

具体来说，可以在 Word、Excel 或 PowerPoint 模板里放入 `{{key}}` 这样的占位符。运行合并命令时，再提供一份 JSON 数据，把占位符替换成客户名称、金额、日期或其他实际内容。

这个替换不仅适用于普通段落，也支持表格单元格、形状、页眉页脚和图表标题。

README 给出的例子，是把发票模板中的客户名称和总金额替换成具体数据，也可以把 PowerPoint 模板批量生成不同客户的版本。

这样做的意义是，昂贵的版式设计只需要进行一次。之后生成很多份报告时，只填充数据，不必让 AI 每次从头设计页面。README 特别强调，这能减少重复消耗的 token，也就是 AI 处理文本时使用的计算资源，并避免每份报告的版式出现不一致。

##### 七、Dump 和 Batch：把文档变成可重放的操作

OfficeCLI 还提供了 `dump` 和 `batch` 两组能力。

`dump` 的作用，是把一个现有的 Word、Excel 或 PowerPoint 文件，或者文件中的某个子树，转换成结构化的批处理 JSON。

这里的“子树”，可以是一段文字、一张表、单页幻灯片、单个工作表，甚至是文档的样式、主题和设置。

这样，AI 不需要直接阅读复杂的 OOXML XML。OOXML 是 Office 文件内部使用的一套开放 XML 标准。OfficeCLI 可以先把文档转成更容易理解的结构化规格，AI 修改这些规格后，再用 `batch` 命令重新执行操作。

这就打通了两种场景：一是让 AI 学习一份现成模板，二是根据这份模板批量生成很多变体。

`batch` 则可以在一次打开和保存周期里执行多条命令。例如，一次性修改多个文本框、改变多个形状颜色，或者批量更新 Excel 单元格。

默认情况下，如果其中一条命令出错，批处理会停止。使用 `--force` 参数，则可以跳过错误，继续执行后面的操作。

##### 八、驻留模式和保存机制

在处理大量操作时，OfficeCLI 支持驻留模式。

驻留模式会把文档保持在内存中，通过命名管道通信。命名管道可以理解为本机进程之间传递命令的一种方式。这样可以减少反复打开和保存文件带来的开销，命令延迟也会更低。

使用 `open` 可以启动驻留模式，使用 `close` 可以保存并释放文档。

需要注意的是，驻留模式下，OfficeCLI 自己的 `get`、`query` 和 `view` 命令始终能够读取到最新修改。但如果要让其他程序看到修改结果，比如 Python 脚本、Microsoft Word、其他渲染器，或者准备上传文件，就应该先运行 `officecli save`，把内容真正写回磁盘。

如果直接关闭驻留模式，`close` 会同时完成保存和释放。README 还提到，驻留进程闲置大约十秒后，也会自动落盘一次。

##### 九、三层操作方式：从简单读取到原始 XML

OfficeCLI 的操作可以分成三层。

第一层是语义视图，也就是从用户角度查看文档内容。常用命令包括 `view text`、`view outline`、`view stats`、`view issues`、`view html` 和 `view screenshot`。

例如，查看 Word 的结构大纲，或者查看 Excel 指定列的文本内容。这一层最适合先了解文档发生了什么。

第二层是结构化元素操作。它提供 `get`、`query`、`set`、`add`、`remove`、`move` 和 `swap` 等命令。

其中，`query` 可以按照类似 CSS 的条件查找元素。CSS 是网页中常见的样式和选择规则。OfficeCLI 也支持按属性匹配、查找包含某段文字的元素，或者查找包含某类子元素的元素。

每个文档元素都有稳定路径。例如，第一张幻灯片里的第二个形状，可以用类似 `/slide[1]/shape[2]` 的路径定位。索引从一开始计算，而且这是 OfficeCLI 自己的路径语法，并不是 XPath。

第三层是原始 XML 操作。当结构化命令不够用时，可以使用 `raw` 查看 Office 文件内部的 XML，使用 `raw-set` 配合 XPath 直接修改 XML，还可以添加新的文档部件。

XPath 是一种在 XML 文档中查找和定位节点的语言。第三层相当于提供了一个通用兜底方案，适合处理比较特殊、比较底层的文档结构。

##### 十、AI 集成和自愈式工作流

OfficeCLI 内置了 MCP 服务器。

MCP 是 Model Context Protocol，也就是模型上下文协议。它是一种让 AI 工具调用外部能力的标准方式。OfficeCLI 可以通过 MCP，把文档操作能力暴露给 Claude Code、Cursor、VS Code、GitHub Copilot 和 LM Studio 等工具。

安装时，只需要运行对应的 `officecli mcp` 命令，或者使用 `officecli mcp list` 查看注册状态。

除了 MCP，OfficeCLI 还支持所有命令输出 JSON。这样，AI 不需要依赖人类可读的终端文字，也不需要用正则表达式去猜测命令结果，而是可以直接读取结构化字段。

它的错误信息也采用结构化格式。比如，如果 AI 请求第九十九页幻灯片，但文件只有八页，工具会返回 `not_found` 错误，并提示有效范围是第一到第八页。

常见错误还包括无效值、不支持的属性、无效路径、文件不存在、文件被锁定，以及无效选择器等。

如果属性名拼写错误，OfficeCLI 会给出最接近的正确写法。这样，AI 可以先检查错误，再根据建议自动修正，而不必等待人工干预。

README 给出的典型工作流是：先创建演示文稿，再添加内容；然后查看大纲，运行文档校验；如果发现标题溢出、字体不合适或其他问题，再通过 `view issues` 获取结构化问题列表，最后自动执行修复。

这就是所谓的“自愈式工作流”：AI 不只负责生成文件，还能检查自己的结果，并根据错误反馈继续修改。

##### 十一、实际使用场景

从使用场景看，开发者可以用 OfficeCLI 根据数据库或 API 自动生成报告，也可以批量查找和替换文本、批量更新样式。

在 CI/CD 流程中，它可以根据测试结果自动构建文档，或者在没有图形界面的 Docker 容器里完成 Office 自动化。

AI 智能体可以根据用户提示生成演示文稿，从文档提取结构化数据到 JSON，并在交付前验证文档质量。

团队则可以先维护一份文档模板，再批量填充业务数据，也可以把文档质量检查放进自动化流水线。

与 Microsoft Office、LibreOffice 以及 Python 文档库相比，OfficeCLI 的突出差异包括：单一可执行文件、跨平台、基于命令行、支持 JSON、支持按路径访问元素，并且内置 HTML 和 PNG 渲染能力。

它还提供跨格式模板合并、Dump 到 Batch 的往返能力，以及适合无头服务器环境的运行方式。这里的“无头”是指没有图形界面或显示器，但程序仍然可以在后台运行。

##### 十二、一个完整示例

最后，用一个完整流程把这些能力串起来。

第一步，创建一个名为 `report.pptx` 的演示文稿。

第二步，添加一页标题为“Q4 Results”的幻灯片，再添加收入数据和增长原因等文本内容。

第三步，运行 `view outline` 查看幻灯片大纲，确认内容结构是否正确。

第四步，运行 `validate` 检查文件是否符合 OpenXML 标准。OpenXML 是 Word、Excel 和 PowerPoint 文件使用的开放文档标准。

第五步，运行 `view issues --json` 查看排版和结构问题。如果发现问题，就用 `set` 命令修改字体、颜色、位置或其他属性。

在这个过程中，AI 可以通过 `get` 获取元素详情，通过 `query` 查找目标，通过 `set` 修改属性，再通过渲染预览确认视觉效果。整个流程不要求人工打开 Office，也不要求人工逐页检查。

##### 最后，记住这五点

第一，OfficeCLI 是一个面向 AI 智能体的跨平台 Office 自动化工具，支持 Word、Excel 和 PowerPoint。

第二，它不需要安装 Office，程序本身自带运行环境，并可以通过一条命令安装和配置多种 AI 工具。

第三，它内置高保真的 HTML、PNG 和实时预览渲染能力，让 AI 能够真正看见排版，并形成“渲染、查看、修改”的闭环。

第四，它不仅能生成文字，还支持 Excel 的三百五十多个函数、数据透视表、复杂图表、模板合并和批量文档生成。

第五，它通过路径寻址、JSON 输出、结构化错误、MCP 和原始 XML 兜底，让 AI 可以从简单读取开始，逐步深入到精细修改，并在发现问题后自动修复。

## 深度解读（1）

### 2026-09-18 00:32:54

#### AI 生成 Office 文档的关键，不是“会写”，而是“能看见并纠错”

OfficeCLI 最值得关注的，并非它宣称支持多少 Word、Excel、PowerPoint 功能，而是它对 AI 文档自动化失败原因的判断：**智能体可以修改文档结构，却通常不知道最终呈现是否正确。**

传统库能让模型写入文本、坐标和样式，但标题溢出、图形重叠、分页错乱等问题，只有渲染后才能发现。OfficeCLI 因而内置 HTML/PNG 渲染，把流程变成“修改—渲染—观察—再修改”。这与代码智能体依靠编译器和测试反馈迭代类似：真正提升可靠性的，不只是更强的生成能力，而是把结果转换成机器可以检查的反馈。

这一思路也揭示了办公智能体的重要评价标准：不能只看“是否成功生成文件”，还要看**能否在无 Office、无人工介入的环境中验证语义、结构和视觉结果**。不过，README 只描述了能力，没有给出复杂文档的渲染一致性、修复成功率或与 Microsoft Office 的对照测试；“高保真”仍是需要验证的产品主张。

##### 它试图建立的，其实是一层“智能体原生文档接口”

OfficeCLI 将复杂的 OOXML 封装成稳定路径、JSON 返回、结构化错误和分层操作：智能体先读取语义视图，再操作文档元素，必要时才进入原始 XML。价值不只是少写几十行 Python，而是降低模型操作复杂软件时的搜索空间，并让错误可以自动恢复。

其中更成熟的设计，是把探索性生成与规模化生产分开：智能体先设计一次模板，后续通过 `merge` 确定性填充数据；或把现有文档 `dump` 成可重放的 JSON，再批量生成变体。**AI 适合处理模糊意图和首次设计，传统程序更适合重复执行。** 这比“每份报告都让模型从头生成”更省成本，也更容易保持品牌和版式一致。

最明确的早期需求，因此可能不是普通用户偶尔做一份 PPT，而是咨询报告、财务报表、销售提案、测试报告等高频且有固定结构的文档流水线。现有替代方案是 Office 自动化、LibreOffice 或多套 Python 库；OfficeCLI 的差异化假设，是单一跨格式接口、无头运行和视觉反馈足以抵消迁移成本。

##### 功能广度很诱人，但可信度取决于边界场景

README 罗列了公式、透视表、动画、RTL、3D 模型等大量能力，但这是一份项目自述，不是独立测评。真正决定能否进入生产环境的，是复杂模板往返编辑后是否失真、公式计算是否与 Excel 一致、渲染结果是否代表用户最终看到的效果，以及失败时能否避免损坏原文件。

此外，“把远程技能文件交给智能体安装”、`curl | bash`、自动更新和广泛的文件修改权限，也扩大了供应链与代理执行风险。企业采用时需要版本锁定、沙箱、权限控制和操作审计。

因此，OfficeCLI 最有价值的信号不是“Office 已被一条命令取代”，而是：**面向智能体的软件接口，正在从提供操作能力，升级为同时提供感知、反馈、纠错与确定性复用。** 这套设计是否成立，应优先用真实复杂文档的端到端成功率来检验，而不是用功能清单判断。

##### 一句话看懂

OfficeCLI 是一个面向 AI 智能体和自动化流程的开源命令行工具，可在不安装 Microsoft Office 的情况下创建、读取、修改并预览 Word、Excel 和 PowerPoint 文件。

##### 关键内容

- 它用统一命令操作 `.docx`、`.xlsx`、`.pptx`，支持结构化 JSON、稳定元素路径、批量处理及原始 XML 兜底，适合 AI 工具、脚本和 CI/CD。
- 核心卖点是内置 HTML/PNG 渲染：AI 不仅能读取文档结构，还能查看实际排版，再根据溢出、重叠等问题修改，形成“渲染—检查—修正”循环。
- 功能覆盖公式、图表、透视表、动画、模板占位符替换，以及把现有文档导出为可重复执行的 JSON；还能接入 Claude Code、Cursor、Copilot 等工具。
- 项目采用 Apache 2.0 许可，提供跨平台单一可执行文件。文中“全球首个、最好”等属于项目方宣传，未提供独立比较或测试证明。

##### 通俗解读

它更像“让 AI 操作文档的工具箱”，而不是给普通用户手动排版的 Office 替代品。若你要让 AI 批量生成报告、套模板或在服务器上处理 Office 文件，值得细读命令和兼容范围；仅日常写文档则没必要。所给原文末尾被截断，但核心介绍基本完整。
