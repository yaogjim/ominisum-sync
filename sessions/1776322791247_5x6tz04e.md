## 分析要点

- **核心高价值点**：指出Hermes默认会加载体积巨大的项目级AGENTS.md，调整主agent的cwd或自定义提示文件即可显著减少约5k token开销。
- **留存建议**：短期参考后可归档，适合在调试Agent提示词或做上下文瘦身时回看（包含对Hermes系统提示词结构、上下文来源和token优化点的实践性拆解，可作为后续排查和优化Agent配置的参考材料）

**知识要点**

- Hermes系统提示词由身份、记忆规则、记忆快照、用户画像、技能索引、项目指南、平台提示和会话元信息等模块拼接而成
- Skills索引与AGENTS.md是主要token消耗来源，其中AGENTS.md可能占系统提示近一半
- Hermes按项目路径动态选择.hremes.md、AGENTS.md、CLAUDE.md或.cursorrules等文件注入上下文
- 工具加载由配置和check\_fn共同决定，并非所有注册工具都会进入当前会话

**行动项**

- 检查自己的Hermes或类似Agent是否默认注入过大的项目级说明文件，并评估是否需要精简
- 在实际使用中导出完整系统提示词，按模块统计token占用，优先优化高占比上下文
- 为不同项目设置合适的cwd或定制更轻量的AGENTS.md，以降低长期对话成本
- 定期清理或治理Skill和Memory内容，避免上下文膨胀影响效率与稳定性

#### 第6层： AGENTS.md — 项目开发指南（\~20,300 chars，被截断到 14K+4K）

4K + 4K 代表啥：

> AGENTS.md 原文（20,360 chars） ├── 前 14,000 chars → 保留（项目结构、核心 API、工具开发指南等重要内容） ├── 中间 2,360 chars → 丢弃，替换为截断提示 └── 后 4,000 chars → 保留（Known Pitfalls、测试指南等收尾内容）

- 单文件上限：20,000 chars
- 截断比例：头部 70%（14K），尾部 30%（无显式定义，即剩余部分约 4-6K）
- AGENTS.md 有 20,360 chars，超了 360 chars，所以中间被砍了一小段

## 通俗精炼（1）

### 2026-04-16 06:58:20

#### Hermes Agent 系统提示词拆解：核心结论

##### 一、这篇文章讲了什么

作者把 Hermes Agent 发给模型的完整系统提示词导了出来，发现它的提示词非常长，约 **3.67 万字符、接近 1 万 tokens**。  
文章的核心不是“提示词长”，而是进一步拆解：**这些 tokens 到底花在哪、哪些是必要的、哪些可以优化掉。**

##### 二、Hermes 的系统提示词由哪些部分组成

Hermes 的系统提示词大致由 9 层构成：

###### 1. Agent 身份设定
定义 AI 的人格和角色，来自 `SOUL.md`。

###### 2. Memory 使用规则
告诉模型什么时候该写入长期记忆、什么时候不该写，以及技能该如何维护。

###### 3. MEMORY 长期记忆快照
保存用户偏好、环境信息、历史事实等，是一份会话内冻结的“长期记忆摘要”。

###### 4. USER PROFILE 用户画像
描述用户是谁、偏好什么、对输出格式和准确性有什么要求。

###### 5. Skills 技能索引
列出大量技能名称和简介，模型按需再调用详细内容。  
这一层本身也很大，约 **5000 chars**。

###### 6. AGENTS.md 项目开发指南
这是最大头，包含项目结构、API、工具开发方式、已知问题、测试指南等，几乎占了系统提示的一大半。

###### 7. 会话元数据
包括当前时间、模型名、Provider 等基础信息。

###### 8. 平台提示
比如 Telegram、Discord 等平台的特殊规则，告诉模型不同平台该怎么输出。

###### 9. 会话上下文
说明当前会话来自哪里、是群聊还是私聊、有哪些投递选项等。

##### 三、真正的“耗 token 大户”是谁

文章最重要的发现是：**最大的 token 消耗并不是人格设定，也不是记忆，而是 `AGENTS.md`。**

###### 主要消耗项
- `AGENTS.md`：约 **2 万字符**，是最大来源
- Skills 索引：约 **5000 chars**
- MEMORY 快照：约 **3700+ chars**

也就是说，Hermes 每次对话都可能先背上一大段“项目说明书”，这会显著增加 token 成本。

##### 四、作者给出的优化方法

###### 核心思路
**不要让 Hermes 默认加载那份庞大的 `AGENTS.md`。**

因为如果你只是日常使用 Hermes，而不是开发或维护 Hermes 本身，那么这部分项目级开发说明其实没必要每轮都带上。

###### 优化方式
通过调整 Hermes 的 **工作目录（CWD）**，让它不要默认读取 `~/.hermes/hermes-agent/AGENTS.md`，或者改成加载你自己更精简的说明文件。

###### 优化效果
作者实测后发现：

- 系统提示词体积明显下降
- **单次对话大约可节省 50% 左右 tokens**
- 新开 session 后效果更明显

##### 五、这篇文章的核心价值

###### 1. 让人看清 Agent 的真实成本结构
很多人以为 token 主要花在聊天内容上，但实际上，**系统提示词本身就可能很重**。

###### 2. 说明 Agent 设计是“能力”和“成本”的平衡
Hermes 的设计很强大，支持人格、记忆、技能、平台适配、项目上下文，但这些能力都会推高上下文成本。

###### 3. 提醒大家关注“默认配置陷阱”
默认加载大文件虽然方便，但未必适合所有用户。  
**对普通用户来说，很多上下文其实是冗余的。**

##### 六、一句话总结

Hermes Agent 的系统提示词结构很完整，但也非常“重”；其中最大的冗余来源是默认加载的 `AGENTS.md`。  
**如果不是做 Hermes 开发维护，精简这部分内容，就能显著降低 token 消耗，提升日常使用效率。**

## 结构化（1）

### 2026-04-17 05:43:24

#### 主旨概括

这篇文章拆解了 Hermes Agent 的系统提示词（System Prompt）到底由哪些部分组成，并指出：**Hermes 的系统提示词体量非常大，约 10K tokens，其中 `AGENTS.md` 和 Skills 索引是主要“耗 token 大户”**。  
作者还给出一个很实用的优化方法：**通过调整 Agent 的工作目录，避免加载庞大的 `AGENTS.md`，日常对话可节省约 50% tokens**。

##### 0. 准备阶段：先把 Hermes 的完整提示词导出来

- 作者为了完整分析 Hermes 发给模型的提示词，使用了自研工具 `model-box` 来导出 Agent 的全量提示词。
- 工具地址：`https://github.com/cclank/modelbox`
- 使用方式很简单：
  - 按项目文档部署
  - 启动时选择 `mock` 模式
  - 启动后通过 `/models` 切换到 `modelbox`
- 作者强调：这一步是可选的，不自己操作也可以直接看后续分析。

##### 1. 系统提示词的整体结构：共 9 层

作者从源码 `agent/prompt_builder.py` 入手，发现系统提示词由 `AIAgent._build_system_prompt()` 统一拼接，核心模块包括身份定义、平台提示、技能索引和上下文文件。

Hermes 的系统提示词主要由 9 个部分组成：

1. `SOUL.md`：Agent 身份/人格  
2. 记忆使用指南：Memory 工具规范  
3. `MEMORY`：持久化记忆快照  
4. `USER PROFILE`：用户画像快照  
5. Skills 索引：全量技能列表  
6. `AGENTS.md`：项目级开发指南  
7. 会话元数据：时间、模型、Provider  
8. 平台提示：如 Telegram 的行为规则  
9. 会话上下文：来源、群组、投递选项等  

- 总字符数约：`36,700 chars`
- 折合约：`~10K tokens`

作者对这个规模很震惊，因为它和 OpenClaw 一样，也达到了“万字级”系统提示词。

##### 2. 前四层：人格、记忆规则、记忆快照、用户画像

###### 2.1 `SOUL.md`：定义 Agent 的人格

- 来源：`~/.hermes/SOUL.md`
- 大小约：`~500 chars`
- 作用：定义 Agent 的身份和人格特征
- 特点：这是用户自己可定义的内容，所以每个人都可能不同。

###### 2.2 Memory 使用指南：告诉模型怎么“记住东西”

- 大小约：`~600 chars`
- 位置：硬编码在 `_build_system_prompt()` 里
- 关键规则包括：
  - 持久事实要用 `memory` 工具保存
  - 不要保存任务进度和完成日志，这类内容应通过 `session_search` 回忆
  - 如果发现可复用的工作流，应保存为 Skill
  - 如果发现 Skill 过时，应立即用 `skill_manage(action='patch')` 修复

通俗理解就是：**这一层像“记忆使用说明书”，规定什么该长期记，什么不该记。**

###### 2.3 `MEMORY`：持久化记忆快照

- 默认路径：`~/.hermes/memories/MEMORY.md`
- 当前大小：`~3,725 / 4,000 chars`
- 占用率：`93%`
- 特点：
  - 是“冻结快照”，在当前会话中不变
  - 包含 7 个主题板块
  - 主要记录用户的一些关键长期信息

作者提到一个实际问题：自己之前测试人格时配置过的 `coze` 社区 API key，竟然被保存进了 MEMORY，这说明**记忆系统可能误存敏感信息，需要后续优化**。

###### 2.4 `USER PROFILE`：用户画像快照

- 默认路径：`~/.hermes/memories/USER.md`
- 当前大小：`~682 / 1,375 chars`
- 占用率：`49%`
- 特点：
  - 也是冻结快照
  - 用来描述“用户是谁、偏好是什么”

文中给出的典型内容包括：

- 当前模型配置概览
- Wiki 维护要求：**高精度、必须源码验证、不能编造**
- GitHub 排版偏好：**纯 Markdown，禁用 Obsidian wikilinks，禁用 HTML 居中标签**

这说明 Hermes 不只是记“事实”，也会记用户的写作和协作偏好。

##### 3. 第五层：Skills 索引很大，约 5000 chars

- 大小约：`~5,000 chars`
- 包含：`~80+` 个 Skill
- 组织方式：按分类列出
- 每个 Skill 只展示：
  - 名称
  - 描述前缀（截断后的简介）

真正需要详情时，模型再调用 `skill_view(name)` 加载完整内容。

作者的核心观点是：

- Hermes 的 Skill 体系很丰富，说明它具备较好的“技能化、自进化”能力
- 但副作用也很明显：**技能索引本身会变大，导致提示词膨胀**
- 后续可能需要考虑“skill 泛滥”的治理问题

可以把它理解成：**目录做得很全，但目录本身也会占不少空间。**

##### 4. 第六层：`AGENTS.md` 是最大头，几乎占了系统提示的一半

这是全文最关键的部分。

- 原文件大小：`20,360 chars`
- 单文件上限：`20,000 chars`
- 实际保留策略：
  - 前 `14,000 chars` 保留
  - 中间 `2,360 chars` 丢弃并替换为截断提示
  - 后 `4,000 chars` 保留
- 作者估算：这部分大约占了 `~5K tokens`

###### 为什么这样截断？

作者解释，这种策略是因为：

- 文件开头通常最重要，例如目录结构、核心 API
- 文件结尾也常有重要内容，比如注意事项、测试指南
- 中间往往是细节，相对可牺牲

###### `AGENTS.md` 包含什么内容？

主要是 Hermes 项目本身的开发说明，包括：

- 完整项目结构和目录职责
- 文件依赖链：`registry → tools → model_tools → run_agent`
- `AIAgent` 类的构造参数和核心接口
- CLI 架构：`Rich`、`prompt_toolkit`、`KawaiiSpinner`、Slash Command Registry
- 如何添加工具
- 如何添加配置
- Skin/Theme 系统说明
- `Known Pitfalls`：6 个已知坑
- pytest 测试指南

###### 作者的判断

如果你不是在做以下事情，这部分其实没必要每次都带上：

- 开发 Hermes
- 升级维护 Hermes
- 调试 Hermes 内核

也就是说，**普通用户日常聊天时，不需要把一大坨项目开发文档放进系统提示词里**。

##### 5. 最实用的优化建议：改 CWD，能省约一半 tokens

作者给出的最佳优化方式是：

- **针对不同 agent 配置 `TERMINAL CWD` 路径**
- 让 Hermes 主 agent 的工作目录改到你指定的位置，然后重启

示例指令思路：

> 请将主 agent cwd 配置为 `~`，然后重启

###### 为什么这样能省 tokens？

因为 Hermes 会按优先级动态加载项目提示文件：

- `.hermes.md`
- `AGENTS.md`
- `CLAUDE.md`
- `.cursorrules`

如果默认启动目录指向 Hermes 自身仓库，系统就很可能加载 `~/.hermes/hermes-agent/AGENTS.md`，而这个文件非常大。  
把工作目录改掉后，就可能避开这个超大的 `AGENTS.md`，于是系统提示词立刻变短。

###### 优化效果

- 作者展示的结果是：**提示词体量“瞬间少了一半”**
- 代价是：需要开启一个新 session，重新加载上下文

这也是文章标题里提到的“降低 50% tokens 的小妙招”。

##### 6. Hermes 与 OpenClaw 的差别：Hermes 更灵活

作者顺带对比了 Hermes 和 OpenClaw 在 `AGENTS.md` 加载机制上的差异：

- Hermes 的 `AGENTS.md` 是**项目级动态加载**
- OpenClaw 的 `AGENT.md` 更偏**全局固定加载**
- 作者认为 Hermes 的方案更好，因为更灵活

通俗说就是：

- Hermes 更像“看你当前在哪个项目，就带哪个项目说明”
- OpenClaw 更像“无论你在哪，都背着一套固定说明书”

##### 7. 第七到第九层：会话元数据、平台提示、上下文信息

###### 7.1 会话元数据

- 大小约：`~200 chars`
- 示例内容：
  - 会话开始时间：`Monday, April 13, 2026 09:58 PM`
  - 模型：`qwen3.6-plus`
  - Provider：`alibaba`

此外还有一条重要规则：

- 当被问到“你是什么模型”时，必须根据这里的信息回答

###### 7.2 平台提示：按 Telegram、Discord 等平台定制

- 大小约：`~200 chars`
- 如果当前平台是 Telegram，就会注入 Telegram 专属规则
- 文中列出的规则例子：
  - 不使用 Markdown（作者对此存疑，觉得 Telegram 实际支持）
  - 媒体文件通过 `MEDIA:/path/to/file` 投递
  - 图片 URL 用 `![alt](url)` 可自动作为原生照片发送

作者认为这部分设计得很好，因为**不同平台的行为差异被显式告诉了模型**。

###### 7.3 会话上下文元信息

- 大小约：`~400 chars`
- 作用：告诉模型“你现在在哪、处于什么会话环境”

示例信息包括：

- 来源：Telegram 群“爱马仕小分队”，thread 205
- 会话类型：多用户线程
- 消息格式：带 `[sender name]` 前缀
- 已连接平台：`local + telegram`
- Home Channel：telegram Home
- 定时任务投递选项：`origin / local / telegram`

这部分相当于给模型一个“当前场景定位”。

##### 8. 系统提示词之后还有什么：对话消息、工具列表、工具筛选机制

###### 8.1 对话消息

- 就是用户与 Hermes 每轮实际聊天内容
- 会随着会话不断追加

###### 8.2 工具列表：并不是所有工具都会加载

- Hermes 总共注册：`51` 个工具
- 当前会话实际加载：`30` 个工具

未加载工具及原因包括：

- `mcp_*`（3 个）：没配 MCP server
- `rl_*`（10 个）：RL 训练工具集未启用
- `homeassistant_*`（4 个）：未配 Home Assistant
- `image_generation`：未配图像生成 API Key
- `mixture_of_agents`：MoA 工具集未启用
- `send_message`：可能当前平台未启用

###### 8.3 工具是如何筛选的？

筛选逻辑在 `model_tools.py` 的 `_discover_tools()` 中，主要依据：

- `check_fn`：比如检查 API Key 是否存在
- `enabled_toolsets`
- `disabled_toolsets`

也就是说，Hermes 的工具不是“全塞进去”，而是**根据环境和配置按需启用**。

##### 9. 作者的最终结论：真正要优化的，是 Skill 膨胀和 `AGENTS.md` 过大

文章最后，作者总结出两个主要问题：

###### 9.1 Skill 机制虽好，但可能导致“技能泛滥”

- Hermes 有很强的 Skill 自进化逻辑
- 但随着 Skill 越来越多，索引本身会越来越大
- 这会持续推高系统提示词成本

###### 9.2 `AGENTS.md` 默认加载过重，普通场景没必要

- 默认情况下，Hermes 很可能会加载 `~/.hermes/hermes-agent/AGENTS.md`
- 这个文件太大，甚至已经被截断
- 大约会吃掉 `~5K tokens`

作者建议两种处理方式：

- 更推荐：**按自己的使用场景调整 CWD，避免加载无关的大文件**
- 更省事：**直接缩减 `AGENTS.md` 内容**
  - 但要注意：后续更新时可能被覆盖

#### 一句话结论

**这篇文章最重要的价值有两个：一是把 Hermes 的系统提示词拆成了清晰的 9 层；二是指出普通用户日常最该优化的是 `AGENTS.md` 的加载问题，调整工作目录后，提示词成本可直接降低约一半。**
