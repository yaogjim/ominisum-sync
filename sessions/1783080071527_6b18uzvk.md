- 一个最小Loop应包含目标、执行、检查、纠错、状态、沉淀和停止条件七个要素。

- 复杂任务应让AI每轮输出回合报告，记录新增结果、剔除原因、反馈更新和当前状态。

### Loop Engineering 实操指南：告别 AI 返工

看完这篇，你会拿到三样东西： 一个最小 Loop 模板， 一个 KOL Loop 完整案例，三个可迁移场景：写文章、做视频、整理周报

我们以前用 AI 做复杂任务时，最烦的是它中途跑偏，还要自己发现、提醒、返工。

Loop Engineering 解决的就是这个问题：提前设计目标、检查标准、反馈方式和停止条件，让 AI 自己一轮轮修正到可交付。

这篇文章会用 KOL Loop、Article Loop 和内容工作流，讲清楚普通人怎么把找 KOL、写文章、做视频、整理周报这类任务，变成 AI 可以持续执行的工作循环。

很多人用 AI 卡住的地方，其实就在这里：

- 它跑偏了，你要发现。它漏条件了，你要提醒
- 它混进脏数据了，你要筛。它输出格式不对，你要重整

Loop Engineering 想解决的，就是这部分人肉盯场成本。

---

#### 1\. 先给一个最小定义

Loop Engineering 的最小形态，可以理解成一句话：

> 给 Agent 一个目标，让它执行一轮；用明确标准检查结果；把问题变成下一轮反馈；记录当前状态；继续修正，直到达到停止条件。

所以一个可用 Loop 至少要有 7 个要素：

Heartbeat、Skill、Connector、多 Agent、State 这些组件，会让 Loop 更稳定、更自动、更可复用。

但它们属于增强件。

最小 Loop 的核心就是：

执行一轮 -&gt; 检查结果 -&gt; 反馈问题 -&gt; 修正规则 -&gt; 继续执行 -&gt; 达标后停止。

---

#### 2\. Goal、Skill、Loop 怎么区分

很多人第一次接触 Loop Engineering，会把 Goal、Skill、Loop 混在一起。

我用一个很简单的方式理解：

打个比方，你要做番茄牛腩：

- Goal：今晚做一份能上桌的番茄牛腩
- Skill：番茄牛腩的菜谱和经验
- Loop：切菜、炖煮、试味、调整、继续炖，直到味道合格

放到 Codex 或 Claude Code 里也一样。

Goal 定义终点，Skill 沉淀方法，Loop 负责把方法跑到终点。

---

#### 3\. 你可以这样告诉 Agent

普通人设计 Loop，不要先问“该用什么工具”。

先把任务写成这个结构：

```plaintext
请你把这个任务当成一个 Loop 来完成。

目标：
[最后要交付什么]

输入：
[你可以读取哪些资料、链接、表格、笔记、历史结果]

每一轮动作：
1. 执行：[这一轮先做什么]
2. 检查：[用什么标准检查]
3. 纠错：[发现问题后怎么改]
4. 记录：[本轮新增什么规则或状态]

合格标准：
- [标准 1]
- [标准 2]
- [标准 3]

反馈分层：
- Hard Gate：必须剔除的问题
- Soft Rubric：需要评分或人工复核的问题
- Observation：先记录、暂不升级成规则的问题

停止条件：
达到 [数量/质量/格式/验证标准] 后停止。
如果连续 [N] 轮无法改善，请停止并说明卡在哪里。

最终交付：
[表格/文章/报告/清单/可发布版本]
```

这个模板的重点只有一个：

你提前把“检查”和“纠错”写进去。

很多人给 AI 的指令只有目标和步骤。结果 AI 确实执行了，但中途跑偏也会继续往下跑。

Loop 的关键，是让它每一轮都知道：怎么判断自己做得对不对，错了以后下一轮怎么改。

每一轮结束后，也最好让 Agent 固定输出一份“回合报告”：

```plaintext
本轮结果：
- 新增合格结果：
- 剔除结果：
- 剔除原因：

反馈更新：
- 新增 Hard Gate：
- 新增 Soft Rubric：
- Observation：

当前状态：
- 当前进度：
- 下一轮只优化：
- 是否达到停止条件：
```

这份回合报告很重要。

它能防止 Agent 每一轮都像从零开始，也能让你看清楚：它到底是在变好，还是只是在重复生成。

#### 4\. 我的 KOL Loop：一个可以照抄的例子

Loop Engineering 到底怎么用？

我直接分享一个我的工作流。你可以把任务换成自己的场景，结构照着改。

如果我要找英文金融 KOL，我不会只说：

> 帮我找 30 个金融博主。

这个指令太松。AI 很容易混进媒体号、公司号、生活号、纯 Crypto 号，最后还要人一条条检查。

我会这样写：

```plaintext
text
请使用「Loop Engineering + KOL Finder」方法，帮我寻找英文金融 KOL。

要求：
1. 平台：YouTube、TikTok、Instagram
2. 国家：英国、加拿大、澳洲、新加坡、新西兰
3. 语言：英文
4. 粉丝门槛：100K+
5. 数量：找到 30 个后跳出 Loop
6. 内容：金融交易、股票投资、外汇、黄金、金融时事、个人理财、投资教育
7. 排除：媒体号、公司号、品牌号、CEO/创始人号、政治号、生活号、汽车号、纯 Crypto/Web3 号
8. 可以有少量 Web3，但不能以 Web3/Crypto 为主
9. 必须跟之前名单去重
10. 输出 Excel，粉丝用 K/M，链接用 handle 格式，国家用中文，联系方式能找到就列出来
```

这里的重点是：硬条件、排除条件、停止条件、输出格式，全都提前写清楚。

这样 Agent 每一轮都知道自己要检查什么。

KOL Loop 真正节省的，是反复检查、纠错、去重、补字段的时间。

你给 AI 的任务越清楚，它越容易跑成一套会自己筛错的工作循环。

这里还有一个容易被忽略的东西：State。

如果没有状态表，Agent 很容易每一轮都重新理解任务。你最好让它维护一个简单的进度表：

这个表就是 KOL Loop 的“记忆”。

它能让下一轮搜索带着上一轮的经验继续跑，而不是重新开始。

#### 5\. KOL Loop 背后的 6 个零件

如果把一个更完整的 Loop 系统拆开看，常见会用到 Heartbeat、Isolation、Skill、Connector、Agent、State 这些能力。

它们不是 Loop Engineering 的固定公式，也不是一开始就必须全部配齐。

但这些词能帮你理解：为什么一个 Loop 可以变得更稳定、更自动、更可复用。

放到 KOL 场景里，就很好理解。

普通人一开始不用全部配齐。

先把 Define、Filter、QA、Feedback、Stop 写清楚，就能跑出一个简单 Loop。

等这个任务变成高频工作，再逐步加 Skill、Connector、Heartbeat 和多 Agent。

#### 6\. 写文章本身，也可以是一个 Loop

你正在读的这篇文章，就是一个 Article Loop 的结果。

它没有一上来就让 AI 直接写完。

我们是这样跑的：

你也可以这样告诉 AI：

```plaintext
请使用「Loop Engineering + Article Writer」方法，帮我写一篇适合发 X 的长文。

要求：
1. 主题：Loop Engineering 如何实操
2. 读者：听过 AI 工具，但不知道如何设计工作流的小白用户
3. 目标：让读者看完知道怎么设计自己的 Loop
4. 必须包含：开头钩子、实操模板、真实案例、常见误区、结尾判断
5. 风格：像一个人在分享经验，不要写成百科解释
6. 排除：空泛概念、连续排比、AI 腔、过度客气的表达
7. 输出：先给大纲，再写初稿，最后检查是否适合 X 发布
```

写文章的 Loop 可以很简单：

定义 -&gt; 研究 -&gt; 大纲 -&gt; 草稿 -&gt; 质量保证 -&gt; 反馈 -&gt; 修订 -&gt; 交付

好文章很少一次生成。它通常是在多轮检查和修正里慢慢长出来的。

#### 7\. 自媒体、视频和日常工作怎么用

这些场景也适合 Loop，因为它们天然需要反复测试。

内容创作 Loop

```plaintext
请使用「Loop Engineering + Content Creator」方法，帮我设计一套短视频 / X / 小红书内容生产 Loop。

要求：
1. 平台：X、小红书、YouTube Shorts 或 TikTok
2. 主题方向：[AI 工具 / 投资教育 / 职场效率]
3. 目标受众：[AI 小白 / 自媒体创作者 / 创业者]
4. 每轮产出：选题、标题、开头钩子、脚本大纲、发布文案
5. 检查标准：是否有痛点、是否具体、是否能引发评论或收藏
6. 数据反馈：发布后根据浏览、点赞、收藏、评论、完播率调整下一轮规则
7. 输出：给我 10 个选题，并说明每个选题适合的平台和切入角度
```

这个 Loop 的关键是：

趋势 -&gt; 角度 -&gt; 脚本 -&gt; QA -&gt; 反馈

先找热点和需求，再选切入角度，然后生成脚本，最后用数据反馈更新下一轮规则。

日常工作 Loop

```plaintext
请使用「Loop Engineering + Work Assistant」方法，帮我管理本周项目跟进。

要求：
1. 输入：会议纪要、聊天记录、任务清单、项目文档
2. 目标：整理出本周待办、负责人、截止时间、风险点
3. 检查标准：每个任务必须有负责人、下一步动作、截止时间
4. QA：检查有没有模糊任务、没人负责的任务、已经过期的任务
5. Feedback：如果发现信息缺失，请列出需要我补充的问题
6. Stop：所有任务都补齐负责人和下一步动作后停止
7. 输出：一份可直接发送的周报或项目跟进表
```

这个 Loop 的关键是：

收集 -&gt; 提取 -&gt; 质量保证 -&gt; 反馈 -&gt; 交付

把会议纪要、聊天记录、任务清单丢进去，让 AI 提取任务，再检查缺口，最后输出可用周报。

只要你的工作里有重复检查，就有设计 Loop 的空间。

#### 8\. 几个更可靠的案例

我重新看了几个比较可靠的资料。它们给普通人的启发很一致：

Loop 不是让 AI 一直跑。Loop 是让 AI 留下过程证据，接受检查，把反馈变成下一轮规则。

#### OpenAI 智能体改进循环

OpenAI 手册的智能体改进循环做的是：

真实运行 Agent -&gt; 查看 traces -&gt; 收集人类反馈和模型反馈 -&gt; 生成 evals -&gt; 决定是否改 instructions、tools、routing、output requirements、validation checks。

普通人可以借鉴一件事：

不要把每个错误都变成硬规则。

更稳的反馈分层是：

规则太松，结果会脏。

规则太死，结果池会被杀光。

分层反馈能让 Loop 更稳。

#### Codex 难题循环

OpenAI Codex 的“对难题进行迭代”强调：评估系统、停止规则、运行日志、工件检查。

翻成普通人能用的话：

- evaluation system：怎么判断这轮有没有变好
- stopping rule：什么时候停
- running log：上一轮做了什么、还差什么
- artifact inspection：最终产物能不能直接用

这个特别适合写文章、做报告、做复杂项目。

每轮结束后，让 AI 输出：

- 当前最好版本是什么
- 本轮改了什么
- 哪些地方变好了
- 哪些地方还没解决
- 下一轮只改什么
- 达到什么标准后停止

这样能减少“越改越乱”。

#### Claude 代码验证循环

Anthropic 的 Claude Code best practices 里有一个很实用的思路：

给 Claude 一个验证自己工作的方式。

写代码时，验证方式可能是测试、build、lint、截图对比。

放到普通任务里也一样：

- 找 KOL：国家是否可信、粉丝是否达标、是否个人创作者、近期内容是否垂直
- 写文章：开头是否直接给结果、有没有真实案例、有没有可复制模板、是否适合 X 发布
- 做视频：开头 3 秒是否抓人、脚本是否有具体场景、标题是否过度承诺

设计 Loop 的第一步，通常是给 AI 一个检查自己的方法。

#### Claude 钩子 和 子代理

Claude Code 的 hooks 和 subagents 可以理解成高级版 Loop 零件。

放到 KOL Loop 里：

- Search Agent：找候选
- Filter Agent：查粉丝、国家、语言、账号类型
- Content Audit Agent：看近期内容是否金融垂类
- QA Agent：查重复、脏数据、联系方式、格式
- 交付代理：整理 Excel

Hooks 可以放在关键节点：

- 写入正式名单前，触发去重检查
- 交付 Excel 前，触发字段完整性检查
- 每轮搜索结束后，触发污染项总结
- 找不到足够数量时，触发库存上限报告

你一开始不用配置复杂系统。先在 prompt 里写清楚这些检查节点，已经能获得很多收益。

---

#### 9\. 最后提醒

Loop Engineering 很有用，但不要把它理解成“让 AI 无限自动跑”。

越自动，越需要边界。

涉及金钱、法律、医疗、合规、公开发布、客户沟通的任务，一定要保留人工确认节点。

建议是：

- 低风险、重复、可检查的部分交给 Loop
- 高风险、需要负责的部分留给人判断
- 每一轮都记录状态
- 规则太死时，允许 Agent 报告库存上限
- 规则太松时，强化 Hard Gate

未来真正拉开差距的，可能不在提问技巧。

更大的差距，会来自谁更早学会把自己的工作拆成目标、标准、检查、纠错、状态和停止条件。这是 Loop Engineering 对普通人真正有用的地方。

#### Loop Engineering 实操指南：精炼总结与解读

##### 一、深度总结

**Loop Engineering 的核心：让 AI 不只是“执行任务”，而是能“自我检查、自我修正、直到达标”。**

过去用 AI 做复杂任务，最大问题是：

- AI 会跑偏
- 会漏条件
- 会混入脏数据
- 输出格式不稳定
- 人需要反复盯、改、返工

Loop Engineering 解决的是：**降低人肉监督成本**。

它的最小循环是：

```text
执行一轮 → 检查结果 → 发现问题 → 反馈修正 → 记录状态 → 继续执行 → 达标停止
```

一个可用 Loop 至少包含 7 个要素：

| 要素 | 作用 |
|---|---|
| 目标 | 最终交付什么 |
| 执行 | 每轮做什么 |
| 检查 | 什么算合格 |
| 纠错 | 不合格怎么改 |
| 状态 | 当前进度、问题、缺口 |
| 沉淀 | 把经验变成下一轮规则 |
| 停止 | 什么时候结束 |

文章重点不是讲复杂技术，而是告诉普通人：  
**凡是需要重复检查、筛选、修正的工作，都可以设计成 Loop。**

典型场景包括：

- 找 KOL
- 写文章
- 做短视频
- 整理周报
- 做项目跟进
- 内容生产
- 数据清洗
- 报告生成

其中最重要的不是“让 AI 一直跑”，而是提前写清楚：

1. 目标是什么  
2. 合格标准是什么  
3. 不合格如何处理  
4. 每轮记录什么  
5. 何时停止

##### 二、深入浅出解读

###### 1. Loop Engineering 到底是什么？

通俗说：

> 不是让 AI 一次性给答案，而是让 AI 像实习生一样：做一版、检查一版、改一版，直到能交付。

普通 Prompt 是：

```text
帮我找 30 个金融 KOL。
```

Loop Prompt 是：

```text
帮我找 30 个英文金融 KOL。
每轮先搜索，再检查粉丝、国家、语言、账号类型。
排除媒体号、公司号、纯 Crypto 号。
每轮记录已找到多少、剔除谁、为什么剔除。
找到 30 个合格账号后停止。
如果连续 2 轮没有新增合格结果，就停止并说明原因。
```

区别在于：

| 普通 Prompt | Loop Prompt |
|---|---|
| 只给目标 | 给目标 + 标准 + 纠错 + 停止条件 |
| AI 容易跑偏 | AI 每轮自查 |
| 人负责发现错误 | AI 先暴露错误 |
| 结果不稳定 | 过程可追踪 |

---

###### 2. Goal、Skill、Loop 的区别

可以用做菜理解：

| 概念 | 类比 | 含义 |
|---|---|---|
| Goal | 做一份番茄牛腩 | 任务终点 |
| Skill | 菜谱 | 方法经验 |
| Loop | 切菜、炖、试味、调整 | 反复执行和修正 |

放到 AI 工作里：

- **Goal**：我要什么结果
- **Skill**：我沉淀的方法
- **Loop**：让 AI 按方法不断检查、修正、交付

---

###### 3. 最小可复制模板

```text
请把这个任务当成一个 Loop 来完成。

目标：
[最终交付什么]

输入：
[资料、链接、表格、笔记]

每一轮动作：
1. 执行：[本轮做什么]
2. 检查：[用什么标准判断]
3. 纠错：[发现问题后怎么改]
4. 记录：[本轮状态和新规则]

合格标准：
- [标准 1]
- [标准 2]
- [标准 3]

反馈分层：
- Hard Gate：必须剔除的问题
- Soft Rubric：需要评分或人工复核的问题
- Observation：先记录，暂不升级为规则的问题

停止条件：

如果连续 [N] 轮没有改善，请停止并说明卡点。

最终交付：
[表格 / 文章 / 报告 / 清单]
```

核心就一句：

> 不要只告诉 AI 做什么，还要告诉它怎么判断自己做得对不对。

##### 三、关键案例提炼

###### 1. KOL Finder Loop

目标：找 30 个英文金融 KOL。

关键规则：

- 平台：YouTube、TikTok、Instagram
- 国家：英国、加拿大、澳洲、新加坡、新西兰
- 粉丝：100K+
- 内容：股票、外汇、黄金、理财、投资教育
- 排除：媒体号、公司号、品牌号、CEO 号、政治号、生活号、纯 Crypto 号
- 输出：Excel，包含国家、平台、handle、粉丝、联系方式、审核说明

它的 Loop 是：

```text
搜索候选 → 筛选条件 → 内容审核 → 剔除污染项 → 记录规则 → 继续搜索 → 达到 30 个停止
```

真正节省的是：

- 去重时间
- 查错时间
- 补字段时间
- 筛脏数据时间
- 人工返工时间

###### 2. Article Writer Loop

写文章也不是一次生成，而是：

```text
定义读者 → 收集资料 → 生成大纲 → 写初稿 → QA 检查 → 反馈修改 → 输出发布版
```

检查标准可以是：

- 开头是否有钩子
- 是否有真实案例
- 是否有可复制模板
- 是否避免 AI 腔
- 是否适合平台发布

好文章不是“一次写出来的”，而是“多轮改出来的”。

---

###### 3. Work Assistant Loop

用于周报、项目跟进：

```text
收集会议纪要 → 提取任务 → 检查负责人/截止时间/下一步 → 发现缺口 → 向人提问 → 输出周报
```

关键检查标准：

- 每个任务是否有负责人
- 是否有下一步动作
- 是否有截止时间
- 是否有风险点
- 是否有模糊任务

适合所有重复、琐碎、但可检查的工作。

##### 四、文章最有价值的观点

###### 1. AI 工作流的重点不是“生成”，而是“校验”

很多人只会让 AI 生成内容。  
但真正能提高效率的是：

> 让 AI 自己先检查、自己先发现问题、自己先修一轮。

生成只是第一步。  
检查、纠错、沉淀，才是生产力提升的关键。

---

###### 2. 状态 State 很重要

没有状态，AI 每轮都像重新开始。

状态表可以记录：

| 字段 | 示例 |
|---|---|
| 已完成数量 | 18/30 |
| 本轮污染项 | 公司号、纯 Crypto |
| 新增规则 | 近期内容必须以金融为主 |
| 待复核项 | 国家不明账号 5 个 |
| 下一轮重点 | 补加拿大、新西兰 |
| 停止条件 | 达到 30 个或连续 2 轮无新增 |

状态就是 AI 的“工作记忆”。

---

###### 3. 反馈要分层，不能一刀切

错误不应该全部变成硬规则。

| 类型 | 处理方式 |
|---|---|
| Hard Gate | 必须剔除 |
| Soft Rubric | 打分或人工复核 |
| Observation | 先观察，重复出现再升级 |

原因是：

- 规则太松，结果会脏
- 规则太死，结果会少
- 分层反馈，Loop 才稳定

---

##### 五、辩证思考

###### 1. Loop Engineering 很有用，但不是万能自动化

它适合：

- 低风险
- 高频重复
- 标准明确
- 可验证
- 可拆分的任务

例如：

- 找资料
- 整理表格
- 生成草稿
- 检查格式
- 内容初筛
- 周报整理

但不适合完全放手的场景：

- 金融决策
- 医疗建议
- 法律判断
- 合同签署
- 客户沟通
- 品牌公开发布
- 高风险商业决策

越自动，越需要边界。

---

###### 2. Loop 的本质不是“让 AI 替代人”，而是“让人少做低价值监督”

人不应该反复做：

- 查格式
- 查重复
- 查缺字段
- 查明显不合格项

这些可以交给 Loop。

但人仍然应该负责：

- 判断方向
- 设定标准
- 做最终取舍
- 处理责任问题
- 判断灰度地带

所以更准确地说：

> Loop Engineering 不是取消人的判断，而是把人的判断前置成规则。

---

###### 3. 最大难点不在工具，而在标准

很多人做不好 Loop，不是因为不会用 AI，而是因为自己也没想清楚：

- 什么叫好？
- 什么叫差？
- 哪些必须排除？
- 哪些可以容忍？
- 什么时候停止？
- 什么情况需要人工介入？

AI 只是放大你的工作流。  
你的标准模糊，AI 就会稳定地产出模糊结果。

---

###### 4. 未来差距可能不在 Prompt，而在工作拆解能力

简单 Prompt 是：

> 帮我完成任务。

Loop 思维是：

> 我把任务拆成目标、标准、检查、反馈、状态、停止条件，再让 AI 持续执行。

真正的能力差距会变成：

- 谁更会定义目标
- 谁更会设计标准
- 谁更会拆流程
- 谁更会沉淀经验
- 谁更会控制风险

这比单纯会写提示词更重要。

---

##### 六、一句话结论

**Loop Engineering 的核心，是把“人反复盯 AI”的过程，改造成“AI 按标准自查、自改、记录、迭代”的工作循环。**

最小实践公式：

```text
目标明确
标准清楚
每轮检查
错误反馈
状态记录
达标停止
人工兜底
```

真正值得学的不是某个模板，而是这种思维：

> 任何重复性工作，只要能定义标准，就可以被设计成 Loop。

## 结构化（1）

### 2026-07-06 00:02:17

##### 主旨概括

这篇文章介绍了 **Loop Engineering（循环工程）** 的实操方法：通过提前设计目标、检查标准、反馈机制、状态记录和停止条件，让 AI 不再“一路跑偏”，而是能在多轮执行中自我检查、自我修正，直到产出可交付结果。  
作者用 **KOL 搜索、文章写作、内容创作、周报整理** 等案例说明，普通人也可以把重复性工作设计成稳定的 AI 工作循环。

---

##### 1. Loop Engineering 解决什么问题

很多人用 AI 做复杂任务时，常遇到这些问题：

- AI 中途跑偏，需要人发现；
- 漏掉条件，需要人提醒；
- 混入脏数据，需要人筛选；
- 输出格式不对，需要人重整；
- 每一轮像从零开始，缺少状态记忆。

**Loop Engineering 的核心价值**，就是减少这种“人肉盯场”和反复返工的成本。

它不是简单地让 AI 自动执行任务，而是让 AI 在每一轮任务后：

1. 执行；
2. 检查；
3. 发现问题；
4. 修正规则；
5. 记录状态；
6. 继续下一轮；
7. 达到标准后停止。

---

##### 2. 最小 Loop 模板：7 个关键要素

作者把 Loop Engineering 的最小形态概括为：

> 给 Agent 一个目标，让它执行一轮；用明确标准检查结果；把问题变成下一轮反馈；记录当前状态；继续修正，直到达到停止条件。

一个可用的 Loop 至少包含 7 个要素：

| 要素 | 需要写清楚什么 |
|---|---|
| 目标 | 最后要交付什么 |
| 执行 | 每一轮要做什么 |
| 检查 | 什么结果算合格 |
| 纠错 | 不合格时怎么改 |
| 状态 | 当前做到哪里、还差什么 |
| 沉淀 | 哪些经验要变成下一轮规则 |
| 停止 | 什么时候跳出循环 |

最小 Loop 的流程是：

> 执行一轮 → 检查结果 → 反馈问题 → 修正规则 → 继续执行 → 达标后停止。

像 Heartbeat、Skill、Connector、多 Agent、State 等组件，可以让 Loop 更稳定、更自动，但它们属于增强功能，不是一开始必须具备。

---

##### 3. Goal、Skill、Loop 的区别

作者用“做番茄牛腩”来解释三个概念：

| 概念 | 含义 | 例子 |
|---|---|---|
| Goal | 任务终点 | 今晚做一份能上桌的番茄牛腩 |
| Skill | 已沉淀的方法 | 番茄牛腩的菜谱和经验 |
| Loop | 一轮轮执行、检查、调整 | 切菜、炖煮、试味、调整，直到味道合格 |

放到 AI 工作流里也是一样：

- **Goal**：定义终点；
- **Skill**：沉淀方法；
- **Loop**：负责把方法跑到终点。

##### 4. 给 Agent 的通用 Loop 指令结构

作者建议普通人不要一开始纠结工具，而是先把任务写成结构化 Loop。

核心模板包括：

```text
请你把这个任务当成一个 Loop 来完成。

目标：
[最后要交付什么]

输入：
[可以读取哪些资料、链接、表格、笔记、历史结果]

每一轮动作：
1. 执行：[这一轮先做什么]
2. 检查：[用什么标准检查]
3. 纠错：[发现问题后怎么改]
4. 记录：[本轮新增什么规则或状态]

合格标准：
- [标准 1]
- [标准 2]
- [标准 3]

反馈分层：
- Hard Gate：必须剔除的问题
- Soft Rubric：需要评分或人工复核的问题
- Observation：先记录、暂不升级成规则的问题

停止条件：
达到 [数量/质量/格式/验证标准] 后停止。
如果连续 [N] 轮无法改善，请停止并说明卡在哪里。

最终交付：
[表格/文章/报告/清单/可发布版本]
```

这个模板的重点是：**提前写清楚“检查”和“纠错”**。

很多人只告诉 AI 目标和步骤，结果 AI 即使跑偏也会继续执行。Loop 的关键是让 AI 每一轮都知道：

- 怎么判断自己做得对不对；
- 错了以后下一轮怎么改；
- 什么时候应该停下来。

##### 5. 回合报告：防止每轮从零开始

作者建议每一轮结束后，让 Agent 输出一份“回合报告”。

示例结构：

```text
本轮结果：
- 新增合格结果：
- 剔除结果：
- 剔除原因：

反馈更新：
- 新增 Hard Gate：
- 新增 Soft Rubric：
- Observation：

当前状态：
- 当前进度：
- 下一轮只优化：
- 是否达到停止条件：
```

这份报告的作用是：

- 防止 AI 每一轮都重新理解任务；
- 让用户看清 AI 是否真的在变好；
- 避免 AI 只是重复生成类似内容；
- 帮助下一轮带着上一轮经验继续优化。

##### 6. KOL Loop 案例：寻找英文金融 KOL

作者用“找英文金融 KOL”展示了完整 Loop。

如果只说：

> 帮我找 30 个金融博主。

这个指令太宽泛，AI 容易混入媒体号、公司号、生活号、纯 Crypto 号等。

作者改成了更明确的指令：

- 平台：YouTube、TikTok、Instagram；
- 国家：英国、加拿大、澳洲、新加坡、新西兰；
- 语言：英文；
- 粉丝门槛：100K+；
- 数量：找到 30 个后停止；
- 内容方向：金融交易、股票投资、外汇、黄金、金融时事、个人理财、投资教育；
- 排除：媒体号、公司号、品牌号、CEO/创始人号、政治号、生活号、汽车号、纯 Crypto/Web3 号；
- 可以有少量 Web3，但不能以 Web3/Crypto 为主；
- 必须和之前名单去重；
- 输出 Excel；
- 粉丝用 K/M；
- 链接用 handle 格式；
- 国家用中文；
- 联系方式能找到就列出。

这个案例的关键是：**硬条件、排除条件、停止条件、输出格式都提前写清楚**。

##### 7. KOL Loop 的执行流程

KOL Loop 可以拆成几个阶段：

| 阶段 | 动作 | 检查重点 |
|---|---|---|
| 定义 | 锁定国家、语言、平台、粉丝、内容范围、排除类型、数量目标 | 防止条件太宽 |
| 搜索 | 用 KOL Finder、Apify、YouTube API、TikTok 标签、Instagram 资料、Google 搜索拉候选池 | 先扩大范围 |
| 筛选 | 查粉丝、语言、国家、重复账号、账号类型 | 先挡掉脏数据 |
| 内容审核 | 看近期作品 | 确认持续讲金融、交易、投资、理财 |
| QA | 查污染项，如汽车号、新闻号、政治号、生活号、纯 Crypto、国家靠猜、字段错误 | 保证质量 |
| 反馈 | 把错误变成下一轮规则 | 如汽车号混入，就强化排除词 |
| 停止 | 达到 30 个合格账号就停 | 条件太严找不够时，报告库存上限 |
| 交付 | 输出 Excel | 包括国家、平台、handle、粉丝、联系方式、审核说明、验证状态 |

这个 Loop 节省的主要是：

- 反复检查时间；
- 纠错时间；
- 去重时间；
- 补字段时间。

##### 8. State：KOL Loop 的“记忆”

作者特别强调了 **State（状态表）** 的重要性。

如果没有状态表，AI 很容易每一轮都重新开始。一个简单的状态表可以包括：

| 字段 | 示例 |
|---|---|
| 已找到合格数量 | 18/30 |
| 本轮污染项 | 公司号、纯 Crypto、国家不明 |
| 新增规则 | 近期内容必须以金融/投资为主 |
| 待复核项 | 国家不明账号 5 个 |
| 下一轮重点 | 补加拿大和新西兰 |
| 停止条件 | 达到 30 个，或连续 2 轮无新增合格账号 |

这个状态表能让下一轮搜索带着上一轮经验继续，而不是重新开始。

##### 9. 完整 Loop 系统的 6 个零件

作者将更完整的 Loop 系统拆成 6 个常见能力：

| 零件 | 在 KOL Loop 中的作用 |
|---|---|
| Heartbeat 心跳 | 每周刷新候选池，每月复查老 KOL，每次 Campaign 前检查粉丝、内容、联系方式 |
| Isolation 隔离 | 分成候选池、待复核池、正式交付池，避免脏数据污染最终名单 |
| Skill 技能 | 沉淀 KOL 筛选方法，以后只替换国家、平台、垂类、粉丝门槛 |
| Connector 连接器 | 连接 YouTube API、TikTok、Instagram、Apify、Google 搜索、Excel、Obsidian |
| Agent 代理 | 搜索、筛选、内容审核、QA、交付分工处理 |
| State 状态 | 记住找到多少、排除了谁、为什么排除、还差多少、下一轮重点 |

作者提醒：普通人一开始不需要全部配齐。  
先把 **Define、Filter、QA、Feedback、Stop** 写清楚，就能跑出简单可用的 Loop。

##### 10. Article Loop：写文章也可以循环优化

作者指出，这篇文章本身就是一个 Article Loop 的结果，而不是一次生成完成。

它的流程是：

| 阶段 | 做了什么 |
|---|---|
| 定义 | 确定写给小白，讲清楚 Loop Engineering 怎么实操 |
| 研究 | 收集 OpenAI、Anthropic、Addy Osmani、中文 X 讨论、KOL Loop 案例 |
| 大纲 | 先做素材表和大纲，放入 Obsidian 草稿 |
| 初稿 | 写第一版长文 |
| QA | 检查开头、AI 腔、案例是否具体、结构是否清楚 |
| 反馈 | 把每次反馈变成下一版规则 |
| 修改 | 重写 KOL 案例、补官方案例、调整版面 |
| 交付 | 输出可发布版本 |

文章写作 Loop 可以简化为：

> 定义 → 研究 → 大纲 → 草稿 → 质量保证 → 反馈 → 修订 → 交付。

作者强调：**好文章很少一次生成，通常是在多轮检查和修正里慢慢长出来的。**

##### 11. 内容创作和短视频 Loop

Loop 也适合自媒体和短视频，因为内容天然需要不断测试和反馈。

内容创作 Loop 的结构可以是：

- 平台：X、小红书、YouTube Shorts、TikTok；
- 主题：AI 工具、投资教育、职场效率等；
- 受众：AI 小白、自媒体创作者、创业者；
- 每轮产出：选题、标题、开头钩子、脚本大纲、发布文案；
- 检查标准：是否有痛点、是否具体、是否能引发评论或收藏；
- 数据反馈：根据浏览、点赞、收藏、评论、完播率调整下一轮规则；
- 输出：10 个选题，并说明适合平台和切入角度。

这个 Loop 的关键链路是：

> 趋势 → 角度 → 脚本 → QA → 反馈。

先找热点和需求，再选角度、生成脚本，最后用数据反馈更新下一轮规则。

---

##### 12. 日常工作 Loop：整理周报和项目跟进

Loop 也适合日常工作，比如整理会议纪要、聊天记录、任务清单和项目文档。

一个项目跟进 Loop 可以这样设计：

- 输入：会议纪要、聊天记录、任务清单、项目文档；
- 目标：整理本周待办、负责人、截止时间、风险点；
- 检查标准：每个任务必须有负责人、下一步动作、截止时间；
- QA：检查模糊任务、没人负责的任务、已过期任务；
- Feedback：信息缺失时列出需要补充的问题；
- Stop：所有任务都补齐负责人和下一步动作后停止；
- 输出：可直接发送的周报或项目跟进表。

这个 Loop 的核心流程是：

> 收集 → 提取 → 质量保证 → 反馈 → 交付。

只要工作中存在重复检查，就有设计 Loop 的空间。

---

##### 13. 可靠案例给普通人的启发

作者参考了 OpenAI、Codex、Claude Code 等相关实践，总结出一个共同点：

> Loop 不是让 AI 一直跑，而是让 AI 留下过程证据，接受检查，并把反馈变成下一轮规则。

###### 13.1 OpenAI 智能体改进循环

OpenAI 的智能体改进循环包括：

1. 真实运行 Agent；
2. 查看 traces；
3. 收集人类反馈和模型反馈；
4. 生成 evals；
5. 决定是否修改 instructions、tools、routing、output requirements、validation checks。

普通人可以借鉴的是：**不要把每个错误都变成硬规则**。

反馈应该分层：

| 类型 | 处理方式 | KOL 例子 |
|---|---|---|
| Hard Gate 硬闸 | 明确剔除 | 粉丝低于 100K、国家不在目标范围、重复账号、媒体号 |
| Soft Rubric 柔性评分 | 评分或人工复核 | Web3 内容偏多、金融内容不够垂直、商业价值一般 |
| Observation 观察 | 先记录，连续出现再升级 | 偶然混入汽车号，先观察下一轮是否重复 |

规则太松，结果会脏；规则太死，结果池会被杀光。  
分层反馈能让 Loop 更稳定。

###### 13.2 Codex 难题循环

Codex 的“对难题进行迭代”强调：

- evaluation system：怎么判断这轮有没有变好；
- stopping rule：什么时候停；
- running log：上一轮做了什么、还差什么；
- artifact inspection：最终产物能不能直接用。

这适合文章、报告和复杂项目。每轮结束后，可以让 AI 输出：

- 当前最好版本是什么；
- 本轮改了什么；
- 哪些地方变好了；
- 哪些地方还没解决；
- 下一轮只改什么；
- 达到什么标准后停止。

这样能减少“越改越乱”。

###### 13.3 Claude 代码验证循环

Claude Code 的实用思路是：

> 给 Claude 一个验证自己工作的方式。

写代码时，验证方式可能是测试、build、lint、截图对比。  
普通任务也可以设计验证标准：

- 找 KOL：国家是否可信、粉丝是否达标、是否个人创作者、近期内容是否垂直；
- 写文章：开头是否直接给结果、有没有真实案例、有没有可复制模板、是否适合 X 发布；
- 做视频：开头 3 秒是否抓人、脚本是否有具体场景、标题是否过度承诺。

设计 Loop 的第一步，通常就是给 AI 一个检查自己的方法。

---

##### 14. Hooks 和多 Agent：高级版 Loop 组件

作者提到 Claude Code 的 hooks 和 subagents，可以理解为高级版 Loop 零件。

放到 KOL Loop 中，可以拆成多个 Agent：

- Search Agent：找候选；
- Filter Agent：查粉丝、国家、语言、账号类型；
- Content Audit Agent：审核近期内容是否金融垂类；
- QA Agent：查重复、脏数据、联系方式、格式；
- 交付 Agent：整理 Excel。

Hooks 可以设置在关键节点：

- 写入正式名单前，触发去重检查；
- 交付 Excel 前，触发字段完整性检查；
- 每轮搜索结束后，触发污染项总结；
- 找不到足够数量时，触发库存上限报告。

不过作者强调，普通人一开始不用配置复杂系统，只要在 prompt 里写清楚检查节点，就已经能获得明显收益。

---

##### 15. 最后提醒：Loop 需要边界

Loop Engineering 很有用，但不能理解成“让 AI 无限自动跑”。

越自动，越需要边界。涉及以下场景时，必须保留人工确认节点：

- 金钱；
- 法律；
- 医疗；
- 合规；
- 公开发布；
- 客户沟通。

作者给出的建议是：

- 低风险、重复、可检查的部分交给 Loop；
- 高风险、需要负责的部分留给人判断；
- 每一轮都记录状态；
- 规则太死时，允许 Agent 报告库存上限；
- 规则太松时，强化 Hard Gate。

---

##### 总结

这篇文章的核心观点是：未来真正拉开差距的，可能不是谁更会写 Prompt，而是谁更早学会把工作拆成 **目标、标准、检查、纠错、状态和停止条件**。  

Loop Engineering 的实用价值在于，它能把找 KOL、写文章、做视频、整理周报等重复性任务，变成 AI 可以持续执行、持续修正、最终交付的工作循环。

##### 最小 Loop 的七个要素

一个可用循环包括：**目标、执行、检查、纠错、状态、经验沉淀、停止条件**。基本流程是：

> 执行一轮 → 检查结果 → 反馈问题 → 修正规则 → 继续执行 → 达标后停止

其中，Goal 定义终点，Skill 是可复用的方法，Loop 则负责反复执行和校正。每轮最好生成“回合报告”，记录新增结果、剔除原因、规则变化、当前进度及下一轮重点，避免 Agent 每次从零开始或重复生成。

##### 反馈要分层，规则不能过松或过死

作者建议将问题分为三类：

- **Hard Gate**：必须剔除，如不满足数量、国家或账号类型要求。
- **Soft Rubric**：需要评分或人工复核，如内容垂直度、商业价值。
- **Observation**：暂时记录，重复出现后再升级为规则。

状态表同样关键：它要保存已完成数量、污染项、待复核项和剩余任务，使后续循环继承经验。

##### 从找 KOL 到内容与周报

KOL 案例中，AI 按平台、国家、粉丝量和内容范围搜索，再检查重复、账号属性与近期内容，达到 30 个合格账号后停止；若连续多轮没有新增，则报告“库存上限”，而非硬凑数量。同一结构也可迁移到文章写作、短视频生产和项目周报：先产出，再通过质量标准或发布数据修订下一轮。

更复杂的系统可加入 API、定时运行、多 Agent 和自动检查，但作者建议从“定义—筛选—质检—反馈—停止”起步。Loop 并非无限自动化：涉及金钱、法律、医疗、合规和公开发布时，仍应保留人工确认。
