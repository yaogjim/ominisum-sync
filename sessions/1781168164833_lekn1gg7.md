**小盖**

### 总结下我使用 Codex 的 8 个高频场景。

总结一下我使用 Codex 的几个主要场景。Coding 就不说了，这是它的看家本领。但除了 Coding 之外，我发现这个工具已经慢慢融入到我日常工作的方方面面。

一、配图

我现在写文章、PPT，甚至公司内部文档时，配图这件事基本都交给 Codex 来处理。根据不同场景，大概可以分成三类。

第一种，信息型配图。

我会直接把文章丢给 Codex，再调用自己提前做好的文章配图 Skill。

这个 Skill 会先通读整篇文章，判断哪些地方适合插入配图，然后和我确认。确认之后，它会直接生成一个 HTML 版本的配图页面。

我很喜欢这种方式，因为配图本质上变成了网页。如果有哪里不满意，无论是文字、排版还是布局，都能快速修改，不需要重新生成。

而且用下来我越来越觉得，很多文章配图其实并不需要 GPT Image 2 这种图片模型。

对于信息传递来说，简单的图形、线条和排版往往已经足够了。有时候越简单，反而越容易让读者把注意力放在内容本身。

比如下面的配图，其实就是一个网页。

![Image](https://pbs.twimg.com/media/HKW_zyubQAAkn4q?format=jpg&name=large)

第二种，手绘风格的脑图、流程图、时序图、架构图等等。

工作里经常会遇到需要画流程图、梳理逻辑关系的时候。我一直很喜欢用 Excalidraw，因为它画出来的东西天然带着一种手绘感，看起来没有那么生硬，很有味道。

现在，我的流程是先把一段文字或者一个想法丢给 Codex，让它先帮我拆解。比如这段内容如果要画成流程图，需要哪些节点、哪些关系、应该怎么组织结构。等整体框架确认之后，再调用我专门做的 Excalidraw Diagram Skill 生成。

这个 Skill 会同时输出两个文件，一个是 PNG，一个是 Excalidraw 文件。PNG 可以直接拿来用。Excalidraw 文件则可以重新导入 Excalidraw 进行二次编辑。

![Image](https://pbs.twimg.com/media/HKW_6RqbEAA2SWC?format=jpg&name=large)

Skill 地址在这里：

[https://github.com/coleam00/excalidraw-diagram-skill](https://github.com/coleam00/excalidraw-diagram-skill)

第三种，制作有趣的 PPT 插图。

这个 Skill 是我在 X 上发现的，特别好用。它可以把一段原本很枯燥的内容，自动转换成这种带有强烈手绘风格的插图。

这种风格最大的特点，就是把原本严肃、抽象的内容，用手绘插画的方式重新表达出来。画面里会出现各种小人、道具、场景和夸张的视觉元素，看起来像是在讲一个故事。

地址在这里：

[https://github.com/helloianneo/ian-xiaohei-illustrations/tree/main](https://github.com/helloianneo/ian-xiaohei-illustrations/tree/main)

![Image](https://pbs.twimg.com/media/HKW_-jWasAA4dEF?format=jpg&name=large)

二、整理电脑磁盘

如果你的电脑存储空间本来就不大，经常需要清理磁盘腾地方的话，我觉得有了 Codex 之后，真的没必要再专门买那些磁盘清理软件了。

我家里的 Macbook 存储空间并不大。今年我往这台电脑上装了特别多 Agent 产品，其实很多都是体验，装完很快又卸载了。

但后来我发现，直接把它拖到废纸篓是没办法彻底删除的。因为很多 Agent 软件背后都有很多依赖软件。

后来我突然想到，为什么不让 Codex 帮我查查。

于是我直接让它扫描系统，看看过去装过的那些 Agent 软件有没有残留文件，哪些关联组件还能安全删除。结果还真找出来不少没卸载干净的关联文件。而且动辄就占几个 G。

![Image](https://pbs.twimg.com/media/HKXADH3bYAAXhNo?format=jpg&name=large)

三、长文转 Slides

我给自己定了一个要求：每周至少精读一篇长文章。

这里说的长文章，指那些真正值得花时间读完的长博客、深度访谈或者研究文章，而非新闻和各种碎片化资讯。

因为我越来越觉得，在信息泛滥的时代，单纯刷新闻的价值其实并不高。很多内容看完当下觉得自己知道了，但过两天就忘了。

相比之下，那些经过充分思考和沉淀的长文，反而更容易给人带来新的认知。

现在我的做法简单很多。每次读完一篇文章，我会直接把文章交给 Codex，让它帮我生成一份 HTML 版 Slides。

内容不需要面面俱到，重点是把文章的核心观点、关键论据和整体脉络梳理出来。

生成之后，我会对着这份 Slides 再完整过一遍，相当于重新复盘一次文章。

这个过程其实很有意思。第一次阅读是在吸收信息，第二次借助 Slides 回顾的时候，更多是在整理自己的理解。

很多第一次阅读时忽略的细节，往往会在这个阶段重新浮现出来。

Skill 地址：

[https://github.com/gainubi/note-slides](https://github.com/gainubi/note-slides)

四、处理会议纪要

现在各种软件都有会议纪要功能，但我还是习惯把会议纪要导出成 Markdown 文件，再交给 Codex 处理。

尤其是当同一个主题连续开了好几次会的时候，这种方法特别好用。

比如这周围绕某个项目开了三四次会，我会把所有会议纪要一次性丢给 Codex，让它从整体视角去分析，而不是只看某一次会议发生了什么。

最直接的用法当然是整理 Todo。

我会先让它把所有待办事项提取出来，然后继续追问一句：这些 Todo 里面，哪些事情是你可以直接帮我完成的？

有意思的是，很多事情它还真能做。比如整理资料、写初稿、做调研、分析数据、汇总信息、生成文档、整理方案之类的工作，很多时候都可以直接交给它继续往下执行。

如果是客户会议或者用户访谈，我会让它帮我梳理用户最关注的问题、最频繁出现的抱怨，以及那些容易被忽略但值得关注的反馈。

有时候为了收集用户声音，我们会从很多渠道拿资料。有的是微信群聊天记录，有的是用户访谈纪要，有的是问卷反馈。以前这些内容散落在各个地方，很难整体分析。

现在我会把这些资料统一整理出来，一股脑丢给 Codex，让它帮我做用户痛点分析、需求归类和观点提炼。

特别是当数据量比较大的时候，这种工作我越来越倾向于交给 Codex。因为它能同时阅读大量资料，还能快速发现不同信息之间的关联。

五、连接飞书

这个用法我上周刚专门写过一篇文章，估计很多人还不知道。

如果想在手机上使用 Codex，其实除了 ChatGPT App 之外，还可以直接接入飞书。整个过程非常简单，和之前在飞书里接 OpenClaw 的方式差不多，几分钟就能搞定。

连接 Codex 和飞书，我的本意是通过手机操作 Codex。但真正用下来之后，我发现自己反而更喜欢在电脑端的飞书里使用 Codex。

因为飞书本身就是我的工作中心。聊天记录、会议纪要、文档、项目资料，很多内容本来就在飞书里。

比如看到一段群聊讨论，我可以直接转发给 Codex，让它帮我整理重点。开完会的纪要，也可以顺手丢给它分析。

更有意思的是飞书文档。以前如果想让 Codex 帮我修改一段内容，通常需要把内容复制出来，再扔给 Codex。

现在很多时候根本不用这么麻烦。比如我正在写这篇文章，写到某一段的时候，觉得表达还不够顺，或者想从另一个角度展开，直接在飞书文档里 @ Codex 就行。

六、接入微信读书

微信读书最近也发布了 Skill，可以直接一键安装，大家搜一下就能找到。

顺便说一下我自己的阅读习惯。

除了文学类作品，我其实很少把一本工具书从第一页一直读到最后一页。因为很多工具书本身就不是按照小说的方式来阅读的，里面真正有价值的内容往往集中在少数几个章节。

所以我经常会先打开微信读书，看这本书的热门划线。把热门划线先看一遍之后，这本书最核心的观点、最有启发的内容，基本就已经了解个七七八八了。然后再根据自己的兴趣，去挑一些章节精读。

这也是为什么我每年都会给微信读书续费。因为热门划线这个功能实在太好用了。

某种程度上，相当于成千上万名读者提前帮我们做了一轮筛选。哪些内容最值得停下来思考，哪些段落最容易引发共鸣，大家其实已经用划线投过票了。

而接入 Codex 之后，这件事又方便了一大截。

因为平时经常写文章，经常会遇到一种情况：明明记得某本书里看过一个特别好的观点，或者一句特别有启发的话，但就是想不起来具体在哪。以前只能自己回去翻书。现在我直接让 Codex 去微信读书里找。

比如让它围绕某个主题，从热门划线里筛选相关内容；或者帮我找某位作者关于某个问题的观点；再或者从几本书的热门划线里整理出共同出现的关键概念。

对于经常阅读、经常写作的人来说，这种体验还是挺爽的。因为书里的内容并没有变多，但调用这些内容的成本被大幅降低了。

七、部署网站

现在大家都在 Vibe Coding 自己的小产品，前后端都有。我自己也已经 Vibe Coding 了 11 个小工具。

这些小工具很多是有后端的，涉及到怎么部署到服务器上。我现在用的是腾讯云的 CloudBase，它同样有 CLI，所以只要完成一次授权，后面所有的部署，都可以在 Codex 里搞定，不需要再去 CloudBase 后台做各种配置。

![Image](https://pbs.twimg.com/media/HKXAIKMacAA3HuZ?format=jpg&name=large)

八、处理公司日常琐碎事务

我们是小公司，所以很多原本需要行政、HR、财务甚至法务处理的基础工作，现在基本都交给 Codex 了。

比如一份合同拿过来，我通常会直接丢给它。让它先检查风险、梳理重点条款，或者按照我们的需求修改。很多标准化合同，它处理起来已经相当成熟了。

包括一些制度文件、招聘相关资料、流程文档之类的工作，也都可以交给它先完成第一版。

而我觉得更有价值的，是它和飞书数据打通之后带来的变化。

我们公司的很多经营数据、财务数据，其实都放在飞书多维表格里。给 Codex 装上飞书 CLI 之后，它就可以直接和这些数据连接。

这样一来，它就不只是一个聊天工具了，而是能够真正参与到日常运营当中。比如新增数据、修改数据、批量检查数据，这些事情都可以直接交给它处理。

我自己现在还有一些固定的自动化流程。

比如每天上午，我都会让 Codex 去检查前一天的数据。看看有没有遗漏记录、异常数据，或者一些明显不合理的地方。

![Image](https://pbs.twimg.com/media/HKXAMAgasAI3Rbp?format=jpg&name=large)

很多时候，人录数据难免会出错。但让它每天固定巡检一次，很多问题当天就能发现。到了月底，我直接跑一个命令，Codex 就会把这个月的经营情况梳理出来。

##### 一、深度总结

这篇内容的核心不是“Codex 会写代码”，而是：

> **Codex 正在从编程工具，变成一个可调用文件、数据、文档、流程和外部系统的工作型 Agent。**

作者的 8 个高频场景可以归为四类：

| 类别 | 场景 | 本质 |
|---|---|---|
| 内容生产 | 配图、长文转 Slides、PPT 插图 | 把信息重新组织成更易理解的表达形式 |
| 信息整理 | 会议纪要、用户反馈、微信读书 | 从大量文本中提炼结构、观点和行动项 |
| 系统操作 | 清理磁盘、部署网站 | 让 AI 直接执行本地或云端任务 |
| 公司运营 | 合同、制度、数据巡检、飞书集成 | 把 AI 嵌入日常业务流程 |

作者真正想表达的是：

> **Codex 的价值不只是“生成内容”，而是“理解内容 → 生成方案 → 调用工具 → 完成任务”。**

##### 三、深入浅出解读

如果用一句话解释这篇文章：

> 作者不是在说 Codex 有 8 个功能，而是在展示一种新的工作方式：把 AI 当成一个能读、能写、能查、能改、能执行的数字同事。

过去的 AI 更像：

> 你问一句，它答一句。

现在的 Codex 更像：

> 你给它一个目标，它自己拆任务、读资料、调工具、产出结果。

比如：

- 写文章缺图？它帮你生成可编辑配图。
- 开了三次会？它帮你汇总 Todo。
- 磁盘满了？它帮你找残留文件。
- 读过一本书想找观点？它帮你翻。
- 公司数据乱了？它每天帮你巡检。
- 网站要上线？它调用 CLI 帮你部署。

所以这篇文章的重点不是“效率提升一点点”，而是：

> 很多原本需要人手动切换软件、查资料、整理格式、执行流程的工作，现在可以被 Codex 串起来。

真正的价值在“连接”：

- 连接文档
- 连接会议
- 连接本地系统
- 连接飞书
- 连接微信读书
- 连接云服务
- 连接公司数据

一旦连接完成，AI 就从“聊天窗口”变成了“工作操作系统”。

---

##### 四、我的辩证思考

###### 1. Codex 的最大价值：不是智能，而是可执行

很多 AI 工具只会“说”，但 Codex 的优势在于能“做”。

它能调用：

- 文件系统
- CLI
- 外部 Skill
- 飞书
- 云服务
- 数据表

这意味着 AI 的边界从“生成答案”扩展到“完成任务”。

但也正因为它能执行，风险也更高。

---

###### 2. 越接近真实业务，越需要权限控制

让 Codex 清理磁盘、改数据、查合同、部署网站，这些都很方便。

但问题是：

- 它可能误删文件
- 可能误改数据
- 可能误解合同条款
- 可能部署错误版本
- 可能泄露敏感信息

所以越是强大的 Agent，越需要：

- 操作前确认
- 关键步骤留痕
- 权限最小化
- 数据备份
- 人类最终审核

一句话：

> AI 可以代劳，但不应完全脱管。

---

###### 3. 它适合做“第一版”和“批量活”，不适合直接做最终判断

Codex 特别适合：

- 初稿
- 整理
- 分类
- 汇总
- 检查
- 转换格式
- 批量处理
- 发现异常

但在这些场景仍需谨慎：

- 法务定责
- 财务决策
- 重大合同
- 人事裁决
- 核心业务判断

AI 可以把人从低价值劳动中解放出来，但不应替代人的责任承担。

---

###### 4. 真正的门槛不在工具，而在工作流设计

很多人用 AI 只是提问，所以只能得到零散答案。

作者的用法更高级，因为他做了三件事：

1. 把常见任务做成 Skill  
2. 把 Codex 接入工作系统  
3. 把重复流程自动化  

这说明未来的竞争力可能不是“会不会用 AI”，而是：

> 能不能把自己的工作拆成可被 AI 执行的流程。

谁能把流程标准化、工具化、自动化，谁就能获得更高杠杆。

---

##### 五、最精炼结论

这篇文章真正讲的是：

> **Codex 正在从“写代码工具”变成“个人与小公司的通用执行助手”。**

它的 8 个场景背后，是 3 个趋势：

1. **内容生产自动化**：文章、图表、Slides、文档都能快速生成  
2. **信息处理智能化**：会议、书籍、反馈、数据都能被结构化  
3. **工作流程代理化**：AI 不只回答问题，还能调用工具完成任务  

但同时也要记住：

> **越能干的 AI，越需要清晰边界、权限管理和人工复核。**

##### 主旨概括

##### 一、配图：把内容可视化交给 Codex

作者认为，文章、PPT、内部文档中的配图，很多时候都可以由 Codex 辅助完成，主要分为三类：

###### 1. 信息型配图

- 作者会把整篇文章交给 Codex，并调用自制的文章配图 Skill。
- Codex 会先阅读文章，判断哪些位置适合插图，再生成一个 **HTML 版配图页面**。
- 这种方式的好处是：
  - 配图本质上是网页，文字、排版、布局都能快速修改；
  - 不一定需要 GPT Image 2 这类图片模型；
  - 对信息传递来说，简单图形、线条、排版往往更清晰。

###### 2. 手绘风格图表

- 适用于脑图、流程图、时序图、架构图等。
- 作者喜欢 Excalidraw 的手绘风格，因为视觉上不生硬。
- 使用流程是：
  1. 把文字或想法交给 Codex；
  2. 让它拆解节点、关系和结构；
  3. 确认后调用 Excalidraw Diagram Skill 生成图表。
- 输出包括：
  - PNG 文件，可直接使用；
  - Excalidraw 文件，可再次编辑。
- Skill 地址：  
  &lt;https://github.com/coleam00/excalidraw-diagram-skill>

###### 3. PPT 趣味插图

- 作者使用一个在 X 上发现的 Skill，把枯燥内容转成手绘插画。
- 特点是用小人、道具、场景、夸张视觉元素，把严肃内容讲成故事。
- 适合用于 PPT 或演示材料中增强表现力。
- Skill 地址：  
  &lt;https://github.com/helloianneo/ian-xiaohei-illustrations/tree/main>

##### 二、整理电脑磁盘：找出卸载残留文件

作者认为，如果电脑存储空间有限，有了 Codex 后不一定需要购买专门的磁盘清理软件。

- 作者的 MacBook 存储空间不大，今年安装过很多 Agent 产品。
- 很多软件虽然拖进废纸篓卸载了，但依赖组件和残留文件还在。
- 作者让 Codex 扫描系统，检查过去安装过的 Agent 软件是否有残留。
- Codex 找出了不少未卸载干净的关联文件，有些甚至占用 **几个 GB**。
- 价值在于：Codex 能帮助判断哪些文件可以安全删除，减少手动排查成本。

---

##### 三、长文转 Slides：帮助深度阅读复盘

作者每周要求自己至少精读一篇长文章，包括长博客、深度访谈、研究文章等。

- 他认为，在信息泛滥时代，刷新闻价值有限，很多内容很快会忘。
- 真正经过思考和沉淀的长文，更容易带来认知提升。
- 现在他的做法是：
  1. 读完长文；
  2. 把文章交给 Codex；
  3. 生成一份 HTML 版 Slides；
  4. 借助 Slides 再复盘一遍文章。
- Slides 不追求面面俱到，而是提炼：
  - 核心观点；
  - 关键论据；
  - 整体脉络。
- 这个过程相当于二次阅读：第一次吸收信息，第二次整理理解。
- Skill 地址：  
  &lt;https://github.com/gainubi/note-slides>

##### 四、处理会议纪要：从多个会议中提炼行动和洞察

虽然很多软件都有会议纪要功能，但作者更习惯把会议纪要导出为 Markdown，再交给 Codex 处理。

###### 1. 多次会议整体分析

- 如果同一主题连续开了三四次会，作者会把所有纪要一次性丢给 Codex。
- Codex 可以从整体视角分析，而不是只看某一次会议。

###### 2. 提取 Todo 并继续执行

- 作者会先让 Codex 提取所有待办事项。
- 然后追问：这些 Todo 里，哪些事情你可以直接帮我完成？
- Codex 可以继续处理很多任务，例如：
  - 整理资料；
  - 写初稿；
  - 做调研；
  - 分析数据；
  - 汇总信息；
  - 生成文档；
  - 整理方案。

###### 3. 分析客户会议和用户反馈

- 对客户会议或用户访谈，作者会让 Codex 总结：
  - 用户最关注的问题；
  - 高频抱怨；
  - 容易被忽略但值得关注的反馈。
- 当资料来自微信群聊天记录、访谈纪要、问卷反馈等多个渠道时，Codex 能统一分析用户痛点、需求类别和核心观点。
- 数据量越大，Codex 的优势越明显，因为它能同时阅读大量材料并找出信息之间的关联。

---

##### 五、连接飞书：把 Codex 接入工作中心

作者最近尝试把 Codex 接入飞书，最初目的是在手机上操作 Codex，但实际使用后发现电脑端飞书更适合。

- 飞书本身就是作者的工作中心，里面有：
  - 聊天记录；
  - 会议纪要；
  - 文档；
  - 项目资料。
- 接入后，可以直接把群聊讨论转发给 Codex，让它整理重点。
- 会议结束后，也可以直接把纪要丢给 Codex 分析。
- 在飞书文档里写作时，如果某一段表达不顺，或者想换个角度展开，可以直接在文档中 `@ Codex`。
- 这样减少了复制、粘贴、来回切换工具的成本。

---

##### 六、接入微信读书：降低调用书中知识的成本

微信读书最近也发布了 Skill，可以一键安装。

###### 作者的阅读习惯

- 除文学类作品外，作者很少从头到尾读完一本工具书。
- 他通常会先看微信读书里的热门划线。
- 热门划线相当于由大量读者提前筛选出书中最有价值、最有共鸣的内容。
- 因此作者每年都会续费微信读书，因为热门划线功能非常实用。

###### Codex 接入后的变化

- 以前写文章时，作者常常记得某本书里有个好观点，但想不起具体位置，只能回去翻书。
- 现在可以直接让 Codex 去微信读书里查找。
- 典型用法包括：
  - 围绕某个主题，从热门划线中筛选相关内容；
  - 查找某位作者关于某个问题的观点；
  - 从几本书的热门划线中整理共同出现的关键概念。
- 核心价值是：书本内容没有变多，但调用知识的成本大幅降低。

---

##### 七、部署网站：用 Codex 完成小工具上线

作者提到，现在很多人都在用 Vibe Coding 做自己的小产品，前后端都有。

- 作者自己已经 Vibe Coding 了 **11 个小工具**。
- 这些小工具很多带后端，需要部署到服务器。
- 作者使用的是腾讯云 CloudBase。
- CloudBase 有 CLI，只要完成一次授权，后续部署都可以在 Codex 中完成。
- 这样就不需要频繁进入 CloudBase 后台做各种配置。

---

##### 八、处理公司日常琐事：让 Codex 参与运营

作者所在公司规模较小，因此很多原本需要行政、HR、财务、法务处理的基础工作，现在都交给 Codex 先做。

###### 1. 合同和制度文档处理

- 一份合同拿来后，作者会直接交给 Codex：
  - 检查风险；
  - 梳理重点条款；
  - 按需求修改。
- 对标准化合同，Codex 已经处理得比较成熟。
- 其他如制度文件、招聘资料、流程文档等，也可以让 Codex 先完成第一版。

###### 2. 连接飞书多维表格处理经营数据

- 公司很多经营数据、财务数据都放在飞书多维表格中。
- 给 Codex 装上飞书 CLI 后，它可以直接连接这些数据。
- Codex 不再只是聊天工具，而是能参与日常运营，比如：
  - 新增数据；
  - 修改数据；
  - 批量检查数据。

###### 3. 自动化巡检和月度总结

- 作者每天上午会让 Codex 检查前一天的数据。
- 重点检查：
  - 是否有遗漏记录；
  - 是否存在异常数据；
  - 是否有明显不合理的地方。
- 因为人工录入数据难免出错，Codex 的每日巡检能让问题当天被发现。
- 到月底时，作者只需跑一个命令，Codex 就能整理出当月经营情况。

---

##### 总结

作者的经验表明，Codex 的价值已经远远超出写代码：它可以生成配图、整理磁盘、复盘长文、处理会议纪要、连接飞书和微信读书、部署网站，还能参与公司日常运营。真正的变化在于，Codex 正在从“回答问题的工具”变成“能连接资料、执行任务、参与工作流的助手”。
