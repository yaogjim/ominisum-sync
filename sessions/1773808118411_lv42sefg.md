**Brian Scanlan**

We've been building an internal Claude Code plugin system at Intercom with 13 plugins, 100+ skills, and hooks that turn Claude into a full-stack engineering platform. Lots done, more to do. Here's a thread of some highlights.

---

##### 热门回复

**@kosmyk** ♥ 536 · 💬 0

Tutorial on how to send funds privately or publicly with Kosmyk Cash $KMK

**@Brian Scanlan** ♥ 41 · 💬 3

The wildest one: we gave Claude a read-only Rails production console via MCP. Claude can now execute arbitrary Ruby against production data - feature flag checks, business logic validation, cache state inspection etc.

**@Brian Scanlan** ♥ 34 · 💬 4

Safety gates: read-replica only, blocked critical tables, mandatory model verification before every query, Okta auth, DynamoDB audit trail. I launched it by saying "It is either the worst thing in the world that will ruin Intercom, or complete genius."

**@Brian Scanlan** ♥ 29 · 💬 1

We instrumented every Claude Code lifecycle event with OpenTelemetry. SessionStart, UserPromptSubmit, PreToolUse, PostToolUse, PermissionRequest, SubagentStart... 14 event types flowing to Honeycomb. Privacy-first: we explicitly never capture user prompts, messages, or tool input

**@Brian Scanlan** ♥ 22 · 💬 2

Session transcripts sync to S3 (with username SHA256-hashed for privacy). We can analyze how people actually use Claude at scale. On SessionEnd, a hook analyzes the entire session transcript with Claude Haiku looking for improvement opportunities.

## 结构化（1）

### 2026-03-18 04:28:38

这篇内容主要讲的是：Intercom 正在把 Claude Code 从 “写代码助手” 扩展成 “内部全栈工程平台”。他们已经做出一套较完整的插件、技能、权限控制和观测体系，同时也在探索高风险但高价值的能力。

- 第一部分：整体建设规模
  - Intercom 内部已经为 Claude Code 搭建了一个插件系统。
  - 当前规模包括：`13 个插件`、`100+ skills（技能）`，以及一套`hooks（钩子）`机制。
  - 这些能力组合起来，让 Claude 不只是回答问题，而是能更深度参与工程流程。

- 第二部分：最激进的能力 —— 连接生产环境
  - 他们给 Claude 接入了一个`只读的 Rails 生产控制台`，通过 MCP 使用。
  - 这意味着 Claude 可以对生产数据执行任意 Ruby 代码，但限定为只读场景。
  - 具体用途包括：
    - 检查`feature flag`是否开启；
    - 验证业务逻辑；
    - 查看缓存状态等。
  - 作者形容这个功能 “要么是会毁掉 Intercom 的最糟糕想法，要么是绝对天才”，说明它价值很大，但风险也非常高。

- 第三部分：为高风险能力加安全护栏
  - 为了降低生产环境访问风险，他们加了多层安全限制：
    - 只允许访问`read-replica（只读副本）`；
    - 屏蔽关键数据表；
    - 每次查询前都必须做模型校验；
    - 使用`Okta`做身份认证；
    - 用`DynamoDB`保存审计日志。
  - 简单说，就是让 Claude “能看、能验证”，但尽量避免误操作核心数据。

- 第四部分：全链路观测 Claude 的使用过程
  - 他们把 Claude Code 生命周期中的每个关键事件都接入了`OpenTelemetry`。
  - 一共追踪了`14 类事件`，例如：
    - `SessionStart`
    - `UserPromptSubmit`
    - `PreToolUse`
    - `PostToolUse`
    - `PermissionRequest`
    - `SubagentStart`
  - 这些数据会流向`Honeycomb`，用于观察 Claude 在真实工作中的表现。
  - 但他们强调 “隐私优先”：`明确不采集用户 prompt、消息内容和工具输入`。

- 第五部分：会话记录分析与持续优化
  - Claude 的会话转录会同步到`S3`。
  - 为保护隐私，用户名会做`SHA256 哈希`处理。
  - 这样团队就能分析：大家在真实场景下到底是怎么使用 Claude 的。
  - 在`SessionEnd`时，还会通过一个 hook，用`Claude Haiku`分析整段会话，寻找可改进的地方。
  - 这相当于让系统不仅 “被使用”，还能 “自动复盘并优化”。

- 第六部分：核心价值
  - 这套系统的重点，不只是给 Claude 增加更多功能，而是把它做成一个可接入生产环境、可审计、可观测、可持续优化的工程平台。
  - 从案例看，Intercom 的思路很明确：一边大胆开放能力，一边用权限、审计和隐私机制兜底。
