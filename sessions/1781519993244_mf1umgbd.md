context 有5种handoff 方法：

1\. subagent：主 agent 发指令给 subagent，无缓存继承。workflow 用的大量 subagent。

4\. claude --continue --fork-session： 在当前目录执行，会 复制出一个最近对话的上下文。100% 缓存。

5\. ⌘F：本文介绍的 skill，比 4更强，在对话过程中直接弹出旁窗，复制上下文，进行新对话。100% 缓存。

#### Context Handoff 的 5 种方法总结

##### 核心观点

作者总结了在使用 Claude Code / Agent 工作流时，进行「上下文交接」的 5 种方式。不同方式在缓存继承、使用场景和灵活性上差异明显，核心目标是：**在不中断主线任务的情况下，复用已有上下文，开启分支探索或新任务。**

---

##### 1. Subagent：适合工作流拆分

主 Agent 向 Subagent 发指令，让子 Agent 执行具体任务。

特点是：

- 适合复杂 workflow
- 常用于多 Agent 协作
- **不会继承缓存**
- 更像是任务分发，而不是完整上下文复制

适合场景：主任务明确，需要把子任务外包给其他 Agent。

---

##### 2. `/model`：直接切换模型

在当前窗口中切换使用的模型。

特点是：

- 操作简单
- 但切换后缓存会全部 miss
- 成本和效率可能受影响

适合场景：确认后续是长程任务，且有必要换更强或更合适的模型时使用。

---

##### 3. `/export`：导出聊天记录再导入

把当前聊天记录导出，然后在其他模型或会话中导入使用。

特点是：

- 更像人工搬运上下文
- 跨模型、跨环境使用方便
- 不一定有缓存优势

适合场景：需要把已有对话迁移到另一个模型或工具中继续使用。

---

##### 4. `claude --continue --fork-session`：复制最近对话上下文

在当前目录执行该命令，可以复制出最近一次对话的上下文。

特点是：

- 上下文继承完整
- **100% 缓存命中**
- 适合从当前任务中开一个分支

适合场景：想保留主线，同时尝试另一种方案。

---

##### 5. `⌘F` Skill：更强的 Fork 能力

作者重点推荐的方式。它可以在对话过程中直接弹出旁窗，复制当前上下文，并开启新对话。

特点是：

- 不需要离开当前对话
- 可随时开启分支探索
- **100% 缓存命中**
- 比 `--fork-session` 更灵活

适合场景：主线任务进行中，临时想问岔路问题、尝试激进改法，又不想污染当前上下文。

---

##### 一句话总结

这 5 种方法本质是在解决同一个问题：**如何高效管理 AI 对话上下文，既保留主线，又能安全开启分支。**

其中：

- 简单任务拆分：用 `subagent`
- 长程任务换模型：用 `/model`
- 跨工具迁移：用 `/export`
- 命令行复制会话：用 `--fork-session`
- 对话中即时开分支：用 `⌘F Skill`

作者认为，`⌘F` 是目前最强的上下文管理方式，适合高频使用 Claude Code 的进阶用户。
